# 8.8.2 Recherche avec CONTAINS et FREETEXT

## Introduction

L'index de texte intégral est en place (§8.8.1). Il est temps de l'interroger. SQL Server propose deux prédicats et deux fonctions de table :

- `CONTAINS` — recherche **précise** et contrôlée (mots, préfixes, proximité, pondération…).
- `FREETEXT` — recherche en **langage naturel**, plus souple.
- `CONTAINSTABLE` / `FREETEXTTABLE` — mêmes recherches, mais renvoient en plus un **score de pertinence** (`RANK`).

---

## CONTAINS : la recherche précise

`CONTAINS` s'utilise dans la clause `WHERE`. Il offre un contrôle fin sur ce que l'on cherche.

### Mot ou phrase exacte

```sql
-- Articles contenant le mot « imperméable »
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'imperméable');

-- Phrase exacte (guillemets internes)
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, '"chaussures de course"');
```

### Recherche par préfixe

```sql
-- Mots commençant par « informa » (informatique, information, informaticien...)
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, '"informa*"');
```

> ⚠️ Le joker `*` ne fonctionne qu'en **suffixe** d'un préfixe entre guillemets (`"mot*"`). Ce n'est pas le `%` de `LIKE`.

### Opérateurs booléens

```sql
-- « chaussures » ET « imperméable »
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'chaussures AND imperméable');

-- « chaussures » mais PAS « enfant »
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'chaussures AND NOT enfant');
```

### Proximité avec NEAR

```sql
-- « course » à proximité de « montagne »
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'NEAR(course, montagne)');

-- « course » à 5 mots maximum de « trail », dans cet ordre
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'NEAR((course, trail), 5, TRUE)');
```

### Formes fléchies (FORMSOF INFLECTIONAL)

```sql
-- Trouve « courir », « course », « courons », « couru »...
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'FORMSOF(INFLECTIONAL, courir)');
```

C'est l'atout linguistique majeur par rapport à `LIKE` : on cherche un **concept**, pas une chaîne brute.

### Synonymes (FORMSOF THESAURUS)

```sql
-- Selon le thésaurus configuré : « PC » trouve aussi « ordinateur »
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'FORMSOF(THESAURUS, PC)');
```

### Pondération (ISABOUT)

```sql
-- Donne plus de poids à certains termes dans le calcul de pertinence
SELECT Titre FROM Articles
WHERE CONTAINS(Contenu, 'ISABOUT(course WEIGHT(0.8), randonnée WEIGHT(0.2))');
```

---

## FREETEXT : la recherche en langage naturel

`FREETEXT` est plus simple à utiliser : on lui donne une **phrase**, et SQL Server se charge de la décomposer en mots, d'appliquer la racinisation et le thésaurus, puis de trouver les lignes pertinentes.

```sql
-- SQL Server interprète le « sens » de la requête
SELECT Titre FROM Articles
WHERE FREETEXT(Contenu, 'chaussures imperméables pour courir en montagne');
```

➡️ Pas besoin d'opérateurs : c'est l'idéal pour une **barre de recherche** où l'utilisateur tape librement. En contrepartie, on a moins de contrôle fin que `CONTAINS`.

---

## Obtenir un score de pertinence : CONTAINSTABLE et FREETEXTTABLE

Pour classer les résultats du plus pertinent au moins pertinent, on utilise les **fonctions de table** `CONTAINSTABLE` / `FREETEXTTABLE`, qui renvoient deux colonnes : `KEY` (la clé de la ligne) et `RANK` (score de 0 à 1000).

```sql
SELECT a.Titre, ft.RANK
FROM FREETEXTTABLE(Articles, Contenu, 'chaussures imperméables course') AS ft
JOIN Articles AS a ON a.ArticleID = ft.[KEY]
ORDER BY ft.RANK DESC;   -- les plus pertinents d'abord
```

> 💡 C'est exactement le mécanisme d'un moteur de recherche : on joint la table sur la clé renvoyée, et on trie par `RANK` décroissant. On peut aussi limiter avec `TOP`.

```sql
-- Les 10 articles les plus pertinents
SELECT TOP 10 a.Titre, ct.RANK
FROM CONTAINSTABLE(Articles, Contenu, 'FORMSOF(INFLECTIONAL, courir)') AS ct
JOIN Articles AS a ON a.ArticleID = ct.[KEY]
ORDER BY ct.RANK DESC;
```

---

## CONTAINS vs FREETEXT : que choisir ?

| Critère | `CONTAINS` | `FREETEXT` |
|---------|-----------|-----------|
| Contrôle | Fin (booléens, proximité, poids) | Faible (automatique) |
| Simplicité d'écriture | Plus technique | Très simple |
| Formes fléchies | Sur demande (`FORMSOF`) | **Automatique** |
| Thésaurus | Sur demande (`FORMSOF`) | **Automatique** |
| Usage typique | Recherche experte, filtres précis | Barre de recherche grand public |

> 🧠 **Règle simple** : `FREETEXT` pour une recherche « grand public » intuitive ; `CONTAINS` quand on a besoin de précision (proximité, exclusion, pondération).

---

## Exemple : une mini fonction de recherche

```sql
-- Recherche d'articles, triés par pertinence, avec extrait
SELECT TOP 20
    a.ArticleID,
    a.Titre,
    ft.RANK AS Pertinence
FROM FREETEXTTABLE(Articles, (Titre, Contenu), @termesRecherche) AS ft
JOIN Articles AS a ON a.ArticleID = ft.[KEY]
ORDER BY ft.RANK DESC;
```

(`(Titre, Contenu)` recherche dans les deux colonnes ; `*` rechercherait dans toutes les colonnes indexées.)

## Bonnes pratiques et pièges

- ✅ **Choisir la bonne langue** d'index (racinisation, mots vides corrects).
- ✅ Utiliser **`CONTAINSTABLE`/`FREETEXTTABLE`** dès qu'on veut **classer** les résultats.
- ✅ Combiner avec des **filtres SQL classiques** (catégorie, date, statut) dans la même requête — c'est l'avantage d'une FTS intégrée.
- ⚠️ Ne pas confondre le joker FTS (`"mot*"`, préfixe) avec le `%` de `LIKE`.
- ⚠️ Les **mots vides** sont ignorés : rechercher « le » seul ne renverra rien.
- ⚠️ Vérifier que l'index est **peuplé** avant de s'étonner d'un résultat vide.

## Questions fréquentes

**Q : `CONTAINS` ne trouve pas « courir » alors que « course » existe — pourquoi ?**
R : Par défaut, `CONTAINS` cherche le terme exact. Pour les variantes, utilisez `FORMSOF(INFLECTIONAL, courir)` ou `FREETEXT`.

**Q : Comment paginer des résultats de recherche ?**
R : Combinez `CONTAINSTABLE`/`FREETEXTTABLE`, triez par `RANK DESC`, puis appliquez `OFFSET ... FETCH NEXT` (voir §3.3.3).

**Q : Le score `RANK` est-il comparable d'une requête à l'autre ?**
R : Non. Le `RANK` est **relatif** à une requête donnée : il ordonne ses propres résultats, il ne compare pas deux recherches différentes.

---

## Résumé

- `CONTAINS` offre une recherche **précise** : phrases, préfixes (`"mot*"`), booléens, proximité (`NEAR`), formes fléchies (`FORMSOF INFLECTIONAL`), synonymes (`FORMSOF THESAURUS`), pondération (`ISABOUT`).
- `FREETEXT` offre une recherche en **langage naturel**, idéale pour une barre de recherche.
- `CONTAINSTABLE` / `FREETEXTTABLE` renvoient un **score `RANK`** pour classer les résultats par pertinence.
- On joint la fonction de table sur `[KEY]` et on trie par `RANK DESC`.
- La FTS se **combine** naturellement avec les filtres SQL classiques.
