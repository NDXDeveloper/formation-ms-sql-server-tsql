# 3.2.5 Gestion des NULL (IS NULL, IS NOT NULL)

## Introduction

Les valeurs `NULL` sont l'un des concepts les plus **déroutants** pour les débutants en SQL, mais aussi l'un des plus **importants** à maîtriser. NULL est partout dans les bases de données réelles, et ne pas comprendre comment il fonctionne peut conduire à des erreurs silencieuses et des résultats inattendus.

**Question simple** : Que signifie NULL ?

**Réponse simple** : NULL signifie "**absence de valeur**" ou "**valeur inconnue**". Ce n'est **pas** zéro, ce n'est **pas** une chaîne vide, c'est l'**absence d'information**.

---

## 1. Qu'est-ce que NULL ?

### Définition

`NULL` représente :
- Une valeur **manquante**
- Une valeur **inconnue**
- Une information **non applicable**
- L'**absence** de donnée

### Analogies pour comprendre NULL

**Analogie 1 : Le formulaire incomplet**

Imaginez un formulaire d'inscription :
- **Nom** : Dupont ✅ (valeur connue)
- **Prénom** : Sophie ✅ (valeur connue)
- **Téléphone** : ___________ ❓ (non renseigné = NULL)
- **Email** : sophie@mail.com ✅ (valeur connue)

Le téléphone est `NULL` car l'information n'a pas été fournie.

**Analogie 2 : La boîte mystère**

- Une boîte **vide** = chaîne vide `''` ou nombre `0`
- Une boîte **absente** = NULL (pas de boîte du tout !)

---

### NULL vs zéro vs chaîne vide

| Valeur | Type | Signification | Exemple |
|--------|------|---------------|---------|
| `NULL` | Absence | Inconnu / Non renseigné | Téléphone non fourni |
| `0` | Nombre | Zéro (valeur connue) | Solde bancaire à 0€ |
| `''` | Chaîne vide | Chaîne sans caractère | Commentaire laissé vide |

**Important** : Ce sont trois choses **totalement différentes** !

---

### Exemples de NULL en situation réelle

| Colonne | Valeur | Raison du NULL |
|---------|--------|----------------|
| DateDeces | NULL | La personne est vivante (non applicable) |
| Telephone | NULL | Numéro non fourni (manquant) |
| DateLivraison | NULL | Commande pas encore livrée (inconnu) |
| Remise | NULL | Pas de remise appliquée (non applicable) |
| NomJeuneFille | NULL | Personne non mariée (non applicable) |

---

## 2. Pourquoi NULL est spécial ?

### Le problème des comparaisons classiques

Avec les opérateurs normaux (`=`, `!=`, `>`, `<`), NULL se comporte **différemment** de toutes les autres valeurs.

**Règle fondamentale** : Toute comparaison avec NULL retourne `UNKNOWN` (inconnu), pas `TRUE` ou `FALSE`.

### Exemples de comparaisons qui échouent

#### Tentative 1 : Égalité avec NULL

```sql
SELECT *
FROM Clients
WHERE Telephone = NULL  -- ❌ Ne fonctionne PAS !
```

**Résultat** : **Aucune ligne** retournée, même s'il existe des clients sans téléphone.

**Pourquoi ?** Parce que `Telephone = NULL` ne retourne ni VRAI ni FAUX, mais `UNKNOWN`.

---

#### Tentative 2 : Différence avec NULL

```sql
SELECT *
FROM Clients
WHERE Telephone != NULL  -- ❌ Ne fonctionne PAS non plus !
```

**Résultat** : **Aucune ligne** retournée.

**Pourquoi ?** Même raison : on ne peut pas comparer quelque chose à NULL avec `=` ou `!=`.

---

### La logique à trois valeurs

En SQL, à cause de NULL, la logique n'est pas binaire (VRAI/FAUX) mais **ternaire** :

| Résultat possible | Signification |
|-------------------|---------------|
| `TRUE` | La condition est vraie |
| `FALSE` | La condition est fausse |
| `UNKNOWN` | On ne peut pas savoir (à cause de NULL) |

**Règle SQL** : Seules les lignes où la condition retourne `TRUE` sont incluses dans les résultats. `UNKNOWN` est traité comme `FALSE`.

---

## 3. IS NULL : Tester la présence de NULL

### La bonne syntaxe

Pour tester si une colonne contient NULL, utilisez **toujours** :

```sql
WHERE colonne IS NULL
```

**Pas** `= NULL` !

### Exemple basique

Trouver les clients qui n'ont **pas fourni** leur numéro de téléphone :

```sql
SELECT Prenom, Nom, Telephone
FROM Clients
WHERE Telephone IS NULL
```

**Résultat** :

| Prenom | Nom | Telephone |
|--------|-----|-----------|
| Sophie | Martin | NULL |
| Pierre | Dubois | NULL |

---

### Exemples pratiques avec IS NULL

#### Exemple 1 : Commandes non livrées

Trouver les commandes qui n'ont pas encore été livrées :

```sql
SELECT CommandeID, DateCommande, DateLivraison
FROM Commandes
WHERE DateLivraison IS NULL
```

**Interprétation** : Si `DateLivraison` est NULL, la commande est en cours.

---

#### Exemple 2 : Produits sans description

Trouver les produits dont la description n'a pas été renseignée :

```sql
SELECT NomProduit, Description
FROM Produits
WHERE Description IS NULL
```

---

#### Exemple 3 : Employés sans manager

Trouver les employés qui n'ont pas de manager assigné (probablement les dirigeants) :

```sql
SELECT Prenom, Nom, ManagerID
FROM Employes
WHERE ManagerID IS NULL
```

---

#### Exemple 4 : Clients sans email

Trouver les clients dont l'email n'a pas été fourni :

```sql
SELECT Prenom, Nom, Email
FROM Clients
WHERE Email IS NULL
```

---

#### Exemple 5 : Articles sans remise

Trouver les produits qui n'ont pas de remise :

```sql
SELECT NomProduit, Prix, Remise
FROM Produits
WHERE Remise IS NULL
```

---

## 4. IS NOT NULL : Tester l'absence de NULL

### La syntaxe

Pour tester qu'une colonne contient **une valeur** (pas NULL), utilisez :

```sql
WHERE colonne IS NOT NULL
```

### Exemple basique

Trouver les clients qui **ont fourni** leur numéro de téléphone :

```sql
SELECT Prenom, Nom, Telephone
FROM Clients
WHERE Telephone IS NOT NULL
```

**Résultat** :

| Prenom | Nom | Telephone |
|--------|-----|-----------|
| Marie | Leroy | 06 12 34 56 78 |
| Luc | Moreau | 06 23 45 67 89 |

---

### Exemples pratiques avec IS NOT NULL

#### Exemple 1 : Commandes livrées

Trouver toutes les commandes qui ont été livrées :

```sql
SELECT CommandeID, DateCommande, DateLivraison
FROM Commandes
WHERE DateLivraison IS NOT NULL
```

---

#### Exemple 2 : Produits avec description

Trouver les produits qui ont une description :

```sql
SELECT NomProduit, Description
FROM Produits
WHERE Description IS NOT NULL
```

---

#### Exemple 3 : Clients contactables

Trouver les clients qui ont au moins un moyen de contact (email ou téléphone) :

```sql
SELECT Prenom, Nom, Email, Telephone
FROM Clients
WHERE Email IS NOT NULL OR Telephone IS NOT NULL
```

**Interprétation** : Au moins un des deux doit avoir une valeur.

---

#### Exemple 4 : Employés avec bonus

Trouver les employés qui ont reçu un bonus :

```sql
SELECT Prenom, Nom, Bonus
FROM Employes
WHERE Bonus IS NOT NULL
```

---

#### Exemple 5 : Validations complètes

Trouver les enregistrements complets (toutes les colonnes importantes renseignées) :

```sql
SELECT *
FROM Inscriptions
WHERE Nom IS NOT NULL
  AND Prenom IS NOT NULL
  AND Email IS NOT NULL
  AND Telephone IS NOT NULL
```

---

## 5. NULL et les opérateurs de comparaison

### Tableau de vérité avec NULL

Voici ce que retournent les comparaisons avec NULL :

| Expression | Résultat |
|------------|----------|
| `NULL = NULL` | **UNKNOWN** (pas TRUE !) |
| `NULL = 5` | **UNKNOWN** |
| `NULL != 5` | **UNKNOWN** |
| `NULL > 5` | **UNKNOWN** |
| `NULL < 5` | **UNKNOWN** |
| `5 = NULL` | **UNKNOWN** |

**Conclusion** : On ne peut **jamais** comparer NULL avec `=`, `!=`, `>`, `<`, etc.

---

### Exemple : Le piège de la double négation

**Question** : Quel est le contraire de `Telephone IS NULL` ?

**❌ Réponse incorrecte** : `Telephone != NULL`

**✅ Réponse correcte** : `Telephone IS NOT NULL`

**Démonstration** :

```sql
-- Clients SANS téléphone
SELECT COUNT(*) FROM Clients WHERE Telephone IS NULL
-- Résultat : 50

-- Clients AVEC téléphone
SELECT COUNT(*) FROM Clients WHERE Telephone IS NOT NULL
-- Résultat : 150

-- TOTAL
SELECT COUNT(*) FROM Clients
-- Résultat : 200 (50 + 150 = 200) ✅

-- ❌ Tentative avec !=
SELECT COUNT(*) FROM Clients WHERE Telephone != NULL
-- Résultat : 0 (ne trouve personne !)
```

---

## 6. NULL et les opérateurs logiques (AND, OR, NOT)

### NULL avec AND

| A | B | A AND B |
|---|---|---------|
| TRUE | NULL | **UNKNOWN** |
| FALSE | NULL | **FALSE** |
| NULL | NULL | **UNKNOWN** |

**Exemple** :
```sql
WHERE Prix > 100 AND Remise IS NULL
```

Si `Prix` est NULL, l'expression complète retourne `UNKNOWN` (traité comme `FALSE`).

---

### NULL avec OR

| A | B | A OR B |
|---|---|--------|
| TRUE | NULL | **TRUE** |
| FALSE | NULL | **UNKNOWN** |
| NULL | NULL | **UNKNOWN** |

**Exemple** :
```sql
WHERE Email IS NULL OR Telephone IS NULL
```

Si les deux sont NULL, l'expression retourne `UNKNOWN` (traité comme `FALSE`).

---

### NULL avec NOT

| A | NOT A |
|---|-------|
| NULL | **UNKNOWN** |

**Exemple** :
```sql
WHERE NOT (Remise IS NULL)
```

**Équivalent à** : `WHERE Remise IS NOT NULL`

---

## 7. NULL et les opérateurs IN, BETWEEN, LIKE

### NULL avec IN

```sql
-- ❌ Ceci ne trouve PAS les NULL
SELECT * FROM Produits WHERE Categorie IN ('A', 'B', NULL)
```

**Explication** : Même avec `NULL` dans la liste, `IN` ne retournera pas les lignes où `Categorie` est NULL.

**✅ Pour inclure les NULL** :
```sql
SELECT * FROM Produits
WHERE Categorie IN ('A', 'B') OR Categorie IS NULL
```

---

### NULL avec NOT IN : Le piège !

**Attention** : `NOT IN` avec NULL dans la liste peut donner des résultats surprenants.

```sql
SELECT * FROM Produits
WHERE Categorie NOT IN ('A', 'B', NULL)
```

**Résultat** : **Aucune ligne** (même celles qui ont des catégories 'C', 'D', etc.) !

**Pourquoi ?** Parce que SQL ne peut pas déterminer si une valeur est différente de NULL.

**✅ Solution** : Évitez NULL dans les listes `NOT IN`, ou gérez-le explicitement.

---

### NULL avec BETWEEN

```sql
SELECT * FROM Produits
WHERE Prix BETWEEN 10 AND 50
```

Les produits dont `Prix` est NULL ne sont **pas** retournés.

**Équivalent à** :
```sql
WHERE Prix >= 10 AND Prix <= 50
```

Et comme `NULL >= 10` retourne `UNKNOWN`, les NULL sont exclus.

---

### NULL avec LIKE

```sql
SELECT * FROM Clients
WHERE Nom LIKE 'M%'
```

Les clients dont `Nom` est NULL ne sont **pas** retournés.

**Pour inclure les NULL** :
```sql
SELECT * FROM Clients
WHERE Nom LIKE 'M%' OR Nom IS NULL
```

---

## 8. Fonctions pour gérer NULL

SQL Server fournit des fonctions pour travailler avec NULL :

### ISNULL() : Remplacer NULL par une valeur

**Syntaxe** :
```sql
ISNULL(colonne, valeur_si_null)
```

**Exemple 1** : Afficher "Non renseigné" pour les téléphones NULL

```sql
SELECT
    Prenom,
    Nom,
    ISNULL(Telephone, 'Non renseigné') AS Telephone
FROM Clients
```

**Résultat** :

| Prenom | Nom | Telephone |
|--------|-----|-----------|
| Sophie | Martin | Non renseigné |
| Marie | Leroy | 06 12 34 56 78 |

---

**Exemple 2** : Remise par défaut à 0

```sql
SELECT
    NomProduit,
    Prix,
    ISNULL(Remise, 0) AS Remise,
    Prix * (1 - ISNULL(Remise, 0)) AS PrixFinal
FROM Produits
```

**Explication** : Si `Remise` est NULL, elle est considérée comme 0 (pas de remise).

---

**Exemple 3** : Date de livraison par défaut

```sql
SELECT
    CommandeID,
    ISNULL(DateLivraison, 'En cours') AS StatutLivraison
FROM Commandes
```

---

### COALESCE() : Première valeur non NULL

**Syntaxe** :
```sql
COALESCE(valeur1, valeur2, valeur3, ...)
```

**Fonctionnement** : Retourne la **première** valeur non NULL de la liste.

**Exemple 1** : Utiliser l'email, sinon le téléphone, sinon "Aucun contact"

```sql
SELECT
    Prenom,
    Nom,
    COALESCE(Email, Telephone, 'Aucun contact') AS Contact
FROM Clients
```

**Résultat** :

| Prenom | Nom | Contact |
|--------|-----|---------|
| Sophie | Martin | sophie@mail.com |
| Pierre | Dubois | 06 12 34 56 78 |
| Marie | Leroy | Aucun contact |

**Explication** :
- Sophie : Email existe → Email retourné
- Pierre : Email NULL, mais Telephone existe → Telephone retourné
- Marie : Email et Telephone NULL → "Aucun contact" retourné

---

**Exemple 2** : Adresse de livraison par défaut

```sql
SELECT
    CommandeID,
    COALESCE(AdresseLivraison, AdresseFacturation, 'Adresse manquante') AS Adresse
FROM Commandes
```

---

### NULLIF() : Convertir une valeur en NULL

**Syntaxe** :
```sql
NULLIF(valeur1, valeur2)
```

**Fonctionnement** : Retourne NULL si `valeur1 = valeur2`, sinon retourne `valeur1`.

**Exemple** : Convertir les chaînes vides en NULL

```sql
SELECT
    NomProduit,
    NULLIF(Description, '') AS Description
FROM Produits
```

**Explication** : Si `Description` est une chaîne vide `''`, elle devient NULL.

---

**Exemple 2** : Éviter la division par zéro

```sql
SELECT
    Montant,
    Quantite,
    Montant / NULLIF(Quantite, 0) AS PrixUnitaire
FROM Ventes
```

**Explication** : Si `Quantite` est 0, `NULLIF` retourne NULL, évitant l'erreur de division par zéro.

---

## 9. Tri avec NULL : ORDER BY

### Comportement par défaut

Par défaut en SQL Server, les valeurs NULL sont considérées comme les **plus petites** valeurs lors du tri.

#### Tri ascendant (ASC)

```sql
SELECT Prenom, Nom, Telephone
FROM Clients
ORDER BY Telephone ASC
```

**Résultat** :

| Prenom | Nom | Telephone |
|--------|-----|-----------|
| Sophie | Martin | NULL | ← Les NULL en premier
| Pierre | Dubois | NULL |
| Marie | Leroy | 06 12 34 56 78 |
| Luc | Moreau | 06 23 45 67 89 |

---

#### Tri descendant (DESC)

```sql
SELECT Prenom, Nom, Telephone
FROM Clients
ORDER BY Telephone DESC
```

**Résultat** :

| Prenom | Nom | Telephone |
|--------|-----|-----------|
| Luc | Moreau | 06 23 45 67 89 |
| Marie | Leroy | 06 12 34 56 78 |
| Sophie | Martin | NULL | ← Les NULL en dernier
| Pierre | Dubois | NULL |

---

### Contrôler la position des NULL

Pour forcer les NULL à la fin même en tri ASC :

```sql
SELECT Prenom, Nom, Telephone
FROM Clients
ORDER BY
    CASE WHEN Telephone IS NULL THEN 1 ELSE 0 END,
    Telephone ASC
```

## 10. Agrégations avec NULL

### Comportement des fonctions d'agrégation

Les fonctions comme `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` **ignorent** les valeurs NULL (sauf `COUNT(*)`).

#### COUNT()

```sql
-- Compte toutes les lignes
SELECT COUNT(*) FROM Clients
-- Résultat : 200

-- Compte uniquement les lignes où Telephone n'est pas NULL
SELECT COUNT(Telephone) FROM Clients
-- Résultat : 150 (si 50 clients n'ont pas de téléphone)

-- Compte les lignes où Telephone est NULL
SELECT COUNT(*) FROM Clients WHERE Telephone IS NULL
-- Résultat : 50
```

---

#### AVG() : Moyenne

```sql
SELECT AVG(Bonus) FROM Employes
```

**Important** : `AVG` ignore les NULL. Si 5 employés sur 10 ont un bonus :
- La moyenne se calcule sur les 5 employés qui ont un bonus
- Les 5 autres (NULL) ne sont pas comptés comme 0 !

---

#### SUM() : Somme

```sql
SELECT SUM(Remise) FROM Produits
```

Les produits sans remise (NULL) ne contribuent pas à la somme.

**Attention** : Ce n'est pas la même chose que de compter NULL comme 0 !

---

## 11. Cas d'usage et bonnes pratiques

### Quand autoriser NULL ?

**✅ Autorisez NULL quand** :
- L'information est **optionnelle** (ex: numéro de téléphone)
- L'information est **non applicable** (ex: date de décès pour une personne vivante)
- L'information est **temporairement inconnue** (ex: date de livraison future)

**❌ Évitez NULL quand** :
- L'information est **obligatoire** (ex: nom d'un client)
- Cela complique inutilement la logique
- Une valeur par défaut a du sens (ex: 0 pour une quantité)

---

### Contrainte NOT NULL

Pour interdire NULL sur une colonne :

```sql
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom VARCHAR(100) NOT NULL,  -- Obligatoire
    Prenom VARCHAR(100) NOT NULL,  -- Obligatoire
    Email VARCHAR(200),  -- Optionnel (NULL autorisé)
    Telephone VARCHAR(20)  -- Optionnel (NULL autorisé)
)
```

---

### Valeur par défaut vs NULL

**Option 1** : Autoriser NULL
```sql
Remise DECIMAL(5,2) NULL
```

**Option 2** : Valeur par défaut
```sql
Remise DECIMAL(5,2) NOT NULL DEFAULT 0
```

**Quelle option choisir ?**
- NULL = "Pas de remise" vs "Remise inconnue"
- 0 = "Explicitement pas de remise"

**Recommandation** : Utilisez une valeur par défaut quand elle a du sens (0 pour une quantité, chaîne vide pour un commentaire optionnel).

## 12. Pièges courants avec NULL

### Piège 1 : Comparaison avec =

**❌ Erreur** :
```sql
WHERE Telephone = NULL
```

**✅ Correct** :
```sql
WHERE Telephone IS NULL
```

---

### Piège 2 : NOT IN avec NULL

**❌ Problématique** :
```sql
WHERE Categorie NOT IN ('A', 'B', NULL)
-- Peut retourner 0 ligne !
```

**✅ Sécurisé** :
```sql
WHERE Categorie NOT IN ('A', 'B')
  OR Categorie IS NULL
```

---

### Piège 3 : Calculs avec NULL

```sql
SELECT Prix * Quantite AS Total
FROM Commandes
```

Si `Prix` ou `Quantite` est NULL, `Total` sera NULL (pas 0) !

**✅ Solution** :
```sql
SELECT ISNULL(Prix, 0) * ISNULL(Quantite, 0) AS Total
FROM Commandes
```

---

### Piège 4 : Concaténation avec NULL

```sql
SELECT Prenom + ' ' + Nom AS NomComplet
FROM Clients
```

Si `Prenom` ou `Nom` est NULL, `NomComplet` sera NULL !

**✅ Solution** :
```sql
SELECT
    ISNULL(Prenom, '') + ' ' + ISNULL(Nom, '') AS NomComplet
FROM Clients
```

Ou utilisez `CONCAT` qui ignore les NULL :
```sql
SELECT CONCAT(Prenom, ' ', Nom) AS NomComplet
FROM Clients
```

---

### Piège 5 : Comptage incorrect

**Question** : Combien d'employés ont un bonus ?

**❌ Incorrect** :
```sql
SELECT COUNT(Bonus) FROM Employes WHERE Bonus != 0
```

**Problème** : Exclut les bonus à 0 ET les NULL.

**✅ Correct** :
```sql
SELECT COUNT(*) FROM Employes WHERE Bonus IS NOT NULL AND Bonus != 0
```

---

## 13. Stratégies pour gérer NULL

### Stratégie 1 : Filtrage explicite

Toujours être explicite sur le traitement des NULL :

```sql
-- Chercher les produits disponibles
SELECT * FROM Produits
WHERE Stock > 0
  AND Stock IS NOT NULL  -- Explicite !
```

---

### Stratégie 2 : Valeurs de remplacement

Remplacer NULL par une valeur par défaut pour les calculs :

```sql
SELECT
    NomProduit,
    Prix * (1 - ISNULL(Remise, 0)) AS PrixFinal
FROM Produits
```

---

### Stratégie 3 : Exclusion des NULL

Exclure les NULL quand ils ne sont pas pertinents :

```sql
SELECT AVG(Note) AS MoyenneNotes
FROM Evaluations
WHERE Note IS NOT NULL
```

---

### Stratégie 4 : Traitement séparé

Traiter NULL comme un cas particulier :

```sql
SELECT
    NomProduit,
    CASE
        WHEN DateExpiration IS NULL THEN 'Jamais'
        WHEN DateExpiration < GETDATE() THEN 'Expiré'
        ELSE 'Valide'
    END AS Statut
FROM Produits
```

## 14. Tableau récapitulatif

### Opérateurs pour NULL

| Opération | ❌ Incorrect | ✅ Correct |
|-----------|-------------|-----------|
| Tester NULL | `= NULL` | `IS NULL` |
| Tester non NULL | `!= NULL` | `IS NOT NULL` |
| Remplacer NULL | N/A | `ISNULL(col, val)` |
| Première non NULL | N/A | `COALESCE(v1, v2, v3)` |

---

### Comportement de NULL

| Contexte | Comportement |
|----------|--------------|
| Comparaisons (`=`, `!=`, `>`, `<`) | Retourne `UNKNOWN` |
| `AND` | TRUE AND NULL = UNKNOWN |
| `OR` | TRUE OR NULL = TRUE |
| `NOT` | NOT NULL = UNKNOWN |
| Agrégations | NULL ignorés (sauf COUNT(*)) |
| Calculs | Résultat = NULL si un opérande est NULL |
| Tri | NULL = plus petite valeur |
| `IN` | NULL dans liste ignoré |

---

## 15. Bonnes pratiques

### ✅ À faire

1. **Toujours utiliser IS NULL / IS NOT NULL** :
   ```sql
   WHERE Telephone IS NULL
   ```

2. **Être explicite sur le traitement des NULL** :
   ```sql
   WHERE (Stock > 0 AND Stock IS NOT NULL) OR StatutSpecial = 'Commande'
   ```

3. **Utiliser ISNULL/COALESCE pour les valeurs par défaut** :
   ```sql
   SELECT ISNULL(Remise, 0) AS Remise
   ```

4. **Documenter les colonnes NULL** :
   ```sql
   -- Telephone peut être NULL si non fourni
   Telephone VARCHAR(20) NULL
   ```

5. **Tester les deux cas** (avec et sans NULL) lors des tests :
   ```sql
   -- Test 1 : Avec valeur
   -- Test 2 : Avec NULL
   ```

---

### ❌ À éviter

1. **Ne jamais utiliser = ou != avec NULL** :
   ```sql
   WHERE Col = NULL  -- ❌ Ne fonctionne jamais
   ```

2. **Ne pas oublier NULL dans les exclusions** :
   ```sql
   WHERE Categorie != 'A'  -- ❌ N'exclut pas les NULL !
   ```

3. **Attention aux calculs** :
   ```sql
   Prix * Quantite  -- ❌ Peut donner NULL
   ```

4. **Éviter NULL dans NOT IN** :
   ```sql
   WHERE Col NOT IN ('A', NULL)  -- ❌ Problématique
   ```

5. **Ne pas confondre NULL avec 0 ou ''** :
   ```sql
   -- NULL ≠ 0 ≠ ''
   ```

---

## Résumé

### Points clés à retenir

1. **NULL** = Absence de valeur, valeur inconnue (pas 0, pas '')

2. **IS NULL** : Teste si une colonne est NULL
   ```sql
   WHERE Telephone IS NULL
   ```

3. **IS NOT NULL** : Teste si une colonne a une valeur
   ```sql
   WHERE Telephone IS NOT NULL
   ```

4. **Jamais = ou !=** : Ne fonctionnent pas avec NULL
   ```sql
   WHERE Col = NULL  -- ❌ FAUX
   WHERE Col IS NULL  -- ✅ CORRECT
   ```

5. **Fonctions utiles** :
   - `ISNULL(col, valeur)` : Remplace NULL
   - `COALESCE(v1, v2, v3)` : Première non NULL

6. **NULL dans les calculs** : Propage NULL
   - `5 + NULL = NULL`
   - `'Bonjour' + NULL = NULL`

7. **Agrégations** : Ignorent NULL (sauf COUNT(*))

### Aide-mémoire

| Besoin | Syntaxe |
|--------|---------|
| Tester NULL | `IS NULL` |
| Tester non NULL | `IS NOT NULL` |
| Remplacer NULL | `ISNULL(col, val)` |
| Première non NULL | `COALESCE(v1, v2)` |
| Exclure NULL | `WHERE col IS NOT NULL` |

---

La gestion de NULL est un sujet complexe, mais essentiel pour écrire des requêtes SQL robustes et correctes. Avec la pratique, le réflexe d'utiliser `IS NULL` deviendra naturel ! 🎯
