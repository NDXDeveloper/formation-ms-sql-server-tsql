# 1.2.3 Outils de Gestion : SSMS et VS Code (anciennement Azure Data Studio)

> ⚠️ **Mise à jour 2026** : **Azure Data Studio (ADS)**, décrit en détail dans cette section, a été **retiré par Microsoft le 28 février 2026**. Son successeur officiel est **Visual Studio Code avec l'extension MSSQL**, qui reprend ses capacités (ADS était lui-même bâti sur VS Code). Tout ce qui est dit ci-dessous au sujet d'ADS s'applique très largement à **VS Code + extension MSSQL**. Pour l'installation des outils, voir l'[annexe A](/09-annexes/A-guide-installation.md).

## Introduction

Pour travailler avec SQL Server, vous avez besoin d'**outils** qui vous permettent de vous connecter à l'instance, d'écrire des requêtes SQL, de gérer les bases de données, et bien plus encore. Microsoft propose principalement **SQL Server Management Studio (SSMS)** (Windows) et **Visual Studio Code avec l'extension MSSQL** (multiplateforme). Ce dernier **remplace Azure Data Studio**, l'outil moderne décrit plus bas, retiré en 2026.

### Analogie : La boîte à outils

Imaginez que SQL Server est une voiture :
- Le **moteur** de la voiture = SQL Server Database Engine
- Les **outils de garage** pour réparer et entretenir = SSMS et VS Code
- Vous êtes le **mécanicien** qui utilise ces outils

Vous ne pouvez pas ouvrir le capot d'une voiture avec vos mains nues ; vous avez besoin de clés, de tournevis, etc. De même, vous avez besoin d'outils pour interagir avec SQL Server !

## SQL Server Management Studio (SSMS)

### Qu'est-ce que SSMS ?

**SQL Server Management Studio** (SSMS) est l'outil **historique** et **complet** de Microsoft pour gérer SQL Server. C'est une application Windows qui existe depuis 2005 (anciennement appelée Enterprise Manager).

**En résumé :**
- 🎯 **Outil principal** pour SQL Server
- 💻 **Windows uniquement** (pas Mac, pas Linux)
- 📦 **Gratuit** et complet
- 🏢 **Professionnel** et mature
- 📊 **Interface graphique** riche

### Principales caractéristiques

#### Une interface graphique complète

SSMS offre une **interface graphique** (GUI - Graphical User Interface) qui permet de faire presque tout sans écrire de code :
- Créer des bases de données en cliquant
- Créer des tables visuellement
- Visualiser les données
- Gérer la sécurité
- Planifier des sauvegardes
- Et bien plus...

**Mais attention :** Même si SSMS permet de faire beaucoup de choses "en cliquant", il est **essentiel** d'apprendre le langage T-SQL, car :
- C'est plus rapide une fois maîtrisé
- C'est scriptable et automatisable
- C'est portable (fonctionne partout)
- C'est ce qui est vraiment exécuté en arrière-plan

#### Installation de SSMS

**Où le télécharger ?**
- Site officiel Microsoft : [https://aka.ms/ssmsfullsetup](https://aka.ms/ssmsfullsetup)
- **Gratuit** et sans restriction

**Versions :**
- SSMS est mis à jour fréquemment : **installez toujours la dernière version** depuis le lien officiel ci-dessus.
- Une même version de SSMS gère **toutes les versions** de SQL Server (rétrocompatibilité).

**Compatibilité :**
- Fonctionne avec **toutes les versions** de SQL Server (2012 à 2022)
- Compatible avec Azure SQL Database
- Windows 10, 11, Windows Server 2016+

**Taille du téléchargement :** Environ 600 Mo

**Système requis :**
- Windows uniquement
- .NET Framework 4.7.2 ou supérieur
- 2 Go de RAM minimum (4 Go recommandés)

#### Les principales zones de l'interface

##### 1. Object Explorer (Explorateur d'objets)

**Position :** Panneau de gauche

**Rôle :**
- Affiche une **arborescence** de tous les objets SQL Server
- Navigation dans les bases de données, tables, vues, etc.
- Point d'accès principal pour la gestion

**Arborescence typique :**
```
📁 Serveur (SERVEUR01)
  ├─ 📦 Databases (Bases de données)
  │   ├─ 📂 System Databases
  │   │   ├─ master
  │   │   ├─ model
  │   │   ├─ msdb
  │   │   └─ tempdb
  │   └─ 📂 User Databases
  │       ├─ GestionCommerciale
  │       │   ├─ 📊 Tables
  │       │   │   ├─ dbo.Clients
  │       │   │   ├─ dbo.Produits
  │       │   │   └─ dbo.Commandes
  │       │   ├─ 👁️ Views
  │       │   ├─ ⚙️ Stored Procedures
  │       │   ├─ 🔧 Functions
  │       │   └─ ...
  │       └─ SiteWeb_Ecommerce
  ├─ 🔒 Security (Sécurité)
  │   ├─ Logins
  │   └─ Server Roles
  ├─ 📊 Management
  │   ├─ Maintenance Plans
  │   └─ SQL Server Logs
  └─ 🤖 SQL Server Agent (Jobs)
      ├─ Jobs
      └─ Alerts
```

**Actions possibles par clic-droit :**
- Créer une nouvelle base de données
- Créer une nouvelle table
- Afficher les données d'une table
- Sauvegarder une base
- Restaurer une base
- Générer un script

##### 2. Query Editor (Éditeur de requête)

**Position :** Zone centrale principale

**Rôle :**
- Écrire et exécuter des **requêtes SQL/T-SQL**
- Éditeur de code avec coloration syntaxique
- IntelliSense (auto-complétion)

**Fonctionnalités clés :**
- **Coloration syntaxique** : Les mots-clés SQL sont colorés
- **IntelliSense** : Auto-complétion des noms de tables, colonnes
- **Exécution** : Bouton ▶️ ou touche F5
- **Numérotation des lignes**
- **Onglets multiples** : Plusieurs requêtes ouvertes simultanément

**Exemple d'utilisation :**
```sql
-- Ceci est un commentaire
SELECT
    ClientID,
    Nom,
    Prenom,
    Email
FROM
    Clients
WHERE
    Ville = 'Paris'
ORDER BY
    Nom;
```

Appuyez sur **F5** ou cliquez sur ▶️ **Execute** pour exécuter.

##### 3. Results Panel (Panneau des résultats)

**Position :** En bas de l'éditeur de requête

**Rôle :**
- Affiche les **résultats** des requêtes SELECT
- Messages d'erreur ou de succès
- Statistiques d'exécution

**Trois onglets possibles :**
- **Results** : Résultats sous forme de grille
- **Messages** : Messages système (nombre de lignes affectées, erreurs)
- **Execution Plan** : Plan d'exécution de la requête (pour l'optimisation)

**Modes d'affichage :**
- **Grille** (Grid) : Tableau formaté (par défaut)
- **Texte** (Text) : Format texte brut
- **Fichier** (File) : Exporter directement dans un fichier

##### 4. Barre d'outils

**Position :** En haut

**Boutons principaux :**
- 🔌 **New Query** : Nouvelle requête
- 📂 **Open** : Ouvrir un fichier .sql
- 💾 **Save** : Enregistrer la requête
- ▶️ **Execute** : Exécuter la requête (F5)
- ⏹️ **Cancel** : Annuler l'exécution
- 📊 **Include Execution Plan** : Afficher le plan d'exécution
- 🎨 **Change Connection** : Changer de serveur/base

### Fonctionnalités principales de SSMS

#### 1. Gestion des bases de données

**Créer une base de données :**
- Clic-droit sur "Databases" → New Database
- Remplir le nom
- Configurer les options (ou laisser par défaut)

**Sauvegarder une base :**
- Clic-droit sur la base → Tasks → Backup
- Choisir le type (Full, Differential, Log)
- Définir la destination

**Restaurer une base :**
- Clic-droit sur "Databases" → Restore Database
- Choisir la source (fichier .bak)
- Lancer la restauration

#### 2. Conception de tables (Table Designer)

**Mode graphique :**
- Clic-droit sur "Tables" → New Table
- Remplir les colonnes visuellement :
  - Nom de la colonne
  - Type de données
  - Allow Nulls (NULL/NOT NULL)
- Définir la clé primaire (clic-droit sur la colonne)

**Exemple visuel :**
```
┌────────────────┬──────────────┬────────────┐
│ Column Name    │ Data Type    │ Allow Nulls│
├────────────────┼──────────────┼────────────┤
│ ClientID       │ int          │ ☐          │ 🔑 (clé primaire)
│ Nom            │ nvarchar(50) │ ☐          │
│ Prenom         │ nvarchar(50) │ ☐          │
│ Email          │ nvarchar(100)│ ☑          │
│ DateInscription│ date         │ ☐          │
└────────────────┴──────────────┴────────────┘
```

**Attention :** Même si c'est pratique, il est **préférable** d'apprendre à créer des tables en T-SQL pour mieux comprendre et automatiser.

#### 3. Visualisation des données

**Afficher les données :**
- Clic-droit sur une table → "Select Top 1000 Rows"
- Génère automatiquement un SELECT
- Affiche les résultats

**Modifier les données directement :**
- Clic-droit sur une table → "Edit Top 200 Rows"
- Grille éditable (comme Excel)
- ⚠️ **Attention** : Modifications directes en production = dangereux !

#### 4. Génération de scripts

**Générer le script d'une base complète :**
- Clic-droit sur la base → Tasks → Generate Scripts
- Choisir les objets à scripter
- Obtenir un fichier .sql avec tout le code

**Utilité :**
- **Migration** : Recréer la base ailleurs
- **Sauvegarde** : Garder une version du schéma
- **Documentation** : Voir le code SQL généré
- **Apprentissage** : Comprendre comment SSMS crée les objets

#### 5. Gestion de la sécurité

**Créer un login :**
- Security → Logins → New Login
- Authentification Windows ou SQL Server
- Définir les droits

**Créer un utilisateur de base :**
- Base de données → Security → Users → New User
- Associer à un login
- Définir les rôles (db_owner, db_datareader, etc.)

#### 6. SQL Server Agent (Automatisation)

**Créer un Job (tâche planifiée) :**
- SQL Server Agent → Jobs → New Job
- Définir les étapes (scripts T-SQL)
- Définir le planning (tous les jours à 2h, par exemple)
- Configurer les alertes email

**Exemple d'utilisation :**
- Sauvegarde automatique chaque nuit
- Purge de vieilles données chaque dimanche
- Génération de rapports mensuels

⚠️ **Rappel** : SQL Server Agent n'est **pas disponible** dans SQL Server Express !

#### 7. Activity Monitor (Moniteur d'activité)

**Accès :**
- Clic-droit sur le serveur → Activity Monitor

**Informations affichées :**
- Processus en cours
- Requêtes actives
- Utilisation CPU et mémoire
- Opérations I/O (lecture/écriture disque)
- Blocages et attentes

**Utilité :**
- Diagnostiquer les problèmes de performance
- Identifier les requêtes lentes
- Détecter les blocages

#### 8. Import/Export de données

**Assistant Import/Export :**
- Clic-droit sur base → Tasks → Import Data ou Export Data
- Sources supportées :
  - Excel
  - CSV
  - Access
  - Autres bases SQL Server
  - Fichiers plats

**Wizard intuitif :**
1. Choisir la source
2. Choisir la destination
3. Mapper les colonnes
4. Exécuter

### Avantages de SSMS

- ✅ **Complet** : Toutes les fonctionnalités SQL Server
- ✅ **Mature** : Outil éprouvé depuis 2005
- ✅ **Gratuit** : Aucun coût
- ✅ **Puissant** : Gestion avancée (Agent, profiling, etc.)

- ❌ **Mono-plateforme** : Optimisé pour SQL Server uniquement
- ❌ **Personnalisation** : Moins flexible que des éditeurs modernes

## Visual Studio Code (extension MSSQL)

### Qu'est-ce que VS Code + l'extension MSSQL ?

**Visual Studio Code** (VS Code) est l'éditeur de code **moderne, gratuit et multiplateforme** de Microsoft. Couplé à l'**extension MSSQL** (officielle Microsoft), il devient un véritable outil de gestion SQL Server. C'est le **successeur d'Azure Data Studio** (retiré en février 2026), dont il reprend — et étend — les capacités.

> 🕰️ **Note historique** : l'outil multiplateforme s'appelait auparavant **Azure Data Studio** (créé en 2018, lui-même basé sur VS Code). Microsoft l'a retiré le 28 février 2026 et recommande désormais **VS Code + extension MSSQL**. Les descriptions ci-dessous valent pour ce duo.

**En résumé :**
- 🌍 **Multiplateforme** : Windows, Mac, Linux
- ⚡ **Léger et rapide**
- 🎨 **Interface moderne**
- 🔌 **Extensible** (des milliers d'extensions)
- ☁️ **Orienté cloud** (Azure SQL) et intégration **Git**
- 📊 **Notebooks** (comme Jupyter)

### Principales caractéristiques

#### Multi-plateforme

**Grande nouveauté :** Fonctionne sur tous les systèmes !
- ✅ **Windows** (7, 10, 11)
- ✅ **macOS** (10.13+)
- ✅ **Linux** (Ubuntu, Red Hat, Debian, etc.)

**Idéal pour :**
- Développeurs utilisant Mac ou Linux
- Environnements cloud/containers
- Équipes multi-plateformes

#### C'est Visual Studio Code

L'outil **est** VS Code, l'un des éditeurs les plus utilisés au monde :
- Moteur moderne (Electron)
- Immense écosystème d'extensions
- Mises à jour mensuelles

**Avantages :**
- Interface moderne et fluide
- Un **seul** outil pour le code applicatif **et** le SQL
- Familier pour des millions de développeurs

#### Installation

**Où le télécharger ?**
- VS Code : [https://code.visualstudio.com](https://code.visualstudio.com)
- Puis, dans VS Code, installez l'extension **« SQL Server (mssql) »** depuis l'onglet Extensions
- Ou via un gestionnaire de paquets (Chocolatey, Homebrew, apt)

**Taille :** Environ 100 Mo (beaucoup plus léger que SSMS !)

**Installation simple :**
- Windows : Télécharger et installer (.exe)
- Mac : Télécharger le .zip, extraire, glisser dans Applications
- Linux : Package .deb ou .rpm selon la distribution

## Quand utiliser quel outil ?

### Cas d'usage pour SSMS

**✅ Utilisez SSMS quand :**

1. **Administration complète**
   - Gestion de SQL Server Agent (jobs, alertes)
   - Création de plans de maintenance
   - Configuration avancée du serveur

2. **Windows uniquement**
   - Vous travaillez exclusivement sur Windows
   - Pas besoin de portabilité

3. **Gestion graphique**
   - Vous préférez les assistants graphiques
   - Création de tables via designer
   - Diagrammes de bases de données

4. **Environnement traditionnel**
   - Infrastructure existante SSMS
   - Équipe habituée à SSMS
   - Procédures établies

5. **Fonctionnalités avancées spécifiques**
   - Profiler (bientôt deprecated, mais encore là)
   - Tuning Advisor
   - Replication Management

**Exemple de profil utilisateur :**
> *Jean, DBA senior, gère 20 serveurs SQL Server on-premises sur Windows Server. Il planifie des jobs, maintient des plans de sauvegarde, et surveille les performances. SSMS est parfait pour lui.*

### Cas d'usage pour VS Code

**✅ Utilisez VS Code quand :**

1. **Multi-plateforme**
   - Vous utilisez Mac ou Linux
   - Équipe multi-OS
   - Environnements cloud/containers

2. **Développement moderne**
   - Écriture de requêtes principalement
   - Versioning Git des scripts
   - Workflow moderne (VS Code-like)

3. **Documentation et partage**
   - Créer des notebooks pour documenter
   - Tutoriels interactifs
   - Analyses partageables

4. **Azure SQL Database**
   - Travail principal sur Azure
   - Environnements cloud-first

5. **Multi-SGBD**
   - Travail avec PostgreSQL ou MySQL également
   - Environnement hétérogène

6. **Extensibilité**
   - Besoin de plugins personnalisés
   - Intégration avec d'autres outils

**Exemple de profil utilisateur :**
> *Marie, développeuse full-stack sur Mac, travaille avec Azure SQL Database et PostgreSQL. Elle crée des notebooks pour documenter ses analyses et utilise Git pour versionner ses scripts. VS Code est idéal pour elle.*

### Approche hybride (Recommandé !)

**La meilleure stratégie : Utiliser les deux !**

Beaucoup de professionnels utilisent **les deux outils** selon les besoins :

**Scénario typique :**
- **SSMS** pour :
  - Administration serveur
  - Configuration SQL Server Agent
  - Tâches ponctuelles nécessitant des assistants graphiques

- **VS Code** pour :
  - Développement quotidien de requêtes
  - Création de notebooks
  - Travail collaboratif avec Git

**Avantage :**
- ✅ Profiter du meilleur des deux mondes
- ✅ Flexibilité maximale
- ✅ S'adapter à chaque tâche

## Autres outils complémentaires

## Installation et premiers pas

### Installation de SSMS

**Étapes :**
1. Télécharger depuis [https://aka.ms/ssmsfullsetup](https://aka.ms/ssmsfullsetup)
2. Exécuter le fichier SSMS-Setup-ENU.exe
3. Accepter la licence
4. Choisir l'emplacement (ou laisser par défaut)
5. Cliquer sur "Install"
6. Attendre 10-15 minutes
7. Redémarrer si nécessaire

**Première connexion :**
1. Lancer SSMS
2. Fenêtre "Connect to Server"
3. Remplir :
   - Server name : `localhost` ou `(local)` ou `.\SQLEXPRESS`
   - Authentication : Windows Authentication (par défaut)
4. Cliquer "Connect"

### Installation de VS Code

**Étapes (Windows) :**
1. Télécharger depuis [https://code.visualstudio.com](https://code.visualstudio.com)
2. Exécuter le fichier .exe
3. Accepter la licence
4. Choisir les options
5. Installer (rapide, 2-3 minutes)

**Première connexion :**
1. Lancer VS Code
2. Cliquer "New Connection" ou Ctrl+Shift+C
3. Remplir :
   - Server : `localhost` ou `.\SQLEXPRESS`
   - Authentication type : Windows Authentication
4. Cliquer "Connect"
5. Sauvegarder la connexion

## Conseils pour les débutants

### Quel outil choisir pour apprendre ?

**Recommandation :**

1. **Commencez avec SSMS** si :
   - Vous êtes sur Windows
   - Vous voulez voir toutes les fonctionnalités
   - Vous suivez des tutoriels basés sur SSMS

2. **Commencez avec VS Code** si :
   - Vous êtes sur Mac/Linux
   - Vous préférez les interfaces modernes
   - Vous voulez découvrir les notebooks

3. **Idéalement : Essayez les deux !**
   - Installez les deux (c'est gratuit)
   - Comprenez leurs différences
   - Choisissez selon les tâches

### Progression d'apprentissage

**Phase 1 : Bases (SSMS ou VS Code)**
- Se connecter à une instance
- Explorer l'Object Explorer
- Écrire des requêtes SELECT simples
- Voir les résultats

**Phase 2 : Développement (SSMS ou VS Code)**
- Créer des tables (en T-SQL, pas graphiquement)

- Écrire des requêtes complexes
- Comprendre les erreurs

**Phase 3 : Gestion (SSMS principalement)**
- Créer des sauvegardes
- Gérer la sécurité
- Planifier des jobs (si pas Express)
- Optimiser les performances

- Procédures stockées
- Triggers

- Notebooks de documentation (VS Code)

## Résumé

### Points clés à retenir

| Aspect | SSMS | VS Code |
|--------|------|-------------------|
| **Âge** | Mature (2005) | VS Code 2015 + extension MSSQL |
| **Philosophie** | Tout-en-un | Léger et extensible |
| **Meilleur pour** | Administration complète | Développement moderne |
| **Plateforme** | Windows | Multi-plateforme |
| **Interface** | Traditionnelle | Moderne |
| **Innovation** | Table designer, Agent | Notebooks, Git, Extensions |

### Checklist de l'apprenant

- ✅ Installer au moins un des deux outils (ou les deux)
- ✅ Se connecter avec succès à une instance SQL Server
- ✅ Explorer l'Object Explorer / Connections
- ✅ Écrire et exécuter une requête SELECT simple
- ✅ Comprendre où voir les résultats
- ✅ Sauvegarder une requête dans un fichier .sql
- ✅ Connaître le raccourci pour exécuter (F5)

### Ce qu'il faut retenir

- **SSMS** = Outil **complet** et **Windows** pour **tout faire**
- **VS Code** = Outil **moderne**, **multi-plateforme**, **léger** et **extensible**
- Les deux sont **gratuits** et **complémentaires**
- Il n'y a **pas de mauvais choix** : choisissez selon vos besoins et préférences
- Vous pouvez (et devriez) **utiliser les deux** selon les tâches
- L'important est d'apprendre **T-SQL**, pas l'outil en lui-même

### Pour aller plus loin

Une fois à l'aise avec l'un des outils, concentrez-vous sur :
- **Le langage T-SQL** (le vrai pouvoir)
- **La conception de bases de données**
- **L'optimisation des requêtes**
- **Les bonnes pratiques**

Les outils ne sont que des moyens pour interagir avec SQL Server. La vraie compétence réside dans la maîtrise du langage SQL et la compréhension des concepts de bases de données !
