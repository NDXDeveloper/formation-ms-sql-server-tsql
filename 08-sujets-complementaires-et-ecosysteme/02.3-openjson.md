# 8.2.3 OPENJSON (Transformer JSON en table)

## Introduction

Dans les sections précédentes, nous avons appris à extraire des valeurs individuelles avec `JSON_VALUE()` et des fragments JSON avec `JSON_QUERY()`. Ces fonctions sont parfaites pour extraire quelques valeurs, mais que se passe-t-il quand vous avez un **tableau d'objets JSON** que vous souhaitez transformer en **lignes de table** ?

C'est là qu'intervient **`OPENJSON()`**, la fonction la plus puissante pour travailler avec JSON dans SQL Server. Elle permet de "déplier" (ou "exploser") un JSON en un ensemble de lignes relationnelles.

**OPENJSON()** est particulièrement utile pour :
- Transformer des tableaux JSON en tables
- Analyser des réponses d'API complexes
- Importer des données JSON en masse
- Créer des rapports à partir de données JSON hiérarchiques

## Le problème : Tableaux d'objets JSON

Imaginez que vous recevez ce JSON d'une API :

```json
{
    "commande": {
        "numero": 12345,
        "date": "2024-11-18",
        "articles": [
            {
                "code": "A001",
                "nom": "Clavier",
                "quantite": 2,
                "prix": 79.99
            },
            {
                "code": "A002",
                "nom": "Souris",
                "quantite": 3,
                "prix": 29.99
            },
            {
                "code": "A003",
                "nom": "Écran",
                "quantite": 1,
                "prix": 299.99
            }
        ]
    }
}
```

Avec `JSON_VALUE()`, vous pourriez extraire le premier article ainsi :

```sql
SELECT
    JSON_VALUE(@json, '$.commande.articles[0].nom'),
    JSON_VALUE(@json, '$.commande.articles[1].nom'),
    JSON_VALUE(@json, '$.commande.articles[2].nom')
```

Mais c'est **fastidieux, rigide et limité** ! Que faire si vous avez 100 articles ? Ou un nombre variable ?

**`OPENJSON()`** résout ce problème en transformant automatiquement le tableau en lignes de table.

## Concept de OPENJSON()

**OPENJSON()** est une **fonction table** (Table-Valued Function) qui :
1. Prend du JSON en entrée
2. Retourne un **ensemble de lignes** (rowset)
3. Chaque élément du tableau JSON devient une ligne
4. Peut extraire automatiquement les propriétés en colonnes

**Analogie** : Imaginez une boîte contenant plusieurs objets. `OPENJSON()` ouvre cette boîte et dispose tous les objets sur une table, un par un, pour que vous puissiez les examiner facilement.

## Syntaxe de base : Mode par défaut

La syntaxe la plus simple d'OPENJSON retourne 3 colonnes standard :

```sql
OPENJSON(json_expression)
```

### Les 3 colonnes par défaut

| Colonne | Type | Description |
|---------|------|-------------|
| `key` | NVARCHAR(4000) | La clé ou l'index de l'élément |
| `value` | NVARCHAR(MAX) | La valeur de l'élément (en tant que texte) |
| `type` | INT | Le type JSON de la valeur |

### Types JSON

La colonne `type` peut avoir ces valeurs :

| Valeur | Type JSON | Exemple |
|--------|-----------|---------|
| 0 | null | `null` |
| 1 | string (chaîne) | `"texte"` |
| 2 | number (nombre) | `42`, `3.14` |
| 3 | true | `true` |
| 4 | false | `false` |
| 5 | object (objet) | `{"prop": "val"}` |
| 6 | array (tableau) | `[1, 2, 3]` |

## Exemples de base avec OPENJSON

### Exemple 1 : Tableau simple de valeurs

```sql
DECLARE @json NVARCHAR(MAX) = '["Paris", "Lyon", "Marseille", "Toulouse"]';

SELECT * FROM OPENJSON(@json);
```

**Résultat** :
```
key | value      | type
----|------------|-----
0   | Paris      | 1
1   | Lyon       | 1
2   | Marseille  | 1
3   | Toulouse   | 1
```

**Observations** :
- `key` contient l'index (0, 1, 2, 3)
- `value` contient les valeurs
- `type` = 1 (string/chaîne)

### Exemple 2 : Tableau de nombres

```sql
DECLARE @json NVARCHAR(MAX) = '[100, 200, 300, 400]';

SELECT * FROM OPENJSON(@json);
```

**Résultat** :
```
key | value | type
----|-------|-----
0   | 100   | 2
1   | 200   | 2
2   | 300   | 2
3   | 400   | 2
```

**Note** : `type` = 2 (number/nombre)

### Exemple 3 : Objet simple (paires clé-valeur)

```sql
DECLARE @json NVARCHAR(MAX) = '{
    "nom": "Dupont",
    "prenom": "Jean",
    "age": 30,
    "actif": true
}';

SELECT * FROM OPENJSON(@json);
```

**Résultat** :
```
key    | value  | type
-------|--------|-----
nom    | Dupont | 1
prenom | Jean   | 1
age    | 30     | 2
actif  | true   | 3
```

**Observations** :
- `key` contient les noms de propriétés
- Chaque propriété devient une ligne

### Exemple 4 : Filtrer par type

Vous pouvez filtrer les résultats par type :

```sql
DECLARE @json NVARCHAR(MAX) = '{
    "nom": "Dupont",
    "age": 30,
    "actif": true,
    "salaire": 45000.50
}';

-- Extraire uniquement les nombres (type = 2)
SELECT [key], [value]
FROM OPENJSON(@json)
WHERE [type] = 2;
```

**Résultat** :
```
key     | value
--------|----------
age     | 30
salaire | 45000.50
```

## OPENJSON avec schéma explicite (WITH clause)

La vraie puissance d'OPENJSON vient de la clause **`WITH`** qui permet de définir un **schéma explicite** et de mapper directement les propriétés JSON vers des colonnes SQL typées.

### Syntaxe avec WITH

```sql
OPENJSON(json_expression)
WITH (
    colonne1 TYPE chemin_json,
    colonne2 TYPE chemin_json,
    ...
)
```

**Avantages** :
- Types SQL natifs (pas besoin de CAST)
- Nommage personnalisé des colonnes
- Extraction de propriétés imbriquées
- Plus lisible et maintenable

### Exemple 5 : Objet simple avec schéma

```sql
DECLARE @json NVARCHAR(MAX) = '{
    "nom": "Dupont",
    "prenom": "Jean",
    "age": 30,
    "salaire": 45000.50
}';

SELECT *
FROM OPENJSON(@json)
WITH (
    Nom NVARCHAR(100) '$.nom',
    Prenom NVARCHAR(100) '$.prenom',
    Age INT '$.age',
    Salaire DECIMAL(10,2) '$.salaire'
);
```

**Résultat** :
```
Nom    | Prenom | Age | Salaire
-------|--------|-----|----------
Dupont | Jean   | 30  | 45000.50
```

**Observations** :
- Les types sont automatiquement convertis
- Les colonnes ont des noms personnalisés
- Une seule ligne retournée (car c'est un objet, pas un tableau)

## OPENJSON avec tableaux d'objets

C'est ici que `OPENJSON()` brille vraiment : transformer un **tableau d'objets JSON** en **plusieurs lignes**.

### Exemple 6 : Tableau d'articles

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {
        "code": "A001",
        "nom": "Clavier mécanique",
        "quantite": 2,
        "prix": 79.99
    },
    {
        "code": "A002",
        "nom": "Souris gaming",
        "quantite": 3,
        "prix": 29.99
    },
    {
        "code": "A003",
        "nom": "Écran 27 pouces",
        "quantite": 1,
        "prix": 299.99
    }
]';

SELECT *
FROM OPENJSON(@json)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Quantite INT '$.quantite',
    Prix DECIMAL(10,2) '$.prix'
);
```

**Résultat** :
```
Code | Nom                | Quantite | Prix
-----|--------------------|---------|---------
A001 | Clavier mécanique  | 2       | 79.99
A002 | Souris gaming      | 3       | 29.99
A003 | Écran 27 pouces    | 1       | 299.99
```

**Magic!** ✨ Chaque objet du tableau est devenu une ligne !

### Exemple 7 : Calculs sur les données extraites

Une fois les données en format tabulaire, vous pouvez utiliser SQL classique :

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {"code": "A001", "nom": "Clavier", "quantite": 2, "prix": 79.99},
    {"code": "A002", "nom": "Souris", "quantite": 3, "prix": 29.99},
    {"code": "A003", "nom": "Écran", "quantite": 1, "prix": 299.99}
]';

SELECT
    Code,
    Nom,
    Quantite,
    Prix,
    Quantite * Prix AS Montant
FROM OPENJSON(@json)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Quantite INT '$.quantite',
    Prix DECIMAL(10,2) '$.prix'
);
```

**Résultat** :
```
Code | Nom      | Quantite | Prix   | Montant
-----|----------|----------|--------|--------
A001 | Clavier  | 2        | 79.99  | 159.98
A002 | Souris   | 3        | 29.99  | 89.97
A003 | Écran    | 1        | 299.99 | 299.99
```

### Exemple 8 : Agrégations

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {"code": "A001", "nom": "Clavier", "quantite": 2, "prix": 79.99},
    {"code": "A002", "nom": "Souris", "quantite": 3, "prix": 29.99},
    {"code": "A003", "nom": "Écran", "quantite": 1, "prix": 299.99}
]';

SELECT
    COUNT(*) AS NombreArticles,
    SUM(Quantite) AS QuantiteTotale,
    SUM(Quantite * Prix) AS MontantTotal
FROM OPENJSON(@json)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Quantite INT '$.quantite',
    Prix DECIMAL(10,2) '$.prix'
);
```

**Résultat** :
```
NombreArticles | QuantiteTotale | MontantTotal
---------------|----------------|-------------
3              | 6              | 549.94
```

## OPENJSON avec des données dans une table

Dans la réalité, votre JSON est souvent stocké dans une **colonne de table**. Voici comment utiliser OPENJSON avec `CROSS APPLY`.

### Préparation : Table avec JSON

```sql
-- Créer la table
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY IDENTITY(1,1),
    Client NVARCHAR(100),
    CommandeJSON NVARCHAR(MAX)
);

-- Insérer des commandes avec leurs articles
INSERT INTO Commandes (Client, CommandeJSON) VALUES
('Société ABC', '[
    {"code": "A001", "nom": "Clavier", "quantite": 2, "prix": 79.99},
    {"code": "A002", "nom": "Souris", "quantite": 3, "prix": 29.99}
]'),

('Entreprise XYZ', '[
    {"code": "B001", "nom": "Laptop", "quantite": 5, "prix": 899.99},
    {"code": "B002", "nom": "Sacoche", "quantite": 5, "prix": 39.99}
]'),

('Client Solo', '[
    {"code": "C001", "nom": "Tablette", "quantite": 1, "prix": 599.99}
]');
```

### Exemple 9 : OPENJSON avec CROSS APPLY

Pour "exploser" le JSON de chaque commande en lignes d'articles :

```sql
SELECT
    C.CommandeID,
    C.Client,
    A.Code,
    A.Nom,
    A.Quantite,
    A.Prix,
    A.Quantite * A.Prix AS Montant
FROM Commandes C
CROSS APPLY OPENJSON(C.CommandeJSON)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Quantite INT '$.quantite',
    Prix DECIMAL(10,2) '$.prix'
) AS A;
```

**Résultat** :
```
CommandeID | Client         | Code | Nom      | Quantite | Prix   | Montant
-----------|----------------|------|----------|----------|--------|--------
1          | Société ABC    | A001 | Clavier  | 2        | 79.99  | 159.98
1          | Société ABC    | A002 | Souris   | 3        | 29.99  | 89.97
2          | Entreprise XYZ | B001 | Laptop   | 5        | 899.99 | 4499.95
2          | Entreprise XYZ | B002 | Sacoche  | 5        | 39.99  | 199.95
3          | Client Solo    | C001 | Tablette | 1        | 599.99 | 599.99
```

**Observations importantes** :
- Chaque commande génère **plusieurs lignes** (une par article)
- Les informations de la commande (`CommandeID`, `Client`) sont **répétées** pour chaque article
- C'est exactement comme une **jointure** entre une table de commandes et une table d'articles !

### Pourquoi CROSS APPLY ?

**`CROSS APPLY`** est un opérateur qui :
1. Prend chaque ligne de la table principale (`Commandes`)
2. Applique la fonction table (`OPENJSON`) à cette ligne
3. Combine les résultats

**Analogie** : C'est comme une boucle `FOR EACH` qui, pour chaque commande, décompose ses articles et les affiche.

### Exemple 10 : Agrégation par commande

```sql
SELECT
    C.CommandeID,
    C.Client,
    COUNT(*) AS NombreArticles,
    SUM(A.Quantite) AS QuantiteTotale,
    SUM(A.Quantite * A.Prix) AS MontantTotal
FROM Commandes C
CROSS APPLY OPENJSON(C.CommandeJSON)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Quantite INT '$.quantite',
    Prix DECIMAL(10,2) '$.prix'
) AS A
GROUP BY C.CommandeID, C.Client;
```

**Résultat** :
```
CommandeID | Client         | NombreArticles | QuantiteTotale | MontantTotal
-----------|----------------|----------------|----------------|-------------
1          | Société ABC    | 2              | 5              | 249.95
2          | Entreprise XYZ | 2              | 10             | 4699.90
3          | Client Solo    | 1              | 1              | 599.99
```

## Chemins JSON imbriqués

### Exemple 11 : JSON avec structure imbriquée

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {
        "code": "A001",
        "nom": "Ordinateur",
        "specifications": {
            "processeur": "Intel i7",
            "ram": "16GB"
        },
        "prix": 1299.99
    },
    {
        "code": "A002",

        "specifications": {
            "processeur": "Snapdragon 888",
            "ram": "8GB"
        },
        "prix": 899.99
    }
]';

SELECT *
FROM OPENJSON(@json)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Processeur NVARCHAR(50) '$.specifications.processeur',
    RAM NVARCHAR(20) '$.specifications.ram',
```

**Observation** : Les chemins JSON peuvent naviguer dans des objets imbriqués avec la notation `.`

## Extraire à la fois des objets et des tableaux

### Exemple 12 : Colonnes de type AS JSON

Parfois, vous voulez extraire un objet ou un tableau entier en tant que JSON :

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {
        "code": "A001",
        "nom": "Ordinateur",
        "specifications": {
            "processeur": "Intel i7",
            "ram": "16GB"
        },
        "couleurs": ["Noir", "Argent"]
    }
]';

SELECT *
FROM OPENJSON(@json)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Specifications NVARCHAR(MAX) '$.specifications' AS JSON,
    Couleurs NVARCHAR(MAX) '$.couleurs' AS JSON
);
```

**Résultat** :
```
Code | Nom         | Specifications                            | Couleurs
-----|-------------|-------------------------------------------|------------------
A001 | Ordinateur  | {"processeur":"Intel i7","ram":"16GB"}    | ["Noir","Argent"]
```

**Note** : La clause **`AS JSON`** indique que vous voulez conserver la valeur en tant que JSON, pas la convertir en texte simple.

## OPENJSON imbriqué (tableaux dans des tableaux)

### Exemple 13 : Commande avec articles, chaque article ayant des options

```sql
DECLARE @json NVARCHAR(MAX) = '{
    "commandeID": 12345,
    "articles": [
        {
            "code": "A001",
            "nom": "Ordinateur",
            "options": [
                {"nom": "Garantie étendue", "prix": 99.99},
                {"nom": "Souris incluse", "prix": 0}
            ]
        },
        {
            "code": "A002",
            "nom": "Écran",
            "options": [
                {"nom": "Support mural", "prix": 49.99}
            ]
        }
    ]
}';

-- Extraire les articles
SELECT
    JSON_VALUE(@json, '$.commandeID') AS CommandeID,
    A.Code,
    A.Nom,
    O.OptionNom,
    O.OptionPrix
FROM OPENJSON(@json, '$.articles')
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Options NVARCHAR(MAX) '$.options' AS JSON
) AS A
-- Puis extraire les options de chaque article
CROSS APPLY OPENJSON(A.Options)
WITH (
    OptionNom NVARCHAR(100) '$.nom',
    OptionPrix DECIMAL(10,2) '$.prix'
) AS O;
```

**Résultat** :
```
CommandeID | Code | Nom        | OptionNom          | OptionPrix
-----------|------|------------|--------------------|------------
12345      | A001 | Ordinateur | Garantie étendue   | 99.99
12345      | A001 | Ordinateur | Souris incluse     | 0.00
12345      | A002 | Écran      | Support mural      | 49.99
```

**Explication** :
1. Premier `OPENJSON` : Extrait les articles
2. Deuxième `OPENJSON` avec `CROSS APPLY` : Extrait les options de chaque article
3. Résultat : Une ligne par option de chaque article

## Spécifier un chemin de départ

### Syntaxe avec chemin

```sql
OPENJSON(json_expression, 'chemin_json')
```

Le deuxième paramètre permet de spécifier un **point de départ** dans le JSON.

### Exemple 14 : JSON complexe avec chemin

```sql
DECLARE @json NVARCHAR(MAX) = '{
    "commande": {
        "numero": 12345,
        "client": "Société ABC",
        "articles": [
            {"code": "A001", "nom": "Clavier", "prix": 79.99},
            {"code": "A002", "nom": "Souris", "prix": 29.99}
        ]
    }
}';

-- Sans chemin : analyserait la racine
-- Avec chemin : commence directement aux articles
SELECT *
FROM OPENJSON(@json, '$.commande.articles')
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom',
    Prix DECIMAL(10,2) '$.prix'
);
```

**Résultat** :
```
Code | Nom     | Prix
-----|---------|------
A001 | Clavier | 79.99
A002 | Souris  | 29.99
```

**Avantage** : Vous pouvez directement cibler le tableau qui vous intéresse sans avoir à le spécifier dans chaque chemin de colonne.

## Cas d'usage pratiques

### Cas 1 : Importer des données depuis une API

```sql
-- JSON reçu d'une API de météo
DECLARE @apiResponse NVARCHAR(MAX) = '{
    "ville": "Paris",
    "previsions": [
        {"jour": "Lundi", "temp_min": 12, "temp_max": 18, "conditions": "Nuageux"},
        {"jour": "Mardi", "temp_min": 14, "temp_max": 20, "conditions": "Ensoleillé"},
        {"jour": "Mercredi", "temp_min": 13, "temp_max": 19, "conditions": "Pluvieux"}
    ]
}';

-- Insérer les prévisions dans une table
INSERT INTO Previsions (Ville, Jour, TempMin, TempMax, Conditions)
SELECT
    JSON_VALUE(@apiResponse, '$.ville'),
    P.Jour,
    P.TempMin,
    P.TempMax,
    P.Conditions
FROM OPENJSON(@apiResponse, '$.previsions')
WITH (
    Jour NVARCHAR(20) '$.jour',
    TempMin INT '$.temp_min',
    TempMax INT '$.temp_max',
    Conditions NVARCHAR(50) '$.conditions'
) AS P;
```

### Cas 2 : Analyser des logs JSON

```sql
CREATE TABLE Logs (
    LogID INT PRIMARY KEY IDENTITY,
    DateLog DATETIME DEFAULT GETDATE(),
    DonneesJSON NVARCHAR(MAX)
);

-- Supposons que les logs contiennent des tableaux d'erreurs
INSERT INTO Logs (DonneesJSON) VALUES
('{"erreurs": [
    {"code": 404, "message": "Page non trouvée", "url": "/api/produits"},
    {"code": 500, "message": "Erreur serveur", "url": "/api/commandes"}
]}');

-- Analyser tous les logs et extraire toutes les erreurs
SELECT
    L.LogID,
    L.DateLog,
    E.Code,
    E.Message,
    E.URL
FROM Logs L
CROSS APPLY OPENJSON(L.DonneesJSON, '$.erreurs')
WITH (
    Code INT '$.code',
    Message NVARCHAR(200) '$.message',
    URL NVARCHAR(500) '$.url'
) AS E;
```

### Cas 3 : Transformer JSON en table temporaire

```sql
-- Créer une table temporaire à partir de JSON
DECLARE @json NVARCHAR(MAX) = '[
    {"nom": "Alice", "score": 95},
    {"nom": "Bob", "score": 87},
    {"nom": "Charlie", "score": 92}
]';

SELECT *
INTO #ResultatsTemp
FROM OPENJSON(@json)
WITH (
    Nom NVARCHAR(100) '$.nom',
    Score INT '$.score'
);

-- Utiliser la table temporaire
SELECT * FROM #ResultatsTemp WHERE Score >= 90;

-- Résultat:
-- Nom     | Score
-- --------|------
-- Alice   | 95
-- Charlie | 92
```

### Cas 4 : Rapports avec données JSON

```sql
-- Table contenant des enquêtes de satisfaction
CREATE TABLE Enquetes (
    EnqueteID INT PRIMARY KEY,
    DateEnquete DATE,
    ReponsesJSON NVARCHAR(MAX)
);

INSERT INTO Enquetes VALUES
(1, '2024-11-01', '[
    {"question": "Qualité", "note": 4},
    {"question": "Service", "note": 5},
    {"question": "Prix", "note": 3}
]'),
(2, '2024-11-02', '[
    {"question": "Qualité", "note": 5},
    {"question": "Service", "note": 4},
    {"question": "Prix", "note": 4}
]');

-- Calculer la note moyenne par question
SELECT
    R.Question,
    AVG(CAST(R.Note AS FLOAT)) AS NoteMoyenne,
    COUNT(*) AS NombreReponses
FROM Enquetes E
CROSS APPLY OPENJSON(E.ReponsesJSON)
WITH (
    Question NVARCHAR(50) '$.question',
    Note INT '$.note'
) AS R
GROUP BY R.Question;
```

**Résultat** :
```
Question | NoteMoyenne | NombreReponses
---------|-------------|----------------
Prix     | 3.5         | 2
Qualité  | 4.5         | 2
Service  | 4.5         | 2
```

## Gestion des valeurs NULL et propriétés manquantes

### Exemple 15 : Propriétés optionnelles

```sql
DECLARE @json NVARCHAR(MAX) = '[
    {"nom": "Alice", "email": "alice@example.com", "telephone": "0123456789"},
    {"nom": "Bob", "email": "bob@example.com"},
    {"nom": "Charlie", "telephone": "0987654321"}
]';

SELECT *
FROM OPENJSON(@json)
WITH (
    Nom NVARCHAR(100) '$.nom',
    Email NVARCHAR(100) '$.email',
    Telephone NVARCHAR(20) '$.telephone'
);
```

**Résultat** :
```
Nom     | Email               | Telephone
--------|---------------------|------------
Alice   | alice@example.com   | 0123456789
Bob     | bob@example.com     | NULL
Charlie | NULL                | 0987654321
```

**Observation** : Les propriétés manquantes sont automatiquement converties en `NULL`.

## OPENJSON vs JSON_VALUE : Quand utiliser quoi ?

| Scénario | Utiliser | Exemple |
|----------|----------|---------|
| Extraire UNE valeur d'un objet | `JSON_VALUE()` | `$.prix` |
| Extraire PLUSIEURS valeurs d'un objet | `OPENJSON()` avec WITH | Toutes les propriétés |
| Transformer un TABLEAU en lignes | `OPENJSON()` | Array d'articles → plusieurs lignes |
| Extraire un élément spécifique d'un tableau | `JSON_VALUE()` | `$.articles[0].nom` |
| JSON dans une colonne de table | `OPENJSON()` avec CROSS APPLY | Exploser les tableaux |

**Règle générale** :
- **JSON_VALUE()** : Pour extractions ponctuelles et simples
- **OPENJSON()** : Pour transformations de tableaux et extractions massives

## Performance et bonnes pratiques

### 1. Utiliser des index pour filtrer

Quand vous filtrez sur des colonnes de la table avant d'appliquer OPENJSON :

```sql
-- ✅ Bon : Filtrage sur index avant OPENJSON
SELECT C.CommandeID, A.*
FROM Commandes C
CROSS APPLY OPENJSON(C.CommandeJSON)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom'
) AS A
WHERE C.CommandeID = 123;  -- Utilise l'index sur CommandeID

-- ❌ Moins bon : Filtrage après OPENJSON
SELECT C.CommandeID, A.*
FROM Commandes C
CROSS APPLY OPENJSON(C.CommandeJSON)
WITH (
    Code NVARCHAR(20) '$.code',
    Nom NVARCHAR(100) '$.nom'
) AS A
WHERE A.Code = 'A001';  -- Doit parcourir tout le JSON
```

### 2. Spécifier les types appropriés

Utilisez les types SQL les plus précis :

```sql
-- ✅ Bon : Types précis
WITH (
    Prix DECIMAL(10,2),  -- Pas NVARCHAR
    Quantite INT,        -- Pas NVARCHAR
    Actif BIT            -- Pas NVARCHAR
)

-- ❌ Moins bon : Tout en NVARCHAR (nécessite des conversions)
WITH (
    Prix NVARCHAR(50),
    Quantite NVARCHAR(50),
    Actif NVARCHAR(10)
)
```

### 3. Éviter OPENJSON pour de petites extractions

```sql
-- Si vous avez besoin d'UNE seule valeur :

-- ❌ Overkill
SELECT TOP 1 Nom
FROM OPENJSON(@json)
WITH (Nom NVARCHAR(100) '$.nom');

-- ✅ Plus simple
SELECT JSON_VALUE(@json, '$.nom');
```

### 4. Attention aux gros volumes

Pour de très gros JSON (> 100 Mo), considérez :
- Découper le JSON en plusieurs parties
- Utiliser un traitement par lots (batch)
- Stocker les données extraites dans des tables relationnelles

## Limitations

### 1. Profondeur de nidification

SQL Server a une limite de profondeur pour l'imbrication JSON (généralement 128 niveaux). Pour du JSON extrêmement imbriqué, vous devrez peut-être chaîner plusieurs `OPENJSON`.

### 2. Taille maximale

NVARCHAR(MAX) peut contenir jusqu'à 2 Go, mais parser de très gros JSON peut être lent.

### 3. Pas de modification directe

`OPENJSON()` est en **lecture seule**. Pour modifier du JSON, utilisez `JSON_MODIFY()` (vu dans une section ultérieure).

## Résumé des syntaxes

### Mode par défaut (3 colonnes)

```sql
SELECT * FROM OPENJSON(@json)
-- Retourne : key, value, type
```

### Avec schéma explicite (WITH)

```sql
SELECT * FROM OPENJSON(@json)
WITH (
    Colonne1 TYPE '$.chemin1',
    Colonne2 TYPE '$.chemin2'
)
```

### Avec chemin de départ

```sql
SELECT * FROM OPENJSON(@json, '$.chemin.vers.tableau')
WITH (...)
```

### Avec CROSS APPLY (depuis une table)

```sql
SELECT T.*, J.*
FROM MaTable T
CROSS APPLY OPENJSON(T.ColonneJSON)
WITH (...) AS J
```

### Avec AS JSON (conserver le JSON)

```sql
WITH (
    ColonneJSON NVARCHAR(MAX) '$.objet' AS JSON
)
```

## Exemple complet : Scénario réel

Voici un exemple complet qui combine plusieurs techniques :

```sql
-- Table de commandes avec JSON
CREATE TABLE CommandesAPI (
    ID INT PRIMARY KEY IDENTITY,
    DateReception DATETIME DEFAULT GETDATE(),
    CommandeJSON NVARCHAR(MAX)
);

-- Insérer une commande complexe
INSERT INTO CommandesAPI (CommandeJSON) VALUES
('{
    "numero": "CMD-2024-001",
    "date": "2024-11-18",
    "client": {
        "nom": "Société ABC",
        "email": "contact@abc.com"
    },
    "livraison": {
        "adresse": "10 rue de la Paix",
        "ville": "Paris",
        "codePostal": "75001"
    },
    "articles": [
        {
            "code": "PROD-001",
            "libelle": "Ordinateur portable Dell",
            "quantite": 2,
            "prixUnitaire": 899.99,
            "remise": 10
        },
        {
            "code": "PROD-002",
            "libelle": "Souris sans fil",
            "quantite": 5,
            "prixUnitaire": 29.99,
            "remise": 0
        }
    ],
    "paiement": {
        "methode": "Carte bancaire",
        "montant": 1949.93
    }
}');

-- Requête complète d'analyse
SELECT
    C.ID AS CommandeID,
    C.DateReception,

    -- Informations de commande (racine)
    JSON_VALUE(C.CommandeJSON, '$.numero') AS NumeroCommande,
    JSON_VALUE(C.CommandeJSON, '$.date') AS DateCommande,

    -- Informations client (objet imbriqué)
    JSON_VALUE(C.CommandeJSON, '$.client.nom') AS Client,
    JSON_VALUE(C.CommandeJSON, '$.client.email') AS EmailClient,

    -- Informations de livraison
    JSON_VALUE(C.CommandeJSON, '$.livraison.ville') AS VilleLivraison,

    -- Articles (tableau transformé en lignes)
    A.CodeProduit,
    A.Libelle,
    A.Quantite,
    A.PrixUnitaire,
    A.Remise,

    -- Calculs
    A.Quantite * A.PrixUnitaire AS MontantBrut,
    A.Quantite * A.PrixUnitaire * (1 - A.Remise / 100.0) AS MontantNet

FROM CommandesAPI C
CROSS APPLY OPENJSON(C.CommandeJSON, '$.articles')
WITH (
    CodeProduit NVARCHAR(50) '$.code',
    Libelle NVARCHAR(200) '$.libelle',
    Quantite INT '$.quantite',
    PrixUnitaire DECIMAL(10,2) '$.prixUnitaire',
    Remise DECIMAL(5,2) '$.remise'
) AS A;
```

## Conclusion

**`OPENJSON()`** est la fonction la plus puissante pour travailler avec JSON dans SQL Server. Elle vous permet de :

- ✅ Transformer des **tableaux JSON** en **lignes de table**
- ✅ Extraire facilement **plusieurs propriétés** d'objets JSON
- ✅ Utiliser des **types SQL natifs** sans conversion manuelle
- ✅ Appliquer toute la puissance de **SQL** (WHERE, JOIN, GROUP BY, etc.)
- ✅ Traiter des structures JSON **complexes et imbriquées**

**Points clés à retenir** :
1. Utilisez `WITH` pour définir un schéma explicite avec types SQL
2. Utilisez `CROSS APPLY` pour traiter le JSON de colonnes de table
3. Le deuxième paramètre d'OPENJSON spécifie un chemin de départ
4. `AS JSON` préserve les valeurs JSON (objets/tableaux)
5. Parfait pour transformer des données d'API en données relationnelles

**Quand utiliser OPENJSON ?**
- Tableaux d'objets à transformer en lignes
- Import de données JSON en masse
- Analyse de réponses d'API
- Transformation de logs JSON

Dans la prochaine section (8.2.4), nous verrons l'opération inverse : **`FOR JSON`**, qui permet de générer du JSON à partir de données relationnelles !
