# 4.4.1 UNION (Suppression des doublons)

## Introduction

L'opérateur **UNION** est l'un des opérateurs d'ensemble en SQL qui permet de **combiner les résultats de deux ou plusieurs requêtes SELECT** en un seul ensemble de résultats. Sa caractéristique principale est qu'il **élimine automatiquement les doublons** du résultat final.

### Analogie simple

Imaginez que vous avez deux listes de noms :
- **Liste A** : Alice, Bob, Charlie, Alice
- **Liste B** : Bob, David, Eve

Si vous fusionnez ces listes avec `UNION`, vous obtenez :
- **Résultat** : Alice, Bob, Charlie, David, Eve

Notez que :
- Alice (qui apparaît 2 fois dans Liste A) n'apparaît qu'**une seule fois** dans le résultat
- Bob (qui apparaît dans les deux listes) n'apparaît qu'**une seule fois** dans le résultat
- Les doublons sont **automatiquement supprimés**

## Qu'est-ce que UNION ?

### Définition

`UNION` est un opérateur qui :
1. Combine les lignes de deux requêtes SELECT ou plus
2. **Élimine automatiquement les doublons**
3. Retourne un ensemble de lignes **uniques**

### Syntaxe de base

```sql
SELECT colonnes
FROM table1
WHERE conditions1

UNION

SELECT colonnes
FROM table2
WHERE conditions2;
```

**Structure :**
- Chaque requête SELECT est séparée par le mot-clé `UNION`
- Les deux requêtes doivent avoir le **même nombre de colonnes**
- Les types de données des colonnes correspondantes doivent être **compatibles**

## Contexte : Tables d'exemple

Pour illustrer nos exemples, utilisons des tables simples :

**Table ClientsFrance**
| ClientID | NomClient | Ville |
|----------|-----------|-------|
| 1 | Dupont | Paris |
| 2 | Martin | Lyon |
| 3 | Bernard | Paris |

**Table ClientsBelgique**
| ClientID | NomClient | Ville |
|----------|-----------|----------|
| 4 | Dubois | Bruxelles |
| 5 | Lambert | Liège |
| 2 | Martin | Lyon |

**Table EmployesParis**
| EmployeID | Nom | Poste |
|-----------|-----|-------|
| 1 | Alice | Manager |
| 2 | Bob | Développeur |
| 3 | Charlie | Designer |

**Table EmployesLyon**
| EmployeID | Nom | Poste |
|-----------|-----|-------------|
| 4 | David | Manager |
| 5 | Eve | Développeur |
| 2 | Bob | Développeur |

## Exemple de base : UNION simple

### Exemple 1 : Combiner deux listes de clients

Obtenir une liste unique de tous les clients (France et Belgique).

```sql
SELECT NomClient, Ville
FROM ClientsFrance

UNION

SELECT NomClient, Ville
FROM ClientsBelgique;
```

**Résultat :**
| NomClient | Ville |
|-----------|----------|
| Bernard | Paris |
| Dubois | Bruxelles |
| Dupont | Paris |
| Lambert | Liège |
| Martin | Lyon |

**Observations importantes :**
1. **Martin (Lyon)** apparaît dans les deux tables, mais n'est listé qu'**une seule fois**
2. Le résultat contient **5 lignes** alors que les deux tables combinées en ont 6
3. Les résultats sont **triés** (comportement par défaut de UNION pour éliminer les doublons)

### Processus d'exécution de UNION

Voici ce qui se passe en interne :

**Étape 1 : Exécution des deux SELECT**
```
Résultat SELECT 1:        Résultat SELECT 2:
- Dupont, Paris           - Dubois, Bruxelles
- Martin, Lyon            - Lambert, Liège
- Bernard, Paris          - Martin, Lyon
```

**Étape 2 : Combinaison des résultats**
```
Combinaison temporaire (6 lignes):
- Dupont, Paris
- Martin, Lyon
- Bernard, Paris
- Dubois, Bruxelles
- Lambert, Liège
- Martin, Lyon  ← Doublon !
```

**Étape 3 : Élimination des doublons**
```
Résultat final (5 lignes):
- Bernard, Paris
- Dubois, Bruxelles
- Dupont, Paris
- Lambert, Liège
- Martin, Lyon  (une seule fois)
```

**Étape 4 : Tri (pour détecter les doublons)**
```
Les résultats sont triés pour faciliter
la détection et l'élimination des doublons
```

## Comment UNION détecte les doublons ?

### Critère de doublon

Deux lignes sont considérées comme des **doublons** si **toutes leurs colonnes** ont les mêmes valeurs.

**Exemple 1 : Doublons détectés**
```sql
SELECT 'Alice' AS Nom, 30 AS Age
UNION
SELECT 'Alice' AS Nom, 30 AS Age;
```
**Résultat :** Une seule ligne (doublon éliminé)
| Nom | Age |
|-----|-----|
| Alice | 30 |

**Exemple 2 : Pas de doublon (colonnes différentes)**
```sql
SELECT 'Alice' AS Nom, 30 AS Age
UNION
SELECT 'Alice' AS Nom, 31 AS Age;
```
**Résultat :** Deux lignes (pas de doublon car Age différent)
| Nom | Age |
|-----|-----|
| Alice | 30 |
| Alice | 31 |

### Comparaison avec NULL

**Important :** Dans UNION, deux valeurs `NULL` sont considérées comme **égales**.

```sql
SELECT 'Alice' AS Nom, NULL AS Age
UNION
SELECT 'Alice' AS Nom, NULL AS Age;
```
**Résultat :** Une seule ligne
| Nom | Age |
|-----|-----|
| Alice | NULL |

Ceci est différent du comportement normal de SQL où `NULL = NULL` retourne `FALSE`.

## Règles et contraintes de UNION

### Règle 1 : Même nombre de colonnes

Les deux requêtes SELECT doivent avoir le **même nombre de colonnes**.

```sql
-- ❌ ERREUR : Nombre de colonnes différent
SELECT NomClient, Ville
FROM ClientsFrance

UNION

SELECT NomClient, Ville, Pays  -- 3 colonnes !
FROM ClientsBelgique;
```

**Solution :** Ajouter une colonne constante ou NULL

```sql
-- ✅ CORRECT : Même nombre de colonnes
SELECT NomClient, Ville, 'France' AS Pays
FROM ClientsFrance

UNION

SELECT NomClient, Ville, 'Belgique' AS Pays
FROM ClientsBelgique;
```

### Règle 2 : Types de données compatibles

Les colonnes correspondantes doivent avoir des **types de données compatibles**.

```sql
-- ❌ ERREUR : Types incompatibles
SELECT NomClient, ClientID  -- ClientID est INT
FROM ClientsFrance

UNION

SELECT NomClient, Ville  -- Ville est VARCHAR
FROM ClientsBelgique;
```

**Types compatibles :**
- `INT` avec `BIGINT`, `DECIMAL`
- `VARCHAR` avec `NVARCHAR`, `CHAR`
- `DATE` avec `DATETIME`, `DATETIME2`

### Règle 3 : Les noms de colonnes viennent de la première requête

Le résultat final utilise les **noms de colonnes de la première requête** SELECT.

```sql
SELECT
    NomClient AS Client,  -- ← Ce nom sera utilisé
    Ville AS Location     -- ← Ce nom sera utilisé
FROM ClientsFrance

UNION

SELECT
    NomClient AS Nom,     -- ← Ignoré
    Ville AS City         -- ← Ignoré
FROM ClientsBelgique;
```

**Résultat :** Les colonnes s'appellent `Client` et `Location`

### Règle 4 : ORDER BY à la fin uniquement

La clause `ORDER BY` ne peut être utilisée qu'**à la fin**, après tous les UNION.

```sql
-- ❌ ERREUR : ORDER BY dans une requête intermédiaire
SELECT NomClient, Ville
FROM ClientsFrance
ORDER BY Ville  -- Erreur !

UNION

SELECT NomClient, Ville
FROM ClientsBelgique;
```

```sql
-- ✅ CORRECT : ORDER BY à la fin
SELECT NomClient, Ville
FROM ClientsFrance

UNION

SELECT NomClient, Ville
FROM ClientsBelgique

ORDER BY Ville;  -- ← Tri tout le résultat final
```

## Exemples pratiques

### Exemple 3 : Combiner des employés de plusieurs bureaux

Obtenir une liste unique de tous les employés (Paris et Lyon).

```sql
SELECT Nom, Poste
FROM EmployesParis

UNION

SELECT Nom, Poste
FROM EmployesLyon

ORDER BY Nom;
```

**Résultat :**
| Nom | Poste |
|---------|-------------|
| Alice | Manager |
| Bob | Développeur |
| Charlie | Designer |
| David | Manager |
| Eve | Développeur |

**Observation :** Bob apparaît dans les deux tables mais n'est listé qu'une fois.

### Exemple 4 : Ajouter une colonne d'identification

Identifier la source des données dans le résultat.

```sql
SELECT
    Nom,
    Poste,
    'Paris' AS Bureau
FROM EmployesParis

UNION

SELECT
    Nom,
    Poste,
    'Lyon' AS Bureau
FROM EmployesLyon

ORDER BY Nom, Bureau;
```

**Résultat :**
| Nom | Poste | Bureau |
|---------|-------------|--------|
| Alice | Manager | Paris |
| Bob | Développeur | Lyon |
| Bob | Développeur | Paris |
| Charlie | Designer | Paris |
| David | Manager | Lyon |
| Eve | Développeur | Lyon |

**Observation :** Bob apparaît maintenant **deux fois** car la colonne `Bureau` est différente (Paris vs Lyon), donc ce ne sont plus des doublons !

### Exemple 5 : Combiner plus de deux requêtes

UNION peut combiner plus de deux requêtes SELECT.

```sql
SELECT NomClient AS Personne, 'Client' AS Type
FROM ClientsFrance

UNION

SELECT Nom, 'Employé' AS Type
FROM EmployesParis

UNION

SELECT NomClient, 'Client' AS Type
FROM ClientsBelgique

ORDER BY Type, Personne;
```

**Résultat :**
| Personne | Type |
|----------|---------|
| Bernard | Client |
| Dubois | Client |
| Dupont | Client |
| Lambert | Client |
| Martin | Client |
| Alice | Employé |
| Bob | Employé |
| Charlie | Employé |

### Exemple 6 : Combiner des valeurs littérales avec des tables

```sql
-- Ajouter une ligne d'en-tête ou de total
SELECT 'TOTAL' AS Nom, SUM(Salaire) AS Montant
FROM Employes

UNION

SELECT NomEmploye, Salaire
FROM Employes

ORDER BY
    CASE WHEN Nom = 'TOTAL' THEN 0 ELSE 1 END,
    Nom;
```

### Exemple 7 : Utiliser UNION avec des sous-requêtes

```sql
-- Combiner les meilleurs vendeurs de deux régions
SELECT TOP 3 Vendeur, SUM(Montant) AS Total
FROM VentesNord
GROUP BY Vendeur
ORDER BY Total DESC

UNION

SELECT TOP 3 Vendeur, SUM(Montant) AS Total
FROM VentesSud
GROUP BY Vendeur
ORDER BY Total DESC;
```

**Note :** Ici, les `ORDER BY` dans les sous-requêtes fonctionnent avec `TOP`.

## Cas d'usage typiques de UNION

### 1. Consolidation de données de plusieurs sources

Combiner des données provenant de plusieurs bases, serveurs, ou tables similaires.

```sql
-- Consolidation de données de différents pays
SELECT ClientID, NomClient, 'France' AS Pays
FROM ClientsFrance

UNION

SELECT ClientID, NomClient, 'Belgique' AS Pays
FROM ClientsBelgique

UNION

SELECT ClientID, NomClient, 'Suisse' AS Pays
FROM ClientsSuisse;
```

### 2. Combiner des données historiques et actuelles

```sql
-- Combiner commandes archivées et actuelles
SELECT CommandeID, ClientID, DateCommande, Montant
FROM CommandesArchivees

UNION

SELECT CommandeID, ClientID, DateCommande, Montant
FROM CommandesActuelles;
```

### 3. Créer des listes de référence

```sql
-- Liste unique de toutes les villes où on a des clients ou employés
SELECT Ville FROM Clients
UNION
SELECT Ville FROM Employes
UNION
SELECT Ville FROM Fournisseurs
ORDER BY Ville;
```

### 4. Requêtes de reporting

```sql
-- Rapport combinant différentes catégories
SELECT 'Ventes Q1' AS Categorie, SUM(Montant) AS Total
FROM Ventes
WHERE DATEPART(QUARTER, DateVente) = 1

UNION

SELECT 'Ventes Q2', SUM(Montant)
FROM Ventes
WHERE DATEPART(QUARTER, DateVente) = 2

UNION

SELECT 'Total Année', SUM(Montant)
FROM Ventes;
```

## Impact sur les performances

### Coût de l'élimination des doublons

L'élimination des doublons a un **coût en performance** car SQL Server doit :
1. Trier les résultats
2. Comparer chaque ligne avec les autres
3. Éliminer les doublons

**Opérations effectuées par UNION :**
```
Requête 1 → Résultats → ┐
                        ├→ Combiner → Trier → Éliminer doublons → Résultat final
Requête 2 → Résultats → ┘
```

### Comparaison : UNION vs UNION ALL

| Opération | UNION | UNION ALL |
|-----------|-------|-----------|
| Combine les résultats | ✅ | ✅ |
| Élimine les doublons | ✅ | ❌ |
| Nécessite un tri | ✅ | ❌ |
| Performance | ⚠️ Plus lent | ✅ Plus rapide |

**Exemple de temps d'exécution (hypothétique) :**
- UNION : 100 ms (tri + élimination)
- UNION ALL : 20 ms (simple combinaison)

### Quand utiliser UNION ?

✅ **Utilisez UNION quand :**
- Vous avez besoin d'**éliminer les doublons**
- Les données peuvent contenir des **lignes identiques**
- La **précision** est plus importante que la performance
- Les volumes de données sont **raisonnables**

⚠️ **Envisagez UNION ALL si :**
- Vous savez que les données **n'ont pas de doublons**
- Les doublons ne posent **pas de problème**
- La **performance** est critique
- Vous travaillez avec de **gros volumes**

## Optimisation avec UNION

### Technique 1 : Filtrer avant UNION

Réduisez le nombre de lignes **avant** le UNION pour améliorer les performances.

```sql
-- ❌ Moins efficace : Filtre après UNION
SELECT NomClient, Ville
FROM ClientsFrance
UNION
SELECT NomClient, Ville
FROM ClientsBelgique
WHERE Ville = 'Paris';  -- Filtre seulement la 2ème requête

-- ✅ Plus efficace : Filtre dans chaque requête
SELECT NomClient, Ville
FROM ClientsFrance
WHERE Ville = 'Paris'
UNION
SELECT NomClient, Ville
FROM ClientsBelgique
WHERE Ville = 'Paris';
```

### Technique 2 : Utiliser des index

Assurez-vous que les colonnes utilisées dans UNION sont indexées.

```sql
-- Index recommandés pour cette requête
CREATE INDEX IDX_Clients_Ville ON ClientsFrance(Ville);
CREATE INDEX IDX_Clients_Ville ON ClientsBelgique(Ville);

SELECT NomClient, Ville
FROM ClientsFrance
WHERE Ville = 'Paris'
UNION
SELECT NomClient, Ville
FROM ClientsBelgique
WHERE Ville = 'Paris';
```

### Technique 3 : Éviter UNION si possible avec d'autres approches

Parfois, une approche alternative peut être plus performante.

**Au lieu de UNION :**
```sql
SELECT NomClient, Ville FROM ClientsFrance
UNION
SELECT NomClient, Ville FROM ClientsBelgique;
```

**Considérez une table unique avec un indicateur :**
```sql
-- Table unique : Clients (avec colonne Pays)
SELECT DISTINCT NomClient, Ville
FROM Clients
WHERE Pays IN ('France', 'Belgique');
```

## Différences subtiles et pièges

### Piège 1 : UNION trie les résultats

UNION effectue un **tri implicite** pour détecter les doublons.

```sql
-- Le résultat sera trié, même sans ORDER BY explicite
SELECT NomClient FROM ClientsFrance
UNION
SELECT NomClient FROM ClientsBelgique;
-- Les noms seront dans un ordre trié
```

Si vous voulez un ordre spécifique, utilisez explicitement `ORDER BY`.

### Piège 2 : Les NULL sont considérés égaux

```sql
SELECT 'Alice' AS Nom, NULL AS Telephone
UNION
SELECT 'Alice', NULL;
-- Résultat : Une seule ligne (les NULL sont considérés égaux)
```

### Piège 3 : Attention aux types de données implicites

SQL Server convertit automatiquement les types compatibles, mais peut perdre en précision.

```sql
SELECT 'Alice' AS Nom, 100 AS Valeur  -- INT
UNION
SELECT 'Bob', 100.5;  -- DECIMAL
-- La première valeur (100) sera convertie en DECIMAL
```

### Piège 4 : Les noms de colonnes peuvent induire en erreur

```sql
SELECT
    Prenom AS Nom,  -- ← Ce nom est utilisé
    Age
FROM Personnes

UNION

SELECT
    NomFamille AS Nom,  -- Même si appelé "Nom", c'est le nom de famille !
    Age
FROM Autres;
-- La colonne s'appellera "Nom" mais contiendra des prénoms ET des noms de famille
```

## Exemples avancés

### Exemple 8 : UNION avec agrégations

```sql
-- Combiner des statistiques de plusieurs sources
SELECT
    'Ventes en magasin' AS Source,
    COUNT(*) AS NombreVentes,
    SUM(Montant) AS TotalVentes
FROM VentesMagasin

UNION

SELECT
    'Ventes en ligne',
    COUNT(*),
    SUM(Montant)
FROM VentesEnLigne

UNION

SELECT
    'TOTAL GÉNÉRAL',
    (SELECT COUNT(*) FROM VentesMagasin) + (SELECT COUNT(*) FROM VentesEnLigne),
    (SELECT SUM(Montant) FROM VentesMagasin) + (SELECT SUM(Montant) FROM VentesEnLigne);
```

### Exemple 9 : UNION avec CASE

```sql
-- Catégoriser et combiner des données
SELECT
    NomEmploye,
    Salaire,
    CASE
        WHEN Salaire > 5000 THEN 'Élevé'
        WHEN Salaire > 3000 THEN 'Moyen'
        ELSE 'Base'
    END AS Categorie
FROM EmployesParis

UNION

SELECT
    NomEmploye,
    Salaire,
    CASE
        WHEN Salaire > 5000 THEN 'Élevé'
        WHEN Salaire > 3000 THEN 'Moyen'
        ELSE 'Base'
    END
FROM EmployesLyon

ORDER BY Categorie, Salaire DESC;
```

### Exemple 10 : UNION dans une sous-requête

```sql
-- Utiliser UNION dans un FROM
SELECT
    Categorie,
    AVG(Salaire) AS SalaireMoyen
FROM (
    SELECT NomEmploye, Salaire, 'Paris' AS Categorie
    FROM EmployesParis

    UNION

    SELECT NomEmploye, Salaire, 'Lyon'
    FROM EmployesLyon
) AS TousEmployes
GROUP BY Categorie;
```

```sql
-- ✅ Tracer l'origine des données
SELECT

SELECT
    ClientID,
    NomClient,
    'Belgique',
```

### 3. Commenter les UNION complexes

```sql
-- Rapport consolidé des ventes par canal
SELECT
```

## Résumé

L'opérateur **UNION** combine les résultats de plusieurs requêtes SELECT en **éliminant automatiquement les doublons**.

### Syntaxe clé

```sql
SELECT colonnes FROM table1
UNION
SELECT colonnes FROM table2;
```

### Caractéristiques essentielles

✅ **Fonctionnement :**
- Combine les résultats de plusieurs SELECT
- **Élimine automatiquement les doublons**
- Nécessite un tri pour détecter les doublons
- Même nombre de colonnes requises
- Types de données compatibles

⚠️ **Points d'attention :**
- **Coût en performance** (tri + élimination des doublons)
- Plus lent que UNION ALL
- Les NULL sont considérés égaux
- Tri implicite des résultats
- ORDER BY seulement à la fin

### Quand utiliser UNION ?

✅ **Utilisez UNION quand :**
- Vous devez éliminer les doublons
- La précision prime sur la performance
- Vous combinez des données de sources multiples
- Vous créez des listes uniques

❌ **Évitez UNION si :**
- Vous savez qu'il n'y a pas de doublons → Utilisez **UNION ALL**
- La performance est critique → Utilisez **UNION ALL**
- Vous travaillez avec de gros volumes → Utilisez **UNION ALL**

### Règles importantes

1. **Même structure** : Même nombre de colonnes, types compatibles
2. **Noms de la première requête** : Les noms viennent du premier SELECT
3. **ORDER BY à la fin** : Une seule clause ORDER BY après tous les UNION
4. **Suppression automatique** : Les doublons sont éliminés sans configuration

L'opérateur UNION est un outil puissant pour consolider des données de multiples sources tout en garantissant l'unicité des résultats. Dans la section suivante, nous verrons **UNION ALL** qui offre de meilleures performances en conservant tous les doublons !
