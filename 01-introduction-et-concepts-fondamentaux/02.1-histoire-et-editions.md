# 1.2.1 Histoire et Éditions de Microsoft SQL Server

## Introduction

Microsoft SQL Server est l'un des systèmes de gestion de bases de données relationnelles les plus populaires au monde. Avant de commencer à l'utiliser, il est intéressant de comprendre d'où il vient et quelles sont les différentes versions disponibles pour choisir celle qui correspond le mieux à vos besoins.

## L'histoire de SQL Server : Un voyage dans le temps

### Les débuts (1989)

L'histoire de SQL Server commence dans les années 1980, lorsque Microsoft s'associe avec deux autres entreprises :
- **Sybase** (éditeur de bases de données)
- **Ashton-Tate** (éditeur de logiciels)

En **1989**, ils lancent ensemble **SQL Server 1.0** pour le système d'exploitation OS/2 (un système concurrent de Windows à l'époque).

### L'indépendance de Microsoft (années 1990)

#### SQL Server 4.2 (1992)
- Première version pour **Windows NT**
- Microsoft commence à se démarquer de Sybase

#### SQL Server 6.0 (1995)
- Première version **entièrement développée par Microsoft**
- Rupture définitive avec Sybase
- Architecture repensée pour Windows

#### SQL Server 7.0 (1998)
- **Réécriture complète** du moteur
- Introduction d'une interface graphique moderne (SQL Server Enterprise Manager)
- Amélioration majeure des performances

### L'ère moderne (années 2000)

#### SQL Server 2000
- Introduction des fonctionnalités XML
- Support amélioré pour les grandes entreprises
- SQL Server devient un acteur majeur du marché

#### SQL Server 2005
- **Révolution majeure** avec l'intégration de .NET CLR
- Introduction des types de données XML natifs
- Apparition de SQL Server Management Studio (SSMS)
- Améliorations massives de la sécurité

#### SQL Server 2008 / 2008 R2
- Support des données géospatiales
- Compression de données
- Introduction de PowerPivot pour l'analyse

### La consolidation (années 2010)

#### SQL Server 2012
- Introduction de **AlwaysOn Availability Groups** (haute disponibilité)
- **ColumnStore Index** pour les performances analytiques
- Améliorations de la Business Intelligence

#### SQL Server 2014
- **In-Memory OLTP** (tables en mémoire pour des performances extrêmes)
- Nouvelles fonctionnalités de sécurité

#### SQL Server 2016
- Support natif du **JSON**
- **Query Store** pour le diagnostic de performance
- **Row-Level Security** (sécurité au niveau ligne)
- Chiffrement "Always Encrypted"

#### SQL Server 2017
- **SQL Server sur Linux** ! (grande nouveauté)
- Support des conteneurs Docker
- Amélioration des performances avec le traitement de requêtes adaptatif

#### SQL Server 2019
- Support des **Big Data Clusters**
- Amélioration du moteur intelligent de requêtes
- Support UTF-8
- Accélération matérielle pour les données chiffrées

### L'ère du Cloud (2020 et au-delà)

#### SQL Server 2022
- Intégration Azure encore plus poussée
- Amélioration des performances et de la sécurité
- Support de nouvelles fonctionnalités de gouvernance des données

#### Azure SQL
- Évolution continue vers le **cloud**
- Offres **PaaS** (Platform as a Service) entièrement gérées
- Innovation constante avec des mises à jour régulières

### Frise chronologique simplifiée

```
1989 ──→ 1995 ──→ 2000 ──→ 2005 ──→ 2012 ──→ 2017 ──→ 2022 ──→ Aujourd'hui
  │        │        │        │        │        │        │           │
  │        │        │        │        │        │        │           │
```

## Les différentes éditions de SQL Server

Microsoft propose plusieurs **éditions** de SQL Server, adaptées à différents besoins et budgets. Chaque édition offre des fonctionnalités spécifiques.

### Vue d'ensemble des éditions

| Édition | Public cible | Prix | Cas d'usage typique |
|---------|--------------|------|---------------------|
| **Express** | Développeurs, apprentissage, petites applications | **Gratuit** | Apprentissage, développement, petites apps |
| **Developer** | Développeurs | **Gratuit** | Développement et tests uniquement |
| **Web** | Hébergeurs web | Licence abordable | Sites web, applications en ligne |
| **Standard** | PME | Licence payante (modéré) | Entreprises moyennes |
| **Enterprise** | Grandes entreprises | Licence payante (élevé) | Grandes entreprises, critiques |
| **Azure SQL** | Tous | Paiement à l'usage | Cloud, évolutivité, peu de gestion |

### 1. SQL Server Express Edition 🆓

#### Caractéristiques
- **Totalement gratuit**
- Idéal pour **apprendre** et **développer**
- Parfait pour les **petites applications**

#### Limitations principales
- **Taille de base de données** : Maximum 10 Go par base
- **Mémoire** : Utilise au maximum 1 Go de RAM
- **CPU** : Limité à 1 socket ou 4 cœurs
- Pas de SQL Server Agent (planification de tâches automatiques)
- Pas de fonctionnalités avancées de haute disponibilité

#### Quand l'utiliser ?
✅ **Recommandé pour :**
- **Apprentissage** de SQL et T-SQL (c'est parfait pour cette formation !)
- Développement d'applications personnelles
- Petites applications de bureau
- Applications avec peu de données (< 10 Go)
- Sites web à faible trafic

❌ **Pas adapté pour :**
- Grandes entreprises
- Applications critiques nécessitant une haute disponibilité
- Bases de données volumineuses (> 10 Go)
- Besoins de performances élevées

#### Exemple d'usage
Une petite association qui gère une base de 200 membres avec leurs coordonnées et leurs cotisations. Données totales : 50 Mo.

### 2. SQL Server Developer Edition 🆓

#### Caractéristiques
- **Gratuit** également !
- Fonctionnalités **complètes** (identiques à Enterprise)
- Réservé au **développement et aux tests**

#### Limitations
- **Licence** : Interdit d'utiliser en production (uniquement dev/test)
- Sinon, aucune limitation technique !

#### Quand l'utiliser ?
✅ **Recommandé pour :**
- Développeurs qui veulent tester toutes les fonctionnalités
- Environnements de développement professionnels
- Tests de fonctionnalités avancées
- Formation avancée (fonctionnalités Enterprise)

❌ **Interdit pour :**
- Mise en production (c'est illégal selon la licence !)

#### Exemple d'usage
Une équipe de développement teste une application avec des fonctionnalités avancées (Always On, Columnstore Indexes) avant de déployer en production avec une édition payante.

### 3. SQL Server Web Edition 🌐

#### Caractéristiques
- **Licence à coût modéré**
- Conçue pour les **hébergeurs web**
- Bonnes performances pour les sites web

#### Limitations
- Certaines fonctionnalités avancées non disponibles
- Principalement vendue aux hébergeurs (pas directement aux entreprises)

#### Quand l'utiliser ?
✅ **Recommandé pour :**
- Hébergement de sites web
- Applications en ligne
- SaaS (Software as a Service)

#### Exemple d'usage
Un hébergeur web propose SQL Server Web à ses clients pour héberger leurs sites e-commerce.

### 4. SQL Server Standard Edition 💼

#### Caractéristiques
- **Licence payante** (prix modéré)
- Fonctionnalités **professionnelles** complètes
- Pas de limite de taille de base de données
- Bonnes performances

#### Limitations principales
- Mémoire : Utilise jusqu'à 128 Go de RAM (largement suffisant pour la plupart)
- Pas de fonctionnalités ultra-avancées (Columnstore Online, Always On avec replicas multiples)
- Compression de données basique uniquement

#### Quand l'utiliser ?
✅ **Recommandé pour :**
- **PME** (Petites et Moyennes Entreprises)
- Applications d'entreprise classiques
- ERP, CRM, systèmes de gestion
- Bases de données jusqu'à plusieurs centaines de Go
- Besoin de haute disponibilité basique

#### Prix approximatif
- Par cœur (core licensing) : environ 3 900 € par cœur (2 cœurs minimum)
- Serveur + CAL (Client Access License) : environ 920 € serveur + ~230 € par utilisateur

#### Exemple d'usage
Une entreprise de 150 employés utilise un ERP avec SQL Server Standard pour gérer les stocks, la comptabilité et les ressources humaines.

### 5. SQL Server Enterprise Edition 🏢

#### Caractéristiques
- **Licence haut de gamme** (prix élevé)
- **Toutes les fonctionnalités** disponibles
- Performances et scalabilité maximales
- Haute disponibilité avancée

#### Fonctionnalités exclusives
- **AlwaysOn Availability Groups** avancés (plusieurs replicas)
- **Columnstore Indexes** en ligne
- Compression de données avancée
- Partitionnement de tables (pour bases massives)
- In-Memory OLTP avancé
- Pas de limites de RAM ou CPU

#### Quand l'utiliser ?
✅ **Recommandé pour :**
- **Grandes entreprises**
- Applications **critiques** (banques, assurances)
- Bases de données **très volumineuses** (plusieurs To)
- Besoin de **haute disponibilité** maximale
- Performances extrêmes requises
- Analyses de Big Data

#### Prix approximatif
- Par cœur : environ 15 000 € par cœur (2 cœurs minimum)
- Soit un investissement de **30 000 € minimum** pour une licence de base !

#### Exemple d'usage
Une grande banque gère des millions de transactions par jour avec une base de données de 5 To, nécessitant une disponibilité de 99,99% (pas de temps d'arrêt).

### 6. Azure SQL (Cloud) ☁️

Azure SQL n'est pas vraiment une "édition" mais un ensemble de **services cloud** proposés par Microsoft Azure.

#### Les trois options Azure SQL

##### a) Azure SQL Database (Single Database)
- **Base de données unique** dans le cloud
- Complètement gérée par Microsoft
- Pas besoin de gérer le serveur
- Idéal pour les applications modernes

**Avantages :**
- Pas de gestion de l'infrastructure
- Mises à jour automatiques
- Sauvegardes automatiques
- Scalabilité instantanée (monter/descendre en puissance)

**Modèle de tarification :**
- **DTU** (Database Transaction Unit) : de 5 à 4000 DTU
- **vCore** : De 2 à 80 vCores
- Paiement **mensuel** selon les ressources utilisées

**Exemple de prix :**
- Basic : ~4€/mois (pour dev/test)
- Standard S0 : ~13€/mois
- Premium : à partir de ~400€/mois

##### b) Azure SQL Managed Instance
- **Instance SQL Server complète** dans le cloud
- Compatible à 100% avec SQL Server on-premises
- Idéal pour la **migration** d'applications existantes

**Avantages :**
- Migration facile depuis SQL Server classique
- Fonctionnalités SQL Server complètes
- Réseau virtuel privé possible

**Prix :**
- Plus cher que SQL Database
- À partir de ~300€/mois pour une petite instance

##### c) SQL Server on Azure VM (IaaS)
- SQL Server installé sur une **machine virtuelle Azure**
- Contrôle total (comme un serveur classique)
- Vous gérez tout vous-même

**Avantages :**
- Contrôle complet
- Compatibilité totale
- Flexibilité maximale

**Inconvénients :**
- Vous devez gérer les mises à jour
- Plus complexe à administrer

#### Quand choisir Azure SQL ?
✅ **Recommandé pour :**
- **Startups** (pas d'investissement matériel initial)
- Applications **SaaS**
- Besoin de **scalabilité** rapide
- Pas de compétences d'administration serveur
- Applications **cloud-native**
- Développement agile

❌ **Moins adapté pour :**
- Réglementations strictes (données qui ne peuvent pas quitter le pays)
- Besoin de contrôle total du matériel
- Coûts prévisibles à très long terme (peut devenir cher)

#### Exemple d'usage
Une startup développe une application SaaS. Elle commence avec Azure SQL Database Basic (4€/mois) pour 10 utilisateurs, puis scale automatiquement à Azure SQL Premium quand elle atteint 10 000 utilisateurs, sans changer de code !

## Comment choisir la bonne édition ?

### Arbre de décision simplifié

```
Vous apprenez SQL ou développez une petite app ?
│
├─→ OUI → SQL Server Express ✅
│
└─→ NON → Vous êtes en phase de développement/test ?
           │
           ├─→ OUI → SQL Server Developer ✅
           │
           └─→ NON → Vous préférez le cloud (pas de serveur à gérer) ?
                      │
                      ├─→ OUI → Azure SQL Database ☁️ ✅
                      │
                      └─→ NON → Vous avez un budget limité (PME) ?
                                 │
                                 ├─→ OUI → SQL Server Standard 💼 ✅
                                 │
                                 └─→ NON → SQL Server Enterprise 🏢 ✅
```

### Questions à se poser

1. **Budget disponible ?**
   - Gratuit → Express ou Developer
   - Modéré → Standard ou Azure
   - Important → Enterprise

2. **Taille des données ?**
   - < 10 Go → Express convient
   - 10 Go - 500 Go → Standard ou Azure
   - > 500 Go → Enterprise ou Azure

3. **Criticité de l'application ?**
   - Faible (app interne) → Express/Standard
   - Élevée (production) → Standard/Azure
   - Critique (banque) → Enterprise

4. **Compétences techniques ?**
   - Limitées → Azure (géré par Microsoft)
   - Bonnes → Standard/Enterprise
   - Experts → Enterprise on-premises

5. **Disponibilité requise ?**
   - Normale → Standard
   - Haute (99,9%) → Azure ou Enterprise
   - Très haute (99,99%) → Enterprise

## L'évolution vers le Cloud

### Tendance actuelle

Microsoft pousse fortement vers **Azure SQL** :
- Innovation plus rapide dans le cloud
- Nouvelles fonctionnalités d'abord sur Azure
- Modèle économique récurrent pour Microsoft

### Hybrid Cloud

Beaucoup d'entreprises adoptent un **modèle hybride** :
- Données sensibles → SQL Server on-premises (sur site)
- Applications modernes → Azure SQL
- Réplication entre les deux environnements

## Licence : Modèles de tarification

### Pour SQL Server on-premises (Standard/Enterprise)

#### 1. Licence par Cœur (Core-based)
- Vous achetez des licences **par cœur de processeur**
- Minimum : **4 cœurs** (ou 16 pour Enterprise si serveur physique)
- Nombre d'utilisateurs illimité
- **Recommandé** pour de nombreux utilisateurs

**Exemple :**
Serveur avec 8 cœurs → 8 licences nécessaires

#### 2. Licence Serveur + CAL
- **Serveur** : Licence pour le serveur
- **CAL** (Client Access License) : Licence par utilisateur ou par device
- **Recommandé** pour peu d'utilisateurs

**Exemple :**
1 serveur + 50 utilisateurs → 1 licence serveur + 50 CAL

### Pour Azure SQL

#### Modèle à l'usage
- Vous payez selon **l'utilisation**
- Facturation à l'**heure** ou au **mois**
- Possibilité de mettre en pause (arrêter de payer)

#### Options
- **DTU** : Unité de performance globale (simple mais moins flexible)
- **vCore** : CPU virtuels + RAM + stockage (plus flexible, plus cher)

## Résumé

### L'histoire
- SQL Server existe depuis **1989**
- Évolution constante avec des versions majeures tous les 2-3 ans
- Tendance actuelle : **Cloud** avec Azure SQL

### Les éditions
| Édition | Prix | Pour qui ? |
|---------|------|-----------|
| **Express** | Gratuit | Apprentissage, petites apps (< 10 Go) |
| **Developer** | Gratuit | Développement uniquement |
| **Standard** | ~4000€/cœur | PME, applications professionnelles |
| **Enterprise** | ~15000€/cœur | Grandes entreprises, apps critiques |
| **Azure SQL** | Variable | Cloud, scalabilité, gestion simplifiée |

### Pour cette formation
- Nous utiliserons **SQL Server Express** (gratuit et suffisant)
- Ou **SQL Server Developer** si vous voulez tester des fonctionnalités avancées
- Tous les concepts s'appliquent à **toutes les éditions** !

### Conseil pratique
**Pour débuter :** Installez SQL Server Express ou Developer. Vous apprendrez exactement les mêmes concepts que sur les versions payantes, et pourrez migrer facilement plus tard si nécessaire.
