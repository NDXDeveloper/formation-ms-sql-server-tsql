# 8.1.1 Le type de données XML

## Introduction au XML

Avant de parler du type de données XML dans SQL Server, commençons par comprendre ce qu'est le XML.

**XML** (eXtensible Markup Language) est un format de données structuré qui utilise des balises pour organiser l'information, un peu comme HTML mais avec des règles plus strictes. Il est très utilisé pour :
- Échanger des données entre systèmes différents
- Stocker des configurations
- Représenter des données hiérarchiques
- Intégrer des données provenant de services web

### Exemple simple de XML

```xml
<Client>
    <Nom>Dupont</Nom>
    <Prenom>Jean</Prenom>
    <Email>jean.dupont@example.com</Email>
    <Adresse>
        <Rue>15 rue de la Paix</Rue>
        <Ville>Paris</Ville>
        <CodePostal>75001</CodePostal>
    </Adresse>
</Client>
```

Dans cet exemple, on voit bien la structure hiérarchique : un client contient des informations, et l'adresse elle-même contient plusieurs éléments.

## Le type de données XML dans SQL Server

SQL Server propose un **type de données natif XML** qui permet de stocker directement des documents XML dans une colonne de table. C'est beaucoup plus puissant que de simplement stocker le XML comme une chaîne de caractères (VARCHAR ou NVARCHAR).

### Pourquoi utiliser le type XML ?

**Avantages par rapport à une simple chaîne de caractères :**

1. **Validation automatique** : SQL Server vérifie que le XML est bien formé
2. **Interrogation native** : Possibilité d'extraire des valeurs directement avec XQuery
3. **Indexation** : On peut créer des index spécifiques pour optimiser les recherches
4. **Gestion de l'espace** : Stockage optimisé en format binaire interne
5. **Typage fort** : Possibilité de valider contre un schéma XML (XSD)

### Déclaration d'une colonne XML

La syntaxe est très simple, comme pour n'importe quel autre type de données :

```sql
-- Créer une table avec une colonne XML
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom NVARCHAR(100),
    DonneesXML XML
);
```

### Insertion de données XML

Pour insérer des données XML, on utilise simplement une chaîne de caractères qui contient du XML valide :

```sql
INSERT INTO Clients (ClientID, Nom, DonneesXML)
VALUES (
    1,
    'Dupont',
    '<Client>
        <Email>jean.dupont@example.com</Email>
        <Telephone>0123456789</Telephone>
        <DateNaissance>1985-06-15</DateNaissance>
    </Client>'
);
```

**Important** : Si le XML n'est pas bien formé, SQL Server retournera une erreur. Par exemple, une balise non fermée provoquera une erreur.

```sql
-- Ceci provoquera une ERREUR car la balise Email n'est pas fermée
INSERT INTO Clients (ClientID, Nom, DonneesXML)
VALUES (
    2,
    'Martin',
    '<Client>
        <Email>martin@example.com
        <Telephone>0987654321</Telephone>
    </Client>'
);
```

### Sélection de données XML

Lorsqu'on sélectionne une colonne XML, SQL Server la retourne comme un objet XML :

```sql
SELECT ClientID, Nom, DonneesXML
FROM Clients;
```

Le résultat affichera le contenu XML complet de la colonne.

### XML typé vs XML non typé

Il existe deux façons d'utiliser le type XML :

#### 1. XML non typé (par défaut)

C'est ce que nous avons vu jusqu'à présent. SQL Server vérifie simplement que le XML est bien formé, mais n'impose aucune structure particulière.

```sql
CREATE TABLE Documents (
    DocID INT PRIMARY KEY,
    Contenu XML  -- XML non typé
);
```

**Avantages** :
- Flexibilité totale
- Pas besoin de définir de schéma
- Idéal pour des données variées

**Inconvénients** :
- Aucune validation de la structure
- Pas de contrôle sur les éléments présents

#### 2. XML typé (avec schéma)

On peut associer un schéma XML (XSD) à la colonne pour valider la structure des données.

```sql
-- D'abord, créer une collection de schémas XML
CREATE XML SCHEMA COLLECTION SchemaClient AS
'<xsd:schema xmlns:xsd="http://www.w3.org/2001/XMLSchema">
    <xsd:element name="Client">
        <xsd:complexType>
            <xsd:sequence>
                <xsd:element name="Email" type="xsd:string"/>
                <xsd:element name="Telephone" type="xsd:string"/>
            </xsd:sequence>
        </xsd:complexType>
    </xsd:element>
</xsd:schema>';

-- Ensuite, utiliser ce schéma pour typer la colonne
CREATE TABLE ClientsTypés (
    ClientID INT PRIMARY KEY,
    DonneesXML XML(SchemaClient)  -- XML typé avec schéma
);
```

Avec un XML typé, toute insertion qui ne respecte pas le schéma sera rejetée.

**Avantages** :
- Validation stricte de la structure
- Garantie de la cohérence des données
- Meilleure performance pour les requêtes (SQL Server connaît la structure)

**Inconvénients** :
- Moins flexible
- Nécessite de définir et maintenir des schémas
- Plus complexe à mettre en place

### Considérations de stockage

Le type XML stocke les données en format binaire interne, ce qui présente plusieurs caractéristiques :

- **Taille maximale** : Jusqu'à 2 Go de données par valeur
- **Optimisation** : Le format binaire est généralement plus compact que le texte brut
- **Performance** : L'accès et l'interrogation sont optimisés

### Quand utiliser le type XML ?

**Utilisez le type XML quand** :
- Vous devez stocker des données hiérarchiques complexes
- La structure des données peut varier d'un enregistrement à l'autre
- Vous devez interroger des éléments spécifiques dans le XML
- Vous recevez des données XML de sources externes (API, fichiers)

**Évitez le type XML quand** :
- Les données ont une structure fixe et simple (utilisez plutôt des colonnes normales)
- Vous n'avez pas besoin d'interroger le contenu du XML
- La performance des requêtes est critique (les colonnes normales sont plus rapides)
- Vous travaillez avec de très gros volumes (le XML peut être gourmand en ressources)

## Exemple complet

Voici un exemple complet illustrant l'utilisation du type XML :

```sql
-- 1. Créer la table
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY IDENTITY(1,1),
    DateCommande DATETIME DEFAULT GETDATE(),
    Client NVARCHAR(100),
    DetailsXML XML
);

-- 2. Insérer des données
INSERT INTO Commandes (Client, DetailsXML)
VALUES (
    'Société ABC',
    '<Commande>
        <Articles>
            <Article>
                <Code>A001</Code>
                <Nom>Ordinateur portable</Nom>
                <Quantite>2</Quantite>
                <PrixUnitaire>899.99</PrixUnitaire>
            </Article>
            <Article>
                <Code>A002</Code>
                <Nom>Souris sans fil</Nom>
                <Quantite>5</Quantite>
                <PrixUnitaire>29.99</PrixUnitaire>
            </Article>
        </Articles>
        <Livraison>
            <Adresse>10 Avenue des Champs</Adresse>
            <Ville>Lyon</Ville>
            <CodePostal>69001</CodePostal>
        </Livraison>
    </Commande>'
);

-- 3. Consulter les données
SELECT CommandeID, Client, DetailsXML
FROM Commandes;
```

## Résumé des points clés

| Aspect | Description |
|--------|-------------|
| **Type** | `XML` - Type de données natif de SQL Server |
| **Taille max** | 2 Go par valeur |
| **Validation** | Vérifie automatiquement que le XML est bien formé |
| **Variantes** | XML non typé (flexible) ou XML typé (avec schéma XSD) |
| **Stockage** | Format binaire optimisé |
| **Usage principal** | Données hiérarchiques, échanges de données, structures variables |

## Conclusion

Le type de données XML dans SQL Server est un outil puissant pour gérer des données semi-structurées. Il offre un bon équilibre entre flexibilité et performance, tout en assurant la validité des données stockées.
