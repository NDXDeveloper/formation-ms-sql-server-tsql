# 4.1.6 CROSS JOIN

## Introduction

Après avoir exploré les jointures avec conditions (INNER, LEFT, RIGHT, FULL OUTER), il est temps de découvrir un type de jointure très particulier : le **CROSS JOIN**.

Le CROSS JOIN est unique parmi les jointures car il **n'a pas de condition de correspondance**. Il génère simplement **toutes les combinaisons possibles** entre les lignes de deux tables.

Vous vous souvenez du produit cartésien dont nous avons parlé au début ? Le CROSS JOIN est **exactement cela** : le produit cartésien pur et simple !

**Attention** : Le CROSS JOIN peut rapidement générer un nombre astronomique de lignes. Il doit être utilisé avec précaution et en connaissance de cause.

---

## Qu'est-ce qu'un CROSS JOIN ?

### Définition

Un **CROSS JOIN** (jointure croisée ou produit cartésien) combine **chaque ligne de la première table avec chaque ligne de la seconde table**, sans aucune condition de filtrage.

Si la table A contient **n lignes** et la table B contient **m lignes**, le résultat du CROSS JOIN contiendra **n × m lignes**.

### Analogie visuelle : Le diagramme de Venn

Contrairement aux autres jointures, le diagramme de Venn n'est pas vraiment approprié pour le CROSS JOIN car il ne s'agit pas d'une intersection ou d'une union, mais d'une **multiplication** :

```
Table A (3 lignes)    ×    Table B (2 lignes)    =    Résultat (6 lignes)
------------------         -------------------         ------------------
Ligne A1                   Ligne B1                    A1 + B1
Ligne A2                   Ligne B2                    A1 + B2
Ligne A3                                               A2 + B1
                                                        A2 + B2
                                                        A3 + B1
                                                        A3 + B2
```

Chaque ligne de A est combinée avec **chaque** ligne de B.

### Rappel : Le produit cartésien

Si vous avez lu la section 4.1.1, vous reconnaissez le produit cartésien ! Le CROSS JOIN est la mise en œuvre **intentionnelle** de ce concept.

**Exemple concret** : Vous avez 3 t-shirts et 2 pantalons. Combien de tenues différentes pouvez-vous créer ? 3 × 2 = **6 tenues** (toutes les combinaisons possibles).

---

## Syntaxe du CROSS JOIN

### Syntaxe explicite (recommandée)

```sql
SELECT colonnes
FROM Table1
CROSS JOIN Table2;
```

**Caractéristique importante** : Notez l'**absence de clause ON**. Le CROSS JOIN n'a pas besoin de condition de jointure car il combine tout avec tout.

### Syntaxe implicite (ancienne)

```sql
SELECT colonnes
FROM Table1, Table2;
```

Cette syntaxe avec une simple virgule produit également un produit cartésien, mais elle est **déconseillée** car :
- Elle peut être confondue avec un oubli de condition de jointure
- Elle est moins explicite sur l'intention
- Elle peut mener à des produits cartésiens accidentels

**Bonne pratique** : Utilisez toujours `CROSS JOIN` explicitement pour montrer clairement votre intention.

---

## Exemple simple et détaillé

### Contexte : Tables de départ

Créons deux petites tables pour bien comprendre le mécanisme :

**Table `Tailles`**

| TailleID | NomTaille |
|----------|-----------|
| 1        | S         |
| 2        | M         |
| 3        | L         |

**Table `Couleurs`**

| CouleurID | NomCouleur |
|-----------|------------|
| 1         | Rouge      |
| 2         | Bleu       |

### Requête CROSS JOIN

```sql
SELECT
    T.NomTaille,
    C.NomCouleur
FROM Tailles T
CROSS JOIN Couleurs C;
```

### Résultat (6 lignes)

| NomTaille | NomCouleur |
|-----------|------------|
| S         | Rouge      |
| S         | Bleu       |
| M         | Rouge      |
| M         | Bleu       |
| L         | Rouge      |
| L         | Bleu       |

### Analyse du résultat

Le résultat contient **3 × 2 = 6 lignes** :
- Chaque taille (S, M, L) est associée à chaque couleur (Rouge, Bleu)
- Nous obtenons toutes les combinaisons possibles
- Aucune ligne n'est filtrée ou exclue

**Application pratique** : Si vous gérez un catalogue de vêtements, ce CROSS JOIN génère toutes les variantes de produits (S Rouge, S Bleu, M Rouge, etc.).

---

## Calcul du nombre de lignes

### Formule mathématique

```
Nombre de lignes du résultat = (Lignes de Table1) × (Lignes de Table2)
```

### Exemples de calcul

| Table A | Table B | Résultat CROSS JOIN |
|---------|---------|---------------------|
| 10 lignes | 5 lignes | **50 lignes** |
| 100 lignes | 10 lignes | **1 000 lignes** |
| 1 000 lignes | 100 lignes | **100 000 lignes** |
| 10 000 lignes | 10 000 lignes | **100 000 000 lignes** ! |

### Le danger de l'explosion combinatoire

Comme vous pouvez le constater, le nombre de lignes **croît très rapidement** (de façon multiplicative).

**Exemple dramatique** :
- Deux tables de 1 000 lignes chacune
- CROSS JOIN entre elles → **1 million de lignes** !
- Si chaque ligne fait 100 octets → 100 Mo de données
- Temps de traitement potentiellement très long

**Règle d'or** : Avant d'utiliser un CROSS JOIN, calculez toujours le nombre de lignes résultant pour éviter les mauvaises surprises !

---

## Différence avec les autres types de JOIN

### Comparaison visuelle

```sql
-- INNER JOIN : Seulement les correspondances (avec condition ON)
SELECT * FROM TableA A
INNER JOIN TableB B ON A.ID = B.ID;
→ Résultat : Quelques lignes (selon les correspondances)

-- LEFT JOIN : Toute la table A + correspondances (avec condition ON)
SELECT * FROM TableA A
LEFT JOIN TableB B ON A.ID = B.ID;
→ Résultat : Au moins autant de lignes que dans TableA

-- CROSS JOIN : TOUTES les combinaisons (SANS condition ON)
SELECT * FROM TableA A
CROSS JOIN TableB B;
→ Résultat : Lignes de A × Lignes de B
```

### Le CROSS JOIN n'utilise JAMAIS de clause ON

```sql
-- ❌ ERREUR DE SYNTAXE : ON n'est pas permis avec CROSS JOIN
SELECT * FROM TableA
CROSS JOIN TableB ON TableA.ID = TableB.ID;
```

Si vous avez besoin d'une condition, utilisez INNER JOIN, pas CROSS JOIN.

### Tableau récapitulatif

| Caractéristique | INNER/LEFT/RIGHT/FULL | CROSS JOIN |
|-----------------|------------------------|------------|
| Clause ON | ✅ Obligatoire | ❌ Interdite |
| Condition de jointure | ✅ Oui | ❌ Non |
| Filtrage | ✅ Oui (selon condition) | ❌ Non (tout combiné) |
| Nombre de lignes | Variable (selon correspondances) | Fixe (n × m) |
| Produit cartésien | ❌ Non (filtré) | ✅ Oui (complet) |

## Cas d'usage pratiques du CROSS JOIN

Contrairement aux autres jointures très couramment utilisées, le CROSS JOIN a des cas d'usage **plus spécifiques et limités**. Voyons les principaux :

### 1. Génération de combinaisons de produits

**Scénario** : Vous gérez une boutique de vêtements et voulez générer toutes les variantes possibles.

```sql
-- Générer toutes les combinaisons taille × couleur × matière
SELECT
    T.NomTaille,
    C.NomCouleur,
    M.NomMatiere,
    -- Prix de base + ajustements selon attributs
    (100 + T.SupplementTaille + C.SupplementCouleur + M.SupplementMatiere) AS PrixFinal
FROM Tailles T
CROSS JOIN Couleurs C
CROSS JOIN Matieres M;
```

**Résultat** : Si vous avez 5 tailles, 8 couleurs et 3 matières → 5 × 8 × 3 = **120 variantes de produits**.

### 2. Génération de calendriers ou grilles horaires

**Scénario** : Créer toutes les créneaux horaires possibles pour un système de réservation.

```sql
-- Tous les jours × tous les créneaux horaires
SELECT
    J.Jour,
    H.HeureDebut,
    H.HeureFin,
    CONCAT(J.Jour, ' ', H.HeureDebut, '-', H.HeureFin) AS Creneau
FROM Jours J
CROSS JOIN Horaires H
ORDER BY J.JourID, H.HeureDebut;
```

Si vous avez 7 jours et 12 créneaux horaires → **84 créneaux** disponibles.

### 3. Génération de données de test

**Scénario** : Créer rapidement un grand volume de données pour tester les performances.

```sql
-- Générer 10 000 enregistrements de test
SELECT
    N1.Numero * 100 + N2.Numero AS ID,
    'Utilisateur_' + CAST(N1.Numero * 100 + N2.Numero AS VARCHAR) AS NomUtilisateur
FROM Nombres N1
CROSS JOIN Nombres N2
WHERE N1.Numero BETWEEN 1 AND 100
  AND N2.Numero BETWEEN 1 AND 100;
```

Si la table Nombres contient 100 lignes → 100 × 100 = **10 000 lignes** générées.

### 4. Création de matrices de comparaison

**Scénario** : Comparer tous les éléments d'un ensemble avec tous les autres.

```sql
-- Comparer chaque produit avec chaque autre produit
SELECT
    P1.NomProduit AS Produit1,
    P2.NomProduit AS Produit2,
    ABS(P1.Prix - P2.Prix) AS DifferencePrix
FROM Produits P1
CROSS JOIN Produits P2
WHERE P1.ProduitID < P2.ProduitID  -- Éviter les doublons et auto-comparaisons
ORDER BY DifferencePrix DESC;
```

### 5. Remplissage de tables de dimension (Data Warehousing)

**Scénario** : Créer une table de dimension avec toutes les combinaisons d'attributs.

```sql
-- Table de dimension pour un cube OLAP
INSERT INTO DIM_Produit_Complet (TailleID, CouleurID, StyleID)
SELECT
    T.TailleID,
    C.CouleurID,
    S.StyleID
FROM DIM_Tailles T
CROSS JOIN DIM_Couleurs C
CROSS JOIN DIM_Styles S;
```

### 6. Génération de séquences numériques

**Scénario** : Créer une table de nombres pour diverses utilisations.

```sql
-- Générer les nombres de 1 à 1000
WITH Dizaines AS (
    SELECT 0 AS N UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL
    SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5 UNION ALL
    SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9
),
Centaines AS (SELECT N FROM Dizaines)
SELECT
    (C.N * 100 + D.N * 10 + U.N) AS Nombre
FROM Centaines C
CROSS JOIN Dizaines D
CROSS JOIN Dizaines U
WHERE (C.N * 100 + D.N * 10 + U.N) BETWEEN 1 AND 1000
ORDER BY Nombre;
```

## CROSS JOIN avec conditions dans WHERE

Bien que CROSS JOIN n'accepte pas de clause ON, vous pouvez filtrer le résultat avec WHERE :

### Syntaxe

```sql
SELECT *
FROM TableA A
CROSS JOIN TableB B
WHERE condition_de_filtrage;
```

### Exemple : Filtrer les combinaisons

```sql
-- Toutes les combinaisons, mais seulement celles où le prix est cohérent
SELECT
    T.NomTaille,
    C.NomCouleur,
    (100 + T.SupplementTaille + C.SupplementCouleur) AS Prix
FROM Tailles T
CROSS JOIN Couleurs C
WHERE (100 + T.SupplementTaille + C.SupplementCouleur) < 200;
```

### Note importante

Un CROSS JOIN avec une condition WHERE qui compare les clés des deux tables devient **équivalent à un INNER JOIN** :

```sql
-- Ces deux requêtes produisent le même résultat :

-- Version 1 : CROSS JOIN + WHERE
SELECT *
FROM Clients C
CROSS JOIN Commandes CMD
WHERE C.ClientID = CMD.ClientID;

-- Version 2 : INNER JOIN (préférée)
SELECT *
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Préférez toujours la version INNER JOIN** : elle est plus claire et l'optimiseur peut mieux l'optimiser.

---

## CROSS JOIN avec plusieurs tables

Vous pouvez enchaîner plusieurs CROSS JOIN, mais attention à l'explosion combinatoire !

### Exemple avec 3 tables

```sql
SELECT
    T.NomTaille,
    C.NomCouleur,
    M.NomMotif
FROM Tailles T          -- 5 lignes
CROSS JOIN Couleurs C   -- 8 lignes
CROSS JOIN Motifs M;    -- 4 lignes
-- Résultat : 5 × 8 × 4 = 160 lignes
```

### Calcul avec n tables

```
Résultat = Lignes_Table1 × Lignes_Table2 × Lignes_Table3 × ... × Lignes_TableN
```

### Danger de l'explosion exponentielle

```sql
-- ⚠️ ATTENTION : Peut générer des millions de lignes !
SELECT *
FROM Table1          -- 1 000 lignes
CROSS JOIN Table2    -- 1 000 lignes
CROSS JOIN Table3    -- 1 000 lignes
CROSS JOIN Table4;   -- 1 000 lignes
-- Résultat : 1 000 × 1 000 × 1 000 × 1 000 = 1 000 000 000 000 lignes !
-- = 1 TRILLION de lignes !!!
```

**Conseil** : Avec plusieurs CROSS JOIN, calculez toujours le nombre de lignes résultant **avant** d'exécuter la requête !

## Performances et optimisation

### CROSS JOIN est coûteux

Le CROSS JOIN est **très gourmand en ressources** car :
- Il génère potentiellement des millions de lignes
- Chaque ligne doit être traitée en mémoire ou écrite sur disque
- Les opérations suivantes (WHERE, GROUP BY, etc.) doivent traiter toutes ces lignes

### Conseils d'optimisation

#### 1. Limitez la taille des tables sources

```sql
-- ❌ Dangereux
SELECT * FROM GrosseTable1 CROSS JOIN GrosseTable2;

-- ✅ Meilleur : Filtrez d'abord
SELECT *
FROM (SELECT TOP 100 * FROM GrosseTable1) T1
CROSS JOIN (SELECT TOP 10 * FROM GrosseTable2) T2;
```

#### 2. Utilisez TOP ou FETCH pour limiter le résultat

```sql
-- Limiter à 1000 combinaisons aléatoires
SELECT TOP 1000
    T.NomTaille,
    C.NomCouleur
FROM Tailles T
CROSS JOIN Couleurs C
ORDER BY NEWID();  -- Ordre aléatoire
```

#### 3. Filtrez tôt avec WHERE

```sql
-- ✅ Bon : Filtrage immédiat après le CROSS JOIN
SELECT *
FROM Petite_Table1 T1
CROSS JOIN Petite_Table2 T2
WHERE T1.Actif = 1 AND T2.Actif = 1;
```

#### 4. Évitez les CROSS JOIN sur de grandes tables

Si possible, restructurez votre requête pour éviter le CROSS JOIN :

```sql
-- ❌ Évitez ceci sur de grandes tables
SELECT * FROM Clients CROSS JOIN Produits;

-- ✅ Mieux : Utilisez une table de liaison si elle existe
SELECT C.*, P.*
FROM Clients C
INNER JOIN ClientProduits CP ON C.ClientID = CP.ClientID
INNER JOIN Produits P ON CP.ProduitID = P.ProduitID;
```

## CROSS JOIN vs Produit cartésien accidentel

### Le produit cartésien accidentel

Un piège courant pour les débutants est d'oublier la condition de jointure avec les anciennes syntaxes :

```sql
-- ❌ ERREUR COURANTE : Oubli de la condition
-- Génère un produit cartésien non intentionnel !
SELECT *
FROM Clients C, Commandes CMD;
-- Résultat : TOUTES les combinaisons clients × commandes
```

Ce code devrait probablement être :

```sql
-- ✅ CORRECT : Avec condition
SELECT *
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### Le CROSS JOIN intentionnel

Quand vous utilisez `CROSS JOIN` explicitement, vous montrez clairement votre intention :

```sql
-- ✅ INTENTION CLAIRE : Je veux vraiment toutes les combinaisons
SELECT *
FROM Tailles T
CROSS JOIN Couleurs C;
```

**Bonne pratique** : Utilisez toujours `CROSS JOIN` au lieu de la syntaxe avec virgule pour éviter la confusion.

---

## Erreurs courantes à éviter

### 1. Oublier de calculer le nombre de lignes résultant

```sql
-- ❌ Dangereux sans vérification préalable
SELECT * FROM Table1 CROSS JOIN Table2;
```

**Solution** : Comptez d'abord !

```sql
-- ✅ Vérifiez avant
SELECT COUNT(*) FROM Table1;  -- Ex: 10 000 lignes
SELECT COUNT(*) FROM Table2;  -- Ex: 50 000 lignes
-- Résultat potentiel : 10 000 × 50 000 = 500 millions de lignes !
```

### 2. Utiliser CROSS JOIN quand un INNER JOIN suffit

```sql
-- ❌ Mauvais : CROSS JOIN + WHERE pour simuler INNER JOIN
SELECT *
FROM Clients C
CROSS JOIN Commandes CMD
WHERE C.ClientID = CMD.ClientID;

-- ✅ Meilleur : INNER JOIN direct
SELECT *
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### 3. Enchaîner trop de CROSS JOIN

```sql
-- ❌ Explosion combinatoire incontrôlée
SELECT *
FROM T1 CROSS JOIN T2 CROSS JOIN T3
CROSS JOIN T4 CROSS JOIN T5 CROSS JOIN T6;
-- Potentiellement des milliards de lignes !
```

### 4. Ne pas filtrer assez tôt

```sql
-- ❌ Génère d'abord toutes les combinaisons, filtre ensuite
SELECT *
FROM GrosseTable1 GT1
CROSS JOIN GrosseTable2 GT2
WHERE GT1.Date > '2025-01-01' AND GT2.Actif = 1;

-- ✅ Mieux : Filtrer avant de joindre
SELECT *
FROM (SELECT * FROM GrosseTable1 WHERE Date > '2025-01-01') GT1
CROSS JOIN (SELECT * FROM GrosseTable2 WHERE Actif = 1) GT2;
```

### 5. Confondre CROSS JOIN et FULL OUTER JOIN

```sql
-- CROSS JOIN : Toutes les COMBINAISONS (multiplication)
SELECT * FROM TableA CROSS JOIN TableB;
-- Si A = 3 lignes et B = 2 lignes → 6 lignes résultat

-- FULL OUTER JOIN : Toutes les lignes (union)
SELECT * FROM TableA FULL OUTER JOIN TableB ON condition;
-- Si A = 3 lignes et B = 2 lignes → Au plus 5 lignes résultat
```

## Alternative : Éviter CROSS JOIN quand possible

Dans certains cas, vous pouvez éviter un CROSS JOIN coûteux en utilisant d'autres techniques :

### Exemple 1 : Utiliser des CTEs récursives pour les séquences

```sql
-- Au lieu de CROSS JOIN pour générer des nombres
WITH Nombres AS (
    SELECT 1 AS N
    UNION ALL
    SELECT N + 1
    FROM Nombres
    WHERE N < 1000
)
SELECT N FROM Nombres
OPTION (MAXRECURSION 1000);
```

### Exemple 2 : Utiliser des tables de dimension pré-calculées

```sql
-- Au lieu de calculer à chaque fois
SELECT * FROM Tailles CROSS JOIN Couleurs;

-- Créer une table permanente
CREATE TABLE VariantesProduits (
    TailleID INT,
    CouleurID INT,
    -- Autres colonnes utiles
);

-- Remplir une seule fois
INSERT INTO VariantesProduits (TailleID, CouleurID)
SELECT T.TailleID, C.CouleurID
FROM Tailles T
CROSS JOIN Couleurs C;

-- Utiliser ensuite avec de simples SELECT
SELECT * FROM VariantesProduits;
```

## Points clés à retenir

1. **CROSS JOIN** génère **toutes les combinaisons possibles** entre deux tables (produit cartésien).

2. **Syntaxe** : `FROM Table1 CROSS JOIN Table2` (SANS clause ON).

3. **Nombre de lignes** : Lignes_Table1 × Lignes_Table2 (multiplication).

4. **Pas de condition ON** : Le CROSS JOIN n'utilise jamais de clause ON.

5. **Danger d'explosion** : Le nombre de lignes peut devenir astronomique très rapidement.

6. **Utilisations spécifiques** : Génération de combinaisons, calendriers, données de test, matrices.

7. **Rarement utilisé** : Contrairement aux autres JOIN, le CROSS JOIN est utilisé dans des cas précis seulement.

8. **Calcul obligatoire** : Toujours calculer le nombre de lignes résultant avant d'exécuter.

9. **CROSS JOIN ≠ FULL OUTER JOIN** : Ne confondez pas combinaisons (×) et union (+).

10. **Performance** : Le CROSS JOIN est coûteux - utilisez-le avec précaution.

---

## Quand utiliser un CROSS JOIN ?

Utilisez un CROSS JOIN quand :

- ✅ Vous voulez **générer toutes les combinaisons** possibles entre deux ensembles
- ✅ Vous créez des **variantes de produits** (tailles × couleurs × styles)
- ✅ Vous générez des **calendriers ou grilles horaires**
- ✅ Vous créez des **données de test** en volume
- ✅ Vous construisez des **matrices de comparaison**
- ✅ Vous peuplez des **tables de dimension** pour un data warehouse
- ✅ Le nombre de lignes résultant est **raisonnable et contrôlé**

N'utilisez PAS un CROSS JOIN quand :

- ❌ Vous voulez des données avec correspondance → Utilisez INNER JOIN
- ❌ Les tables sont volumineuses (risque d'explosion)
- ❌ Vous pouvez utiliser une autre technique plus efficace
- ❌ Vous avez oublié la condition de jointure (utilisez INNER/LEFT/RIGHT JOIN)
- ❌ Vous voulez simplement toutes les lignes des deux tables → Utilisez FULL OUTER JOIN

## Tableau comparatif final : Tous les types de JOIN

| Type de JOIN | Condition ON | Lignes résultat | Cas d'usage principal |
|--------------|--------------|-----------------|----------------------|
| **INNER** | ✅ Obligatoire | Seulement les correspondances | Joindre des données liées (80% des cas) |
| **LEFT** | ✅ Obligatoire | Toute table gauche + correspondances | Garder tous les enregistrements principaux |
| **RIGHT** | ✅ Obligatoire | Toute table droite + correspondances | Rare (équivalent à LEFT inversé) |
| **FULL OUTER** | ✅ Obligatoire | Toutes les lignes des deux tables | Réconciliation, comparaison exhaustive |
| **CROSS** | ❌ Interdite | Table1 × Table2 (multiplication) | Générer des combinaisons |

---

## En résumé

Le **CROSS JOIN** est un outil puissant mais potentiellement dangereux. Il génère **toutes les combinaisons possibles** entre deux tables, ce qui peut rapidement mener à une explosion du nombre de lignes.

**Points essentiels à retenir** :
- Utilisez-le uniquement quand vous voulez vraiment toutes les combinaisons
- Calculez toujours le nombre de lignes résultant avant l'exécution
- Il n'utilise jamais de clause ON
- C'est le produit cartésien du chapitre 4.1.1, utilisé intentionnellement
- Les cas d'usage sont spécifiques et limités

**Conseil pratique** : Dans 95% des cas, vous utiliserez INNER JOIN ou LEFT JOIN. Le CROSS JOIN est un outil spécialisé pour des situations particulières. Quand vous en avez besoin, vous le savez - et vous devez l'utiliser avec précaution !

Maintenant que vous maîtrisez tous les types de jointures (INNER, LEFT, RIGHT, FULL OUTER, CROSS), vous êtes prêt à découvrir les auto-jointures (Self-Joins) qui utilisent ces concepts pour joindre une table avec elle-même !
