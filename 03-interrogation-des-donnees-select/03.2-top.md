# 3.3.2 TOP (n) et TOP (n) PERCENT

## Introduction

Dans de nombreuses situations, vous ne souhaitez pas récupérer **toutes** les lignes d'une table, mais seulement un **nombre limité** de résultats. Par exemple :
- Les 10 meilleurs clients par chiffre d'affaires
- Les 5 produits les plus chers
- Les 20% des employés les mieux payés
- Les 3 dernières commandes passées

La clause `TOP` de SQL Server vous permet de limiter le nombre de lignes retournées par une requête. C'est un outil simple mais extrêmement utile au quotidien.

## Syntaxe de base

### TOP (n)

```sql
SELECT TOP (n) colonnes
FROM table
[ORDER BY colonne];
```

- **n** : Le nombre de lignes à retourner
- Les parenthèses autour de `n` sont optionnelles mais recommandées

### TOP (n) PERCENT

```sql
SELECT TOP (n) PERCENT colonnes
FROM table
[ORDER BY colonne];
```

- **n** : Le pourcentage de lignes à retourner (ex: 10 pour 10%)
- Retourne environ n% des lignes totales du résultat

## TOP (n) : Limiter à un nombre fixe de lignes

### Exemple 1 : Les 5 produits les plus chers

Imaginons une table `Produits` avec les colonnes `ProduitID`, `NomProduit`, `Prix`.

```sql
SELECT TOP (5) NomProduit, Prix
FROM Produits
ORDER BY Prix DESC;
```

Cette requête retourne les **5 produits** ayant les prix les plus élevés.

**Résultat possible :**
```
NomProduit              Prix
----------------------  -------
Ordinateur portable     1299.00
Tablette graphique      899.00
Imprimante laser        549.99
Moniteur 27 pouces      399.00
Clavier mécanique       159.99
```

### Exemple 2 : Les 10 dernières commandes

```sql
SELECT TOP (10) NumeroCommande, DateCommande, MontantTotal
FROM Commandes
ORDER BY DateCommande DESC;
```

En triant par date décroissante et en limitant à 10, nous obtenons les 10 commandes les plus récentes.

### Exemple 3 : Sans parenthèses (syntaxe alternative)

Bien que les parenthèses soient recommandées, cette syntaxe fonctionne également :

```sql
SELECT TOP 3 NomClient, Ville
FROM Clients
ORDER BY NomClient;
```

**⚠️ Recommandation :** Utilisez toujours les parenthèses `TOP (n)` pour une meilleure lisibilité et cohérence avec la syntaxe moderne.

## L'importance de ORDER BY avec TOP

### Sans ORDER BY

Si vous utilisez `TOP` **sans** `ORDER BY`, SQL Server retournera simplement les n premières lignes qu'il rencontre, dans un ordre qui peut sembler arbitraire :

```sql
SELECT TOP (5) NomProduit, Prix
FROM Produits;
-- Retourne 5 produits, mais lesquels ? C'est imprévisible !
```

**⚠️ Attention :** Sans `ORDER BY`, l'ordre n'est pas garanti et peut varier d'une exécution à l'autre. Les résultats ne seront pas forcément les mêmes !

### Avec ORDER BY (recommandé)

Pour obtenir des résultats **prévisibles et cohérents**, combinez toujours `TOP` avec `ORDER BY` :

```sql
SELECT TOP (5) NomProduit, Prix
FROM Produits
ORDER BY Prix DESC;
-- Retourne toujours les 5 produits les plus chers
```

## TOP (n) PERCENT : Limiter à un pourcentage

Plutôt que de spécifier un nombre fixe de lignes, vous pouvez demander un **pourcentage** du résultat total.

### Syntaxe

```sql
SELECT TOP (n) PERCENT colonnes
FROM table
ORDER BY colonne;
```

### Exemple 1 : Les 10% des employés les mieux payés

Supposons une table `Employes` avec 100 employés.

```sql
SELECT TOP (10) PERCENT Nom, Prenom, Salaire
FROM Employes
ORDER BY Salaire DESC;
```

Cette requête retourne environ **10 employés** (10% de 100).

**Résultat possible :**
```
Nom         Prenom      Salaire
----------  ----------  --------
Dupont      Marie       85000
Martin      Jean        82000
Bernard     Sophie      79500
Petit       Luc         78000
...
```

### Exemple 2 : Les 5% des meilleures ventes

```sql
SELECT TOP (5) PERCENT
    NumeroCommande,
    DateCommande,
    MontantTotal
FROM Commandes
ORDER BY MontantTotal DESC;
```

Si la table contient 200 commandes, cette requête retournera les **10 commandes** avec les montants les plus élevés (5% de 200).

### Arrondi avec PERCENT

Le calcul du pourcentage peut donner un **nombre décimal**. SQL Server arrondit alors **vers le haut** :

- Si vous avez 47 lignes et demandez `TOP (10) PERCENT` :
  - 10% de 47 = 4,7
  - SQL Server retournera **5 lignes** (arrondi supérieur)

## Gestion des égalités (ex-aequo)

### Problème des valeurs identiques

Que se passe-t-il si plusieurs lignes ont la **même valeur** pour la colonne de tri ?

**Exemple :** Vous demandez le TOP 3 des produits les plus chers :

```sql
SELECT TOP (3) NomProduit, Prix
FROM Produits
ORDER BY Prix DESC;
```

Si vous avez cette situation :

| NomProduit | Prix |
|------------|------|
| Produit A  | 100  |
| Produit B  | 90   |
| Produit C  | 80   |
| Produit D  | 80   | ← Même prix que C
| Produit E  | 80   | ← Même prix que C

Lesquels seront retournés ? **C'est imprévisible !** SQL Server choisira arbitrairement 3 des 4 lignes ayant un prix ≥ 80.

### Solution : WITH TIES

Pour inclure **toutes** les lignes qui ont la même valeur que la dernière ligne retournée, utilisez `WITH TIES` :

```sql
SELECT TOP (3) WITH TIES NomProduit, Prix
FROM Produits
ORDER BY Prix DESC;
```

**Résultat avec WITH TIES :**
```
NomProduit      Prix
--------------  -----
Produit A       100
Produit B       90
Produit C       80
Produit D       80   ← Inclus car même prix que C
Produit E       80   ← Inclus car même prix que C
```

Cette requête retourne **5 lignes** au lieu de 3, car il y a des ex-aequo en 3ème position.

**⚠️ Important :** `WITH TIES` nécessite **obligatoirement** une clause `ORDER BY` pour fonctionner.

## Combinaison avec WHERE

Vous pouvez combiner `TOP` avec la clause `WHERE` pour filtrer avant de limiter :

```sql
SELECT TOP (5) NomProduit, Prix, Categorie
FROM Produits
WHERE Categorie = 'Électronique'
ORDER BY Prix DESC;
```

**Ordre d'exécution :**
1. **WHERE** : Filtre uniquement les produits de catégorie "Électronique"
2. **ORDER BY** : Trie par prix décroissant
3. **TOP** : Retourne les 5 premiers résultats

## TOP vs LIMIT (autres SGBD)

Si vous avez déjà utilisé d'autres systèmes de gestion de bases de données :

| SGBD | Syntaxe de limitation |
|------|----------------------|
| **SQL Server** | `SELECT TOP (n)` |
| MySQL / PostgreSQL | `SELECT ... LIMIT n` |
| Oracle | `SELECT ... FETCH FIRST n ROWS ONLY` |

**Attention :** `TOP` est spécifique à SQL Server (et Sybase). D'autres SGBD utilisent des syntaxes différentes.

## Cas d'usage courants

### 1. Tableau de bord : Top 10 des ventes

```sql
SELECT TOP (10)
    VendeurID,
    NomVendeur,
    TotalVentes
FROM Vendeurs
ORDER BY TotalVentes DESC;
```

### 2. Échantillonnage de données

```sql
SELECT TOP (100) *
FROM GrandeTable
ORDER BY NEWID();  -- Ordre aléatoire
```

`NEWID()` génère un identifiant unique aléatoire, ce qui permet d'obtenir un échantillon aléatoire de 100 lignes.

### 3. Meilleurs et pires éléments

**Les 5 meilleurs :**
```sql
SELECT TOP (5) NomProduit, NoteClient
FROM Produits
ORDER BY NoteClient DESC;
```

**Les 5 pires :**
```sql
SELECT TOP (5) NomProduit, NoteClient
FROM Produits
ORDER BY NoteClient ASC;
```

### 4. Comparaison TOP vs TOP PERCENT

```sql
-- Nombre fixe : toujours 20 lignes
SELECT TOP (20) *
FROM Clients
ORDER BY ChiffreAffaires DESC;

-- Pourcentage : dépend du nombre total de clients
-- Si 500 clients → 50 lignes (10%)
-- Si 1000 clients → 100 lignes (10%)
SELECT TOP (10) PERCENT *
FROM Clients
ORDER BY ChiffreAffaires DESC;
```

## Performance et bonnes pratiques

### ✅ Bonnes pratiques

1. **Toujours utiliser ORDER BY** avec TOP pour des résultats prévisibles
2. **Utiliser les parenthèses** : `TOP (n)` plutôt que `TOP n`
3. **Penser aux index** : Si vous triez souvent sur une colonne, créez un index dessus
4. **Utiliser WITH TIES** si les égalités sont importantes pour votre logique métier
5. **Préférer TOP pour la lisibilité** plutôt que des sous-requêtes complexes

### ⚠️ Points d'attention

1. **TOP sans ORDER BY** = résultats imprévisibles
2. **PERCENT** peut retourner un nombre de lignes différent selon la taille de la table
3. **WITH TIES** peut retourner **plus** de lignes que demandé
4. **Performance** : TOP est généralement très efficace, surtout avec les bons index

## Différence avec OFFSET/FETCH (pagination)

`TOP` est idéal pour obtenir les "n premiers" résultats, mais pour la **pagination** (page 1, page 2, etc.), SQL Server offre une syntaxe plus moderne : `OFFSET` et `FETCH NEXT`.

**Avec TOP (limité) :**
```sql
-- Impossible de sauter des lignes facilement
SELECT TOP (10) *
FROM Produits
ORDER BY ProduitID;
```

**Avec OFFSET/FETCH (pagination) :**
```sql
-- Page 1 : lignes 1-10
SELECT *
FROM Produits
ORDER BY ProduitID
OFFSET 0 ROWS
FETCH NEXT 10 ROWS ONLY;

-- Page 2 : lignes 11-20
SELECT *
FROM Produits
ORDER BY ProduitID
OFFSET 10 ROWS
FETCH NEXT 10 ROWS ONLY;
```

Nous verrons `OFFSET` et `FETCH NEXT` dans la section suivante (3.3.3).

## Exemples récapitulatifs

### Exemple complet 1 : Rapport des meilleures ventes

```sql
SELECT TOP (10)
    p.NomProduit,
    p.Prix,
    p.Stock,
    c.NomCategorie
FROM Produits p
INNER JOIN Categories c ON p.CategorieID = c.CategorieID
WHERE p.Stock > 0
ORDER BY p.NombreVentes DESC;
```

Cette requête :
- Retourne les 10 produits les plus vendus
- Filtre uniquement ceux en stock
- Affiche le nom, prix, stock et catégorie
- Trie par nombre de ventes décroissant

### Exemple complet 2 : Clients premium (top 5%)

```sql
SELECT TOP (5) PERCENT WITH TIES
    ClientID,
    NomClient,
    TotalAchats,
    DateDerniereCommande
FROM Clients
WHERE TotalAchats > 1000
ORDER BY TotalAchats DESC;
```

Cette requête :
- Retourne environ 5% des meilleurs clients
- Filtre ceux ayant dépensé plus de 1000€
- Inclut tous les ex-aequo au niveau du seuil (WITH TIES)
- Trie par montant total d'achats

## Résumé

| Syntaxe | Description | Exemple |
|---------|-------------|---------|
| `TOP (n)` | Retourne n lignes | `TOP (10)` → 10 lignes |
| `TOP (n) PERCENT` | Retourne n% des lignes | `TOP (5) PERCENT` → 5% |
| `TOP (n) WITH TIES` | Inclut les ex-aequo | Peut retourner plus que n |
| `TOP (n) ... ORDER BY` | Recommandé ! | Résultats prévisibles |

## Tableau comparatif

| Critère | TOP (n) | TOP (n) PERCENT |
|---------|---------|-----------------|
| **Nombre de lignes retournées** | Fixe | Variable selon la taille de la table |
| **Prévisibilité** | Toujours n lignes* | Dépend du nombre total |
| **Utilisation typique** | Top 10, Top 5, etc. | Top 10%, 20% les meilleurs, etc. |
| **Arrondi** | N/A | Arrondi supérieur |

*Sauf avec WITH TIES

## Conclusion

La clause `TOP` est un outil simple mais puissant pour limiter le nombre de résultats retournés par vos requêtes SQL. Que vous ayez besoin d'un nombre fixe de lignes avec `TOP (n)` ou d'un pourcentage avec `TOP (n) PERCENT`, cette fonctionnalité est essentielle pour :

- Créer des classements et palmarès
- Optimiser les performances en limitant les résultats
- Réaliser des échantillonnages de données
- Générer des rapports "Top N"

**Points clés à retenir :**
1. Utilisez **toujours ORDER BY** avec TOP pour des résultats cohérents
2. **WITH TIES** permet de gérer les égalités
3. **PERCENT** est utile quand le nombre total de lignes varie
4. TOP est une fonctionnalité **spécifique à SQL Server**

Dans la prochaine section, nous découvrirons `OFFSET` et `FETCH NEXT`, une alternative plus moderne et flexible pour la pagination des résultats.
