# 2.4.3 INSERT INTO ... SELECT

## Introduction

Jusqu'à présent, nous avons appris à insérer des données en tapant manuellement les valeurs avec `INSERT INTO ... VALUES`. Mais que se passe-t-il si vous devez copier des données d'une table existante vers une autre ? Ou si vous devez insérer le résultat d'une requête complexe ?

C'est là qu'intervient `INSERT INTO ... SELECT`, une technique puissante qui permet d'**insérer des données en provenance d'une requête** plutôt que de valeurs écrites en dur.

---

## Qu'est-ce que INSERT INTO ... SELECT ?

`INSERT INTO ... SELECT` est une combinaison de deux instructions que nous connaissons déjà :

- **INSERT INTO** : Pour insérer des données dans une table
- **SELECT** : Pour récupérer des données depuis une ou plusieurs tables

Au lieu de fournir des valeurs manuellement, vous utilisez les **résultats d'une requête SELECT** comme source de données.

### Analogie simple

Imaginez que vous devez :
- **Avec VALUES** : Recopier un texte lettre par lettre depuis un livre vers un cahier
- **Avec SELECT** : Scanner les pages d'un livre et les imprimer directement dans un cahier

La deuxième approche est beaucoup plus rapide et efficace !

---

## Syntaxe de base

```sql
INSERT INTO table_destination (colonne1, colonne2, colonne3, ...)
SELECT colonne1, colonne2, colonne3, ...
FROM table_source
WHERE condition;
```

### Décomposition

- **INSERT INTO table_destination** : La table où vous voulez insérer les données
- **(colonne1, colonne2, ...)** : Les colonnes de la table de destination
- **SELECT colonne1, colonne2, ...** : Les colonnes à récupérer depuis la source
- **FROM table_source** : La table d'où proviennent les données
- **WHERE condition** : Filtre facultatif pour sélectionner uniquement certaines lignes

> **Important** : Le nombre et le type de colonnes dans le SELECT doivent correspondre aux colonnes spécifiées dans l'INSERT INTO.

---

## Exemple simple et détaillé

### Contexte

Imaginons deux tables :

**Table `Employes`** (Table source)
```sql
CREATE TABLE Employes (
    EmployeID INT PRIMARY KEY,
    Prenom VARCHAR(50),
    Nom VARCHAR(50),
    Departement VARCHAR(50),
    Salaire DECIMAL(10, 2),
    AnneeEmbauche INT
);
```

**Table `EmployesArchive`** (Table destination)
```sql
CREATE TABLE EmployesArchive (
    EmployeID INT PRIMARY KEY,
    Prenom VARCHAR(50),
    Nom VARCHAR(50),
    Departement VARCHAR(50),
    Salaire DECIMAL(10, 2)
);
```

### Copie simple de toutes les données

Pour copier **tous les employés** de `Employes` vers `EmployesArchive` :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes;
```

**Que se passe-t-il ?**
1. SQL Server exécute d'abord la requête `SELECT` et récupère toutes les données
2. Ensuite, il insère chaque ligne résultante dans `EmployesArchive`
3. Si la table `Employes` contient 1000 lignes, 1000 lignes seront insérées dans `EmployesArchive`

---

## Copie avec filtrage (clause WHERE)

Souvent, vous ne voulez pas copier **toutes** les données, mais seulement un sous-ensemble.

### Exemple : Archiver les anciens employés

Copier uniquement les employés embauchés avant 2020 :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes
WHERE AnneeEmbauche < 2020;
```

**Résultat** : Seuls les employés dont `AnneeEmbauche` est inférieure à 2020 seront copiés.

### Exemple : Copier un département spécifique

Copier uniquement les employés du département IT :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes
WHERE Departement = 'IT';
```

---

## Transformation des données pendant l'insertion

Vous pouvez **modifier** ou **calculer** des valeurs pendant la copie.

### Exemple 1 : Augmentation de salaire

Copier les employés en augmentant leur salaire de 10% :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire * 1.10
FROM Employes;
```

> **Note** : `Salaire * 1.10` calcule le salaire augmenté de 10% pour chaque employé.

### Exemple 2 : Concaténation de colonnes

Créer un nom complet à partir du prénom et du nom :

```sql
INSERT INTO Contacts (ContactID, NomComplet, Email)
SELECT EmployeID, Prenom + ' ' + Nom, Email
FROM Employes;
```

Ici, `Prenom + ' ' + Nom` combine le prénom et le nom avec un espace entre les deux.

### Exemple 3 : Valeurs constantes

Vous pouvez ajouter des valeurs constantes lors de l'insertion :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire, Statut)
SELECT EmployeID, Prenom, Nom, Departement, Salaire, 'Archivé'
FROM Employes
WHERE AnneeEmbauche < 2015;
```

Ici, tous les enregistrements insérés auront `'Archivé'` dans la colonne `Statut`.

---

## Correspondance des colonnes

### Ordre et type des colonnes

Les colonnes dans le `SELECT` doivent correspondre **en nombre, en ordre et en type** aux colonnes de l'`INSERT INTO`.

#### ✅ Correct

```sql
INSERT INTO TableA (Col1, Col2, Col3)
SELECT ColX, ColY, ColZ
FROM TableB;
```

- `Col1` reçoit les valeurs de `ColX`
- `Col2` reçoit les valeurs de `ColY`
- `Col3` reçoit les valeurs de `ColZ`

#### ❌ Incorrect - Nombre différent

```sql
-- ERREUR : 3 colonnes dans INSERT mais seulement 2 dans SELECT
INSERT INTO TableA (Col1, Col2, Col3)
SELECT ColX, ColY
FROM TableB;
```

#### ❌ Incorrect - Types incompatibles

```sql
-- ERREUR : Col1 est INT mais ColX est VARCHAR
INSERT INTO TableA (Col1, Col2)
SELECT ColX, ColY  -- ColX est VARCHAR
FROM TableB;
```

### Omission de la liste de colonnes

Comme avec `INSERT INTO ... VALUES`, vous pouvez omettre la liste des colonnes de destination, mais **ce n'est pas recommandé** :

```sql
-- ❌ Déconseillé : Risqué si la structure de la table change
INSERT INTO EmployesArchive
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes;
```

**Bonne pratique** : Spécifiez toujours explicitement les colonnes.

## Insertion depuis plusieurs tables (avec JOIN)

Vous pouvez combiner des données de **plusieurs tables** grâce aux jointures.

### Exemple : Combiner des données de deux tables

Imaginons deux tables :

**Table `Employes`**
| EmployeID | Prenom | Nom | DepartementID |
|-----------|--------|-----|---------------|
| 1 | Marie | Dupont | 10 |
| 2 | Pierre | Martin | 20 |

**Table `Departements`**
| DepartementID | NomDepartement |
|---------------|----------------|
| 10 | Ventes |
| 20 | IT |

**Objectif** : Créer une table `EmployesComplet` avec le nom du département au lieu de l'ID.

```sql
INSERT INTO EmployesComplet (EmployeID, Prenom, Nom, Departement)
SELECT e.EmployeID, e.Prenom, e.Nom, d.NomDepartement
FROM Employes e
INNER JOIN Departements d ON e.DepartementID = d.DepartementID;
```

**Résultat dans `EmployesComplet`** :
| EmployeID | Prenom | Nom | Departement |
|-----------|--------|-----|-------------|
| 1 | Marie | Dupont | Ventes |
| 2 | Pierre | Martin | IT |

## Agrégation et regroupement

Vous pouvez également utiliser des fonctions d'agrégation pour insérer des données résumées.

### Exemple : Statistiques par département

Créer une table de statistiques avec le salaire moyen par département :

```sql
-- Table de destination
CREATE TABLE StatsDepartements (
    Departement VARCHAR(50),
    NombreEmployes INT,
    SalaireMoyen DECIMAL(10, 2)
);

-- Insertion des statistiques
INSERT INTO StatsDepartements (Departement, NombreEmployes, SalaireMoyen)
SELECT
    Departement,
    COUNT(*) AS NombreEmployes,
    AVG(Salaire) AS SalaireMoyen
FROM Employes
GROUP BY Departement;
```

**Résultat** : Chaque département aura une ligne avec son nombre d'employés et le salaire moyen.

---

## Insertion avec sous-requêtes

Vous pouvez utiliser des sous-requêtes complexes dans votre `SELECT`.

### Exemple : Copier les employés gagnant plus que la moyenne

```sql
INSERT INTO EmployesHautSalaire (EmployeID, Prenom, Nom, Salaire)
SELECT EmployeID, Prenom, Nom, Salaire
FROM Employes
WHERE Salaire > (SELECT AVG(Salaire) FROM Employes);
```

**Explication** :
1. La sous-requête `(SELECT AVG(Salaire) FROM Employes)` calcule le salaire moyen
2. La requête principale sélectionne les employés dont le salaire dépasse cette moyenne
3. Ces employés sont insérés dans `EmployesHautSalaire`

---

## Création et insertion en une seule étape (SELECT INTO)

SQL Server offre une syntaxe raccourcie pour **créer une nouvelle table** et y insérer des données en une seule instruction : `SELECT INTO`.

### Syntaxe

```sql
SELECT colonne1, colonne2, colonne3, ...
INTO nouvelle_table
FROM table_source
WHERE condition;
```

### Exemple

```sql
SELECT EmployeID, Prenom, Nom, Salaire
INTO EmployesIT
FROM Employes
WHERE Departement = 'IT';
```

**Que se passe-t-il ?**
1. SQL Server **crée automatiquement** une nouvelle table appelée `EmployesIT`
2. La structure de la table est basée sur les colonnes du `SELECT`
3. Les données sont insérées immédiatement

### Différence avec INSERT INTO ... SELECT

| Aspect | INSERT INTO ... SELECT | SELECT INTO |
|--------|------------------------|-------------|
| Table destination | Doit exister | Créée automatiquement |
| Structure | Définie manuellement | Déduite du SELECT |
| Contraintes | Conservées | Aucune (sauf NOT NULL) |
| Index | Conservés | Aucun |

> **Note** : `SELECT INTO` est très pratique pour créer des tables temporaires ou de test rapidement.

---

## Nombre de lignes insérées

Pour connaître le nombre de lignes insérées, utilisez la variable système `@@ROWCOUNT` :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes
WHERE AnneeEmbauche < 2020;

SELECT @@ROWCOUNT AS [Lignes insérées];
```

Si 150 employés ont été embauchés avant 2020, le résultat affichera : `150`.

## Performance et considérations

### Avantages

1. **Rapidité** : Beaucoup plus rapide que des insertions individuelles
2. **Simplicité** : Pas besoin de boucles ou de code procédural
3. **Flexibilité** : Permet des transformations et des filtres complexes
4. **Efficacité** : Une seule transaction pour toutes les insertions

### Points d'attention

1. **Verrouillage** : L'insertion de grandes quantités de données peut verrouiller la table
2. **Espace disque** : Assurez-vous d'avoir suffisamment d'espace pour les nouvelles données
3. **Index** : Si la table de destination a beaucoup d'index, l'insertion sera plus lente
4. **Transaction** : Toutes les insertions sont atomiques (tout ou rien)

---

## Erreurs courantes et solutions

### 1. Incompatibilité de types de données

```sql
-- ❌ ERREUR : Salaire (DECIMAL) vers EmployeID (INT)
INSERT INTO TableTest (EmployeID, Nom)
SELECT Salaire, Prenom
FROM Employes;
```

**Solution** : Assurez-vous que les types de données correspondent ou utilisez des conversions (CAST/CONVERT).

### 2. Violation de contrainte PRIMARY KEY

```sql
-- ❌ ERREUR : Tentative d'insérer un EmployeID existant
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom)
SELECT EmployeID, Prenom, Nom
FROM Employes;
```

Si un `EmployeID` existe déjà dans `EmployesArchive`, l'insertion échouera.

**Solution** : Utilisez une clause `WHERE` pour exclure les doublons :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom)
SELECT EmployeID, Prenom, Nom
FROM Employes
WHERE EmployeID NOT IN (SELECT EmployeID FROM EmployesArchive);
```

### 3. Nombre de colonnes incorrect

```sql
-- ❌ ERREUR : 3 colonnes dans INSERT, 4 dans SELECT
INSERT INTO TableA (Col1, Col2, Col3)
SELECT ColW, ColX, ColY, ColZ
FROM TableB;
```

**Solution** : Assurez-vous que le nombre de colonnes correspond exactement.

## Cas d'usage pratiques

### 1. Archivage de données historiques

```sql
-- Déplacer les commandes de l'année dernière vers une table d'archives
INSERT INTO CommandesArchive (CommandeID, ClientID, DateCommande, Montant)
SELECT CommandeID, ClientID, DateCommande, Montant
FROM Commandes
WHERE YEAR(DateCommande) = 2024;
```

### 2. Création de tables de rapports

```sql
-- Créer un rapport mensuel des ventes
INSERT INTO RapportVentesMensuel (Mois, Annee, TotalVentes, NombreCommandes)
SELECT
    MONTH(DateCommande) AS Mois,
    YEAR(DateCommande) AS Annee,
    SUM(Montant) AS TotalVentes,
    COUNT(*) AS NombreCommandes
FROM Commandes
WHERE YEAR(DateCommande) = 2025
GROUP BY YEAR(DateCommande), MONTH(DateCommande);
```

### 3. Synchronisation de données entre environnements

```sql
-- Copier les données de test depuis la production (attention : à faire prudemment !)
INSERT INTO Test.dbo.Clients (ClientID, Nom, Email)
SELECT TOP 100 ClientID, Nom, Email
FROM Production.dbo.Clients
ORDER BY NEWID();  -- Ordre aléatoire
```

### 4. Duplication de données pour tests

```sql
-- Créer une copie de sauvegarde avant des modifications importantes
INSERT INTO Produits_Backup (ProduitID, Nom, Prix, Stock)
SELECT ProduitID, Nom, Prix, Stock
FROM Produits;
```

## Combinaison avec d'autres techniques

### Avec CTE (Common Table Expression)

```sql
WITH EmployesRecents AS (
    SELECT EmployeID, Prenom, Nom, Departement, Salaire
    FROM Employes
    WHERE AnneeEmbauche >= 2023
)
INSERT INTO NouveauxEmployes (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM EmployesRecents;
```

### Avec UNION

```sql
-- Combiner des données de plusieurs sources
INSERT INTO TousLesContacts (Nom, Email, Type)
SELECT Nom, Email, 'Employe' AS Type
FROM Employes
UNION ALL
SELECT Nom, Email, 'Client' AS Type
FROM Clients;
```

## Bonnes pratiques

### ✅ À faire

1. **Spécifiez toujours les colonnes** explicitement dans l'INSERT INTO
2. **Testez d'abord le SELECT** seul pour vérifier les résultats avant d'insérer
3. **Utilisez des transactions** pour les grandes insertions (pour pouvoir annuler si nécessaire)
4. **Filtrez intelligemment** avec WHERE pour éviter les doublons
5. **Vérifiez les contraintes** de la table de destination avant l'insertion
6. **Documentez votre code** : expliquez pourquoi vous copiez ces données

### ❌ À éviter

1. Ne copiez pas aveuglément toutes les données sans filtrage
2. N'oubliez pas de vérifier les violations de contraintes potentielles
3. N'utilisez pas SELECT * (soyez explicite sur les colonnes)
4. Ne lancez pas d'insertions massives sans d'abord estimer l'impact sur les performances

## Vérification après insertion

Toujours vérifier que l'insertion s'est bien déroulée :

```sql
-- Insérer les données
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom, Departement, Salaire)
SELECT EmployeID, Prenom, Nom, Departement, Salaire
FROM Employes
WHERE AnneeEmbauche < 2020;

-- Vérifier le nombre de lignes insérées
PRINT 'Nombre de lignes insérées : ' + CAST(@@ROWCOUNT AS VARCHAR(10));

-- Vérifier les données insérées
SELECT COUNT(*) AS [Total dans archive]
FROM EmployesArchive;

-- Vérifier un échantillon
SELECT TOP 5 *
FROM EmployesArchive
ORDER BY EmployeID DESC;
```

## Résumé

`INSERT INTO ... SELECT` est une technique puissante et flexible pour copier et transformer des données entre tables. Voici les points essentiels :

- **Syntaxe** : `INSERT INTO table_dest (cols) SELECT cols FROM table_source WHERE ...`
- **Flexibilité** : Permet de filtrer, transformer, calculer, et combiner des données
- **Performance** : Beaucoup plus rapide que des insertions individuelles
- **Jointures** : Peut combiner des données de plusieurs tables
- **Agrégation** : Peut insérer des données résumées (GROUP BY, COUNT, AVG, etc.)
- **Atomicité** : Tout ou rien - soit toutes les lignes sont insérées, soit aucune

### Comparaison des méthodes d'insertion

| Méthode | Cas d'usage | Performance |
|---------|-------------|-------------|
| INSERT ... VALUES | Valeurs fixes, peu de lignes | Moyenne |
| INSERT ... VALUES (multiple) | Valeurs fixes, plusieurs lignes | Bonne |
| INSERT ... SELECT | Copie/transformation de données | Excellente |
| SELECT INTO | Création rapide de table + insertion | Excellente |
