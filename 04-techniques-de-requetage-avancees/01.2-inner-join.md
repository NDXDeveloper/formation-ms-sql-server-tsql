# 4.1.2 INNER JOIN (Intersection)

## Introduction

Maintenant que vous comprenez le concept du produit cartésien, nous allons découvrir le type de jointure le plus couramment utilisé en SQL : **l'INNER JOIN**.

L'INNER JOIN est la jointure par défaut et la plus intuitive. Elle permet de combiner des données provenant de deux tables en ne conservant **que les lignes qui ont une correspondance dans les deux tables**.

C'est un peu comme si vous cherchiez à associer des personnes qui ont un intérêt commun : seules les personnes qui partagent cet intérêt seront retenues dans le résultat final.

---

## Qu'est-ce qu'un INNER JOIN ?

### Définition

Un **INNER JOIN** (jointure interne) retourne uniquement les lignes pour lesquelles il existe une correspondance entre les deux tables, selon la condition de jointure spécifiée.

En termes d'ensembles mathématiques, l'INNER JOIN représente **l'intersection** des deux tables.

### Analogie visuelle : Le diagramme de Venn

Imaginez deux cercles qui se chevauchent (diagramme de Venn) :

```
        Table A              Table B
          ___                  ___
         /   \                /   \
        |     \              /     |
        |      \    ____    /      |
        |       \  /    \  /       |
        |        \/      \/        |
        |        /\      /\        |
        |       /  \____/  \       |
        |      /            \      |
        |     /              \     |
         \___/                \___/

         A seulement    INTERSECTION    B seulement
                       (INNER JOIN)
```

L'**INNER JOIN** ne retourne que la partie centrale où les deux cercles se chevauchent, c'est-à-dire les données qui existent **dans les deux tables**.

---

## Syntaxe de l'INNER JOIN

### Syntaxe de base

```sql
SELECT colonnes
FROM Table1
INNER JOIN Table2 ON condition_de_jointure;
```

### Décomposition de la syntaxe

- **SELECT colonnes** : Les colonnes que vous souhaitez afficher dans le résultat
- **FROM Table1** : La première table (souvent appelée table de gauche)
- **INNER JOIN Table2** : La deuxième table à joindre (souvent appelée table de droite)
- **ON condition_de_jointure** : La condition qui détermine comment les lignes des deux tables doivent être associées

### Note sur le mot-clé INNER

Le mot-clé `INNER` est optionnel. Ces deux syntaxes sont strictement équivalentes :

```sql
-- Avec INNER (explicite et recommandé)
SELECT * FROM Clients INNER JOIN Commandes ON Clients.ClientID = Commandes.ClientID;

-- Sans INNER (implicite)
SELECT * FROM Clients JOIN Commandes ON Clients.ClientID = Commandes.ClientID;
```

**Bonne pratique** : Il est recommandé d'écrire explicitement `INNER JOIN` pour rendre le code plus lisible et éviter toute ambiguïté.

---

## Exemple complet et détaillé

### Contexte : Tables de départ

Reprenons nos tables d'exemple d'une boutique en ligne :

**Table `Clients`**

| ClientID | NomClient | Ville      |
|----------|-----------|------------|
| 1        | Dupont    | Paris      |
| 2        | Martin    | Lyon       |
| 3        | Bernard   | Marseille  |
| 4        | Dubois    | Toulouse   |

**Table `Commandes`**

| CommandeID | ClientID | Montant | DateCommande |
|------------|----------|---------|--------------|
| 101        | 1        | 150€    | 2025-01-15   |
| 102        | 2        | 200€    | 2025-01-16   |
| 103        | 1        | 75€     | 2025-01-17   |
| 104        | 5        | 300€    | 2025-01-18   |

### Observations importantes

- Le client **Dupont** (ClientID = 1) a passé **2 commandes** (101 et 103)
- Le client **Martin** (ClientID = 2) a passé **1 commande** (102)
- Le client **Bernard** (ClientID = 3) n'a passé **aucune commande**
- Le client **Dubois** (ClientID = 4) n'a passé **aucune commande**
- La commande 104 fait référence au ClientID = 5 qui **n'existe pas** dans la table Clients

### Requête INNER JOIN

```sql
SELECT
    Clients.ClientID,
    Clients.NomClient,
    Clients.Ville,
    Commandes.CommandeID,
    Commandes.Montant,
    Commandes.DateCommande
FROM Clients
INNER JOIN Commandes ON Clients.ClientID = Commandes.ClientID;
```

### Résultat

| ClientID | NomClient | Ville | CommandeID | Montant | DateCommande |
|----------|-----------|-------|------------|---------|--------------|
| 1        | Dupont    | Paris | 101        | 150€    | 2025-01-15   |
| 1        | Dupont    | Paris | 103        | 75€     | 2025-01-17   |
| 2        | Martin    | Lyon  | 102        | 200€    | 2025-01-16   |

### Analyse du résultat

**Ce qui est inclus :**
- Dupont apparaît **2 fois** (car il a 2 commandes)
- Martin apparaît **1 fois** (car il a 1 commande)

**Ce qui est exclu :**
- Bernard et Dubois **n'apparaissent pas** (ils n'ont aucune commande)
- La commande 104 **n'apparaît pas** (le ClientID = 5 n'existe pas dans la table Clients)

**Règle d'or de l'INNER JOIN** : Seules les lignes qui ont une correspondance **dans les deux tables** sont retournées.

## Fonctionnement étape par étape

Voici comment SQL Server traite un INNER JOIN :

### Étape 1 : Création du produit cartésien

SQL Server commence par générer mentalement toutes les combinaisons possibles entre les tables Clients (4 lignes) et Commandes (4 lignes), soit 4 × 4 = 16 combinaisons potentielles.

### Étape 2 : Application de la condition ON

SQL Server applique ensuite la condition `Clients.ClientID = Commandes.ClientID` pour filtrer le produit cartésien :

```
Dupont (ID=1)   +   Commande 101 (ClientID=1)   ✓ Correspond
Dupont (ID=1)   +   Commande 102 (ClientID=2)   ✗ Ne correspond pas
Dupont (ID=1)   +   Commande 103 (ClientID=1)   ✓ Correspond
Dupont (ID=1)   +   Commande 104 (ClientID=5)   ✗ Ne correspond pas

Martin (ID=2)   +   Commande 101 (ClientID=1)   ✗ Ne correspond pas
Martin (ID=2)   +   Commande 102 (ClientID=2)   ✓ Correspond
Martin (ID=2)   +   Commande 103 (ClientID=1)   ✗ Ne correspond pas
Martin (ID=2)   +   Commande 104 (ClientID=5)   ✗ Ne correspond pas

Bernard (ID=3)  +   Commande 101 (ClientID=1)   ✗ Ne correspond pas
Bernard (ID=3)  +   Commande 102 (ClientID=2)   ✗ Ne correspond pas
Bernard (ID=3)  +   Commande 103 (ClientID=1)   ✗ Ne correspond pas
Bernard (ID=3)  +   Commande 104 (ClientID=5)   ✗ Ne correspond pas

Dubois (ID=4)   +   Commande 101 (ClientID=1)   ✗ Ne correspond pas
Dubois (ID=4)   +   Commande 102 (ClientID=2)   ✗ Ne correspond pas
Dubois (ID=4)   +   Commande 103 (ClientID=1)   ✗ Ne correspond pas
Dubois (ID=4)   +   Commande 104 (ClientID=5)   ✗ Ne correspond pas
```

### Étape 3 : Résultat final

Seules les combinaisons marquées ✓ sont conservées, d'où les **3 lignes** dans le résultat final.

## Utilisation des alias de tables

Pour améliorer la lisibilité, on utilise souvent des **alias** (raccourcis) pour les noms de tables :

### Sans alias (verbose)

```sql
SELECT
    Clients.ClientID,
    Clients.NomClient,
    Commandes.CommandeID,
    Commandes.Montant
FROM Clients
INNER JOIN Commandes ON Clients.ClientID = Commandes.ClientID;
```

### Avec alias (concis)

```sql
SELECT
    C.ClientID,
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients AS C
INNER JOIN Commandes AS CMD ON C.ClientID = CMD.ClientID;
```

Le mot-clé `AS` est optionnel, vous pouvez écrire simplement :

```sql
SELECT
    C.ClientID,
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Avantages des alias :**
- Code plus court et plus facile à lire
- Indispensable quand on travaille avec de nombreuses tables
- Obligatoire pour les auto-jointures (que nous verrons plus tard)

---

## Jointures sur plusieurs colonnes

Parfois, la correspondance entre deux tables nécessite plusieurs colonnes. On peut combiner plusieurs conditions avec `AND` :

### Exemple

```sql
SELECT
    A.ColonneA,
    B.ColonneB
FROM TableA A
INNER JOIN TableB B ON A.Colonne1 = B.Colonne1
                    AND A.Colonne2 = B.Colonne2;
```

Cette requête ne retourne que les lignes où **les deux conditions sont vraies simultanément**.

### Cas d'usage réel

Imaginons une table `Livraisons` avec une clé composite (ClientID + CommandeID) :

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    L.DateLivraison
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
INNER JOIN Livraisons L ON L.ClientID = CMD.ClientID
                        AND L.CommandeID = CMD.CommandeID;
```

---

## Jointures multiples (plus de 2 tables)

Vous pouvez enchaîner plusieurs INNER JOIN pour joindre 3, 4 tables ou plus :

### Exemple avec 3 tables

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    P.NomProduit,
    D.Quantite
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
INNER JOIN DetailsCommande D ON CMD.CommandeID = D.CommandeID
INNER JOIN Produits P ON D.ProduitID = P.ProduitID;
```

### Ordre de lecture

SQL Server traite les jointures **de haut en bas** :
1. Joint d'abord `Clients` avec `Commandes`
2. Puis joint le résultat avec `DetailsCommande`
3. Enfin joint avec `Produits`

**Important** : Seules les lignes qui ont des correspondances **dans toutes les tables** seront retournées.

---

## Conditions supplémentaires avec WHERE

Vous pouvez ajouter des filtres supplémentaires après la jointure avec la clause `WHERE` :

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.Montant > 100;
```

### Différence entre ON et WHERE

- **ON** : Définit la condition de jointure (comment les tables sont reliées)
- **WHERE** : Filtre le résultat final après la jointure

### Exemple illustrant la différence

```sql
-- Filtre dans ON (pas recommandé pour INNER JOIN)
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID AND CMD.Montant > 100;

-- Filtre dans WHERE (recommandé et plus clair)
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.Montant > 100;
```

Pour un INNER JOIN, ces deux requêtes donnent le **même résultat**, mais la seconde est plus lisible car elle sépare clairement :
- La logique de jointure (ON)
- La logique de filtrage métier (WHERE)

**Note** : Cette distinction devient cruciale pour les LEFT/RIGHT JOIN (que nous verrons plus tard).

---

## Comparaison avec l'ancienne syntaxe

Avant la norme SQL-92, on utilisait une syntaxe différente avec des virgules et WHERE :

### Ancienne syntaxe (à éviter)

```sql
SELECT
    C.NomClient,
    CMD.CommandeID
FROM Clients C, Commandes CMD
WHERE C.ClientID = CMD.ClientID;
```

### Syntaxe moderne (recommandée)

```sql
SELECT
    C.NomClient,
    CMD.CommandeID
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### Pourquoi préférer la syntaxe moderne ?

1. **Lisibilité** : La condition de jointure est clairement séparée des autres filtres
2. **Maintenabilité** : Plus facile à comprendre et à modifier
3. **Sécurité** : Réduit le risque d'oublier une condition de jointure (produit cartésien accidentel)
4. **Cohérence** : Syntaxe uniforme avec LEFT/RIGHT/FULL JOIN
5. **Standard** : Respecte les normes SQL modernes

## Cas d'usage courants de l'INNER JOIN

### 1. Enrichir des données avec des informations de référence

Associer des codes à leurs libellés :

```sql
SELECT
    V.NumeroVente,
    V.Montant,
    C.NomCategorie
FROM Ventes V
INNER JOIN Categories C ON V.CategorieID = C.CategorieID;
```

### 2. Rapports et analyses

Créer des rapports combinant plusieurs sources de données :

```sql
SELECT
    E.NomEmploye,
    D.NomDepartement,
    E.Salaire
FROM Employes E
INNER JOIN Departements D ON E.DepartementID = D.DepartementID;
```

### 3. Vérification d'existence

Trouver les enregistrements qui existent dans les deux tables :

```sql
-- Clients qui ont passé au moins une commande
SELECT DISTINCT C.ClientID, C.NomClient
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### 4. Agrégations avec données reliées

Calculer des statistiques sur des données jointes :

```sql
SELECT
    C.NomClient,
    COUNT(CMD.CommandeID) AS NombreCommandes,
    SUM(CMD.Montant) AS TotalDepense
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.ClientID, C.NomClient;
```

## Gestion des colonnes avec le même nom

Lorsque deux tables ont des colonnes avec le même nom (comme `ClientID`), vous devez **obligatoirement** préfixer le nom de la colonne par le nom de la table ou son alias :

### Erreur : Ambiguïté

```sql
-- ❌ ERREUR : Ambiguous column name 'ClientID'
SELECT ClientID, NomClient, Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### Correction : Spécifier la table

```sql
-- ✓ CORRECT
SELECT
    C.ClientID,      -- ou CMD.ClientID, les deux ont la même valeur ici
    C.NomClient,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### Bonne pratique

Même pour les colonnes sans ambiguïté, il est recommandé de toujours préfixer les colonnes avec l'alias de la table pour :
- Améliorer la lisibilité
- Faciliter la maintenance
- Éviter les erreurs futures si les schémas changent

## Performances et index

### Impact des index

Les performances des INNER JOIN dépendent fortement de la présence d'**index** sur les colonnes de jointure.

**Sans index** : SQL Server doit scanner toutes les lignes des deux tables (lent)  
**Avec index** : SQL Server peut utiliser l'index pour trouver rapidement les correspondances (rapide)  

### Recommandations

- Les colonnes utilisées dans les conditions de jointure (souvent des clés étrangères) doivent idéalement être indexées
- Les clés primaires sont automatiquement indexées
- Les clés étrangères ne le sont **pas automatiquement** dans SQL Server

### Exemple de création d'index pour optimiser une jointure

```sql
-- Créer un index sur la colonne ClientID de la table Commandes
CREATE INDEX IX_Commandes_ClientID ON Commandes(ClientID);
```

---

## Erreurs courantes à éviter

### 1. Oublier la condition ON

```sql
-- ❌ ERREUR DE SYNTAXE
SELECT * FROM Clients C
INNER JOIN Commandes CMD;
```

Cette requête génère une erreur car la clause `ON` est obligatoire pour un INNER JOIN.

### 2. Utiliser WHERE au lieu de ON

```sql
-- ❌ MAUVAIS : Fonctionne mais peu lisible
SELECT * FROM Clients C, Commandes CMD
WHERE C.ClientID = CMD.ClientID;
```

Bien que cette syntaxe fonctionne, préférez toujours la syntaxe `INNER JOIN ... ON`.

### 3. Produit cartésien accidentel

```sql
-- ❌ ERREUR : Produit cartésien (oubli de condition)
SELECT * FROM Clients C
INNER JOIN Commandes CMD ON 1=1;  -- Condition toujours vraie !
```

Cette requête retourne toutes les combinaisons possibles (16 lignes dans notre exemple).

### 4. Confusion entre colonnes de jointure

```sql
-- ❌ ERREUR LOGIQUE : Mauvaise colonne
SELECT * FROM Clients C
INNER JOIN Commandes CMD ON C.NomClient = CMD.Montant;
```

Cette requête fonctionne syntaxiquement, mais n'a aucun sens logique (comparer un nom avec un montant).

---

## Points clés à retenir

1. **L'INNER JOIN** retourne uniquement les lignes qui ont une correspondance **dans les deux tables**.

2. **Syntaxe** : `FROM Table1 INNER JOIN Table2 ON condition`

3. **Le mot-clé INNER** est optionnel mais recommandé pour la clarté.

4. **L'INNER JOIN** représente **l'intersection** des deux tables en termes mathématiques.

5. **Les lignes sans correspondance** sont automatiquement exclues du résultat.

6. **Vous pouvez joindre** plusieurs tables en enchaînant plusieurs INNER JOIN.

7. **Utilisez des alias** pour améliorer la lisibilité de vos requêtes.

8. **La clause ON** définit comment les tables sont reliées, la clause **WHERE** filtre ensuite le résultat.

9. **Les performances** dépendent des index sur les colonnes de jointure.

10. **L'INNER JOIN est le type de jointure le plus courant** en SQL (environ 80% des cas d'usage).

---

## Quand utiliser un INNER JOIN ?

Utilisez un INNER JOIN quand :

- ✅ Vous voulez uniquement les données qui existent dans **les deux tables**
- ✅ Les lignes sans correspondance ne vous intéressent pas
- ✅ Vous cherchez une intersection de données
- ✅ Vous voulez enrichir des données avec des informations de référence

N'utilisez PAS un INNER JOIN quand :

- ❌ Vous voulez conserver toutes les lignes d'une table même sans correspondance → Utilisez LEFT JOIN ou RIGHT JOIN
- ❌ Vous voulez toutes les lignes des deux tables → Utilisez FULL OUTER JOIN
- ❌ Vous voulez toutes les combinaisons possibles → Utilisez CROSS JOIN

---

## En résumé

L'**INNER JOIN** est le type de jointure le plus simple et le plus utilisé. Il permet de combiner des données de plusieurs tables en ne gardant que les enregistrements qui ont une correspondance des deux côtés.

C'est l'outil idéal quand vous voulez répondre à des questions comme :
- "Quels clients ont passé des commandes ?"
- "Quels produits ont été vendus ?"
- "Quels employés travaillent dans quels départements ?"

Maintenant que vous maîtrisez l'INNER JOIN, vous êtes prêt à découvrir les jointures externes (LEFT JOIN, RIGHT JOIN, FULL JOIN) qui permettent de gérer les cas où des correspondances peuvent ne pas exister dans l'une ou l'autre table !
