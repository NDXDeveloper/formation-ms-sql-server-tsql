# 4.5.5 Fonctions de décalage (LAG, LEAD)

## Introduction aux fonctions de décalage

Les **fonctions de décalage** (ou *offset functions*) permettent d'accéder aux valeurs d'autres lignes **sans avoir besoin de jointures**. Elles sont extrêmement utiles pour comparer une ligne avec les lignes précédentes ou suivantes dans un jeu de résultats ordonné.

Les deux fonctions principales sont :
- **LAG()** : Accède aux valeurs des lignes **précédentes** (vers le haut)
- **LEAD()** : Accède aux valeurs des lignes **suivantes** (vers le bas)

### Pourquoi utiliser LAG et LEAD ?

Avant ces fonctions, pour comparer une ligne avec la précédente, il fallait :
- Des auto-jointures complexes
- Des sous-requêtes corrélées
- Des curseurs (très lents)

Avec LAG et LEAD, c'est **simple, lisible et performant** !

## 1. LAG() - Accéder aux valeurs précédentes

### Concept

`LAG()` permet de "regarder en arrière" et récupérer la valeur d'une colonne d'une ligne **précédente**.

### Analogie simple

Imaginez une file de personnes :
- Vous êtes la personne n°5
- `LAG()` vous permet de voir les informations de la personne n°4 (ou n°3, ou n°1...) devant vous

### Syntaxe

```sql
LAG(colonne [, decalage] [, valeur_par_defaut])
    OVER([PARTITION BY colonne1, ...] ORDER BY colonne2, ...)
```

**Paramètres** :
- **colonne** : La colonne dont vous voulez récupérer la valeur
- **décalage** : Nombre de lignes en arrière (par défaut = 1)
- **valeur_par_défaut** : Valeur si la ligne n'existe pas (par défaut = NULL)
- **ORDER BY** : Obligatoire (définit l'ordre de navigation)

### Exemple de base : LAG avec 1 ligne de décalage

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes) OVER(ORDER BY Mois) AS VentesMoisPrecedent
FROM VentesMensuelles;
```

**Données :**

| Mois | Ventes |
|------|--------|
| Janvier | 10000 |
| Février | 15000 |
| Mars | 12000 |
| Avril | 18000 |

**Résultat :**

| Mois | Ventes | VentesMoisPrecedent |
|------|--------|---------------------|
| Janvier | 10000 | NULL |
| Février | 15000 | 10000 |
| Mars | 12000 | 15000 |
| Avril | 18000 | 12000 |

**Explication** :
- **Janvier** : Pas de mois précédent → NULL
- **Février** : Ventes du mois précédent (Janvier) = 10000
- **Mars** : Ventes du mois précédent (Février) = 15000
- **Avril** : Ventes du mois précédent (Mars) = 12000

### Calcul de variation avec LAG

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes) OVER(ORDER BY Mois) AS VentesMoisPrecedent,
    Ventes - LAG(Ventes) OVER(ORDER BY Mois) AS Variation,
    CAST(
        (Ventes - LAG(Ventes) OVER(ORDER BY Mois)) * 100.0 /
        LAG(Ventes) OVER(ORDER BY Mois)
    AS DECIMAL(5,2)) AS VariationPct
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisPrecedent | Variation | VariationPct |
|------|--------|---------------------|-----------|--------------|
| Janvier | 10000 | NULL | NULL | NULL |
| Février | 15000 | 10000 | +5000 | +50.00 |
| Mars | 12000 | 15000 | -3000 | -20.00 |
| Avril | 18000 | 12000 | +6000 | +50.00 |

Vous voyez immédiatement l'évolution mois par mois !

### LAG avec un décalage de 2 lignes

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes, 1) OVER(ORDER BY Mois) AS VentesMoisPrecedent,
    LAG(Ventes, 2) OVER(ORDER BY Mois) AS VentesIl2Mois
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisPrecedent | VentesIl2Mois |
|------|--------|---------------------|---------------|
| Janvier | 10000 | NULL | NULL |
| Février | 15000 | 10000 | NULL |
| Mars | 12000 | 15000 | 10000 |
| Avril | 18000 | 12000 | 15000 |
| Mai | 14000 | 18000 | 12000 |

**Explication pour Mars** :
- **VentesMoisPrecedent** : Février (1 ligne avant) = 15000
- **VentesIl2Mois** : Janvier (2 lignes avant) = 10000

### LAG avec valeur par défaut

Au lieu d'avoir NULL pour la première ligne, vous pouvez spécifier une valeur par défaut :

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes, 1, 0) OVER(ORDER BY Mois) AS VentesMoisPrecedent
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisPrecedent |
|------|--------|---------------------|
| Janvier | 10000 | 0 |
| Février | 15000 | 10000 |
| Mars | 12000 | 15000 |

Maintenant, au lieu de NULL, la première ligne affiche **0**.

## 2. LEAD() - Accéder aux valeurs suivantes

### Concept

`LEAD()` permet de "regarder en avant" et récupérer la valeur d'une colonne d'une ligne **suivante**.

### Analogie simple

Dans la même file de personnes :
- Vous êtes la personne n°5
- `LEAD()` vous permet de voir les informations de la personne n°6 (ou n°7, ou n°10...) derrière vous

### Syntaxe

```sql
LEAD(colonne [, decalage] [, valeur_par_defaut])
    OVER([PARTITION BY colonne1, ...] ORDER BY colonne2, ...)
```

Les paramètres sont identiques à `LAG()`, mais la navigation se fait vers **l'avant**.

### Exemple de base : LEAD avec 1 ligne de décalage

```sql
SELECT
    Mois,
    Ventes,
    LEAD(Ventes) OVER(ORDER BY Mois) AS VentesMoisSuivant
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisSuivant |
|------|--------|-------------------|
| Janvier | 10000 | 15000 |
| Février | 15000 | 12000 |
| Mars | 12000 | 18000 |
| Avril | 18000 | NULL |

**Explication** :
- **Janvier** : Ventes du mois suivant (Février) = 15000
- **Février** : Ventes du mois suivant (Mars) = 12000
- **Mars** : Ventes du mois suivant (Avril) = 18000
- **Avril** : Pas de mois suivant → NULL

### Prévision vs Réalité

```sql
SELECT
    Mois,
    VentesReelles,
    LEAD(VentesReelles) OVER(ORDER BY Mois) AS VentesReellesMoisSuivant,
    Prevision,
    LEAD(VentesReelles) OVER(ORDER BY Mois) - Prevision AS EcartPrevision
FROM VentesAvecPrevisions;
```

Compare la prévision du mois actuel avec les ventes réelles du mois suivant.

### LEAD avec un décalage de 2 lignes

```sql
SELECT
    Mois,
    Ventes,
    LEAD(Ventes, 1) OVER(ORDER BY Mois) AS VentesMoisSuivant,
    LEAD(Ventes, 2) OVER(ORDER BY Mois) AS VentesDans2Mois
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisSuivant | VentesDans2Mois |
|------|--------|-------------------|-----------------|
| Janvier | 10000 | 15000 | 12000 |
| Février | 15000 | 12000 | 18000 |
| Mars | 12000 | 18000 | 14000 |
| Avril | 18000 | 14000 | NULL |
| Mai | 14000 | NULL | NULL |

## 3. Combinaison LAG et LEAD

Vous pouvez utiliser LAG et LEAD dans la même requête pour une vue complète :

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes) OVER(ORDER BY Mois) AS VentesMoisPrecedent,
    LEAD(Ventes) OVER(ORDER BY Mois) AS VentesMoisSuivant,
    (LAG(Ventes) OVER(ORDER BY Mois) +
     Ventes +
     LEAD(Ventes) OVER(ORDER BY Mois)) / 3.0 AS MoyenneMobile3
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesMoisPrecedent | VentesMoisSuivant | MoyenneMobile3 |
|------|--------|---------------------|-------------------|----------------|
| Janvier | 10000 | NULL | 15000 | NULL |
| Février | 15000 | 10000 | 12000 | 12333.33 |
| Mars | 12000 | 15000 | 18000 | 15000.00 |
| Avril | 18000 | 12000 | NULL | NULL |

**Mars** affiche la moyenne de Février (15000), Mars (12000) et Avril (18000) = 15000.

## 4. LAG et LEAD avec PARTITION BY

La vraie puissance de ces fonctions se révèle avec `PARTITION BY` : vous pouvez comparer **à l'intérieur de chaque groupe**.

### Exemple : Ventes par vendeur

```sql
SELECT
    Vendeur,
    Mois,
    Ventes,
    LAG(Ventes) OVER(PARTITION BY Vendeur ORDER BY Mois) AS VentesMoisPrecedent,
    Ventes - LAG(Ventes) OVER(PARTITION BY Vendeur ORDER BY Mois) AS Variation
FROM VentesVendeurs;
```

**Données :**

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Martin | Jan | 5000 |
| Martin | Fév | 7000 |
| Martin | Mar | 6000 |
| Durand | Jan | 4000 |
| Durand | Fév | 5000 |
| Durand | Mar | 6500 |

**Résultat :**

| Vendeur | Mois | Ventes | VentesMoisPrecedent | Variation |
|---------|------|--------|---------------------|-----------|
| Martin | Jan | 5000 | NULL | NULL |
| Martin | Fév | 7000 | 5000 | +2000 |
| Martin | Mar | 6000 | 7000 | -1000 |
| Durand | Jan | 4000 | NULL | NULL |
| Durand | Fév | 5000 | 4000 | +1000 |
| Durand | Mar | 6500 | 5000 | +1500 |

**Le compteur LAG redémarre pour chaque vendeur !**

### Exemple : Ventes par produit et région

```sql
SELECT
    Region,
    Produit,
    Annee,
    Ventes,
    LAG(Ventes) OVER(
        PARTITION BY Region, Produit
        ORDER BY Annee
    ) AS VentesAnneePrecedente,
    CAST(
        (Ventes - LAG(Ventes) OVER(PARTITION BY Region, Produit ORDER BY Annee)) * 100.0 /
        LAG(Ventes) OVER(PARTITION BY Region, Produit ORDER BY Annee)
    AS DECIMAL(5,2)) AS CroissancePct
FROM VentesRegionales;
```

Compare les ventes année par année pour **chaque combinaison** de région et produit.

## 5. Cas d'usage pratiques

### A. Détection de changements d'état

```sql
SELECT
    Date,
    ClientID,
    Statut,
    LAG(Statut) OVER(PARTITION BY ClientID ORDER BY Date) AS StatutPrecedent,
    CASE
        WHEN Statut <> LAG(Statut) OVER(PARTITION BY ClientID ORDER BY Date)
        THEN 'Changement'
        ELSE 'Stable'
    END AS TypeEvenement
FROM HistoriqueStatutClients;
```

**Résultat :**

| Date | ClientID | Statut | StatutPrecedent | TypeEvenement |
|------|----------|--------|-----------------|---------------|
| 2024-01-01 | 100 | Actif | NULL | Stable |
| 2024-02-01 | 100 | Actif | Actif | Stable |
| 2024-03-01 | 100 | Inactif | Actif | Changement |
| 2024-04-01 | 100 | Inactif | Inactif | Stable |

Détecte automatiquement quand un client change de statut.

### B. Calcul de durée entre événements

```sql
SELECT
    ClientID,
    DateCommande,
    LEAD(DateCommande) OVER(PARTITION BY ClientID ORDER BY DateCommande) AS DateCommandeSuivante,
    DATEDIFF(
        DAY,
        DateCommande,
        LEAD(DateCommande) OVER(PARTITION BY ClientID ORDER BY DateCommande)
    ) AS JoursEntreCommandes
FROM Commandes;
```

**Résultat :**

| ClientID | DateCommande | DateCommandeSuivante | JoursEntreCommandes |
|----------|--------------|----------------------|---------------------|
| 100 | 2024-01-05 | 2024-02-10 | 36 |
| 100 | 2024-02-10 | 2024-03-15 | 34 |
| 100 | 2024-03-15 | NULL | NULL |

Calcule automatiquement le nombre de jours entre les achats d'un client.

### C. Identification du premier et dernier événement

```sql
SELECT
    Employe,
    DatePromotion,
    NouveauTitre,
    LAG(NouveauTitre) OVER(PARTITION BY Employe ORDER BY DatePromotion) AS TitrePrecedent,
    CASE
        WHEN LAG(NouveauTitre) OVER(PARTITION BY Employe ORDER BY DatePromotion) IS NULL
        THEN 'Première promotion'
        ELSE 'Promotion suivante'
    END AS TypePromotion
FROM HistoriquePromotions;
```

### D. Comparaison avec plusieurs périodes précédentes

```sql
SELECT
    Trimestre,
    ChiffreAffaires,
    LAG(ChiffreAffaires, 1) OVER(ORDER BY Trimestre) AS CA_Trim_Precedent,
    LAG(ChiffreAffaires, 4) OVER(ORDER BY Trimestre) AS CA_MemeTrimestreAnneePrecedente,
    ChiffreAffaires - LAG(ChiffreAffaires, 1) OVER(ORDER BY Trimestre) AS Variation_Trimestrielle,
    ChiffreAffaires - LAG(ChiffreAffaires, 4) OVER(ORDER BY Trimestre) AS Variation_Annuelle
FROM VentesTrimestrielles;
```

**Résultat :**

| Trimestre | ChiffreAffaires | CA_Trim_Precedent | CA_MemeTrimestreAnneePrecedente | Variation_Trimestrielle | Variation_Annuelle |
|-----------|-----------------|-------------------|---------------------------------|-------------------------|-------------------|
| 2023-Q1 | 100000 | NULL | NULL | NULL | NULL |
| 2023-Q2 | 120000 | 100000 | NULL | +20000 | NULL |
| 2023-Q3 | 115000 | 120000 | NULL | -5000 | NULL |
| 2023-Q4 | 130000 | 115000 | NULL | +15000 | NULL |
| 2024-Q1 | 110000 | 130000 | 100000 | -20000 | +10000 |

**2024-Q1** compare avec :
- **Trimestre précédent** (2023-Q4) : 130000
- **Même trimestre année précédente** (2023-Q1) : 100000

### E. Détection de séquences

```sql
SELECT
    Date,
    Temperature,
    LAG(Temperature, 1) OVER(ORDER BY Date) AS TempHier,
    LAG(Temperature, 2) OVER(ORDER BY Date) AS TempAvantHier,
    CASE
        WHEN Temperature > LAG(Temperature, 1) OVER(ORDER BY Date)
         AND LAG(Temperature, 1) OVER(ORDER BY Date) > LAG(Temperature, 2) OVER(ORDER BY Date)
        THEN 'Hausse 3 jours consécutifs'
        ELSE 'Autre'
    END AS Tendance
FROM Meteo;
```

Détecte quand la température augmente 3 jours de suite.

### F. Gap Analysis (recherche de trous)

```sql
SELECT
    NumeroCommande,
    LEAD(NumeroCommande) OVER(ORDER BY NumeroCommande) AS NumeroCommandeSuivant,
    LEAD(NumeroCommande) OVER(ORDER BY NumeroCommande) - NumeroCommande AS Ecart,
    CASE
        WHEN LEAD(NumeroCommande) OVER(ORDER BY NumeroCommande) - NumeroCommande > 1
        THEN 'Numéros manquants'
        ELSE 'OK'
    END AS Statut
FROM Commandes;
```

**Résultat :**

| NumeroCommande | NumeroCommandeSuivant | Ecart | Statut |
|----------------|----------------------|-------|--------|
| 1001 | 1002 | 1 | OK |
| 1002 | 1003 | 1 | OK |
| 1003 | 1007 | 4 | Numéros manquants |
| 1007 | 1008 | 1 | OK |

Identifie les numéros de commande manquants (1004, 1005, 1006).

## 6. Comparaison avec d'autres méthodes

### Avant LAG/LEAD : Auto-jointure

**Ancienne méthode (complexe et lente)** :

```sql
SELECT
    V1.Mois,
    V1.Ventes,
    V2.Ventes AS VentesMoisPrecedent
FROM VentesMensuelles V1
LEFT JOIN VentesMensuelles V2
    ON V1.MoisNumero = V2.MoisNumero + 1;
```

**Méthode moderne (simple et rapide)** :

```sql
SELECT
    Mois,
    Ventes,
    LAG(Ventes) OVER(ORDER BY Mois) AS VentesMoisPrecedent
FROM VentesMensuelles;
```

### Avantages de LAG/LEAD

| Aspect | Auto-jointure | LAG/LEAD |
|--------|--------------|----------|
| **Lisibilité** | Complexe | Simple et clair |
| **Performance** | Plus lent | Optimisé |
| **Maintenance** | Difficile | Facile |
| **Décalages multiples** | Jointures multiples | Un seul paramètre |
| **NULL handling** | Gestion manuelle | Valeur par défaut intégrée |

## 7. Gestion des valeurs NULL

### NULL dans la colonne source

Si la colonne que vous regardez contient des NULL, `LAG()` et `LEAD()` retournent NULL :

```sql
SELECT
    Date,
    Temperature, -- Peut être NULL
    LAG(Temperature) OVER(ORDER BY Date) AS TemperatureHier
FROM Meteo;
```

Si Temperature d'hier était NULL, vous obtenez NULL.

### Remplacer les NULL

Utilisez `ISNULL()` ou `COALESCE()` :

```sql
SELECT
    Date,
    Temperature,
    ISNULL(LAG(Temperature) OVER(ORDER BY Date), 0) AS TemperatureHier
FROM Meteo;
```

Ou avec la valeur par défaut de LAG :

```sql
SELECT
    Date,
    Temperature,
    LAG(Temperature, 1, 0) OVER(ORDER BY Date) AS TemperatureHier
FROM Meteo;
```

### Ignorer les NULL et prendre la valeur non-NULL précédente

C'est plus complexe, mais possible avec un CTE :

```sql
WITH DonneesAvecGroupe AS (
    SELECT
        Date,
        Temperature,
        SUM(CASE WHEN Temperature IS NOT NULL THEN 1 ELSE 0 END)
            OVER(ORDER BY Date) AS GroupeNonNull
    FROM Meteo
)
SELECT
    Date,
    Temperature,
    FIRST_VALUE(Temperature) OVER(
        PARTITION BY GroupeNonNull
        ORDER BY Date
    ) AS DerniereTemperatureNonNull
FROM DonneesAvecGroupe;
```

## 8. LAG/LEAD avec expressions

Vous pouvez utiliser des expressions, pas seulement des colonnes :

### LAG/LEAD sur des calculs

```sql
SELECT
    Mois,
    Ventes,
    Couts,
    Ventes - Couts AS Profit,
    LAG(Ventes - Couts) OVER(ORDER BY Mois) AS ProfitMoisPrecedent,
    (Ventes - Couts) - LAG(Ventes - Couts) OVER(ORDER BY Mois) AS VariationProfit
FROM Finances;
```

### LAG/LEAD avec CASE

```sql
SELECT
    Date,
    Ventes,
    CASE
        WHEN Ventes > LAG(Ventes) OVER(ORDER BY Date) THEN 'Hausse'
        WHEN Ventes < LAG(Ventes) OVER(ORDER BY Date) THEN 'Baisse'
        ELSE 'Stable'
    END AS Tendance
FROM VentesQuotidiennes;
```

## 9. Performance et bonnes pratiques

### 1. Index appropriés

Les fonctions LAG/LEAD bénéficient d'index sur :
- Les colonnes dans **PARTITION BY**
- Les colonnes dans **ORDER BY**

```sql
-- Cette requête bénéficiera d'un index sur (Vendeur, Date)
CREATE INDEX IX_Ventes_Vendeur_Date ON Ventes(Vendeur, Date);

SELECT
    LAG(Montant) OVER(PARTITION BY Vendeur ORDER BY Date)
FROM Ventes;
```

### 2. Éviter les calculs redondants

**Mauvais** : Appeler LAG plusieurs fois avec les mêmes paramètres

```sql
SELECT
    Ventes,
    LAG(Ventes) OVER(ORDER BY Date),
    Ventes - LAG(Ventes) OVER(ORDER BY Date),
    Ventes / LAG(Ventes) OVER(ORDER BY Date)
FROM VentesMensuelles;
```

**Meilleur** : Utiliser un CTE

```sql
WITH VentesAvecPrecedent AS (
    SELECT
        Ventes,
        LAG(Ventes) OVER(ORDER BY Date) AS VentesPrecedentes
    FROM VentesMensuelles
)
SELECT
    Ventes,
    VentesPrecedentes,
    Ventes - VentesPrecedentes AS Variation,
    CAST(Ventes * 1.0 / VentesPrecedentes AS DECIMAL(5,2)) AS Ratio
FROM VentesAvecPrecedent;
```

### 3. ORDER BY obligatoire

LAG et LEAD **nécessitent toujours** ORDER BY :

```sql
-- ❌ ERREUR : ORDER BY manquant
LAG(Ventes) OVER(PARTITION BY Vendeur)
```

```sql
-- ✅ CORRECT
LAG(Ventes) OVER(PARTITION BY Vendeur ORDER BY Date)
```

### 4. Attention aux égalités dans ORDER BY

Si plusieurs lignes ont la même valeur dans ORDER BY, l'ordre peut être **non déterministe** :

```sql
-- Ordre non déterministe si plusieurs ventes le même jour
LAG(Montant) OVER(ORDER BY Date)
```

**Solution** : Ajouter une colonne de tri secondaire

```sql
-- Ordre déterministe
LAG(Montant) OVER(ORDER BY Date, CommandeID)
```

### 5. Types de données compatibles

La valeur par défaut doit avoir le même type que la colonne :

```sql
-- ❌ ERREUR si Ventes est INT
LAG(Ventes, 1, 'N/A') OVER(ORDER BY Date)
```

```sql
-- ✅ CORRECT
LAG(Ventes, 1, 0) OVER(ORDER BY Date)
```

## 10. Fonctions complémentaires

### FIRST_VALUE et LAST_VALUE

Bien qu'elles ne soient pas des fonctions de décalage, elles sont souvent utilisées ensemble :

**FIRST_VALUE** : Première valeur de la fenêtre

```sql
SELECT
    Mois,
    Ventes,
    FIRST_VALUE(Ventes) OVER(
        PARTITION BY Annee
        ORDER BY Mois
    ) AS VentesJanvier
FROM VentesMensuelles;
```

**LAST_VALUE** : Dernière valeur de la fenêtre

```sql
SELECT
    Mois,
    Ventes,
    LAST_VALUE(Ventes) OVER(
        PARTITION BY Annee
        ORDER BY Mois
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS VentesDernierMois
FROM VentesMensuelles;
```

**Note** : LAST_VALUE nécessite souvent un cadre de fenêtre explicite.

### Différence avec LAG/LEAD

| Fonction | Cible |
|----------|-------|
| **LAG(col, N)** | N lignes **avant** la ligne courante |
| **LEAD(col, N)** | N lignes **après** la ligne courante |
| **FIRST_VALUE()** | **Première** ligne de la fenêtre |
| **LAST_VALUE()** | **Dernière** ligne de la fenêtre |

## 11. Exemple complet : Analyse de tendance

Voici un exemple complet qui combine plusieurs concepts :

```sql
WITH VentesAvecDecalages AS (
    SELECT
        Produit,
        Mois,
        Ventes,
        LAG(Ventes, 1) OVER(PARTITION BY Produit ORDER BY Mois) AS VentesMois_1,
        LAG(Ventes, 2) OVER(PARTITION BY Produit ORDER BY Mois) AS VentesMois_2,
        LAG(Ventes, 12) OVER(PARTITION BY Produit ORDER BY Mois) AS VentesMemesMoisAnneeDerniere,
        LEAD(Ventes, 1) OVER(PARTITION BY Produit ORDER BY Mois) AS VentesMoisSuivant
    FROM VentesMensuelles
)
SELECT
    Produit,
    Mois,
    Ventes,
    VentesMois_1,

    -- Variation mensuelle
    Ventes - VentesMois_1 AS VariationMensuelle,
    CAST((Ventes - VentesMois_1) * 100.0 / NULLIF(VentesMois_1, 0) AS DECIMAL(5,2)) AS VariationMensuellePct,

    -- Variation annuelle
    Ventes - VentesMemesMoisAnneeDerniere AS VariationAnnuelle,
    CAST((Ventes - VentesMemesMoisAnneeDerniere) * 100.0 / NULLIF(VentesMemesMoisAnneeDerniere, 0) AS DECIMAL(5,2)) AS VariationAnnuellePct,

    -- Moyenne mobile 3 mois
    (VentesMois_2 + VentesMois_1 + Ventes) / 3.0 AS MoyenneMobile3,

    -- Tendance
    CASE
        WHEN Ventes > VentesMois_1 AND VentesMois_1 > VentesMois_2 THEN 'Hausse continue'
        WHEN Ventes < VentesMois_1 AND VentesMois_1 < VentesMois_2 THEN 'Baisse continue'
        WHEN Ventes > VentesMois_1 THEN 'Hausse'
        WHEN Ventes < VentesMois_1 THEN 'Baisse'
        ELSE 'Stable'
    END AS Tendance,

    -- Prévision simple (prolongation de la tendance)
    Ventes + (Ventes - VentesMois_1) AS PrevisionSimple

FROM VentesAvecDecalages
WHERE VentesMois_1 IS NOT NULL; -- Exclure le premier mois
```

Cette requête fournit une **analyse complète** avec :
- Variations mensuelles et annuelles
- Moyennes mobiles
- Détection de tendances
- Prévisions simples

## Tableau récapitulatif

| Aspect | LAG() | LEAD() |
|--------|-------|--------|
| **Direction** | Vers le passé (↑) | Vers le futur (↓) |
| **Ligne cible** | N lignes avant | N lignes après |
| **NULL par défaut** | Première(s) ligne(s) | Dernière(s) ligne(s) |
| **Usage principal** | Comparaisons historiques | Prévisions, anticipations |
| **Exemple typique** | Variation vs mois précédent | Durée jusqu'au prochain événement |

## Résumé

Les fonctions LAG et LEAD sont des outils puissants pour :

**Points clés** :
- **Accéder aux valeurs** d'autres lignes sans jointures
- **LAG()** : Regarder vers le passé
- **LEAD()** : Regarder vers le futur
- **ORDER BY** : Toujours obligatoire
- **PARTITION BY** : Pour des comparaisons par groupe
- **Décalage** : Paramétrable (1 par défaut)
- **Valeur par défaut** : Pour gérer les extrémités

**Cas d'usage principaux** :
- Calculs de variations (mois à mois, année à année)
- Détection de changements d'état
- Analyse de tendances
- Calcul de durées entre événements
- Identification de séquences
- Détection de trous (gap analysis)

**Avantages** :
- Simple et lisible
- Performant (optimisé par SQL Server)
- Pas besoin d'auto-jointures complexes
- Gestion native des partitions

Les fonctions LAG et LEAD sont essentielles pour toute analyse temporelle ou séquentielle de données. Elles simplifient considérablement des requêtes qui seraient autrement très complexes !
