# 3.2.2 Opérateurs de comparaison (=, !=, >, <, >=, <=)

## Introduction

Les **opérateurs de comparaison** sont les outils fondamentaux qui vous permettent de comparer des valeurs dans vos requêtes SQL. Ils sont le cœur même de la clause `WHERE` et déterminent quelles lignes seront incluses dans vos résultats.

Pensez aux opérateurs de comparaison comme aux questions que vous posez :
- "Est-ce que ce prix **est égal à** 100€ ?"
- "Est-ce que cet âge **est supérieur à** 18 ?"
- "Est-ce que cette date **est antérieure à** 2024 ?"

Maîtriser ces opérateurs est essentiel pour écrire des requêtes efficaces.

---

## Les six opérateurs de comparaison

Voici les six opérateurs de comparaison de base en SQL :

| Opérateur | Nom | Signification | Exemple en français |
|-----------|-----|---------------|---------------------|
| `=` | Égal | Est égal à | "Le prix est 100" |
| `!=` ou `<>` | Différent | N'est pas égal à | "La ville n'est pas Paris" |
| `>` | Supérieur | Est strictement supérieur à | "L'âge est supérieur à 18" |
| `<` | Inférieur | Est strictement inférieur à | "Le stock est inférieur à 10" |
| `>=` | Supérieur ou égal | Est supérieur ou égal à | "L'âge est 18 ou plus" |
| `<=` | Inférieur ou égal | Est inférieur ou égal à | "Le prix est 50 ou moins" |

---

## 1. L'opérateur = (Égal)

### Description

L'opérateur `=` teste l'**égalité exacte** entre deux valeurs. C'est l'opérateur le plus utilisé.

### Syntaxe

```sql
WHERE colonne = valeur
```

### Exemples avec différents types de données

#### Avec des nombres

```sql
-- Trouver les produits dont le prix est exactement 99.99€
SELECT NomProduit, Prix
FROM Produits
WHERE Prix = 99.99
```

```sql
-- Trouver les employés avec un salaire de 3000€
SELECT Prenom, Nom, Salaire
FROM Employes
WHERE Salaire = 3000
```

#### Avec des chaînes de caractères

```sql
-- Trouver tous les clients de Lyon
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville = 'Lyon'
```

```sql
-- Trouver un produit spécifique
SELECT *
FROM Produits
WHERE NomProduit = 'Ordinateur Portable'
```

#### Avec des dates

```sql
-- Trouver les commandes passées exactement le 15 janvier 2024
SELECT CommandeID, DateCommande
FROM Commandes
WHERE DateCommande = '2024-01-15'
```

### Cas d'usage typiques

**1. Recherche par identifiant unique** :
```sql
SELECT *
FROM Clients
WHERE ClientID = 12345
```

**2. Filtrage par statut** :
```sql
SELECT *
FROM Commandes
WHERE Statut = 'Livré'
```

**3. Recherche par catégorie** :
```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Categorie = 'Électronique'
```

### Points importants

- **Casse** : selon la *collation*, `'Paris'` et `'PARIS'` peuvent être considérés comme **égaux** (collation insensible à la casse — le **défaut** en SQL Server) ou **différents** (collation sensible à la casse).
- ⚠️ **Espaces de fin ignorés** : pour l'opérateur `=`, SQL Server **ignore les espaces en fin de chaîne**. Ainsi `'Lyon' = 'Lyon '` est **vrai** (les espaces de *début*, eux, comptent).
- **Arrondis** : avec les types **approximatifs** (`FLOAT`/`REAL`), `0.1 + 0.2` peut ne pas égaler exactement `0.3`. Avec `DECIMAL`/`NUMERIC` (précision exacte), ce problème **n'existe pas**.

---

## 2. Les opérateurs != et <> (Différent)

### Description

Ces deux opérateurs sont **équivalents** et testent l'**inégalité**. Ils retournent toutes les lignes où la valeur est **différente** de celle spécifiée.

### Syntaxe

```sql
WHERE colonne != valeur
-- ou
WHERE colonne <> valeur
```

### Quelle syntaxe choisir ?

| `!=` | `<>` |
|------|------|
| Plus courant en programmation (C, Java, JavaScript) | Standard SQL officiel |
| Plus lisible pour les débutants | Recommandé pour la portabilité |
| Fonctionne en T-SQL | Fonctionne dans tous les SGBD |

**Recommandation** : Choisissez-en un et restez cohérent dans votre code.

### Exemples

#### Exclure une valeur spécifique

```sql
-- Tous les clients sauf ceux de Paris
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville != 'Paris'
```

**Résultat** : Sophie de Lyon, Pierre de Marseille, etc. (mais pas les Parisiens)

#### Exclure un statut

```sql
-- Toutes les commandes qui ne sont pas annulées
SELECT CommandeID, Statut
FROM Commandes
WHERE Statut != 'Annulé'
```

```sql
-- Équivalent avec <>
SELECT CommandeID, Statut
FROM Commandes
WHERE Statut <> 'Annulé'
```

#### Exclure une catégorie

```sql
-- Tous les produits sauf ceux de la catégorie Livres
SELECT NomProduit, Categorie
FROM Produits
WHERE Categorie != 'Livres'
```

### Attention : Comportement avec NULL

**Piège important** : Les comparaisons avec `NULL` ne fonctionnent pas comme attendu !

```sql
-- ❌ Ceci ne retourne PAS les lignes où Email est NULL
SELECT *
FROM Clients
WHERE Email != 'exemple@mail.com'
```

**Pourquoi ?** Parce que `NULL != quelque_valeur` retourne `NULL` (inconnu), pas `TRUE`.

**✅ Solution** : Nous verrons `IS NULL` dans la section 3.2.5.

---

## 3. L'opérateur > (Supérieur)

### Description

L'opérateur `>` teste si une valeur est **strictement supérieure** à une autre. La valeur limite est **exclue**.

### Syntaxe

```sql
WHERE colonne > valeur
```

### Exemples avec les nombres

#### Prix supérieur à un seuil

```sql
-- Produits dont le prix dépasse 100€
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > 100
```

**Important** : Les produits à **exactement** 100€ ne sont **pas** inclus.

**Résultat** :
| NomProduit | Prix |
|------------|------|
| Ordinateur | 800  |
| Téléphone  | 550  |
| Tablette   | 350  |

Un produit à 100€ n'apparaîtrait **pas** dans cette liste.

#### Âge minimum

```sql
-- Employés de plus de 30 ans
SELECT Prenom, Nom, Age
FROM Employes
WHERE Age > 30
```

Les employés de 30 ans exactement ne sont **pas** inclus (utilisez `>=` pour les inclure).

#### Stock faible

```sql
-- Produits avec un stock supérieur à 0 (disponibles)
SELECT NomProduit, Stock
FROM Produits
WHERE Stock > 0
```

### Exemples avec les dates

#### Commandes récentes

```sql
-- Commandes passées après le 1er janvier 2024
SELECT CommandeID, DateCommande
FROM Commandes
WHERE DateCommande > '2024-01-01'
```

**Important** : Les commandes du 1er janvier à 00:00:00 ne sont **pas** incluses.

#### Embauches récentes

```sql
-- Employés embauchés après juin 2023
SELECT Prenom, Nom, DateEmbauche
FROM Employes
WHERE DateEmbauche > '2023-06-30'
```

### Visualisation avec un exemple

Imaginons des produits avec ces prix : 50€, 100€, 150€, 200€

```sql
WHERE Prix > 100
```

```
    50€        100€        150€        200€
     |          |           |           |
     ❌         ❌          ✅          ✅
  Exclu      Exclu      Inclus      Inclus
           (limite)
```

Seuls 150€ et 200€ sont retournés.

---

## 4. L'opérateur < (Inférieur)

### Description

L'opérateur `<` teste si une valeur est **strictement inférieure** à une autre. La valeur limite est **exclue**.

### Syntaxe

```sql
WHERE colonne < valeur
```

### Exemples

#### Prix maximum

```sql
-- Produits à moins de 50€
SELECT NomProduit, Prix
FROM Produits
WHERE Prix < 50
```

Les produits à **exactement** 50€ ne sont **pas** inclus.

#### Stock critique

```sql
-- Produits en rupture imminente (stock critique)
SELECT NomProduit, Stock
FROM Produits
WHERE Stock < 10
```

#### Age limite

```sql
-- Employés de moins de 25 ans
SELECT Prenom, Nom, Age
FROM Employes
WHERE Age < 25
```

Les employés de 25 ans ne sont **pas** inclus.

### Exemples avec les dates

#### Anciennes commandes

```sql
-- Commandes passées avant 2024
SELECT CommandeID, DateCommande
FROM Commandes
WHERE DateCommande < '2024-01-01'
```

Toutes les commandes de 2023 et avant sont incluses, mais pas celles du 1er janvier 2024.

#### Produits ajoutés avant une date

```sql
-- Produits ajoutés avant le 1er juin 2024
SELECT NomProduit, DateAjout
FROM Produits
WHERE DateAjout < '2024-06-01'
```

### Visualisation

Imaginons des produits avec ces prix : 20€, 50€, 80€, 100€

```sql
WHERE Prix < 50
```

```
    20€        50€         80€        100€
     |          |           |           |
     ✅         ❌          ❌          ❌
  Inclus     Exclu       Exclu       Exclu
           (limite)
```

Seul 20€ est retourné.

---

## 5. L'opérateur >= (Supérieur ou égal)

### Description

L'opérateur `>=` teste si une valeur est **supérieure OU égale** à une autre. La valeur limite est **incluse**.

### Syntaxe

```sql
WHERE colonne >= valeur
```

### Différence avec >

| Opérateur | Inclut la limite ? | Exemple |
|-----------|-------------------|---------|
| `>` | ❌ Non | `Prix > 100` exclut 100€ |
| `>=` | ✅ Oui | `Prix >= 100` inclut 100€ |

### Exemples pratiques

#### Âge minimum (inclus)

```sql
-- Clients majeurs (18 ans ou plus)
SELECT Prenom, Nom, Age
FROM Clients
WHERE Age >= 18
```

Les clients de **exactement** 18 ans **sont inclus**.

#### Prix minimum

```sql
-- Produits à partir de 100€
SELECT NomProduit, Prix
FROM Produits
WHERE Prix >= 100
```

**Résultat** :
| NomProduit | Prix |
|------------|------|
| Tablette   | 100  | ← Inclus !
| Ordinateur | 800  |
| Téléphone  | 550  |

#### Date de début (incluse)

```sql
-- Commandes à partir du 1er janvier 2024 (inclus)
SELECT CommandeID, DateCommande
FROM Commandes
WHERE DateCommande >= '2024-01-01'
```

Les commandes du 1er janvier à 00:00:00 **sont incluses**.

### Cas d'usage : Seuils et limites

**Âge légal** :
```sql
-- Accès réservé aux 21 ans et plus
WHERE Age >= 21
```

**Montant minimum de commande** :
```sql
-- Livraison gratuite à partir de 50€
WHERE MontantTotal >= 50
```

**Ancienneté** :
```sql
-- Employés avec au moins 5 ans d'ancienneté
WHERE DATEDIFF(YEAR, DateEmbauche, GETDATE()) >= 5
```

### Visualisation

Imaginons des produits avec ces prix : 50€, 100€, 150€, 200€

```sql
WHERE Prix >= 100
```

```
    50€        100€        150€        200€
     |          |           |           |
     ❌         ✅          ✅          ✅
  Exclu      Inclus      Inclus      Inclus
           (limite)
```

100€, 150€ et 200€ sont retournés.

---

## 6. L'opérateur <= (Inférieur ou égal)

### Description

L'opérateur `<=` teste si une valeur est **inférieure OU égale** à une autre. La valeur limite est **incluse**.

### Syntaxe

```sql
WHERE colonne <= valeur
```

### Différence avec <

| Opérateur | Inclut la limite ? | Exemple |
|-----------|-------------------|---------|
| `<` | ❌ Non | `Prix < 50` exclut 50€ |
| `<=` | ✅ Oui | `Prix <= 50` inclut 50€ |

### Exemples pratiques

#### Prix maximum (inclus)

```sql
-- Produits jusqu'à 50€ (inclus)
SELECT NomProduit, Prix
FROM Produits
WHERE Prix <= 50
```

Les produits à **exactement** 50€ **sont inclus**.

#### Stock maximum

```sql
-- Produits en stock faible (10 unités ou moins)
SELECT NomProduit, Stock
FROM Produits
WHERE Stock <= 10
```

#### Date limite

```sql
-- Commandes jusqu'au 31 décembre 2023 (inclus)
SELECT CommandeID, DateCommande
FROM Commandes
WHERE DateCommande <= '2023-12-31'
```

Toutes les commandes de 2023 **sont incluses**.

### Cas d'usage : Plafonds et maxima

**Budget maximum** :
```sql
-- Produits dans mon budget (500€ maximum)
WHERE Prix <= 500
```

**Age maximum** :
```sql
-- Programme jeunesse (25 ans ou moins)
WHERE Age <= 25
```

**Date limite de candidature** :
```sql
-- Candidatures reçues jusqu'à la date limite
WHERE DateCandidature <= '2024-03-31'
```

### Visualisation

Imaginons des produits avec ces prix : 20€, 50€, 80€, 100€

```sql
WHERE Prix <= 50
```

```
    20€        50€         80€        100€
     |          |           |           |
     ✅         ✅          ❌          ❌
  Inclus     Inclus      Exclu       Exclu
           (limite)
```

20€ et 50€ sont retournés.

---

## Comparaison : > vs >= et < vs <=

### Tableau comparatif

| Situation | Opérateur à utiliser | Exemple |
|-----------|---------------------|---------|
| "Plus de 100" (100 exclu) | `>` | `Prix > 100` |
| "À partir de 100" (100 inclus) | `>=` | `Prix >= 100` |
| "Moins de 50" (50 exclu) | `<` | `Prix < 50` |
| "Jusqu'à 50" (50 inclus) | `<=` | `Prix <= 50` |
| "Strictement supérieur" | `>` | `Age > 18` |
| "18 ans ou plus" | `>=` | `Age >= 18` |

### Questions à se poser

Avant de choisir entre `>` et `>=` (ou `<` et `<=`), demandez-vous :

**"Est-ce que la valeur limite doit être incluse dans les résultats ?"**

- **Oui** → Utilisez `>=` ou `<=`
- **Non** → Utilisez `>` ou `<`

### Exemples concrets

**Scénario 1 : Majorité**
- **Objectif** : Clients ayant 18 ans ou plus
- **Solution** : `WHERE Age >= 18` ✅ (inclut 18)

**Scénario 2 : Remise**
- **Objectif** : Remise pour achats de plus de 100€
- **Question** : Un achat de exactement 100€ a-t-il droit à la remise ?
  - Si oui : `WHERE Montant >= 100`
  - Si non : `WHERE Montant > 100`

**Scénario 3 : Date d'expiration**
- **Objectif** : Produits expirés
- **Solution** : `WHERE DateExpiration < GETDATE()` (aujourd'hui n'est pas encore expiré)
- Ou : `WHERE DateExpiration <= GETDATE()` (aujourd'hui est considéré comme expiré)

## Combinaison d'opérateurs

Bien que nous verrons les opérateurs logiques (AND, OR) dans la section suivante, voici un aperçu :

### Plage de valeurs avec deux conditions

```sql
-- Produits entre 50€ et 100€ (inclus)
SELECT NomProduit, Prix
FROM Produits
WHERE Prix >= 50 AND Prix <= 100
```

```sql
-- Employés entre 25 et 40 ans
SELECT Prenom, Nom, Age
FROM Employes
WHERE Age >= 25 AND Age <= 40
```

## Comparaison de différents types de données

### 1. Nombres (INT, DECIMAL, FLOAT)

```sql
-- Entiers
WHERE Quantite > 50

-- Décimaux
WHERE Prix >= 99.99

-- Flottants
WHERE Poids < 1.5
```

**Attention** : avec les types **approximatifs** `FLOAT`/`REAL`, les arrondis binaires peuvent causer des surprises (une somme peut ne pas égaler exactement la valeur attendue) :
```sql
-- Avec des valeurs FLOAT, l'égalité exacte est risquée
DECLARE @a FLOAT = 0.1, @b FLOAT = 0.2;
SELECT IIF(@a + @b = 0.3, 'égal', 'différent');   -- peut afficher 'différent' !
```
Les types **`DECIMAL`/`NUMERIC`** (précision exacte) n'ont pas ce problème — c'est l'une des raisons de leur usage pour les montants. *(À noter : en SQL Server, le littéral `0.1` est de type `NUMERIC`, donc `0.1 + 0.2 = 0.3` est bien vrai ; le piège n'apparaît qu'avec des valeurs `FLOAT`.)*

### 2. Chaînes de caractères (VARCHAR, NVARCHAR)

Les chaînes sont comparées **alphabétiquement** :

```sql
-- Vrai : 'B' > 'A'
WHERE Nom > 'M'  -- Noms classés APRÈS 'M' : inclut 'Martin', 'Moreau'… (car 'Ma…' > 'M'), puis N, O … Z
```

**Exemple** :
```sql
SELECT Nom
FROM Clients
WHERE Nom >= 'M'
```

**Résultat possible** :
- Martin ✅
- Moreau ✅
- Dupont ❌ (commence par D, donc < M)

**Attention** : Sensibilité à la casse selon la configuration (collation).

### 3. Dates et heures (DATE, DATETIME, DATETIME2)

```sql
-- Date seule
WHERE DateNaissance > '1990-01-01'

-- Date et heure
WHERE DateCommande >= '2024-01-01 14:30:00'

-- Date actuelle
WHERE DateCreation < GETDATE()
```

**Format recommandé** : `'AAAA-MM-JJ'` ou `'AAAA-MM-JJ HH:MM:SS'`

## Pièges courants et erreurs à éviter

### Piège 1 : Confusion entre = et ==

**❌ Erreur de débutant** :
```sql
WHERE Prix == 100  -- Erreur de syntaxe !
```

**✅ Correct** :
```sql
WHERE Prix = 100   -- Un seul signe =
```

**Pourquoi ?** En SQL, l'égalité est `=` (un seul signe), pas `==` comme en C, Java ou JavaScript.

---

### Piège 2 : Comparaison de chaînes sans apostrophes

**❌ Erreur** :
```sql
WHERE Ville = Paris  -- Erreur : Paris sera interprété comme une colonne
```

**✅ Correct** :
```sql
WHERE Ville = 'Paris'  -- Avec apostrophes
```

---

### Piège 3 : Comparaison avec NULL

**❌ Ne fonctionne pas** :
```sql
WHERE Email = NULL
WHERE Email != NULL
```

**✅ Correct** :
```sql
WHERE Email IS NULL
WHERE Email IS NOT NULL
```

Nous verrons cela en détail dans la section 3.2.5.

---

### Piège 4 : Confusion > et >=

**Scénario** : Vous voulez les employés de 18 ans ou plus

**❌ Incorrect** :
```sql
WHERE Age > 18  -- Exclut les personnes de 18 ans !
```

**✅ Correct** :
```sql
WHERE Age >= 18  -- Inclut les personnes de 18 ans
```

---

### Piège 5 : Format de date incorrect

**❌ Risqué** :
```sql
WHERE DateCommande > '15/01/2024'  -- Format ambigu (JJ/MM ou MM/JJ ?)
```

**✅ Recommandé** :
```sql
WHERE DateCommande > '2024-01-15'  -- Format ISO sans ambiguïté
```

---

## Bonnes pratiques

### ✅ À faire

1. **Utilisez le bon opérateur selon votre besoin** :
   - Limite incluse ? → `>=` ou `<=`
   - Limite exclue ? → `>` ou `<`

2. **Soyez cohérent avec != et <>** :
   ```sql
   -- Choisissez-en un et gardez-le dans tout votre code
   WHERE Statut != 'Annulé'
   ```

3. **Utilisez des parenthèses pour la clarté** :
   ```sql
   WHERE (Prix >= 50) AND (Prix <= 100)
   ```

4. **Format de date ISO** :
   ```sql
   WHERE DateCommande >= '2024-01-01'
   ```

5. **Commentez les cas limites** :
   ```sql
   -- Les clients de 18 ans sont inclus (majorité)
   WHERE Age >= 18
   ```

---

### ❌ À éviter

1. **Double égal `==`** :
   ```sql
   WHERE Prix == 100  -- ❌ Erreur de syntaxe
   ```

2. **Comparaison de types incompatibles** :
   ```sql
   WHERE Prix > 'cent'  -- ❌ Nombre vs chaîne
   ```

3. **NULL avec = ou !=** :
   ```sql
   WHERE Email = NULL  -- ❌ Utiliser IS NULL
   ```

4. **Confusion entre opérateurs** :
   ```sql
   WHERE Age > 18  -- Quand vous voulez >= 18
   ```

## Résumé

### Points clés à retenir

1. **Six opérateurs** : `=`, `!=` (ou `<>`), `>`, `<`, `>=`, `<=`

2. **Inclusion de la limite** :
   - `>` et `<` → **Exclut** la valeur limite
   - `>=` et `<=` → **Inclut** la valeur limite

3. **Égalité en SQL** : Un seul `=`, pas `==`

4. **Différence** : `!=` ou `<>` (équivalents)

5. **Chaînes** : Toujours entre apostrophes `'texte'`

6. **Dates** : Format ISO `'AAAA-MM-JJ'`

7. **NULL** : Cas spécial (voir section 3.2.5)

### Aide-mémoire

Demandez-vous :
- **"Exactement cette valeur ?"** → `=`
- **"Sauf cette valeur ?"** → `!=` ou `<>`
- **"Au-delà (exclu) ?"** → `>`
- **"En-dessous (exclu) ?"** → `<`
- **"À partir de (inclus) ?"** → `>=`
- **"Jusqu'à (inclus) ?"** → `<=`
