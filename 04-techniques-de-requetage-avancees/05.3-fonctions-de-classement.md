# 4.5.3 Fonctions de classement (ROW_NUMBER, RANK, DENSE_RANK, NTILE)

## Introduction aux fonctions de classement

Les **fonctions de classement** (ou *ranking functions*) sont des fonctions de fenêtrage spéciales qui attribuent un **numéro de position** à chaque ligne selon un ordre spécifique. Elles sont extrêmement utiles pour :

- Numéroter les lignes de manière séquentielle
- Attribuer des rangs dans un classement
- Identifier les "top N" résultats
- Diviser des données en groupes égaux
- Détecter les doublons

## Les quatre fonctions de classement

T-SQL propose quatre fonctions principales de classement :

1. **ROW_NUMBER()** : Numérotation unique et séquentielle
2. **RANK()** : Classement avec sauts en cas d'ex-aequo
3. **DENSE_RANK()** : Classement sans sauts en cas d'ex-aequo
4. **NTILE(n)** : Division en n groupes de taille égale

**Particularité importante** : Ces fonctions **nécessitent toujours** une clause `ORDER BY` dans le `OVER()`.

## 1. ROW_NUMBER() - Numérotation séquentielle

### Concept

`ROW_NUMBER()` attribue un **numéro unique** à chaque ligne, de manière **strictement séquentielle** (1, 2, 3, 4...), sans jamais répéter un numéro.

### Syntaxe

```sql
ROW_NUMBER() OVER(ORDER BY colonne [ASC|DESC])
```

### Exemple de base

```sql
SELECT
    Nom,
    Prenom,
    Salaire,
    ROW_NUMBER() OVER(ORDER BY Salaire DESC) AS NumeroLigne
FROM Employes;
```

**Données de départ :**

| Nom | Prenom | Salaire |
|-----|--------|---------|
| Dupont | Marie | 65000 |
| Martin | Paul | 55000 |
| Durand | Sophie | 55000 |
| Leroy | Jean | 45000 |
| Moreau | Luc | 50000 |

**Résultat :**

| Nom | Prenom | Salaire | NumeroLigne |
|-----|--------|---------|-------------|
| Dupont | Marie | 65000 | 1 |
| Martin | Paul | 55000 | 2 |
| Durand | Sophie | 55000 | 3 |
| Moreau | Luc | 50000 | 4 |
| Leroy | Jean | 45000 | 5 |

### Points clés de ROW_NUMBER()

- **Numéros toujours uniques** : Jamais de doublons, même en cas d'ex-aequo
- **Séquence continue** : 1, 2, 3, 4, 5... sans sauts
- **Gestion des ex-aequo** : L'ordre est **arbitraire** (Martin avant Durand ou vice-versa)
- **Déterminisme** : Pour un ordre déterministe avec des ex-aequo, ajoutez une colonne de tri secondaire

### Ordre déterministe en cas d'ex-aequo

```sql
SELECT
    Nom,
    Prenom,
    Salaire,
    ROW_NUMBER() OVER(ORDER BY Salaire DESC, Nom ASC) AS NumeroLigne
FROM Employes;
```

Maintenant, en cas d'égalité de salaire, le tri se fait par nom alphabétique.

**Résultat :**

| Nom | Prenom | Salaire | NumeroLigne |
|-----|--------|---------|-------------|
| Dupont | Marie | 65000 | 1 |
| Durand | Sophie | 55000 | 2 |
| Martin | Paul | 55000 | 3 |
| Moreau | Luc | 50000 | 4 |
| Leroy | Jean | 45000 | 5 |

### Cas d'usage : Sélectionner le top N

```sql
-- Trouver les 3 employés les mieux payés
WITH EmployesNumeros AS (
    SELECT
        Nom,
        Prenom,
        Salaire,
        ROW_NUMBER() OVER(ORDER BY Salaire DESC) AS NumeroLigne
    FROM Employes
)
SELECT
    Nom,
    Prenom,
    Salaire
FROM EmployesNumeros
WHERE NumeroLigne <= 3;
```

## 2. RANK() - Classement avec sauts

### Concept

`RANK()` attribue un **rang** à chaque ligne. En cas d'**ex-aequo**, plusieurs lignes reçoivent le **même rang**, et le rang suivant est **sauté** en conséquence.

### Syntaxe

```sql
RANK() OVER(ORDER BY colonne [ASC|DESC])
```

### Exemple

```sql
SELECT
    Nom,
    Prenom,
    Salaire,
    RANK() OVER(ORDER BY Salaire DESC) AS Rang
FROM Employes;
```

**Résultat :**

| Nom | Prenom | Salaire | Rang |
|-----|--------|---------|------|
| Dupont | Marie | 65000 | 1 |
| Martin | Paul | 55000 | 2 |
| Durand | Sophie | 55000 | 2 |
| Moreau | Luc | 50000 | 4 |
| Leroy | Jean | 45000 | 5 |

### Points clés de RANK()

- **Ex-aequo** : Martin et Durand ont tous deux le rang **2**
- **Sauts** : Le rang suivant est **4** (pas 3), car deux personnes occupent le rang 2
- **Logique** : C'est comme un classement sportif traditionnel
  - 1er place : 1 personne → rang 1
  - 2ème place : 2 personnes → rang 2 (ex-aequo)
  - 3ème place n'existe pas (sautée)
  - 4ème place : 1 personne → rang 4

### Analogie : Course à pied

Imaginez une course :
- Marie arrive 1ère → **Rang 1**
- Paul et Sophie arrivent en même temps → **Rang 2** (ex-aequo)
- Luc arrive ensuite → **Rang 4** (car il y a 3 personnes devant lui)

## 3. DENSE_RANK() - Classement sans sauts

### Concept

`DENSE_RANK()` fonctionne comme `RANK()`, mais **sans sauter de rangs**. Les rangs sont **consécutifs** même en cas d'ex-aequo.

### Syntaxe

```sql
DENSE_RANK() OVER(ORDER BY colonne [ASC|DESC])
```

### Exemple

```sql
SELECT
    Nom,
    Prenom,
    Salaire,
    DENSE_RANK() OVER(ORDER BY Salaire DESC) AS RangDense
FROM Employes;
```

**Résultat :**

| Nom | Prenom | Salaire | RangDense |
|-----|--------|---------|-----------|
| Dupont | Marie | 65000 | 1 |
| Martin | Paul | 55000 | 2 |
| Durand | Sophie | 55000 | 2 |
| Moreau | Luc | 50000 | 3 |
| Leroy | Jean | 45000 | 4 |

### Points clés de DENSE_RANK()

- **Ex-aequo** : Martin et Durand ont tous deux le rang **2**
- **Pas de sauts** : Le rang suivant est **3** (pas 4 comme avec RANK)
- **Séquence dense** : 1, 2, 2, 3, 4... (toujours consécutif)
- **Nombre de rangs** : Correspond au nombre de **valeurs distinctes** dans la colonne de tri

### Quand utiliser DENSE_RANK() ?

Utilisez `DENSE_RANK()` quand vous voulez :
- Compter le nombre de valeurs distinctes
- Un classement où chaque "niveau" compte, sans trous
- Afficher les "top N valeurs distinctes"

## 4. NTILE(n) - Division en groupes

### Concept

`NTILE(n)` divise les lignes en **n groupes** de taille **approximativement égale** et attribue un numéro de groupe (1 à n) à chaque ligne.

### Syntaxe

```sql
NTILE(nombre_de_groupes) OVER(ORDER BY colonne [ASC|DESC])
```

### Exemple : Division en 3 groupes (tertiles)

```sql
SELECT
    Nom,
    Prenom,
    Salaire,
    NTILE(3) OVER(ORDER BY Salaire DESC) AS Groupe
FROM Employes;
```

**Avec 5 employés, division en 3 groupes :**

| Nom | Prenom | Salaire | Groupe |
|-----|--------|---------|--------|
| Dupont | Marie | 65000 | 1 |
| Martin | Paul | 55000 | 1 |
| Durand | Sophie | 55000 | 2 |
| Moreau | Luc | 50000 | 2 |
| Leroy | Jean | 45000 | 3 |

**Répartition** :
- Groupe 1 : 2 employés (les 2 premiers)
- Groupe 2 : 2 employés (les 2 suivants)
- Groupe 3 : 1 employé (le dernier)

### Points clés de NTILE()

- **Répartition équitable** : SQL Server répartit les lignes aussi équitablement que possible
- **Groupes complets d'abord** : Les premiers groupes peuvent avoir **une ligne de plus** si la division n'est pas exacte
- **Ordre important** : L'ordre dans `ORDER BY` détermine qui va dans quel groupe

### Cas d'usage courants

#### 1. Quartiles (division en 4)

```sql
SELECT
    Nom,
    Salaire,
    NTILE(4) OVER(ORDER BY Salaire DESC) AS Quartile
FROM Employes;
```

Utile pour :
- Identifier les 25% les mieux payés (quartile 1)
- Identifier les 25% les moins payés (quartile 4)

#### 2. Déciles (division en 10)

```sql
SELECT
    Produit,
    ChiffreAffaires,
    NTILE(10) OVER(ORDER BY ChiffreAffaires DESC) AS Decile
FROM Ventes;
```

Utile pour : Analyse ABC (les 10% de produits générant le plus de CA)

#### 3. Division en groupes de travail

```sql
SELECT
    NomClient,
    NTILE(5) OVER(ORDER BY DateInscription) AS EquipeCommerciale
FROM Clients;
```

Répartir 5 équipes commerciales de manière équitable sur la base de clients.

## Comparaison des quatre fonctions

Voici un exemple qui compare les quatre fonctions côte à côte :

```sql
SELECT
    Nom,
    Salaire,
    ROW_NUMBER() OVER(ORDER BY Salaire DESC) AS RowNum,
    RANK() OVER(ORDER BY Salaire DESC) AS Rank,
    DENSE_RANK() OVER(ORDER BY Salaire DESC) AS DenseRank,
    NTILE(3) OVER(ORDER BY Salaire DESC) AS Ntile3
FROM Employes;
```

**Données avec plusieurs ex-aequo :**

| Nom | Salaire |
|-----|---------|
| Marie | 70000 |
| Paul | 60000 |
| Sophie | 60000 |
| Jean | 60000 |
| Luc | 50000 |
| Claire | 40000 |

**Résultat comparatif :**

| Nom | Salaire | RowNum | Rank | DenseRank | Ntile3 |
|-----|---------|--------|------|-----------|--------|
| Marie | 70000 | 1 | 1 | 1 | 1 |
| Paul | 60000 | 2 | 2 | 2 | 1 |
| Sophie | 60000 | 3 | 2 | 2 | 2 |
| Jean | 60000 | 4 | 2 | 2 | 2 |
| Luc | 50000 | 5 | 5 | 3 | 3 |
| Claire | 40000 | 6 | 6 | 4 | 3 |

### Analyse des différences

**ROW_NUMBER** : 1, 2, 3, 4, 5, 6
- Numéros toujours uniques et séquentiels

**RANK** : 1, 2, 2, 2, 5, 6
- Les trois personnes à 60000€ ont le rang **2** (ex-aequo)
- Saut jusqu'au rang **5** (car 3 personnes au rang 2)

**DENSE_RANK** : 1, 2, 2, 2, 3, 4
- Les trois personnes à 60000€ ont le rang **2**
- Pas de saut, le rang suivant est **3**

**NTILE(3)** : 1, 1, 2, 2, 3, 3
- Division en 3 groupes de 2 personnes chacun
- Groupe 1 : Top 2, Groupe 2 : Milieu 2, Groupe 3 : Bas 2

## Combinaison avec PARTITION BY

C'est là que les fonctions de classement deviennent vraiment puissantes ! Vous pouvez **classer à l'intérieur de chaque groupe**.

### Exemple : Meilleur employé par département

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    ROW_NUMBER() OVER(PARTITION BY Departement ORDER BY Salaire DESC) AS RangDansDept
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | RangDansDept |
|-----|-------------|---------|--------------|
| Dupont | IT | 65000 | 1 |
| Martin | IT | 55000 | 2 |
| Bernard | IT | 50000 | 3 |
| Durand | RH | 47000 | 1 |
| Leroy | RH | 45000 | 2 |
| Moreau | Ventes | 60000 | 1 |
| Petit | Ventes | 54000 | 2 |

**Le numéro repart à 1 pour chaque département !**

### Cas d'usage : Top 2 par catégorie

```sql
-- Trouver les 2 produits les plus vendus dans chaque catégorie
WITH ProduitsClasses AS (
    SELECT
        Categorie,
        NomProduit,
        QuantiteVendue,
        ROW_NUMBER() OVER(PARTITION BY Categorie ORDER BY QuantiteVendue DESC) AS Rang
    FROM Ventes
)
SELECT
    Categorie,
    NomProduit,
    QuantiteVendue
FROM ProduitsClasses
WHERE Rang <= 2;
```

Cela retourne les 2 meilleurs produits de **chaque** catégorie.

### Exemple avec RANK() et PARTITION BY

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    RANK() OVER(PARTITION BY Departement ORDER BY Salaire DESC) AS RangDept
FROM Employes;
```

Chaque département a son propre classement avec gestion des ex-aequo.

## Cas pratiques avancés

### 1. Détecter les doublons

```sql
-- Trouver les clients avec des emails en double
WITH ClientsNumeros AS (
    SELECT
        ClientID,
        Email,
        Nom,
        ROW_NUMBER() OVER(PARTITION BY Email ORDER BY DateInscription) AS NumDuplicate
    FROM Clients
)
SELECT
    ClientID,
    Email,
    Nom
FROM ClientsNumeros
WHERE NumDuplicate > 1; -- Les doublons
```

### 2. Supprimer les doublons en gardant le plus récent

```sql
WITH ClientsNumeros AS (
    SELECT
        ClientID,
        Email,
        ROW_NUMBER() OVER(PARTITION BY Email ORDER BY DateInscription DESC) AS Rang
    FROM Clients
)
DELETE FROM ClientsNumeros
WHERE Rang > 1; -- Garde seulement le plus récent (rang = 1)
```

### 3. Pagination de résultats

```sql
-- Page 2 avec 10 résultats par page
WITH ResultatsPagines AS (
    SELECT
        *,
        ROW_NUMBER() OVER(ORDER BY DateCommande DESC) AS NumLigne
    FROM Commandes
)
SELECT
    CommandeID,
    DateCommande,
    Montant
FROM ResultatsPagines
WHERE NumLigne BETWEEN 11 AND 20; -- Lignes 11 à 20 = page 2
```

### 4. Analyse des meilleurs et pires performers

```sql
SELECT
    NomVendeur,
    ChiffreAffaires,
    NTILE(100) OVER(ORDER BY ChiffreAffaires DESC) AS Percentile,
    CASE
        WHEN NTILE(100) OVER(ORDER BY ChiffreAffaires DESC) <= 10 THEN 'Top 10%'
        WHEN NTILE(100) OVER(ORDER BY ChiffreAffaires DESC) <= 25 THEN 'Top 25%'
        WHEN NTILE(100) OVER(ORDER BY ChiffreAffaires DESC) >= 90 THEN 'Bottom 10%'
        ELSE 'Moyen'
    END AS Categorie
FROM Vendeurs;
```

### 5. Trouver les valeurs médianes

```sql
-- Trouver le salaire médian par département
WITH SalairesClasses AS (
    SELECT
        Departement,
        Salaire,
        ROW_NUMBER() OVER(PARTITION BY Departement ORDER BY Salaire) AS RangAsc,
        COUNT(*) OVER(PARTITION BY Departement) AS TotalEmployes
    FROM Employes
)
SELECT
    Departement,
    AVG(Salaire) AS SalaireMedian
FROM SalairesClasses
WHERE RangAsc IN ((TotalEmployes + 1) / 2, (TotalEmployes + 2) / 2)
GROUP BY Departement;
```

Cette requête gère correctement les cas pairs et impairs.

## Ordre d'exécution et limitations

### Ordre logique d'une requête avec fonctions de classement

1. **FROM** : Tables source
2. **WHERE** : Filtrage des lignes
3. **GROUP BY** : Regroupement
4. **HAVING** : Filtrage des groupes
5. **SELECT** : Sélection des colonnes
6. **Fonctions de fenêtrage (ROW_NUMBER, RANK, etc.)**
7. **ORDER BY** : Tri final des résultats

### Conséquence importante

Vous **ne pouvez pas** utiliser directement une fonction de classement dans WHERE :

```sql
-- ❌ ERREUR : Impossible
SELECT
    Nom,
    Salaire
FROM Employes
WHERE ROW_NUMBER() OVER(ORDER BY Salaire DESC) <= 3;
```

### Solutions

**Solution 1 : CTE (Common Table Expression)**

```sql
-- ✅ CORRECT
WITH EmployesClasses AS (
    SELECT
        Nom,
        Salaire,
        ROW_NUMBER() OVER(ORDER BY Salaire DESC) AS Rang
    FROM Employes
)
SELECT
    Nom,
    Salaire
FROM EmployesClasses
WHERE Rang <= 3;
```

**Solution 2 : Sous-requête**

```sql
-- ✅ CORRECT
SELECT
    Nom,
    Salaire
FROM (
    SELECT
        Nom,
        Salaire,
        ROW_NUMBER() OVER(ORDER BY Salaire DESC) AS Rang
    FROM Employes
) AS Subquery
WHERE Rang <= 3;
```

## Tableau récapitulatif

| Fonction | Ex-aequo | Séquence | Usage principal |
|----------|----------|----------|-----------------|
| **ROW_NUMBER()** | Numéros différents | 1,2,3,4,5,6 | Numérotation unique, pagination, suppression doublons |
| **RANK()** | Même rang, puis saut | 1,2,2,2,5,6 | Classement sportif traditionnel |
| **DENSE_RANK()** | Même rang, sans saut | 1,2,2,2,3,4 | Top N valeurs distinctes |
| **NTILE(n)** | Répartition en groupes | 1,1,2,2,3,3 | Quartiles, percentiles, segmentation |

## Bonnes pratiques

### 1. Choisir la bonne fonction

- **ROW_NUMBER()** : Quand vous avez besoin d'identifiants uniques ou de numérotation stricte
- **RANK()** : Pour des classements "traditionnels" avec reconnaissance des ex-aequo
- **DENSE_RANK()** : Pour compter les valeurs distinctes ou éviter les trous dans le classement
- **NTILE()** : Pour diviser en groupes égaux (analyses statistiques, segmentation)

### 2. Toujours inclure ORDER BY

```sql
-- ❌ ERREUR : ORDER BY manquant
SELECT
    Nom,
    ROW_NUMBER() OVER(PARTITION BY Departement) AS Rang
FROM Employes;
```

```sql
-- ✅ CORRECT
SELECT
    Nom,
    ROW_NUMBER() OVER(PARTITION BY Departement ORDER BY Salaire DESC) AS Rang
FROM Employes;
```

### 3. Gérer les ex-aequo avec ROW_NUMBER()

Si l'ordre est important avec des ex-aequo, ajoutez une colonne de tri secondaire :

```sql
ROW_NUMBER() OVER(ORDER BY Salaire DESC, Nom ASC)
```

### 4. Performance avec index

Les fonctions de classement bénéficient d'index sur les colonnes utilisées dans :
- **PARTITION BY** : Index sur la colonne de partition
- **ORDER BY** : Index sur la colonne de tri

```sql
-- Cette requête bénéficiera d'un index sur (Departement, Salaire)
SELECT
    ROW_NUMBER() OVER(PARTITION BY Departement ORDER BY Salaire DESC)
FROM Employes;
```

### 5. Utiliser des CTE pour la lisibilité

Plutôt que des requêtes imbriquées complexes, utilisez des CTE :

```sql
WITH EmployesClasses AS (
    SELECT
        *,
        ROW_NUMBER() OVER(PARTITION BY Departement ORDER BY Salaire DESC) AS Rang
    FROM Employes
),
TopEmployes AS (
    SELECT * FROM EmployesClasses WHERE Rang = 1
)
SELECT
    Departement,
    Nom,
    Salaire
FROM TopEmployes;
```

## Résumé

Les fonctions de classement sont des outils puissants pour :
- Attribuer des numéros séquentiels aux lignes
- Créer des classements avec ou sans gestion des ex-aequo
- Diviser les données en groupes de taille égale
- Identifier les "top N" dans chaque catégorie
- Détecter et supprimer les doublons

**Points clés à retenir** :
- Toutes nécessitent `ORDER BY` dans le `OVER()`
- Peuvent être combinées avec `PARTITION BY` pour des classements par groupe
- Ne peuvent pas être utilisées directement dans WHERE (utiliser CTE ou sous-requête)
- Chaque fonction a un comportement spécifique avec les ex-aequo

Les fonctions de classement sont indispensables pour les analyses avancées et font partie des fonctionnalités T-SQL les plus utilisées par les développeurs et analystes de données !
