# 8.1.3 FOR XML (Génération de XML)

## Introduction

Dans les sections précédentes, nous avons appris à **stocker** et **interroger** des données XML. Maintenant, nous allons voir comment faire l'opération inverse : **générer du XML à partir de données relationnelles**.

C'est très utile dans de nombreux scénarios :
- Exporter des données vers d'autres systèmes
- Créer des fichiers de configuration
- Générer des flux RSS ou des documents SOAP
- Préparer des données pour des API
- Créer des rapports au format XML

SQL Server offre la clause **`FOR XML`** qui permet de transformer automatiquement les résultats d'une requête SELECT en format XML.

## Les quatre modes de FOR XML

La clause `FOR XML` propose **quatre modes** différents, chacun avec ses propres caractéristiques :

| Mode | Caractéristique | Niveau de contrôle | Complexité |
|------|-----------------|-------------------|------------|
| **RAW** | Structure simple et générique | Faible | Très simple |
| **AUTO** | Structure basée sur les relations | Moyen | Simple |
| **PATH** | Contrôle total de la structure | Élevé | Moyen |
| **EXPLICIT** | Contrôle maximal (obsolète) | Maximum | Très complexe |

**Note** : Le mode EXPLICIT est maintenant considéré comme obsolète. Microsoft recommande d'utiliser **PATH** pour un contrôle avancé.

Nous allons explorer les trois premiers modes (RAW, AUTO et PATH) qui sont les plus utilisés.

## Préparation : Données d'exemple

Pour illustrer les différents modes, créons des tables simples :

```sql
-- Table des clients
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom NVARCHAR(50),
    Ville NVARCHAR(50)
);

-- Table des commandes
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY,
    ClientID INT,
    DateCommande DATE,
    Montant DECIMAL(10,2),
    FOREIGN KEY (ClientID) REFERENCES Clients(ClientID)
);

-- Insertion de données
INSERT INTO Clients VALUES
(1, 'Dupont', 'Paris'),
(2, 'Martin', 'Lyon'),
(3, 'Durand', 'Marseille');

INSERT INTO Commandes VALUES
(101, 1, '2024-11-01', 250.00),
(102, 1, '2024-11-10', 180.50),
(103, 2, '2024-11-05', 420.00),
(104, 3, '2024-11-15', 95.75);
```

## Mode RAW : Le plus simple

### Concept

Le mode **RAW** est le plus basique. Il génère un XML avec :
- Un élément `<row>` pour chaque ligne du résultat
- Les colonnes deviennent des **attributs** de `<row>`

### Syntaxe de base

```sql
SELECT colonnes
FROM table
FOR XML RAW;
```

### Exemple 1 : RAW simple

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML RAW;
```

**Résultat** :
```xml
<row ClientID="1" Nom="Dupont" Ville="Paris"/>
<row ClientID="2" Nom="Martin" Ville="Lyon"/>
<row ClientID="3" Nom="Durand" Ville="Marseille"/>
```

**Observation** : Chaque ligne devient un élément `<row>` et chaque colonne devient un attribut.

### Exemple 2 : Personnaliser le nom de l'élément

On peut remplacer `<row>` par un nom personnalisé :

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML RAW('Client');
```

**Résultat** :
```xml
<Client ClientID="1" Nom="Dupont" Ville="Paris"/>
<Client ClientID="2" Nom="Martin" Ville="Lyon"/>
<Client ClientID="3" Nom="Durand" Ville="Marseille"/>
```

### Exemple 3 : Ajouter un élément racine

Par défaut, il n'y a pas d'élément racine unique. On peut en ajouter un avec `ROOT` :

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML RAW('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client ClientID="1" Nom="Dupont" Ville="Paris"/>
  <Client ClientID="2" Nom="Martin" Ville="Lyon"/>
  <Client ClientID="3" Nom="Durand" Ville="Marseille"/>
</Clients>
```

### Exemple 4 : Colonnes comme éléments au lieu d'attributs

Par défaut, les colonnes sont des attributs. Avec `ELEMENTS`, elles deviennent des sous-éléments :

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML RAW('Client'), ROOT('Clients'), ELEMENTS;
```

**Résultat** :
```xml
<Clients>
  <Client>
    <ClientID>1</ClientID>
    <Nom>Dupont</Nom>
    <Ville>Paris</Ville>
  </Client>
  <Client>
    <ClientID>2</ClientID>
    <Nom>Martin</Nom>
    <Ville>Lyon</Ville>
  </Client>
  <Client>
    <ClientID>3</ClientID>
    <Nom>Durand</Nom>
    <Ville>Marseille</Ville>
  </Client>
</Clients>
```

### Avantages et limites de RAW

**Avantages** :
- Très simple à utiliser
- Rapide pour des exports basiques
- Pas besoin de connaître la structure des relations

**Limites** :
- Structure plate (pas de hiérarchie réelle)
- Peu de contrôle sur la structure finale
- Noms d'éléments génériques

## Mode AUTO : Structure automatique

### Concept

Le mode **AUTO** analyse automatiquement les **relations** entre les tables et crée une **structure hiérarchique** correspondante.

- Chaque table devient un élément
- Les relations parent-enfant sont respectées
- La structure dépend de l'ordre des colonnes dans le SELECT

### Syntaxe de base

```sql
SELECT colonnes
FROM table1
JOIN table2 ON ...
FOR XML AUTO;
```

### Exemple 1 : AUTO simple

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML AUTO;
```

**Résultat** :
```xml
<Clients ClientID="1" Nom="Dupont" Ville="Paris"/>
<Clients ClientID="2" Nom="Martin" Ville="Lyon"/>
<Clients ClientID="3" Nom="Durand" Ville="Marseille"/>
```

**Note** : Le nom de l'élément est automatiquement le nom de la table (`Clients`).

### Exemple 2 : AUTO avec jointure

Voici où AUTO devient intéressant - il crée automatiquement une hiérarchie :

```sql
SELECT
    C.ClientID,
    C.Nom,
    C.Ville,
    CMD.CommandeID,
    CMD.DateCommande,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
FOR XML AUTO, ROOT('Données');
```

**Résultat** :
```xml
<Données>
  <C ClientID="1" Nom="Dupont" Ville="Paris">
    <CMD CommandeID="101" DateCommande="2024-11-01" Montant="250.00"/>
    <CMD CommandeID="102" DateCommande="2024-11-10" Montant="180.50"/>
  </C>
  <C ClientID="2" Nom="Martin" Ville="Lyon">
    <CMD CommandeID="103" DateCommande="2024-11-05" Montant="420.00"/>
  </C>
  <C ClientID="3" Nom="Durand" Ville="Marseille">
    <CMD CommandeID="104" DateCommande="2024-11-15" Montant="95.75"/>
  </C>
</Données>
```

**Observation importante** : Les commandes sont **imbriquées** dans leurs clients respectifs ! SQL Server a automatiquement détecté la relation parent-enfant.

**Note** : Les noms d'éléments (`C` et `CMD`) correspondent aux alias de tables utilisés dans la requête.

### Exemple 3 : AUTO avec ELEMENTS

Comme avec RAW, on peut utiliser ELEMENTS pour avoir des sous-éléments plutôt que des attributs :

```sql
SELECT
    C.ClientID,
    C.Nom,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE C.ClientID = 1
FOR XML AUTO, ROOT('Données'), ELEMENTS;
```

**Résultat** :
```xml
<Données>
  <C>
    <ClientID>1</ClientID>
    <Nom>Dupont</Nom>
    <CMD>
      <CommandeID>101</CommandeID>
      <Montant>250.00</Montant>
    </CMD>
    <CMD>
      <CommandeID>102</CommandeID>
      <Montant>180.50</Montant>
    </CMD>
  </C>
</Données>
```

### Impact de l'ordre des colonnes

**Important** : L'ordre des colonnes dans le SELECT affecte la structure hiérarchique !

```sql
-- Ordre 1 : Client puis Commande
SELECT C.Nom, CMD.CommandeID
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE C.ClientID = 1
FOR XML AUTO;
```

**Résultat** :
```xml
<C Nom="Dupont">
  <CMD CommandeID="101"/>
  <CMD CommandeID="102"/>
</C>
```

```sql
-- Ordre 2 : Commande puis Client (inversé)
SELECT CMD.CommandeID, C.Nom
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE C.ClientID = 1
FOR XML AUTO;
```

**Résultat** :
```xml
<CMD CommandeID="101" Nom="Dupont"/>
<CMD CommandeID="102" Nom="Dupont"/>
```

La structure est complètement différente ! Le premier élément mentionné devient le parent.

### Avantages et limites de AUTO

**Avantages** :
- Crée automatiquement des hiérarchies
- Respecte les relations entre tables
- Plus structuré que RAW

**Limites** :
- Contrôle limité sur la structure
- Les noms d'éléments dépendent des alias
- L'ordre des colonnes est crucial et peut être confus

## Mode PATH : Contrôle maximum

### Concept

Le mode **PATH** offre un **contrôle total** sur la structure XML générée. C'est le mode le plus puissant et le plus flexible.

- On définit la structure en utilisant des **chemins XPath** dans les alias de colonnes
- Syntaxe avec `/` pour créer des hiérarchies
- Syntaxe avec `@` pour créer des attributs

**C'est le mode recommandé** pour un contrôle précis de la structure XML.

### Syntaxe de base

```sql
SELECT colonnes AS 'chemin/xpath'
FROM table
FOR XML PATH('nom_element');
```

### Exemple 1 : PATH simple (équivalent à RAW)

Sans spécifier de chemins, PATH se comporte de manière similaire à RAW avec ELEMENTS :

```sql
SELECT ClientID, Nom, Ville
FROM Clients
FOR XML PATH('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client>
    <ClientID>1</ClientID>
    <Nom>Dupont</Nom>
    <Ville>Paris</Ville>
  </Client>
  <Client>
    <ClientID>2</ClientID>
    <Nom>Martin</Nom>
    <Ville>Lyon</Ville>
  </Client>
  <Client>
    <ClientID>3</ClientID>
    <Nom>Durand</Nom>
    <Ville>Marseille</Ville>
  </Client>
</Clients>
```

### Exemple 2 : Créer des attributs avec @

En préfixant un alias avec `@`, on crée un **attribut** :

```sql
SELECT
    ClientID AS '@ID',
    Nom AS '@Nom',
    Ville
FROM Clients
FOR XML PATH('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client ID="1" Nom="Dupont">
    <Ville>Paris</Ville>
  </Client>
  <Client ID="2" Nom="Martin">
    <Ville>Lyon</Ville>
  </Client>
  <Client ID="3" Nom="Durand">
    <Ville>Marseille</Ville>
  </Client>
</Clients>
```

**Explication** : `ClientID` et `Nom` sont devenus des attributs (`@`), tandis que `Ville` reste un élément.

### Exemple 3 : Créer une hiérarchie avec /

On utilise `/` pour créer des niveaux hiérarchiques :

```sql
SELECT
    ClientID AS '@ID',
    Nom,
    Ville AS 'Adresse/Ville'
FROM Clients
WHERE ClientID = 1
FOR XML PATH('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client ID="1">
    <Nom>Dupont</Nom>
    <Adresse>
      <Ville>Paris</Ville>
    </Adresse>
  </Client>
</Clients>
```

**Explication** : `'Adresse/Ville'` crée un élément `<Adresse>` contenant un élément `<Ville>`.

### Exemple 4 : Structure plus complexe

Créons une structure plus élaborée avec plusieurs niveaux :

```sql
SELECT
    ClientID AS '@ID',
    Nom AS 'Informations/NomComplet',
    Ville AS 'Informations/Adresse/Ville',
    'France' AS 'Informations/Adresse/Pays'
FROM Clients
WHERE ClientID = 1
FOR XML PATH('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client ID="1">
    <Informations>
      <NomComplet>Dupont</NomComplet>
      <Adresse>
        <Ville>Paris</Ville>
        <Pays>France</Pays>
      </Adresse>
    </Informations>
  </Client>
</Clients>
```

### Exemple 5 : Combiner PATH avec des jointures

PATH fonctionne très bien avec des jointures. Créons une structure client avec ses commandes :

```sql
SELECT
    C.ClientID AS '@ID',
    C.Nom AS 'Nom',
    C.Ville AS 'Ville',
    (
        SELECT
            CMD.CommandeID AS '@NumCommande',
            CMD.DateCommande AS 'Date',
            CMD.Montant AS 'Montant'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR XML PATH('Commande'), TYPE
    ) AS 'Commandes'
FROM Clients C
WHERE C.ClientID = 1
FOR XML PATH('Client'), ROOT('Clients');
```

**Résultat** :
```xml
<Clients>
  <Client ID="1">
    <Nom>Dupont</Nom>
    <Ville>Paris</Ville>
    <Commandes>
      <Commande NumCommande="101">
        <Date>2024-11-01</Date>
        <Montant>250.00</Montant>
      </Commande>
      <Commande NumCommande="102">
        <Date>2024-11-10</Date>
        <Montant>180.50</Montant>
      </Commande>
    </Commandes>
  </Client>
</Clients>
```

**Points importants** :
1. On utilise une **sous-requête** pour générer les commandes
2. Le mot-clé **`TYPE`** est crucial : il indique que le résultat est du type XML (pas une chaîne)
3. Sans `TYPE`, le XML serait échappé (avec `&lt;` au lieu de `<`)

### Exemple 6 : Chemin vide pour du texte brut

Un chemin vide (`''`) ou l'utilisation de `data()` permet d'insérer du texte directement :

```sql
SELECT
    Nom AS 'Client/Nom',
    'habite à ' AS 'Client/data()',
    Ville AS 'Client/data()'
FROM Clients
WHERE ClientID = 1
FOR XML PATH(''), ROOT('Info');
```

**Résultat** :
```xml
<Info>
  <Client>
    <Nom>Dupont</Nom>habite à Paris
  </Client>
</Info>
```

**Note** : `data()` insère du texte sans créer de balise.

### Avantages et limites de PATH

**Avantages** :
- Contrôle total sur la structure XML
- Syntaxe intuitive avec XPath
- Très flexible
- Mode recommandé par Microsoft

**Limites** :
- Requêtes potentiellement plus complexes
- Nécessite de bien comprendre les chemins XPath
- Peut devenir verbeux pour des structures très complexes

## Options communes à tous les modes

### ROOT : Ajouter un élément racine

```sql
FOR XML [MODE], ROOT('NomRacine')
```

Ajoute un élément racine englobant tous les autres.

### ELEMENTS : Colonnes comme éléments

```sql
FOR XML [MODE], ELEMENTS
```

Force les colonnes à devenir des sous-éléments plutôt que des attributs (sauf PATH avec `@`).

### TYPE : Retourner du type XML

```sql
FOR XML [MODE], TYPE
```

Retourne un résultat de **type XML** au lieu d'une chaîne de caractères. Utile pour :
- Imbrication de requêtes
- Éviter l'échappement HTML
- Manipulations ultérieures avec les méthodes XML

### ELEMENTS XSINIL : Gérer les NULL

Par défaut, les valeurs NULL ne génèrent pas d'élément. Avec `ELEMENTS XSINIL`, elles créent un élément vide avec l'attribut `xsi:nil="true"` :

```sql
-- Ajoutons une colonne nullable
ALTER TABLE Clients ADD Email NVARCHAR(100) NULL;

-- Mise à jour partielle
UPDATE Clients SET Email = 'dupont@example.com' WHERE ClientID = 1;

-- Sans XSINIL
SELECT ClientID, Nom, Email
FROM Clients
FOR XML PATH('Client'), ROOT('Clients'), ELEMENTS;
```

**Résultat** :
```xml
<Clients>
  <Client>
    <ClientID>1</ClientID>
    <Nom>Dupont</Nom>
    <Email>dupont@example.com</Email>
  </Client>
  <Client>
    <ClientID>2</ClientID>
    <Nom>Martin</Nom>
    <!-- Pas d'élément Email pour les NULL -->
  </Client>
</Clients>
```

```sql
-- Avec XSINIL
SELECT ClientID, Nom, Email
FROM Clients
FOR XML PATH('Client'), ROOT('Clients'), ELEMENTS XSINIL;
```

**Résultat** :
```xml
<Clients xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <Client>
    <ClientID>1</ClientID>
    <Nom>Dupont</Nom>
    <Email>dupont@example.com</Email>
  </Client>
  <Client>
    <ClientID>2</ClientID>
    <Nom>Martin</Nom>
    <Email xsi:nil="true"/>
  </Client>
</Clients>
```

## Cas d'usage pratiques

### 1. Export de données pour un système externe

```sql
-- Générer un fichier XML de tous les clients avec leurs commandes
SELECT
    C.ClientID AS '@ID',
    C.Nom,
    C.Ville,
    (
        SELECT
            CommandeID AS '@Numero',
            DateCommande AS 'Date',
            Montant
        FROM Commandes
        WHERE ClientID = C.ClientID
        FOR XML PATH('Commande'), TYPE
    ) AS 'Commandes'
FROM Clients C
FOR XML PATH('Client'), ROOT('ExportClients');
```

### 2. Générer une configuration XML

```sql
-- Créer une configuration d'application
SELECT
    'MyApp' AS 'Application/@Name',
    'Production' AS 'Application/Environnement',
    'Server01' AS 'Application/Database/Server',
    'MyDatabase' AS 'Application/Database/Name',
    '30' AS 'Application/Database/Timeout'
FOR XML PATH(''), ROOT('Configuration');
```

**Résultat** :
```xml
<Configuration>
  <Application Name="MyApp">
    <Environnement>Production</Environnement>
    <Database>
      <Server>Server01</Server>
      <Name>MyDatabase</Name>
      <Timeout>30</Timeout>
    </Database>
  </Application>
</Configuration>
```

### 3. Créer un flux RSS simple

```sql
-- Structure simplifiée d'un flux RSS
SELECT
    'Mon Blog' AS 'channel/title',
    'http://monblog.com' AS 'channel/link',
    'Derniers articles' AS 'channel/description',
    (
        SELECT
            Titre AS 'title',
            Lien AS 'link',
            Description AS 'description',
            DatePublication AS 'pubDate'
        FROM Articles
        ORDER BY DatePublication DESC
        FOR XML PATH('item'), TYPE
    ) AS 'channel'
FOR XML PATH(''), ROOT('rss');
```

## Comparaison des trois modes

| Critère | RAW | AUTO | PATH |
|---------|-----|------|------|
| **Simplicité** | ★★★★★ | ★★★★☆ | ★★★☆☆ |
| **Contrôle structure** | ★☆☆☆☆ | ★★☆☆☆ | ★★★★★ |
| **Hiérarchie auto** | Non | Oui | Manuelle |
| **Personnalisation** | Faible | Moyenne | Totale |
| **Cas d'usage** | Export simple | Export avec relations | Structure précise |
| **Recommandation** | Débutant | Intermédiaire | Expert / Production |

## Bonnes pratiques

1. **Choisir le bon mode** :
   - RAW pour des exports simples et rapides
   - AUTO pour des exports avec relations simples
   - PATH pour un contrôle précis de la structure

2. **Utiliser TYPE dans les sous-requêtes** :
   - Toujours ajouter `TYPE` quand vous imbriquez des `FOR XML`
   - Sinon, le XML sera échappé (`&lt;` au lieu de `<`)

3. **Ajouter ROOT pour un XML valide** :
   - Un document XML doit avoir un seul élément racine
   - Utilisez `ROOT('NomRacine')` pour respecter cette règle

4. **Gérer les NULL explicitement** :
   - Décidez si les NULL doivent être absents ou représentés
   - Utilisez `ELEMENTS XSINIL` si nécessaire

5. **Performance** :
   - FOR XML peut être coûteux sur de gros volumes
   - Testez les performances et envisagez une pagination
   - Considérez l'utilisation d'index appropriés

6. **Validation** :
   - Le XML généré est bien formé mais pas forcément valide selon un schéma
   - Validez le XML généré si vous devez respecter un schéma XSD spécifique

## Résumé des syntaxes

### RAW
```sql
FOR XML RAW                                    -- Éléments <row>
FOR XML RAW('NomElement')                      -- Personnaliser le nom
FOR XML RAW, ROOT('Racine')                    -- Ajouter racine
FOR XML RAW, ELEMENTS                          -- Colonnes comme éléments
```

### AUTO
```sql
FOR XML AUTO                                   -- Structure automatique
FOR XML AUTO, ROOT('Racine')                   -- Avec racine
FOR XML AUTO, ELEMENTS                         -- Colonnes comme éléments
```

### PATH
```sql
FOR XML PATH('NomElement')                     -- Element de base
FOR XML PATH('NomElement'), ROOT('Racine')     -- Avec racine
FOR XML PATH(''), ROOT('Racine')               -- Pas d'élément intermédiaire

-- Dans les alias de colonnes :
AS '@attribut'                                 -- Créer un attribut
AS 'Element/SousElement'                       -- Créer une hiérarchie
AS 'data()'                                    -- Texte brut
```

## Conclusion

La clause `FOR XML` est un outil puissant pour transformer des données relationnelles en XML :

- **RAW** : Simple et rapide, idéal pour débuter
- **AUTO** : Pratique pour des structures avec relations
- **PATH** : Le plus puissant et flexible, recommandé pour la production

Le mode **PATH** est généralement le meilleur choix car il offre le contrôle le plus fin tout en restant relativement intuitif une fois que l'on comprend la syntaxe XPath.

Avec ces trois modes, vous pouvez couvrir pratiquement tous les besoins de génération XML dans SQL Server !
