# 5.5.1 CREATE PROCEDURE (ou PROC)

## Introduction

Les **procédures stockées** (ou *stored procedures* en anglais) sont des programmes SQL enregistrés dans la base de données qui peuvent être exécutés à la demande. Elles constituent l'un des outils les plus puissants de T-SQL pour encapsuler la logique métier et automatiser les tâches.

### Qu'est-ce qu'une Procédure Stockée ?

Une procédure stockée est un **ensemble d'instructions SQL** regroupées sous un nom unique et stockées dans la base de données. Une fois créée, elle peut être exécutée autant de fois que nécessaire, comme si vous appeliez une fonction dans un langage de programmation traditionnel.

**Analogie simple :** C'est comme une **recette de cuisine** enregistrée :
- La recette (procédure) décrit les étapes à suivre
- Les ingrédients sont les paramètres
- Vous pouvez exécuter la recette à volonté
- Le plat final est le résultat

---

## Pourquoi Utiliser des Procédures Stockées ?

### Sans procédure stockée

Imaginez que vous devez régulièrement ajouter un nouveau client avec vérifications :

```sql
-- À chaque fois, vous devez écrire tout ce code
DECLARE @Email VARCHAR(100) = 'nouveau@email.com';

-- Vérifier si l'email existe déjà
IF EXISTS (SELECT 1 FROM Clients WHERE Email = @Email)
BEGIN
    PRINT 'Erreur : Email déjà utilisé';
    RETURN;
END

-- Insérer le client
INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
VALUES ('Dupont', 'Jean', @Email, GETDATE());

-- Logger l'opération
INSERT INTO LogOperations (TypeOperation, DateOperation, Details)
VALUES ('CREATION_CLIENT', GETDATE(), 'Client créé avec email: ' + @Email);

PRINT 'Client créé avec succès';
```

**Problèmes :**
- Code répétitif et verbeux
- Risque d'erreurs (oubli d'une étape)
- Difficile à maintenir (changements à répliquer partout)
- Logique métier exposée dans l'application

### Avec une procédure stockée

```sql
-- Créer la procédure une seule fois
CREATE PROCEDURE SpCreerClient
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100)
AS
BEGIN
    -- Toute la logique est encapsulée ici
    IF EXISTS (SELECT 1 FROM Clients WHERE Email = @Email)
    BEGIN
        PRINT 'Erreur : Email déjà utilisé';
        RETURN;
    END

    INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
    VALUES (@Nom, @Prenom, @Email, GETDATE());

    INSERT INTO LogOperations (TypeOperation, DateOperation, Details)
    VALUES ('CREATION_CLIENT', GETDATE(), 'Client créé avec email: ' + @Email);

    PRINT 'Client créé avec succès';
END;

-- Utilisation simple et réutilisable
EXEC SpCreerClient 'Dupont', 'Jean', 'nouveau@email.com';
```

**Avantages :**
- ✅ Code réutilisable
- ✅ Maintenance centralisée
- ✅ Sécurité accrue (logique cachée)
- ✅ Performance optimisée

## Syntaxe de Base

### Structure minimale

```sql
CREATE PROCEDURE nom_procedure
AS
BEGIN
    -- Instructions SQL ici
END;
```

### Syntaxe complète

```sql
CREATE PROCEDURE [schema.]nom_procedure
    @parametre1 type_donnees [= valeur_defaut],
    @parametre2 type_donnees [= valeur_defaut]
AS
BEGIN
    -- Instructions SQL
    -- Peuvent inclure : SELECT, INSERT, UPDATE, DELETE
    -- Variables, conditions, boucles, etc.
END;
```

**Éléments clés :**
- `CREATE PROCEDURE` ou `CREATE PROC` (les deux sont acceptés)
- Le nom de la procédure (convention : préfixe `Sp` pour "Stored Procedure")
- Les paramètres (optionnels)
- `AS` introduit le corps de la procédure
- `BEGIN` et `END` délimitent le bloc d'instructions

---

## Premier Exemple : Procédure Simple

### Exemple 1 : Afficher un message

La procédure la plus simple possible :

```sql
-- Créer la procédure
CREATE PROCEDURE SpDireBonjour
AS
BEGIN
    PRINT 'Bonjour ! Ceci est ma première procédure stockée.';
END;
```

**Exécuter la procédure :**

```sql
-- Méthode 1 : Avec EXECUTE
EXECUTE SpDireBonjour;

-- Méthode 2 : Avec EXEC (plus court)
EXEC SpDireBonjour;

-- Méthode 3 : Sans mot-clé (si première instruction)
SpDireBonjour;
```

**Résultat :**
```
Bonjour ! Ceci est ma première procédure stockée.
```

**Note :** `PRINT` affiche un message dans l'onglet "Messages" de SSMS, pas dans les résultats.

---

### Exemple 2 : Procédure avec requête SELECT

```sql
-- Procédure qui retourne des données
CREATE PROCEDURE SpListerClients
AS
BEGIN
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        DateInscription
    FROM Clients
    ORDER BY Nom, Prenom;
END;
```

**Exécution :**

```sql
EXEC SpListerClients;
```

**Résultat :** Un jeu de résultats avec tous les clients, exactement comme si vous aviez exécuté le SELECT directement.

---

### Exemple 3 : Procédure avec INSERT

```sql
-- Procédure pour insérer un nouveau département
CREATE PROCEDURE SpAjouterDepartement
AS
BEGIN
    INSERT INTO Departements (NomDepartement, DateCreation)
    VALUES ('Nouveau Département', GETDATE());

    PRINT 'Département ajouté avec succès';
END;
```

**Exécution :**

```sql
EXEC SpAjouterDepartement;
```

**Résultat :** Un nouveau département est créé dans la table.

## Procédures avec Paramètres

Les paramètres permettent de rendre les procédures **flexibles et réutilisables**.

### Syntaxe des paramètres

```sql
CREATE PROCEDURE nom_procedure
    @parametre1 type,
    @parametre2 type,
    @parametre3 type = valeur_defaut  -- Paramètre optionnel
AS
BEGIN
    -- Utiliser @parametre1, @parametre2, @parametre3
END;
```

---

### Exemple 4 : Procédure avec un paramètre

```sql
-- Procédure pour rechercher un client par ID
CREATE PROCEDURE SpObtenirClient
    @ClientID INT
AS
BEGIN
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Ville
    FROM Clients
    WHERE ClientID = @ClientID;
END;
```

**Exécution avec paramètre :**

```sql
-- Méthode 1 : Par position
EXEC SpObtenirClient 5;

-- Méthode 2 : Par nom (recommandé pour la clarté)
EXEC SpObtenirClient @ClientID = 5;
```

---

### Exemple 5 : Procédure avec plusieurs paramètres

```sql
-- Procédure pour insérer un nouveau client
CREATE PROCEDURE SpInsererClient
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100),
    @Ville VARCHAR(50)
AS
BEGIN
    INSERT INTO Clients (Nom, Prenom, Email, Ville, DateInscription)
    VALUES (@Nom, @Prenom, @Email, @Ville, GETDATE());

    PRINT 'Client inséré avec succès';
END;
```

**Exécution :**

```sql
-- Passage par position
EXEC SpInsererClient 'Martin', 'Sophie', 'sophie.martin@email.com', 'Paris';

-- Passage par nom (plus clair)
EXEC SpInsererClient
    @Nom = 'Martin',
    @Prenom = 'Sophie',
    @Email = 'sophie.martin@email.com',
    @Ville = 'Paris';
```

**Bonne pratique :** Utilisez toujours le passage par nom pour améliorer la lisibilité.

---

### Exemple 6 : Paramètres avec valeurs par défaut

Les paramètres optionnels ont une valeur par défaut :

```sql
-- Procédure de recherche avec filtre optionnel
CREATE PROCEDURE SpRechercherClients
    @Ville VARCHAR(50) = NULL,  -- Paramètre optionnel
    @ActifUniquement BIT = 1    -- Valeur par défaut : 1 (vrai)
AS
BEGIN
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Ville,
        Actif
    FROM Clients
    WHERE
        (@Ville IS NULL OR Ville = @Ville)
        AND Actif = @ActifUniquement
    ORDER BY Nom;
END;
```

**Différentes façons d'exécuter :**

```sql
-- Sans paramètres (utilise les valeurs par défaut)
EXEC SpRechercherClients;
-- Retourne tous les clients actifs

-- Avec le filtre ville
EXEC SpRechercherClients @Ville = 'Paris';
-- Retourne uniquement les clients actifs de Paris

-- Avec les deux paramètres
EXEC SpRechercherClients @Ville = 'Lyon', @ActifUniquement = 0;
-- Retourne les clients inactifs de Lyon

-- Paramètre par défaut + un paramètre personnalisé
EXEC SpRechercherClients @ActifUniquement = 0;
-- Retourne tous les clients inactifs (toutes villes)
```

## Utilisation de Variables Locales

À l'intérieur d'une procédure, vous pouvez déclarer et utiliser des **variables locales**.

### Syntaxe

```sql
CREATE PROCEDURE nom_procedure
AS
BEGIN
    -- Déclaration de variables
    DECLARE @variable1 type;
    DECLARE @variable2 type = valeur_initiale;

    -- Utilisation des variables
    SET @variable1 = valeur;
    SELECT @variable2 = colonne FROM table;
END;
```

---

### Exemple 7 : Procédure avec variables locales

```sql
-- Calculer et afficher des statistiques
CREATE PROCEDURE SpStatistiquesClients
AS
BEGIN
    DECLARE @NombreTotal INT;
    DECLARE @NombreActifs INT;
    DECLARE @Pourcentage DECIMAL(5,2);

    -- Calculer le nombre total de clients
    SELECT @NombreTotal = COUNT(*) FROM Clients;

    -- Calculer le nombre de clients actifs
    SELECT @NombreActifs = COUNT(*) FROM Clients WHERE Actif = 1;

    -- Calculer le pourcentage
    SET @Pourcentage = (@NombreActifs * 100.0) / @NombreTotal;

    -- Afficher les résultats
    PRINT 'Statistiques des clients :';
    PRINT 'Nombre total : ' + CAST(@NombreTotal AS VARCHAR(10));
    PRINT 'Nombre actifs : ' + CAST(@NombreActifs AS VARCHAR(10));
    PRINT 'Pourcentage actifs : ' + CAST(@Pourcentage AS VARCHAR(10)) + '%';
END;
```

**Exécution :**

```sql
EXEC SpStatistiquesClients;
```

**Résultat :**
```
Statistiques des clients :
Nombre total : 150
Nombre actifs : 132
Pourcentage actifs : 88.00%
```

---

### Exemple 8 : Procédure avec logique conditionnelle

```sql
-- Procédure pour mettre à jour le statut d'un client
CREATE PROCEDURE SpMettreAJourStatutClient
    @ClientID INT,
    @NouveauStatut BIT
AS
BEGIN
    DECLARE @StatutActuel BIT;
    DECLARE @NomClient VARCHAR(100);

    -- Récupérer le statut actuel
    SELECT
        @StatutActuel = Actif,
        @NomClient = Nom + ' ' + Prenom
    FROM Clients
    WHERE ClientID = @ClientID;

    -- Vérifier si le client existe
    IF @NomClient IS NULL
    BEGIN
        PRINT 'Erreur : Client introuvable';
        RETURN;
    END

    -- Vérifier si le statut change réellement
    IF @StatutActuel = @NouveauStatut
    BEGIN
        PRINT 'Le statut est déjà ' +
              CASE WHEN @NouveauStatut = 1 THEN 'actif' ELSE 'inactif' END;
        RETURN;
    END

    -- Effectuer la mise à jour
    UPDATE Clients
    SET Actif = @NouveauStatut
    WHERE ClientID = @ClientID;

    -- Confirmer l'opération
    PRINT 'Statut de ' + @NomClient + ' mis à jour avec succès';
END;
```

**Exécution :**

```sql
-- Désactiver le client avec ID 5
EXEC SpMettreAJourStatutClient @ClientID = 5, @NouveauStatut = 0;
```

## Gestion des Erreurs de Base

### Exemple 9 : Validation des paramètres

```sql
-- Procédure avec validation des entrées
CREATE PROCEDURE SpCreerCommande
    @ClientID INT,
    @MontantTotal DECIMAL(10,2)
AS
BEGIN
    -- Validation : Montant doit être positif
    IF @MontantTotal <= 0
    BEGIN
        PRINT 'Erreur : Le montant doit être supérieur à zéro';
        RETURN;
    END

    -- Validation : Le client doit exister
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        PRINT 'Erreur : Client introuvable';
        RETURN;
    END

    -- Validation : Le client doit être actif
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID AND Actif = 1)
    BEGIN
        PRINT 'Erreur : Le client n''est pas actif';
        RETURN;
    END

    -- Si toutes les validations passent, créer la commande
    INSERT INTO Commandes (ClientID, DateCommande, MontantTotal, Statut)
    VALUES (@ClientID, GETDATE(), @MontantTotal, 'En attente');

    PRINT 'Commande créée avec succès';
END;
```

**Exécution avec données invalides :**

```sql
-- Tentative avec montant négatif
EXEC SpCreerCommande @ClientID = 5, @MontantTotal = -100;
-- Résultat : Erreur : Le montant doit être supérieur à zéro

-- Tentative avec client inexistant
EXEC SpCreerCommande @ClientID = 9999, @MontantTotal = 100;
-- Résultat : Erreur : Client introuvable
```

## Retourner des Données

Les procédures peuvent retourner des données de plusieurs façons :

### Méthode 1 : Avec SELECT

```sql
CREATE PROCEDURE SpObtenirCommandesClient
    @ClientID INT
AS
BEGIN
    SELECT
        CommandeID,
        DateCommande,
        MontantTotal,
        Statut
    FROM Commandes
    WHERE ClientID = @ClientID
    ORDER BY DateCommande DESC;
END;
```

**Utilisation dans une application :**
- Le résultat du SELECT est retourné au client (application, SSMS, etc.)
- Peut être consommé comme n'importe quel jeu de résultats

---

### Méthode 2 : Multiples jeux de résultats

Une procédure peut retourner plusieurs jeux de résultats :

```sql
CREATE PROCEDURE SpRapportClient
    @ClientID INT
AS
BEGIN
    -- Premier jeu : Informations du client
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        DateInscription
    FROM Clients
    WHERE ClientID = @ClientID;

    -- Deuxième jeu : Commandes du client
    SELECT
        CommandeID,
        DateCommande,
        MontantTotal,
        Statut
    FROM Commandes
    WHERE ClientID = @ClientID
    ORDER BY DateCommande DESC;

    -- Troisième jeu : Statistiques
    SELECT
        COUNT(*) AS NombreCommandes,
        SUM(MontantTotal) AS TotalAchats,
        AVG(MontantTotal) AS MoyenneCommande
    FROM Commandes
    WHERE ClientID = @ClientID;
END;
```

**Exécution :**

```sql
EXEC SpRapportClient @ClientID = 5;
```

**Résultat :** Trois onglets de résultats distincts dans SSMS.

## Options et Paramètres Avancés

### SET NOCOUNT ON

Cette option empêche SQL Server d'envoyer des messages de comptage de lignes :

```sql
CREATE PROCEDURE SpExempleNoCount
AS
BEGIN
    SET NOCOUNT ON;  -- Désactive les messages "X row(s) affected"

    -- Vos instructions
    INSERT INTO LogOperations (TypeOperation, DateOperation)
    VALUES ('TEST', GETDATE());

    SELECT * FROM LogOperations WHERE TypeOperation = 'TEST';
END;
```

**Pourquoi utiliser SET NOCOUNT ON ?**
- ✅ Réduit le trafic réseau (moins de messages)
- ✅ Améliore légèrement les performances
- ✅ Standard pour les procédures stockées en production

**Convention :** Placez toujours `SET NOCOUNT ON;` au début de vos procédures.

## Conventions de Nommage

### Bonnes pratiques pour nommer les procédures

#### 1. Utiliser un préfixe cohérent

```sql
-- ✅ BON : Préfixe 'Sp' ou 'usp' (user stored procedure)
CREATE PROCEDURE SpCreerClient ...
CREATE PROCEDURE uspCreerClient ...

-- ❌ MAUVAIS : Pas de préfixe ou préfixe système 'sp_'
CREATE PROCEDURE CreerClient ...
CREATE PROCEDURE sp_CreerClient ...  -- Éviter 'sp_' (réservé au système)
```

**Note :** Le préfixe `sp_` est réservé aux procédures système de Microsoft. L'utiliser peut causer des problèmes de performance car SQL Server cherche d'abord dans la base `master`.

#### 2. Utiliser des verbes d'action

```sql
-- ✅ BON : Verbe d'action clair
CREATE PROCEDURE SpCreerClient ...
CREATE PROCEDURE SpSupprimerCommande ...
CREATE PROCEDURE SpMettreAJourPrix ...
CREATE PROCEDURE SpObtenirStatistiques ...

-- ❌ MAUVAIS : Nom ambigu
CREATE PROCEDURE SpClient ...
CREATE PROCEDURE SpDonnees ...
```

#### 3. Être descriptif mais concis

```sql
-- ✅ BON : Descriptif et concis
CREATE PROCEDURE SpValiderCommande ...
CREATE PROCEDURE SpCalculerTotalVentes ...

-- ❌ MAUVAIS : Trop long
CREATE PROCEDURE SpProcedurePourValiderUneCommandeEtMettreAJourLeStock ...

-- ❌ MAUVAIS : Trop vague
CREATE PROCEDURE SpFaire ...
```

#### 4. Convention CRUD (Create, Read, Update, Delete)

```sql
-- Créer
CREATE PROCEDURE SpCreerClient ...
CREATE PROCEDURE SpInsererProduit ...

-- Lire / Obtenir
CREATE PROCEDURE SpObtenirClient ...
CREATE PROCEDURE SpListerProduits ...

-- Mettre à jour
CREATE PROCEDURE SpMettreAJourClient ...
CREATE PROCEDURE SpModifierPrix ...

-- Supprimer
CREATE PROCEDURE SpSupprimerClient ...
CREATE PROCEDURE SpEffacerCommande ...
```

## Modifier une Procédure Existante

### ALTER PROCEDURE

Pour modifier une procédure existante sans la supprimer :

```sql
ALTER PROCEDURE SpObtenirClient
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Nouvelle version avec plus de colonnes
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Telephone,  -- Colonne ajoutée
        Ville,
        DateInscription
    FROM Clients
    WHERE ClientID = @ClientID;
END;
```

**Avantage :** Les permissions sont conservées (pas besoin de les réattribuer).

---

### CREATE OR ALTER (SQL Server 2016+)

Syntaxe moderne qui crée la procédure si elle n'existe pas, ou la modifie si elle existe :

```sql
CREATE OR ALTER PROCEDURE SpObtenirClient
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ClientID,
        Nom,
        Prenom,
        Email
    FROM Clients
    WHERE ClientID = @ClientID;
END;
```

**Avantage :** Pas besoin de vérifier si la procédure existe avant de la créer/modifier.

## Exemple Complet : Procédure de Gestion de Commande

Voici un exemple réaliste qui combine plusieurs concepts :

```sql
CREATE OR ALTER PROCEDURE SpPasserCommande
    @ClientID INT,
    @ProduitID INT,
    @Quantite INT,
    @PrixUnitaire DECIMAL(10,2) = NULL  -- Optionnel, sinon prix du catalogue
AS
BEGIN
    SET NOCOUNT ON;

    -- Variables locales
    DECLARE @MontantTotal DECIMAL(10,2);
    DECLARE @StockDisponible INT;
    DECLARE @CommandeID INT;

    -- === VALIDATIONS ===

    -- 1. Vérifier que le client existe et est actif
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID AND Actif = 1)
    BEGIN
        PRINT 'Erreur : Client introuvable ou inactif';
        RETURN;
    END

    -- 2. Vérifier que le produit existe
    IF NOT EXISTS (SELECT 1 FROM Produits WHERE ProduitID = @ProduitID)
    BEGIN
        PRINT 'Erreur : Produit introuvable';
        RETURN;
    END

    -- 3. Vérifier la quantité
    IF @Quantite <= 0
    BEGIN
        PRINT 'Erreur : La quantité doit être supérieure à zéro';
        RETURN;
    END

    -- 4. Vérifier le stock disponible
    SELECT @StockDisponible = StockDisponible
    FROM Produits
    WHERE ProduitID = @ProduitID;

    IF @StockDisponible < @Quantite
    BEGIN
        PRINT 'Erreur : Stock insuffisant. Disponible : ' + CAST(@StockDisponible AS VARCHAR(10));
        RETURN;
    END

    -- === TRAITEMENT ===

    -- 5. Déterminer le prix (catalogue si non fourni)
    IF @PrixUnitaire IS NULL
    BEGIN
        SELECT @PrixUnitaire = Prix
        FROM Produits
        WHERE ProduitID = @ProduitID;
    END

    -- 6. Calculer le montant total
    SET @MontantTotal = @PrixUnitaire * @Quantite;

    -- 7. Créer la commande
    INSERT INTO Commandes (ClientID, DateCommande, MontantTotal, Statut)
    VALUES (@ClientID, GETDATE(), @MontantTotal, 'En cours');

    -- Récupérer l'ID de la commande créée
    SET @CommandeID = SCOPE_IDENTITY();

    -- 8. Créer la ligne de détail
    INSERT INTO DetailsCommande (CommandeID, ProduitID, Quantite, PrixUnitaire)
    VALUES (@CommandeID, @ProduitID, @Quantite, @PrixUnitaire);

    -- 9. Mettre à jour le stock
    UPDATE Produits
    SET StockDisponible = StockDisponible - @Quantite
    WHERE ProduitID = @ProduitID;

    -- 10. Logger l'opération
    INSERT INTO LogOperations (TypeOperation, DateOperation, Details)
    VALUES ('CREATION_COMMANDE', GETDATE(),
            'Commande ' + CAST(@CommandeID AS VARCHAR(10)) +
            ' créée pour le client ' + CAST(@ClientID AS VARCHAR(10)));

    -- === CONFIRMATION ===
    PRINT 'Commande créée avec succès !';
    PRINT 'Numéro de commande : ' + CAST(@CommandeID AS VARCHAR(10));
    PRINT 'Montant total : ' + CAST(@MontantTotal AS VARCHAR(10)) + ' €';
END;
```

**Utilisation :**

```sql
-- Passer une commande
EXEC SpPasserCommande
    @ClientID = 5,
    @ProduitID = 12,
    @Quantite = 3;
```

## Bonnes Pratiques

### ✅ À FAIRE

1. **Toujours utiliser SET NOCOUNT ON**
   ```sql
   CREATE PROCEDURE SpNomProcedure
   AS
   BEGIN
       SET NOCOUNT ON;  -- Première ligne après BEGIN
       -- Reste du code
   END;
   ```

2. **Valider tous les paramètres d'entrée**
   ```sql
   IF @Parametre IS NULL OR @Parametre = ''
   BEGIN
       PRINT 'Erreur : Paramètre invalide';
       RETURN;
   END
   ```

3. **Utiliser des noms explicites**
   - ✅ `SpCreerFacture`, `SpCalculerTVA`
   - ❌ `SpProc1`, `SpFaire`

4. **Documenter avec des commentaires**
   ```sql
   /*
   Nom : SpPasserCommande
   Description : Crée une nouvelle commande avec validation du stock
   Paramètres :
       @ClientID - ID du client
       @ProduitID - ID du produit
       @Quantite - Quantité commandée
   Auteur : Votre Nom
   Date : 2024-11-18
   */
   CREATE PROCEDURE SpPasserCommande ...
   ```

5. **Utiliser BEGIN...END pour la clarté**
   ```sql
   IF @Condition = 1
   BEGIN
       -- Instructions
   END
   ```

6. **Gérer les erreurs (TRY...CATCH)**
   - Voir la section 5.3 (Gestion des erreurs), déjà abordée plus tôt dans ce chapitre

### ❌ À ÉVITER

1. **Ne pas utiliser SELECT * dans les procédures**
   ```sql
   -- ❌ MAUVAIS
   SELECT * FROM Clients;

   -- ✅ BON
   SELECT ClientID, Nom, Prenom, Email FROM Clients;
   ```

2. **Ne pas utiliser le préfixe 'sp_' (réservé au système)**
   ```sql
   -- ❌ MAUVAIS
   CREATE PROCEDURE sp_ObtenirClient ...

   -- ✅ BON
   CREATE PROCEDURE SpObtenirClient ...
   ```

3. **Éviter les procédures trop longues**
   - Si > 200 lignes, envisager de diviser en plusieurs procédures

4. **Ne pas mélanger logique métier et présentation**
   - Les procédures doivent contenir la logique
   - La présentation doit être gérée par l'application

## Comparaison : Procédures vs Autres Objets

| Aspect | Procédure Stockée | Vue | Fonction Table |
|--------|-------------------|-----|----------------|
| **Paramètres** | ✅ Oui | ❌ Non | ✅ Oui |
| **Logique conditionnelle** | ✅ Oui (IF, WHILE) | ❌ Non | ⚠️ Limitée |
| **Modification de données** | ✅ Oui (INSERT, UPDATE, DELETE) | ⚠️ Limitée | ❌ Non |
| **Retour de valeur** | Multiples jeux de résultats | 1 jeu de résultats | 1 jeu de résultats |
| **Utilisation** | EXEC ProcName | SELECT FROM ViewName | SELECT FROM FunctionName(@param) |
| **Gestion d'erreurs** | ✅ TRY...CATCH | ❌ Non | ⚠️ Limitée |
| **Performance** | ✅ Optimisée (plan caché) | Variable | Variable |

## Sécurité et Permissions

### Exécuter une procédure nécessite des permissions

```sql
-- Donner la permission d'exécuter une procédure
GRANT EXECUTE ON SpObtenirClient TO UtilisateurTest;

-- Révoquer la permission
REVOKE EXECUTE ON SpObtenirClient FROM UtilisateurTest;
```

### Avantage : Sécurité par encapsulation

L'utilisateur peut exécuter la procédure sans avoir accès direct aux tables :

```sql
-- L'utilisateur n'a PAS accès à la table Clients
-- MAIS il peut exécuter cette procédure
EXEC SpObtenirClient @ClientID = 5;
```

**Bénéfice :** Contrôle fin de ce que les utilisateurs peuvent faire.

## Résumé

### Points Clés

**Qu'est-ce qu'une procédure stockée ?**
- Ensemble d'instructions SQL enregistrées sous un nom
- Exécutable à la demande avec `EXEC` ou `EXECUTE`
- Peut accepter des paramètres et retourner des résultats

**Syntaxe de base :**
```sql
CREATE PROCEDURE nom_procedure
    @param1 type,
    @param2 type = valeur_defaut
AS
BEGIN
    SET NOCOUNT ON;
    -- Instructions SQL
END;
```

**Avantages principaux :**
- 🔄 Réutilisabilité du code
- 🔒 Sécurité accrue (logique encapsulée)
- ⚡ Performance optimisée (plan d'exécution caché)
- 🛠️ Maintenance centralisée
- ✅ Validation et gestion d'erreurs

**Bonnes pratiques :**
- Toujours utiliser `SET NOCOUNT ON`
- Valider tous les paramètres
- Utiliser des noms explicites avec préfixe
- Documenter le code
- Éviter `SELECT *`
