# 4.6.3 L'instruction MERGE (Concepts et utilisation)

## Introduction

L'instruction **MERGE** (aussi appelée "UPSERT" dans d'autres SGBD) est une commande puissante qui permet de **synchroniser deux tables** en effectuant des opérations INSERT, UPDATE et/ou DELETE en **une seule instruction atomique**.

MERGE est particulièrement utile pour :
- Synchroniser des données entre une source et une destination
- Mettre à jour des enregistrements existants ou en insérer de nouveaux
- Maintenir des entrepôts de données (Data Warehouses)
- Effectuer des opérations conditionnelles complexes

### Le concept en une phrase

MERGE compare une **table source** avec une **table cible** et effectue différentes actions selon que les lignes correspondent ou non.

## Le problème que MERGE résout

### Sans MERGE : Code complexe et répétitif

Avant MERGE, pour synchroniser des données, vous deviez écrire plusieurs instructions :

```sql
-- 1. Mettre à jour les enregistrements existants
UPDATE Cible
SET Cible.Prix = Source.Prix,
    Cible.Stock = Source.Stock
FROM ProduitsCible Cible
INNER JOIN ProduitsSource Source ON Cible.ProduitID = Source.ProduitID;

-- 2. Insérer les nouveaux enregistrements
INSERT INTO ProduitsCible (ProduitID, NomProduit, Prix, Stock)
SELECT ProduitID, NomProduit, Prix, Stock
FROM ProduitsSource Source
WHERE NOT EXISTS (
    SELECT 1 FROM ProduitsCible Cible
    WHERE Cible.ProduitID = Source.ProduitID
);

-- 3. Supprimer les enregistrements obsolètes (optionnel)
DELETE FROM ProduitsCible
WHERE ProduitID NOT IN (SELECT ProduitID FROM ProduitsSource);
```

**Problèmes :**
- Trois instructions séparées (possibilité d'incohérence)
- Code verbose et répétitif
- Difficile à maintenir
- Potentiellement moins performant

### Avec MERGE : Une seule instruction

```sql
MERGE INTO ProduitsCible AS Cible
USING ProduitsSource AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET
        Cible.Prix = Source.Prix,
        Cible.Stock = Source.Stock
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Stock)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Stock)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

**Avantages :**
- Une seule instruction atomique
- Plus lisible et maintenable
- Potentiellement plus performant
- Garantit la cohérence

## Analogie simple : La bibliothèque

Imaginez que vous devez synchroniser le catalogue de votre bibliothèque (cible) avec une liste mise à jour de livres (source) :

- **Livres déjà en catalogue** (MATCHED) → Mettre à jour les informations (prix, disponibilité)
- **Nouveaux livres** (NOT MATCHED BY TARGET) → Ajouter au catalogue
- **Livres retirés** (NOT MATCHED BY SOURCE) → Supprimer du catalogue

MERGE fait tout cela en **une seule opération** !

## Syntaxe de MERGE

### Structure de base

```sql
MERGE INTO table_cible AS alias_cible
USING table_source AS alias_source
ON condition_de_correspondance
WHEN MATCHED [AND condition_supplémentaire] THEN
    UPDATE SET colonne = valeur, ...
WHEN NOT MATCHED BY TARGET [AND condition] THEN
    INSERT (colonnes) VALUES (valeurs)
WHEN NOT MATCHED BY SOURCE [AND condition] THEN
    DELETE
[OUTPUT ...]
;  -- Point-virgule OBLIGATOIRE !
```

### Éléments clés

**1. MERGE INTO** : La table de destination (cible) que vous voulez synchroniser

**2. USING** : La source des données (table, vue, sous-requête)

**3. ON** : La condition qui détermine si une ligne correspond (souvent sur la clé primaire)

**4. WHEN MATCHED** : Que faire quand une ligne existe dans les deux tables

**5. WHEN NOT MATCHED BY TARGET** : Que faire quand une ligne existe seulement dans la source

**6. WHEN NOT MATCHED BY SOURCE** : Que faire quand une ligne existe seulement dans la cible

**7. Point-virgule (;)** : OBLIGATOIRE à la fin de l'instruction MERGE

## Exemple de base pas à pas

### Scénario : Mise à jour des stocks

**Table cible (Inventaire actuel) :**

| ProduitID | Produit | Prix | Stock |
|-----------|---------|------|-------|
| 1 | Laptop | 800 | 10 |
| 2 | Souris | 25 | 50 |
| 3 | Clavier | 60 | 30 |

**Table source (Nouvelle livraison) :**

| ProduitID | Produit | Prix | Stock |
|-----------|---------|------|-------|
| 2 | Souris | 20 | 100 |
| 3 | Clavier | 60 | 80 |
| 4 | Écran | 300 | 15 |

**Objectif :**
- **Produit 1 (Laptop)** : Absent de la source → Garder tel quel (ou supprimer)
- **Produit 2 (Souris)** : Dans les deux → Mettre à jour le prix et le stock
- **Produit 3 (Clavier)** : Dans les deux → Mettre à jour le stock (prix identique)
- **Produit 4 (Écran)** : Nouveau → Ajouter à l'inventaire

### Requête MERGE

```sql
MERGE INTO Inventaire AS Cible
USING NouveauxProduits AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET
        Cible.Prix = Source.Prix,
        Cible.Stock = Source.Stock
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, Produit, Prix, Stock)
    VALUES (Source.ProduitID, Source.Produit, Source.Prix, Source.Stock);
```

**Résultat dans Inventaire :**

| ProduitID | Produit | Prix | Stock | Action |
|-----------|---------|------|-------|--------|
| 1 | Laptop | 800 | 10 | Inchangé |
| 2 | Souris | 20 | 100 | Mis à jour |
| 3 | Clavier | 60 | 80 | Mis à jour |
| 4 | Écran | 300 | 15 | Inséré |

## Les trois clauses WHEN

### 1. WHEN MATCHED - Correspondance trouvée

**Signification :** Une ligne existe dans **les deux** tables (source ET cible).

**Action typique :** UPDATE

```sql
WHEN MATCHED THEN
    UPDATE SET
        Cible.Colonne1 = Source.Colonne1,
        Cible.Colonne2 = Source.Colonne2
```

**Avec condition supplémentaire :**

```sql
WHEN MATCHED AND Source.Prix <> Cible.Prix THEN
    UPDATE SET Cible.Prix = Source.Prix
```

Ne met à jour que si le prix a changé.

**Ou DELETE :**

```sql
WHEN MATCHED AND Source.Actif = 0 THEN
    DELETE
```

Supprime les lignes correspondantes si elles sont marquées comme inactives dans la source.

### 2. WHEN NOT MATCHED BY TARGET - Nouvelle ligne

**Signification :** Une ligne existe dans la **source** mais PAS dans la **cible**.

**Action typique :** INSERT

```sql
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, Produit, Prix, Stock)
    VALUES (Source.ProduitID, Source.Produit, Source.Prix, Source.Stock)
```

**Avec condition :**

```sql
WHEN NOT MATCHED BY TARGET AND Source.Stock > 0 THEN
    INSERT (ProduitID, Produit, Prix, Stock)
    VALUES (Source.ProduitID, Source.Produit, Source.Prix, Source.Stock)
```

N'insère que les produits en stock.

### 3. WHEN NOT MATCHED BY SOURCE - Ligne obsolète

**Signification :** Une ligne existe dans la **cible** mais PAS dans la **source**.

**Action typique :** DELETE

```sql
WHEN NOT MATCHED BY SOURCE THEN
    DELETE
```

Supprime les produits qui ne sont plus dans la source.

**Avec condition :**

```sql
WHEN NOT MATCHED BY SOURCE AND Cible.DateCreation < '2024-01-01' THEN
    DELETE
```

Ne supprime que les anciennes entrées.

**Ou UPDATE :**

```sql
WHEN NOT MATCHED BY SOURCE THEN
    UPDATE SET Cible.Actif = 0
```

Marque comme inactif au lieu de supprimer.

## Exemples pratiques détaillés

### Exemple 1 : MERGE simple (INSERT et UPDATE uniquement)

**Scénario :** Synchroniser une liste de clients.

```sql
MERGE INTO Clients AS Cible
USING ClientsImportes AS Source
ON Cible.ClientID = Source.ClientID
WHEN MATCHED THEN
    UPDATE SET
        Cible.Nom = Source.Nom,
        Cible.Email = Source.Email,
        Cible.Telephone = Source.Telephone,
        Cible.DateMiseAJour = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ClientID, Nom, Email, Telephone, DateCreation)
    VALUES (Source.ClientID, Source.Nom, Source.Email, Source.Telephone, GETDATE());
```

**Actions :**
- Clients existants : Mise à jour des informations
- Nouveaux clients : Insertion
- Clients absents de la source : Pas de suppression (conservés)

### Exemple 2 : MERGE avec DELETE

**Scénario :** Synchroniser un catalogue de produits en supprimant les produits obsolètes.

```sql
MERGE INTO CatalogueProduits AS Cible
USING CatalogueSource AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET
        Cible.NomProduit = Source.NomProduit,
        Cible.Prix = Source.Prix,
        Cible.Description = Source.Description
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Description)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Description)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

**Actions :**
- Produits existants : Mise à jour
- Nouveaux produits : Insertion
- Produits obsolètes : Suppression

### Exemple 3 : MERGE avec conditions multiples

**Scénario :** Mettre à jour seulement si les valeurs ont changé.

```sql
MERGE INTO Produits AS Cible
USING ProduitsSource AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED AND (
    Cible.Prix <> Source.Prix OR
    Cible.Stock <> Source.Stock
) THEN
    UPDATE SET
        Cible.Prix = Source.Prix,
        Cible.Stock = Source.Stock,
        Cible.DateModification = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Stock, DateCreation)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Stock, GETDATE());
```

**Optimisation :** Ne met à jour que si nécessaire (économise des écritures).

### Exemple 4 : MERGE avec source complexe

**Scénario :** La source est une sous-requête agrégée.

```sql
MERGE INTO StatistiquesVendeurs AS Cible
USING (
    SELECT
        VendeurID,
        COUNT(*) AS NombreVentes,
        SUM(Montant) AS TotalVentes,
        AVG(Montant) AS MoyenneVentes
    FROM Ventes
    WHERE YEAR(DateVente) = 2024
    GROUP BY VendeurID
) AS Source
ON Cible.VendeurID = Source.VendeurID AND Cible.Annee = 2024
WHEN MATCHED THEN
    UPDATE SET
        Cible.NombreVentes = Source.NombreVentes,
        Cible.TotalVentes = Source.TotalVentes,
        Cible.MoyenneVentes = Source.MoyenneVentes
WHEN NOT MATCHED BY TARGET THEN
    INSERT (VendeurID, Annee, NombreVentes, TotalVentes, MoyenneVentes)
    VALUES (Source.VendeurID, 2024, Source.NombreVentes, Source.TotalVentes, Source.MoyenneVentes);
```

La source peut être une **requête complexe** avec jointures et agrégations.

### Exemple 5 : MERGE avec plusieurs actions MATCHED

```sql
MERGE INTO Employes AS Cible
USING EmployesImportes AS Source
ON Cible.EmployeID = Source.EmployeID
WHEN MATCHED AND Source.Actif = 0 THEN
    DELETE
WHEN MATCHED AND Source.Actif = 1 THEN
    UPDATE SET
        Cible.Nom = Source.Nom,
        Cible.Salaire = Source.Salaire,
        Cible.Departement = Source.Departement
WHEN NOT MATCHED BY TARGET THEN
    INSERT (EmployeID, Nom, Salaire, Departement, Actif)
    VALUES (Source.EmployeID, Source.Nom, Source.Salaire, Source.Departement, 1);
```

**Deux clauses MATCHED** : Une pour supprimer, une pour mettre à jour.

## La clause OUTPUT

OUTPUT permet de capturer les résultats de l'opération MERGE.

### Syntaxe de base

```sql
MERGE INTO Cible
USING Source
ON ...
WHEN MATCHED THEN UPDATE ...
WHEN NOT MATCHED THEN INSERT ...
OUTPUT
    $action AS Action,
    inserted.ColonneID,
    deleted.ColonneID;
```

### Variables spéciales

**$action** : Type d'action effectuée ('INSERT', 'UPDATE', ou 'DELETE')

**inserted** : Nouvelles valeurs (après INSERT ou UPDATE)

**deleted** : Anciennes valeurs (avant UPDATE ou après DELETE)

### Exemple avec OUTPUT

```sql
DECLARE @Changes TABLE (
    Action VARCHAR(10),
    ProduitID INT,
    AncienPrix DECIMAL(10,2),
    NouveauPrix DECIMAL(10,2)
);

MERGE INTO Produits AS Cible
USING ProduitsSource AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET Cible.Prix = Source.Prix
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix)
OUTPUT
    $action,
    COALESCE(inserted.ProduitID, deleted.ProduitID),
    deleted.Prix,
    inserted.Prix
INTO @Changes;

-- Afficher les changements
SELECT * FROM @Changes;
```

**Résultat possible :**

| Action | ProduitID | AncienPrix | NouveauPrix |
|--------|-----------|------------|-------------|
| UPDATE | 2 | 25.00 | 20.00 |
| INSERT | 4 | NULL | 300.00 |

### Journalisation avec OUTPUT

```sql
-- Table de journal
CREATE TABLE JournalMerge (
    DateOperation DATETIME DEFAULT GETDATE(),
    Action VARCHAR(10),
    ProduitID INT,
    AncienneValeur VARCHAR(MAX),
    NouvelleValeur VARCHAR(MAX)
);

-- MERGE avec journalisation
MERGE INTO Produits AS Cible
USING ProduitsSource AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET
        Cible.Prix = Source.Prix,
        Cible.Stock = Source.Stock
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Stock)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Stock)
OUTPUT
    $action,
    COALESCE(inserted.ProduitID, deleted.ProduitID),
    CONCAT('Prix:', deleted.Prix, ' Stock:', deleted.Stock),
    CONCAT('Prix:', inserted.Prix, ' Stock:', inserted.Stock)
INTO JournalMerge(Action, ProduitID, AncienneValeur, NouvelleValeur);
```

Crée un **historique complet** de toutes les modifications.

## Cas d'usage pratiques

### A. Data Warehouse : Chargement de dimension

**Scénario :** Mise à jour quotidienne d'une table de dimension.

```sql
-- Dimension Clients dans l'entrepôt
MERGE INTO DWH.DimClients AS Cible
USING (
    SELECT
        ClientID,
        NomComplet,
        Email,
        Ville,
        Pays
    FROM OLTP.Clients
    WHERE DateModification >= DATEADD(DAY, -1, GETDATE())
) AS Source
ON Cible.ClientID = Source.ClientID
WHEN MATCHED THEN
    UPDATE SET
        Cible.NomComplet = Source.NomComplet,
        Cible.Email = Source.Email,
        Cible.Ville = Source.Ville,
        Cible.Pays = Source.Pays,
        Cible.DateMAJ = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ClientID, NomComplet, Email, Ville, Pays, DateCreation)
    VALUES (Source.ClientID, Source.NomComplet, Source.Email, Source.Ville, Source.Pays, GETDATE());
```

### B. Synchronisation de répliques

**Scénario :** Synchroniser deux bases de données (par exemple, entre sites).

```sql
-- Synchroniser les produits du site principal vers le site secondaire
MERGE INTO SiteSecondaire.dbo.Produits AS Cible
USING SitePrincipal.dbo.Produits AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED AND Source.DateModification > Cible.DateModification THEN
    UPDATE SET
        Cible.NomProduit = Source.NomProduit,
        Cible.Prix = Source.Prix,
        Cible.Description = Source.Description,
        Cible.DateModification = Source.DateModification
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Description, DateModification)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Description, Source.DateModification)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

### C. Mise à jour de cache

**Scénario :** Maintenir une table de cache à jour.

```sql
-- Cache des totaux par client
MERGE INTO CacheTotauxClients AS Cible
USING (
    SELECT
        ClientID,
        COUNT(*) AS NombreCommandes,
        SUM(Montant) AS TotalAchats,
        MAX(DateCommande) AS DerniereCommande
    FROM Commandes
    GROUP BY ClientID
) AS Source
ON Cible.ClientID = Source.ClientID
WHEN MATCHED THEN
    UPDATE SET
        Cible.NombreCommandes = Source.NombreCommandes,
        Cible.TotalAchats = Source.TotalAchats,
        Cible.DerniereCommande = Source.DerniereCommande,
        Cible.DateMAJ = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ClientID, NombreCommandes, TotalAchats, DerniereCommande, DateMAJ)
    VALUES (Source.ClientID, Source.NombreCommandes, Source.TotalAchats, Source.DerniereCommande, GETDATE());
```

### D. Import de fichiers CSV

**Scénario :** Importer des données depuis un fichier externe.

```sql
-- 1. Charger le CSV dans une table temporaire
CREATE TABLE #TempImport (
    ProduitID INT,
    NomProduit VARCHAR(100),
    Prix DECIMAL(10,2)
);

BULK INSERT #TempImport
FROM 'C:\imports\produits.csv'
WITH (FIELDTERMINATOR = ',', ROWTERMINATOR = '\n', FIRSTROW = 2);

-- 2. MERGE depuis la table temporaire
MERGE INTO Produits AS Cible
USING #TempImport AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET
        Cible.NomProduit = Source.NomProduit,
        Cible.Prix = Source.Prix
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix);

DROP TABLE #TempImport;
```

### E. Gestion de SCD Type 1 (Slowly Changing Dimension)

**Scénario :** Mise à jour simple en écrasant les anciennes valeurs.

```sql
MERGE INTO DimProduits AS Cible
USING ProduitsCourants AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED AND (
    Cible.Prix <> Source.Prix OR
    Cible.Categorie <> Source.Categorie
) THEN
    UPDATE SET
        Cible.Prix = Source.Prix,
        Cible.Categorie = Source.Categorie,
        Cible.DateDerniereMAJ = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProduitID, NomProduit, Prix, Categorie, DateCreation)
    VALUES (Source.ProduitID, Source.NomProduit, Source.Prix, Source.Categorie, GETDATE());
```

## Performance et optimisation

### Index appropriés

MERGE bénéficie grandement d'index sur les colonnes de jointure :

```sql
-- Index sur la colonne de jointure dans les deux tables
CREATE INDEX IX_Produits_ProduitID ON Produits(ProduitID);
CREATE INDEX IX_ProduitsSource_ProduitID ON ProduitsSource(ProduitID);
```

### Statistiques à jour

```sql
-- Mettre à jour les statistiques avant MERGE
UPDATE STATISTICS Produits;
UPDATE STATISTICS ProduitsSource;
```

### Batch processing pour gros volumes

Pour de très gros volumes, divisez en lots :

```sql
DECLARE @BatchSize INT = 10000;
DECLARE @RowsAffected INT = @BatchSize;

WHILE @RowsAffected = @BatchSize
BEGIN
    MERGE INTO Produits AS Cible
    USING (
        SELECT TOP (@BatchSize) *
        FROM ProduitsSource
        WHERE Traite = 0
    ) AS Source
    ON Cible.ProduitID = Source.ProduitID
    WHEN MATCHED THEN
        UPDATE SET Cible.Prix = Source.Prix
    WHEN NOT MATCHED THEN
        INSERT (ProduitID, NomProduit, Prix)
        VALUES (Source.ProduitID, Source.NomProduit, Source.Prix);

    SET @RowsAffected = @@ROWCOUNT;

    -- Marquer comme traité
    UPDATE ProduitsSource SET Traite = 1
    WHERE ProduitID IN (SELECT ProduitID FROM Source);
END;
```

### Transactions et gestion d'erreurs

```sql
BEGIN TRANSACTION;
BEGIN TRY
    MERGE INTO Produits AS Cible
    USING ProduitsSource AS Source
    ON Cible.ProduitID = Source.ProduitID
    WHEN MATCHED THEN
        UPDATE SET Cible.Prix = Source.Prix
    WHEN NOT MATCHED THEN
        INSERT (ProduitID, NomProduit, Prix)
        VALUES (Source.ProduitID, Source.NomProduit, Source.Prix);

    COMMIT TRANSACTION;
    PRINT 'MERGE réussi';
END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION;
    PRINT 'Erreur : ' + ERROR_MESSAGE();
END CATCH;
```

## Limitations et pièges

### 1. Point-virgule obligatoire

```sql
-- ❌ ERREUR : Manque le point-virgule
MERGE INTO Produits AS Cible
USING Source AS S
ON ...
WHEN MATCHED THEN UPDATE ...

-- ✅ CORRECT
MERGE INTO Produits AS Cible
USING Source AS S
ON ...
WHEN MATCHED THEN UPDATE ...;  -- Point-virgule obligatoire !
```

### 2. Pas d'UPDATE de la colonne de jointure

```sql
-- ❌ ERREUR : Ne peut pas modifier ProduitID
MERGE INTO Produits AS Cible
USING Source AS S
ON Cible.ProduitID = S.ProduitID
WHEN MATCHED THEN
    UPDATE SET Cible.ProduitID = S.NouveauID;  -- Erreur !
```

### 3. Maximum de 2 clauses WHEN MATCHED

Vous ne pouvez avoir que 2 clauses WHEN MATCHED maximum, et une seule peut utiliser UPDATE.

```sql
-- ✅ CORRECT : Une UPDATE et une DELETE
WHEN MATCHED AND Source.Actif = 1 THEN
    UPDATE SET ...
WHEN MATCHED AND Source.Actif = 0 THEN
    DELETE

-- ❌ ERREUR : Deux UPDATE
WHEN MATCHED AND Source.Type = 'A' THEN
    UPDATE SET Prix = Source.Prix
WHEN MATCHED AND Source.Type = 'B' THEN
    UPDATE SET Prix = Source.Prix * 1.1  -- Erreur !
```

### 4. Problème de clés multiples

Si plusieurs lignes de la source correspondent à une ligne de la cible, MERGE échoue :

```sql
-- ❌ ERREUR si Source a des doublons sur ProduitID
MERGE INTO Produits AS Cible
USING Source AS S
ON Cible.ProduitID = S.ProduitID
...
```

**Solution :** Éliminer les doublons dans la source :

```sql
MERGE INTO Produits AS Cible
USING (
    SELECT DISTINCT ProduitID, NomProduit, Prix
    FROM Source
) AS S
ON Cible.ProduitID = S.ProduitID
...
```

Ou utiliser ROW_NUMBER pour garder une seule ligne par clé :

```sql
MERGE INTO Produits AS Cible
USING (
    SELECT ProduitID, NomProduit, Prix
    FROM (
        SELECT *,
            ROW_NUMBER() OVER(PARTITION BY ProduitID ORDER BY DateImport DESC) AS Rn
        FROM Source
    ) AS Sub
    WHERE Rn = 1
) AS S
ON Cible.ProduitID = S.ProduitID
...
```

### 5. Triggers et MERGE

Les triggers sur la table cible sont déclenchés par MERGE. Soyez conscient des impacts :

```sql
-- Si un trigger AFTER UPDATE existe sur Produits
-- Il sera déclenché pour chaque UPDATE du MERGE
```

### 6. Problème de sécurité (CVE-2010-2751)

Dans les anciennes versions de SQL Server, MERGE avait une vulnérabilité où les actions pouvaient être exécutées dans le mauvais ordre. Ce bug a été corrigé, mais soyez prudent avec les anciennes versions.

## Alternatives à MERGE

### Quand ne PAS utiliser MERGE

**1. Simple INSERT ou UPDATE**

Si vous n'avez besoin que d'une opération :

```sql
-- Plus simple qu'un MERGE pour un simple UPDATE
UPDATE Produits
SET Prix = 100
WHERE ProduitID = 5;
```

**2. Performance critique avec volumes énormes**

Parfois, des opérations séparées avec de bons index sont plus rapides.

**3. Logique très complexe**

Si la logique devient trop complexe, des instructions séparées peuvent être plus lisibles.

### Alternative : INSERT ... ON CONFLICT (non disponible en T-SQL)

**Note :** T-SQL n'a pas de syntaxe ON CONFLICT comme PostgreSQL. MERGE est la solution native.

### Alternative : IF EXISTS avec UPDATE/INSERT

```sql
IF EXISTS (SELECT 1 FROM Produits WHERE ProduitID = @ID)
    UPDATE Produits SET Prix = @Prix WHERE ProduitID = @ID;
ELSE
    INSERT INTO Produits (ProduitID, Prix) VALUES (@ID, @Prix);
```

Moins efficace que MERGE pour plusieurs lignes, mais acceptable pour une seule ligne.

## Bonnes pratiques

### ✅ À faire

1. **Toujours terminer par un point-virgule**
   ```sql
   MERGE ... ;
   ```

2. **Utiliser des alias clairs**
   ```sql
   MERGE INTO Produits AS Cible
   USING ProduitsSource AS Source
   ```

3. **Éliminer les doublons dans la source**
   ```sql
   USING (SELECT DISTINCT ... FROM Source) AS S
   ```

4. **Utiliser OUTPUT pour la traçabilité**
   ```sql
   OUTPUT $action, inserted.*, deleted.*
   ```

5. **Encapsuler dans des transactions pour les opérations critiques**
   ```sql
   BEGIN TRANSACTION;
   MERGE ...;
   COMMIT;
   ```

6. **Créer des index sur les colonnes de jointure**
   ```sql
   CREATE INDEX IX_JoinColumn ON Table(JoinColumn);
   ```

7. **Tester avec des petits volumes d'abord**

8. **Ajouter des conditions pour éviter les mises à jour inutiles**
   ```sql
   WHEN MATCHED AND Source.Prix <> Cible.Prix THEN
       UPDATE SET Cible.Prix = Source.Prix
   ```

### ❌ À éviter

1. **Oublier le point-virgule final**
2. **Modifier la colonne de jointure dans UPDATE**
3. **Ne pas gérer les doublons dans la source**
4. **Utiliser MERGE pour une simple insertion**
5. **Ignorer les performances sur gros volumes**
6. **Ne pas utiliser de transactions pour les opérations critiques**
7. **Utiliser MERGE sans comprendre les trois clauses WHEN**

## Résumé

L'instruction **MERGE** est un outil puissant pour synchroniser des données entre deux sources.

**Points clés :**

**Syntaxe de base :**
```sql
MERGE INTO cible
USING source
ON condition_jointure
WHEN MATCHED THEN UPDATE
WHEN NOT MATCHED BY TARGET THEN INSERT
WHEN NOT MATCHED BY SOURCE THEN DELETE;
```

**Les trois clauses WHEN :**
- **MATCHED** : Ligne existe dans les deux tables → UPDATE ou DELETE
- **NOT MATCHED BY TARGET** : Ligne seulement dans source → INSERT
- **NOT MATCHED BY SOURCE** : Ligne seulement dans cible → DELETE ou UPDATE

**Avantages :**
- Une instruction atomique pour INSERT, UPDATE, DELETE
- Plus lisible et maintenable
- Souvent plus performant
- Idéal pour ETL et synchronisation

**Points d'attention :**
- Point-virgule obligatoire
- Pas de modification de la colonne de jointure
- Gérer les doublons dans la source
- Index sur les colonnes de jointure
- Utiliser OUTPUT pour la traçabilité

**Cas d'usage :**
- Data Warehouse (chargement de dimensions)
- Synchronisation de bases de données
- Mise à jour de caches
- Import de fichiers externes
- Gestion de données maître

MERGE est particulièrement utile dans les architectures ETL (Extract, Transform, Load) et pour maintenir la cohérence des données entre différents systèmes !
