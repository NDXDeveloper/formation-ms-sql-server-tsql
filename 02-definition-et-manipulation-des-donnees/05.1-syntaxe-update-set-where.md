# 2.5.1 Syntaxe UPDATE ... SET ... WHERE

## Introduction

L'instruction **UPDATE** est l'une des commandes les plus utilisées en SQL Server. Elle permet de **modifier des données existantes** dans une table. Que ce soit pour corriger une erreur, mettre à jour un statut, ou ajuster des prix, UPDATE est l'outil qu'il vous faut.

Dans cette section, nous allons apprendre à utiliser UPDATE de manière sûre et efficace. Vous découvrirez comment modifier une ligne, plusieurs lignes, ou même toutes les lignes d'une table, tout en évitant les erreurs courantes qui peuvent avoir des conséquences désastreuses.

---

## Qu'est-ce que UPDATE ?

**UPDATE** est une commande DML (Data Manipulation Language) qui permet de **modifier les valeurs existantes** dans une ou plusieurs colonnes d'une table.

### Analogie du monde réel

Imaginez un carnet d'adresses :
- **INSERT** : Ajouter un nouveau contact
- **UPDATE** : Modifier le numéro de téléphone d'un contact existant
- **DELETE** : Supprimer un contact

UPDATE, c'est comme prendre une gomme et un crayon pour corriger ou mettre à jour une information déjà écrite.

### Ce que UPDATE peut faire

- ✅ Modifier une seule colonne d'une ligne
- ✅ Modifier plusieurs colonnes d'une ligne
- ✅ Modifier plusieurs lignes en même temps
- ✅ Modifier toutes les lignes d'une table
- ✅ Modifier des valeurs en fonction de calculs
- ✅ Utiliser des valeurs d'autres colonnes

---

## La syntaxe de base

Voici la structure fondamentale de l'instruction UPDATE :

```sql
UPDATE nom_table
SET colonne1 = nouvelle_valeur1,
    colonne2 = nouvelle_valeur2,
    ...
WHERE condition;
```

### Décomposition de la syntaxe

| Élément | Rôle | Obligatoire ? |
|---------|------|---------------|
| **UPDATE** | Mot-clé qui démarre la commande | ✅ Oui |
| **nom_table** | La table à modifier | ✅ Oui |
| **SET** | Introduit les colonnes à modifier | ✅ Oui |
| **colonne = valeur** | Assignation de la nouvelle valeur | ✅ Oui |
| **WHERE** | Condition pour filtrer les lignes | ⚠️ Fortement recommandé |

**⚠️ ATTENTION CRITIQUE :** Sans clause WHERE, **TOUTES** les lignes de la table seront modifiées !

## Exemples de base

### Exemple 1 : Modifier une seule colonne d'une ligne

Imaginons une table de clients :

```sql
-- État initial de la table
SELECT * FROM Clients;

/*
ClientID | Nom           | Email                | Telephone
---------|---------------|----------------------|-------------
1        | Marie Dupont  | marie.d@email.fr     | 0612345678
2        | Pierre Martin | pierre.m@email.com   | 0623456789
3        | Julie Leroux  | julie.l@email.fr     | NULL
*/

-- Mettre à jour l'email de Marie Dupont
UPDATE Clients
SET Email = 'marie.dupont@nouvellemail.fr'
WHERE ClientID = 1;

-- Résultat après UPDATE
SELECT * FROM Clients WHERE ClientID = 1;

/*
ClientID | Nom           | Email                         | Telephone
---------|---------------|-------------------------------|-------------
1        | Marie Dupont  | marie.dupont@nouvellemail.fr  | 0612345678
*/
```

**Explication :**
- `UPDATE Clients` : on modifie la table Clients
- `SET Email = ...` : on change la valeur de la colonne Email
- `WHERE ClientID = 1` : uniquement pour le client avec l'ID 1

### Exemple 2 : Modifier plusieurs colonnes d'une ligne

```sql
-- Mettre à jour plusieurs informations pour Pierre Martin
UPDATE Clients
SET Email = 'pierre.martin@email.fr',
    Telephone = '0634567890'
WHERE ClientID = 2;

-- Résultat
SELECT * FROM Clients WHERE ClientID = 2;

/*
ClientID | Nom           | Email                  | Telephone
---------|---------------|------------------------|-------------
2        | Pierre Martin | pierre.martin@email.fr | 0634567890
*/
```

**Explication :**
- On peut modifier plusieurs colonnes en les séparant par des virgules
- Toutes les modifications sont appliquées en une seule opération

### Exemple 3 : Modifier plusieurs lignes en même temps

```sql
-- Créer une table de produits pour l'exemple
CREATE TABLE Produits (
    ProduitID INT,
    Nom NVARCHAR(100),
    Prix DECIMAL(10, 2),
    EnPromotion BIT
);

INSERT INTO Produits VALUES
    (1, N'Ordinateur portable', 899.99, 0),
    (2, N'Souris sans fil', 29.99, 0),
    (3, N'Clavier mécanique', 149.99, 0),
    (4, N'Écran 24 pouces', 199.99, 0);

-- Mettre tous les produits en promotion
UPDATE Produits
SET EnPromotion = 1
WHERE Prix > 100;

-- Résultat : 3 lignes modifiées
SELECT * FROM Produits;

/*
ProduitID | Nom                  | Prix   | EnPromotion
----------|----------------------|--------|-------------
1         | Ordinateur portable  | 899.99 | 1
2         | Souris sans fil      | 29.99  | 0
3         | Clavier mécanique    | 149.99 | 1
4         | Écran 24 pouces      | 199.99 | 1
*/
```

**Explication :**
- La condition `WHERE Prix > 100` sélectionne 3 produits
- Ces 3 produits sont mis à jour en une seule instruction
- Le produit "Souris sans fil" n'est pas affecté car son prix est ≤ 100

## La clause WHERE : Votre filet de sécurité

La clause WHERE est **ESSENTIELLE** pour contrôler quelles lignes sont modifiées.

### Sans WHERE : DANGER ! ☠️

```sql
-- ❌ ERREUR CATASTROPHIQUE
UPDATE Clients
SET Email = 'erreur@email.com';

-- Résultat : TOUS les clients ont maintenant le même email !
/*
ClientID | Nom           | Email              | Telephone
---------|---------------|--------------------|-------------
1        | Marie Dupont  | erreur@email.com   | 0612345678
2        | Pierre Martin | erreur@email.com   | 0623456789
3        | Julie Leroux  | erreur@email.com   | NULL
*/
```

**Conséquence :** Toutes les lignes de la table ont été modifiées ! C'est rarement ce que vous voulez.

### Avec WHERE : Contrôle précis ✅

```sql
-- ✅ CORRECT : modification ciblée
UPDATE Clients
SET Email = 'nouveau@email.com'
WHERE ClientID = 1;

-- Une seule ligne est modifiée
```

### Bonne pratique : Toujours tester avec SELECT d'abord

**Avant de faire un UPDATE, utilisez un SELECT avec la même clause WHERE :**

```sql
-- 1. D'abord : vérifier quelles lignes seront affectées
SELECT * FROM Clients
WHERE ClientID = 1;

-- 2. Si le SELECT affiche les bonnes lignes, faire l'UPDATE
UPDATE Clients
SET Email = 'nouveau@email.com'
WHERE ClientID = 1;
```

**Cette technique simple évite 99% des erreurs !**

## Opérateurs dans la clause WHERE

Vous pouvez utiliser de nombreux opérateurs pour filtrer les lignes à modifier.

### Opérateurs de comparaison

```sql
-- Égalité
UPDATE Produits SET EnPromotion = 1
WHERE ProduitID = 5;

-- Différent de
UPDATE Produits SET EnPromotion = 0
WHERE ProduitID != 5;
-- ou
UPDATE Produits SET EnPromotion = 0
WHERE ProduitID <> 5;

-- Plus grand que
UPDATE Produits SET EnPromotion = 1
WHERE Prix > 100;

-- Plus grand ou égal
UPDATE Produits SET EnPromotion = 1
WHERE Prix >= 100;

-- Plus petit que
UPDATE Produits SET Disponible = 0
WHERE Stock < 5;

-- Plus petit ou égal
UPDATE Produits SET Disponible = 0
WHERE Stock <= 0;
```

### Opérateurs logiques (AND, OR, NOT)

```sql
-- AND : toutes les conditions doivent être vraies
UPDATE Produits
SET EnPromotion = 1
WHERE Prix > 100 AND Stock > 0;

-- OR : au moins une condition doit être vraie
UPDATE Produits
SET AReapprovisionner = 1
WHERE Stock < 5 OR Stock IS NULL;

-- NOT : inverse la condition
UPDATE Produits
SET Actif = 0
WHERE NOT (Stock > 0);
```

### Opérateur IN (liste de valeurs)

```sql
-- Modifier plusieurs IDs spécifiques
UPDATE Produits
SET EnPromotion = 1
WHERE ProduitID IN (1, 3, 5, 7);

-- Équivalent à :
-- WHERE ProduitID = 1 OR ProduitID = 3 OR ProduitID = 5 OR ProduitID = 7
```

### Opérateur BETWEEN (plage de valeurs)

```sql
-- Modifier tous les produits dans une plage de prix
UPDATE Produits
SET Categorie = N'Milieu de gamme'
WHERE Prix BETWEEN 100 AND 500;

-- Équivalent à :
-- WHERE Prix >= 100 AND Prix <= 500
```

### Opérateur LIKE (correspondance de motif)

```sql
-- Modifier tous les produits dont le nom commence par "Clavier"
UPDATE Produits
SET Type = N'Périphérique'
WHERE Nom LIKE N'Clavier%';

-- % = n'importe quelle séquence de caractères
-- _ = un seul caractère

-- Autres exemples :
WHERE Nom LIKE N'%portable%'  -- Contient "portable"
WHERE Email LIKE N'%@gmail.com'  -- Se termine par "@gmail.com"
WHERE Code LIKE N'A_B'  -- A, un caractère, puis B (ex: A1B, A2B)
```

### Vérification de NULL

```sql
-- Mettre à jour les lignes où Telephone est NULL
UPDATE Clients
SET Telephone = 'Non renseigné'
WHERE Telephone IS NULL;

-- Mettre à jour les lignes où Telephone n'est PAS NULL
UPDATE Clients
SET TelephoneVerifie = 1
WHERE Telephone IS NOT NULL;

-- ⚠️ IMPORTANT : N'utilisez JAMAIS = NULL ou != NULL
-- ❌ Incorrect (ne fonctionne pas)
WHERE Telephone = NULL

-- ✅ Correct
WHERE Telephone IS NULL
```

## Mise à jour avec calculs

UPDATE permet d'effectuer des calculs lors de la modification.

### Calculs arithmétiques

```sql
-- Augmenter tous les prix de 10%
UPDATE Produits
SET Prix = Prix * 1.10
WHERE EnPromotion = 0;

-- Décrémenter le stock après une vente
UPDATE Produits
SET Stock = Stock - 1
WHERE ProduitID = 5;

-- Doubler les points de fidélité
UPDATE Clients
SET PointsFidelite = PointsFidelite * 2
WHERE DateInscription < '2024-01-01';

-- Ajouter une valeur fixe
UPDATE Employes
SET Salaire = Salaire + 1000
WHERE AnneeAnciennete > 5;
```

### Utiliser des valeurs d'autres colonnes

```sql
-- Table d'exemple : Commandes
CREATE TABLE Commandes (
    CommandeID INT,
    MontantHT DECIMAL(10, 2),
    TauxTVA DECIMAL(5, 4),
    MontantTTC DECIMAL(10, 2)
);

-- Calculer le montant TTC à partir du HT et du taux
UPDATE Commandes
SET MontantTTC = MontantHT * (1 + TauxTVA);

-- Exemple avec plusieurs colonnes
UPDATE Produits
SET PrixRemise = Prix * (1 - TauxRemise),
    DateModification = GETDATE();
```

### Fonctions dans UPDATE

```sql
-- Mettre en majuscules
UPDATE Clients
SET Nom = UPPER(Nom);

-- Nettoyer les espaces
UPDATE Clients
SET Email = TRIM(Email);

-- Date du jour
UPDATE Commandes
SET DateModification = GETDATE()
WHERE StatutCommande = N'Expédiée';

-- Concaténation
UPDATE Employes
SET NomComplet = Prenom + ' ' + Nom;

-- Extraction de sous-chaîne
UPDATE Produits
SET CodeCourt = LEFT(CodeProduit, 3);
```

### Exemple 2 : Gestion d'utilisateurs

```sql
CREATE TABLE Utilisateurs (
    UtilisateurID INT PRIMARY KEY,
    Email VARCHAR(255),
    Nom NVARCHAR(100),
    EstActif BIT,
    DerniereConnexion DATETIME2(3),
    NombreConnexions INT,

);

-- Enregistrer une connexion
UPDATE Utilisateurs

UPDATE Utilisateurs

  AND EstActif = 1;

UPDATE Utilisateurs

```

### Exemple 3 : Gestion de prix et promotions

```sql
CREATE TABLE Articles (
    ArticleID INT PRIMARY KEY,
    Nom NVARCHAR(200),
    PrixNormal DECIMAL(10, 2),

    EnPromotion BIT,

-- Lancer une promotion de 20% sur certains articles
UPDATE Articles
```

### Exemple 4 : Mise à jour conditionnelle avec CASE

```sql
CREATE TABLE Commandes (
    CommandeID INT,
    MontantTotal DECIMAL(10, 2),
    FraisLivraison DECIMAL(10, 2),
    CodePromo NVARCHAR(20)
);

-- Calculer les frais de livraison selon le montant
UPDATE Commandes
SET FraisLivraison = CASE
    WHEN MontantTotal >= 100 THEN 0.00       -- Livraison gratuite
    WHEN MontantTotal >= 50 THEN 5.00        -- Frais réduits
    ELSE 10.00                                -- Frais standard
END;

-- Appliquer une réduction selon le code promo
UPDATE Commandes
SET MontantTotal = CASE
    WHEN CodePromo = 'PROMO20' THEN MontantTotal * 0.80
    WHEN CodePromo = 'PROMO10' THEN MontantTotal * 0.90
    WHEN CodePromo = 'PROMO5' THEN MontantTotal * 0.95
    ELSE MontantTotal
END;
```

## Mise à jour à partir d'une autre table (JOIN dans UPDATE)

Vous pouvez utiliser des informations d'une autre table pour mettre à jour vos données.

### Syntaxe avec JOIN

```sql
UPDATE table_a_modifier
SET colonne = nouvelle_valeur
FROM table_a_modifier
INNER JOIN autre_table ON condition_jointure
WHERE condition;
```

### Exemple pratique

```sql
-- Tables pour l'exemple
CREATE TABLE Employes (
    EmployeID INT,
    Nom NVARCHAR(100),
    DepartementID INT,
    NomDepartement NVARCHAR(100)
);

CREATE TABLE Departements (
    DepartementID INT,
    NomDepartement NVARCHAR(100)
);

INSERT INTO Departements VALUES
    (1, N'Ressources Humaines'),
    (2, N'Informatique'),
    (3, N'Ventes');

INSERT INTO Employes VALUES
    (1, N'Marie Dupont', 1, NULL),
    (2, N'Pierre Martin', 2, NULL),
    (3, N'Julie Leroux', 3, NULL);

-- Mettre à jour le nom du département dans la table Employes
UPDATE Employes
SET NomDepartement = D.NomDepartement
FROM Employes E
INNER JOIN Departements D ON E.DepartementID = D.DepartementID;

-- Résultat
SELECT * FROM Employes;

/*
EmployeID | Nom           | DepartementID | NomDepartement
----------|---------------|---------------|---------------------
1         | Marie Dupont  | 1             | Ressources Humaines
2         | Pierre Martin | 2             | Informatique
3         | Julie Leroux  | 3             | Ventes
*/
```

### Autre exemple : Mise à jour des totaux

```sql
CREATE TABLE Commandes (
    CommandeID INT,
    ClientID INT,
    NombreArticles INT,
    MontantTotal DECIMAL(10, 2)
);

CREATE TABLE LignesCommande (
    LigneID INT,
    CommandeID INT,
    PrixUnitaire DECIMAL(10, 2),
    Quantite INT
);

-- Calculer le total de chaque commande
UPDATE Commandes
SET MontantTotal = CalculTotal.Total,
    NombreArticles = CalculTotal.NbArticles
FROM Commandes C
INNER JOIN (
    SELECT
        CommandeID,
        SUM(PrixUnitaire * Quantite) AS Total,
        COUNT(*) AS NbArticles
    FROM LignesCommande
    GROUP BY CommandeID
) CalculTotal ON C.CommandeID = CalculTotal.CommandeID;
```

## Vérifier le résultat : @@ROWCOUNT

SQL Server fournit une variable système qui indique le nombre de lignes affectées par la dernière opération.

### Utilisation de @@ROWCOUNT

```sql
-- Faire une mise à jour
UPDATE Produits
SET EnPromotion = 1
WHERE Prix > 500;

-- Vérifier combien de lignes ont été modifiées
SELECT @@ROWCOUNT AS NombreLignesModifiees;

-- Résultat : par exemple "3 ligne(s) affectée(s)"
```

### Utiliser @@ROWCOUNT dans la logique

```sql
-- Mise à jour conditionnelle
UPDATE Clients
SET EstPremium = 1
WHERE MontantAchatsTotal > 10000;

-- Vérifier si des lignes ont été modifiées
IF @@ROWCOUNT > 0
BEGIN
    PRINT 'Des clients ont été promus Premium';
END
ELSE
BEGIN
    PRINT 'Aucun client ne remplit les critères';
END
```

## Pièges courants et erreurs à éviter

### Piège 1 : Oublier la clause WHERE

```sql
-- ❌ CATASTROPHE : Tous les clients auront le même email !
UPDATE Clients
SET Email = 'nouveau@email.com';

-- ✅ CORRECT : Spécifier quelle ligne modifier
UPDATE Clients
SET Email = 'nouveau@email.com'
WHERE ClientID = 1;
```

**Solution :** Toujours utiliser WHERE, sauf si vous voulez vraiment modifier toutes les lignes.

### Piège 2 : Mauvaise condition WHERE

```sql
-- ❌ Utiliser = au lieu de LIKE
UPDATE Produits
SET EnPromotion = 1
WHERE Nom = 'Clavier';  -- Ne trouve que "Clavier" exactement

-- ✅ Utiliser LIKE pour une recherche partielle
UPDATE Produits
SET EnPromotion = 1
WHERE Nom LIKE N'%Clavier%';  -- Trouve tous les claviers
```

### Piège 3 : Mauvais type de données dans SET

```sql
-- ❌ Assigner un texte à une colonne numérique
UPDATE Produits
SET Prix = 'cher';  -- Erreur de conversion !

-- ✅ Utiliser le bon type
UPDATE Produits
SET Prix = 199.99;
```

### Piège 4 : Oublier les guillemets pour NVARCHAR

```sql
-- ❌ Oublier le N pour Unicode
UPDATE Clients
SET Nom = 'François';  -- L'accent peut être perdu

-- ✅ Utiliser N pour les chaînes Unicode
UPDATE Clients
SET Nom = N'François';
```

### Piège 5 : Modification circulaire

```sql
-- ⚠️ ATTENTION : Ordre d'évaluation
UPDATE Produits
SET Prix = Prix + 10,
    PrixAvecTaxe = Prix * 1.20;  -- Utilise l'ancien prix ou le nouveau ?

-- ✅ SQL Server utilise les ANCIENNES valeurs pour les calculs
-- Dans cet exemple, PrixAvecTaxe sera calculé avec l'ANCIEN prix
-- Pour utiliser le nouveau prix, faites deux UPDATE séparés
```

### Piège 6 : Mise à jour et contraintes

```sql
-- Si une contrainte FOREIGN KEY existe
CREATE TABLE Commandes (
    CommandeID INT,
    ClientID INT,
    FOREIGN KEY (ClientID) REFERENCES Clients(ClientID)
);

-- ❌ Ceci échouera si le client 999 n'existe pas
UPDATE Commandes
SET ClientID = 999
WHERE CommandeID = 1;
-- Erreur : violation de contrainte de clé étrangère
```

### Piège 7 : NULL dans les calculs

```sql
-- Table avec des valeurs NULL
CREATE TABLE Test (
    ID INT,
    Valeur INT
);

INSERT INTO Test VALUES (1, 10), (2, NULL), (3, 20);

-- ❌ Le résultat sera NULL si Valeur est NULL
UPDATE Test
SET Valeur = Valeur + 5;

-- Ligne 2 : NULL + 5 = NULL (reste NULL)

-- ✅ Gérer NULL avec ISNULL ou COALESCE
UPDATE Test
SET Valeur = ISNULL(Valeur, 0) + 5;
-- Ligne 2 : 0 + 5 = 5
```

## Bonnes pratiques

### 1. Toujours tester avec SELECT d'abord

```sql
-- ✅ BONNE PRATIQUE
-- Étape 1 : Vérifier avec SELECT
SELECT * FROM Clients WHERE ClientID = 1;

-- Étape 2 : Si OK, remplacer SELECT par UPDATE
UPDATE Clients
SET Email = 'nouveau@email.com'
WHERE ClientID = 1;
```

### 2. Utiliser des transactions pour les mises à jour importantes

```sql
-- Commencer une transaction
BEGIN TRANSACTION;

    -- Faire la mise à jour
    UPDATE Produits
    SET Prix = Prix * 1.10
    WHERE Categorie = N'Électronique';

    -- Vérifier le résultat
    SELECT * FROM Produits WHERE Categorie = N'Électronique';

    -- Si tout est OK : valider
    COMMIT;

    -- Si erreur : annuler
    -- ROLLBACK;
```

### 3. Sauvegarder les données avant une mise à jour importante

```sql
-- Créer une copie de sauvegarde
SELECT * INTO Clients_Backup FROM Clients;

-- Faire la mise à jour risquée
UPDATE Clients
SET Email = LOWER(Email);

-- Si problème, restaurer depuis la sauvegarde
-- DELETE FROM Clients;
-- INSERT INTO Clients SELECT * FROM Clients_Backup;
```

### 4. Utiliser des alias pour plus de clarté

```sql
-- ✅ Avec alias (plus lisible)
UPDATE P
SET P.Prix = P.Prix * 1.10
FROM Produits P
WHERE P.Categorie = N'Électronique';
```

### 5. Documenter les mises à jour importantes

```sql
-- Ajouter des commentaires pour expliquer
-- Mise à jour : Promotion Black Friday 2024
-- Date : 15/11/2024
-- Réduction de 20% sur tous les produits électroniques
UPDATE Produits
SET PrixPromo = Prix * 0.80,
    EnPromotion = 1,
    DateDebutPromo = '2024-11-25',
    DateFinPromo = '2024-11-30'
WHERE Categorie = N'Électronique';
```

### 6. Limiter le nombre de lignes (pour les grosses tables)

```sql
-- Pour une très grosse table, mettre à jour par lots
WHILE 1 = 1
BEGIN
    UPDATE TOP (1000) Produits
    SET DateModification = GETDATE()
    WHERE DateModification IS NULL;

    IF @@ROWCOUNT = 0 BREAK;  -- Plus rien à mettre à jour
END
```

## UPDATE et performances

### Impact des index

```sql
-- UPDATE sur une colonne indexée peut être plus rapide
CREATE INDEX IX_Clients_Email ON Clients(Email);

UPDATE Clients
SET NombreConnexions = NombreConnexions + 1
WHERE Email = 'marie@email.com';  -- Utilise l'index
```

### UPDATE et verrouillage

```sql
-- UPDATE verrouille les lignes modifiées
-- D'autres utilisateurs ne peuvent pas modifier ces lignes simultanément
UPDATE Produits
SET Stock = Stock - 1
WHERE ProduitID = 1;
-- Les autres sessions doivent attendre que cette transaction soit terminée
```

### Éviter les mises à jour inutiles

```sql
-- ❌ Mise à jour même si la valeur ne change pas
UPDATE Clients
SET Email = 'marie@email.com'
WHERE ClientID = 1;  -- Même si l'email est déjà celui-là

-- ✅ Vérifier que la valeur change vraiment
UPDATE Clients
SET Email = 'marie@email.com'
WHERE ClientID = 1
  AND Email != 'marie@email.com';
```

## Points clés à retenir

✅ **UPDATE** modifie des données existantes (ne crée pas de nouvelles lignes)

✅ **WHERE est crucial** : sans WHERE, toutes les lignes sont modifiées !

✅ **Tester avec SELECT** avant de faire UPDATE avec la même clause WHERE

✅ **@@ROWCOUNT** indique le nombre de lignes modifiées

✅ **SET** peut utiliser des calculs, des fonctions, d'autres colonnes

✅ **CASE** permet des mises à jour conditionnelles complexes

✅ **JOIN** permet d'utiliser des données d'autres tables

✅ **Transactions** permettent d'annuler en cas d'erreur

❌ **Ne jamais oublier WHERE** (sauf si intentionnel)

❌ **Attention aux NULL** dans les calculs (utilisez ISNULL/COALESCE)

❌ **Vérifier les contraintes** (FOREIGN KEY, CHECK, etc.)

### Syntaxe minimale

```sql
UPDATE table

```

### Syntaxe complète

```sql
UPDATE alias_table
SET
    colonne1 = valeur1,
    colonne2 = valeur2,
    colonne3 = CASE
        WHEN condition THEN valeur_a
        ELSE valeur_b
    END
FROM table AS alias_table
INNER JOIN autre_table ON condition_jointure
WHERE condition_filtrage;
```

## Conclusion

L'instruction **UPDATE** est un outil puissant mais qui doit être utilisé avec précaution. La clause **WHERE** est votre meilleur allié pour éviter les catastrophes.

**Règles d'or :**
1. Toujours tester avec SELECT avant UPDATE
2. Utiliser WHERE (sauf cas très spécifiques)
3. Vérifier avec @@ROWCOUNT
4. Utiliser des transactions pour les opérations critiques
5. Faire des sauvegardes avant les mises à jour massives

Avec ces connaissances et ces bonnes pratiques, vous êtes maintenant capable d'utiliser UPDATE de manière sûre et efficace pour modifier vos données dans SQL Server !
