# 8.9.2 Méthodes spatiales et index spatiaux

## Introduction

Une fois les données spatiales stockées (§8.9.1), on veut **les interroger** : mesurer des distances, tester si un point est dans une zone, trouver les objets proches… SQL Server fournit pour cela des dizaines de **méthodes** (préfixées `ST` selon la norme OGC). Et pour que ces requêtes restent rapides sur de gros volumes, il propose les **index spatiaux**. Voyons les deux.

---

## Les méthodes de mesure

| Méthode | Rôle | Retour (GEOGRAPHY) |
|---------|------|--------------------|
| `STDistance(autre)` | Distance entre deux objets | mètres |
| `STLength()` | Longueur d'une ligne | mètres |
| `STArea()` | Aire d'un polygone | mètres carrés |

```sql
DECLARE @paris GEOGRAPHY = geography::Point(48.8566, 2.3522, 4326);
DECLARE @lyon  GEOGRAPHY = geography::Point(45.7640, 4.8357, 4326);

SELECT @paris.STDistance(@lyon) AS Metres;          -- ≈ 392 000
SELECT @paris.STDistance(@lyon) / 1000.0 AS Km;     -- ≈ 392
```

---

## Les méthodes de relation (prédicats)

Elles renvoient 1 (vrai) ou 0 (faux) et répondent à « ces deux formes ont-elles telle relation ? »

| Méthode | Question |
|---------|----------|
| `STIntersects(autre)` | Les deux formes se touchent-elles / se croisent-elles ? |
| `STContains(autre)` | La forme contient-elle l'autre ? |
| `STWithin(autre)` | La forme est-elle contenue dans l'autre ? |
| `STOverlaps(autre)` | Les deux surfaces se chevauchent-elles partiellement ? |
| `STTouches(autre)` | Se touchent-elles seulement par la frontière ? |

```sql
-- Un point est-il dans une zone (polygone) ?
DECLARE @zone GEOGRAPHY = geography::STGeomFromText(
    'POLYGON((2.2 48.8, 2.5 48.8, 2.5 49.0, 2.2 49.0, 2.2 48.8))', 4326);
DECLARE @client GEOGRAPHY = geography::Point(48.86, 2.35, 4326);

SELECT @zone.STIntersects(@client) AS DansLaZone;   -- 1 = oui
```

---

## Les méthodes de construction

Elles **créent** de nouvelles formes à partir d'existantes :

| Méthode | Rôle |
|---------|------|
| `STBuffer(distance)` | Crée une zone tampon (cercle/contour) autour de la forme |
| `STUnion(autre)` | Fusionne deux formes |
| `STIntersection(autre)` | Zone commune à deux formes |
| `STCentroid()` | Centre géométrique d'un polygone |
| `STEnvelope()` | Rectangle englobant |

```sql
-- Zone tampon de 5 km autour d'un magasin
DECLARE @magasin GEOGRAPHY = geography::Point(48.8566, 2.3522, 4326);
DECLARE @zone5km GEOGRAPHY = @magasin.STBuffer(5000);  -- 5000 mètres
```

---

## Cas pratique : les magasins à moins de 5 km

C'est LE cas d'usage emblématique. On cherche les magasins proches d'une position donnée, triés par distance :

```sql
DECLARE @position GEOGRAPHY = geography::Point(48.8566, 2.3522, 4326);

SELECT
    Nom,
    Position.STDistance(@position) / 1000.0 AS DistanceKm
FROM Magasins
WHERE Position.STDistance(@position) <= 5000   -- 5 km en mètres
ORDER BY Position.STDistance(@position);
```

➡️ Lisible, puissant — mais sur des millions de lignes, ce calcul appliqué à chaque ligne serait lent **sans index spatial**.

---

## Les index spatiaux

### Le problème

Sans index, une requête de proximité doit calculer la distance pour **chaque** ligne de la table : c'est un balayage complet, inacceptable sur de gros volumes.

### La solution : la tessellation en grille

Un **index spatial** découpe l'espace en une **grille hiérarchique** (plusieurs niveaux de grilles emboîtées) : c'est la **tessellation**. Chaque objet est associé aux cellules qu'il occupe. Pour une recherche de proximité, SQL Server n'examine alors que les objets des **cellules pertinentes**, au lieu de toute la table.

```
   Niveau 1 (grille grossière)      Niveau 2 (plus fine)
   ┌───┬───┬───┬───┐                chaque cellule est
   │   │   │ ● │   │                re-découpée en sous-grille
   ├───┼───┼───┼───┤                pour localiser finement
   │   │ ●●│   │   │                les objets
   └───┴───┴───┴───┘
```

### Créer un index spatial

```sql
-- Sur une colonne GEOGRAPHY
CREATE SPATIAL INDEX SIX_Magasins_Position
ON Magasins(Position)
USING GEOGRAPHY_GRID
WITH (GRIDS = (MEDIUM, MEDIUM, MEDIUM, MEDIUM));
```

Pour une colonne `GEOMETRY`, l'index exige en plus une **zone de délimitation** (`BOUNDING_BOX`), car le plan n'est pas borné comme la Terre :

```sql
CREATE SPATIAL INDEX SIX_Plan_Forme
ON Plan(Forme)
USING GEOMETRY_GRID
WITH (BOUNDING_BOX = (0, 0, 1000, 1000));
```

> ⚠️ **Prérequis** : comme pour les autres index, la table doit posséder une **clé primaire cluster**. Une table ne peut pas avoir d'index spatial sans PK.

### Quelles requêtes l'index accélère-t-il ?

L'optimiseur peut utiliser l'index spatial lorsque les méthodes de relation/distance sont utilisées dans une forme reconnue, par exemple :

```sql
-- Forme « sargable » spatiale : l'index peut être utilisé
WHERE Position.STDistance(@p) IS NOT NULL AND Position.STDistance(@p) <= 5000
WHERE Position.STIntersects(@zone) = 1
```

> 💡 Vérifiez dans le **plan d'exécution** (voir §7.3) que l'index spatial est bien utilisé. Les prédicats `STDistance(...) <= n` et `STIntersects(...) = 1` sont parmi les mieux pris en charge.

---

## Performance : bonnes pratiques

- ✅ **Toujours créer un index spatial** sur les colonnes interrogées sur de gros volumes.
- ✅ Comparer `STDistance(...) <= n` plutôt que de filtrer après coup.
- ✅ Ajuster la **densité de grille** (`GRIDS`) et `CELLS_PER_OBJECT` selon la nature des données (gros polygones vs points).
- ⚠️ Le bon réglage d'un index spatial dépend des données : tester avec des volumes réalistes.

---

## Questions fréquentes

**Q : Pourquoi `STDistance` me renvoie `NULL` ?**
R : Très probablement des **SRID différents** entre les deux objets. Vérifiez `.STSrid`.

**Q : Mes distances sont absurdes (des millions de km) ?**
R : Inversion **latitude/longitude** (voir §8.9.1), ou usage de `GEOMETRY` au lieu de `GEOGRAPHY`.

**Q : Puis-je afficher mes formes sur une carte ?**
R : Oui : exportez en WKT (`STAsText()`) ou en GeoJSON, exploitables par la plupart des bibliothèques cartographiques.

---

## Résumé

- Les méthodes de **mesure** (`STDistance`, `STArea`, `STLength`), de **relation** (`STIntersects`, `STContains`, `STWithin`…) et de **construction** (`STBuffer`, `STUnion`…) couvrent l'essentiel des besoins.
- Le cas emblématique « objets à moins de X mètres » s'écrit en quelques lignes avec `STDistance`.
- Les **index spatiaux** (tessellation en grille) sont indispensables sur de gros volumes ; `GEOMETRY` requiert une `BOUNDING_BOX`.
- Vérifier dans le **plan d'exécution** que l'index est utilisé ; attention aux SRID et à l'ordre lat/long.
