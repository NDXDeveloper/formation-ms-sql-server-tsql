# 3.2.3 Opérateurs logiques (AND, OR, NOT)

## Introduction

Dans la section précédente, vous avez appris à filtrer des données avec une seule condition. Mais la réalité est souvent plus complexe ! Vous aurez besoin de combiner plusieurs conditions pour obtenir exactement les données recherchées.

**Exemples de besoins réels** :
- "Je veux les produits de catégorie 'Électronique' **ET** dont le prix est inférieur à 500€"
- "Je veux les clients de Paris **OU** de Lyon"
- "Je veux tous les produits **SAUF** ceux de la catégorie 'Livres'"

C'est là qu'interviennent les **opérateurs logiques** : `AND`, `OR`, et `NOT`.

---

## Les trois opérateurs logiques

| Opérateur | Mot français | Signification | Exemple en français |
|-----------|--------------|---------------|---------------------|
| `AND` | ET | Les deux conditions doivent être vraies | "Majeur ET parisien" |
| `OR` | OU | Au moins une condition doit être vraie | "Paris OU Lyon" |
| `NOT` | NON | Inverse la condition | "PAS annulé" |

---

## 1. L'opérateur AND (ET)

### Description

L'opérateur `AND` combine deux ou plusieurs conditions. **Toutes** les conditions doivent être **vraies** pour qu'une ligne soit incluse dans les résultats.

**Analogie** : C'est comme un videur de boîte de nuit qui demande :
- "Vous devez avoir 18 ans **ET** avoir une invitation"
- Si une seule condition manque, vous n'entrez pas !

### Syntaxe

```sql
WHERE condition1 AND condition2
```

### Fonctionnement

Une ligne n'est retournée que si **TOUTES** les conditions sont vraies :

| Condition 1 | Condition 2 | Résultat |
|-------------|-------------|----------|
| VRAI | VRAI | ✅ VRAI (inclus) |
| VRAI | FAUX | ❌ FAUX (exclu) |
| FAUX | VRAI | ❌ FAUX (exclu) |
| FAUX | FAUX | ❌ FAUX (exclu) |

### Exemple simple

**Objectif** : Trouver les produits électroniques de moins de 500€

```sql
SELECT NomProduit, Categorie, Prix
FROM Produits
WHERE Categorie = 'Électronique' AND Prix < 500
```

**Données de la table** :

| NomProduit | Categorie | Prix |
|------------|-----------|------|
| Ordinateur | Électronique | 800 |
| Souris | Électronique | 25 |
| Roman | Livre | 15 |
| Téléphone | Électronique | 450 |

**Résultat de la requête** :

| NomProduit | Categorie | Prix |
|------------|-----------|------|
| Souris | Électronique | 25 |
| Téléphone | Électronique | 450 |

**Pourquoi ?**
- ❌ Ordinateur : Électronique ✅ mais prix ≥ 500 ❌
- ✅ Souris : Électronique ✅ et prix < 500 ✅
- ❌ Roman : Pas électronique ❌
- ✅ Téléphone : Électronique ✅ et prix < 500 ✅

---

### Exemples avec AND

#### Exemple 1 : Plage de valeurs

Trouver les produits entre 50€ et 100€ :

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix >= 50 AND Prix <= 100
```

**Traduction** : "Le prix doit être supérieur ou égal à 50 **ET** inférieur ou égal à 100"

---

#### Exemple 2 : Filtres multiples

Trouver les employés du département IT avec un salaire supérieur à 3000€ :

```sql
SELECT Prenom, Nom, Departement, Salaire
FROM Employes
WHERE Departement = 'IT' AND Salaire > 3000
```

---

#### Exemple 3 : Avec des dates

Trouver les commandes de janvier 2024 :

```sql
SELECT CommandeID, DateCommande, MontantTotal
FROM Commandes
WHERE DateCommande >= '2024-01-01' AND DateCommande < '2024-02-01'
```

**Explication** : Date >= 1er janvier **ET** date < 1er février

---

#### Exemple 4 : Trois conditions ou plus

Trouver les produits électroniques, en stock, et pas chers :

```sql
SELECT NomProduit, Categorie, Prix, Stock
FROM Produits
WHERE Categorie = 'Électronique'
  AND Stock > 0
  AND Prix < 100
```

**Note** : Vous pouvez chaîner autant de conditions AND que nécessaire.

---

### Visualisation de AND

```
Condition 1: Catégorie = 'Électronique'
    ┌─────────────────┐
    │   Électronique  │
    │                 │
    │     ┌────┐      │
    │     │ ✅ │ ← Les deux cercles se chevauchent
    └─────┴────┴──────┘
          │    │
          └────┘
Condition 2: Prix < 500

Seule la zone d'intersection (✅) est retournée
```

## 2. L'opérateur OR (OU)

### Description

L'opérateur `OR` combine deux ou plusieurs conditions. **Au moins une** des conditions doit être **vraie** pour qu'une ligne soit incluse.

**Analogie** : C'est comme un magasin qui dit :
- "Réduction si vous êtes étudiant **OU** senior"
- Il suffit d'être l'un des deux !

### Syntaxe

```sql
WHERE condition1 OR condition2
```

### Fonctionnement

Une ligne est retournée si **AU MOINS UNE** condition est vraie :

| Condition 1 | Condition 2 | Résultat |
|-------------|-------------|----------|
| VRAI | VRAI | ✅ VRAI (inclus) |
| VRAI | FAUX | ✅ VRAI (inclus) |
| FAUX | VRAI | ✅ VRAI (inclus) |
| FAUX | FAUX | ❌ FAUX (exclu) |

### Exemple simple

**Objectif** : Trouver les clients de Paris ou de Lyon

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville = 'Paris' OR Ville = 'Lyon'
```

**Données de la table** :

| Prenom | Nom | Ville |
|--------|-----|-------|
| Sophie | Martin | Paris |
| Pierre | Dubois | Lyon |
| Marie | Leroy | Marseille |
| Luc | Moreau | Paris |

**Résultat de la requête** :

| Prenom | Nom | Ville |
|--------|-----|-------|
| Sophie | Martin | Paris |
| Pierre | Dubois | Lyon |
| Luc | Moreau | Paris |

**Pourquoi ?**
- ✅ Sophie : Ville = Paris ✅
- ✅ Pierre : Ville = Lyon ✅
- ❌ Marie : Ni Paris ni Lyon ❌
- ✅ Luc : Ville = Paris ✅

---

### Exemples avec OR

#### Exemple 1 : Plusieurs valeurs possibles

Trouver les produits de plusieurs catégories :

```sql
SELECT NomProduit, Categorie
FROM Produits
WHERE Categorie = 'Électronique'
   OR Categorie = 'Informatique'
   OR Categorie = 'Téléphonie'
```

**Note** : La section 3.2.4 présentera l'opérateur `IN` qui simplifie cette syntaxe.

---

#### Exemple 2 : Conditions d'urgence

Trouver les produits en rupture ou en stock critique :

```sql
SELECT NomProduit, Stock
FROM Produits
WHERE Stock = 0 OR Stock < 5
```

---

#### Exemple 3 : Statuts multiples

Trouver les commandes actives (en cours ou en préparation) :

```sql
SELECT CommandeID, Statut
FROM Commandes
WHERE Statut = 'En cours' OR Statut = 'En préparation'
```

---

#### Exemple 4 : Critères alternatifs

Produits soit chers (>1000€) soit en promotion :

```sql
SELECT NomProduit, Prix, EnPromotion
FROM Produits
WHERE Prix > 1000 OR EnPromotion = 1
```

---

### Visualisation de OR

```
Condition 1: Ville = 'Paris'
    ┌─────────────────┐
    │     Paris       │
    │       ✅        │
    └─────────────────┘
           OU
    ┌─────────────────┐
    │     Lyon        │
    │       ✅        │
    └─────────────────┘
Condition 2: Ville = 'Lyon'

Les deux zones complètes (✅) sont retournées
```

## 3. L'opérateur NOT (NON)

### Description

L'opérateur `NOT` **inverse** une condition. Il retourne les lignes qui **ne satisfont pas** la condition.

**Analogie** : C'est comme dire :
- "Tout sauf ça"
- "Tous les clients sauf ceux de Paris"

### Syntaxe

```sql
WHERE NOT condition
```

Ou avec des parenthèses (plus lisible) :

```sql
WHERE NOT (condition)
```

### Fonctionnement

`NOT` inverse le résultat :

| Condition | NOT Condition | Résultat |
|-----------|---------------|----------|
| VRAI | FAUX | ❌ Exclu |
| FAUX | VRAI | ✅ Inclus |

### Exemple simple

**Objectif** : Trouver tous les clients sauf ceux de Paris

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE NOT (Ville = 'Paris')
```

**Équivalent avec != :**
```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville != 'Paris'
```

---

### Exemples avec NOT

#### Exemple 1 : Exclure une catégorie

Tous les produits sauf les livres :

```sql
SELECT NomProduit, Categorie
FROM Produits
WHERE NOT (Categorie = 'Livres')
```

**Équivalent** :
```sql
WHERE Categorie != 'Livres'
```

---

#### Exemple 2 : NOT avec AND

Produits pas en électronique ET pas chers :

```sql
SELECT NomProduit, Categorie, Prix
FROM Produits
WHERE NOT (Categorie = 'Électronique') AND Prix < 50
```

---

#### Exemple 3 : NOT avec OR

Clients ni de Paris ni de Lyon :

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE NOT (Ville = 'Paris' OR Ville = 'Lyon')
```

**Équivalent avec AND** :
```sql
WHERE Ville != 'Paris' AND Ville != 'Lyon'
```

---

#### Exemple 4 : NOT avec conditions complexes

Exclure les commandes annulées ou refusées :

```sql
SELECT CommandeID, Statut
FROM Commandes
WHERE NOT (Statut = 'Annulé' OR Statut = 'Refusé')
```

---

### Quand utiliser NOT ?

| Situation | Avec NOT | Sans NOT (équivalent) |
|-----------|----------|----------------------|
| Une seule exclusion | `NOT (Ville = 'Paris')` | `Ville != 'Paris'` ← Plus simple |
| Exclusions multiples | `NOT (Ville = 'Paris' OR Ville = 'Lyon')` | `Ville != 'Paris' AND Ville != 'Lyon'` |
| Conditions complexes | `NOT (condition complexe)` | Peut être difficile à réécrire |

**Recommandation** : Pour une seule condition, `!=` est plus simple. Pour des conditions complexes, `NOT` peut être plus lisible.

---

## 4. Combinaison d'opérateurs : AND, OR, NOT ensemble

### Le pouvoir de la combinaison

La vraie puissance de ces opérateurs apparaît quand vous les **combinez** pour créer des filtres précis et complexes.

### Exemple 1 : AND et OR ensemble

**Objectif** : Produits électroniques de moins de 500€ OU produits en promotion

```sql
SELECT NomProduit, Categorie, Prix, EnPromotion
FROM Produits
WHERE (Categorie = 'Électronique' AND Prix < 500)
   OR EnPromotion = 1
```

**Explication** :
- Un produit est retourné si :
  - Il est électronique **ET** coûte moins de 500€
  - **OU** il est en promotion (quelle que soit la catégorie/prix)

---

### Exemple 2 : Filtrage par ville et budget

Clients de Paris ou Lyon avec un budget supérieur à 1000€ :

```sql
SELECT Prenom, Nom, Ville, Budget
FROM Clients
WHERE (Ville = 'Paris' OR Ville = 'Lyon')
  AND Budget > 1000
```

**Explication** :
- La ville doit être Paris **OU** Lyon
- **ET** le budget doit être > 1000€

---

### Exemple 3 : Exclusion avec AND

Produits en stock mais pas en promotion :

```sql
SELECT NomProduit, Stock, EnPromotion
FROM Produits
WHERE Stock > 0
  AND NOT (EnPromotion = 1)
```

**Équivalent** :
```sql
WHERE Stock > 0 AND EnPromotion = 0
```

---

## 5. Ordre de priorité des opérateurs

### Le problème de priorité

Sans parenthèses, SQL évalue les opérateurs dans un ordre spécifique, ce qui peut donner des résultats inattendus.

### Ordre de priorité (du plus au moins prioritaire)

1. **Parenthèses** `()`
2. **NOT**
3. **AND**
4. **OR**

### Exemple de confusion

**Requête ambiguë** :
```sql
SELECT *
FROM Produits
WHERE Categorie = 'Électronique' OR Categorie = 'Informatique' AND Prix < 100
```

**Comment SQL l'interprète** (AND avant OR) :
```sql
WHERE Categorie = 'Électronique'
   OR (Categorie = 'Informatique' AND Prix < 100)
```

**Résultat** :
- ✅ **TOUS** les produits électroniques (quel que soit le prix)
- ✅ Les produits informatiques de **moins de 100€**

**Ce que vous vouliez probablement** :
```sql
WHERE (Categorie = 'Électronique' OR Categorie = 'Informatique')
  AND Prix < 100
```

**Résultat corrigé** :
- ✅ Les produits électroniques **OU** informatiques
- ✅ **Mais** uniquement ceux de moins de 100€

---

### Importance des parenthèses

**Règle d'or** : **Utilisez toujours des parenthèses** pour clarifier vos intentions, même si elles ne sont pas techniquement nécessaires !

**❌ Ambigu** :
```sql
WHERE Ville = 'Paris' OR Ville = 'Lyon' AND Budget > 1000
```

**✅ Clair (intention 1)** :
```sql
WHERE (Ville = 'Paris' OR Ville = 'Lyon') AND Budget > 1000
```
→ Parisiens ou Lyonnais avec budget > 1000€

**✅ Clair (intention 2)** :
```sql
WHERE Ville = 'Paris' OR (Ville = 'Lyon' AND Budget > 1000)
```
→ Tous les Parisiens + Lyonnais avec budget > 1000€

---

### Visualisation de la priorité

**Sans parenthèses** :
```sql
WHERE A OR B AND C
```

Est interprété comme :
```sql
WHERE A OR (B AND C)
```

**Avec parenthèses** :
```sql
WHERE (A OR B) AND C
```

Est clair et intentionnel.

## 6. Tables de vérité

### Table de vérité pour AND

| A | B | A AND B |
|---|---|---------|
| VRAI | VRAI | **VRAI** ✅ |
| VRAI | FAUX | FAUX ❌ |
| FAUX | VRAI | FAUX ❌ |
| FAUX | FAUX | FAUX ❌ |

**Mnémotechnique** : Les deux doivent être VRAI (exigeant).

---

### Table de vérité pour OR

| A | B | A OR B |
|---|---|--------|
| VRAI | VRAI | **VRAI** ✅ |
| VRAI | FAUX | **VRAI** ✅ |
| FAUX | VRAI | **VRAI** ✅ |
| FAUX | FAUX | FAUX ❌ |

**Mnémotechnique** : Au moins un doit être VRAI (tolérant).

---

### Table de vérité pour NOT

| A | NOT A |
|---|-------|
| VRAI | FAUX ❌ |
| FAUX | **VRAI** ✅ |

**Mnémotechnique** : Inverse le résultat.

## 7. Exemples pratiques par domaine

### E-commerce

**Produits populaires ou en promotion** :
```sql
SELECT NomProduit, NombreVentes, EnPromotion
FROM Produits
WHERE NombreVentes > 100 OR EnPromotion = 1
```

**Produits abordables en stock** :
```sql
SELECT NomProduit, Prix, Stock
FROM Produits
WHERE Prix < 50 AND Stock > 0
```

**Électronique ou informatique de moins de 200€** :
```sql
SELECT NomProduit, Categorie, Prix
FROM Produits
WHERE (Categorie = 'Électronique' OR Categorie = 'Informatique')
  AND Prix < 200
```

---

### Ressources Humaines

**Employés IT ou Marketing avec salaire élevé** :
```sql
SELECT Prenom, Nom, Departement, Salaire
FROM Employes
WHERE (Departement = 'IT' OR Departement = 'Marketing')
  AND Salaire > 4000
```

**Employés seniors ou managers** :
```sql
SELECT Prenom, Nom, Age, Poste
FROM Employes
WHERE Age > 45 OR Poste = 'Manager'
```

**Employés récents d'un département spécifique** :
```sql
SELECT Prenom, Nom, DateEmbauche, Departement
FROM Employes
WHERE DateEmbauche >= '2024-01-01'
  AND Departement = 'Ventes'
```

---

### Gestion de projet

**Projets urgents ou en retard** :
```sql
SELECT NomProjet, Priorite, Statut
FROM Projets
WHERE Priorite = 'Haute' OR Statut = 'En retard'
```

**Projets actifs mais pas encore commencés** :
```sql
SELECT NomProjet, Statut, DateDebut
FROM Projets
WHERE Statut = 'Actif'
  AND DateDebut > GETDATE()
```

**Projets de grande taille avec budget limité** :
```sql
SELECT NomProjet, NombreHeures, Budget
FROM Projets
WHERE NombreHeures > 500
  AND Budget < 50000
```

## 8. Pièges courants et erreurs à éviter

### Piège 1 : Oublier les parenthèses

**❌ Problématique** :
```sql
WHERE Ville = 'Paris' OR Ville = 'Lyon' AND Budget > 1000
```

**Interprétation SQL** :
```sql
WHERE Ville = 'Paris' OR (Ville = 'Lyon' AND Budget > 1000)
```

**✅ Correction** :
```sql
WHERE (Ville = 'Paris' OR Ville = 'Lyon') AND Budget > 1000
```

---

### Piège 2 : Répétition inutile avec OR

**⚠️ Redondant** :
```sql
WHERE (Prix < 50 OR Prix < 100)
```

**Explication** : Si Prix < 50, alors Prix < 100 est automatiquement vrai. La condition `OR Prix < 100` est inutile.

**✅ Simplifié** :
```sql
WHERE Prix < 100
```

---

### Piège 3 : Conditions contradictoires avec AND

**❌ Impossible** :
```sql
WHERE Ville = 'Paris' AND Ville = 'Lyon'
```

**Explication** : Une ville ne peut pas être Paris **ET** Lyon en même temps. Cette requête retournera toujours zéro résultat.

**✅ Correction** :
```sql
WHERE Ville = 'Paris' OR Ville = 'Lyon'
```

---

### Piège 4 : NOT mal placé

**❌ Ambigu** :
```sql
WHERE NOT Ville = 'Paris' OR Ville = 'Lyon'
```

**Interprétation** :
```sql
WHERE (NOT (Ville = 'Paris')) OR Ville = 'Lyon'
```

**✅ Clair** :
```sql
WHERE NOT (Ville = 'Paris' OR Ville = 'Lyon')
```

---

### Piège 5 : Comparaison de types incompatibles

**❌ Erreur** :
```sql
WHERE Prix > 100 AND Categorie > 50  -- Comparer un texte avec un nombre
```

**✅ Cohérent** :
```sql
WHERE Prix > 100 AND Stock > 50
```

---

### Piège 6 : Utilisation excessive de NOT

**⚠️ Compliqué** :
```sql
WHERE NOT (NOT (Ville = 'Paris'))
```

**✅ Simplifié** :
```sql
WHERE Ville = 'Paris'
```

**Règle** : Double négation = affirmation

---

## 9. Bonnes pratiques

### ✅ À faire

1. **Toujours utiliser des parenthèses** pour clarifier :
   ```sql
   WHERE (Categorie = 'A' OR Categorie = 'B') AND Prix < 100
   ```

2. **Indenter pour la lisibilité** :
   ```sql
   WHERE
       (Ville = 'Paris' OR Ville = 'Lyon')
       AND Budget > 1000
       AND Statut = 'Actif'
   ```

3. **Regrouper les conditions similaires** :
   ```sql
   WHERE (Ville = 'Paris' OR Ville = 'Lyon')  -- Villes ensemble
     AND (Prix < 100 OR EnPromotion = 1)       -- Prix/promo ensemble
   ```

4. **Utiliser des commentaires** pour les conditions complexes :
   ```sql
   WHERE
       -- Clients VIP des grandes villes
       (Ville = 'Paris' OR Ville = 'Lyon')
       AND StatutVIP = 1
   ```

5. **Tester progressivement** :
   ```sql
   -- Étape 1 : Tester la première condition
   WHERE Categorie = 'Électronique'

   -- Étape 2 : Ajouter la seconde
   WHERE Categorie = 'Électronique' AND Prix < 500
   ```

---

### ❌ À éviter

1. **Conditions sans parenthèses** quand on mélange AND et OR :
   ```sql
   WHERE A OR B AND C  -- ❌ Ambigu
   ```

2. **Trop de négations** :
   ```sql
   WHERE NOT (NOT (NOT Condition))  -- ❌ Illisible
   ```

3. **Conditions impossibles** :
   ```sql
   WHERE Prix > 1000 AND Prix < 100  -- ❌ Impossible
   ```

4. **Répétitions inutiles** :
   ```sql
   WHERE (Ville = 'Paris' OR Ville = 'Paris')  -- ❌ Redondant
   ```

---

## 10. Stratégies de construction de requêtes complexes

### Méthode 1 : Construction progressive

**Étape 1** - Commencez simple :
```sql
SELECT * FROM Produits
WHERE Categorie = 'Électronique'
```

**Étape 2** - Ajoutez une condition :
```sql
SELECT * FROM Produits
WHERE Categorie = 'Électronique'
  AND Prix < 500
```

**Étape 3** - Ajoutez une alternative :
```sql
SELECT * FROM Produits
WHERE (Categorie = 'Électronique' AND Prix < 500)
   OR EnPromotion = 1
```

---

### Méthode 2 : Diagramme mental

Avant d'écrire votre requête, dessinez ou imaginez :

```
JE VEUX :
├── (Électronique ET moins de 500€)
│   └── Condition 1 AND Condition 2
└── OU
    └── En promotion
        └── Condition 3

REQUÊTE :
WHERE (Categorie = 'Électronique' AND Prix < 500) OR EnPromotion = 1
```

---

### Méthode 3 : Phrase en français

Traduisez votre besoin en français, puis en SQL :

**Français** : "Je veux les clients de Paris ou Lyon qui ont un budget supérieur à 1000€ et qui sont actifs"

**Découpage** :
- Ville = Paris **OU** Lyon
- **ET** Budget > 1000
- **ET** Statut = Actif

**SQL** :
```sql
WHERE (Ville = 'Paris' OR Ville = 'Lyon')
  AND Budget > 1000
  AND Statut = 'Actif'
```

## 11. Aide-mémoire visuel

### Quand utiliser chaque opérateur ?

```
┌─────────────────────────────────────────────┐
│ JE VEUX...                                  │
├─────────────────────────────────────────────┤
│ Conditions multiples TOUTES obligatoires    │
│ → AND                                       │
│ Exemple: Électronique ET pas cher           │
├─────────────────────────────────────────────┤
│ Au moins UNE condition parmi plusieurs      │
│ → OR                                        │
│ Exemple: Paris OU Lyon                      │
├─────────────────────────────────────────────┤
│ EXCLURE quelque chose                       │
│ → NOT ou !=                                 │
│ Exemple: Tout SAUF Paris                    │
└─────────────────────────────────────────────┘
```

## 12. Tableau récapitulatif complet

| Opérateur | Fonction | Condition pour TRUE | Exemple |
|-----------|----------|---------------------|---------|
| **AND** | Toutes vraies | A=VRAI **ET** B=VRAI | `Prix < 100 AND Stock > 0` |
| **OR** | Au moins une vraie | A=VRAI **OU** B=VRAI | `Ville = 'Paris' OR Ville = 'Lyon'` |
| **NOT** | Inverse | A=FAUX | `NOT (Categorie = 'Livres')` |

---

## Résumé

### Points clés à retenir

1. **AND** : Toutes les conditions doivent être vraies (restrictif)

2. **OR** : Au moins une condition doit être vraie (permissif)

3. **NOT** : Inverse une condition (exclusion)

4. **Priorité** : NOT → AND → OR (mais toujours utiliser des parenthèses !)

5. **Parenthèses** : Essentielles pour la clarté et l'intention

6. **Lisibilité** : Indentez et commentez les conditions complexes

### Formules pratiques

| Besoin | Formule |
|--------|---------|
| Plage de valeurs | `x >= min AND x <= max` |
| Plusieurs valeurs | `x = val1 OR x = val2 OR x = val3` |
| Exclusion | `NOT (x = val)` ou `x != val` |
| Exclusions multiples | `NOT (x = val1 OR x = val2)` |
| Conditions mixtes | `(A OR B) AND C` |
