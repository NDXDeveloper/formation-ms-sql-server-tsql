# 2.6.1 Syntaxe DELETE FROM ... WHERE

## Introduction

L'instruction **DELETE** est la commande SQL qui permet de **supprimer des données existantes** d'une table. Tout comme UPDATE, DELETE est une opération puissante qui doit être utilisée avec une extrême précaution.

Si UPDATE modifie des données, DELETE les fait disparaître complètement. Une fois exécuté et validé, un DELETE est irréversible (sauf restauration depuis une sauvegarde). C'est pourquoi la maîtrise de cette commande et de ses bonnes pratiques est absolument essentielle.

Dans cette section, nous allons apprendre à utiliser DELETE de manière sûre et efficace pour supprimer les bonnes données au bon moment.

---

## Qu'est-ce que DELETE ?

**DELETE** est une commande DML (Data Manipulation Language) qui permet de **supprimer des lignes entières** d'une table.

### Analogie du monde réel

Reprenons notre analogie du carnet d'adresses :
- **INSERT** : Ajouter un nouveau contact sur une page vierge
- **UPDATE** : Corriger l'adresse ou le téléphone d'un contact existant
- **DELETE** : Rayer complètement un contact et retirer la page

### Ce que DELETE fait et ne fait pas

✅ **DELETE fait :**
- Supprimer une ou plusieurs lignes complètes
- Réduire le nombre de lignes dans la table
- Libérer de l'espace (éventuellement)
- Déclencher les triggers DELETE (si définis)

❌ **DELETE ne fait PAS :**
- Supprimer des colonnes (c'est ALTER TABLE)
- Supprimer la table elle-même (c'est DROP TABLE)
- Vider partiellement une ligne (utilisez UPDATE avec NULL)
- Supprimer la structure de la table

---

## La syntaxe de base

Voici la structure fondamentale de l'instruction DELETE :

```sql
DELETE FROM nom_table
WHERE condition;
```

### Décomposition de la syntaxe

| Élément | Rôle | Obligatoire ? |
|---------|------|---------------|
| **DELETE FROM** | Mots-clés qui démarrent la commande | ✅ Oui |
| **nom_table** | La table dont on supprime les lignes | ✅ Oui |
| **WHERE** | Condition pour filtrer les lignes à supprimer | ⚠️ CRUCIAL (fortement recommandé) |

**Note :** On peut aussi écrire simplement `DELETE nom_table` (sans FROM), mais `DELETE FROM` est plus explicite et recommandé.

**⚠️ AVERTISSEMENT CRITIQUE :** Sans clause WHERE, **TOUTES** les lignes de la table seront supprimées !

## Exemples de base

### Exemple 1 : Supprimer une seule ligne

Imaginons une table de clients :

```sql
-- État initial de la table
SELECT * FROM Clients;

/*
ClientID | Nom           | Email                | EstActif
---------|---------------|----------------------|----------
1        | Marie Dupont  | marie.d@email.fr     | 1
2        | Pierre Martin | pierre.m@email.com   | 1
3        | Julie Leroux  | julie.l@email.fr     | 0
4        | Luc Petit     | luc.p@email.fr       | 1
*/

-- Supprimer le client inactif (ID 3)
DELETE FROM Clients
WHERE ClientID = 3;

-- Résultat après DELETE
SELECT * FROM Clients;

/*
ClientID | Nom           | Email                | EstActif
---------|---------------|----------------------|----------
1        | Marie Dupont  | marie.d@email.fr     | 1
2        | Pierre Martin | pierre.m@email.com   | 1
4        | Luc Petit     | luc.p@email.fr       | 1
*/
```

**Explication :**
- `DELETE FROM Clients` : on supprime des lignes de la table Clients
- `WHERE ClientID = 3` : uniquement la ligne avec l'ID 3
- Le nombre de lignes passe de 4 à 3
- Julie Leroux a complètement disparu de la table

### Exemple 2 : Supprimer plusieurs lignes

```sql
-- Table de produits
CREATE TABLE Produits (
    ProduitID INT,
    Nom NVARCHAR(100),
    Stock INT,
    DateAjout DATE
);

INSERT INTO Produits VALUES
    (1, N'Laptop Dell', 5, '2024-01-15'),
    (2, N'Souris Logitech', 0, '2024-02-20'),
    (3, N'Clavier Corsair', 0, '2024-03-10'),
    (4, N'Écran Samsung', 10, '2024-04-05'),
    (5, N'Webcam HP', 0, '2024-05-12');

-- Supprimer tous les produits en rupture de stock
DELETE FROM Produits
WHERE Stock = 0;

-- Résultat : 3 lignes supprimées (IDs 2, 3, 5)
SELECT * FROM Produits;

/*
ProduitID | Nom           | Stock | DateAjout
----------|---------------|-------|------------
1         | Laptop Dell   | 5     | 2024-01-15
4         | Écran Samsung | 10    | 2024-04-05
*/
```

**Explication :**
- La condition `WHERE Stock = 0` sélectionne 3 produits
- Ces 3 produits sont supprimés en une seule opération
- Les produits avec du stock restent dans la table

### Exemple 3 : Le danger de DELETE sans WHERE

```sql
-- ❌ CATASTROPHE : Supprimer TOUS les clients !
DELETE FROM Clients;
-- OUPS ! Pas de WHERE !

-- Résultat : La table est VIDE
SELECT * FROM Clients;

/*
ClientID | Nom | Email | EstActif
---------|-----|-------|----------
(0 lignes)
*/
```

**Conséquence :** Toutes les données clients ont été perdues définitivement (sauf restauration depuis sauvegarde).

## La clause WHERE : Votre protection essentielle

Comme pour UPDATE, la clause WHERE est **absolument cruciale** dans DELETE.

### Sans WHERE : Désastre garanti

```sql
-- Table avec 50 000 commandes
DELETE FROM Commandes;
-- CATASTROPHE : 50 000 commandes supprimées !
```

### Avec WHERE : Contrôle précis

```sql
-- Supprimer uniquement les commandes annulées de plus de 2 ans
DELETE FROM Commandes
WHERE Statut = N'Annulée'
  AND DateCommande < DATEADD(YEAR, -2, GETDATE());
```

### Bonne pratique : Tester avec SELECT d'abord

**C'est LA règle d'or pour éviter les catastrophes !**

```sql
-- ✅ PROCESSUS SÉCURISÉ

-- Étape 1 : Vérifier QUELLES lignes seront supprimées
SELECT * FROM Clients
WHERE EstActif = 0 AND DerniereConnexion < '2023-01-01';

-- Vérifier le nombre de lignes
SELECT COUNT(*) FROM Clients
WHERE EstActif = 0 AND DerniereConnexion < '2023-01-01';
-- Résultat : 23 lignes

-- Étape 2 : Si OK, remplacer SELECT par DELETE avec la MÊME clause WHERE
DELETE FROM Clients
WHERE EstActif = 0 AND DerniereConnexion < '2023-01-01';

-- Étape 3 : Vérifier le résultat
SELECT @@ROWCOUNT AS LignesSupprimees;
-- Résultat : 23 lignes supprimées (correspond aux attentes ✓)
```

## Opérateurs dans la clause WHERE

Vous pouvez utiliser tous les opérateurs de filtrage dans la clause WHERE de DELETE.

### Opérateurs de comparaison

```sql
-- Égalité
DELETE FROM Produits WHERE ProduitID = 5;

-- Différent de
DELETE FROM Logs WHERE Niveau != 'ERROR';
-- ou
DELETE FROM Logs WHERE Niveau <> 'ERROR';

-- Plus grand que
DELETE FROM Sessions WHERE DateCreation > '2024-01-01';

-- Plus grand ou égal
DELETE FROM Commandes WHERE DateCommande >= '2023-01-01';

-- Plus petit que
DELETE FROM Produits WHERE Prix < 10;

-- Plus petit ou égal
DELETE FROM Utilisateurs WHERE AgeCompte <= 0;
```

### Opérateurs logiques (AND, OR, NOT)

```sql
-- AND : toutes les conditions doivent être vraies
DELETE FROM Produits
WHERE Stock = 0 AND DateAjout < '2023-01-01';

-- OR : au moins une condition doit être vraie
DELETE FROM Logs
WHERE Niveau = 'DEBUG' OR DateLog < DATEADD(DAY, -30, GETDATE());

-- NOT : inverse la condition
DELETE FROM Utilisateurs
WHERE NOT (EstPremium = 1);
```

### Opérateur IN (liste de valeurs)

```sql
-- Supprimer plusieurs IDs spécifiques
DELETE FROM Clients
WHERE ClientID IN (5, 12, 18, 25);

-- Équivalent à :
-- WHERE ClientID = 5 OR ClientID = 12 OR ClientID = 18 OR ClientID = 25

-- Avec des chaînes
DELETE FROM Produits
WHERE Categorie IN (N'Obsolète', N'Discontinué', N'Retiré');
```

### Opérateur BETWEEN (plage de valeurs)

```sql
-- Supprimer les commandes d'une période spécifique
DELETE FROM Commandes
WHERE DateCommande BETWEEN '2023-01-01' AND '2023-12-31';

-- Équivalent à :
-- WHERE DateCommande >= '2023-01-01' AND DateCommande <= '2023-12-31'

-- Avec des nombres
DELETE FROM Produits
WHERE Prix BETWEEN 0 AND 10;
```

### Opérateur LIKE (correspondance de motif)

```sql
-- Supprimer tous les produits dont le nom commence par "Test"
DELETE FROM Produits
WHERE Nom LIKE N'Test%';

-- Supprimer les emails temporaires
DELETE FROM Utilisateurs
WHERE Email LIKE '%@temp.com';

-- Supprimer les codes avec un format spécifique
DELETE FROM Codes
WHERE CodeProduit LIKE 'OLD-____';  -- 4 caractères après OLD-
```

### Vérification de NULL

```sql
-- Supprimer les lignes où l'email est NULL
DELETE FROM Clients
WHERE Email IS NULL;

-- Supprimer les lignes où l'email n'est PAS NULL
DELETE FROM ClientsTemporaires
WHERE Email IS NOT NULL;

-- ⚠️ IMPORTANT : N'utilisez JAMAIS = NULL
-- ❌ Incorrect (ne fonctionne pas)
DELETE FROM Clients WHERE Email = NULL;

-- ✅ Correct
DELETE FROM Clients WHERE Email IS NULL;
```

## Exemples pratiques complets

### Exemple 1 : Nettoyage de logs

```sql
-- Table de logs système
CREATE TABLE LogsSysteme (
    LogID INT IDENTITY(1,1),
    DateLog DATETIME2(3),
    Niveau NVARCHAR(20),
    Message NVARCHAR(MAX)
);

-- La table contient 10 millions de lignes
-- On veut supprimer les logs de plus de 90 jours

-- Étape 1 : Vérifier combien de lignes seront supprimées
SELECT COUNT(*) AS LogsASupprimer
FROM LogsSysteme
WHERE DateLog < DATEADD(DAY, -90, GETDATE());
-- Résultat : 8 500 000 lignes

-- Étape 2 : Vérifier quelques exemples
SELECT TOP 10 * FROM LogsSysteme
WHERE DateLog < DATEADD(DAY, -90, GETDATE())
ORDER BY DateLog;

-- Étape 3 : Supprimer dans une transaction
BEGIN TRANSACTION;
    DELETE FROM LogsSysteme
    WHERE DateLog < DATEADD(DAY, -90, GETDATE());

    PRINT 'Logs supprimés : ' + CAST(@@ROWCOUNT AS VARCHAR);
    -- Logs supprimés : 8500000
COMMIT;
```

### Exemple 2 : Suppression de comptes inactifs

```sql
-- Supprimer les comptes utilisateurs inactifs depuis plus d'un an
CREATE TABLE Utilisateurs (
    UtilisateurID INT,
    Email VARCHAR(255),
    DerniereConnexion DATETIME2(3),
    EstActif BIT
);

-- Processus sécurisé
-- Étape 1 : Identifier les comptes à supprimer
SELECT
    UtilisateurID,
    Email,
    DerniereConnexion,
    DATEDIFF(DAY, DerniereConnexion, GETDATE()) AS JoursSansCo
FROM Utilisateurs
WHERE EstActif = 0
  AND DerniereConnexion < DATEADD(YEAR, -1, GETDATE());

-- Étape 2 : Compter
SELECT COUNT(*) AS ComptesASupprimer
FROM Utilisateurs
WHERE EstActif = 0
  AND DerniereConnexion < DATEADD(YEAR, -1, GETDATE());
-- Résultat : 1 247 comptes

-- Étape 3 : Créer une sauvegarde
SELECT * INTO Utilisateurs_Supprimés_20241115
FROM Utilisateurs
WHERE EstActif = 0
  AND DerniereConnexion < DATEADD(YEAR, -1, GETDATE());

-- Étape 4 : Supprimer
BEGIN TRANSACTION;
    DELETE FROM Utilisateurs
    WHERE EstActif = 0
      AND DerniereConnexion < DATEADD(YEAR, -1, GETDATE());

    IF @@ROWCOUNT = 1247
        PRINT 'Suppression réussie';
    ELSE
        PRINT 'ALERTE : Nombre de suppressions incorrect !';
COMMIT;
```

### Exemple 3 : Suppression en cascade manuelle

```sql
-- Supprimer une commande et toutes ses lignes de commande

-- Tables
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY,
    ClientID INT,
    DateCommande DATE
);

CREATE TABLE LignesCommande (
    LigneID INT PRIMARY KEY,
    CommandeID INT,
    ProduitID INT,
    Quantite INT
);

-- Processus de suppression
BEGIN TRANSACTION;
    -- Étape 1 : Supprimer d'abord les lignes de commande (table enfant)
    DELETE FROM LignesCommande
    WHERE CommandeID = 123;

    PRINT 'Lignes de commande supprimées : ' + CAST(@@ROWCOUNT AS VARCHAR);

    -- Étape 2 : Supprimer ensuite la commande (table parent)
    DELETE FROM Commandes
    WHERE CommandeID = 123;

    PRINT 'Commande supprimée : ' + CAST(@@ROWCOUNT AS VARCHAR);
COMMIT;
```

### Exemple 4 : Suppression avec JOIN

Vous pouvez utiliser des informations d'autres tables pour décider quoi supprimer.

```sql
-- Supprimer les produits de catégories obsolètes

CREATE TABLE Produits (
    ProduitID INT,
    Nom NVARCHAR(100),
    CategorieID INT
);

CREATE TABLE Categories (
    CategorieID INT,
    NomCategorie NVARCHAR(100),
    EstObsolete BIT
);

-- Méthode 1 : Avec sous-requête
DELETE FROM Produits
WHERE CategorieID IN (
    SELECT CategorieID
    FROM Categories
    WHERE EstObsolete = 1
);

-- Méthode 2 : Avec JOIN (syntaxe SQL Server)
DELETE P
FROM Produits P
INNER JOIN Categories C ON P.CategorieID = C.CategorieID
WHERE C.EstObsolete = 1;
```

### Exemple 5 : Suppression conditionnelle avec EXISTS

```sql
-- Supprimer les clients qui n'ont jamais passé de commande

DELETE FROM Clients
WHERE NOT EXISTS (
    SELECT 1
    FROM Commandes
    WHERE Commandes.ClientID = Clients.ClientID
);

-- Ou avec NOT IN (moins performant)
DELETE FROM Clients
WHERE ClientID NOT IN (
    SELECT DISTINCT ClientID
    FROM Commandes
);
```

## DELETE et @@ROWCOUNT

Comme pour UPDATE, la variable système @@ROWCOUNT indique le nombre de lignes affectées.

### Utilisation de @@ROWCOUNT

```sql
-- Supprimer des produits obsolètes
DELETE FROM Produits
WHERE DateAjout < '2020-01-01';

-- Vérifier combien de lignes ont été supprimées
SELECT @@ROWCOUNT AS LignesSupprimees;

-- Utiliser dans la logique
DECLARE @NbSupprimes INT;

DELETE FROM TempData WHERE Processed = 1;
SET @NbSupprimes = @@ROWCOUNT;

IF @NbSupprimes > 0
    PRINT CAST(@NbSupprimes AS VARCHAR) + ' lignes supprimées avec succès';
ELSE
    PRINT 'Aucune ligne à supprimer';
```

### Vérification de sécurité avec @@ROWCOUNT

```sql
BEGIN TRANSACTION;
    -- Supprimer une ligne spécifique
    DELETE FROM Clients WHERE ClientID = 123;

    -- Vérifier qu'exactement 1 ligne a été supprimée
    IF @@ROWCOUNT = 1
    BEGIN
        PRINT 'Suppression réussie';
        COMMIT;
    END
    ELSE
    BEGIN
        PRINT 'ERREUR : Nombre de suppressions incorrect !';
        ROLLBACK;
    END
```

## DELETE avec TOP : Limiter le nombre de suppressions

Vous pouvez limiter le nombre de lignes supprimées avec TOP.

### Syntaxe avec TOP

```sql
-- Supprimer seulement les 10 premières lignes qui correspondent
DELETE TOP (10) FROM Logs
WHERE DateLog < '2023-01-01';

-- Avec pourcentage
DELETE TOP (5) PERCENT FROM TableTest
WHERE Processed = 1;
```

### Cas d'usage pratique

```sql
-- Supprimer progressivement les vieux logs pour éviter de bloquer la table
DECLARE @BatchSize INT = 1000;
DECLARE @TotalDeleted INT = 0;

WHILE 1 = 1
BEGIN
    DELETE TOP (@BatchSize) FROM LogsSysteme
    WHERE DateLog < DATEADD(DAY, -90, GETDATE());

    SET @TotalDeleted = @TotalDeleted + @@ROWCOUNT;

    IF @@ROWCOUNT = 0 BREAK;  -- Plus rien à supprimer

    PRINT CAST(@TotalDeleted AS VARCHAR) + ' lignes supprimées...';
    WAITFOR DELAY '00:00:01';  -- Pause de 1 seconde
END

PRINT 'Terminé ! Total : ' + CAST(@TotalDeleted AS VARCHAR) + ' lignes supprimées';
```

## Pièges courants et erreurs à éviter

### Piège 1 : Oublier la clause WHERE

```sql
-- ❌ CATASTROPHE
DELETE FROM Clients;
-- Tous les clients supprimés !

-- ✅ CORRECT
DELETE FROM Clients
WHERE ClientID = 123;
```

**Solution :** Toujours inclure WHERE, sauf si vous voulez vraiment tout supprimer.

### Piège 2 : Violation de contrainte de clé étrangère

```sql
-- Table parent
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom NVARCHAR(100)
);

-- Table enfant avec FOREIGN KEY
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY,
    ClientID INT FOREIGN KEY REFERENCES Clients(ClientID),
    DateCommande DATE
);

-- ❌ Erreur : impossible de supprimer le client s'il a des commandes
DELETE FROM Clients WHERE ClientID = 1;
-- Erreur : violation de contrainte FOREIGN KEY

-- ✅ Solution : Supprimer d'abord les commandes (enfants)
DELETE FROM Commandes WHERE ClientID = 1;
-- Puis supprimer le client (parent)
DELETE FROM Clients WHERE ClientID = 1;
```

### Piège 3 : Mauvaise condition WHERE

```sql
-- ❌ Utiliser = au lieu de LIKE
DELETE FROM Produits
WHERE Nom = 'Test';  -- Ne supprime que "Test" exactement

-- ✅ Utiliser LIKE pour une recherche partielle
DELETE FROM Produits
WHERE Nom LIKE N'Test%';  -- Supprime tout ce qui commence par "Test"
```

### Piège 4 : Oublier les dépendances

```sql
-- ❌ Supprimer une catégorie sans vérifier les produits
DELETE FROM Categories WHERE CategorieID = 5;
-- Que faire des produits de cette catégorie ?

-- ✅ Vérifier d'abord
SELECT COUNT(*) FROM Produits WHERE CategorieID = 5;

-- Puis décider :
-- Option 1 : Réassigner les produits
UPDATE Produits SET CategorieID = 99 WHERE CategorieID = 5;
DELETE FROM Categories WHERE CategorieID = 5;

-- Option 2 : Supprimer les produits aussi
DELETE FROM Produits WHERE CategorieID = 5;
DELETE FROM Categories WHERE CategorieID = 5;
```

### Piège 5 : DELETE vs TRUNCATE confusion

```sql
-- DELETE : Peut avoir un WHERE, plus lent, enregistré dans le log
DELETE FROM Logs WHERE DateLog < '2023-01-01';

-- TRUNCATE : Pas de WHERE, très rapide, peu de logging
TRUNCATE TABLE Logs;  -- Supprime TOUT

-- ❌ Erreur courante : essayer d'utiliser WHERE avec TRUNCATE
TRUNCATE TABLE Logs WHERE DateLog < '2023-01-01';  -- ERREUR SYNTAXE !
```

### Piège 6 : NULL dans les comparaisons

```sql
-- ❌ Ceci ne supprime RIEN (même si Email est NULL)
DELETE FROM Clients WHERE Email = NULL;

-- ✅ Correct
DELETE FROM Clients WHERE Email IS NULL;

-- ⚠️ Attention aux calculs avec NULL
DELETE FROM Produits WHERE Prix - PrixCout > 0;
-- Si PrixCout est NULL, la ligne ne sera PAS supprimée (NULL > 0 = NULL)
```

## Bonnes pratiques pour DELETE

### 1. Toujours tester avec SELECT d'abord

```sql
-- ✅ PROCESSUS SÉCURISÉ
-- Étape 1 : SELECT pour voir ce qui sera supprimé
SELECT * FROM Clients WHERE EstActif = 0;

-- Étape 2 : Compter pour être sûr
SELECT COUNT(*) FROM Clients WHERE EstActif = 0;

-- Étape 3 : DELETE avec la même clause WHERE
DELETE FROM Clients WHERE EstActif = 0;
```

### 2. Utiliser des transactions

```sql
BEGIN TRANSACTION;
    DELETE FROM Produits WHERE Stock = 0;

    -- Vérifier le résultat
    SELECT @@ROWCOUNT;

    -- Si OK : valider
    COMMIT;

    -- Si problème : annuler
    -- ROLLBACK;
```

### 3. Sauvegarder les données avant suppression importante

```sql
-- Créer une table de sauvegarde
SELECT * INTO ClientsInactifs_Backup_20241115
FROM Clients
WHERE EstActif = 0;

-- Maintenant, supprimer en toute sécurité
DELETE FROM Clients WHERE EstActif = 0;

-- En cas de problème, restaurer :
-- INSERT INTO Clients SELECT * FROM ClientsInactifs_Backup_20241115;
```

### 4. Documenter les suppressions importantes

```sql
-- Ajouter des commentaires explicatifs
-- Suppression des comptes inactifs > 2 ans
-- Date : 2024-11-15
-- Demandeur : Service Juridique (ticket #12345)
-- Nombre estimé : 1247 comptes
DELETE FROM Utilisateurs
WHERE EstActif = 0
  AND DerniereConnexion < DATEADD(YEAR, -2, GETDATE());
```

### 5. Pour les grosses suppressions, procéder par lots

```sql
-- Au lieu de tout supprimer d'un coup
WHILE 1 = 1
BEGIN
    DELETE TOP (1000) FROM LogsSysteme
    WHERE DateLog < DATEADD(DAY, -90, GETDATE());

    IF @@ROWCOUNT = 0 BREAK;

    WAITFOR DELAY '00:00:01';  -- Pause pour ne pas surcharger
END
```

### 6. Vérifier les triggers

```sql
-- Vérifier si des triggers existent sur la table
SELECT
    name AS TriggerName,
    OBJECT_NAME(parent_id) AS TableName
FROM sys.triggers
WHERE parent_id = OBJECT_ID('Clients');

-- Les triggers DELETE peuvent :
-- - Archiver les données supprimées
-- - Empêcher certaines suppressions
-- - Déclencher des effets de bord
```

## DELETE et les performances

### Impact sur les performances

```sql
-- ❌ Lent : suppression de millions de lignes
DELETE FROM LogsSysteme
WHERE DateLog < '2023-01-01';
-- Peut prendre des heures sur une grosse table

-- ✅ Plus rapide : suppression par lots
WHILE 1 = 1
BEGIN
    DELETE TOP (10000) FROM LogsSysteme
    WHERE DateLog < '2023-01-01';

    IF @@ROWCOUNT = 0 BREAK;
END
```

### DELETE vs TRUNCATE (performance)

```sql
-- DELETE : Plus lent mais flexible
DELETE FROM TableTemporaire;  -- Enregistré dans le log, peut avoir WHERE

-- TRUNCATE : Beaucoup plus rapide
TRUNCATE TABLE TableTemporaire;  -- Minimal logging, pas de WHERE

-- Pour vider complètement une table, préférez TRUNCATE si possible
```

### Index et DELETE

```sql
-- Les index peuvent accélérer DELETE
CREATE INDEX IX_Logs_DateLog ON LogsSysteme(DateLog);

-- Maintenant ce DELETE est plus rapide
DELETE FROM LogsSysteme
WHERE DateLog < '2023-01-01';
-- L'index permet de trouver rapidement les lignes à supprimer
```

## DELETE et récupération

### Si vous êtes dans une transaction : ROLLBACK

```sql
BEGIN TRANSACTION;
    DELETE FROM Clients;
    -- OUPS ! Oublié le WHERE !

    -- Vérifier combien de lignes supprimées
    SELECT @@ROWCOUNT;  -- 50 000 lignes !

    -- VITE ! Annuler
    ROLLBACK;

-- Ouf, les données sont sauvées
```

### Si déjà committé : Restauration nécessaire

```sql
-- Option 1 : Restaurer depuis une table de backup
INSERT INTO Clients
SELECT * FROM Clients_Backup_20241115;

-- Option 2 : Restaurer la base depuis sauvegarde (perte de toutes les données récentes)
RESTORE DATABASE MaBase FROM DISK = 'C:\Backup\MaBase.bak';

-- Option 3 : Récupération depuis les logs de transaction (complexe, requiert un DBA)
```

## Cas particulier : DELETE sans WHERE volontaire

Il existe des cas légitimes où vous voulez supprimer **toutes** les lignes.

### Exemples légitimes

```sql
-- Vider une table temporaire
DELETE FROM TempCalculations;

-- Nettoyer une table de cache
DELETE FROM Cache;

-- Réinitialiser une table de test
DELETE FROM TableTest;
```

### Comment s'assurer que c'est volontaire ?

```sql
-- ✅ BONNE PRATIQUE : Ajouter un commentaire explicite
-- ATTENTION : Cette requête supprime TOUTES les lignes de la table
-- C'est volontaire pour réinitialiser le cache
DELETE FROM Cache;

-- Ou mieux : utiliser TRUNCATE si pas de conditions
TRUNCATE TABLE Cache;  -- Plus explicite, plus rapide
```

## Checklist de sécurité avant DELETE

Avant d'exécuter **TOUTE** instruction DELETE en production, vérifiez :

### ✅ Checklist pré-exécution

- [ ] **J'ai testé avec SELECT d'abord** avec la même clause WHERE
- [ ] **J'ai vérifié le nombre de lignes** qui seront supprimées
- [ ] **J'ai une clause WHERE** (sauf si suppression totale volontaire et documentée)
- [ ] **J'ai une sauvegarde récente** de la base ou une copie des données à supprimer
- [ ] **Je suis dans une transaction** (BEGIN TRANSACTION)
- [ ] **J'ai vérifié les contraintes** de clé étrangère
- [ ] **J'ai vérifié les dépendances** dans d'autres tables
- [ ] **Je connais le nombre attendu de lignes** à supprimer

### ✅ Checklist post-exécution

- [ ] **J'ai vérifié @@ROWCOUNT** immédiatement après
- [ ] **Le nombre de lignes supprimées correspond** à mes attentes
- [ ] **J'ai vérifié** qu'il ne reste pas de données orphelines
- [ ] **Aucune contrainte n'a été violée**
- [ ] **Je peux COMMIT** la transaction en toute sécurité

## Exemples de scénarios complets

### Scénario 1 : Nettoyage de sessions expirées

```sql
-- Supprimer les sessions expirées depuis plus de 24h
BEGIN TRANSACTION;
    -- Étape 1 : Voir ce qui sera supprimé
    SELECT
        SessionID,
        UtilisateurID,
        DateCreation,
        DateExpiration
    FROM Sessions
    WHERE DateExpiration < DATEADD(HOUR, -24, GETDATE());

    -- Étape 2 : Compter
    SELECT COUNT(*) AS SessionsExpirees
    FROM Sessions
    WHERE DateExpiration < DATEADD(HOUR, -24, GETDATE());

    -- Étape 3 : Supprimer
    DELETE FROM Sessions
    WHERE DateExpiration < DATEADD(HOUR, -24, GETDATE());

    PRINT 'Sessions supprimées : ' + CAST(@@ROWCOUNT AS VARCHAR);
COMMIT;
```

### Scénario 2 : Suppression de données avec archivage

```sql
-- Archiver puis supprimer les vieilles commandes
BEGIN TRANSACTION;
    -- Étape 1 : Copier dans une table d'archive
    INSERT INTO CommandesArchive
    SELECT * FROM Commandes
    WHERE DateCommande < DATEADD(YEAR, -5, GETDATE());

    PRINT 'Commandes archivées : ' + CAST(@@ROWCOUNT AS VARCHAR);

    -- Étape 2 : Supprimer de la table principale
    DELETE FROM Commandes
    WHERE DateCommande < DATEADD(YEAR, -5, GETDATE());

    PRINT 'Commandes supprimées : ' + CAST(@@ROWCOUNT AS VARCHAR);
COMMIT;
```

### Scénario 3 : Suppression avec vérification métier

```sql
-- Supprimer un produit seulement s'il n'a jamais été commandé
BEGIN TRANSACTION;
    DECLARE @ProduitID INT = 42;
    DECLARE @NbCommandes INT;

    -- Vérifier si le produit a été commandé
    SELECT @NbCommandes = COUNT(*)
    FROM LignesCommande
    WHERE ProduitID = @ProduitID;

    IF @NbCommandes = 0
    BEGIN
        DELETE FROM Produits WHERE ProduitID = @ProduitID;
        PRINT 'Produit supprimé (jamais commandé)';
        COMMIT;
    END
    ELSE
    BEGIN
        PRINT 'ERREUR : Le produit a ' + CAST(@NbCommandes AS VARCHAR) + ' commande(s)';
        ROLLBACK;
    END
```

## Points clés à retenir

✅ **DELETE** supprime des lignes entières (pas des colonnes)

✅ **WHERE est CRUCIAL** : sans WHERE, toutes les lignes sont supprimées !

✅ **TOUJOURS tester avec SELECT** avant de faire DELETE

✅ **Utiliser des transactions** pour pouvoir annuler

✅ **Vérifier @@ROWCOUNT** après chaque DELETE

✅ **Sauvegarder** les données importantes avant suppression

✅ **Respecter l'ordre** : enfants avant parents (clés étrangères)

✅ **TOP** permet de limiter le nombre de suppressions

❌ **Pas de CTRL+Z** : une fois COMMIT, c'est permanent

❌ **Attention aux contraintes** de clé étrangère

❌ **DELETE est plus lent** que TRUNCATE pour vider une table

---

## Règle ultime

> **Si vous avez le moindre doute, NE FAITES PAS le DELETE.**
>
> Prenez le temps de :
> 1. Vérifier avec SELECT
> 2. Compter les lignes
> 3. Créer une sauvegarde
> 4. Utiliser une transaction
> 5. Vérifier le résultat
>
> **Une suppression accidentelle peut détruire des années de données en quelques secondes.**

## Conclusion

L'instruction **DELETE** est simple dans sa syntaxe mais dangereuse dans son exécution. Une seule erreur peut causer des dégâts irréparables.

**Les trois commandements du DELETE :**

1. **Tu testeras avec SELECT d'abord**
2. **Tu utiliseras des transactions**
3. **Tu sauvegarderas avant les suppressions importantes**

Contrairement à UPDATE qui écrase les données, DELETE les fait complètement disparaître. Il n'y a pas de récupération facile sans sauvegarde. La prévention est votre seule protection.

**Rappelez-vous : En SQL, supprimer est facile. Récupérer est difficile, voire impossible.**
