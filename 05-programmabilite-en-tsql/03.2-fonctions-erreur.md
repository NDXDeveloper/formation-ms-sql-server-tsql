# 5.3.2 Fonctions d'erreur (ERROR_NUMBER, ERROR_MESSAGE, etc.)

## Introduction

Dans la section précédente, nous avons découvert les blocs **TRY ... CATCH** qui permettent de capturer les erreurs. Mais capturer une erreur, c'est comme attraper un poisson : vous l'avez, mais il faut maintenant **l'examiner** pour comprendre ce que c'est !

Les **fonctions d'erreur** sont vos outils d'investigation. Elles vous permettent de :
- Identifier **quel type** d'erreur s'est produit
- Comprendre **pourquoi** elle s'est produite
- Savoir **où** elle s'est produite dans votre code
- Décider **comment** réagir en conséquence

Dans cette section, nous allons explorer en détail les six fonctions d'erreur principales de T-SQL et apprendre à les utiliser efficacement pour créer des systèmes de gestion d'erreurs robustes et informatifs.

---

## 1. Vue d'ensemble des fonctions d'erreur

### Les six fonctions principales

T-SQL propose six fonctions pour obtenir des informations sur une erreur dans un bloc CATCH :

| Fonction | Description | Type retourné |
|----------|-------------|---------------|
| `ERROR_NUMBER()` | Numéro unique identifiant le type d'erreur | INT |
| `ERROR_MESSAGE()` | Message texte décrivant l'erreur | NVARCHAR(4000) |
| `ERROR_SEVERITY()` | Niveau de gravité de l'erreur (11-25) | INT |
| `ERROR_STATE()` | Code d'état interne de l'erreur | INT |
| `ERROR_LINE()` | Numéro de ligne où l'erreur s'est produite | INT |
| `ERROR_PROCEDURE()` | Nom de la procédure/fonction où l'erreur s'est produite | NVARCHAR(128) |

### Règle importante

⚠️ **Ces fonctions ne fonctionnent QUE dans un bloc CATCH !**

```sql
-- ❌ Ne fonctionne PAS en dehors d'un CATCH
SELECT ERROR_MESSAGE();  -- Retourne NULL

-- ✅ Fonctionne dans un CATCH
BEGIN TRY
    SELECT 1/0;
END TRY
BEGIN CATCH
    SELECT ERROR_MESSAGE();  -- Retourne le message d'erreur
END CATCH
```

### Analogie

Pensez à ces fonctions comme à un **rapport d'accident** :
- **ERROR_NUMBER** = Code du type d'accident (collision, dérapage, etc.)
- **ERROR_MESSAGE** = Description de ce qui s'est passé
- **ERROR_SEVERITY** = Gravité (léger, moyen, grave)
- **ERROR_STATE** = Circonstances spécifiques
- **ERROR_LINE** = Lieu exact (kilomètre, rue)
- **ERROR_PROCEDURE** = Véhicule impliqué (voiture, camion)

## 2. ERROR_NUMBER() - Le numéro d'erreur

### Description

**ERROR_NUMBER()** retourne le **numéro unique** qui identifie le type d'erreur qui s'est produite. Chaque type d'erreur en SQL Server a un numéro spécifique.

### Type de retour

`INT` (entier)

### Exemples de numéros d'erreur courants

| Numéro | Description |
|--------|-------------|
| 8134 | Division par zéro |
| 2627 | Violation de contrainte PRIMARY KEY |
| 2601 | Violation de contrainte UNIQUE |
| 547 | Violation de contrainte FOREIGN KEY |
| 515 | Insertion de NULL dans une colonne NOT NULL |
| 245 | Erreur de conversion (ex: VARCHAR vers INT) |
| 208 | Nom d'objet invalide (table inexistante) |
| 2812 | Procédure stockée introuvable |

### Exemple de base

```sql
BEGIN TRY
    SELECT 100 / 0;  -- Division par zéro
END TRY
BEGIN CATCH
    PRINT 'Numéro d''erreur : ' + CAST(ERROR_NUMBER() AS VARCHAR);
END CATCH
```

**Résultat :**
```
Numéro d'erreur : 8134
```

### Utilisation pour gérer différents types d'erreurs

```sql
BEGIN TRY
    -- Tentative d'insertion
    INSERT INTO Employes (EmployeID, Nom, Email)
    VALUES (1, 'Dupont', 'dupont@email.com');
END TRY
BEGIN CATCH
    DECLARE @NumErreur INT = ERROR_NUMBER();

    IF @NumErreur = 2627
        PRINT 'Erreur : Cet ID employé existe déjà';
    ELSE IF @NumErreur = 2601
        PRINT 'Erreur : Cet email est déjà utilisé';
    ELSE IF @NumErreur = 515
        PRINT 'Erreur : Tous les champs obligatoires doivent être remplis';
    ELSE
        PRINT 'Erreur inconnue (numéro ' + CAST(@NumErreur AS VARCHAR) + ')';
END CATCH
```

### Exemple pratique : Routage des erreurs

```sql
BEGIN TRY
    -- Code risqué
    DECLARE @Prix DECIMAL(10,2) = CAST('abc' AS DECIMAL);
END TRY
BEGIN CATCH
    DECLARE @ErrNum INT = ERROR_NUMBER();

    -- Router vers différents gestionnaires selon le type
    IF @ErrNum IN (245, 8114, 8115)  -- Erreurs de conversion
    BEGIN
        PRINT '⚠ Erreur de conversion de données';
        PRINT 'Veuillez vérifier le format des données';
    END
    ELSE IF @ErrNum IN (2627, 2601)  -- Erreurs de contrainte d'unicité
    BEGIN
        PRINT '⚠ Erreur : Donnée dupliquée';
        PRINT 'Cette valeur existe déjà dans la base';
    END
    ELSE IF @ErrNum = 547  -- Erreur de clé étrangère
    BEGIN
        PRINT '⚠ Erreur de référence';
        PRINT 'L''enregistrement référencé n''existe pas';
    END
    ELSE
    BEGIN
        PRINT '❌ Erreur système (code ' + CAST(@ErrNum AS VARCHAR) + ')';
        PRINT 'Contactez l''administrateur';
    END
END CATCH
```

## 3. ERROR_MESSAGE() - Le message d'erreur

### Description

**ERROR_MESSAGE()** retourne le **message texte** complet décrivant l'erreur. C'est généralement le message le plus utile pour comprendre ce qui s'est passé.

### Type de retour

`NVARCHAR(4000)`

### Exemple de base

```sql
BEGIN TRY
    SELECT 100 / 0;
END TRY
BEGIN CATCH
    PRINT 'Message : ' + ERROR_MESSAGE();
END CATCH
```

**Résultat :**
```
Message : Divide by zero error encountered.
```

### Exemple avec plusieurs langues

Le message d'erreur est affiché dans la langue configurée pour SQL Server.

```sql
BEGIN TRY
    -- Tentative d'insertion avec violation de clé
    INSERT INTO Clients (ClientID, Nom)
    VALUES (1, 'Dupont');

    INSERT INTO Clients (ClientID, Nom)
    VALUES (1, 'Martin');  -- Même ID !
END TRY
BEGIN CATCH
    PRINT ERROR_MESSAGE();
END CATCH
```

**Résultat possible (en français) :**
```
Violation de la contrainte PRIMARY KEY 'PK_Clients_ClientID'. Impossible d'insérer une clé en double dans l'objet 'dbo.Clients'.
```

**Résultat possible (en anglais) :**
```
Violation of PRIMARY KEY constraint 'PK_Clients_ClientID'. Cannot insert duplicate key in object 'dbo.Clients'.
```

### Utilisation pour le logging

```sql
BEGIN TRY
    -- Opération complexe
    UPDATE Produits
    SET Prix = Prix * 1.1
    WHERE CategorieID = 999;  -- Catégorie inexistante
END TRY
BEGIN CATCH
    -- Logger avec message complet
    INSERT INTO LogErreurs (
        DateErreur,
        MessageComplet,
        Utilisateur
    )
    VALUES (
        GETDATE(),
        ERROR_MESSAGE(),
        SYSTEM_USER
    );

    PRINT 'Erreur enregistrée dans les logs';
END CATCH
```

### Formater le message pour l'utilisateur

```sql
BEGIN TRY
    -- Conversion impossible
    DECLARE @Age INT = CAST('vingt-cinq' AS INT);
END TRY
BEGIN CATCH
    DECLARE @MsgErreur NVARCHAR(4000) = ERROR_MESSAGE();

    -- Message technique
    PRINT '═══════════════════════════════════';
    PRINT 'DÉTAILS TECHNIQUES';
    PRINT '═══════════════════════════════════';
    PRINT @MsgErreur;
    PRINT '';

    -- Message utilisateur simplifié
    PRINT '═══════════════════════════════════';
    PRINT 'MESSAGE UTILISATEUR';
    PRINT '═══════════════════════════════════';
    PRINT 'Format de données invalide.';
    PRINT 'Veuillez saisir un nombre entier.';
END CATCH
```

## 4. ERROR_SEVERITY() - La gravité

### Description

**ERROR_SEVERITY()** retourne le **niveau de gravité** de l'erreur. C'est un nombre entre 0 et 25 qui indique à quel point l'erreur est sérieuse.

### Type de retour

`INT`

### Échelle de gravité

| Niveau | Type | Description | Exemple |
|--------|------|-------------|---------|
| 0-10 | **Information** | Messages informatifs, pas vraiment des erreurs | Messages système |
| 11-16 | **Erreur utilisateur** | Erreurs corrigibles par l'utilisateur | Violation de contrainte, division par zéro |
| 17-19 | **Erreur ressource** | Problèmes de ressources | Mémoire insuffisante, disque plein |
| 20-25 | **Erreur fatale** | Erreurs système graves | Corruption de base, perte de connexion |

### Points importants

- Les erreurs de **niveau 11-16** sont les plus courantes
- Les erreurs de **niveau 20-25** sont très graves et peuvent fermer la connexion
- **Seules les erreurs 11+** peuvent être capturées par TRY...CATCH

### Exemple de base

```sql
BEGIN TRY
    SELECT 100 / 0;
END TRY
BEGIN CATCH
    PRINT 'Gravité : ' + CAST(ERROR_SEVERITY() AS VARCHAR);
END CATCH
```

**Résultat :**
```
Gravité : 16
```

### Utilisation pour prioriser les erreurs

```sql
BEGIN TRY
    -- Code risqué
    INSERT INTO Commandes (CommandeID, ClientID, Montant)
    VALUES (1, 999, 100.00);  -- ClientID inexistant
END TRY
BEGIN CATCH
    DECLARE @Severite INT = ERROR_SEVERITY();

    IF @Severite >= 20
    BEGIN
        -- Erreur critique
        PRINT '🔴 ERREUR CRITIQUE - Niveau ' + CAST(@Severite AS VARCHAR);
        PRINT 'Arrêt immédiat requis';
        PRINT 'Contactez immédiatement l''administrateur système';

        -- Envoyer une alerte
        -- EXEC EnvoyerAlerteCritique;
    END
    ELSE IF @Severite >= 17
    BEGIN
        -- Erreur sérieuse
        PRINT '🟠 ERREUR SÉRIEUSE - Niveau ' + CAST(@Severite AS VARCHAR);
        PRINT 'Problème de ressources ou de configuration';
        PRINT 'Intervention administrative nécessaire';
    END
    ELSE
    BEGIN
        -- Erreur standard
        PRINT '🟡 ERREUR STANDARD - Niveau ' + CAST(@Severite AS VARCHAR);
        PRINT 'Erreur corrigible par l''utilisateur';
        PRINT ERROR_MESSAGE();
    END
END CATCH
```

### Exemple avec système de notification

```sql
CREATE PROCEDURE TraiterDonnees
AS
BEGIN
    BEGIN TRY
        -- Traitement de données
        UPDATE GrandeTable SET Valeur = Valeur * 2;
    END TRY
    BEGIN CATCH
        DECLARE @Severite INT = ERROR_SEVERITY();
        DECLARE @Message NVARCHAR(4000) = ERROR_MESSAGE();

        -- Logger dans tous les cas
        INSERT INTO LogErreurs (Severite, Message, DateErreur)
        VALUES (@Severite, @Message, GETDATE());

        -- Notification selon gravité
        IF @Severite >= 17
        BEGIN
            -- Envoyer un email d'alerte
            EXEC msdb.dbo.sp_send_dbmail
                @profile_name = 'AlertProfile',
                @recipients = 'admin@societe.com',
                @subject = 'ALERTE SQL - Erreur grave',
                @body = @Message,
                @importance = 'High';
        END
        ELSE IF @Severite >= 14
        BEGIN
            -- Notification normale
            PRINT 'Une erreur modérée s''est produite';
        END
    END CATCH
END
```

## 5. ERROR_STATE() - L'état

### Description

**ERROR_STATE()** retourne un **code d'état** interne utilisé par SQL Server. Ce nombre aide SQL Server (et Microsoft) à identifier la source exacte d'une erreur lorsque le même numéro d'erreur peut être généré à différents endroits dans le code du moteur.

### Type de retour

`INT` (généralement entre 0 et 127)

### Utilité

L'état est **principalement utile pour Microsoft** lors du support technique. Pour les développeurs, c'est moins critique que les autres fonctions, mais peut être utile pour :
- Distinguer différentes occurrences de la même erreur
- Logger des informations complètes pour le débogage
- Transmettre à Microsoft en cas de bug

### Exemple de base

```sql
BEGIN TRY
    SELECT 100 / 0;
END TRY
BEGIN CATCH
    PRINT 'État : ' + CAST(ERROR_STATE() AS VARCHAR);
END CATCH
```

**Résultat :**
```
État : 1
```

### Exemple avec informations complètes

```sql
BEGIN TRY
    -- Opération qui échoue
    INSERT INTO Employes (EmployeID, Nom)
    VALUES (NULL, 'Dupont');  -- NULL dans PRIMARY KEY
END TRY
BEGIN CATCH
    PRINT '═══════════════════════════════════════════════';
    PRINT 'RAPPORT D''ERREUR COMPLET';
    PRINT '═══════════════════════════════════════════════';
    PRINT 'Numéro    : ' + CAST(ERROR_NUMBER() AS VARCHAR);
    PRINT 'État      : ' + CAST(ERROR_STATE() AS VARCHAR);
    PRINT 'Gravité   : ' + CAST(ERROR_SEVERITY() AS VARCHAR);
    PRINT 'Message   : ' + ERROR_MESSAGE();
    PRINT '═══════════════════════════════════════════════';
END CATCH
```

### Utilisation pour le support technique

```sql
CREATE PROCEDURE RapportErreurComplet
AS
BEGIN
    BEGIN TRY
        -- Code applicatif
        EXEC UneAutreProcedure;
    END TRY
    BEGIN CATCH
        -- Créer un rapport complet pour le support
        DECLARE @Rapport NVARCHAR(MAX);

        SET @Rapport =
            'RAPPORT D''ERREUR POUR LE SUPPORT' + CHAR(13) + CHAR(10) +
            '=================================' + CHAR(13) + CHAR(10) +
            'Date/Heure  : ' + CONVERT(VARCHAR, GETDATE(), 120) + CHAR(13) + CHAR(10) +
            'Serveur     : ' + @@SERVERNAME + CHAR(13) + CHAR(10) +
            'Base        : ' + DB_NAME() + CHAR(13) + CHAR(10) +
            'Utilisateur : ' + SYSTEM_USER + CHAR(13) + CHAR(10) +
            '=================================' + CHAR(13) + CHAR(10) +
            'Err. Numéro : ' + CAST(ERROR_NUMBER() AS VARCHAR) + CHAR(13) + CHAR(10) +
            'Err. État   : ' + CAST(ERROR_STATE() AS VARCHAR) + CHAR(13) + CHAR(10) +
            'Err. Gravité: ' + CAST(ERROR_SEVERITY() AS VARCHAR) + CHAR(13) + CHAR(10) +
            'Err. Ligne  : ' + CAST(ERROR_LINE() AS VARCHAR) + CHAR(13) + CHAR(10) +
            'Err. Proc   : ' + ISNULL(ERROR_PROCEDURE(), 'N/A') + CHAR(13) + CHAR(10) +
            'Message     : ' + ERROR_MESSAGE();

        -- Afficher ou envoyer le rapport
        PRINT @Rapport;

        -- Sauvegarder pour analyse
        INSERT INTO SuportTickets (RapportComplet, DateCreation)
        VALUES (@Rapport, GETDATE());
    END CATCH
END
```

## 6. ERROR_LINE() - Le numéro de ligne

### Description

**ERROR_LINE()** retourne le **numéro de ligne** dans le batch, la procédure ou le trigger où l'erreur s'est produite. C'est extrêmement utile pour le débogage !

### Type de retour

`INT`

### Exemple de base

```sql
-- Ligne 1
BEGIN TRY
    -- Ligne 3
    DECLARE @X INT = 10;
    DECLARE @Y INT = 0;
    DECLARE @Resultat INT = @X / @Y;  -- Ligne 6 - ERREUR ICI !
    PRINT 'Résultat : ' + CAST(@Resultat AS VARCHAR);
END TRY
BEGIN CATCH
    PRINT 'Erreur à la ligne : ' + CAST(ERROR_LINE() AS VARCHAR);
END CATCH
```

**Résultat :**
```
Erreur à la ligne : 6
```

### Exemple dans une procédure stockée

```sql
CREATE PROCEDURE CalculerRemise
    @MontantHT DECIMAL(10,2),
    @TauxRemise DECIMAL(5,2)
AS
BEGIN
    BEGIN TRY
        -- Ligne 6
        DECLARE @Remise DECIMAL(10,2);
        DECLARE @MontantFinal DECIMAL(10,2);

        -- Ligne 10 - Validation
        IF @TauxRemise < 0 OR @TauxRemise > 100
            RAISERROR('Taux de remise invalide', 16, 1);

        -- Ligne 14 - Calculs
        SET @Remise = @MontantHT * (@TauxRemise / 100);
        SET @MontantFinal = @MontantHT - @Remise;

        -- Ligne 18 - Affichage
        PRINT 'Montant HT    : ' + CAST(@MontantHT AS VARCHAR);
        PRINT 'Remise        : ' + CAST(@Remise AS VARCHAR);
        PRINT 'Montant final : ' + CAST(@MontantFinal AS VARCHAR);
    END TRY
    BEGIN CATCH
        PRINT '═══════════════════════════════════════';
        PRINT 'ERREUR DANS CalculerRemise';
        PRINT '═══════════════════════════════════════';
        PRINT 'Ligne     : ' + CAST(ERROR_LINE() AS VARCHAR);
        PRINT 'Message   : ' + ERROR_MESSAGE();
        PRINT '═══════════════════════════════════════';
    END CATCH
END
GO

-- Test avec erreur
EXEC CalculerRemise @MontantHT = 1000, @TauxRemise = 150;
```

**Résultat :**
```
═══════════════════════════════════════
ERREUR DANS CalculerRemise
═══════════════════════════════════════
Ligne     : 12
Message   : Taux de remise invalide
═══════════════════════════════════════
```

### Utilisation pour le débogage avancé

```sql
CREATE PROCEDURE TraitementComplexe
AS
BEGIN
    BEGIN TRY
        -- Section 1 : Validation (lignes 5-10)
        PRINT 'Début validation...';
        IF NOT EXISTS (SELECT 1 FROM Configuration WHERE Active = 1)
            RAISERROR('Configuration invalide', 16, 1);
        PRINT 'Validation OK';

        -- Section 2 : Préparation (lignes 12-17)
        PRINT 'Préparation des données...';
        DECLARE @Compteur INT = 0;
        SELECT @Compteur = COUNT(*) FROM Donnees WHERE Statut = 'Pending';
        PRINT 'Données prêtes : ' + CAST(@Compteur AS VARCHAR);

        -- Section 3 : Traitement (lignes 19-24)
        PRINT 'Traitement en cours...';
        UPDATE Donnees
        SET Statut = 'Processed',
            DateTraitement = GETDATE()
        WHERE Statut = 'Pending';

        -- Section 4 : Finalisation (lignes 26-30)
        PRINT 'Finalisation...';
        INSERT INTO Historique (Type, Date)
        VALUES ('TraitementComplexe', GETDATE());

    END TRY
    BEGIN CATCH
        DECLARE @Ligne INT = ERROR_LINE();

        -- Identifier la section qui a échoué
        PRINT '❌ ERREUR DÉTECTÉE';
        PRINT '';

        IF @Ligne BETWEEN 5 AND 10
            PRINT 'Section échouée : VALIDATION';
        ELSE IF @Ligne BETWEEN 12 AND 17
            PRINT 'Section échouée : PRÉPARATION';
        ELSE IF @Ligne BETWEEN 19 AND 24
            PRINT 'Section échouée : TRAITEMENT';
        ELSE IF @Ligne BETWEEN 26 AND 30
            PRINT 'Section échouée : FINALISATION';

        PRINT 'Ligne exacte : ' + CAST(@Ligne AS VARCHAR);
        PRINT 'Erreur : ' + ERROR_MESSAGE();
    END CATCH
END
```

## 7. ERROR_PROCEDURE() - Le nom de la procédure

### Description

**ERROR_PROCEDURE()** retourne le **nom de la procédure stockée, fonction ou trigger** où l'erreur s'est produite. Retourne NULL si l'erreur s'est produite en dehors d'une procédure/fonction/trigger.

### Type de retour

`NVARCHAR(128)` (ou NULL)

### Exemple dans un batch

```sql
-- Directement dans un batch (pas dans une procédure)
BEGIN TRY
    SELECT 1 / 0;
END TRY
BEGIN CATCH
    PRINT 'Procédure : ' + ISNULL(ERROR_PROCEDURE(), 'N/A (batch direct)');
END CATCH
```

**Résultat :**
```
Procédure : N/A (batch direct)
```

### Exemple dans une procédure

```sql
CREATE PROCEDURE CalculerTotal
    @CommandeID INT
AS
BEGIN
    BEGIN TRY
        -- Calcul qui peut échouer
        DECLARE @Total DECIMAL(10,2);

        SELECT @Total = SUM(Prix * Quantite)
        FROM DetailsCommande
        WHERE CommandeID = @CommandeID;

        -- Division risquée : si la commande n'a aucun détail, COUNT(*) = 0.
        -- ⚠️ Subtilité : @Total vaudrait alors NULL (SUM sur 0 ligne), et « NULL / 0 »
        -- renvoie NULL SANS lever d'erreur (le NULL se propage). Pour déclencher de
        -- façon fiable la division par zéro, on force le numérateur à 0 avec ISNULL :
        -- « 0 / 0 », lui, lève bien l'erreur 8134.
        DECLARE @Moyenne DECIMAL(10,2);
        SELECT @Moyenne = ISNULL(@Total, 0) / COUNT(*)
        FROM DetailsCommande
        WHERE CommandeID = @CommandeID;

        PRINT 'Moyenne : ' + CAST(@Moyenne AS VARCHAR);
    END TRY
    BEGIN CATCH
        PRINT 'Erreur dans : ' + ERROR_PROCEDURE();
        PRINT 'Ligne       : ' + CAST(ERROR_LINE() AS VARCHAR);
        PRINT 'Message     : ' + ERROR_MESSAGE();
    END CATCH
END
GO

-- Exécution avec une commande sans détails (division par zéro)
EXEC CalculerTotal @CommandeID = 999;
```

**Résultat :**
```
Erreur dans : CalculerTotal
Ligne       : 16
Message     : Divide by zero error encountered.
```

### Utilisation avec des procédures imbriquées

```sql
-- Procédure niveau 1
CREATE PROCEDURE Proc1
AS
BEGIN
    BEGIN TRY
        EXEC Proc2;  -- Appel de Proc2
    END TRY
    BEGIN CATCH
        PRINT 'Erreur capturée dans Proc1';
        PRINT 'Origine : ' + ISNULL(ERROR_PROCEDURE(), 'N/A');

        -- Relancer l'erreur
        THROW;
    END CATCH
END
GO

-- Procédure niveau 2
CREATE PROCEDURE Proc2
AS
BEGIN
    BEGIN TRY
        EXEC Proc3;  -- Appel de Proc3
    END TRY
    BEGIN CATCH
        PRINT 'Erreur capturée dans Proc2';
        PRINT 'Origine : ' + ISNULL(ERROR_PROCEDURE(), 'N/A');

        -- Relancer l'erreur
        THROW;
    END CATCH
END
GO

-- Procédure niveau 3 (où l'erreur se produit vraiment)
CREATE PROCEDURE Proc3
AS
BEGIN
    SELECT 1 / 0;  -- Erreur ici !
END
GO

-- Test
BEGIN TRY
    EXEC Proc1;
END TRY
BEGIN CATCH
    PRINT '';
    PRINT 'Erreur finale capturée';
    PRINT 'Procédure source : ' + ERROR_PROCEDURE();
END CATCH
```

**Résultat :**
```
Erreur capturée dans Proc2
Origine : Proc3
Erreur capturée dans Proc1
Origine : Proc3

Erreur finale capturée
Procédure source : Proc3
```

### Exemple de traçabilité complète

```sql
CREATE PROCEDURE InsererClient
    @Nom VARCHAR(100),
    @Email VARCHAR(100)
AS
BEGIN
    BEGIN TRY
        -- Validation
        IF @Email NOT LIKE '%@%'
            RAISERROR('Email invalide', 16, 1);

        -- Insertion
        INSERT INTO Clients (Nom, Email, DateCreation)
        VALUES (@Nom, @Email, GETDATE());

        PRINT 'Client créé avec succès';
    END TRY
    BEGIN CATCH
        -- Log complet avec contexte
        INSERT INTO LogErreurs (
            DateErreur,
            NomProcedure,
            NumeroLigne,
            NumeroErreur,
            MessageErreur,
            Contexte
        )
        VALUES (
            GETDATE(),
            ERROR_PROCEDURE(),
            ERROR_LINE(),
            ERROR_NUMBER(),
            ERROR_MESSAGE(),
            'Paramètres: Nom=' + @Nom + ', Email=' + @Email
        );

        -- Message utilisateur
        PRINT 'Erreur lors de la création du client';
        PRINT 'Référence log : Procédure ' + ERROR_PROCEDURE() +
              ', ligne ' + CAST(ERROR_LINE() AS VARCHAR);
    END CATCH
END
```

## 8. Utiliser toutes les fonctions ensemble

### Table de log complète

Créons d'abord une table pour stocker toutes les informations d'erreur :

```sql
CREATE TABLE LogErreursComplet (
    LogID INT IDENTITY(1,1) PRIMARY KEY,
    DateErreur DATETIME DEFAULT GETDATE(),
    NumeroErreur INT,
    MessageErreur NVARCHAR(4000),
    Severite INT,
    Etat INT,
    NumeroLigne INT,
    NomProcedure NVARCHAR(128),
    Utilisateur NVARCHAR(128) DEFAULT SYSTEM_USER,
    BaseDonnees NVARCHAR(128) DEFAULT DB_NAME(),
    Serveur NVARCHAR(128) DEFAULT @@SERVERNAME
);
```

### Procédure de logging centralisée

```sql
CREATE PROCEDURE LoggerErreur
AS
BEGIN
    SET NOCOUNT ON;

    -- Insérer toutes les informations d'erreur
    INSERT INTO LogErreursComplet (
        NumeroErreur,
        MessageErreur,
        Severite,
        Etat,
        NumeroLigne,
        NomProcedure
    )
    VALUES (
        ERROR_NUMBER(),
        ERROR_MESSAGE(),
        ERROR_SEVERITY(),
        ERROR_STATE(),
        ERROR_LINE(),
        ERROR_PROCEDURE()
    );

    -- Remarque : si l'on veut renvoyer l'ID du log créé, on l'expose via un paramètre
    -- OUTPUT (ex. @LogID INT OUTPUT = SCOPE_IDENTITY()). On évite RETURN, réservé aux
    -- codes d'état entiers — SCOPE_IDENTITY() renvoie d'ailleurs un NUMERIC (voir 5.5.3).
END
GO
```

### Utilisation dans une procédure

```sql
CREATE PROCEDURE TraiterCommande
    @CommandeID INT
AS
BEGIN
    BEGIN TRY
        -- Traitement
        UPDATE Commandes
        SET Statut = 'Traité',
            DateTraitement = GETDATE()
        WHERE CommandeID = @CommandeID;

        IF @@ROWCOUNT = 0
            RAISERROR('Commande introuvable', 16, 1);

        PRINT 'Commande traitée avec succès';

    END TRY
    BEGIN CATCH
        -- Logger l'erreur
        EXEC LoggerErreur;

        -- Afficher un résumé
        PRINT '═══════════════════════════════════════════';
        PRINT 'ERREUR LORS DU TRAITEMENT';
        PRINT '═══════════════════════════════════════════';
        PRINT 'Procédure : ' + ISNULL(ERROR_PROCEDURE(), 'N/A');
        PRINT 'Ligne     : ' + CAST(ERROR_LINE() AS VARCHAR);
        PRINT 'Erreur #  : ' + CAST(ERROR_NUMBER() AS VARCHAR);
        PRINT 'Gravité   : ' + CAST(ERROR_SEVERITY() AS VARCHAR);
        PRINT 'Message   : ' + ERROR_MESSAGE();
        PRINT '═══════════════════════════════════════════';
        PRINT 'L''erreur a été enregistrée dans les logs';

        -- Relancer si erreur grave
        IF ERROR_SEVERITY() >= 16
            THROW;

    END CATCH
END
```

## 9. Exemples pratiques avancés

### Exemple 1 : Système de retry avec log

```sql
CREATE PROCEDURE TraiterAvecRetry
    @CommandeID INT,
    @MaxTentatives INT = 3
AS
BEGIN
    DECLARE @Tentative INT = 1;
    DECLARE @Succes BIT = 0;

    WHILE @Tentative <= @MaxTentatives AND @Succes = 0
    BEGIN
        BEGIN TRY
            PRINT 'Tentative ' + CAST(@Tentative AS VARCHAR) + '/' +
                  CAST(@MaxTentatives AS VARCHAR);

            -- Traitement qui peut échouer
            UPDATE Commandes
            SET Statut = 'Traité'
            WHERE CommandeID = @CommandeID;

            SET @Succes = 1;
            PRINT 'Succès !';

        END TRY
        BEGIN CATCH
            -- Logger la tentative échouée
            INSERT INTO LogErreursComplet (
                NumeroErreur, MessageErreur, Severite,
                NumeroLigne, NomProcedure
            )
            VALUES (
                ERROR_NUMBER(), ERROR_MESSAGE(), ERROR_SEVERITY(),
                ERROR_LINE(), ERROR_PROCEDURE()
            );

            PRINT 'Échec - Erreur : ' + ERROR_MESSAGE();

            -- Si dernière tentative, abandonner
            IF @Tentative = @MaxTentatives
            BEGIN
                PRINT 'Nombre maximum de tentatives atteint';
                THROW;
            END

            -- Attendre avant de réessayer
            WAITFOR DELAY '00:00:02';
        END CATCH

        SET @Tentative = @Tentative + 1;
    END
END
```

```sql
    MAX(DateErreur) AS DerniereOccurrence,
```

## 10. Bonnes pratiques

### ✅ À FAIRE

1. **Toujours capturer TOUTES les informations d'erreur**
   ```sql
   BEGIN CATCH
       DECLARE @ErrNum INT = ERROR_NUMBER();
       DECLARE @ErrMsg NVARCHAR(4000) = ERROR_MESSAGE();
       DECLARE @ErrSev INT = ERROR_SEVERITY();
       DECLARE @ErrState INT = ERROR_STATE();
       DECLARE @ErrLine INT = ERROR_LINE();
       DECLARE @ErrProc NVARCHAR(128) = ERROR_PROCEDURE();

       -- Utiliser ces variables
   END CATCH
   ```

2. **Logger les erreurs dans une table**
   - Ne vous fiez pas uniquement à PRINT
   - Conservez un historique permanent

3. **Utiliser ERROR_PROCEDURE() et ERROR_LINE() pour le débogage**
   - Identifiez rapidement où se trouve le problème

4. **Créer des messages d'erreur clairs**
   - Message technique pour les logs
   - Message simplifié pour les utilisateurs

5. **Utiliser ERROR_SEVERITY() pour prioriser**
   - Réagir différemment selon la gravité

### ❌ À ÉVITER

1. **N'utilisez PAS ces fonctions en dehors de CATCH**
   ```sql
   -- ❌ Ne fonctionne pas
   SELECT ERROR_MESSAGE();  -- Retourne NULL
   ```

2. **Ne pas ignorer ERROR_PROCEDURE()**
   - Même si c'est NULL, c'est une information utile

3. **Ne pas oublier d'utiliser ISNULL() avec ERROR_PROCEDURE()**
   ```sql
   -- ❌ Peut causer des erreurs de concaténation
   PRINT 'Proc: ' + ERROR_PROCEDURE();

   -- ✅ Sûr
   PRINT 'Proc: ' + ISNULL(ERROR_PROCEDURE(), 'N/A');
   ```

4. **Ne pas sous-estimer ERROR_STATE()**
   - Même si vous ne l'utilisez pas souvent, loggez-le

## Résumé

- Les **six fonctions d'erreur** fournissent des informations détaillées sur les erreurs dans un bloc CATCH
- **ERROR_NUMBER()** identifie le type d'erreur (8134 = division par zéro, 2627 = clé primaire, etc.)
- **ERROR_MESSAGE()** donne une description textuelle de l'erreur
- **ERROR_SEVERITY()** indique la gravité (11-16 = utilisateur, 17-19 = ressource, 20-25 = fatal)
- **ERROR_STATE()** fournit un code d'état interne (surtout utile pour Microsoft)
- **ERROR_LINE()** localise exactement où l'erreur s'est produite (essentiel pour le débogage)
- **ERROR_PROCEDURE()** identifie la procédure/fonction/trigger concernée (NULL si dans un batch)
- Ces fonctions ne fonctionnent **QUE dans un bloc CATCH**
- Utilisez-les pour créer des **systèmes de logging** complets et informatifs
- Combinez-les pour un **débogage efficace** et une **gestion d'erreurs professionnelle**

Les fonctions d'erreur sont vos meilleurs alliés pour comprendre et gérer les problèmes dans vos applications T-SQL. Elles transforment des erreurs cryptiques en informations exploitables pour améliorer la qualité et la fiabilité de votre code.
