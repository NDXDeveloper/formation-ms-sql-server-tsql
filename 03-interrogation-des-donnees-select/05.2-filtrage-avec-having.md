# 3.5.2 Filtrage des groupes avec HAVING

## Introduction

Dans la section précédente, nous avons appris à regrouper des données avec `GROUP BY`. Maintenant, nous allons découvrir comment **filtrer ces groupes** avec la clause `HAVING`.

La clause `HAVING` est l'équivalent de `WHERE`, mais pour les groupes. Elle permet de ne conserver que les groupes qui répondent à certains critères **après** l'agrégation.

## Pourquoi HAVING ? La différence avec WHERE

### Le problème

Imaginez que vous voulez trouver les catégories de produits qui contiennent **plus de 5 produits**. Vous pourriez penser à écrire :

```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
WHERE COUNT(*) > 5  -- ❌ CECI NE FONCTIONNE PAS
GROUP BY Categorie;
```

**Cette requête génère une erreur !** Pourquoi ?

Parce que `WHERE` filtre les lignes **avant** le regroupement, mais `COUNT(*)` est calculé **pendant** le regroupement. On ne peut pas utiliser une fonction d'agrégation dans `WHERE`.

### La solution : HAVING

C'est exactement pour résoudre ce problème que `HAVING` existe :

```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie
HAVING COUNT(*) > 5;  -- ✅ CORRECT
```

`HAVING` filtre les groupes **après** que les agrégations aient été calculées.

## WHERE vs HAVING : Comprendre la différence

| Aspect | WHERE | HAVING |
|--------|-------|--------|
| **Filtre** | Les lignes individuelles | Les groupes après agrégation |
| **Moment d'exécution** | AVANT le regroupement | APRÈS le regroupement |
| **Peut utiliser des fonctions d'agrégation** | ❌ NON | ✅ OUI |
| **Agit sur** | Colonnes de la table | Résultats des agrégations |

### Analogie simple

Imaginez que vous triez des cartes par couleur (GROUP BY) :

- **WHERE** : Vous retirez certaines cartes **avant** de les trier par couleur
  - Exemple : "Ne prends pas les cartes abîmées"

- **HAVING** : Vous éliminez certains groupes **après** avoir trié
  - Exemple : "Ne garde que les couleurs qui ont plus de 10 cartes"

## Syntaxe de base

```sql
SELECT colonne_de_groupement, FONCTION_AGREGATION(colonne)
FROM nom_table
GROUP BY colonne_de_groupement
HAVING condition_sur_agregation;
```

## Exemples progressifs

### Exemple 1 : Catégories avec plus de 2 produits

Reprenons notre table `Produits` :

| ProduitID | NomProduit | Categorie | Prix |
|-----------|------------|-----------|------|
| 1 | Laptop | Informatique | 899 |
| 2 | Souris | Informatique | 25 |
| 3 | Chaise | Mobilier | 150 |
| 4 | Bureau | Mobilier | 300 |
| 5 | Clavier | Informatique | 45 |
| 6 | Lampe | Mobilier | 75 |

**Sans HAVING :**
```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie;
```

**Résultat :**

| Categorie | NombreProduits |
|-----------|----------------|
| Informatique | 3 |
| Mobilier | 3 |

**Avec HAVING :**
```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie
HAVING COUNT(*) > 2;
```

**Résultat :**

| Categorie | NombreProduits |
|-----------|----------------|
| Informatique | 3 |
| Mobilier | 3 |

Dans cet exemple, les deux catégories ont plus de 2 produits, donc les deux sont conservées.

### Exemple 2 : Catégories avec un prix moyen supérieur à 100

**Requête :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits,
    AVG(Prix) AS PrixMoyen
FROM Produits
GROUP BY Categorie
HAVING AVG(Prix) > 100;
```

**Étapes d'exécution :**
1. Regroupement par `Categorie`
2. Calcul du prix moyen pour chaque catégorie
   - Informatique : (899 + 25 + 45) / 3 = 323
   - Mobilier : (150 + 300 + 75) / 3 = 175
3. Filtrage avec `HAVING` : ne garde que les catégories où le prix moyen > 100

**Résultat :**

| Categorie | NombreProduits | PrixMoyen |
|-----------|----------------|-----------|
| Informatique | 3 | 323.00 |
| Mobilier | 3 | 175.00 |

Les deux catégories sont conservées car leurs prix moyens dépassent 100.

### Exemple 3 : Vendeurs avec un chiffre d'affaires supérieur à 2000

Table `Ventes` :

| VenteID | Vendeur | Montant |
|---------|---------|---------|
| 1 | Alice | 1000 |
| 2 | Alice | 1500 |
| 3 | Alice | 800 |
| 4 | Bob | 1200 |
| 5 | Bob | 600 |
| 6 | Charlie | 3000 |

**Requête :**
```sql
SELECT
    Vendeur,
    COUNT(*) AS NombreVentes,
    SUM(Montant) AS ChiffreAffaires
FROM Ventes
GROUP BY Vendeur
HAVING SUM(Montant) > 2000;
```

**Résultat :**

| Vendeur | NombreVentes | ChiffreAffaires |
|---------|--------------|-----------------|
| Alice | 3 | 3300 |
| Charlie | 1 | 3000 |

**Explication :**
- Alice : 1000 + 1500 + 800 = 3300 ✅ (> 2000)
- Bob : 1200 + 600 = 1800 ❌ (< 2000, groupe éliminé)
- Charlie : 3000 ✅ (> 2000)

## Utiliser plusieurs conditions dans HAVING

Vous pouvez combiner plusieurs conditions avec `AND` et `OR`, comme dans `WHERE`.

### Exemple 4 : Conditions multiples

**Requête :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits,
    AVG(Prix) AS PrixMoyen,
    SUM(Prix) AS PrixTotal
FROM Produits
GROUP BY Categorie
HAVING COUNT(*) >= 2 AND AVG(Prix) < 300;
```

**Explication :**
- Ne garde que les catégories qui ont au moins 2 produits **ET** un prix moyen inférieur à 300
- Les deux conditions doivent être vraies pour qu'un groupe soit conservé

### Exemple 5 : Utiliser OR

**Requête :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits,
    SUM(Prix) AS PrixTotal
FROM Produits
GROUP BY Categorie
HAVING COUNT(*) > 5 OR SUM(Prix) > 1000;
```

**Explication :**
- Garde les catégories qui ont plus de 5 produits **OU** un prix total supérieur à 1000
- Une seule des deux conditions suffit pour qu'un groupe soit conservé

## Combiner WHERE et HAVING

Vous pouvez utiliser `WHERE` et `HAVING` dans la même requête. C'est même très courant et très puissant !

### Exemple 6 : WHERE puis HAVING

Table `Commandes` :

| CommandeID | Client | Montant | Statut |
|------------|--------|---------|--------|
| 1 | Alice | 500 | Validée |
| 2 | Alice | 300 | Annulée |
| 3 | Alice | 800 | Validée |
| 4 | Bob | 1000 | Validée |
| 5 | Bob | 200 | Validée |
| 6 | Charlie | 600 | Annulée |
| 7 | Charlie | 1500 | Validée |

**Requête :**
```sql
SELECT
    Client,
    COUNT(*) AS NombreCommandes,
    SUM(Montant) AS TotalAchats
FROM Commandes
WHERE Statut = 'Validée'
GROUP BY Client
HAVING SUM(Montant) > 1000;
```

**Ordre d'exécution :**
1. **WHERE** filtre d'abord les commandes validées (élimine les annulées)
2. **GROUP BY** regroupe par client
3. **HAVING** ne garde que les clients dont le total des achats validés > 1000

**Résultat après WHERE (lignes considérées) :**

| CommandeID | Client | Montant | Statut |
|------------|--------|---------|--------|
| 1 | Alice | 500 | Validée |
| 3 | Alice | 800 | Validée |
| 4 | Bob | 1000 | Validée |
| 5 | Bob | 200 | Validée |
| 7 | Charlie | 1500 | Validée |

**Résultat après GROUP BY et HAVING :**

| Client | NombreCommandes | TotalAchats |
|--------|-----------------|-------------|
| Alice | 2 | 1300 |
| Bob | 2 | 1200 |
| Charlie | 1 | 1500 |

Tous les clients dépassent 1000€ en commandes validées, donc tous sont conservés.

## Ordre logique d'exécution complet

Voici l'ordre dans lequel SQL exécute une requête complète :

```
1. FROM       → Identifier la table source
2. WHERE      → Filtrer les lignes individuelles
3. GROUP BY   → Créer les groupes
4. HAVING     → Filtrer les groupes
5. SELECT     → Calculer les expressions et les agrégations
6. ORDER BY   → Trier les résultats finaux
```

### Exemple illustrant l'ordre complet

```sql
SELECT
    Categorie,
    AVG(Prix) AS PrixMoyen
FROM Produits
WHERE Prix > 50
GROUP BY Categorie
HAVING AVG(Prix) > 200
ORDER BY PrixMoyen DESC;
```

**Étapes :**
1. **FROM** : SQL prend la table `Produits`
2. **WHERE** : Ne garde que les produits avec `Prix > 50`
3. **GROUP BY** : Regroupe les produits restants par `Categorie`
4. **HAVING** : Ne garde que les catégories avec `AVG(Prix) > 200`
5. **SELECT** : Calcule les colonnes à afficher (dont l'alias `PrixMoyen`)
6. **ORDER BY** : Trie les résultats par prix moyen décroissant

## Utiliser des alias dans HAVING

⚠️ **Attention à une subtilité importante !**

Contrairement à `ORDER BY`, la clause `HAVING` **ne peut généralement pas** utiliser les alias définis dans `SELECT`, car `HAVING` s'exécute **avant** `SELECT` dans l'ordre logique.

❌ **Ne fonctionne pas en SQL Server :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie
HAVING NombreProduits > 5;  -- ❌ Erreur : « Invalid column name 'NombreProduits' »
```

✅ **CORRECT (recommandé) :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie
HAVING COUNT(*) > 5;  -- Répéter la fonction d'agrégation
```

**Note :** En SQL Server, les alias définis dans `SELECT` **ne sont pas utilisables** dans `HAVING` (ni dans `WHERE`, ni dans `GROUP BY`) : vous obtiendrez l'erreur *« Invalid column name »*. Certains SGBD comme MySQL le tolèrent, mais ce n'est pas le standard SQL. **Répétez donc toujours la fonction d'agrégation** dans le `HAVING`.

## Cas d'usage courants

### 1. Trouver les clients fidèles

```sql
SELECT
    ClientID,
    COUNT(*) AS NombreCommandes,
    SUM(Montant) AS TotalDepense
FROM Commandes
GROUP BY ClientID
HAVING COUNT(*) >= 10;
```

Trouve les clients qui ont passé au moins 10 commandes.

### 2. Identifier les produits populaires

```sql
SELECT
    ProduitID,
    COUNT(*) AS NombreVentes
FROM LignesCommande
GROUP BY ProduitID
HAVING COUNT(*) > 100
ORDER BY NombreVentes DESC;
```

Trouve les produits vendus plus de 100 fois, triés par popularité.

### 3. Analyser les départements sous-effectifs

```sql
SELECT
    Departement,
    COUNT(*) AS NombreEmployes,
    AVG(Salaire) AS SalaireMoyen
FROM Employes
GROUP BY Departement
HAVING COUNT(*) < 5;
```

Identifie les départements ayant moins de 5 employés.

### 4. Trouver les mois avec ventes exceptionnelles

```sql
SELECT
    YEAR(DateVente) AS Annee,
    MONTH(DateVente) AS Mois,
    SUM(Montant) AS ChiffreAffaires
FROM Ventes
GROUP BY YEAR(DateVente), MONTH(DateVente)
HAVING SUM(Montant) > 50000
ORDER BY Annee, Mois;
```

Identifie les mois où le chiffre d'affaires dépasse 50 000.

### 5. Détecter les anomalies (écart de prix important)

```sql
SELECT
    Categorie,
    MIN(Prix) AS PrixMin,
    MAX(Prix) AS PrixMax,
    MAX(Prix) - MIN(Prix) AS Ecart
FROM Produits
GROUP BY Categorie
HAVING MAX(Prix) - MIN(Prix) > 500;
```

Trouve les catégories où l'écart entre le produit le moins cher et le plus cher dépasse 500.

## Erreurs courantes à éviter

### Erreur 1 : Utiliser HAVING sans GROUP BY

❌ **INCORRECT :**
```sql
SELECT COUNT(*) AS Total
FROM Produits
HAVING COUNT(*) > 100;
```

**Explication :** Techniquement, cette requête peut fonctionner (SQL considère toutes les lignes comme un seul groupe implicite), mais c'est déroutant et inutile. Si vous ne groupez pas, utilisez simplement `WHERE`.

✅ **MIEUX :**
```sql
SELECT COUNT(*) AS Total
FROM Produits;
-- Puis vérifiez le résultat dans votre application
```

### Erreur 2 : Confondre WHERE et HAVING

❌ **INCORRECT :**
```sql
SELECT Categorie, AVG(Prix) AS PrixMoyen
FROM Produits
HAVING Prix > 100  -- Prix est une colonne, pas une agrégation
GROUP BY Categorie;
```

✅ **CORRECT :**
```sql
SELECT Categorie, AVG(Prix) AS PrixMoyen
FROM Produits
WHERE Prix > 100  -- Filtrer les lignes AVANT le regroupement
GROUP BY Categorie;
```

### Erreur 3 : Filtrer sur une colonne non agrégée dans HAVING

❌ **INCORRECT :**
```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
GROUP BY Categorie
HAVING Categorie = 'Informatique';  -- Pas optimal
```

✅ **MIEUX (utiliser WHERE) :**
```sql
SELECT Categorie, COUNT(*) AS NombreProduits
FROM Produits
WHERE Categorie = 'Informatique'  -- Plus efficace
GROUP BY Categorie;
```

**Pourquoi ?** `WHERE` filtre avant le regroupement, ce qui est plus efficace. N'utilisez `HAVING` que pour des conditions sur des agrégations.

## Règle d'or : Quand utiliser WHERE vs HAVING ?

### Utilisez WHERE quand :
- Vous filtrez sur des **colonnes individuelles** de la table
- Le filtre porte sur les **lignes avant regroupement**
- Vous **n'utilisez pas** de fonctions d'agrégation dans la condition

**Exemples :**
```sql
WHERE Prix > 100
WHERE Categorie = 'Informatique'
WHERE DateVente >= '2024-01-01'
```

### Utilisez HAVING quand :
- Vous filtrez sur des **résultats d'agrégation**
- Le filtre porte sur les **groupes après regroupement**
- Vous **utilisez** des fonctions d'agrégation dans la condition

**Exemples :**
```sql
HAVING COUNT(*) > 5
HAVING AVG(Prix) > 200
HAVING SUM(Montant) > 10000
```

## Récapitulatif

La clause `HAVING` permet de :
- **Filtrer les groupes** après l'agrégation
- **Utiliser des fonctions d'agrégation** dans les conditions de filtrage
- **Compléter GROUP BY** pour des analyses plus précises

**Points clés à retenir :**
- `WHERE` filtre les lignes **avant** le regroupement
- `HAVING` filtre les groupes **après** l'agrégation
- `HAVING` peut utiliser des fonctions d'agrégation, `WHERE` ne le peut pas
- Vous pouvez combiner `WHERE` et `HAVING` dans la même requête
- Ordre d'exécution : `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`

## Exemples récapitulatifs complets

### Analyse des ventes par région
```sql
SELECT
    Region,
    COUNT(*) AS NombreVentes,
    SUM(Montant) AS ChiffreAffaires,
    AVG(Montant) AS PanierMoyen
FROM Ventes
WHERE YEAR(DateVente) = 2024
GROUP BY Region
HAVING SUM(Montant) > 100000
ORDER BY ChiffreAffaires DESC;
```

### Identification des catégories rentables
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits,
    AVG(Prix) AS PrixMoyen,
    MIN(Prix) AS PrixMin,
    MAX(Prix) AS PrixMax
FROM Produits
WHERE EstActif = 1
GROUP BY Categorie
HAVING COUNT(*) >= 5 AND AVG(Prix) > 100
ORDER BY PrixMoyen DESC;
```

### Recherche de clients à risque (peu d'achats récents)
```sql
SELECT
    ClientID,
    COUNT(*) AS NombreCommandes,
    MAX(DateCommande) AS DerniereCommande
FROM Commandes
WHERE DateCommande >= DATEADD(YEAR, -1, GETDATE())
GROUP BY ClientID
HAVING COUNT(*) < 3
ORDER BY DerniereCommande;
```
