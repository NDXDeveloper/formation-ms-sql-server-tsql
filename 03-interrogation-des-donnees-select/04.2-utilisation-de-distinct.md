# 3.4.2 Utilisation de DISTINCT

## Introduction

Lorsque vous interrogez une base de données, il arrive fréquemment que certaines valeurs apparaissent **plusieurs fois** dans les résultats. Par exemple :
- Une liste de villes où habitent vos clients (Paris peut apparaître 500 fois)
- Les catégories de produits vendus (la même catégorie apparaît pour chaque produit)
- Les années de commandes dans votre historique

Parfois, vous ne voulez pas voir ces **doublons** : vous voulez simplement connaître les **valeurs uniques**. C'est précisément le rôle du mot-clé `DISTINCT`.

`DISTINCT` est un modificateur qui élimine les lignes en double dans vos résultats, ne conservant que les **valeurs distinctes** (uniques).

## Qu'est-ce que DISTINCT ?

**DISTINCT** (qui signifie "distinct" ou "différent" en français) est un mot-clé SQL qui :

1. **Examine** toutes les lignes retournées par votre requête
2. **Identifie** les lignes qui sont identiques
3. **Supprime** les doublons
4. **Ne garde** qu'une seule occurrence de chaque valeur unique

**Analogie :** Imaginez que vous avez une pile de cartes de visite avec des doublons. `DISTINCT` parcourt la pile et ne garde qu'un seul exemplaire de chaque carte unique.

## Syntaxe de base

```sql
SELECT DISTINCT colonne1, colonne2, ...
FROM table;
```

Le mot-clé `DISTINCT` se place juste après `SELECT` et **avant** les noms de colonnes.

## DISTINCT sur une seule colonne

### Exemple de base

Imaginons une table `Commandes` :

| CommandeID | ClientID | Ville |
|------------|----------|-------|
| 1 | 101 | Paris |
| 2 | 102 | Lyon |
| 3 | 103 | Paris |
| 4 | 104 | Marseille |
| 5 | 105 | Lyon |
| 6 | 106 | Paris |

**Sans DISTINCT :**
```sql
SELECT Ville
FROM Commandes;
```

**Résultat :**
```
Ville
---------
Paris
Lyon
Paris
Marseille
Lyon
Paris
```

6 lignes sont retournées, avec des doublons.

**Avec DISTINCT :**
```sql
SELECT DISTINCT Ville
FROM Commandes;
```

**Résultat :**
```
Ville
---------
Lyon
Marseille
Paris
```

Seulement 3 lignes sont retournées : les valeurs uniques.

### Exemple pratique : Liste des pays de clients

```sql
SELECT DISTINCT Pays
FROM Clients
ORDER BY Pays;
```

**Résultat possible :**
```
Pays
-----------
Allemagne
Belgique
France
Italie
Suisse
```

Au lieu d'avoir 10 000 lignes (une pour chaque client), vous obtenez uniquement la liste des pays où vous avez des clients.

### Utilité

`DISTINCT` est particulièrement utile pour :
- Créer des **listes de sélection** (dropdowns) dans les applications
- Obtenir un **aperçu des valeurs possibles** dans une colonne
- **Compter le nombre de valeurs uniques** (nous le verrons avec COUNT)
- **Éliminer les doublons** dans des rapports

## DISTINCT sur plusieurs colonnes

Lorsque vous utilisez `DISTINCT` avec **plusieurs colonnes**, SQL considère qu'une ligne est en double **uniquement si toutes les colonnes sont identiques**.

### Exemple : Table Commandes

| CommandeID | ClientID | Ville | Pays |
|------------|----------|-------|------|
| 1 | 101 | Paris | France |
| 2 | 102 | Lyon | France |
| 3 | 103 | Paris | France |
| 4 | 104 | Paris | Belgique |
| 5 | 105 | Lyon | France |

**Requête avec deux colonnes :**
```sql
SELECT DISTINCT Ville, Pays
FROM Commandes;
```

**Résultat :**
```
Ville    Pays
------   --------
Lyon     France
Paris    Belgique
Paris    France
```

**Explication :**
- `Lyon, France` apparaît 2 fois dans la table → 1 fois dans le résultat
- `Paris, France` apparaît 2 fois → 1 fois dans le résultat
- `Paris, Belgique` apparaît 1 fois → 1 fois dans le résultat

`Paris` apparaît 2 fois dans le résultat car associé à **deux pays différents**. Les **combinaisons** `(Paris, France)` et `(Paris, Belgique)` sont considérées comme distinctes.

### Attention à l'ordre des colonnes

L'ordre des colonnes **n'affecte pas** le résultat de `DISTINCT`, mais peut affecter l'ordre d'affichage :

```sql
SELECT DISTINCT Pays, Ville
FROM Commandes;
```

**Résultat :**
```
Pays        Ville
--------    ------
Belgique    Paris
France      Lyon
France      Paris
```

Les mêmes combinaisons uniques sont retournées, mais dans un ordre différent.

## DISTINCT avec COUNT()

Une des utilisations les plus courantes de `DISTINCT` est avec la fonction `COUNT()` pour compter le **nombre de valeurs uniques**.

### COUNT(DISTINCT colonne)

Nous avons déjà vu cette fonction dans la section précédente, mais voyons-la en détail :

```sql
SELECT COUNT(DISTINCT Ville) AS NombreVillesUniques
FROM Clients;
```

**Résultat possible :**
```
NombreVillesUniques
-------------------
47
```

**Explication :** Cette requête compte combien de villes **différentes** apparaissent dans la table Clients, même si certaines villes ont des centaines de clients.

### Comparaison COUNT(*) vs COUNT(DISTINCT)

```sql
-- Nombre total de commandes
SELECT COUNT(*) AS TotalCommandes
FROM Commandes;
-- Résultat : 1532

-- Nombre de clients ayant passé au moins une commande
SELECT COUNT(DISTINCT ClientID) AS ClientsUniques
FROM Commandes;
-- Résultat : 428
```

**Interprétation :** 1532 commandes ont été passées par 428 clients différents. Certains clients ont donc passé plusieurs commandes.

### Calculer la moyenne de commandes par client

```sql
SELECT
    COUNT(*) AS TotalCommandes,
    COUNT(DISTINCT ClientID) AS ClientsUniques,
    CAST(COUNT(*) AS FLOAT) / COUNT(DISTINCT ClientID) AS CommandesParClient
FROM Commandes;
```

**Résultat possible :**
```
TotalCommandes  ClientsUniques  CommandesParClient
--------------  --------------  ------------------
1532            428             3.58
```

**Interprétation :** En moyenne, chaque client a passé 3,58 commandes.

## DISTINCT avec d'autres clauses SQL

### DISTINCT avec WHERE

Vous pouvez filtrer les données **avant** d'appliquer DISTINCT :

```sql
SELECT DISTINCT Ville
FROM Clients
WHERE Pays = 'France'
ORDER BY Ville;
```

**Ordre d'exécution :**
1. **FROM** : Identifier la table Clients
2. **WHERE** : Filtrer uniquement les clients français
3. **SELECT DISTINCT** : Éliminer les doublons dans les villes
4. **ORDER BY** : Trier alphabétiquement

### DISTINCT avec JOIN

```sql
SELECT DISTINCT c.Categorie
FROM Produits p
INNER JOIN Categories c ON p.CategorieID = c.CategorieID
WHERE p.EnStock = 1;
```

Cette requête retourne la liste des catégories qui ont au moins un produit en stock.

### DISTINCT avec ORDER BY

```sql
SELECT DISTINCT Ville, Pays
FROM Clients
ORDER BY Pays, Ville;
```

Vous pouvez trier les résultats après avoir éliminé les doublons.

## DISTINCT vs GROUP BY

`DISTINCT` et `GROUP BY` peuvent parfois donner des résultats similaires, mais ils ont des usages différents.

### DISTINCT : Pour obtenir des valeurs uniques

```sql
SELECT DISTINCT Ville
FROM Clients;
```

**Résultat :**
```
Ville
------
Lyon
Paris
Marseille
```

### GROUP BY : Pour agréger et calculer

```sql
SELECT Ville, COUNT(*) AS NombreClients
FROM Clients
GROUP BY Ville;
```

**Résultat :**
```
Ville        NombreClients
---------    -------------
Lyon         125
Paris        523
Marseille    87
```

### Quand utiliser quoi ?

| Besoin | Utilisez | Exemple |
|--------|----------|---------|
| Liste de valeurs uniques | `DISTINCT` | Liste des villes |
| Calculs par groupe | `GROUP BY` | Nombre de clients par ville |
| Valeurs uniques + 1 agrégation simple | Les deux fonctionnent | Comptage uniquement |
| Plusieurs agrégations | `GROUP BY` obligatoire | COUNT, SUM, AVG, etc. |

### Équivalence pour un simple comptage

Ces deux requêtes donnent le même résultat :

```sql
-- Avec DISTINCT
SELECT COUNT(DISTINCT Ville) AS NombreVilles
FROM Clients;

-- Avec GROUP BY
SELECT COUNT(*) AS NombreVilles
FROM (
    SELECT Ville
    FROM Clients
    GROUP BY Ville
) AS VillesUniques;
```

**Recommandation :** Pour un simple comptage de valeurs uniques, utilisez `COUNT(DISTINCT)` qui est plus lisible.

---

## DISTINCT sur toutes les colonnes (SELECT DISTINCT *)

Vous pouvez utiliser `DISTINCT` avec `SELECT *` :

```sql
SELECT DISTINCT *
FROM Commandes;
```

Cette requête élimine les lignes **entièrement identiques** (toutes les colonnes doivent être identiques).

**Attention :** Dans une table bien conçue avec une clé primaire, `DISTINCT *` ne devrait éliminer aucune ligne, car chaque ligne est unique par définition.

### Cas d'usage

`SELECT DISTINCT *` est utile dans des situations spécifiques :

1. **Données importées avec doublons**
```sql
-- Nettoyer une table temporaire après import
SELECT DISTINCT *
INTO Clients_NettoyeS
FROM Clients_Import;
```

2. **Résultats de jointures multiples**
```sql
SELECT DISTINCT c.*
FROM Clients c
INNER JOIN Commandes cmd ON c.ClientID = cmd.ClientID
INNER JOIN LignesCommande lc ON cmd.CommandeID = lc.CommandeID;
```

Ici, sans `DISTINCT`, un client pourrait apparaître plusieurs fois s'il a plusieurs commandes avec plusieurs lignes.

## Gestion des valeurs NULL

`DISTINCT` traite les valeurs NULL comme des valeurs identiques entre elles.

### Exemple avec NULL

Table `Produits` :

| ProduitID | Couleur |
|-----------|---------|
| 1 | Rouge |
| 2 | Bleu |
| 3 | NULL |
| 4 | Rouge |
| 5 | NULL |
| 6 | Bleu |

```sql
SELECT DISTINCT Couleur
FROM Produits;
```

**Résultat :**
```
Couleur
-------
Bleu
NULL
Rouge
```

**Explication :** Les deux valeurs NULL sont considérées comme identiques, donc une seule ligne avec NULL est retournée.

### Compter les valeurs uniques

```sql
-- ⚠️ COUNT(DISTINCT ...) IGNORE les NULL (comme tout COUNT de colonne)
SELECT COUNT(DISTINCT Couleur) AS CouleursDistinctes
FROM Produits;
-- Résultat : 2  (Bleu et Rouge ; les NULL ne sont PAS comptés)

-- Ajouter ce WHERE ne change rien : les NULL étaient déjà ignorés
SELECT COUNT(DISTINCT Couleur) AS CouleursDistinctes
FROM Produits
WHERE Couleur IS NOT NULL;
-- Résultat : 2  (identique)
```

> ⚠️ **Point important** — Bien que `SELECT DISTINCT Couleur` **affiche** une ligne `NULL` (voir plus haut), `COUNT(DISTINCT Couleur)` ne **compte jamais** les NULL. Pour compter NULL comme une « catégorie » supplémentaire, il faut l'ajouter explicitement :
> ```sql
> SELECT COUNT(DISTINCT Couleur)
>      + CASE WHEN COUNT(*) > COUNT(Couleur) THEN 1 ELSE 0 END AS CouleursAvecNull
> FROM Produits;   -- Résultat : 3 (Bleu, Rouge, + le groupe NULL)
> ```

## Performances et optimisation

### Impact sur les performances

`DISTINCT` nécessite que SQL Server :
1. **Récupère** toutes les lignes
2. **Trie** ou utilise une table de hachage pour identifier les doublons
3. **Élimine** les doublons
4. **Retourne** les résultats

Cela peut être **coûteux** sur de grandes tables, surtout sans index approprié.

### Bonnes pratiques pour les performances

**1. Utiliser des index**

Si vous utilisez fréquemment `DISTINCT` sur une colonne :

```sql
-- Créer un index sur la colonne
CREATE INDEX IX_Clients_Ville ON Clients(Ville);

-- La requête sera plus rapide
SELECT DISTINCT Ville FROM Clients;
```

**2. Filtrer avant DISTINCT**

```sql
-- ✅ Efficace : filtre d'abord, puis DISTINCT
SELECT DISTINCT Ville
FROM Clients
WHERE Pays = 'France';

-- ❌ Moins efficace : DISTINCT sur toutes les données
SELECT DISTINCT Ville
FROM Clients;
```

**3. Limiter le nombre de colonnes**

```sql
-- ✅ Rapide : peu de colonnes
SELECT DISTINCT Ville, Pays
FROM Clients;

-- ❌ Plus lent : beaucoup de colonnes
SELECT DISTINCT *
FROM Clients;
```

Plus il y a de colonnes, plus la comparaison est coûteuse.

**4. Préférer des index couvrants**

Pour des requêtes fréquentes avec DISTINCT :

```sql
-- Index couvrant pour une requête spécifique
CREATE INDEX IX_Clients_VillePays
ON Clients(Ville, Pays);

-- Cette requête utilisera l'index efficacement
SELECT DISTINCT Ville, Pays
FROM Clients;
```

## Cas d'usage pratiques

### 1. Créer une liste déroulante pour une application

```sql
-- Liste des catégories pour un menu de filtrage
SELECT DISTINCT Categorie
FROM Produits
WHERE Actif = 1
ORDER BY Categorie;
```

**Résultat :**
```
Categorie
--------------
Alimentation
Électronique
Vêtements
```

### 2. Analyser la couverture géographique

```sql
SELECT
    COUNT(DISTINCT Pays) AS NombrePays,
    COUNT(DISTINCT Ville) AS NombreVilles,
    COUNT(*) AS NombreClients
FROM Clients;
```

**Résultat :**
```
NombrePays  NombreVilles  NombreClients
----------  ------------  -------------
12          147           5234
```

**Interprétation :** Vous avez 5234 clients répartis dans 147 villes de 12 pays.

### 3. Identifier les clients actifs et leurs caractéristiques

```sql
SELECT
    COUNT(DISTINCT ClientID) AS ClientsActifs,
    COUNT(DISTINCT Ville) AS VillesCouvertes,
    COUNT(*) AS CommandesTotal
FROM Commandes
WHERE DateCommande >= DATEADD(MONTH, -12, GETDATE());
```

**Résultat :**
```
ClientsActifs  VillesCouvertes  CommandesTotal
-------------  ---------------  --------------
428            67               1532
```

### 4. Détecter les produits multi-catégories (cas d'erreur)

```sql
-- Vérifier si un produit apparaît dans plusieurs catégories (erreur de données)
SELECT ProduitID, COUNT(DISTINCT CategorieID) AS NombreCategories
FROM ProduitsCategories
GROUP BY ProduitID
HAVING COUNT(DISTINCT CategorieID) > 1;
```

Cette requête aide à identifier des problèmes de qualité de données.

### 5. Analyser la diversité des commandes

```sql
SELECT
    ClientID,
    COUNT(*) AS NombreCommandes,
    COUNT(DISTINCT CAST(DateCommande AS DATE)) AS JoursDistincts,
    COUNT(DISTINCT Ville) AS VillesDifferentes
FROM Commandes
GROUP BY ClientID
HAVING COUNT(DISTINCT Ville) > 1;
```

Identifie les clients qui commandent depuis plusieurs villes (déménagements, entreprises multi-sites, etc.).

## Erreurs courantes et pièges

### 1. DISTINCT ne fonctionne pas "par colonne"

```sql
-- ❌ Erreur conceptuelle : ceci ne retourne pas les villes distinctes ET les pays distincts séparément
SELECT DISTINCT Ville, Pays
FROM Clients;
```

`DISTINCT` s'applique à la **combinaison** des colonnes, pas à chaque colonne individuellement.

**Si vous voulez vraiment :**
```sql
-- Villes distinctes
SELECT DISTINCT Ville FROM Clients;

-- Pays distincts
SELECT DISTINCT Pays FROM Clients;
```

### 2. DISTINCT sur une colonne ne garantit pas l'unicité des autres

```sql
-- ⚠️ Attention : ne retourne PAS forcément des ClientID uniques
SELECT DISTINCT Ville, ClientID
FROM Clients;
```

Si deux clients habitent Paris, les deux seront dans le résultat car les combinaisons `(Paris, Client1)` et `(Paris, Client2)` sont différentes.

### 3. Oublier ORDER BY pour un résultat prévisible

```sql
-- ❌ L'ordre peut varier d'une exécution à l'autre
SELECT DISTINCT Ville
FROM Clients;

-- ✅ Ordre prévisible
SELECT DISTINCT Ville
FROM Clients
ORDER BY Ville;
```

### 4. DISTINCT dans une sous-requête inutile

```sql
-- ❌ DISTINCT inutile ici
SELECT *
FROM Clients
WHERE ClientID IN (SELECT DISTINCT ClientID FROM Commandes);

-- ✅ IN élimine automatiquement les doublons
SELECT *
FROM Clients
WHERE ClientID IN (SELECT ClientID FROM Commandes);
```

Le `IN` vérifie uniquement l'existence, donc `DISTINCT` est redondant.

### 5. Confusion entre DISTINCT et GROUP BY

```sql
-- ❌ Erreur : on ne peut pas mélanger DISTINCT et agrégations
SELECT DISTINCT Ville, COUNT(*) AS NombreClients
FROM Clients;

-- ✅ Utiliser GROUP BY pour les agrégations
SELECT Ville, COUNT(*) AS NombreClients
FROM Clients
GROUP BY Ville;
```

## DISTINCT avec des expressions calculées

Vous pouvez utiliser `DISTINCT` sur des colonnes calculées ou des expressions :

### Exemple 1 : Années de commandes

```sql
SELECT DISTINCT YEAR(DateCommande) AS Annee
FROM Commandes
ORDER BY Annee DESC;
```

**Résultat :**
```
Annee
-----
2024
2023
2022
2021
```

### Exemple 2 : Premières lettres des noms

```sql
SELECT DISTINCT LEFT(NomClient, 1) AS InitialeNom
FROM Clients
ORDER BY InitialeNom;
```

**Résultat :**
```
InitialeNom
-----------
A
B
C
...
Z
```

### Exemple 3 : Tranches de prix

```sql
SELECT DISTINCT
    CASE
        WHEN Prix < 10 THEN 'Moins de 10€'
        WHEN Prix BETWEEN 10 AND 50 THEN '10-50€'
        WHEN Prix BETWEEN 50 AND 100 THEN '50-100€'
        ELSE 'Plus de 100€'
    END AS TranchePrix
FROM Produits
ORDER BY TranchePrix;
```

---

## DISTINCT dans les sous-requêtes

`DISTINCT` est souvent utilisé dans les sous-requêtes pour garantir l'unicité.

### Exemple 1 : Clients ayant commandé

```sql
SELECT *
FROM Clients
WHERE ClientID IN (
    SELECT DISTINCT ClientID
    FROM Commandes
);
```

**Note :** Ici, `DISTINCT` est optionnel car `IN` vérifie juste l'existence, mais il peut améliorer la lisibilité.

### Exemple 2 : Produits jamais commandés

```sql
SELECT *
FROM Produits
WHERE ProduitID NOT IN (
    SELECT DISTINCT ProduitID
    FROM LignesCommande
);
```

### Exemple 3 : Avec EXISTS (alternative)

```sql
-- Souvent plus performant que IN avec DISTINCT
SELECT *
FROM Clients c
WHERE EXISTS (
    SELECT 1
    FROM Commandes cmd
    WHERE cmd.ClientID = c.ClientID
);
```

---

## DISTINCT ALL (le contraire)

En SQL, `ALL` est l'opposé de `DISTINCT` : il conserve tous les doublons.

```sql
-- Ces deux requêtes sont équivalentes
SELECT Ville FROM Clients;
SELECT ALL Ville FROM Clients;
```

`ALL` est le comportement **par défaut**, donc il n'est généralement pas nécessaire de l'écrire explicitement.

## Bonnes pratiques

### ✅ À faire

1. **Utiliser DISTINCT quand c'est vraiment nécessaire**
```sql
-- Si vous voulez vraiment les valeurs uniques
SELECT DISTINCT Categorie FROM Produits;
```

2. **Combiner avec ORDER BY pour la lisibilité**
```sql
SELECT DISTINCT Ville
FROM Clients
ORDER BY Ville;
```

3. **Documenter pourquoi vous utilisez DISTINCT**
```sql
-- Liste des pays pour le menu déroulant de filtrage
SELECT DISTINCT Pays
FROM Clients
WHERE Actif = 1;
```

4. **Utiliser COUNT(DISTINCT) pour les statistiques**
```sql
SELECT COUNT(DISTINCT ClientID) AS ClientsUniques
FROM Commandes;
```

5. **Créer des index sur les colonnes fréquemment utilisées avec DISTINCT**
```sql
CREATE INDEX IX_Clients_Pays ON Clients(Pays);
```

### ❌ À éviter

1. **Utiliser DISTINCT pour masquer des problèmes de jointures**
```sql
-- ❌ DISTINCT cache peut-être un problème de jointure
SELECT DISTINCT c.ClientID, c.NomClient
FROM Clients c
INNER JOIN Commandes cmd ON c.ClientID = cmd.ClientID
INNER JOIN LignesCommande lc ON cmd.CommandeID = lc.CommandeID;

-- ✅ Mieux : comprendre pourquoi il y a des doublons
```

2. **Utiliser DISTINCT par défaut "au cas où"**
```sql
-- ❌ DISTINCT inutile si la table a une clé primaire
SELECT DISTINCT * FROM Clients;
```

3. **Oublier que DISTINCT a un coût**
```sql
-- ❌ Sur une table de millions de lignes sans index
SELECT DISTINCT Ville FROM HugeTable;
```

4. **Mélanger DISTINCT et GROUP BY**
```sql
-- ❌ Incohérent
SELECT DISTINCT Ville, COUNT(*) FROM Clients GROUP BY Ville;
-- Utilisez GROUP BY seul
```

## Différences avec d'autres SGBD

`DISTINCT` fonctionne de manière similaire dans la plupart des systèmes de gestion de bases de données, mais quelques nuances existent :

| SGBD | Particularités |
|------|----------------|
| **SQL Server** | `DISTINCT` standard, supporte `DISTINCT` avec `TOP` |
| **MySQL** | Identique, mais `DISTINCT` peut être utilisé avec `LIMIT` |
| **PostgreSQL** | Support de `DISTINCT ON` pour plus de contrôle |
| **Oracle** | Similaire, mais préfère souvent `UNIQUE` dans certains contextes |

**Note sur PostgreSQL :**
```sql
-- PostgreSQL permet DISTINCT ON (non disponible en SQL Server)
SELECT DISTINCT ON (ClientID) *
FROM Commandes
ORDER BY ClientID, DateCommande DESC;
```

En SQL Server, il faudrait utiliser `ROW_NUMBER()` ou `GROUP BY` pour obtenir le même résultat.

## Résumé

### Syntaxe

```sql
SELECT DISTINCT colonne1, colonne2, ...
FROM table
[WHERE condition]
[ORDER BY colonne];
```

### Points clés

| Concept | Description |
|---------|-------------|
| **Fonction** | Élimine les lignes en double |
| **Unicité** | Basée sur **toutes** les colonnes sélectionnées |
| **NULL** | Traité comme une valeur identique aux autres NULL |
| **Performance** | Peut être coûteux sur de grandes tables sans index |
| **Ordre** | N'est pas garanti sans `ORDER BY` |

### Quand utiliser DISTINCT ?

✅ **Utiliser DISTINCT quand :**
- Vous avez besoin de la liste des valeurs uniques
- Vous créez des listes de sélection pour une interface
- Vous comptez des valeurs distinctes avec `COUNT(DISTINCT)`
- Vous analysez la diversité des données

❌ **Ne pas utiliser DISTINCT quand :**
- Vous voulez des agrégations par groupe (utilisez `GROUP BY`)
- Vous masquez des problèmes de qualité de données ou de jointures
- La table a déjà une clé primaire qui garantit l'unicité
- Les performances sont critiques et les doublons ne posent pas problème

### Formules utiles

```sql
-- Nombre de valeurs uniques
SELECT COUNT(DISTINCT colonne) FROM table;

-- Liste triée de valeurs uniques
SELECT DISTINCT colonne FROM table ORDER BY colonne;

-- Combinaisons uniques de plusieurs colonnes
SELECT DISTINCT col1, col2, col3 FROM table;

-- Valeurs uniques avec filtrage
SELECT DISTINCT colonne FROM table WHERE condition;
```

---

## Conclusion

`DISTINCT` est un outil simple mais essentiel dans votre boîte à outils SQL. Il vous permet de transformer des résultats avec doublons en listes de valeurs uniques, ce qui est indispensable pour :

- L'analyse de données (combien de catégories, de villes, de produits différents ?)
- La création d'interfaces utilisateur (listes déroulantes, filtres)
- Les statistiques (nombre de clients uniques, de jours d'activité, etc.)
- Le nettoyage de données

Cependant, utilisez-le avec discernement : `DISTINCT` a un coût en termes de performance, et son utilisation excessive peut masquer des problèmes de conception de base de données ou de requêtes. Combinez-le judicieusement avec les clauses `WHERE`, `ORDER BY`, et les fonctions d'agrégation pour obtenir des résultats précis et performants.

**Points essentiels à retenir :**
1. `DISTINCT` élimine les lignes en double
2. L'unicité est basée sur **toutes** les colonnes sélectionnées
3. `COUNT(DISTINCT colonne)` compte les valeurs uniques
4. Pensez aux performances : créez des index si nécessaire
5. `DISTINCT` ≠ `GROUP BY` : utilisez le bon outil pour le bon besoin
