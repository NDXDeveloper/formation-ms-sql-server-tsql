# 5.2.4 L'instruction CASE (Simple et "Searched")

## Introduction

Dans les sections précédentes, nous avons vu comment utiliser **IF ... ELSE** pour prendre des décisions dans notre code. Mais que faire quand vous voulez **transformer des valeurs** directement dans une requête SELECT, ou assigner différentes valeurs selon plusieurs conditions ?

C'est là qu'intervient l'instruction **CASE**, l'équivalent SQL du "switch" ou "match" d'autres langages de programmation. CASE permet d'évaluer des conditions et de **retourner des valeurs différentes** selon le résultat, le tout **dans une expression**.

Il existe deux types de CASE en T-SQL :
1. **CASE Simple** : pour comparer une expression à plusieurs valeurs
2. **CASE Searched** (recherché) : pour évaluer plusieurs conditions différentes

Dans cette section, nous allons explorer ces deux variantes et apprendre quand utiliser l'une ou l'autre.

---

## 1. Concept de base

### Qu'est-ce que CASE ?

**CASE** est une **expression conditionnelle** qui :
- Évalue une ou plusieurs conditions
- Retourne une valeur en fonction de la première condition vraie
- Peut être utilisée partout où une expression est attendue

### Différence avec IF

| IF ... ELSE | CASE |
|-------------|------|
| **Structure de contrôle** | **Expression** |
| Contrôle le flux du programme | Retourne une valeur |
| Utilisé pour exécuter des blocs de code | Utilisé dans les requêtes (SELECT, UPDATE, etc.) |
| Ne peut pas être dans un SELECT | Peut être dans un SELECT |

### Analogie

Imaginez un distributeur automatique :
- Vous appuyez sur un bouton (condition)
- Le distributeur vous donne le produit correspondant (valeur retournée)
- Si aucun bouton ne correspond, il peut donner un produit par défaut (ELSE)

## 2. CASE Simple

### Syntaxe

```sql
CASE expression_a_tester
    WHEN valeur1 THEN resultat1
    WHEN valeur2 THEN resultat2
    WHEN valeur3 THEN resultat3
    ...
    ELSE resultat_par_defaut
END
```

### Comment ça fonctionne ?

1. T-SQL évalue l'**expression_a_tester**
2. Compare cette valeur avec **chaque WHEN** dans l'ordre
3. Dès qu'une correspondance est trouvée, retourne le **résultat** associé
4. Si aucune correspondance, retourne le **ELSE** (optionnel)
5. **END** marque la fin de l'expression CASE

### Premier exemple simple

```sql
DECLARE @Jour INT = 3;
DECLARE @NomJour VARCHAR(20);

SET @NomJour = CASE @Jour
    WHEN 1 THEN 'Lundi'
    WHEN 2 THEN 'Mardi'
    WHEN 3 THEN 'Mercredi'
    WHEN 4 THEN 'Jeudi'
    WHEN 5 THEN 'Vendredi'
    WHEN 6 THEN 'Samedi'
    WHEN 7 THEN 'Dimanche'
    ELSE 'Jour invalide'
END;

SELECT @NomJour AS NomDuJour;
```

**Résultat :**
```
NomDuJour
---------
Mercredi
```

### Exemple dans un SELECT

```sql
SELECT
    EmployeID,
    Prenom,
    Nom,
    Departement,
    CASE Departement
        WHEN 'IT' THEN 'Informatique'
        WHEN 'HR' THEN 'Ressources Humaines'
        WHEN 'Sales' THEN 'Ventes'
        WHEN 'Marketing' THEN 'Marketing'
        ELSE 'Autre département'
    END AS DepartementFR
FROM Employes;
```

**Résultat :**
```
EmployeID  Prenom   Nom      Departement  DepartementFR
---------  -------  -------  -----------  ------------------
1          Marie    Dupont   IT           Informatique
2          Jean     Martin   HR           Ressources Humaines
3          Sophie   Bernard  Sales        Ventes
4          Pierre   Durand   Finance      Autre département
```

### Exemple avec différents types de données

#### Avec des nombres

```sql
SELECT
    ProduitID,
    NomProduit,
    CategorieID,
    CASE CategorieID
        WHEN 1 THEN 'Électronique'
        WHEN 2 THEN 'Vêtements'
        WHEN 3 THEN 'Alimentation'
        WHEN 4 THEN 'Livres'
        ELSE 'Non catégorisé'
    END AS Categorie
FROM Produits;
```

#### Avec des caractères

```sql
SELECT
    CommandeID,
    Statut,
    CASE Statut
        WHEN 'P' THEN 'En préparation'
        WHEN 'E' THEN 'Expédiée'
        WHEN 'L' THEN 'Livrée'
        WHEN 'A' THEN 'Annulée'
        ELSE 'Statut inconnu'
    END AS StatutComplet
FROM Commandes;
```

## 3. CASE Searched (Recherché)

### Syntaxe

```sql
CASE
    WHEN condition1 THEN resultat1
    WHEN condition2 THEN resultat2
    WHEN condition3 THEN resultat3
    ...
    ELSE resultat_par_defaut
END
```

### Différence avec CASE Simple

| CASE Simple | CASE Searched |
|-------------|---------------|
| Compare **une seule expression** à plusieurs valeurs | Évalue **plusieurs conditions** différentes |
| `CASE expression WHEN valeur...` | `CASE WHEN condition...` |
| Seulement test d'égalité (=) | Tous opérateurs possibles (>, <, >=, <=, LIKE, IN, etc.) |
| Conditions sur la même variable | Conditions sur des variables différentes |

### Premier exemple

```sql
DECLARE @Age INT = 25;
DECLARE @Categorie VARCHAR(20);

SET @Categorie = CASE
    WHEN @Age < 13 THEN 'Enfant'
    WHEN @Age < 18 THEN 'Adolescent'
    WHEN @Age < 65 THEN 'Adulte'
    ELSE 'Senior'
END;

SELECT @Categorie AS Categorie;
```

**Résultat :**
```
Categorie
---------
Adulte
```

### Exemple avec plusieurs conditions

```sql
DECLARE @Temperature INT = 22;
DECLARE @Humidite INT = 60;
DECLARE @Confort VARCHAR(30);

SET @Confort = CASE
    WHEN @Temperature < 15 THEN 'Trop froid'
    WHEN @Temperature > 30 THEN 'Trop chaud'
    WHEN @Humidite > 70 THEN 'Trop humide'
    WHEN @Temperature BETWEEN 20 AND 25 AND @Humidite BETWEEN 40 AND 60 THEN 'Parfait'
    ELSE 'Acceptable'
END;

SELECT @Confort AS NiveauConfort;
```

### Exemple dans un SELECT avec opérateurs

```sql
SELECT
    EmployeID,
    Prenom,
    Nom,
    Salaire,
    CASE
        WHEN Salaire < 2000 THEN 'Bas'
        WHEN Salaire >= 2000 AND Salaire < 4000 THEN 'Moyen'
        WHEN Salaire >= 4000 AND Salaire < 6000 THEN 'Bon'
        ELSE 'Élevé'
    END AS NiveauSalaire
FROM Employes;
```

**Résultat :**
```
EmployeID  Prenom   Nom      Salaire  NiveauSalaire
---------  -------  -------  -------  -------------
1          Marie    Dupont   3500.00  Moyen
2          Jean     Martin   5500.00  Bon
3          Sophie   Bernard  7000.00  Élevé
4          Pierre   Durand   1800.00  Bas
```

### Exemple avec opérateurs complexes

```sql
SELECT
    ProduitID,
    NomProduit,
    Prix,
    QuantiteStock,
    CASE
        WHEN QuantiteStock = 0 THEN '🔴 Rupture de stock'
        WHEN QuantiteStock < 10 THEN '🟠 Stock faible'
        WHEN QuantiteStock < 50 THEN '🟡 Stock moyen'
        ELSE '🟢 Stock suffisant'
    END AS StatutStock,
    CASE
        WHEN Prix < 50 THEN 'Entrée de gamme'
        WHEN Prix BETWEEN 50 AND 200 THEN 'Milieu de gamme'
        WHEN Prix > 200 THEN 'Haut de gamme'
    END AS GammePrix
FROM Produits;
```

## 4. Comparaison : Simple vs Searched

### Quand utiliser CASE Simple ?

**✅ Utilisez CASE Simple quand :**
- Vous comparez **une seule variable** à plusieurs valeurs
- Vous testez uniquement **l'égalité** (=)
- Les valeurs de test sont **simples** et **constantes**

**Exemple approprié pour CASE Simple :**
```sql
CASE @Statut
    WHEN 'A' THEN 'Actif'
    WHEN 'I' THEN 'Inactif'
    WHEN 'S' THEN 'Suspendu'
END
```

### Quand utiliser CASE Searched ?

**✅ Utilisez CASE Searched quand :**
- Vous avez des **conditions complexes**
- Vous utilisez d'autres opérateurs que = (>, <, LIKE, IN, etc.)
- Vous testez **plusieurs variables différentes**
- Vous avez des **conditions combinées** (AND, OR)

**Exemple approprié pour CASE Searched :**
```sql
CASE
    WHEN Salaire > 5000 AND Anciennete > 5 THEN 'Senior bien payé'
    WHEN Salaire > 5000 THEN 'Bien payé'
    WHEN Anciennete > 5 THEN 'Senior'
    ELSE 'Junior'
END
```

### Conversion entre les deux types

Certains CASE Simple peuvent être écrits en CASE Searched (mais pas l'inverse).

**CASE Simple :**
```sql
CASE @Statut
    WHEN 'A' THEN 'Actif'
    WHEN 'I' THEN 'Inactif'
END
```

**Équivalent en CASE Searched :**
```sql
CASE
    WHEN @Statut = 'A' THEN 'Actif'
    WHEN @Statut = 'I' THEN 'Inactif'
END
```

## 5. Utilisation de CASE dans différents contextes

### Dans SELECT (colonnes calculées)

C'est l'usage le plus courant de CASE.

```sql
SELECT
    ClientID,
    Nom,
    Prenom,
    Solde,
    CASE
        WHEN Solde < 0 THEN 'Débiteur'
        WHEN Solde = 0 THEN 'Équilibré'
        ELSE 'Créditeur'
    END AS TypeCompte,
    CASE
        WHEN Solde < -1000 THEN 'Action urgente requise'
        WHEN Solde < 0 THEN 'Surveiller'
        ELSE 'OK'
    END AS Alerte
FROM Clients;
```

### Dans WHERE (filtrage)

```sql
DECLARE @TypeRecherche VARCHAR(20) = 'Actifs';

SELECT *
FROM Employes
WHERE
    CASE @TypeRecherche
        WHEN 'Actifs' THEN EstActif
        WHEN 'Inactifs' THEN CASE WHEN EstActif = 0 THEN 1 ELSE 0 END
        ELSE 1  -- Tous
    END = 1;
```

### Dans ORDER BY (tri personnalisé)

```sql
SELECT
    CommandeID,
    ClientID,
    Statut,
    Montant
FROM Commandes
ORDER BY
    -- Trier par priorité de statut
    CASE Statut
        WHEN 'Urgente' THEN 1
        WHEN 'EnCours' THEN 2
        WHEN 'EnAttente' THEN 3
        WHEN 'Terminée' THEN 4
        ELSE 5
    END,
    -- Puis par montant décroissant
    Montant DESC;
```

### Dans UPDATE (mise à jour conditionnelle)

```sql
UPDATE Employes
SET Prime = CASE
    WHEN Anciennete >= 10 THEN Salaire * 0.20
    WHEN Anciennete >= 5 THEN Salaire * 0.15
    WHEN Anciennete >= 2 THEN Salaire * 0.10
    ELSE Salaire * 0.05
END,
Status = CASE
    WHEN Anciennete >= 10 THEN 'Senior'
    WHEN Anciennete >= 5 THEN 'Confirmé'
    ELSE 'Junior'
END
WHERE Departement = 'IT';
```

### Dans INSERT (valeurs conditionnelles)

```sql
INSERT INTO Rapports (Date, Type, Priorite, Message)
VALUES (
    GETDATE(),
    'Ventes',
    CASE
        WHEN (SELECT SUM(Montant) FROM Ventes WHERE MONTH(DateVente) = MONTH(GETDATE())) < 10000
        THEN 'Haute'
        ELSE 'Normale'
    END,
    'Rapport mensuel'
);
```

### Dans les agrégations

```sql
SELECT
    Departement,
    COUNT(*) AS TotalEmployes,
    SUM(CASE WHEN Sexe = 'M' THEN 1 ELSE 0 END) AS Hommes,
    SUM(CASE WHEN Sexe = 'F' THEN 1 ELSE 0 END) AS Femmes,
    SUM(CASE WHEN Salaire > 4000 THEN 1 ELSE 0 END) AS SalaireElevé,
    AVG(CASE WHEN EstActif = 1 THEN Salaire ELSE NULL END) AS SalaireMoyenActifs
FROM Employes
GROUP BY Departement;
```

## 6. CASE imbriqués

Vous pouvez imbriquer des CASE les uns dans les autres, mais attention à la lisibilité !

### Exemple simple

```sql
SELECT
    ProduitID,
    NomProduit,
    CategorieID,
    Prix,
    CASE CategorieID
        WHEN 1 THEN
            CASE
                WHEN Prix < 100 THEN 'Électronique économique'
                WHEN Prix < 500 THEN 'Électronique milieu'
                ELSE 'Électronique premium'
            END
        WHEN 2 THEN
            CASE
                WHEN Prix < 50 THEN 'Vêtements basiques'
                ELSE 'Vêtements de marque'
            END
        ELSE 'Autre produit'
    END AS Description
FROM Produits;
```

### ⚠️ Attention à la complexité

Trop de CASE imbriqués rendent le code difficile à lire. Préférez :
- Plusieurs colonnes avec des CASE simples
- Des vues ou fonctions pour encapsuler la logique
- Diviser en étapes avec des tables temporaires

**❌ Trop complexe :**
```sql
CASE
    WHEN ... THEN
        CASE
            WHEN ... THEN
                CASE
                    WHEN ... THEN ...
                END
        END
END
```

**✅ Meilleure approche :**
```sql
-- Colonne 1
CASE ... END AS Info1,
-- Colonne 2
CASE ... END AS Info2,
-- Colonne 3
CASE ... END AS Info3
```

## 7. Gestion de NULL avec CASE

### Tester NULL

```sql
SELECT
    EmployeID,
    Prenom,
    Nom,
    Email,
    CASE
        WHEN Email IS NULL THEN 'Pas d''email'
        WHEN Email = '' THEN 'Email vide'
        ELSE Email
    END AS EmailFormate
FROM Employes;
```

### Retourner NULL

```sql
SELECT
    ProduitID,
    NomProduit,
    CASE
        WHEN EstArchive = 1 THEN NULL  -- Masquer le prix
        ELSE Prix
    END AS PrixAffiche
FROM Produits;
```

### Alternative : COALESCE vs CASE

**Avec CASE :**
```sql
SELECT
    CASE
        WHEN Telephone IS NULL THEN 'Non renseigné'
        ELSE Telephone
    END AS TelephoneAffiche
FROM Clients;
```

**Avec COALESCE (plus court) :**
```sql
SELECT
    COALESCE(Telephone, 'Non renseigné') AS TelephoneAffiche
FROM Clients;
```

## 8. Exemples pratiques complets

### Exemple 1 : Système de notation

```sql
SELECT
    EtudiantID,
    Nom,
    Prenom,
    Note,
    CASE
        WHEN Note >= 16 THEN 'Très Bien'
        WHEN Note >= 14 THEN 'Bien'
        WHEN Note >= 12 THEN 'Assez Bien'
        WHEN Note >= 10 THEN 'Passable'
        ELSE 'Insuffisant'
    END AS Mention,
    CASE
        WHEN Note >= 10 THEN '✓ Admis'
        ELSE '✗ Ajourné'
    END AS Resultat,
    CASE
        WHEN Note >= 16 THEN 'Félicitations du jury'
        WHEN Note >= 14 THEN 'Encouragements'
        WHEN Note >= 10 THEN ''
        ELSE 'Doit se représenter'
    END AS Commentaire
FROM Resultats;
```

### Exemple 2 : Gestion des remises

```sql
SELECT
    CommandeID,
    ClientID,
    MontantHT,
    CASE
        WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 20 THEN 0.20
        WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 10 THEN 0.15
        WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 5 THEN 0.10
        ELSE 0.00
    END AS TauxRemise,
    MontantHT * (1 -
        CASE
            WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 20 THEN 0.20
            WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 10 THEN 0.15
            WHEN (SELECT COUNT(*) FROM Commandes c2 WHERE c2.ClientID = c.ClientID) >= 5 THEN 0.10
            ELSE 0.00
        END
    ) AS MontantFinal
FROM Commandes c;
```

### Exemple 3 : Tableau de bord des ventes

```sql
SELECT
    VendeurID,
    Nom,
    Prenom,
    VentesTotales,
    ObjectifAnnuel,
    CASE
        WHEN VentesTotales >= ObjectifAnnuel * 1.2 THEN '★★★ Excellent'
        WHEN VentesTotales >= ObjectifAnnuel THEN '★★ Objectif atteint'
        WHEN VentesTotales >= ObjectifAnnuel * 0.8 THEN '★ Proche de l''objectif'
        ELSE '⚠ En-dessous de l''objectif'
    END AS Performance,
    CASE
        WHEN VentesTotales >= ObjectifAnnuel THEN 'Oui'
        ELSE 'Non'
    END AS PrimeEligible,
    CASE
        WHEN VentesTotales >= ObjectifAnnuel
        THEN (VentesTotales - ObjectifAnnuel) * 0.05
        ELSE 0
    END AS MontantPrime
FROM Vendeurs;
```

### Exemple 4 : Classification de produits

```sql
SELECT
    ProduitID,
    NomProduit,
    Prix,
    QuantiteVendue,
    CASE
        WHEN Prix * QuantiteVendue > 100000 THEN 'A - Produit star'
        WHEN Prix * QuantiteVendue > 50000 THEN 'B - Bon vendeur'
        WHEN Prix * QuantiteVendue > 10000 THEN 'C - Vendeur moyen'
        ELSE 'D - Faible performance'
    END AS Categorie,
    CASE
        WHEN QuantiteVendue = 0 THEN 'Arrêter'
        WHEN Prix * QuantiteVendue < 5000 THEN 'Évaluer'
        WHEN Prix * QuantiteVendue > 100000 THEN 'Promouvoir'
        ELSE 'Maintenir'
    END AS ActionRecommandee
FROM Produits;
```

### Exemple 5 : Reporting avec CASE et GROUP BY

```sql
SELECT
    Departement,
    COUNT(*) AS TotalEmployes,
    CASE
        WHEN COUNT(*) > 50 THEN 'Grand département'
        WHEN COUNT(*) > 20 THEN 'Département moyen'
        ELSE 'Petit département'
    END AS Taille,
    AVG(Salaire) AS SalaireMoyen,
    SUM(CASE WHEN Salaire > 5000 THEN 1 ELSE 0 END) AS NombreSalaireEleve,
    CASE
        WHEN AVG(Salaire) > 4500 THEN 'Salaires élevés'
        WHEN AVG(Salaire) > 3000 THEN 'Salaires moyens'
        ELSE 'Salaires faibles'
    END AS NiveauSalarial
FROM Employes
GROUP BY Departement
HAVING COUNT(*) > 5
ORDER BY
    CASE
        WHEN AVG(Salaire) > 4500 THEN 1
        WHEN AVG(Salaire) > 3000 THEN 2
        ELSE 3
    END;
```

## 9. CASE et performance

### Ordre des conditions

L'ordre des WHEN est **important** ! SQL Server évalue les conditions dans l'ordre et s'arrête à la première vraie.

**✅ Plus efficace (condition la plus fréquente en premier) :**
```sql
CASE
    WHEN Statut = 'Actif' THEN 'A'  -- 90% des cas
    WHEN Statut = 'Inactif' THEN 'I'  -- 9% des cas
    WHEN Statut = 'Supprimé' THEN 'S'  -- 1% des cas
END
```

**❌ Moins efficace (rare en premier) :**
```sql
CASE
    WHEN Statut = 'Supprimé' THEN 'S'  -- 1% des cas, testé en premier
    WHEN Statut = 'Inactif' THEN 'I'  -- 9% des cas
    WHEN Statut = 'Actif' THEN 'A'  -- 90% des cas, testé en dernier
END
```

### Éviter les sous-requêtes répétées

**❌ Mauvais (sous-requête exécutée plusieurs fois) :**
```sql
CASE
    WHEN (SELECT COUNT(*) FROM Commandes WHERE ClientID = c.ClientID) > 100 THEN 'VIP'
    WHEN (SELECT COUNT(*) FROM Commandes WHERE ClientID = c.ClientID) > 50 THEN 'Premium'
    WHEN (SELECT COUNT(*) FROM Commandes WHERE ClientID = c.ClientID) > 10 THEN 'Standard'
    ELSE 'Nouveau'
END
```

**✅ Meilleur (utiliser une CTE ou une jointure) :**
```sql
WITH CommandesParClient AS (
    SELECT ClientID, COUNT(*) AS NbCommandes
    FROM Commandes
    GROUP BY ClientID
)
SELECT
    c.ClientID,
    c.Nom,
    CASE
        WHEN cpc.NbCommandes > 100 THEN 'VIP'
        WHEN cpc.NbCommandes > 50 THEN 'Premium'
        WHEN cpc.NbCommandes > 10 THEN 'Standard'
        ELSE 'Nouveau'
    END AS Categorie
FROM Clients c
LEFT JOIN CommandesParClient cpc ON c.ClientID = cpc.ClientID;
```

## 10. Alternatives à CASE

### IIF (plus simple pour 2 branches)

**IIF** est une fonction raccourcie pour un CASE à deux branches (disponible depuis SQL Server 2012).

**Avec CASE :**
```sql
SELECT
    CASE
        WHEN Salaire > 5000 THEN 'Élevé'
        ELSE 'Normal'
    END AS Niveau
```

**Avec IIF :**
```sql
SELECT
    IIF(Salaire > 5000, 'Élevé', 'Normal') AS Niveau
```

### CHOOSE (pour indices numériques)

**CHOOSE** sélectionne une valeur dans une liste basée sur un index (1, 2, 3, ...).

**Avec CASE :**
```sql
CASE @Mois
    WHEN 1 THEN 'Janvier'
    WHEN 2 THEN 'Février'
    WHEN 3 THEN 'Mars'
END
```

**Avec CHOOSE :**
```sql
CHOOSE(@Mois, 'Janvier', 'Février', 'Mars')
```

## 11. Bonnes pratiques

### ✅ À FAIRE

1. **Toujours inclure ELSE** (sauf si vous voulez explicitement NULL)
2. **Utiliser CASE Simple** quand c'est possible (plus lisible)
3. **Indenter correctement** les WHEN pour la lisibilité
4. **Ordonner les conditions** de la plus fréquente à la moins fréquente
5. **Donner des alias** aux colonnes avec CASE
6. **Commenter** les CASE complexes
7. **Tester tous les cas** possibles, y compris NULL

### ❌ À ÉVITER

1. **Oublier le ELSE** (peut causer des NULL inattendus)
2. **Imbriquer trop de CASE** (difficile à lire)
3. **Répéter des sous-requêtes** dans plusieurs WHEN
4. **Utiliser CASE quand IIF suffit** (trop verbeux)
5. **Mélanger types de données** incompatibles dans les THEN

### Exemple de code bien structuré

```sql
SELECT
    ClientID,
    Nom,
    Prenom,
    -- Classification client
    CASE
        WHEN NbCommandesAn > 50 THEN 'VIP'
        WHEN NbCommandesAn > 20 THEN 'Premium'
        WHEN NbCommandesAn > 5 THEN 'Regular'
        ELSE 'Occasionnel'
    END AS CategorieClient,

    -- Réduction applicable
    CASE
        WHEN NbCommandesAn > 50 THEN 0.25
        WHEN NbCommandesAn > 20 THEN 0.15
        WHEN NbCommandesAn > 5 THEN 0.10
        ELSE 0.00
    END AS TauxReduction,

    -- Message personnalisé
    CASE
        WHEN NbCommandesAn > 50 THEN 'Merci pour votre fidélité exceptionnelle !'
        WHEN NbCommandesAn > 20 THEN 'Merci d''être un client fidèle'
        WHEN NbCommandesAn = 0 THEN 'Bienvenue ! Profitez de nos offres'
        ELSE 'Merci pour votre confiance'
    END AS Message
FROM Clients;
```

## 12. Débogage et messages d'erreur

### Erreur : Tous les résultats doivent être du même type

**❌ Erreur :**
```sql
CASE @Type
    WHEN 1 THEN 'Texte'  -- VARCHAR
    WHEN 2 THEN 123      -- INT
END
```

**Erreur :** Conversion failed when converting the varchar value 'Texte' to data type int.

**✅ Solution :**
```sql
CASE @Type
    WHEN 1 THEN 'Texte'
    WHEN 2 THEN '123'  -- Tout en VARCHAR
END
```

### Erreur : END manquant

**❌ Erreur :**
```sql
CASE @Status
    WHEN 'A' THEN 'Actif'
    -- END oublié !
```

Toujours terminer par **END**.

## Résumé

- **CASE** est une expression conditionnelle qui retourne une valeur
- **CASE Simple** : compare une expression à plusieurs valeurs (test d'égalité uniquement)
  - `CASE expression WHEN valeur1 THEN resultat1 ... END`
- **CASE Searched** : évalue plusieurs conditions différentes (tous opérateurs)
  - `CASE WHEN condition1 THEN resultat1 ... END`
- CASE peut être utilisé dans **SELECT, WHERE, ORDER BY, UPDATE, INSERT**
- L'ordre des **WHEN** est important (première condition vraie)
- Toujours inclure **ELSE** pour gérer les cas non prévus
- **END** est obligatoire pour terminer le CASE
- Peut être **imbriqué** mais attention à la complexité
- Alternatives : **IIF** (2 branches), **CHOOSE** (index numérique)
- Optimiser en plaçant les conditions **les plus fréquentes en premier**

CASE est un outil extrêmement puissant et flexible en T-SQL. Il permet de transformer et classifier des données directement dans vos requêtes, rendant votre code plus expressif et concis. Dans les sections suivantes, nous découvrirons la gestion des erreurs avec TRY ... CATCH.
