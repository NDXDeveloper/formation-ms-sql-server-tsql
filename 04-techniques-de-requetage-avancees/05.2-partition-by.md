# 4.5.2 PARTITION BY (Agrégation sans GROUP BY)

## Introduction à PARTITION BY

Dans le chapitre précédent, nous avons découvert la clause `OVER()` qui permet de calculer des agrégations sans perdre les détails des lignes. Maintenant, nous allons ajouter `PARTITION BY` pour diviser nos données en groupes et calculer des agrégations **par groupe**, tout en conservant chaque ligne individuelle.

### Rappel : OVER() sans PARTITION BY

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER() AS MoyenneGlobale
FROM Employes;
```

Cette requête calcule la moyenne sur **toutes** les lignes.

### Maintenant avec PARTITION BY

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDepartement
FROM Employes;
```

Cette requête calcule la moyenne **par département**, mais conserve toutes les lignes !

## Le concept de PARTITION BY

`PARTITION BY` divise (ou "partitionne") vos données en sous-ensembles selon une ou plusieurs colonnes, puis applique la fonction à chaque sous-ensemble indépendamment.

### Analogie simple

Imaginez une classe avec des élèves de différentes sections :

- **Sans PARTITION BY** : Vous calculez la moyenne de **toute la classe**
- **Avec PARTITION BY Section** : Vous calculez la moyenne de **chaque section**, mais vous écrivez cette moyenne à côté de chaque élève

Chaque élève conserve sa ligne, mais voit la moyenne de SA section.

## Syntaxe

```sql
fonction() OVER(PARTITION BY colonne1 [, colonne2, ...])
```

### Éléments clés :
- **fonction()** : SUM, AVG, COUNT, MIN, MAX, etc.
- **PARTITION BY** : Divise les données en groupes
- **colonne1, colonne2...** : Colonnes utilisées pour créer les groupes

## Exemple détaillé : Moyenne par département

### Données de départ

Table `Employes` :

| EmployeID | Nom | Departement | Salaire |
|-----------|-----|-------------|---------|
| 1 | Dupont | IT | 65000 |
| 2 | Martin | IT | 55000 |
| 3 | Durand | RH | 45000 |
| 4 | Leroy | RH | 47000 |
| 5 | Moreau | Ventes | 50000 |
| 6 | Bernard | Ventes | 54000 |

### Requête avec PARTITION BY

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept
FROM Employes;
```

### Résultat

| Nom | Departement | Salaire | MoyenneDept |
|-----|-------------|---------|-------------|
| Dupont | IT | 65000 | 60000 |
| Martin | IT | 55000 | 60000 |
| Durand | RH | 45000 | 46000 |
| Leroy | RH | 47000 | 46000 |
| Moreau | Ventes | 50000 | 52000 |
| Bernard | Ventes | 54000 | 52000 |

### Explication :
- Les employés IT voient **60000** (moyenne de 65000 et 55000)
- Les employés RH voient **46000** (moyenne de 45000 et 47000)
- Les employés Ventes voient **52000** (moyenne de 50000 et 54000)

**Chaque employé est conservé**, mais la moyenne est calculée **par département** !

## Comparaison : PARTITION BY vs GROUP BY

C'est la question la plus importante à comprendre.

### Avec GROUP BY (Agrégation classique)

```sql
SELECT
    Departement,
    AVG(Salaire) AS MoyenneDept
FROM Employes
GROUP BY Departement;
```

**Résultat : 3 lignes** (une par département)

| Departement | MoyenneDept |
|-------------|-------------|
| IT | 60000 |
| RH | 46000 |
| Ventes | 52000 |

**Nous perdons les noms et salaires individuels !**

### Avec PARTITION BY (Fonction de fenêtrage)

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept
FROM Employes;
```

**Résultat : 6 lignes** (une par employé)

| Nom | Departement | Salaire | MoyenneDept |
|-----|-------------|---------|-------------|
| Dupont | IT | 65000 | 60000 |
| Martin | IT | 55000 | 60000 |
| Durand | RH | 45000 | 46000 |
| Leroy | RH | 47000 | 46000 |
| Moreau | Ventes | 50000 | 52000 |
| Bernard | Ventes | 54000 | 52000 |

**Nous conservons tous les détails !**

## Tableau comparatif

| Aspect | GROUP BY | PARTITION BY |
|--------|----------|--------------|
| **Nombre de lignes** | Réduit (une par groupe) | Conserve toutes les lignes |
| **Détails individuels** | Perdus | Conservés |
| **Colonnes SELECT** | Limitées au GROUP BY + agrégations | Toutes colonnes disponibles |
| **Usage** | Résumé/Rapport agrégé | Analyse détaillée avec contexte |

## Cas d'usage pratiques

### 1. Comparer chaque employé à la moyenne de son département

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept,
    Salaire - AVG(Salaire) OVER(PARTITION BY Departement) AS EcartMoyenne
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | MoyenneDept | EcartMoyenne |
|-----|-------------|---------|-------------|--------------|
| Dupont | IT | 65000 | 60000 | +5000 |
| Martin | IT | 55000 | 60000 | -5000 |
| Durand | RH | 45000 | 46000 | -1000 |
| Leroy | RH | 47000 | 46000 | +1000 |

Vous voyez immédiatement qui est au-dessus ou en-dessous de la moyenne de son département !

### 2. Total des ventes par vendeur ET par région

```sql
SELECT
    NomVendeur,
    Region,
    MontantVente,
    SUM(MontantVente) OVER(PARTITION BY NomVendeur) AS TotalVendeur,
    SUM(MontantVente) OVER(PARTITION BY Region) AS TotalRegion
FROM Ventes;
```

Cette requête montre :
- Chaque vente individuelle
- Le total des ventes de chaque vendeur
- Le total des ventes de chaque région

Tout cela dans une seule requête !

### 3. Compter le nombre d'employés par département

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    COUNT(*) OVER(PARTITION BY Departement) AS NbEmployesDept
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | NbEmployesDept |
|-----|-------------|---------|----------------|
| Dupont | IT | 65000 | 2 |
| Martin | IT | 55000 | 2 |
| Durand | RH | 45000 | 2 |
| Leroy | RH | 47000 | 2 |
| Moreau | Ventes | 50000 | 2 |
| Bernard | Ventes | 54000 | 2 |

### 4. Min et Max par groupe

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    MIN(Salaire) OVER(PARTITION BY Departement) AS SalaireMinDept,
    MAX(Salaire) OVER(PARTITION BY Departement) AS SalaireMaxDept
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | SalaireMinDept | SalaireMaxDept |
|-----|-------------|---------|----------------|----------------|
| Dupont | IT | 65000 | 55000 | 65000 |
| Martin | IT | 55000 | 55000 | 65000 |
| Durand | RH | 45000 | 45000 | 47000 |
| Leroy | RH | 47000 | 45000 | 47000 |

Chaque employé voit le salaire minimum et maximum de son département.

## Partitionnement sur plusieurs colonnes

Vous pouvez partitionner sur **plusieurs colonnes** pour créer des groupes plus spécifiques.

### Exemple : Moyenne par département ET par ville

```sql
SELECT
    Nom,
    Departement,
    Ville,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement, Ville) AS MoyenneDeptVille
FROM Employes;
```

Cela calcule la moyenne pour chaque combinaison unique de (Département, Ville).

### Données exemple :

| Nom | Departement | Ville | Salaire | MoyenneDeptVille |
|-----|-------------|-------|---------|------------------|
| Dupont | IT | Paris | 65000 | 65000 |
| Martin | IT | Lyon | 55000 | 57500 |
| Durand | IT | Lyon | 60000 | 57500 |
| Leroy | RH | Paris | 45000 | 45000 |

**Ici** :
- IT à Paris : moyenne de 65000 (un seul employé)
- IT à Lyon : moyenne de 57500 (Martin et Durand)
- RH à Paris : moyenne de 45000 (un seul employé)

## Combiner avec des calculs

Vous pouvez utiliser la valeur calculée dans d'autres expressions.

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept,
    CASE
        WHEN Salaire > AVG(Salaire) OVER(PARTITION BY Departement)
        THEN 'Au-dessus'
        WHEN Salaire < AVG(Salaire) OVER(PARTITION BY Departement)
        THEN 'En-dessous'
        ELSE 'Égal'
    END AS PositionVsMoyenne
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | MoyenneDept | PositionVsMoyenne |
|-----|-------------|---------|-------------|-------------------|
| Dupont | IT | 65000 | 60000 | Au-dessus |
| Martin | IT | 55000 | 60000 | En-dessous |
| Durand | RH | 45000 | 46000 | En-dessous |
| Leroy | RH | 47000 | 46000 | Au-dessus |

## Alternative aux sous-requêtes corrélées

Avant l'existence de `PARTITION BY`, on utilisait des sous-requêtes corrélées (lentes et complexes).

### Ancienne méthode (Sous-requête corrélée)

```sql
SELECT
    E1.Nom,
    E1.Departement,
    E1.Salaire,
    (SELECT AVG(E2.Salaire)
     FROM Employes E2
     WHERE E2.Departement = E1.Departement) AS MoyenneDept
FROM Employes E1;
```

❌ **Problèmes** :
- Complexe à lire
- Moins performant (sous-requête exécutée pour chaque ligne)
- Difficile à maintenir

### Méthode moderne (PARTITION BY)

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept
FROM Employes;
```

✅ **Avantages** :
- Simple et lisible
- Performant (optimisé par SQL Server)
- Facile à maintenir

## Ordre d'exécution logique

Il est important de comprendre **quand** `PARTITION BY` est évalué dans une requête :

1. **FROM** : Sélection des tables
2. **WHERE** : Filtrage des lignes
3. **GROUP BY** : Regroupement (si présent)
4. **HAVING** : Filtrage des groupes
5. **SELECT** : Sélection des colonnes
6. **Fonctions de fenêtrage (OVER / PARTITION BY)** : Calculs sur les fenêtres
7. **ORDER BY** : Tri final

Cela signifie que :
- Les fonctions de fenêtrage voient les données **après** WHERE
- Elles s'appliquent **avant** ORDER BY
- Vous **ne pouvez pas** utiliser une fonction de fenêtrage dans WHERE

### Exemple : Erreur courante

```sql
-- ❌ ERREUR : Impossible d'utiliser une fonction de fenêtrage dans WHERE
SELECT
    Nom,
    Salaire
FROM Employes
WHERE Salaire > AVG(Salaire) OVER(PARTITION BY Departement);
```

### Solution : Utiliser un CTE ou une sous-requête

```sql
-- ✅ CORRECT : Utiliser un CTE
WITH EmployesAvecMoyenne AS (
    SELECT
        Nom,
        Departement,
        Salaire,
        AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept
    FROM Employes
)
SELECT
    Nom,
    Departement,
    Salaire,
    MoyenneDept
FROM EmployesAvecMoyenne
WHERE Salaire > MoyenneDept;
```

## Points d'attention

### 1. Performance

Les fonctions de fenêtrage sont généralement **très performantes**, mais :
- Sur de très gros volumes, elles peuvent consommer de la mémoire
- Assurez-vous d'avoir des index appropriés sur les colonnes de PARTITION BY
- Évitez de partitionner sur des colonnes avec trop de valeurs uniques (mauvaise cardinalité)

### 2. Différence avec GROUP BY

| Critère | Quand utiliser GROUP BY | Quand utiliser PARTITION BY |
|---------|-------------------------|----------------------------|
| **Besoin** | Résumé agrégé uniquement | Détails + contexte agrégé |
| **Lignes** | Veut réduire les lignes | Veut conserver toutes les lignes |
| **Exemple** | Rapport mensuel des ventes | Liste des ventes avec total mensuel |

### 3. NULL dans PARTITION BY

Les valeurs NULL sont traitées comme un groupe à part entière.

```sql
SELECT
    Nom,
    Departement, -- Peut contenir NULL
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS Moyenne
FROM Employes;
```

Tous les employés avec `Departement = NULL` formeront un groupe séparé.

## Exemple complet : Analyse de performance commerciale

```sql
SELECT
    NomVendeur,
    Region,
    Trimestre,
    ChiffreAffaires,

    -- Total du vendeur
    SUM(ChiffreAffaires) OVER(PARTITION BY NomVendeur) AS TotalVendeur,

    -- Total de la région
    SUM(ChiffreAffaires) OVER(PARTITION BY Region) AS TotalRegion,

    -- Moyenne de la région
    AVG(ChiffreAffaires) OVER(PARTITION BY Region) AS MoyenneRegion,

    -- Écart par rapport à la moyenne régionale
    ChiffreAffaires - AVG(ChiffreAffaires) OVER(PARTITION BY Region) AS EcartMoyenne,

    -- Pourcentage du total régional
    CAST(ChiffreAffaires * 100.0 / SUM(ChiffreAffaires) OVER(PARTITION BY Region) AS DECIMAL(5,2)) AS PourcentageRegion

FROM VentesTrimestrielles;
```

Cette requête fournit une **analyse riche** tout en conservant **chaque ligne de vente** !

## Résumé

| Aspect | Explication |
|--------|-------------|
| **Syntaxe** | `fonction() OVER(PARTITION BY colonne)` |
| **Objectif** | Diviser les données en groupes pour des calculs indépendants |
| **Différence vs GROUP BY** | Conserve toutes les lignes au lieu de les réduire |
| **Partitions multiples** | `PARTITION BY col1, col2` pour des groupes plus spécifiques |
| **Fonctions supportées** | SUM, AVG, COUNT, MIN, MAX, etc. |
| **Avantage principal** | Contexte agrégé disponible sur chaque ligne détaillée |
