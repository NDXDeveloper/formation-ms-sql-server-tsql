# 5.6.2 Fonctions Table (TVF) - En ligne (Inline)

## Introduction

Les **fonctions table en ligne** (ou Inline Table-Valued Functions - TVF) sont des fonctions qui retournent un **ensemble de lignes** (une table) plutôt qu'une seule valeur. Contrairement aux fonctions scalaires qui retournent un seul résultat, les fonctions table inline retournent un jeu de résultats complet que vous pouvez utiliser comme une table dans vos requêtes.

**Analogie simple :** Si une fonction scalaire est comme une calculatrice qui vous donne un seul nombre, une fonction table inline est comme un filtre ou une vue dynamique qui vous donne un ensemble de données basé sur des critères que vous lui fournissez.

---

## Qu'est-ce qu'une fonction table inline ?

Une fonction table inline (TVF inline) est une fonction qui :
- Accepte **zéro ou plusieurs paramètres** en entrée
- **Retourne une table** (un ensemble de lignes et de colonnes)
- Est définie par **une seule requête SELECT**
- Peut être utilisée dans la clause FROM comme si c'était une table ou une vue
- Est **très performante** car elle est intégrée directement dans le plan d'exécution de la requête

**Différence clé avec les fonctions scalaires :**
- Fonction scalaire → retourne **UNE valeur**
- Fonction table inline → retourne **PLUSIEURS lignes**

---

## Syntaxe de base

Voici la structure pour créer une fonction table inline :

```sql
CREATE FUNCTION nom_schema.nom_fonction
(
    @parametre1 type_donnees,
    @parametre2 type_donnees,
    ...
)
RETURNS TABLE
AS
RETURN
(
    -- Une seule requête SELECT
    SELECT
        colonne1,
        colonne2,
        ...
    FROM table
    WHERE condition_utilisant_les_parametres
);
```

**Éléments clés :**
- `CREATE FUNCTION` : Mot-clé pour créer la fonction
- `RETURNS TABLE` : Indique que la fonction retourne une table (pas de structure définie !)
- `AS RETURN` : Directement suivi de la requête SELECT entre parenthèses
- **PAS de BEGIN...END** : C'est une seule instruction SELECT
- La requête SELECT définit implicitement la structure de la table retournée

**Important :** Notez qu'on ne définit PAS la structure de la table retournée - elle est déterminée automatiquement par la requête SELECT.

---

## Exemple 1 : Fonction simple sans paramètre

Créons une fonction qui retourne tous les produits actifs :

```sql
CREATE FUNCTION dbo.ObtenirProduitsActifs()
RETURNS TABLE
AS
RETURN
(
    SELECT
        ProduitID,
        NomProduit,
        PrixUnitaire,
        Stock
    FROM Produits
    WHERE Actif = 1
);
```

**Utilisation :**
```sql
-- Utiliser la fonction comme une table
SELECT * FROM dbo.ObtenirProduitsActifs();

-- Filtrer les résultats de la fonction
SELECT
    NomProduit,
    PrixUnitaire
FROM dbo.ObtenirProduitsActifs()
WHERE PrixUnitaire > 50
ORDER BY PrixUnitaire DESC;

-- Joindre la fonction avec une autre table
SELECT
    c.NomCategorie,
    p.NomProduit,
    p.PrixUnitaire
FROM dbo.ObtenirProduitsActifs() AS p
INNER JOIN Categories AS c ON p.CategorieID = c.CategorieID;
```

**Explication :**
- La fonction retourne toutes les colonnes des produits actifs
- On peut l'utiliser exactement comme une table dans la clause FROM
- On peut la filtrer, la trier, la joindre avec d'autres tables
- Notez l'utilisation d'un alias (AS p) comme pour une table normale

## Exemple 2 : Fonction avec un paramètre

Créons une fonction qui retourne les commandes d'un client spécifique :

```sql
CREATE FUNCTION dbo.ObtenirCommandesClient
(
    @clientID INT
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        CommandeID,
        DateCommande,
        MontantTotal,
        Statut
    FROM Commandes
    WHERE ClientID = @clientID
);
```

**Utilisation :**
```sql
-- Obtenir toutes les commandes du client 5
SELECT * FROM dbo.ObtenirCommandesClient(5);

-- Obtenir uniquement les commandes livrées
SELECT
    CommandeID,
    DateCommande,
    MontantTotal
FROM dbo.ObtenirCommandesClient(5)
WHERE Statut = 'Livré'
ORDER BY DateCommande DESC;

-- Calculer le total des commandes d'un client
SELECT
    SUM(MontantTotal) AS TotalAchats,
    COUNT(*) AS NombreCommandes
FROM dbo.ObtenirCommandesClient(5);
```

**Explication :**
- Le paramètre `@clientID` est utilisé dans la clause WHERE
- La fonction filtre automatiquement les commandes pour ce client
- On peut ensuite appliquer des filtres supplémentaires sur les résultats

## Exemple 3 : Fonction avec plusieurs paramètres

Créons une fonction qui retourne les produits dans une fourchette de prix :

```sql
CREATE FUNCTION dbo.ObtenirProduitsPrix
(
    @prixMin DECIMAL(10,2),
    @prixMax DECIMAL(10,2)
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        ProduitID,
        NomProduit,
        PrixUnitaire,
        Categorie,
        Stock
    FROM Produits
    WHERE PrixUnitaire BETWEEN @prixMin AND @prixMax
        AND Actif = 1
);
```

**Utilisation :**
```sql
-- Produits entre 10€ et 50€
SELECT * FROM dbo.ObtenirProduitsPrix(10.00, 50.00);

-- Compter les produits dans différentes gammes de prix
SELECT
    'Entrée de gamme' AS Gamme,
    COUNT(*) AS NombreProduits
FROM dbo.ObtenirProduitsPrix(0, 20)
UNION ALL
SELECT
    'Milieu de gamme' AS Gamme,
    COUNT(*) AS NombreProduits
FROM dbo.ObtenirProduitsPrix(20, 100)
UNION ALL
SELECT
    'Haut de gamme' AS Gamme,
    COUNT(*) AS NombreProduits
FROM dbo.ObtenirProduitsPrix(100, 9999);
```

## Exemple 4 : Fonction avec jointures

Créons une fonction qui retourne des informations enrichies sur les commandes d'un client :

```sql
CREATE FUNCTION dbo.ObtenirCommandesDetailleesClient
(
    @clientID INT
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        c.CommandeID,
        c.DateCommande,
        c.MontantTotal,
        c.Statut,
        cl.NomClient,
        cl.Email,
        COUNT(dc.DetailID) AS NombreArticles,
        SUM(dc.Quantite) AS QuantiteTotale
    FROM Commandes AS c
    INNER JOIN Clients AS cl ON c.ClientID = cl.ClientID
    LEFT JOIN DetailsCommande AS dc ON c.CommandeID = dc.CommandeID
    WHERE c.ClientID = @clientID
    GROUP BY
        c.CommandeID,
        c.DateCommande,
        c.MontantTotal,
        c.Statut,
        cl.NomClient,
        cl.Email
);
```

**Utilisation :**
```sql
-- Obtenir toutes les informations détaillées
SELECT * FROM dbo.ObtenirCommandesDetailleesClient(5);

-- Filtrer sur les commandes importantes
SELECT
    CommandeID,
    DateCommande,
    MontantTotal,
    NombreArticles
FROM dbo.ObtenirCommandesDetailleesClient(5)
WHERE MontantTotal > 500
ORDER BY DateCommande DESC;
```

**Explication :**
- La fonction effectue des jointures entre plusieurs tables
- Elle effectue des agrégations (COUNT, SUM)
- Tout ceci est encapsulé dans la fonction pour une réutilisation facile

## Exemple 5 : Fonction avec calculs et transformations

Créons une fonction qui retourne des statistiques de ventes par produit pour une période donnée :

```sql
CREATE FUNCTION dbo.ObtenirStatistiquesVentesProduit
(
    @dateDebut DATE,
    @dateFin DATE
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        p.ProduitID,
        p.NomProduit,
        p.PrixUnitaire,
        COUNT(dc.DetailID) AS NombreVentes,
        SUM(dc.Quantite) AS QuantiteVendue,
        SUM(dc.Quantite * dc.PrixUnitaire) AS ChiffreAffaires,
        AVG(CAST(dc.Quantite AS DECIMAL(10,2))) AS QuantiteMoyenne, -- CAST indispensable : sans lui, AVG sur une colonne INT renvoie une moyenne tronquée (division entière)
        MIN(c.DateCommande) AS PremiereVente,
        MAX(c.DateCommande) AS DerniereVente
    FROM Produits AS p
    LEFT JOIN DetailsCommande AS dc ON p.ProduitID = dc.ProduitID
    LEFT JOIN Commandes AS c ON dc.CommandeID = c.CommandeID
    WHERE c.DateCommande BETWEEN @dateDebut AND @dateFin
        OR c.DateCommande IS NULL  -- Inclure les produits sans vente
    GROUP BY
        p.ProduitID,
        p.NomProduit,
        p.PrixUnitaire
);
```

**Utilisation :**
```sql
-- Statistiques du dernier trimestre
SELECT *
FROM dbo.ObtenirStatistiquesVentesProduit('2025-08-01', '2025-10-31')
ORDER BY ChiffreAffaires DESC;

-- Top 10 des meilleurs ventes
SELECT TOP 10
    NomProduit,
    ChiffreAffaires,
    QuantiteVendue
FROM dbo.ObtenirStatistiquesVentesProduit('2025-01-01', '2025-12-31')
ORDER BY ChiffreAffaires DESC;

-- Produits sans aucune vente
SELECT
    NomProduit,
    PrixUnitaire
FROM dbo.ObtenirStatistiquesVentesProduit('2025-01-01', '2025-12-31')
WHERE NombreVentes = 0;
```

## Exemple 6 : Fonction pour filtrage dynamique

Créons une fonction qui recherche des clients selon plusieurs critères optionnels :

```sql
CREATE FUNCTION dbo.RechercherClients
(
    @ville VARCHAR(50),
    @pays VARCHAR(50)
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        ClientID,
        NomClient,
        Email,
        Ville,
        Pays,
        DateInscription
    FROM Clients
    WHERE
        (@ville IS NULL OR Ville = @ville)
        AND (@pays IS NULL OR Pays = @pays)
);
```

**Utilisation :**
```sql
-- Tous les clients de Paris
SELECT * FROM dbo.RechercherClients('Paris', NULL);

-- Tous les clients de France
SELECT * FROM dbo.RechercherClients(NULL, 'France');

-- Clients de Lyon en France
SELECT * FROM dbo.RechercherClients('Lyon', 'France');

-- Tous les clients (si on passe NULL partout)
SELECT * FROM dbo.RechercherClients(NULL, NULL);
```

**Explication :**
- Les conditions `@parametre IS NULL OR colonne = @parametre` permettent de rendre les filtres optionnels
- Si le paramètre est NULL, cette partie de la condition est ignorée
- C'est une technique très utile pour créer des fonctions de recherche flexibles

## Avantages majeurs des fonctions table inline

### 1. Performance excellente

Les fonctions table inline sont **très performantes** car :
- Elles sont **intégrées** dans le plan d'exécution de la requête principale
- L'optimiseur SQL Server peut les optimiser comme si c'était une vue
- Pas d'exécution ligne par ligne comme avec les fonctions scalaires

```sql
-- Ces deux requêtes auront des performances similaires :

-- Avec fonction inline
SELECT *
FROM dbo.ObtenirProduitsActifs()
WHERE PrixUnitaire > 50;

-- Requête directe équivalente
SELECT *
FROM Produits
WHERE Actif = 1 AND PrixUnitaire > 50;
```

### 2. Réutilisabilité et encapsulation

```sql
-- Au lieu de répéter cette logique complexe partout :
SELECT p.*, c.NomCategorie, ...
FROM Produits AS p
INNER JOIN Categories AS c ON p.CategorieID = c.CategorieID
WHERE p.Actif = 1 AND p.Stock > 0 AND ...;

-- Vous créez une fonction une fois :
CREATE FUNCTION dbo.ObtenirProduitsDisponibles()
RETURNS TABLE AS RETURN (
    SELECT p.*, c.NomCategorie, ...
    FROM Produits AS p
    INNER JOIN Categories AS c ON p.CategorieID = c.CategorieID
    WHERE p.Actif = 1 AND p.Stock > 0 AND ...
);

-- Et vous l'utilisez simplement :
SELECT * FROM dbo.ObtenirProduitsDisponibles();
```

### 3. Paramétrisation de vues

Les vues ne peuvent pas avoir de paramètres, mais les fonctions table inline oui :

```sql
-- Une vue ne peut pas faire ça :
CREATE VIEW VueCommandesClient AS
SELECT * FROM Commandes WHERE ClientID = ???  -- Impossible !

-- Mais une fonction table inline oui :
CREATE FUNCTION ObtenirCommandesClient(@clientID INT)
RETURNS TABLE AS RETURN (
    SELECT * FROM Commandes WHERE ClientID = @clientID
);
```

### 4. Simplification des requêtes complexes

```sql
-- Au lieu d'une requête compliquée et difficile à lire :
SELECT
    c.ClientID,
    c.NomClient,
    (SELECT SUM(MontantTotal)
     FROM Commandes
     WHERE ClientID = c.ClientID
       AND YEAR(DateCommande) = 2025) AS Total2025
FROM Clients AS c;

-- Créez une fonction claire :
CREATE FUNCTION dbo.ObtenirTotalCommandesClientAnnee
(
    @clientID INT,
    @annee INT
)
RETURNS TABLE AS RETURN (
    SELECT SUM(MontantTotal) AS Total
    FROM Commandes
    WHERE ClientID = @clientID AND YEAR(DateCommande) = @annee
);

-- Et utilisez-la simplement :
SELECT
    c.ClientID,
    c.NomClient,
    t.Total AS Total2025
FROM Clients AS c
CROSS APPLY dbo.ObtenirTotalCommandesClientAnnee(c.ClientID, 2025) AS t;
```

## Différences avec les fonctions scalaires

| Aspect | Fonction Scalaire | Fonction Table Inline |
|--------|------------------|----------------------|
| **Retour** | Une seule valeur | Plusieurs lignes (table) |
| **Syntaxe** | BEGIN...END avec RETURN | AS RETURN (SELECT...) |
| **Performance** | ❌ Souvent lente | ✅ Excellente |
| **Utilisation** | Dans SELECT, WHERE, etc. | Dans FROM (comme une table) |
| **Optimisation** | Limitée | Complète |
| **Cas d'usage** | Calculs simples | Ensembles de données |

**Exemple de conversion :**

```sql
-- ❌ Fonction scalaire (peut être lente)
CREATE FUNCTION dbo.CompterCommandesClient(@clientID INT)
RETURNS INT
AS BEGIN
    DECLARE @count INT;
    SELECT @count = COUNT(*) FROM Commandes WHERE ClientID = @clientID;
    RETURN @count;
END;

-- Utilisation :
SELECT ClientID, dbo.CompterCommandesClient(ClientID) AS NbCommandes
FROM Clients;

-- ✅ Fonction table inline (beaucoup plus performante)
CREATE FUNCTION dbo.ObtenirStatsCommandes(@clientID INT)
RETURNS TABLE AS RETURN (
    SELECT
        COUNT(*) AS NbCommandes,
        SUM(MontantTotal) AS TotalAchats
    FROM Commandes
    WHERE ClientID = @clientID
);

-- Utilisation :
SELECT
    c.ClientID,
    s.NbCommandes,
    s.TotalAchats
FROM Clients AS c
CROSS APPLY dbo.ObtenirStatsCommandes(c.ClientID) AS s;
```

## Utilisation avec APPLY

Les fonctions table inline sont souvent utilisées avec les opérateurs `CROSS APPLY` et `OUTER APPLY` pour des requêtes avancées.

### CROSS APPLY

```sql
-- Pour chaque client, obtenir ses 3 dernières commandes
SELECT
    c.ClientID,
    c.NomClient,
    cmd.CommandeID,
    cmd.DateCommande,
    cmd.MontantTotal
FROM Clients AS c
CROSS APPLY (
    SELECT TOP 3
        CommandeID,
        DateCommande,
        MontantTotal
    FROM Commandes
    WHERE ClientID = c.ClientID
    ORDER BY DateCommande DESC
) AS cmd;

-- Avec une fonction inline, c'est encore plus clair :
CREATE FUNCTION dbo.ObtenirDernieresCommandes
(
    @clientID INT,
    @nombre INT
)
RETURNS TABLE AS RETURN (
    SELECT TOP (@nombre)
        CommandeID,
        DateCommande,
        MontantTotal
    FROM Commandes
    WHERE ClientID = @clientID
    ORDER BY DateCommande DESC
);

-- Utilisation :
SELECT
    c.ClientID,
    c.NomClient,
    cmd.CommandeID,
    cmd.DateCommande
FROM Clients AS c
CROSS APPLY dbo.ObtenirDernieresCommandes(c.ClientID, 3) AS cmd;
```

### OUTER APPLY

```sql
-- Comme LEFT JOIN, mais avec une fonction
SELECT
    c.ClientID,
    c.NomClient,
    ISNULL(cmd.CommandeID, 0) AS DerniereCommandeID,
    cmd.DateCommande
FROM Clients AS c
OUTER APPLY (
    SELECT TOP 1
        CommandeID,
        DateCommande
    FROM Commandes
    WHERE ClientID = c.ClientID
    ORDER BY DateCommande DESC
) AS cmd;
```

**Différence :**
- `CROSS APPLY` : comme INNER JOIN (ne retourne que les clients qui ont des commandes)
- `OUTER APPLY` : comme LEFT JOIN (retourne tous les clients, même sans commandes)

## Limitations et contraintes

### 1. Une seule instruction SELECT

Une fonction table inline doit contenir **une seule** instruction SELECT. Vous ne pouvez pas :
- Utiliser plusieurs SELECT
- Déclarer des variables temporaires
- Utiliser des boucles ou conditions (IF/WHILE)

```sql
-- ❌ Ceci n'est PAS possible dans une fonction inline
CREATE FUNCTION dbo.Exemple()
RETURNS TABLE AS RETURN (
    DECLARE @temp INT;  -- ERREUR !
    SET @temp = 5;      -- ERREUR !
    SELECT * FROM Table WHERE ID = @temp;
);
```

Pour des logiques plus complexes, vous devrez utiliser une **fonction table multi-instructions** (vue dans la section suivante).

### 2. Pas de modifications de données

Comme toutes les fonctions, vous ne pouvez pas :
- Insérer, modifier ou supprimer des données (INSERT, UPDATE, DELETE)
- Créer ou modifier des objets
- Utiliser des transactions explicites

### 3. Restrictions sur certaines fonctions non-déterministes

Attention : certaines fonctions non-déterministes sont **interdites** dans *toute* fonction utilisateur (scalaire, inline ou multi-instructions) :
- ✅ `GETDATE()`, `GETUTCDATE()`, `CURRENT_TIMESTAMP` : **autorisées** (elles rendent simplement la fonction non-déterministe)
- ❌ `NEWID()`, `NEWSEQUENTIALID()`, `RAND()`, `TEXTPTR()` : **interdites** — elles déclenchent l'erreur *Msg 443 : « Invalid use of a side-effecting operator within a function »*

> 💡 **Contournement** : si vous avez absolument besoin de `NEWID()` (ou `RAND()`) dans une fonction, encapsulez l'appel dans une **vue**, puis interrogez cette vue depuis la fonction.

## Modifier ou supprimer une fonction

### Modifier une fonction existante

Utilisez `ALTER FUNCTION` :

```sql
ALTER FUNCTION dbo.ObtenirCommandesClient
(
    @clientID INT
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        CommandeID,
        DateCommande,
        MontantTotal,
        Statut,
        DateLivraison  -- Nouvelle colonne ajoutée
    FROM Commandes
    WHERE ClientID = @clientID
        AND Statut != 'Annulé'  -- Nouveau filtre
);
```

### Supprimer une fonction

```sql
DROP FUNCTION IF EXISTS dbo.ObtenirCommandesClient;
```

## Bonnes pratiques

### 1. Nommage explicite

Utilisez des noms qui indiquent clairement que c'est une fonction qui retourne des données :

```sql
-- ✅ Bon
dbo.ObtenirCommandesClient
dbo.RechercherProduits
dbo.FiltrerVentesParPeriode

-- ❌ Moins clair
dbo.Commandes
dbo.Produits
dbo.Ventes
```

### 2. Documentation

Ajoutez des commentaires explicatifs :

```sql
/*
Fonction : dbo.ObtenirCommandesClient
Description : Retourne toutes les commandes d'un client spécifique
Paramètres :
    @clientID INT - Identifiant du client
Retourne : Table avec CommandeID, DateCommande, MontantTotal, Statut
Auteur : Votre Nom
Date : 2025-11-18
*/
CREATE FUNCTION dbo.ObtenirCommandesClient
(
    @clientID INT
)
RETURNS TABLE
AS
RETURN
(
    ...
);
```

### 3. Validation des paramètres

Si possible, ajoutez des validations directement dans le WHERE :

```sql
CREATE FUNCTION dbo.ObtenirProduitsCategorie
(
    @categorieID INT
)
RETURNS TABLE
AS
RETURN
(
    SELECT *
    FROM Produits
    WHERE CategorieID = @categorieID
        AND @categorieID > 0  -- Validation simple
);
```

### 4. Préférez les fonctions inline aux scalaires

Quand c'est possible, utilisez des fonctions inline plutôt que scalaires pour de meilleures performances :

```sql
-- ❌ Fonction scalaire
SELECT ClientID, dbo.CalculerTotalCommandes(ClientID) AS Total
FROM Clients;

-- ✅ Fonction inline avec CROSS APPLY
SELECT c.ClientID, t.Total
FROM Clients AS c
CROSS APPLY dbo.ObtenirTotalCommandesClient(c.ClientID) AS t;
```

## Cas d'usage pratiques

### 1. Filtres réutilisables

```sql
-- Pour les rapports qui nécessitent toujours les mêmes filtres complexes
CREATE FUNCTION dbo.ObtenirTransactionsValides
(
    @dateDebut DATE,
    @dateFin DATE
)
RETURNS TABLE AS RETURN (
    SELECT t.*
    FROM Transactions AS t
    WHERE t.DateTransaction BETWEEN @dateDebut AND @dateFin
        AND t.Statut = 'Validé'
        AND t.MontantHT > 0
        AND t.Supprime = 0
);
```

### 2. Vues paramétrées

```sql
-- Quand vous avez besoin d'une "vue" mais avec des paramètres
CREATE FUNCTION dbo.ObtenirVentesMois
(
    @annee INT,
    @mois INT
)
RETURNS TABLE AS RETURN (
    SELECT
        DATEPART(DAY, DateVente) AS Jour,
        SUM(MontantTotal) AS CA_Jour,
        COUNT(*) AS NombreVentes
    FROM Ventes
    WHERE YEAR(DateVente) = @annee
        AND MONTH(DateVente) = @mois
    GROUP BY DATEPART(DAY, DateVente)
);
```

### 3. Hiérarchies et dépendances

```sql
-- Pour naviguer dans des structures hiérarchiques
CREATE FUNCTION dbo.ObtenirSousCategories
(
    @categorieParentID INT
)
RETURNS TABLE AS RETURN (
    SELECT
        CategorieID,
        NomCategorie,
        Niveau
    FROM Categories
    WHERE ParentID = @categorieParentID
);
```

## Résumé

Les **fonctions table inline** (TVF inline) sont un outil puissant et performant en T-SQL pour :
- Encapsuler des requêtes complexes réutilisables
- Créer des "vues paramétrées"
- Retourner des ensembles de données basés sur des paramètres
- Simplifier le code et améliorer la maintenance

**Points clés à retenir :**
- Elles retournent une **table** (plusieurs lignes)
- Elles contiennent **une seule requête SELECT**
- Elles sont **très performantes** (optimisées comme des vues)
- Elles s'utilisent dans la clause **FROM** comme une table
- Elles sont souvent utilisées avec **APPLY**

**Quand les utiliser :**
- ✅ Pour des ensembles de données paramétrés
- ✅ Pour remplacer des vues qui nécessiteraient des paramètres
- ✅ Pour encapsuler des jointures complexes
- ✅ Avec APPLY pour des requêtes corrélées

**À privilégier par rapport aux fonctions scalaires** pour des raisons de performance !
