# 1.3.2 Les Sous-langages : DDL, DML, DCL, TCL

## Introduction

Vous savez maintenant que T-SQL est le langage utilisé pour communiquer avec SQL Server. Mais T-SQL n'est pas un bloc monolithique : il est organisé en **plusieurs sous-langages**, chacun ayant un rôle spécifique.

### Analogie : Les outils d'un artisan

Imaginez un menuisier qui construit des meubles :
- 🔨 Des **outils pour construire** la structure (scie, marteau) → **DDL**
- 🪛 Des **outils pour travailler** le bois (rabot, ciseau) → **DML**
- 🔒 Des **outils pour sécuriser** l'atelier (cadenas, alarme) → **DCL**
- ✅ Des **outils pour valider** le travail (niveau, équerre) → **TCL**

De même, T-SQL est divisé en sous-langages selon la **nature des opérations** que vous voulez effectuer.

## Les quatre sous-langages principaux

T-SQL se divise traditionnellement en **quatre catégories** de commandes :

| Sous-langage | Signification | Rôle principal |
|--------------|---------------|----------------|
| **DDL** | Data Definition Language | Définir la **structure** |
| **DML** | Data Manipulation Language | Manipuler les **données** |
| **DCL** | Data Control Language | Contrôler les **accès** |
| **TCL** | Transaction Control Language | Gérer les **transactions** |

## 1. DDL - Data Definition Language

### Qu'est-ce que le DDL ?

**DDL** (Data Definition Language) est le sous-langage qui permet de **définir et modifier la structure** de la base de données.

**En termes simples :** C'est comme l'**architecte** qui dessine les plans d'une maison avant de la construire.

### Analogie : Construire une maison

- **CREATE** : Construire une nouvelle maison
- **ALTER** : Rénover, ajouter une pièce, modifier la structure
- **DROP** : Démolir complètement la maison
- **TRUNCATE** : Vider la maison de tous ses meubles (mais garder la structure)

### Les commandes DDL principales

#### CREATE - Créer des objets

**Rôle :** Créer de nouveaux objets de base de données.

**Objets créables :**
- Bases de données
- Tables
- Vues
- Index
- Procédures stockées
- Fonctions
- Triggers
- Et plus...

**Exemples :**

**Créer une base de données :**
```sql
CREATE DATABASE MaBoutique;
```

**Créer une table :**
```sql
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY IDENTITY(1,1),
    Nom NVARCHAR(50) NOT NULL,
    Prenom NVARCHAR(50) NOT NULL,
    Email NVARCHAR(100) UNIQUE,
    DateInscription DATE DEFAULT GETDATE()
);
```

**Créer une vue :**
```sql
CREATE VIEW Vue_ClientsParis AS
SELECT ClientID, Nom, Prenom, Email
FROM Clients
WHERE Ville = 'Paris';
```

**Créer un index :**
```sql
CREATE INDEX IX_Clients_Email
ON Clients(Email);
```

#### ALTER - Modifier des objets

**Rôle :** Modifier la structure d'objets existants.

**Exemples :**

**Ajouter une colonne à une table :**
```sql
ALTER TABLE Clients
ADD Telephone NVARCHAR(20);
```

**Modifier le type d'une colonne :**
```sql
ALTER TABLE Clients
ALTER COLUMN Email NVARCHAR(150);
```

**Supprimer une colonne :**
```sql
ALTER TABLE Clients
DROP COLUMN Fax;
```

**Ajouter une contrainte :**
```sql
ALTER TABLE Commandes
ADD CONSTRAINT FK_Commandes_Clients
FOREIGN KEY (ClientID) REFERENCES Clients(ClientID);
```

#### DROP - Supprimer des objets

**Rôle :** Supprimer définitivement des objets de la base de données.

⚠️ **ATTENTION** : DROP est **irréversible** ! L'objet et toutes ses données sont **perdus**.

**Exemples :**

**Supprimer une table :**
```sql
DROP TABLE ClientsArchives;
```

**Supprimer une base de données :**
```sql
DROP DATABASE AncienneBD;
```

**Supprimer un index :**
```sql
DROP INDEX IX_Clients_Email ON Clients;
```

#### TRUNCATE - Vider une table

**Rôle :** Supprimer **toutes les lignes** d'une table, mais **conserver la structure**.

**Différence avec DELETE :**
- **TRUNCATE** : Supprime tout rapidement, réinitialise les compteurs IDENTITY
- **DELETE** : Peut supprimer ligne par ligne avec WHERE, plus lent

**Exemple :**
```sql
TRUNCATE TABLE LogsTemporaires;
```

**Résultat :** La table `LogsTemporaires` existe toujours, mais elle est vide.

### Tableau récapitulatif DDL

| Commande | Action | Exemple |
|----------|--------|---------|
| **CREATE** | Créer un objet | `CREATE TABLE Produits (...)` |
| **ALTER** | Modifier un objet | `ALTER TABLE Produits ADD Prix DECIMAL(10,2)` |
| **DROP** | Supprimer un objet | `DROP TABLE ProduitsObsoletes` |
| **TRUNCATE** | Vider une table | `TRUNCATE TABLE Logs` |

### Qui utilise le DDL ?

- 👨‍💼 **Administrateurs de bases de données (DBA)**
- 🏗️ **Architectes de données**
- 👨‍💻 **Développeurs** (lors de la création initiale ou des migrations)

**Fréquence :** Occasionnelle (au début du projet, lors de changements de structure)

## 2. DML - Data Manipulation Language

### Qu'est-ce que le DML ?

**DML** (Data Manipulation Language) est le sous-langage qui permet de **manipuler les données** dans les tables.

**En termes simples :** C'est comme remplir, lire, modifier ou vider les tiroirs d'un meuble (la structure existe déjà).

### Analogie : Gérer une bibliothèque

- **INSERT** : Ajouter de nouveaux livres sur les étagères
- **SELECT** : Chercher et consulter des livres
- **UPDATE** : Mettre à jour les informations d'un livre (édition révisée)
- **DELETE** : Retirer des livres des étagères

### Les commandes DML principales

#### SELECT - Lire des données

**Rôle :** **Interroger** la base de données pour récupérer des informations.

C'est la commande **la plus utilisée** en SQL !

**Structure de base :**
```sql
SELECT colonnes
FROM table
WHERE conditions
ORDER BY colonnes;
```

**Exemples :**

**Sélectionner toutes les colonnes :**
```sql
SELECT * FROM Clients;
```

**Sélectionner des colonnes spécifiques :**
```sql
SELECT Nom, Prenom, Email FROM Clients;
```

**Avec une condition :**
```sql
SELECT Nom, Prenom
FROM Clients
WHERE Ville = 'Paris';
```

**Avec tri :**
```sql
SELECT Nom, Prenom, DateInscription
FROM Clients
ORDER BY DateInscription DESC;
```

**Avec agrégation :**
```sql
SELECT Ville, COUNT(*) AS NombreClients
FROM Clients
GROUP BY Ville;
```

#### INSERT - Ajouter des données

**Rôle :** **Insérer** de nouvelles lignes dans une table.

**Structure de base :**
```sql
INSERT INTO table (colonne1, colonne2, ...)
VALUES (valeur1, valeur2, ...);
```

**Exemples :**

**Insérer une ligne :**
```sql
INSERT INTO Clients (Nom, Prenom, Email, Ville)
VALUES ('Dupont', 'Jean', 'jean.dupont@email.com', 'Paris');
```

**Insérer plusieurs lignes :**
```sql
INSERT INTO Clients (Nom, Prenom, Email, Ville)
VALUES
    ('Martin', 'Marie', 'marie.martin@email.com', 'Lyon'),
    ('Bernard', 'Paul', 'paul.bernard@email.com', 'Marseille'),
    ('Durand', 'Sophie', 'sophie.durand@email.com', 'Paris');
```

**Insérer à partir d'une autre table :**
```sql
INSERT INTO ClientsArchives (Nom, Prenom, Email)
SELECT Nom, Prenom, Email
FROM Clients
WHERE DateInscription < '2020-01-01';
```

#### UPDATE - Modifier des données

**Rôle :** **Mettre à jour** des données existantes.

⚠️ **ATTENTION** : Sans clause WHERE, **toutes les lignes** sont modifiées !

**Structure de base :**
```sql
UPDATE table
SET colonne1 = nouvelle_valeur1,
    colonne2 = nouvelle_valeur2
WHERE condition;
```

**Exemples :**

**Modifier une ligne spécifique :**
```sql
UPDATE Clients
SET Telephone = '0612345678'
WHERE ClientID = 123;
```

**Modifier plusieurs colonnes :**
```sql
UPDATE Clients
SET Email = 'nouveau.email@example.com',
    Ville = 'Toulouse'
WHERE ClientID = 456;
```

**Modifier plusieurs lignes :**
```sql
UPDATE Produits
SET Prix = Prix * 1.10  -- Augmentation de 10%
WHERE Categorie = 'Electronique';
```

**⚠️ DANGER - Sans WHERE (modifie TOUT) :**
```sql
UPDATE Clients
SET Ville = 'Paris';  -- TOUS les clients auront Paris comme ville !
```

#### DELETE - Supprimer des données

**Rôle :** **Supprimer** des lignes d'une table.

⚠️ **ATTENTION** : Sans clause WHERE, **toutes les lignes** sont supprimées !

**Structure de base :**
```sql
DELETE FROM table
WHERE condition;
```

**Exemples :**

**Supprimer une ligne spécifique :**
```sql
DELETE FROM Clients
WHERE ClientID = 789;
```

**Supprimer plusieurs lignes :**
```sql
DELETE FROM Commandes
WHERE DateCommande < '2020-01-01';
```

**Supprimer avec sous-requête :**
```sql
DELETE FROM Clients
WHERE ClientID IN (
    SELECT ClientID
    FROM Commandes
    WHERE Statut = 'Annulée'
);
```

**⚠️ DANGER - Sans WHERE (supprime TOUT) :**
```sql
DELETE FROM Clients;  -- TOUS les clients sont supprimés !
```

### L'acronyme CRUD

Les opérations DML sont souvent résumées par l'acronyme **CRUD** :

| Lettre | Signification | Commande SQL |
|--------|---------------|--------------|
| **C** | Create (Créer) | INSERT |
| **R** | Read (Lire) | SELECT |
| **U** | Update (Mettre à jour) | UPDATE |
| **D** | Delete (Supprimer) | DELETE |

**Ces quatre opérations représentent 90% de ce que vous ferez au quotidien avec une base de données !**

### Tableau récapitulatif DML

| Commande | Action | Exemple |
|----------|--------|---------|
| **SELECT** | Lire/Interroger | `SELECT * FROM Clients WHERE Ville = 'Paris'` |
| **INSERT** | Ajouter | `INSERT INTO Clients (...) VALUES (...)` |
| **UPDATE** | Modifier | `UPDATE Clients SET Email = '...' WHERE ClientID = 1` |
| **DELETE** | Supprimer | `DELETE FROM Clients WHERE ClientID = 1` |

### Qui utilise le DML ?

- 👨‍💻 **Développeurs** (quotidiennement)
- 📊 **Analystes de données** (principalement SELECT)
- 🧪 **Testeurs** (création de données de test)
- 👥 **Utilisateurs finaux** (via des applications)

**Fréquence :** **Très élevée** (plusieurs fois par minute dans une application en production)

## 3. DCL - Data Control Language

### Qu'est-ce que le DCL ?

**DCL** (Data Control Language) est le sous-langage qui permet de **contrôler les accès** et les permissions sur les objets de la base de données.

**En termes simples :** C'est comme un **système de badges** dans un bâtiment qui détermine qui peut accéder à quelles pièces.

### Analogie : Sécurité d'un immeuble

- **GRANT** : Donner un badge d'accès à quelqu'un
- **DENY** : Interdire explicitement l'accès (même si un autre badge le permettrait)
- **REVOKE** : Retirer un badge d'accès

### Les commandes DCL principales

#### GRANT - Accorder des permissions

**Rôle :** **Autoriser** un utilisateur ou un rôle à effectuer certaines actions.

**Structure de base :**
```sql
GRANT permission ON objet TO utilisateur;
```

**Exemples :**

**Autoriser la lecture d'une table :**
```sql
GRANT SELECT ON Clients TO Utilisateur_Jean;
```

**Autoriser plusieurs permissions :**
```sql
GRANT SELECT, INSERT, UPDATE ON Produits TO Utilisateur_Marie;
```

**Autoriser toutes les permissions sur une table :**
```sql
GRANT ALL ON Commandes TO Role_Gestionnaires;
```

**Autoriser l'exécution d'une procédure stockée :**
```sql
GRANT EXECUTE ON dbo.AjouterClient TO Utilisateur_App;
```

**Autoriser avec droit de transmission (WITH GRANT OPTION) :**
```sql
GRANT SELECT ON Clients TO Utilisateur_Admin WITH GRANT OPTION;
-- L'admin peut maintenant donner ce droit à d'autres
```

#### DENY - Refuser des permissions

**Rôle :** **Interdire explicitement** une action, même si d'autres permissions pourraient la permettre.

⚠️ **DENY est plus fort que GRANT !**

**Structure de base :**
```sql
DENY permission ON objet TO utilisateur;
```

**Exemples :**

**Interdire la suppression :**
```sql
DENY DELETE ON Clients TO Utilisateur_Stagiaire;
```

**Interdire la modification de colonnes sensibles :**
```sql
DENY UPDATE ON Employes(Salaire) TO Role_Managers;
```

**Pourquoi utiliser DENY ?**

Imaginez qu'un utilisateur appartient à deux groupes :
- Groupe A : A le droit SELECT sur Clients
- Groupe B : A le droit SELECT sur toutes les tables

Sans DENY, l'utilisateur aurait accès à Clients. Avec DENY, vous pouvez bloquer explicitement :

```sql
DENY SELECT ON Clients TO Utilisateur_Particulier;
```

#### REVOKE - Retirer des permissions

**Rôle :** **Annuler** une permission précédemment accordée (ou refusée).

**Structure de base :**
```sql
REVOKE permission ON objet FROM utilisateur;
```

**Exemples :**

**Retirer un droit accordé :**
```sql
REVOKE INSERT ON Produits FROM Utilisateur_Jean;
```

**Retirer un DENY** (un simple `REVOKE` annule aussi bien un `GRANT` qu'un `DENY`) **:**
```sql
REVOKE DELETE ON Clients FROM Utilisateur_Stagiaire;
```

**Retirer toutes les permissions :**
```sql
REVOKE ALL ON Commandes FROM Utilisateur_Temporaire;
```

### Hiérarchie des permissions

```
DENY > GRANT > Aucune permission

Explication :
- Si un utilisateur a DENY : Accès refusé (peu importe les autres droits)
- Si un utilisateur a GRANT : Accès autorisé
- Si aucune permission : Accès refusé (par défaut)
```

### Tableau récapitulatif DCL

| Commande | Action | Exemple |
|----------|--------|---------|
| **GRANT** | Accorder une permission | `GRANT SELECT ON Clients TO User1` |
| **DENY** | Refuser une permission | `DENY DELETE ON Clients TO User2` |
| **REVOKE** | Retirer une permission | `REVOKE INSERT ON Produits FROM User3` |

### Types de permissions courants

| Permission | Description |
|------------|-------------|
| **SELECT** | Lire les données |
| **INSERT** | Ajouter des données |
| **UPDATE** | Modifier des données |
| **DELETE** | Supprimer des données |
| **EXECUTE** | Exécuter des procédures/fonctions |
| **ALTER** | Modifier la structure |
| **CREATE** | Créer des objets |
| **DROP** | Supprimer des objets |
| **ALL** | Toutes les permissions |

### Qui utilise le DCL ?

- 🔐 **Administrateurs de bases de données (DBA)**
- 👮 **Responsables sécurité**
- 👨‍💼 **Administrateurs système**

**Fréquence :** Occasionnelle (lors de la création d'utilisateurs, changements d'organisation)

## 4. TCL - Transaction Control Language

### Qu'est-ce que le TCL ?

**TCL** (Transaction Control Language) est le sous-langage qui permet de **gérer les transactions** : valider ou annuler des groupes d'opérations.

**En termes simples :** C'est comme un système de **sauvegarde/annulation** pour vos modifications.

### Qu'est-ce qu'une transaction ?

Une **transaction** est un **groupe d'opérations** qui doivent toutes réussir ou toutes échouer ensemble.

**Propriété ACID :**
- **A**tomicité : Tout ou rien
- **C**ohérence : Les données restent valides
- **I**solation : Les transactions ne s'interfèrent pas
- **D**urabilité : Une fois validée, c'est permanent

### Analogie : Transaction bancaire

Imaginez un virement bancaire :

```
1. Débiter 100€ du compte A
2. Créditer 100€ sur le compte B
```

**Sans transaction :**
- Si l'opération 1 réussit mais l'opération 2 échoue → 100€ disparaissent ! ❌

**Avec transaction :**
- Les deux opérations sont liées
- Si l'une échoue, l'ensemble est annulé (on revient à l'état initial) avec un `ROLLBACK`
- Les deux réussissent ou les deux échouent ✅

### Les commandes TCL principales

#### BEGIN TRANSACTION - Démarrer une transaction

**Rôle :** **Marquer le début** d'un bloc de transactions.

**Syntaxe :**
```sql
BEGIN TRANSACTION;
-- ou simplement
BEGIN TRAN;
```

#### COMMIT - Valider une transaction

**Rôle :** **Valider** définitivement toutes les modifications depuis BEGIN TRANSACTION.

**Syntaxe :**
```sql
COMMIT TRANSACTION;
-- ou simplement
COMMIT;
```

#### ROLLBACK - Annuler une transaction

**Rôle :** **Annuler** toutes les modifications depuis BEGIN TRANSACTION.

**Syntaxe :**
```sql
ROLLBACK TRANSACTION;
-- ou simplement
ROLLBACK;
```

#### SAVE TRANSACTION - Point de sauvegarde

**Rôle :** Créer un **point de sauvegarde** à l'intérieur d'une transaction pour y revenir si nécessaire.

**Syntaxe :**
```sql
SAVE TRANSACTION nom_point_sauvegarde;
```

### Exemple complet de transaction

**Scénario : Transfert d'argent entre deux comptes**

```sql
-- Démarrer la transaction
BEGIN TRANSACTION;

    -- Étape 1 : Débiter le compte source
    UPDATE Comptes
    SET Solde = Solde - 100
    WHERE CompteID = 1;

    -- Vérifier que le compte n'est pas à découvert
    IF (SELECT Solde FROM Comptes WHERE CompteID = 1) < 0
    BEGIN
        -- Annuler si découvert
        ROLLBACK TRANSACTION;
        PRINT 'Transaction annulée : Solde insuffisant';
        RETURN;
    END

    -- Étape 2 : Créditer le compte destination
    UPDATE Comptes
    SET Solde = Solde + 100
    WHERE CompteID = 2;

    -- Tout s'est bien passé, on valide
    COMMIT TRANSACTION;
    PRINT 'Transaction réussie : 100€ transférés';
```

### Exemple avec point de sauvegarde

```sql
BEGIN TRANSACTION;

    INSERT INTO Clients (Nom) VALUES ('Client A');

    -- Point de sauvegarde
    SAVE TRANSACTION Point1;

    INSERT INTO Clients (Nom) VALUES ('Client B');

    -- Oups, erreur pour Client B, on revient au point 1
    ROLLBACK TRANSACTION Point1;

    INSERT INTO Clients (Nom) VALUES ('Client C');

    -- Valider (Client A et C sont ajoutés, pas B)
    COMMIT TRANSACTION;
```

### Transactions automatiques (autocommit) vs explicites

#### Transactions explicites (recommandées)

Vous contrôlez manuellement avec BEGIN/COMMIT/ROLLBACK :

```sql
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.10;
COMMIT;
```

#### Mode autocommit (par défaut)

Par défaut, SQL Server est en mode **autocommit** : chaque instruction forme sa propre transaction, automatiquement validée si elle réussit :

```sql
UPDATE Produits SET Prix = Prix * 1.10;
-- Automatiquement validée (committée) si elle réussit
```

> ℹ️ À ne pas confondre avec le mode **« transactions implicites »** (`SET IMPLICIT_TRANSACTIONS ON`), où une transaction s'ouvre automatiquement mais doit être validée **manuellement** par `COMMIT`. Ce mode (et la distinction implicite/explicite) est détaillé au §6.2.5.

### Tableau récapitulatif TCL

| Commande | Action | Exemple |
|----------|--------|---------|
| **BEGIN TRANSACTION** | Démarrer une transaction | `BEGIN TRAN;` |
| **COMMIT** | Valider les changements | `COMMIT;` |
| **ROLLBACK** | Annuler les changements | `ROLLBACK;` |
| **SAVE TRANSACTION** | Créer un point de sauvegarde | `SAVE TRAN Point1;` |

### Qui utilise le TCL ?

- 👨‍💻 **Développeurs** (pour sécuriser les opérations critiques)
- 🧪 **Testeurs** (pour annuler facilement des tests)
- 👨‍💼 **Administrateurs** (pour des opérations de maintenance)

**Fréquence :** Régulière (dans les procédures stockées, opérations critiques)

## Tableau récapitulatif général des sous-langages

| Sous-langage | Objectif | Commandes | Utilisateurs | Fréquence |
|--------------|----------|-----------|--------------|-----------|
| **DDL** | Structure | CREATE, ALTER, DROP, TRUNCATE | DBA, Architectes | Occasionnelle |
| **DML** | Données | SELECT, INSERT, UPDATE, DELETE | Développeurs, Analystes | Très élevée |
| **DCL** | Sécurité | GRANT, DENY, REVOKE | DBA, Sécurité | Occasionnelle |
| **TCL** | Transactions | BEGIN, COMMIT, ROLLBACK, SAVE | Développeurs, DBA | Régulière |

## Scénario complet : Utilisation des 4 sous-langages

Imaginons le cycle de vie d'une application de e-commerce :

### Phase 1 : Création (DDL)

**L'architecte crée la structure :**

```sql
-- Créer la base de données
CREATE DATABASE Boutique;

-- Créer les tables
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY IDENTITY(1,1),
    Nom NVARCHAR(50) NOT NULL,
    Email NVARCHAR(100)
);

CREATE TABLE Produits (
    ProduitID INT PRIMARY KEY IDENTITY(1,1),
    Nom NVARCHAR(100),
    Prix DECIMAL(10,2)
);

CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY IDENTITY(1,1),
    ClientID INT,
    DateCommande DATETIME DEFAULT GETDATE(),
    FOREIGN KEY (ClientID) REFERENCES Clients(ClientID)
);
```

### Phase 2 : Sécurisation (DCL)

**L'administrateur configure les accès :**

```sql
-- Créer des utilisateurs
CREATE LOGIN App_User WITH PASSWORD = 'MotDePasse123!';
CREATE USER App_User FOR LOGIN App_User;

-- Donner les droits appropriés
GRANT SELECT, INSERT, UPDATE ON Clients TO App_User;
GRANT SELECT ON Produits TO App_User;
GRANT INSERT ON Commandes TO App_User;

-- Interdire la suppression
DENY DELETE ON Clients TO App_User;
DENY DELETE ON Produits TO App_User;
```

### Phase 3 : Utilisation quotidienne (DML + TCL)

**Les développeurs manipulent les données :**

```sql
-- Ajouter un nouveau client (DML)
INSERT INTO Clients (Nom, Email)
VALUES ('Dupont', 'dupont@email.com');

-- Consulter les produits (DML)
SELECT * FROM Produits WHERE Prix < 100;

-- Passer une commande (DML + TCL)
BEGIN TRANSACTION;

    -- Insérer la commande
    INSERT INTO Commandes (ClientID, DateCommande)
    VALUES (1, GETDATE());

    -- Décrémenter le stock
    UPDATE Produits
    SET Stock = Stock - 1
    WHERE ProduitID = 5;

    -- Vérifier le stock
    IF (SELECT Stock FROM Produits WHERE ProduitID = 5) < 0
    BEGIN
        ROLLBACK; -- Annuler si stock insuffisant
        PRINT 'Stock insuffisant';
    END
    ELSE
    BEGIN
        COMMIT; -- Valider la commande
        PRINT 'Commande confirmée';
    END
```

### Phase 4 : Évolution (DDL)

**L'architecte fait évoluer la structure :**

```sql
-- Ajouter une nouvelle colonne
ALTER TABLE Clients
ADD Telephone NVARCHAR(20);

-- Créer un index pour les performances
CREATE INDEX IX_Commandes_Date
ON Commandes(DateCommande);
```

## Bonnes pratiques par sous-langage

### DDL - Bonnes pratiques

- ✅ **Toujours** scripter les modifications (ne pas utiliser uniquement l'interface graphique)
- ✅ **Versionner** les scripts DDL (Git, SVN)
- ✅ **Tester** dans un environnement de développement avant la production
- ✅ **Sauvegarder** avant de faire des DROP
- ✅ **Documenter** les changements de structure

- ❌ Éviter les modifications de structure en production aux heures de pointe
- ❌ Ne jamais faire DROP sans être absolument certain

### DML - Bonnes pratiques

- ✅ **Toujours** utiliser WHERE avec UPDATE et DELETE (sauf si vraiment intentionnel)
- ✅ **Tester** les requêtes avec SELECT avant de faire UPDATE/DELETE
- ✅ Utiliser des **transactions** pour les opérations critiques
- ✅ **Optimiser** les requêtes SELECT (pas de SELECT *)
- ✅ Utiliser des **index** pour améliorer les performances

- ❌ Ne jamais faire `DELETE FROM Table` sans WHERE en production
- ❌ Éviter SELECT * (choisir les colonnes nécessaires)

### DCL - Bonnes pratiques

- ✅ **Principe du moindre privilège** : Ne donner que les droits strictement nécessaires
- ✅ Utiliser des **rôles** plutôt que des permissions individuelles
- ✅ **Documenter** qui a accès à quoi
- ✅ **Réviser régulièrement** les permissions
- ✅ Utiliser **DENY** avec parcimonie (peut créer de la confusion)

- ❌ Ne jamais donner des droits "db_owner" à tout le monde
- ❌ Éviter de gérer les permissions utilisateur par utilisateur

### TCL - Bonnes pratiques

- ✅ **Toujours** utiliser des transactions pour les opérations multi-étapes
- ✅ Garder les transactions **courtes** (pour éviter les blocages)
- ✅ **Gérer les erreurs** avec TRY...CATCH
- ✅ **Tester** les scénarios d'échec
- ✅ Utiliser des **points de sauvegarde** pour les longues transactions

- ❌ Ne pas oublier de COMMIT ou ROLLBACK (laisse la transaction ouverte)
- ❌ Éviter les transactions trop longues (risque de blocage)

## Résumé

### Les 4 piliers de T-SQL

```
┌──────────────────────────────────────────────────────────┐
│                     T-SQL                                │
│                                                          │
│  DDL          DML          DCL          TCL              │
│  (Structure)  (Données)    (Sécurité)   (Transactions)   │
│                                                          │
│  🏗️ Bâtir     📝 Remplir    🔒 Protéger  ✅ Valider       │
│                                                          │
│  CREATE       SELECT       GRANT        BEGIN TRAN       │
│  ALTER        INSERT       DENY         COMMIT           │
│  DROP         UPDATE       REVOKE       ROLLBACK         │
│  TRUNCATE     DELETE                    SAVE TRAN        │
└──────────────────────────────────────────────────────────┘
```

### Aide-mémoire visuel

**Question à se poser :** Que voulez-vous faire ?

```
🤔 Que voulez-vous faire ?
│
├─ Créer/Modifier la STRUCTURE de la base ?
│  └─→ Utilisez DDL (CREATE, ALTER, DROP)
│
├─ Travailler avec les DONNÉES ?
│  └─→ Utilisez DML (SELECT, INSERT, UPDATE, DELETE)
│
├─ Gérer les DROITS D'ACCÈS ?
│  └─→ Utilisez DCL (GRANT, DENY, REVOKE)
│
└─ Contrôler une TRANSACTION ?
   └─→ Utilisez TCL (BEGIN, COMMIT, ROLLBACK)
```

### Points clés à retenir

1. **T-SQL** = DDL + DML + DCL + TCL (+ extensions Microsoft)

2. **DDL** : "Je construis la maison" (structure)

3. **DML** : "Je vis dans la maison" (90% de votre temps)

4. **DCL** : "Je contrôle qui entre" (sécurité)

5. **TCL** : "Je valide ou j'annule mes actions" (fiabilité)

6. Chaque sous-langage a un **rôle spécifique** et des **commandes dédiées**

7. Dans la pratique, vous utiliserez **principalement DML** (SELECT, INSERT, UPDATE, DELETE)

8. Les autres sous-langages sont utilisés **ponctuellement** mais sont tout aussi importants

### Ordre d'apprentissage recommandé

```
1️⃣ DML (SELECT) → Commencez par lire les données
2️⃣ DML (INSERT, UPDATE, DELETE) → Puis manipulez-les
3️⃣ DDL (CREATE TABLE) → Créez vos propres structures
4️⃣ TCL (BEGIN, COMMIT, ROLLBACK) → Sécurisez vos opérations
5️⃣ DDL (ALTER, DROP) → Modifiez les structures
6️⃣ DCL (GRANT, DENY, REVOKE) → Gérez la sécurité
```
