# 8.3.3 Interrogation à un instant T (AS OF)

## Introduction

Vous avez créé votre table temporelle avec `SYSTEM_VERSIONING` (section 8.3.2), et maintenant vos données sont automatiquement historisées. Mais comment accéder à cet historique ? Comment savoir quel était le prix d'un produit le 15 mars dernier ? Ou comment voir l'état complet de votre base de données tel qu'il était il y a 6 mois ?

C'est exactement ce que nous allons apprendre dans cette section : **voyager dans le temps** avec vos données grâce à la clause `FOR SYSTEM_TIME`.

## Le concept : Voyager dans le temps

Imaginez que vous ayez une **machine à remonter le temps** pour vos données. Avec les tables temporelles, vous pouvez :

- 📅 Voir les données **telles qu'elles étaient à une date précise** (ex: 1er janvier 2024)
- 📊 Comparer l'état des données **entre deux dates** (ex: entre janvier et juin)
- 🔍 Trouver **toutes les versions** d'une ligne spécifique
- 📈 Analyser **l'évolution** de vos données dans le temps

Le tout avec des requêtes SQL simples !

## Syntaxe de base : FOR SYSTEM_TIME

La clause `FOR SYSTEM_TIME` s'ajoute après le nom de la table dans votre requête `SELECT` :

```sql
SELECT colonnes
FROM NomTable
    FOR SYSTEM_TIME <clause_temporelle>
WHERE conditions;
```

Il existe **5 clauses temporelles** différentes que nous allons explorer :

1. `AS OF` - Voir les données à une date précise
2. `FROM ... TO` - Voir les versions actives pendant une période (fin exclue)
3. `BETWEEN ... AND` - Voir les versions actives pendant une période (fin incluse)
4. `CONTAINED IN` - Voir les versions créées ET terminées dans une période
5. `ALL` - Voir absolument toutes les versions (historique complet)

## 1. AS OF : Voir les données à un instant précis

C'est la clause la plus utilisée et la plus intuitive.

### Syntaxe

```sql
SELECT *
FROM Produits
    FOR SYSTEM_TIME AS OF '2024-06-15 10:30:00'
WHERE CategorieID = 5;
```

Cette requête retourne les données **telles qu'elles étaient valides** le 15 juin 2024 à 10h30.

### Comment ça fonctionne ?

SQL Server recherche les lignes où :
- `ValidFrom <= '2024-06-15 10:30:00'`
- `ValidTo > '2024-06-15 10:30:00'`

Autrement dit, il trouve les versions qui étaient **actives** à ce moment précis.

### Exemple concret

Reprenons notre table `Produits` avec son historique :

**Table Produits (actuelle)** :
| ProduitID | Nom        | Prix | ValidFrom           | ValidTo             |
|-----------|------------|------|---------------------|---------------------|
| 1         | Ordinateur | 700€ | 2024-11-01 14:22:00 | 9999-12-31 23:59:59 |

**Table Produits_History** :
| ProduitID | Nom        | Prix | ValidFrom           | ValidTo             |
|-----------|------------|------|---------------------|---------------------|
| 1         | Ordinateur | 800€ | 2024-01-01 08:00:00 | 2024-06-01 10:15:00 |
| 1         | Ordinateur | 750€ | 2024-06-01 10:15:00 | 2024-11-01 14:22:00 |

Maintenant, exécutons plusieurs requêtes `AS OF` :

#### Requête 1 : Prix au 15 mars 2024

```sql
SELECT ProduitID, Nom, Prix
FROM Produits
    FOR SYSTEM_TIME AS OF '2024-03-15'
WHERE ProduitID = 1;
```

**Résultat** :
| ProduitID | Nom        | Prix |
|-----------|------------|------|
| 1         | Ordinateur | 800€ |

💡 **Explication** : Le 15 mars 2024, la version à 800€ était active (valide du 1er janvier au 1er juin).

#### Requête 2 : Prix au 15 août 2024

```sql
SELECT ProduitID, Nom, Prix
FROM Produits
    FOR SYSTEM_TIME AS OF '2024-08-15'
WHERE ProduitID = 1;
```

**Résultat** :
| ProduitID | Nom        | Prix |
|-----------|------------|------|
| 1         | Ordinateur | 750€ |

💡 **Explication** : Le 15 août 2024, la version à 750€ était active (valide du 1er juin au 1er novembre).

#### Requête 3 : Prix aujourd'hui

```sql
SELECT ProduitID, Nom, Prix
FROM Produits
    FOR SYSTEM_TIME AS OF SYSUTCDATETIME()
WHERE ProduitID = 1;
```

**Résultat** :
| ProduitID | Nom        | Prix |
|-----------|------------|------|
| 1         | Ordinateur | 700€ |

💡 **Astuce** : `SYSUTCDATETIME()` retourne la date/heure actuelle. Cette requête est équivalente à un simple `SELECT * FROM Produits WHERE ProduitID = 1` (sans clause temporelle).

### Cas d'usage pratiques pour AS OF

#### 1. Facturation au prix historique

Un client conteste une facture et affirme que le prix était différent à la date de sa commande :

```sql
-- Vérifier le prix du produit à la date de la commande
SELECT
    p.ProduitID,
    p.Nom,
    p.Prix AS PrixALaDateDeCommande,
    c.DateCommande
FROM
    Commandes c
    INNER JOIN Produits
        FOR SYSTEM_TIME AS OF c.DateCommande AS p
        ON c.ProduitID = p.ProduitID
WHERE
    c.CommandeID = 12345;
```

💡 **Remarque** : Notez que la date `AS OF` peut être une **colonne** d'une autre table ! Ici, on utilise `c.DateCommande`.

#### 2. Audit : Qui a vu quoi ?

Un responsable veut savoir quels produits étaient en promotion lors d'une campagne marketing passée :

```sql
-- Produits en promotion le 15 septembre 2024
SELECT
    ProduitID,
    Nom,
    Prix,
    PrixPromo
FROM
    Produits
    FOR SYSTEM_TIME AS OF '2024-09-15'
WHERE
    PrixPromo IS NOT NULL
    AND PrixPromo < Prix;
```

#### 3. Comparaison avant/après

Comparer les prix actuels avec ceux d'il y a 6 mois :

```sql
-- Comparaison des prix : aujourd'hui vs il y a 6 mois
SELECT
    p_actuel.ProduitID,
    p_actuel.Nom,
    p_passe.Prix AS PrixIl6Mois,
    p_actuel.Prix AS PrixActuel,
    p_actuel.Prix - p_passe.Prix AS Variation,
    CAST(((p_actuel.Prix - p_passe.Prix) / p_passe.Prix * 100) AS DECIMAL(5,2)) AS VariationPourcentage
FROM
    Produits AS p_actuel
    LEFT JOIN Produits
        FOR SYSTEM_TIME AS OF DATEADD(MONTH, -6, SYSUTCDATETIME()) AS p_passe
        ON p_actuel.ProduitID = p_passe.ProduitID;
```

**Résultat exemple** :
| ProduitID | Nom        | PrixIl6Mois | PrixActuel | Variation | VariationPourcentage |
|-----------|------------|-------------|------------|-----------|----------------------|
| 1         | Ordinateur | 750€        | 700€       | -50€      | -6.67%               |
| 2         | Souris     | 25€         | 30€        | +5€       | +20.00%              |

## 2. FROM ... TO : Versions actives pendant une période (fin exclue)

La clause `FROM ... TO` retourne toutes les versions qui étaient actives **à n'importe quel moment** entre deux dates.

### Syntaxe

```sql
SELECT *
FROM Produits
    FOR SYSTEM_TIME FROM '2024-01-01' TO '2024-06-30'
WHERE ProduitID = 1;
```

⚠️ **Important** : La date de fin (`TO`) est **exclusive** (exclue). Les versions valides exactement à `2024-06-30` ne sont **pas incluses**.

### Différence avec AS OF

- `AS OF` : Retourne **1 version** valide à un instant précis
- `FROM ... TO` : Retourne **plusieurs versions** valides pendant une période

### Exemple

Avec notre historique précédent :

```sql
SELECT ProduitID, Nom, Prix, ValidFrom, ValidTo
FROM Produits
    FOR SYSTEM_TIME FROM '2024-01-01' TO '2024-12-01'
WHERE ProduitID = 1;
```

**Résultat** :
| ProduitID | Nom        | Prix | ValidFrom           | ValidTo             |
|-----------|------------|------|---------------------|---------------------|
| 1         | Ordinateur | 800€ | 2024-01-01 08:00:00 | 2024-06-01 10:15:00 |
| 1         | Ordinateur | 750€ | 2024-06-01 10:15:00 | 2024-11-01 14:22:00 |
| 1         | Ordinateur | 700€ | 2024-11-01 14:22:00 | 9999-12-31 23:59:59 |

💡 **Explication** : Les trois versions ont été actives à un moment ou un autre entre le 1er janvier et le 1er décembre.

### Cas d'usage pour FROM ... TO

#### Analyser l'évolution des prix sur une période

```sql
-- Voir toutes les variations de prix d'un produit en 2024
SELECT
    ProduitID,
    Nom,
    Prix,
    ValidFrom AS ChangementLe,
    DATEDIFF(DAY, ValidFrom, ValidTo) AS NombreJoursValide
FROM
    Produits
    FOR SYSTEM_TIME FROM '2024-01-01' TO '2025-01-01'
WHERE
    ProduitID = 1
ORDER BY
    ValidFrom;
```

#### Détecter les changements fréquents

```sql
-- Produits dont le prix a changé plus de 3 fois en 2024
SELECT
    ProduitID,
    Nom,
    COUNT(*) AS NombreChangements
FROM
    Produits
    FOR SYSTEM_TIME FROM '2024-01-01' TO '2025-01-01'
GROUP BY
    ProduitID, Nom
HAVING
    COUNT(*) > 3
ORDER BY
    NombreChangements DESC;
```

## 3. BETWEEN ... AND : Versions actives pendant une période (fin incluse)

Identique à `FROM ... TO`, mais la date de fin est **inclusive** (incluse).

### Syntaxe

```sql
SELECT *
FROM Produits
    FOR SYSTEM_TIME BETWEEN '2024-01-01' AND '2024-06-30'
WHERE ProduitID = 1;
```

✅ **Différence** : Les versions valides exactement à `2024-06-30` **sont incluses**.

### Comparaison FROM...TO vs BETWEEN...AND

```sql
-- FROM...TO (fin exclue) — la borne tombe exactement sur le changement de version
SELECT COUNT(*) AS NombreVersions
FROM Produits
    FOR SYSTEM_TIME FROM '2024-01-01' TO '2024-06-01 10:15:00'
WHERE ProduitID = 1;
-- Résultat : 1 version (seulement celle à 800€ ; la version à 750€, qui débute
-- exactement à 2024-06-01 10:15:00, est EXCLUE car la borne TO est exclusive)

-- BETWEEN...AND (fin incluse) — même borne
SELECT COUNT(*) AS NombreVersions
FROM Produits
    FOR SYSTEM_TIME BETWEEN '2024-01-01' AND '2024-06-01 10:15:00'
WHERE ProduitID = 1;
-- Résultat : 2 versions (celle à 800€ ET celle à 750€ qui débute exactement
-- à 2024-06-01 10:15:00, INCLUSE car la borne AND est inclusive)
```

💡 **Conseil** : Utilisez `BETWEEN ... AND` quand vous voulez inclure les modifications qui se sont produites exactement à la date de fin.

## 4. CONTAINED IN : Versions créées ET terminées dans une période

Cette clause retourne uniquement les versions dont la **durée de vie complète** est contenue dans la période spécifiée.

### Syntaxe

```sql
SELECT *
FROM Produits
    FOR SYSTEM_TIME CONTAINED IN ('2024-01-01', '2024-12-31')
WHERE ProduitID = 1;
```

### Critère de sélection

Une version est retournée si :
- `ValidFrom >= '2024-01-01'` **ET**
- `ValidTo <= '2024-12-31'`

Autrement dit, la version a été créée **et** est devenue obsolète **entièrement dans la période**.

### Exemple

Avec notre historique :

```sql
SELECT ProduitID, Nom, Prix, ValidFrom, ValidTo
FROM Produits
    FOR SYSTEM_TIME CONTAINED IN ('2024-01-01', '2024-12-31')
WHERE ProduitID = 1;
```

**Résultat** :
| ProduitID | Nom        | Prix | ValidFrom           | ValidTo             |
|-----------|------------|------|---------------------|---------------------|
| 1         | Ordinateur | 800€ | 2024-01-01 08:00:00 | 2024-06-01 10:15:00 |
| 1         | Ordinateur | 750€ | 2024-06-01 10:15:00 | 2024-11-01 14:22:00 |

💡 **Explication** :
- La version à 700€ n'est **pas incluse** car son `ValidTo` est `9999-12-31` (toujours active, donc pas terminée dans la période)
- Seules les versions qui ont commencé ET terminé en 2024 sont retournées

### Cas d'usage pour CONTAINED IN

#### Trouver les versions éphémères

Identifier les changements qui n'ont duré que peu de temps :

```sql
-- Trouver les prix qui n'ont été valides que moins de 7 jours en 2024
SELECT
    ProduitID,
    Nom,
    Prix,
    ValidFrom,
    ValidTo,
    DATEDIFF(DAY, ValidFrom, ValidTo) AS DureeJours
FROM
    Produits
    FOR SYSTEM_TIME CONTAINED IN ('2024-01-01', '2024-12-31')
WHERE
    DATEDIFF(DAY, ValidFrom, ValidTo) < 7
ORDER BY
    DureeJours;
```

#### Analyser les modifications ponctuelles

```sql
-- Produits modifiés puis revenus à leur valeur initiale dans l'année
WITH ChangementsAnnuels AS (
    SELECT
        ProduitID,
        Nom,
        Prix,
        ROW_NUMBER() OVER (PARTITION BY ProduitID ORDER BY ValidFrom) AS Ordre
    FROM
        Produits
        FOR SYSTEM_TIME CONTAINED IN ('2024-01-01', '2024-12-31')
)
SELECT
    c1.ProduitID,
    c1.Nom,
    c1.Prix AS PrixInitial,
    c2.Prix AS PrixFinal
FROM
    ChangementsAnnuels c1
    INNER JOIN ChangementsAnnuels c2
        ON c1.ProduitID = c2.ProduitID
WHERE
    c1.Ordre = 1
    AND c2.Ordre = (SELECT MAX(Ordre) FROM ChangementsAnnuels WHERE ProduitID = c1.ProduitID)
    AND c1.Prix = c2.Prix;
```

## 5. ALL : Voir toutes les versions (historique complet)

La clause `ALL` retourne **absolument toutes les versions** d'une ligne : l'historique complet ET la version actuelle.

### Syntaxe

```sql
SELECT *
FROM Produits
    FOR SYSTEM_TIME ALL
WHERE ProduitID = 1
ORDER BY ValidFrom;
```

### Résultat

**Toutes les versions** :
| ProduitID | Nom        | Prix | ValidFrom           | ValidTo             |
|-----------|------------|------|---------------------|---------------------|
| 1         | Ordinateur | 800€ | 2024-01-01 08:00:00 | 2024-06-01 10:15:00 |
| 1         | Ordinateur | 750€ | 2024-06-01 10:15:00 | 2024-11-01 14:22:00 |
| 1         | Ordinateur | 700€ | 2024-11-01 14:22:00 | 9999-12-31 23:59:59 |

💡 **Équivalent à** : Faire un `UNION ALL` entre la table principale et la table d'historique.

### Cas d'usage pour ALL

#### 1. Historique complet d'un enregistrement

Afficher toute l'histoire d'un produit, du début à aujourd'hui :

```sql
SELECT
    ProduitID,
    Nom,
    Prix,
    ValidFrom AS DateChangement,
    CASE
        WHEN ValidTo = CAST('9999-12-31 23:59:59.9999999' AS DATETIME2)
        THEN 'Version actuelle'
        ELSE 'Version historique'
    END AS Statut,
    DATEDIFF(DAY, ValidFrom, CASE
        WHEN ValidTo = CAST('9999-12-31 23:59:59.9999999' AS DATETIME2)
        THEN SYSUTCDATETIME()
        ELSE ValidTo
    END) AS DureeJours
FROM
    Produits
    FOR SYSTEM_TIME ALL
WHERE
    ProduitID = 1
ORDER BY
    ValidFrom;
```

#### 2. Nombre total de modifications

Compter combien de fois un produit a été modifié :

```sql
SELECT
    ProduitID,
    Nom,
    COUNT(*) - 1 AS NombreTotalModifications  -- -1 car la version initiale n'est pas une modification
FROM
    Produits
    FOR SYSTEM_TIME ALL
GROUP BY
    ProduitID, Nom
HAVING
    COUNT(*) > 1  -- Seulement les produits modifiés
ORDER BY
    NombreTotalModifications DESC;
```

#### 3. Graphique d'évolution des prix

Créer un dataset pour visualiser l'évolution complète des prix :

```sql
SELECT
    ProduitID,
    Nom,
    Prix,
    ValidFrom,
    CASE
        WHEN ValidTo = CAST('9999-12-31 23:59:59.9999999' AS DATETIME2)
        THEN SYSUTCDATETIME()
        ELSE ValidTo
    END AS ValidTo_Reel
FROM
    Produits
    FOR SYSTEM_TIME ALL
WHERE
    ProduitID IN (1, 2, 3)  -- Produits à comparer
ORDER BY
    ProduitID, ValidFrom;
```

Ce résultat peut être exporté vers Excel, Power BI ou un autre outil de visualisation pour créer des graphiques temporels.

## Requêtes avancées avec les clauses temporelles

### 1. Joindre des tables temporelles

Vous pouvez joindre plusieurs tables temporelles entre elles :

```sql
-- Voir les commandes et leurs produits tels qu'ils étaient au moment de la commande
SELECT
    c.CommandeID,
    c.DateCommande,
    p.Nom AS NomProduit,
    p.Prix AS PrixALepoque,
    cd.Quantite,
    p.Prix * cd.Quantite AS MontantLigne
FROM
    Commandes AS c
    INNER JOIN CommandeDetails AS cd
        ON c.CommandeID = cd.CommandeID
    INNER JOIN Produits
        FOR SYSTEM_TIME AS OF c.DateCommande AS p
        ON cd.ProduitID = p.ProduitID
WHERE
    c.CommandeID = 5678;
```

💡 **Cas d'usage** : Recalculer le montant exact d'une facture historique avec les prix qui étaient en vigueur à la date de la commande.

### 2. Comparer plusieurs périodes

Analyser l'évolution entre plusieurs points dans le temps :

```sql
-- Comparer les prix en début d'année, milieu d'année et fin d'année
SELECT
    p1.ProduitID,
    p1.Nom,
    p1.Prix AS Prix_Jan2024,
    p2.Prix AS Prix_Jun2024,
    p3.Prix AS Prix_Dec2024,
    p3.Prix - p1.Prix AS Variation_AnnuelleTotale,
    CASE
        WHEN p3.Prix > p1.Prix THEN 'Hausse'
        WHEN p3.Prix < p1.Prix THEN 'Baisse'
        ELSE 'Stable'
    END AS Tendance
FROM
    Produits FOR SYSTEM_TIME AS OF '2024-01-01' AS p1
    LEFT JOIN Produits FOR SYSTEM_TIME AS OF '2024-06-01' AS p2
        ON p1.ProduitID = p2.ProduitID
    LEFT JOIN Produits FOR SYSTEM_TIME AS OF '2024-12-01' AS p3
        ON p1.ProduitID = p3.ProduitID
WHERE
    p1.CategorieID = 5;
```

### 3. Détecter les valeurs manquantes historiques

Trouver les produits qui existaient dans le passé mais qui ont été supprimés :

```sql
-- Produits qui existaient il y a 1 an mais n'existent plus aujourd'hui
SELECT
    p_passe.ProduitID,
    p_passe.Nom,
    p_passe.Prix AS DernierPrixConnu
FROM
    Produits FOR SYSTEM_TIME AS OF DATEADD(YEAR, -1, SYSUTCDATETIME()) AS p_passe
    LEFT JOIN Produits AS p_actuel
        ON p_passe.ProduitID = p_actuel.ProduitID
WHERE
    p_actuel.ProduitID IS NULL;
```

### 4. Agréger les données temporelles

Calculer des statistiques sur l'historique :

```sql
-- Prix moyen de chaque produit à travers toutes ses versions
SELECT
    ProduitID,
    Nom,
    AVG(Prix) AS PrixMoyen,
    MIN(Prix) AS PrixMin,
    MAX(Prix) AS PrixMax,
    MAX(Prix) - MIN(Prix) AS EcartMaxMin,
    COUNT(*) AS NombreVersions
FROM
    Produits
    FOR SYSTEM_TIME ALL
GROUP BY
    ProduitID, Nom
HAVING
    COUNT(*) > 1
ORDER BY
    EcartMaxMin DESC;
```

## Performances et bonnes pratiques

### 1. Toujours filtrer avec WHERE

N'interrogez pas toute la table d'historique sans nécessité :

```sql
-- ❌ MAUVAIS : Retourne tout l'historique de tous les produits
SELECT *
FROM Produits
    FOR SYSTEM_TIME ALL;

-- ✅ BON : Filtre sur un produit spécifique
SELECT *
FROM Produits
    FOR SYSTEM_TIME ALL
WHERE ProduitID = 1;
```

### 2. Créer des index sur la table d'historique

Pour optimiser les requêtes temporelles :

```sql
-- Index clustered sur les colonnes temporelles
CREATE CLUSTERED INDEX IX_Produits_History
ON Produits_History (ValidTo, ValidFrom);

-- Index non-clustered sur les colonnes fréquemment filtrées
CREATE NONCLUSTERED INDEX IX_Produits_History_ProduitID
ON Produits_History (ProduitID, ValidFrom, ValidTo);
```

### 3. Utiliser les statistiques

SQL Server utilise les statistiques pour optimiser les plans d'exécution. Assurez-vous qu'elles sont à jour :

```sql
-- Mettre à jour les statistiques de la table d'historique
UPDATE STATISTICS Produits_History;
```

### 4. Limiter la période interrogée

Plus la période est large, plus la requête sera lente :

```sql
-- ❌ LENT : Interroge 10 ans d'historique
SELECT *
FROM Produits
    FOR SYSTEM_TIME BETWEEN '2014-01-01' AND '2024-12-31'
WHERE CategorieID = 5;

-- ✅ RAPIDE : Limite à la période nécessaire
SELECT *
FROM Produits
    FOR SYSTEM_TIME BETWEEN '2024-01-01' AND '2024-12-31'
WHERE CategorieID = 5;
```

### 5. Utiliser AS OF plutôt que ALL quand possible

Si vous avez juste besoin d'un instantané :

```sql
-- ❌ MOINS EFFICACE : Retourne toutes les versions puis filtre
SELECT *
FROM Produits
    FOR SYSTEM_TIME ALL
WHERE ValidFrom <= '2024-06-15' AND ValidTo > '2024-06-15';

-- ✅ PLUS EFFICACE : Utilise AS OF
SELECT *
FROM Produits
    FOR SYSTEM_TIME AS OF '2024-06-15';
```

## Pièges courants et solutions

### Piège 1 : Confusion entre dates locales et UTC

Les tables temporelles utilisent généralement **UTC** pour éviter les problèmes de fuseaux horaires.

```sql
-- ❌ POTENTIELLEMENT INCORRECT : Date locale
SELECT *
FROM Produits
    FOR SYSTEM_TIME AS OF GETDATE();  -- Heure locale du serveur

-- ✅ CORRECT : Date UTC
SELECT *
FROM Produits
    FOR SYSTEM_TIME AS OF SYSUTCDATETIME();  -- Heure UTC
```

💡 **Conseil** : Si vos colonnes temporelles ont été créées avec `DEFAULT SYSUTCDATETIME()`, utilisez toujours `SYSUTCDATETIME()` dans vos requêtes pour la cohérence.

### Piège 2 : Oublier que FROM...TO exclut la date de fin

```sql
-- Vouloir voir les données du 1er au 30 juin inclus
SELECT *
FROM Produits
    FOR SYSTEM_TIME FROM '2024-06-01' TO '2024-06-30';  -- ❌ Exclut le 30 juin !

-- Solution 1 : Utiliser BETWEEN...AND
SELECT *
FROM Produits
    FOR SYSTEM_TIME BETWEEN '2024-06-01' AND '2024-06-30';  -- ✅ Inclut le 30 juin

-- Solution 2 : Ajouter 1 jour à la date de fin
SELECT *
FROM Produits
    FOR SYSTEM_TIME FROM '2024-06-01' TO '2024-07-01';  -- ✅ Inclut tout le 30 juin
```

### Piège 3 : Tentative de modification via une requête temporelle

Vous ne pouvez pas faire d'`UPDATE` ou `DELETE` avec les clauses temporelles :

```sql
-- ❌ ERREUR : Impossible de modifier via FOR SYSTEM_TIME
UPDATE Produits
    FOR SYSTEM_TIME AS OF '2024-06-15'
SET Prix = 850
WHERE ProduitID = 1;

-- Message d'erreur :
-- "Temporal FOR SYSTEM_TIME clause can only be used with SELECT statements."
```

✅ **Solution** : Les modifications se font uniquement sur la table actuelle (sans clause temporelle). L'historique est géré automatiquement par SQL Server.

### Piège 4 : Performances sur de gros volumes

Interroger des années d'historique peut être lent sans index appropriés :

```sql
-- Peut être très lent sur une grosse table
SELECT *
FROM Produits
    FOR SYSTEM_TIME ALL
WHERE Nom LIKE '%Ordinateur%';
```

✅ **Solution** :
1. Créez des index sur les colonnes fréquemment filtrées dans la table d'historique
2. Limitez la période avec `FROM...TO` ou `BETWEEN...AND`
3. Utilisez des colonnes calculées et des vues si nécessaire

## Cas d'usage métier réels

### 1. Conformité RGPD : Prouver la suppression

```sql
-- Vérifier qu'une donnée client a bien été supprimée
SELECT
    ClientID,
    Email,
    ValidFrom AS DateCreation,
    ValidTo AS DateSuppression
FROM
    Clients
    FOR SYSTEM_TIME ALL
WHERE
    Email = 'client@example.com'
ORDER BY
    ValidFrom;
```

### 2. Finance : Audit de transactions

```sql
-- Reconstituer l'état d'un compte bancaire à une date spécifique
SELECT
    CompteID,
    Solde AS SoldeAuMoment,
    DerniereTransaction
FROM
    Comptesbancaires
    FOR SYSTEM_TIME AS OF '2024-06-30 23:59:59'
WHERE
    CompteID = 'FR76 1234 5678 9012 3456';
```

### 3. E-commerce : Analyse des stratégies de prix

```sql
-- Corrélation entre changements de prix et volumes de ventes
SELECT
    p.ProduitID,
    p.Nom,
    p.Prix,
    p.ValidFrom AS DateChangementPrix,
    DATEDIFF(DAY, p.ValidFrom, p.ValidTo) AS DureeJours,
    COUNT(v.VenteID) AS NombreVentes,
    SUM(v.Quantite) AS QuantiteTotaleVendue
FROM
    Produits FOR SYSTEM_TIME ALL AS p
    LEFT JOIN Ventes AS v
        ON p.ProduitID = v.ProduitID
        AND v.DateVente >= p.ValidFrom
        AND v.DateVente < p.ValidTo
WHERE
    p.ProduitID = 1
GROUP BY
    p.ProduitID, p.Nom, p.Prix, p.ValidFrom, p.ValidTo
ORDER BY
    p.ValidFrom;
```

### 4. Ressources Humaines : Historique salarial

```sql
-- Voir toute l'évolution de carrière d'un employé
SELECT
    EmployeID,
    Nom,
    Prenom,
    Poste,
    Salaire,
    DepartementID,
    ValidFrom AS DateEffet,
    CASE
        WHEN ValidTo = CAST('9999-12-31 23:59:59.9999999' AS DATETIME2)
        THEN 'Poste actuel'
        ELSE CAST(ValidTo AS VARCHAR(20))
    END AS DateFin,
    DATEDIFF(MONTH, ValidFrom, CASE
        WHEN ValidTo = CAST('9999-12-31 23:59:59.9999999' AS DATETIME2)
        THEN SYSUTCDATETIME()
        ELSE ValidTo
    END) AS DureeMois
FROM
    Employes
    FOR SYSTEM_TIME ALL
WHERE
    EmployeID = 1234
ORDER BY
    ValidFrom;
```

## Tableau récapitulatif des clauses temporelles

| Clause | Retourne | Date de fin | Cas d'usage typique |
|--------|----------|-------------|---------------------|
| **AS OF** | Version valide à une date précise | N/A | Voir l'état à un moment donné |
| **FROM ... TO** | Versions actives dans la période | Exclusive | Analyser une plage temporelle |
| **BETWEEN ... AND** | Versions actives dans la période | Inclusive | Analyser une plage temporelle (fin incluse) |
| **CONTAINED IN** | Versions créées ET terminées dans la période | N/A | Trouver les changements temporaires |
| **ALL** | Toutes les versions (historique + actuel) | N/A | Historique complet, audits |

## Conclusion

Les clauses temporelles de SQL Server transforment vos tables en **machines à remonter le temps** pour vos données :

- 🕐 **AS OF** : "Montre-moi les données comme elles étaient le..."
- 📅 **FROM...TO / BETWEEN...AND** : "Montre-moi toutes les versions pendant la période..."
- 🔍 **CONTAINED IN** : "Montre-moi les changements qui ont commencé ET terminé pendant..."
- 📚 **ALL** : "Montre-moi absolument tout l'historique"

Ces outils puissants permettent de :
- ✅ Auditer les modifications de données
- ✅ Analyser les tendances temporelles
- ✅ Reconstituer des états passés
- ✅ Comparer les données entre différentes périodes
- ✅ Répondre aux exigences de conformité

Avec la pratique, interroger les tables temporelles deviendra aussi naturel que d'écrire un `SELECT` classique !

---

**Points clés à retenir** :
- `FOR SYSTEM_TIME` s'ajoute après le nom de la table dans le SELECT
- `AS OF` est la clause la plus utilisée pour voir les données à un instant T
- `FROM...TO` exclut la date de fin, `BETWEEN...AND` l'inclut
- `ALL` retourne toutes les versions (historique complet)
- Toujours filtrer avec WHERE pour optimiser les performances
- Créez des index sur la table d'historique pour accélérer les requêtes
- Utilisez UTC (SYSUTCDATETIME) pour éviter les problèmes de fuseaux horaires
