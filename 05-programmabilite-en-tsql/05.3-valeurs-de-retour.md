# 5.5.3 Valeurs de Retour (RETURN)

## Introduction

L'instruction `RETURN` est une fonctionnalité simple mais puissante des procédures stockées qui permet de **terminer l'exécution** d'une procédure et de **retourner un code d'état** à l'appelant. C'est particulièrement utile pour indiquer le succès ou l'échec d'une opération.

### Qu'est-ce que RETURN ?

`RETURN` est une instruction qui :
1. **Termine immédiatement** l'exécution de la procédure
2. **Retourne une valeur entière** (INT) à l'appelant
3. Est souvent utilisée pour indiquer des **codes d'état** (succès/échec)

**Analogie simple :** C'est comme le **feu de signalisation** d'une opération :
- 🟢 Vert (1) = Succès
- 🔴 Rouge (0) = Échec
- 🟡 Jaune (autre code) = État particulier

---

## 1. Syntaxe de Base

### Structure simple

```sql
CREATE PROCEDURE nom_procedure
AS
BEGIN
    -- Instructions

    RETURN valeur_entiere;  -- Terminer et retourner un code
END;
```

**Points clés :**
- `RETURN` peut apparaître n'importe où dans la procédure
- Dès que `RETURN` est exécuté, la procédure **s'arrête immédiatement**
- La valeur retournée doit être un **entier (INT)**
- Si aucun `RETURN` n'est spécifié, la valeur 0 est retournée par défaut

## 2. Exemple Simple : Code de Succès/Échec

### Exemple 1 : Vérification d'existence

```sql
-- Procédure qui vérifie si un client existe
CREATE PROCEDURE SpClientExiste
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Vérifier si le client existe
    IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        RETURN 1;  -- Client trouvé
    END
    ELSE
    BEGIN
        RETURN 0;  -- Client non trouvé
    END
END;
```

**Exécution et récupération du code de retour :**

```sql
-- Déclarer une variable pour recevoir le code de retour
DECLARE @CodeRetour INT;

-- Exécuter la procédure et capturer le code
EXEC @CodeRetour = SpClientExiste @ClientID = 5;

-- Utiliser le code de retour
IF @CodeRetour = 1
    PRINT 'Le client existe';
ELSE
    PRINT 'Le client n''existe pas';
```

**Résultat :**
```
Le client existe
```

**Note importante :** Pour capturer la valeur de retour, utilisez la syntaxe `EXEC @variable = nom_procedure`.

---

### Exemple 2 : Codes de retour multiples

Vous pouvez utiliser différents codes pour différentes situations :

```sql
-- Procédure avec plusieurs codes de retour
CREATE PROCEDURE SpValiderConnexion
    @Email VARCHAR(100),
    @MotDePasse VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @Actif BIT;
    DECLARE @MotDePasseCorrect VARCHAR(100);

    -- Vérifier si l'utilisateur existe
    IF NOT EXISTS (SELECT 1 FROM Utilisateurs WHERE Email = @Email)
    BEGIN
        RETURN -1;  -- Code -1 : Utilisateur inexistant
    END

    -- Récupérer les informations
    SELECT
        @MotDePasseCorrect = MotDePasse,
        @Actif = Actif
    FROM Utilisateurs
    WHERE Email = @Email;

    -- Vérifier si le compte est actif
    IF @Actif = 0
    BEGIN
        RETURN -2;  -- Code -2 : Compte désactivé
    END

    -- Vérifier le mot de passe
    IF @MotDePasseCorrect != @MotDePasse
    BEGIN
        RETURN -3;  -- Code -3 : Mot de passe incorrect
    END

    -- Tout est OK
    RETURN 1;  -- Code 1 : Connexion réussie
END;
```

**Exécution avec interprétation des codes :**

```sql
DECLARE @Resultat INT;

EXEC @Resultat = SpValiderConnexion
    @Email = 'user@exemple.com',
    @MotDePasse = 'monMotDePasse';

-- Interpréter le code de retour
IF @Resultat = 1
    PRINT 'Connexion réussie';
ELSE IF @Resultat = -1
    PRINT 'Erreur : Utilisateur inexistant';
ELSE IF @Resultat = -2
    PRINT 'Erreur : Compte désactivé';
ELSE IF @Resultat = -3
    PRINT 'Erreur : Mot de passe incorrect';
ELSE
    PRINT 'Erreur inconnue';
```

## 3. RETURN pour Sortir Prématurément

`RETURN` est très utile pour **arrêter l'exécution** d'une procédure dès qu'une condition d'erreur est détectée.

### Exemple 3 : Validation avec sortie anticipée

```sql
-- Procédure de création de commande avec validations
CREATE PROCEDURE SpCreerCommande
    @ClientID INT,
    @ProduitID INT,
    @Quantite INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation 1 : Client existe
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        PRINT 'Erreur : Client inexistant';
        RETURN -1;  -- Sortir immédiatement
    END

    -- Validation 2 : Client actif
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID AND Actif = 1)
    BEGIN
        PRINT 'Erreur : Client inactif';
        RETURN -2;  -- Sortir immédiatement
    END

    -- Validation 3 : Produit existe
    IF NOT EXISTS (SELECT 1 FROM Produits WHERE ProduitID = @ProduitID)
    BEGIN
        PRINT 'Erreur : Produit inexistant';
        RETURN -3;  -- Sortir immédiatement
    END

    -- Validation 4 : Stock suffisant
    IF NOT EXISTS (
        SELECT 1 FROM Produits
        WHERE ProduitID = @ProduitID AND StockDisponible >= @Quantite
    )
    BEGIN
        PRINT 'Erreur : Stock insuffisant';
        RETURN -4;  -- Sortir immédiatement
    END

    -- Toutes les validations sont passées, créer la commande
    INSERT INTO Commandes (ClientID, ProduitID, Quantite, DateCommande)
    VALUES (@ClientID, @ProduitID, @Quantite, GETDATE());

    PRINT 'Commande créée avec succès';
    RETURN 1;  -- Succès
END;
```

**Avantage de cette approche :**
- Le code est plus **lisible** (pas de IF imbriqués)
- Chaque validation est **indépendante**
- On sort dès qu'un problème est détecté (pas de traitement inutile)

**Exécution :**

```sql
DECLARE @Code INT;

-- Tentative avec un client inactif
EXEC @Code = SpCreerCommande
    @ClientID = 5,
    @ProduitID = 10,
    @Quantite = 2;

PRINT 'Code de retour : ' + CAST(@Code AS VARCHAR(10));
```

## 4. Valeur de Retour par Défaut

Si vous n'utilisez pas explicitement `RETURN`, SQL Server retourne automatiquement la valeur **0** (zéro).

### Exemple 4 : Retour implicite

```sql
-- Procédure sans RETURN explicite
CREATE PROCEDURE SpAfficherMessage
AS
BEGIN
    PRINT 'Ceci est un message';
    -- Pas de RETURN explicite
END;
```

**Exécution :**

```sql
DECLARE @Code INT;
EXEC @Code = SpAfficherMessage;

PRINT 'Code de retour : ' + CAST(@Code AS VARCHAR(10));
```

**Résultat :**
```
Ceci est un message
Code de retour : 0
```

**Convention :** Par défaut, 0 signifie généralement "succès" ou "pas d'erreur".

## 5. RETURN sans Valeur

Vous pouvez utiliser `RETURN` sans spécifier de valeur pour simplement **quitter la procédure**.

```sql
CREATE PROCEDURE SpExempleReturnVide
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Si le client n'existe pas, sortir immédiatement
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        PRINT 'Client non trouvé';
        RETURN;  -- Sortir sans valeur (retourne 0 par défaut)
    END

    -- Code pour un client existant
    PRINT 'Traitement du client...';
    -- ...
END;
```

## 6. Conventions des Codes de Retour

Voici les conventions couramment utilisées pour les codes de retour :

### Convention Standard

| Code | Signification | Usage |
|------|---------------|-------|
| **0** | Succès (défaut) | Opération réussie, pas d'erreur |
| **1** | Succès explicite | Opération réussie avec confirmation |
| **-1** | Erreur générique | Première erreur possible |
| **-2, -3, -4...** | Erreurs spécifiques | Différents types d'erreur |
| **> 0** | États particuliers | Codes personnalisés (optionnel) |

### Exemple d'utilisation des conventions

```sql
CREATE PROCEDURE SpSupprimerClient
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Vérifier que le client existe
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
        RETURN -1;  -- Erreur : Client inexistant

    -- Vérifier qu'il n'a pas de commandes
    IF EXISTS (SELECT 1 FROM Commandes WHERE ClientID = @ClientID)
        RETURN -2;  -- Erreur : Client a des commandes

    -- Supprimer le client
    DELETE FROM Clients WHERE ClientID = @ClientID;

    RETURN 1;  -- Succès
END;
```

**Utilisation avec messages explicites :**

```sql
DECLARE @Resultat INT;

EXEC @Resultat = SpSupprimerClient @ClientID = 5;

-- Interpréter le résultat
IF @Resultat = 1
    PRINT '✓ Client supprimé avec succès';
ELSE IF @Resultat = -1
    PRINT '✗ Erreur : Le client n''existe pas';
ELSE IF @Resultat = -2
    PRINT '✗ Erreur : Impossible de supprimer un client avec des commandes';
ELSE
    PRINT '✗ Erreur inconnue';
```

## 7. RETURN vs OUTPUT vs SELECT

Comparons les trois méthodes pour retourner des informations :

### Exemple Comparatif

```sql
-- Méthode 1 : RETURN (code d'état uniquement)
CREATE PROCEDURE SpMethode1_Return
    @ClientID INT
AS
BEGIN
    IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
        RETURN 1;
    ELSE
        RETURN 0;
END;

-- Utilisation
DECLARE @Existe INT;
EXEC @Existe = SpMethode1_Return @ClientID = 5;
-- @Existe contient 1 ou 0


-- Méthode 2 : OUTPUT (valeur calculée)
CREATE PROCEDURE SpMethode2_Output
    @ClientID INT,
    @NombreCommandes INT OUTPUT
AS
BEGIN
    SELECT @NombreCommandes = COUNT(*)
    FROM Commandes
    WHERE ClientID = @ClientID;
END;

-- Utilisation
DECLARE @NbCmd INT;
EXEC SpMethode2_Output @ClientID = 5, @NombreCommandes = @NbCmd OUTPUT;
-- @NbCmd contient le nombre de commandes


-- Méthode 3 : SELECT (jeu de résultats)
CREATE PROCEDURE SpMethode3_Select
    @ClientID INT
AS
BEGIN
    SELECT
        CommandeID,
        DateCommande,
        MontantTotal
    FROM Commandes
    WHERE ClientID = @ClientID;
END;

-- Utilisation
EXEC SpMethode3_Select @ClientID = 5;
-- Retourne un jeu de résultats (tableau)
```

---

### Tableau Comparatif Détaillé

| Aspect | RETURN | OUTPUT | SELECT |
|--------|--------|--------|--------|
| **Type de données** | INT uniquement | Tous types | Tous types |
| **Nombre de valeurs** | 1 seule valeur | Plusieurs possible | Illimité |
| **Usage principal** | Codes d'état | Valeurs calculées | Données tabulaires |
| **Capture** | `EXEC @var = Proc` | Variable OUTPUT | Jeu de résultats |
| **Exemple** | `RETURN 1` (succès) | `@Total INT OUTPUT` | `SELECT * FROM...` |
| **Arrêt procédure** | ✅ Oui (immédiat) | ❌ Non | ❌ Non |
| **Combinable** | Avec OUTPUT et SELECT | Avec RETURN et SELECT | Avec RETURN et OUTPUT |

---

### Quand Utiliser Quoi ?

#### Utilisez RETURN pour :
- ✅ Codes de succès/échec (0, 1, -1, -2, etc.)
- ✅ Indicateurs binaires (oui/non, existe/n'existe pas)
- ✅ Sortir prématurément d'une procédure
- ✅ Codes d'état standardisés

#### Utilisez OUTPUT pour :
- ✅ Retourner 1 à 5 valeurs calculées
- ✅ IDs générés (SCOPE_IDENTITY())
- ✅ Valeurs de tous types (pas seulement INT)
- ✅ Messages d'erreur textuels

#### Utilisez SELECT pour :
- ✅ Jeux de résultats (plusieurs lignes)
- ✅ Rapports et listes
- ✅ Données tabulaires
- ✅ Multiples colonnes

## 8. Combiner RETURN et OUTPUT

Vous pouvez combiner `RETURN` et `OUTPUT` dans la même procédure :

### Exemple 5 : Combinaison RETURN + OUTPUT

```sql
-- Procédure retournant un code ET des valeurs calculées
CREATE PROCEDURE SpAnalyserClient
    @ClientID INT,
    @NombreCommandes INT OUTPUT,
    @TotalAchats DECIMAL(10,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    -- Initialiser les sorties
    SET @NombreCommandes = 0;
    SET @TotalAchats = 0;

    -- Vérifier que le client existe
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        RETURN -1;  -- Erreur : Client inexistant
    END

    -- Calculer les statistiques
    SELECT
        @NombreCommandes = COUNT(*),
        @TotalAchats = ISNULL(SUM(MontantTotal), 0)
    FROM Commandes
    WHERE ClientID = @ClientID;

    -- Vérifier si le client a des commandes
    IF @NombreCommandes = 0
        RETURN 0;  -- Succès mais pas de commandes

    RETURN 1;  -- Succès avec commandes
END;
```

**Utilisation :**

```sql
DECLARE @Code INT;
DECLARE @NbCmd INT;
DECLARE @Total DECIMAL(10,2);

-- Exécuter la procédure
EXEC @Code = SpAnalyserClient
    @ClientID = 5,
    @NombreCommandes = @NbCmd OUTPUT,
    @TotalAchats = @Total OUTPUT;

-- Interpréter le résultat
IF @Code = 1
BEGIN
    PRINT 'Client trouvé avec commandes';
    PRINT 'Nombre de commandes : ' + CAST(@NbCmd AS VARCHAR(10));
    PRINT 'Total des achats : ' + CAST(@Total AS VARCHAR(20)) + '€';
END
ELSE IF @Code = 0
BEGIN
    PRINT 'Client trouvé mais sans commandes';
END
ELSE IF @Code = -1
BEGIN
    PRINT 'Erreur : Client inexistant';
END
```

**Avantage :** Vous obtenez à la fois le **code d'état** (succès/échec) et les **valeurs calculées**.

## 9. Exemples Pratiques et Réalistes

### Exemple 6 : Système d'Authentification

```sql
-- Procédure de connexion complète
CREATE PROCEDURE SpAuthentifier
    @Email VARCHAR(100),
    @MotDePasse VARCHAR(100),
    @UtilisateurID INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @MotDePasseStocke VARCHAR(100);
    DECLARE @Actif BIT;
    DECLARE @NbTentatives INT;

    -- Initialiser
    SET @UtilisateurID = NULL;

    -- Vérifier que l'email existe
    IF NOT EXISTS (SELECT 1 FROM Utilisateurs WHERE Email = @Email)
    BEGIN
        PRINT 'Email non reconnu';
        RETURN -1;  -- Email inexistant
    END

    -- Récupérer les informations
    SELECT
        @UtilisateurID = UtilisateurID,
        @MotDePasseStocke = MotDePasse,
        @Actif = Actif,
        @NbTentatives = TentativesEchouees
    FROM Utilisateurs
    WHERE Email = @Email;

    -- Vérifier si le compte est bloqué (trop de tentatives)
    IF @NbTentatives >= 5
    BEGIN
        PRINT 'Compte bloqué après trop de tentatives';
        SET @UtilisateurID = NULL;
        RETURN -2;  -- Compte bloqué
    END

    -- Vérifier si le compte est actif
    IF @Actif = 0
    BEGIN
        PRINT 'Compte désactivé';
        SET @UtilisateurID = NULL;
        RETURN -3;  -- Compte inactif
    END

    -- Vérifier le mot de passe
    IF @MotDePasseStocke != @MotDePasse
    BEGIN
        -- Incrémenter le compteur de tentatives échouées
        UPDATE Utilisateurs
        SET TentativesEchouees = TentativesEchouees + 1
        WHERE Email = @Email;

        PRINT 'Mot de passe incorrect';
        SET @UtilisateurID = NULL;
        RETURN -4;  -- Mot de passe incorrect
    END

    -- Connexion réussie : réinitialiser les tentatives
    UPDATE Utilisateurs
    SET
        TentativesEchouees = 0,
        DerniereConnexion = GETDATE()
    WHERE Email = @Email;

    PRINT 'Authentification réussie';
    RETURN 1;  -- Succès
END;
```

**Utilisation dans une application :**

```sql
DECLARE @CodeAuth INT;
DECLARE @UserID INT;

-- Tenter de se connecter
EXEC @CodeAuth = SpAuthentifier
    @Email = 'utilisateur@exemple.com',
    @MotDePasse = 'MonMotDePasse123',
    @UtilisateurID = @UserID OUTPUT;

-- Gérer le résultat
IF @CodeAuth = 1
BEGIN
    PRINT 'Bienvenue ! Votre ID utilisateur : ' + CAST(@UserID AS VARCHAR(10));
    -- Rediriger vers l'application
END
ELSE
BEGIN
    -- Afficher le message d'erreur approprié
    IF @CodeAuth = -1
        PRINT 'Identifiants incorrects';
    ELSE IF @CodeAuth = -2
        PRINT 'Compte bloqué. Contactez l''administrateur';
    ELSE IF @CodeAuth = -3
        PRINT 'Compte désactivé';
    ELSE IF @CodeAuth = -4
        PRINT 'Mot de passe incorrect. Tentatives restantes : ' +
              CAST(5 - (SELECT TentativesEchouees FROM Utilisateurs WHERE Email = 'utilisateur@exemple.com') AS VARCHAR(10));
END
```

### Exemple 7 : Traitement de Commande

```sql
-- Procédure de validation de commande
CREATE PROCEDURE SpValiderCommande
    @CommandeID INT,
    @MontantTotal DECIMAL(10,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @Statut VARCHAR(20);

    -- Initialiser
    SET @MontantTotal = 0;

    -- Vérifier que la commande existe
    IF NOT EXISTS (SELECT 1 FROM Commandes WHERE CommandeID = @CommandeID)
        RETURN -1;  -- Commande inexistante

    -- Récupérer le statut et le montant
    SELECT
        @Statut = Statut,
        @MontantTotal = MontantTotal
    FROM Commandes
    WHERE CommandeID = @CommandeID;

    -- Vérifier le statut actuel
    IF @Statut = 'Validée'
        RETURN 0;  -- Déjà validée (pas une erreur)

    IF @Statut = 'Annulée'
        RETURN -2;  -- Commande annulée

    -- Vérifier le montant
    IF @MontantTotal <= 0
        RETURN -3;  -- Montant invalide

    -- Valider la commande
    UPDATE Commandes
    SET
        Statut = 'Validée',
        DateValidation = GETDATE()
    WHERE CommandeID = @CommandeID;

    -- Logger l'opération
    INSERT INTO LogOperations (TypeOperation, DateOperation, Details)
    VALUES ('VALIDATION_COMMANDE', GETDATE(), 'Commande ' + CAST(@CommandeID AS VARCHAR(10)));

    RETURN 1;  -- Succès
END;
```

**Utilisation :**

```sql
DECLARE @Code INT;
DECLARE @Montant DECIMAL(10,2);

EXEC @Code = SpValiderCommande
    @CommandeID = 12345,
    @MontantTotal = @Montant OUTPUT;

-- Afficher le résultat approprié
IF @Code = 1
    PRINT 'Commande validée avec succès. Montant : ' + CAST(@Montant AS VARCHAR(20)) + '€';
ELSE IF @Code = 0
    PRINT 'Cette commande était déjà validée';
ELSE IF @Code = -1
    PRINT 'Erreur : Commande introuvable';
ELSE IF @Code = -2
    PRINT 'Erreur : Impossible de valider une commande annulée';
ELSE IF @Code = -3
    PRINT 'Erreur : Montant de commande invalide';
```

## 10. Gestion d'Erreurs avec RETURN

`RETURN` peut être utilisé dans les blocs TRY...CATCH pour gérer les erreurs :

```sql
CREATE PROCEDURE SpTransfererFonds
    @CompteSource INT,
    @CompteDestination INT,
    @Montant DECIMAL(10,2)
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        -- Vérifications AVANT d'ouvrir la transaction
        -- (un RETURN ne fait PAS de ROLLBACK : voir la note ci-dessous)
        IF @Montant <= 0
            RETURN -1;  -- Montant invalide

        IF NOT EXISTS (SELECT 1 FROM Comptes WHERE CompteID = @CompteSource)
            RETURN -2;  -- Compte source inexistant

        IF NOT EXISTS (SELECT 1 FROM Comptes WHERE CompteID = @CompteDestination)
            RETURN -3;  -- Compte destination inexistant

        -- Vérifier le solde
        IF (SELECT Solde FROM Comptes WHERE CompteID = @CompteSource) < @Montant
            RETURN -4;  -- Solde insuffisant

        -- Toutes les validations sont passées : ouvrir la transaction
        BEGIN TRANSACTION;

        -- Effectuer le transfert
        UPDATE Comptes
        SET Solde = Solde - @Montant
        WHERE CompteID = @CompteSource;

        UPDATE Comptes
        SET Solde = Solde + @Montant
        WHERE CompteID = @CompteDestination;

        COMMIT TRANSACTION;
        RETURN 1;  -- Succès

    END TRY
    BEGIN CATCH
        -- En cas d'erreur SQL
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;

        PRINT 'Erreur système : ' + ERROR_MESSAGE();
        RETURN -99;  -- Erreur système
    END CATCH
END;
```

> ⚠️ **Piège : `RETURN` ne valide ni n'annule une transaction ouverte.**  
> Si vous ouvrez la transaction *avant* les validations, un `RETURN -1` (ou -2, -3, -4) quitte la procédure **en laissant la transaction ouverte** : le `RETURN` sort immédiatement, et le bloc `CATCH` ne se déclenche **pas** (il n'intercepte que les erreurs SQL, pas un `RETURN`). SQL Server signale alors l'erreur **266** *« Transaction count after EXECUTE indicates a mismatching number of BEGIN and COMMIT statements »*, et la transaction reste active — verrous conservés, risque de blocage.
>
> Deux solutions :  
> 1. **Valider en amont** (approche ci-dessus) : placez tous les `RETURN` de validation **avant** le `BEGIN TRANSACTION`. C'est le plus simple et le plus lisible.  
> 2. Si une vérification doit absolument se faire *dans* la transaction, faites un `ROLLBACK TRANSACTION;` **juste avant** chaque `RETURN` d'erreur.

## 12. Erreurs Courantes à Éviter

### Erreur 1 : Utiliser RETURN pour retourner des données

```sql
-- ❌ ERREUR : RETURN ne peut retourner qu'un INT
CREATE PROCEDURE SpMauvais
AS
BEGIN
    RETURN 'Message d''erreur';  -- Échec à l'exécution : conversion impossible en INT
END;

-- ✅ CORRECT : Utiliser OUTPUT pour les messages
CREATE PROCEDURE SpCorrect
    @Message VARCHAR(255) OUTPUT
AS
BEGIN
    SET @Message = 'Message d''erreur';
    RETURN -1;  -- Code d'erreur
END;
```

### Erreur 2 : Ne pas capturer la valeur de retour

```sql
-- ❌ ERREUR : Ne pas capturer le code
EXEC SpValiderClient @ClientID = 5;
-- Le code de retour est perdu !

-- ✅ CORRECT : Capturer le code
DECLARE @Code INT;
EXEC @Code = SpValiderClient @ClientID = 5;
IF @Code = 1
    PRINT 'Validation réussie';
```

### Erreur 3 : Oublier de documenter les codes

```sql
-- ❌ MAUVAIS : Codes mystérieux
IF @Code = 42
    PRINT 'Quelque chose s''est passé...';  -- Quoi exactement ?

-- ✅ BON : Codes documentés et explicites
/*
Codes de retour :
    1 : Succès
    42 : Client VIP nécessitant approbation manuelle
*/
IF @Code = 42
    PRINT 'Client VIP : Approbation manuelle requise';
```

### Erreur 4 : Utiliser des codes incohérents

```sql
-- ❌ MAUVAIS : Pas de logique dans les codes
RETURN 5;   -- Qu'est-ce que 5 signifie ?
RETURN 18;  -- Et 18 ?
RETURN -42; -- Et -42 ?

-- ✅ BON : Convention cohérente
RETURN 1;   -- Succès
RETURN 0;   -- Neutre / Déjà fait
RETURN -1;  -- Première erreur
RETURN -2;  -- Deuxième erreur
```

## 13. Bonnes Pratiques

### ✅ À FAIRE

1. **Utiliser des conventions cohérentes**
   ```sql
   -- Convention standard
   RETURN 1;   -- Succès
   RETURN 0;   -- Neutre
   RETURN -1;  -- Erreur 1
   RETURN -2;  -- Erreur 2
   ```

2. **Documenter tous les codes de retour**
   - Dans l'en-tête de la procédure
   - Dans la documentation du projet

3. **Toujours capturer la valeur de retour**
   ```sql
   DECLARE @Code INT;
   EXEC @Code = MaProcedure;
   ```

4. **Combiner avec OUTPUT pour plus d'informations**
   ```sql
   DECLARE @Code INT, @Message VARCHAR(255);
   EXEC @Code = MaProcedure @MessageErreur = @Message OUTPUT;
   ```

5. **Utiliser RETURN pour sortir tôt**
   ```sql
   IF @Erreur
   BEGIN
       PRINT 'Erreur détectée';
       RETURN -1;  -- Sortir immédiatement
   END
   ```

### ❌ À ÉVITER

1. **Ne pas retourner de valeurs non-INT**
   - RETURN accepte uniquement des entiers

2. **Ne pas ignorer les codes de retour**
   - Toujours les vérifier

3. **Ne pas utiliser de codes magiques non documentés**
   - Expliquez ce que chaque code signifie

4. **Ne pas mélanger les conventions**
   - Soyez cohérent dans tout le projet

## Résumé

### Points Clés

**Qu'est-ce que RETURN ?**
- Instruction qui termine immédiatement une procédure
- Retourne un code d'état **entier (INT)**
- Valeur par défaut : 0 (si pas de RETURN explicite)

**Syntaxe :**
```sql
RETURN valeur_entiere;
```

**Capture de la valeur :**
```sql
DECLARE @Code INT;
EXEC @Code = nom_procedure parametres;
```

**Conventions courantes :**
- `1` : Succès explicite
- `0` : Succès par défaut / Neutre
- `-1, -2, -3...` : Différents types d'erreur
- Positifs > 1 : États particuliers (optionnel)

**Comparaison avec OUTPUT et SELECT :**
- **RETURN** : Codes d'état (INT uniquement, 1 valeur)
- **OUTPUT** : Valeurs calculées (tous types, plusieurs valeurs)
- **SELECT** : Jeux de résultats (tableaux de données)

**Quand utiliser RETURN :**
- ✅ Indiquer le succès ou l'échec d'une opération
- ✅ Codes d'état standardisés
- ✅ Sortir prématurément d'une procédure
- ✅ Validation avec codes d'erreur multiples

**Bonnes pratiques :**
- Documenter tous les codes de retour
- Utiliser des conventions cohérentes
- Toujours capturer la valeur
- Combiner avec OUTPUT si nécessaire

`RETURN` est un outil simple mais essentiel pour communiquer l'état d'exécution des procédures stockées. Maîtriser son utilisation permet de créer des APIs de base de données robustes et faciles à utiliser !
