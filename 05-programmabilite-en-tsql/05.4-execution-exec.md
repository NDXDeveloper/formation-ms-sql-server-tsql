# 5.5.4 Exécution (EXECUTE ou EXEC)

## Introduction

Après avoir créé une procédure stockée, il faut savoir comment l'**exécuter** (ou l'**appeler**). SQL Server offre plusieurs façons d'exécuter une procédure stockée, chacune ayant ses particularités et ses cas d'usage.

Dans cette section, nous allons explorer en détail toutes les méthodes pour exécuter les procédures stockées efficacement.

### Qu'est-ce que l'Exécution d'une Procédure ?

**Exécuter une procédure**, c'est déclencher son code pour qu'il soit traité par SQL Server. C'est comme appuyer sur le bouton "Play" d'une vidéo : le contenu (les instructions SQL) est lu et exécuté.

**Analogie :** Si la procédure est une **recette de cuisine**, l'exécution c'est le moment où vous **suivez les étapes** pour préparer le plat.

---

## 1. Syntaxes de Base

SQL Server offre deux mots-clés pour exécuter une procédure : `EXECUTE` et `EXEC`.

### 1.1 EXECUTE (forme complète)

```sql
EXECUTE nom_procedure;
```

### 1.2 EXEC (forme abrégée)

```sql
EXEC nom_procedure;
```

**Important :** `EXECUTE` et `EXEC` sont **strictement équivalents**. `EXEC` est simplement une version abrégée et plus couramment utilisée.

### 1.3 Sans mot-clé (cas particulier)

Si l'exécution de la procédure est la **première instruction** du batch, vous pouvez omettre le mot-clé :

```sql
nom_procedure;
```

**Recommandation :** Utilisez toujours `EXEC` pour la clarté, même si ce n'est pas obligatoire.

---

## 2. Exécution Simple (Sans Paramètres)

### Exemple 1 : Procédure la plus simple

```sql
-- Créer une procédure sans paramètres
CREATE PROCEDURE SpDireBonjour
AS
BEGIN
    PRINT 'Bonjour, bienvenue dans SQL Server !';
END;
```

**Trois façons de l'exécuter :**

```sql
-- Méthode 1 : EXECUTE (forme complète)
EXECUTE SpDireBonjour;

-- Méthode 2 : EXEC (forme abrégée - recommandée)
EXEC SpDireBonjour;

-- Méthode 3 : Sans mot-clé (si première instruction)
SpDireBonjour;
```

**Résultat pour toutes les méthodes :**
```
Bonjour, bienvenue dans SQL Server !
```

---

### Exemple 2 : Procédure qui retourne des données

```sql
-- Procédure qui affiche une liste
CREATE PROCEDURE SpListerClients
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ClientID,
        Nom,
        Prenom,
        Email
    FROM Clients
    ORDER BY Nom;
END;
```

**Exécution :**

```sql
EXEC SpListerClients;
```

**Résultat :** Un jeu de résultats avec tous les clients.

## 3. Exécution avec Paramètres

### 3.1 Passage Par Position

Les valeurs sont passées dans **l'ordre de déclaration** des paramètres.

```sql
-- Procédure avec paramètres
CREATE PROCEDURE SpObtenirClient
    @ClientID INT,
    @InclureInactifs BIT
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Actif
    FROM Clients
    WHERE
        ClientID = @ClientID
        AND (@InclureInactifs = 1 OR Actif = 1);
END;
```

**Exécution par position :**

```sql
-- Les valeurs sont dans l'ordre : ClientID, puis InclureInactifs
EXEC SpObtenirClient 5, 1;
```

**Équivalent à :**
- `@ClientID = 5`
- `@InclureInactifs = 1`

---

### 3.2 Passage Par Nom (Recommandé)

Vous spécifiez explicitement le nom de chaque paramètre.

```sql
-- Exécution par nom (plus clair)
EXEC SpObtenirClient
    @ClientID = 5,
    @InclureInactifs = 1;
```

**Avantages du passage par nom :**
- ✅ **Lisibilité** : On voit clairement quelle valeur correspond à quel paramètre
- ✅ **Flexibilité** : L'ordre n'a pas d'importance
- ✅ **Maintenance** : Si la procédure change, le code reste clair
- ✅ **Sécurité** : Moins de risque d'erreur

**Exemple avec ordre différent :**

```sql
-- L'ordre n'a pas d'importance avec le passage par nom
EXEC SpObtenirClient
    @InclureInactifs = 1,  -- Paramètre 2 en premier
    @ClientID = 5;         -- Paramètre 1 en second
```

**Résultat :** Fonctionne parfaitement !

---

### 3.3 Mélange Position et Nom

Vous pouvez mélanger les deux approches, mais les paramètres par position doivent venir **avant** les paramètres par nom.

```sql
-- ✅ CORRECT : Position d'abord, puis nom
EXEC SpObtenirClient 5, @InclureInactifs = 1;

-- ❌ ERREUR : Nom puis position (interdit)
EXEC SpObtenirClient @ClientID = 5, 1;
```

**Règle :** Une fois que vous utilisez le passage par nom, vous ne pouvez plus revenir au passage par position.

## 4. Paramètres Optionnels (Valeurs Par Défaut)

### 4.1 Principe

Les paramètres avec valeurs par défaut peuvent être omis lors de l'exécution.

```sql
-- Procédure avec paramètres optionnels
CREATE PROCEDURE SpRechercherProduits
    @Categorie VARCHAR(50) = NULL,     -- Optionnel
    @PrixMax DECIMAL(10,2) = 1000,     -- Valeur par défaut : 1000
    @EnStock BIT = 1                   -- Valeur par défaut : 1 (vrai)
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ProduitID,
        NomProduit,
        Categorie,
        Prix,
        StockDisponible
    FROM Produits
    WHERE
        (@Categorie IS NULL OR Categorie = @Categorie)
        AND Prix <= @PrixMax
        AND (@EnStock = 0 OR StockDisponible > 0)
    ORDER BY Prix;
END;
```

---

### 4.2 Différentes Façons d'Exécuter

```sql
-- 1. Sans aucun paramètre (tous par défaut)
EXEC SpRechercherProduits;
-- Résultat : Tous les produits en stock, prix <= 1000

-- 2. Avec un seul paramètre
EXEC SpRechercherProduits @Categorie = 'Électronique';
-- Résultat : Produits électroniques en stock, prix <= 1000

-- 3. Avec deux paramètres
EXEC SpRechercherProduits
    @Categorie = 'Électronique',
    @PrixMax = 500;
-- Résultat : Produits électroniques en stock, prix <= 500

-- 4. Avec tous les paramètres
EXEC SpRechercherProduits
    @Categorie = 'Électronique',
    @PrixMax = 500,
    @EnStock = 0;  -- Inclure aussi les produits en rupture
-- Résultat : Tous produits électroniques, prix <= 500 (même sans stock)
```

---

### 4.3 Sauter des Paramètres Optionnels

Avec le passage par nom, vous pouvez sauter des paramètres intermédiaires :

```sql
-- Sauter le deuxième paramètre
EXEC SpRechercherProduits
    @Categorie = 'Électronique',
    -- @PrixMax sauté (utilisera 1000 par défaut)
    @EnStock = 0;

-- Ou utiliser seulement le dernier paramètre
EXEC SpRechercherProduits
    @EnStock = 0;  -- Les deux premiers utilisent leurs valeurs par défaut
```

**Important :** Avec le passage par position, vous ne pouvez pas sauter des paramètres intermédiaires.

```sql
-- ❌ ERREUR : Impossible de sauter un paramètre par position
EXEC SpRechercherProduits 'Électronique', , 0;  -- Syntaxe invalide

-- ✅ CORRECT : Utiliser DEFAULT pour un paramètre
EXEC SpRechercherProduits 'Électronique', DEFAULT, 0;
```

## 5. Capturer la Valeur de Retour (RETURN)

### 5.1 Syntaxe

Pour capturer le code de retour d'une procédure, utilisez la syntaxe suivante :

```sql
DECLARE @CodeRetour INT;
EXEC @CodeRetour = nom_procedure parametres;
```

---

### 5.2 Exemple

```sql
-- Procédure qui retourne un code
CREATE PROCEDURE SpValiderEmail
    @Email VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    -- Vérifier le format de base
    IF @Email NOT LIKE '%@%.%'
        RETURN -1;  -- Format invalide

    -- Vérifier si déjà utilisé
    IF EXISTS (SELECT 1 FROM Clients WHERE Email = @Email)
        RETURN -2;  -- Email déjà utilisé

    RETURN 1;  -- Email valide
END;
```

**Exécution avec capture du code :**

```sql
-- Déclarer une variable pour le code de retour
DECLARE @Code INT;

-- Exécuter et capturer
EXEC @Code = SpValiderEmail @Email = 'test@exemple.com';

-- Utiliser le code
IF @Code = 1
    PRINT 'Email valide';
ELSE IF @Code = -1
    PRINT 'Format d''email invalide';
ELSE IF @Code = -2
    PRINT 'Email déjà utilisé';
```

## 6. Paramètres OUTPUT

### 6.1 Syntaxe

Pour les paramètres OUTPUT, le mot-clé `OUTPUT` (ou `OUT`) doit être présent lors de l'exécution.

```sql
-- Déclaration de variables pour recevoir les sorties
DECLARE @Variable1 type;
DECLARE @Variable2 type;

-- Exécution avec OUTPUT
EXEC nom_procedure
    @parametre_entree = valeur,
    @parametre_sortie1 = @Variable1 OUTPUT,
    @parametre_sortie2 = @Variable2 OUTPUT;
```

---

### 6.2 Exemple Complet

```sql
-- Procédure avec paramètres INPUT et OUTPUT
CREATE PROCEDURE SpCalculerStatistiquesClient
    @ClientID INT,                     -- Entrée
    @NombreCommandes INT OUTPUT,       -- Sortie
    @TotalAchats DECIMAL(10,2) OUTPUT  -- Sortie
AS
BEGIN
    SET NOCOUNT ON;

    -- Calculer les statistiques
    SELECT
        @NombreCommandes = COUNT(*),
        @TotalAchats = ISNULL(SUM(MontantTotal), 0)
    FROM Commandes
    WHERE ClientID = @ClientID;

    RETURN 1;  -- Code de succès
END;
```

**Exécution complète :**

```sql
-- Variables pour les résultats
DECLARE @Code INT;
DECLARE @NbCmd INT;
DECLARE @Total DECIMAL(10,2);

-- Exécuter avec capture du code ET des paramètres OUTPUT
EXEC @Code = SpCalculerStatistiquesClient
    @ClientID = 5,
    @NombreCommandes = @NbCmd OUTPUT,    -- OUTPUT obligatoire !
    @TotalAchats = @Total OUTPUT;        -- OUTPUT obligatoire !

-- Vérifier le résultat
IF @Code = 1
BEGIN
    PRINT 'Succès !';
    PRINT 'Nombre de commandes : ' + CAST(@NbCmd AS VARCHAR(10));
    PRINT 'Total des achats : ' + CAST(@Total AS VARCHAR(20)) + '€';
END
```

**Rappel important :** N'oubliez jamais le mot-clé `OUTPUT` lors de l'exécution, sinon les variables ne recevront pas les valeurs !

## 7. Exécution avec Schéma

### 7.1 Spécifier le Schéma

Il est recommandé de toujours spécifier le **schéma** lors de l'exécution.

```sql
-- ✅ BONNE PRATIQUE : Spécifier le schéma
EXEC dbo.SpListerClients;

-- ⚠️ ACCEPTABLE : Sans schéma (utilise le schéma par défaut)
EXEC SpListerClients;
```

**Avantages de spécifier le schéma :**
- ✅ Performance légèrement meilleure (pas de recherche)
- ✅ Clarté du code
- ✅ Évite les ambiguïtés si plusieurs schémas existent

---

### 7.2 Procédures dans d'Autres Bases

Vous pouvez exécuter une procédure d'une autre base de données :

```sql
-- Syntaxe : [nom_base].[schéma].[nom_procedure]
EXEC AutreBase.dbo.SpListerClients;

-- Avec des paramètres
EXEC AutreBase.dbo.SpObtenirClient @ClientID = 5;
```

**Note :** Vous devez avoir les permissions nécessaires sur l'autre base.

## 8. Exécution Depuis une Application

### 8.1 Exemple en C# (ADO.NET)

```csharp
using (SqlConnection conn = new SqlConnection(connectionString))
{
    SqlCommand cmd = new SqlCommand("SpObtenirClient", conn);
    cmd.CommandType = CommandType.StoredProcedure;

    // Ajouter les paramètres d'entrée
    cmd.Parameters.AddWithValue("@ClientID", 5);

    // Ajouter un paramètre de sortie
    SqlParameter outputParam = new SqlParameter("@NombreCommandes", SqlDbType.Int);
    outputParam.Direction = ParameterDirection.Output;
    cmd.Parameters.Add(outputParam);

    // Ajouter le code de retour
    SqlParameter returnValue = new SqlParameter();
    returnValue.Direction = ParameterDirection.ReturnValue;
    cmd.Parameters.Add(returnValue);

    conn.Open();
    cmd.ExecuteNonQuery();

    // Récupérer les résultats
    int nbCommandes = (int)outputParam.Value;
    int codeRetour = (int)returnValue.Value;

    Console.WriteLine($"Nombre de commandes : {nbCommandes}");
    Console.WriteLine($"Code de retour : {codeRetour}");
}
```

---

### 8.2 Exemple en Python (pyodbc)

```python
import pyodbc

conn = pyodbc.connect('connection_string')
cursor = conn.cursor()

# Paramètres d'entrée
client_id = 5

# Exécuter la procédure

# Récupérer les résultats
for row in cursor:
    print(f"Client : {row.Nom} {row.Prenom}")

cursor.close()
conn.close()
```

## 9. Exécution Dynamique (SQL Dynamique)

### 9.1 EXEC avec Chaîne de Caractères

Vous pouvez exécuter une procédure dont le nom est construit dynamiquement :

```sql
-- Construire le nom de la procédure dynamiquement
DECLARE @NomProcedure NVARCHAR(128) = 'SpListerClients';

-- Exécuter avec EXEC()
EXEC @NomProcedure;
```

---

### 9.2 Exécution Complètement Dynamique

```sql
DECLARE @SQL NVARCHAR(MAX);
DECLARE @ClientID INT = 5;

-- Construire la commande SQL
SET @SQL = N'EXEC SpObtenirClient @ClientID = ' + CAST(@ClientID AS NVARCHAR(10));

-- Exécuter
EXEC sp_executesql @SQL;
```

**Meilleure approche avec paramètres :**

```sql
DECLARE @SQL NVARCHAR(MAX);
DECLARE @ClientID INT = 5;

-- Construire la commande avec paramètre
SET @SQL = N'EXEC SpObtenirClient @ClientID = @ID';

-- Exécuter avec sp_executesql (plus sûr)
EXEC sp_executesql
    @SQL,
    N'@ID INT',  -- Déclaration du paramètre
    @ID = @ClientID;  -- Valeur du paramètre
```

**Avantage de sp_executesql :** Protection contre l'injection SQL et réutilisation du plan d'exécution.

## 10. Exécution en Cascade (Chaînage)

Une procédure peut en appeler une autre.

### 10.1 Exemple Simple

```sql
-- Première procédure
CREATE PROCEDURE SpLoggerOperation
    @TypeOperation VARCHAR(50),
    @Details VARCHAR(255)
AS
BEGIN
    INSERT INTO LogOperations (TypeOperation, DateOperation, Details)
    VALUES (@TypeOperation, GETDATE(), @Details);
END;

-- Deuxième procédure qui appelle la première
CREATE PROCEDURE SpCreerClient
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    -- Créer le client
    INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
    VALUES (@Nom, @Prenom, @Email, GETDATE());

    -- Logger l'opération (appel de l'autre procédure)
    EXEC SpLoggerOperation
        @TypeOperation = 'CREATION_CLIENT',
        @Details = 'Client créé : ' + @Email;

    PRINT 'Client créé et opération loggée';
END;
```

**Exécution :**

```sql
EXEC SpCreerClient
    @Nom = 'Martin',
    @Prenom = 'Sophie',
    @Email = 'sophie.martin@email.com';
```

**Résultat :** Le client est créé ET l'opération est loggée automatiquement.

---

### 10.2 Capturer le Code de Retour d'une Procédure Appelée

```sql
CREATE PROCEDURE SpValiderEtCreerClient
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @CodeValidation INT;

    -- Appeler une procédure de validation
    EXEC @CodeValidation = SpValiderEmail @Email = @Email;

    -- Vérifier le résultat
    IF @CodeValidation != 1
    BEGIN
        PRINT 'Email invalide, création annulée';
        RETURN @CodeValidation;  -- Propager le code d'erreur
    END

    -- Email valide, créer le client
    INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
    VALUES (@Nom, @Prenom, @Email, GETDATE());

    RETURN 1;  -- Succès
END;
```

## 11. Exécution avec Permissions

### 11.1 Exécuter en Tant Que (EXECUTE AS)

Vous pouvez exécuter une procédure avec les permissions d'un autre utilisateur :

```sql
-- Exécuter avec les permissions d'un autre utilisateur
EXECUTE AS USER = 'AutreUtilisateur';
EXEC SpListerClients;
REVERT;  -- Revenir à l'utilisateur original
```

**Usage :** Utile pour tester les permissions ou pour des contextes de sécurité spécifiques.

---

### 11.2 Donner la Permission d'Exécuter

```sql
-- Donner la permission d'exécuter une procédure
GRANT EXECUTE ON SpListerClients TO UtilisateurTest;

-- Retirer la permission
REVOKE EXECUTE ON SpListerClients FROM UtilisateurTest;

-- Refuser explicitement
DENY EXECUTE ON SpListerClients TO UtilisateurTest;
```

## 12. Astuces et Techniques Avancées

### 12.1 Exécution Conditionnelle

```sql
DECLARE @TypeRapport VARCHAR(20) = 'Clients';

-- Exécuter une procédure différente selon une condition
IF @TypeRapport = 'Clients'
    EXEC SpRapportClients;
ELSE IF @TypeRapport = 'Produits'
    EXEC SpRapportProduits;
ELSE IF @TypeRapport = 'Ventes'
    EXEC SpRapportVentes;
ELSE
    PRINT 'Type de rapport inconnu';
```

---

### 12.2 Exécution dans une Boucle

```sql
DECLARE @ClientID INT = 1;
DECLARE @MaxClientID INT;

-- Obtenir le nombre de clients
SELECT @MaxClientID = MAX(ClientID) FROM Clients;

-- Boucle sur tous les clients
WHILE @ClientID <= @MaxClientID
BEGIN
    -- Exécuter la procédure pour chaque client
    EXEC SpEnvoyerEmailClient @ClientID = @ClientID;

    SET @ClientID = @ClientID + 1;
END
```

**Attention :** Les boucles peuvent être lentes sur de gros volumes. Privilégiez les opérations ensemblistes quand c'est possible.

---

### 12.3 Exécution avec Transaction

```sql
BEGIN TRANSACTION;

BEGIN TRY
    -- Exécuter plusieurs procédures dans une transaction
    EXEC SpCreerCommande @ClientID = 5, @ProduitID = 10, @Quantite = 2;
    EXEC SpMettreAJourStock @ProduitID = 10, @Quantite = -2;
    EXEC SpEnvoyerEmailConfirmation @ClientID = 5;

    -- Tout s'est bien passé
    COMMIT TRANSACTION;
    PRINT 'Transaction réussie';

END TRY
BEGIN CATCH
    -- En cas d'erreur, annuler tout
    ROLLBACK TRANSACTION;
    PRINT 'Erreur : ' + ERROR_MESSAGE();
END CATCH
```

## 14. Erreurs Courantes et Solutions

### Erreur 1 : Oublier OUTPUT

```sql
-- ❌ ERREUR : OUTPUT manquant
DECLARE @Total INT;
EXEC SpCalculerTotal @Resultat = @Total;  -- @Total reste NULL !

-- ✅ CORRECT
DECLARE @Total INT;
EXEC SpCalculerTotal @Resultat = @Total OUTPUT;
```

---

### Erreur 2 : Mauvais Ordre des Paramètres

```sql
-- Procédure : SpCreerClient(@Nom, @Prenom, @Email)

-- ❌ ERREUR : Ordre incorrect
EXEC SpCreerClient 'jean.martin@email.com', 'Martin', 'Jean';

-- ✅ CORRECT : Utiliser les noms
EXEC SpCreerClient
    @Nom = 'Martin',
    @Prenom = 'Jean',
    @Email = 'jean.martin@email.com';
```

---

### Erreur 3 : Oublier @ devant les Noms de Paramètres

```sql
-- ❌ ERREUR : @ manquant
EXEC SpObtenirClient ClientID = 5;

-- ✅ CORRECT
EXEC SpObtenirClient @ClientID = 5;
```

---

### Erreur 4 : Procédure Introuvable

```sql
-- ❌ ERREUR : Nom incorrect ou mauvaise base
EXEC SpListerClient;  -- Faute de frappe (manque le 's')

-- Message d'erreur : "Could not find stored procedure 'SpListerClient'"

-- ✅ CORRECT
EXEC SpListerClients;
```

**Solution :** Vérifiez l'orthographe et le schéma :
```sql
-- Lister toutes les procédures
SELECT name FROM sys.procedures ORDER BY name;
```

## 15. Bonnes Pratiques

### ✅ À FAIRE

1. **Toujours utiliser EXEC explicitement**
   ```sql
   -- ✅ BON
   EXEC SpListerClients;

   -- ⚠️ ACCEPTABLE mais moins clair
   SpListerClients;
   ```

2. **Préférer le passage par nom**
   ```sql
   -- ✅ MEILLEUR
   EXEC SpCreerClient
       @Nom = 'Martin',
       @Prenom = 'Jean',
       @Email = 'jean@email.com';

   -- ⚠️ MOINS CLAIR
   EXEC SpCreerClient 'Martin', 'Jean', 'jean@email.com';
   ```

3. **Spécifier le schéma**
   ```sql
   -- ✅ BON
   EXEC dbo.SpListerClients;

   -- ⚠️ ACCEPTABLE
   EXEC SpListerClients;
   ```

4. **Capturer les codes de retour**
   ```sql
   -- ✅ BON
   DECLARE @Code INT;
   EXEC @Code = SpCreerClient @Nom = 'Martin', @Prenom = 'Jean', @Email = 'jean@email.com';
   IF @Code = 1
       PRINT 'Succès';
   ```

5. **Ne jamais oublier OUTPUT**
   ```sql
   -- ✅ BON
   DECLARE @Total INT;
   EXEC SpCalculer @Resultat = @Total OUTPUT;
   ```

6. **Utiliser sp_executesql pour le SQL dynamique**
   ```sql
   -- ✅ MEILLEUR (sécurisé)
   EXEC sp_executesql
       N'EXEC SpObtenirClient @ID',
       N'@ID INT',
       @ID = 5;

   -- ⚠️ MOINS SÛR
   EXEC ('EXEC SpObtenirClient ' + CAST(5 AS VARCHAR(10)));
   ```

### ❌ À ÉVITER

1. **Ne pas construire du SQL dynamique avec concaténation**
   - Risque d'injection SQL

2. **Ne pas oublier les mots-clés OUTPUT lors de l'exécution**
   - Les variables ne recevront pas les valeurs

3. **Ne pas ignorer les codes de retour**
   - Toujours vérifier si l'opération a réussi

4. **Ne pas mélanger position et nom incorrectement**
   - Position d'abord, puis nom uniquement

## 16. Résumé Visuel

```sql
/*
=================================================================
SYNTAXES D'EXÉCUTION - RÉSUMÉ
=================================================================

1. SIMPLE (sans paramètres)
   EXEC SpProcedure;

2. AVEC PARAMÈTRES (par nom - recommandé)
   EXEC SpProcedure
       @Param1 = valeur1,
       @Param2 = valeur2;

3. AVEC PARAMÈTRES (par position)
   EXEC SpProcedure valeur1, valeur2;

4. AVEC CODE DE RETOUR
   DECLARE @Code INT;
   EXEC @Code = SpProcedure @Param = valeur;

5. AVEC PARAMÈTRES OUTPUT
   DECLARE @Resultat INT;
   EXEC SpProcedure
       @Param = valeur,
       @ResultatOutput = @Resultat OUTPUT;

6. COMPLET (code + output)
   DECLARE @Code INT, @Resultat INT;
   EXEC @Code = SpProcedure
       @Param = valeur,
       @ResultatOutput = @Resultat OUTPUT;

7. AVEC SCHÉMA
   EXEC dbo.SpProcedure @Param = valeur;

8. AUTRE BASE
   EXEC AutreBase.dbo.SpProcedure @Param = valeur;

=================================================================
*/
```

## Résumé

### Points Clés

**Mots-clés d'exécution :**
- `EXECUTE` (forme complète)
- `EXEC` (forme abrégée - recommandée)
- Sans mot-clé (si première instruction - déconseillé)

**Passage de paramètres :**
- **Par position** : `EXEC Sp 5, 'texte', 1`
- **Par nom** : `EXEC Sp @Param1 = 5, @Param2 = 'texte'` (recommandé)
- **Mixte** : Position avant, nom après

**Paramètres optionnels :**
- Peuvent être omis
- Utilisent leur valeur par défaut
- Utiliser `DEFAULT` pour sauter en mode position

**Capturer les résultats :**
- Code de retour : `EXEC @Code = SpProcedure`
- Paramètres OUTPUT : `@Variable OUTPUT` (obligatoire)

**Bonnes pratiques :**
- Toujours utiliser `EXEC` explicitement
- Préférer le passage par nom
- Spécifier le schéma (dbo.SpProcedure)
- Capturer et vérifier les codes de retour
- Ne jamais oublier OUTPUT
