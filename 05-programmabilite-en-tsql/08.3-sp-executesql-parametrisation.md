# 5.8.3 Utilisation de sp_executesql pour la paramétrisation

## Introduction : La solution au problème d'injection SQL

Dans la section précédente, nous avons vu les dangers de l'injection SQL. Maintenant, nous allons voir **comment s'en protéger efficacement** en utilisant `sp_executesql` avec des **paramètres**.

### Le principe de la paramétrisation

La **paramétrisation** consiste à séparer clairement :
- **Le code SQL** (la structure de la requête) - ce qui est fixe
- **Les données** (les valeurs) - ce qui est variable

Ainsi, SQL Server sait toujours ce qui est une instruction et ce qui est une donnée, et ne peut jamais les confondre.

### Analogie pour comprendre

**Sans paramétrisation** (recette écrite à la main) :
```
"Mettre " + quantité + " grammes de farine"
→ Si quantité = "500 et jeter tout le reste"
→ La recette devient : "Mettre 500 et jeter tout le reste grammes de farine"
→ Confusion entre ingrédient et instruction !
```

**Avec paramétrisation** (recette à trous) :
```
"Mettre [QUANTITÉ] grammes de farine"
Paramètre: QUANTITÉ = 500
→ La recette reste claire : "Mettre 500 grammes de farine"
→ QUANTITÉ est toujours traité comme une quantité, jamais comme une instruction
```

## Rappel : sp_executesql vs EXEC

### Syntaxe EXEC (non paramétré - dangereux)

```sql
-- ❌ DANGEREUX : Concaténation directe
DECLARE @SQL NVARCHAR(500);
DECLARE @Nom VARCHAR(50) = 'Dupont';

SET @SQL = 'SELECT * FROM Clients WHERE Nom = ''' + @Nom + '''';
EXEC(@SQL);
```

**Problème** : `@Nom` est directement intégré dans la chaîne SQL. Si `@Nom` contient du code SQL malveillant, il sera exécuté.

### Syntaxe sp_executesql (paramétré - sécurisé)

```sql
-- ✅ SÉCURISÉ : Utilisation de paramètres
DECLARE @SQL NVARCHAR(500);
DECLARE @Nom VARCHAR(50) = 'Dupont';

SET @SQL = N'SELECT * FROM Clients WHERE Nom = @Nom_Param';

EXEC sp_executesql
    @SQL,                           -- La requête avec des paramètres
    N'@Nom_Param VARCHAR(50)',      -- Déclaration du paramètre
    @Nom_Param = @Nom;              -- Valeur du paramètre
```

**Protection** : `@Nom_Param` est traité comme une **valeur**, jamais comme du **code SQL**.

## Anatomie de sp_executesql

### Structure complète

```sql
EXEC sp_executesql
    @statement = N'requête_SQL_avec_paramètres',
    @params = N'déclaration_des_paramètres',
    @param1 = valeur1,
    @param2 = valeur2,
    ...
```

### Les trois composants

#### 1. @statement (La requête SQL)

- Type : `NVARCHAR(MAX)`
- **Obligatoire** : Le N devant la chaîne
- Contenu : La requête SQL avec des **placeholders** (paramètres)

```sql
N'SELECT * FROM Clients WHERE Nom = @Nom_Param AND Ville = @Ville_Param'
```

#### 2. @params (Déclaration des paramètres)

- Type : `NVARCHAR(MAX)`
- **Obligatoire** : Le N devant la chaîne
- Contenu : Liste des paramètres avec leurs types
- Syntaxe : `@nom_param TYPE [, @nom_param2 TYPE2, ...]`

```sql
N'@Nom_Param VARCHAR(50), @Ville_Param VARCHAR(50)'
```

#### 3. Assignation des valeurs

- Syntaxe : `@nom_param = valeur`
- Pour chaque paramètre déclaré, vous fournissez sa valeur

```sql
@Nom_Param = @Nom,
@Ville_Param = @Ville
```

### Exemple complet annoté

```sql
-- Variables avec les valeurs à rechercher
DECLARE @NomRecherche VARCHAR(50) = 'Dupont';
DECLARE @VilleRecherche VARCHAR(50) = 'Paris';

-- Construction de la requête SQL
DECLARE @SQL NVARCHAR(500);
SET @SQL = N'SELECT * FROM Clients
             WHERE Nom = @Nom_Param
             AND Ville = @Ville_Param';
--                    ↑            ↑
--                    Ces @ indiquent des PARAMÈTRES

-- Exécution avec sp_executesql
EXEC sp_executesql
    @SQL,                                           -- 1. La requête
    N'@Nom_Param VARCHAR(50), @Ville_Param VARCHAR(50)',  -- 2. Déclaration des types
    @Nom_Param = @NomRecherche,                    -- 3. Valeur du 1er paramètre
    @Ville_Param = @VilleRecherche;                -- 4. Valeur du 2ème paramètre
```

## Protection contre l'injection SQL : Comment ça marche ?

### Test avec une entrée malveillante

```sql
-- Simulons une attaque
DECLARE @NomMalveillant VARCHAR(50) = ''' OR ''1''=''1';  -- Tentative d'injection

-- Avec EXEC (VULNÉRABLE)
DECLARE @SQL_Vulnerable NVARCHAR(500);
SET @SQL_Vulnerable = 'SELECT * FROM Clients WHERE Nom = ''' + @NomMalveillant + '''';
PRINT 'SQL généré avec EXEC :';
PRINT @SQL_Vulnerable;
-- Résultat : SELECT * FROM Clients WHERE Nom = '' OR '1'='1'
--                                                ↑↑↑↑↑↑↑↑↑↑↑
--                                          INJECTION RÉUSSIE !

EXEC(@SQL_Vulnerable);  -- Retourne TOUS les clients 🚨

-- Avec sp_executesql (SÉCURISÉ)
DECLARE @SQL_Secure NVARCHAR(500);
SET @SQL_Secure = N'SELECT * FROM Clients WHERE Nom = @Nom_Param';

EXEC sp_executesql
    @SQL_Secure,
    N'@Nom_Param VARCHAR(50)',
    @Nom_Param = @NomMalveillant;
-- Cherche littéralement un client avec le nom "' OR '1'='1"
-- Ne trouve rien (ce nom n'existe pas)
-- ✅ INJECTION BLOQUÉE !
```

### Pourquoi c'est sécurisé ?

Quand vous utilisez `sp_executesql` avec des paramètres :

1. **SQL Server compile** la requête en reconnaissant les paramètres comme des **placeholders**
2. **Les valeurs sont liées** aux paramètres au moment de l'exécution
3. **Les valeurs sont traitées comme des données**, jamais comme du code
4. **Impossible d'injecter du code** car SQL Server ne réinterprète jamais les valeurs

```
┌──────────────────────────────────────────────────────────┐
│ AVEC EXEC : Tout est mélangé                             │
│ "SELECT * FROM Users WHERE Name = '" + INPUT + "'"       │
│ ↓                                                        │
│ Code et données sont indissociables                      │
│ SQL Server exécute TOUT comme du code                    │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│ AVEC sp_executesql : Séparation claire                   │
│ Requête: "SELECT * FROM Users WHERE Name = @Name"        │
│ Paramètre: @Name = INPUT                                 │
│ ↓                                                        │
│ SQL Server compile la requête d'abord                    │
│ Puis lie les valeurs aux paramètres                      │
│ Les valeurs ne sont JAMAIS exécutées comme du code       │
└──────────────────────────────────────────────────────────┘
```

## Exemples par type d'opération

### SELECT avec paramètres

#### Exemple 1 : Recherche simple

```sql
CREATE PROCEDURE sp_GetClientByID
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Clients WHERE ClientID = @ID_Param';

    EXEC sp_executesql
        @SQL,
        N'@ID_Param INT',
        @ID_Param = @ClientID;
END;
```

#### Exemple 2 : Recherche avec LIKE

```sql
CREATE PROCEDURE sp_SearchClients
    @SearchTerm VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);
    DECLARE @Pattern VARCHAR(102);

    -- Construire le pattern pour LIKE
    SET @Pattern = '%' + @SearchTerm + '%';

    -- Requête paramétrée
    SET @SQL = N'SELECT * FROM Clients WHERE Nom LIKE @Pattern_Param';

    EXEC sp_executesql
        @SQL,
        N'@Pattern_Param VARCHAR(102)',
        @Pattern_Param = @Pattern;
END;
```

**Note** : Le caractère `%` est ajouté dans le code T-SQL, pas dans la requête dynamique. C'est sécurisé car `%` fait partie de la **valeur du paramètre**, pas de la **structure SQL**.

#### Exemple 3 : Recherche avec plusieurs critères optionnels

```sql
CREATE PROCEDURE sp_SearchClientsAdvanced
    @Nom VARCHAR(50) = NULL,
    @Ville VARCHAR(50) = NULL,
    @AgeMin INT = NULL,
    @AgeMax INT = NULL
AS
BEGIN
    SET NOCOUNT ON;

    -- Construire la requête dynamiquement selon les paramètres fournis
    DECLARE @SQL NVARCHAR(MAX) = N'SELECT * FROM Clients WHERE 1=1';
    DECLARE @ParamsDef NVARCHAR(500) = N'';

    -- Ajouter les conditions selon ce qui est fourni
    IF @Nom IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Nom LIKE @Nom_Param';
        SET @ParamsDef = @ParamsDef + N'@Nom_Param VARCHAR(52),';
    END;

    IF @Ville IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Ville = @Ville_Param';
        SET @ParamsDef = @ParamsDef + N'@Ville_Param VARCHAR(50),';
    END;

    IF @AgeMin IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Age >= @AgeMin_Param';
        SET @ParamsDef = @ParamsDef + N'@AgeMin_Param INT,';
    END;

    IF @AgeMax IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Age <= @AgeMax_Param';
        SET @ParamsDef = @ParamsDef + N'@AgeMax_Param INT,';
    END;

    -- Retirer la dernière virgule
    IF LEN(@ParamsDef) > 0
        SET @ParamsDef = LEFT(@ParamsDef, LEN(@ParamsDef) - 1);

    -- Exécuter avec les paramètres
    EXEC sp_executesql
        @SQL,
        @ParamsDef,
        @Nom_Param = @Nom,
        @Ville_Param = @Ville,
        @AgeMin_Param = @AgeMin,
        @AgeMax_Param = @AgeMax;
END;
GO

-- Utilisation
EXEC sp_SearchClientsAdvanced @Nom = 'Dupont', @Ville = 'Paris';
EXEC sp_SearchClientsAdvanced @AgeMin = 30, @AgeMax = 50;
EXEC sp_SearchClientsAdvanced @Nom = 'Martin';
```

CREATE PROCEDURE sp_UpdateClientEmail

### DELETE avec paramètres

```sql
CREATE PROCEDURE sp_DeleteClient
    @ClientID INT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);

    -- Vérifier d'abord si le client existe
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        RAISERROR('Client non trouvé', 16, 1);
        RETURN;
    END;

    SET @SQL = N'DELETE FROM Clients WHERE ClientID = @ID_Param';

    EXEC sp_executesql
        @SQL,
        N'@ID_Param INT',
        @ID_Param = @ClientID;

    PRINT 'Client supprimé';
END;
```

## Paramètres OUTPUT : Récupérer des valeurs

### Principe

`sp_executesql` permet de récupérer des valeurs depuis le SQL dynamique en utilisant des paramètres `OUTPUT`.

### Syntaxe

```sql
EXEC sp_executesql
    @SQL,
    N'@Param_Out TYPE OUTPUT',  -- Marquer comme OUTPUT dans la déclaration
    @Param_Out = @Variable OUTPUT;  -- Marquer comme OUTPUT dans l'assignation
```

### Exemple 1 : Récupérer un COUNT

```sql
CREATE PROCEDURE sp_CountClientsByCity
    @Ville VARCHAR(50),
    @Count INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);

    SET @SQL = N'SELECT @Count_Out = COUNT(*)
                 FROM Clients
                 WHERE Ville = @Ville_Param';

    EXEC sp_executesql
        @SQL,
        N'@Ville_Param VARCHAR(50), @Count_Out INT OUTPUT',
        @Ville_Param = @Ville,
        @Count_Out = @Count OUTPUT;  -- Récupération de la valeur
END;
GO

-- Utilisation
DECLARE @NombreClients INT;
EXEC sp_CountClientsByCity 'Paris', @NombreClients OUTPUT;
PRINT 'Nombre de clients à Paris : ' + CAST(@NombreClients AS VARCHAR);
```

### Exemple 2 : Récupérer une valeur calculée

```sql
CREATE PROCEDURE sp_GetTotalCommandes
    @ClientID INT,
    @Total DECIMAL(10,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);

    SET @SQL = N'SELECT @Total_Out = ISNULL(SUM(Montant), 0)
                 FROM Commandes
                 WHERE ClientID = @ClientID_Param';

    EXEC sp_executesql
        @SQL,
        N'@ClientID_Param INT, @Total_Out DECIMAL(10,2) OUTPUT',
        @ClientID_Param = @ClientID,
        @Total_Out = @Total OUTPUT;
END;
GO

-- Utilisation
DECLARE @MontantTotal DECIMAL(10,2);
EXEC sp_GetTotalCommandes 5, @MontantTotal OUTPUT;
PRINT 'Total des commandes : ' + CAST(@MontantTotal AS VARCHAR);
```

### Exemple 3 : Récupérer l'ID d'une insertion

```sql
CREATE PROCEDURE sp_InsertClientAndGetID
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100),
    @NewID INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(500);

    SET @SQL = N'INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
                 VALUES (@Nom_P, @Prenom_P, @Email_P, GETDATE());

                 SET @NewID_Out = SCOPE_IDENTITY();';

    EXEC sp_executesql
        @SQL,
        N'@Nom_P VARCHAR(50), @Prenom_P VARCHAR(50), @Email_P VARCHAR(100), @NewID_Out INT OUTPUT',
        @Nom_P = @Nom,
        @Prenom_P = @Prenom,
        @Email_P = @Email,
        @NewID_Out = @NewID OUTPUT;
END;
GO

-- Utilisation
DECLARE @ClientID INT;
EXEC sp_InsertClientAndGetID 'Dupont', 'Jean', 'jean@email.com', @ClientID OUTPUT;
PRINT 'Nouveau client créé avec l''ID : ' + CAST(@ClientID AS VARCHAR);
```

## Cas particulier : Noms d'objets dynamiques

### Le problème

Les paramètres ne peuvent pas être utilisés pour les **noms d'objets** (tables, colonnes, schémas) :

```sql
-- ❌ CECI NE FONCTIONNE PAS
DECLARE @TableName VARCHAR(50) = 'Clients';
EXEC sp_executesql
    N'SELECT * FROM @TableName_Param',
    N'@TableName_Param VARCHAR(50)',
    @TableName_Param = @TableName;
-- ERREUR : Must declare the table variable "@TableName_Param"
```

### Solution : Concaténation sécurisée avec QUOTENAME

Pour les noms d'objets, vous devez les concaténer, mais en utilisant **QUOTENAME** pour la sécurité :

```sql
CREATE PROCEDURE sp_GetTableCount
    @TableName NVARCHAR(128)
AS
BEGIN
    SET NOCOUNT ON;

    -- 1. Valider que la table existe
    IF OBJECT_ID(@TableName, 'U') IS NULL
    BEGIN
        RAISERROR('La table %s n''existe pas', 16, 1, @TableName);
        RETURN;
    END;

    -- 2. Utiliser QUOTENAME pour sécuriser le nom
    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT COUNT(*) AS NombreLignes FROM ' + QUOTENAME(@TableName);

    -- 3. Exécuter
    EXEC sp_executesql @SQL;
END;
GO

-- Utilisation
EXEC sp_GetTableCount 'Clients';
EXEC sp_GetTableCount 'Commandes';
```

### QUOTENAME : Protection des identifiants

`QUOTENAME` ajoute des crochets `[]` autour du nom et échappe les caractères spéciaux :

```sql
SELECT QUOTENAME('Clients');           -- Résultat : [Clients]
SELECT QUOTENAME('Table avec espaces'); -- Résultat : [Table avec espaces]
SELECT QUOTENAME('Table]Malveillante'); -- Résultat : [Table]]Malveillante]
--                                                           ↑↑
--                                               Le ] est échappé en ]]
```

### Exemple : Tri dynamique sécurisé

```sql
CREATE PROCEDURE sp_GetClientsSorted
    @SortColumn VARCHAR(50) = 'Nom',
    @SortOrder VARCHAR(4) = 'ASC'
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation stricte : Liste blanche des colonnes autorisées
    IF @SortColumn NOT IN ('Nom', 'Prenom', 'Ville', 'Email', 'DateInscription')
    BEGIN
        RAISERROR('Colonne de tri invalide: %s', 16, 1, @SortColumn);
        RETURN;
    END;

    -- Validation de l'ordre
    IF @SortOrder NOT IN ('ASC', 'DESC')
        SET @SortOrder = 'ASC';

    -- Construction sécurisée avec QUOTENAME
    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Clients ORDER BY ' +
               QUOTENAME(@SortColumn) + N' ' + @SortOrder;

    -- Exécution
    EXEC sp_executesql @SQL;
END;
GO

-- Utilisation
EXEC sp_GetClientsSorted 'Nom', 'ASC';
EXEC sp_GetClientsSorted 'DateInscription', 'DESC';
```

## Combinaison : Noms dynamiques + Valeurs paramétrées

Souvent, vous avez besoin de combiner les deux approches :

```sql
CREATE PROCEDURE sp_SearchInTable
    @TableName NVARCHAR(128),
    @ColumnName NVARCHAR(128),
    @SearchValue VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation de la table
    IF OBJECT_ID(@TableName, 'U') IS NULL
    BEGIN
        RAISERROR('Table invalide', 16, 1);
        RETURN;
    END;

    -- Validation de la colonne
    IF NOT EXISTS (
        SELECT 1 FROM INFORMATION_SCHEMA.COLUMNS
        WHERE TABLE_NAME = @TableName
        AND COLUMN_NAME = @ColumnName
    )
    BEGIN
        RAISERROR('Colonne invalide', 16, 1);
        RETURN;
    END;

    -- Construction de la requête
    -- Noms d'objets : concaténés avec QUOTENAME
    -- Valeurs : paramétrées
    DECLARE @SQL NVARCHAR(MAX);
    SET @SQL = N'SELECT * FROM ' + QUOTENAME(@TableName) +
               N' WHERE ' + QUOTENAME(@ColumnName) +
               N' LIKE @SearchPattern_Param';

    -- Exécution avec paramètre pour la valeur
    DECLARE @Pattern VARCHAR(102) = '%' + @SearchValue + '%';

    EXEC sp_executesql
        @SQL,
        N'@SearchPattern_Param VARCHAR(102)',
        @SearchPattern_Param = @Pattern;
END;
GO

-- Utilisation
EXEC sp_SearchInTable 'Clients', 'Nom', 'Dupont';
EXEC sp_SearchInTable 'Produits', 'Description', 'ordinateur';
```

## Types de données et paramètres

### Correspondance des types

Les types des paramètres doivent correspondre aux types des colonnes ou des valeurs :

```sql
-- Table Clients
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom VARCHAR(50),
    DateNaissance DATE,
    Salaire DECIMAL(10,2),
    EstActif BIT
);

-- Procédure avec types correspondants
CREATE PROCEDURE sp_InsertClient_Typed
    @Nom VARCHAR(50),          -- Correspond à la colonne
    @DateNaissance DATE,       -- Correspond à la colonne
    @Salaire DECIMAL(10,2),    -- Correspond à la colonne
    @EstActif BIT              -- Correspond à la colonne
AS
BEGIN
    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'INSERT INTO Clients (Nom, DateNaissance, Salaire, EstActif)
                 VALUES (@N, @D, @S, @A)';

    EXEC sp_executesql
        @SQL,
        N'@N VARCHAR(50), @D DATE, @S DECIMAL(10,2), @A BIT',
        @N = @Nom,
        @D = @DateNaissance,
        @S = @Salaire,
        @A = @EstActif;
END;
```

### Attention aux longueurs

```sql
-- ⚠️ ATTENTION à la longueur des types VARCHAR/NVARCHAR
DECLARE @SQL NVARCHAR(500);
SET @SQL = N'SELECT * FROM Clients WHERE Nom = @Nom_Param';

-- ❌ Si vous déclarez VARCHAR(10) mais la colonne est VARCHAR(50),
-- les valeurs seront tronquées
EXEC sp_executesql @SQL, N'@Nom_Param VARCHAR(10)', @Nom_Param = 'UnNomTresLong';

-- ✅ Utilisez la même longueur que la colonne (ou plus grande)
EXEC sp_executesql @SQL, N'@Nom_Param VARCHAR(50)', @Nom_Param = 'UnNomTresLong';
```

### Types NVARCHAR (Unicode)

Pour les données internationales, utilisez NVARCHAR :

```sql
DECLARE @SQL NVARCHAR(500);
SET @SQL = N'SELECT * FROM Clients WHERE Nom = @Nom_Param';

-- Avec NVARCHAR (supporte tous les caractères Unicode)
EXEC sp_executesql
    @SQL,
    N'@Nom_Param NVARCHAR(50)',  -- NVARCHAR
    @Nom_Param = N'François';     -- Le N préserve les accents
```

## Validation des entrées : Couche supplémentaire

La paramétrisation protège contre l'injection SQL, mais vous devriez **aussi valider** les entrées :

### Validation du format

```sql
CREATE PROCEDURE sp_SearchClientSecure
    @Email VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation : Format d'email basique
    IF @Email NOT LIKE '%@%.%'
    BEGIN
        RAISERROR('Format d''email invalide', 16, 1);
        RETURN;
    END;

    -- Validation : Longueur
    IF LEN(@Email) > 100
    BEGIN
        RAISERROR('Email trop long', 16, 1);
        RETURN;
    END;

    -- Si validations OK, exécuter la recherche
    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Clients WHERE Email = @Email_Param';

    EXEC sp_executesql
        @SQL,
        N'@Email_Param VARCHAR(100)',
        @Email_Param = @Email;
END;
```

### Liste blanche (Whitelist)

Pour les valeurs qui doivent appartenir à un ensemble connu :

```sql
CREATE PROCEDURE sp_GetClientsByStatus
    @Status VARCHAR(20)
AS
BEGIN
    SET NOCOUNT ON;

    -- Liste blanche : seules ces valeurs sont autorisées
    IF @Status NOT IN ('Actif', 'Inactif', 'Suspendu', 'Nouveau')
    BEGIN
        RAISERROR('Statut invalide: %s', 16, 1, @Status);
        RETURN;
    END;

    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Clients WHERE Statut = @Status_Param';

    EXEC sp_executesql
        @SQL,
        N'@Status_Param VARCHAR(20)',
        @Status_Param = @Status;
END;
```

### Validation de plage

```sql
CREATE PROCEDURE sp_GetProductsByPriceRange
    @MinPrice DECIMAL(10,2),
    @MaxPrice DECIMAL(10,2)
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation : prix positifs
    IF @MinPrice < 0 OR @MaxPrice < 0
    BEGIN
        RAISERROR('Les prix doivent être positifs', 16, 1);
        RETURN;
    END;

    -- Validation : ordre logique
    IF @MinPrice > @MaxPrice
    BEGIN
        RAISERROR('Prix minimum supérieur au prix maximum', 16, 1);
        RETURN;
    END;

    -- Validation : plage raisonnable
    IF @MaxPrice > 1000000
    BEGIN
        RAISERROR('Prix maximum trop élevé', 16, 1);
        RETURN;
    END;

    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Produits
                 WHERE Prix BETWEEN @Min_Param AND @Max_Param';

    EXEC sp_executesql
        @SQL,
        N'@Min_Param DECIMAL(10,2), @Max_Param DECIMAL(10,2)',
        @Min_Param = @MinPrice,
        @Max_Param = @MaxPrice;
END;
```

## Gestion d'erreurs et débogage

### TRY...CATCH avec SQL dynamique

```sql
CREATE PROCEDURE sp_SafeDynamicQuery
    @TableName NVARCHAR(128),
    @MinValue INT
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        -- Validation
        IF OBJECT_ID(@TableName, 'U') IS NULL
        BEGIN
            RAISERROR('Table inexistante', 16, 1);
            RETURN;
        END;

        -- Construction
        DECLARE @SQL NVARCHAR(500);
        SET @SQL = N'SELECT * FROM ' + QUOTENAME(@TableName) +
                   N' WHERE Valeur >= @Min_Param';

        -- Affichage pour débogage (en développement uniquement)
        PRINT 'SQL à exécuter :';
        PRINT @SQL;
        PRINT 'Paramètre @Min_Param = ' + CAST(@MinValue AS VARCHAR);

        -- Exécution
        EXEC sp_executesql
            @SQL,
            N'@Min_Param INT',
            @Min_Param = @MinValue;

    END TRY
    BEGIN CATCH
        -- En cas d'erreur, afficher les détails
        DECLARE @ErrorMessage NVARCHAR(4000) = ERROR_MESSAGE();
        DECLARE @ErrorSeverity INT = ERROR_SEVERITY();
        DECLARE @ErrorState INT = ERROR_STATE();

        PRINT 'Erreur dans le SQL dynamique :';
        PRINT 'Message : ' + @ErrorMessage;
        PRINT 'SQL : ' + ISNULL(@SQL, 'N/A');

        RAISERROR(@ErrorMessage, @ErrorSeverity, @ErrorState);
    END CATCH;
END;
```

### Exemple de procédure sécurisée complète

```sql
CREATE PROCEDURE sp_SecureSearchExample
    @TableName NVARCHAR(128),
    @SearchColumn NVARCHAR(128),
    @SearchValue VARCHAR(100),
    @MaxRows INT = 100
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        -- ═══════════════════════════════════════
        -- VALIDATION 1 : Table existe
        -- ═══════════════════════════════════════
        IF OBJECT_ID(@TableName, 'U') IS NULL
        BEGIN
            RAISERROR('Table invalide: %s', 16, 1, @TableName);
            RETURN;
        END;

        -- ═══════════════════════════════════════
        -- VALIDATION 2 : Colonne existe
        -- ═══════════════════════════════════════
        IF NOT EXISTS (
            SELECT 1 FROM INFORMATION_SCHEMA.COLUMNS
            WHERE TABLE_NAME = @TableName
            AND COLUMN_NAME = @SearchColumn
        )
        BEGIN
            RAISERROR('Colonne invalide: %s', 16, 1, @SearchColumn);
            RETURN;
        END;

        -- ═══════════════════════════════════════
        -- VALIDATION 3 : Longueur de la recherche
        -- ═══════════════════════════════════════
        IF LEN(@SearchValue) > 100
        BEGIN
            RAISERROR('Valeur de recherche trop longue', 16, 1);
            RETURN;
        END;

        -- ═══════════════════════════════════════
        -- VALIDATION 4 : Nombre maximum de lignes
        -- ═══════════════════════════════════════
        IF @MaxRows < 1 OR @MaxRows > 1000
        BEGIN
            RAISERROR('MaxRows doit être entre 1 et 1000', 16, 1);
            RETURN;
        END;

        -- ═══════════════════════════════════════
        -- CONSTRUCTION SÉCURISÉE
        -- ═══════════════════════════════════════
        DECLARE @SQL NVARCHAR(MAX);
        SET @SQL = N'SELECT TOP (@MaxRows_P) * FROM ' +
                   QUOTENAME(@TableName) +           -- QUOTENAME pour les objets
                   N' WHERE ' + QUOTENAME(@SearchColumn) +
                   N' LIKE @SearchPattern_P';

        DECLARE @Pattern VARCHAR(102) = '%' + @SearchValue + '%';

        -- ═══════════════════════════════════════
        -- EXÉCUTION PARAMÉTRÉE
        -- ═══════════════════════════════════════
        EXEC sp_executesql
            @SQL,
            N'@SearchPattern_P VARCHAR(102), @MaxRows_P INT',  -- Paramètres
            @SearchPattern_P = @Pattern,
            @MaxRows_P = @MaxRows;

    END TRY
    BEGIN CATCH
        -- Gestion d'erreur
        DECLARE @ErrorMsg NVARCHAR(4000) = ERROR_MESSAGE();
        RAISERROR('Erreur dans la recherche: %s', 16, 1, @ErrorMsg);
    END CATCH;
END;
GO

-- Utilisation
EXEC sp_SecureSearchExample 'Clients', 'Nom', 'Dupont', 50;
```

## Résumé

### Points clés à retenir

1. **sp_executesql est LA solution** contre l'injection SQL en SQL dynamique
2. **Paramètres pour les valeurs** : Toujours passer les données en paramètres
3. **QUOTENAME pour les objets** : Protéger les noms de tables/colonnes
4. **Validation en plus** : Ne pas se reposer uniquement sur la paramétrisation
5. **Types cohérents** : Faire correspondre les types des paramètres aux colonnes
6. **OUTPUT pour récupérer** : Utiliser OUTPUT pour obtenir des valeurs de retour

### Règles d'or

- ✅ **Toujours utiliser sp_executesql avec paramètres en production**
- ✅ **Valider TOUTES les entrées utilisateur**
- ✅ **Utiliser QUOTENAME pour les identifiants**
- ✅ **Vérifier l'existence des objets avant utilisation**
- ✅ **Appliquer le principe du moindre privilège**
- ✅ **Tester avec des entrées malveillantes**
- ✅ **Documenter pourquoi le SQL dynamique est nécessaire**
- ✅ **Gérer les erreurs avec TRY...CATCH**

### Template de code sécurisé

```sql
CREATE PROCEDURE sp_Template_Secure
    @UserInput VARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        -- 1. VALIDATION
        IF @UserInput IS NULL OR LEN(@UserInput) = 0
        BEGIN
            RAISERROR('Entrée invalide', 16, 1);
            RETURN;
        END;

        -- 2. CONSTRUCTION AVEC PARAMÈTRES
        DECLARE @SQL NVARCHAR(MAX);
        SET @SQL = N'SELECT * FROM MaTable WHERE MaColonne = @Param';

        -- 3. EXÉCUTION PARAMÉTRÉE
        EXEC sp_executesql
            @SQL,
            N'@Param VARCHAR(100)',
            @Param = @UserInput;

    END TRY
    BEGIN CATCH
        -- 4. GESTION D'ERREUR
        DECLARE @ErrorMsg NVARCHAR(4000) = ERROR_MESSAGE();
        RAISERROR('Erreur: %s', 16, 1, @ErrorMsg);
    END CATCH;
END;
```

## Conclusion

L'utilisation de `sp_executesql` avec des paramètres est **la méthode recommandée** pour exécuter du SQL dynamique de manière sécurisée. Elle offre :

- 🛡️ **Protection contre l'injection SQL** : Séparation claire code/données
- ⚡ **Meilleures performances** : Réutilisation des plans d'exécution
- 📖 **Code plus lisible** : Pas de gestion complexe d'apostrophes
- 🔄 **Récupération de valeurs** : Paramètres OUTPUT

**Principe final** :
> "Si vous construisez du SQL dynamiquement, vous DEVEZ utiliser sp_executesql avec des paramètres. Pas d'exception."

La sécurité de votre base de données et des données de vos utilisateurs en dépend !
