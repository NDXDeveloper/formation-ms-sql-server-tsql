# 8.2.2 Fonctions natives JSON (ISJSON, JSON_VALUE, JSON_QUERY)

## Introduction

Dans la section précédente, nous avons appris à **stocker** du JSON dans SQL Server en utilisant des colonnes NVARCHAR. Maintenant, la question cruciale est : **comment extraire et utiliser les données contenues dans ce JSON ?**

SQL Server fournit plusieurs **fonctions natives** pour travailler avec JSON. Dans cette section, nous allons explorer les trois fonctions les plus importantes :

1. **`ISJSON()`** : Valider si une chaîne est du JSON valide
2. **`JSON_VALUE()`** : Extraire une **valeur scalaire** (texte, nombre, booléen)
3. **`JSON_QUERY()`** : Extraire un **objet ou un tableau** JSON

Ces fonctions vous permettent de transformer des données JSON en colonnes relationnelles utilisables dans vos requêtes SQL.

## Données d'exemple

Pour illustrer ces fonctions, créons une table avec des données JSON :

```sql
-- Créer la table
CREATE TABLE Produits (
    ProduitID INT PRIMARY KEY IDENTITY(1,1),
    Nom NVARCHAR(100),
    DetailsJSON NVARCHAR(MAX)
);

-- Insérer des données d'exemple
INSERT INTO Produits (Nom, DetailsJSON) VALUES
('Ordinateur portable', '{
    "marque": "Dell",
    "modele": "XPS 15",
    "prix": 1299.99,
    "stock": 5,
    "disponible": true,
    "specifications": {
        "processeur": "Intel i7",
        "ram": "16GB",
        "stockage": "512GB SSD"
    },
    "couleurs": ["Argent", "Noir"]
}'),

('Smartphone', '{
    "marque": "Samsung",
    "modele": "Galaxy S23",
    "prix": 899.00,
    "stock": 0,
    "disponible": false,
    "specifications": {
        "processeur": "Snapdragon 8 Gen 2",
        "ram": "8GB",
        "stockage": "256GB"
    },
    "couleurs": ["Noir", "Blanc", "Vert"]
}'),

('Tablette', '{
    "marque": "Apple",
    "modele": "iPad Pro",
    "prix": 1099.00,
    "stock": 12,
    "disponible": true,
    "specifications": {
        "processeur": "M2",
        "ram": "8GB",
        "stockage": "128GB"
    },
    "couleurs": ["Gris sidéral", "Argent"]
}');
```

## La fonction ISJSON()

### Concept

La fonction **`ISJSON()`** vérifie si une chaîne de caractères contient du **JSON valide**.

**Valeur de retour** :
- `1` : Si la chaîne est du JSON valide
- `0` : Si la chaîne n'est PAS du JSON valide
- `NULL` : Si l'entrée est NULL

### Syntaxe

```sql
ISJSON(expression)
```

**Paramètre** :
- `expression` : La chaîne de caractères à valider (généralement NVARCHAR)

### Exemples de base

#### Exemple 1 : JSON valide

```sql
SELECT ISJSON('{"nom": "Dupont", "age": 30}') AS EstJSON;
```

**Résultat** :
```
EstJSON
-------
1
```

✅ Retourne `1` car c'est du JSON valide.

#### Exemple 2 : JSON invalide (clés sans guillemets)

```sql
SELECT ISJSON('{nom: "Dupont", age: 30}') AS EstJSON;
```

**Résultat** :
```
EstJSON
-------
0
```

❌ Retourne `0` car les clés ne sont pas entre guillemets.

#### Exemple 3 : JSON invalide (virgule finale)

```sql
SELECT ISJSON('{"nom": "Dupont", "age": 30,}') AS EstJSON;
```

**Résultat** :
```
EstJSON
-------
0
```

❌ Retourne `0` car il y a une virgule finale non autorisée.

#### Exemple 4 : Texte simple (pas du JSON)

```sql
SELECT ISJSON('Bonjour le monde') AS EstJSON;
```

**Résultat** :
```
EstJSON
-------
0
```

❌ Retourne `0` car c'est du texte simple, pas du JSON.

#### Exemple 5 : Valeur NULL

```sql
SELECT ISJSON(NULL) AS EstJSON;
```

**Résultat** :
```
EstJSON
-------
NULL
```

Retourne `NULL` pour une entrée NULL.

### Utilisation pratique : Validation de données

#### Filtrer les lignes avec JSON valide

```sql
SELECT ProduitID, Nom, DetailsJSON
FROM Produits
WHERE ISJSON(DetailsJSON) = 1;
```

Cette requête retourne uniquement les produits dont le JSON est valide.

#### Identifier les JSON invalides

```sql
SELECT ProduitID, Nom, DetailsJSON
FROM Produits
WHERE ISJSON(DetailsJSON) = 0 OR DetailsJSON IS NULL;
```

Utile pour identifier les données problématiques dans votre base.

#### Contrainte CHECK (rappel)

Comme vu dans la section précédente, utilisez `ISJSON()` dans une contrainte :

```sql
ALTER TABLE Produits
ADD CONSTRAINT CK_DetailsJSON_Valide
CHECK (DetailsJSON IS NULL OR ISJSON(DetailsJSON) = 1);
```

Cette contrainte garantit qu'on ne peut insérer que du JSON valide (ou NULL).

### Cas particuliers

#### Tableaux JSON

```sql
SELECT ISJSON('[1, 2, 3, 4]') AS EstJSON;  -- Retourne 1
SELECT ISJSON('["a", "b", "c"]') AS EstJSON;  -- Retourne 1
```

✅ Les tableaux JSON sont également valides.

#### Valeurs JSON primitives

```sql
SELECT ISJSON('"texte"') AS EstJSON;  -- Retourne 1
SELECT ISJSON('123') AS EstJSON;      -- Retourne 1
SELECT ISJSON('true') AS EstJSON;     -- Retourne 1
SELECT ISJSON('null') AS EstJSON;     -- Retourne 1
```

✅ Les valeurs primitives JSON sont valides (même isolées).

**Important** : Notez que `"texte"` entre guillemets doubles est du JSON valide, mais `'texte'` entre guillemets simples ne l'est pas.

```sql
SELECT ISJSON('"texte"') AS EstJSON;  -- 1 (valide)
SELECT ISJSON('''texte''') AS EstJSON;  -- 0 (invalide, guillemets simples)
```

## La fonction JSON_VALUE()

### Concept

La fonction **`JSON_VALUE()`** extrait une **valeur scalaire** (simple) d'un document JSON.

**Valeur scalaire** = valeur unique de type :
- Texte (chaîne)
- Nombre
- Booléen (`true`/`false`)
- `null`

**Important** : `JSON_VALUE()` ne peut PAS extraire des objets `{}` ou des tableaux `[]`. Pour cela, utilisez `JSON_QUERY()`.

### Syntaxe

```sql
JSON_VALUE(expression_json, chemin_json)
```

**Paramètres** :
1. `expression_json` : La chaîne JSON (colonne NVARCHAR)
2. `chemin_json` : Le chemin vers la valeur à extraire (JSON Path)

**Valeur de retour** :
- Une chaîne de caractères NVARCHAR(4000)
- `NULL` si le chemin n'existe pas ou si la valeur est un objet/tableau

### Chemins JSON (JSON Path)

Les chemins JSON utilisent une notation avec **point** (`.`) et **crochets** (`[]`) :

| Syntaxe | Description | Exemple |
|---------|-------------|---------|
| `$` | Racine du document | `$` |
| `$.propriété` | Accès à une propriété | `$.marque` |
| `$.objet.propriété` | Propriété imbriquée | `$.specifications.ram` |
| `$[index]` | Élément d'un tableau (index commence à 0) | `$[0]` |
| `$.tableau[index]` | Élément dans un tableau nommé | `$.couleurs[0]` |

**Important** : Les chemins JSON sont **sensibles à la casse** !

### Exemples d'extraction de valeurs simples

#### Exemple 1 : Extraire une chaîne de caractères

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Marque
----------|----------------------|--------
1         | Ordinateur portable  | Dell
2         | Smartphone           | Samsung
3         | Tablette             | Apple
```

**Explication** : `$.marque` accède à la propriété `marque` à la racine du JSON.

#### Exemple 2 : Extraire un nombre

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.prix') AS Prix
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Prix
----------|----------------------|---------
1         | Ordinateur portable  | 1299.99
2         | Smartphone           | 899.00
3         | Tablette             | 1099.00
```

**Important** : Le résultat est retourné comme **chaîne de caractères**. Pour l'utiliser comme nombre, convertissez-le :

```sql
SELECT
    ProduitID,
    Nom,
    CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) AS Prix
FROM Produits;
```

#### Exemple 3 : Extraire un booléen

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.disponible') AS Disponible
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Disponible
----------|----------------------|------------
1         | Ordinateur portable  | true
2         | Smartphone           | false
3         | Tablette             | true
```

Pour utiliser comme booléen dans SQL :

```sql
SELECT
    ProduitID,
    Nom,
    CASE
        WHEN JSON_VALUE(DetailsJSON, '$.disponible') = 'true' THEN 'Oui'
        WHEN JSON_VALUE(DetailsJSON, '$.disponible') = 'false' THEN 'Non'
        ELSE 'Inconnu'
    END AS Disponible
FROM Produits;
```

### Extraction de valeurs imbriquées

Pour accéder à des propriétés dans des **objets imbriqués**, utilisez le `.` :

#### Exemple 4 : Propriété imbriquée

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.specifications.processeur') AS Processeur,
    JSON_VALUE(DetailsJSON, '$.specifications.ram') AS RAM,
    JSON_VALUE(DetailsJSON, '$.specifications.stockage') AS Stockage
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Processeur           | RAM   | Stockage
----------|----------------------|----------------------|-------|----------
1         | Ordinateur portable  | Intel i7             | 16GB  | 512GB SSD
2         | Smartphone           | Snapdragon 8 Gen 2   | 8GB   | 256GB
3         | Tablette             | M2                   | 8GB   | 128GB
```

**Explication** : `$.specifications.processeur` navigue dans l'objet `specifications` puis accède à la propriété `processeur`.

### Extraction d'éléments de tableaux

Pour accéder à un élément d'un **tableau**, utilisez `[index]` (l'index commence à 0) :

#### Exemple 5 : Premier élément d'un tableau

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.couleurs[0]') AS PremiereCouleur
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | PremiereCouleur
----------|----------------------|----------------
1         | Ordinateur portable  | Argent
2         | Smartphone           | Noir
3         | Tablette             | Gris sidéral
```

#### Exemple 6 : Deuxième élément d'un tableau

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.couleurs[0]') AS Couleur1,
    JSON_VALUE(DetailsJSON, '$.couleurs[1]') AS Couleur2,
    JSON_VALUE(DetailsJSON, '$.couleurs[2]') AS Couleur3
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Couleur1     | Couleur2 | Couleur3
----------|----------------------|--------------|----------|----------
1         | Ordinateur portable  | Argent       | Noir     | NULL
2         | Smartphone           | Noir         | Blanc    | Vert
3         | Tablette             | Gris sidéral | Argent   | NULL
```

**Note** : Si l'index n'existe pas, `JSON_VALUE()` retourne `NULL`.

### Utilisation dans des clauses WHERE

Vous pouvez utiliser `JSON_VALUE()` dans des conditions :

#### Exemple 7 : Filtrer par marque

```sql
SELECT ProduitID, Nom
FROM Produits
WHERE JSON_VALUE(DetailsJSON, '$.marque') = 'Apple';
```

**Résultat** :
```
ProduitID | Nom
----------|----------
3         | Tablette
```

#### Exemple 8 : Filtrer par disponibilité

```sql
SELECT ProduitID, Nom
FROM Produits
WHERE JSON_VALUE(DetailsJSON, '$.disponible') = 'true';
```

**Résultat** :
```
ProduitID | Nom
----------|----------------------
1         | Ordinateur portable
3         | Tablette
```

#### Exemple 9 : Filtrer par prix (avec conversion)

```sql
SELECT ProduitID, Nom
FROM Produits
WHERE CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) < 1000;
```

**Résultat** :
```
ProduitID | Nom
----------|------------
2         | Smartphone
```

### Utilisation dans ORDER BY

#### Exemple 10 : Trier par prix

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.prix') AS Prix
FROM Produits
ORDER BY CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2));
```

**Résultat** :
```
ProduitID | Nom                  | Prix
----------|----------------------|---------
2         | Smartphone           | 899.00
3         | Tablette             | 1099.00
1         | Ordinateur portable  | 1299.99
```

### Gestion des valeurs NULL

`JSON_VALUE()` retourne `NULL` dans plusieurs cas :

1. Le chemin n'existe pas
2. La valeur JSON est `null`
3. Le chemin pointe vers un objet ou un tableau

#### Exemple 11 : Chemin inexistant

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.garantie') AS Garantie
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Garantie
----------|----------------------|----------
1         | Ordinateur portable  | NULL
2         | Smartphone           | NULL
3         | Tablette             | NULL
```

Aucun produit n'a la propriété `garantie`, donc tous retournent `NULL`.

#### Exemple 12 : Utiliser ISNULL pour valeur par défaut

```sql
SELECT
    ProduitID,
    Nom,
    ISNULL(JSON_VALUE(DetailsJSON, '$.garantie'), 'Non spécifiée') AS Garantie
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Garantie
----------|----------------------|---------------
1         | Ordinateur portable  | Non spécifiée
2         | Smartphone           | Non spécifiée
3         | Tablette             | Non spécifiée
```

## La fonction JSON_QUERY()

### Concept

La fonction **`JSON_QUERY()`** extrait un **objet** (`{}`) ou un **tableau** (`[]`) JSON.

**Différence avec JSON_VALUE()** :
- `JSON_VALUE()` : Valeurs scalaires (texte, nombre, booléen)
- `JSON_QUERY()` : Objets et tableaux

### Syntaxe

```sql
JSON_QUERY(expression_json, chemin_json)
```

**Paramètres** :
- Identiques à `JSON_VALUE()`

**Valeur de retour** :
- Un fragment JSON (objet ou tableau) sous forme de chaîne
- `NULL` si le chemin n'existe pas ou pointe vers une valeur scalaire

### Exemples d'extraction d'objets

#### Exemple 1 : Extraire un objet imbriqué

```sql
SELECT
    ProduitID,
    Nom,
    JSON_QUERY(DetailsJSON, '$.specifications') AS Specifications
FROM Produits
WHERE ProduitID = 1;
```

**Résultat** :
```
ProduitID | Nom                  | Specifications
----------|----------------------|---------------------------------------
1         | Ordinateur portable  | {"processeur":"Intel i7","ram":"16GB","stockage":"512GB SSD"}
```

**Explication** : L'objet `specifications` entier est extrait en tant que JSON.

#### Exemple 2 : Extraire un tableau

```sql
SELECT
    ProduitID,
    Nom,
    JSON_QUERY(DetailsJSON, '$.couleurs') AS Couleurs
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Couleurs
----------|----------------------|---------------------------
1         | Ordinateur portable  | ["Argent","Noir"]
2         | Smartphone           | ["Noir","Blanc","Vert"]
3         | Tablette             | ["Gris sidéral","Argent"]
```

### Cas où JSON_QUERY() retourne NULL

#### Exemple 3 : Tenter d'extraire une valeur scalaire

```sql
SELECT
    ProduitID,
    Nom,
    JSON_QUERY(DetailsJSON, '$.marque') AS Marque  -- ❌ Scalaire
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Marque
----------|----------------------|--------
1         | Ordinateur portable  | NULL
2         | Smartphone           | NULL
3         | Tablette             | NULL
```

❌ `JSON_QUERY()` retourne `NULL` car `marque` est une valeur scalaire (texte), pas un objet ou tableau.

**Solution** : Utilisez `JSON_VALUE()` à la place.

### Mode strict : Gestion d'erreurs explicite

Par défaut, SQL Server utilise le mode **lax** (tolérant) : les erreurs de chemin retournent `NULL`.

Vous pouvez activer le mode **strict** pour générer une erreur si le chemin est invalide :

```sql
SELECT
    JSON_QUERY(DetailsJSON, 'strict $.specifications') AS Specs
FROM Produits;
```

En mode strict, une erreur sera levée si le chemin est invalide.

**Note pour débutants** : Le mode lax (par défaut) est généralement plus pratique.

## JSON_VALUE vs JSON_QUERY : Tableau comparatif

| Aspect | JSON_VALUE() | JSON_QUERY() |
|--------|--------------|--------------|
| **Extrait** | Valeurs scalaires | Objets et tableaux |
| **Types supportés** | Texte, Nombre, Booléen, null | `{}` ou `[]` |
| **Retour** | NVARCHAR(4000) | NVARCHAR(MAX) |
| **Exemple** | `$.nom`, `$.prix` | `$.specifications`, `$.couleurs` |
| **Retourne NULL si** | Chemin inexistant ou pointe vers objet/tableau | Chemin inexistant ou pointe vers scalaire |

### Règle simple

- **Valeur simple** (un texte, un nombre) → `JSON_VALUE()`
- **Structure complexe** (objet avec `{}` ou tableau avec `[]`) → `JSON_QUERY()`

### Exemple combiné

```sql
SELECT
    ProduitID,
    Nom,
    -- Valeurs scalaires avec JSON_VALUE
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    JSON_VALUE(DetailsJSON, '$.prix') AS Prix,
    JSON_VALUE(DetailsJSON, '$.disponible') AS Disponible,

    -- Objets/Tableaux avec JSON_QUERY
    JSON_QUERY(DetailsJSON, '$.specifications') AS Specifications,
    JSON_QUERY(DetailsJSON, '$.couleurs') AS Couleurs
FROM Produits;
```

**Résultat** :
```
ProduitID | Nom                  | Marque  | Prix    | Disponible | Specifications                                               | Couleurs
----------|----------------------|---------|---------|------------|--------------------------------------------------------------|---------------------------
1         | Ordinateur portable  | Dell    | 1299.99 | true       | {"processeur":"Intel i7","ram":"16GB","stockage":"512GB SSD"}| ["Argent","Noir"]
2         | Smartphone           | Samsung | 899.00  | false      | {"processeur":"Snapdragon 8 Gen 2","ram":"8GB",...}          | ["Noir","Blanc","Vert"]
3         | Tablette             | Apple   | 1099.00 | true       | {"processeur":"M2","ram":"8GB","stockage":"128GB"}           | ["Gris sidéral","Argent"]
```

## Cas d'usage pratiques

### Cas 1 : Créer une vue avec colonnes JSON extraites

```sql
CREATE VIEW V_ProduitsDetails AS
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    JSON_VALUE(DetailsJSON, '$.modele') AS Modele,
    CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) AS Prix,
    CAST(JSON_VALUE(DetailsJSON, '$.stock') AS INT) AS Stock,
    CASE
        WHEN JSON_VALUE(DetailsJSON, '$.disponible') = 'true' THEN 'Oui'
        ELSE 'Non'
    END AS Disponible,
    JSON_VALUE(DetailsJSON, '$.specifications.processeur') AS Processeur,
    JSON_VALUE(DetailsJSON, '$.specifications.ram') AS RAM
FROM Produits;

-- Utilisation simple
SELECT * FROM V_ProduitsDetails;
```

Cette vue "aplatit" le JSON en colonnes relationnelles classiques.

### Cas 2 : Rapport avec agrégations

```sql
-- Nombre de produits par marque
SELECT
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    COUNT(*) AS NombreProduits,
    AVG(CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2))) AS PrixMoyen
FROM Produits
GROUP BY JSON_VALUE(DetailsJSON, '$.marque');
```

**Résultat** :
```
Marque  | NombreProduits | PrixMoyen
--------|----------------|----------
Apple   | 1              | 1099.00
Dell    | 1              | 1299.99
Samsung | 1              | 899.00
```

### Cas 3 : Requête complexe avec plusieurs conditions

```sql
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) AS Prix,
    CAST(JSON_VALUE(DetailsJSON, '$.stock') AS INT) AS Stock
FROM Produits
WHERE
    JSON_VALUE(DetailsJSON, '$.disponible') = 'true'
    AND CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) < 1200
    AND CAST(JSON_VALUE(DetailsJSON, '$.stock') AS INT) > 0
ORDER BY CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2));
```

Cette requête trouve tous les produits :
- Disponibles
- Prix < 1200€
- En stock
- Triés par prix croissant

### Cas 4 : Mise à jour basée sur JSON

```sql
-- Réduire le prix des produits en rupture de stock (stock = 0)
UPDATE Produits
SET DetailsJSON = JSON_MODIFY(
    DetailsJSON,
    '$.prix',
    CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) * 0.9
)
WHERE CAST(JSON_VALUE(DetailsJSON, '$.stock') AS INT) = 0;
```

**Note** : `JSON_MODIFY()` sera vu dans une section ultérieure, mais cet exemple montre comment `JSON_VALUE()` s'intègre dans des opérations de mise à jour.

## Performance : Considérations importantes

### Problème de performance

Extraire des valeurs JSON avec `JSON_VALUE()` nécessite de **parser le JSON à chaque requête**, ce qui peut être lent sur de gros volumes.

```sql
-- Cette requête parse le JSON pour CHAQUE ligne à CHAQUE exécution
SELECT
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    COUNT(*)
FROM Produits
GROUP BY JSON_VALUE(DetailsJSON, '$.marque');
```

### Solution 1 : Colonnes calculées persistées

Créez des **colonnes calculées** qui extraient et stockent les valeurs JSON :

```sql
-- Ajouter des colonnes calculées persistées
ALTER TABLE Produits
ADD Marque AS JSON_VALUE(DetailsJSON, '$.marque') PERSISTED;

ALTER TABLE Produits
ADD Prix AS CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) PERSISTED;

-- Créer un index sur la colonne calculée
CREATE INDEX IX_Produits_Marque ON Produits(Marque);
CREATE INDEX IX_Produits_Prix ON Produits(Prix);

-- Maintenant la requête est beaucoup plus rapide
SELECT Marque, COUNT(*)
FROM Produits
GROUP BY Marque;
```

**Avantages** :
- Parsing JSON effectué une seule fois (à l'insertion/mise à jour)
- Requêtes rapides sur les colonnes calculées
- Possibilité d'indexer

**Inconvénients** :
- Espace de stockage supplémentaire
- Mise à jour légèrement plus lente

### Solution 2 : Vue indexée

Pour SQL Server Enterprise Edition, vous pouvez créer une **vue indexée** :

```sql
CREATE VIEW V_ProduitsMaterialize
WITH SCHEMABINDING
AS
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) AS Prix
FROM dbo.Produits;

-- Créer un index sur la vue (la matérialise)
CREATE UNIQUE CLUSTERED INDEX IX_V_ProduitsMaterialize
ON V_ProduitsMaterialize(ProduitID);
```

**Note** : Cette fonctionnalité nécessite SQL Server Enterprise Edition.

### Recommandation

Pour des **lectures fréquentes** de propriétés JSON spécifiques :
1. Créez des colonnes calculées persistées
2. Indexez ces colonnes
3. Utilisez directement ces colonnes dans vos requêtes

Pour des **lectures occasionnelles** :
- Utilisez directement `JSON_VALUE()` / `JSON_QUERY()`

## Gestion des erreurs et valeurs NULL

### NULL vs chaîne vide vs valeur absente

```sql
-- Créons un exemple avec différents cas
INSERT INTO Produits (Nom, DetailsJSON) VALUES
('Test NULL', '{"marque": null, "prix": 100}'),
('Test Absent', '{"prix": 100}'),
('Test Vide', '{"marque": "", "prix": 100}');

SELECT
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,
    LEN(JSON_VALUE(DetailsJSON, '$.marque')) AS Longueur
FROM Produits
WHERE Nom LIKE 'Test%';
```

**Résultat** :
```
Nom          | Marque | Longueur
-------------|--------|----------
Test NULL    | NULL   | NULL
Test Absent  | NULL   | NULL
Test Vide    |        | 0
```

**Observations** :
- Valeur JSON `null` → SQL `NULL`
- Propriété absente → SQL `NULL`
- Chaîne vide `""` → Chaîne vide SQL (longueur 0)

### Distinguer NULL de valeur absente

SQL Server ne fait pas de distinction entre une valeur JSON `null` et une propriété absente - les deux retournent SQL `NULL`.

Pour différencier, vous pouvez utiliser une approche indirecte :

```sql
SELECT
    Nom,
    CASE
        WHEN JSON_QUERY(DetailsJSON, '$') LIKE '%"marque"%'
        THEN 'Propriété existe'
        ELSE 'Propriété absente'
    END AS StatutMarque
FROM Produits
WHERE Nom LIKE 'Test%';
```

## Chemins JSON avancés

### Propriétés avec espaces ou caractères spéciaux

Si une propriété JSON contient des espaces ou caractères spéciaux, utilisez la notation entre crochets :

```json
{
    "nom du produit": "Test",
    "prix-unitaire": 100
}
```

```sql
-- Utiliser des guillemets doubles dans le chemin
SELECT JSON_VALUE(json_col, '$."nom du produit"')
SELECT JSON_VALUE(json_col, '$."prix-unitaire"')
```

### Mode lax vs strict

Par défaut, SQL Server utilise le mode **lax** (tolérant) :

```sql
-- Mode lax (par défaut) - retourne NULL si erreur
SELECT JSON_VALUE(DetailsJSON, '$.propriete.inexistante')  -- Retourne NULL

-- Mode strict - génère une erreur si chemin invalide
SELECT JSON_VALUE(DetailsJSON, 'strict $.propriete.inexistante')  -- ERREUR
```

**Recommandation** : Utilisez le mode lax (par défaut) pour plus de flexibilité.

## Bonnes pratiques

### 1. Conversion de types systématique

Toujours convertir les valeurs extraites vers leur type SQL approprié :

```sql
-- ❌ Mauvais : comparaison de textes
WHERE JSON_VALUE(DetailsJSON, '$.prix') > '1000'

-- ✅ Bon : conversion en type numérique
WHERE CAST(JSON_VALUE(DetailsJSON, '$.prix') AS DECIMAL(10,2)) > 1000
```

### 2. Utiliser ISNULL ou COALESCE pour valeurs par défaut

```sql
SELECT
    ProduitID,
    ISNULL(JSON_VALUE(DetailsJSON, '$.garantie'), '1 an') AS Garantie,
    COALESCE(JSON_VALUE(DetailsJSON, '$.couleur'), 'Standard') AS Couleur
FROM Produits;
```

### 3. Valider le JSON avant extraction

```sql
SELECT
    CASE
        WHEN ISJSON(DetailsJSON) = 1
        THEN JSON_VALUE(DetailsJSON, '$.marque')
        ELSE 'JSON invalide'
    END AS Marque
FROM Produits;
```

### 4. Utiliser des alias courts dans les chemins répétés

```sql
-- ❌ Répétitif
SELECT
    JSON_VALUE(DetailsJSON, '$.specifications.processeur'),
    JSON_VALUE(DetailsJSON, '$.specifications.ram'),
    JSON_VALUE(DetailsJSON, '$.specifications.stockage')
FROM Produits;

-- ✅ Mieux : utiliser CROSS APPLY (vu dans la prochaine section)
-- Ou créer une vue avec colonnes calculées
```

### 5. Documenter les chemins JSON utilisés

```sql
-- Commenter les chemins JSON pour référence future
SELECT
    ProduitID,
    Nom,
    JSON_VALUE(DetailsJSON, '$.marque') AS Marque,           -- Texte : nom de la marque
    JSON_VALUE(DetailsJSON, '$.prix') AS Prix,               -- Décimal : prix en euros
    JSON_VALUE(DetailsJSON, '$.specifications.ram') AS RAM   -- Texte : capacité RAM
FROM Produits;
```

## Résumé des fonctions

### ISJSON()

```sql
ISJSON(expression)
-- Retourne : 1 (valide), 0 (invalide), NULL (entrée NULL)
-- Usage : Validation de JSON
```

### JSON_VALUE()

```sql
JSON_VALUE(json_expression, json_path)
-- Retourne : NVARCHAR(4000) - valeur scalaire
-- Usage : Extraire texte, nombre, booléen, null
-- NULL si : chemin inexistant, valeur est objet/tableau
```

### JSON_QUERY()

```sql
JSON_QUERY(json_expression, json_path)
-- Retourne : NVARCHAR(MAX) - fragment JSON
-- Usage : Extraire objet {} ou tableau []
-- NULL si : chemin inexistant, valeur est scalaire
```

### Tableau récapitulatif

| Fonction | Extrait | Exemple de chemin | Exemple de valeur |
|----------|---------|-------------------|-------------------|
| `ISJSON()` | Validation | N/A | `1` ou `0` |
| `JSON_VALUE()` | Scalaire | `$.nom` | `"Dell"` |
| `JSON_VALUE()` | Scalaire | `$.prix` | `1299.99` |
| `JSON_VALUE()` | Scalaire | `$.actif` | `true` |
| `JSON_VALUE()` | Élément tableau | `$.couleurs[0]` | `"Noir"` |
| `JSON_QUERY()` | Objet | `$.specifications` | `{"ram":"16GB",...}` |
| `JSON_QUERY()` | Tableau | `$.couleurs` | `["Noir","Blanc"]` |

## Exemple complet : Requête d'analyse

Voici un exemple qui combine toutes les fonctions vues :

```sql
SELECT
    -- Colonnes relationnelles
    P.ProduitID,
    P.Nom,

    -- Validation JSON
    CASE
        WHEN ISJSON(P.DetailsJSON) = 1 THEN 'Valide'
        ELSE 'Invalide'
    END AS StatutJSON,

    -- Extraction de valeurs scalaires
    JSON_VALUE(P.DetailsJSON, '$.marque') AS Marque,
    JSON_VALUE(P.DetailsJSON, '$.modele') AS Modele,

    -- Conversion de types
    CAST(JSON_VALUE(P.DetailsJSON, '$.prix') AS DECIMAL(10,2)) AS Prix,
    CAST(JSON_VALUE(P.DetailsJSON, '$.stock') AS INT) AS Stock,

    -- Valeurs booléennes
    CASE
        WHEN JSON_VALUE(P.DetailsJSON, '$.disponible') = 'true' THEN 'Oui'
        WHEN JSON_VALUE(P.DetailsJSON, '$.disponible') = 'false' THEN 'Non'
        ELSE 'Non spécifié'
    END AS Disponible,

    -- Valeurs imbriquées
    JSON_VALUE(P.DetailsJSON, '$.specifications.processeur') AS Processeur,
    JSON_VALUE(P.DetailsJSON, '$.specifications.ram') AS RAM,

    -- Éléments de tableau
    JSON_VALUE(P.DetailsJSON, '$.couleurs[0]') AS PremiereCouleur,

    -- Extraction d'objets/tableaux
    JSON_QUERY(P.DetailsJSON, '$.specifications') AS SpecsJSON,
    JSON_QUERY(P.DetailsJSON, '$.couleurs') AS CouleursJSON

FROM Produits P
WHERE ISJSON(P.DetailsJSON) = 1  -- Seulement les JSON valides
ORDER BY CAST(JSON_VALUE(P.DetailsJSON, '$.prix') AS DECIMAL(10,2)) DESC;
```

## Conclusion

Les trois fonctions `ISJSON()`, `JSON_VALUE()` et `JSON_QUERY()` sont les **fondations du travail avec JSON** dans SQL Server :

- **`ISJSON()`** : Valide le JSON avant de le manipuler
- **`JSON_VALUE()`** : Extrait des valeurs simples pour les utiliser dans des requêtes
- **`JSON_QUERY()`** : Extrait des structures complexes (objets, tableaux)

**Points clés à retenir** :
1. Toujours convertir les valeurs extraites vers leur type SQL approprié
2. `JSON_VALUE()` pour scalaires, `JSON_QUERY()` pour structures
3. Les deux fonctions retournent `NULL` en cas d'erreur (mode lax)
4. Pour de meilleures performances, utilisez des colonnes calculées persistées
