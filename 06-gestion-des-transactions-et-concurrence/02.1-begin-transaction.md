# 6.2.1 BEGIN TRANSACTION

## Introduction

Dans les sections précédentes, nous avons découvert le concept de transaction et les propriétés ACID qui garantissent leur fiabilité. Maintenant, il est temps d'apprendre à **contrôler** les transactions en T-SQL.

La première commande que nous allons découvrir est `BEGIN TRANSACTION`, qui permet de **démarrer explicitement** une transaction. C'est le point de départ de tout contrôle transactionnel en T-SQL.

## Qu'est-ce que BEGIN TRANSACTION ?

`BEGIN TRANSACTION` (ou `BEGIN TRAN` en abrégé) est une commande T-SQL qui marque le **début d'une transaction explicite**. À partir de ce point, toutes les modifications de données qui suivent font partie de la même transaction, jusqu'à ce qu'un `COMMIT` ou un `ROLLBACK` soit exécuté.

### Analogie : Ouvrir un Brouillon

Imaginez que vous écrivez un document important :

```
Sans BEGIN TRANSACTION (sauvegarde automatique) :
Vous tapez → Enregistré ✓
Vous tapez → Enregistré ✓
Vous tapez → Enregistré ✓

Avec BEGIN TRANSACTION (mode brouillon) :
BEGIN TRANSACTION → "Mode Brouillon" activé
Vous tapez → Pas encore enregistré
Vous tapez → Pas encore enregistré
Vous tapez → Pas encore enregistré
COMMIT → Enregistrer tout ✓
OU
ROLLBACK → Tout annuler ✗
```

`BEGIN TRANSACTION` active le "mode brouillon" où vos modifications ne sont pas encore définitives.

## Syntaxe de Base

### Forme Simple

```sql
BEGIN TRANSACTION;
-- ou en abrégé :
BEGIN TRAN;
```

C'est la forme la plus courante et la plus simple. Elle démarre une transaction sans nom.

### Forme avec Nom

```sql
BEGIN TRANSACTION nom_transaction;
-- ou :
BEGIN TRAN nom_transaction;
```

Vous pouvez donner un nom à votre transaction pour la rendre plus facilement identifiable, surtout dans les logs ou lors du débogage.

### Forme Complète (Rarement Utilisée)

```sql
BEGIN TRANSACTION [ nom_transaction ]
    [ WITH MARK [ 'description' ] ];
```

La clause `WITH MARK` est utilisée pour marquer le journal de transactions, ce qui est utile pour la récupération à un point précis. C'est un usage très avancé que nous n'utiliserons pas dans ce cours.

## Pourquoi Utiliser BEGIN TRANSACTION ?

Vous vous demandez peut-être : "Pourquoi dois-je utiliser BEGIN TRANSACTION alors que mes requêtes fonctionnent déjà sans ça ?"

### Transactions Automatiques (Auto-Commit) vs Explicites

En T-SQL, il existe deux façons courantes de gérer les transactions :

#### 1. Mode Auto-Commit (Par Défaut)

Par défaut, chaque instruction SQL individuelle est **automatiquement** une transaction :

```sql
-- Cette instruction est automatiquement une transaction
UPDATE Produits SET Prix = Prix * 1.1 WHERE CategorieID = 5;
-- Si elle réussit → COMMIT automatique
-- Si elle échoue → ROLLBACK automatique
```

Vous n'avez rien à faire, SQL Server gère tout automatiquement. Ce mode par défaut s'appelle l'**auto-commit** ; il ne faut pas le confondre avec le mode *transactions implicites* (`SET IMPLICIT_TRANSACTIONS ON`), détaillé en [6.2.5](/06-gestion-des-transactions-et-concurrence/02.5-transactions-implicites-vs-explicites.md).

#### 2. Transactions Explicites (Avec BEGIN TRANSACTION)

Quand vous utilisez `BEGIN TRANSACTION`, vous regroupez **plusieurs** instructions en une seule transaction :

```sql
BEGIN TRANSACTION;

    -- Ces trois instructions forment UNE SEULE transaction
    UPDATE Produits SET Prix = Prix * 1.1 WHERE CategorieID = 5;
    INSERT INTO HistoriquePrix (ProduitID, NouveauPrix, Date) VALUES (123, 99.99, GETDATE());
    UPDATE Statistiques SET DerniereMiseAJour = GETDATE();

COMMIT TRANSACTION;
-- Les trois réussissent ensemble ou échouent ensemble
```

### Quand Utiliser BEGIN TRANSACTION ?

Utilisez `BEGIN TRANSACTION` lorsque :

✅ **Plusieurs opérations doivent réussir ensemble**
```sql
-- Transfert bancaire : les deux opérations sont liées
BEGIN TRANSACTION;
    UPDATE Comptes SET Solde = Solde - 500 WHERE NumCompte = 'A123';
    UPDATE Comptes SET Solde = Solde + 500 WHERE NumCompte = 'B456';
COMMIT TRANSACTION;
```

✅ **Vous avez besoin de logique conditionnelle**
```sql
-- Vérifier avant de valider
BEGIN TRANSACTION;
    UPDATE Stock SET Quantite = Quantite - 10 WHERE ProduitID = 789;

    IF (SELECT Quantite FROM Stock WHERE ProduitID = 789) < 0
    BEGIN
        ROLLBACK; -- Annuler si stock négatif
        PRINT 'Stock insuffisant';
    END
    ELSE
    BEGIN
        COMMIT; -- Valider si tout va bien
        PRINT 'Stock mis à jour';
    END
```

✅ **Vous devez gérer les erreurs de manière centralisée**
```sql
BEGIN TRANSACTION;
BEGIN TRY
    -- Plusieurs opérations
    INSERT INTO Commandes (...) VALUES (...);
    UPDATE Stock ...;
    INSERT INTO FacturesCommandes (...) VALUES (...);

    COMMIT TRANSACTION;
END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION; -- Annuler tout en cas d'erreur
    PRINT ERROR_MESSAGE();
END CATCH;
```

## Exemples Détaillés

### Exemple 1 : Transaction Simple

Voici la structure de base d'une transaction :

```sql
-- Démarrer la transaction
BEGIN TRANSACTION;

    -- Opération 1
    INSERT INTO Clients (ClientID, Nom, Email)
    VALUES (1001, 'Martin Dupont', 'martin@example.com');

    -- Opération 2
    INSERT INTO Adresses (ClientID, Rue, Ville)
    VALUES (1001, '12 rue des Lilas', 'Paris');

-- Valider la transaction
COMMIT TRANSACTION;

PRINT 'Client et adresse créés avec succès !';
```

**Analyse** :
1. `BEGIN TRANSACTION` démarre la transaction
2. Les deux INSERT sont exécutés
3. `COMMIT` valide définitivement les deux insertions
4. ⚠️ Tel quel (sans `TRY...CATCH` ni `SET XACT_ABORT ON`), si le 2ᵉ INSERT échoue, le 1ᵉʳ n'est **pas** annulé automatiquement : SQL Server n'annule que l'instruction fautive et poursuit. Pour un véritable « tout ou rien », il faut gérer le `ROLLBACK` (voir l'Exemple 3)

### Exemple 2 : Transaction Nommée

Donner un nom à votre transaction peut faciliter le débogage :

```sql
-- Transaction avec un nom explicite
BEGIN TRANSACTION TraitementCommande;

    -- Créer la commande
    INSERT INTO Commandes (ClientID, DateCommande, Total)
    VALUES (123, GETDATE(), 250.00);

    DECLARE @CommandeID INT = SCOPE_IDENTITY();

    -- Ajouter les lignes de commande
    INSERT INTO LignesCommande (CommandeID, ProduitID, Quantite)
    VALUES (@CommandeID, 456, 2);

    -- Mettre à jour le stock
    UPDATE Produits
    SET StockDisponible = StockDisponible - 2
    WHERE ProduitID = 456;

COMMIT TRANSACTION TraitementCommande;

PRINT 'Commande traitée avec succès !';
```

**Avantage** : Si vous consultez les logs SQL Server ou utilisez des outils de monitoring, vous verrez "TraitementCommande" ce qui rend l'identification plus facile.

### Exemple 3 : Transaction avec Gestion d'Erreur Complète

Voici un exemple réaliste avec gestion complète des erreurs :

```sql
BEGIN TRANSACTION;

BEGIN TRY
    -- Opération 1 : Créer une nouvelle catégorie
    INSERT INTO Categories (NomCategorie, Description)
    VALUES ('Électronique', 'Appareils électroniques');

    DECLARE @CategorieID INT = SCOPE_IDENTITY();

    -- Opération 2 : Ajouter des produits dans cette catégorie
    INSERT INTO Produits (Nom, CategorieID, Prix, Stock)
    VALUES
        ('Smartphone XYZ', @CategorieID, 599.99, 50),
        ('Tablette ABC', @CategorieID, 399.99, 30);

    -- Opération 3 : Mettre à jour les statistiques
    UPDATE StatistiquesGlobales
    SET NombreCategories = NombreCategories + 1,
        NombreProduits = NombreProduits + 2;

    -- Si tout s'est bien passé, valider
    COMMIT TRANSACTION;
    PRINT '✓ Transaction validée : catégorie et produits créés.';

END TRY
BEGIN CATCH
    -- En cas d'erreur, annuler tout
    ROLLBACK TRANSACTION;

    -- Afficher les détails de l'erreur
    PRINT '✗ Erreur détectée, transaction annulée.';
    PRINT 'Numéro erreur : ' + CAST(ERROR_NUMBER() AS VARCHAR);
    PRINT 'Message : ' + ERROR_MESSAGE();
    PRINT 'Ligne : ' + CAST(ERROR_LINE() AS VARCHAR);
END CATCH;
```

**Ce qui se passe ici :**
1. On démarre une transaction
2. On essaie d'exécuter trois opérations liées
3. Si tout réussit → COMMIT → Tout est enregistré
4. Si une erreur survient → CATCH → ROLLBACK → Rien n'est enregistré

### Exemple 4 : Transaction avec Logique Conditionnelle

Parfois, vous devez vérifier des conditions avant de valider :

```sql
BEGIN TRANSACTION;

    -- Tenter de réserver un siège
    DECLARE @SiegeID INT = 42;
    DECLARE @Vol VARCHAR(10) = 'AF123';

    -- Marquer le siège comme réservé
    UPDATE Sieges
    SET Statut = 'Réservé', ClientID = 5678
    WHERE SiegeID = @SiegeID
      AND VolID = @Vol
      AND Statut = 'Disponible'; -- Important : seulement si disponible

    -- Vérifier si la mise à jour a fonctionné
    IF @@ROWCOUNT = 0
    BEGIN
        -- Échec : le siège n'était pas disponible
        ROLLBACK TRANSACTION;
        PRINT '✗ Siège non disponible, réservation annulée.';
    END
    ELSE
    BEGIN
        -- Succès : le siège a été réservé
        INSERT INTO Reservations (ClientID, SiegeID, DateReservation)
        VALUES (5678, @SiegeID, GETDATE());

        COMMIT TRANSACTION;
        PRINT '✓ Siège réservé avec succès !';
    END
```

**Point clé** : Nous utilisons `@@ROWCOUNT` pour vérifier si l'UPDATE a affecté une ligne. Si non, c'est que le siège n'était pas disponible.

## BEGIN TRANSACTION et les Variables @@TRANCOUNT

Quand vous utilisez `BEGIN TRANSACTION`, SQL Server maintient un compteur appelé `@@TRANCOUNT` qui indique le **niveau d'imbrication** des transactions.

### Comprendre @@TRANCOUNT

```sql
-- Au début, aucune transaction
SELECT @@TRANCOUNT AS 'Niveau Transaction'; -- Résultat : 0

BEGIN TRANSACTION;
SELECT @@TRANCOUNT AS 'Niveau Transaction'; -- Résultat : 1

    BEGIN TRANSACTION; -- Transaction imbriquée
    SELECT @@TRANCOUNT AS 'Niveau Transaction'; -- Résultat : 2

    COMMIT TRANSACTION; -- Diminue de 1
    SELECT @@TRANCOUNT AS 'Niveau Transaction'; -- Résultat : 1

COMMIT TRANSACTION; -- Diminue de 1
SELECT @@TRANCOUNT AS 'Niveau Transaction'; -- Résultat : 0
```

**Important** :
- Chaque `BEGIN TRANSACTION` incrémente `@@TRANCOUNT` de 1
- Chaque `COMMIT TRANSACTION` décrémente `@@TRANCOUNT` de 1
- Un `ROLLBACK TRANSACTION` ramène `@@TRANCOUNT` à 0 (annule TOUTES les transactions)

### Utiliser @@TRANCOUNT pour Éviter les Erreurs

C'est une bonne pratique de vérifier `@@TRANCOUNT` dans vos procédures stockées :

```sql
CREATE PROCEDURE TraiterCommande
    @ClientID INT,
    @ProduitID INT,
    @Quantite INT
AS
BEGIN
    -- Vérifier si une transaction est déjà en cours
    DECLARE @TransactionDemarree BIT = 0;

    IF @@TRANCOUNT = 0
    BEGIN
        -- Pas de transaction en cours, on en démarre une
        BEGIN TRANSACTION;
        SET @TransactionDemarree = 1;
    END

    BEGIN TRY
        -- Logique métier ici
        INSERT INTO Commandes (ClientID, DateCommande)
        VALUES (@ClientID, GETDATE());

        UPDATE Stock
        SET Quantite = Quantite - @Quantite
        WHERE ProduitID = @ProduitID;

        -- Si c'est nous qui avons démarré la transaction, on la valide
        IF @TransactionDemarree = 1
            COMMIT TRANSACTION;

    END TRY
    BEGIN CATCH
        -- Si c'est nous qui avons démarré la transaction, on l'annule
        IF @TransactionDemarree = 1
            ROLLBACK TRANSACTION;

        -- Propager l'erreur
        THROW;
    END CATCH
END;
```

**Pourquoi cette précaution ?**
Si votre procédure est appelée depuis un contexte qui a déjà une transaction ouverte, vous ne voulez pas en démarrer une nouvelle. Cette technique permet à votre procédure d'être flexible.

## Bonnes Pratiques avec BEGIN TRANSACTION

### ✅ Toujours Terminer une Transaction

**Mauvais exemple** :
```sql
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.1;
-- ⚠️ ERREUR : Transaction jamais terminée !
```

**Bon exemple** :
```sql
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.1;
COMMIT TRANSACTION; -- ✓ Transaction terminée
```

### ✅ Garder les Transactions Courtes

Les transactions **verrouillent** des ressources. Plus une transaction est longue, plus elle bloque les autres utilisateurs.

**Mauvais exemple** :
```sql
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.1;

    -- ⚠️ Opération longue dans la transaction
    WAITFOR DELAY '00:05:00'; -- Attend 5 minutes !

COMMIT TRANSACTION;
-- Pendant 5 minutes, personne ne peut modifier les produits !
```

**Bon exemple** :
```sql
-- Faire les calculs/traitements AVANT la transaction
DECLARE @NouveauxPrix TABLE (ProduitID INT, NouveauPrix DECIMAL(10,2));

INSERT INTO @NouveauxPrix
SELECT ProduitID, Prix * 1.1
FROM Produits;

-- Traitement long ici si nécessaire...

-- Transaction courte pour la mise à jour
BEGIN TRANSACTION;
    UPDATE p
    SET p.Prix = np.NouveauPrix
    FROM Produits p
    INNER JOIN @NouveauxPrix np ON p.ProduitID = np.ProduitID;
COMMIT TRANSACTION;
```

### ✅ Utiliser TRY...CATCH avec les Transactions

**Toujours** combiner BEGIN TRANSACTION avec TRY...CATCH :

```sql
BEGIN TRANSACTION;
BEGIN TRY
    -- Vos opérations ici

    COMMIT TRANSACTION;
END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION;
    -- Gérer l'erreur
END CATCH;
```

### ✅ Éviter les Interactions Utilisateur dans les Transactions

**Mauvais exemple** :
```sql
BEGIN TRANSACTION;
    UPDATE Stock SET Quantite = Quantite - 10;

    -- ⚠️ Attente d'une action utilisateur
    PRINT 'Appuyez sur Enter pour continuer...';
    -- L'utilisateur peut prendre des heures à répondre !

COMMIT TRANSACTION;
```

**Bon exemple** :
```sql
-- Obtenir la confirmation AVANT la transaction
PRINT 'Confirmer l''opération ? (O/N)';
-- Après confirmation :

BEGIN TRANSACTION;
    UPDATE Stock SET Quantite = Quantite - 10;
COMMIT TRANSACTION;
```

### ✅ Documenter vos Transactions

Ajoutez des commentaires pour expliquer pourquoi vous utilisez une transaction :

```sql
-- Transaction nécessaire car :
-- 1. La commande et les lignes doivent être créées ensemble
-- 2. Le stock doit être mis à jour de façon cohérente
-- 3. En cas d'erreur, rien ne doit être enregistré
BEGIN TRANSACTION;
    -- Code ici...
COMMIT TRANSACTION;
```

## Erreurs Courantes à Éviter

### ❌ Erreur 1 : Oublier COMMIT ou ROLLBACK

```sql
BEGIN TRANSACTION;
    UPDATE Comptes SET Solde = Solde - 100;
-- Transaction jamais terminée = verrous jamais libérés !
```

**Conséquence** : La transaction reste ouverte indéfiniment, bloquant les autres utilisateurs.

### ❌ Erreur 2 : BEGIN TRANSACTION en Double sans Gestion

```sql
BEGIN TRANSACTION;
    BEGIN TRANSACTION; -- ⚠️ Transaction imbriquée
        UPDATE Table1 ...;
    COMMIT; -- Décrémente seulement
    -- On est toujours dans la première transaction !
COMMIT; -- C'est seulement maintenant que tout est validé
```

**Conseil** : Évitez les transactions imbriquées sauf si vous savez exactement ce que vous faites.

### ❌ Erreur 3 : Ignorer les Erreurs

```sql
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.1;
    -- Si cette ligne échoue, on continue quand même
    INSERT INTO HistoriquePrix (ProduitID, Prix) VALUES (999, 'texte'); -- ERREUR
    -- Et on valide, y compris l'erreur !
COMMIT TRANSACTION;
```

**Solution** : Toujours utiliser TRY...CATCH.

### ❌ Erreur 4 : Transactions Trop Longues

```sql
BEGIN TRANSACTION;
    -- Mise à jour de 10 millions de lignes
    UPDATE GrosseTable SET Colonne = Valeur; -- Peut prendre des heures !
COMMIT TRANSACTION;
```

**Solution** : Diviser en plusieurs petites transactions si possible, ou utiliser des techniques de traitement par lots.

## Points Clés à Retenir

### ✓ BEGIN TRANSACTION démarre une transaction explicite

C'est le point de départ pour regrouper plusieurs opérations en une seule unité.

### ✓ Toujours terminer avec COMMIT ou ROLLBACK

Une transaction non terminée bloque les ressources et cause des problèmes de performance.

### ✓ Utilisez BEGIN TRANSACTION pour regrouper des opérations liées

Quand plusieurs opérations doivent réussir ou échouer ensemble.

### ✓ Combinez avec TRY...CATCH pour gérer les erreurs

C'est une bonne pratique essentielle pour un code robuste.

### ✓ Gardez les transactions courtes

Plus une transaction est courte, moins elle bloque les autres utilisateurs.

### ✓ Surveillez @@TRANCOUNT dans les procédures stockées

Cela permet d'éviter les transactions imbriquées non intentionnelles.

### ✓ Nommez vos transactions pour faciliter le débogage

`BEGIN TRANSACTION MonNom` est plus clair dans les logs.

## Conclusion

`BEGIN TRANSACTION` est la première étape pour prendre le contrôle de vos transactions en T-SQL. C'est une commande simple mais puissante qui vous permet de regrouper plusieurs opérations et de garantir leur cohérence.

**Souvenez-vous de la règle d'or** : Toute transaction commencée avec `BEGIN TRANSACTION` doit **toujours** se terminer par un `COMMIT` ou un `ROLLBACK`.

Dans les sections suivantes, nous approfondirons les commandes `COMMIT` et `ROLLBACK`, ainsi que les points de sauvegarde avec `SAVE TRANSACTION`.
