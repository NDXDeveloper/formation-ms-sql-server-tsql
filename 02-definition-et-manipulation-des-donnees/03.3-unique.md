# 2.3.3 UNIQUE (Contrainte d'unicité)

## Introduction

Imaginez une école où chaque élève doit avoir une **adresse email unique** pour accéder à sa plateforme d'apprentissage. Deux élèves ne peuvent pas partager la même adresse email, même s'ils peuvent avoir le même nom ou prénom. Comment garantir cela dans votre base de données ?

C'est exactement le rôle de la contrainte **UNIQUE** : elle garantit qu'**aucune valeur en double** n'existe dans une colonne (ou un ensemble de colonnes), à l'exception des valeurs NULL.

## Qu'est-ce qu'une Contrainte UNIQUE ?

### Définition Simple

Une contrainte UNIQUE empêche l'insertion de **valeurs dupliquées** dans une colonne. Chaque valeur doit être unique dans toute la table.

**Analogie :**
- Dans une table `Employes`, chaque employé a un **email unique**
- Dans une table `Produits`, chaque produit a un **code-barres unique**
- Dans une table `Utilisateurs`, chaque utilisateur a un **nom d'utilisateur unique**

### Exemple Visuel

```sql
CREATE TABLE Utilisateurs
(
    IdUtilisateur INT PRIMARY KEY,
    NomUtilisateur VARCHAR(50) UNIQUE,
    Email VARCHAR(100) UNIQUE,
    MotDePasse VARCHAR(255)
);
```

**Données valides :**

| IdUtilisateur | NomUtilisateur | Email | MotDePasse |
|---------------|----------------|-------|------------|
| 1 | alice123 | alice@email.com | ••••• |
| 2 | bob456 | bob@email.com | ••••• |
| 3 | charlie789 | charlie@email.com | ••••• |

**Tentatives invalides :**

```sql
-- ❌ ERREUR : alice123 existe déjà
INSERT INTO Utilisateurs (IdUtilisateur, NomUtilisateur, Email, MotDePasse)
VALUES (4, 'alice123', 'alice2@email.com', 'password');

-- ❌ ERREUR : alice@email.com existe déjà
INSERT INTO Utilisateurs (IdUtilisateur, NomUtilisateur, Email, MotDePasse)
VALUES (4, 'alice_new', 'alice@email.com', 'password');

-- ✅ OK : Toutes les valeurs sont uniques
INSERT INTO Utilisateurs (IdUtilisateur, NomUtilisateur, Email, MotDePasse)
VALUES (4, 'david999', 'david@email.com', 'password');
```

## UNIQUE vs PRIMARY KEY : Quelle est la Différence ?

Beaucoup de débutants confondent UNIQUE et PRIMARY KEY. Voici les différences :

| Caractéristique | PRIMARY KEY | UNIQUE |
|-----------------|-------------|--------|
| **Nombre par table** | Une seule | Plusieurs possibles |
| **Valeurs NULL** | ❌ Interdit | ✅ Autorisé (une fois*) |
| **Usage principal** | Identifiant de la ligne | Garantir l'unicité d'autres colonnes |
| **Index** | Crée automatiquement un index clustered | Crée automatiquement un index non-clustered |
| **Rôle** | Identification unique de l'enregistrement | Contrainte métier d'unicité |

\* Par défaut, une contrainte UNIQUE autorise une valeur NULL, mais une seule.

### Exemple Comparatif

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,           -- Identifiant unique (PK)
    Email VARCHAR(100) UNIQUE,           -- Email unique (UNIQUE)
    NumeroSecuriteSociale CHAR(15) UNIQUE, -- Numéro unique (UNIQUE)
    Nom VARCHAR(100),
    Prenom VARCHAR(50)
);
```

**Explication :**
- `IdEmploye` : clé primaire, identifie chaque employé
- `Email` : doit être unique, mais ce n'est pas la clé primaire
- `NumeroSecuriteSociale` : doit aussi être unique
- On peut avoir **plusieurs** contraintes UNIQUE mais **une seule** PRIMARY KEY

**Données exemple :**

| IdEmploye | Email | NumeroSecuriteSociale | Nom | Prenom |
|-----------|-------|----------------------|-----|--------|
| 1 | alice@entreprise.com | 123-45-6789 | Dupont | Alice |
| 2 | bob@entreprise.com | 987-65-4321 | Martin | Bob |

```sql
-- ❌ ERREUR : Email en double
INSERT INTO Employes VALUES (3, 'alice@entreprise.com', '111-22-3333', 'Bernard', 'Charlie');

-- ❌ ERREUR : NumeroSecuriteSociale en double
INSERT INTO Employes VALUES (3, 'charlie@entreprise.com', '123-45-6789', 'Bernard', 'Charlie');

-- ✅ OK : Tout est unique
INSERT INTO Employes VALUES (3, 'charlie@entreprise.com', '111-22-3333', 'Bernard', 'Charlie');
```

## Comment Créer une Contrainte UNIQUE ?

Il existe plusieurs méthodes pour définir une contrainte UNIQUE.

### Méthode 1 : Lors de la Création de la Table (Inline)

La méthode la plus simple :

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    CodeProduit VARCHAR(20) UNIQUE,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2)
);
```

### Méthode 2 : Avec Contrainte Nommée (Recommandé)

Il est préférable de **nommer** vos contraintes pour faciliter la gestion :

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    CodeProduit VARCHAR(20),
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    CONSTRAINT UQ_Produits_CodeProduit UNIQUE (CodeProduit)
);
```

**Convention de nommage :** `UQ_NomTable_NomColonne` ou `UK_NomTable_NomColonne`

### Méthode 3 : Après la Création de la Table

Vous pouvez ajouter une contrainte UNIQUE à une table existante :

```sql
-- D'abord créer la table
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    CodeProduit VARCHAR(20),
    Nom VARCHAR(150),
    Prix DECIMAL(10,2)
);

-- Ensuite ajouter la contrainte UNIQUE
ALTER TABLE Produits
ADD CONSTRAINT UQ_Produits_CodeProduit UNIQUE (CodeProduit);
```

**Important :** La colonne ne doit pas déjà contenir de doublons avant d'ajouter la contrainte.

### Méthode 4 : Plusieurs Contraintes UNIQUE

Une table peut avoir plusieurs contraintes UNIQUE :

```sql
CREATE TABLE Utilisateurs
(
    IdUtilisateur INT PRIMARY KEY,
    NomUtilisateur VARCHAR(50),
    Email VARCHAR(100),
    NumeroTelephone VARCHAR(20),
    CONSTRAINT UQ_Utilisateurs_NomUtilisateur UNIQUE (NomUtilisateur),
    CONSTRAINT UQ_Utilisateurs_Email UNIQUE (Email),
    CONSTRAINT UQ_Utilisateurs_Telephone UNIQUE (NumeroTelephone)
);
```

## Contrainte UNIQUE sur Plusieurs Colonnes (Composite)

Parfois, l'unicité doit être garantie sur une **combinaison de colonnes** plutôt qu'une seule colonne.

### Syntaxe

```sql
CREATE TABLE Inscriptions
(
    IdInscription INT PRIMARY KEY,
    IdEtudiant INT,
    IdCours INT,
    Semestre VARCHAR(20),
    CONSTRAINT UQ_Inscriptions_Etudiant_Cours_Semestre
        UNIQUE (IdEtudiant, IdCours, Semestre)
);
```

### Exemple Expliqué

Cette contrainte signifie : **Un étudiant ne peut s'inscrire qu'une seule fois à un cours donné pour un semestre donné.**

**Données valides :**

| IdInscription | IdEtudiant | IdCours | Semestre |
|---------------|------------|---------|----------|
| 1 | 100 | 201 | Automne 2025 |
| 2 | 100 | 202 | Automne 2025 | ✅ OK : cours différent |
| 3 | 100 | 201 | Printemps 2026 | ✅ OK : semestre différent |
| 4 | 101 | 201 | Automne 2025 | ✅ OK : étudiant différent |

**Tentative invalide :**

| IdInscription | IdEtudiant | IdCours | Semestre |
|---------------|------------|---------|----------|
| 5 | 100 | 201 | Automne 2025 | ❌ ERREUR : combinaison déjà existante |

```sql
-- ❌ ERREUR : L'étudiant 100 est déjà inscrit au cours 201 pour Automne 2025
INSERT INTO Inscriptions (IdInscription, IdEtudiant, IdCours, Semestre)
VALUES (5, 100, 201, 'Automne 2025');
```

### Autre Exemple : Horaires de Travail

```sql
CREATE TABLE Horaires
(
    IdHoraire INT PRIMARY KEY,
    IdEmploye INT,
    Jour DATE,
    HeureDebut TIME,
    CONSTRAINT UQ_Horaires_Employe_Jour
        UNIQUE (IdEmploye, Jour)
);
```

**Règle :** Un employé ne peut avoir qu'**un seul** horaire par jour.

**Données valides :**

| IdHoraire | IdEmploye | Jour | HeureDebut |
|-----------|-----------|------|------------|
| 1 | 10 | 2025-01-15 | 09:00 |
| 2 | 10 | 2025-01-16 | 09:00 | ✅ OK : jour différent |
| 3 | 11 | 2025-01-15 | 10:00 | ✅ OK : employé différent |

**Tentative invalide :**

```sql
-- ❌ ERREUR : L'employé 10 a déjà un horaire pour le 2025-01-15
INSERT INTO Horaires (IdHoraire, IdEmploye, Jour, HeureDebut)
VALUES (4, 10, '2025-01-15', '14:00');
```

## UNIQUE et les Valeurs NULL

C'est un point important et parfois source de confusion : **une contrainte UNIQUE autorise les valeurs NULL**, et généralement **une seule** valeur NULL.

### Comportement par Défaut

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Email VARCHAR(100) UNIQUE,
    NumeroTelephone VARCHAR(20) UNIQUE
);

-- ✅ OK : Premier NULL
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (1, 'alice@email.com', NULL);

-- ✅ OK selon le comportement SQL Server : Second NULL autorisé pour UNIQUE
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (2, 'bob@email.com', NULL);

-- ❌ ERREUR : Email en double
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (3, 'alice@email.com', '555-1234');
```

**Note SQL Server :** Par défaut, SQL Server autorise **plusieurs** valeurs NULL dans une colonne UNIQUE (comportement différent de certains autres SGBD).

### Si Vous Voulez Interdire NULL

Combinez UNIQUE avec NOT NULL :

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Email VARCHAR(100) UNIQUE NOT NULL,  -- Email obligatoire ET unique
    NumeroTelephone VARCHAR(20) UNIQUE   -- Téléphone optionnel mais unique si fourni
);

-- ✅ OK
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (1, 'alice@email.com', '555-1234');

-- ❌ ERREUR : Email ne peut pas être NULL
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (2, NULL, '555-5678');

-- ✅ OK : Téléphone peut être NULL
INSERT INTO Employes (IdEmploye, Email, NumeroTelephone)
VALUES (2, 'bob@email.com', NULL);
```

### Index Filtré pour Unicité avec NULL Limité

Si vous voulez autoriser NULL mais un seul, utilisez un **index unique filtré** :

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Email VARCHAR(100),
    NumeroTelephone VARCHAR(20)
);

-- Index unique qui ignore les NULL
CREATE UNIQUE INDEX UQ_Employes_Telephone
ON Employes(NumeroTelephone)
WHERE NumeroTelephone IS NOT NULL;
```

Avec cet index, plusieurs employés peuvent avoir `NULL` comme téléphone, mais deux employés ne peuvent pas avoir le **même** numéro non-NULL.


## Supprimer une Contrainte UNIQUE

Pour supprimer une contrainte UNIQUE :

```sql
-- Méthode 1 : Si vous connaissez le nom de la contrainte
ALTER TABLE Produits
DROP CONSTRAINT UQ_Produits_CodeProduit;

-- Méthode 2 : Trouver le nom des contraintes UNIQUE
SELECT
    tc.CONSTRAINT_NAME,
    tc.TABLE_NAME,
    cu.COLUMN_NAME
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS tc
INNER JOIN INFORMATION_SCHEMA.CONSTRAINT_COLUMN_USAGE cu
    ON tc.CONSTRAINT_NAME = cu.CONSTRAINT_NAME
WHERE tc.CONSTRAINT_TYPE = 'UNIQUE'
    AND tc.TABLE_NAME = 'Produits';

-- Puis supprimer avec le nom trouvé
ALTER TABLE Produits
DROP CONSTRAINT [nom_trouvé];
```

## Modifier une Colonne pour Ajouter UNIQUE

```sql
-- Table existante sans contrainte
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Email VARCHAR(100),
    Nom VARCHAR(100)
);

-- Vérifier qu'il n'y a pas de doublons
SELECT Email, COUNT(*) AS NombreOccurrences
FROM Employes
GROUP BY Email
HAVING COUNT(*) > 1;

-- Si pas de doublons, ajouter la contrainte
ALTER TABLE Employes
ADD CONSTRAINT UQ_Employes_Email UNIQUE (Email);
```

## Erreurs Courantes et Solutions

### Erreur 1 : Tentative d'Insertion de Doublon

```sql
INSERT INTO Utilisateurs (IdUtilisateur, Email)
VALUES (1, 'alice@email.com');

-- ❌ ERREUR
INSERT INTO Utilisateurs (IdUtilisateur, Email)
VALUES (2, 'alice@email.com');
-- Erreur : Violation of UNIQUE KEY constraint
```

**Solution :** Vérifiez d'abord si la valeur existe :

```sql
-- Vérifier avant insertion
IF NOT EXISTS (SELECT 1 FROM Utilisateurs WHERE Email = 'alice@email.com')
BEGIN
    INSERT INTO Utilisateurs (IdUtilisateur, Email)
    VALUES (2, 'alice@email.com');
END
ELSE
BEGIN
    PRINT 'Cet email existe déjà';
END
```

### Erreur 2 : Doublons Existants lors de l'Ajout de la Contrainte

```sql
-- Table avec doublons
CREATE TABLE Test (Id INT, Email VARCHAR(100));
INSERT INTO Test VALUES (1, 'test@email.com'), (2, 'test@email.com');

-- ❌ ERREUR : Impossible d'ajouter UNIQUE
ALTER TABLE Test
ADD CONSTRAINT UQ_Test_Email UNIQUE (Email);
-- Erreur : Cannot create constraint... duplicate key
```

**Solution :** Nettoyer les doublons d'abord :

```sql
-- Identifier les doublons
SELECT Email, COUNT(*) AS Compte
FROM Test
GROUP BY Email
HAVING COUNT(*) > 1;

-- Supprimer les doublons (garder seulement le premier)
WITH CTE AS (
    SELECT Id, Email,
           ROW_NUMBER() OVER (PARTITION BY Email ORDER BY Id) AS rn
    FROM Test
)
DELETE FROM CTE WHERE rn > 1;

-- Maintenant ajouter la contrainte
ALTER TABLE Test
ADD CONSTRAINT UQ_Test_Email UNIQUE (Email);
```

### Erreur 3 : Mise à Jour Créant un Doublon

```sql
-- Données existantes
-- Id=1, Email='alice@email.com'
-- Id=2, Email='bob@email.com'

-- ❌ ERREUR : Tentative de mettre l'email de Bob à celui d'Alice
UPDATE Utilisateurs
SET Email = 'alice@email.com'
WHERE Id = 2;
-- Erreur : Violation of UNIQUE KEY constraint
```

**Solution :** Vérifiez avant la mise à jour :

```sql
DECLARE @NouvelEmail VARCHAR(100) = 'alice@email.com';
DECLARE @IdUtilisateur INT = 2;

IF NOT EXISTS (
    SELECT 1 FROM Utilisateurs
    WHERE Email = @NouvelEmail AND Id != @IdUtilisateur
)
BEGIN
    UPDATE Utilisateurs
    SET Email = @NouvelEmail
    WHERE Id = @IdUtilisateur;
END
ELSE
BEGIN
    PRINT 'Cet email est déjà utilisé par un autre utilisateur';
END
```

## Vérifier les Contraintes UNIQUE

### Lister toutes les contraintes UNIQUE d'une table

```sql
SELECT
    tc.CONSTRAINT_NAME AS NomContrainte,
    tc.TABLE_NAME AS NomTable,
    cu.COLUMN_NAME AS NomColonne
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS tc
INNER JOIN INFORMATION_SCHEMA.CONSTRAINT_COLUMN_USAGE cu
    ON tc.CONSTRAINT_NAME = cu.CONSTRAINT_NAME
WHERE tc.CONSTRAINT_TYPE = 'UNIQUE'
    AND tc.TABLE_NAME = 'Utilisateurs'
ORDER BY tc.CONSTRAINT_NAME;
```

### Vérifier si une valeur existe déjà

```sql
-- Avant une insertion, vérifier l'existence
DECLARE @Email VARCHAR(100) = 'test@email.com';

IF EXISTS (SELECT 1 FROM Utilisateurs WHERE Email = @Email)
    PRINT 'Cet email existe déjà';
ELSE
    PRINT 'Cet email est disponible';
```

## Bonnes Pratiques

### 1. Toujours Nommer Vos Contraintes

```sql
-- ✅ BON : Contrainte nommée
CONSTRAINT UQ_Produits_CodeProduit UNIQUE (CodeProduit)

-- ❌ À éviter : Contrainte anonyme
CodeProduit VARCHAR(20) UNIQUE
```

**Avantage :** Facilite la maintenance et la suppression.

### 2. Convention de Nommage Cohérente

Choisissez un format et respectez-le :
- `UQ_NomTable_NomColonne`
- `UK_NomTable_NomColonne` (UK = Unique Key)
- `UNQ_NomTable_NomColonne`

**Exemples :**
- `UQ_Clients_Email`
- `UQ_Produits_CodeBarre`
- `UQ_Inscriptions_Etudiant_Cours`

### 3. Combiner avec NOT NULL si Nécessaire

```sql
-- Si la valeur est obligatoire ET doit être unique
Email VARCHAR(150) UNIQUE NOT NULL

-- Si la valeur est optionnelle mais unique si fournie
NumeroTelephone VARCHAR(20) UNIQUE  -- NULL autorisé
```

### 4. Documenter les Contraintes Composites

```sql
-- Contrainte métier : Un étudiant ne peut s'inscrire qu'une fois
-- à un cours pour un semestre donné
CONSTRAINT UQ_Inscriptions_Etudiant_Cours_Semestre
    UNIQUE (IdEtudiant, IdCours, Semestre)
```

### 5. Vérifier les Doublons Avant d'Ajouter la Contrainte

```sql
-- 1. Identifier les doublons potentiels
SELECT Email, COUNT(*) AS Compte
FROM Clients
GROUP BY Email
HAVING COUNT(*) > 1;

-- 2. Nettoyer si nécessaire
-- 3. Ajouter la contrainte
ALTER TABLE Clients
ADD CONSTRAINT UQ_Clients_Email UNIQUE (Email);
```

### 6. Utiliser UNIQUE pour les Colonnes Métier Importantes

**Candidats typiques pour UNIQUE :**
- Adresses email
- Noms d'utilisateur
- Codes produits
- Numéros de série
- Codes-barres
- Numéros de téléphone
- Numéros de sécurité sociale
- Numéros de commande/facture

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Email VARCHAR(150) UNIQUE NOT NULL,
    NumeroClient VARCHAR(20) UNIQUE NOT NULL,  -- Code client unique
    NumeroTelephone VARCHAR(20) UNIQUE,        -- Optionnel mais unique
    Nom VARCHAR(100) NOT NULL,
    Prenom VARCHAR(50) NOT NULL
);
```

### 7. Index Créés Automatiquement

Sachez que SQL Server crée **automatiquement un index non-clustered** pour chaque contrainte UNIQUE :

```sql
-- Cette contrainte UNIQUE crée automatiquement un index
ALTER TABLE Produits
ADD CONSTRAINT UQ_Produits_CodeBarre UNIQUE (CodeBarre);

-- Vous pouvez voir les index créés
SELECT
    i.name AS NomIndex,
    i.type_desc AS TypeIndex,
    c.name AS NomColonne
FROM sys.indexes i
INNER JOIN sys.index_columns ic ON i.object_id = ic.object_id AND i.index_id = ic.index_id
INNER JOIN sys.columns c ON ic.object_id = c.object_id AND ic.column_id = c.column_id
WHERE i.object_id = OBJECT_ID('Produits')
    AND i.is_unique_constraint = 1;
```

**Avantage :** Les recherches sur ces colonnes sont automatiquement optimisées.

## Comparaison Visuelle : PRIMARY KEY vs UNIQUE

```sql
CREATE TABLE Exemple
(
    -- PRIMARY KEY : Une seule, NOT NULL obligatoire, identifiant principal
    IdExemple INT PRIMARY KEY,

    -- UNIQUE : Plusieurs possibles, NULL autorisé, contraintes métier
    Email VARCHAR(100) UNIQUE NOT NULL,
    NumeroTelephone VARCHAR(20) UNIQUE,  -- NULL autorisé
    CodeClient VARCHAR(20) UNIQUE NOT NULL,

    -- Colonnes normales : pas de contrainte d'unicité
    Nom VARCHAR(100),
    Prenom VARCHAR(50)
);
```

**Résumé visuel :**

| Colonne | PRIMARY KEY | UNIQUE | NOT NULL | NULL autorisé | Rôle |
|---------|-------------|--------|----------|---------------|------|
| IdExemple | ✅ | | ✅ | ❌ | Identifiant |
| Email | | ✅ | ✅ | ❌ | Email unique obligatoire |
| NumeroTelephone | | ✅ | | ✅ | Téléphone unique optionnel |
| CodeClient | | ✅ | ✅ | ❌ | Code unique obligatoire |
| Nom | | | | ✅ | Aucune contrainte |
| Prenom | | | | ✅ | Aucune contrainte |

## Résumé

| Aspect | Description |
|--------|-------------|
| **Définition** | Garantit qu'aucune valeur en double n'existe dans une colonne |
| **Nombre par table** | Plusieurs contraintes UNIQUE possibles |
| **NULL** | Autorisé par défaut (SQL Server autorise plusieurs NULL) |
| **Syntaxe simple** | `Email VARCHAR(100) UNIQUE` |
| **Syntaxe nommée** | `CONSTRAINT UQ_Table_Colonne UNIQUE (Colonne)` |
| **Composite** | `UNIQUE (Colonne1, Colonne2)` pour combinaison unique |
| **vs PRIMARY KEY** | PK = identifiant, UNIQUE = contrainte métier |
| **Index** | Crée automatiquement un index non-clustered |
| **Cas d'usage** | Emails, codes produits, noms d'utilisateur, etc. |

## Points Clés à Retenir

1. ✅ UNIQUE garantit qu'**aucune valeur en double** n'existe (sauf NULL)
2. ✅ Une table peut avoir **plusieurs** contraintes UNIQUE
3. ✅ Différent de PRIMARY KEY : UNIQUE autorise NULL et n'est pas l'identifiant principal
4. 📝 Nommez toujours vos contraintes : `UQ_Table_Colonne`
5. ✅ Utilisez UNIQUE pour les colonnes métier importantes (email, codes, etc.)
6. 🔄 Peut être **simple** (une colonne) ou **composite** (plusieurs colonnes)
7. ⚡ Crée automatiquement un **index** pour optimiser les performances
8. ✅ Combinez avec `NOT NULL` si la valeur est obligatoire
