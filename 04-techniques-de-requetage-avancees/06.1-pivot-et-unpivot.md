# 4.6.1 PIVOT et UNPIVOT

## Introduction

**PIVOT** et **UNPIVOT** sont deux opérateurs T-SQL qui permettent de **transformer la structure de vos données** :

- **PIVOT** : Transforme des **lignes en colonnes** (rotation des données)
- **UNPIVOT** : Transforme des **colonnes en lignes** (opération inverse)

Ces opérations sont particulièrement utiles pour :
- Créer des rapports en tableau croisé
- Réorganiser des données pour l'analyse
- Préparer des données pour des outils de visualisation
- Normaliser ou dénormaliser des structures de données

## 1. PIVOT - Transformer des lignes en colonnes

### Concept

L'opérateur **PIVOT** prend des valeurs situées dans les **lignes** et les transforme en **colonnes**, en effectuant généralement une agrégation.

### Analogie simple

Imaginez un tableau de ventes avec une ligne par transaction :

```
Vendeur | Mois    | Montant
Martin  | Janvier | 1000
Martin  | Février | 1500
Durand  | Janvier | 1200
Durand  | Février | 1300
```

Avec **PIVOT**, vous pouvez créer un tableau où :
- Chaque **vendeur** est une ligne
- Chaque **mois** devient une colonne
- Les **montants** sont agrégés dans les cellules

```
Vendeur | Janvier | Février
Martin  | 1000    | 1500
Durand  | 1200    | 1300
```

### Structure des données avant PIVOT

Généralement, vos données sont sous forme **normalisée** (format "long") :

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Martin | Jan | 5000 |
| Martin | Fév | 7000 |
| Martin | Mar | 6000 |
| Durand | Jan | 4000 |
| Durand | Fév | 5000 |
| Durand | Mar | 6500 |

### Structure après PIVOT

Les données deviennent un **tableau croisé** (format "large") :

| Vendeur | Jan | Fév | Mar |
|---------|-----|-----|-----|
| Martin | 5000 | 7000 | 6000 |
| Durand | 4000 | 5000 | 6500 |

### Syntaxe de PIVOT

```sql
SELECT <colonnes_non_pivotées>, [colonne_pivotée_1], [colonne_pivotée_2], ...
FROM (
    <requête_source>
) AS SourceTable
PIVOT (
    <fonction_agrégation>(<colonne_à_agréger>)
    FOR <colonne_à_pivoter> IN ([valeur1], [valeur2], [valeur3], ...)
) AS PivotTable;
```

**Éléments clés :**
- **fonction_agrégation** : SUM, AVG, COUNT, MIN, MAX, etc.
- **colonne_à_agréger** : Les valeurs à agréger (ex: montants de ventes)
- **colonne_à_pivoter** : La colonne dont les valeurs deviendront des colonnes
- **IN (...)** : Liste explicite des valeurs qui deviendront des colonnes

### Exemple de base

**Données source :**

```sql
CREATE TABLE VentesVendeurs (
    Vendeur NVARCHAR(50),
    Mois NVARCHAR(10),
    Ventes INT
);

INSERT INTO VentesVendeurs VALUES
('Martin', 'Jan', 5000),
('Martin', 'Fév', 7000),
('Martin', 'Mar', 6000),
('Durand', 'Jan', 4000),
('Durand', 'Fév', 5000),
('Durand', 'Mar', 6500);
```

**Requête PIVOT :**

```sql
SELECT
    Vendeur,
    [Jan],
    [Fév],
    [Mar]
FROM (
    SELECT Vendeur, Mois, Ventes
    FROM VentesVendeurs
) AS SourceData
PIVOT (
    SUM(Ventes)
    FOR Mois IN ([Jan], [Fév], [Mar])
) AS PivotTable;
```

**Résultat :**

| Vendeur | Jan | Fév | Mar |
|---------|-----|-----|-----|
| Martin | 5000 | 7000 | 6000 |
| Durand | 4000 | 5000 | 6500 |

### Décortiquons la requête

**1. La sous-requête source :**
```sql
SELECT Vendeur, Mois, Ventes
FROM VentesVendeurs
```
Prépare les données : sélectionne uniquement les colonnes nécessaires.

**2. La clause PIVOT :**
```sql
PIVOT (
    SUM(Ventes)           -- Agrège les ventes
    FOR Mois IN ([Jan], [Fév], [Mar])  -- Les mois deviennent des colonnes
)
```

**3. Le SELECT final :**
```sql
SELECT Vendeur, [Jan], [Fév], [Mar]
```
Sélectionne les colonnes du résultat (la colonne non pivotée + les nouvelles colonnes).

### Pourquoi une sous-requête ?

La sous-requête est **recommandée** pour :
- Sélectionner uniquement les colonnes nécessaires
- Éviter les ambiguïtés
- Contrôler précisément les données pivotées

**Sans sous-requête** (peut causer des problèmes) :
```sql
-- ❌ Peut produire des résultats inattendus si la table a d'autres colonnes
SELECT Vendeur, [Jan], [Fév], [Mar]
FROM VentesVendeurs
PIVOT (
    SUM(Ventes)
    FOR Mois IN ([Jan], [Fév], [Mar])
) AS PivotTable;
```

### Exemple avec AVG au lieu de SUM

```sql
SELECT
    Produit,
    [Q1],
    [Q2],
    [Q3],
    [Q4]
FROM (
    SELECT Produit, Trimestre, PrixMoyen
    FROM PrixProduits
) AS SourceData
PIVOT (
    AVG(PrixMoyen)
    FOR Trimestre IN ([Q1], [Q2], [Q3], [Q4])
) AS PivotTable;
```

Calcule le **prix moyen** par produit et par trimestre.

### Exemple avec COUNT

```sql
SELECT
    Region,
    [Bronze],
    [Argent],
    [Or]
FROM (
    SELECT Region, NiveauClient
    FROM Clients
) AS SourceData
PIVOT (
    COUNT(NiveauClient)
    FOR NiveauClient IN ([Bronze], [Argent], [Or])
) AS PivotTable;
```

Compte le **nombre de clients** de chaque niveau par région.

### PIVOT avec plusieurs agrégations

Un `PIVOT` n'applique **qu'une seule fonction d'agrégation**. Pour combiner par exemple un total (`SUM`) ET une moyenne (`AVG`) sur les mêmes données, le `PIVOT` seul ne suffit pas : il faudrait écrire **deux PIVOT séparés** (un par fonction) puis les joindre.

La solution la plus simple et lisible est l'**agrégation conditionnelle** avec `CASE`, qui autorise des fonctions différentes par colonne :

```sql
SELECT
    Vendeur,
    SUM(CASE WHEN Mois = 'Jan' THEN Ventes END) AS Jan_Total,
    AVG(CASE WHEN Mois = 'Jan' THEN Ventes END) AS Jan_Moyenne,
    SUM(CASE WHEN Mois = 'Fév' THEN Ventes END) AS Fev_Total,
    AVG(CASE WHEN Mois = 'Fév' THEN Ventes END) AS Fev_Moyenne
FROM VentesVendeurs
GROUP BY Vendeur;
```

> ⚠️ Évitez l'astuce qui consiste à dupliquer les lignes avec des suffixes (`Mois + '_Moyenne'`) puis à appliquer `SUM` dans le `PIVOT` : la colonne « moyenne » contiendrait alors une **somme**, pas une moyenne.

### Gestion des valeurs NULL

Si une combinaison n'existe pas dans les données, PIVOT retourne **NULL** :

**Données :**
```
Vendeur | Mois | Ventes
Martin  | Jan  | 5000
Martin  | Fév  | 7000
Durand  | Jan  | 4000
-- Durand n'a pas de ventes en Février
```

**Résultat PIVOT :**

| Vendeur | Jan | Fév |
|---------|-----|-----|
| Martin | 5000 | 7000 |
| Durand | 4000 | NULL |

**Remplacer NULL par 0 :**

```sql
SELECT
    Vendeur,
    ISNULL([Jan], 0) AS Jan,
    ISNULL([Fév], 0) AS Fév,
    ISNULL([Mar], 0) AS Mar
FROM (
    SELECT Vendeur, Mois, Ventes
    FROM VentesVendeurs
) AS SourceData
PIVOT (
    SUM(Ventes)
    FOR Mois IN ([Jan], [Fév], [Mar])
) AS PivotTable;
```

### PIVOT dynamique avec SQL dynamique

Souvent, vous ne connaissez pas à l'avance toutes les valeurs à pivoter. Vous pouvez générer la requête **dynamiquement** :

```sql
DECLARE @columns NVARCHAR(MAX), @sql NVARCHAR(MAX);

-- Construire la liste des colonnes dynamiquement
SELECT @columns = STRING_AGG(QUOTENAME(Mois), ',')
FROM (SELECT DISTINCT Mois FROM VentesVendeurs) AS Mois;

-- Construire la requête PIVOT dynamique
SET @sql = N'
SELECT Vendeur, ' + @columns + '
FROM (
    SELECT Vendeur, Mois, Ventes
    FROM VentesVendeurs
) AS SourceData
PIVOT (
    SUM(Ventes)
    FOR Mois IN (' + @columns + ')
) AS PivotTable;';

-- Exécuter la requête dynamique
EXEC sp_executesql @sql;
```

**Note :** STRING_AGG est disponible à partir de SQL Server 2017. Pour les versions antérieures, utilisez FOR XML PATH.

### Alternative à PIVOT : Agrégation conditionnelle

Vous pouvez obtenir le même résultat avec CASE et GROUP BY :

```sql
SELECT
    Vendeur,
    SUM(CASE WHEN Mois = 'Jan' THEN Ventes ELSE 0 END) AS Jan,
    SUM(CASE WHEN Mois = 'Fév' THEN Ventes ELSE 0 END) AS Fév,
    SUM(CASE WHEN Mois = 'Mar' THEN Ventes ELSE 0 END) AS Mar
FROM VentesVendeurs
GROUP BY Vendeur;
```

**Avantages de cette méthode :**
- Plus flexible (plusieurs agrégations différentes)
- Pas besoin de sous-requête
- Plus facile à comprendre pour certains

**Inconvénient :**
- Plus verbeux pour beaucoup de colonnes

## 2. UNPIVOT - Transformer des colonnes en lignes

### Concept

L'opérateur **UNPIVOT** fait l'opération **inverse** de PIVOT : il prend des valeurs situées dans plusieurs **colonnes** et les transforme en **lignes**.

### Analogie simple

Vous avez un tableau avec une colonne par mois :

```
Vendeur | Jan  | Fév  | Mar
Martin  | 5000 | 7000 | 6000
Durand  | 4000 | 5000 | 6500
```

Avec **UNPIVOT**, vous pouvez créer une table normalisée :

```
Vendeur | Mois | Ventes
Martin  | Jan  | 5000
Martin  | Fév  | 7000
Martin  | Mar  | 6000
Durand  | Jan  | 4000
Durand  | Fév  | 5000
Durand  | Mar  | 6500
```

### Syntaxe de UNPIVOT

```sql
SELECT <colonnes>
FROM (
    <requête_source>
) AS SourceTable
UNPIVOT (
    <colonne_valeurs>
    FOR <colonne_noms> IN ([colonne1], [colonne2], [colonne3], ...)
) AS UnpivotTable;
```

**Éléments clés :**
- **colonne_valeurs** : Nom de la nouvelle colonne qui contiendra les valeurs
- **colonne_noms** : Nom de la nouvelle colonne qui contiendra les noms des colonnes d'origine
- **IN (...)** : Liste des colonnes à "dépivoter"

### Exemple de base

**Données source (table pivotée) :**

```sql
CREATE TABLE VentesPivotees (
    Vendeur NVARCHAR(50),
    Jan INT,
    Fév INT,
    Mar INT
);

INSERT INTO VentesPivotees VALUES
('Martin', 5000, 7000, 6000),
('Durand', 4000, 5000, 6500);
```

**Table actuelle :**

| Vendeur | Jan | Fév | Mar |
|---------|-----|-----|-----|
| Martin | 5000 | 7000 | 6000 |
| Durand | 4000 | 5000 | 6500 |

**Requête UNPIVOT :**

```sql
SELECT
    Vendeur,
    Mois,
    Ventes
FROM (
    SELECT Vendeur, Jan, Fév, Mar
    FROM VentesPivotees
) AS SourceData
UNPIVOT (
    Ventes FOR Mois IN ([Jan], [Fév], [Mar])
) AS UnpivotTable;
```

**Résultat :**

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Martin | Jan | 5000 |
| Martin | Fév | 7000 |
| Martin | Mar | 6000 |
| Durand | Jan | 4000 |
| Durand | Fév | 5000 |
| Durand | Mar | 6500 |

### Décortiquons la requête

**1. La sous-requête source :**
```sql
SELECT Vendeur, Jan, Fév, Mar
FROM VentesPivotees
```
Sélectionne les colonnes à dépivoter.

**2. La clause UNPIVOT :**
```sql
UNPIVOT (
    Ventes FOR Mois IN ([Jan], [Fév], [Mar])
)
```
- **Ventes** : Nom de la colonne qui contiendra les valeurs (5000, 7000, etc.)
- **Mois** : Nom de la colonne qui contiendra les noms de colonnes d'origine (Jan, Fév, Mar)
- **IN ([Jan], [Fév], [Mar])** : Les colonnes à transformer en lignes

### Gestion des valeurs NULL avec UNPIVOT

**Important :** UNPIVOT **ignore automatiquement** les valeurs NULL.

**Données avec NULL :**

| Vendeur | Jan | Fév | Mar |
|---------|-----|-----|-----|
| Martin | 5000 | 7000 | 6000 |
| Durand | 4000 | NULL | 6500 |

**Résultat UNPIVOT :**

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Martin | Jan | 5000 |
| Martin | Fév | 7000 |
| Martin | Mar | 6000 |
| Durand | Jan | 4000 |
| Durand | Mar | 6500 |

**La ligne avec Fév = NULL pour Durand est absente !**

Si vous voulez conserver les NULL, utilisez l'alternative avec CROSS APPLY (voir ci-dessous).

### Exemple avec plusieurs colonnes à conserver

```sql
SELECT
    Vendeur,
    Region,  -- Colonne supplémentaire conservée
    Mois,
    Ventes
FROM (
    SELECT Vendeur, Region, Jan, Fév, Mar
    FROM VentesPivoteesAvecRegion
) AS SourceData
UNPIVOT (
    Ventes FOR Mois IN ([Jan], [Fév], [Mar])
) AS UnpivotTable;
```

**Résultat :**

| Vendeur | Region | Mois | Ventes |
|---------|--------|------|--------|
| Martin | Nord | Jan | 5000 |
| Martin | Nord | Fév | 7000 |
| Martin | Nord | Mar | 6000 |

### Alternative à UNPIVOT : CROSS APPLY avec VALUES

Cette méthode est plus flexible et **conserve les NULL** :

```sql
SELECT
    Vendeur,
    Mois,
    Ventes
FROM VentesPivotees
CROSS APPLY (
    VALUES
        ('Jan', Jan),
        ('Fév', Fév),
        ('Mar', Mar)
) AS Unpivoted(Mois, Ventes);
```

**Avantages :**
- Conserve les valeurs NULL
- Plus facile à lire pour certains
- Permet plus de flexibilité (conversions de types, calculs, etc.)

**Exemple avec conservation des NULL :**

**Données :**

| Vendeur | Jan | Fév | Mar |
|---------|-----|-----|-----|
| Durand | 4000 | NULL | 6500 |

**Avec CROSS APPLY :**

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Durand | Jan | 4000 |
| Durand | Fév | NULL |
| Durand | Mar | 6500 |

**La ligne avec NULL est conservée !**

### UNPIVOT dynamique

Comme pour PIVOT, vous pouvez générer UNPIVOT dynamiquement si vous ne connaissez pas les colonnes à l'avance :

```sql
DECLARE @columns NVARCHAR(MAX), @sql NVARCHAR(MAX);

-- Obtenir les colonnes à dépivoter (toutes sauf 'Vendeur')
SELECT @columns = STRING_AGG(QUOTENAME(COLUMN_NAME), ',')
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'VentesPivotees'
  AND COLUMN_NAME <> 'Vendeur';

-- Construire la requête UNPIVOT dynamique
SET @sql = N'
SELECT Vendeur, Mois, Ventes
FROM (
    SELECT * FROM VentesPivotees
) AS SourceData
UNPIVOT (
    Ventes FOR Mois IN (' + @columns + ')
) AS UnpivotTable;';

-- Exécuter
EXEC sp_executesql @sql;
```

## 3. Cas d'usage pratiques

### A. Rapport de ventes mensuel (PIVOT)

**Besoin :** Créer un rapport montrant les ventes de chaque produit par mois.

```sql
SELECT
    Produit,
    [Janvier],
    [Février],
    [Mars],
    [Avril],
    [Mai],
    [Juin],
    [Juillet],
    [Août],
    [Septembre],
    [Octobre],
    [Novembre],
    [Décembre]
FROM (
    SELECT
        Produit,
        DATENAME(MONTH, DateVente) AS Mois,
        Montant
    FROM Ventes
    WHERE YEAR(DateVente) = 2024
) AS SourceData
PIVOT (
    SUM(Montant)
    FOR Mois IN (
        [Janvier], [Février], [Mars], [Avril], [Mai], [Juin],
        [Juillet], [Août], [Septembre], [Octobre], [Novembre], [Décembre]
    )
) AS PivotTable
ORDER BY Produit;
```

### B. Tableau croisé dynamique (PIVOT)

**Besoin :** Nombre de commandes par région et par statut.

```sql
SELECT
    Region,
    [En attente],
    [En cours],
    [Livré],
    [Annulé]
FROM (
    SELECT Region, Statut
    FROM Commandes
) AS SourceData
PIVOT (
    COUNT(Statut)
    FOR Statut IN ([En attente], [En cours], [Livré], [Annulé])
) AS PivotTable;
```

### C. Normalisation de données (UNPIVOT)

**Besoin :** Vous recevez un fichier Excel avec une colonne par trimestre, vous devez le normaliser.

```sql
SELECT
    Produit,
    Trimestre,
    Ventes
FROM (
    SELECT Produit, Q1, Q2, Q3, Q4
    FROM VentesTrimestre
) AS SourceData
UNPIVOT (
    Ventes FOR Trimestre IN ([Q1], [Q2], [Q3], [Q4])
) AS UnpivotTable;
```

### D. Transformation pour graphique (UNPIVOT)

**Besoin :** Transformer des données en format "long" pour un outil de visualisation.

```sql
-- Données originales : une colonne par année
-- Vendeur | 2022 | 2023 | 2024

-- Transformation :
SELECT
    Vendeur,
    Annee,
    ChiffreAffaires
FROM (
    SELECT Vendeur, [2022], [2023], [2024]
    FROM VentesAnnuelles
) AS SourceData
UNPIVOT (
    ChiffreAffaires FOR Annee IN ([2022], [2023], [2024])
) AS UnpivotTable;

-- Résultat : format "long" idéal pour les graphiques
-- Vendeur | Annee | ChiffreAffaires
-- Martin  | 2022  | 50000
-- Martin  | 2023  | 60000
-- Martin  | 2024  | 70000
```

### E. Statistiques par catégorie (PIVOT)

```sql
-- Notes moyennes par matière pour chaque élève
SELECT
    Eleve,
    [Mathématiques],
    [Français],
    [Histoire],
    [Sciences]
FROM (
    SELECT Eleve, Matiere, Note
    FROM Notes
) AS SourceData
PIVOT (
    AVG(Note)
    FOR Matiere IN ([Mathématiques], [Français], [Histoire], [Sciences])
) AS PivotTable;
```

## 4. Combinaison PIVOT et UNPIVOT

Vous pouvez chaîner les opérations pour des transformations complexes :

```sql
-- D'abord UNPIVOT pour normaliser
WITH Normalise AS (
    SELECT Vendeur, Mois, Ventes
    FROM (SELECT Vendeur, Jan, Fév, Mar FROM VentesPivotees) AS Src
    UNPIVOT (Ventes FOR Mois IN ([Jan], [Fév], [Mar])) AS Unp
),
-- Puis PIVOT avec une autre dimension
Repivoté AS (
    SELECT
        Mois,
        [Martin],
        [Durand]
    FROM Normalise
    PIVOT (
        SUM(Ventes)
        FOR Vendeur IN ([Martin], [Durand])
    ) AS Piv
)
SELECT * FROM Repivoté;
```

**Résultat :** Les vendeurs sont maintenant en colonnes au lieu des mois !

## 5. Limitations et pièges

### Limitations de PIVOT

**1. Liste statique des valeurs**

Vous devez lister explicitement les valeurs dans IN (...) :
```sql
FOR Mois IN ([Jan], [Fév], [Mar])  -- Pas de SELECT dynamique ici
```

**Solution :** Utiliser du SQL dynamique (voir exemple plus haut).

**2. Une seule agrégation à la fois**

Difficile de faire plusieurs agrégations (SUM et AVG) dans le même PIVOT.

**Solution :** Utiliser plusieurs PIVOT ou des agrégations conditionnelles avec CASE.

**3. Les colonnes doivent exister**

Si vous mentionnez [Avril] dans IN (...) mais qu'il n'y a pas de données pour avril, vous obtenez des NULL partout pour cette colonne.

### Limitations de UNPIVOT

**1. Suppression automatique des NULL**

UNPIVOT exclut les lignes avec NULL.

**Solution :** Utiliser CROSS APPLY avec VALUES pour conserver les NULL.

**2. Types de données homogènes**

Toutes les colonnes dépivotées doivent avoir le **même type de données**.

```sql
-- ❌ ERREUR si Jan est INT et Fév est VARCHAR
UNPIVOT (Ventes FOR Mois IN ([Jan], [Fév]))
```

**Solution :** Convertir les colonnes au même type dans la sous-requête source.

**3. Liste statique des colonnes**

Comme PIVOT, vous devez lister explicitement les colonnes.

**Solution :** SQL dynamique.

## 6. Performance

### Conseils de performance

**1. Index appropriés**

Pour PIVOT, assurez-vous d'avoir des index sur :
- La colonne qui devient les lignes (ex: Vendeur)
- La colonne à pivoter (ex: Mois)

**2. Limiter les données**

Filtrez les données dans la sous-requête source :
```sql
FROM (
    SELECT Vendeur, Mois, Ventes
    FROM VentesVendeurs
    WHERE Annee = 2024  -- Filtre ici !
) AS SourceData
```

**3. Alternative GROUP BY peut être plus rapide**

Pour un petit nombre de colonnes, l'agrégation conditionnelle avec CASE peut être plus performante :

```sql
-- Parfois plus rapide que PIVOT
SELECT
    Vendeur,
    SUM(CASE WHEN Mois = 'Jan' THEN Ventes END) AS Jan,
    SUM(CASE WHEN Mois = 'Fév' THEN Ventes END) AS Fév
FROM VentesVendeurs
GROUP BY Vendeur;
```

**4. Éviter le SQL dynamique quand possible**

Le SQL dynamique empêche la mise en cache des plans d'exécution. Utilisez-le seulement quand vraiment nécessaire.

## 7. Bonnes pratiques

### Pour PIVOT

✅ **À faire :**
- Toujours utiliser une sous-requête pour préparer les données
- Lister uniquement les colonnes nécessaires dans la sous-requête
- Gérer les NULL avec ISNULL ou COALESCE
- Utiliser des noms de colonnes clairs avec QUOTENAME en SQL dynamique

❌ **À éviter :**
- Pivoter directement depuis la table sans sous-requête
- Inclure des colonnes inutiles qui peuvent causer des doublons
- Oublier de gérer les valeurs manquantes

### Pour UNPIVOT

✅ **À faire :**
- Vérifier que toutes les colonnes ont le même type
- Utiliser CROSS APPLY si vous devez conserver les NULL
- Documenter la transformation pour la maintenance

❌ **À éviter :**
- Supposer que les NULL seront conservés
- Mélanger des types de données différents
- Oublier d'inclure les colonnes d'identification (ex: Vendeur)

## 8. Alternatives modernes

### Avec fonctions de fenêtrage et agrégations conditionnelles

```sql
-- Alternative à PIVOT pour un tableau croisé
SELECT
    Vendeur,
    SUM(CASE WHEN Mois = 'Jan' THEN Ventes ELSE 0 END) AS Jan,
    SUM(CASE WHEN Mois = 'Fév' THEN Ventes ELSE 0 END) AS Fév,
    SUM(CASE WHEN Mois = 'Mar' THEN Ventes ELSE 0 END) AS Mar
FROM VentesVendeurs
GROUP BY Vendeur;
```

### Avec STRING_AGG (SQL Server 2017+)

Pour créer des listes au lieu de sommes :

```sql
-- Créer une liste des produits par catégorie
SELECT
    Categorie,
    STRING_AGG(Produit, ', ') AS ListeProduits
FROM Produits
GROUP BY Categorie;
```

## Tableau récapitulatif

| Aspect | PIVOT | UNPIVOT |
|--------|-------|---------|
| **Transformation** | Lignes → Colonnes | Colonnes → Lignes |
| **Usage** | Créer tableaux croisés | Normaliser les données |
| **Agrégation** | Obligatoire (SUM, AVG, etc.) | Aucune |
| **NULL** | Résultat contient NULL si absent | NULL automatiquement exclus |
| **Flexibilité** | Liste statique de valeurs | Liste statique de colonnes |
| **Alternative** | Agrégation conditionnelle + GROUP BY | CROSS APPLY + VALUES |

## Résumé

**PIVOT et UNPIVOT** sont des outils puissants pour transformer la structure de vos données :

**PIVOT :**
- Transforme des lignes en colonnes
- Nécessite une fonction d'agrégation
- Utile pour les rapports en tableau croisé
- Nécessite une liste explicite des valeurs

**UNPIVOT :**
- Transforme des colonnes en lignes
- Normalise les données
- Exclut automatiquement les NULL
- Nécessite des types de données homogènes

**Points clés :**
- Toujours utiliser des sous-requêtes pour préparer les données
- Considérer les alternatives (CASE + GROUP BY, CROSS APPLY)
- Utiliser SQL dynamique pour des listes de valeurs dynamiques
- Gérer explicitement les valeurs NULL

**Quand les utiliser :**
- PIVOT : Pour créer des rapports, des tableaux croisés, des vues agrégées
- UNPIVOT : Pour normaliser des données, préparer pour l'analyse, nettoyer des imports Excel

Ces opérateurs sont particulièrement utiles lors de l'intégration de données provenant de sources externes ou lors de la création de rapports pour des outils de visualisation !
