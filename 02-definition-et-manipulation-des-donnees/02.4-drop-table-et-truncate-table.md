# 2.2.4 DROP TABLE et TRUNCATE TABLE

## Introduction

Dans la gestion des bases de données, il arrive parfois que vous ayez besoin de :
- **Supprimer complètement une table** (sa structure ET ses données)
- **Vider une table** (supprimer toutes les données mais garder la structure)

SQL Server propose deux commandes pour ces opérations :
- `DROP TABLE` : supprime la table entièrement
- `TRUNCATE TABLE` : vide la table mais conserve sa structure

**⚠️ AVERTISSEMENT IMPORTANT** : Ces deux commandes suppriment des données de façon **immédiate**. Hors d'une transaction explicite, il n'y a pas de « Ctrl+Z » possible — alors **sauvegardez toujours avant** ! (Bon à savoir : sous SQL Server, exécutées *dans* une transaction explicite, elles peuvent être annulées par un `ROLLBACK` ; nous y revenons plus bas.)

## DROP TABLE : Supprimer une Table Complètement

### Qu'est-ce que DROP TABLE ?

`DROP TABLE` supprime **complètement** une table de votre base de données :
- La **structure** de la table (colonnes, types de données)
- **Toutes les données** contenues dans la table
- Les **index** associés
- Les **contraintes** définies sur la table

**Analogie :** C'est comme détruire un meuble et tout ce qu'il contient. Après, il n'en reste plus rien.

### Syntaxe de Base

```sql
DROP TABLE NomTable;
```

### Exemple Simple

```sql
-- Supprimer la table Clients
DROP TABLE Clients;
```

Après cette commande, la table `Clients` n'existe plus du tout dans votre base de données.

### DROP TABLE avec Vérification d'Existence

Pour éviter une erreur si la table n'existe pas, vous pouvez vérifier son existence avant :

#### Méthode Classique

```sql
IF OBJECT_ID('Clients', 'U') IS NOT NULL
    DROP TABLE Clients;
```

**Explication :**
- `OBJECT_ID('Clients', 'U')` vérifie si l'objet existe
- `'U'` signifie "User Table" (table utilisateur)
- Si la table existe, elle est supprimée
- Si elle n'existe pas, aucune erreur n'est générée

#### Méthode Moderne (SQL Server 2016+)

```sql
DROP TABLE IF EXISTS Clients;
```

Cette syntaxe est plus simple et plus lisible. C'est la méthode recommandée si vous utilisez SQL Server 2016 ou supérieur.

### Supprimer Plusieurs Tables

Vous pouvez supprimer plusieurs tables en une seule commande :

```sql
DROP TABLE Clients, Commandes, Produits;
```

**Note :** Attention à l'ordre si vos tables ont des relations (clés étrangères). Voir la section "Restrictions" ci-dessous.

### Quand Utiliser DROP TABLE ?

Utilisez `DROP TABLE` quand :
- ✅ Vous voulez **supprimer définitivement** une table de test
- ✅ Une table est devenue **obsolète** et n'est plus nécessaire
- ✅ Vous voulez **recréer une table** avec une nouvelle structure
- ✅ Vous faites du **nettoyage** dans votre base de données

### Exemple Pratique : Recréer une Table

```sql
-- Supprimer l'ancienne table si elle existe
DROP TABLE IF EXISTS Employes;

-- Créer une nouvelle table avec une structure améliorée
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    NomComplet VARCHAR(150) NOT NULL,
    Email VARCHAR(100),
    DateEmbauche DATE,
    Salaire DECIMAL(10, 2)
);
```

## TRUNCATE TABLE : Vider une Table

### Qu'est-ce que TRUNCATE TABLE ?

`TRUNCATE TABLE` supprime **toutes les données** d'une table, mais **conserve la structure** de la table :
- ✅ La structure (colonnes, types) reste intacte
- ✅ Les contraintes sont conservées
- ❌ Toutes les lignes de données sont supprimées

**Analogie :** C'est comme vider tous les tiroirs d'un meuble, mais garder le meuble lui-même intact et prêt à être rempli à nouveau.

### Syntaxe

```sql
TRUNCATE TABLE NomTable;
```

### Exemple Simple

```sql
-- Vider la table Logs sans la supprimer
TRUNCATE TABLE Logs;
```

Après cette commande :
- La table `Logs` existe toujours
- Elle a toujours les mêmes colonnes
- Mais elle ne contient plus aucune ligne de données (elle est vide)

### Quand Utiliser TRUNCATE TABLE ?

Utilisez `TRUNCATE TABLE` quand :
- ✅ Vous voulez **supprimer toutes les données** mais **garder la table**
- ✅ Vous avez une table de **logs** ou de **données temporaires** à vider régulièrement
- ✅ Vous voulez **réinitialiser** une table de test
- ✅ Vous préparez une table pour un **rechargement complet** de données

### Exemple Pratique : Réinitialiser des Données de Test

```sql
-- Vider la table pour refaire des tests propres
TRUNCATE TABLE CommandesTest;

-- La table est maintenant vide et prête pour de nouvelles insertions
INSERT INTO CommandesTest (IdCommande, DateCommande, Montant)
VALUES (1, '2025-01-15', 150.00);
```

## Différences entre DROP et TRUNCATE

Voici un tableau comparatif pour bien comprendre les différences :

| Critère | DROP TABLE | TRUNCATE TABLE |
|---------|------------|----------------|
| **Structure de la table** | ❌ Supprimée | ✅ Conservée |
| **Données** | ❌ Supprimées | ❌ Supprimées |
| **Contraintes** | ❌ Supprimées | ✅ Conservées |
| **Index** | ❌ Supprimés | ✅ Conservés |
| **Peut être annulé (ROLLBACK)** | ⚠️ Oui (si dans une transaction) | ⚠️ Oui (si dans une transaction) |
| **Performance** | Rapide | Très rapide |
| **Réinitialise l'identité (IDENTITY)** | N/A | ✅ Oui |
| **Déclenche les triggers** | ❌ Non | ❌ Non |
| **Nécessite des permissions** | Hautes (DROP) | Moyennes (ALTER) |

### Cas d'Usage Comparés

```sql
-- ❌ Scénario 1 : Je ne veux PLUS la table du tout
DROP TABLE CommandesArchivees;
-- Résultat : La table n'existe plus

-- ✅ Scénario 2 : Je veux GARDER la table mais VIDER son contenu
TRUNCATE TABLE LogsTemporaires;
-- Résultat : La table existe toujours, mais est vide
```

## DELETE vs TRUNCATE : Une Différence Importante

Il existe aussi une commande `DELETE` qui supprime des données. Voici la différence avec `TRUNCATE` :

| Critère | TRUNCATE TABLE | DELETE FROM |
|---------|----------------|-------------|
| **Supprime toutes les lignes** | ✅ Oui (sans condition) | ✅ Oui (si pas de WHERE) |
| **Peut supprimer certaines lignes** | ❌ Non | ✅ Oui (avec WHERE) |
| **Performance** | ⚡ Très rapide | 🐌 Plus lent |
| **Réinitialise l'IDENTITY** | ✅ Oui | ❌ Non |
| **Déclenche les triggers** | ❌ Non | ✅ Oui |
| **Enregistre chaque suppression dans le log** | ❌ Non (minimal) | ✅ Oui |
| **Peut être utilisé avec WHERE** | ❌ Non | ✅ Oui |

### Exemples Comparatifs

```sql
-- TRUNCATE : Vide toute la table (très rapide)
TRUNCATE TABLE Logs;

-- DELETE : Vide toute la table (plus lent)
DELETE FROM Logs;

-- DELETE : Supprime seulement certaines lignes (impossible avec TRUNCATE)
DELETE FROM Logs WHERE DateLog < '2025-01-01';
```

**Règle simple :**
- Utilisez `TRUNCATE` quand vous voulez **vider toute la table rapidement**
- Utilisez `DELETE` quand vous voulez **supprimer seulement certaines lignes**

## Restrictions et Limitations

### Restrictions sur DROP TABLE

Vous **ne pouvez pas** supprimer une table si :

1. **Elle est référencée par une clé étrangère** dans une autre table

```sql
-- Cette commande échouera si la table Commandes a une clé étrangère vers Clients
DROP TABLE Clients;
-- Erreur : Could not drop object 'Clients' because it is referenced by a FOREIGN KEY constraint
```

**Solution :** Supprimez d'abord les contraintes de clés étrangères ou supprimez les tables dans le bon ordre :

```sql
-- Ordre correct : tables dépendantes d'abord
DROP TABLE Commandes;      -- Table qui référence Clients
DROP TABLE Clients;         -- Table référencée
```

2. **Elle est utilisée dans une vue** (selon les paramètres)

3. **Vous n'avez pas les permissions nécessaires**

### Restrictions sur TRUNCATE TABLE

Vous **ne pouvez pas** utiliser `TRUNCATE` si :

1. **La table est référencée par une clé étrangère** (même restriction que DROP)

```sql
-- Cette commande échouera si une autre table référence Clients
TRUNCATE TABLE Clients;
-- Erreur : Cannot truncate table 'Clients' because it is being referenced by a FOREIGN KEY constraint
```

**Solution :** Utilisez `DELETE FROM` à la place :

```sql
DELETE FROM Clients;
```

2. **La table est publiée dans une réplication** (transactionnelle ou de fusion)

3. **La table est référencée par une vue indexée** (*indexed view*)

## Exemples Pratiques Complets

### Exemple 1 : Nettoyage de Tables de Test

```sql
-- Script de nettoyage après des tests

-- Supprimer complètement les tables de test
DROP TABLE IF EXISTS Test_Commandes;
DROP TABLE IF EXISTS Test_Clients;
DROP TABLE IF EXISTS Test_Produits;

-- Message de confirmation
PRINT 'Tables de test supprimées avec succès';
```

### Exemple 2 : Réinitialisation de Données Temporaires

```sql
-- Script de réinitialisation quotidienne

-- Vider les tables de logs (garder la structure)
TRUNCATE TABLE LogsConnexions;
TRUNCATE TABLE LogsErreurs;
TRUNCATE TABLE LogsPerformances;

-- Vérifier que les tables sont vides
SELECT 'LogsConnexions' AS TableName, COUNT(*) AS NombreLignes FROM LogsConnexions
UNION ALL
SELECT 'LogsErreurs', COUNT(*) FROM LogsErreurs
UNION ALL
SELECT 'LogsPerformances', COUNT(*) FROM LogsPerformances;
```

### Exemple 3 : Recréation d'une Table avec Sauvegarde

```sql
-- Sauvegarder les données avant suppression
SELECT * INTO Clients_Backup_20251116
FROM Clients;

-- Vérifier la sauvegarde
SELECT COUNT(*) AS NombreLignesSauvegardees FROM Clients_Backup_20251116;

-- Supprimer l'ancienne table
DROP TABLE Clients;

-- Créer la nouvelle structure
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY IDENTITY(1,1),
    NomComplet VARCHAR(150) NOT NULL,
    Email VARCHAR(100) UNIQUE,
    Telephone VARCHAR(20),
    DateInscription DATE DEFAULT GETDATE(),
    EstActif BIT DEFAULT 1
);

-- Réimporter les données (après adaptation si nécessaire)
-- INSERT INTO Clients (NomComplet, Email, ...)
-- SELECT NomComplet, Email, ... FROM Clients_Backup_20251116;
```

### Exemple 4 : Gestion des Dépendances

```sql
-- Scénario : Supprimer une table avec des dépendances

-- Étape 1 : Identifier les contraintes
SELECT
    OBJECT_NAME(fk.parent_object_id) AS TableReferencante,
    fk.name AS NomContrainte
FROM sys.foreign_keys fk
WHERE OBJECT_NAME(fk.referenced_object_id) = 'Clients';

-- Étape 2 : Supprimer les contraintes de clés étrangères
ALTER TABLE Commandes
DROP CONSTRAINT FK_Commandes_Clients;

-- Étape 3 : Maintenant on peut supprimer la table
DROP TABLE Clients;
```

## Bonnes Pratiques de Sécurité

### 1. Toujours Sauvegarder Avant de Supprimer

```sql
-- ✅ BON : Créer une sauvegarde d'abord
SELECT * INTO MaTable_Backup FROM MaTable;
DROP TABLE MaTable;

-- ❌ MAUVAIS : Supprimer sans sauvegarde
DROP TABLE MaTable;
```

### 2. Utiliser les Transactions pour DROP (Environnement de Test)

```sql
-- Démarrer une transaction
BEGIN TRANSACTION;

    -- Supprimer la table
    DROP TABLE TableTest;

    -- Vérifier que c'est bien ce que vous vouliez
    -- Si erreur ou regret, vous pouvez faire ROLLBACK

-- Si tout est OK
COMMIT TRANSACTION;

-- Si vous changez d'avis (seulement avant le COMMIT)
-- ROLLBACK TRANSACTION;
```

**⚠️ Note :** En production, `DROP` est généralement immédiat et ne peut pas être annulé facilement.

### 3. Ajouter des Confirmations dans les Scripts

```sql
-- Demander confirmation avant suppression
DECLARE @Confirmation NVARCHAR(10);
SET @Confirmation = 'OUI'; -- Changez cette valeur pour exécuter

IF @Confirmation = 'OUI'
BEGIN
    DROP TABLE IF EXISTS DonneesImportantes;
    PRINT 'Table supprimée';
END
ELSE
BEGIN
    PRINT 'Suppression annulée - Changez @Confirmation = ''OUI'' pour exécuter';
END
```

### 4. Documenter les Suppressions

```sql
-- =========================================
-- SUPPRESSION DE TABLES OBSOLÈTES
-- Date: 2025-11-16
-- Auteur: Équipe Développement
-- Raison: Migration vers nouvelle structure
-- Sauvegarde: Clients_Backup_20251116
-- =========================================

DROP TABLE IF EXISTS AncienneTableClients;
DROP TABLE IF EXISTS AncienneTableCommandes;

PRINT 'Nettoyage des tables obsolètes terminé.';
```

### 5. Vérifier Avant d'Exécuter en Production

```sql
-- ✅ BON : Tester sur une copie de développement d'abord
-- ✅ BON : Vérifier qu'aucune application n'utilise la table
-- ✅ BON : Planifier pendant une fenêtre de maintenance
-- ✅ BON : Avoir un plan de rollback (restauration)
```

## Réinitialisation de l'IDENTITY avec TRUNCATE

Un avantage important de `TRUNCATE` : il réinitialise automatiquement le compteur `IDENTITY` (auto-incrémentation).

### Exemple avec TRUNCATE

```sql
CREATE TABLE TestIdentity
(
    Id INT IDENTITY(1,1),
    Valeur VARCHAR(50)
);

-- Insérer des données
INSERT INTO TestIdentity (Valeur) VALUES ('A'), ('B'), ('C');
-- Résultat : Id = 1, 2, 3

-- Vider avec TRUNCATE
TRUNCATE TABLE TestIdentity;

-- Réinsérer des données
INSERT INTO TestIdentity (Valeur) VALUES ('X'), ('Y');
-- Résultat : Id = 1, 2 (le compteur a été réinitialisé)
```

### Exemple avec DELETE

```sql
-- Vider avec DELETE
DELETE FROM TestIdentity;

-- Réinsérer des données
INSERT INTO TestIdentity (Valeur) VALUES ('X'), ('Y');
-- Résultat : Id = 4, 5 (le compteur continue)
```

Pour réinitialiser manuellement l'IDENTITY après un DELETE :

```sql
DBCC CHECKIDENT ('TestIdentity', RESEED, 0);
```

## Messages de Confirmation

Après vos opérations, vous pouvez afficher des messages de confirmation :

```sql
-- Avec DROP
DROP TABLE IF EXISTS MaTable;
IF OBJECT_ID('MaTable', 'U') IS NULL
    PRINT '✓ Table MaTable supprimée avec succès';
ELSE
    PRINT '✗ Erreur : La table existe encore';

-- Avec TRUNCATE
TRUNCATE TABLE LogsTemporaires;
SELECT COUNT(*) AS NombreLignesRestantes FROM LogsTemporaires;
-- Devrait afficher 0
```

## Checklist Avant Suppression

Avant de supprimer une table importante, posez-vous ces questions :

- [ ] Ai-je vraiment besoin de supprimer cette table ?
- [ ] Ai-je créé une sauvegarde ?
- [ ] Cette table est-elle référencée par d'autres tables (clés étrangères) ?
- [ ] Cette table est-elle utilisée dans des vues, procédures stockées ou applications ?
- [ ] Ai-je testé la suppression en développement ?
- [ ] Ai-je les permissions nécessaires ?
- [ ] Ai-je prévenu les utilisateurs/développeurs concernés ?
- [ ] Ai-je documenté cette suppression ?

## Résumé

| Commande | Effet | Quand l'utiliser |
|----------|-------|------------------|
| **DROP TABLE** | Supprime la table entière (structure + données) | Table obsolète, recréation complète |
| **TRUNCATE TABLE** | Vide la table (conserve la structure) | Réinitialisation, nettoyage de données temporaires |
| **DELETE FROM** | Supprime des lignes (avec ou sans condition) | Suppression sélective de données |

## Points Clés à Retenir

1. 🛑 **DROP TABLE** supprime **tout** : structure + données + contraintes + index
2. 🔄 **TRUNCATE TABLE** vide la table mais **conserve la structure**
3. ⚡ **TRUNCATE** est beaucoup **plus rapide** que **DELETE** pour vider une table entière
4. 🔄 **TRUNCATE** réinitialise le compteur **IDENTITY**
5. ⚠️ Hors transaction, ces commandes prennent effet **immédiatement** — mais sous SQL Server, un `ROLLBACK` les annule si elles sont exécutées dans une transaction explicite. Dans tous les cas, **sauvegardez avant** !
6. 🔒 Les tables avec **clés étrangères** nécessitent des précautions particulières
7. ✅ Utilisez **IF EXISTS** pour éviter les erreurs
