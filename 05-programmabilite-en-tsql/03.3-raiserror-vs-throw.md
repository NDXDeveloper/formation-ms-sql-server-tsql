# 5.3.3 RAISERROR (ancienne méthode) vs THROW (moderne)

## Introduction

Jusqu'à présent, nous avons appris à **capturer** et **analyser** les erreurs qui se produisent dans notre code. Mais parfois, vous avez besoin de **générer volontairement** une erreur pour signaler un problème : "Cette valeur est invalide", "Cet utilisateur n'a pas les permissions nécessaires", "Cette opération est interdite".

En T-SQL, vous disposez de deux méthodes pour générer des erreurs personnalisées :
1. **RAISERROR** : la méthode historique (depuis SQL Server 6.0)
2. **THROW** : la méthode moderne (depuis SQL Server 2012)

Dans cette section, nous allons découvrir les deux méthodes, comprendre leurs différences, et apprendre quand utiliser l'une ou l'autre.

---

## 1. Pourquoi générer des erreurs ?

### Le besoin de validation

Imaginez une procédure qui enregistre une commande :

```sql
CREATE PROCEDURE CreerCommande
    @ClientID INT,
    @Montant DECIMAL(10,2)
AS
BEGIN
    -- Et si le montant est négatif ?
    -- Et si le client n'existe pas ?
    -- Comment signaler le problème ?

    INSERT INTO Commandes (ClientID, Montant, DateCommande)
    VALUES (@ClientID, @Montant, GETDATE());
END
```

**Problèmes :**
- Aucune validation
- Pas de message d'erreur clair
- Comportement imprévisible avec des données invalides

### La solution : Générer des erreurs

```sql
CREATE PROCEDURE CreerCommande
    @ClientID INT,
    @Montant DECIMAL(10,2)
AS
BEGIN
    -- Validation du montant
    IF @Montant <= 0
    BEGIN
        THROW 50001, 'Le montant doit être positif', 1;
    END

    -- Validation du client
    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
    BEGIN
        THROW 50002, 'Client introuvable', 1;
    END

    -- Si tout est OK, insérer
    INSERT INTO Commandes (ClientID, Montant, DateCommande)
    VALUES (@ClientID, @Montant, GETDATE());

    PRINT 'Commande créée avec succès';
END
```

**Avantages :**
- Validation explicite
- Messages d'erreur clairs
- Contrôle du flux d'exécution

### Analogie

Pensez à un contrôleur de sécurité dans un bâtiment :
- Si votre badge est invalide → Il **génère une alerte** (erreur)
- Si tout est OK → Il vous laisse passer (exécution normale)

RAISERROR et THROW sont vos "générateurs d'alertes" en T-SQL.

## 2. RAISERROR - La méthode historique

### Qu'est-ce que RAISERROR ?

**RAISERROR** (prononcez "raise error" = lever une erreur) est la méthode **historique** pour générer des erreurs personnalisées en T-SQL. Elle existe depuis SQL Server 6.0 (1995).

### Syntaxe de base

```sql
RAISERROR('Message d''erreur', gravité, état);
```

**Paramètres :**
1. **Message** : Texte décrivant l'erreur (VARCHAR ou référence à sys.messages)
2. **Gravité** : Niveau de sévérité (0-25)
3. **État** : Code d'état défini par l'utilisateur (0-255)

### Premier exemple simple

```sql
DECLARE @Age INT = 15;

IF @Age < 18
BEGIN
    RAISERROR('L''utilisateur doit avoir au moins 18 ans', 16, 1);
END

PRINT 'Accès autorisé';
```

**Résultat :**
```
Msg 50000, Level 16, State 1
L'utilisateur doit avoir au moins 18 ans
```

**Note :** ⚠️ Contrairement à ce qu'on pourrait croire, `RAISERROR` (gravité 11-16) **n'interrompt PAS** le batch : hors d'un `TRY...CATCH`, l'instruction `PRINT 'Accès autorisé'` qui suit **s'exécute quand même** (juste après le message d'erreur). C'est une différence fondamentale avec `THROW`, qui lui **termine** le batch — voir la comparaison au §4.

### Les niveaux de gravité

| Gravité | Type | Description | Comportement |
|---------|------|-------------|--------------|
| 0-10 | Information | Messages informatifs | N'arrête pas l'exécution |
| 11-16 | Erreur utilisateur | Erreurs corrigibles | Peut être capturée par TRY...CATCH |
| 17-19 | Erreur ressource | Problèmes de ressources | Peut être capturée par TRY...CATCH |
| 20-25 | Erreur fatale | Erreurs système graves | Ferme la connexion |

### Exemples avec différentes gravités

#### Gravité 10 ou moins (Informatif)

```sql
-- Niveau 10 : Simple information
RAISERROR('Traitement en cours...', 10, 1) WITH NOWAIT;
PRINT 'Cette ligne s''exécute normalement';
```

**Résultat :**
```
Traitement en cours...
Cette ligne s'exécute normalement
```

**Note :** `WITH NOWAIT` force l'affichage immédiat du message.

#### Gravité 11-16 (Erreur standard)

```sql
BEGIN TRY
    RAISERROR('Erreur de validation', 16, 1);
    PRINT 'Cette ligne ne sera jamais exécutée';
END TRY
BEGIN CATCH
    PRINT 'Erreur capturée : ' + ERROR_MESSAGE();
END CATCH
```

**Résultat :**
```
Erreur capturée : Erreur de validation
```

### Messages avec paramètres

RAISERROR supporte les **paramètres formatés** comme printf en C :

```sql
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @Age INT = 15;

RAISERROR('L''utilisateur %s (%d ans) est trop jeune', 16, 1, @Nom, @Age);
```

**Résultat :**
```
L'utilisateur Dupont (15 ans) est trop jeune
```

**Marqueurs de format courants :**
- `%s` : Chaîne de caractères (string)
- `%d` : Entier (decimal/digit)
- `%i` : Entier (integer)
- `%f` : Nombre à virgule flottante (float)

### Exemple avec formatage

```sql
DECLARE @NomProduit VARCHAR(100) = 'Ordinateur';
DECLARE @Stock INT = 5;
DECLARE @Demande INT = 10;

IF @Stock < @Demande
BEGIN
    RAISERROR('Stock insuffisant pour "%s". Disponible: %d, Demandé: %d',
              16, 1, @NomProduit, @Stock, @Demande);
END
```

**Résultat :**
```
Stock insuffisant pour "Ordinateur". Disponible: 5, Demandé: 10
```

### WITH NOWAIT

Par défaut, les messages sont mis en buffer. `WITH NOWAIT` force l'affichage immédiat :

```sql
-- Sans NOWAIT : le message apparaît après l'attente
RAISERROR('Début du traitement...', 10, 1);
WAITFOR DELAY '00:00:05';
PRINT 'Fin';

-- Avec NOWAIT : le message apparaît immédiatement
RAISERROR('Début du traitement...', 10, 1) WITH NOWAIT;
WAITFOR DELAY '00:00:05';
PRINT 'Fin';
```

### WITH LOG

`WITH LOG` enregistre l'erreur dans le journal Windows et le journal d'erreurs SQL Server :

```sql
-- Enregistre dans les logs système
RAISERROR('Erreur critique détectée', 16, 1) WITH LOG;
```

**Note :** Nécessite les permissions sysadmin pour les gravités < 19.

## 3. THROW - La méthode moderne

### Qu'est-ce que THROW ?

**THROW** est la méthode **moderne** pour générer des erreurs, introduite dans SQL Server 2012. Elle est plus simple et plus cohérente que RAISERROR.

### Syntaxe

#### Syntaxe 1 : THROW avec paramètres

```sql
THROW numéro_erreur, 'Message d''erreur', état;
```

**Paramètres :**
1. **Numéro d'erreur** : Entier >= 50000
2. **Message** : Texte de l'erreur (NVARCHAR)
3. **État** : Code d'état (0-255)

#### Syntaxe 2 : THROW sans paramètres (dans CATCH uniquement)

```sql
THROW;  -- Relance l'erreur courante
```

### Premier exemple simple

```sql
DECLARE @Age INT = 15;

IF @Age < 18
BEGIN
    THROW 50001, 'L''utilisateur doit avoir au moins 18 ans', 1;
END

PRINT 'Accès autorisé';
```

**Résultat :**
```
Msg 50001, Level 16, State 1
L'utilisateur doit avoir au moins 18 ans
```

### Différence majeure : Tous les paramètres sont obligatoires

**❌ Ceci ne fonctionne PAS :**
```sql
THROW 'Message d''erreur';  -- ERREUR : manque numéro et état
```

**✅ Tous les paramètres sont requis :**
```sql
THROW 50001, 'Message d''erreur', 1;  -- OK
```

### Numéros d'erreur personnalisés

Les numéros d'erreur personnalisés doivent être **>= 50000** :

```sql
-- ❌ Erreur : Numéro trop petit
THROW 100, 'Message', 1;

-- ✅ OK : Numéro >= 50000
THROW 50001, 'Message', 1;
```

**Convention recommandée :**
- 50001-50099 : Erreurs de validation
- 50100-50199 : Erreurs métier
- 50200-50299 : Erreurs de sécurité
- etc.

### Exemple avec codes d'erreur organisés

```sql
-- Constantes pour les codes d'erreur
DECLARE @ERR_VALIDATION INT = 50001;
DECLARE @ERR_NOT_FOUND INT = 50002;
DECLARE @ERR_PERMISSION INT = 50003;

DECLARE @ClientID INT = 999;

-- Vérifier si le client existe
IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
BEGIN
    THROW @ERR_NOT_FOUND, 'Client introuvable', 1;
END
```

### THROW pour relancer une erreur

Dans un bloc CATCH, `THROW;` (sans paramètres) relance l'erreur originale :

```sql
BEGIN TRY
    SELECT 1 / 0;
END TRY
BEGIN CATCH
    -- Logger l'erreur
    PRINT 'Erreur loggée : ' + ERROR_MESSAGE();

    -- Relancer la même erreur
    THROW;
END CATCH
```

**Résultat :**
```
Erreur loggée : Divide by zero error encountered.
Msg 8134, Level 16, State 1
Divide by zero error encountered.
```

## 4. Comparaison : RAISERROR vs THROW

### Tableau comparatif

| Critère | RAISERROR | THROW |
|---------|-----------|-------|
| **Disponibilité** | SQL Server 6.0+ (1995) | SQL Server 2012+ |
| **Syntaxe** | Complexe | Simple |
| **Paramètres** | Message peut être seul | Tous obligatoires (ou aucun) |
| **Numéro d'erreur** | 50000 par défaut | >= 50000 obligatoire |
| **Formatage** | Supporte %s, %d, etc. | Non supporté |
| **Gravité** | Paramétrable (0-25) | Toujours 16 |
| **Arrête le batch** | Non : le batch continue (sauf gravité ≥ 20 qui ferme la connexion) | Oui : termine le batch (sauf s'il est dans un TRY) |
| **Points-virgules** | Optionnel | **REQUIS avant THROW** |
| **Dans CATCH** | Génère nouvelle erreur | Peut relancer l'erreur courante |
| **WITH NOWAIT** | Oui | Non |
| **WITH LOG** | Oui | Non |

### Exemple côte à côte

**Avec RAISERROR :**
```sql
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @Montant DECIMAL(10,2) = -100;

IF @Montant < 0
    RAISERROR('Montant invalide pour %s: %f', 16, 1, @Nom, @Montant);
```

**Avec THROW :**
```sql
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @Montant DECIMAL(10,2) = -100;
DECLARE @Message NVARCHAR(2048);

IF @Montant < 0
BEGIN
    SET @Message = 'Montant invalide pour ' + @Nom + ': ' + CAST(@Montant AS VARCHAR);
    THROW 50001, @Message, 1;
END
```

**Note :** THROW nécessite de construire le message manuellement.

## 5. Le piège du point-virgule avec THROW

### Problème majeur

THROW **EXIGE** un point-virgule avant lui si une autre instruction le précède sur la même ligne logique.

**❌ Erreur courante :**
```sql
DECLARE @X INT = 0

IF @X = 0
    THROW 50001, 'X ne peut pas être zéro', 1  -- ERREUR DE SYNTAXE !
```

**Erreur :**
```
Incorrect syntax near 'THROW'.
```

**✅ Solution :**
```sql
DECLARE @X INT = 0;  -- Point-virgule ici

IF @X = 0
    THROW 50001, 'X ne peut pas être zéro', 1;  -- OK
```

**Ou plus sûr :**
```sql
DECLARE @X INT = 0

IF @X = 0
BEGIN
    ;THROW 50001, 'X ne peut pas être zéro', 1;  -- Point-virgule avant THROW
END
```

### Bonne pratique : Toujours mettre un point-virgule avant THROW

```sql
-- Recommandé
;THROW 50001, 'Message d''erreur', 1;
```

## 6. Quand utiliser RAISERROR ?

### ✅ Utilisez RAISERROR pour :

#### 1. Compatibilité avec versions anciennes

```sql
-- Si votre code doit fonctionner sur SQL Server 2008 R2 ou antérieur
IF @Condition = 0
    RAISERROR('Condition non remplie', 16, 1);
```

#### 2. Messages avec formatage complexe

```sql
DECLARE @Client VARCHAR(50) = 'ACME Corp';
DECLARE @Commande INT = 12345;
DECLARE @Montant DECIMAL(10,2) = 9999.99;

RAISERROR('Client: %s | Commande #%d | Montant: %.2f €',
          16, 1, @Client, @Commande, @Montant);
```

**Résultat :**
```
Client: ACME Corp | Commande #12345 | Montant: 9999.99 €
```

#### 3. Messages informatifs (gravité 0-10)

```sql
-- Afficher la progression sans arrêter l'exécution
DECLARE @I INT = 1;

WHILE @I <= 5
BEGIN
    RAISERROR('Traitement de l''élément %d/5', 10, 1, @I) WITH NOWAIT;
    WAITFOR DELAY '00:00:01';
    SET @I = @I + 1;
END
```

#### 4. Logging dans le journal système

```sql
-- Enregistrer dans les logs Windows
RAISERROR('Événement de sécurité détecté', 16, 1) WITH LOG;
```

## 7. Quand utiliser THROW ?

### ✅ Utilisez THROW pour :

#### 1. Nouveau code sur SQL Server 2012+

```sql
-- Simple, moderne, recommandé
IF @Valeur < 0
    THROW 50001, 'La valeur ne peut pas être négative', 1;
```

#### 2. Relancer une erreur dans CATCH

```sql
BEGIN TRY
    -- Code risqué
    EXEC UneAutreProcedure;
END TRY
BEGIN CATCH
    -- Logger l'erreur
    INSERT INTO LogErreurs (Message) VALUES (ERROR_MESSAGE());

    -- Relancer pour que l'appelant soit informé
    THROW;  -- Plus simple que RAISERROR
END CATCH
```

#### 3. Validation simple sans formatage

```sql
IF NOT EXISTS (SELECT 1 FROM Users WHERE UserID = @UserID)
    THROW 50404, 'Utilisateur introuvable', 1;

IF @Prix <= 0
    THROW 50001, 'Le prix doit être positif', 1;

IF @Email NOT LIKE '%@%'
    THROW 50002, 'Format email invalide', 1;
```

#### 4. Code moderne et cohérent

```sql
-- THROW est plus cohérent avec les standards modernes
BEGIN TRY
    IF @Condition
        THROW 50001, 'Erreur', 1;
END TRY
BEGIN CATCH
    -- Gestion cohérente avec THROW
    THROW;
END CATCH
```

## 8. Exemples pratiques

### Exemple 1 : Procédure de validation avec THROW

```sql
CREATE PROCEDURE CreerUtilisateur
    @Nom VARCHAR(100),
    @Email VARCHAR(100),
    @Age INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Validation des paramètres
    IF @Nom IS NULL OR LEN(@Nom) = 0
        THROW 50001, 'Le nom est obligatoire', 1;

    IF @Email NOT LIKE '%@%'
        THROW 50002, 'Format email invalide', 1;

    IF @Age < 18
        THROW 50003, 'L''utilisateur doit avoir au moins 18 ans', 1;

    IF EXISTS (SELECT 1 FROM Utilisateurs WHERE Email = @Email)
        THROW 50004, 'Cet email est déjà utilisé', 1;

    -- Si toutes les validations passent
    BEGIN TRY
        INSERT INTO Utilisateurs (Nom, Email, Age, DateCreation)
        VALUES (@Nom, @Email, @Age, GETDATE());

        PRINT 'Utilisateur créé avec succès';
    END TRY
    BEGIN CATCH
        -- En cas d'erreur système, relancer
        THROW;
    END CATCH
END
```

### Exemple 2 : Progression avec RAISERROR

```sql
CREATE PROCEDURE TraiterLotsCommandes
    @NombreLots INT = 10
AS
BEGIN
    DECLARE @I INT = 1;
    DECLARE @Message VARCHAR(100);

    WHILE @I <= @NombreLots
    BEGIN
        -- Afficher progression immédiatement
        RAISERROR('Traitement du lot %d/%d...', 10, 1, @I, @NombreLots) WITH NOWAIT;

        -- Traiter le lot
        UPDATE Commandes
        SET Statut = 'Traité'
        WHERE LotID = @I;

        -- Petite pause
        WAITFOR DELAY '00:00:01';

        SET @I = @I + 1;
    END

    RAISERROR('Traitement terminé !', 10, 1) WITH NOWAIT;
END
```

### Exemple 3 : Validation métier complexe

```sql
CREATE PROCEDURE EffectuerVirement
    @CompteSource INT,
    @CompteDest INT,
    @Montant DECIMAL(10,2)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SoldeSource DECIMAL(10,2);
    DECLARE @NomSource VARCHAR(100);
    DECLARE @NomDest VARCHAR(100);

    BEGIN TRY
        BEGIN TRANSACTION;

        -- Validation 1 : Montant positif
        IF @Montant <= 0
            THROW 50101, 'Le montant doit être positif', 1;

        -- Validation 2 : Comptes différents
        IF @CompteSource = @CompteDest
            THROW 50102, 'Les comptes source et destination doivent être différents', 1;

        -- Validation 3 : Compte source existe
        SELECT @SoldeSource = Solde, @NomSource = Titulaire
        FROM Comptes
        WHERE CompteID = @CompteSource;

        IF @NomSource IS NULL
            THROW 50103, 'Compte source introuvable', 1;

        -- Validation 4 : Solde suffisant
        IF @SoldeSource < @Montant
        BEGIN
            DECLARE @Msg NVARCHAR(200);
            SET @Msg = 'Solde insuffisant. Disponible: ' +
                       CAST(@SoldeSource AS VARCHAR) +
                       ', Demandé: ' + CAST(@Montant AS VARCHAR);
            THROW 50104, @Msg, 1;
        END

        -- Validation 5 : Compte destination existe
        SELECT @NomDest = Titulaire
        FROM Comptes
        WHERE CompteID = @CompteDest;

        IF @NomDest IS NULL
            THROW 50105, 'Compte destination introuvable', 1;

        -- Toutes validations OK, effectuer le virement
        UPDATE Comptes SET Solde = Solde - @Montant WHERE CompteID = @CompteSource;
        UPDATE Comptes SET Solde = Solde + @Montant WHERE CompteID = @CompteDest;

        -- Logger l'opération
        INSERT INTO HistoriqueVirements (CompteSource, CompteDest, Montant, DateVirement)
        VALUES (@CompteSource, @CompteDest, @Montant, GETDATE());

        COMMIT TRANSACTION;

        PRINT 'Virement effectué avec succès';
        PRINT 'De: ' + @NomSource + ' vers ' + @NomDest;
        PRINT 'Montant: ' + CAST(@Montant AS VARCHAR) + ' €';

    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;

        -- Logger l'erreur
        INSERT INTO LogErreurs (NumeroErreur, MessageErreur, DateErreur)
        VALUES (ERROR_NUMBER(), ERROR_MESSAGE(), GETDATE());

        -- Relancer l'erreur
        THROW;
    END CATCH
END
```

### Exemple 4 : Système d'erreurs centralisé

```sql
-- Table des codes d'erreur
CREATE TABLE CodesErreur (
    CodeErreur INT PRIMARY KEY,
    Message NVARCHAR(1000),
    Categorie VARCHAR(50),
    NiveauGravite INT
);

-- Insérer des codes d'erreur
INSERT INTO CodesErreur VALUES
(50001, 'Le {0} ne peut pas être vide', 'Validation', 16),
(50002, 'Format invalide pour {0}', 'Validation', 16),
(50003, '{0} introuvable (ID: {1})', 'NotFound', 16),
(50004, 'Solde insuffisant. Disponible: {0}, Requis: {1}', 'Business', 16);
GO

-- Fonction pour générer une erreur
CREATE PROCEDURE GenererErreur
    @Code INT,
    @Param1 NVARCHAR(100) = NULL,
    @Param2 NVARCHAR(100) = NULL
AS
BEGIN
    DECLARE @Message NVARCHAR(1000);

    -- Récupérer le message template
    SELECT @Message = Message
    FROM CodesErreur
    WHERE CodeErreur = @Code;

    IF @Message IS NULL
        SET @Message = 'Erreur inconnue (Code: ' + CAST(@Code AS VARCHAR) + ')';

    -- Remplacer les paramètres
    IF @Param1 IS NOT NULL
        SET @Message = REPLACE(@Message, '{0}', @Param1);
    IF @Param2 IS NOT NULL
        SET @Message = REPLACE(@Message, '{1}', @Param2);

    -- Générer l'erreur
    THROW @Code, @Message, 1;
END
GO

-- Utilisation
BEGIN TRY
    IF @Email IS NULL
        EXEC GenererErreur @Code = 50001, @Param1 = 'Email';

    IF NOT EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
        EXEC GenererErreur @Code = 50003, @Param1 = 'Client', @Param2 = @ClientID;
END TRY
BEGIN CATCH
    PRINT ERROR_MESSAGE();
END CATCH
```

## 9. Messages d'erreur personnalisés (sys.messages)

### Stocker des messages réutilisables

Vous pouvez enregistrer des messages d'erreur dans `sys.messages` pour les réutiliser :

```sql
-- Ajouter un message personnalisé
EXEC sp_addmessage
    @msgnum = 50001,
    @severity = 16,
    @msgtext = 'Le client %s n''a pas les permissions nécessaires';
GO

-- Utiliser avec RAISERROR
RAISERROR(50001, 16, 1, 'Dupont');

-- Afficher les messages personnalisés
SELECT * FROM sys.messages WHERE message_id >= 50000;

-- Supprimer un message
EXEC sp_dropmessage @msgnum = 50001;
```

**Note :** THROW ne peut PAS utiliser les messages de sys.messages, seulement RAISERROR.

## 10. Bonnes pratiques

### ✅ À FAIRE

1. **Utilisez THROW pour le nouveau code (SQL Server 2012+)**
   ```sql
   IF @Condition
       THROW 50001, 'Message d''erreur', 1;
   ```

2. **Utilisez des codes d'erreur significatifs**
   ```sql
   -- Organisez par catégorie
   50001-50099: Validation
   50100-50199: Erreurs métier
   50200-50299: Sécurité
   ```

3. **Créez des messages d'erreur clairs et actionnables**
   ```sql
   -- ❌ Mauvais
   THROW 50001, 'Erreur', 1;

   -- ✅ Bon
   THROW 50001, 'Email invalide: format requis exemple@domaine.com', 1;
   ```

4. **Documentez vos codes d'erreur**
   ```sql
   -- Créez une table de référence
   CREATE TABLE DocumentationErreurs (
       CodeErreur INT PRIMARY KEY,
       Description VARCHAR(500),
       Solution VARCHAR(1000)
   );
   ```

5. **Utilisez RAISERROR pour le formatage complexe**
   ```sql
   RAISERROR('Client: %s, Commande: %d, Erreur: %s',
             16, 1, @Client, @NumCommande, @Erreur);
   ```

### ❌ À ÉVITER

1. **N'oubliez pas le point-virgule avant THROW**
   ```sql
   -- ❌ Erreur
   DECLARE @X INT = 0
   THROW 50001, 'Message', 1;

   -- ✅ Correct
   DECLARE @X INT = 0;
   THROW 50001, 'Message', 1;
   ```

2. **N'utilisez pas des numéros < 50000 avec THROW**
   ```sql
   -- ❌ Erreur
   THROW 100, 'Message', 1;

   -- ✅ Correct
   THROW 50100, 'Message', 1;
   ```

3. **N'essayez pas de formater avec THROW**
   ```sql
   -- ❌ Ne fonctionne pas
   THROW 50001, 'Utilisateur: %s', 1, @Nom;

   -- ✅ Construisez le message
   DECLARE @Msg NVARCHAR(100);
   SET @Msg = 'Utilisateur: ' + @Nom;
   THROW 50001, @Msg, 1;
   ```

4. **Ne mélangez pas RAISERROR et THROW sans raison**
   ```sql
   -- ❌ Incohérent
   IF @A
       RAISERROR('Erreur A', 16, 1);
   IF @B
       THROW 50001, 'Erreur B', 1;

   -- ✅ Cohérent
   IF @A
       THROW 50001, 'Erreur A', 1;
   IF @B
       THROW 50002, 'Erreur B', 1;
   ```

## 11. Recommandation finale

### Pour du nouveau code

**Utilisez THROW** pour la plupart des cas :
- Plus simple
- Plus moderne
- Mieux intégré avec TRY...CATCH
- Standard Microsoft recommandé

### Exceptions : Utilisez RAISERROR quand

1. Vous devez supporter SQL Server 2008 R2 ou antérieur
2. Vous avez besoin de formatage complexe avec %s, %d, etc.
3. Vous voulez afficher des messages informatifs (gravité 0-10)
4. Vous avez besoin de WITH LOG ou WITH NOWAIT

### En résumé

```sql
-- ✅ Recommandé pour nouveau code
IF @Validation
    THROW 50001, 'Message d''erreur clair', 1;

-- ✅ OK si besoin de formatage
RAISERROR('Client %s: montant %.2f invalide', 16, 1, @Nom, @Montant);

-- ✅ OK pour messages informatifs
RAISERROR('Progression: %d%%', 10, 1, @Pourcent) WITH NOWAIT;
```

---

## Résumé

- **RAISERROR** est la méthode historique (SQL Server 6.0+), plus flexible mais plus complexe
- **THROW** est la méthode moderne (SQL Server 2012+), plus simple et recommandée
- RAISERROR supporte le **formatage** (%s, %d) et les messages informatifs (gravité 0-10)
- THROW exige **tous les paramètres** (ou aucun dans CATCH pour relancer)
- THROW nécessite un **point-virgule** avant lui
- Les codes d'erreur personnalisés doivent être **>= 50000**
- Utilisez **THROW** pour la majorité du nouveau code
- Utilisez **RAISERROR** pour le formatage complexe ou la compatibilité
- Dans un CATCH, `THROW;` relance l'erreur courante (équivalent plus simple que RAISERROR)
- Créez des **messages d'erreur clairs et actionnables**
- **Organisez vos codes d'erreur** par catégories (validation, métier, sécurité, etc.)

Les deux méthodes ont leur place en T-SQL. Comprendre leurs différences vous permet de choisir l'outil approprié pour chaque situation et de créer des systèmes de gestion d'erreurs robustes et maintenables.
