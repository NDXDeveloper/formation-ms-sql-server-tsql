# 2.1.1 Types numériques (INT, DECIMAL, NUMERIC, FLOAT)

## Introduction

Les types numériques sont essentiels pour stocker toutes sortes de valeurs chiffrées dans une base de données SQL Server : des quantités, des prix, des identifiants, des mesures, etc. Choisir le bon type numérique permet d'optimiser l'espace de stockage et d'assurer la précision des calculs.

Dans cette section, nous allons découvrir les principaux types numériques utilisés en T-SQL et apprendre quand utiliser chacun d'eux.

---

## Les différentes familles de types numériques

SQL Server propose deux grandes familles de types numériques :

1. **Les nombres entiers** : pour stocker des valeurs sans partie décimale
2. **Les nombres décimaux** : pour stocker des valeurs avec une partie décimale (virgule)

---

## 1. Les types entiers : INT et sa famille

### Qu'est-ce qu'un nombre entier ?

Un nombre entier est un nombre sans virgule, comme 1, 42, -15, 1000, etc. En SQL Server, on dispose de plusieurs types entiers qui diffèrent par la plage de valeurs qu'ils peuvent stocker et par l'espace qu'ils occupent en mémoire.

### Le type INT

**INT** (ou INTEGER) est le type entier le plus couramment utilisé.

**Caractéristiques :**
- **Plage de valeurs** : de -2,147,483,648 à 2,147,483,647
- **Espace de stockage** : 4 octets
- **Usage typique** : identifiants, quantités, âges, compteurs

**Exemple de déclaration :**

```sql
CREATE TABLE Produits (
    ProduitID INT,
    Quantite INT,
    AnneeProduction INT
);
```

**Exemple d'insertion :**

```sql
INSERT INTO Produits (ProduitID, Quantite, AnneeProduction)
VALUES (1, 500, 2024);
```

### Les variantes de INT

SQL Server propose d'autres types entiers pour des besoins spécifiques :

| Type | Plage de valeurs | Espace | Utilisation typique |
|------|------------------|--------|---------------------|
| **TINYINT** | 0 à 255 | 1 octet | Valeurs très petites (ex: âge, pourcentage) |
| **SMALLINT** | -32,768 à 32,767 | 2 octets | Petits compteurs |
| **INT** | -2,147,483,648 à 2,147,483,647 | 4 octets | Usage général |
| **BIGINT** | -9,223,372,036,854,775,808 à 9,223,372,036,854,775,807 | 8 octets | Très grandes valeurs |

**Conseil pratique :** Pour la plupart des cas, **INT** suffit amplement. Utilisez BIGINT uniquement si vous savez que vos valeurs dépasseront 2 milliards.

**Exemple avec différents types entiers :**

```sql
CREATE TABLE Exemple (
    Age TINYINT,           -- 0 à 255 suffit pour un âge
    Population BIGINT,     -- Pour de très grands nombres
    Compteur INT           -- Usage général
);
```

## 2. Les types décimaux : DECIMAL et NUMERIC

### Qu'est-ce qu'un nombre décimal ?

Un nombre décimal contient une partie entière et une partie décimale (après la virgule), comme 19.99, 3.14159, -0.5, etc. Ces types sont parfaits pour stocker des valeurs monétaires ou des mesures précises.

### Les types DECIMAL et NUMERIC

**DECIMAL** et **NUMERIC** sont **identiques** en T-SQL. Ce sont deux noms pour le même type de données. Par convention, on utilise souvent DECIMAL, mais vous pouvez utiliser l'un ou l'autre indifféremment.

**Caractéristiques :**
- **Précision fixe** : le nombre de chiffres est défini à l'avance
- **Pas d'arrondi inattendu** : idéal pour les calculs financiers
- **Syntaxe** : `DECIMAL(p, s)` ou `NUMERIC(p, s)`
  - **p** (précision) : nombre total de chiffres (avant et après la virgule)
  - **s** (échelle) : nombre de chiffres après la virgule

**Espace de stockage :** varie de 5 à 17 octets selon la précision

### Comprendre la précision et l'échelle

Prenons l'exemple de `DECIMAL(10, 2)` :
- **10** = précision totale (10 chiffres maximum)
- **2** = échelle (2 chiffres après la virgule)

Cela signifie :
- Avant la virgule : maximum 8 chiffres (10 - 2)
- Après la virgule : maximum 2 chiffres

**Valeurs possibles :**
- ✅ 12345678.99 (8 chiffres + 2 décimales = 10 chiffres)
- ✅ 99.50
- ✅ -1234.00
- ❌ 123456789.99 (9 + 2 = 11 chiffres, dépasse la précision)
- ❌ 99.999 (3 décimales au lieu de 2)

### Exemples d'utilisation

**Exemple 1 : Prix de produits**

```sql
CREATE TABLE Articles (
    ArticleID INT,
    Nom VARCHAR(100),
    Prix DECIMAL(10, 2)  -- Maximum 99999999.99
);

INSERT INTO Articles (ArticleID, Nom, Prix)
VALUES
    (1, 'Ordinateur portable', 899.99),
    (2, 'Souris', 15.50),
    (3, 'Clavier', 45.00);
```

**Exemple 2 : Taux et pourcentages**

```sql
CREATE TABLE TauxInteret (
    TauxID INT,
    Description VARCHAR(50),
    Taux DECIMAL(5, 4)  -- Par exemple : 0.0375 pour 3.75%
);

INSERT INTO TauxInteret (TauxID, Description, Taux)
VALUES (1, 'Taux annuel', 0.0375);
```

### Règles importantes pour DECIMAL/NUMERIC

1. **Toujours préciser la précision et l'échelle** pour éviter les valeurs par défaut
2. **Pour les montants** : `DECIMAL(10, 2)` ou `DECIMAL(18, 2)` sont des choix courants
3. **Pour les pourcentages** : `DECIMAL(5, 4)` permet de stocker jusqu'à 9.9999
4. **Les calculs conservent la précision** : pas d'arrondi inattendu

> ⚠️ **Piège du `DECIMAL` sans paramètres** — Si vous écrivez `DECIMAL` (ou `NUMERIC`) seul, SQL Server applique **`DECIMAL(18, 0)`** par défaut : précision 18, mais **échelle 0**, donc **aucune décimale** ! La partie après la virgule est alors arrondie :
> ```sql
> DECLARE @prix DECIMAL = 19.99;
> SELECT @prix;          -- 20  (et non 19.99 !)
> ```
> D'où la règle : **toujours** indiquer `(p, s)`, par exemple `DECIMAL(10, 2)`.

## 3. Le type à virgule flottante : FLOAT

### Qu'est-ce qu'un nombre à virgule flottante ?

Le type **FLOAT** stocke des nombres avec une précision approximative. Contrairement à DECIMAL qui garantit une précision exacte, FLOAT peut avoir de petites imprécisions dues à la façon dont les nombres sont représentés en mémoire.

**Caractéristiques :**
- **Précision approximative** : peut avoir de légers arrondis
- **Grande plage de valeurs** : peut stocker des nombres très grands ou très petits
- **Syntaxe** : `FLOAT(n)` où n est la précision (1 à 53)
- **Espace de stockage** : 4 octets (n ≤ 24) ou 8 octets (n > 24)

### Variantes de FLOAT

| Type | Précision | Espace | Équivalent |
|------|-----------|--------|------------|
| **REAL** | 7 chiffres | 4 octets | FLOAT(24) |
| **FLOAT** | 15 chiffres | 8 octets | FLOAT(53) par défaut |

### Quand utiliser FLOAT ?

**FLOAT est adapté pour :**
- Les calculs scientifiques
- Les mesures physiques
- Les coordonnées GPS
- Les données où une petite imprécision est acceptable

**FLOAT n'est PAS adapté pour :**
- ❌ Les montants monétaires
- ❌ Les quantités exactes
- ❌ Tout calcul nécessitant une précision absolue

### Exemple d'utilisation

```sql
CREATE TABLE Mesures (
    MesureID INT,
    Temperature FLOAT,          -- -273.15 à des millions de degrés
    Latitude FLOAT,             -- Coordonnées GPS
    Longitude FLOAT,
    DistanceKm DECIMAL(10, 2)   -- Pour les distances, préférez DECIMAL
);

INSERT INTO Mesures (MesureID, Temperature, Latitude, Longitude, DistanceKm)
VALUES (1, 23.456789, 48.8566, 2.3522, 150.25);
```

### Le problème de précision avec FLOAT

**Démonstration du problème :**

```sql
DECLARE @valeurFloat FLOAT = 0.1;
DECLARE @valeurDecimal DECIMAL(10, 1) = 0.1;

SELECT
    @valeurFloat + @valeurFloat + @valeurFloat AS ResultatFloat,
    @valeurDecimal + @valeurDecimal + @valeurDecimal AS ResultatDecimal;
```

**Résultat possible :**
- ResultatFloat : 0.30000000000000004
- ResultatDecimal : 0.3

C'est pourquoi **on évite FLOAT pour les calculs financiers !**

## Et les types MONEY et SMALLMONEY ?

SQL Server propose aussi deux types **dédiés aux montants** : **MONEY** (8 octets) et **SMALLMONEY** (4 octets), qui stockent toujours 4 décimales.

En pratique, la plupart des spécialistes **recommandent `DECIMAL` plutôt que `MONEY`** pour les montants financiers : `MONEY` peut introduire de petites erreurs d'arrondi dans les calculs intermédiaires (notamment les divisions). Pour un montant, préférez donc `DECIMAL(18, 2)` (le standard retenu dans cette formation), ou `DECIMAL(19, 4)` si vous avez besoin de 4 décimales.

> 📎 Ces deux types sont présentés en détail — avec exemples et pièges — dans la section [2.1.4 Autres types](/02-definition-et-manipulation-des-donnees/01.4-autres-types.md).

## Comparaison et guide de choix

### Tableau récapitulatif

| Type | Usage principal | Précision | Exemple |
|------|----------------|-----------|---------|
| **INT** | Nombres entiers (compteurs, ID) | Exacte | 42, -1000, 2024 |
| **BIGINT** | Très grands nombres entiers | Exacte | 9000000000000 |
| **DECIMAL(p,s)** | Montants, prix, mesures exactes | Exacte, fixe | 19.99, 1234.56 |
| **NUMERIC(p,s)** | Identique à DECIMAL | Exacte, fixe | 99.95 |
| **FLOAT** | Calculs scientifiques | Approximative | 3.14159265359 |

### Comment choisir le bon type ?

**Posez-vous ces questions :**

1. **Est-ce un nombre entier ?**
   - Oui → Utilisez **INT** (ou BIGINT si très grand)

2. **Est-ce un montant d'argent ?**
   - Oui → Utilisez **DECIMAL(10, 2)** ou **DECIMAL(18, 2)**

3. **Ai-je besoin d'une précision exacte ?**
   - Oui → Utilisez **DECIMAL**
   - Non (calculs scientifiques) → Utilisez **FLOAT**

4. **Combien de chiffres après la virgule ?**
   - 2 (prix) → DECIMAL(10, 2)
   - 4 (taux) → DECIMAL(5, 4)
   - Variable → FLOAT (si précision approximative acceptable)

## Exemples pratiques complets

### Exemple 1 : Table de commandes en ligne

```sql
CREATE TABLE Commandes (
    CommandeID INT,                    -- Identifiant (nombre entier)
    ClientID INT,                      -- Identifiant client
    MontantHT DECIMAL(10, 2),          -- Montant hors taxe (précision exacte)
    TauxTVA DECIMAL(5, 4),             -- 0.2000 pour 20%
    MontantTTC DECIMAL(10, 2),         -- Montant TTC calculé
    PoidsKg DECIMAL(8, 3),             -- Poids avec 3 décimales
    NombreArticles INT                 -- Quantité (entier)
);
```

### Exemple 2 : Table de données scientifiques

```sql
CREATE TABLE Experiences (
    ExperienceID INT,
    DateExperience DATE,
    TemperatureCelsius FLOAT,          -- Mesure scientifique
    PressionPascals FLOAT,              -- Grande plage de valeurs
    VolumeML DECIMAL(10, 2),           -- Volume exact en millilitres
    NombreEchantillons INT             -- Compteur
);
```

### Exemple 3 : Calcul avec DECIMAL

```sql
-- Calcul d'un prix TTC
DECLARE @PrixHT DECIMAL(10, 2) = 100.00;
DECLARE @TauxTVA DECIMAL(5, 4) = 0.2000;
DECLARE @PrixTTC DECIMAL(10, 2);

SET @PrixTTC = @PrixHT * (1 + @TauxTVA);

SELECT
    @PrixHT AS PrixHT,
    @TauxTVA AS TauxTVA,
    @PrixTTC AS PrixTTC;  -- Résultat : 120.00
```

## Points clés à retenir

✅ **INT** : le choix par défaut pour les nombres entiers

✅ **DECIMAL(p, s)** : pour tous les calculs nécessitant une précision exacte (argent, mesures)

✅ **FLOAT** : uniquement pour les calculs scientifiques où une approximation est acceptable

✅ Toujours définir explicitement la précision et l'échelle pour DECIMAL : `DECIMAL(10, 2)`

✅ Pour les montants monétaires : jamais de FLOAT, toujours DECIMAL

✅ NUMERIC et DECIMAL sont identiques, utilisez celui que vous préférez

---

## Conclusion

Le choix du bon type numérique est crucial pour :
- **La précision** : éviter les erreurs d'arrondi
- **La performance** : utiliser l'espace de stockage de manière optimale
- **La fiabilité** : garantir que vos calculs sont exacts

En règle générale :
- Pour les identifiants et compteurs → **INT**
- Pour l'argent et les mesures précises → **DECIMAL**
- Pour les calculs scientifiques → **FLOAT**

Avec ces connaissances, vous êtes maintenant capable de choisir le type numérique approprié pour chaque situation dans vos bases de données SQL Server !
