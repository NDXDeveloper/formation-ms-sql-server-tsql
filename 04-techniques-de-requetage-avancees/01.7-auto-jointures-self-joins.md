# 4.1.7 Auto-jointures (Self-Joins)

## Introduction

Jusqu'à présent, vous avez appris à joindre **deux tables différentes** entre elles (Clients avec Commandes, par exemple). Mais que se passe-t-il si vous devez joindre **une table avec elle-même** ?

C'est exactement ce que permettent les **auto-jointures** (Self-Joins en anglais) !

Une auto-jointure est une jointure où une table est jointe à elle-même. Cela peut sembler étrange au premier abord, mais c'est une technique extrêmement utile pour gérer des relations hiérarchiques, des comparaisons entre lignes, ou des relations réflexives dans vos données.

**Rassurez-vous** : Une auto-jointure n'est pas un nouveau type de jointure - c'est simplement l'utilisation d'un INNER JOIN, LEFT JOIN ou autre type de jointure, mais appliqué à la même table.

---

## Qu'est-ce qu'une auto-jointure ?

### Définition

Une **auto-jointure** (Self-Join) est une jointure où une table est jointe à **elle-même**. On traite la même table physique comme si c'était deux tables différentes en utilisant des **alias différents**.

### Pourquoi en avoir besoin ?

Les auto-jointures sont nécessaires quand **les données liées se trouvent dans la même table**. Voici des exemples courants :

- **Relations hiérarchiques** : Employés et leurs managers (tous dans la table Employes)
- **Relations entre pairs** : Produits similaires, amis sur un réseau social
- **Comparaisons** : Comparer des lignes d'une même table entre elles
- **Séquences** : Trouver des lignes consécutives dans un ordre

### Concept clé : Les alias sont obligatoires

Comme vous joignez la même table deux fois, vous **devez** utiliser des alias différents pour les distinguer. Sans alias, SQL Server ne saurait pas à quelle "copie" de la table vous faites référence.

```sql
-- ❌ IMPOSSIBLE : Pas d'alias
SELECT *
FROM Employes
INNER JOIN Employes ON Employes.ManagerID = Employes.EmployeID;
-- SQL Server ne sait pas quelle version d'Employes vous voulez !

-- ✅ CORRECT : Avec alias
SELECT *
FROM Employes E
INNER JOIN Employes M ON E.ManagerID = M.EmployeID;
-- E = table des employés, M = table des managers
```

## Exemple fondamental : Hiérarchie Employés-Managers

### Contexte : Table avec relations hiérarchiques

C'est l'exemple classique et le plus courant d'auto-jointure.

**Table `Employes`**

| EmployeID | NomEmploye | Poste           | ManagerID |
|-----------|------------|-----------------|-----------|
| 1         | Alice      | PDG             | NULL      |
| 2         | Bob        | Directeur       | 1         |
| 3         | Charlie    | Directeur       | 1         |
| 4         | Diana      | Chef d'équipe   | 2         |
| 5         | Eve        | Chef d'équipe   | 2         |
| 6         | Frank      | Développeur     | 4         |
| 7         | Grace      | Développeur     | 4         |
| 8         | Henry      | Développeur     | 5         |

### Observations clés

- Chaque employé a un `EmployeID` unique
- La colonne `ManagerID` fait référence à l'`EmployeID` d'un autre employé dans **la même table**
- Alice (PDG) n'a pas de manager → `ManagerID = NULL`
- Bob et Charlie rapportent à Alice (ManagerID = 1)
- Diana et Eve rapportent à Bob (ManagerID = 2)
- Etc.

### Visualisation de la hiérarchie

```
Alice (PDG)
├── Bob (Directeur)
│   ├── Diana (Chef d'équipe)
│   │   ├── Frank (Développeur)
│   │   └── Grace (Développeur)
│   └── Eve (Chef d'équipe)
│       └── Henry (Développeur)
└── Charlie (Directeur)
```

### Objectif

Nous voulons afficher **chaque employé avec le nom de son manager**.

### Requête avec auto-jointure INNER JOIN

```sql
SELECT
    E.EmployeID,
    E.NomEmploye AS Employe,
    E.Poste AS PosteEmploye,
    M.NomEmploye AS Manager,
    M.Poste AS PosteManager
FROM Employes E
INNER JOIN Employes M ON E.ManagerID = M.EmployeID;
```

### Résultat

| EmployeID | Employe | PosteEmploye    | Manager | PosteManager |
|-----------|---------|-----------------|---------|--------------|
| 2         | Bob     | Directeur       | Alice   | PDG          |
| 3         | Charlie | Directeur       | Alice   | PDG          |
| 4         | Diana   | Chef d'équipe   | Bob     | Directeur    |
| 5         | Eve     | Chef d'équipe   | Bob     | Directeur    |
| 6         | Frank   | Développeur     | Diana   | Chef d'équipe|
| 7         | Grace   | Développeur     | Diana   | Chef d'équipe|
| 8         | Henry   | Développeur     | Eve     | Chef d'équipe|

### Analyse du résultat

- ✅ Tous les employés avec un manager apparaissent
- ❌ Alice (PDG) n'apparaît **pas** car elle n'a pas de manager (ManagerID = NULL)

**Pourquoi Alice est absente ?**
L'INNER JOIN ne retourne que les lignes avec correspondance. Comme `ManagerID = NULL` pour Alice, il n'y a pas de correspondance dans la "table M" (deuxième référence à Employes).

### Comment l'auto-jointure fonctionne

1. **E** (alias pour Employes) représente les employés
2. **M** (alias pour Employes) représente les managers
3. La condition `E.ManagerID = M.EmployeID` lie chaque employé à son manager
4. Même si c'est physiquement la même table, SQL Server la traite comme deux tables distinctes grâce aux alias

## Auto-jointure avec LEFT JOIN

Pour inclure **tous les employés**, même ceux sans manager, utilisez un LEFT JOIN :

### Requête avec LEFT JOIN

```sql
SELECT
    E.EmployeID,
    E.NomEmploye AS Employe,
    E.Poste AS PosteEmploye,
    COALESCE(M.NomEmploye, 'Aucun manager') AS Manager,
    M.Poste AS PosteManager
FROM Employes E
LEFT JOIN Employes M ON E.ManagerID = M.EmployeID
ORDER BY E.EmployeID;
```

### Résultat

| EmployeID | Employe | PosteEmploye    | Manager        | PosteManager |
|-----------|---------|-----------------|----------------|--------------|
| 1         | Alice   | PDG             | Aucun manager  | NULL         |
| 2         | Bob     | Directeur       | Alice          | PDG          |
| 3         | Charlie | Directeur       | Alice          | PDG          |
| 4         | Diana   | Chef d'équipe   | Bob            | Directeur    |
| 5         | Eve     | Chef d'équipe   | Bob            | Directeur    |
| 6         | Frank   | Développeur     | Diana          | Chef d'équipe|
| 7         | Grace   | Développeur     | Diana          | Chef d'équipe|
| 8         | Henry   | Développeur     | Eve            | Chef d'équipe|

### Analyse

- ✅ Tous les employés sont maintenant présents
- ✅ Alice apparaît avec "Aucun manager"
- ✅ Le LEFT JOIN préserve tous les employés, même sans correspondance de manager

**Utilisation de COALESCE** : La fonction `COALESCE(M.NomEmploye, 'Aucun manager')` remplace NULL par un texte plus explicite.

## Cas d'usage pratiques des auto-jointures

### 1. Trouver les collègues (même manager)

Trouver tous les employés qui ont le même manager qu'un employé donné :

```sql
-- Trouver les collègues de Diana (même manager)
SELECT
    E2.NomEmploye AS Collegue,
    E2.Poste
FROM Employes E1
INNER JOIN Employes E2 ON E1.ManagerID = E2.ManagerID
WHERE E1.NomEmploye = 'Diana'
  AND E2.NomEmploye != 'Diana';  -- Exclure Diana elle-même
```

**Résultat** : Eve (car Diana et Eve ont toutes deux Bob comme manager)

### 2. Comparer des lignes entre elles

Comparer chaque produit avec les autres produits pour trouver des similitudes :

**Table `Produits`**

| ProduitID | NomProduit  | Categorie    | Prix  |
|-----------|-------------|--------------|-------|
| 1         | Laptop      | Informatique | 1000€ |
| 2         | Souris      | Informatique | 25€   |
| 3         | Clavier     | Informatique | 50€   |
| 4         | Imprimante  | Informatique | 200€  |

```sql
-- Trouver les produits de la même catégorie avec une différence de prix < 100€
SELECT
    P1.NomProduit AS Produit1,
    P2.NomProduit AS Produit2,
    ABS(P1.Prix - P2.Prix) AS DifferencePrix
FROM Produits P1
INNER JOIN Produits P2 ON P1.Categorie = P2.Categorie
                       AND P1.ProduitID < P2.ProduitID  -- Éviter les doublons
WHERE ABS(P1.Prix - P2.Prix) < 100;
```

**Note** : La condition `P1.ProduitID < P2.ProduitID` évite de comparer un produit avec lui-même et d'avoir des doublons (Produit1-Produit2 et Produit2-Produit1).

### 3. Relations d'amitié (réseaux sociaux)

Dans un réseau social où les amitiés sont stockées dans une table :

**Table `Amities`**

| UtilisateurID | AmiID |
|---------------|-------|
| 1             | 2     |
| 1             | 3     |
| 2             | 3     |
| 2             | 4     |

```sql
-- Trouver les amis communs entre deux utilisateurs
SELECT DISTINCT
    U1.Nom AS Utilisateur1,
    U2.Nom AS Utilisateur2,
    U3.Nom AS AmiCommun
FROM Amities A1
INNER JOIN Amities A2 ON A1.AmiID = A2.AmiID
INNER JOIN Utilisateurs U1 ON A1.UtilisateurID = U1.UtilisateurID
INNER JOIN Utilisateurs U2 ON A2.UtilisateurID = U2.UtilisateurID
INNER JOIN Utilisateurs U3 ON A1.AmiID = U3.UtilisateurID
WHERE A1.UtilisateurID < A2.UtilisateurID;
```

### 4. Séquences et lignes consécutives

Trouver des transactions consécutives pour le même client :

```sql
-- Trouver les achats consécutifs d'un même client
SELECT
    T1.TransactionID AS Transaction1,
    T1.DateTransaction AS Date1,
    T2.TransactionID AS Transaction2,
    T2.DateTransaction AS Date2,
    DATEDIFF(DAY, T1.DateTransaction, T2.DateTransaction) AS JoursEntre
FROM Transactions T1
INNER JOIN Transactions T2 ON T1.ClientID = T2.ClientID
                           AND T2.DateTransaction > T1.DateTransaction
WHERE T1.ClientID = 123
ORDER BY T1.DateTransaction;
```

### 5. Détecter des doublons ou des similitudes

Trouver des clients potentiellement en double :

```sql
-- Trouver les clients avec des noms très similaires
SELECT
    C1.ClientID AS Client1_ID,
    C1.Nom AS Client1_Nom,
    C2.ClientID AS Client2_ID,
    C2.Nom AS Client2_Nom
FROM Clients C1
INNER JOIN Clients C2 ON SOUNDEX(C1.Nom) = SOUNDEX(C2.Nom)
                      AND C1.ClientID < C2.ClientID;
```

**Note** : `SOUNDEX` compare phonétiquement les noms pour détecter des orthographes différentes du même nom.

## Auto-jointures multiples

Vous pouvez joindre une table avec elle-même plusieurs fois pour explorer des relations plus profondes :

### Exemple : Hiérarchie sur 3 niveaux

Afficher employé → manager → manager du manager :

```sql
SELECT
    E.NomEmploye AS Employe,
    M1.NomEmploye AS Manager,
    M2.NomEmploye AS ManagerDuManager
FROM Employes E
LEFT JOIN Employes M1 ON E.ManagerID = M1.EmployeID
LEFT JOIN Employes M2 ON M1.ManagerID = M2.EmployeID
ORDER BY E.EmployeID;
```

**Résultat pour Frank** :
- Employe : Frank
- Manager : Diana
- ManagerDuManager : Bob

### Visualisation des alias

```
E (Employes - niveau employé)
    ↓ join sur E.ManagerID = M1.EmployeID
M1 (Employes - niveau manager)
    ↓ join sur M1.ManagerID = M2.EmployeID
M2 (Employes - niveau manager du manager)
```

Chaque alias représente un "niveau" différent dans la hiérarchie.

---

## Choix du type de jointure pour les auto-jointures

### INNER JOIN (auto-jointure restrictive)

```sql
FROM Table T1
INNER JOIN Table T2 ON condition
```

**Utilisation** : Quand vous ne voulez que les lignes ayant une correspondance des deux côtés.

**Exemple** : Employés ayant un manager (exclut les PDG/directeurs sans manager).

### LEFT JOIN (auto-jointure inclusive)

```sql
FROM Table T1
LEFT JOIN Table T2 ON condition
```

**Utilisation** : Quand vous voulez toutes les lignes de la première référence, même sans correspondance.

**Exemple** : Tous les employés, y compris ceux sans manager.

### RIGHT JOIN (rarement utilisé)

```sql
FROM Table T1
RIGHT JOIN Table T2 ON condition
```

**Utilisation** : Rare en auto-jointure. Préférez réorganiser avec LEFT JOIN.

### CROSS JOIN (cas spécial)

```sql
FROM Table T1
CROSS JOIN Table T2
WHERE T1.ID != T2.ID
```

**Utilisation** : Pour comparer chaque ligne avec toutes les autres (attention à l'explosion combinatoire !).

**Exemple** : Comparer tous les produits entre eux pour trouver des similitudes.

## Techniques avancées avec auto-jointures

### 1. Éviter les auto-comparaisons

Quand vous comparez une table avec elle-même, vous voulez généralement exclure la comparaison d'une ligne avec elle-même :

```sql
-- ❌ Inclut la comparaison d'un produit avec lui-même
SELECT P1.NomProduit, P2.NomProduit
FROM Produits P1
INNER JOIN Produits P2 ON P1.Categorie = P2.Categorie;

-- ✅ Exclut l'auto-comparaison
SELECT P1.NomProduit, P2.NomProduit
FROM Produits P1
INNER JOIN Produits P2 ON P1.Categorie = P2.Categorie
                       AND P1.ProduitID != P2.ProduitID;
```

### 2. Éviter les doublons inversés

Quand vous comparez des paires, vous obtenez souvent des doublons (A-B et B-A) :

```sql
-- ❌ Produit des doublons : (Produit1, Produit2) et (Produit2, Produit1)
SELECT P1.NomProduit, P2.NomProduit
FROM Produits P1
INNER JOIN Produits P2 ON P1.Categorie = P2.Categorie
                       AND P1.ProduitID != P2.ProduitID;

-- ✅ Évite les doublons en ne gardant que les paires où ID1 < ID2
SELECT P1.NomProduit, P2.NomProduit
FROM Produits P1
INNER JOIN Produits P2 ON P1.Categorie = P2.Categorie
                       AND P1.ProduitID < P2.ProduitID;
```

**Explication** : La condition `P1.ProduitID < P2.ProduitID` garantit que chaque paire n'apparaît qu'une fois.

### 3. Agrégations avec auto-jointures

Compter le nombre de subordonnés directs pour chaque manager :

```sql
SELECT
    M.NomEmploye AS Manager,
    COUNT(E.EmployeID) AS NombreSubordonnes
FROM Employes M
LEFT JOIN Employes E ON M.EmployeID = E.ManagerID
GROUP BY M.EmployeID, M.NomEmploye
HAVING COUNT(E.EmployeID) > 0
ORDER BY NombreSubordonnes DESC;
```

**Résultat** :
- Bob : 2 subordonnés (Diana, Eve)
- Alice : 2 subordonnés (Bob, Charlie)
- Diana : 2 subordonnés (Frank, Grace)
- Eve : 1 subordonné (Henry)

## Hiérarchies récursives : Aller au-delà de l'auto-jointure

Les auto-jointures simples fonctionnent bien pour **un ou deux niveaux** de hiérarchie. Mais que faire si vous avez une hiérarchie **de profondeur variable ou inconnue** ?

### Limitation des auto-jointures simples

```sql
-- Fonctionne pour 3 niveaux seulement
SELECT
    E.NomEmploye,
    M1.NomEmploye AS Manager,
    M2.NomEmploye AS ManagerN2,
    M3.NomEmploye AS ManagerN3
FROM Employes E
LEFT JOIN Employes M1 ON E.ManagerID = M1.EmployeID
LEFT JOIN Employes M2 ON M1.ManagerID = M2.EmployeID
LEFT JOIN Employes M3 ON M2.ManagerID = M3.EmployeID;
```

**Problème** : Si votre hiérarchie a 10 niveaux, vous devez écrire 10 LEFT JOIN !

### Solution : CTE récursives

Pour les hiérarchies de profondeur variable, utilisez des **CTE récursives** (Common Table Expressions) :

```sql
WITH HierarchieEmployes AS (
    -- Ancre : Niveau de départ (employé sans manager)
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    -- Partie récursive : Descendre dans la hiérarchie
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        H.Niveau + 1
    FROM Employes E
    INNER JOIN HierarchieEmployes H ON E.ManagerID = H.EmployeID
)
SELECT
    REPLICATE('  ', Niveau) + NomEmploye AS Hierarchie,
    Niveau
FROM HierarchieEmployes
ORDER BY Niveau, NomEmploye;
```

**Note** : Les CTE récursives sont un sujet avancé qui sera couvert dans la section 4.3.3. Pour l'instant, sachez simplement qu'elles existent pour les hiérarchies complexes.

## Performances des auto-jointures

### Impact sur les performances

Les auto-jointures peuvent être **coûteuses** en termes de performance car :
- Elles scannent la même table plusieurs fois
- Elles génèrent potentiellement beaucoup de combinaisons
- Elles nécessitent des index appropriés

### Optimisations recommandées

#### 1. Indexer les colonnes de jointure

```sql
-- Index sur la colonne ManagerID pour accélérer l'auto-jointure
CREATE INDEX IX_Employes_ManagerID ON Employes(ManagerID);

-- Index sur la clé primaire (déjà existant généralement)
-- EmployeID est automatiquement indexé si c'est la clé primaire
```

#### 2. Limiter les résultats si possible

```sql
-- ✅ Limiter avec WHERE pour réduire le volume
SELECT E.NomEmploye, M.NomEmploye AS Manager
FROM Employes E
INNER JOIN Employes M ON E.ManagerID = M.EmployeID
WHERE E.Departement = 'IT';  -- Filtre pour réduire le nombre de lignes
```

#### 3. Éviter les CROSS JOIN accidentels

```sql
-- ❌ DANGER : Sans condition appropriée, risque de CROSS JOIN
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1, Employes E2;
-- Génère N × N lignes !

-- ✅ Toujours avoir une condition de jointure
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1
INNER JOIN Employes E2 ON E1.ManagerID = E2.EmployeID;
```

#### 4. Utiliser des sous-requêtes ou CTEs pour pré-filtrer

```sql
-- Pré-filtrer avant l'auto-jointure pour de meilleures performances
WITH EmployesActifs AS (
    SELECT * FROM Employes WHERE Actif = 1
)
SELECT
    E.NomEmploye,
    M.NomEmploye AS Manager
FROM EmployesActifs E
LEFT JOIN EmployesActifs M ON E.ManagerID = M.EmployeID;
```

## Erreurs courantes à éviter

### 1. Oublier les alias

```sql
-- ❌ ERREUR : Pas d'alias - SQL Server ne sait pas quelle référence utiliser
SELECT NomEmploye, ManagerID
FROM Employes
INNER JOIN Employes ON ManagerID = EmployeID;
```

**Erreur** : "Ambiguous column name"

**Solution** : Toujours utiliser des alias distincts.

### 2. Confusion dans les alias

```sql
-- ❌ Confusion : Quel alias représente quoi ?
SELECT E.NomEmploye, E.NomEmploye
FROM Employes E
INNER JOIN Employes E ON E.ManagerID = E.EmployeID;
-- Les deux alias s'appellent 'E' !
```

**Solution** : Utilisez des alias significatifs (E pour Employé, M pour Manager).

### 3. Utiliser INNER JOIN alors que LEFT JOIN est nécessaire

```sql
-- ❌ Exclut les employés sans manager
SELECT E.NomEmploye, M.NomEmploye AS Manager
FROM Employes E
INNER JOIN Employes M ON E.ManagerID = M.EmployeID;

-- ✅ Inclut tous les employés
SELECT E.NomEmploye, COALESCE(M.NomEmploye, 'Aucun') AS Manager
FROM Employes E
LEFT JOIN Employes M ON E.ManagerID = M.EmployeID;
```

### 4. Auto-comparaison non filtrée

```sql
-- ❌ Compare chaque employé avec lui-même
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1
CROSS JOIN Employes E2;

-- ✅ Exclut l'auto-comparaison
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1
CROSS JOIN Employes E2
WHERE E1.EmployeID != E2.EmployeID;
```

### 5. Doublons inversés non gérés

```sql
-- ❌ Génère (Alice, Bob) ET (Bob, Alice)
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1
INNER JOIN Employes E2 ON E1.Departement = E2.Departement
WHERE E1.EmployeID != E2.EmployeID;

-- ✅ Ne génère que (Alice, Bob) en éliminant (Bob, Alice)
SELECT E1.NomEmploye, E2.NomEmploye
FROM Employes E1
INNER JOIN Employes E2 ON E1.Departement = E2.Departement
WHERE E1.EmployeID < E2.EmployeID;
```

## Points clés à retenir

1. **Auto-jointure** = Joindre une table avec **elle-même** en utilisant des alias différents.

2. **Les alias sont obligatoires** pour distinguer les différentes références à la même table.

3. **Aucun nouveau type de jointure** : Utilisez INNER JOIN, LEFT JOIN, etc., comme avec des tables différentes.

4. **Cas d'usage principal** : Relations hiérarchiques (employés-managers), comparaisons, relations réflexives.

5. **LEFT JOIN vs INNER JOIN** : Choisissez selon que vous voulez inclure ou non les lignes sans correspondance.

6. **Évitez les auto-comparaisons** : Utilisez `T1.ID != T2.ID` si vous comparez des lignes.

7. **Évitez les doublons inversés** : Utilisez `T1.ID < T2.ID` pour les paires uniques.

8. **Performance** : Indexez les colonnes de jointure et limitez les résultats quand possible.

9. **Hiérarchies profondes** : Considérez les CTE récursives pour les hiérarchies de profondeur variable.

10. **Alias significatifs** : Utilisez des noms d'alias clairs (E pour Employé, M pour Manager, etc.).

---

## Quand utiliser une auto-jointure ?

Utilisez une auto-jointure quand :

- ✅ Vous avez des **relations hiérarchiques** dans une même table (employés-managers)
- ✅ Vous voulez **comparer des lignes** d'une même table entre elles
- ✅ Vous cherchez des **similitudes ou différences** entre enregistrements
- ✅ Vous gérez des **relations réflexives** (amis, collègues, produits similaires)
- ✅ Vous voulez trouver des **séquences ou lignes consécutives**
- ✅ Vous détectez des **doublons ou des enregistrements similaires**

N'utilisez PAS une auto-jointure quand :

- ❌ Les données liées sont dans des tables différentes → Utilisez une jointure classique
- ❌ Une CTE récursive serait plus appropriée (hiérarchies profondes)
- ❌ Une fonction de fenêtrage (LAG, LEAD) pourrait suffire
- ❌ Vous pouvez résoudre le problème avec une simple sous-requête

## Tableau récapitulatif : Types d'auto-jointures

| Scénario | Type de JOIN | Exemple |
|----------|--------------|---------|
| Employés avec leur manager (tous) | LEFT JOIN | Inclut les employés sans manager |
| Employés avec leur manager (seulement ceux qui en ont) | INNER JOIN | Exclut les employés sans manager |
| Comparer chaque ligne avec les autres | CROSS JOIN + WHERE | Produits similaires, détection de doublons |
| Trouver des lignes consécutives | INNER JOIN | Transactions successives d'un client |
| Hiérarchie multi-niveaux | Plusieurs LEFT JOIN | Employé → Manager → Manager du manager |
| Hiérarchie profondeur variable | CTE récursive | Arbre organisationnel complet |

## En résumé

Les **auto-jointures** sont une technique puissante qui vous permet de gérer des relations et des comparaisons au sein d'une même table. C'est simplement l'application des principes de jointure que vous connaissez déjà, mais avec une particularité : la table est jointe à elle-même.

**Points essentiels à retenir** :
- Les alias sont obligatoires et doivent être significatifs
- Ce n'est pas un nouveau type de jointure, mais une application créative des jointures existantes
- Très utile pour les hiérarchies, les comparaisons et les relations réflexives
- Attention aux performances : indexez correctement et filtrez tôt
- Évitez les auto-comparaisons non intentionnelles et les doublons

**Conseil pratique** : Les auto-jointures sont particulièrement courantes dans les applications d'entreprise où les hiérarchies organisationnelles sont modélisées. Maîtriser cette technique vous sera très utile dans votre carrière de développeur SQL !

Avec cette compréhension complète de tous les types de jointures (INNER, LEFT, RIGHT, FULL OUTER, CROSS et Self-Joins), vous avez maintenant une base solide pour combiner des données de manière efficace. La prochaine section vous fera découvrir les sous-requêtes, une autre technique puissante pour manipuler les données !
