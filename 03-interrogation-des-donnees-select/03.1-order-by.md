# 3.3.1 ORDER BY (ASC, DESC)

## Introduction

Lorsque vous interrogez une base de données avec l'instruction `SELECT`, les résultats sont renvoyés dans un ordre qui peut sembler aléatoire ou imprévisible. La clause `ORDER BY` vous permet de **contrôler l'ordre d'affichage** des lignes retournées par votre requête, en les triant selon une ou plusieurs colonnes.

## Syntaxe de base

```sql
SELECT colonnes
FROM table
ORDER BY colonne [ASC | DESC];
```

- **ASC** : Tri par ordre **croissant** (Ascending) - *c'est l'ordre par défaut*
- **DESC** : Tri par ordre **décroissant** (Descending)

## Pourquoi utiliser ORDER BY ?

Imaginez une liste de clients dans votre base de données. Sans tri, les données apparaissent dans l'ordre où elles ont été insérées physiquement dans la table. Pour faciliter la lecture et l'analyse, vous voudrez souvent :

- Trier les noms par ordre alphabétique
- Afficher les montants du plus élevé au plus bas
- Classer les dates de la plus récente à la plus ancienne
- Organiser les résultats de manière logique et cohérente

## Tri simple sur une colonne

### Exemple 1 : Tri croissant (ASC)

Supposons que nous avons une table `Produits` avec les colonnes suivantes : `ProduitID`, `NomProduit`, `Prix`.

```sql
SELECT NomProduit, Prix
FROM Produits
ORDER BY Prix ASC;
```

Cette requête affiche les produits **du moins cher au plus cher**.

**Résultat possible :**
```
NomProduit          Prix
------------------  ------
Stylo               1.50
Cahier              3.00
Calculatrice        15.99
Sac à dos           45.00
```

### Exemple 2 : Tri décroissant (DESC)

```sql
SELECT NomProduit, Prix
FROM Produits
ORDER BY Prix DESC;
```

Cette requête affiche les produits **du plus cher au moins cher**.

**Résultat possible :**
```
NomProduit          Prix
------------------  ------
Sac à dos           45.00
Calculatrice        15.99
Cahier              3.00
Stylo               1.50
```

### Exemple 3 : Tri par défaut

Si vous ne précisez ni `ASC` ni `DESC`, le tri est **croissant par défaut** :

```sql
SELECT NomProduit, Prix
FROM Produits
ORDER BY Prix;  -- Équivalent à ORDER BY Prix ASC
```

## Tri sur plusieurs colonnes

Vous pouvez trier les résultats selon **plusieurs colonnes**. SQL triera d'abord par la première colonne, puis en cas d'égalité, par la deuxième, et ainsi de suite.

### Syntaxe

```sql
SELECT colonnes
FROM table
ORDER BY colonne1 [ASC | DESC], colonne2 [ASC | DESC], ...;
```

### Exemple : Table Employés

Imaginons une table `Employes` avec les colonnes : `EmployeID`, `Nom`, `Prenom`, `Departement`, `Salaire`.

```sql
SELECT Nom, Prenom, Departement, Salaire
FROM Employes
ORDER BY Departement ASC, Salaire DESC;
```

Cette requête :
1. Trie d'abord les employés par **département** (ordre alphabétique croissant)
2. Au sein de chaque département, trie par **salaire** (du plus élevé au plus bas)

**Résultat possible :**
```
Nom         Prenom      Departement     Salaire
----------  ----------  --------------  --------
Dupont      Marie       Comptabilité    55000
Martin      Jean        Comptabilité    48000
Bernard     Sophie      Informatique    65000
Petit       Luc         Informatique    52000
Robert      Anne        Ventes          43000
```

Notez que chaque colonne peut avoir son propre ordre (ASC ou DESC).

## Tri avec des chaînes de caractères

Lorsque vous triez des colonnes contenant du texte (chaînes de caractères), le tri s'effectue selon l'**ordre alphabétique**.

```sql
SELECT NomClient, Ville
FROM Clients
ORDER BY NomClient ASC;
```

**Points importants :**

- Le tri est **sensible à la casse** selon la configuration de votre base de données (collation)
- Les chiffres dans les chaînes sont triés comme des caractères (ex: "10" vient avant "2" alphabétiquement)
- Les caractères spéciaux et accents suivent les règles de la collation configurée

## Tri avec des dates

Le tri sur des colonnes de type date/heure fonctionne de manière chronologique :

```sql
SELECT NumeroCommande, DateCommande, MontantTotal
FROM Commandes
ORDER BY DateCommande DESC;
```

- **DESC** : Les dates les plus **récentes** en premier
- **ASC** : Les dates les plus **anciennes** en premier

**Résultat possible :**
```
NumeroCommande  DateCommande    MontantTotal
--------------  -------------   ------------
1025            2025-11-15      350.00
1024            2025-11-14      120.50
1023            2025-11-10      89.99
```

## Gestion des valeurs NULL

Les valeurs `NULL` (absence de valeur) nécessitent une attention particulière lors du tri :

- Avec `ORDER BY ... ASC` : Les `NULL` apparaissent généralement **en premier** dans SQL Server
- Avec `ORDER BY ... DESC` : Les `NULL` apparaissent généralement **en dernier** dans SQL Server

```sql
SELECT NomProduit, DatePeremption
FROM Produits
ORDER BY DatePeremption ASC;
```

Les produits sans date de péremption (`NULL`) apparaîtront en premier.

## Tri par position de colonne (à éviter)

Il est techniquement possible de référencer les colonnes par leur **position** dans la liste SELECT plutôt que par leur nom :

```sql
SELECT NomProduit, Prix, Stock
FROM Produits
ORDER BY 2 DESC;  -- Trie par la 2ème colonne (Prix)
```

**⚠️ Cette pratique est déconseillée** car :
- Le code devient moins lisible
- Si l'ordre des colonnes change dans le SELECT, le tri change aussi
- Risque d'erreurs lors de la maintenance

**Préférez toujours utiliser les noms de colonnes explicites.**

## Ordre logique d'exécution de la requête

Il est important de comprendre que `ORDER BY` est exécuté **en dernier** dans le traitement d'une requête SQL :

1. **FROM** : Identification de la table source
2. **WHERE** : Filtrage des lignes
3. **GROUP BY** : Regroupement (si applicable)
4. **HAVING** : Filtrage des groupes (si applicable)
5. **SELECT** : Sélection des colonnes
6. **ORDER BY** : Tri des résultats finaux

Cela signifie que vous pouvez utiliser les **alias de colonnes** définis dans le SELECT directement dans la clause ORDER BY :

```sql
SELECT
    NomProduit,
    Prix,
    Prix * 1.20 AS PrixTTC
FROM Produits
ORDER BY PrixTTC DESC;  -- L'alias fonctionne ici !
```

## Combinaison avec d'autres clauses

La clause `ORDER BY` peut être combinée avec toutes les autres clauses SQL que vous avez apprises :

```sql
SELECT
    Categorie,
    NomProduit,
    Prix
FROM Produits
WHERE Prix > 10
ORDER BY Categorie ASC, Prix DESC;
```

Cette requête :
1. Filtre les produits de plus de 10€
2. Les trie par catégorie (A→Z)
3. Puis par prix décroissant au sein de chaque catégorie

## Bonnes pratiques

### ✅ À faire :

- **Toujours utiliser ORDER BY** si l'ordre des résultats est important pour votre application
- **Spécifier explicitement ASC ou DESC** pour la clarté du code, même si ASC est le défaut
- **Utiliser les noms de colonnes** plutôt que les positions numériques
- **Penser à l'impact sur les performances** : le tri peut être coûteux sur de grandes tables

### ❌ À éviter :

- **Compter sur un ordre "par défaut"** sans ORDER BY (l'ordre n'est pas garanti)
- **Utiliser les positions numériques** des colonnes (moins lisible)
- **Oublier le tri** quand vous présentez des données à un utilisateur final
- **Trier inutilement** si l'ordre n'a pas d'importance (économise des ressources)

## Résumé

| Syntaxe | Description | Exemple |
|---------|-------------|---------|
| `ORDER BY colonne` | Tri croissant (par défaut) | `ORDER BY Prix` |
| `ORDER BY colonne ASC` | Tri croissant (explicite) | `ORDER BY Prix ASC` |
| `ORDER BY colonne DESC` | Tri décroissant | `ORDER BY Prix DESC` |
| `ORDER BY col1, col2` | Tri multi-colonnes | `ORDER BY Dept, Salaire DESC` |

## Cas d'usage courants

### Afficher les 5 clients les plus récents

```sql
SELECT TOP 5 NomClient, DateInscription
FROM Clients
ORDER BY DateInscription DESC;
```

### Lister les produits par catégorie et prix

```sql
SELECT Categorie, NomProduit, Prix
FROM Produits
ORDER BY Categorie, Prix;
```

### Afficher un classement de ventes

```sql
SELECT
    VendeurID,
    NomVendeur,
    TotalVentes
FROM Vendeurs
ORDER BY TotalVentes DESC;
```

## Conclusion

La clause `ORDER BY` est un outil fondamental pour organiser vos résultats de requête de manière claire et logique. Bien que simple dans son principe, elle est essentielle pour présenter des données exploitables et compréhensibles. Maîtriser le tri sur une ou plusieurs colonnes, ainsi que la gestion des tris croissants et décroissants, vous permettra de structurer efficacement vos résultats SQL.

N'oubliez pas : **sans ORDER BY, l'ordre des résultats n'est jamais garanti** !
