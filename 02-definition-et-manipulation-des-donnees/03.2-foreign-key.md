# 2.3.2 FOREIGN KEY (Clé étrangère) - Intégrité référentielle

## Introduction

Imaginez une bibliothèque où chaque livre emprunté est enregistré avec le nom de l'emprunteur écrit à la main. Que se passe-t-il si quelqu'un écrit mal le nom ? Ou si un lecteur change de nom ? C'est le chaos !

La solution : au lieu d'écrire le nom complet, on écrit simplement le **numéro de carte du lecteur**. Ce numéro **pointe vers** la fiche complète du lecteur. C'est exactement le principe d'une **clé étrangère** (FOREIGN KEY).

Une **clé étrangère** est une colonne (ou un ensemble de colonnes) dans une table qui **fait référence** à la clé primaire d'une autre table. Elle crée un **lien** entre deux tables et garantit l'**intégrité référentielle**.

## Qu'est-ce qu'une Clé Étrangère ?

### Définition Simple

Une clé étrangère est une colonne qui contient des valeurs **correspondant** à la clé primaire d'une autre table.

**Analogie :**
- Un livre emprunté a un `NumeroCarteLecteur` qui pointe vers la table `Lecteurs`
- Une commande a un `IdClient` qui pointe vers la table `Clients`
- Un employé a un `IdDepartement` qui pointe vers la table `Departements`

### Exemple Visuel

**Table Clients (Table Parent/Référencée)**
```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100),
    Email VARCHAR(100)
);
```

| IdClient | Nom | Email |
|----------|-----|-------|
| 1 | Dupont | dupont@email.com |
| 2 | Martin | martin@email.com |
| 3 | Bernard | bernard@email.com |

**Table Commandes (Table Enfant/Référençante)**
```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,  -- Clé étrangère vers Clients
    DateCommande DATE,
    MontantTotal DECIMAL(10,2),
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
```

| IdCommande | IdClient | DateCommande | MontantTotal |
|------------|----------|--------------|--------------|
| 101 | 1 | 2025-01-15 | 150.00 |
| 102 | 2 | 2025-01-16 | 280.50 |
| 103 | 1 | 2025-01-17 | 99.99 |

**Relation :** Chaque commande appartient à un client. Le `IdClient` dans la table `Commandes` **référence** le `IdClient` dans la table `Clients`.

## Qu'est-ce que l'Intégrité Référentielle ?

L'**intégrité référentielle** est une règle qui garantit que les **relations** entre les tables restent **cohérentes**.

### Les Règles de l'Intégrité Référentielle

1. **Vous ne pouvez pas créer une commande pour un client inexistant**
   ```sql
   -- ❌ ERREUR : Le client 999 n'existe pas
   INSERT INTO Commandes (IdCommande, IdClient, DateCommande, MontantTotal)
   VALUES (104, 999, '2025-01-18', 200.00);
   -- Erreur : The INSERT statement conflicted with the FOREIGN KEY constraint
   ```

2. **Vous ne pouvez pas supprimer un client qui a des commandes**
   ```sql
   -- ❌ ERREUR : Le client 1 a des commandes (101 et 103)
   DELETE FROM Clients WHERE IdClient = 1;
   -- Erreur : The DELETE statement conflicted with the REFERENCE constraint
   ```

3. **Vous ne pouvez pas modifier l'ID d'un client qui a des commandes**
   ```sql
   -- ❌ ERREUR : Le client 1 est référencé par des commandes
   UPDATE Clients SET IdClient = 10 WHERE IdClient = 1;
   -- Erreur : The UPDATE statement conflicted with the REFERENCE constraint
   ```

### Pourquoi c'est Important ?

Sans intégrité référentielle, votre base de données peut devenir **incohérente** :

```sql
-- ❌ SANS clé étrangère : Problème !
-- Quelqu'un supprime accidentellement un client
DELETE FROM Clients WHERE IdClient = 1;

-- Maintenant, les commandes 101 et 103 pointent vers un client inexistant !
SELECT * FROM Commandes WHERE IdClient = 1;
-- Ces commandes sont "orphelines" - le client n'existe plus !
```

```sql
-- ✅ AVEC clé étrangère : Protection !
DELETE FROM Clients WHERE IdClient = 1;
-- Erreur : impossible, le client a des commandes
-- La cohérence est préservée !
```

## Comment Créer une Clé Étrangère ?

Il existe plusieurs méthodes pour définir une clé étrangère.

### Méthode 1 : Lors de la Création de la Table (Recommandé)

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    MontantTotal DECIMAL(10,2),
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
```

**Explication :**
- `FK_Commandes_Clients` : nom de la contrainte (convention : FK_TableEnfant_TableParent)
- `FOREIGN KEY (IdClient)` : la colonne dans la table actuelle
- `REFERENCES Clients(IdClient)` : la table et la colonne référencées

### Méthode 2 : Après la Création de la Table

```sql
-- D'abord créer la table
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    MontantTotal DECIMAL(10,2)
);

-- Ensuite ajouter la clé étrangère
ALTER TABLE Commandes
ADD CONSTRAINT FK_Commandes_Clients
    FOREIGN KEY (IdClient) REFERENCES Clients(IdClient);
```

### Méthode 3 : Syntaxe Simplifiée (Sans Nom de Contrainte)

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT FOREIGN KEY REFERENCES Clients(IdClient),
    DateCommande DATE,
    MontantTotal DECIMAL(10,2)
);
```

**⚠️ Note :** Cette syntaxe est plus courte mais ne donne pas de nom explicite à la contrainte, ce qui complique la gestion.

### Convention de Nommage

**Format recommandé :** `FK_TableEnfant_TableParent` ou `FK_TableEnfant_TableParent_Colonne`

Exemples :
- `FK_Commandes_Clients`
- `FK_Employes_Departements`
- `FK_LignesCommande_Produits`
- `FK_Articles_Auteurs_IdAuteur` (si plusieurs FK vers la même table)

## Ordre de Création des Tables

**Important :** Vous devez créer les tables dans le bon ordre !

### Règle Générale

**Créez d'abord les tables "parent" (référencées), puis les tables "enfant" (référençantes).**

```sql
-- ✅ BON ORDRE

-- 1. Tables parent (sans dépendances)
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(100)
);

-- 2. Tables enfant (avec clés étrangères)
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);

CREATE TABLE LignesCommande
(
    IdLigne INT PRIMARY KEY,
    IdCommande INT,
    IdProduit INT,
    CONSTRAINT FK_Lignes_Commandes FOREIGN KEY (IdCommande) REFERENCES Commandes(IdCommande),
    CONSTRAINT FK_Lignes_Produits FOREIGN KEY (IdProduit) REFERENCES Produits(IdProduit)
);
```

```sql
-- ❌ MAUVAIS ORDRE

-- Erreur : Impossible de créer une FK vers une table qui n'existe pas encore
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
    -- Erreur : La table 'Clients' n'existe pas !
);

CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);
```

## Types de Relations entre Tables

Les clés étrangères permettent de modéliser différents types de relations.

### 1. Relation Un-à-Plusieurs (1-N)

**La relation la plus courante.** Un enregistrement dans la table parent peut être référencé par plusieurs enregistrements dans la table enfant.

**Exemple : Un client peut avoir plusieurs commandes**

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
```

**Schéma :**
```
Clients (1) ────< Commandes (N)
  IdClient          IdClient (FK)
```

**Données exemple :**

Clients :
| IdClient | Nom |
|----------|-----|
| 1 | Dupont |
| 2 | Martin |

Commandes :
| IdCommande | IdClient | DateCommande |
|------------|----------|--------------|
| 101 | 1 | 2025-01-15 |
| 102 | 1 | 2025-01-16 |
| 103 | 2 | 2025-01-17 |

Le client 1 (Dupont) a **deux** commandes (101 et 102).

### 2. Relation Plusieurs-à-Plusieurs (N-N)

Cette relation nécessite une **table de liaison** (aussi appelée table d'association ou table de jonction).

**Exemple : Un étudiant peut suivre plusieurs cours, et un cours peut avoir plusieurs étudiants**

```sql
-- Table parent 1
CREATE TABLE Etudiants
(
    IdEtudiant INT PRIMARY KEY,
    Nom VARCHAR(100)
);

-- Table parent 2
CREATE TABLE Cours
(
    IdCours INT PRIMARY KEY,
    NomCours VARCHAR(100)
);

-- Table de liaison (N-N)
CREATE TABLE Inscriptions
(
    IdEtudiant INT,
    IdCours INT,
    DateInscription DATE,
    CONSTRAINT PK_Inscriptions PRIMARY KEY (IdEtudiant, IdCours),
    CONSTRAINT FK_Inscriptions_Etudiants FOREIGN KEY (IdEtudiant) REFERENCES Etudiants(IdEtudiant),
    CONSTRAINT FK_Inscriptions_Cours FOREIGN KEY (IdCours) REFERENCES Cours(IdCours)
);
```

**Schéma :**
```
Etudiants (N) ────< Inscriptions >──── Cours (N)
  IdEtudiant           IdEtudiant (FK)     IdCours
                       IdCours (FK)
```

**Données exemple :**

Etudiants :
| IdEtudiant | Nom |
|------------|-----|
| 1 | Alice |
| 2 | Bob |

Cours :
| IdCours | NomCours |
|---------|----------|
| 101 | Mathématiques |
| 102 | Physique |

Inscriptions :
| IdEtudiant | IdCours | DateInscription |
|------------|---------|-----------------|
| 1 | 101 | 2025-01-10 |
| 1 | 102 | 2025-01-10 |
| 2 | 101 | 2025-01-11 |

Alice suit Mathématiques et Physique. Bob suit Mathématiques.

### 3. Relation Un-à-Un (1-1)

**Moins courante.** Un enregistrement dans une table correspond à exactement un enregistrement dans une autre table.

**Exemple : Un employé a un seul badge, et un badge appartient à un seul employé**

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100)
);

CREATE TABLE Badges
(
    NumeroBadge INT PRIMARY KEY,
    IdEmploye INT UNIQUE,  -- UNIQUE garantit la relation 1-1
    DateEmission DATE,
    CONSTRAINT FK_Badges_Employes FOREIGN KEY (IdEmploye) REFERENCES Employes(IdEmploye)
);
```

**Note :** La colonne `IdEmploye` dans `Badges` doit être à la fois une **clé étrangère** ET **UNIQUE** pour garantir la relation 1-1.

**Quand l'utiliser :**
- Pour séparer des informations rarement utilisées
- Pour des raisons de sécurité (informations sensibles dans une table séparée)
- Pour des extensions optionnelles

**Alternative :** Dans la plupart des cas, on peut simplement ajouter les colonnes directement dans la table principale.

## Actions Référentielles (CASCADE)

Que se passe-t-il quand vous supprimez ou modifiez un enregistrement parent qui est référencé ? Les **actions référentielles** définissent ce comportement.

### Les Options Disponibles

| Option | Description | Utilisation |
|--------|-------------|-------------|
| **NO ACTION** (défaut) | Empêche la suppression/modification | Protection stricte |
| **CASCADE** | Supprime/modifie automatiquement les enfants | Synchronisation automatique |
| **SET NULL** | Met NULL dans la colonne FK des enfants | Référence optionnelle |
| **SET DEFAULT** | Met une valeur par défaut dans la FK | Référence par défaut |

### ON DELETE CASCADE

Supprime **automatiquement** les enregistrements enfants quand le parent est supprimé.

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON DELETE CASCADE
);
```

**Comportement :**

```sql
-- Données initiales
Clients: IdClient = 1 (Dupont)
Commandes: IdCommande = 101, IdClient = 1
           IdCommande = 102, IdClient = 1

-- Suppression du client
DELETE FROM Clients WHERE IdClient = 1;

-- Résultat : Le client ET ses deux commandes sont supprimés automatiquement
```

**⚠️ Attention :** Utilisez CASCADE avec précaution ! La suppression se propage en chaîne et peut supprimer beaucoup de données.

### ON UPDATE CASCADE

Met à jour **automatiquement** les clés étrangères quand la clé primaire parent change.

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON UPDATE CASCADE
);
```

**Comportement :**

```sql
-- Modification de l'ID du client
UPDATE Clients SET IdClient = 100 WHERE IdClient = 1;

-- Résultat : Toutes les commandes avec IdClient = 1 sont automatiquement mises à jour à IdClient = 100
```

**Note :** Dans la pratique, on évite généralement de modifier les clés primaires, donc `ON UPDATE CASCADE` est moins utilisé.

### ON DELETE SET NULL

Met la clé étrangère à **NULL** quand le parent est supprimé.

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT NULL,  -- Doit autoriser NULL
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON DELETE SET NULL
);
```

**Comportement :**

```sql
-- Suppression du client
DELETE FROM Clients WHERE IdClient = 1;

-- Résultat : Les commandes existent toujours, mais IdClient = NULL
-- (commandes "orphelines" mais conservées)
```

**Quand l'utiliser :** Quand vous voulez conserver l'historique même si le parent n'existe plus.

### ON DELETE SET DEFAULT

Met la clé étrangère à sa **valeur par défaut** quand le parent est supprimé.

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT DEFAULT 0,  -- Client "inconnu"
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON DELETE SET DEFAULT
);
```

**Note :** Nécessite qu'un enregistrement avec cette valeur par défaut existe dans la table parent.

### Exemple Complet avec Actions

```sql
-- Table parent
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

-- Table enfant avec différentes actions
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON DELETE CASCADE      -- Supprime les commandes si le client est supprimé
        ON UPDATE CASCADE      -- Met à jour IdClient si celui du client change
);

CREATE TABLE LignesCommande
(
    IdLigne INT PRIMARY KEY,
    IdCommande INT,
    IdProduit INT,
    Quantite INT,
    CONSTRAINT FK_Lignes_Commandes
        FOREIGN KEY (IdCommande) REFERENCES Commandes(IdCommande)
        ON DELETE CASCADE      -- Supprime les lignes si la commande est supprimée
);
```

**Cascade en chaîne :**
```
Suppression d'un Client
    ↓ (ON DELETE CASCADE)
Supprime toutes ses Commandes
    ↓ (ON DELETE CASCADE)
Supprime toutes les LignesCommande de ces commandes
```

## Clés Étrangères Multiples

Une table peut avoir plusieurs clés étrangères vers différentes tables.

### Exemple : Table LignesCommande

```sql
CREATE TABLE LignesCommande
(
    IdLigne INT PRIMARY KEY,
    IdCommande INT,
    IdProduit INT,
    Quantite INT,
    PrixUnitaire DECIMAL(10,2),
    -- Deux clés étrangères
    CONSTRAINT FK_Lignes_Commandes
        FOREIGN KEY (IdCommande) REFERENCES Commandes(IdCommande),
    CONSTRAINT FK_Lignes_Produits
        FOREIGN KEY (IdProduit) REFERENCES Produits(IdProduit)
);
```

**Schéma :**
```
Commandes ────< LignesCommande >──── Produits
  IdCommande      IdCommande (FK)      IdProduit
                  IdProduit (FK)
```

### Clés Étrangères Auto-Référencées

Une table peut avoir une clé étrangère vers **elle-même** (auto-référence).

**Exemple : Structure hiérarchique d'employés (manager/subordonné)**

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100),
    IdManager INT,  -- Référence un autre employé
    CONSTRAINT FK_Employes_Manager
        FOREIGN KEY (IdManager) REFERENCES Employes(IdEmploye)
);
```

**Données exemple :**

| IdEmploye | Nom | IdManager |
|-----------|-----|-----------|
| 1 | Directeur | NULL |
| 2 | Manager A | 1 |
| 3 | Manager B | 1 |
| 4 | Employé X | 2 |
| 5 | Employé Y | 2 |

Le Directeur (1) n'a pas de manager (NULL). Les managers A et B reportent au Directeur. Les employés X et Y reportent au Manager A.

## Valeurs NULL dans les Clés Étrangères

Par défaut, une clé étrangère **peut être NULL**, ce qui signifie "aucune référence".

### FK avec NULL Autorisé (Défaut)

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT NULL,  -- Peut être NULL
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);

-- ✅ OK : Commande sans client (commande anonyme)
INSERT INTO Commandes (IdCommande, IdClient, DateCommande)
VALUES (101, NULL, '2025-01-15');
```

### FK Obligatoire (NOT NULL)

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT NOT NULL,  -- Obligatoire
    DateCommande DATE,
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);

-- ❌ ERREUR : IdClient ne peut pas être NULL
INSERT INTO Commandes (IdCommande, IdClient, DateCommande)
VALUES (101, NULL, '2025-01-15');
```

**Recommandation :** Utilisez `NOT NULL` quand la relation est obligatoire (une commande DOIT avoir un client), et autorisez `NULL` quand elle est optionnelle.

### Exemple 1 : Système de Blog

```sql

CREATE TABLE Auteurs
(
    IdAuteur INT IDENTITY(1,1) PRIMARY KEY,

    Email VARCHAR(150) UNIQUE
);

-- Table Categories
CREATE TABLE Categories
(
    IdCategorie INT IDENTITY(1,1) PRIMARY KEY,
    NomCategorie VARCHAR(50) NOT NULL UNIQUE
);

-- Table Articles avec deux clés étrangères
CREATE TABLE Articles
(
    IdArticle INT IDENTITY(1,1) PRIMARY KEY,
    Titre VARCHAR(200) NOT NULL,
    Contenu TEXT,

    DatePublication DATETIME2 DEFAULT GETDATE(),
    CONSTRAINT FK_Articles_Auteurs

        ON DELETE SET NULL  -- Si la catégorie est supprimée, l'article reste

```

### Exemple 2 : Système de Gestion de Commandes

```sql
-- 1. Tables parent
CREATE TABLE Clients
(
    IdClient INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(100) NOT NULL,
    Email VARCHAR(150) UNIQUE
);

CREATE TABLE Produits
(
    IdProduit INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(150) NOT NULL,
    Prix DECIMAL(10,2) NOT NULL,
    Stock INT DEFAULT 0
);

-- 2. Table intermédiaire
CREATE TABLE Commandes
(
    IdCommande INT IDENTITY(1,1) PRIMARY KEY,
    IdClient INT NOT NULL,
    DateCommande DATETIME2 DEFAULT GETDATE(),
    Statut VARCHAR(20) DEFAULT 'En attente',
    CONSTRAINT FK_Commandes_Clients
        FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
        ON DELETE NO ACTION  -- On ne peut pas supprimer un client avec des commandes
);

-- 3. Table de détails (N-N entre Commandes et Produits)
CREATE TABLE LignesCommande
(
    IdLigne INT IDENTITY(1,1) PRIMARY KEY,
    IdCommande INT NOT NULL,
    IdProduit INT NOT NULL,
    Quantite INT NOT NULL CHECK (Quantite > 0),
    PrixUnitaire DECIMAL(10,2) NOT NULL,
    CONSTRAINT FK_Lignes_Commandes
        FOREIGN KEY (IdCommande) REFERENCES Commandes(IdCommande)
        ON DELETE CASCADE,  -- Si la commande est supprimée, ses lignes aussi
    CONSTRAINT FK_Lignes_Produits
        FOREIGN KEY (IdProduit) REFERENCES Produits(IdProduit)
        ON DELETE NO ACTION  -- On ne peut pas supprimer un produit commandé
);

-- Insertions
INSERT INTO Clients (Nom, Email) VALUES ('Dupont', 'dupont@email.com');
INSERT INTO Produits (Nom, Prix, Stock) VALUES ('Ordinateur', 899.99, 10);
INSERT INTO Produits (Nom, Prix, Stock) VALUES ('Souris', 29.99, 50);

-- Créer une commande
INSERT INTO Commandes (IdClient) VALUES (1);

-- Ajouter des produits à la commande
INSERT INTO LignesCommande (IdCommande, IdProduit, Quantite, PrixUnitaire)
VALUES (1, 1, 1, 899.99);

INSERT INTO LignesCommande (IdCommande, IdProduit, Quantite, PrixUnitaire)
VALUES (1, 2, 2, 29.99);
```

## Supprimer une Clé Étrangère

Pour supprimer une contrainte de clé étrangère :

```sql
-- Supprimer par le nom
ALTER TABLE Commandes
DROP CONSTRAINT FK_Commandes_Clients;

-- Trouver le nom des contraintes FK
SELECT
    fk.name AS NomContrainte,
    OBJECT_NAME(fk.parent_object_id) AS TableEnfant,
    OBJECT_NAME(fk.referenced_object_id) AS TableParent
FROM sys.foreign_keys fk
WHERE OBJECT_NAME(fk.parent_object_id) = 'Commandes';
```

## Vérifier les Clés Étrangères

### Voir toutes les FK d'une table

```sql
-- Méthode 1 : Via INFORMATION_SCHEMA
SELECT
    fk.CONSTRAINT_NAME,
    fk.TABLE_NAME AS TableEnfant,
    cu.COLUMN_NAME AS ColonneEnfant,
    pk.TABLE_NAME AS TableParent,
    pt.COLUMN_NAME AS ColonneParent
FROM INFORMATION_SCHEMA.REFERENTIAL_CONSTRAINTS fk
INNER JOIN INFORMATION_SCHEMA.CONSTRAINT_COLUMN_USAGE cu
    ON fk.CONSTRAINT_NAME = cu.CONSTRAINT_NAME
INNER JOIN INFORMATION_SCHEMA.CONSTRAINT_COLUMN_USAGE pt
    ON fk.UNIQUE_CONSTRAINT_NAME = pt.CONSTRAINT_NAME
INNER JOIN INFORMATION_SCHEMA.TABLE_CONSTRAINTS pk
    ON fk.UNIQUE_CONSTRAINT_NAME = pk.CONSTRAINT_NAME
WHERE fk.TABLE_NAME = 'Commandes';

-- Méthode 2 : Via sp_help
EXEC sp_help 'Commandes';
```

### Désactiver temporairement les contraintes

Parfois utile pour des opérations de maintenance :

```sql
-- Désactiver une contrainte spécifique
ALTER TABLE Commandes
NOCHECK CONSTRAINT FK_Commandes_Clients;

-- Faire vos opérations...

-- Réactiver la contrainte
ALTER TABLE Commandes
CHECK CONSTRAINT FK_Commandes_Clients;

-- Désactiver toutes les contraintes d'une table
ALTER TABLE Commandes
NOCHECK CONSTRAINT ALL;
```

**⚠️ Attention :** Désactiver les contraintes peut créer des incohérences. À utiliser avec précaution et uniquement temporairement.

## Erreurs Courantes et Solutions

### Erreur 1 : Référence à un Enregistrement Inexistant

```sql
INSERT INTO Commandes (IdCommande, IdClient, DateCommande)
VALUES (101, 999, '2025-01-15');
-- Erreur : The INSERT statement conflicted with the FOREIGN KEY constraint
```

**Solution :** Vérifiez que le client existe d'abord :
```sql
-- Vérifier
SELECT * FROM Clients WHERE IdClient = 999;

-- Si n'existe pas, créer d'abord le client
INSERT INTO Clients (IdClient, Nom) VALUES (999, 'Nouveau Client');

-- Puis créer la commande
INSERT INTO Commandes (IdCommande, IdClient, DateCommande)
VALUES (101, 999, '2025-01-15');
```

### Erreur 2 : Impossible de Supprimer un Parent Référencé

```sql
DELETE FROM Clients WHERE IdClient = 1;
-- Erreur : The DELETE statement conflicted with the REFERENCE constraint
```

**Solutions :**

Option 1 : Supprimer d'abord les enfants
```sql
DELETE FROM Commandes WHERE IdClient = 1;
DELETE FROM Clients WHERE IdClient = 1;
```

Option 2 : Utiliser CASCADE (si défini)
```sql
-- Si ON DELETE CASCADE est défini, la suppression se propage
DELETE FROM Clients WHERE IdClient = 1;
```

Option 3 : Mettre à jour les enfants
```sql
-- Réassigner les commandes à un autre client
UPDATE Commandes SET IdClient = 2 WHERE IdClient = 1;
DELETE FROM Clients WHERE IdClient = 1;
```

### Erreur 3 : Table Parent N'existe Pas

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
-- Erreur : Could not create constraint... 'Clients' does not exist
```

**Solution :** Créez d'abord la table parent :
```sql
-- D'abord la table parent
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

-- Ensuite la table enfant
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
```

### Erreur 4 : Types de Données Incompatibles

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient BIGINT,  -- Type différent !
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
-- Erreur : types incompatibles
```

**Solution :** Les types doivent correspondre exactement :
```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,  -- Même type que dans Clients
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);
```

## Bonnes Pratiques

### 1. Toujours Nommer Vos Contraintes

```sql
-- ✅ BON : Contrainte nommée
CONSTRAINT FK_Commandes_Clients
    FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)

-- ❌ À éviter : Contrainte anonyme
FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
```

### 2. Suivre une Convention de Nommage

- `FK_TableEnfant_TableParent`
- `FK_Commandes_Clients`
- `FK_LignesCommande_Produits`

### 3. Définir les Actions Référentielles Appropriées

```sql
-- Pour les données critiques : NO ACTION (défaut)
CONSTRAINT FK_Commandes_Clients
    FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
    ON DELETE NO ACTION

-- Pour les données dépendantes : CASCADE
CONSTRAINT FK_LignesCommande_Commandes
    FOREIGN KEY (IdCommande) REFERENCES Commandes(IdCommande)
    ON DELETE CASCADE

-- Pour l'historique : SET NULL
CONSTRAINT FK_Articles_Categories
    FOREIGN KEY (IdCategorie) REFERENCES Categories(IdCategorie)
    ON DELETE SET NULL
```

### 4. Documenter les Relations Complexes

```sql
-- Table de liaison entre Étudiants et Cours
-- Permet la relation N-N : un étudiant peut suivre plusieurs cours
-- et un cours peut avoir plusieurs étudiants
CREATE TABLE Inscriptions
(
    IdEtudiant INT,
    IdCours INT,
    DateInscription DATE,
    CONSTRAINT PK_Inscriptions PRIMARY KEY (IdEtudiant, IdCours),
    CONSTRAINT FK_Inscriptions_Etudiants
        FOREIGN KEY (IdEtudiant) REFERENCES Etudiants(IdEtudiant)
        ON DELETE CASCADE,
    CONSTRAINT FK_Inscriptions_Cours
        FOREIGN KEY (IdCours) REFERENCES Cours(IdCours)
        ON DELETE CASCADE
);
```

### 5. Utiliser NOT NULL Quand la Relation est Obligatoire

```sql
-- Relation obligatoire
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT NOT NULL,  -- Une commande DOIT avoir un client
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);

-- Relation optionnelle
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    IdManager INT NULL,  -- Un employé PEUT ne pas avoir de manager
    CONSTRAINT FK_Employes_Manager FOREIGN KEY (IdManager) REFERENCES Employes(IdEmploye)
);
```

### 6. Créer des Index sur les Clés Étrangères

Bien que la clé primaire ait automatiquement un index, les clés étrangères n'en ont pas automatiquement :

```sql
-- Créer un index sur la clé étrangère pour améliorer les performances
CREATE INDEX IX_Commandes_IdClient ON Commandes(IdClient);
CREATE INDEX IX_LignesCommande_IdProduit ON LignesCommande(IdProduit);
```

**Performance :** Les index sur les FK améliorent les jointures et les vérifications d'intégrité.

## Résumé

| Concept | Description |
|---------|-------------|
| **Clé étrangère** | Colonne qui référence la clé primaire d'une autre table |
| **Intégrité référentielle** | Garantit la cohérence des relations entre tables |
| **Table parent** | Table référencée (contient la PK) |
| **Table enfant** | Table référençante (contient la FK) |
| **1-N** | Relation un-à-plusieurs (la plus courante) |
| **N-N** | Relation plusieurs-à-plusieurs (nécessite une table de liaison) |
| **CASCADE** | Propage les suppressions/modifications |
| **SET NULL** | Met NULL si le parent est supprimé |
| **NO ACTION** | Empêche la suppression/modification (défaut) |

## Points Clés à Retenir

1. ✅ Les clés étrangères **créent des relations** entre tables
2. ✅ Elles **garantissent l'intégrité référentielle** (cohérence des données)
3. ✅ Créez toujours les tables **parent avant enfant**
4. ✅ Nommez vos contraintes : `FK_TableEnfant_TableParent`
5. ✅ Choisissez l'action référentielle appropriée (CASCADE, NO ACTION, SET NULL)
6. ✅ Utilisez `NOT NULL` pour les relations obligatoires
7. ⚠️ Attention avec CASCADE : la suppression se propage !
8. ✅ Créez des **index** sur les colonnes FK pour les performances

Les clés étrangères sont essentielles pour créer des bases de données relationnelles robustes et cohérentes ! 🎯
