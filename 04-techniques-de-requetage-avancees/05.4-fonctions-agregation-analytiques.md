# 4.5.4 Fonctions d'agrégation analytiques (SUM() OVER(...), AVG() OVER(...))

## Introduction aux fonctions d'agrégation analytiques

Les **fonctions d'agrégation analytiques** sont les fonctions d'agrégation classiques (SUM, AVG, COUNT, MIN, MAX) utilisées avec la clause `OVER()`. Elles permettent de calculer des agrégations **tout en conservant les détails de chaque ligne**, ce qui ouvre la porte à des analyses très puissantes :

- Totaux cumulatifs (running totals)
- Moyennes mobiles (moving averages)
- Comparaisons à des agrégats
- Calculs de pourcentages du total

## Rappel : Agrégation classique vs analytique

### Agrégation classique avec GROUP BY

```sql
SELECT
    Departement,
    SUM(Salaire) AS TotalSalaires
FROM Employes
GROUP BY Departement;
```

**Résultat** : Une ligne par département (perte des détails individuels)

| Departement | TotalSalaires |
|-------------|---------------|
| IT | 180000 |
| RH | 92000 |
| Ventes | 155000 |

### Agrégation analytique avec OVER()

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    SUM(Salaire) OVER(PARTITION BY Departement) AS TotalDept
FROM Employes;
```

**Résultat** : Une ligne par employé (conservation des détails)

| Nom | Departement | Salaire | TotalDept |
|-----|-------------|---------|-----------|
| Dupont | IT | 65000 | 180000 |
| Martin | IT | 60000 | 180000 |
| Bernard | IT | 55000 | 180000 |
| Durand | RH | 47000 | 92000 |
| Leroy | RH | 45000 | 92000 |

**Chaque employé voit le total de son département !**

## Les fonctions d'agrégation disponibles

Toutes les fonctions d'agrégation classiques peuvent être utilisées avec `OVER()` :

| Fonction | Description |
|----------|-------------|
| **SUM()** | Somme des valeurs |
| **AVG()** | Moyenne des valeurs |
| **COUNT()** | Nombre de lignes |
| **MIN()** | Valeur minimale |
| **MAX()** | Valeur maximale |

## 1. SUM() OVER() - Totaux et cumuls

### A. Total global

```sql
SELECT
    Produit,
    Ventes,
    SUM(Ventes) OVER() AS TotalGlobal,
    CAST(Ventes * 100.0 / SUM(Ventes) OVER() AS DECIMAL(5,2)) AS PourcentageTotal
FROM VentesProduits;
```

**Données :**

| Produit | Ventes |
|---------|--------|
| Laptop | 50000 |
| Souris | 5000 |
| Clavier | 10000 |
| Écran | 35000 |

**Résultat :**

| Produit | Ventes | TotalGlobal | PourcentageTotal |
|---------|--------|-------------|------------------|
| Laptop | 50000 | 100000 | 50.00 |
| Souris | 5000 | 100000 | 5.00 |
| Clavier | 10000 | 100000 | 10.00 |
| Écran | 35000 | 100000 | 35.00 |

### B. Total par partition (avec PARTITION BY)

```sql
SELECT
    Produit,
    Categorie,
    Ventes,
    SUM(Ventes) OVER(PARTITION BY Categorie) AS TotalCategorie,
    CAST(Ventes * 100.0 / SUM(Ventes) OVER(PARTITION BY Categorie) AS DECIMAL(5,2)) AS PctCategorie
FROM VentesProduits;
```

**Données :**

| Produit | Categorie | Ventes |
|---------|-----------|--------|
| Laptop | Informatique | 50000 |
| Tablette | Informatique | 30000 |
| Souris | Accessoires | 5000 |
| Clavier | Accessoires | 10000 |

**Résultat :**

| Produit | Categorie | Ventes | TotalCategorie | PctCategorie |
|---------|-----------|--------|----------------|--------------|
| Laptop | Informatique | 50000 | 80000 | 62.50 |
| Tablette | Informatique | 30000 | 80000 | 37.50 |
| Souris | Accessoires | 5000 | 15000 | 33.33 |
| Clavier | Accessoires | 10000 | 15000 | 66.67 |

### C. Total cumulatif (Running Total)

**Concept clé** : Avec `ORDER BY` dans le `OVER()`, vous créez un **total cumulatif** !

```sql
SELECT
    Mois,
    Ventes,
    SUM(Ventes) OVER(ORDER BY Mois) AS VentesCumulatives
FROM VentesMensuelles;
```

**Données :**

| Mois | Ventes |
|------|--------|
| Janvier | 10000 |
| Février | 15000 |
| Mars | 12000 |
| Avril | 18000 |

**Résultat :**

| Mois | Ventes | VentesCumulatives |
|------|--------|-------------------|
| Janvier | 10000 | 10000 |
| Février | 15000 | 25000 |
| Mars | 12000 | 37000 |
| Avril | 18000 | 55000 |

**Explication ligne par ligne** :
- **Janvier** : 10000 (première valeur)
- **Février** : 10000 + 15000 = 25000
- **Mars** : 25000 + 12000 = 37000
- **Avril** : 37000 + 18000 = 55000

### D. Total cumulatif par groupe

```sql
SELECT
    Vendeur,
    Mois,
    Ventes,
    SUM(Ventes) OVER(PARTITION BY Vendeur ORDER BY Mois) AS CumulVendeur
FROM VentesVendeurs;
```

**Données :**

| Vendeur | Mois | Ventes |
|---------|------|--------|
| Martin | Jan | 5000 |
| Martin | Fév | 7000 |
| Martin | Mar | 6000 |
| Durand | Jan | 4000 |
| Durand | Fév | 5000 |
| Durand | Mar | 6500 |

**Résultat :**

| Vendeur | Mois | Ventes | CumulVendeur |
|---------|------|--------|--------------|
| Martin | Jan | 5000 | 5000 |
| Martin | Fév | 7000 | 12000 |
| Martin | Mar | 6000 | 18000 |
| Durand | Jan | 4000 | 4000 |
| Durand | Fév | 5000 | 9000 |
| Durand | Mar | 6500 | 15500 |

**Le cumul redémarre pour chaque vendeur !**

## 2. AVG() OVER() - Moyennes et moyennes mobiles

### A. Moyenne globale

```sql
SELECT
    Nom,
    Salaire,
    AVG(Salaire) OVER() AS MoyenneGlobale,
    Salaire - AVG(Salaire) OVER() AS EcartMoyenne
FROM Employes;
```

**Résultat :**

| Nom | Salaire | MoyenneGlobale | EcartMoyenne |
|-----|---------|----------------|--------------|
| Dupont | 65000 | 52000 | +13000 |
| Martin | 55000 | 52000 | +3000 |
| Durand | 45000 | 52000 | -7000 |
| Leroy | 50000 | 52000 | -2000 |

### B. Moyenne par partition

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    AVG(Salaire) OVER(PARTITION BY Departement) AS MoyenneDept,
    CASE
        WHEN Salaire > AVG(Salaire) OVER(PARTITION BY Departement)
        THEN 'Au-dessus'
        ELSE 'En-dessous ou égal'
    END AS Position
FROM Employes;
```

**Résultat :**

| Nom | Departement | Salaire | MoyenneDept | Position |
|-----|-------------|---------|-------------|----------|
| Dupont | IT | 65000 | 60000 | Au-dessus |
| Martin | IT | 55000 | 60000 | En-dessous ou égal |
| Durand | RH | 47000 | 46000 | Au-dessus |
| Leroy | RH | 45000 | 46000 | En-dessous ou égal |

### C. Moyenne mobile (Moving Average)

Une **moyenne mobile** calcule la moyenne des N dernières valeurs. Très utile pour lisser des tendances !

**Moyenne mobile sur 3 mois :**

```sql
SELECT
    Mois,
    Ventes,
    AVG(Ventes) OVER(
        ORDER BY Mois
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS MoyenneMobile3
FROM VentesMensuelles;
```

**Données :**

| Mois | Ventes |
|------|--------|
| Jan | 10000 |
| Fév | 15000 |
| Mar | 12000 |
| Avr | 18000 |
| Mai | 14000 |

**Résultat :**

| Mois | Ventes | MoyenneMobile3 |
|------|--------|----------------|
| Jan | 10000 | 10000 |
| Fév | 15000 | 12500 |
| Mar | 12000 | 12333 |
| Avr | 18000 | 15000 |
| Mai | 14000 | 14667 |

**Explication** :
- **Jan** : Moyenne de [10000] = 10000
- **Fév** : Moyenne de [10000, 15000] = 12500
- **Mar** : Moyenne de [10000, 15000, 12000] = 12333
- **Avr** : Moyenne de [15000, 12000, 18000] = 15000
- **Mai** : Moyenne de [12000, 18000, 14000] = 14667

### D. Moyenne mobile centrée

```sql
SELECT
    Mois,
    Ventes,
    AVG(Ventes) OVER(
        ORDER BY Mois
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS MoyenneCentree3
FROM VentesMensuelles;
```

Calcule la moyenne du mois précédent, actuel et suivant (utile pour lisser les données).

## 3. COUNT() OVER() - Comptages

### A. Comptage global

```sql
SELECT
    Nom,
    Departement,
    COUNT(*) OVER() AS TotalEmployes
FROM Employes;
```

Chaque ligne affiche le nombre total d'employés.

### B. Comptage par partition

```sql
SELECT
    Nom,
    Departement,
    Salaire,
    COUNT(*) OVER(PARTITION BY Departement) AS NbEmployesDept,
    CAST(Salaire * 1.0 / COUNT(*) OVER(PARTITION BY Departement) AS DECIMAL(10,2)) AS SalaireParTete
FROM Employes;
```

### C. Comptage cumulatif

```sql
SELECT
    DateInscription,
    NomClient,
    COUNT(*) OVER(ORDER BY DateInscription) AS NombreClientsCumul
FROM Clients;
```

**Résultat :**

| DateInscription | NomClient | NombreClientsCumul |
|----------------|-----------|-------------------|
| 2024-01-05 | Dupont | 1 |
| 2024-01-12 | Martin | 2 |
| 2024-01-20 | Durand | 3 |
| 2024-02-03 | Leroy | 4 |

Utile pour suivre la croissance du nombre de clients dans le temps.

## 4. MIN() et MAX() OVER() - Valeurs extrêmes

### A. Valeurs globales

```sql
SELECT
    Produit,
    Prix,
    MIN(Prix) OVER() AS PrixMin,
    MAX(Prix) OVER() AS PrixMax,
    Prix - MIN(Prix) OVER() AS EcartMinimum
FROM Produits;
```

**Résultat :**

| Produit | Prix | PrixMin | PrixMax | EcartMinimum |
|---------|------|---------|---------|--------------|
| Laptop | 800 | 10 | 800 | 790 |
| Souris | 10 | 10 | 800 | 0 |
| Clavier | 50 | 10 | 800 | 40 |
| Écran | 300 | 10 | 800 | 290 |

### B. Valeurs par partition

```sql
SELECT
    Produit,
    Categorie,
    Prix,
    MIN(Prix) OVER(PARTITION BY Categorie) AS PrixMinCategorie,
    MAX(Prix) OVER(PARTITION BY Categorie) AS PrixMaxCategorie
FROM Produits;
```

Chaque produit voit le prix minimum et maximum de sa catégorie.

### C. Maximum cumulatif (Record historique)

```sql
SELECT
    Date,
    Temperature,
    MAX(Temperature) OVER(ORDER BY Date) AS RecordHistorique
FROM Meteo;
```

**Résultat :**

| Date | Temperature | RecordHistorique |
|------|-------------|------------------|
| 2024-01-01 | 5 | 5 |
| 2024-01-02 | 7 | 7 |
| 2024-01-03 | 6 | 7 |
| 2024-01-04 | 10 | 10 |
| 2024-01-05 | 8 | 10 |

Le **record** est mis à jour uniquement quand une température plus élevée est atteinte.

## 5. Cadres de fenêtre (Window Frames)

Jusqu'à présent, nous avons vu :
- `OVER()` vide : Toutes les lignes
- `OVER(PARTITION BY ...)` : Toutes les lignes de la partition
- `OVER(ORDER BY ...)` : Du début jusqu'à la ligne courante (par défaut)

Mais vous pouvez définir **précisément** quelles lignes inclure avec **ROWS** ou **RANGE**.

### Syntaxe des cadres de fenêtre

```sql
fonction() OVER(
    [PARTITION BY ...]
    ORDER BY ...
    {ROWS | RANGE} BETWEEN debut AND fin
)
```

### Options de délimitation

| Expression | Signification |
|------------|---------------|
| **UNBOUNDED PRECEDING** | Depuis le début de la partition |
| **N PRECEDING** | N lignes avant la ligne courante |
| **CURRENT ROW** | La ligne courante |
| **N FOLLOWING** | N lignes après la ligne courante |
| **UNBOUNDED FOLLOWING** | Jusqu'à la fin de la partition |

### A. ROWS : Cadre physique

`ROWS` compte les **lignes physiques**.

```sql
-- Somme des 3 dernières lignes (ligne courante + 2 précédentes)
SUM(Ventes) OVER(
    ORDER BY Date
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
)
```

### B. RANGE : Cadre logique

`RANGE` regroupe les lignes ayant la **même valeur** dans ORDER BY.

```sql
-- Somme de toutes les lignes avec la même date ou avant
SUM(Ventes) OVER(
    ORDER BY Date
    RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

### Différence ROWS vs RANGE

**Données avec dates en double :**

| ID | Date | Ventes |
|----|------|--------|
| 1 | 2024-01-01 | 100 |
| 2 | 2024-01-01 | 150 |
| 3 | 2024-01-02 | 200 |

```sql
SELECT
    ID,
    Date,
    Ventes,
    SUM(Ventes) OVER(ORDER BY Date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS CumulRows,
    SUM(Ventes) OVER(ORDER BY Date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS CumulRange
FROM Ventes;
```

**Résultat :**

| ID | Date | Ventes | CumulRows | CumulRange |
|----|------|--------|-----------|------------|
| 1 | 2024-01-01 | 100 | 100 | 250 |
| 2 | 2024-01-01 | 150 | 250 | 250 |
| 3 | 2024-01-02 | 200 | 450 | 450 |

**Explication** :
- **CumulRows** : Compte ligne par ligne (100, puis 100+150, puis 100+150+200)
- **CumulRange** : Groupe les lignes avec la même date (lignes 1 et 2 voient toutes deux 250)

### C. Exemples pratiques de cadres

**1. Total des 7 derniers jours (semaine glissante)**

```sql
SELECT
    Date,
    Ventes,
    SUM(Ventes) OVER(
        ORDER BY Date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS VentesSemaine
FROM VentesQuotidiennes;
```

**2. Moyenne des 5 dernières valeurs (moyenne mobile)**

```sql
SELECT
    Date,
    CoursAction,
    AVG(CoursAction) OVER(
        ORDER BY Date
        ROWS BETWEEN 4 PRECEDING AND CURRENT ROW
    ) AS Moyenne5Jours
FROM Bourse;
```

**3. Total depuis le début jusqu'à maintenant**

```sql
SELECT
    Mois,
    Ventes,
    SUM(Ventes) OVER(
        ORDER BY Mois
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS CumulDepuisDebut
FROM VentesMensuelles;
```

**4. Total de toute la période (équivalent à OVER() vide)**

```sql
SELECT
    Mois,
    Ventes,
    SUM(Ventes) OVER(
        ORDER BY Mois
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS TotalComplet
FROM VentesMensuelles;
```

## Cas pratiques avancés

### 1. Analyse de tendance avec pourcentages

```sql
SELECT
    Mois,
    Ventes,
    SUM(Ventes) OVER(ORDER BY Mois) AS VentesCumulatives,
    CAST(Ventes * 100.0 / SUM(Ventes) OVER() AS DECIMAL(5,2)) AS PctTotal,
    CAST(
        SUM(Ventes) OVER(ORDER BY Mois) * 100.0 /
        SUM(Ventes) OVER()
    AS DECIMAL(5,2)) AS PctCumulatif
FROM VentesMensuelles;
```

**Résultat :**

| Mois | Ventes | VentesCumulatives | PctTotal | PctCumulatif |
|------|--------|-------------------|----------|--------------|
| Jan | 10000 | 10000 | 18.18 | 18.18 |
| Fév | 15000 | 25000 | 27.27 | 45.45 |
| Mar | 12000 | 37000 | 21.82 | 67.27 |
| Avr | 18000 | 55000 | 32.73 | 100.00 |

### 2. Comparaison avec la période précédente

```sql
SELECT
    Annee,
    Trimestre,
    Ventes,
    AVG(Ventes) OVER(
        PARTITION BY Trimestre
        ORDER BY Annee
        ROWS BETWEEN 1 PRECEDING AND 1 PRECEDING
    ) AS VentesAnneePrecedente,
    Ventes - AVG(Ventes) OVER(
        PARTITION BY Trimestre
        ORDER BY Annee
        ROWS BETWEEN 1 PRECEDING AND 1 PRECEDING
    ) AS Variation
FROM VentesTrimestrielles;
```

Compare chaque trimestre avec le même trimestre de l'année précédente.

### 3. Détection d'anomalies (écart-type)

```sql
SELECT
    Date,
    Valeur,
    AVG(Valeur) OVER(
        ORDER BY Date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS MoyenneMobile7j,
    STDEV(Valeur) OVER(
        ORDER BY Date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS EcartType7j,
    CASE
        WHEN ABS(Valeur - AVG(Valeur) OVER(
            ORDER BY Date
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        )) > 2 * STDEV(Valeur) OVER(
            ORDER BY Date
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        )
        THEN 'ANOMALIE'
        ELSE 'Normal'
    END AS Statut
FROM Mesures;
```

Identifie les valeurs qui s'écartent de plus de 2 écarts-types de la moyenne mobile.

### 4. Analyse de contribution

```sql
SELECT
    Vendeur,
    Region,
    Ventes,
    SUM(Ventes) OVER(PARTITION BY Region) AS TotalRegion,
    SUM(Ventes) OVER() AS TotalGlobal,
    CAST(Ventes * 100.0 / SUM(Ventes) OVER(PARTITION BY Region) AS DECIMAL(5,2)) AS PctRegion,
    CAST(Ventes * 100.0 / SUM(Ventes) OVER() AS DECIMAL(5,2)) AS PctGlobal
FROM VentesVendeurs;
```

Montre la contribution de chaque vendeur à sa région ET au total global.

### 5. Classement par rapport à la moyenne

```sql
SELECT
    Etudiant,
    Note,
    AVG(Note) OVER() AS MoyenneClasse,
    CASE
        WHEN Note >= AVG(Note) OVER() + 10 THEN 'Excellent'
        WHEN Note >= AVG(Note) OVER() THEN 'Au-dessus de la moyenne'
        WHEN Note >= AVG(Note) OVER() - 10 THEN 'En-dessous de la moyenne'
        ELSE 'En difficulté'
    END AS Appreciation
FROM Notes;
```

## Comportement par défaut de ORDER BY

Quand vous utilisez `ORDER BY` sans spécifier de cadre explicite :

```sql
SUM(Ventes) OVER(ORDER BY Date)
```

Le cadre par défaut est :
```sql
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

C'est pourquoi vous obtenez un **total cumulatif** !

### Équivalences

```sql
-- Ces trois requêtes sont IDENTIQUES :
SUM(Ventes) OVER(ORDER BY Date)

SUM(Ventes) OVER(ORDER BY Date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

SUM(Ventes) OVER(ORDER BY Date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
-- (si Date est unique pour chaque ligne)
```

## Combinaison de plusieurs agrégations

Vous pouvez combiner plusieurs fonctions dans la même requête :

```sql
SELECT
    Produit,
    Mois,
    Ventes,

    -- Cumuls
    SUM(Ventes) OVER(PARTITION BY Produit ORDER BY Mois) AS VentesCumul,

    -- Moyennes mobiles
    AVG(Ventes) OVER(
        PARTITION BY Produit
        ORDER BY Mois
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS MoyenneMobile3,

    -- Comparaisons
    Ventes - AVG(Ventes) OVER(PARTITION BY Produit) AS EcartMoyenne,

    -- Pourcentages
    CAST(Ventes * 100.0 / SUM(Ventes) OVER(PARTITION BY Produit) AS DECIMAL(5,2)) AS PctTotalProduit

FROM VentesMensuelles;
```

Cette requête fournit une **analyse complète** en une seule passe !

## Performance et bonnes pratiques

### 1. Index pour les performances

Les agrégations analytiques bénéficient d'index sur :
- Les colonnes dans **PARTITION BY**
- Les colonnes dans **ORDER BY**

```sql
-- Cette requête bénéficiera d'un index sur (Categorie, Date)
CREATE INDEX IX_Ventes_Categorie_Date ON Ventes(Categorie, Date);

SELECT
    SUM(Montant) OVER(PARTITION BY Categorie ORDER BY Date)
FROM Ventes;
```

### 2. Éviter les calculs redondants

**Mauvais** : Calculer la même agrégation plusieurs fois

```sql
SELECT
    Ventes,
    AVG(Ventes) OVER(),
    Ventes - AVG(Ventes) OVER(),
    Ventes / AVG(Ventes) OVER()
FROM VentesMensuelles;
```

**Meilleur** : Utiliser un CTE

```sql
WITH VentesAvecMoyenne AS (
    SELECT
        Ventes,
        AVG(Ventes) OVER() AS Moyenne
    FROM VentesMensuelles
)
SELECT
    Ventes,
    Moyenne,
    Ventes - Moyenne AS Ecart,
    Ventes / Moyenne AS Ratio
FROM VentesAvecMoyenne;
```

### 3. Cadres de fenêtre et performance

- `ROWS` est généralement **plus rapide** que `RANGE`
- Les cadres larges (ex: `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`) peuvent consommer beaucoup de mémoire
- Limitez la taille des cadres aux besoins réels

### 4. NULL dans les agrégations

Les fonctions d'agrégation **ignorent les NULL** :

```sql
-- Si certaines valeurs sont NULL, elles sont exclues du calcul
AVG(Salaire) OVER() -- Moyenne seulement des salaires non-NULL
```

Pour inclure les NULL comme zéros :

```sql
AVG(ISNULL(Salaire, 0)) OVER()
```

## Limitations et pièges courants

### 1. Impossible d'utiliser dans WHERE

```sql
-- ❌ ERREUR
SELECT *
FROM Ventes
WHERE SUM(Montant) OVER(PARTITION BY Client) > 10000;
```

**Solution** : Utiliser un CTE

```sql
-- ✅ CORRECT
WITH VentesClient AS (
    SELECT
        *,
        SUM(Montant) OVER(PARTITION BY Client) AS TotalClient
    FROM Ventes
)
SELECT *
FROM VentesClient
WHERE TotalClient > 10000;
```

### 2. ORDER BY obligatoire pour certains cadres

```sql
-- ❌ ERREUR : ROWS nécessite ORDER BY
SUM(Ventes) OVER(ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
```

```sql
-- ✅ CORRECT
SUM(Ventes) OVER(ORDER BY Date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
```

### 3. Attention aux types de données

```sql
-- ❌ Division entière (résultat tronqué)
Ventes / SUM(Ventes) OVER()

-- ✅ Division décimale
Ventes * 1.0 / SUM(Ventes) OVER()
-- ou
CAST(Ventes AS DECIMAL(10,2)) / SUM(Ventes) OVER()
```

## Tableau récapitulatif

| Fonction | Sans ORDER BY | Avec ORDER BY | Avec ROWS/RANGE |
|----------|---------------|---------------|-----------------|
| **SUM()** | Total de la partition | Cumul jusqu'à la ligne | Cumul dans le cadre |
| **AVG()** | Moyenne de la partition | Moyenne cumulative | Moyenne mobile |
| **COUNT()** | Comptage partition | Comptage cumulatif | Comptage dans le cadre |
| **MIN()** | Min de la partition | Min cumulatif | Min dans le cadre |
| **MAX()** | Max de la partition | Max cumulatif | Max dans le cadre |

## Résumé

Les fonctions d'agrégation analytiques avec `OVER()` permettent :

**Points clés** :
- **Conserver les détails** tout en calculant des agrégations
- **Créer des totaux cumulatifs** avec `ORDER BY`
- **Calculer des moyennes mobiles** avec des cadres de fenêtre
- **Comparer chaque ligne** à des valeurs agrégées
- **Éviter les sous-requêtes** corrélées complexes

**Syntaxe générale** :
```sql
fonction_agregation(colonne) OVER(
    [PARTITION BY colonne1, ...]
    [ORDER BY colonne2, ...]
    [ROWS | RANGE BETWEEN ... AND ...]
)
```

**Cas d'usage principaux** :
- Analyses financières (cumuls, tendances)
- Calculs de pourcentages du total
- Moyennes mobiles pour lisser les données
- Comparaisons individuelles vs agrégats
- Détection d'anomalies

Les fonctions d'agrégation analytiques sont parmi les outils les plus puissants de T-SQL pour l'analyse de données. Elles permettent des calculs complexes qui nécessiteraient autrement des jointures multiples ou des sous-requêtes coûteuses !
