# 3.1.1 SELECT (Choix des colonnes) et FROM (Source des données)

## Introduction

La requête `SELECT` est la commande la plus fondamentale et la plus utilisée en SQL. Elle permet de **lire** et **afficher** des données stockées dans une base de données. Si vous ne deviez apprendre qu'une seule instruction SQL, ce serait celle-ci !

Imaginez une base de données comme une bibliothèque remplie de livres (les tables), et la commande `SELECT` comme votre demande au bibliothécaire : "Je voudrais consulter tel livre, et voir telles informations précises".

---

## Structure de base

Toute requête de consultation de données commence par ces deux éléments essentiels :

```sql
SELECT colonnes
FROM table
```

- **SELECT** : indique **quelles colonnes** (informations) vous souhaitez voir
- **FROM** : indique **de quelle table** (source de données) proviennent ces informations

---

## La clause FROM : Choisir la source des données

### Qu'est-ce qu'une table ?

Une table est une structure qui organise les données sous forme de **lignes** et de **colonnes**, similaire à un tableau Excel :

- Chaque **ligne** (ou enregistrement) représente une entité complète (par exemple, un client, un produit, une commande)
- Chaque **colonne** représente un attribut ou une caractéristique de cette entité (nom, prénom, prix, date, etc.)

### Syntaxe de FROM

La clause `FROM` est obligatoire dans presque toutes les requêtes `SELECT`. Elle indique au système de gestion de base de données où aller chercher les informations.

```sql
FROM nom_de_la_table
```

**Exemple** : Si vous avez une table appelée `Clients`, vous écrirez :

```sql
FROM Clients
```

---

## La clause SELECT : Choisir les colonnes à afficher

### Sélectionner des colonnes spécifiques

Une fois que vous avez indiqué la table (avec `FROM`), vous devez préciser quelles colonnes vous souhaitez consulter avec `SELECT`.

**Syntaxe** :

```sql
SELECT colonne1, colonne2, colonne3
FROM nom_de_la_table
```

**Exemple concret** :

Imaginons une table `Clients` contenant les colonnes suivantes :
- `ClientID`
- `Prenom`
- `Nom`
- `Email`
- `Telephone`
- `DateInscription`

Si vous souhaitez afficher uniquement le prénom et le nom des clients, vous écrirez :

```sql
SELECT Prenom, Nom
FROM Clients
```

**Résultat attendu** :

| Prenom  | Nom      |
|---------|----------|
| Sophie  | Martin   |
| Pierre  | Dubois   |
| Marie   | Leroy    |

---

### Sélectionner une seule colonne

Vous pouvez bien sûr ne sélectionner qu'une seule colonne si c'est tout ce dont vous avez besoin :

```sql
SELECT Email
FROM Clients
```

**Résultat** :

| Email                  |
|------------------------|
| sophie.martin@mail.fr  |
| pierre.dubois@mail.fr  |
| marie.leroy@mail.fr    |

---

### L'ordre des colonnes

L'ordre dans lequel vous listez les colonnes après `SELECT` détermine l'ordre d'affichage dans les résultats.

**Exemple 1** :
```sql
SELECT Nom, Prenom
FROM Clients
```

**Résultat** :

| Nom      | Prenom  |
|----------|---------|
| Martin   | Sophie  |
| Dubois   | Pierre  |
| Leroy    | Marie   |

**Exemple 2** (ordre inversé) :
```sql
SELECT Prenom, Nom
FROM Clients
```

**Résultat** :

| Prenom  | Nom      |
|---------|----------|
| Sophie  | Martin   |
| Pierre  | Dubois   |
| Marie   | Leroy    |

---

## Exemples complets

### Exemple 1 : Table Produits

Supposons une table `Produits` avec ces colonnes :
- `ProduitID`
- `NomProduit`
- `Prix`
- `Stock`
- `Categorie`

**Requête** : Afficher le nom et le prix de tous les produits

```sql
SELECT NomProduit, Prix
FROM Produits
```

---

### Exemple 2 : Table Employes

Supposons une table `Employes` avec ces colonnes :
- `EmployeID`
- `Prenom`
- `Nom`
- `Poste`
- `Salaire`
- `DateEmbauche`

**Requête** : Afficher le prénom, le nom et le poste de tous les employés

```sql
SELECT Prenom, Nom, Poste
FROM Employes
```

## Points importants à retenir

### 1. Les noms de colonnes sont sensibles à la casse (parfois)

Selon la configuration de votre serveur SQL Server, les noms peuvent être sensibles à la casse. Il est recommandé de respecter l'orthographe exacte des noms de colonnes tels qu'ils ont été définis dans la table.

### 2. Espacement et lisibilité

Pour améliorer la lisibilité, il est courant d'écrire les requêtes sur plusieurs lignes :

```sql
SELECT
    Prenom,
    Nom,
    Email
FROM
    Clients
```

Cette présentation est équivalente à :

```sql
SELECT Prenom, Nom, Email FROM Clients
```

SQL ne tient pas compte des retours à la ligne et des espaces supplémentaires (tant que vous ne coupez pas un mot).

### 3. Le point-virgule (;)

En T-SQL (le dialecte SQL de Microsoft SQL Server), le point-virgule en fin de requête est **optionnel** dans la plupart des cas, mais c'est une bonne pratique de l'utiliser :

```sql
SELECT Prenom, Nom
FROM Clients;
```

---

## Schémas (Organisation logique)

Dans certaines bases de données plus complexes, les tables sont organisées en **schémas**. Un schéma est simplement un conteneur logique qui regroupe des tables.

La syntaxe complète devient alors :

```sql
SELECT colonnes
FROM schema.nom_de_la_table
```

**Exemple** : Si vos clients sont dans un schéma appelé `Ventes` :

```sql
SELECT Prenom, Nom
FROM Ventes.Clients
```

Par défaut, si vous ne précisez pas de schéma, SQL Server utilise le schéma `dbo` (database owner).

---

## Résumé

| Élément | Rôle | Obligatoire ? |
|---------|------|---------------|
| `SELECT` | Définit les colonnes à afficher | Oui |
| `FROM` | Indique la table source | Oui (sauf cas très rares) |
| Noms de colonnes | Séparés par des virgules | Oui |
| Point-virgule (;) | Marque la fin de la requête | Recommandé |

---

## Conseil pour les débutants

Lorsque vous débutez avec une nouvelle table, il peut être utile de commencer par voir **toutes** les colonnes disponibles avant de faire votre sélection. Dans la prochaine section (3.1.2), nous verrons comment utiliser `SELECT *` pour afficher toutes les colonnes d'une table.

Pour l'instant, retenez que :
- `SELECT` choisit **QUOI** afficher
- `FROM` indique **OÙ** aller chercher les données

Ces deux clauses forment le socle de toute interrogation de base de données !
