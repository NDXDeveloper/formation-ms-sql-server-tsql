# 5.7.5 Triggers DDL (Niveau serveur ou base de données)

## Introduction : Une autre catégorie de triggers

Jusqu'à présent, nous avons vu les **triggers DML** qui réagissent aux opérations de manipulation de données (INSERT, UPDATE, DELETE). Les **triggers DDL** sont fondamentalement différents :

**Ils réagissent aux changements de structure de la base de données, pas aux modifications de données.**

### DML vs DDL : Rappel

**DML (Data Manipulation Language)** - Manipulation des données :
- INSERT, UPDATE, DELETE
- Modifie le **contenu** des tables
- Exemple : Ajouter un client, modifier un prix

**DDL (Data Definition Language)** - Définition des structures :
- CREATE, ALTER, DROP, RENAME
- Modifie la **structure** de la base de données
- Exemple : Créer une table, ajouter une colonne, supprimer un index

### À quoi servent les triggers DDL ?

Les triggers DDL permettent de :
- 📋 **Auditer** les changements de structure (qui a créé/modifié/supprimé quelle table ?)
- 🛡️ **Empêcher** certaines modifications dangereuses (protection contre la suppression accidentelle)
- 📧 **Notifier** les administrateurs lors de changements importants
- 📊 **Enregistrer l'historique** des modifications de schéma

### Analogie pour comprendre

Imaginez un bâtiment :

**Triggers DML** (données) :
- Surveillent les personnes qui entrent/sortent des bureaux
- "Jean est entré dans le bureau 101"
- "Marie a quitté le bureau 205"

**Triggers DDL** (structure) :
- Surveillent les modifications du bâtiment lui-même
- "Un nouveau mur a été construit au 3e étage"
- "La porte du bureau 101 a été remplacée"
- "Une pièce entière a été supprimée"

## Différences fondamentales avec les triggers DML

| Aspect | Triggers DML | Triggers DDL |
|--------|--------------|--------------|
| **Cible** | Tables (données) | Serveur ou Base de données (structure) |
| **Événements** | INSERT, UPDATE, DELETE | CREATE, ALTER, DROP, etc. |
| **Portée** | Une table spécifique | Toute la base ou tout le serveur |
| **Tables INSERTED/DELETED** | ✅ Oui | ❌ Non |
| **Fonction EVENTDATA()** | ❌ Non | ✅ Oui |
| **Usage principal** | Audit des données, validation | Audit de structure, sécurité |

## Syntaxe de base

### Trigger DDL au niveau BASE DE DONNÉES

```sql
CREATE TRIGGER nom_du_trigger
ON DATABASE  -- Niveau base de données
FOR {événement_DDL | groupe_événements}
AS
BEGIN
    -- Votre code ici
END;
```

### Trigger DDL au niveau SERVEUR

```sql
CREATE TRIGGER nom_du_trigger
ON ALL SERVER  -- Niveau serveur
FOR {événement_DDL | groupe_événements}
AS
BEGIN
    -- Votre code ici
END;
```

### Différence de portée

**Niveau DATABASE** :
- S'applique à **une base de données spécifique**
- Réagit aux DDL dans cette base uniquement
- Exemple : Surveiller les CREATE TABLE dans la base "Ventes"

**Niveau ALL SERVER** :
- S'applique à **tout le serveur SQL Server**
- Réagit aux DDL dans toutes les bases de données
- Exemple : Surveiller toutes les créations de bases de données
- ⚠️ Nécessite des privilèges serveur élevés

## Événements DDL disponibles

### Événements les plus courants

#### Événements sur les tables

```sql
-- Création de table
CREATE_TABLE

-- Modification de table
ALTER_TABLE

-- Suppression de table
DROP_TABLE
```

#### Événements sur les vues

```sql
CREATE_VIEW
ALTER_VIEW
DROP_VIEW
```

#### Événements sur les procédures et fonctions

```sql
CREATE_PROCEDURE
ALTER_PROCEDURE
DROP_PROCEDURE

CREATE_FUNCTION
ALTER_FUNCTION
DROP_FUNCTION
```

#### Événements sur les index

```sql
CREATE_INDEX
ALTER_INDEX
DROP_INDEX
```

#### Événements au niveau base de données

```sql
CREATE_DATABASE
ALTER_DATABASE
DROP_DATABASE
```

### Groupes d'événements

SQL Server permet de surveiller plusieurs événements avec des **groupes** :

```sql
-- Groupe pour TOUTES les opérations sur les tables
DDL_TABLE_EVENTS  -- Inclut CREATE_TABLE, ALTER_TABLE, DROP_TABLE

-- Groupe pour TOUTES les opérations sur les vues
DDL_VIEW_EVENTS

-- Groupe pour TOUTES les opérations DDL dans la base
DDL_DATABASE_LEVEL_EVENTS

-- Groupe pour TOUTES les opérations DDL sur le serveur
DDL_SERVER_LEVEL_EVENTS
```

### Exemple d'utilisation de groupes

```sql
-- Surveille TOUTES les modifications sur les tables
CREATE TRIGGER trg_Audit_All_Table_Changes
ON DATABASE
FOR DDL_TABLE_EVENTS  -- CREATE_TABLE, ALTER_TABLE, DROP_TABLE
AS
BEGIN
    PRINT 'Une table a été modifiée !';
END;
```

## La fonction EVENTDATA()

### Qu'est-ce que EVENTDATA() ?

Dans les triggers DDL, il n'y a pas de tables INSERTED/DELETED. À la place, SQL Server fournit la fonction **EVENTDATA()** qui retourne un document XML contenant toutes les informations sur l'événement qui a déclenché le trigger.

### Structure du XML retourné

```xml
<EVENT_INSTANCE>
  <EventType>CREATE_TABLE</EventType>
  <PostTime>2024-11-18T14:30:00.000</PostTime>
  <SPID>52</SPID>
  <ServerName>MON_SERVEUR</ServerName>
  <LoginName>sa</LoginName>
  <UserName>dbo</UserName>
  <DatabaseName>MaBase</DatabaseName>
  <SchemaName>dbo</SchemaName>
  <ObjectName>Clients</ObjectName>
  <ObjectType>TABLE</ObjectType>
  <TSQLCommand>
    <SetOptions ... />
    <CommandText>CREATE TABLE Clients (...)</CommandText>
  </TSQLCommand>
</EVENT_INSTANCE>
```

### Extraire les informations du XML

```sql
CREATE TRIGGER trg_Audit_DDL
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();

    -- Extraire les informations importantes
    DECLARE @EventType VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)');
    DECLARE @ObjectName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)');
    DECLARE @ObjectType VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/ObjectType)[1]', 'VARCHAR(100)');
    DECLARE @LoginName VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)');
    DECLARE @CommandText VARCHAR(MAX) = @EventData.value('(/EVENT_INSTANCE/TSQLCommand/CommandText)[1]', 'VARCHAR(MAX)');

    -- Afficher les informations (pour l'exemple)
    PRINT 'Événement : ' + @EventType;
    PRINT 'Objet : ' + ISNULL(@ObjectName, 'N/A');
    PRINT 'Par : ' + @LoginName;
END;
```

### Méthode XQuery expliquée

La syntaxe `.value()` permet d'extraire des valeurs du XML :

```sql
-- Syntaxe générale
@EventData.value('(chemin_xpath)[1]', 'type_de_donnees')

-- Exemples
@EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)')
--                ↑ Chemin dans le XML              ↑ Type de retour
--                              ↑ [1] = premier élément trouvé
```

## Cas d'usage 1 : Audit complet des modifications de structure

### Création d'une table d'audit

```sql
-- Table pour stocker l'historique des modifications DDL
CREATE TABLE Audit_DDL (
    AuditID INT IDENTITY(1,1) PRIMARY KEY,
    EventType VARCHAR(100),
    ObjectName VARCHAR(255),
    ObjectType VARCHAR(100),
    DatabaseName VARCHAR(100),
    SchemaName VARCHAR(100),
    LoginName VARCHAR(100),
    HostName VARCHAR(100),
    CommandText VARCHAR(MAX),
    EventDate DATETIME DEFAULT GETDATE()
);
```

### Trigger d'audit complet

```sql
CREATE TRIGGER trg_Audit_DDL_Complete
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();

    -- Insérer dans la table d'audit
    INSERT INTO Audit_DDL (
        EventType,
        ObjectName,
        ObjectType,
        DatabaseName,
        SchemaName,
        LoginName,
        HostName,
        CommandText
    )
    SELECT
        @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)'),
        @EventData.value('(/EVENT_INSTANCE/ObjectType)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/DatabaseName)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/SchemaName)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)'),
        HOST_NAME(),
        @EventData.value('(/EVENT_INSTANCE/TSQLCommand/CommandText)[1]', 'VARCHAR(MAX)');
END;
```

**Résultat** : Chaque fois qu'une table, vue, procédure, etc. est créée, modifiée ou supprimée, une ligne est automatiquement ajoutée dans Audit_DDL !

### Interroger l'historique d'audit

```sql
-- Voir toutes les tables créées dans les 7 derniers jours
SELECT
    EventDate,
    ObjectName,
    LoginName,
    CommandText
FROM Audit_DDL
WHERE EventType = 'CREATE_TABLE'
  AND EventDate >= DATEADD(DAY, -7, GETDATE())
ORDER BY EventDate DESC;

-- Voir qui a supprimé des objets
SELECT
    EventDate,
    EventType,
    ObjectName,
    ObjectType,
    LoginName
FROM Audit_DDL
WHERE EventType LIKE 'DROP_%'
ORDER BY EventDate DESC;
```

## Cas d'usage 2 : Prévention de suppressions accidentelles

### Empêcher la suppression de tables critiques

```sql
CREATE TRIGGER trg_Prevent_Drop_Critical_Tables
ON DATABASE
FOR DROP_TABLE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();
    DECLARE @ObjectName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)');

    -- Liste des tables critiques qu'on ne peut pas supprimer
    IF @ObjectName IN ('Clients', 'Commandes', 'Produits', 'Factures')
    BEGIN
        RAISERROR('Impossible de supprimer la table %s : table critique protégée', 16, 1, @ObjectName);
        ROLLBACK TRANSACTION;
    END
END;
```

**Test** :

```sql
-- Ceci sera autorisé
DROP TABLE TableTemporaire;

-- Ceci sera bloqué par le trigger
DROP TABLE Clients;
-- Erreur : Impossible de supprimer la table Clients : table critique protégée
```

### Protection avec liste d'exceptions

```sql
CREATE TRIGGER trg_Prevent_Drop_Except_Admin
ON DATABASE
FOR DROP_TABLE, DROP_VIEW
AS
BEGIN
    SET NOCOUNT ON;

    -- Autoriser uniquement certains utilisateurs
    IF SYSTEM_USER NOT IN ('sa', 'admin', 'dba')
    BEGIN
        DECLARE @EventData XML = EVENTDATA();
        DECLARE @ObjectName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)');
        DECLARE @ObjectType VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/ObjectType)[1]', 'VARCHAR(100)');

        RAISERROR('Seuls les administrateurs peuvent supprimer des %s. Contactez le DBA.', 16, 1, @ObjectType);
        ROLLBACK TRANSACTION;
    END
END;
```

## Cas d'usage 3 : Notification lors de changements importants

### Envoyer une alerte par email

```sql
CREATE TRIGGER trg_Alert_On_Table_Drop
ON DATABASE
FOR DROP_TABLE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();
    DECLARE @ObjectName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)');
    DECLARE @LoginName VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)');

    -- Construire le message d'alerte
    DECLARE @Subject VARCHAR(255) = 'ALERTE : Table supprimée dans ' + DB_NAME();
    DECLARE @Body VARCHAR(MAX) =
        'Une table a été supprimée !' + CHAR(13) + CHAR(10) +
        'Table : ' + @ObjectName + CHAR(13) + CHAR(10) +
        'Par : ' + @LoginName + CHAR(13) + CHAR(10) +
        'Date : ' + CONVERT(VARCHAR, GETDATE(), 120) + CHAR(13) + CHAR(10) +
        'Serveur : ' + @@SERVERNAME + CHAR(13) + CHAR(10) +
        'Base : ' + DB_NAME();

    -- Envoyer l'email (nécessite la configuration de Database Mail)
    EXEC msdb.dbo.sp_send_dbmail
        @profile_name = 'MonProfil',
        @recipients = 'dba@monentreprise.com',
        @subject = @Subject,
        @body = @Body;
END;
```

### Enregistrer dans une table de log critique

```sql
CREATE TRIGGER trg_Log_Critical_Changes
ON DATABASE
FOR ALTER_TABLE, DROP_TABLE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();

    -- Insérer dans une table de log avec horodatage précis
    INSERT INTO Log_Critical_Changes (
        EventType,
        ObjectName,
        LoginName,
        HostName,
        AppName,
        CommandText,
        EventTime
    )
    SELECT
        @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)'),
        @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)'),
        HOST_NAME(),
        APP_NAME(),
        @EventData.value('(/EVENT_INSTANCE/TSQLCommand/CommandText)[1]', 'VARCHAR(MAX)'),
        GETDATE();

    -- Enregistrer également le XML complet pour analyse détaillée
    INSERT INTO Log_EventData (EventDataXML, EventTime)
    VALUES (@EventData, GETDATE());
END;
```

## Cas d'usage 4 : Conformité et gouvernance

### Forcer des standards de nommage

```sql
CREATE TRIGGER trg_Enforce_Naming_Convention
ON DATABASE
FOR CREATE_TABLE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();
    DECLARE @ObjectName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)');

    -- Vérifier que le nom commence par 'tbl_'
    IF @ObjectName NOT LIKE 'tbl_%'
    BEGIN
        RAISERROR('Les tables doivent commencer par "tbl_". Table rejetée : %s', 16, 1, @ObjectName);
        ROLLBACK TRANSACTION;
    END

    -- Vérifier que le nom ne contient pas d'espaces
    IF @ObjectName LIKE '% %'
    BEGIN
        RAISERROR('Les noms de tables ne doivent pas contenir d''espaces : %s', 16, 1, @ObjectName);
        ROLLBACK TRANSACTION;
    END
END;
```

### Empêcher la création d'objets dans certains schémas

```sql
CREATE TRIGGER trg_Protect_System_Schema
ON DATABASE
FOR CREATE_TABLE, CREATE_VIEW, CREATE_PROCEDURE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();
    DECLARE @SchemaName VARCHAR(100) = @EventData.value('(/EVENT_INSTANCE/SchemaName)[1]', 'VARCHAR(100)');

    -- Empêcher la création d'objets dans le schéma 'sys' ou 'internal'
    IF @SchemaName IN ('sys', 'internal', 'restricted')
    BEGIN
        RAISERROR('Création interdite dans le schéma %s', 16, 1, @SchemaName);
        ROLLBACK TRANSACTION;
    END
END;
```

## Triggers au niveau SERVEUR

### Exemple : Auditer la création de bases de données

```sql
-- Ce trigger doit être créé dans la base master ou avec ON ALL SERVER
USE master;
GO

CREATE TRIGGER trg_Audit_Database_Creation
ON ALL SERVER  -- Niveau serveur !
FOR CREATE_DATABASE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();

    -- Enregistrer dans une table d'audit (dans master ou une base dédiée)
    INSERT INTO master.dbo.Audit_Server_DDL (
        EventType,
        DatabaseName,
        LoginName,
        EventDate,
        EventDataXML
    )
    VALUES (
        @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)'),
        @EventData.value('(/EVENT_INSTANCE/DatabaseName)[1]', 'VARCHAR(255)'),
        @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)'),
        GETDATE(),
        @EventData
    );

    -- Optionnel : Envoyer une notification
    PRINT 'Nouvelle base de données créée : ' +
          @EventData.value('(/EVENT_INSTANCE/DatabaseName)[1]', 'VARCHAR(255)');
END;
GO
```

### Exemple : Empêcher la suppression de bases de données

```sql
CREATE TRIGGER trg_Prevent_Database_Drop
ON ALL SERVER
FOR DROP_DATABASE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @EventData XML = EVENTDATA();
    DECLARE @DatabaseName VARCHAR(255) = @EventData.value('(/EVENT_INSTANCE/DatabaseName)[1]', 'VARCHAR(255)');

    -- Liste des bases de données critiques
    IF @DatabaseName IN ('Production', 'Ventes', 'Comptabilite')
    BEGIN
        RAISERROR('Impossible de supprimer la base de données %s : base de données critique', 16, 1, @DatabaseName);
        ROLLBACK TRANSACTION;
    END

    -- Log de la tentative (même si bloquée)
    INSERT INTO master.dbo.Log_Blocked_Operations (
        OperationType,
        ObjectName,
        LoginName,
        AttemptDate
    )
    VALUES (
        'DROP_DATABASE_BLOCKED',
        @DatabaseName,
        SYSTEM_USER,
        GETDATE()
    );
END;
GO
```

## Gestion des erreurs dans les triggers DDL

### Gestion d'erreur robuste

```sql
CREATE TRIGGER trg_Safe_DDL_Audit
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        DECLARE @EventData XML = EVENTDATA();

        -- Tentative d'insertion dans la table d'audit
        INSERT INTO Audit_DDL (EventType, ObjectName, LoginName, EventDate, EventDataXML)
        SELECT
            @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)'),
            @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)'),
            @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)'),
            GETDATE(),
            @EventData;

    END TRY
    BEGIN CATCH
        -- En cas d'erreur dans le trigger, on ne bloque PAS l'opération DDL
        -- On log juste l'erreur
        INSERT INTO Log_Trigger_Errors (
            TriggerName,
            ErrorMessage,
            ErrorDate
        )
        VALUES (
            'trg_Safe_DDL_Audit',
            ERROR_MESSAGE(),
            GETDATE()
        );

        -- Ne pas faire ROLLBACK ici sauf si c'est intentionnel
        -- Un ROLLBACK bloquerait l'opération DDL
    END CATCH
END;
```

### Importance de la gestion d'erreur

⚠️ **Attention** : Si votre trigger DDL génère une erreur non gérée, **l'opération DDL échoue** !

```sql
-- ❌ Trigger mal écrit
CREATE TRIGGER trg_Bad_Audit
ON DATABASE
FOR CREATE_TABLE
AS
BEGIN
    -- Si cette table n'existe pas, le trigger plante
    INSERT INTO TableAuditQuiNexistePas (...) VALUES (...);
    -- Résultat : Plus PERSONNE ne peut créer de tables dans cette base !
END;
```

**Solution** : Toujours utiliser TRY...CATCH et décider si on veut bloquer ou juste logger l'erreur.

## Limitations et considérations

### Limitation 1 : Pas de tables INSERTED/DELETED

Les triggers DDL n'ont pas accès à INSERTED et DELETED. Utilisez EVENTDATA() à la place.

### Limitation 2 : Pas de trigger INSTEAD OF pour DDL

Il n'existe **pas** de trigger INSTEAD OF pour les événements DDL. Seulement AFTER (implicite, le mot-clé AFTER n'est pas nécessaire).

```sql
-- ✅ VALIDE (AFTER est implicite)
CREATE TRIGGER trg_Example ON DATABASE FOR CREATE_TABLE

-- ✅ VALIDE (AFTER explicite)
CREATE TRIGGER trg_Example ON DATABASE AFTER CREATE_TABLE

-- ❌ INVALIDE
CREATE TRIGGER trg_Example ON DATABASE INSTEAD OF CREATE_TABLE
```

### Limitation 3 : Performance

Les triggers DDL ajoutent une surcharge à chaque opération DDL. Pour les opérations d'audit simples, ce n'est pas un problème. Mais attention aux triggers complexes !

### Limitation 4 : Privilèges requis

- Trigger niveau DATABASE : Nécessite ALTER ANY DATABASE DDL TRIGGER
- Trigger niveau SERVER : Nécessite CONTROL SERVER (privilèges très élevés)

## Gestion et administration

### Voir tous les triggers DDL d'une base de données

```sql
-- Triggers au niveau base de données
SELECT
    name AS TriggerName,
    create_date AS DateCreation,
    modify_date AS DateModification,
    is_disabled AS EstDesactive
FROM sys.triggers
WHERE parent_class = 0;  -- 0 = DATABASE level
```

### Voir tous les triggers DDL au niveau serveur

```sql
-- Doit être exécuté dans master
USE master;
SELECT
    name AS TriggerName,
    create_date AS DateCreation,
    modify_date AS DateModification,
    is_disabled AS EstDesactive
FROM sys.server_triggers;
```

### Désactiver temporairement un trigger DDL

```sql
-- Niveau base de données
DISABLE TRIGGER trg_Audit_DDL ON DATABASE;

-- Niveau serveur
DISABLE TRIGGER trg_Audit_Server ON ALL SERVER;
```

### Réactiver un trigger DDL

```sql
-- Niveau base de données
ENABLE TRIGGER trg_Audit_DDL ON DATABASE;

-- Niveau serveur
ENABLE TRIGGER trg_Audit_Server ON ALL SERVER;
```

### Supprimer un trigger DDL

```sql
-- Niveau base de données
DROP TRIGGER trg_Audit_DDL ON DATABASE;

-- Niveau serveur
DROP TRIGGER trg_Audit_Server ON ALL SERVER;
```

### Voir le code source d'un trigger DDL

```sql
-- Niveau base de données
SELECT
    OBJECT_DEFINITION(OBJECT_ID('trg_Audit_DDL'));

-- Niveau serveur (dans master)
USE master;
SELECT
    OBJECT_DEFINITION(OBJECT_ID('trg_Audit_Server', 'TR'));
```

## Bonnes pratiques

### 1. Utilisez des noms descriptifs

```sql
-- ✅ BON : Nom descriptif
CREATE TRIGGER trg_Audit_Table_Changes ON DATABASE FOR DDL_TABLE_EVENTS

-- ❌ MAUVAIS : Nom vague
CREATE TRIGGER trg1 ON DATABASE FOR DDL_TABLE_EVENTS
```

### 2. Documentez abondamment

```sql
/*
================================================================
TRIGGER DDL: trg_Audit_Production_DDL
NIVEAU: DATABASE
BASE: Production
ÉVÉNEMENTS: DDL_DATABASE_LEVEL_EVENTS

OBJECTIF:
    Audite TOUS les changements de structure dans la base Production
    pour respecter les exigences de conformité SOX.

AUTEUR: Jean Dupont
DATE: 2024-11-18

TABLES UTILISÉES:
    - Audit_DDL (insertion)

ACTIONS:
    1. Capture l'événement DDL avec EVENTDATA()
    2. Extrait les informations pertinentes
    3. Enregistre dans Audit_DDL
    4. Envoie une alerte si DROP_TABLE

MAINTENANCE:
    - Conserver l'historique pendant 7 ans (exigence légale)
    - Vérifier la table Audit_DDL mensuellement

DÉPENDANCES:
    - Table Audit_DDL doit exister
    - Database Mail doit être configuré pour les alertes
================================================================
*/
CREATE TRIGGER trg_Audit_Production_DDL
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS
AS
...
```

### 3. Gérez les erreurs proprement

Toujours utiliser TRY...CATCH pour éviter de bloquer les opérations DDL légitimes en cas d'erreur dans votre trigger.

### 4. Testez minutieusement

```sql
-- Créer un trigger de test dans une base de test d'abord
USE TestDB;
GO

CREATE TRIGGER trg_Test_Audit
ON DATABASE
FOR CREATE_TABLE
AS
BEGIN
    PRINT 'Trigger déclenché';
    -- Votre code ici
END;
GO

-- Tester
CREATE TABLE TestTable (ID INT);
-- Le message 'Trigger déclenché' devrait s'afficher

-- Nettoyer
DROP TABLE TestTable;

```

### 5. Soyez sélectif dans les événements surveillés

```sql
-- ❌ TROP LARGE : Capture TOUT
CREATE TRIGGER trg_Too_Broad
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS  -- Beaucoup trop d'événements !

-- ✅ MIEUX : Capture seulement ce qui est nécessaire
CREATE TRIGGER trg_Focused
ON DATABASE
FOR CREATE_TABLE, ALTER_TABLE, DROP_TABLE  -- Seulement les tables
```

### 6. Considérez l'impact sur les performances

Les triggers DDL s'exécutent dans la transaction de l'opération DDL. Gardez-les rapides !

```sql
-- ✅ BON : Insertion simple et rapide
INSERT INTO Audit_DDL (...) VALUES (...);

-- ❌ MAUVAIS : Opérations longues
WAITFOR DELAY '00:00:10';  -- Ne faites jamais ça !
EXEC LongueOperationExterne;  -- Évitez
```

## Scénarios d'utilisation recommandés

### ✅ Utilisez les triggers DDL pour :

1. **Audit et conformité** - Tracer qui change quoi et quand
2. **Protection de données critiques** - Empêcher la suppression accidentelle
3. **Application de standards** - Forcer des conventions de nommage
4. **Alertes** - Notifier les administrateurs des changements importants
5. **Gouvernance** - Contrôler les modifications de schéma en production

### ❌ N'utilisez PAS les triggers DDL pour :

1. **Logique métier** - Ce n'est pas leur rôle
2. **Opérations longues** - Ralentit les opérations DDL
3. **Modifications complexes** - Risque de bloquer des opérations légitimes
4. **Remplacer les permissions** - Utilisez plutôt les permissions SQL Server appropriées

## Exemple complet : Système d'audit DDL professionnel

### Configuration complète

```sql
-- 1. Table d'audit
CREATE TABLE Audit_DDL_Complete (
    AuditID INT IDENTITY(1,1) PRIMARY KEY,
    EventType VARCHAR(100) NOT NULL,
    EventDate DATETIME DEFAULT GETDATE() NOT NULL,
    DatabaseName VARCHAR(100),
    SchemaName VARCHAR(100),
    ObjectName VARCHAR(255),
    ObjectType VARCHAR(100),
    LoginName VARCHAR(100),
    HostName VARCHAR(100),
    ApplicationName VARCHAR(255),
    CommandText VARCHAR(MAX),
    EventDataXML XML
);

-- 2. Index pour les requêtes fréquentes
CREATE INDEX IX_Audit_DDL_EventDate ON Audit_DDL_Complete(EventDate);
CREATE INDEX IX_Audit_DDL_EventType ON Audit_DDL_Complete(EventType);
CREATE INDEX IX_Audit_DDL_LoginName ON Audit_DDL_Complete(LoginName);

-- 3. Trigger d'audit complet
CREATE TRIGGER trg_Audit_DDL_Professional
ON DATABASE
FOR DDL_DATABASE_LEVEL_EVENTS
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        DECLARE @EventData XML = EVENTDATA();

        INSERT INTO Audit_DDL_Complete (
            EventType,
            DatabaseName,
            SchemaName,
            ObjectName,
            ObjectType,
            LoginName,
            HostName,
            ApplicationName,
            CommandText,
            EventDataXML
        )
        SELECT
            @EventData.value('(/EVENT_INSTANCE/EventType)[1]', 'VARCHAR(100)'),
            @EventData.value('(/EVENT_INSTANCE/DatabaseName)[1]', 'VARCHAR(100)'),
            @EventData.value('(/EVENT_INSTANCE/SchemaName)[1]', 'VARCHAR(100)'),
            @EventData.value('(/EVENT_INSTANCE/ObjectName)[1]', 'VARCHAR(255)'),
            @EventData.value('(/EVENT_INSTANCE/ObjectType)[1]', 'VARCHAR(100)'),
            @EventData.value('(/EVENT_INSTANCE/LoginName)[1]', 'VARCHAR(100)'),
            HOST_NAME(),
            APP_NAME(),
            @EventData.value('(/EVENT_INSTANCE/TSQLCommand/CommandText)[1]', 'VARCHAR(MAX)'),
            @EventData;

    END TRY
    BEGIN CATCH
        -- Log l'erreur sans bloquer l'opération DDL
        INSERT INTO Log_Errors (ErrorMessage, ErrorDate)
        VALUES (ERROR_MESSAGE(), GETDATE());
    END CATCH
END;
GO
```

### Requêtes d'analyse

```sql
-- Qui a fait le plus de modifications ce mois-ci ?
SELECT
    LoginName,
    COUNT(*) AS NombreModifications
FROM Audit_DDL_Complete
WHERE EventDate >= DATEADD(MONTH, -1, GETDATE())
GROUP BY LoginName
ORDER BY NombreModifications DESC;

-- Quelles tables ont été supprimées récemment ?
SELECT
    EventDate,
    ObjectName,
    LoginName,
    CommandText
FROM Audit_DDL_Complete
WHERE EventType = 'DROP_TABLE'
  AND EventDate >= DATEADD(DAY, -7, GETDATE())
ORDER BY EventDate DESC;

-- Historique complet d'une table spécifique
SELECT
    EventDate,
    EventType,
    LoginName,
    CommandText
FROM Audit_DDL_Complete
WHERE ObjectName = 'Clients'
ORDER BY EventDate DESC;
```

## Résumé

### Points clés à retenir

1. **Triggers DDL vs DML** : DDL surveille la structure, pas les données
2. **Deux niveaux** : DATABASE (une base) ou ALL SERVER (tout le serveur)
3. **EVENTDATA()** : Remplace INSERTED/DELETED pour les triggers DDL
4. **Usage principal** : Audit, protection, conformité
5. **Pas de INSTEAD OF** : Seulement AFTER (implicite)
6. **Gestion d'erreur critique** : Une erreur bloque l'opération DDL

### Événements DDL les plus utiles

| Événement | Description | Usage typique |
|-----------|-------------|---------------|
| CREATE_TABLE | Création de table | Audit, standards de nommage |
| ALTER_TABLE | Modification de table | Audit des changements de structure |
| DROP_TABLE | Suppression de table | Protection, alertes |
| DDL_TABLE_EVENTS | Tous les événements table | Audit complet des tables |
| CREATE_DATABASE | Création de base | Audit au niveau serveur |
| DROP_DATABASE | Suppression de base | Protection des bases critiques |

### Règle de décision

```
Avez-vous besoin de surveiller/contrôler des changements de STRUCTURE ?
    ├─ Non → Utilisez des triggers DML
    └─ Oui → Utilisez des triggers DDL
        ├─ Une seule base ? → Trigger ON DATABASE
        └─ Tout le serveur ? → Trigger ON ALL SERVER
```

## Conclusion

Les triggers DDL sont des outils essentiels pour :
- **La gouvernance** de vos bases de données
- **La conformité** réglementaire (audit trail)
- **La protection** contre les erreurs humaines
- **La traçabilité** des changements de structure

Utilisez-les judicieusement pour maintenir l'intégrité et la sécurité de votre environnement SQL Server, tout en documentant qui fait quoi et quand. C'est particulièrement important dans les environnements de production où chaque changement doit être tracé et justifié.

**Conseil final** : Dans un environnement de production, un trigger DDL d'audit devrait être l'un des premiers objets que vous créez dans chaque nouvelle base de données !
