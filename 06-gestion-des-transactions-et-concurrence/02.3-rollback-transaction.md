# 6.2.3 ROLLBACK TRANSACTION

## Introduction

Nous avons découvert `BEGIN TRANSACTION` pour démarrer une transaction et `COMMIT` pour valider les modifications. Maintenant, nous allons explorer l'autre façon de terminer une transaction : **ROLLBACK TRANSACTION**.

`ROLLBACK` est l'opposé de `COMMIT`. Là où COMMIT valide et rend permanentes les modifications, ROLLBACK les **annule complètement** et restaure la base de données à son état initial, comme si la transaction n'avait jamais eu lieu.

C'est votre bouton "Annuler" ou "Ctrl+Z" pour les bases de données !

## Qu'est-ce que ROLLBACK TRANSACTION ?

`ROLLBACK TRANSACTION` (ou simplement `ROLLBACK`) est une commande T-SQL qui **annule** une transaction en supprimant **toutes** les modifications effectuées depuis le `BEGIN TRANSACTION`.

Une fois le ROLLBACK exécuté :
- ❌ Les modifications sont **complètement annulées**
- ⏪ La base de données retourne à son **état initial** (avant BEGIN TRANSACTION)
- ✅ Les **verrous** sont **libérés**
- ✅ La transaction est **terminée**
- 🔢 `@@TRANCOUNT` est remis à **0**

### Analogie : La Gomme Magique

Imaginez que vous écrivez au crayon sur une feuille de papier :

```
Situation 1 : Avec COMMIT (encre permanente)
├─► Vous écrivez au STYLO 🖊️
├─► Une fois écrit, c'est permanent
└─► Impossible d'effacer

Situation 2 : Avec ROLLBACK (crayon + gomme)
├─► Vous écrivez au CRAYON ✏️
├─► Vous pouvez tout EFFACER 🧽
├─► La feuille redevient vierge
└─► Comme si vous n'aviez jamais écrit
```

Le `ROLLBACK` est comme une gomme magique qui efface instantanément tout ce qui a été fait dans la transaction.

### Autre Analogie : Le Jeu Vidéo

```
Point de Sauvegarde (BEGIN TRANSACTION)
    │
    ├─► Action 1 : Combattre un ennemi
    ├─► Action 2 : Ouvrir un coffre
    ├─► Action 3 : Mourir face au boss 💀
    │
    ├─► ROLLBACK = "Charger la sauvegarde"
    │   └─► Retour au point de sauvegarde
    │       Comme si actions 1, 2, 3 n'avaient jamais eu lieu
    │
    └─► COMMIT = "Sauvegarder définitivement"
        └─► Impossible de revenir en arrière
```

## Syntaxe de ROLLBACK TRANSACTION

### Forme Simple (La Plus Courante)

```sql
ROLLBACK TRANSACTION;
-- ou simplement :
ROLLBACK;
-- ou en abrégé :
ROLLBACK TRAN;
```

Ces trois formes sont équivalentes. La forme `ROLLBACK;` est la plus concise et la plus utilisée.

### Forme avec Nom (Optionnel)

```sql
ROLLBACK TRANSACTION nom_transaction;
-- ou :
ROLLBACK TRAN nom_transaction;
```

**Important** : Contrairement au nom dans COMMIT qui est ignoré, le nom dans ROLLBACK n'annule **pas** seulement la transaction nommée. Il annule **TOUTES** les transactions actives et ramène `@@TRANCOUNT` à 0.

### Forme Recommandée

Pour la simplicité et la clarté, utilisez simplement :

```sql
BEGIN TRANSACTION;
    -- Opérations...
ROLLBACK; -- En cas d'erreur
```

## Ce qui Se Passe Lors d'un ROLLBACK

Quand vous exécutez `ROLLBACK TRANSACTION`, SQL Server effectue plusieurs opérations importantes :

### 1. Annulation de Toutes les Modifications

Toutes les modifications effectuées depuis le `BEGIN TRANSACTION` sont **supprimées** :

```
État Avant Transaction     État Après ROLLBACK
┌─────────────────────┐   ┌─────────────────────┐
│ Compte A : 1000€    │   │ Compte A : 1000€    │
│ Compte B : 500€     │   │ Compte B : 500€     │
└─────────────────────┘   └─────────────────────┘
         │                         ▲
         │                         │
         ▼                         │
BEGIN TRANSACTION                  │
         │                         │
         ▼                         │
┌─────────────────────┐            │
│ Compte A : 500€  ❌ │            │
│ Compte B : 1000€ ❌ │            │
└─────────────────────┘            │
    Modifications                  │
    temporaires                    │
         │                         │
         ▼                         │
    ROLLBACK ──────────────────────┘

    Tout est annulé ⏪
    Retour à l'état initial ✓
```

### 2. Libération Immédiate des Verrous

Tout comme COMMIT, ROLLBACK libère tous les verrous instantanément :

```
Pendant la Transaction :
┌──────────────────────┐
│ Transaction A        │──► 🔒 Verrous actifs
│ (modifications)      │
└──────────────────────┘
         │
         │ Autres utilisateurs : ⏳ EN ATTENTE
         │
         ▼
      ROLLBACK
         │
         ▼
┌──────────────────────┐
│ Verrous libérés      │──► ✅ Ressources disponibles
│ Modifications        │
│ annulées             │
└──────────────────────┘
         │
         │ Autres utilisateurs : ✓ PEUVENT ACCÉDER
```

### 3. Restauration à Partir du Journal

SQL Server lit le **journal des transactions** en sens inverse pour annuler chaque opération :

```
Journal de Transactions :
┌────────────────────────────────┐
│ T1 : INSERT Client (ID=100)    │ ──► Annulé : DELETE Client (ID=100)
│ T2 : UPDATE Compte SET Solde.. │ ──► Annulé : Restaure ancienne valeur
│ T3 : DELETE Produit (ID=50)    │ ──► Annulé : Réinsère Produit (ID=50)
└────────────────────────────────┘

ROLLBACK lit le journal en SENS INVERSE
et effectue l'opération OPPOSÉE pour chaque ligne
```

### 4. Remise à Zéro de @@TRANCOUNT

**Différence importante avec COMMIT :**
- `COMMIT` décrémente `@@TRANCOUNT` de 1
- `ROLLBACK` met `@@TRANCOUNT` à **0** (peu importe le niveau d'imbrication)

```sql
SELECT @@TRANCOUNT; -- 0

BEGIN TRANSACTION; -- Niveau 1
SELECT @@TRANCOUNT; -- 1

    BEGIN TRANSACTION; -- Niveau 2 (imbriquée)
    SELECT @@TRANCOUNT; -- 2

    ROLLBACK; -- ⚠️ Annule TOUT
    SELECT @@TRANCOUNT; -- 0 (pas 1 !)

-- Toutes les transactions sont annulées
```

## Exemples Détaillés

### Exemple 1 : ROLLBACK Simple en Cas d'Erreur

Voici l'utilisation la plus basique de ROLLBACK :

```sql
BEGIN TRANSACTION;

    -- Débiter un compte
    UPDATE Comptes
    SET Solde = Solde - 500
    WHERE NumeroCompte = 'A123';

    -- Vérifier que le compte existe
    IF @@ROWCOUNT = 0
    BEGIN
        -- Le compte n'existe pas, annuler
        ROLLBACK;
        PRINT '✗ Erreur : Compte inexistant. Transaction annulée.';
        RETURN; -- Sortir du script
    END

    -- Créditer un autre compte
    UPDATE Comptes
    SET Solde = Solde + 500
    WHERE NumeroCompte = 'B456';

    -- Vérifier le succès
    IF @@ROWCOUNT = 0
    BEGIN
        -- Le compte destinataire n'existe pas, annuler
        ROLLBACK;
        PRINT '✗ Erreur : Compte destinataire inexistant. Transaction annulée.';
        RETURN;
    END

    -- Tout est OK, valider
    COMMIT;
    PRINT '✓ Transfert effectué avec succès !';
```

**Ce qui se passe :**
- Si un des comptes n'existe pas → ROLLBACK
- Aucune modification n'est appliquée
- La base reste dans son état initial

### Exemple 2 : ROLLBACK Automatique avec TRY...CATCH

La méthode la plus professionnelle et robuste :

```sql
BEGIN TRANSACTION;

BEGIN TRY
    -- Opération 1 : Créer une commande
    INSERT INTO Commandes (ClientID, DateCommande, Statut)
    VALUES (999, GETDATE(), 'En cours'); -- Supposons que ClientID 999 n'existe pas

    -- Opération 2 : Cette ligne ne s'exécutera jamais car la précédente échoue
    INSERT INTO LignesCommande (CommandeID, ProduitID, Quantite)
    VALUES (1, 123, 5);

    -- Si tout réussit, valider
    COMMIT;
    PRINT '✓ Commande créée avec succès !';

END TRY
BEGIN CATCH
    -- En cas d'erreur, annuler automatiquement
    ROLLBACK;

    PRINT '✗ Une erreur s''est produite :';
    PRINT '   Code : ' + CAST(ERROR_NUMBER() AS VARCHAR);
    PRINT '   Message : ' + ERROR_MESSAGE();
    PRINT '   Ligne : ' + CAST(ERROR_LINE() AS VARCHAR);
    PRINT '   Transaction annulée.';
END CATCH;
```

**Avantages :**
- ✅ Gestion automatique des erreurs
- ✅ ROLLBACK garanti en cas de problème
- ✅ Informations détaillées sur l'erreur
- ✅ Code propre et lisible

### Exemple 3 : ROLLBACK Conditionnel (Validation Métier)

Parfois, vous devez annuler selon des règles métier spécifiques :

```sql
BEGIN TRANSACTION;

BEGIN TRY
    DECLARE @StockActuel INT;
    DECLARE @QuantiteDemandee INT = 100;
    DECLARE @ProduitID INT = 456;

    -- Mettre à jour le stock
    UPDATE Produits
    SET StockDisponible = StockDisponible - @QuantiteDemandee
    WHERE ProduitID = @ProduitID;

    -- Vérifier le stock résultant
    SELECT @StockActuel = StockDisponible
    FROM Produits
    WHERE ProduitID = @ProduitID;

    -- Règle métier : le stock ne peut jamais être négatif
    IF @StockActuel < 0
    BEGIN
        ROLLBACK;
        PRINT '✗ Stock insuffisant !';
        PRINT '   Stock actuel : ' + CAST(@StockActuel + @QuantiteDemandee AS VARCHAR);
        PRINT '   Quantité demandée : ' + CAST(@QuantiteDemandee AS VARCHAR);
        PRINT '   Transaction annulée.';
        RETURN;
    END

    -- Le stock est OK, créer la commande
    INSERT INTO Commandes (ProduitID, Quantite, DateCommande)
    VALUES (@ProduitID, @QuantiteDemandee, GETDATE());

    COMMIT;
    PRINT '✓ Commande validée. Nouveau stock : ' + CAST(@StockActuel AS VARCHAR);

END TRY
BEGIN CATCH
    ROLLBACK;
    PRINT '✗ Erreur technique : ' + ERROR_MESSAGE();
END CATCH;
```

### Exemple 4 : ROLLBACK Après Plusieurs Opérations

Démonstration de l'annulation de multiples opérations :

```sql
-- Afficher l'état initial
PRINT '=== ÉTAT INITIAL ===';
SELECT * FROM Produits WHERE ProduitID IN (1, 2, 3);

BEGIN TRANSACTION;

    PRINT '=== DÉBUT DE LA TRANSACTION ===';

    -- Opération 1
    UPDATE Produits SET Prix = Prix * 1.5 WHERE ProduitID = 1;
    PRINT 'Opération 1 : Prix du produit 1 augmenté de 50%';

    -- Opération 2
    UPDATE Produits SET StockDisponible = 0 WHERE ProduitID = 2;
    PRINT 'Opération 2 : Stock du produit 2 mis à zéro';

    -- Opération 3
    DELETE FROM Produits WHERE ProduitID = 3;
    PRINT 'Opération 3 : Produit 3 supprimé';

    -- Afficher l'état modifié (temporaire)
    PRINT '=== ÉTAT PENDANT LA TRANSACTION ===';
    SELECT * FROM Produits WHERE ProduitID IN (1, 2, 3);

    -- Simuler une erreur
    PRINT '=== ERREUR DÉTECTÉE - ROLLBACK ===';
    ROLLBACK;

-- Afficher l'état final (restauré)
PRINT '=== ÉTAT APRÈS ROLLBACK ===';
SELECT * FROM Produits WHERE ProduitID IN (1, 2, 3);
-- Les produits sont revenus à leur état initial !
```

**Résultat :** Toutes les modifications (UPDATE et DELETE) sont annulées. C'est comme si rien ne s'était passé.

### Exemple 5 : ROLLBACK dans une Procédure Stockée

Exemple réaliste de gestion d'une transaction dans une procédure :

```sql
CREATE PROCEDURE TraiterRetourProduit
    @CommandeID INT,
    @ProduitID INT,
    @Quantite INT
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRANSACTION;

    BEGIN TRY
        -- Variables
        DECLARE @Prix DECIMAL(10,2);
        DECLARE @ClientID INT;

        -- 1. Vérifier que la commande existe
        IF NOT EXISTS (SELECT 1 FROM Commandes WHERE CommandeID = @CommandeID)
        BEGIN
            RAISERROR('Commande inexistante', 16, 1);
        END

        -- 2. Récupérer les infos
        SELECT @ClientID = ClientID
        FROM Commandes
        WHERE CommandeID = @CommandeID;

        SELECT @Prix = PrixUnitaire * @Quantite
        FROM LignesCommande
        WHERE CommandeID = @CommandeID AND ProduitID = @ProduitID;

        IF @Prix IS NULL
        BEGIN
            RAISERROR('Produit non trouvé dans la commande', 16, 1);
        END

        -- 3. Rembourser le client
        UPDATE Clients
        SET Solde = Solde + @Prix
        WHERE ClientID = @ClientID;

        -- 4. Remettre le stock
        UPDATE Produits
        SET StockDisponible = StockDisponible + @Quantite
        WHERE ProduitID = @ProduitID;

        -- 5. Marquer la ligne de commande comme retournée
        UPDATE LignesCommande
        SET Statut = 'Retourné'
        WHERE CommandeID = @CommandeID AND ProduitID = @ProduitID;

        -- 6. Enregistrer dans l'historique
        INSERT INTO HistoriqueRetours (CommandeID, ProduitID, Quantite, DateRetour, Montant)
        VALUES (@CommandeID, @ProduitID, @Quantite, GETDATE(), @Prix);

        -- Tout est OK, valider
        COMMIT;

        PRINT '✓ Retour traité avec succès !';
        PRINT '  Montant remboursé : ' + CAST(@Prix AS VARCHAR) + ' €';
        RETURN 0; -- Code de succès

    END TRY
    BEGIN CATCH
        -- Annuler en cas d'erreur
        IF @@TRANCOUNT > 0
            ROLLBACK;

        PRINT '✗ Impossible de traiter le retour :';
        PRINT '  ' + ERROR_MESSAGE();
        RETURN -1; -- Code d'erreur
    END CATCH
END;
GO

-- Utilisation :
EXEC TraiterRetourProduit @CommandeID = 100, @ProduitID = 456, @Quantite = 2;
```

## COMMIT vs ROLLBACK : Comparaison

Voici un tableau comparatif des deux commandes :

| Aspect | COMMIT | ROLLBACK |
|--------|--------|----------|
| **But** | Valider les modifications | Annuler les modifications |
| **Résultat** | Modifications permanentes ✅ | Retour à l'état initial ⏪ |
| **@@TRANCOUNT** | Décrémente de 1 | Met à 0 (annule tout) |
| **Verrous** | Libérés ✅ | Libérés ✅ |
| **Écriture disque** | Oui (données et journal) | Oui (journal uniquement) |
| **Visibilité** | Changements visibles à tous | Aucun changement visible |
| **Réversibilité** | Non (sauf restore backup) | N/A (les changements n'existent plus) |
| **Quand utiliser** | Tout s'est bien passé ✓ | Une erreur s'est produite ✗ |

## ROLLBACK et Transactions Imbriquées

**Point crucial** : ROLLBACK annule **TOUTES** les transactions, même imbriquées.

### Comportement avec Transactions Imbriquées

```sql
PRINT 'État initial : @@TRANCOUNT = ' + CAST(@@TRANCOUNT AS VARCHAR);

BEGIN TRANSACTION; -- Transaction niveau 1
PRINT 'Après BEGIN 1 : @@TRANCOUNT = ' + CAST(@@TRANCOUNT AS VARCHAR);

    INSERT INTO Table1 VALUES (1);

    BEGIN TRANSACTION; -- Transaction niveau 2
    PRINT 'Après BEGIN 2 : @@TRANCOUNT = ' + CAST(@@TRANCOUNT AS VARCHAR);

        INSERT INTO Table2 VALUES (2);

        BEGIN TRANSACTION; -- Transaction niveau 3
        PRINT 'Après BEGIN 3 : @@TRANCOUNT = ' + CAST(@@TRANCOUNT AS VARCHAR);

            INSERT INTO Table3 VALUES (3);

            -- ROLLBACK à n'importe quel niveau annule TOUT
            ROLLBACK;
            PRINT 'Après ROLLBACK : @@TRANCOUNT = ' + CAST(@@TRANCOUNT AS VARCHAR);

-- Résultat : @@TRANCOUNT = 0
-- Toutes les insertions (1, 2, 3) sont annulées !
```

**Important :** Il n'y a pas de "ROLLBACK partiel" d'une transaction imbriquée. ROLLBACK annule toujours tout.

### Illustration Visuelle

```
@@TRANCOUNT:  0 ──► 1 ──────► 2 ──────► 3 ──────► 0
                │             │         │          │
              BEGIN         BEGIN     BEGIN    ROLLBACK
              TRAN          TRAN      TRAN         │
                │             │         │          │
                ▼             ▼         ▼          ▼
              INSERT       INSERT    INSERT    ❌ TOUT
              Table1       Table2    Table3    ANNULÉ
                │             │         │          │
                └─────────────┴─────────┴──────────┘
                          Toutes les opérations
                          sont annulées, peu importe
                          le niveau où ROLLBACK est appelé
```

## Quand Utiliser ROLLBACK ?

### ✅ Cas d'Usage Appropriés

#### 1. Erreur SQL Détectée

```sql
BEGIN TRANSACTION;
BEGIN TRY
    -- Opérations...

    COMMIT;
END TRY
BEGIN CATCH
    ROLLBACK; -- Erreur SQL → Annuler
    THROW;
END CATCH;
```

#### 2. Violation de Règle Métier

```sql
BEGIN TRANSACTION;
    UPDATE Compte SET Solde = Solde - 1000 WHERE ID = 1;

    IF (SELECT Solde FROM Compte WHERE ID = 1) < 0
    BEGIN
        ROLLBACK; -- Solde négatif interdit → Annuler
        PRINT 'Solde insuffisant';
    END
    ELSE
        COMMIT;
```

#### 3. Condition Non Satisfaite

```sql
BEGIN TRANSACTION;
    DECLARE @NbLignes INT;

    DELETE FROM Produits WHERE Obsolete = 1;
    SET @NbLignes = @@ROWCOUNT;

    IF @NbLignes > 100
    BEGIN
        ROLLBACK; -- Trop de suppressions → Annuler par sécurité
        PRINT 'Trop de produits seraient supprimés';
    END
    ELSE
        COMMIT;
```

#### 4. Test/Développement

```sql
-- Tester une série d'opérations sans les appliquer
BEGIN TRANSACTION;
    UPDATE Produits SET Prix = Prix * 1.1;
    SELECT * FROM Produits; -- Voir le résultat
ROLLBACK; -- Annuler (c'était juste un test)
```

## Bonnes Pratiques avec ROLLBACK

### ✅ Toujours Vérifier @@TRANCOUNT

Dans une procédure stockée, vérifiez qu'une transaction est active avant de faire ROLLBACK :

```sql
IF @@TRANCOUNT > 0
BEGIN
    ROLLBACK;
    PRINT 'Transaction annulée';
END
ELSE
BEGIN
    PRINT 'Aucune transaction à annuler';
END
```

### ✅ ROLLBACK puis RETURN

Après un ROLLBACK, sortez immédiatement du script ou de la procédure :

```sql
BEGIN TRANSACTION;
    UPDATE Table1 ...;

    IF @Erreur = 1
    BEGIN
        ROLLBACK;
        RETURN; -- ✓ Sortir immédiatement
    END

    UPDATE Table2 ...;
COMMIT;
```

**Sans RETURN** :
```sql
BEGIN TRANSACTION;
    UPDATE Table1 ...;

    IF @Erreur = 1
        ROLLBACK;
    -- ⚠️ Le script continue !

    UPDATE Table2 ...; -- S'exécute en auto-commit
COMMIT; -- ⚠️ Erreur : pas de transaction active
```

### ✅ Loggez les ROLLBACK

Enregistrez toujours pourquoi un ROLLBACK a été effectué :

```sql
BEGIN TRANSACTION;
BEGIN TRY
    -- Opérations...

    COMMIT;
END TRY
BEGIN CATCH
    ROLLBACK;

    -- Logger l'erreur
    INSERT INTO LogErreurs (DateErreur, Procedure, Erreur, Message)
    VALUES (GETDATE(), OBJECT_NAME(@@PROCID), ERROR_NUMBER(), ERROR_MESSAGE());

    THROW;
END CATCH;
```

### ✅ Utilisez TRY...CATCH Systématiquement

La structure TRY...CATCH garantit un ROLLBACK en cas d'erreur :

```sql
-- ✓ CORRECT
BEGIN TRANSACTION;
BEGIN TRY
    -- Opérations...
    COMMIT;
END TRY
BEGIN CATCH
    ROLLBACK;
    -- Gestion d'erreur
END CATCH;
```

```sql
-- ✗ DÉCONSEILLÉ
BEGIN TRANSACTION;
    -- Opérations sans gestion d'erreur
COMMIT; -- Si erreur, transaction reste ouverte !
```

### ✅ Documentez les Raisons de ROLLBACK

Ajoutez des commentaires expliquant pourquoi vous annulez :

```sql
IF @StockFinal < 0
BEGIN
    ROLLBACK;
    -- Raison : Règle métier - Le stock ne peut jamais être négatif
    -- Impact : Commande refusée, client notifié
    PRINT 'Stock insuffisant';
END
```

## Erreurs Courantes avec ROLLBACK

### ❌ Erreur 1 : Oublier RETURN après ROLLBACK

```sql
BEGIN TRANSACTION;
    UPDATE Table1 SET Col = 'A';

    IF @Erreur = 1
        ROLLBACK; -- ⚠️ Mais le script continue !

    UPDATE Table2 SET Col = 'B'; -- S'exécute quand même !
COMMIT; -- ⚠️ Erreur : pas de transaction
```

**Solution :** Toujours ajouter RETURN

```sql
IF @Erreur = 1
BEGIN
    ROLLBACK;
    RETURN; -- ✓ Sortir du script
END
```

### ❌ Erreur 2 : ROLLBACK sans Transaction Active

```sql
-- Aucune transaction en cours
ROLLBACK; -- ⚠️ Erreur : "The ROLLBACK TRANSACTION request has no corresponding BEGIN TRANSACTION"
```

**Solution :** Vérifier @@TRANCOUNT

```sql
IF @@TRANCOUNT > 0
    ROLLBACK;
```

### ❌ Erreur 3 : Penser que ROLLBACK peut être Sélectif

```sql
BEGIN TRANSACTION;
    INSERT INTO Table1 VALUES (1); -- Je veux garder ça
    INSERT INTO Table2 VALUES (2); -- Je veux annuler ça
    ROLLBACK; -- ⚠️ Annule LES DEUX insertions !
```

**ROLLBACK annule TOUT.** Il n'y a pas de ROLLBACK partiel (sauf avec SAVE TRANSACTION, que nous verrons plus tard).

### ❌ Erreur 4 : ROLLBACK dans une Boucle Sans Sortie

```sql
WHILE @i < 100
BEGIN
    BEGIN TRANSACTION;
        -- Opération...

        IF @Erreur = 1
            ROLLBACK; -- ⚠️ Mais la boucle continue !
        ELSE
            COMMIT;

    SET @i = @i + 1;
END
```

**Solution :** Sortir de la boucle après ROLLBACK

```sql
WHILE @i < 100
BEGIN
    BEGIN TRANSACTION;
        -- Opération...

        IF @Erreur = 1
        BEGIN
            ROLLBACK;
            BREAK; -- ✓ Sortir de la boucle
        END
        ELSE
            COMMIT;

    SET @i = @i + 1;
END
```

## ROLLBACK et Performance

### Impact Positif : Libération Rapide des Verrous

ROLLBACK libère immédiatement tous les verrous, permettant aux autres utilisateurs de continuer :

```
Transaction en cours : 🔒 Verrous actifs
                       ⏳ Autres utilisateurs bloqués
                         │
                         ▼
                     ROLLBACK
                         │
                         ▼
Verrous libérés :      ✅ Ressources disponibles
                       ▶️ Autres utilisateurs débloqués
```

### Impact du Journal : Moins Coûteux que COMMIT

ROLLBACK est généralement **plus rapide** que COMMIT car :
- ❌ Pas d'écriture finale des données sur disque
- ✅ Juste lecture du journal pour annuler les opérations
- ✅ Pas de synchronisation complète

```
COMMIT :                      ROLLBACK :
├─► Écriture journal 💾       ├─► Lecture journal 📖
├─► Écriture données 💾       ├─► Annulation en mémoire ⚡
└─► Synchronisation 🔄        └─► Terminé ✓

Plus lent                     Plus rapide
```

```
      │  ├─► Annulation UPDATE    ⏪ Valeur = 100
      │  ├─► Annulation INSERT    ⏪ Ligne supprimée
      │  ├─► Libération verrous   ✅ Ressources libres
      │  └─► @@TRANCOUNT = 0      ✓ Transaction finie
      │
  T6  │  État final              ✓ Valeur = 100
      │                          ✓ Identique à T0 !
──────┴───────────────────────────────────────────────
```

---

## Résumé : Le Pattern Complet BEGIN-COMMIT-ROLLBACK

Voici le pattern standard pour une transaction robuste :

```sql
-- Structure complète et robuste
BEGIN TRANSACTION;

BEGIN TRY
    -- ========================================
    -- VOS OPÉRATIONS SQL ICI
    -- ========================================

    INSERT INTO ...;
    UPDATE ...;
    DELETE ...;

    -- ========================================
    -- VALIDATIONS MÉTIER (optionnel)
    -- ========================================

    IF [condition métier non respectée]
    BEGIN
        RAISERROR('Règle métier violée', 16, 1);
    END

    -- ========================================
    -- SI TOUT EST OK : COMMIT
    -- ========================================

    COMMIT;
    PRINT '✓ Transaction validée avec succès';

END TRY
BEGIN CATCH
    -- ========================================
    -- EN CAS D'ERREUR : ROLLBACK
    -- ========================================

    IF @@TRANCOUNT > 0
        ROLLBACK;

    PRINT '✗ Erreur : Transaction annulée';
    PRINT '  ' + ERROR_MESSAGE();

    -- Optionnel : Relancer l'erreur
    -- THROW;

END CATCH;
```

---

## Points Clés à Retenir

### ✓ ROLLBACK annule toutes les modifications

Retour complet à l'état avant BEGIN TRANSACTION, comme si rien ne s'était passé.

### ✓ ROLLBACK ramène @@TRANCOUNT à 0

Contrairement à COMMIT qui décrémente de 1, ROLLBACK annule TOUT.

### ✓ Il n'y a pas de ROLLBACK partiel

ROLLBACK annule toujours l'intégralité de la transaction, pas seulement une partie.

### ✓ ROLLBACK libère tous les verrous

Les autres utilisateurs peuvent immédiatement accéder aux ressources.

### ✓ Toujours utiliser RETURN après ROLLBACK

Sortir du script/procédure immédiatement après annulation.

### ✓ TRY...CATCH garantit le ROLLBACK

C'est la meilleure pratique pour gérer automatiquement les erreurs.

### ✓ ROLLBACK est plus rapide que COMMIT

Moins d'écritures sur disque nécessaires.

### ✓ Loggez les ROLLBACK pour le diagnostic

Enregistrez pourquoi une transaction a été annulée.

---

## Conclusion

`ROLLBACK TRANSACTION` est votre bouton "Annuler" dans SQL Server. C'est un mécanisme de sécurité essentiel qui garantit que, en cas d'erreur ou de problème, votre base de données peut retourner à un état cohérent.

**Les trois règles d'or :**
1. Toute transaction doit se terminer par COMMIT **ou** ROLLBACK
2. En cas d'erreur, utilisez ROLLBACK pour protéger l'intégrité des données
3. Combinez toujours avec TRY...CATCH pour une gestion robuste
