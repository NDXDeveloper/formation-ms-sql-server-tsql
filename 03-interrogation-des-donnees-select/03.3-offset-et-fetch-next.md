# 3.3.3 OFFSET et FETCH NEXT (Pagination moderne)

## Introduction

Lorsque vous consultez un site web de commerce en ligne ou effectuez une recherche sur internet, vous remarquez que les résultats sont présentés **page par page** : page 1 avec les résultats 1-20, page 2 avec les résultats 21-40, etc. Cette technique s'appelle la **pagination**.

La clause `TOP` que nous avons vue précédemment permet d'obtenir les "n premiers" résultats, mais elle ne permet pas facilement de **sauter des lignes** pour afficher les pages suivantes.

SQL Server 2012 a introduit les clauses `OFFSET` et `FETCH NEXT`, qui constituent la méthode **moderne et standard** pour implémenter la pagination de manière élégante et efficace.

## Pourquoi OFFSET et FETCH NEXT ?

### Limitations de TOP pour la pagination

Avec `TOP`, comment afficher la page 3 (lignes 21 à 30) ?

```sql
-- Page 1 : facile
SELECT TOP (10) * FROM Produits ORDER BY ProduitID;

-- Page 2 : compliqué !
-- Il faudrait une sous-requête complexe pour "sauter" les 10 premières lignes
```

### Avantages de OFFSET/FETCH NEXT

- ✅ Syntaxe claire et lisible
- ✅ Contrôle précis du nombre de lignes à sauter
- ✅ Standard SQL (compatible avec d'autres SGBD)
- ✅ Parfait pour la pagination web

## Syntaxe de base

```sql
SELECT colonnes
FROM table
ORDER BY colonne
OFFSET nombre_lignes_a_sauter ROWS
FETCH NEXT nombre_lignes_a_retourner ROWS ONLY;
```

### Éléments de la syntaxe

- **OFFSET** : Indique combien de lignes **sauter** depuis le début
- **ROWS** : Mot-clé obligatoire (même pour 0 ou 1 ligne)
- **FETCH NEXT** : Indique combien de lignes **récupérer**
- **ROWS ONLY** : Termine la clause (obligatoire)

**⚠️ Important :** `ORDER BY` est **obligatoire** avec `OFFSET` et `FETCH`. Sans tri, la pagination n'aurait aucun sens !

## Principe de fonctionnement

Imaginons une table `Produits` avec 100 produits triés par nom :

```
Ligne 1:  Produit A
Ligne 2:  Produit B
Ligne 3:  Produit C
...
Ligne 100: Produit Z
```

### Exemple : Afficher la page 1 (lignes 1-10)

```sql
SELECT ProduitID, NomProduit, Prix
FROM Produits
ORDER BY NomProduit
OFFSET 0 ROWS          -- Ne sauter aucune ligne
FETCH NEXT 10 ROWS ONLY;  -- Prendre les 10 premières
```

**Résultat :** Lignes 1 à 10

### Exemple : Afficher la page 2 (lignes 11-20)

```sql
SELECT ProduitID, NomProduit, Prix
FROM Produits
ORDER BY NomProduit
OFFSET 10 ROWS         -- Sauter les 10 premières lignes
FETCH NEXT 10 ROWS ONLY;  -- Prendre les 10 suivantes
```

**Résultat :** Lignes 11 à 20

### Exemple : Afficher la page 3 (lignes 21-30)

```sql
SELECT ProduitID, NomProduit, Prix
FROM Produits
ORDER BY NomProduit
OFFSET 20 ROWS         -- Sauter les 20 premières lignes
FETCH NEXT 10 ROWS ONLY;  -- Prendre les 10 suivantes
```

**Résultat :** Lignes 21 à 30

## Formule de pagination

Pour afficher une page donnée avec un nombre fixe de résultats par page, utilisez cette formule :

```sql
OFFSET (NumeroPage - 1) * TailleDePageLignes ROWS
FETCH NEXT TailleDePage ROWS ONLY
```

### Exemple concret : 20 résultats par page

```sql
-- Variables pour la pagination
DECLARE @NumeroPage INT = 3;        -- Page souhaitée
DECLARE @TaillePage INT = 20;        -- Résultats par page

-- Calcul du nombre de lignes à sauter
DECLARE @Offset INT = (@NumeroPage - 1) * @TaillePage;

-- Requête paginée
SELECT ProduitID, NomProduit, Prix
FROM Produits
ORDER BY NomProduit
OFFSET @Offset ROWS
FETCH NEXT @TaillePage ROWS ONLY;
```

**Explication du calcul :**
- Page 1 : `(1-1) * 20 = 0` → Sauter 0 ligne
- Page 2 : `(2-1) * 20 = 20` → Sauter 20 lignes
- Page 3 : `(3-1) * 20 = 40` → Sauter 40 lignes
- Page 4 : `(4-1) * 20 = 60` → Sauter 60 lignes

## Utilisation de OFFSET seul

Vous pouvez utiliser `OFFSET` **sans** `FETCH NEXT` si vous voulez simplement sauter des lignes et retourner **tout le reste** :

```sql
SELECT NomProduit, Prix
FROM Produits
ORDER BY Prix DESC
OFFSET 5 ROWS;  -- Saute les 5 premiers, retourne tout le reste
```

**Exemple :** Si vous avez 50 produits, cette requête retournera les 45 produits restants après avoir sauté les 5 plus chers.

## Utilisation de FETCH NEXT seul ?

**Non !** Vous **ne pouvez pas** utiliser `FETCH NEXT` sans `OFFSET`.

```sql
-- ❌ ERREUR : Syntaxe invalide
SELECT * FROM Produits
ORDER BY ProduitID
FETCH NEXT 10 ROWS ONLY;
```

Si vous voulez juste limiter les résultats sans sauter de lignes, utilisez `OFFSET 0` :

```sql
-- ✅ Correct : équivalent à TOP (10)
SELECT * FROM Produits
ORDER BY ProduitID
OFFSET 0 ROWS
FETCH NEXT 10 ROWS ONLY;
```

## Variantes de syntaxe

### ROW vs ROWS

Vous pouvez écrire `ROW` (singulier) ou `ROWS` (pluriel) :

```sql
-- Ces deux syntaxes sont équivalentes
OFFSET 1 ROW
FETCH NEXT 1 ROW ONLY;

OFFSET 1 ROWS
FETCH NEXT 1 ROWS ONLY;
```

**Recommandation :** Utilisez toujours `ROWS` pour la cohérence, même pour 1 ligne.

### FETCH FIRST vs FETCH NEXT

`FETCH FIRST` et `FETCH NEXT` sont synonymes :

```sql
-- Ces deux syntaxes sont équivalentes
FETCH NEXT 10 ROWS ONLY;
FETCH FIRST 10 ROWS ONLY;
```

**Recommandation :** Utilisez `FETCH NEXT` pour la clarté (on récupère les "prochaines" lignes).

## Exemples pratiques de pagination

### Exemple 1 : Liste de clients paginée

Table `Clients` avec 500 clients. Affichage de 25 clients par page.

**Page 1 :**
```sql
SELECT ClientID, NomClient, Ville, Email
FROM Clients
ORDER BY NomClient
OFFSET 0 ROWS
FETCH NEXT 25 ROWS ONLY;
```

**Page 2 :**
```sql
SELECT ClientID, NomClient, Ville, Email
FROM Clients
ORDER BY NomClient
OFFSET 25 ROWS
FETCH NEXT 25 ROWS ONLY;
```

**Page 10 :**
```sql
SELECT ClientID, NomClient, Ville, Email
FROM Clients
ORDER BY NomClient
OFFSET 225 ROWS  -- (10-1) * 25 = 225
FETCH NEXT 25 ROWS ONLY;
```

### Exemple 2 : Historique de commandes

Afficher les 50 commandes d'un client spécifique, page par page (10 par page).

```sql
DECLARE @ClientID INT = 1001;
DECLARE @NumeroPage INT = 3;
DECLARE @TaillePage INT = 10;

SELECT
    NumeroCommande,
    DateCommande,
    MontantTotal,
    Statut
FROM Commandes
WHERE ClientID = @ClientID
ORDER BY DateCommande DESC
OFFSET (@NumeroPage - 1) * @TaillePage ROWS
FETCH NEXT @TaillePage ROWS ONLY;
```

### Exemple 3 : Top 100 avec pagination

Afficher seulement les 100 meilleurs produits, mais paginés par groupes de 10.

```sql
-- On veut la page 5 des Top 100 (lignes 41-50)
SELECT NomProduit, NombreVentes
FROM (
    SELECT TOP (100) NomProduit, NombreVentes
    FROM Produits
    ORDER BY NombreVentes DESC
) AS Top100
ORDER BY NombreVentes DESC
OFFSET 40 ROWS
FETCH NEXT 10 ROWS ONLY;
```

## Combinaison avec WHERE et JOIN

`OFFSET` et `FETCH` fonctionnent naturellement avec toutes les autres clauses SQL.

### Exemple : Recherche paginée avec filtres

```sql
DECLARE @Recherche NVARCHAR(50) = 'ordinateur';
DECLARE @CategorieID INT = 5;
DECLARE @PageNum INT = 2;
DECLARE @PageSize INT = 20;

SELECT
    p.ProduitID,
    p.NomProduit,
    p.Prix,
    c.NomCategorie
FROM Produits p
INNER JOIN Categories c ON p.CategorieID = c.CategorieID
WHERE
    p.CategorieID = @CategorieID
    AND p.NomProduit LIKE '%' + @Recherche + '%'
ORDER BY p.NomProduit
OFFSET (@PageNum - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;
```

## Compter le nombre total de pages

Pour afficher "Page 3 sur 15" dans votre application, vous devez connaître le **nombre total de lignes**.

### Méthode 1 : Deux requêtes distinctes

```sql
-- 1. Compter le nombre total de résultats
DECLARE @Total INT;
SELECT @Total = COUNT(*)
FROM Produits
WHERE Prix > 50;

-- 2. Calculer le nombre de pages
DECLARE @TaillePage INT = 20;
DECLARE @NombrePages INT = CEILING(@Total * 1.0 / @TaillePage);
-- CEILING arrondit vers le haut : 105/20 = 5.25 → 6 pages

-- 3. Récupérer la page demandée
DECLARE @NumeroPage INT = 3;
SELECT ProduitID, NomProduit, Prix
FROM Produits
WHERE Prix > 50
ORDER BY NomProduit
OFFSET (@NumeroPage - 1) * @TaillePage ROWS
FETCH NEXT @TaillePage ROWS ONLY;
```

### Méthode 2 : Avec une fonction de fenêtrage (avancé)

```sql
DECLARE @NumeroPage INT = 3;
DECLARE @TaillePage INT = 20;

WITH ResultatsPagines AS (
    SELECT
        ProduitID,
        NomProduit,
        Prix,
        COUNT(*) OVER() AS TotalResultats  -- Compte le total
    FROM Produits
    WHERE Prix > 50
)
SELECT
    ProduitID,
    NomProduit,
    Prix,
    TotalResultats,
    CEILING(TotalResultats * 1.0 / @TaillePage) AS NombrePages
FROM ResultatsPagines
ORDER BY NomProduit
OFFSET (@NumeroPage - 1) * @TaillePage ROWS
FETCH NEXT @TaillePage ROWS ONLY;
```

Cette méthode retourne les informations de pagination **dans chaque ligne** du résultat.

## Ordre d'exécution de la requête

Comprendre l'ordre d'exécution logique aide à mieux utiliser `OFFSET`/`FETCH` :

1. **FROM** : Identification des tables
2. **JOIN** : Jointures
3. **WHERE** : Filtrage des lignes
4. **GROUP BY** : Regroupement
5. **HAVING** : Filtrage des groupes
6. **SELECT** : Sélection des colonnes
7. **ORDER BY** : Tri (obligatoire avant OFFSET/FETCH)
8. **OFFSET** : Saut des lignes
9. **FETCH** : Limitation du nombre de lignes

`OFFSET` et `FETCH` sont exécutés **en dernier**, après le tri.

## Performances et optimisation

### Index et pagination

Pour une pagination efficace, assurez-vous d'avoir un **index** sur la ou les colonnes de tri :

```sql
-- Si vous paginez souvent sur NomProduit
CREATE INDEX IX_Produits_NomProduit
ON Produits(NomProduit);

-- Requête paginée optimisée
SELECT ProduitID, NomProduit, Prix
FROM Produits
ORDER BY NomProduit  -- Utilise l'index
OFFSET 100 ROWS
FETCH NEXT 20 ROWS ONLY;
```

### Problème des grandes valeurs OFFSET

Plus vous avancez dans les pages (OFFSET élevé), plus SQL Server doit **parcourir et sauter** de lignes :

- Page 1 : `OFFSET 0` → Très rapide
- Page 100 : `OFFSET 1980` → Plus lent (doit sauter 1980 lignes)
- Page 1000 : `OFFSET 19980` → Encore plus lent

**Alternative pour les grandes paginations :** Utiliser une pagination basée sur les **valeurs** plutôt que sur les positions (technique du "keyset pagination").

## OFFSET/FETCH vs TOP

### Comparaison

| Critère | TOP | OFFSET/FETCH |
|---------|-----|--------------|
| **Pagination** | Difficile | Facile et naturelle |
| **Sauter des lignes** | Non | Oui |
| **Standard SQL** | Non (SQL Server uniquement) | Oui (SQL:2008) |
| **Syntaxe** | Plus courte | Plus verbeuse |
| **Performance** | Légèrement plus rapide | Comparable |
| **Ordre d'exécution** | Avant ORDER BY | Après ORDER BY |

### Quand utiliser TOP ?

```sql
-- Simple : les 10 premiers résultats
SELECT TOP (10) *
FROM Produits
ORDER BY Prix DESC;
```

### Quand utiliser OFFSET/FETCH ?

```sql
-- Pagination : page 5 de 10 résultats
SELECT *
FROM Produits
ORDER BY Prix DESC
OFFSET 40 ROWS
FETCH NEXT 10 ROWS ONLY;
```

**Recommandation :**
- Utilisez `TOP` pour des cas simples ("top 10", "top 100")
- Utilisez `OFFSET/FETCH` pour la pagination (navigation page par page)

## Cas d'usage courants

### 1. Application web avec pagination

```sql
-- Paramètres passés par l'application web
DECLARE @Page INT = 2;           -- Page demandée par l'utilisateur
DECLARE @ParPage INT = 25;       -- Nombre d'articles par page

SELECT
    ArticleID,
    Titre,
    Auteur,
    DatePublication
FROM Articles
WHERE Publie = 1
ORDER BY DatePublication DESC
OFFSET (@Page - 1) * @ParPage ROWS
FETCH NEXT @ParPage ROWS ONLY;
```

### 2. API REST avec limite et offset

```sql
-- API appelée avec : /api/produits?limit=50&offset=200
DECLARE @Limit INT = 50;
DECLARE @Offset INT = 200;

SELECT
    ProduitID,
    NomProduit,
    Prix,
    Description
FROM Produits
ORDER BY ProduitID
OFFSET @Offset ROWS
FETCH NEXT @Limit ROWS ONLY;
```

### 3. Traitement par lots

```sql
-- Traiter 1000 commandes à la fois
DECLARE @TailleLot INT = 1000;
DECLARE @LotActuel INT = 0;

WHILE EXISTS (
    SELECT 1 FROM Commandes
    WHERE Traitee = 0
)
BEGIN
    -- Récupérer le prochain lot
    SELECT CommandeID, MontantTotal
    FROM Commandes
    WHERE Traitee = 0
    ORDER BY DateCommande
    OFFSET @LotActuel * @TailleLot ROWS
    FETCH NEXT @TailleLot ROWS ONLY;

    -- Traiter le lot...

    SET @LotActuel = @LotActuel + 1;
END
```

### 4. Carousel ou diaporama

```sql
-- Afficher 5 produits à la fois dans un carousel
-- Position actuelle : 15 (3ème groupe de 5)
DECLARE @Position INT = 15;
DECLARE @NombreElements INT = 5;

SELECT
    ProduitID,
    NomProduit,
    ImageURL,
    Prix
FROM ProduitsMisEnAvant
ORDER BY OrdreAffichage
OFFSET @Position ROWS
FETCH NEXT @NombreElements ROWS ONLY;
```

## Bonnes pratiques

### ✅ À faire

1. **Toujours inclure ORDER BY** (obligatoire et logique)
2. **Créer des index** sur les colonnes de tri pour les performances
3. **Valider les paramètres** : page et taille doivent être > 0
4. **Limiter la taille de page maximum** (ex: max 100 par page)
5. **Retourner le nombre total** de résultats pour afficher "Page X sur Y"

### ❌ À éviter

1. **Paginer sans ORDER BY** (impossible de toute façon)
2. **Permettre des OFFSET très élevés** sans optimisation
3. **Oublier de compter le total** si vous affichez la pagination
4. **Utiliser SELECT *** dans la pagination (récupérez uniquement les colonnes nécessaires)

## Gestion des cas limites

### Que se passe-t-il si OFFSET dépasse le nombre de lignes ?

```sql
-- La table a 100 lignes, mais on demande OFFSET 200
SELECT * FROM Produits
ORDER BY ProduitID
OFFSET 200 ROWS
FETCH NEXT 10 ROWS ONLY;
```

**Résultat :** Aucune erreur, la requête retourne simplement **0 ligne** (résultat vide).

### OFFSET ou FETCH avec des valeurs négatives ?

```sql
-- ❌ ERREUR : les valeurs doivent être >= 0
OFFSET -5 ROWS
FETCH NEXT -10 ROWS ONLY;
```

SQL Server génère une erreur. Les valeurs doivent être des entiers **positifs ou zéro**.

## Exemple complet : Système de pagination

```sql
-- Procédure stockée pour gérer la pagination
CREATE PROCEDURE sp_ObtenirProduitsPagines
    @NumeroPage INT = 1,
    @TaillePage INT = 20,
    @TriColonne NVARCHAR(50) = 'NomProduit',
    @TriOrdre NVARCHAR(4) = 'ASC'
AS
BEGIN
    -- Validation
    IF @NumeroPage < 1 SET @NumeroPage = 1;
    IF @TaillePage < 1 OR @TaillePage > 100 SET @TaillePage = 20;

    -- Compter le total
    DECLARE @TotalLignes INT;
    SELECT @TotalLignes = COUNT(*) FROM Produits;

    DECLARE @TotalPages INT = CEILING(@TotalLignes * 1.0 / @TaillePage);

    -- Récupérer la page
    SELECT
        ProduitID,
        NomProduit,
        Prix,
        Stock,
        @TotalLignes AS TotalResultats,
        @TotalPages AS TotalPages,
        @NumeroPage AS PageActuelle
    FROM Produits
    ORDER BY
        CASE WHEN @TriColonne = 'NomProduit' AND @TriOrdre = 'ASC'
             THEN NomProduit END ASC,
        CASE WHEN @TriColonne = 'NomProduit' AND @TriOrdre = 'DESC'
             THEN NomProduit END DESC,
        CASE WHEN @TriColonne = 'Prix' AND @TriOrdre = 'ASC'
             THEN Prix END ASC,
        CASE WHEN @TriColonne = 'Prix' AND @TriOrdre = 'DESC'
             THEN Prix END DESC
    OFFSET (@NumeroPage - 1) * @TaillePage ROWS
    FETCH NEXT @TaillePage ROWS ONLY;
END
GO

-- Utilisation
EXEC sp_ObtenirProduitsPagines
    @NumeroPage = 3,
    @TaillePage = 25,
    @TriColonne = 'Prix',
    @TriOrdre = 'DESC';
```

## Résumé

| Élément | Description | Exemple |
|---------|-------------|---------|
| **OFFSET n ROWS** | Saute les n premières lignes | `OFFSET 20 ROWS` |
| **FETCH NEXT n ROWS ONLY** | Retourne les n lignes suivantes | `FETCH NEXT 10 ROWS ONLY` |
| **ORDER BY** | Obligatoire avec OFFSET | `ORDER BY NomProduit` |
| **Formule pagination** | `(Page - 1) × Taille` | Page 3, taille 20 → OFFSET 40 |

## Conclusion

`OFFSET` et `FETCH NEXT` constituent la méthode **moderne et standard** pour implémenter la pagination dans SQL Server. Introduites avec SQL Server 2012, ces clauses offrent :

- ✅ Une syntaxe claire et lisible
- ✅ Un contrôle précis de la pagination
- ✅ Une compatibilité avec le standard SQL
- ✅ Une parfaite intégration avec les autres clauses SQL

Bien que `TOP` reste utile pour des cas simples, `OFFSET` et `FETCH` sont **indispensables** pour toute application nécessitant une navigation page par page dans des ensembles de données.

**Points clés à retenir :**
1. `ORDER BY` est **obligatoire** avec OFFSET/FETCH
2. La formule : `OFFSET (Page - 1) × TaillePage ROWS`
3. Pensez aux **index** sur les colonnes de tri pour les performances
4. C'est le standard pour la pagination moderne en SQL

Vous disposez maintenant de tous les outils pour trier (`ORDER BY`), limiter (`TOP`) et paginer (`OFFSET`/`FETCH`) efficacement vos résultats SQL Server !
