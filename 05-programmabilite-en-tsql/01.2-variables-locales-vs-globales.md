# 5.1.2 Variables locales vs globales (ex: @@ROWCOUNT)

## Introduction

Dans la section précédente, nous avons appris à déclarer et utiliser des **variables locales** (avec un seul `@`). T-SQL propose également des **variables globales** (également appelées **variables système** ou **fonctions système**) qui sont automatiquement maintenues par SQL Server et fournissent des informations sur l'état du système ou de la session en cours.

Dans cette section, nous allons explorer les différences entre ces deux types de variables et découvrir les variables globales les plus utiles.

---

## 1. Rappel : Les variables locales

### Caractéristiques

Les variables locales sont celles que nous déclarons nous-mêmes :

```sql
DECLARE @MaVariable INT;
SET @MaVariable = 100;
```

**Points clés des variables locales :**
- Commencent par **un seul @**
- Doivent être **déclarées avec DECLARE**
- Sont **locales au batch** (elles n'existent que dans le script où elles sont définies)
- Nous contrôlons leur **nom**, leur **type** et leur **valeur**
- Disparaissent à la fin du batch

### Exemple de portée limitée

```sql
-- Batch 1
DECLARE @Message VARCHAR(50);
SET @Message = 'Bonjour';
SELECT @Message AS Message;
GO

-- Batch 2 (séparé par GO)
SELECT @Message AS Message; -- ERREUR ! La variable n'existe plus
```

---

## 2. Les variables globales (système)

### Qu'est-ce qu'une variable globale ?

Les **variables globales** sont des variables système prédéfinies par SQL Server qui fournissent des informations sur :
- L'état de la dernière opération exécutée
- Les paramètres de configuration
- Les informations de session
- Les statistiques du serveur

### Caractéristiques

**Points clés des variables globales :**
- Commencent par **deux @** (@@)
- **Ne nécessitent PAS** de déclaration (DECLARE)
- Sont **automatiquement maintenues** par SQL Server
- Sont **accessibles dans tous les batches** d'une même session
- Ont des **noms prédéfinis** que nous ne pouvons pas changer
- Sont **en lecture seule** (nous ne pouvons pas modifier leur valeur)

### Syntaxe

```sql
SELECT @@NomVariableGlobale;
```

---

## 3. @@ROWCOUNT : Nombre de lignes affectées

### Description

`@@ROWCOUNT` est l'une des variables globales les plus utilisées. Elle retourne le **nombre de lignes affectées** par la dernière instruction T-SQL exécutée.

### Type de données

`@@ROWCOUNT` retourne un entier (INT).

### Exemple 1 : Avec SELECT

```sql
-- Supposons que la table Employes contient 50 employés
SELECT * FROM Employes;

-- Afficher combien de lignes ont été retournées
SELECT @@ROWCOUNT AS NombreLignesRetournees;
```

**Résultat :**
```
NombreLignesRetournees
----------------------
50
```

### Exemple 2 : Avec INSERT

```sql
-- Insérer un nouvel employé
INSERT INTO Employes (Prenom, Nom, Salaire)
VALUES ('Pierre', 'Durand', 3000);

-- Vérifier si l'insertion a réussi
SELECT @@ROWCOUNT AS LignesInserees;
```

**Résultat :**
```
LignesInserees
--------------
1
```

### Exemple 3 : Avec UPDATE

```sql
-- Augmenter le salaire de tous les employés du département Ventes
UPDATE Employes
SET Salaire = Salaire * 1.10
WHERE Departement = 'Ventes';

-- Afficher combien d'employés ont été mis à jour
SELECT @@ROWCOUNT AS EmployesMisAJour;
```

**Résultat :**
```
EmployesMisAJour
----------------
12
```

### Exemple 4 : Avec DELETE

```sql
-- Supprimer les employés inactifs
DELETE FROM Employes
WHERE EstActif = 0;

-- Vérifier combien de lignes ont été supprimées
SELECT @@ROWCOUNT AS LignesSupprimees;
```

**Résultat :**
```
LignesSupprimees
----------------
3
```

### ⚠️ Attention : @@ROWCOUNT est volatile !

`@@ROWCOUNT` est **réinitialisé après chaque instruction**. Il faut donc le capturer immédiatement si vous voulez le réutiliser.

**Exemple incorrect :**

```sql
UPDATE Employes
SET Salaire = Salaire * 1.05
WHERE Departement = 'IT';

-- Une autre instruction
SELECT * FROM Departements;

-- @@ROWCOUNT contient maintenant le nombre de départements, pas d'employés mis à jour !
SELECT @@ROWCOUNT AS Resultat; -- Ne donne PAS le résultat de l'UPDATE
```

**Solution : Capturer la valeur dans une variable locale :**

```sql
UPDATE Employes
SET Salaire = Salaire * 1.05
WHERE Departement = 'IT';

-- Capturer immédiatement la valeur
DECLARE @NombreMisAJour INT;
SET @NombreMisAJour = @@ROWCOUNT;

-- Maintenant on peut faire d'autres opérations
SELECT * FROM Departements;

-- La valeur est préservée dans notre variable
SELECT @NombreMisAJour AS EmployesMisAJour;
```

## 4. Utilisation pratique de @@ROWCOUNT

### Vérifier qu'une opération a réussi

```sql
-- Mettre à jour un employé spécifique
UPDATE Employes
SET Salaire = 4500
WHERE EmployeID = 25;

-- Vérifier si la mise à jour a affecté une ligne
IF @@ROWCOUNT = 0
BEGIN
    PRINT 'Aucun employé trouvé avec cet ID.';
END
ELSE
BEGIN
    PRINT 'Mise à jour effectuée avec succès.';
END
```

### Contrôler la logique métier

```sql
-- Supprimer les commandes anciennes
DELETE FROM Commandes
WHERE DateCommande < '2020-01-01';

DECLARE @NombreSupprime INT = @@ROWCOUNT;

-- Informer l'utilisateur
IF @NombreSupprime = 0
    PRINT 'Aucune commande ancienne à supprimer.';
ELSE
    PRINT 'Nombre de commandes supprimées : ' + CAST(@NombreSupprime AS VARCHAR);
```

### Validation dans les procédures stockées

```sql
CREATE PROCEDURE AugmenterSalaireIT
AS
BEGIN
    UPDATE Employes
    SET Salaire = Salaire * 1.10
    WHERE Departement = 'IT';

    -- Retourner le nombre de lignes affectées
    RETURN @@ROWCOUNT;
END
```

## 5. Autres variables globales courantes

Voici un aperçu des variables globales les plus utilisées :

### @@ERROR

Retourne le **numéro d'erreur** de la dernière instruction exécutée. Si aucune erreur ne s'est produite, retourne 0.

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES (1, 'Jean', 'Martin'); -- Si l'ID 1 existe déjà, erreur de clé primaire

IF @@ERROR <> 0
BEGIN
    PRINT 'Une erreur s''est produite lors de l''insertion.';
END
```

**Note :** Depuis SQL Server 2005, il est préférable d'utiliser les blocs **TRY...CATCH** plutôt que @@ERROR.

### @@IDENTITY

Retourne la **dernière valeur d'identité** (auto-incrémentée) insérée dans la session courante.

```sql
INSERT INTO Clients (Nom, Email)
VALUES ('Dupont', 'dupont@email.com');

-- Récupérer l'ID du client qui vient d'être inséré
SELECT @@IDENTITY AS NouvelID;
```

**Résultat :**
```
NouvelID
--------
1523
```

**⚠️ Attention :** Préférez `SCOPE_IDENTITY()` qui est plus sûr (ne prend pas en compte les triggers).

### @@TRANCOUNT

Retourne le **nombre de transactions actives** dans la session courante.

```sql
SELECT @@TRANCOUNT AS TransactionsActives; -- 0 si aucune transaction

BEGIN TRANSACTION;
SELECT @@TRANCOUNT AS TransactionsActives; -- 1

BEGIN TRANSACTION;
SELECT @@TRANCOUNT AS TransactionsActives; -- 2

COMMIT;
SELECT @@TRANCOUNT AS TransactionsActives; -- 1

COMMIT;
SELECT @@TRANCOUNT AS TransactionsActives; -- 0
```

### @@VERSION

Retourne des informations sur la **version de SQL Server** installée.

```sql
SELECT @@VERSION AS VersionSQLServer;
```

**Résultat (exemple) :**
```
Microsoft SQL Server 2022 (RTM) - 16.0.1000.6 (X64)
...
```

### @@SERVERNAME

Retourne le **nom du serveur** SQL Server.

```sql
SELECT @@SERVERNAME AS NomServeur;
```

### @@SPID

Retourne l'**identifiant de session** (Session Process ID) de la connexion courante.

```sql
SELECT @@SPID AS SessionID;
```

**Résultat :**
```
SessionID
---------
52
```

## 6. Tableau récapitulatif : Variables locales vs globales

| Critère | Variables locales | Variables globales |
|---------|-------------------|-------------------|
| **Préfixe** | Un seul `@` | Double `@@` |
| **Déclaration** | Obligatoire (DECLARE) | Pas nécessaire |
| **Nom** | Défini par le développeur | Prédéfini par SQL Server |
| **Portée** | Locale au batch | Accessible dans toute la session |
| **Modification** | Oui (SET, SELECT) | Non (lecture seule) |
| **Exemple** | `@MaVariable` | `@@ROWCOUNT` |
| **Usage** | Stocker des valeurs temporaires | Obtenir des informations système |

## 7. Exemples pratiques combinés

### Exemple 1 : Combinaison de variables locales et globales

```sql
-- Variables locales
DECLARE @Departement VARCHAR(50) = 'Ventes';
DECLARE @Augmentation DECIMAL(5,2) = 5.00;
DECLARE @NombreAffecte INT;

-- Mise à jour
UPDATE Employes
SET Salaire = Salaire * (1 + @Augmentation / 100)
WHERE Departement = @Departement;

-- Capturer le résultat dans une variable locale
SET @NombreAffecte = @@ROWCOUNT;

-- Afficher les résultats
SELECT
    @Departement AS DepartementMisAJour,
    @Augmentation AS PourcentageAugmentation,
    @NombreAffecte AS EmployesAffectes,
    @@SERVERNAME AS ServeurExecution;
```

### Exemple 2 : Vérification d'existence avant insertion

```sql
DECLARE @Email VARCHAR(100) = 'nouveau@email.com';
DECLARE @ClientExiste INT;

-- Vérifier si le client existe déjà
SELECT @ClientExiste = COUNT(*)
FROM Clients
WHERE Email = @Email;

IF @ClientExiste = 0
BEGIN
    -- Insérer le nouveau client
    INSERT INTO Clients (Nom, Email)
    VALUES ('Nouveau Client', @Email);

    -- Vérifier l'insertion
    IF @@ROWCOUNT = 1
        PRINT 'Client ajouté avec succès. ID = ' + CAST(@@IDENTITY AS VARCHAR);
    ELSE
        PRINT 'Erreur lors de l''insertion.';
END
ELSE
BEGIN
    PRINT 'Ce client existe déjà.';
END
```

### Exemple 3 : Audit simple avec variables système

```sql
-- Créer une table d'audit
CREATE TABLE AuditModifications (
    AuditID INT IDENTITY(1,1) PRIMARY KEY,
    TableModifiee VARCHAR(50),
    TypeOperation VARCHAR(20),
    NombreLignes INT,
    DateOperation DATETIME,
    SessionID INT,
    NomServeur VARCHAR(100)
);

-- Effectuer une opération
UPDATE Produits
SET Prix = Prix * 1.05
WHERE Categorie = 'Electronique';

-- Enregistrer l'audit
INSERT INTO AuditModifications (
    TableModifiee,
    TypeOperation,
    NombreLignes,
    DateOperation,
    SessionID,
    NomServeur
)
VALUES (
    'Produits',
    'UPDATE',
    @@ROWCOUNT,        -- Variable globale
    GETDATE(),
    @@SPID,           -- Variable globale
    @@SERVERNAME      -- Variable globale
);
```

## 8. Bonnes pratiques

### ✅ À FAIRE

1. **Capturer immédiatement @@ROWCOUNT** dans une variable locale si vous devez le réutiliser
2. **Utiliser @@ROWCOUNT** pour valider le succès des opérations DML
3. **Préférer SCOPE_IDENTITY()** à @@IDENTITY pour récupérer les ID auto-incrémentés
4. **Utiliser TRY...CATCH** plutôt que @@ERROR pour la gestion d'erreurs moderne
5. **Utiliser les variables globales** pour obtenir des informations système fiables

### ❌ À ÉVITER

1. **Ne pas essayer de déclarer une variable globale** avec DECLARE
2. **Ne pas tenter de modifier une variable globale** (elles sont en lecture seule)
3. **Ne pas supposer que @@ROWCOUNT reste constant** (il change après chaque instruction)
4. **Ne pas confondre @ (local) et @@ (global)**

## Résumé

- Les **variables locales** (`@`) sont déclarées par le développeur et ont une portée limitée au batch
- Les **variables globales** (`@@`) sont prédéfinies par SQL Server et fournissent des informations système
- **@@ROWCOUNT** est la variable globale la plus utilisée : elle indique le nombre de lignes affectées
- **@@ROWCOUNT est volatile** : capturez-la immédiatement dans une variable locale si nécessaire
- Les variables globales sont **en lecture seule** et ne nécessitent pas de déclaration
- D'autres variables globales utiles incluent **@@ERROR**, **@@IDENTITY**, **@@TRANCOUNT**, **@@VERSION**, etc.
