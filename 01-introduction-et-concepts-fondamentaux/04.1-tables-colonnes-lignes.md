# 1.4.1 Tables, Colonnes et Lignes

## Introduction

Vous avez appris ce qu'est une base de données, le modèle relationnel, et le langage SQL/T-SQL. Mais concrètement, comment les données sont-elles organisées à l'intérieur d'une base de données SQL Server ?

La réponse tient en trois mots : **Tables**, **Colonnes**, et **Lignes**.

Ces trois éléments forment la **structure fondamentale** de toute base de données relationnelle. Comprendre ces concepts est absolument **essentiel** avant d'aller plus loin.

### Analogie principale : Le tableur Excel

Si vous avez déjà utilisé **Microsoft Excel** ou **Google Sheets**, vous connaissez déjà les bases !

```
┌────────────────────────────────────────────────────┐
│  Fichier Excel = Base de données                   │
│                                                    │
│  ┌──────────────────────────────────────────────┐  │
│  │  Feuille 1 = Table "Clients"                 │  │
│  │                                              │  │
│  │  A        B         C           D            │  │
│  │  ┌────────┬─────────┬──────────┬──────────┐  │  │
│  │  │ ID     │ Nom     │ Prénom   │ Email    │  │  ← Colonnes
│  │  ├────────┼─────────┼──────────┼──────────┤  │  │
│  │  │ 1      │ Dupont  │ Jean     │ j@...    │  │  ← Ligne 1
│  │  ├────────┼─────────┼──────────┼──────────┤  │  │
│  │  │ 2      │ Martin  │ Marie    │ m@...    │  │  ← Ligne 2
│  │  ├────────┼─────────┼──────────┼──────────┤  │  │
│  │  │ 3      │ Bernard │ Paul     │ p@...    │  │  ← Ligne 3
│  │  └────────┴─────────┴──────────┴──────────┘  │  │
│  └──────────────────────────────────────────────┘  │
│                                                    │

└────────────────────────────────────────────────────┘
```

**La différence majeure ?**
- Excel : Données dans un fichier sur votre PC
- SQL Server : Données dans un serveur avec des règles strictes, des contrôles de sécurité, et bien plus de puissance !

## Les Tables

### Qu'est-ce qu'une table ?

Une **table** est une structure qui organise les données sous forme d'un **tableau à deux dimensions** (lignes et colonnes).

**Définition formelle :**
> Une table est un **objet de base de données** qui stocke des données de manière structurée, où chaque ligne représente un enregistrement et chaque colonne représente un attribut.

**Définition simple :**
> Une table, c'est comme une **feuille de calcul Excel**, mais avec des règles beaucoup plus strictes et puissantes.

### Analogies pour comprendre les tables

#### Analogie 1 : Le classeur à fiches

Imaginez un classeur physique avec des fiches cartonnées :
- **Le classeur entier** = La base de données
- **Une section du classeur** (clients, produits, commandes) = Une table
- **Chaque fiche** = Une ligne (un enregistrement)
- **Les champs de la fiche** (Nom, Prénom, Adresse) = Les colonnes

#### Analogie 2 : L'annuaire téléphonique

```
TABLE : Contacts
┌───────────────────────────────────────────────────┐
│ Nom       │ Prénom    │ Téléphone    │ Ville      │
├───────────┼───────────┼──────────────┼────────────┤
│ Dupont    │ Jean      │ 01 23 45 67  │ Paris      │
│ Martin    │ Sophie    │ 06 98 76 54  │ Lyon       │
│ Bernard   │ Paul      │ 04 56 78 90  │ Marseille  │
└───────────┴───────────┴──────────────┴────────────┘
```

Chaque **ligne** représente une personne différente.  
Chaque **colonne** représente un type d'information identique pour toutes les personnes.  

### Caractéristiques d'une table

#### 1. Un nom unique

Chaque table a un **nom unique** dans la base de données.

**Exemples de noms de tables :**
- `Clients`
- `Produits`
- `Commandes`
- `Employes`
- `Factures`

**Conventions de nommage (bonnes pratiques) :**
- ✅ **Nom au pluriel** : `Clients` (représente plusieurs clients)
- ✅ **Pas d'espaces** : `CommandesClients` (PascalCase) ou `commandes_clients` (snake_case)
- ✅ **Nom descriptif** : `EmployesActifs` plutôt que `Emp1`
- ✅ **En anglais ou en français** : Cohérence dans tout le projet

**Noms à éviter :**
- ❌ Mots réservés SQL : `SELECT`, `FROM`, `TABLE`
- ❌ Espaces : `Mes Clients` (utilisez `MesClients` à la place)
- ❌ Caractères spéciaux : `Clients@2024`, `Produits#`

#### 2. Une structure définie

Une table a une **structure fixe** définie à l'avance :
- Nombre de colonnes défini
- Type de données pour chaque colonne
- Règles de validation (contraintes)

**Contrairement à Excel où vous pouvez modifier à volonté, une table SQL a des règles strictes !**

#### 3. Zéro à plusieurs millions de lignes

Une table peut contenir :
- **0 ligne** : Table vide (juste la structure)
- **Quelques lignes** : Petite table (10-100 lignes)
- **Milliers de lignes** : Table moyenne (1 000 - 100 000)
- **Millions de lignes** : Grande table (100 000+)
- **Milliards de lignes** : Très grande table (possible mais rare)

**Exemple :**
- Table `Pays` : ~200 lignes
- Table `Clients` d'une PME : ~5 000 lignes
- Table `Transactions` d'une banque : ~100 millions de lignes

#### 4. Capacités et limites concrètes

Côté SQL Server, il est utile de connaître quelques limites :

| Élément | Limite |
|---------|--------|
| Colonnes par table | **1 024** (jusqu'à 30 000 avec les colonnes éparses) |
| Taille d'une ligne | **8 060 octets** (hors données volumineuses comme `VARCHAR(MAX)`) |
| Nombre de lignes | Limité par l'espace disque → en pratique **quasi illimité** |
| Tables par base | Limité par le nombre total d'objets (plus de 2 milliards) |

En pratique, on atteint **rarement** ces limites. Une table bien conçue compte généralement **quelques dizaines de colonnes** au maximum : une table de 100+ colonnes est souvent le signe d'une conception à revoir (informations mal réparties qui mériteraient d'être éclatées en plusieurs tables).

### Représentation en T-SQL

Voici à quoi ressemble la création d'une table en T-SQL :

```sql
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom NVARCHAR(50),
    Prenom NVARCHAR(50),
    Email NVARCHAR(100),
    Ville NVARCHAR(50)
);
```

**Ne vous inquiétez pas si cela semble complexe pour l'instant !** Nous apprendrons la syntaxe en détail plus tard.

## Les Colonnes

### Qu'est-ce qu'une colonne ?

Une **colonne** (aussi appelée **champ** ou **attribut**) représente une **caractéristique** ou **propriété** commune à tous les enregistrements de la table.

**Définition simple :**
> Une colonne définit **QUEL TYPE d'information** est stocké.

### Analogie : Les rubriques d'un formulaire

Imaginez un formulaire d'inscription :

```
┌─────────────────────────────────────┐
│  FORMULAIRE D'INSCRIPTION           │
├─────────────────────────────────────┤
│                                     │
│  Nom :         ___________________  │ ← Colonne "Nom"
│                                     │
│  Prénom :      ___________________  │ ← Colonne "Prenom"
│                                     │
│  Email :       ___________________  │ ← Colonne "Email"
│                                     │
│  Téléphone :   ___________________  │ ← Colonne "Telephone"
│                                     │
│  Date naiss. : ___________________  │ ← Colonne "DateNaissance"
│                                     │
└─────────────────────────────────────┘
```

Chaque **rubrique** du formulaire correspond à une **colonne** dans la table.

### Caractéristiques d'une colonne

#### 1. Un nom unique dans la table

Chaque colonne a un **nom unique** au sein de sa table.

**Exemples de noms de colonnes :**
- `ClientID`
- `Nom`
- `Prenom`
- `Email`
- `DateInscription`
- `MontantTotal`

**Conventions de nommage :**
- ✅ **PascalCase** : `DateInscription`, `MontantTotal`
- ✅ **snake_case** : `date_inscription`, `montant_total`
- ✅ **Descriptif** : `PrixUnitaire` plutôt que `Prix1`
- ✅ **Cohérence** : Choisissez une convention et gardez-la !

**Noms à éviter :**
- ❌ Mots réservés : `SELECT`, `FROM`, `ORDER`
- ❌ Noms ambigus : `Data`, `Value`

#### 2. Un type de données

Chaque colonne a un **type de données** qui définit :
- Quel genre de valeurs peut être stocké
- Combien d'espace mémoire est utilisé
- Quelles opérations sont possibles

**Types de données courants :**

| Type | Description | Exemple |
|------|-------------|---------|
| `INT` | Nombre entier | 42, -15, 1000 |
| `DECIMAL(10,2)` | Nombre décimal | 99.99, 1250.50 |
| `NVARCHAR(50)` | Texte (50 caractères max) | "Dupont", "Paris" |
| `DATE` | Date | 2024-11-16 |
| `DATETIME` | Date et heure | 2024-11-16 14:30:00 |
| `BIT` | Booléen (Vrai/Faux) | 0 ou 1 |

**Exemple concret :**
```sql
CREATE TABLE Employes (
    EmployeID INT,              -- Nombre entier
    Nom NVARCHAR(50),           -- Texte jusqu'à 50 caractères
    Salaire DECIMAL(10,2),      -- Nombre décimal (ex: 3500.00)
    DateEmbauche DATE,          -- Date
    EstActif BIT                -- Vrai (1) ou Faux (0)
);
```

**Pourquoi c'est important ?**
- ✅ **Cohérence** : Toutes les valeurs dans une colonne sont du même type
- ✅ **Validation** : SQL Server refuse les données incorrectes
- ✅ **Performance** : Stockage optimisé selon le type
- ✅ **Fonctionnalités** : Opérations spécifiques au type (calculs sur nombres, recherche sur texte)

#### 3. NULL ou NOT NULL

Chaque colonne peut être **obligatoire** ou **facultative** :

**NULL** : La colonne peut être vide (valeur absente)
```sql
Email NVARCHAR(100) NULL  -- L'email peut être absent
```

**NOT NULL** : La colonne doit toujours avoir une valeur
```sql
Nom NVARCHAR(50) NOT NULL  -- Le nom est obligatoire
```

**Exemple visuel :**
```
Table Clients :
┌──────────┬──────────┬──────────┬──────────────────┐
│ ClientID │ Nom      │ Prenom   │ Email            │
│ NOT NULL │ NOT NULL │ NOT NULL │ NULL (optionnel) │
├──────────┼──────────┼──────────┼──────────────────┤
│ 1        │ Dupont   │ Jean     │ j.d@email.com    │
│ 2        │ Martin   │ Marie    │ NULL             │ ← Pas d'email
│ 3        │ Bernard  │ Paul     │ p.b@email.com    │
└──────────┴──────────┴──────────┴──────────────────┘
```

**Qu'est-ce que NULL ?**
- NULL ≠ Zéro (0)
- NULL ≠ Chaîne vide ("")
- NULL = **Absence de valeur**, **valeur inconnue**

#### 4. Valeur par défaut (optionnelle)

Une colonne peut avoir une **valeur par défaut** qui est automatiquement insérée si aucune valeur n'est fournie.

```sql
DateInscription DATE DEFAULT GETDATE()  -- Date du jour par défaut
Stock INT DEFAULT 0                      -- 0 par défaut
EstActif BIT DEFAULT 1                   -- Vrai (1) par défaut
```

**Exemple :**
```sql
INSERT INTO Clients (Nom, Prenom)
VALUES ('Dupont', 'Jean');
-- DateInscription sera automatiquement la date du jour
```

## Les Lignes

### Qu'est-ce qu'une ligne ?

Une **ligne** (aussi appelée **enregistrement**, **tuple**, ou **row**) représente un **élément unique** dans la table.

**Définition simple :**
> Une ligne stocke **UN ENSEMBLE de valeurs** correspondant à **UN objet** ou **UNE entité** spécifique.

### Analogie : Une fiche complète

Reprenons l'analogie du classeur :
- **Une ligne** = Une fiche cartonnée complète avec toutes les informations remplies
- **Chaque case de la fiche** correspond à une colonne

```
┌─────────────────────────────────────────┐
│  FICHE CLIENT #1                        │
├─────────────────────────────────────────┤
│  ClientID :    1                        │
│  Nom :         Dupont                   │
│  Prénom :      Jean                     │
│  Email :       jean.dupont@email.com    │
│  Ville :       Paris                    │
│  DateInscr. :  2024-01-10               │
└─────────────────────────────────────────┘

Cette fiche = UNE ligne de la table Clients
```

### Caractéristiques d'une ligne

#### 1. Une ligne = Un enregistrement complet

Une ligne contient **une valeur pour chaque colonne** (ou NULL si la colonne l'autorise).

**Exemple :**
```
Table Clients - Ligne #2 :
┌──────────┬────────┬─────────┬───────────────────┬────────┐
│ ClientID │ Nom    │ Prénom  │ Email             │ Ville  │
├──────────┼────────┼─────────┼───────────────────┼────────┤
│ 2        │ Martin │ Marie   │ marie.m@email.com │ Lyon   │
└──────────┴────────┴─────────┴───────────────────┴────────┘

Cette ligne représente le client Marie Martin de Lyon.
```

#### 2. Chaque ligne devrait être unique

Idéalement, chaque ligne est **unique** et identifiable.

**Comment ?** Grâce à une **clé primaire** (nous y reviendrons en détail).

**Exemple :**
```
┌──────────┬────────┬─────────┐
│ ClientID │ Nom    │ Prénom  │
├──────────┼────────┼─────────┤
│ 1        │ Dupont │ Jean    │ ← Ligne unique grâce à ClientID = 1
│ 2        │ Dupont │ Jean    │ ← Ligne différente (ClientID = 2)
│ 3        │ Martin │ Marie   │ ← Ligne unique
└──────────┴────────┴─────────┘
```

Même si deux personnes s'appellent "Dupont Jean", elles ont des `ClientID` différents.

#### 3. L'ordre des lignes n'est pas garanti

**Important :** Dans une table SQL, les lignes n'ont **pas d'ordre intrinsèque** !

❌ **Contrairement à Excel**, SQL ne garantit pas que :
- Ligne 1 reste en position 1
- Les lignes sont dans l'ordre d'insertion

✅ **Pour obtenir un ordre**, vous devez **explicitement** utiliser `ORDER BY` dans vos requêtes :

```sql
-- Sans ORDER BY : ordre imprévisible
SELECT * FROM Clients;

-- Avec ORDER BY : ordre garanti
SELECT * FROM Clients ORDER BY Nom;
```

#### 4. Une ligne peut être ajoutée, modifiée, supprimée

Les opérations sur les lignes :

**Ajouter (INSERT) :**
```sql
INSERT INTO Clients (ClientID, Nom, Prenom, Email, Ville)
VALUES (5, 'Leroy', 'Luc', 'luc.l@email.com', 'Bordeaux');
```

**Modifier (UPDATE) :**
```sql
UPDATE Clients
SET Email = 'nouveau.email@example.com'
WHERE ClientID = 5;
```

**Supprimer (DELETE) :**
```sql
DELETE FROM Clients
WHERE ClientID = 5;
```

## La relation entre Tables, Colonnes et Lignes

### Vision d'ensemble

```
┌───────────────────────────────────────────────────────────┐
│                        TABLE                              │
│                     (Structure)                           │
│                                                           │
│  Définit :                                                │
│  • Nom de la table                                        │
│  • Liste des colonnes                                     │
│  • Contraintes et règles                                  │
│                                                           │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              COLONNES (Verticales)                  │  │
│  │                                                     │  │
│  │  Définissent :                                      │  │
│  │  • QUEL TYPE d'information (Nom, Prix, Date...)     │  │
│  │  • Type de données (INT, VARCHAR, DATE...)          │  │
│  │  • Règles (NULL/NOT NULL, Default, etc.)            │  │
│  │                                                     │  │
│  │  Col1    Col2    Col3    Col4                       │  │
│  │  ─────┬───────┬────────┬────────                    │  │
│  │       │       │        │                            │  │
│  │  ─────┼───────┼────────┼────────  ← LIGNES          │  │
│  │       │       │        │             (Horizontales) │  │
│  │  ─────┼───────┼────────┼────────                    │  │
│  │       │       │        │           Contiennent :    │  │
│  │  ─────┼───────┼────────┼────────   • LES DONNÉES    │  │
│  │       │       │        │           • Un enreg.      │  │
│  │  ─────┼───────┼────────┼────────     par ligne      │  │
│  │       │       │        │                            │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

### La cellule : l'intersection d'une ligne et d'une colonne

À l'endroit précis où une **ligne** croise une **colonne** se trouve une **cellule**. Elle contient **une seule valeur** : l'attribut décrit par la colonne, pour l'enregistrement décrit par la ligne.

```
                   Colonne « Nom »   Colonne « Prix »
                         │                 │
   Ligne produit #1 ─────┼── "Clavier" ────┼──  29.99
                         │                 │
                     (cellule)         (cellule)
```

Règle d'or du modèle relationnel : **une cellule contient une valeur atomique**, c'est-à-dire une seule valeur indivisible — jamais une liste. On ne stocke donc pas `"rouge, vert, bleu"` dans une cellule unique `Couleurs` ; on utilise plutôt une table dédiée. Ce principe (appelé *première forme normale*) garantit des données simples à interroger et à maintenir.

> 🧠 **Vocabulaire** — Une cellule est parfois appelée **champ**, notamment dans le vocabulaire des formulaires et des tableurs. Dans une table de *n* colonnes et *m* lignes, il y a donc *n × m* cellules (d'où les « 30 cellules » de l'exemple plus bas : 6 × 5).

### Métaphore complète : L'immeuble

Pour bien comprendre la hiérarchie, imaginons un **immeuble** :

```
🏢 BASE DE DONNÉES = L'immeuble entier
│
├─ 📁 TABLE "Clients" = Appartement 1
│   │
│   ├─ 📊 COLONNES = Pièces de l'appartement
│   │   ├─ ClientID = Cuisine
│   │   ├─ Nom = Salon
│   │   ├─ Prenom = Chambre 1
│   │   └─ Email = Chambre 2
│   │
│   └─ 📝 LIGNES = Meubles dans chaque pièce
│       ├─ Ligne 1 (Client 1) = Un ensemble de meubles
│       ├─ Ligne 2 (Client 2) = Un autre ensemble
│       └─ Ligne 3 (Client 3) = Encore un autre
│
├─ 📁 TABLE "Produits" = Appartement 2
│   └─ ... (même structure)
│
└─ 📁 TABLE "Commandes" = Appartement 3
    └─ ... (même structure)
```

### Exemple complet et détaillé

**Base de données : Boutique**

**Table : Produits**

**Structure (définition) :**
```sql
CREATE TABLE Produits (
    ProduitID INT NOT NULL PRIMARY KEY,
    Nom NVARCHAR(100) NOT NULL,
    Categorie NVARCHAR(50) NOT NULL,
    Prix DECIMAL(10,2) NOT NULL,
    Stock INT DEFAULT 0,
    DateAjout DATE DEFAULT GETDATE()
);
```

**Données (contenu) :**
```

│ ProduitID │ Nom                │ Categorie   │ Prix    │ Stock │ DateAjout  │
```

**Analyse :**
- **Table** : Produits (contient des informations sur les produits)
- **Colonnes** : 6 colonnes définissant les caractéristiques (ID, Nom, Catégorie, Prix, Stock, Date)
- **Lignes** : 5 lignes représentant 5 produits distincts
- **Cellules** : 30 cellules au total (6 colonnes × 5 lignes)

## Terminologie : Différents mots pour les mêmes concepts

### Pour une Table

| Terme | Utilisation |
|-------|-------------|
| **Table** | Terme standard SQL |
| **Relation** | Terme théorique du modèle relationnel |
| **Entity** | En conception (modèle entité-association) |

### Pour une Colonne

| Terme | Utilisation |
|-------|-------------|
| **Column** (Colonne) | Terme standard SQL |
| **Field** (Champ) | Terme courant |
| **Attribute** (Attribut) | Terme théorique |
| **Property** (Propriété) | En programmation orientée objet |

### Pour une Ligne

| Terme | Utilisation |
|-------|-------------|
| **Row** (Ligne) | Terme standard SQL |
| **Record** (Enregistrement) | Terme très courant |
| **Tuple** | Terme théorique (mathématiques) |
| **Instance** | En conception orientée objet |

**Dans ce cours, nous utiliserons principalement :**
- **Table** pour table
- **Colonne** pour colonne
- **Ligne** ou **Enregistrement** pour ligne

**Questions :**

## Bonnes pratiques de conception

### Pour les Tables

- ✅ **Nom au pluriel** : `Clients`, `Produits`, `Commandes`
- ✅ **Un seul sujet par table** : Une table pour les clients, une autre pour les produits
- ✅ **Cohérence** : Même convention de nommage partout
- ✅ **Pas de données calculées** : Stocker les données brutes, calculer à la volée

- ❌ **Éviter** : Tables trop larges (>50 colonnes), noms ambigus

### Pour les Colonnes

- ✅ **Noms descriptifs** : `DateNaissance` plutôt que `Date1`
- ✅ **Type approprié** : INT pour les nombres, DATE pour les dates
- ✅ **NOT NULL** pour les données obligatoires
- ✅ **Valeurs par défaut** quand c'est logique

- ❌ **Éviter** : Colonnes multivaluées (stocker plusieurs valeurs séparées par des virgules)

### Pour les Lignes

- ✅ **Chaque ligne = une entité distincte**
- ✅ **Utiliser une clé primaire** pour identifier chaque ligne
- ✅ **Éviter les doublons** (sauf si justifié)
- ✅ **Données cohérentes** avec les types de colonnes

- ❌ **Éviter** : Lignes dupliquées, données incohérentes

## Résumé

### Les trois piliers

| Concept | Définition | Analogie |
|---------|------------|----------|
| **TABLE** | Structure qui organise les données | Feuille Excel, Classeur à fiches |
| **COLONNE** | Type d'information (attribut) | Rubrique d'un formulaire |
| **LIGNE** | Un enregistrement complet | Une fiche remplie |

### Points clés à retenir

1. **Table** :
   - Nom unique
   - Structure définie (colonnes)
   - Contient 0 à N lignes

2. **Colonne** :
   - Nom unique dans la table
   - Type de données défini
   - NULL ou NOT NULL
   - Peut avoir une valeur par défaut

3. **Ligne** :
   - Représente un enregistrement unique
   - Contient une valeur par colonne
   - Ordre non garanti (sans ORDER BY)
   - Peut être ajoutée, modifiée, supprimée

### Hiérarchie

```
Base de données
   │
   ├─ Table 1
   │   ├─ Colonne 1, Colonne 2, Colonne 3...
   │   └─ Ligne 1, Ligne 2, Ligne 3...
   │
   ├─ Table 2
   │   ├─ Colonne 1, Colonne 2...
   │   └─ Ligne 1, Ligne 2...
   │
   └─ Table 3
       └─ ...
```

### Citation

> "Une table bien conçue, c'est comme une maison bien organisée : tout est à sa place, facile à trouver, et agréable à utiliser."
