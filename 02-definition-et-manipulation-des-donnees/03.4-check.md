# 2.3.4 CHECK (Validation de données)

## Introduction

Imaginez un site e-commerce où vous devez saisir votre âge. Vous tapez accidentellement **-25 ans** ou **500 ans**. Sans validation, ces valeurs aberrantes seraient enregistrées dans la base de données ! Comment empêcher cela ?

C'est exactement le rôle de la contrainte **CHECK** : elle permet de définir des **règles de validation personnalisées** pour garantir que seules des valeurs **valides et cohérentes** sont insérées dans votre base de données.

**Analogie :** Une contrainte CHECK est comme un vigile à l'entrée d'un bâtiment qui vérifie que vous respectez le code vestimentaire avant de vous laisser entrer.

## Qu'est-ce qu'une Contrainte CHECK ?

### Définition Simple

Une contrainte CHECK définit une **condition** que chaque valeur d'une colonne (ou d'un ensemble de colonnes) doit respecter. Si la condition n'est pas satisfaite, l'insertion ou la modification est **rejetée**.

**Exemples de règles métier :**
- Un âge doit être entre 0 et 120
- Un prix doit être positif
- Une note doit être entre 0 et 20
- Un email doit contenir un @
- Une date de fin doit être après la date de début
- Un code postal doit avoir 5 chiffres

### Exemple Visuel

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150) NOT NULL,
    Prix DECIMAL(10,2),
    Stock INT,
    CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0),
    CONSTRAINT CHK_Produits_Stock CHECK (Stock >= 0)
);
```

**Règles définies :**
- Le prix doit être **strictement positif** (> 0)
- Le stock doit être **positif ou nul** (>= 0)

**Tentatives d'insertion :**

```sql
-- ✅ OK : Prix et stock valides
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (1, 'Ordinateur', 899.99, 10);

-- ❌ ERREUR : Prix négatif
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (2, 'Souris', -29.99, 50);
-- Erreur : The INSERT statement conflicted with the CHECK constraint 'CHK_Produits_Prix'

-- ❌ ERREUR : Stock négatif
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (2, 'Souris', 29.99, -5);
-- Erreur : The INSERT statement conflicted with the CHECK constraint 'CHK_Produits_Stock'

-- ✅ OK : Stock à zéro est valide (>= 0)
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (2, 'Souris', 29.99, 0);
```

## Pourquoi Utiliser des Contraintes CHECK ?

### 1. Garantir la Qualité des Données

Sans contrainte CHECK, des données invalides peuvent entrer dans votre base :

```sql
-- ❌ SANS CHECK : Données invalides acceptées
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Age INT,
    Salaire DECIMAL(10,2)
);

-- Données aberrantes acceptées !
INSERT INTO Employes VALUES (1, -5, -1000.00);  -- Age négatif, salaire négatif
INSERT INTO Employes VALUES (2, 250, 0);        -- Age irréaliste
```

```sql
-- ✅ AVEC CHECK : Protection contre les données invalides
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Age INT,
    Salaire DECIMAL(10,2),
    CONSTRAINT CHK_Employes_Age CHECK (Age BETWEEN 18 AND 70),
    CONSTRAINT CHK_Employes_Salaire CHECK (Salaire > 0)
);

-- Données invalides rejetées !
-- INSERT INTO Employes VALUES (1, -5, -1000.00);  -- Erreur
-- INSERT INTO Employes VALUES (2, 250, 0);        -- Erreur
```

### 2. Appliquer les Règles Métier

Les contraintes CHECK permettent d'implémenter les règles métier directement dans la base de données :

- **E-commerce :** Quantité commandée > 0, prix > 0
- **RH :** Age valide, salaire dans une fourchette
- **Éducation :** Notes entre 0 et 20
- **Réservation :** Date de fin > date de début

### 3. Centraliser la Validation

Plutôt que de valider dans chaque application (web, mobile, API), vous validez **une seule fois** dans la base de données.

```
Application Web ────┐
                    │
Application Mobile ─┤──> Base de données (validation CHECK)
                    │       ✓ Une seule source de vérité
API REST ───────────┘
```

## Comment Créer une Contrainte CHECK ?

Il existe plusieurs méthodes pour définir une contrainte CHECK.

### Méthode 1 : Lors de la Création de la Table (Inline)

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2) CHECK (Prix > 0),
    Stock INT CHECK (Stock >= 0)
);
```

### Méthode 2 : Avec Contrainte Nommée (Recommandé)

Il est préférable de **nommer** vos contraintes :

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    Stock INT,
    CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0),
    CONSTRAINT CHK_Produits_Stock CHECK (Stock >= 0)
);
```

**Convention de nommage :** `CHK_NomTable_NomColonne` ou `CK_NomTable_NomColonne`

### Méthode 3 : Après la Création de la Table

```sql
-- D'abord créer la table
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    Stock INT
);

-- Ensuite ajouter les contraintes CHECK
ALTER TABLE Produits
ADD CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0);

ALTER TABLE Produits
ADD CONSTRAINT CHK_Produits_Stock CHECK (Stock >= 0);
```

### Méthode 4 : Contrainte CHECK sur Plusieurs Colonnes

```sql
CREATE TABLE Reservations
(
    IdReservation INT PRIMARY KEY,
    DateDebut DATE,
    DateFin DATE,
    CONSTRAINT CHK_Reservations_Dates CHECK (DateFin > DateDebut)
);
```

## Types de Validations avec CHECK

### 1. Validation de Plage (Range)

Vérifier qu'une valeur est dans un intervalle donné.

#### Opérateur BETWEEN

```sql
CREATE TABLE Etudiants
(
    IdEtudiant INT PRIMARY KEY,
    Nom VARCHAR(100),
    Age INT,
    Note DECIMAL(4,2),
    CONSTRAINT CHK_Etudiants_Age CHECK (Age BETWEEN 16 AND 30),
    CONSTRAINT CHK_Etudiants_Note CHECK (Note BETWEEN 0 AND 20)
);
```

**Explications :**
- `Age BETWEEN 16 AND 30` : Age entre 16 et 30 inclus
- `Note BETWEEN 0 AND 20` : Note entre 0 et 20 inclus

**Équivalent :**
```sql
CHECK (Age >= 16 AND Age <= 30)
CHECK (Note >= 0 AND Note <= 20)
```

#### Comparaisons Simples

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Prix DECIMAL(10,2),
    Remise DECIMAL(4,2),
    Stock INT,
    CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0),           -- Strictement positif
    CONSTRAINT CHK_Produits_Remise CHECK (Remise >= 0 AND Remise <= 100),  -- Entre 0 et 100%
    CONSTRAINT CHK_Produits_Stock CHECK (Stock >= 0)         -- Positif ou nul
);
```

### 2. Validation de Liste (IN)

Vérifier qu'une valeur fait partie d'une liste prédéfinie.

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    NumeroCommande VARCHAR(30),
    Statut VARCHAR(20),
    Priorite VARCHAR(10),
    CONSTRAINT CHK_Commandes_Statut
        CHECK (Statut IN ('En attente', 'En cours', 'Expédiée', 'Livrée', 'Annulée')),
    CONSTRAINT CHK_Commandes_Priorite
        CHECK (Priorite IN ('Basse', 'Normale', 'Haute', 'Urgente'))
);
```

**Exemple d'utilisation :**

```sql
-- ✅ OK : Statut valide
INSERT INTO Commandes (IdCommande, NumeroCommande, Statut, Priorite)
VALUES (1, 'CMD-001', 'En attente', 'Normale');

-- ❌ ERREUR : Statut invalide
INSERT INTO Commandes (IdCommande, NumeroCommande, Statut, Priorite)
VALUES (2, 'CMD-002', 'En préparation', 'Normale');
-- 'En préparation' n'est pas dans la liste

-- ✅ OK : Mise à jour vers un statut valide
UPDATE Commandes SET Statut = 'Expédiée' WHERE IdCommande = 1;

-- ❌ ERREUR : Priorité invalide
UPDATE Commandes SET Priorite = 'Critique' WHERE IdCommande = 1;
-- 'Critique' n'est pas dans la liste
```

### 3. Validation de Motif (Pattern) avec LIKE

Vérifier qu'une valeur respecte un certain format.

```sql
CREATE TABLE Contacts
(
    IdContact INT PRIMARY KEY,
    Email VARCHAR(150),
    Telephone VARCHAR(20),
    CodePostal VARCHAR(10),
    CONSTRAINT CHK_Contacts_Email
        CHECK (Email LIKE '%_@__%.__%'),  -- Doit contenir @ et un point
    CONSTRAINT CHK_Contacts_Telephone
        CHECK (Telephone LIKE '[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
               OR Telephone LIKE '+[0-9]%'),  -- 10 chiffres ou commence par +
    CONSTRAINT CHK_Contacts_CodePostal
        CHECK (CodePostal LIKE '[0-9][0-9][0-9][0-9][0-9]')  -- 5 chiffres
);
```

**Wildcards LIKE :**
- `%` : n'importe quelle séquence de caractères
- `_` : exactement un caractère
- `[0-9]` : un chiffre entre 0 et 9
- `[A-Z]` : une lettre majuscule

**Exemples :**

```sql
-- ✅ OK : Email valide
INSERT INTO Contacts (IdContact, Email, Telephone, CodePostal)
VALUES (1, 'alice@exemple.com', '0612345678', '75001');

-- ❌ ERREUR : Email sans @
INSERT INTO Contacts (IdContact, Email, Telephone, CodePostal)
VALUES (2, 'alice.exemple.com', '0612345678', '75001');

-- ❌ ERREUR : Code postal avec lettres
INSERT INTO Contacts (IdContact, Email, Telephone, CodePostal)
VALUES (2, 'alice@exemple.com', '0612345678', '750A1');
```

**⚠️ Note :** LIKE est limité pour la validation d'email. Pour une validation robuste, utilisez plutôt la validation dans l'application.

### 4. Validation avec Expressions Logiques

Combiner plusieurs conditions avec AND, OR, NOT.

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Age INT,
    Anciennete INT,
    Salaire DECIMAL(10,2),
    EstCadre BIT,
    CONSTRAINT CHK_Employes_Age_Anciennete
        CHECK (Age >= 18 AND Anciennete >= 0 AND Anciennete <= (Age - 16)),
    CONSTRAINT CHK_Employes_Salaire
        CHECK ((EstCadre = 0 AND Salaire >= 1800) OR (EstCadre = 1 AND Salaire >= 3000))
);
```

**Explications :**
- L'âge doit être >= 18
- L'ancienneté doit être cohérente avec l'âge (on ne peut pas avoir 30 ans d'ancienneté à 25 ans)
- Si non-cadre, salaire minimum 1800
- Si cadre, salaire minimum 3000

### 5. Validation entre Colonnes

Comparer des valeurs de différentes colonnes de la même ligne.

```sql
CREATE TABLE Evenements
(
    IdEvenement INT PRIMARY KEY,
    NomEvenement VARCHAR(200),
    DateDebut DATETIME2,
    DateFin DATETIME2,
    NombreParticipantsMin INT,
    NombreParticipantsMax INT,
    CONSTRAINT CHK_Evenements_Dates
        CHECK (DateFin > DateDebut),
    CONSTRAINT CHK_Evenements_Participants
        CHECK (NombreParticipantsMax >= NombreParticipantsMin)
);
```

```sql
-- ✅ OK : Dates et participants cohérents
INSERT INTO Evenements (IdEvenement, NomEvenement, DateDebut, DateFin, NombreParticipantsMin, NombreParticipantsMax)
VALUES (1, 'Conférence SQL', '2025-03-15 09:00', '2025-03-15 17:00', 10, 50);

-- ❌ ERREUR : Date de fin avant date de début
INSERT INTO Evenements (IdEvenement, NomEvenement, DateDebut, DateFin, NombreParticipantsMin, NombreParticipantsMax)
VALUES (2, 'Workshop', '2025-03-20 09:00', '2025-03-19 17:00', 5, 20);

-- ❌ ERREUR : Max < Min
INSERT INTO Evenements (IdEvenement, NomEvenement, DateDebut, DateFin, NombreParticipantsMin, NombreParticipantsMax)
VALUES (2, 'Workshop', '2025-03-20 09:00', '2025-03-20 17:00', 50, 20);
```

### 6. Validation avec des Calculs

Utiliser des expressions mathématiques.

```sql
CREATE TABLE Promotions
(
    IdPromotion INT PRIMARY KEY,
    PrixOriginal DECIMAL(10,2),
    PourcentageRemise DECIMAL(5,2),
    PrixFinal DECIMAL(10,2),
    CONSTRAINT CHK_Promotions_Remise
        CHECK (PourcentageRemise BETWEEN 0 AND 100),
    CONSTRAINT CHK_Promotions_PrixFinal
        CHECK (PrixFinal = PrixOriginal * (1 - PourcentageRemise / 100))
);
```

**Exemple :**

```sql
-- ✅ OK : Prix final correct (100 - 20% = 80)
INSERT INTO Promotions (IdPromotion, PrixOriginal, PourcentageRemise, PrixFinal)
VALUES (1, 100.00, 20.00, 80.00);

-- ❌ ERREUR : Prix final incorrect
INSERT INTO Promotions (IdPromotion, PrixOriginal, PourcentageRemise, PrixFinal)
VALUES (2, 100.00, 20.00, 85.00);  -- Devrait être 80, pas 85
```

**⚠️ Attention :** Les vérifications avec calculs flottants peuvent être sensibles aux arrondis.

## Exemples Pratiques Complets

### Exemple 1 : Boutique en Ligne

```sql
CREATE TABLE Produits
(
    IdProduit INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(150) NOT NULL,
    Prix DECIMAL(10,2) NOT NULL,
    PrixPromo DECIMAL(10,2),
    Stock INT NOT NULL,
    StockMinimum INT DEFAULT 5,
    Note DECIMAL(3,2),
    CONSTRAINT CHK_Produits_Prix
        CHECK (Prix > 0),
    CONSTRAINT CHK_Produits_PrixPromo
        CHECK (PrixPromo IS NULL OR (PrixPromo > 0 AND PrixPromo < Prix)),
    CONSTRAINT CHK_Produits_Stock
        CHECK (Stock >= 0),
    CONSTRAINT CHK_Produits_StockMinimum
        CHECK (StockMinimum >= 0 AND StockMinimum <= Stock),
    CONSTRAINT CHK_Produits_Note
        CHECK (Note IS NULL OR Note BETWEEN 0 AND 5)
);
```

**Règles métier :**
- Prix doit être positif
- Prix promo doit être inférieur au prix normal
- Stock ne peut pas être négatif
- Stock minimum doit être inférieur au stock actuel
- Note entre 0 et 5 (ou NULL si pas encore noté)

```sql
-- Insertions
INSERT INTO Produits (Nom, Prix, PrixPromo, Stock, StockMinimum, Note)
VALUES ('Ordinateur', 899.99, 799.99, 10, 2, 4.5);

INSERT INTO Produits (Nom, Prix, PrixPromo, Stock, StockMinimum, Note)
VALUES ('Souris', 29.99, NULL, 50, 5, 4.2);

-- ❌ ERREUR : Prix promo supérieur au prix normal
-- INSERT INTO Produits (Nom, Prix, PrixPromo, Stock, StockMinimum)
-- VALUES ('Clavier', 49.99, 59.99, 20, 3);
```

### Exemple 2 : Système de Réservation

```sql
CREATE TABLE Reservations
(
    IdReservation INT IDENTITY(1,1) PRIMARY KEY,
    IdClient INT NOT NULL,
    DateReservation DATETIME2 DEFAULT GETDATE(),
    DateDebut DATE NOT NULL,
    DateFin DATE NOT NULL,
    NombrePersonnes INT NOT NULL,
    Statut VARCHAR(20) DEFAULT 'En attente',
    CONSTRAINT CHK_Reservations_Dates
        CHECK (DateFin > DateDebut),
    CONSTRAINT CHK_Reservations_DateDebut
        CHECK (DateDebut >= CAST(GETDATE() AS DATE)),
    CONSTRAINT CHK_Reservations_NombrePersonnes
        CHECK (NombrePersonnes BETWEEN 1 AND 10),
    CONSTRAINT CHK_Reservations_Statut
        CHECK (Statut IN ('En attente', 'Confirmée', 'Annulée'))
);
```

**Règles métier :**
- Date de fin après date de début
- Date de début ne peut pas être dans le passé
- Nombre de personnes entre 1 et 10
- Statut doit être dans la liste prédéfinie

```sql
-- ✅ OK : Réservation valide
INSERT INTO Reservations (IdClient, DateDebut, DateFin, NombrePersonnes)
VALUES (1, '2025-03-15', '2025-03-20', 4);

-- ❌ ERREUR : Date de fin avant date de début
-- INSERT INTO Reservations (IdClient, DateDebut, DateFin, NombrePersonnes)
-- VALUES (2, '2025-03-20', '2025-03-15', 2);

-- ❌ ERREUR : Date dans le passé
-- INSERT INTO Reservations (IdClient, DateDebut, DateFin, NombrePersonnes)
-- VALUES (2, '2024-01-15', '2024-01-20', 2);
```

### Exemple 3 : Gestion RH

```sql
CREATE TABLE Employes
(
    IdEmploye INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(100) NOT NULL,
    Prenom VARCHAR(50) NOT NULL,
    DateNaissance DATE NOT NULL,
    DateEmbauche DATE NOT NULL,
    Salaire DECIMAL(10,2) NOT NULL,
    Prime DECIMAL(10,2) DEFAULT 0,
    Departement VARCHAR(50),
    Poste VARCHAR(50),
    CONSTRAINT CHK_Employes_DateNaissance
        CHECK (DateNaissance < GETDATE()),
    CONSTRAINT CHK_Employes_DateEmbauche
        CHECK (DateEmbauche >= '2000-01-01' AND DateEmbauche <= GETDATE()),
    CONSTRAINT CHK_Employes_Age
        CHECK (DATEDIFF(YEAR, DateNaissance, DateEmbauche) >= 16),
    CONSTRAINT CHK_Employes_Salaire
        CHECK (Salaire BETWEEN 1800 AND 100000),
    CONSTRAINT CHK_Employes_Prime
        CHECK (Prime >= 0 AND Prime <= Salaire * 0.5),
    CONSTRAINT CHK_Employes_Departement
        CHECK (Departement IN ('IT', 'RH', 'Finance', 'Commercial', 'Production'))
);
```

**Règles métier :**
- Date de naissance dans le passé
- Date d'embauche entre 2000 et aujourd'hui
- Âge minimum de 16 ans à l'embauche
- Salaire entre 1800 et 100000
- Prime maximum de 50% du salaire
- Département dans la liste prédéfinie

### Exemple 4 : Notes Scolaires

```sql
CREATE TABLE Notes
(
    IdNote INT IDENTITY(1,1) PRIMARY KEY,
    IdEtudiant INT NOT NULL,
    IdMatiere INT NOT NULL,
    Note DECIMAL(4,2) NOT NULL,
    Coefficient DECIMAL(3,2) DEFAULT 1.0,
    DateExamen DATE NOT NULL,
    TypeExamen VARCHAR(20),
    CONSTRAINT CHK_Notes_Note
        CHECK (Note BETWEEN 0 AND 20),
    CONSTRAINT CHK_Notes_Coefficient

        UNIQUE (IdEtudiant, IdMatiere, DateExamen)
);
```

## Contraintes CHECK vs Autres Contraintes

Comparons CHECK avec les autres contraintes :

| Contrainte | But | Exemple |
|------------|-----|---------|
| **PRIMARY KEY** | Identifier uniquement | `IdClient INT PRIMARY KEY` |
| **FOREIGN KEY** | Relation entre tables | `IdClient INT FOREIGN KEY REFERENCES Clients` |
| **UNIQUE** | Valeur unique | `Email VARCHAR(100) UNIQUE` |
| **NOT NULL** | Valeur obligatoire | `Nom VARCHAR(100) NOT NULL` |
| **DEFAULT** | Valeur par défaut | `DateCreation DATE DEFAULT GETDATE()` |
| **CHECK** | Règle métier personnalisée | `Age INT CHECK (Age BETWEEN 18 AND 70)` |

**Quand utiliser CHECK :**
- Pour valider des **plages de valeurs** (prix > 0, age entre 18 et 70)
- Pour valider des **listes fermées** (statut IN ('Actif', 'Inactif'))
- Pour valider des **relations entre colonnes** (DateFin > DateDebut)
- Pour appliquer des **règles métier complexes**

## Limitations des Contraintes CHECK

### 1. Pas de Sous-requêtes

Vous **ne pouvez pas** utiliser de sous-requêtes dans une contrainte CHECK :

```sql
-- ❌ INTERDIT : Sous-requête
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,
    MontantTotal DECIMAL(10,2),
    CONSTRAINT CHK_Commandes_Client
        CHECK (IdClient IN (SELECT IdClient FROM Clients))  -- ERREUR !
);
```

**Solution :** Utilisez une clé étrangère à la place :

```sql
-- ✅ Correct : Clé étrangère
CONSTRAINT FK_Commandes_Clients
    FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
```

### 2. Pas de Fonctions Non-Déterministes (Sauf Quelques Exceptions)

Vous ne pouvez pas utiliser certaines fonctions qui peuvent retourner des valeurs différentes :

```sql
-- ❌ Certaines fonctions interdites
CHECK (DateCreation = NEWID())       -- ERREUR : NEWID() non autorisé
CHECK (Montant = RAND() * 100)       -- ERREUR : RAND() non autorisé
```

**Fonctions autorisées :**
```sql
-- ✅ Autorisé
CHECK (DateEmbauche <= GETDATE())    -- GETDATE() est autorisé
CHECK (Age = DATEDIFF(YEAR, DateNaissance, GETDATE()))  -- DATEDIFF avec GETDATE() autorisé
```

### 3. Performances avec Contraintes Complexes

Des contraintes CHECK trop complexes peuvent ralentir les insertions et mises à jour :

```sql
-- ⚠️ Contrainte complexe à utiliser avec prudence
CHECK (
    (Colonne1 > 0 AND Colonne2 < 100 AND Colonne3 IN ('A', 'B', 'C'))
    OR
    (Colonne1 <= 0 AND Colonne2 >= 100 AND Colonne3 = 'D')
)
```

## Supprimer une Contrainte CHECK

Pour supprimer une contrainte CHECK :

```sql
-- Supprimer par le nom
ALTER TABLE Produits
DROP CONSTRAINT CHK_Produits_Prix;

-- Trouver le nom des contraintes CHECK
SELECT
    tc.CONSTRAINT_NAME,
    tc.TABLE_NAME,
    cc.CHECK_CLAUSE
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS tc
INNER JOIN INFORMATION_SCHEMA.CHECK_CONSTRAINTS cc
    ON tc.CONSTRAINT_NAME = cc.CONSTRAINT_NAME
WHERE tc.TABLE_NAME = 'Produits';
```

## Modifier une Contrainte CHECK

On ne peut pas modifier directement une contrainte CHECK. Il faut la supprimer puis la recréer :

```sql
-- 1. Supprimer l'ancienne contrainte
ALTER TABLE Produits
DROP CONSTRAINT CHK_Produits_Prix;

-- 2. Créer la nouvelle contrainte avec la règle modifiée
ALTER TABLE Produits
ADD CONSTRAINT CHK_Produits_Prix CHECK (Prix >= 0);  -- Modifié de > 0 à >= 0
```

## Désactiver Temporairement les Contraintes

Parfois utile pour des opérations de maintenance :

```sql
-- Désactiver une contrainte spécifique
ALTER TABLE Produits
NOCHECK CONSTRAINT CHK_Produits_Prix;

-- Effectuer vos opérations...

-- Réactiver la contrainte
ALTER TABLE Produits
CHECK CONSTRAINT CHK_Produits_Prix;

-- Désactiver toutes les contraintes CHECK d'une table
ALTER TABLE Produits
NOCHECK CONSTRAINT ALL;

-- Réactiver toutes
ALTER TABLE Produits
CHECK CONSTRAINT ALL;
```

**⚠️ Attention :** Désactiver les contraintes peut permettre l'insertion de données invalides. À utiliser avec précaution.

## Erreurs Courantes et Solutions

### Erreur 1 : Violation de la Contrainte CHECK

```sql
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (1, 'Ordinateur', -899.99, 10);
-- Erreur : The INSERT statement conflicted with the CHECK constraint 'CHK_Produits_Prix'
```

**Solution :** Vérifiez et corrigez la valeur :

```sql
-- Identifier le problème
SELECT -899.99 AS Prix,
       CASE WHEN -899.99 > 0 THEN 'Valide' ELSE 'Invalide' END AS Validation;

-- Correction
INSERT INTO Produits (IdProduit, Nom, Prix, Stock)
VALUES (1, 'Ordinateur', 899.99, 10);
```

### Erreur 2 : Impossible d'Ajouter CHECK sur Données Existantes Invalides

```sql
-- Table avec données invalides
CREATE TABLE Test (Id INT, Age INT);
INSERT INTO Test VALUES (1, -5), (2, 250);

-- ❌ ERREUR : Impossible d'ajouter CHECK
ALTER TABLE Test
ADD CONSTRAINT CHK_Test_Age CHECK (Age BETWEEN 0 AND 120);
-- Erreur : ALTER TABLE statement conflicted with the CHECK constraint
```

**Solution :** Nettoyer les données d'abord :

```sql
-- Identifier les données invalides
SELECT * FROM Test WHERE Age < 0 OR Age > 120;

-- Corriger ou supprimer
UPDATE Test SET Age = 0 WHERE Age < 0;
DELETE FROM Test WHERE Age > 120;

-- Maintenant ajouter la contrainte
ALTER TABLE Test
ADD CONSTRAINT CHK_Test_Age CHECK (Age BETWEEN 0 AND 120);
```

### Erreur 3 : CHECK Trop Restrictif

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    Statut VARCHAR(20),
    CONSTRAINT CHK_Commandes_Statut CHECK (Statut IN ('En attente', 'Livrée'))
);

-- Problème : On veut ajouter un statut 'En cours'
-- ❌ ERREUR : Statut non autorisé
INSERT INTO Commandes VALUES (1, 'En cours');
```

**Solution :** Modifier la contrainte :

```sql
-- Supprimer l'ancienne
ALTER TABLE Commandes
DROP CONSTRAINT CHK_Commandes_Statut;

-- Recréer avec la nouvelle liste
ALTER TABLE Commandes
ADD CONSTRAINT CHK_Commandes_Statut
    CHECK (Statut IN ('En attente', 'En cours', 'Expédiée', 'Livrée'));
```

## Vérifier les Contraintes CHECK

### Lister toutes les contraintes CHECK d'une table

```sql
SELECT
    tc.CONSTRAINT_NAME AS NomContrainte,
    cc.CHECK_CLAUSE AS Condition
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS tc
INNER JOIN INFORMATION_SCHEMA.CHECK_CONSTRAINTS cc
    ON tc.CONSTRAINT_NAME = cc.CONSTRAINT_NAME
WHERE tc.TABLE_NAME = 'Produits'
    AND tc.CONSTRAINT_TYPE = 'CHECK';
```

### Tester une valeur avant insertion

```sql
-- Tester si une valeur respecterait la contrainte
DECLARE @Prix DECIMAL(10,2) = -50.00;

IF @Prix > 0
    PRINT 'La valeur est valide';
ELSE
    PRINT 'La valeur violerait la contrainte CHECK';
```

## Bonnes Pratiques

### 1. Toujours Nommer Vos Contraintes

```sql
-- ✅ BON : Contrainte nommée
CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0)

-- ❌ À éviter : Contrainte anonyme
CHECK (Prix > 0)
```

### 2. Convention de Nommage Cohérente

- `CHK_NomTable_NomColonne`
- `CK_NomTable_NomColonne`
- `CHK_NomTable_Description` (pour contraintes multi-colonnes)

**Exemples :**
- `CHK_Produits_Prix`
- `CHK_Employes_Age`
- `CHK_Reservations_Dates`

### 3. Documenter les Règles Complexes

```sql
-- Règle métier : Un employé cadre doit avoir un salaire >= 3000€
-- Un employé non-cadre doit avoir un salaire >= 1800€
CONSTRAINT CHK_Employes_Salaire
    CHECK ((EstCadre = 0 AND Salaire >= 1800) OR (EstCadre = 1 AND Salaire >= 3000))
```

### 4. Privilégier la Simplicité

```sql
-- ✅ BON : Simple et lisible
CHECK (Age >= 18)
CHECK (Prix > 0)
CHECK (Statut IN ('Actif', 'Inactif'))

-- ⚠️ À éviter si possible : Trop complexe
CHECK ((Col1 > 0 AND Col2 < 100) OR (Col1 <= 0 AND Col2 >= 100 AND Col3 = 'X'))
```

### 5. Combiner avec NOT NULL si Nécessaire

```sql
-- Valeur obligatoire ET dans une plage
Age INT NOT NULL CHECK (Age BETWEEN 18 AND 70)

-- Valeur optionnelle mais validée si fournie
Email VARCHAR(150) CHECK (Email LIKE '%@%.%')  -- NULL autorisé
```

### 6. Utiliser CHECK pour les Valeurs Métier, FK pour les Relations

```sql
-- ✅ CHECK pour valider le statut (liste fermée)
Statut VARCHAR(20) CHECK (Statut IN ('Actif', 'Inactif'))

-- ✅ FOREIGN KEY pour référencer une autre table
IdClient INT FOREIGN KEY REFERENCES Clients(IdClient)

-- ❌ Pas de CHECK avec sous-requête
-- CHECK (IdClient IN (SELECT IdClient FROM Clients))  -- Utiliser FK !
```

### 7. Tester Vos Contraintes

Après avoir créé une contrainte, testez-la :

```sql
-- Créer la contrainte
ALTER TABLE Produits
ADD CONSTRAINT CHK_Produits_Prix CHECK (Prix > 0);

-- Tester avec une valeur invalide (doit échouer)
INSERT INTO Produits (IdProduit, Nom, Prix)
VALUES (999, 'Test', -10.00);  -- Doit générer une erreur

-- Si ça passe, votre contrainte ne fonctionne pas !
```

## Messages d'Erreur Personnalisés (Limitation)

SQL Server ne permet pas de messages d'erreur personnalisés dans les contraintes CHECK. Le message sera générique :

```
The INSERT statement conflicted with the CHECK constraint 'CHK_Produits_Prix'
```

**Alternative :** Utilisez des triggers pour des messages plus explicites (sujet avancé).

## Résumé

| Aspect | Description |
|--------|-------------|
| **Définition** | Valide les données selon des règles personnalisées |
| **Syntaxe simple** | `CHECK (Age > 18)` |
| **Syntaxe nommée** | `CONSTRAINT CHK_Table_Colonne CHECK (...)` |
| **Types de validation** | Plages, listes, patterns, logique, multi-colonnes |
| **Nombre par table** | Plusieurs contraintes CHECK possibles |
| **NULL** | NULL n'est pas vérifié par CHECK (NULL passe toujours) |
| **Limitations** | Pas de sous-requêtes, pas de fonctions non-déterministes |
| **Performance** | Impact minimal sauf contraintes très complexes |
| **Désactivation** | Possible avec NOCHECK (temporairement) |

## Points Clés à Retenir

1. ✅ CHECK valide les données selon des **règles métier personnalisées**
2. 📝 Utilisez CHECK pour : plages de valeurs, listes, patterns, relations entre colonnes
3. 🚫 Les **NULL** ne sont **pas** vérifiés par CHECK (ils passent toujours)
4. 🔒 CHECK applique la validation **au niveau base de données** (une seule source de vérité)
5. ⚠️ **Pas de sous-requêtes** dans CHECK (utilisez FOREIGN KEY pour les relations)
6. 📝 **Nommez toujours** vos contraintes : `CHK_Table_Colonne`
7. ✅ Combinez avec `NOT NULL` si la valeur est obligatoire
8. 🎯 Privilégiez des contraintes **simples et lisibles**

## Prochaine Étape

Maintenant que vous maîtrisez CHECK, explorez les autres contraintes complémentaires :
- **DEFAULT** : définir des valeurs par défaut
- **NOT NULL** : rendre des colonnes obligatoires

Les contraintes CHECK sont essentielles pour garantir la **qualité** et la **cohérence** de vos données selon vos règles métier ! 🎯
