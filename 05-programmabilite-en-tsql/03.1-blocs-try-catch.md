# 5.3.1 Blocs TRY ... CATCH

## Introduction

Dans la vie quotidienne, nous anticipons constamment les problèmes : "**Essaie** de démarrer la voiture, **si ça ne marche pas**, appelle un dépanneur". En programmation T-SQL, nous avons besoin de la même capacité à **gérer les erreurs** de manière élégante et contrôlée.

Les blocs **TRY ... CATCH** sont le mécanisme moderne de gestion des erreurs en T-SQL (introduit dans SQL Server 2005). Ils permettent à votre code de **tenter** une opération et de **réagir intelligemment** si une erreur se produit, au lieu de simplement planter.

Dans cette section, nous allons découvrir comment protéger votre code contre les erreurs et créer des applications robustes et fiables.

---

## 1. Pourquoi gérer les erreurs ?

### Le problème sans gestion d'erreurs

Imaginez ce code simple :

```sql
DECLARE @Resultat INT;
SET @Resultat = 100 / 0;  -- Division par zéro !
PRINT 'Le résultat est : ' + CAST(@Resultat AS VARCHAR);
PRINT 'Programme terminé';
```

**Que se passe-t-il ?**
- SQL Server génère une erreur : "Divide by zero error"
- L'exécution s'arrête **immédiatement**
- Les instructions suivantes ne sont **jamais exécutées**
- L'utilisateur voit un message d'erreur cryptique

### Avec gestion d'erreurs (TRY ... CATCH)

```sql
DECLARE @Resultat INT;

BEGIN TRY
    SET @Resultat = 100 / 0;  -- Division par zéro !
    PRINT 'Le résultat est : ' + CAST(@Resultat AS VARCHAR);
END TRY
BEGIN CATCH
    PRINT 'Erreur détectée : impossible de diviser par zéro';
    PRINT 'Le programme continue normalement';
END CATCH

PRINT 'Programme terminé avec succès';
```

**Résultat :**
```
Erreur détectée : impossible de diviser par zéro
Le programme continue normalement
Programme terminé avec succès
```

Le programme **ne plante pas** et peut continuer à fonctionner !

## 2. Concept de base de TRY ... CATCH

### Qu'est-ce que TRY ... CATCH ?

**TRY ... CATCH** est une structure qui permet de :
1. **Essayer** (TRY) d'exécuter du code potentiellement risqué
2. **Attraper** (CATCH) les erreurs qui se produisent
3. **Gérer** ces erreurs de manière contrôlée
4. **Continuer** l'exécution du programme

### Analogie

Pensez à un acrobate avec un filet de sécurité :
- **TRY** = L'acrobate tente un saut périlleux (risqué)
- **CATCH** = Si l'acrobate tombe, le filet le rattrape (gestion de l'erreur)
- Sans filet (sans CATCH), une chute serait catastrophique
- Avec filet (avec CATCH), il peut se relever et continuer le spectacle

---

## 3. Syntaxe de base

### Structure

```sql
BEGIN TRY
    -- Code à essayer (potentiellement risqué)
    -- Toutes les instructions que vous voulez protéger
END TRY
BEGIN CATCH
    -- Code à exécuter EN CAS D'ERREUR
    -- Gestion de l'erreur, messages, logging, etc.
END CATCH
```

### Comment ça fonctionne ?

1. SQL Server exécute le code dans le bloc **TRY**
2. **Si aucune erreur** ne se produit :
   - Le bloc TRY se termine normalement
   - Le bloc CATCH est **ignoré**
   - L'exécution continue après le END CATCH
3. **Si une erreur** se produit dans TRY :
   - L'exécution du bloc TRY s'arrête immédiatement
   - Le contrôle passe au bloc **CATCH**
   - Le code dans CATCH est exécuté
   - Puis l'exécution continue après le END CATCH

### Schéma de fonctionnement

```
BEGIN TRY
    Instruction 1  ────► Exécutée
    Instruction 2  ────► Exécutée
    Instruction 3  ────► ERREUR ! ──────┐
    Instruction 4  ─X─► Ignorée         │
END TRY                                 │
                                        │
BEGIN CATCH                             │
    Gestion erreur ◄────────────────────┘
END CATCH

Suite du programme ────► Exécutée
```

## 4. Premier exemple simple

### Division sécurisée

```sql
DECLARE @Numerateur INT = 100;
DECLARE @Denominateur INT = 0;
DECLARE @Resultat DECIMAL(10,2);

BEGIN TRY
    SET @Resultat = @Numerateur / @Denominateur;
    PRINT 'Résultat : ' + CAST(@Resultat AS VARCHAR);
END TRY
BEGIN CATCH
    PRINT 'Erreur : Division par zéro impossible';
    PRINT 'Veuillez fournir un dénominateur différent de zéro';
END CATCH

PRINT 'Fin du calcul';
```

**Résultat :**
```
Erreur : Division par zéro impossible
Veuillez fournir un dénominateur différent de zéro
Fin du calcul
```

### Insertion sécurisée

```sql
BEGIN TRY
    -- Essayer d'insérer un employé
    INSERT INTO Employes (EmployeID, Nom, Email)
    VALUES (1, 'Dupont', 'dupont@email.com');

    PRINT 'Employé inséré avec succès';
END TRY
BEGIN CATCH
    -- Si l'ID existe déjà (violation de clé primaire)
    PRINT 'Erreur : Impossible d''insérer l''employé';
    PRINT 'L''ID existe peut-être déjà ou l''email est invalide';
END CATCH
```

## 5. Règles importantes

### Règle 1 : BEGIN TRY et BEGIN CATCH doivent être dans le même batch

**❌ Incorrect :**
```sql
BEGIN TRY
    SELECT 1;
END TRY
GO  -- Erreur ! GO sépare les batches

BEGIN CATCH
    PRINT 'Erreur';
END CATCH
```

**✅ Correct :**
```sql
BEGIN TRY
    SELECT 1;
END TRY
BEGIN CATCH
    PRINT 'Erreur';
END CATCH
GO
```

### Règle 2 : TRY doit toujours être suivi de CATCH

**❌ Incorrect :**
```sql
BEGIN TRY
    SELECT 1;
END TRY
-- CATCH manquant !
```

**✅ Correct :**
```sql
BEGIN TRY
    SELECT 1;
END TRY
BEGIN CATCH
    PRINT 'Erreur';
END CATCH
```

### Règle 3 : Le bloc CATCH ne capture que les erreurs du bloc TRY

```sql
BEGIN TRY
    SELECT 1 / 0;  -- Erreur capturée
END TRY
BEGIN CATCH
    PRINT 'Erreur capturée';
END CATCH

SELECT 1 / 0;  -- Erreur NON capturée (en dehors du TRY)
```

## 6. Types d'erreurs capturées

### Erreurs capturées par CATCH

TRY ... CATCH capture la plupart des erreurs d'exécution :

1. **Erreurs arithmétiques**
   - Division par zéro
   - Dépassement de capacité (overflow)

2. **Violations de contraintes**
   - Clé primaire (PRIMARY KEY)
   - Clé étrangère (FOREIGN KEY)
   - Contrainte UNIQUE
   - Contrainte CHECK

3. **Erreurs de conversion**
   - Conversion de type invalide
   - FORMAT incorrect

4. **Erreurs de données à l'exécution**
   - Dépassement de longueur (« String or binary data would be truncated »)
   - Valeur hors de la plage du type

> Remarque : une **colonne** ou un **objet introuvable** est en général une erreur de **compilation** (liaison), donc **non** capturable par `TRY...CATCH` dans le même batch (voir « Erreurs NON capturées » ci-dessous).

### Exemple avec différents types d'erreurs

```sql
-- Erreur de conversion
BEGIN TRY
    DECLARE @Date DATE;
    SET @Date = CAST('Pas une date' AS DATE);
END TRY
BEGIN CATCH
    PRINT 'Erreur de conversion de date';
END CATCH

-- Violation de contrainte
BEGIN TRY
    INSERT INTO Employes (EmployeID, Nom)
    VALUES (NULL, 'Dupont');  -- NULL dans une colonne NOT NULL
END TRY
BEGIN CATCH
    PRINT 'Violation de contrainte : EmployeID ne peut pas être NULL';
END CATCH
```

### Erreurs NON capturées par CATCH

Certaines erreurs graves ne sont **pas** capturées :

1. **Erreurs de compilation**
   - Erreurs de syntaxe
   - Objets inexistants (si détecté à la compilation)

2. **Erreurs de connexion**
   - Perte de connexion réseau
   - Arrêt du serveur

3. **Erreurs fatales**
   - Corruption de base de données
   - Manque de mémoire critique

**Exemple d'erreur NON capturée :**
```sql
BEGIN TRY
    SELCT * FROM Employes;  -- Erreur de syntaxe (SELCT au lieu de SELECT)
END TRY
BEGIN CATCH
    PRINT 'Erreur';  -- Ne sera JAMAIS exécuté
END CATCH
```

L'erreur de syntaxe empêche le code de compiler, donc TRY ... CATCH ne peut pas fonctionner.

## 7. Obtenir des informations sur l'erreur

### Les fonctions d'erreur

Dans le bloc CATCH, vous pouvez utiliser des **fonctions d'erreur** pour obtenir des détails :

| Fonction | Description | Type retourné |
|----------|-------------|---------------|
| `ERROR_NUMBER()` | Numéro de l'erreur | INT |
| `ERROR_MESSAGE()` | Message d'erreur | NVARCHAR |
| `ERROR_SEVERITY()` | Niveau de gravité (11-25) | INT |
| `ERROR_STATE()` | État de l'erreur | INT |
| `ERROR_LINE()` | Numéro de ligne où l'erreur s'est produite | INT |
| `ERROR_PROCEDURE()` | Nom de la procédure (si applicable) | NVARCHAR |

### Exemple complet avec informations d'erreur

```sql
BEGIN TRY
    -- Code risqué
    DECLARE @Resultat INT;
    SET @Resultat = 100 / 0;
END TRY
BEGIN CATCH
    -- Afficher les détails de l'erreur
    PRINT 'Une erreur s''est produite :';
    PRINT '  Numéro d''erreur : ' + CAST(ERROR_NUMBER() AS VARCHAR);
    PRINT '  Message : ' + ERROR_MESSAGE();
    PRINT '  Gravité : ' + CAST(ERROR_SEVERITY() AS VARCHAR);
    PRINT '  État : ' + CAST(ERROR_STATE() AS VARCHAR);
    PRINT '  Ligne : ' + CAST(ERROR_LINE() AS VARCHAR);
END CATCH
```

**Résultat :**
```
Une erreur s'est produite :
  Numéro d'erreur : 8134
  Message : Divide by zero error encountered.
  Gravité : 16
  État : 1
  Ligne : 4
```

### Exemple structuré

```sql
BEGIN TRY
    -- Tentative d'insertion
    INSERT INTO Employes (EmployeID, Nom, Email)
    VALUES (1, 'Martin', 'martin@email.com');

    PRINT 'Insertion réussie';
END TRY
BEGIN CATCH
    -- Structure claire des informations d'erreur
    DECLARE @ErreurNum INT = ERROR_NUMBER();
    DECLARE @ErreurMsg NVARCHAR(4000) = ERROR_MESSAGE();
    DECLARE @ErreurLigne INT = ERROR_LINE();

    -- Afficher de manière formatée
    PRINT '═══════════════════════════════════════';
    PRINT 'ERREUR DÉTECTÉE';
    PRINT '═══════════════════════════════════════';
    PRINT 'Code erreur    : ' + CAST(@ErreurNum AS VARCHAR);
    PRINT 'Description    : ' + @ErreurMsg;
    PRINT 'Ligne          : ' + CAST(@ErreurLigne AS VARCHAR);
    PRINT '═══════════════════════════════════════';
END CATCH
```

## 8. Exemples pratiques

### Exemple 1 : Validation d'insertion

```sql
CREATE PROCEDURE AjouterClient
    @ClientID INT,
    @Nom VARCHAR(100),
    @Email VARCHAR(100)
AS
BEGIN
    BEGIN TRY
        -- Validation manuelle
        IF @Nom IS NULL OR @Nom = ''
        BEGIN
            RAISERROR('Le nom est obligatoire', 16, 1);
        END

        IF @Email NOT LIKE '%@%'
        BEGIN
            RAISERROR('Format email invalide', 16, 1);
        END

        -- Tentative d'insertion
        INSERT INTO Clients (ClientID, Nom, Email)
        VALUES (@ClientID, @Nom, @Email);

        PRINT 'Client ajouté avec succès (ID: ' + CAST(@ClientID AS VARCHAR) + ')';
    END TRY
    BEGIN CATCH
        -- Gestion des erreurs
        IF ERROR_NUMBER() = 2627  -- Violation de clé primaire
        BEGIN
            PRINT 'Erreur : Un client avec cet ID existe déjà';
        END
        ELSE IF ERROR_NUMBER() = 2601  -- Violation de contrainte UNIQUE
        BEGIN
            PRINT 'Erreur : Cet email est déjà utilisé';
        END
        ELSE
        BEGIN
            -- Autres erreurs
            PRINT 'Erreur : ' + ERROR_MESSAGE();
        END
    END CATCH
END
```

### Exemple 2 : Transaction sécurisée

```sql
BEGIN TRY
    BEGIN TRANSACTION;

    -- Opération 1 : Débiter un compte
    UPDATE Comptes
    SET Solde = Solde - 100
    WHERE CompteID = 1;

    -- Opération 2 : Créditer un autre compte
    UPDATE Comptes
    SET Solde = Solde + 100
    WHERE CompteID = 2;

    -- Si tout va bien, valider
    COMMIT TRANSACTION;
    PRINT 'Transfert réussi';
END TRY
BEGIN CATCH
    -- En cas d'erreur, annuler tout
    IF @@TRANCOUNT > 0
        ROLLBACK TRANSACTION;

    PRINT 'Erreur : Le transfert a échoué';
    PRINT 'Détail : ' + ERROR_MESSAGE();
    PRINT 'Toutes les opérations ont été annulées';
END CATCH
```

### Exemple 3 : Traitement par lots avec gestion d'erreurs

```sql
DECLARE @Compteur INT = 1;
DECLARE @ErreurCount INT = 0;
DECLARE @SuccesCount INT = 0;

WHILE @Compteur <= 100
BEGIN
    BEGIN TRY
        -- Traiter un enregistrement
        UPDATE Commandes
        SET Statut = 'Traité'
        WHERE CommandeID = @Compteur;

        -- Si le traitement réussit
        IF @@ROWCOUNT > 0
            SET @SuccesCount = @SuccesCount + 1;
    END TRY
    BEGIN CATCH
        -- Si une erreur se produit, continuer quand même
        SET @ErreurCount = @ErreurCount + 1;

        -- Logger l'erreur
        INSERT INTO LogErreurs (CommandeID, Message, DateErreur)
        VALUES (@Compteur, ERROR_MESSAGE(), GETDATE());
    END CATCH

    SET @Compteur = @Compteur + 1;
END

-- Rapport final
PRINT 'Traitement terminé :';
PRINT '  Succès : ' + CAST(@SuccesCount AS VARCHAR);
PRINT '  Erreurs : ' + CAST(@ErreurCount AS VARCHAR);
```

### Exemple 4 : Logging automatique des erreurs

```sql
-- Table pour stocker les erreurs
CREATE TABLE LogErreurs (
    LogID INT IDENTITY(1,1) PRIMARY KEY,
    NumeroErreur INT,
    MessageErreur NVARCHAR(4000),
    Severite INT,
    LigneErreur INT,
    ProcedureErreur NVARCHAR(128),
    DateErreur DATETIME DEFAULT GETDATE()
);
GO

-- Procédure avec logging
CREATE PROCEDURE TraiterCommande
    @CommandeID INT
AS
BEGIN
    BEGIN TRY
        -- Traitement risqué
        UPDATE Commandes
        SET Statut = 'Traité',
            DateTraitement = GETDATE()
        WHERE CommandeID = @CommandeID;

        -- Calculs complexes qui peuvent échouer
        DECLARE @Total DECIMAL(10,2);
        SELECT @Total = SUM(PrixUnitaire * Quantite) / COUNT(*)
        FROM DetailsCommande
        WHERE CommandeID = @CommandeID;

        PRINT 'Commande traitée avec succès';
    END TRY
    BEGIN CATCH
        -- Logger l'erreur dans la table
        INSERT INTO LogErreurs (
            NumeroErreur,
            MessageErreur,
            Severite,
            LigneErreur,
            ProcedureErreur
        )
        VALUES (
            ERROR_NUMBER(),
            ERROR_MESSAGE(),
            ERROR_SEVERITY(),
            ERROR_LINE(),
            ERROR_PROCEDURE()
        );

        -- Informer l'utilisateur
        PRINT 'Erreur lors du traitement de la commande ' + CAST(@CommandeID AS VARCHAR);
        PRINT 'L''erreur a été enregistrée dans les logs';
    END CATCH
END
```

## 9. TRY ... CATCH imbriqués

Vous pouvez imbriquer des blocs TRY ... CATCH les uns dans les autres.

### Exemple simple

```sql
BEGIN TRY
    PRINT 'Bloc TRY externe';

    BEGIN TRY
        PRINT 'Bloc TRY interne';
        SELECT 1 / 0;  -- Erreur
    END TRY
    BEGIN CATCH
        PRINT 'CATCH interne : Erreur capturée';
    END CATCH

    PRINT 'Continuation du TRY externe';
END TRY
BEGIN CATCH
    PRINT 'CATCH externe : Erreur capturée';
END CATCH
```

**Résultat :**
```
Bloc TRY externe
Bloc TRY interne
CATCH interne : Erreur capturée
Continuation du TRY externe
```

### Exemple pratique : Gestion granulaire

```sql
BEGIN TRY
    -- Opération principale
    PRINT 'Début du traitement principal';

    -- Sous-opération 1 (protégée)
    BEGIN TRY
        INSERT INTO Clients (Nom) VALUES ('Client1');
        PRINT 'Client ajouté';
    END TRY
    BEGIN CATCH
        PRINT 'Avertissement : Impossible d''ajouter le client';
        -- On continue quand même
    END CATCH

    -- Sous-opération 2 (protégée)
    BEGIN TRY
        INSERT INTO Commandes (ClientID, Montant) VALUES (999, 100);
        PRINT 'Commande ajoutée';
    END TRY
    BEGIN CATCH
        PRINT 'Avertissement : Impossible d''ajouter la commande';
        -- On continue quand même
    END CATCH

    PRINT 'Traitement principal terminé';
END TRY
BEGIN CATCH
    -- Erreur fatale au niveau principal
    PRINT 'ERREUR CRITIQUE : ' + ERROR_MESSAGE();
END CATCH
```

## 10. Relancer une erreur (THROW)

### Pourquoi relancer une erreur ?

Parfois, vous voulez :
1. Capturer l'erreur pour la logger
2. Puis **relancer** l'erreur pour que le code appelant puisse aussi la gérer

### Syntaxe avec THROW

```sql
BEGIN TRY
    -- Code risqué
    SELECT 1 / 0;
END TRY
BEGIN CATCH
    -- Logger l'erreur
    PRINT 'Erreur loggée : ' + ERROR_MESSAGE();

    -- Relancer l'erreur
    THROW;  -- Relance la même erreur
END CATCH
```

**Note :** THROW sans paramètres ne peut être utilisé **que dans un bloc CATCH**.

### Exemple pratique : Logger puis relancer

```sql
CREATE PROCEDURE CalculerStats
    @Valeur INT
AS
BEGIN
    BEGIN TRY
        DECLARE @Resultat INT;
        SET @Resultat = 1000 / @Valeur;

        PRINT 'Résultat : ' + CAST(@Resultat AS VARCHAR);
    END TRY
    BEGIN CATCH
        -- Logger l'erreur
        INSERT INTO LogErreurs (MessageErreur, DateErreur)
        VALUES (ERROR_MESSAGE(), GETDATE());

        -- Relancer pour que l'appelant soit au courant
        THROW;
    END CATCH
END
GO

-- Appel de la procédure
BEGIN TRY
    EXEC CalculerStats @Valeur = 0;
END TRY
BEGIN CATCH
    PRINT 'L''application a détecté une erreur dans CalculerStats';
    PRINT 'Erreur : ' + ERROR_MESSAGE();
END CATCH
```

## 11. TRY ... CATCH vs ancienne méthode (@@ERROR)

### Ancienne méthode avec @@ERROR (avant SQL Server 2005)

```sql
-- ❌ Méthode obsolète
INSERT INTO Employes (EmployeID, Nom) VALUES (1, 'Dupont');

IF @@ERROR <> 0
BEGIN
    PRINT 'Erreur lors de l''insertion';
END
```

**Problèmes :**
- @@ERROR est réinitialisé après **chaque instruction**
- Difficile à gérer pour plusieurs opérations
- Moins lisible
- Pas de détails sur l'erreur

### Méthode moderne avec TRY ... CATCH

```sql
-- ✅ Méthode moderne
BEGIN TRY
    INSERT INTO Employes (EmployeID, Nom) VALUES (1, 'Dupont');
    PRINT 'Insertion réussie';
END TRY
BEGIN CATCH
    PRINT 'Erreur : ' + ERROR_MESSAGE();
END CATCH
```

**Avantages :**
- Structure claire et lisible
- Gestion centralisée des erreurs
- Accès à des informations détaillées
- Fonctionne pour plusieurs instructions

## 12. Bonnes pratiques

### ✅ À FAIRE

1. **Toujours utiliser TRY ... CATCH pour les opérations risquées**
   - Insertions, mises à jour, suppressions
   - Conversions de types
   - Calculs arithmétiques
   - Accès à des objets externes

2. **Logger les erreurs**
   ```sql
   BEGIN CATCH
       INSERT INTO LogErreurs (...) VALUES (...);
   END CATCH
   ```

3. **Annuler les transactions en cas d'erreur**
   ```sql
   BEGIN CATCH
       IF @@TRANCOUNT > 0
           ROLLBACK TRANSACTION;
   END CATCH
   ```

4. **Fournir des messages d'erreur clairs**
   ```sql
   BEGIN CATCH
       PRINT 'Erreur : Impossible de traiter la commande';
       PRINT 'Raison : ' + ERROR_MESSAGE();
   END CATCH
   ```

5. **Tester tous les scénarios d'erreur**
   - Erreurs prévisibles
   - Cas limites
   - Erreurs inattendues

### ❌ À ÉVITER

1. **Ne pas ignorer silencieusement les erreurs**
   ```sql
   -- ❌ Mauvais : Bloc CATCH vide
   BEGIN CATCH
       -- Rien ! L'erreur est perdue
   END CATCH
   ```

2. **Ne pas avoir un bloc TRY trop large**
   ```sql
   -- ❌ Trop large : difficile de savoir quelle opération a échoué
   BEGIN TRY
       Operation1();
       Operation2();
       Operation3();
       -- ... 50 autres opérations
   END TRY
   ```

3. **Ne pas oublier de vérifier @@TRANCOUNT**
   ```sql
   -- ❌ Dangereux : ne vérifie pas si une transaction est ouverte
   BEGIN CATCH
       ROLLBACK TRANSACTION;  -- Peut échouer si pas de transaction
   END CATCH

   -- ✅ Correct
   BEGIN CATCH
       IF @@TRANCOUNT > 0
           ROLLBACK TRANSACTION;
   END CATCH
   ```

4. **Ne pas utiliser TRY ... CATCH pour la logique métier**
   ```sql
   -- ❌ Mauvais usage : utiliser les erreurs pour le contrôle de flux
   BEGIN TRY
       SELECT * FROM Clients WHERE ClientID = @ID;
   END TRY
   BEGIN CATCH
       -- Si le client n'existe pas...
   END CATCH

   -- ✅ Meilleur : utiliser IF
   IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ID)
       SELECT * FROM Clients WHERE ClientID = @ID;
   ELSE
       PRINT 'Client introuvable';
   ```

## 13. Modèle de code réutilisable

Voici un modèle de procédure stockée avec gestion d'erreurs complète :

```sql
CREATE PROCEDURE [dbo].[NomProcedure]
    @Parametre1 INT,
    @Parametre2 VARCHAR(100)
AS
BEGIN
    -- Configuration
    SET NOCOUNT ON;

    -- Variables
    DECLARE @ErreurNum INT;
    DECLARE @ErreurMsg NVARCHAR(4000);

    BEGIN TRY
        -- Validation des paramètres
        IF @Parametre1 IS NULL
            RAISERROR('Le paramètre1 est obligatoire', 16, 1);

        -- Début de la transaction
        BEGIN TRANSACTION;

        -- Opérations principales
        -- ... votre code ici ...

        -- Valider la transaction
        COMMIT TRANSACTION;

        -- Message de succès
        PRINT 'Opération réussie';
        RETURN 0;  -- Code de retour : succès

    END TRY
    BEGIN CATCH
        -- Annuler la transaction si ouverte
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;

        -- Capturer les informations d'erreur
        SET @ErreurNum = ERROR_NUMBER();
        SET @ErreurMsg = ERROR_MESSAGE();

        -- Logger l'erreur
        INSERT INTO LogErreurs (
            NumeroErreur,
            MessageErreur,
            ProcedureErreur,
            DateErreur
        )
        VALUES (
            @ErreurNum,
            @ErreurMsg,
            'NomProcedure',
            GETDATE()
        );

        -- Afficher l'erreur
        PRINT 'ERREUR dans NomProcedure';
        PRINT 'Numéro : ' + CAST(@ErreurNum AS VARCHAR);
        PRINT 'Message : ' + @ErreurMsg;

        RETURN -1;  -- Code de retour : erreur

    END CATCH
END
```

## Résumé

- **TRY ... CATCH** est le mécanisme moderne de gestion d'erreurs en T-SQL
- Structure : `BEGIN TRY ... END TRY BEGIN CATCH ... END CATCH`
- Le bloc **TRY** contient le code risqué à essayer
- Le bloc **CATCH** s'exécute **uniquement en cas d'erreur** dans TRY
- Les **fonctions d'erreur** (ERROR_NUMBER, ERROR_MESSAGE, etc.) fournissent des détails
- TRY ... CATCH capture les erreurs **d'exécution**, pas les erreurs de compilation
- Utilisez **THROW** pour relancer une erreur après l'avoir traitée
- Toujours **annuler les transactions** en cas d'erreur avec ROLLBACK
- **Logger les erreurs** pour faciliter le débogage et la maintenance
- TRY ... CATCH peut être **imbriqué** pour une gestion granulaire
- Préférez TRY ... CATCH à l'ancienne méthode @@ERROR

Les blocs TRY ... CATCH sont essentiels pour créer des applications robustes et fiables. Ils permettent à votre code de gérer les erreurs avec élégance au lieu de planter de manière catastrophique. Dans les sections suivantes, nous découvrirons les fonctions d'erreur en détail et comment générer nos propres erreurs personnalisées.
