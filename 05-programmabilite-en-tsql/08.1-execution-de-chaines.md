# 5.8.1 Exécution de chaînes (EXEC ou sp_executesql)

## Introduction au SQL Dynamique

Jusqu'à présent, nous avons écrit du SQL **statique** : le code SQL est connu et fixé à l'avance. Mais parfois, vous avez besoin de construire et d'exécuter du SQL **dynamiquement**, c'est-à-dire de générer le code SQL au moment de l'exécution.

### Qu'est-ce que le SQL dynamique ?

Le **SQL dynamique** (ou Dynamic SQL) consiste à :
1. Construire une requête SQL sous forme de **chaîne de caractères**
2. **Exécuter** cette chaîne comme si c'était du code SQL

### Analogie pour comprendre

Imaginez que vous écrivez une lettre :

**Lettre statique** :
```
Cher Monsieur Dupont,
Nous vous remercions pour votre commande.
Cordialement,
```
Le texte est fixe et connu à l'avance.

**Lettre dynamique** :
```
"Cher " + [nom du client] + ",
Nous vous remercions pour votre commande de " + [produit] + ".
Cordialement,"
```
Le contenu est généré au moment de l'envoi selon les informations disponibles.

De la même manière, le SQL dynamique construit des requêtes "à la volée" selon les besoins.

## Pourquoi utiliser le SQL dynamique ?

### Cas d'usage 1 : Nom de table ou de colonne variable

Vous ne pouvez pas utiliser de variable pour un nom de table ou de colonne en SQL statique :

```sql
-- ❌ CECI NE FONCTIONNE PAS
DECLARE @NomTable VARCHAR(50) = 'Clients';
SELECT * FROM @NomTable;  -- ERREUR : Must declare the table variable "@NomTable"

DECLARE @NomColonne VARCHAR(50) = 'Nom';
SELECT @NomColonne FROM Clients;  -- Ne retourne pas la colonne, mais le texte "Nom"
```

**Solution** : SQL dynamique

```sql
-- ✅ AVEC SQL DYNAMIQUE, ÇA FONCTIONNE
DECLARE @NomTable VARCHAR(50) = 'Clients';
DECLARE @SQL NVARCHAR(MAX);

SET @SQL = 'SELECT * FROM ' + @NomTable;
EXEC(@SQL);  -- Exécute la chaîne comme du SQL
```

### Cas d'usage 2 : Construire des requêtes complexes selon des conditions

```sql
-- Construire une requête de recherche selon les filtres fournis
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @Ville VARCHAR(50) = NULL;
DECLARE @AgeMin INT = NULL;

DECLARE @SQL NVARCHAR(MAX) = 'SELECT * FROM Clients WHERE 1=1';

IF @Nom IS NOT NULL
    SET @SQL = @SQL + ' AND Nom = ''' + @Nom + '''';

IF @Ville IS NOT NULL
    SET @SQL = @SQL + ' AND Ville = ''' + @Ville + '''';

IF @AgeMin IS NOT NULL
    SET @SQL = @SQL + ' AND Age >= ' + CAST(@AgeMin AS VARCHAR);

EXEC(@SQL);
```

### Cas d'usage 3 : Génération de scripts automatisés

Créer automatiquement des requêtes pour toutes les tables d'une base :

```sql
-- Générer un SELECT COUNT(*) pour chaque table
DECLARE @SQL NVARCHAR(MAX) = '';

SELECT @SQL = @SQL +
    'SELECT ''' + TABLE_NAME + ''' AS TableName, COUNT(*) AS NbLignes FROM ' + TABLE_NAME + ';' + CHAR(13)
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_TYPE = 'BASE TABLE';

EXEC(@SQL);
```

## Les deux méthodes d'exécution

SQL Server offre deux façons principales d'exécuter du SQL dynamique :

1. **EXEC** (ou EXECUTE) - Méthode simple
2. **sp_executesql** - Méthode avancée avec paramètres

Voyons chacune en détail.

## Méthode 1 : EXEC (EXECUTE)

### Syntaxe de base

```sql
EXEC(chaîne_SQL)
-- ou
EXECUTE(chaîne_SQL)
```

**EXEC** et **EXECUTE** sont exactement la même chose. EXEC est juste un raccourci.

### Exemple simple

```sql
-- Construire la requête
DECLARE @SQL NVARCHAR(100);
SET @SQL = 'SELECT * FROM Clients WHERE ClientID = 1';

-- L'exécuter
EXEC(@SQL);
```

**Ce qui se passe** :
1. La chaîne `@SQL` contient du texte SQL
2. `EXEC(@SQL)` prend cette chaîne et l'exécute comme si vous l'aviez tapée directement

### Construction de requêtes avec EXEC

```sql
-- Exemple avec un nom de table variable
DECLARE @TableName NVARCHAR(100) = 'Employes';
DECLARE @SQL NVARCHAR(500);

-- Construire la requête
SET @SQL = 'SELECT TOP 10 * FROM ' + @TableName + ' ORDER BY Nom';

-- Afficher la requête (utile pour déboguer)
PRINT @SQL;
-- Résultat : SELECT TOP 10 * FROM Employes ORDER BY Nom

-- Exécuter
EXEC(@SQL);
```

### Concaténation de variables dans EXEC

```sql
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @Prenom VARCHAR(50) = 'Jean';
DECLARE @SQL NVARCHAR(500);

-- Construire la requête avec les valeurs
SET @SQL = 'SELECT * FROM Clients WHERE Nom = ''' + @Nom + ''' AND Prenom = ''' + @Prenom + '''';

-- Afficher pour comprendre
PRINT @SQL;
-- Résultat : SELECT * FROM Clients WHERE Nom = 'Dupont' AND Prenom = 'Jean'
--                                                    ↑↑         ↑↑          ↑↑
--                                                    Notez les apostrophes simples !

EXEC(@SQL);
```

### Important : Les apostrophes dans les chaînes

En SQL, les chaînes de caractères sont entourées d'apostrophes simples `'`. Pour inclure une apostrophe dans une chaîne, il faut la **doubler** : `''`

```sql
-- Pour obtenir cette requête finale :
-- SELECT * FROM Clients WHERE Nom = 'Dupont'
--                                   ↑      ↑
--                                   Ces apostrophes font partie du SQL

-- Vous devez écrire :
SET @SQL = 'SELECT * FROM Clients WHERE Nom = ''' + @Nom + '''';
--                                              ↑↑        ↑↑
--                                              Apostrophes doublées

-- Décomposition :
-- '                     → Début de la chaîne
-- SELECT * FROM...      → Début du SQL
-- ''                    → Une apostrophe dans le résultat
-- ' + @Nom + '          → Concaténation de la variable
-- ''                    → Une apostrophe dans le résultat
-- '                     → Fin de la chaîne
```

### Exemple avec plusieurs instructions

```sql
DECLARE @SQL NVARCHAR(MAX);

-- Plusieurs requêtes dans une seule chaîne
SET @SQL = '
    SELECT COUNT(*) AS NbClients FROM Clients;
    SELECT COUNT(*) AS NbCommandes FROM Commandes;
    SELECT COUNT(*) AS NbProduits FROM Produits;
';

EXEC(@SQL);
-- Exécute les trois SELECT et retourne trois résultats
```

### Limitations de EXEC

#### Limitation 1 : Pas de paramètres

Avec EXEC, vous ne pouvez pas utiliser de paramètres au sens SQL. Tout doit être intégré dans la chaîne :

```sql
-- Vous devez faire ainsi :
DECLARE @ClientID INT = 5;
DECLARE @SQL NVARCHAR(100);
SET @SQL = 'SELECT * FROM Clients WHERE ClientID = ' + CAST(@ClientID AS NVARCHAR);
EXEC(@SQL);

-- Vous ne pouvez PAS faire :
-- EXEC(@SQL, @ClientID)  -- ❌ Ne fonctionne pas
```

#### Limitation 2 : Pas de réutilisation du plan d'exécution

Chaque fois que vous exécutez avec EXEC, SQL Server recompile la requête, même si seules les valeurs changent :

```sql
-- Ces deux exécutions génèrent deux plans d'exécution différents
EXEC('SELECT * FROM Clients WHERE ClientID = 1');
EXEC('SELECT * FROM Clients WHERE ClientID = 2');
-- Moins performant car pas de réutilisation du plan
```

#### Limitation 3 : Vulnérable aux injections SQL

Si vous concaténez directement des entrées utilisateur, vous êtes vulnérable aux attaques :

```sql
-- ⚠️ DANGEREUX !
DECLARE @NomRecherche VARCHAR(50) = ''' OR ''1''=''1';  -- Valeur malveillante
DECLARE @SQL NVARCHAR(500);
SET @SQL = 'SELECT * FROM Clients WHERE Nom = ''' + @NomRecherche + '''';
PRINT @SQL;
-- Résultat : SELECT * FROM Clients WHERE Nom = '' OR '1'='1'
--                                                  ↑↑↑↑↑↑↑↑↑↑↑↑
--                                                  Ceci est toujours VRAI !
EXEC(@SQL);
-- Retourne TOUS les clients au lieu de filtrer !
```

## Méthode 2 : sp_executesql

### Introduction

`sp_executesql` est une procédure système qui exécute du SQL dynamique de manière **paramétrée**. C'est la méthode **recommandée** pour la plupart des cas.

### Syntaxe de base

```sql
EXEC sp_executesql
    @statement = N'chaîne_SQL_avec_paramètres',
    @params = N'déclaration_des_paramètres',
    @param1 = valeur1,
    @param2 = valeur2,
    ...
```

### Exemple simple

```sql
DECLARE @SQL NVARCHAR(500);
DECLARE @ClientID INT = 5;

-- Construire la requête avec un PARAMÈTRE
SET @SQL = N'SELECT * FROM Clients WHERE ClientID = @ClientID_Param';

-- Exécuter avec sp_executesql
EXEC sp_executesql
    @SQL,                                    -- La requête
    N'@ClientID_Param INT',                  -- Déclaration du paramètre
    @ClientID_Param = @ClientID;             -- Valeur du paramètre
```

**Ce qui se passe** :
1. `@SQL` contient une requête avec un **paramètre** `@ClientID_Param`
2. `N'@ClientID_Param INT'` déclare ce paramètre et son type
3. `@ClientID_Param = @ClientID` fournit la valeur

### Important : Le préfixe N

Le **N** devant les chaînes signifie **NVARCHAR** (Unicode). C'est **obligatoire** pour `sp_executesql` :

```sql
-- ✅ CORRECT
EXEC sp_executesql N'SELECT * FROM Clients';

-- ❌ ERREUR si vous oubliez le N
EXEC sp_executesql 'SELECT * FROM Clients';  -- Type de données incorrect
```

### Comparaison visuelle EXEC vs sp_executesql

```sql
-- ═══════════════════════════════════════════════════════════
-- MÉTHODE 1 : EXEC (valeur intégrée dans la chaîne)
-- ═══════════════════════════════════════════════════════════
DECLARE @ClientID INT = 5;
DECLARE @SQL NVARCHAR(500);
SET @SQL = 'SELECT * FROM Clients WHERE ClientID = ' + CAST(@ClientID AS NVARCHAR);
-- @SQL contient : "SELECT * FROM Clients WHERE ClientID = 5"
EXEC(@SQL);

-- ═══════════════════════════════════════════════════════════
-- MÉTHODE 2 : sp_executesql (valeur passée en paramètre)
-- ═══════════════════════════════════════════════════════════
DECLARE @ClientID INT = 5;
DECLARE @SQL NVARCHAR(500);
SET @SQL = N'SELECT * FROM Clients WHERE ClientID = @ClientID_Param';
-- @SQL contient : "SELECT * FROM Clients WHERE ClientID = @ClientID_Param"
EXEC sp_executesql
    @SQL,
    N'@ClientID_Param INT',
    @ClientID_Param = @ClientID;
```

### Exemple avec plusieurs paramètres

```sql
DECLARE @SQL NVARCHAR(500);
DECLARE @Nom VARCHAR(50) = 'Dupont';
DECLARE @AgeMin INT = 30;

-- Requête avec DEUX paramètres
SET @SQL = N'SELECT * FROM Clients
             WHERE Nom = @Nom_Param
             AND Age >= @AgeMin_Param';

-- Exécution avec sp_executesql
EXEC sp_executesql
    @SQL,
    N'@Nom_Param VARCHAR(50), @AgeMin_Param INT',  -- Déclaration des 2 paramètres
    @Nom_Param = @Nom,                              -- Valeur du 1er paramètre
    @AgeMin_Param = @AgeMin;                        -- Valeur du 2ème paramètre
```

### Paramètres de sortie (OUTPUT)

Vous pouvez récupérer des valeurs depuis le SQL dynamique :

```sql
DECLARE @SQL NVARCHAR(500);
DECLARE @NombreClients INT;

-- Requête qui calcule un COUNT
SET @SQL = N'SELECT @Count_Out = COUNT(*) FROM Clients WHERE Ville = @Ville_Param';

-- Exécution avec paramètre de sortie
EXEC sp_executesql
    @SQL,
    N'@Ville_Param VARCHAR(50), @Count_Out INT OUTPUT',  -- OUTPUT indique que c'est une sortie
    @Ville_Param = 'Paris',
    @Count_Out = @NombreClients OUTPUT;                  -- Récupère la valeur

PRINT 'Nombre de clients à Paris : ' + CAST(@NombreClients AS VARCHAR);
```

### Exemple avec un nom de table dynamique

Parfois, vous devez combiner les deux approches : nom de table dynamique + paramètres :

```sql
DECLARE @TableName NVARCHAR(100) = 'Clients';
DECLARE @Ville VARCHAR(50) = 'Paris';
DECLARE @SQL NVARCHAR(500);

-- Le nom de table doit être concaténé (pas de paramètre pour les noms de tables)
-- Mais la valeur de recherche est paramétrée
SET @SQL = N'SELECT * FROM ' + @TableName + N' WHERE Ville = @Ville_Param';

EXEC sp_executesql
    @SQL,
    N'@Ville_Param VARCHAR(50)',
    @Ville_Param = @Ville;
```

## Avantages de sp_executesql sur EXEC

### ✅ Avantage 1 : Sécurité (Protection contre l'injection SQL)

Les paramètres sont traités comme des **valeurs**, pas comme du code SQL :

```sql
-- Avec EXEC (vulnérable)
DECLARE @NomRecherche VARCHAR(50) = ''' OR ''1''=''1';
EXEC('SELECT * FROM Clients WHERE Nom = ''' + @NomRecherche + '''');
-- ⚠️ Injection SQL réussie !

-- Avec sp_executesql (protégé)
EXEC sp_executesql
    N'SELECT * FROM Clients WHERE Nom = @Nom_Param',
    N'@Nom_Param VARCHAR(50)',
    @Nom_Param = ''' OR ''1''=''1';
-- ✅ La chaîne malveillante est traitée comme une valeur texte, pas comme du SQL
-- Cherche littéralement un client avec le nom "' OR '1'='1"
```

### ✅ Avantage 2 : Performance (Réutilisation du plan d'exécution)

SQL Server peut réutiliser le même plan d'exécution pour des valeurs différentes :

```sql
-- Avec sp_executesql : UN SEUL plan pour toutes les valeurs
EXEC sp_executesql N'SELECT * FROM Clients WHERE ClientID = @ID', N'@ID INT', @ID = 1;
EXEC sp_executesql N'SELECT * FROM Clients WHERE ClientID = @ID', N'@ID INT', @ID = 2;
EXEC sp_executesql N'SELECT * FROM Clients WHERE ClientID = @ID', N'@ID INT', @ID = 3;
-- Les trois requêtes réutilisent le même plan d'exécution ✅

-- Avec EXEC : TROIS plans différents
EXEC('SELECT * FROM Clients WHERE ClientID = 1');
EXEC('SELECT * FROM Clients WHERE ClientID = 2');
EXEC('SELECT * FROM Clients WHERE ClientID = 3');
-- Trois plans d'exécution compilés ❌
```

### ✅ Avantage 3 : Lisibilité du code

Pas besoin de gérer les apostrophes compliquées :

```sql
-- Avec EXEC : apostrophes compliquées
SET @SQL = 'SELECT * FROM Clients WHERE Nom = ''' + @Nom + ''' AND Ville = ''' + @Ville + '''';

-- Avec sp_executesql : plus clair
SET @SQL = N'SELECT * FROM Clients WHERE Nom = @Nom_Param AND Ville = @Ville_Param';
EXEC sp_executesql @SQL, N'@Nom_Param VARCHAR(50), @Ville_Param VARCHAR(50)',
                   @Nom_Param = @Nom, @Ville_Param = @Ville;
```

### ✅ Avantage 4 : Récupération de valeurs

Possibilité d'utiliser des paramètres OUTPUT pour récupérer des résultats :

```sql
-- Impossible avec EXEC simple
-- Possible avec sp_executesql
DECLARE @Total DECIMAL(10,2);
EXEC sp_executesql
    N'SELECT @Total_Out = SUM(Montant) FROM Commandes',
    N'@Total_Out DECIMAL(10,2) OUTPUT',
    @Total_Out = @Total OUTPUT;

PRINT 'Total des commandes : ' + CAST(@Total AS VARCHAR);
```

## Tableau comparatif

| Critère | EXEC | sp_executesql |
|---------|------|---------------|
| **Syntaxe** | Plus simple | Plus complexe |
| **Paramètres** | ❌ Non supportés | ✅ Supportés |
| **Sécurité** | ⚠️ Vulnérable aux injections | ✅ Protégé |
| **Performance** | ❌ Pas de réutilisation du plan | ✅ Réutilisation du plan |
| **Paramètres OUTPUT** | ❌ Non | ✅ Oui |
| **Gestion des apostrophes** | ❌ Complexe (doublage) | ✅ Simple |
| **Cas d'usage recommandé** | Scripts simples, noms d'objets dynamiques | Valeurs dynamiques, production |

## Quand utiliser chaque méthode ?

### Utilisez EXEC quand :

✅ **Script simple et rapide** (usage ponctuel, non en production)
```sql
-- Exemple : génération rapide de statistiques
EXEC('SELECT COUNT(*) FROM Clients');
```

✅ **Nom d'objet uniquement dynamique** (sans valeurs de filtrage)
```sql
-- Compter les lignes de toutes les tables
DECLARE @TableName VARCHAR(100) = 'Clients';
EXEC('SELECT COUNT(*) FROM ' + @TableName);
```

✅ **Scripts d'administration** (hors production, en environnement contrôlé)
```sql
-- Générer des commandes de maintenance
DECLARE @SQL VARCHAR(MAX) = 'DBCC CHECKDB';
EXEC(@SQL);
```

### Utilisez sp_executesql quand :

✅ **Code de production** (toujours privilégier en production)
```sql
EXEC sp_executesql N'SELECT * FROM Clients WHERE Ville = @Ville',
                   N'@Ville VARCHAR(50)', @Ville = @MaVille;
```

✅ **Valeurs utilisateur** (données venant d'utilisateurs)
```sql
-- Recherche avec critères utilisateur
EXEC sp_executesql
    N'SELECT * FROM Produits WHERE Nom LIKE @Recherche',
    N'@Recherche VARCHAR(100)',
    @Recherche = '%' + @MotCle + '%';
```

✅ **Requêtes répétées** (même requête avec valeurs différentes)
```sql
-- Boucle qui s'exécute plusieurs fois
DECLARE @i INT = 1;
WHILE @i <= 10
BEGIN
    EXEC sp_executesql
        N'SELECT * FROM Clients WHERE ClientID = @ID',
        N'@ID INT',
        @ID = @i;
    SET @i = @i + 1;
END;
```

✅ **Besoin de récupérer des valeurs**
```sql
DECLARE @MaxSalaire DECIMAL(10,2);
EXEC sp_executesql
    N'SELECT @Max_Out = MAX(Salaire) FROM Employes',
    N'@Max_Out DECIMAL(10,2) OUTPUT',
    @Max_Out = @MaxSalaire OUTPUT;
```

## Bonnes pratiques

### 1. Préférez toujours sp_executesql en production

```sql
-- ❌ À ÉVITER en production
EXEC('SELECT * FROM Clients WHERE ClientID = ' + CAST(@ID AS VARCHAR));

-- ✅ RECOMMANDÉ
EXEC sp_executesql N'SELECT * FROM Clients WHERE ClientID = @ID',
                   N'@ID INT', @ID = @ID;
```

### 2. Validez les noms d'objets dynamiques

Si vous devez utiliser un nom de table dynamique, validez-le :

```sql
DECLARE @TableName NVARCHAR(128) = 'Clients';

-- Vérifier que la table existe
IF OBJECT_ID(@TableName, 'U') IS NULL
BEGIN
    RAISERROR('Table %s non trouvée', 16, 1, @TableName);
    RETURN;
END;

-- Si OK, construire et exécuter
DECLARE @SQL NVARCHAR(500) = N'SELECT * FROM ' + QUOTENAME(@TableName);
EXEC sp_executesql @SQL;
```

### 3. Utilisez QUOTENAME pour sécuriser les identifiants

`QUOTENAME` ajoute des crochets autour des noms et échappe les caractères spéciaux :

```sql
-- Sans QUOTENAME (dangereux si le nom contient des caractères spéciaux)
SET @SQL = N'SELECT * FROM ' + @TableName;

-- Avec QUOTENAME (recommandé)
SET @SQL = N'SELECT * FROM ' + QUOTENAME(@TableName);
-- Si @TableName = 'Clients', résultat : SELECT * FROM [Clients]
-- Si @TableName = 'Table avec espaces', résultat : SELECT * FROM [Table avec espaces]
```

### 4. Affichez le SQL avant de l'exécuter (débogage)

```sql
DECLARE @SQL NVARCHAR(MAX);
SET @SQL = N'SELECT * FROM Clients WHERE Ville = @Ville';

-- Afficher pour vérifier
PRINT @SQL;

-- Puis exécuter
EXEC sp_executesql @SQL, N'@Ville VARCHAR(50)', @Ville = 'Paris';
```

### 5. Gérez les erreurs proprement

```sql
BEGIN TRY
    DECLARE @SQL NVARCHAR(MAX) = N'SELECT * FROM Clients WHERE ClientID = @ID';

    EXEC sp_executesql
        @SQL,
        N'@ID INT',
        @ID = @ClientID;

END TRY
BEGIN CATCH
    PRINT 'Erreur dans le SQL dynamique :';
    PRINT ERROR_MESSAGE();
    PRINT 'SQL exécuté :';
    PRINT @SQL;
END CATCH;
```

### 6. Limitez l'utilisation du SQL dynamique

Le SQL dynamique est puissant mais complexe. Demandez-vous toujours :
> "Est-ce que je peux faire cela avec du SQL statique ?"

Si oui, préférez le SQL statique !

```sql
-- ❌ Inutilement dynamique
DECLARE @SQL NVARCHAR(100) = N'SELECT * FROM Clients WHERE ClientID = @ID';
EXEC sp_executesql @SQL, N'@ID INT', @ID = 5;

-- ✅ Plus simple en statique
SELECT * FROM Clients WHERE ClientID = 5;
```

### 7. Documentez le code dynamique

Le SQL dynamique est plus difficile à comprendre. Documentez bien :

```sql
/*
    OBJECTIF : Recherche de clients avec critères optionnels
    - Si @Nom fourni, filtre sur Nom
    - Si @Ville fournie, filtre sur Ville
    - Si @AgeMin fourni, filtre sur Age >= @AgeMin
*/
DECLARE @SQL NVARCHAR(MAX) = N'SELECT * FROM Clients WHERE 1=1';
DECLARE @Params NVARCHAR(500) = N'@Nom_P VARCHAR(50), @Ville_P VARCHAR(50), @Age_P INT';

IF @Nom IS NOT NULL
    SET @SQL = @SQL + N' AND Nom = @Nom_P';

IF @Ville IS NOT NULL
    SET @SQL = @SQL + N' AND Ville = @Ville_P';

IF @AgeMin IS NOT NULL
    SET @SQL = @SQL + N' AND Age >= @Age_P';

EXEC sp_executesql @SQL, @Params,
     @Nom_P = @Nom, @Ville_P = @Ville, @Age_P = @AgeMin;
```

## Exemples pratiques avancés

### Exemple 1 : Procédure de recherche flexible

```sql
CREATE PROCEDURE sp_RechercheClients
    @Nom VARCHAR(50) = NULL,
    @Ville VARCHAR(50) = NULL,
    @AgeMin INT = NULL,
    @AgeMax INT = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SQL NVARCHAR(MAX) = N'SELECT * FROM Clients WHERE 1=1';
    DECLARE @Params NVARCHAR(500) = N'';

    -- Construire la clause WHERE dynamiquement
    IF @Nom IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Nom LIKE @Nom_Param';
        SET @Params = @Params + N'@Nom_Param VARCHAR(50),';
    END;

    IF @Ville IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Ville = @Ville_Param';
        SET @Params = @Params + N'@Ville_Param VARCHAR(50),';
    END;

    IF @AgeMin IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Age >= @AgeMin_Param';
        SET @Params = @Params + N'@AgeMin_Param INT,';
    END;

    IF @AgeMax IS NOT NULL
    BEGIN
        SET @SQL = @SQL + N' AND Age <= @AgeMax_Param';
        SET @Params = @Params + N'@AgeMax_Param INT,';
    END;

    -- Retirer la dernière virgule
    IF LEN(@Params) > 0
        SET @Params = LEFT(@Params, LEN(@Params) - 1);

    -- Exécuter
    EXEC sp_executesql
        @SQL,
        @Params,
        @Nom_Param = @Nom,
        @Ville_Param = @Ville,
        @AgeMin_Param = @AgeMin,
        @AgeMax_Param = @AgeMax;
END;
GO

-- Utilisation
EXEC sp_RechercheClients @Nom = 'Dupont', @Ville = 'Paris';
EXEC sp_RechercheClients @AgeMin = 30, @AgeMax = 50;
```

### Exemple 2 : Tri dynamique

```sql
CREATE PROCEDURE sp_ListeClients
    @TrierPar VARCHAR(50) = 'Nom',  -- Nom, Prenom, Ville, Age
    @Ordre VARCHAR(4) = 'ASC'        -- ASC ou DESC
AS
BEGIN
    SET NOCOUNT ON;

    -- Valider les entrées
    IF @TrierPar NOT IN ('Nom', 'Prenom', 'Ville', 'Age')
        SET @TrierPar = 'Nom';

    IF @Ordre NOT IN ('ASC', 'DESC')
        SET @Ordre = 'ASC';

    DECLARE @SQL NVARCHAR(500);
    SET @SQL = N'SELECT * FROM Clients ORDER BY ' + QUOTENAME(@TrierPar) + N' ' + @Ordre;

    EXEC sp_executesql @SQL;
END;
GO

-- Utilisation
EXEC sp_ListeClients @TrierPar = 'Age', @Ordre = 'DESC';
```

### Exemple 3 : Génération de rapports pour toutes les tables

```sql
CREATE PROCEDURE sp_CompterToutesLesTables
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @TableName NVARCHAR(128);
    DECLARE @SQL NVARCHAR(500);
    DECLARE @Count INT;

    -- Créer une table temporaire pour les résultats
    CREATE TABLE #Resultats (
        NomTable NVARCHAR(128),
        NombreLignes INT
    );

    -- Curseur sur toutes les tables
    DECLARE curseur CURSOR FOR
        SELECT TABLE_NAME
        FROM INFORMATION_SCHEMA.TABLES
        WHERE TABLE_TYPE = 'BASE TABLE';

    OPEN curseur;
    FETCH NEXT FROM curseur INTO @TableName;

    WHILE @@FETCH_STATUS = 0
    BEGIN
        -- Construire et exécuter un COUNT pour chaque table
        SET @SQL = N'SELECT @Count_Out = COUNT(*) FROM ' + QUOTENAME(@TableName);

        EXEC sp_executesql
            @SQL,
            N'@Count_Out INT OUTPUT',
            @Count_Out = @Count OUTPUT;

        -- Stocker le résultat
        INSERT INTO #Resultats (NomTable, NombreLignes)
        VALUES (@TableName, @Count);

        FETCH NEXT FROM curseur INTO @TableName;
    END;

    CLOSE curseur;
    DEALLOCATE curseur;

    -- Afficher les résultats
    SELECT * FROM #Resultats ORDER BY NombreLignes DESC;

    DROP TABLE #Resultats;
END;
GO
```

## Résumé

### Points clés à retenir

1. **SQL dynamique** : Construction et exécution de requêtes sous forme de chaînes
2. **Deux méthodes** : EXEC (simple) et sp_executesql (recommandée)
3. **sp_executesql** : Paramètres, sécurité, performance
4. **Préfixe N** : Obligatoire pour sp_executesql (Unicode)
5. **QUOTENAME** : Sécurise les noms d'objets dynamiques
6. **Validation** : Toujours valider les entrées utilisateur

### Règles d'or

- ✅ **Toujours privilégier sp_executesql en production**
- ✅ **Utiliser des paramètres pour les valeurs**
- ✅ **Valider les noms d'objets avec OBJECT_ID**
- ✅ **Utiliser QUOTENAME pour les identifiants**
- ✅ **Afficher le SQL pour déboguer (PRINT)**
- ✅ **Gérer les erreurs avec TRY...CATCH**
- ✅ **Limiter l'usage du dynamique au strict nécessaire**

### Aide-mémoire syntaxe

```sql
-- EXEC (simple)
DECLARE @SQL NVARCHAR(MAX) = 'SELECT * FROM MaTable';
EXEC(@SQL);

-- sp_executesql (recommandé)
DECLARE @SQL NVARCHAR(MAX) = N'SELECT * FROM MaTable WHERE ID = @ID_Param';
EXEC sp_executesql
    @SQL,                           -- La requête
    N'@ID_Param INT',              -- Déclaration des paramètres
    @ID_Param = @MonID;            -- Valeurs des paramètres

-- Avec OUTPUT
DECLARE @Resultat INT;
EXEC sp_executesql
    N'SELECT @Out = COUNT(*) FROM MaTable',
    N'@Out INT OUTPUT',
    @Out = @Resultat OUTPUT;
```

## Conclusion

Le SQL dynamique est un outil puissant qui permet une grande flexibilité, mais il doit être utilisé avec précaution.

**Règle de sagesse** :
> "Le SQL dynamique est comme un couteau de cuisine : extrêmement utile quand on en a besoin, mais il faut savoir quand et comment l'utiliser pour éviter de se blesser."

Privilégiez toujours **sp_executesql** avec des **paramètres** pour garantir la sécurité et les performances. N'utilisez le SQL dynamique que lorsque c'est vraiment nécessaire, et documentez abondamment votre code.
