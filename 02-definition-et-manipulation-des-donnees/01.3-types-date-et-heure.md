# 2.1.3 Types de date et heure (DATE, TIME, DATETIME2)

## Introduction

La gestion des dates et heures est un aspect fondamental de la plupart des bases de données. Que ce soit pour enregistrer la date de création d'un compte, l'heure d'une transaction, ou planifier des événements futurs, SQL Server propose plusieurs types de données spécialisés pour gérer le temps.

Dans cette section, nous allons découvrir les types modernes de date et heure en T-SQL, comprendre leurs différences, et apprendre à les utiliser efficacement.

---

## Pourquoi des types spécifiques pour les dates ?

Vous pourriez vous demander : "Pourquoi ne pas stocker les dates sous forme de texte ?"

**Problèmes avec le stockage en texte :**
- ❌ Impossible de trier correctement ('31/12/2024' vient avant '01/01/2025' alphabétiquement)
- ❌ Impossible de calculer des durées (combien de jours entre deux dates ?)
- ❌ Formats incohérents (01/02/2024 = 1er février ou 2 janvier ?)
- ❌ Espace de stockage gaspillé

**Avantages des types DATE/TIME :**
- ✅ Tri chronologique automatique
- ✅ Calculs de durées facilités
- ✅ Validation automatique (pas de 32 février)
- ✅ Format interne optimisé
- ✅ Fonctions spécialisées disponibles

---

## Les trois types modernes principaux

SQL Server 2008 et versions ultérieures proposent trois types modernes pour gérer le temps :

| Type | Contenu | Plage | Précision | Taille |
|------|---------|-------|-----------|--------|
| **DATE** | Date uniquement | 0001-01-01 à 9999-12-31 | 1 jour | 3 octets |
| **TIME** | Heure uniquement | 00:00:00.0000000 à 23:59:59.9999999 | 100 nanosecondes | 3-5 octets |
| **DATETIME2** | Date + Heure | 0001-01-01 à 9999-12-31 | 100 nanosecondes | 6-8 octets |

---

## 1. DATE : Pour les dates sans heure

### Qu'est-ce que DATE ?

**DATE** stocke uniquement une date (année, mois, jour) sans information d'heure. C'est le type idéal quand l'heure n'a pas d'importance.

**Syntaxe :** `DATE`

**Caractéristiques :**
- **Plage** : du 1er janvier de l'an 1 au 31 décembre 9999
- **Format** : YYYY-MM-DD (2024-12-25)
- **Précision** : 1 jour
- **Stockage** : 3 octets (très compact)

### Quand utiliser DATE ?

**DATE est idéal pour :**
- ✅ Dates de naissance
- ✅ Dates d'anniversaires
- ✅ Dates de début/fin de contrat
- ✅ Dates d'échéance
- ✅ Calendrier d'événements (sans heure précise)
- ✅ Historique par jour

### Exemples pratiques avec DATE

```sql
-- Création d'une table avec des dates
CREATE TABLE Employes (
    EmployeID INT,
    Nom NVARCHAR(100),
    Prenom NVARCHAR(100),
    DateNaissance DATE,
    DateEmbauche DATE,
    DateFinContrat DATE
);

-- Insertion de données
INSERT INTO Employes (EmployeID, Nom, Prenom, DateNaissance, DateEmbauche, DateFinContrat)
VALUES
    (1, N'Dupont', N'Marie', '1990-05-15', '2020-01-10', NULL),
    (2, N'Martin', N'Pierre', '1985-12-03', '2018-03-20', '2025-12-31');

-- Sélection
SELECT * FROM Employes;
```

### Format d'insertion des dates

SQL Server accepte plusieurs formats pour insérer des dates :

```sql
-- ✅ Format ISO (recommandé) : YYYY-MM-DD
INSERT INTO Employes (DateNaissance) VALUES ('1990-05-15');

-- ✅ Format avec nom de mois
INSERT INTO Employes (DateNaissance) VALUES ('May 15, 1990');

-- ✅ Format avec séparateurs
INSERT INTO Employes (DateNaissance) VALUES ('1990/05/15');

-- ⚠️ Format ambigu (éviter) : dépend des paramètres régionaux
-- '01/02/2024' = 1er février ou 2 janvier ?
INSERT INTO Employes (DateNaissance) VALUES ('01/02/2024');
```

**Recommandation :** Utilisez toujours le **format ISO (YYYY-MM-DD)** pour éviter toute ambiguïté.

## 2. TIME : Pour les heures sans date

### Qu'est-ce que TIME ?

**TIME** stocke uniquement une heure (heures, minutes, secondes, fractions de secondes) sans information de date.

**Syntaxe :** `TIME(n)`
- **n** : précision des fractions de secondes (0 à 7)

**Caractéristiques :**
- **Plage** : 00:00:00.0000000 à 23:59:59.9999999
- **Format** : HH:MM:SS.nnnnnnn
- **Précision** : configurable (0 à 7 décimales)
- **Stockage** : 3 à 5 octets selon la précision

### Comprendre la précision de TIME

La précision détermine le nombre de décimales pour les fractions de secondes :

```sql
-- TIME(0) : précision à la seconde
-- Stockage : 3 octets
-- Exemple : 14:30:25

-- TIME(3) : précision à la milliseconde (1/1000e de seconde)
-- Stockage : 4 octets
-- Exemple : 14:30:25.123

-- TIME(7) : précision maximale (100 nanosecondes)
-- Stockage : 5 octets
-- Exemple : 14:30:25.1234567
```

### Quand utiliser TIME ?

**TIME est idéal pour :**
- ✅ Horaires d'ouverture/fermeture
- ✅ Horaires de cours ou de réunions récurrentes
- ✅ Durées (temps écoulé)
- ✅ Heures de pointage
- ✅ Plannings répétitifs (indépendants de la date)

### Exemples pratiques avec TIME

```sql
-- Table d'horaires de magasin
CREATE TABLE HorairesMagasin (
    JourSemaine NVARCHAR(20),
    HeureOuverture TIME(0),     -- Précision à la seconde suffit
    HeureFermeture TIME(0)
);

INSERT INTO HorairesMagasin (JourSemaine, HeureOuverture, HeureFermeture)
VALUES
    (N'Lundi', '09:00:00', '18:00:00'),
    (N'Mardi', '09:00:00', '18:00:00'),
    (N'Samedi', '10:00:00', '17:00:00');

-- Table de performances sportives
CREATE TABLE Chronometrage (
    AthleteID INT,
    TempsRealise TIME(3),       -- Précision à la milliseconde
    Epreuve NVARCHAR(50)
);

INSERT INTO Chronometrage (AthleteID, TempsRealise, Epreuve)
VALUES
    (1, '00:09:58.123', N'100m haies'),
    (2, '00:02:15.789', N'800m');
```

### Format d'insertion des heures

```sql
-- ✅ Format complet : HH:MM:SS
INSERT INTO HorairesMagasin (HeureOuverture) VALUES ('09:30:00');

-- ✅ Format court : HH:MM (secondes = 00 par défaut)
INSERT INTO HorairesMagasin (HeureOuverture) VALUES ('09:30');

-- ✅ Avec fractions de secondes
INSERT INTO Chronometrage (TempsRealise) VALUES ('00:09:58.123');

-- ✅ Format 24 heures uniquement
INSERT INTO HorairesMagasin (HeureFermeture) VALUES ('23:59:59');
```

## 3. DATETIME2 : Date et heure combinées

### Qu'est-ce que DATETIME2 ?

**DATETIME2** est le type le plus complet : il stocke à la fois la date ET l'heure avec une grande précision. C'est le type recommandé pour la plupart des besoins de timestamp.

**Syntaxe :** `DATETIME2(n)`
- **n** : précision des fractions de secondes (0 à 7)

**Caractéristiques :**
- **Plage** : 0001-01-01 00:00:00.0000000 à 9999-12-31 23:59:59.9999999
- **Format** : YYYY-MM-DD HH:MM:SS.nnnnnnn
- **Précision** : configurable (0 à 7 décimales)
- **Stockage** : 6 à 8 octets selon la précision

### Pourquoi DATETIME2 est le meilleur choix moderne

Comparé aux anciens types (DATETIME, SMALLDATETIME), DATETIME2 offre :
- ✅ Plage de dates plus étendue (de l'an 1 à 9999)
- ✅ Meilleure précision (100 nanosecondes vs 3.33 millisecondes)
- ✅ Stockage optimisé selon la précision choisie
- ✅ Conforme aux standards SQL (ANSI SQL)

### Quand utiliser DATETIME2 ?

**DATETIME2 est idéal pour :**
- ✅ Horodatage de transactions
- ✅ Logs et historiques (date + heure précise)
- ✅ Dates de création/modification d'enregistrements
- ✅ Rendez-vous avec heure précise
- ✅ Événements planifiés
- ✅ Toute situation nécessitant date ET heure

### Exemples pratiques avec DATETIME2

```sql
-- Table de commandes e-commerce
CREATE TABLE Commandes (
    CommandeID INT,
    ClientID INT,
    DateCommande DATETIME2(3),          -- Précision à la milliseconde
    DateLivraison DATETIME2(0),         -- Précision à la seconde
    DateAnnulation DATETIME2(3),
    MontantTotal DECIMAL(10, 2)
);

INSERT INTO Commandes (CommandeID, ClientID, DateCommande, DateLivraison, MontantTotal)
VALUES
    (1, 100, '2024-11-15 14:30:25.123', '2024-11-18 10:00:00', 159.99),
    (2, 101, '2024-11-15 15:45:10.456', NULL, 89.50);

-- Table de logs système
CREATE TABLE LogsSysteme (
    LogID INT,
    DateHeure DATETIME2(7),             -- Précision maximale pour les logs
    Niveau NVARCHAR(20),
    Message NVARCHAR(MAX)
);

INSERT INTO LogsSysteme (LogID, DateHeure, Niveau, Message)
VALUES
    (1, '2024-11-15 14:30:25.1234567', 'INFO', N'Démarrage du système'),
    (2, '2024-11-15 14:30:26.7891234', 'WARNING', N'Connexion lente détectée');
```

### Choisir la bonne précision pour DATETIME2

| Précision | Fractions de seconde | Stockage | Usage typique |
|-----------|---------------------|----------|---------------|
| DATETIME2(0) | 1 seconde | 6 octets | Événements généraux |
| DATETIME2(3) | 1 milliseconde | 7 octets | **Recommandé** pour la plupart des cas |
| DATETIME2(7) | 100 nanosecondes | 8 octets | Logs système, haute précision |

**Recommandation :** `DATETIME2(3)` est un excellent compromis entre précision et espace de stockage.

## 4. Fonctions courantes pour manipuler les dates

### Obtenir la date et l'heure actuelles

SQL Server fournit plusieurs fonctions pour obtenir la date/heure du système :

```sql
-- Date et heure actuelles (haute précision)
SELECT SYSDATETIME() AS DateHeureActuelle;
-- Résultat : 2024-11-15 14:30:25.1234567

-- Date et heure actuelles (DATETIME2)
SELECT GETDATE() AS DateHeureActuelle;
-- Résultat : 2024-11-15 14:30:25.123

-- Date actuelle uniquement
SELECT CAST(SYSDATETIME() AS DATE) AS DateActuelle;
-- Résultat : 2024-11-15

-- Heure actuelle uniquement
SELECT CAST(SYSDATETIME() AS TIME) AS HeureActuelle;
-- Résultat : 14:30:25.1234567
```

### Extraire des parties d'une date

```sql
DECLARE @maDate DATETIME2 = '2024-11-15 14:30:25';

-- Extraire l'année
SELECT YEAR(@maDate) AS Annee;           -- 2024

-- Extraire le mois
SELECT MONTH(@maDate) AS Mois;           -- 11

-- Extraire le jour
SELECT DAY(@maDate) AS Jour;             -- 15

-- Extraire toutes les parties avec DATEPART
SELECT
    DATEPART(YEAR, @maDate) AS Annee,
    DATEPART(MONTH, @maDate) AS Mois,
    DATEPART(DAY, @maDate) AS Jour,
    DATEPART(HOUR, @maDate) AS Heure,
    DATEPART(MINUTE, @maDate) AS Minute,
    DATEPART(SECOND, @maDate) AS Seconde;
```

### Nom du mois et du jour

```sql
DECLARE @maDate DATETIME2 = '2024-11-15 14:30:25';

-- Nom du mois (en anglais par défaut)
SELECT DATENAME(MONTH, @maDate) AS NomMois;      -- November

-- Nom du jour de la semaine
SELECT DATENAME(WEEKDAY, @maDate) AS NomJour;    -- Friday

-- Numéro du jour de la semaine (1=Dimanche, 7=Samedi)
SELECT DATEPART(WEEKDAY, @maDate) AS NumeroJour; -- 6
```

### Ajouter ou soustraire des intervalles

```sql
DECLARE @dateDepart DATE = '2024-11-15';

-- Ajouter des jours
SELECT DATEADD(DAY, 7, @dateDepart) AS DansSeptJours;
-- Résultat : 2024-11-22

-- Ajouter des mois
SELECT DATEADD(MONTH, 3, @dateDepart) AS DansTroisMois;
-- Résultat : 2025-02-15

-- Ajouter des années
SELECT DATEADD(YEAR, 1, @dateDepart) AS DansUnAn;
-- Résultat : 2025-11-15

-- Soustraire des jours (valeur négative)
SELECT DATEADD(DAY, -30, @dateDepart) AS IlYa30Jours;
-- Résultat : 2024-10-16

-- Ajouter des heures
DECLARE @dateHeure DATETIME2 = '2024-11-15 14:30:00';
SELECT DATEADD(HOUR, 5, @dateHeure) AS Dans5Heures;
-- Résultat : 2024-11-15 19:30:00
```

### Calculer la différence entre deux dates

```sql
DECLARE @date1 DATE = '2024-01-15';
DECLARE @date2 DATE = '2024-11-15';

-- Nombre de jours entre deux dates
SELECT DATEDIFF(DAY, @date1, @date2) AS NombreJours;
-- Résultat : 305

-- Nombre de mois
SELECT DATEDIFF(MONTH, @date1, @date2) AS NombreMois;
-- Résultat : 10

-- Nombre d'années
SELECT DATEDIFF(YEAR, @date1, @date2) AS NombreAnnees;
-- Résultat : 0 (même année)

-- Calculer l'âge d'une personne
DECLARE @dateNaissance DATE = '1990-05-15';
DECLARE @aujourdhui DATE = '2024-11-15';

SELECT DATEDIFF(YEAR, @dateNaissance, @aujourdhui) AS Age;
-- Résultat : 34 ans
```

### Formater les dates pour l'affichage

```sql
DECLARE @maDate DATETIME2 = '2024-11-15 14:30:25';

-- Format personnalisé avec CONVERT
SELECT CONVERT(VARCHAR, @maDate, 103) AS FormatEuropeen;
-- Résultat : 15/11/2024

SELECT CONVERT(VARCHAR, @maDate, 120) AS FormatISO;
-- Résultat : 2024-11-15 14:30:25

-- Format moderne avec FORMAT (plus lisible)
SELECT FORMAT(@maDate, 'dd/MM/yyyy') AS FormatPersonnalise;
-- Résultat : 15/11/2024

SELECT FORMAT(@maDate, 'dd MMMM yyyy', 'fr-FR') AS FormatFrancais;
-- Résultat : 15 novembre 2024

SELECT FORMAT(@maDate, 'dddd dd MMMM yyyy HH:mm', 'fr-FR') AS FormatComplet;
-- Résultat : vendredi 15 novembre 2024 14:30
```

## 5. Comparaison avec les anciens types

### Les types historiques (à éviter)

SQL Server possède des types de date/heure plus anciens, encore présents pour la compatibilité :

| Type ancien | Plage | Précision | Problème | Remplacement |
|-------------|-------|-----------|----------|--------------|
| **DATETIME** | 1753-9999 | 3.33 ms | Plage limitée, précision moyenne | DATETIME2 |
| **SMALLDATETIME** | 1900-2079 | 1 minute | Plage très limitée, faible précision | DATETIME2 |

### Pourquoi préférer les types modernes ?

```sql
-- ❌ Ancien style
CREATE TABLE AncienStyle (
    ID INT,
    DateCreation DATETIME,           -- Type obsolète
    HeureOuverture VARCHAR(10)       -- Stockage textuel !
);

-- ✅ Style moderne recommandé
CREATE TABLE StyleModerne (
    ID INT,
    DateCreation DATETIME2(3),       -- Précis et efficace
    HeureOuverture TIME(0)            -- Type dédié
);
```

**Raisons de migrer vers les types modernes :**
- ✅ Meilleure précision
- ✅ Plage de dates plus étendue
- ✅ Stockage optimisé
- ✅ Séparation claire date/heure/datetime
- ✅ Conformité aux standards

## 6. Cas d'usage pratiques complets

### Exemple 1 : Système de réservation

```sql
CREATE TABLE Reservations (
    ReservationID INT,
    ClientID INT,
    DateReservation DATE,               -- Jour de la réservation
    HeureDebut TIME(0),                 -- Heure de début
    HeureFin TIME(0),                   -- Heure de fin
    DateCreation DATETIME2(3),          -- Quand la réservation a été créée
    StatutReservation NVARCHAR(20)
);

INSERT INTO Reservations
VALUES
    (1, 101, '2024-11-20', '14:00:00', '16:00:00', SYSDATETIME(), N'Confirmée'),
    (2, 102, '2024-11-20', '16:30:00', '18:00:00', SYSDATETIME(), N'En attente');

-- Trouver toutes les réservations pour demain
SELECT *
FROM Reservations
WHERE DateReservation = DATEADD(DAY, 1, CAST(GETDATE() AS DATE));
```

### Exemple 2 : Gestion d'employés

```sql
CREATE TABLE EmployesComplet (
    EmployeID INT,
    Nom NVARCHAR(100),
    Prenom NVARCHAR(100),
    DateNaissance DATE,                 -- Date seule
    DateEmbauche DATE,                  -- Date seule
    DerniereConnexion DATETIME2(3),     -- Date + heure
    HeureArriveeHabituelle TIME(0),     -- Heure de pointage
    HeureDepartHabituelle TIME(0)
);

INSERT INTO EmployesComplet
VALUES
    (1, N'Dupont', N'Marie', '1990-05-15', '2020-01-10',
     '2024-11-15 08:45:32.123', '09:00:00', '17:30:00');

-- Calculer l'ancienneté
SELECT
    Nom,
    Prenom,
    DateEmbauche,
    DATEDIFF(YEAR, DateEmbauche, GETDATE()) AS AnneeAnciennete
FROM EmployesComplet;

-- Calculer l'âge
SELECT
    Nom,
    Prenom,
    DateNaissance,
    DATEDIFF(YEAR, DateNaissance, GETDATE()) AS Age
FROM EmployesComplet;
```

### Exemple 3 : Système de logs

```sql
CREATE TABLE AuditLogs (
    LogID INT,
    Utilisateur NVARCHAR(100),
    Action NVARCHAR(50),
    DateHeureAction DATETIME2(7),       -- Précision maximale
    Duree TIME(3),                      -- Durée de l'opération
    Reussite BIT
);

-- Insertion d'un log
INSERT INTO AuditLogs (LogID, Utilisateur, Action, DateHeureAction, Duree, Reussite)
VALUES
    (1, N'admin', N'LOGIN', SYSDATETIME(), '00:00:00.125', 1),
    (2, N'user123', N'EXPORT_DATA', SYSDATETIME(), '00:00:05.678', 1);

-- Trouver les logs des dernières 24 heures
SELECT *
FROM AuditLogs
WHERE DateHeureAction >= DATEADD(HOUR, -24, SYSDATETIME())
ORDER BY DateHeureAction DESC;
```

### Exemple 4 : Calculs de dates complexes

```sql
-- Trouver le dernier jour du mois
DECLARE @date DATE = '2024-11-15';
SELECT EOMONTH(@date) AS DernierJourDuMois;
-- Résultat : 2024-11-30

-- Trouver le premier jour du mois
SELECT DATEFROMPARTS(YEAR(@date), MONTH(@date), 1) AS PremierJourDuMois;
-- Résultat : 2024-11-01

-- Construire une date à partir de ses composantes
SELECT DATEFROMPARTS(2024, 11, 15) AS DateConstruite;
-- Résultat : 2024-11-15

-- Construire une heure
SELECT TIMEFROMPARTS(14, 30, 25, 0, 0) AS HeureConstruite;
-- Résultat : 14:30:25

-- Construire une datetime
SELECT DATETIME2FROMPARTS(2024, 11, 15, 14, 30, 25, 123, 3) AS DateHeureConstruite;
-- Résultat : 2024-11-15 14:30:25.123
```

## 7. Pièges courants à éviter

### Piège 1 : Comparaisons avec des valeurs textuelles

```sql
-- ❌ ERREUR : comparaison textuelle ambiguë
SELECT * FROM Commandes
WHERE DateCommande = '15/11/2024';  -- Format ambigu !

-- ✅ CORRECT : utilisez le format ISO
SELECT * FROM Commandes
WHERE DateCommande = '2024-11-15';
```

### Piège 2 : Oubli de la partie heure dans les comparaisons

```sql
DECLARE @dateRecherche DATE = '2024-11-15';

-- ❌ INCORRECT : ne trouvera pas les commandes avec une heure
SELECT * FROM Commandes
WHERE DateCommande = @dateRecherche;
-- Ne trouve que les commandes à exactement 00:00:00

-- ✅ CORRECT : comparer uniquement la partie date
SELECT * FROM Commandes
WHERE CAST(DateCommande AS DATE) = @dateRecherche;

-- ✅ ENCORE MIEUX : utiliser une plage
SELECT * FROM Commandes
WHERE DateCommande >= @dateRecherche
  AND DateCommande < DATEADD(DAY, 1, @dateRecherche);
```

### Piège 3 : Mauvais calcul d'âge

```sql
-- ❌ INCORRECT : ne prend pas en compte le mois/jour
DECLARE @dateNaissance DATE = '1990-12-25';
SELECT YEAR(GETDATE()) - YEAR(@dateNaissance) AS Age;
-- Peut donner un résultat erroné si l'anniversaire n'est pas encore passé

-- ✅ CORRECT : utiliser DATEDIFF
SELECT DATEDIFF(YEAR, @dateNaissance, GETDATE()) AS Age;
-- Prend en compte le mois et le jour
```

### Piège 4 : Problèmes de fuseau horaire

```sql
-- ⚠️ ATTENTION : GETDATE() et SYSDATETIME() utilisent l'heure du serveur
-- Pas de gestion automatique des fuseaux horaires

-- Pour gérer les fuseaux, utilisez DATETIMEOFFSET
CREATE TABLE CommandesAvecFuseau (
    CommandeID INT,
    DateCommande DATETIMEOFFSET(3)      -- Inclut le décalage horaire
);

INSERT INTO CommandesAvecFuseau VALUES
    (1, '2024-11-15 14:30:00 +01:00');  -- Heure de Paris (UTC+1)
```

### Piège 5 : NULL dans les dates

```sql
-- Toujours vérifier les NULL dans les comparaisons
SELECT * FROM Employes
WHERE DateFinContrat IS NULL;           -- Employés actifs

-- Ou utiliser ISNULL/COALESCE pour des valeurs par défaut
SELECT
    Nom,
    ISNULL(DateFinContrat, '9999-12-31') AS DateFin
FROM Employes;
```

## 8. Bonnes pratiques

### Choix du type approprié

```sql
-- ✅ Bonnes pratiques de choix de type
CREATE TABLE BonnesPratiques (
    EventID INT,

    -- Pour les dates sans heure
    DateNaissance DATE,
    DateEvenement DATE,

    -- Pour les heures sans date
    HeureOuverture TIME(0),

    -- Pour date + heure (le plus courant)
    DateCreation DATETIME2(3),          -- Précision milliseconde (recommandé)
    DerniereModification DATETIME2(3),

    -- Pour les timestamps haute précision
    TimestampLog DATETIME2(7)           -- Précision maximale
);
```

### Valeurs par défaut

```sql
-- Définir des valeurs par défaut pour l'horodatage automatique
CREATE TABLE CommandesAvecDefaut (
    CommandeID INT,
    DateCommande DATETIME2(3) DEFAULT SYSDATETIME(),
    DateCreation DATETIME2(3) DEFAULT SYSDATETIME()
);

-- Insertion sans spécifier la date (utilise la valeur par défaut)
INSERT INTO CommandesAvecDefaut (CommandeID) VALUES (1);

SELECT * FROM CommandesAvecDefaut;
-- La date actuelle sera automatiquement insérée
```

### Indexation des colonnes de date

```sql
-- Les colonnes de date sont souvent utilisées dans les clauses WHERE
-- Pensez à les indexer pour améliorer les performances

CREATE INDEX IX_DateCommande ON Commandes(DateCommande);

-- Pour les plages de dates fréquentes
CREATE INDEX IX_DateCreation ON AuditLogs(DateHeureAction);
```

### Normalisation des données temporelles

```sql
-- Séparez date et heure si elles ont des usages différents
CREATE TABLE Evenements (
    EventID INT,
    DateEvenement DATE,                 -- Jour de l'événement
    HeureDebut TIME(0),                 -- Heure de début
    HeureFin TIME(0),                   -- Heure de fin
    DateInscription DATETIME2(3)        -- Timestamp d'inscription
);

-- Avantage : requêtes plus simples
-- Tous les événements un jour donné
SELECT * FROM Evenements WHERE DateEvenement = '2024-11-15';

-- Tous les événements commençant à une certaine heure (quel que soit le jour)
SELECT * FROM Evenements WHERE HeureDebut = '14:00:00';
```

## 9. Conversion et cast entre types temporels

### Conversion entre types

```sql
DECLARE @datetime DATETIME2 = '2024-11-15 14:30:25.123';

-- Extraire uniquement la date
DECLARE @dateSeule DATE = CAST(@datetime AS DATE);
SELECT @dateSeule;  -- 2024-11-15

-- Extraire uniquement l'heure
DECLARE @heureSeule TIME = CAST(@datetime AS TIME);
SELECT @heureSeule;  -- 14:30:25.1230000

-- Combiner date et heure
DECLARE @maDate DATE = '2024-11-15';
DECLARE @monHeure TIME = '14:30:00';
DECLARE @combine DATETIME2;

SET @combine = CAST(@maDate AS DATETIME2) + CAST(@monHeure AS DATETIME2);
SELECT @combine;  -- 2024-11-15 14:30:00.0000000
```

### Précision lors de la conversion

```sql
-- Conversion avec perte de précision
DECLARE @precis DATETIME2(7) = '2024-11-15 14:30:25.1234567';

-- Réduire la précision
DECLARE @moinsPrecis DATETIME2(3) = @precis;
SELECT @moinsPrecis;  -- 2024-11-15 14:30:25.123 (arrondi)

-- Conversion vers l'ancien type DATETIME
DECLARE @ancien DATETIME = @precis;
SELECT @ancien;  -- Précision réduite à 3.33ms
```

## Points clés à retenir

✅ **DATE** : pour les dates sans heure (anniversaires, échéances)

✅ **TIME(n)** : pour les heures sans date (horaires, durées)

✅ **DATETIME2(n)** : pour date + heure, le choix moderne recommandé

✅ **Format ISO** : toujours utiliser 'YYYY-MM-DD' pour éviter les ambiguïtés

✅ **Précision** : DATETIME2(3) est un excellent compromis pour la plupart des cas

✅ **Fonctions** : DATEADD, DATEDIFF, YEAR, MONTH, DAY pour manipuler les dates

✅ **Valeurs par défaut** : utilisez SYSDATETIME() pour l'horodatage automatique

❌ **Évitez** les anciens types DATETIME et SMALLDATETIME

❌ **Ne stockez pas** les dates en format texte (VARCHAR)

❌ **Attention** aux comparaisons de dates qui incluent l'heure

---

## Conclusion

Les types de date et heure en SQL Server sont puissants et flexibles :

- **DATE** pour les dates pures
- **TIME** pour les heures pures
- **DATETIME2** pour les combinaisons date/heure

**En pratique, pour les applications modernes :**
- Utilisez **DATETIME2(3)** comme choix par défaut pour les timestamps
- Utilisez **DATE** quand l'heure n'a pas d'importance
- Utilisez **TIME** pour les horaires récurrents
- Profitez des fonctions intégrées pour manipuler facilement les dates

Avec ces connaissances, vous êtes maintenant capable de choisir et d'utiliser le bon type temporel pour chaque situation dans vos bases de données SQL Server !
