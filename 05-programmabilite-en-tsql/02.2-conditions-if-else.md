# 5.2.2 Conditions IF ... ELSE

## Introduction

Dans la vie quotidienne, nous prenons constamment des décisions basées sur des conditions : "**Si** il pleut, je prends un parapluie, **sinon** je n'en prends pas". En programmation T-SQL, nous avons besoin du même type de logique pour faire des choix et exécuter différentes actions selon les circonstances.

La structure **IF ... ELSE** est l'un des outils les plus fondamentaux et les plus puissants en programmation. Elle permet à votre code de **prendre des décisions** et d'adapter son comportement en fonction des données.

Dans cette section, nous allons explorer en détail comment utiliser les conditions IF ... ELSE pour rendre votre code T-SQL intelligent et flexible.

---

## 1. Structure IF simple

### Syntaxe de base

```sql
IF condition
    instruction;
```

Ou avec un bloc :

```sql
IF condition
BEGIN
    instruction1;
    instruction2;
    -- ...
END
```

### Comment ça fonctionne ?

1. T-SQL **évalue la condition**
2. Si la condition est **VRAIE** (TRUE), les instructions sont exécutées
3. Si la condition est **FAUSSE** (FALSE), les instructions sont ignorées

### Exemple simple

```sql
DECLARE @Age INT = 20;

IF @Age >= 18
BEGIN
    PRINT 'Vous êtes majeur';
END
```

**Résultat :**
```
Vous êtes majeur
```

Si on change @Age à 15, rien ne s'affiche car la condition est fausse.

---

## 2. Structure IF ... ELSE

### Syntaxe

```sql
IF condition
BEGIN
    -- Instructions si la condition est VRAIE
END
ELSE
BEGIN
    -- Instructions si la condition est FAUSSE
END
```

### Comment ça fonctionne ?

1. T-SQL évalue la condition
2. Si **VRAIE** : exécute le bloc après IF
3. Si **FAUSSE** : exécute le bloc après ELSE

### Exemple simple

```sql
DECLARE @Temperature INT = 15;

IF @Temperature > 25
BEGIN
    PRINT 'Il fait chaud';
END
ELSE
BEGIN
    PRINT 'Il ne fait pas chaud';
END
```

**Résultat :**
```
Il ne fait pas chaud
```

---

## 3. Les conditions : ce qui peut être testé

### Opérateurs de comparaison

| Opérateur | Signification | Exemple |
|-----------|---------------|---------|
| `=` | Égal à | `@X = 10` |
| `<>` ou `!=` | Différent de | `@X <> 10` |
| `>` | Supérieur à | `@X > 10` |
| `<` | Inférieur à | `@X < 10` |
| `>=` | Supérieur ou égal | `@X >= 10` |
| `<=` | Inférieur ou égal | `@X <= 10` |

### Exemples avec différents opérateurs

```sql
DECLARE @Prix DECIMAL(10,2) = 50.00;

-- Égalité
IF @Prix = 50.00
    PRINT 'Le prix est exactement 50';

-- Différent
IF @Prix <> 100.00
    PRINT 'Le prix n''est pas 100';

-- Supérieur
IF @Prix > 30.00
    PRINT 'Le prix est supérieur à 30';

-- Inférieur ou égal
IF @Prix <= 100.00
    PRINT 'Le prix est inférieur ou égal à 100';
```

### Opérateurs logiques

| Opérateur | Signification | Exemple |
|-----------|---------------|---------|
| `AND` | ET logique (les deux conditions doivent être vraies) | `@X > 0 AND @X < 100` |
| `OR` | OU logique (au moins une condition doit être vraie) | `@X < 0 OR @X > 100` |
| `NOT` | NON logique (inverse la condition) | `NOT (@X = 10)` |

### Exemples avec opérateurs logiques

```sql
DECLARE @Age INT = 25;
DECLARE @Permis BIT = 1; -- 1 = vrai, 0 = faux

-- AND : les deux conditions doivent être vraies
IF @Age >= 18 AND @Permis = 1
BEGIN
    PRINT 'Vous pouvez conduire';
END

-- OR : au moins une condition doit être vraie
DECLARE @Jour VARCHAR(10) = 'Samedi';

IF @Jour = 'Samedi' OR @Jour = 'Dimanche'
BEGIN
    PRINT 'C''est le week-end !';
END

-- NOT : inverse la condition
DECLARE @EstActif BIT = 0;

IF NOT (@EstActif = 1)
BEGIN
    PRINT 'Le compte n''est pas actif';
END
```

## 4. IF ... ELSE IF ... ELSE : Plusieurs conditions

### Syntaxe

```sql
IF condition1
BEGIN
    -- Si condition1 est vraie
END
ELSE IF condition2
BEGIN
    -- Si condition1 est fausse et condition2 est vraie
END
ELSE IF condition3
BEGIN
    -- Si condition1 et condition2 sont fausses et condition3 est vraie
END
ELSE
BEGIN
    -- Si toutes les conditions sont fausses
END
```

### Ordre d'évaluation

Les conditions sont évaluées **dans l'ordre**. Dès qu'une condition est vraie :
1. Son bloc est exécuté
2. Les autres conditions ne sont **pas testées**
3. Le reste de la structure est ignoré

### Exemple : Catégories d'âge

```sql
DECLARE @Age INT = 35;

IF @Age < 13
BEGIN
    PRINT 'Catégorie : Enfant';
END
ELSE IF @Age < 18
BEGIN
    PRINT 'Catégorie : Adolescent';
END
ELSE IF @Age < 65
BEGIN
    PRINT 'Catégorie : Adulte';
END
ELSE
BEGIN
    PRINT 'Catégorie : Senior';
END
```

**Résultat :**
```
Catégorie : Adulte
```

### Exemple : Notes et mentions

```sql
DECLARE @Note DECIMAL(5,2) = 14.5;

IF @Note >= 16
BEGIN
    PRINT 'Mention : Très Bien';
    PRINT 'Félicitations !';
END
ELSE IF @Note >= 14
BEGIN
    PRINT 'Mention : Bien';
    PRINT 'Bon travail';
END
ELSE IF @Note >= 12
BEGIN
    PRINT 'Mention : Assez Bien';
END
ELSE IF @Note >= 10
BEGIN
    PRINT 'Mention : Passable';
END
ELSE
BEGIN
    PRINT 'Échec';
    PRINT 'Redoublement nécessaire';
END
```

**Résultat :**
```
Mention : Bien
Bon travail
```

## 5. Tests avec NULL

### Le problème de NULL

**NULL** signifie "valeur inconnue" ou "absence de valeur". Comparer avec NULL nécessite une syntaxe spéciale.

### ❌ Incorrect : Utiliser = ou <>

```sql
DECLARE @Email VARCHAR(100) = NULL;

IF @Email = NULL  -- ❌ Ne fonctionne PAS !
BEGIN
    PRINT 'Email non renseigné';
END
```

Ce code ne fonctionnera **jamais** car `= NULL` ne retourne jamais TRUE.

### ✅ Correct : Utiliser IS NULL ou IS NOT NULL

```sql
DECLARE @Email VARCHAR(100) = NULL;

IF @Email IS NULL
BEGIN
    PRINT 'Email non renseigné';
END
ELSE
BEGIN
    PRINT 'Email : ' + @Email;
END
```

**Résultat :**
```
Email non renseigné
```

### Exemple pratique

```sql
DECLARE @Telephone VARCHAR(20) = NULL;

IF @Telephone IS NULL
BEGIN
    PRINT 'Aucun numéro de téléphone enregistré';
    PRINT 'Veuillez mettre à jour vos coordonnées';
END
ELSE IF @Telephone = ''
BEGIN
    PRINT 'Le numéro de téléphone est vide';
END
ELSE
BEGIN
    PRINT 'Téléphone : ' + @Telephone;
END
```

## 6. Tests avec EXISTS

### Qu'est-ce que EXISTS ?

**EXISTS** vérifie si une requête retourne **au moins une ligne**. C'est très utile pour tester l'existence de données.

### Syntaxe

```sql
IF EXISTS (SELECT * FROM Table WHERE condition)
BEGIN
    -- Au moins une ligne existe
END
ELSE
BEGIN
    -- Aucune ligne n'existe
END
```

### Exemple : Vérifier si un client existe

```sql
DECLARE @ClientID INT = 123;

IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
BEGIN
    PRINT 'Le client existe';
    PRINT 'Vous pouvez continuer';
END
ELSE
BEGIN
    PRINT 'Client introuvable';
    PRINT 'Veuillez vérifier l''ID';
END
```

### Exemple : Éviter les doublons

```sql
DECLARE @Email VARCHAR(100) = 'nouveau@email.com';

IF EXISTS (SELECT 1 FROM Clients WHERE Email = @Email)
BEGIN
    PRINT 'Erreur : Cet email existe déjà';
    PRINT 'Utilisez un autre email';
END
ELSE
BEGIN
    -- Insérer le nouveau client
    INSERT INTO Clients (Email, Nom)
    VALUES (@Email, 'Nouveau Client');

    PRINT 'Client créé avec succès';
END
```

### SELECT 1 ou SELECT * dans EXISTS ?

```sql
IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = 123)   -- convention courante
IF EXISTS (SELECT * FROM Clients WHERE ClientID = 123)   -- strictement équivalent
```

**Important :** dans un `EXISTS`, les deux écritures ont **exactement la même performance**. SQL Server n'évalue jamais la liste de colonnes d'un `EXISTS` (il n'expanse même pas le `*`) : il vérifie seulement s'il existe **au moins une ligne**. Le choix est donc purement **stylistique** — beaucoup de développeurs écrivent `SELECT 1` par convention, pour signaler que « la liste de colonnes n'a aucune importance ici ». C'est une idée reçue fréquente de croire que `SELECT 1` serait plus rapide.

## 7. IF imbriqués (nested IF)

### Qu'est-ce que l'imbrication ?

Vous pouvez placer des structures IF **à l'intérieur** d'autres structures IF pour des logiques plus complexes.

### Exemple : Validation d'accès

```sql
DECLARE @Age INT = 25;
DECLARE @Permis BIT = 1;
DECLARE @Assurance BIT = 1;

IF @Age >= 18
BEGIN
    PRINT 'Vous avez l''âge requis';

    IF @Permis = 1
    BEGIN
        PRINT 'Vous avez un permis';

        IF @Assurance = 1
        BEGIN
            PRINT 'Vous avez une assurance';
            PRINT '✓ Vous pouvez louer une voiture';
        END
        ELSE
        BEGIN
            PRINT '✗ Assurance requise';
        END
    END
    ELSE
    BEGIN
        PRINT '✗ Permis de conduire requis';
    END
END
ELSE
BEGIN
    PRINT '✗ Âge minimum : 18 ans';
END
```

### ⚠️ Attention à la complexité

Trop d'imbrications rendent le code difficile à lire. Au-delà de 2-3 niveaux, envisagez de :
- Utiliser **CASE** (section suivante)
- Créer des **fonctions ou procédures** séparées
- Réorganiser la logique

## 8. Exemples pratiques complets

### Exemple 1 : Calcul de réduction

```sql
DECLARE @MontantAchat DECIMAL(10,2) = 250.00;
DECLARE @EstMembre BIT = 1;
DECLARE @Reduction DECIMAL(5,2);
DECLARE @MontantFinal DECIMAL(10,2);

-- Déterminer la réduction
IF @EstMembre = 1
BEGIN
    IF @MontantAchat >= 500
    BEGIN
        SET @Reduction = 25.00;
        PRINT 'Réduction membre premium : 25%';
    END
    ELSE IF @MontantAchat >= 200
    BEGIN
        SET @Reduction = 15.00;
        PRINT 'Réduction membre : 15%';
    END
    ELSE
    BEGIN
        SET @Reduction = 10.00;
        PRINT 'Réduction membre : 10%';
    END
END
ELSE
BEGIN
    IF @MontantAchat >= 300
    BEGIN
        SET @Reduction = 10.00;
        PRINT 'Réduction client : 10%';
    END
    ELSE
    BEGIN
        SET @Reduction = 0.00;
        PRINT 'Pas de réduction';
    END
END

-- Calculer le montant final
SET @MontantFinal = @MontantAchat * (1 - @Reduction / 100);

PRINT 'Montant initial : ' + CAST(@MontantAchat AS VARCHAR) + ' €';
PRINT 'Réduction : ' + CAST(@Reduction AS VARCHAR) + '%';
PRINT 'Montant final : ' + CAST(@MontantFinal AS VARCHAR) + ' €';
```

**Résultat :**
```
Réduction membre : 15%
Montant initial : 250.00 €
Réduction : 15%
Montant final : 212.50 €
```

### Exemple 2 : Validation de commande

```sql
DECLARE @CommandeID INT = 1001;
DECLARE @ClientID INT = 5;
DECLARE @Montant DECIMAL(10,2) = 150.00;

-- Variables de validation
DECLARE @ClientExiste BIT = 0;
DECLARE @Solde DECIMAL(10,2);
DECLARE @Actif BIT;

-- Vérifier si le client existe
IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
BEGIN
    SET @ClientExiste = 1;

    -- Récupérer les informations du client
    SELECT @Solde = Solde, @Actif = EstActif
    FROM Clients
    WHERE ClientID = @ClientID;

    -- Valider le compte
    IF @Actif = 0
    BEGIN
        PRINT 'Erreur : Compte client inactif';
    END
    ELSE IF @Solde < @Montant
    BEGIN
        PRINT 'Erreur : Solde insuffisant';
        PRINT 'Solde disponible : ' + CAST(@Solde AS VARCHAR) + ' €';
        PRINT 'Montant requis : ' + CAST(@Montant AS VARCHAR) + ' €';
    END
    ELSE
    BEGIN
        -- Tout est OK, traiter la commande
        INSERT INTO Commandes (CommandeID, ClientID, Montant, DateCommande)
        VALUES (@CommandeID, @ClientID, @Montant, GETDATE());

        -- Mettre à jour le solde
        UPDATE Clients
        SET Solde = Solde - @Montant
        WHERE ClientID = @ClientID;

        PRINT 'Commande enregistrée avec succès';
        PRINT 'Nouveau solde : ' + CAST(@Solde - @Montant AS VARCHAR) + ' €';
    END
END
ELSE
BEGIN
    PRINT 'Erreur : Client introuvable (ID: ' + CAST(@ClientID AS VARCHAR) + ')';
END
```

### Exemple 3 : Gestion des stocks

```sql
CREATE PROCEDURE GererStock
    @ProduitID INT,
    @QuantiteDemandee INT
AS
BEGIN
    DECLARE @Stock INT;
    DECLARE @SeuilMin INT = 10;
    DECLARE @NomProduit VARCHAR(100);

    -- Récupérer les informations du produit
    SELECT
        @Stock = QuantiteEnStock,
        @NomProduit = NomProduit
    FROM Produits
    WHERE ProduitID = @ProduitID;

    -- Vérifier si le produit existe
    IF @NomProduit IS NULL
    BEGIN
        PRINT 'Erreur : Produit introuvable';
        RETURN;
    END

    PRINT 'Produit : ' + @NomProduit;
    PRINT 'Stock actuel : ' + CAST(@Stock AS VARCHAR);

    -- Vérifier la disponibilité
    IF @Stock = 0
    BEGIN
        PRINT 'Statut : RUPTURE DE STOCK';
        PRINT 'Action : Commande urgente nécessaire';
    END
    ELSE IF @Stock < @QuantiteDemandee
    BEGIN
        PRINT 'Statut : Stock insuffisant';
        PRINT 'Disponible : ' + CAST(@Stock AS VARCHAR);
        PRINT 'Demandé : ' + CAST(@QuantiteDemandee AS VARCHAR);
        PRINT 'Manquant : ' + CAST(@QuantiteDemandee - @Stock AS VARCHAR);
    END
    ELSE
    BEGIN
        PRINT 'Statut : Stock suffisant';

        -- Effectuer la sortie de stock
        UPDATE Produits
        SET QuantiteEnStock = QuantiteEnStock - @QuantiteDemandee
        WHERE ProduitID = @ProduitID;

        SET @Stock = @Stock - @QuantiteDemandee;
        PRINT 'Stock après sortie : ' + CAST(@Stock AS VARCHAR);

        -- Vérifier si on atteint le seuil minimal
        IF @Stock < @SeuilMin
        BEGIN
            PRINT 'ALERTE : Stock faible (< ' + CAST(@SeuilMin AS VARCHAR) + ')';
            PRINT 'Action : Réapprovisionnement recommandé';
        END
    END
END
```

## 9. IF avec des calculs et fonctions

### Utiliser des expressions

Vous pouvez utiliser des calculs directement dans les conditions :

```sql
DECLARE @Prix DECIMAL(10,2) = 100.00;
DECLARE @Quantite INT = 5;

IF (@Prix * @Quantite) > 400
BEGIN
    PRINT 'Total important : réduction de 10%';
    PRINT 'Total : ' + CAST(@Prix * @Quantite * 0.9 AS VARCHAR) + ' €';
END
ELSE
BEGIN
    PRINT 'Total : ' + CAST(@Prix * @Quantite AS VARCHAR) + ' €';
END
```

### Utiliser des fonctions

```sql
DECLARE @DateNaissance DATE = '1990-05-15';
DECLARE @Age INT;

-- ⚠️ DATEDIFF(YEAR, ...) seul compte les changements d'année civile, PAS l'âge réel
-- (une personne née le 31/12 serait comptée « +1 an » dès le 1er janvier).
-- Âge exact : on retire 1 si l'anniversaire n'est pas encore passé cette année.
SET @Age = DATEDIFF(YEAR, @DateNaissance, GETDATE())
         - CASE WHEN MONTH(@DateNaissance) > MONTH(GETDATE())
                  OR (MONTH(@DateNaissance) = MONTH(GETDATE()) AND DAY(@DateNaissance) > DAY(GETDATE()))
                THEN 1 ELSE 0 END;

IF @Age >= 18 AND @Age < 25
BEGIN
    PRINT 'Vous bénéficiez de la réduction jeune';
END
ELSE IF @Age >= 65
BEGIN
    PRINT 'Vous bénéficiez de la réduction senior';
END
```

### Exemple avec fonctions de chaînes

```sql
DECLARE @Email VARCHAR(100) = 'contact@exemple.com';

IF @Email LIKE '%@%' AND @Email LIKE '%.%'
BEGIN
    PRINT 'Format d''email valide';

    -- Extraire le domaine
    DECLARE @Domaine VARCHAR(50);
    SET @Domaine = SUBSTRING(@Email, CHARINDEX('@', @Email) + 1, LEN(@Email));

    IF @Domaine IN ('gmail.com', 'yahoo.com', 'hotmail.com')
    BEGIN
        PRINT 'Fournisseur d''email populaire détecté';
    END
END
ELSE
BEGIN
    PRINT 'Format d''email invalide';
END
```

## 10. Comparaison IF vs CASE

### Quand utiliser IF ?

**IF** est préférable pour :
- Des conditions complexes avec plusieurs actions
- Des logiques avec des branches très différentes
- Des modifications de données (INSERT, UPDATE, DELETE)

### Quand utiliser CASE ?

**CASE** (que nous verrons dans la section suivante) est préférable pour :
- Affecter une valeur parmi plusieurs possibilités
- Utiliser dans un SELECT
- Des conditions simples sur une même variable

### Comparaison

**Avec IF :**
```sql
DECLARE @Jour INT = 3;
DECLARE @NomJour VARCHAR(20);

IF @Jour = 1
    SET @NomJour = 'Lundi';
ELSE IF @Jour = 2
    SET @NomJour = 'Mardi';
ELSE IF @Jour = 3
    SET @NomJour = 'Mercredi';
-- ... etc
```

**Avec CASE (plus élégant) :**
```sql
DECLARE @Jour INT = 3;
DECLARE @NomJour VARCHAR(20);

SET @NomJour = CASE @Jour
    WHEN 1 THEN 'Lundi'
    WHEN 2 THEN 'Mardi'
    WHEN 3 THEN 'Mercredi'
    -- ... etc
END;
```

## 11. Bonnes pratiques

### ✅ À FAIRE

1. **Toujours utiliser BEGIN ... END** même pour une instruction (cohérence)
2. **Tester les cas NULL** explicitement avec IS NULL / IS NOT NULL
3. **Ordonner les conditions** de la plus spécifique à la plus générale
4. **Commenter la logique complexe** pour expliquer le raisonnement
5. **Indenter correctement** pour améliorer la lisibilité
6. **Utiliser EXISTS** pour tester l'existence de lignes (plus performant)
7. **Valider les données** avant de les traiter

### ❌ À ÉVITER

1. **Ne jamais utiliser = NULL**, toujours IS NULL
2. **Éviter trop d'imbrications** (max 2-3 niveaux)
3. **Ne pas oublier le ELSE** quand nécessaire (toujours gérer tous les cas)
4. **Ne pas tester la même condition** plusieurs fois (inefficace)
5. **Éviter les conditions redondantes**

### Exemple de condition redondante

**❌ Mauvais :**
```sql
IF @Age >= 18
BEGIN
    IF @Age < 65
    BEGIN
        -- Adulte
    END
    ELSE
    BEGIN
        -- Senior
    END
END
ELSE
BEGIN
    -- Mineur
END
```

**✅ Meilleur :**
```sql
IF @Age < 18
BEGIN
    -- Mineur
END
ELSE IF @Age < 65
BEGIN
    -- Adulte
END
ELSE
BEGIN
    -- Senior
END
```

## 12. Débogage et messages d'erreur

### Utiliser PRINT pour déboguer

```sql
DECLARE @Valeur INT = 50;

PRINT 'Début du test'; -- Message de débogage

IF @Valeur > 100
BEGIN
    PRINT 'Branche 1 : Valeur > 100';
END
ELSE IF @Valeur > 50
BEGIN
    PRINT 'Branche 2 : Valeur > 50';
END
ELSE
BEGIN
    PRINT 'Branche 3 : Valeur <= 50';
    PRINT 'Valeur actuelle : ' + CAST(@Valeur AS VARCHAR);
END

PRINT 'Fin du test';
```

### Afficher des messages informatifs

```sql
IF @@ROWCOUNT = 0
BEGIN
    PRINT 'Avertissement : Aucune ligne n''a été affectée';
    PRINT 'Vérifiez vos critères de recherche';
END
ELSE
BEGIN
    PRINT 'Succès : ' + CAST(@@ROWCOUNT AS VARCHAR) + ' ligne(s) modifiée(s)';
END
```

## Résumé

- **IF** permet d'exécuter du code conditionnellement
- **ELSE** définit ce qui se passe quand la condition est fausse
- **ELSE IF** permet de tester plusieurs conditions en séquence
- Les **opérateurs de comparaison** (=, <>, >, <, >=, <=) testent des valeurs
- Les **opérateurs logiques** (AND, OR, NOT) combinent des conditions
- **IS NULL** et **IS NOT NULL** testent les valeurs NULL
- **EXISTS** vérifie l'existence de lignes dans une requête
- Toujours utiliser **BEGIN ... END** pour regrouper plusieurs instructions
- Une **bonne indentation** est essentielle pour la lisibilité
- Éviter trop d'**imbrications** (préférer des structures plus simples ou CASE)

Les conditions IF ... ELSE sont le fondement de la logique en T-SQL. Elles vous permettent de créer des scripts intelligents qui s'adaptent aux données et aux situations. Dans la section suivante, nous découvrirons les boucles WHILE pour répéter des actions.
