# 2.3.6 NOT NULL vs NULL

## Introduction

Imaginez un formulaire d'inscription où certains champs sont **obligatoires** (nom, prénom, email) et d'autres sont **optionnels** (numéro de téléphone, date de naissance). Si quelqu'un laisse un champ optionnel vide, que mettez-vous dans la base de données ?

C'est là qu'intervient le concept de **NULL**. NULL représente l'**absence de valeur**, le **vide**, l'**inconnu**. Et **NOT NULL** est la contrainte qui rend un champ **obligatoire**.

**Analogie :** NULL est comme une case vide dans un formulaire papier - elle n'est ni 0, ni une chaîne vide, ni rien de spécifique. C'est l'**absence d'information**.

## Qu'est-ce que NULL ?

### Définition

**NULL** est une valeur spéciale en SQL qui représente :
- L'**absence de données**
- Une valeur **inconnue**
- Une valeur **non applicable**
- Une valeur **non encore saisie**

**Important :** NULL n'est **PAS** :
- ❌ Zéro (0)
- ❌ Une chaîne vide ('')
- ❌ Un espace (' ')
- ❌ La valeur "NULL" comme texte

### Exemple Visuel

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100) NOT NULL,        -- Obligatoire
    Prenom VARCHAR(50) NOT NULL,      -- Obligatoire
    Email VARCHAR(150) NOT NULL,      -- Obligatoire
    Telephone VARCHAR(20),            -- Optionnel (NULL autorisé)
    DateNaissance DATE,               -- Optionnel (NULL autorisé)
    Salaire DECIMAL(10,2)            -- Optionnel (NULL autorisé)
);
```

**Données exemple :**

| IdEmploye | Nom | Prenom | Email | Telephone | DateNaissance | Salaire |
|-----------|-----|--------|-------|-----------|---------------|---------|
| 1 | Dupont | Marie | marie@email.com | 0612345678 | 1990-05-15 | 3500.00 |
| 2 | Martin | Paul | paul@email.com | NULL | NULL | 3200.00 |
| 3 | Bernard | Sophie | sophie@email.com | 0698765432 | 1985-08-20 | NULL |

**Interprétation :**
- Paul n'a pas fourni son téléphone ni sa date de naissance : **NULL**
- Sophie n'a pas encore de salaire défini : **NULL**
- Les colonnes Nom, Prenom, Email sont toujours renseignées (NOT NULL)

## NULL vs NOT NULL : La Différence Fondamentale

### Colonne Autorisant NULL (Par Défaut)

Par défaut, si vous ne spécifiez rien, une colonne **autorise NULL** :

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50)  -- NULL autorisé (comportement par défaut)
);

-- ✅ OK : Insertion sans valeur
INSERT INTO Test (Id) VALUES (1);
-- Colonne = NULL

-- ✅ OK : Insertion explicite de NULL
INSERT INTO Test (Id, Colonne) VALUES (2, NULL);
-- Colonne = NULL

-- ✅ OK : Insertion avec valeur
INSERT INTO Test (Id, Colonne) VALUES (3, 'Valeur');
-- Colonne = 'Valeur'
```

### Colonne avec NOT NULL (Obligatoire)

Avec NOT NULL, la colonne **doit toujours avoir une valeur** :

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50) NOT NULL  -- Obligatoire
);

-- ❌ ERREUR : Insertion sans valeur
INSERT INTO Test (Id) VALUES (1);
-- Erreur : Cannot insert NULL into column 'Colonne'

-- ❌ ERREUR : Insertion explicite de NULL
INSERT INTO Test (Id, Colonne) VALUES (2, NULL);
-- Erreur : Cannot insert NULL into column 'Colonne'

-- ✅ OK : Insertion avec valeur
INSERT INTO Test (Id, Colonne) VALUES (3, 'Valeur');
-- Colonne = 'Valeur'
```

## Quand Utiliser NOT NULL ?

### Colonnes qui Doivent Toujours Avoir une Valeur

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Email VARCHAR(150) NOT NULL,      -- Un client doit avoir un email
    Nom VARCHAR(100) NOT NULL,         -- Un client doit avoir un nom
    Prenom VARCHAR(50) NOT NULL,       -- Un client doit avoir un prénom
    DateInscription DATE NOT NULL,     -- Une inscription a toujours une date
    Telephone VARCHAR(20),             -- Optionnel
    Adresse TEXT                        -- Optionnel
);
```

**Règle générale :** Utilisez NOT NULL pour les colonnes **essentielles** à l'identité ou à la logique métier de l'enregistrement.

### Exemples de Colonnes NOT NULL

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    CodeProduit VARCHAR(20) NOT NULL UNIQUE,  -- Code obligatoire et unique
    Nom VARCHAR(150) NOT NULL,                 -- Nom obligatoire
    Prix DECIMAL(10,2) NOT NULL,               -- Prix obligatoire
    Description TEXT,                          -- Description optionnelle
    ImageURL VARCHAR(500)                      -- Image optionnelle
);

CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    NumeroCommande VARCHAR(30) NOT NULL UNIQUE,
    IdClient INT NOT NULL,                     -- Commande doit avoir un client
    DateCommande DATETIME2 NOT NULL,           -- Date obligatoire
    MontantTotal DECIMAL(10,2) NOT NULL,       -- Montant obligatoire
    CommentaireClient TEXT,                    -- Commentaire optionnel
    DateLivraison DATE                         -- Date livraison optionnelle (pas encore livrée)
);
```

## Quand Autoriser NULL ?

### Colonnes Optionnelles ou Non Applicables

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100) NOT NULL,
    Prenom VARCHAR(50) NOT NULL,
    Email VARCHAR(150) NOT NULL,
    Telephone VARCHAR(20),              -- Optionnel : tous les employés n'ont pas de téléphone
    TelephoneMobile VARCHAR(20),        -- Optionnel
    DateNaissance DATE,                 -- Optionnel : donnée sensible, pas toujours fournie
    Salaire DECIMAL(10,2),             -- Optionnel : peut ne pas être encore défini
    IdManager INT,                      -- Optionnel : le PDG n'a pas de manager
    DateDepart DATE                     -- NULL si l'employé est toujours en poste
);
```

### Données Temporairement Manquantes

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    NumeroCommande VARCHAR(30) NOT NULL,
    DateCommande DATETIME2 NOT NULL,
    DateExpedition DATETIME2,           -- NULL jusqu'à l'expédition
    DateLivraison DATETIME2,            -- NULL jusqu'à la livraison
    NumeroSuivi VARCHAR(50)            -- NULL jusqu'à génération du numéro
);
```

## Comportement de NULL dans les Opérations

### 1. Comparaisons avec NULL

NULL a un comportement spécial dans les comparaisons. Vous **ne pouvez pas** utiliser `=` ou `!=` avec NULL.

```sql
CREATE TABLE Test (Id INT, Valeur INT);
INSERT INTO Test VALUES (1, 10), (2, NULL), (3, 20);

-- ❌ MAUVAIS : N'utilise pas = NULL
SELECT * FROM Test WHERE Valeur = NULL;
-- Résultat : Aucune ligne (ne fonctionne pas !)

-- ❌ MAUVAIS : N'utilise pas != NULL
SELECT * FROM Test WHERE Valeur != NULL;
-- Résultat : Aucune ligne (ne fonctionne pas !)

-- ✅ BON : Utilise IS NULL
SELECT * FROM Test WHERE Valeur IS NULL;
-- Résultat : Id=2

-- ✅ BON : Utilise IS NOT NULL
SELECT * FROM Test WHERE Valeur IS NOT NULL;
-- Résultat : Id=1, Id=3
```

**Règle importante :** Utilisez toujours `IS NULL` et `IS NOT NULL` pour tester les valeurs NULL.

### 2. NULL dans les Calculs Arithmétiques

Toute opération arithmétique avec NULL retourne NULL :

```sql
CREATE TABLE Produits (Id INT, Prix DECIMAL(10,2), Remise DECIMAL(10,2));
INSERT INTO Produits VALUES
    (1, 100.00, 10.00),
    (2, 200.00, NULL),
    (3, NULL, 20.00);

-- Calcul du prix après remise
SELECT
    Id,
    Prix,
    Remise,
    Prix - Remise AS PrixFinal
FROM Produits;
```

**Résultat :**

| Id | Prix | Remise | PrixFinal |
|----|------|--------|-----------|
| 1 | 100.00 | 10.00 | 90.00 |
| 2 | 200.00 | NULL | NULL |
| 3 | NULL | 20.00 | NULL |

**Explication :**
- `100 - 10 = 90` ✅
- `200 - NULL = NULL` (pas 200 !)
- `NULL - 20 = NULL` (pas -20 !)

**Solution avec COALESCE :**

```sql
SELECT
    Id,
    Prix,
    Remise,
    COALESCE(Prix, 0) - COALESCE(Remise, 0) AS PrixFinal
FROM Produits;
```

**Résultat :**

| Id | Prix | Remise | PrixFinal |
|----|------|--------|-----------|
| 1 | 100.00 | 10.00 | 90.00 |
| 2 | 200.00 | NULL | 200.00 |
| 3 | NULL | 20.00 | -20.00 |

### 3. NULL dans les Fonctions d'Agrégation

Les fonctions d'agrégation **ignorent** les valeurs NULL (sauf COUNT(*)) :

```sql
CREATE TABLE Notes (IdEtudiant INT, Note INT);
INSERT INTO Notes VALUES
    (1, 15),
    (2, NULL),
    (3, 18),
    (4, NULL),
    (5, 12);

SELECT
    COUNT(*) AS NombreLignes,           -- Compte toutes les lignes
    COUNT(Note) AS NombreNotes,          -- Compte les valeurs non-NULL
    AVG(Note) AS Moyenne,                -- Moyenne des valeurs non-NULL
    SUM(Note) AS Somme,                  -- Somme des valeurs non-NULL
    MIN(Note) AS Minimum,                -- Min des valeurs non-NULL
    MAX(Note) AS Maximum                 -- Max des valeurs non-NULL
FROM Notes;
```

**Résultat :**

| NombreLignes | NombreNotes | Moyenne | Somme | Minimum | Maximum |
|--------------|-------------|---------|-------|---------|---------|
| 5 | 3 | 15 | 45 | 12 | 18 |

**Important :**
- `COUNT(*)` = 5 (toutes les lignes)
- `COUNT(Note)` = 3 (seulement les valeurs non-NULL)
- `AVG(Note)` = 15 (45 ÷ 3, pas 45 ÷ 5)

### 4. NULL dans les Conditions Logiques

NULL a un comportement spécial avec AND, OR, NOT :

```sql
-- Logique à trois valeurs : TRUE, FALSE, NULL

-- TRUE AND NULL = NULL
-- FALSE AND NULL = FALSE
-- TRUE OR NULL = TRUE
-- FALSE OR NULL = NULL
-- NOT NULL = NULL
```

**Exemple pratique :**

```sql
CREATE TABLE Test (Id INT, Valeur1 INT, Valeur2 INT);
INSERT INTO Test VALUES
    (1, 10, 20),
    (2, NULL, 20),
    (3, 10, NULL);

-- Recherche : Valeur1 > 5 AND Valeur2 > 15
SELECT * FROM Test WHERE Valeur1 > 5 AND Valeur2 > 15;
```

**Résultat :**

| Id | Valeur1 | Valeur2 |
|----|---------|---------|
| 1 | 10 | 20 |

**Explication :**
- Id=1 : `10 > 5 AND 20 > 15` = TRUE AND TRUE = TRUE ✅
- Id=2 : `NULL > 5 AND 20 > 15` = NULL AND TRUE = NULL ❌
- Id=3 : `10 > 5 AND NULL > 15` = TRUE AND NULL = NULL ❌

Les lignes avec résultat NULL ne sont **pas** retournées par WHERE.

### 5. NULL et ORDER BY

NULL est trié **en premier** par défaut (considéré comme la plus petite valeur) :

```sql
CREATE TABLE Test (Id INT, Valeur INT);
INSERT INTO Test VALUES (1, 20), (2, NULL), (3, 10), (4, NULL), (5, 30);

-- Tri croissant
SELECT * FROM Test ORDER BY Valeur ASC;
```

**Résultat :**

| Id | Valeur |
|----|--------|
| 2 | NULL |
| 4 | NULL |
| 3 | 10 |
| 1 | 20 |
| 5 | 30 |

```sql
-- Tri décroissant
SELECT * FROM Test ORDER BY Valeur DESC;
```

**Résultat :**

| Id | Valeur |
|----|--------|
| 5 | 30 |
| 1 | 20 |
| 3 | 10 |
| 2 | NULL |
| 4 | NULL |

## Fonctions pour Gérer NULL

SQL Server propose plusieurs fonctions pour gérer les valeurs NULL.

### 1. ISNULL(valeur, remplacement)

Remplace NULL par une valeur de remplacement :

```sql
CREATE TABLE Produits (Id INT, Nom VARCHAR(50), Prix DECIMAL(10,2));
INSERT INTO Produits VALUES
    (1, 'Ordinateur', 899.99),
    (2, 'Souris', NULL),
    (3, 'Clavier', 149.99);

SELECT
    Id,
    Nom,
    Prix,
    ISNULL(Prix, 0.00) AS PrixAvecDefault
FROM Produits;
```

**Résultat :**

| Id | Nom | Prix | PrixAvecDefault |
|----|-----|------|-----------------|
| 1 | Ordinateur | 899.99 | 899.99 |
| 2 | Souris | NULL | 0.00 |
| 3 | Clavier | 149.99 | 149.99 |

### 2. COALESCE(val1, val2, val3, ...)

Retourne la première valeur non-NULL :

```sql
CREATE TABLE Contacts (Id INT, Tel1 VARCHAR(20), Tel2 VARCHAR(20), Tel3 VARCHAR(20));
INSERT INTO Contacts VALUES
    (1, '0612345678', '0698765432', NULL),
    (2, NULL, '0687654321', '0123456789'),
    (3, NULL, NULL, '0198765432'),
    (4, NULL, NULL, NULL);

SELECT
    Id,
    COALESCE(Tel1, Tel2, Tel3, 'Aucun téléphone') AS TelephoneContact
FROM Contacts;
```

**Résultat :**

| Id | TelephoneContact |
|----|------------------|
| 1 | 0612345678 |
| 2 | 0687654321 |
| 3 | 0198765432 |
| 4 | Aucun téléphone |

### 3. NULLIF(val1, val2)

Retourne NULL si val1 = val2, sinon retourne val1 :

```sql
SELECT
    NULLIF(10, 10) AS Resultat1,  -- NULL (10 = 10)
    NULLIF(10, 5) AS Resultat2,    -- 10 (10 != 5)
    NULLIF('', '') AS Resultat3,   -- NULL ('' = '')
    NULLIF('test', '') AS Resultat4 -- 'test' ('test' != '')
```

**Cas d'usage :** Éviter la division par zéro :

```sql
CREATE TABLE Ventes (Id INT, Montant DECIMAL(10,2), Quantite INT);
INSERT INTO Ventes VALUES
    (1, 100.00, 10),
    (2, 200.00, 0),   -- Quantité nulle
    (3, 150.00, 5);

-- Sans NULLIF : Division par zéro
-- SELECT Montant / Quantite FROM Ventes;  -- ERREUR sur ligne 2

-- Avec NULLIF : Évite l'erreur
SELECT
    Id,
    Montant,
    Quantite,
    Montant / NULLIF(Quantite, 0) AS PrixUnitaire
FROM Ventes;
```

**Résultat :**

| Id | Montant | Quantite | PrixUnitaire |
|----|---------|----------|--------------|
| 1 | 100.00 | 10 | 10.00 |
| 2 | 200.00 | 0 | NULL |
| 3 | 150.00 | 5 | 30.00 |

### 4. IS NULL et IS NOT NULL

Tester la présence ou l'absence de NULL :

```sql
CREATE TABLE Employes (Id INT, Nom VARCHAR(50), Email VARCHAR(100), Telephone VARCHAR(20));
INSERT INTO Employes VALUES
    (1, 'Dupont', 'dupont@email.com', '0612345678'),
    (2, 'Martin', 'martin@email.com', NULL),
    (3, 'Bernard', NULL, '0698765432');

-- Employés sans email
SELECT * FROM Employes WHERE Email IS NULL;

-- Employés avec téléphone
SELECT * FROM Employes WHERE Telephone IS NOT NULL;
```

## Ajouter ou Retirer NOT NULL

### Ajouter NOT NULL à une Colonne Existante

```sql
-- Table avec colonne autorisant NULL
CREATE TABLE Test (Id INT, Colonne VARCHAR(50));
INSERT INTO Test VALUES (1, 'Valeur'), (2, NULL), (3, 'Autre');

-- ❌ ERREUR : Impossible d'ajouter NOT NULL si des NULL existent
ALTER TABLE Test
ALTER COLUMN Colonne VARCHAR(50) NOT NULL;
-- Erreur : Cannot define NOT NULL... NULL values exist

-- ✅ Solution : D'abord éliminer les NULL
UPDATE Test SET Colonne = 'Valeur par défaut' WHERE Colonne IS NULL;

-- Maintenant on peut ajouter NOT NULL
ALTER TABLE Test
ALTER COLUMN Colonne VARCHAR(50) NOT NULL;
```

### Retirer NOT NULL d'une Colonne

```sql
-- Rendre une colonne optionnelle
ALTER TABLE Test
ALTER COLUMN Colonne VARCHAR(50) NULL;  -- Autorise maintenant NULL
```

## NULL et les Performances

### Impact sur les Index

Les valeurs NULL peuvent affecter les index :

```sql
-- Index sur une colonne avec beaucoup de NULL
CREATE INDEX IX_Employes_DateDepart ON Employes(DateDepart);
-- Les employés toujours en poste (DateDepart = NULL) ne sont pas dans l'index non-clustered

-- Solution : Index filtré (uniquement les valeurs non-NULL)
CREATE INDEX IX_Employes_DateDepart
ON Employes(DateDepart)
WHERE DateDepart IS NOT NULL;
```

### Recherches avec IS NULL

Les recherches avec `IS NULL` peuvent être moins performantes :

```sql
-- Peut nécessiter un scan complet
SELECT * FROM Employes WHERE Telephone IS NULL;

-- Mieux : Index filtré si les NULL sont fréquents
CREATE INDEX IX_Employes_Telephone
ON Employes(Telephone)
WHERE Telephone IS NOT NULL;
```

### Statistiques sur les NULL

```sql
-- Compter les NULL par colonne
SELECT
    'Telephone' AS Colonne,
    COUNT(*) AS Total,
    COUNT(Telephone) AS NonNull,
    COUNT(*) - COUNT(Telephone) AS NullCount,
    CAST((COUNT(*) - COUNT(Telephone)) * 100.0 / COUNT(*) AS DECIMAL(5,2)) AS PourcentageNull

SELECT

    COUNT(DateNaissance),

    CAST((COUNT(*) - COUNT(DateNaissance)) * 100.0 / COUNT(*) AS DECIMAL(5,2))
FROM Clients;
```

## Erreurs Courantes et Solutions

### Erreur 1 : Comparaison avec = NULL

```sql
-- ❌ ERREUR : Ne fonctionne pas
SELECT * FROM Employes WHERE Telephone = NULL;
-- Résultat : Aucune ligne (même s'il y a des NULL)

-- ✅ CORRECT : Utiliser IS NULL
SELECT * FROM Employes WHERE Telephone IS NULL;
```

### Erreur 2 : Oublier les NULL dans les Calculs

```sql
-- ❌ PROBLÈME : Prix NULL cause PrixFinal NULL
SELECT Prix - Remise AS PrixFinal FROM Produits;

-- ✅ SOLUTION : Gérer les NULL
SELECT COALESCE(Prix, 0) - COALESCE(Remise, 0) AS PrixFinal FROM Produits;
```

### Erreur 3 : COUNT(*) vs COUNT(Colonne)

```sql
-- Table avec des NULL
CREATE TABLE Test (Id INT, Valeur INT);
INSERT INTO Test VALUES (1, 10), (2, NULL), (3, 20);

-- COUNT(*) compte toutes les lignes
SELECT COUNT(*) FROM Test;  -- Résultat : 3

-- COUNT(Colonne) compte seulement les non-NULL
SELECT COUNT(Valeur) FROM Test;  -- Résultat : 2
```

### Erreur 4 : NOT NULL sans Valeur par Défaut

```sql
-- ❌ PROBLÈME : Colonne NOT NULL sans DEFAULT
CREATE TABLE Test (Id INT, Colonne INT NOT NULL);

-- Impossible d'insérer sans valeur
-- INSERT INTO Test (Id) VALUES (1);  -- ERREUR

-- ✅ SOLUTION 1 : Ajouter un DEFAULT
ALTER TABLE Test
ADD CONSTRAINT DF_Test_Colonne DEFAULT 0 FOR Colonne;

-- ✅ SOLUTION 2 : Toujours fournir la valeur
INSERT INTO Test (Id, Colonne) VALUES (1, 0);
```

## Bonnes Pratiques

### 1. Préférer NOT NULL quand Possible

```sql
-- ✅ BON : Colonnes essentielles NOT NULL
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Email VARCHAR(150) NOT NULL,
    Nom VARCHAR(100) NOT NULL,
    DateInscription DATE NOT NULL DEFAULT GETDATE()
);

-- ⚠️ À éviter : Tout en NULL
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Email VARCHAR(150),        -- Devrait être NOT NULL
    Nom VARCHAR(100),          -- Devrait être NOT NULL
    DateInscription DATE       -- Devrait être NOT NULL
);
```

### 2. Combiner NOT NULL avec DEFAULT

```sql
-- ✅ BON : Colonne obligatoire avec valeur par défaut
DateCreation DATETIME2 NOT NULL DEFAULT GETDATE()
EstActif BIT NOT NULL DEFAULT 1
Statut VARCHAR(20) NOT NULL DEFAULT 'En attente'
```

### 3. Documenter la Signification de NULL

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    DateCommande DATETIME2 NOT NULL,
    DateExpedition DATETIME2,     -- NULL = pas encore expédiée
    DateLivraison DATETIME2,      -- NULL = pas encore livrée
    DateAnnulation DATETIME2      -- NULL = commande non annulée
);
```

### 4. Éviter les Chaînes Vides pour Remplacer NULL

```sql
-- ❌ MAUVAIS : Chaîne vide au lieu de NULL
UPDATE Clients SET Telephone = '' WHERE Telephone IS NULL;

-- ✅ BON : Laisser NULL ou utiliser une vraie valeur par défaut
-- NULL signifie "pas de téléphone"
-- '' (chaîne vide) est ambigu
```

### 5. Attention aux NULL dans les Clés Étrangères

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,              -- NULL autorisé
    CONSTRAINT FK_Commandes_Clients FOREIGN KEY (IdClient) REFERENCES Clients(IdClient)
);

-- NULL est autorisé dans une clé étrangère (commande anonyme)
-- Mais demandez-vous si cela a un sens métier
```

### 6. Utiliser COALESCE pour les Affichages

```sql
-- ✅ BON : Affichage clair pour l'utilisateur
SELECT
    Nom,
    COALESCE(Telephone, 'Non renseigné') AS Telephone,
    COALESCE(Email, 'Aucun email') AS Email
FROM Clients;
```

### 7. NULL dans les Conditions WHERE

```sql
-- Recherche incluant les NULL
SELECT * FROM Employes
WHERE (Telephone IS NULL OR Telephone LIKE '06%');

-- Exclusion explicite des NULL
SELECT * FROM Employes
WHERE Telephone IS NOT NULL AND Telephone LIKE '06%';
```

## NULL dans Différents Contextes

### NULL dans les Contraintes

```sql
-- UNIQUE autorise plusieurs NULL
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Email VARCHAR(150) UNIQUE  -- Plusieurs NULL autorisés
);

INSERT INTO Test VALUES (1, NULL), (2, NULL);  -- ✅ OK
INSERT INTO Test VALUES (3, 'test@email.com'), (4, 'test@email.com');  -- ❌ ERREUR

-- CHECK ignore les NULL
CREATE TABLE Test2
(
    Id INT PRIMARY KEY,
    Age INT CHECK (Age >= 18)
);

INSERT INTO Test2 VALUES (1, NULL);  -- ✅ OK (CHECK ne s'applique pas à NULL)
INSERT INTO Test2 VALUES (2, 15);     -- ❌ ERREUR
```

## Résumé

| Aspect | NULL | NOT NULL |
|--------|------|----------|
| **Signification** | Absence de valeur, inconnu | Valeur obligatoire |
| **Par défaut** | Oui (si non spécifié) | Non (doit être spécifié) |
| **Test** | `IS NULL` / `IS NOT NULL` | Comparaisons normales |
| **Calculs** | Résultat = NULL | Calculs normaux |
| **Agrégations** | Ignoré (sauf COUNT(*)) | Inclus |
| **Comparaisons** | `= NULL` ne fonctionne pas | Fonctionne normalement |
| **Usage** | Données optionnelles | Données essentielles |

## Points Clés à Retenir

1. ✅ NULL représente l'**absence de valeur**, pas zéro ni chaîne vide
2. ✅ Utilisez **NOT NULL** pour les colonnes **essentielles**
3. ⚠️ Toujours utiliser **IS NULL** et **IS NOT NULL**, jamais `= NULL`
4. ⚠️ NULL dans les calculs **propage** le NULL (résultat = NULL)
5. ✅ Fonctions utiles : **ISNULL()**, **COALESCE()**, **NULLIF()**
6. ✅ Combinez NOT NULL avec **DEFAULT** pour valeurs obligatoires
7. 🎯 Préférez NOT NULL quand possible pour éviter les bugs
8. 📊 Les agrégations **ignorent** les NULL (sauf COUNT(*))
