# 5.4.1 CREATE VIEW - Abstraction de requêtes complexes

## Introduction aux Vues

Une **vue** (ou *view* en anglais) est un objet de base de données qui agit comme une "table virtuelle". Contrairement à une table réelle qui stocke physiquement des données sur le disque, une vue ne stocke que la **définition d'une requête SQL**.

Lorsque vous interrogez une vue, SQL Server exécute automatiquement la requête sous-jacente et vous retourne les résultats comme s'il s'agissait d'une table ordinaire.

### Analogie simple

Pensez à une vue comme à un **raccourci sur votre bureau** :
- Le raccourci ne contient pas le fichier lui-même
- Il pointe simplement vers l'emplacement réel du fichier
- Quand vous double-cliquez, le fichier s'ouvre automatiquement

De la même manière, une vue ne contient pas de données, mais "pointe" vers une requête qui récupère ces données depuis les tables réelles.

---

## Pourquoi utiliser des vues ?

Les vues offrent plusieurs avantages majeurs :

### 1. **Simplification de requêtes complexes**

Imaginez que vous devez régulièrement exécuter cette requête compliquée :

```sql
SELECT
    c.NomClient,
    c.Email,
    COUNT(co.CommandeID) AS NombreCommandes,
    SUM(co.MontantTotal) AS TotalAchats,
    MAX(co.DateCommande) AS DerniereCommande
FROM Clients c
INNER JOIN Commandes co ON c.ClientID = co.ClientID
WHERE co.Statut = 'Validée'
GROUP BY c.ClientID, c.NomClient, c.Email;
```

Au lieu de réécrire cette requête à chaque fois, vous pouvez créer une vue. Ensuite, il suffira d'écrire :

```sql
SELECT * FROM VueClientsActifs;
```

### 2. **Réutilisabilité**

Une fois créée, une vue peut être utilisée par plusieurs utilisateurs, applications ou autres requêtes. Cela évite la duplication de code.

### 3. **Encapsulation de la logique métier**

Les vues permettent de cacher la complexité des relations entre tables. Les utilisateurs finaux ou les développeurs juniors peuvent interroger la vue sans comprendre toute la logique sous-jacente.

### 4. **Cohérence des données**

Si la logique de calcul change, vous modifiez simplement la vue. Toutes les requêtes qui utilisent cette vue bénéficient automatiquement de la mise à jour.

### 5. **Sécurité et contrôle d'accès**

Vous pouvez donner l'accès à une vue qui montre uniquement certaines colonnes ou lignes, sans donner accès aux tables complètes sous-jacentes.

---

## Syntaxe de CREATE VIEW

La syntaxe de base pour créer une vue est la suivante :

```sql
CREATE VIEW nom_de_la_vue
AS
    -- Votre requête SELECT ici
    SELECT colonne1, colonne2, ...
    FROM table
    WHERE condition;
```

### Règles importantes

1. La clause `AS` est **obligatoire** et introduit la requête SELECT
2. Une vue doit contenir au minimum une instruction `SELECT`
3. Le nom de la vue doit être unique dans le schéma
4. Les vues ne peuvent pas contenir de clause `ORDER BY` (sauf si utilisée avec `TOP` ou `OFFSET-FETCH`)
5. Les vues ne peuvent pas référencer de tables temporaires

## Exemples pratiques

### Exemple 1 : Vue simple - Clients actifs

Supposons que nous ayons une table `Clients` avec les colonnes suivantes :
- `ClientID`
- `Nom`
- `Prenom`
- `Email`
- `Actif` (BIT - 1 pour actif, 0 pour inactif)

**Créer une vue des clients actifs uniquement :**

```sql
CREATE VIEW VueClientsActifs
AS
    SELECT
        ClientID,
        Nom,
        Prenom,
        Email
    FROM Clients
    WHERE Actif = 1;
```

**Utilisation de la vue :**

```sql
-- Au lieu de répéter la condition WHERE à chaque fois
SELECT * FROM VueClientsActifs;

-- Vous pouvez aussi filtrer davantage
SELECT * FROM VueClientsActifs
WHERE Nom LIKE 'D%';
```

---

### Exemple 2 : Vue avec jointure - Commandes détaillées

Imaginons deux tables :

**Table Commandes :**
- `CommandeID`
- `ClientID`
- `DateCommande`
- `MontantTotal`

**Table Clients :**
- `ClientID`
- `Nom`
- `Prenom`

**Créer une vue qui combine ces informations :**

```sql
CREATE VIEW VueCommandesDetaillees
AS
    SELECT
        co.CommandeID,
        co.DateCommande,
        co.MontantTotal,
        c.Nom,
        c.Prenom,
        c.Email
    FROM Commandes co
    INNER JOIN Clients c ON co.ClientID = c.ClientID;
```

**Utilisation :**

```sql
-- Requête simple sur la vue
SELECT * FROM VueCommandesDetaillees
WHERE MontantTotal > 1000;

-- Agrégation sur la vue
SELECT
    Nom,
    Prenom,
    COUNT(*) AS NombreCommandes,
    SUM(MontantTotal) AS TotalDepense
FROM VueCommandesDetaillees
GROUP BY Nom, Prenom;
```

---

### Exemple 3 : Vue avec calculs - Statistiques de ventes

**Créer une vue avec des colonnes calculées :**

```sql
CREATE VIEW VueStatistiquesVentes
AS
    SELECT
        co.CommandeID,
        co.DateCommande,
        co.MontantTotal,
        co.MontantTotal * 0.20 AS TVA,
        co.MontantTotal * 1.20 AS MontantTTC,
        YEAR(co.DateCommande) AS Annee,
        MONTH(co.DateCommande) AS Mois
    FROM Commandes co;
```

**Utilisation :**

```sql
-- Voir les ventes de 2024
SELECT * FROM VueStatistiquesVentes
WHERE Annee = 2024;

-- Calculer le total TTC par mois
SELECT
    Annee,
    Mois,
    SUM(MontantTTC) AS TotalMensuel
FROM VueStatistiquesVentes
GROUP BY Annee, Mois
ORDER BY Annee, Mois;
```

---

### Exemple 4 : Vue complexe - Rapport de synthèse client

**Vue qui combine plusieurs tables et agrégations :**

```sql
CREATE VIEW VueSyntheseClients
AS
    SELECT
        c.ClientID,
        c.Nom + ' ' + c.Prenom AS NomComplet,
        c.Email,
        c.Ville,
        COUNT(co.CommandeID) AS NombreCommandes,
        ISNULL(SUM(co.MontantTotal), 0) AS TotalAchats,
        ISNULL(AVG(co.MontantTotal), 0) AS MoyenneParCommande,
        MAX(co.DateCommande) AS DerniereCommande
    FROM Clients c
    LEFT JOIN Commandes co ON c.ClientID = co.ClientID
    GROUP BY
        c.ClientID,
        c.Nom,
        c.Prenom,
        c.Email,
        c.Ville;
```

**Utilisation :**

```sql
-- Clients qui ont dépensé plus de 5000€
SELECT * FROM VueSyntheseClients
WHERE TotalAchats > 5000;

-- Top 10 des meilleurs clients
SELECT TOP 10 * FROM VueSyntheseClients
ORDER BY TotalAchats DESC;

-- Clients sans commande
SELECT * FROM VueSyntheseClients
WHERE NombreCommandes = 0;
```

## Utilisation du préfixe de schéma

Il est recommandé d'utiliser le schéma lors de la création d'une vue :

```sql
CREATE VIEW dbo.VueClientsActifs
AS
    SELECT ClientID, Nom, Prenom, Email
    FROM dbo.Clients
    WHERE Actif = 1;
```

Le schéma `dbo` (database owner) est le schéma par défaut, mais préciser le schéma améliore la clarté et évite les ambiguïtés.

---

## Convention de nommage

Bien qu'il n'y ait pas de règle stricte, voici quelques conventions courantes :

**Avec préfixe :**
- `vw_ClientsActifs`
- `v_CommandesDetaillees`
- `Vue_StatistiquesVentes`

**Sans préfixe (plus moderne) :**
- `ClientsActifs`
- `CommandesDetaillees`
- `StatistiquesVentes`

L'important est de rester **cohérent** dans votre équipe ou projet.

---

## Vérifier qu'une vue existe

Avant de créer une vue, vous pouvez vérifier si elle existe déjà :

```sql
-- Méthode 1 : Supprimer si elle existe
DROP VIEW IF EXISTS VueClientsActifs;

-- Ensuite créer la vue
CREATE VIEW VueClientsActifs
AS
    SELECT ClientID, Nom, Prenom
    FROM Clients
    WHERE Actif = 1;
```

```sql
-- Méthode 2 : CREATE OR ALTER (SQL Server 2016+)
CREATE OR ALTER VIEW VueClientsActifs
AS
    SELECT ClientID, Nom, Prenom, Email
    FROM Clients
    WHERE Actif = 1;
```

La syntaxe `CREATE OR ALTER` est très pratique : elle crée la vue si elle n'existe pas, ou la modifie si elle existe déjà.

Pour voir comment une vue a été créée :

```sql
-- Méthode 3 : SSMS
-- Clic droit sur la vue > Script View as > CREATE To > New Query Editor Window
```

## Supprimer une vue

Pour supprimer une vue de la base de données :

```sql
DROP VIEW VueClientsActifs;

-- Ou avec vérification
DROP VIEW IF EXISTS VueClientsActifs;
```

**Important :** Supprimer une vue ne supprime pas les tables sous-jacentes ni les données. Seule la définition de la vue est supprimée.

---

## Les vues peuvent interroger d'autres vues

Les vues peuvent être construites à partir d'autres vues, créant ainsi des **niveaux d'abstraction** :

```sql
-- Vue de base
CREATE VIEW VueCommandesValidees
AS
    SELECT CommandeID, ClientID, DateCommande, MontantTotal
    FROM Commandes
    WHERE Statut = 'Validée';

-- Vue basée sur la première vue
CREATE VIEW VueGrossesCommandes
AS
    SELECT *
    FROM VueCommandesValidees
    WHERE MontantTotal > 1000;
```

**Attention :** Trop de niveaux d'imbrication peuvent compliquer le débogage et affecter les performances.

---

## Alias de colonnes dans les vues

Vous pouvez définir des noms de colonnes personnalisés de deux façons :

**Méthode 1 : Dans le SELECT**

```sql
CREATE VIEW VueResume
AS
    SELECT
        ClientID AS ID,
        Nom + ' ' + Prenom AS NomComplet,
        Email AS Courriel
    FROM Clients;
```

**Méthode 2 : Dans la définition de la vue**

```sql
CREATE VIEW VueResume (ID, NomComplet, Courriel)
AS
    SELECT
        ClientID,
        Nom + ' ' + Prenom,
        Email
    FROM Clients;
```

Les deux méthodes sont équivalentes. La première est plus explicite et généralement préférée.

---

## Bonnes pratiques

### ✅ À FAIRE

1. **Utiliser des noms explicites** : `VueClientsActifs` plutôt que `Vue1`
2. **Documenter les vues complexes** avec des commentaires
3. **Spécifier explicitement les colonnes** plutôt que `SELECT *`
4. **Utiliser le préfixe de schéma** : `dbo.VueClients`
5. **Tester la requête** avant de créer la vue

### ❌ À ÉVITER

1. **Ne pas utiliser SELECT *** dans une vue (sauf cas très simple)
2. **Éviter trop de niveaux d'imbrication** de vues
3. **Ne pas créer de vues trop complexes** qui seraient difficiles à maintenir
4. **Éviter les vues qui font des calculs lourds** sans raison (préférer les vues indexées ou tables calculées)

## Exemple complet : Cas d'usage réel

Imaginons une base de données de gestion de bibliothèque avec les tables suivantes :

- `Livres` (LivreID, Titre, Auteur, DatePublication)
- `Emprunts` (EmpruntID, LivreID, MembreID, DateEmprunt, DateRetour)
- `Membres` (MembreID, Nom, Prenom, Email)

**Créer une vue pour suivre les emprunts en cours :**

```sql
CREATE VIEW VueEmpruntsEnCours
AS
    SELECT
        e.EmpruntID,
        l.Titre AS TitreLivre,
        l.Auteur,
        m.Nom + ' ' + m.Prenom AS Emprunteur,
        m.Email,
        e.DateEmprunt,
        DATEDIFF(DAY, e.DateEmprunt, GETDATE()) AS JoursEcoules,
        CASE
            WHEN DATEDIFF(DAY, e.DateEmprunt, GETDATE()) > 30
            THEN 'En retard'
            ELSE 'En cours'
        END AS Statut
    FROM Emprunts e
    INNER JOIN Livres l ON e.LivreID = l.LivreID
    INNER JOIN Membres m ON e.MembreID = m.MembreID
    WHERE e.DateRetour IS NULL;
```

**Utilisation simple :**

```sql
-- Voir tous les emprunts en cours
SELECT * FROM VueEmpruntsEnCours;

-- Trouver les emprunts en retard
SELECT * FROM VueEmpruntsEnCours
WHERE Statut = 'En retard';

-- Compter les emprunts par membre
SELECT
    Emprunteur,
    COUNT(*) AS NombreLivresEmpruntes
FROM VueEmpruntsEnCours
GROUP BY Emprunteur;
```

## Résumé

Les vues sont un outil puissant pour :
- **Simplifier** les requêtes complexes
- **Réutiliser** la logique métier
- **Abstraire** la structure de la base de données
- **Sécuriser** l'accès aux données sensibles

Une vue ne stocke pas de données, elle stocke uniquement une **définition de requête**. Chaque fois que vous interrogez une vue, SQL Server exécute la requête sous-jacente.

La syntaxe de base est simple :

```sql
CREATE VIEW nom_vue
AS
    SELECT colonnes
    FROM tables
    WHERE conditions;
```
