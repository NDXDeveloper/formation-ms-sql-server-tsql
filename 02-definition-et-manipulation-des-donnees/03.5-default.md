# 2.3.5 DEFAULT (Valeur par défaut)

## Introduction

Imaginez que vous créez un compte sur un site web. Certains champs sont pré-remplis : votre pays est automatiquement détecté comme "France", votre langue est "Français", et la date d'inscription est la date du jour. Vous n'avez pas besoin de remplir ces champs manuellement - ils ont des **valeurs par défaut**.

C'est exactement le rôle de la contrainte **DEFAULT** dans SQL Server : elle définit une **valeur automatique** qui sera insérée dans une colonne si aucune valeur n'est fournie explicitement.

**Analogie :** Une contrainte DEFAULT est comme un formulaire papier où certaines cases sont déjà pré-remplies. Si vous les laissez telles quelles, la valeur par défaut sera utilisée ; mais vous pouvez toujours la modifier si nécessaire.

## Qu'est-ce qu'une Contrainte DEFAULT ?

### Définition Simple

Une contrainte DEFAULT spécifie une valeur qui sera **automatiquement insérée** dans une colonne lorsque vous n'en fournissez pas lors d'un INSERT.

**Exemple simple :**

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100),
    Pays VARCHAR(50) DEFAULT 'France',
    DateInscription DATE DEFAULT GETDATE(),
    EstActif BIT DEFAULT 1
);
```

**Sans valeur fournie, SQL Server utilise les valeurs par défaut :**

```sql
-- Insertion sans spécifier Pays, DateInscription, EstActif
INSERT INTO Clients (IdClient, Nom)
VALUES (1, 'Dupont');

-- Résultat : Les valeurs par défaut sont automatiquement insérées
SELECT * FROM Clients;
```

**Résultat :**

| IdClient | Nom | Pays | DateInscription | EstActif |
|----------|-----|------|-----------------|----------|
| 1 | Dupont | France | 2025-11-16 | 1 |

Les colonnes `Pays`, `DateInscription` et `EstActif` ont été remplies automatiquement avec leurs valeurs par défaut.

### Avec Valeur Fournie

Si vous fournissez une valeur, la valeur par défaut est **ignorée** :

```sql
-- Insertion avec valeur personnalisée pour Pays
INSERT INTO Clients (IdClient, Nom, Pays, EstActif)
VALUES (2, 'Martin', 'Belgique', 0);

SELECT * FROM Clients;
```

**Résultat :**

| IdClient | Nom | Pays | DateInscription | EstActif |
|----------|-----|------|-----------------|----------|
| 1 | Dupont | France | 2025-11-16 | 1 |
| 2 | Martin | Belgique | 2025-11-16 | 0 |

Martin a `Belgique` comme pays (valeur fournie) et `0` pour EstActif (valeur fournie), mais `DateInscription` utilise toujours la valeur par défaut.

## Pourquoi Utiliser des Contraintes DEFAULT ?

### 1. Simplifier les Insertions

Sans DEFAULT, vous devez spécifier toutes les colonnes :

```sql
-- ❌ SANS DEFAULT : Fastidieux
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Stock INT,
    EstDisponible BIT,
    DateAjout DATE
);

-- Insertion : Vous devez tout spécifier
INSERT INTO Produits (IdProduit, Nom, Stock, EstDisponible, DateAjout)
VALUES (1, 'Ordinateur', 0, 1, GETDATE());
```

```sql
-- ✅ AVEC DEFAULT : Simplifié
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Stock INT DEFAULT 0,
    EstDisponible BIT DEFAULT 1,
    DateAjout DATE DEFAULT GETDATE()
);

-- Insertion : Seul le nécessaire
INSERT INTO Produits (IdProduit, Nom)
VALUES (1, 'Ordinateur');
-- Stock=0, EstDisponible=1, DateAjout=aujourd'hui automatiquement
```

### 2. Garantir la Cohérence

Les valeurs par défaut garantissent que certaines colonnes ont toujours une valeur sensée :

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    NumeroCommande VARCHAR(30),
    DateCommande DATETIME2 DEFAULT GETDATE(),
    Statut VARCHAR(20) DEFAULT 'En attente',
    Priorite VARCHAR(10) DEFAULT 'Normale'
);
```

Chaque commande aura automatiquement :
- La date du jour
- Le statut "En attente"
- La priorité "Normale"

### 3. Éviter les Valeurs NULL Inutiles

DEFAULT permet d'éviter que des colonnes soient NULL quand une valeur par défaut a du sens :

```sql
-- Sans DEFAULT : Risque de NULL
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100),
    EstActif BIT
);

INSERT INTO Employes (IdEmploye, Nom) VALUES (1, 'Dupont');
-- EstActif = NULL (pas pratique pour les calculs)

-- Avec DEFAULT : Toujours une valeur
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100),
    EstActif BIT DEFAULT 1
);

INSERT INTO Employes (IdEmploye, Nom) VALUES (1, 'Dupont');
-- EstActif = 1 (valeur par défaut)
```

### 4. Documenter les Valeurs Standards

Les valeurs par défaut documentent les valeurs "normales" ou "attendues" :

```sql
CREATE TABLE Parametres
(
    IdParametre INT PRIMARY KEY,
    DelaiLivraison INT DEFAULT 3,           -- 3 jours par défaut
    FraisPort DECIMAL(5,2) DEFAULT 5.99,    -- 5.99€ par défaut
    Devise VARCHAR(3) DEFAULT 'EUR'          -- EUR par défaut
);
```

## Comment Créer une Contrainte DEFAULT ?

Il existe plusieurs méthodes pour définir une contrainte DEFAULT.

### Méthode 1 : Lors de la Création de la Table (Inline)

La méthode la plus simple et la plus courante :

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    Stock INT DEFAULT 0,
    EstDisponible BIT DEFAULT 1,
    DateAjout DATE DEFAULT GETDATE()
);
```

### Méthode 2 : Avec Contrainte Nommée

Il est recommandé de **nommer** vos contraintes pour faciliter la gestion :

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    Stock INT,
    EstDisponible BIT,
    DateAjout DATE,
    CONSTRAINT DF_Produits_Stock DEFAULT 0 FOR Stock,
    CONSTRAINT DF_Produits_EstDisponible DEFAULT 1 FOR EstDisponible,
    CONSTRAINT DF_Produits_DateAjout DEFAULT GETDATE() FOR DateAjout
);
```

**Convention de nommage :** `DF_NomTable_NomColonne` ou `DEF_NomTable_NomColonne`

### Méthode 3 : Après la Création de la Table

Vous pouvez ajouter une contrainte DEFAULT à une colonne existante :

```sql
-- D'abord créer la table
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Nom VARCHAR(150),
    Prix DECIMAL(10,2),
    Stock INT,
    EstDisponible BIT
);

-- Ensuite ajouter les contraintes DEFAULT
ALTER TABLE Produits
ADD CONSTRAINT DF_Produits_Stock DEFAULT 0 FOR Stock;

ALTER TABLE Produits
ADD CONSTRAINT DF_Produits_EstDisponible DEFAULT 1 FOR EstDisponible;
```

**Important :** Les lignes déjà existantes ne sont **pas affectées** par l'ajout d'une contrainte DEFAULT. Seules les futures insertions utiliseront la valeur par défaut.

### Méthode 4 : Syntaxe Alternative avec ALTER COLUMN

```sql
-- Ajouter DEFAULT sans nom de contrainte
ALTER TABLE Produits
ADD DEFAULT 0 FOR Stock;
```

**⚠️ Note :** Cette syntaxe ne nomme pas la contrainte, ce qui complique la suppression ultérieure.

## Types de Valeurs par Défaut

### 1. Valeurs Constantes

Les valeurs constantes sont les plus simples : nombres, textes, dates fixes.

#### Nombres

```sql
CREATE TABLE Produits
(
    IdProduit INT PRIMARY KEY,
    Stock INT DEFAULT 0,
    StockMinimum INT DEFAULT 5,
    PourcentageRemise DECIMAL(5,2) DEFAULT 0.00
);
```

#### Texte

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Pays VARCHAR(50) DEFAULT 'France',
    Langue VARCHAR(10) DEFAULT 'FR',
    Devise VARCHAR(3) DEFAULT 'EUR'
);
```

#### Booléens (BIT)

```sql
CREATE TABLE Utilisateurs
(
    IdUtilisateur INT PRIMARY KEY,
    EstActif BIT DEFAULT 1,            -- Actif par défaut
    EstAbonne BIT DEFAULT 0,           -- Non abonné par défaut
    EstVerifie BIT DEFAULT 0           -- Non vérifié par défaut
);
```

#### Dates Fixes

```sql
CREATE TABLE Parametres
(
    IdParametre INT PRIMARY KEY,
    DateDebut DATE DEFAULT '2025-01-01',
    DateFin DATE DEFAULT '2025-12-31'
);
```

### 2. Fonctions Système

SQL Server propose plusieurs fonctions pour générer des valeurs par défaut dynamiques.

#### GETDATE() - Date et Heure Actuelles

```sql
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    DateCommande DATETIME2 DEFAULT GETDATE(),
    DateModification DATETIME2 DEFAULT GETDATE()
);
```

**Exemple :**

```sql
INSERT INTO Commandes (IdCommande) VALUES (1);
SELECT * FROM Commandes;
```

**Résultat :**

| IdCommande | DateCommande | DateModification |
|------------|--------------|------------------|
| 1 | 2025-11-16 14:30:25 | 2025-11-16 14:30:25 |

#### SYSDATETIME() - Date et Heure avec Plus de Précision

```sql
CREATE TABLE Logs
(
    IdLog INT PRIMARY KEY,
    DateHeureLog DATETIME2 DEFAULT SYSDATETIME()
);
```

**Différence avec GETDATE() :**
- `GETDATE()` : précision à la milliseconde
- `SYSDATETIME()` : précision à 100 nanosecondes (plus précis)

#### NEWID() - Identifiant Unique (GUID)

```sql
CREATE TABLE Documents
(
    IdDocument UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    Nom VARCHAR(200),
    DateCreation DATETIME2 DEFAULT GETDATE()
);
```

**Exemple :**

```sql
INSERT INTO Documents (Nom) VALUES ('Rapport 2025');
SELECT * FROM Documents;
```

**Résultat :**

| IdDocument | Nom | DateCreation |
|------------|-----|--------------|
| 6F9619FF-8B86-D011-B42D-00C04FC964FF | Rapport 2025 | 2025-11-16 14:30:25 |

#### GETUTCDATE() - Date et Heure UTC

```sql
CREATE TABLE Evenements
(
    IdEvenement INT PRIMARY KEY,
    DateEvenementLocal DATETIME2 DEFAULT GETDATE(),
    DateEvenementUTC DATETIME2 DEFAULT GETUTCDATE()
);
```

#### SUSER_NAME() - Nom de l'Utilisateur Connecté

```sql
CREATE TABLE Audits
(
    IdAudit INT PRIMARY KEY,
    UtilisateurCreation VARCHAR(100) DEFAULT SUSER_NAME(),
    DateCreation DATETIME2 DEFAULT GETDATE()
);
```

#### USER_NAME() - Nom de l'Utilisateur de Base de Données

```sql
CREATE TABLE Modifications
(
    IdModification INT PRIMARY KEY,
    UtilisateurDB VARCHAR(100) DEFAULT USER_NAME(),
    DateModification DATETIME2 DEFAULT GETDATE()
);
```

### 3. Expressions et Calculs

Vous pouvez utiliser des expressions simples (mais pas trop complexes) :

```sql
CREATE TABLE Parametres
(
    IdParametre INT PRIMARY KEY,
    AnneeEnCours INT DEFAULT YEAR(GETDATE()),
    MoisEnCours INT DEFAULT MONTH(GETDATE()),
    JourEnCours INT DEFAULT DAY(GETDATE())
);
```

**⚠️ Limitations :** Les expressions complexes ou les sous-requêtes ne sont généralement pas autorisées dans DEFAULT.

### 4. NULL comme Valeur par Défaut (Défaut Implicite)

Si aucun DEFAULT n'est spécifié et que la colonne autorise NULL, la valeur par défaut est NULL :

```sql
CREATE TABLE Exemple
(
    Id INT PRIMARY KEY,
    Colonne1 VARCHAR(50),           -- DEFAULT NULL (implicite)
    Colonne2 VARCHAR(50) NOT NULL,  -- Pas de DEFAULT, doit être fournie
    Colonne3 VARCHAR(50) DEFAULT 'Valeur'  -- DEFAULT explicite
);

INSERT INTO Exemple (Id, Colonne2) VALUES (1, 'Test');
-- Colonne1 = NULL (défaut implicite)
-- Colonne2 = 'Test' (fournie)
-- Colonne3 = 'Valeur' (défaut explicite)
```

## DEFAULT vs NULL

Il est important de comprendre la différence entre DEFAULT et NULL.

### Colonne avec DEFAULT

```sql
CREATE TABLE Test1
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50) DEFAULT 'Valeur par défaut'
);

-- Insertion sans spécifier la colonne
INSERT INTO Test1 (Id) VALUES (1);
-- Résultat : Colonne = 'Valeur par défaut'

-- Insertion avec NULL explicite
INSERT INTO Test1 (Id, Colonne) VALUES (2, NULL);
-- Résultat : Colonne = NULL (le DEFAULT est ignoré)
```

**Important :** Si vous insérez explicitement NULL, le DEFAULT n'est **pas** utilisé.

### Colonne sans DEFAULT

```sql
CREATE TABLE Test2
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50)  -- Pas de DEFAULT
);

-- Insertion sans spécifier la colonne
INSERT INTO Test2 (Id) VALUES (1);
-- Résultat : Colonne = NULL
```

### Combinaison DEFAULT + NOT NULL

```sql
CREATE TABLE Test3
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50) DEFAULT 'Valeur par défaut' NOT NULL
);

-- ✅ OK : Utilise le DEFAULT
INSERT INTO Test3 (Id) VALUES (1);
-- Résultat : Colonne = 'Valeur par défaut'

-- ❌ ERREUR : NULL n'est pas autorisé
INSERT INTO Test3 (Id, Colonne) VALUES (2, NULL);
-- Erreur : Cannot insert NULL
```

**Recommandation :** Combinez DEFAULT avec NOT NULL pour les colonnes qui doivent toujours avoir une valeur.

## Modifier une Contrainte DEFAULT

### Supprimer une Contrainte DEFAULT

Pour supprimer une contrainte DEFAULT :

```sql
-- Si vous connaissez le nom de la contrainte
ALTER TABLE Produits
DROP CONSTRAINT DF_Produits_Stock;

-- Supprimer DEFAULT sans nom (syntaxe alternative)
ALTER TABLE Produits
DROP CONSTRAINT ALL;  -- Attention : supprime toutes les contraintes !
```

### Trouver le Nom d'une Contrainte DEFAULT

```sql
-- Méthode 1 : Via INFORMATION_SCHEMA
SELECT
    tc.CONSTRAINT_NAME,
    tc.TABLE_NAME,
    cu.COLUMN_NAME
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS tc
INNER JOIN INFORMATION_SCHEMA.CONSTRAINT_COLUMN_USAGE cu
    ON tc.CONSTRAINT_NAME = cu.CONSTRAINT_NAME
WHERE tc.CONSTRAINT_TYPE = 'DEFAULT'
    AND tc.TABLE_NAME = 'Produits';

-- Méthode 2 : Via sys.default_constraints
SELECT
    dc.name AS NomContrainte,
    t.name AS NomTable,
    c.name AS NomColonne,
    dc.definition AS Definition
FROM sys.default_constraints dc
INNER JOIN sys.tables t ON dc.parent_object_id = t.object_id
INNER JOIN sys.columns c ON dc.parent_object_id = c.object_id AND dc.parent_column_id = c.column_id
WHERE t.name = 'Produits';
```

### Modifier une Valeur par Défaut

On ne peut pas modifier directement une contrainte DEFAULT. Il faut la supprimer puis la recréer :

```sql
-- 1. Supprimer l'ancienne contrainte
ALTER TABLE Produits
DROP CONSTRAINT DF_Produits_Stock;

-- 2. Créer la nouvelle contrainte avec la valeur modifiée
ALTER TABLE Produits
ADD CONSTRAINT DF_Produits_Stock DEFAULT 10 FOR Stock;
```

**Script Complet pour Modifier :**

```sql
-- Trouver et supprimer la contrainte existante
DECLARE @ConstraintName NVARCHAR(200);

SELECT @ConstraintName = dc.name
FROM sys.default_constraints dc
INNER JOIN sys.columns c ON dc.parent_object_id = c.object_id AND dc.parent_column_id = c.column_id
WHERE OBJECT_NAME(dc.parent_object_id) = 'Produits'
    AND c.name = 'Stock';

IF @ConstraintName IS NOT NULL
BEGIN
    EXEC('ALTER TABLE Produits DROP CONSTRAINT ' + @ConstraintName);
END

-- Ajouter la nouvelle contrainte
ALTER TABLE Produits
ADD CONSTRAINT DF_Produits_Stock DEFAULT 10 FOR Stock;
```

## Appliquer DEFAULT aux Lignes Existantes

**Important :** Ajouter une contrainte DEFAULT n'affecte **pas** les lignes existantes. Elle s'applique uniquement aux **futures insertions**.

### Exemple du Problème

```sql
-- Table avec données existantes
CREATE TABLE Test (Id INT, Colonne INT);
INSERT INTO Test (Id) VALUES (1), (2), (3);
-- Colonne = NULL pour toutes les lignes

-- Ajouter une contrainte DEFAULT
ALTER TABLE Test
ADD CONSTRAINT DF_Test_Colonne DEFAULT 0 FOR Colonne;

-- Les lignes existantes ont toujours NULL !
SELECT * FROM Test;
```

**Résultat :**

| Id | Colonne |
|----|---------|
| 1 | NULL |
| 2 | NULL |
| 3 | NULL |

### Solution : Mettre à Jour Manuellement

Si vous voulez appliquer la valeur par défaut aux lignes existantes, utilisez UPDATE :

```sql
-- Mettre à jour les valeurs NULL avec la valeur par défaut
UPDATE Test
SET Colonne = 0
WHERE Colonne IS NULL;

-- Maintenant toutes les lignes ont la valeur
SELECT * FROM Test;
```

**Résultat :**

| Id | Colonne |
|----|---------|
| 1 | 0 |
| 2 | 0 |
| 3 | 0 |

## Erreurs Courantes et Solutions

### Erreur 1 : Conflit avec NOT NULL sans DEFAULT

```sql
-- ❌ ERREUR : Colonne NOT NULL sans DEFAULT
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne INT NOT NULL  -- Pas de DEFAULT
);

-- Insertion sans spécifier Colonne
INSERT INTO Test (Id) VALUES (1);
-- Erreur : Cannot insert NULL into column 'Colonne'
```

**Solution :** Ajoutez une valeur par défaut :

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne INT NOT NULL DEFAULT 0  -- Avec DEFAULT
);

INSERT INTO Test (Id) VALUES (1);  -- ✅ OK
```

### Erreur 2 : Expression DEFAULT Invalide

```sql
-- ❌ ERREUR : Sous-requête non autorisée
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Valeur INT DEFAULT (SELECT MAX(Id) FROM AutreTable)  -- ERREUR
);
```

**Solution :** Utilisez des valeurs constantes ou des fonctions système :

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Valeur INT DEFAULT 0  -- Constante simple
);
```

### Erreur 3 : Oublier que DEFAULT ne s'Applique pas aux UPDATE

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne INT DEFAULT 0
);

INSERT INTO Test (Id) VALUES (1);  -- Colonne = 0 (DEFAULT)

-- Mise à jour : DEFAULT n'est PAS appliqué
UPDATE Test SET Colonne = NULL WHERE Id = 1;
-- Colonne = NULL (pas 0 !)
```

**Important :** DEFAULT fonctionne uniquement pour INSERT, pas pour UPDATE.

### Erreur 4 : NULL Explicite Ignore DEFAULT

```sql
CREATE TABLE Test
(
    Id INT PRIMARY KEY,
    Colonne VARCHAR(50) DEFAULT 'Valeur'
);

-- ⚠️ Insertion avec NULL explicite
INSERT INTO Test (Id, Colonne) VALUES (1, NULL);
-- Résultat : Colonne = NULL (pas 'Valeur')
```

**Explication :** Si vous spécifiez explicitement NULL, le DEFAULT est ignoré.

## Bonnes Pratiques

### 1. Nommer Vos Contraintes DEFAULT

```sql
-- ✅ BON : Contrainte nommée
CONSTRAINT DF_Produits_Stock DEFAULT 0 FOR Stock

-- ❌ À éviter : Contrainte anonyme
Stock INT DEFAULT 0
```

**Avantage :** Facilite la suppression et la modification.

### 2. Convention de Nommage Cohérente

- `DF_NomTable_NomColonne`
- `DEF_NomTable_NomColonne`
- `DFT_NomTable_NomColonne`

**Exemples :**
- `DF_Clients_Pays`
- `DF_Produits_Stock`
- `DF_Commandes_DateCommande`

### 3. Combiner DEFAULT avec NOT NULL pour Valeurs Obligatoires

```sql
-- ✅ Colonne obligatoire avec valeur par défaut raisonnable
DateCreation DATETIME2 NOT NULL DEFAULT GETDATE()
EstActif BIT NOT NULL DEFAULT 1

-- ⚠️ Colonne optionnelle avec valeur par défaut
Email VARCHAR(150) DEFAULT 'inconnu@email.com'  -- Peu recommandé
```

### 4. Utiliser DEFAULT pour les Horodatages

```sql
-- ✅ BON : Horodatage automatique
CREATE TABLE Audits
(
    IdAudit INT PRIMARY KEY,
    DateCreation DATETIME2 DEFAULT GETDATE(),
    DateModification DATETIME2 DEFAULT GETDATE()
);
```

### 5. DEFAULT pour Valeurs Métier Standards

```sql
-- ✅ BON : Valeurs standards documentées
CREATE TABLE Parametres
(
    IdParametre INT PRIMARY KEY,
    DelaiLivraison INT DEFAULT 3,           -- 3 jours
    FraisPort DECIMAL(5,2) DEFAULT 5.99,    -- 5.99€
    TauxTVA DECIMAL(4,2) DEFAULT 20.00      -- 20%
);
```

### 6. Éviter DEFAULT avec Logique Complexe

```sql
-- ❌ À éviter : Trop complexe
CONSTRAINT DF_Test DEFAULT
    CASE
        WHEN ... THEN ...
        ELSE ...
    END FOR Colonne

-- ✅ Mieux : Simple et clair
CONSTRAINT DF_Test DEFAULT 0 FOR Colonne
```

**Recommandation :** Pour la logique complexe, utilisez des triggers ou calculez dans l'application.

### 7. Documenter les Valeurs par Défaut Non Évidentes

```sql
-- Documentation claire
CREATE TABLE Configurations
(
    IdConfig INT PRIMARY KEY,
    TimeoutSeconde INT DEFAULT 30,          -- 30 secondes par défaut
    NombreTentatives INT DEFAULT 3,         -- 3 essais maximum
    IntervalleRetry INT DEFAULT 60          -- 60 secondes entre tentatives
);
```

### 8. Attention aux Valeurs par Défaut Qui Changent

```sql
-- ⚠️ Attention : La date change à chaque insertion
DateCreation DATETIME2 DEFAULT GETDATE()  -- OK

-- ⚠️ Attention : L'utilisateur peut changer
UtilisateurCreation VARCHAR(100) DEFAULT SUSER_NAME()  -- OK si désiré
```

## Différence entre DEFAULT et Calculated Column

DEFAULT et les colonnes calculées sont différentes :

### DEFAULT : Valeur à l'Insertion

```sql
CREATE TABLE Test1
(
    Id INT PRIMARY KEY,
    Prix DECIMAL(10,2),
    TauxTVA DECIMAL(4,2) DEFAULT 20.00,  -- Valeur par défaut
    PrixTTC AS Prix * (1 + TauxTVA / 100)  -- Colonne calculée
);

INSERT INTO Test1 (Id, Prix) VALUES (1, 100.00);
-- TauxTVA = 20.00 (DEFAULT)
-- PrixTTC = 120.00 (calculé automatiquement)

-- Modification du taux : PrixTTC recalculé automatiquement
UPDATE Test1 SET TauxTVA = 10.00 WHERE Id = 1;
-- PrixTTC = 110.00 (recalculé)
```

**Différence clé :**
- **DEFAULT** : fixe la valeur une seule fois à l'insertion
- **Calculated Column** : recalcule toujours la valeur

## Résumé

| Aspect | Description |
|--------|-------------|
| **Définition** | Valeur insérée automatiquement si non fournie |
| **Syntaxe simple** | `Colonne INT DEFAULT 0` |
| **Syntaxe nommée** | `CONSTRAINT DF_Table_Colonne DEFAULT 0 FOR Colonne` |
| **Types de valeurs** | Constantes, fonctions système, expressions simples |
| **Fonctions courantes** | GETDATE(), NEWID(), SUSER_NAME() |
| **Application** | Uniquement à l'INSERT, pas à l'UPDATE |
| **NULL explicite** | Ignore le DEFAULT |
| **Lignes existantes** | Non affectées par l'ajout de DEFAULT |
| **Combinaison** | Souvent avec NOT NULL pour valeurs obligatoires |

## Points Clés à Retenir

1. ✅ DEFAULT fournit une **valeur automatique** si aucune valeur n'est fournie à l'INSERT
2. ✅ Simplifie les insertions et garantit la cohérence
3. 🎯 Fonctions utiles : **GETDATE()**, **NEWID()**, **SUSER_NAME()**
4. ⚠️ DEFAULT s'applique uniquement aux **INSERT**, pas aux UPDATE
5. ⚠️ Un NULL **explicite** ignore le DEFAULT
6. ⚠️ L'ajout de DEFAULT n'affecte **pas** les lignes existantes
7. ✅ Combinez avec **NOT NULL** pour valeurs obligatoires
8. 📝 Nommez vos contraintes : `DF_Table_Colonne`
