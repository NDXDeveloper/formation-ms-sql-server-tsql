# 1.3.1 Qu'est-ce que T-SQL (Transact-SQL) ?

## Introduction

Vous avez découvert SQL Server, ses éditions, son architecture et ses outils. Mais pour réellement **communiquer** avec SQL Server et lui demander de faire quelque chose avec vos données, vous avez besoin d'un **langage**. Ce langage, c'est le **T-SQL** ou **Transact-SQL**.

### Analogie : Parler à SQL Server

Imaginez que SQL Server est une personne qui gère une immense bibliothèque (vos données) :
- Cette personne ne parle qu'**une seule langue** : le T-SQL
- Si vous voulez lui demander de vous trouver un livre, vous devez parler T-SQL
- Si vous voulez lui demander d'ajouter un nouveau livre, vous devez parler T-SQL
- Si vous voulez organiser les livres différemment, vous devez parler T-SQL

**T-SQL est le langage de communication entre vous et SQL Server.**

## Qu'est-ce que SQL ?

Avant de parler de T-SQL, commençons par comprendre **SQL**.

### Définition de SQL

**SQL** signifie **Structured Query Language** (Langage de Requête Structuré en français).

**C'est quoi ?**
- Un **langage standardisé** pour interagir avec les bases de données relationnelles
- Créé dans les **années 1970** par IBM
- Devenu un **standard international** (ISO/ANSI)
- Utilisé par la **plupart des SGBDR** (Oracle, MySQL, PostgreSQL, SQL Server, etc.)

### Caractéristiques de SQL

#### 1. Langage déclaratif

SQL est un langage **déclaratif**, pas **impératif**.

**Qu'est-ce que ça veut dire ?**

**Langage impératif** (comme Python, C#, Java) :
Vous dites **COMMENT** faire quelque chose, étape par étape.

```python
# Python (impératif)
resultats = []
for client in liste_clients:
    if client.ville == "Paris":
        resultats.append(client)
```

**Langage déclaratif** (comme SQL) :
Vous dites **CE QUE** vous voulez, pas comment l'obtenir.

```sql
-- SQL (déclaratif)
SELECT *
FROM Clients
WHERE Ville = 'Paris';
```

Vous dites simplement : "Je veux tous les clients de Paris", et SQL Server se débrouille pour trouver le meilleur moyen de vous les donner !

#### 2. Langage ensembliste

SQL travaille sur des **ensembles de données** (des groupes de lignes), pas ligne par ligne.

**Exemple :**
```sql
-- Une seule instruction peut affecter des milliers de lignes
UPDATE Produits
SET Prix = Prix * 1.10
WHERE Categorie = 'Electronique';
```

Cette requête augmente le prix de **tous les produits électroniques** de 10% en une seule instruction !

#### 3. Langage non-procédural (SQL standard)

SQL standard n'a pas de structures comme :
- Pas de variables
- Pas de boucles (WHILE, FOR)
- Pas de conditions (IF/ELSE)
- Pas de procédures

**Mais attendez...** c'est là qu'intervient **T-SQL** !

## T-SQL : L'extension Microsoft de SQL

### Définition de T-SQL

**T-SQL** signifie **Transact-SQL**.

C'est l'**extension propriétaire** créée par Microsoft pour SQL Server. T-SQL prend le SQL standard et y ajoute des fonctionnalités puissantes.

**Formule simple :**
```
T-SQL = SQL Standard + Extensions Microsoft
```

### Pourquoi Microsoft a créé T-SQL ?

SQL standard, bien que puissant, a des **limitations** :
- ❌ Pas de variables
- ❌ Pas de logique conditionnelle (IF/ELSE)
- ❌ Pas de boucles
- ❌ Pas de gestion d'erreurs structurée
- ❌ Pas de programmation

Microsoft a donc **étendu** SQL pour ajouter ces capacités et créer un véritable **langage de programmation** tout en gardant la compatibilité avec le standard SQL.

### T-SQL vs SQL standard

| Caractéristique | SQL Standard | T-SQL |
|----------------|--------------|-------|
| **SELECT, INSERT, UPDATE, DELETE** | ✅ Oui | ✅ Oui |
| **Jointures, GROUP BY** | ✅ Oui | ✅ Oui |
| **Variables** | ❌ Non | ✅ Oui (`DECLARE @var`) |
| **IF/ELSE** | ❌ Non | ✅ Oui |
| **Boucles WHILE** | ❌ Non | ✅ Oui |
| **TRY/CATCH** | ❌ Non | ✅ Oui |
| **Procédures stockées** | Basiques | ✅ Avancées |
| **Fonctions utilisateur** | Limitées | ✅ Riches |
| **Gestion transactions** | Basique | ✅ Avancée |
| **Fonctions de fenêtrage** | ✅ Oui (récent) | ✅ Oui + extensions |

## Les extensions T-SQL : Exemples concrets

Voyons quelques fonctionnalités que T-SQL ajoute au SQL standard :

### 1. Variables

**SQL standard :** Pas de variables

**T-SQL :** Vous pouvez déclarer et utiliser des variables !

```sql
-- Déclarer une variable
DECLARE @Prix DECIMAL(10,2);

-- Lui assigner une valeur
SET @Prix = 99.99;

-- L'utiliser dans une requête
SELECT *
FROM Produits
WHERE PrixUnitaire < @Prix;
```

**Utilité :** Stocker temporairement des valeurs, rendre le code plus lisible.

### 2. Structures conditionnelles (IF/ELSE)

**SQL standard :** Pas de conditions

**T-SQL :** Logique conditionnelle complète !

```sql
DECLARE @Stock INT = 5;

IF @Stock < 10
BEGIN
    PRINT 'Alerte : Stock faible !';
    -- Déclencher une commande de réapprovisionnement
END
ELSE
BEGIN
    PRINT 'Stock suffisant.';
END
```

**Utilité :** Prendre des décisions dans votre code SQL.

### 3. Boucles (WHILE)

**SQL standard :** Pas de boucles

**T-SQL :** Boucle WHILE disponible !

```sql
DECLARE @Compteur INT = 1;

WHILE @Compteur <= 5
BEGIN
    PRINT 'Itération numéro ' + CAST(@Compteur AS VARCHAR);
    SET @Compteur = @Compteur + 1;
END
```

**Résultat :**
```
Itération numéro 1
Itération numéro 2
Itération numéro 3
Itération numéro 4
Itération numéro 5
```

**Note :** Les boucles sont rarement nécessaires en SQL (approche ensembliste préférée), mais utiles dans certains cas.

### 4. Gestion d'erreurs (TRY...CATCH)

**SQL standard :** Gestion d'erreurs basique

**T-SQL :** Gestion structurée des erreurs !

```sql
BEGIN TRY
    -- Code qui pourrait échouer
    INSERT INTO Clients (Email) VALUES ('jean.dupont@email.com');
    PRINT 'Client ajouté avec succès !';
END TRY
BEGIN CATCH
    -- Code exécuté en cas d'erreur
    PRINT 'Erreur lors de l''ajout : ' + ERROR_MESSAGE();
END CATCH
```

**Utilité :** Gérer proprement les erreurs sans planter le script.

### 5. Fonctions spécifiques T-SQL

T-SQL ajoute des centaines de fonctions pratiques :

**Fonctions de date :**
```sql
SELECT GETDATE();                    -- Date et heure actuelles
SELECT DATEADD(DAY, 7, GETDATE());  -- Date dans 7 jours
SELECT DATEDIFF(DAY, '2024-01-01', GETDATE()); -- Jours écoulés
```

**Fonctions de chaînes :**
```sql
SELECT LEN('Bonjour');              -- Longueur : 7
SELECT UPPER('bonjour');            -- BONJOUR
SELECT CONCAT('Hello', ' ', 'World'); -- Hello World
```

**Fonctions de conversion :**
```sql
SELECT CAST(123 AS VARCHAR(10));    -- '123'
SELECT CONVERT(VARCHAR(10), GETDATE(), 103); -- Format DD/MM/YYYY
```

**Fonctions NULL :**
```sql
SELECT ISNULL(Email, 'Pas d''email'); -- Remplace NULL
SELECT COALESCE(Email, Telephone, 'Aucun contact'); -- Première valeur non-NULL
```

### 6. Instructions avancées

**MERGE :** Fusion de données (INSERT + UPDATE + DELETE en une seule instruction)

```sql
MERGE INTO Stock AS Cible
USING NouvellesLivraisons AS Source
ON Cible.ProduitID = Source.ProduitID
WHEN MATCHED THEN
    UPDATE SET Cible.Quantite = Cible.Quantite + Source.Quantite
WHEN NOT MATCHED THEN
    INSERT (ProduitID, Quantite) VALUES (Source.ProduitID, Source.Quantite);
```

**OUTPUT :** Capturer les lignes affectées par une opération

```sql
DELETE FROM Clients
OUTPUT DELETED.ClientID, DELETED.Nom
WHERE DateDerniereCommande < '2020-01-01';
```

## À quoi sert T-SQL au quotidien ?

### 1. Manipulation de données (DML)

**Créer des données :**
```sql
INSERT INTO Clients (Nom, Prenom, Email)
VALUES ('Dupont', 'Jean', 'jean.dupont@email.com');
```

**Lire des données :**
```sql
SELECT Nom, Prenom, Email
FROM Clients
WHERE Ville = 'Paris';
```

**Modifier des données :**
```sql
UPDATE Clients
SET Telephone = '0612345678'
WHERE ClientID = 123;
```

**Supprimer des données :**
```sql
DELETE FROM Clients
WHERE DateInscription < '2020-01-01';
```

### 2. Définition de structure (DDL)

**Créer une table :**
```sql
CREATE TABLE Produits (
    ProduitID INT PRIMARY KEY IDENTITY(1,1),
    Nom NVARCHAR(100) NOT NULL,
    Prix DECIMAL(10,2),
    Stock INT DEFAULT 0
);
```

**Modifier une table :**
```sql
ALTER TABLE Produits
ADD Description NVARCHAR(500);
```

**Supprimer une table :**
```sql
DROP TABLE ProduitsObsoletes;
```

### 3. Programmation (Procédures, Fonctions, Triggers)

**Procédure stockée :**
```sql
CREATE PROCEDURE AjouterClient
    @Nom NVARCHAR(50),
    @Email NVARCHAR(100)
AS
BEGIN
    INSERT INTO Clients (Nom, Email, DateInscription)
    VALUES (@Nom, @Email, GETDATE());
END;
```

**Fonction utilisateur :**
```sql
CREATE FUNCTION CalculerTVA (@Montant DECIMAL(10,2))
RETURNS DECIMAL(10,2)
AS
BEGIN
    RETURN @Montant * 0.20;
END;
```

**Trigger :**
```sql
CREATE TRIGGER tr_AuditClients
ON Clients
AFTER INSERT
AS
BEGIN
    INSERT INTO AuditLog (Action, DateHeure)
    VALUES ('Nouveau client créé', GETDATE());
END;
```

### 4. Requêtes complexes

**Jointures multiples :**
```sql
SELECT
    c.Nom AS NomClient,
    p.Nom AS NomProduit,
    cmd.DateCommande,
    cmd.Quantite
FROM
    Commandes cmd
    INNER JOIN Clients c ON cmd.ClientID = c.ClientID
    INNER JOIN Produits p ON cmd.ProduitID = p.ProduitID
WHERE
    cmd.DateCommande >= '2024-01-01';
```

**Agrégations et groupements :**
```sql
SELECT
    Categorie,
    COUNT(*) AS NombreProduits,
    AVG(Prix) AS PrixMoyen,
    SUM(Stock) AS StockTotal
FROM
    Produits
GROUP BY
    Categorie
HAVING
    COUNT(*) > 5;
```

**Sous-requêtes :**
```sql
SELECT Nom, Prix
FROM Produits
WHERE Prix > (SELECT AVG(Prix) FROM Produits);
```

## Les différents "dialectes" de SQL

Chaque SGBDR a sa propre extension de SQL :

| SGBDR | Extension/Dialecte |
|-------|-------------------|
| **SQL Server** | **T-SQL** (Transact-SQL) |
| **Oracle** | PL/SQL (Procedural Language/SQL) |
| **PostgreSQL** | PL/pgSQL |
| **MySQL** | MySQL (avec extensions) |
| **IBM Db2** | SQL PL |

### Compatibilité entre dialectes

**Le SQL de base est similaire partout :**
```sql
-- Cette requête fonctionne sur tous les SGBDR
SELECT Nom, Prenom
FROM Clients
WHERE Ville = 'Paris';
```

**Mais les extensions diffèrent :**

**T-SQL (SQL Server) :**
```sql
DECLARE @Message NVARCHAR(50) = 'Bonjour';
PRINT @Message;
```

**PL/SQL (Oracle) :**
```sql
DECLARE
    v_Message VARCHAR2(50) := 'Bonjour';
BEGIN
    DBMS_OUTPUT.PUT_LINE(v_Message);
END;
```

**Conséquence :** Le code écrit en T-SQL ne fonctionnera pas directement sur Oracle ou MySQL, et vice versa.


```sql
SELECT c.Nom, COUNT(cmd.CommandeID) AS NbCommandes
FROM Clients c
LEFT JOIN Commandes cmd ON c.ClientID = cmd.ClientID
```

**Niveau avancé :**
```sql
WITH VentesRecursives AS (
    SELECT EmployeID, ManagerID, Nom, 1 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL
    UNION ALL
    SELECT e.EmployeID, e.ManagerID, e.Nom, vr.Niveau + 1
    FROM Employes e
    INNER JOIN VentesRecursives vr ON e.ManagerID = vr.EmployeID
)
SELECT * FROM VentesRecursives;
```

## Mythes et réalités sur T-SQL

### ❌ Mythe 1 : "Il faut être un matheux"

**Réalité :** T-SQL est avant tout **logique**. Si vous pouvez formuler une question en français, vous pouvez l'écrire en T-SQL.

**Exemple :**
- Question : "Quels clients habitent à Paris ?"
- T-SQL : `SELECT * FROM Clients WHERE Ville = 'Paris';`

### ❌ Mythe 2 : "C'est trop compliqué"

**Réalité :** T-SQL commence **très simplement**. La complexité vient progressivement.

**Première requête (5 minutes d'apprentissage) :**
```sql
SELECT * FROM Produits;
```

Vous venez d'apprendre à lire toutes les données d'une table !

### ❌ Mythe 3 : "Il faut connaître l'anglais"

**Réalité :** Les mots-clés SQL sont **toujours les mêmes** (50 à mémoriser). Pas besoin d'être bilingue !

**Les mots-clés principaux :**
- SELECT (sélectionner)
- FROM (depuis)
- WHERE (où)
- INSERT (insérer)
- UPDATE (mettre à jour)
- DELETE (supprimer)

### ❌ Mythe 4 : "C'est juste pour les DBA"

**Réalité :** T-SQL est utilisé par :
- 👨‍💻 **Développeurs** (applications web, desktop)
- 📊 **Analystes de données** (Business Intelligence)
- 👨‍🔧 **Administrateurs** (DBA)
- 📈 **Data Scientists** (préparation de données)
- 🎯 **Testeurs** (validation de données)

### ✅ Réalité : "C'est un investissement qui vaut le coup"

Une fois T-SQL maîtrisé, vous avez une compétence **durable** et **valorisée** qui vous servira pendant toute votre carrière !

## Premiers pas avec T-SQL

### Votre première requête T-SQL

Ouvrez SSMS ou VS Code (extension MSSQL), connectez-vous, et tapez :

```sql
SELECT 'Bonjour SQL Server !' AS Message;
```

Appuyez sur **F5** (exécuter).

**Résultat :**
```
Message
------------------------
Bonjour SQL Server !
```

🎉 **Félicitations !** Vous venez d'écrire votre première instruction T-SQL !

### Analyse de cette requête

```sql
SELECT 'Bonjour SQL Server !' AS Message;
```

- **SELECT** : Mot-clé pour "sélectionner" ou "afficher"
- **'Bonjour SQL Server !'** : Une chaîne de caractères (texte)
- **AS Message** : Donne un nom à la colonne du résultat
- **;** : Point-virgule (facultatif mais bonne pratique)

### Deuxième requête : Afficher la date

```sql
SELECT GETDATE() AS DateHeureActuelle;
```

**Résultat :**
```
DateHeureActuelle
------------------------
2024-11-16 14:35:22.123
```

- **GETDATE()** : Fonction T-SQL qui retourne la date et l'heure actuelles

### Troisième requête : Un calcul

```sql
SELECT 10 + 5 AS Somme;
```

**Résultat :**
```
Somme
------
15
```

T-SQL peut faire des calculs !
