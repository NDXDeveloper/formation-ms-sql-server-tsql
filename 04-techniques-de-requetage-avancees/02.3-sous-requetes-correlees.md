# 4.2.3 Sous-requêtes corrélées (Concepts)

## Qu'est-ce qu'une sous-requête corrélée ?

Une **sous-requête corrélée** est une sous-requête qui fait référence à une colonne de la requête externe (principale). Contrairement à une sous-requête classique qui s'exécute une seule fois de manière indépendante, une sous-requête corrélée s'exécute **une fois pour chaque ligne** de la requête externe.

### Différence fondamentale

**Sous-requête classique (non corrélée) :**
```sql
-- La sous-requête s'exécute UNE SEULE FOIS
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > (SELECT AVG(Prix) FROM Produits);
```

**Sous-requête corrélée :**
```sql
-- La sous-requête s'exécute POUR CHAQUE employé
SELECT NomEmploye, Salaire
FROM Employes E
WHERE Salaire > (SELECT AVG(Salaire)
                 FROM Employes
                 WHERE DepartementID = E.DepartementID);
                 --                    ↑
                 --         Référence à la table externe
```

## Anatomie d'une sous-requête corrélée

Voici les éléments clés d'une sous-requête corrélée :

```sql
SELECT colonnes
FROM TableExterne Alias_Externe      -- ① Table externe avec alias
WHERE condition_colonne opérateur (
    SELECT calcul
    FROM TableInterne
    WHERE TableInterne.colonne = Alias_Externe.colonne  -- ② Corrélation
);
```

**Points importants :**
1. La table externe doit avoir un **alias** (ici `Alias_Externe`)
2. La sous-requête **référence** cet alias
3. Cette référence crée la **corrélation** entre les deux requêtes

## Contexte : Tables d'exemple

Pour nos exemples, utilisons les tables suivantes :

## Comment fonctionne une sous-requête corrélée ?

### Mécanisme d'exécution pas à pas

Prenons cet exemple : trouver les employés qui gagnent plus que la moyenne de leur département.

```sql
SELECT NomEmploye, Salaire, DepartementID
FROM Employes E
WHERE Salaire > (SELECT AVG(Salaire)
                 FROM Employes
                 WHERE DepartementID = E.DepartementID);
```

**Étape par étape :**

1. **Ligne 1** (Dupont, Dept 1) :
   - La sous-requête calcule : `AVG(Salaire) WHERE DepartementID = 1`
   - Résultat : (3000 + 3500 + 4000) / 3 = 3500
   - Comparaison : 3000 > 3500 ? **Non** → Ligne exclue

2. **Ligne 2** (Martin, Dept 1) :
   - La sous-requête calcule : `AVG(Salaire) WHERE DepartementID = 1`
   - Résultat : 3500
   - Comparaison : 3500 > 3500 ? **Non** → Ligne exclue

3. **Ligne 3** (Bernard, Dept 2) :
   - La sous-requête calcule : `AVG(Salaire) WHERE DepartementID = 2`
   - Résultat : (2800 + 3200) / 2 = 3000
   - Comparaison : 2800 > 3000 ? **Non** → Ligne exclue

4. **Ligne 4** (Dubois, Dept 2) :
   - La sous-requête calcule : `AVG(Salaire) WHERE DepartementID = 2`
   - Résultat : 3000
   - Comparaison : 3200 > 3000 ? **Oui** ✓ → Ligne incluse

5. **Ligne 5** (Lambert, Dept 1) :
   - La sous-requête calcule : `AVG(Salaire) WHERE DepartementID = 1`
   - Résultat : 3500
   - Comparaison : 4000 > 3500 ? **Oui** ✓ → Ligne incluse

**Résultat final :**
| NomEmploye | Salaire | DepartementID |
|------------|---------|---------------|
| Dubois | 3200 | 2 |
| Lambert | 4000 | 1 |

### Visualisation du processus

```
Requête Externe                    Sous-requête Corrélée
    ↓                                      ↓
Pour chaque ligne                 Utilise les valeurs
de Employes E                     de la ligne courante
    ↓                                      ↓
    ├──→ Ligne 1 (E.DepartementID=1) ──→ Calcul pour Dept 1
    ├──→ Ligne 2 (E.DepartementID=1) ──→ Calcul pour Dept 1
    ├──→ Ligne 3 (E.DepartementID=2) ──→ Calcul pour Dept 2
    └──→ ...
```

## Exemples pratiques

### Exemple 1 : Employés au-dessus de la moyenne départementale

Nous avons déjà vu cet exemple ci-dessus. Voici le code complet :

```sql
SELECT
    NomEmploye,
    Salaire,
    DepartementID,
    (SELECT AVG(Salaire)
     FROM Employes
     WHERE DepartementID = E.DepartementID) AS MoyenneDept
FROM Employes E
WHERE Salaire > (SELECT AVG(Salaire)
                 FROM Employes
                 WHERE DepartementID = E.DepartementID);
```

**Résultat :**
| NomEmploye | Salaire | DepartementID | MoyenneDept |
|------------|---------|---------------|-------------|
| Dubois | 3200 | 2 | 3000 |
| Lambert | 4000 | 1 | 3500 |

### Exemple 2 : Clients avec leur dernière commande

Trouver la date de la dernière commande pour chaque client (en supposant une table Clients) :

```sql
SELECT
    ClientID,
    (SELECT MAX(DateCommande)
     FROM Commandes C
     WHERE C.ClientID = Clients.ClientID) AS DerniereCommande
FROM Clients;
```

**Explication :**
- Pour chaque client dans la table `Clients`
- La sous-requête trouve la date maximale (la plus récente) de ses commandes
- `C.ClientID = Clients.ClientID` établit la corrélation

### Exemple 3 : Avec EXISTS (sous-requête corrélée)

Trouver les clients qui ont passé au moins une commande de plus de 200€ :

```sql
SELECT ClientID, NomClient
FROM Clients C
WHERE EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
    AND CMD.Montant > 200
);
```

**Explication :**
- Pour chaque client `C`
- La sous-requête vérifie s'il existe des commandes pour ce client avec un montant > 200€
- `EXISTS` retourne `TRUE` dès qu'une ligne correspond
- C'est une sous-requête corrélée car elle référence `C.ClientID`

### Exemple 4 : Compter les commandes par client

Afficher chaque client avec le nombre de commandes qu'il a passées :

```sql
SELECT
    ClientID,
    NomClient,
    (SELECT COUNT(*)
     FROM Commandes CMD
     WHERE CMD.ClientID = C.ClientID) AS NombreCommandes
FROM Clients C;
```

**Résultat hypothétique :**
| ClientID | NomClient | NombreCommandes |
|----------|-----------|-----------------|
| 1 | Dupont | 2 |
| 2 | Martin | 2 |
| 3 | Bernard | 0 |

**Note :** Cette approche fonctionne mais une jointure avec `GROUP BY` serait souvent plus performante.

### Exemple 5 : Filtrer avec une condition corrélée complexe

Trouver les employés dont le salaire est dans les 20% supérieurs de leur département :

```sql
SELECT NomEmploye, Salaire, DepartementID
FROM Employes E
WHERE Salaire >= (
    SELECT MAX(Salaire) * 0.8
    FROM Employes
    WHERE DepartementID = E.DepartementID
);
```

**Explication :**
- Pour chaque employé `E`
- Calcule 80% du salaire maximum dans son département
- Ne garde que ceux qui sont au-dessus de ce seuil

## Sous-requêtes corrélées vs Non-corrélées

### Comparaison directe

**Non-corrélée (indépendante) :**
```sql
-- La sous-requête s'exécute une seule fois
SELECT NomEmploye, Salaire
FROM Employes
WHERE Salaire > (SELECT AVG(Salaire) FROM Employes);
```
- ✅ Plus rapide (exécution unique)
- ✅ Plus simple à optimiser
- ❌ Moins flexible (même valeur pour toutes les lignes)

**Corrélée (dépendante) :**
```sql
-- La sous-requête s'exécute N fois (N = nombre de lignes)
SELECT NomEmploye, Salaire
FROM Employes E
WHERE Salaire > (SELECT AVG(Salaire)
                 FROM Employes
                 WHERE DepartementID = E.DepartementID);
```
- ✅ Plus flexible (valeur différente par ligne)
- ✅ Permet des comparaisons contextuelles
- ❌ Potentiellement plus lente (exécutions multiples)

### Tableau récapitulatif

| Aspect | Non-corrélée | Corrélée |
|--------|--------------|----------|
| **Exécutions** | Une seule fois | Une fois par ligne externe |
| **Dépendance** | Indépendante | Dépend de la requête externe |
| **Syntaxe** | Pas de référence externe | Référence à l'alias externe |
| **Performance** | Généralement plus rapide | Peut être plus lente |
| **Flexibilité** | Moins flexible | Très flexible |
| **Cas d'usage** | Comparaison globale | Comparaison contextuelle |

## Quand utiliser les sous-requêtes corrélées ?

### ✅ Situations idéales

1. **Comparaisons contextuelles**
   - Comparer chaque ligne à un agrégat de son groupe
   - Exemple : "Salaire vs moyenne du département"

2. **Vérifications d'existence avec conditions complexes**
   - Utiliser `EXISTS` avec des conditions multiples
   - Exemple : "Clients ayant commandé un produit spécifique récemment"

3. **Calculs dépendants de chaque ligne**
   - Compter les occurrences liées à chaque ligne
   - Exemple : "Nombre de commandes par client"

4. **Filtrage avec données d'une autre table**
   - Conditions qui nécessitent des données liées
   - Exemple : "Employés dont le manager gagne plus de X"

### ⚠️ Quand éviter ou alternatives

1. **Grandes tables sans index appropriés**
   - Peut devenir très lent
   - Alternative : Utiliser des jointures avec `GROUP BY`

2. **Calculs simples dans SELECT**
   - Peut être remplacé par des fonctions de fenêtrage
   - Alternative : `SUM() OVER()`, `AVG() OVER()`, etc.

3. **Agrégations simples**
   - Une jointure peut être plus performante
   - Alternative : `JOIN` avec `GROUP BY`

## Optimisation et performances

### Importance des index

Les sous-requêtes corrélées bénéficient énormément des index :

```sql
-- Cette requête sera beaucoup plus rapide avec un index sur DepartementID
SELECT NomEmploye, Salaire
FROM Employes E
WHERE Salaire > (SELECT AVG(Salaire)
                 FROM Employes
                 WHERE DepartementID = E.DepartementID);

-- Index recommandé :
-- CREATE INDEX IDX_Employes_DepartementID ON Employes(DepartementID);
```

### Exemple de réécriture pour meilleures performances

**Avec sous-requête corrélée (peut être lent) :**
```sql
SELECT
    NomClient,
    (SELECT COUNT(*) FROM Commandes WHERE ClientID = C.ClientID) AS NbCmd
FROM Clients C;
```

**Avec jointure et GROUP BY (généralement plus rapide) :**
```sql
SELECT
    C.NomClient,
    COUNT(CMD.CommandeID) AS NbCmd
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.ClientID, C.NomClient;
```

**Avec fonction de fenêtrage (moderne et performant) :**
```sql
SELECT DISTINCT
    C.NomClient,
    COUNT(CMD.CommandeID) OVER (PARTITION BY C.ClientID) AS NbCmd
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

## Cas d'usage avancés

### Exemple 6 : Trouver les doublons

Identifier les employés qui ont le même salaire qu'au moins un autre employé :

```sql
SELECT NomEmploye, Salaire
FROM Employes E1
WHERE EXISTS (
    SELECT 1
    FROM Employes E2
    WHERE E2.Salaire = E1.Salaire
    AND E2.EmployeID <> E1.EmployeID
);
```

**Explication :**
- Pour chaque employé `E1`
- Cherche s'il existe un autre employé `E2` avec le même salaire
- `E2.EmployeID <> E1.EmployeID` évite de comparer l'employé avec lui-même

### Exemple 7 : Rang sans fonction de fenêtrage

Calculer le rang d'un employé par salaire dans son département (méthode ancienne) :

```sql
SELECT
    NomEmploye,
    Salaire,
    DepartementID,
    (SELECT COUNT(*)
     FROM Employes E2
     WHERE E2.DepartementID = E1.DepartementID
     AND E2.Salaire > E1.Salaire) + 1 AS RangDept
FROM Employes E1
ORDER BY DepartementID, RangDept;
```

**Note :** Aujourd'hui, on utiliserait plutôt `ROW_NUMBER()` ou `RANK()` qui sont plus performants.

### Exemple 8 : Dernière valeur d'une série

Trouver le montant de la commande précédente pour chaque commande :

```sql
SELECT
    CommandeID,
    ClientID,
    Montant,
    (SELECT TOP 1 Montant
     FROM Commandes C2
     WHERE C2.ClientID = C1.ClientID
     AND C2.DateCommande < C1.DateCommande
     ORDER BY C2.DateCommande DESC) AS MontantPrecedent
FROM Commandes C1
ORDER BY ClientID, DateCommande;
```

**Note moderne :** La fonction `LAG()` serait plus appropriée aujourd'hui.

## Points importants à retenir

### ✅ Avantages

1. **Flexibilité** : Permettent des comparaisons contextuelles complexes
2. **Lisibilité** : Parfois plus claires qu'une jointure complexe
3. **Puissance** : Peuvent résoudre des problèmes difficiles à exprimer autrement

### ⚠️ Inconvénients

1. **Performance** : Peuvent être lentes sur de grandes tables
2. **Exécutions multiples** : La sous-requête s'exécute pour chaque ligne
3. **Complexité d'optimisation** : Plus difficiles à optimiser pour le moteur SQL

### 💡 Conseils pratiques

1. **Toujours utiliser des alias** pour la table externe
2. **Créer des index** sur les colonnes utilisées dans la corrélation
3. **Tester les performances** et comparer avec des alternatives (jointures, fonctions de fenêtrage)
4. **Privilégier EXISTS** pour les vérifications d'existence (plus rapide que `IN`)
5. **Documenter** les sous-requêtes corrélées car elles peuvent être moins évidentes à comprendre

## Résumé

Les sous-requêtes corrélées sont un outil puissant qui permet de :
- Effectuer des **comparaisons contextuelles** (comparer chaque ligne à un sous-ensemble pertinent)
- Créer des **calculs dépendants** de la ligne courante
- Résoudre des problèmes qui seraient complexes avec des jointures simples

**Caractéristiques clés :**
- S'exécutent **une fois par ligne** de la requête externe
- **Référencent** la table externe via un alias
- Sont **flexibles** mais peuvent être **moins performantes** que d'autres approches
- Nécessitent des **index appropriés** pour de bonnes performances

**En pratique :**
- Utilisez-les quand elles rendent la logique plus claire
- Comparez les performances avec des alternatives (jointures, fonctions de fenêtrage)
- SQL Server optimise souvent bien ces requêtes, mais surveillez les plans d'exécution
