# 4.3.3 CTE récursives (Concepts de base pour hiérarchies)

## Introduction aux hiérarchies

### Qu'est-ce qu'une hiérarchie ?

Une **hiérarchie** est une structure de données où les éléments sont organisés en **niveaux parent-enfant**. C'est une organisation en forme d'arbre où :
- Un élément peut avoir **un parent** (sauf la racine)
- Un élément peut avoir **plusieurs enfants**
- Il existe une **racine** (élément sans parent)

### Exemples de hiérarchies dans la vie réelle

1. **Organigramme d'entreprise**
   ```
   PDG
   ├── Directeur IT
   │   ├── Chef de projet
   │   │   ├── Développeur 1
   │   │   └── Développeur 2
   │   └── Architecte
   └── Directeur RH
       └── Responsable recrutement
   ```

2. **Catégories de produits**
   ```
   Électronique
   ├── Informatique
   │   ├── Ordinateurs
   │   │   ├── Portables
   │   │   └── Fixes
   │   └── Accessoires
   └── Audio
       ├── Casques
       └── Enceintes
   ```

3. **Structure géographique**
   ```
   Monde
   ├── Europe
   │   ├── France
   │   │   ├── Île-de-France
   │   │   │   ├── Paris
   │   │   │   └── Hauts-de-Seine
   │   │   └── Normandie
   │   └── Espagne
   └── Asie
   ```

4. **Fils de discussion (forums)**
   ```
   Message original
   ├── Réponse 1
   │   ├── Réponse à la réponse 1
   │   └── Autre réponse à la réponse 1
   ├── Réponse 2
   └── Réponse 3
       └── Réponse à la réponse 3
   ```

## Le défi des hiérarchies en SQL

### Structure de table typique pour une hiérarchie

Les hiérarchies sont généralement stockées avec une **auto-référence** :

**Table Employes**
| EmployeID | NomEmploye | ManagerID |
|-----------|------------|-----------|
| 1 | Alice | NULL |
| 2 | Bob | 1 |
| 3 | Charlie | 1 |
| 4 | David | 2 |
| 5 | Eve | 2 |

**Relation :**
- `ManagerID` pointe vers `EmployeID` du manager
- `ManagerID = NULL` signifie que c'est la racine (pas de manager)

### Pourquoi c'est difficile en SQL standard ?

#### Problème 1 : Nombre de niveaux inconnu

Vous ne savez pas à l'avance combien de niveaux il y a dans la hiérarchie.

```sql
-- Comment écrire cette requête si vous ne savez pas combien de niveaux il y a ?
-- Niveau 1
SELECT * FROM Employes WHERE ManagerID = 1;

-- Niveau 2
SELECT * FROM Employes WHERE ManagerID IN (2, 3);

-- Niveau 3 ?
-- Niveau 4 ?
-- ... Combien de niveaux ???
```

#### Problème 2 : Impossible avec une seule jointure

Une jointure simple ne remonte qu'un niveau.

```sql
-- Cette requête ne trouve que les subordonnés DIRECTS
SELECT
    E.NomEmploye AS Employe,
    M.NomEmploye AS Manager
FROM Employes E
LEFT JOIN Employes M ON E.ManagerID = M.EmployeID;
```

**Résultat :**
| Employe | Manager |
|---------|---------|
| Alice | NULL |
| Bob | Alice |
| Charlie | Alice |
| David | Bob |
| Eve | Bob |

❌ Cette requête ne montre pas que David et Eve sont aussi sous Alice (indirectement).

#### Problème 3 : Approches traditionnelles limitées

**Option A : Requêtes multiples** (inefficace)
```sql
-- Requête 1 : Niveau 0
-- Requête 2 : Niveau 1
-- Requête 3 : Niveau 2
-- etc...
```

**Option B : Code applicatif** (complexe)
```java
// Pseudo-code
while (hasMoreLevels) {
    employees = getNextLevel(currentLevel);
    currentLevel++;
}
```

**Option C : Colonnes multiples** (rigide)
```sql
-- Limité à un nombre fixe de niveaux
ALTER TABLE Employes ADD
    Manager1ID INT,
    Manager2ID INT,
    Manager3ID INT;  -- Et si on a besoin de plus ?
```

## La solution : CTE récursives

Les **CTE récursives** résolvent ce problème en permettant à une requête de **se référencer elle-même**.

### Anatomie d'une CTE récursive

Une CTE récursive a **toujours** deux parties obligatoires :

```sql
WITH NomCTE AS (
    -- PARTIE 1 : ANCRE (Anchor Member)
    -- Point de départ : sélection des éléments racines
    SELECT colonnes
    FROM table
    WHERE condition_racine  -- Ex: ManagerID IS NULL

    UNION ALL  -- ← OBLIGATOIRE : UNION ALL (pas UNION)

    -- PARTIE 2 : RÉCURSION (Recursive Member)
    -- Sélection des enfants en référençant le CTE lui-même
    SELECT colonnes
    FROM table T
    INNER JOIN NomCTE CTE ON T.ParentID = CTE.ID
    WHERE condition_arret  -- Optionnel mais recommandé
)
SELECT * FROM NomCTE;
```

**Composants essentiels :**
1. **Ancre** : Requête de base qui initialise la récursion
2. **UNION ALL** : Combine l'ancre et la récursion (doit être `UNION ALL`, pas `UNION`)
3. **Récursion** : Requête qui se joint au CTE lui-même
4. **Condition d'arrêt** : Évite la récursion infinie

### Comment ça fonctionne (étape par étape)

Prenons un exemple simple pour comprendre le mécanisme :

**Table Employes**
| EmployeID | NomEmploye | ManagerID |
|-----------|------------|-----------|
| 1 | Alice | NULL |
| 2 | Bob | 1 |
| 3 | Charlie | 2 |

```sql
WITH Hierarchie AS (
    -- Ancre
    SELECT EmployeID, NomEmploye, ManagerID, 0 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    -- Récursion
    SELECT E.EmployeID, E.NomEmploye, E.ManagerID, H.Niveau + 1
    FROM Employes E
    INNER JOIN Hierarchie H ON E.ManagerID = H.EmployeID
)
SELECT * FROM Hierarchie;
```

**Exécution étape par étape :**

| Étape | Type | Requête exécutée | Résultat ajouté | Table Hierarchie |
|-------|------|------------------|-----------------|------------------|
| 0 | Ancre | `WHERE ManagerID IS NULL` | (1, Alice, NULL, 0) | [(1, Alice, NULL, 0)] |
| 1 | Récursion | `JOIN` sur EmployeID=1 | (2, Bob, 1, 1) | [(1, Alice, NULL, 0), (2, Bob, 1, 1)] |
| 2 | Récursion | `JOIN` sur EmployeID=2 | (3, Charlie, 2, 2) | [(1, Alice, NULL, 0), (2, Bob, 1, 1), (3, Charlie, 2, 2)] |
| 3 | Récursion | `JOIN` sur EmployeID=3 | Aucun (personne n'a Charlie comme manager) | Fin |

**Visualisation du processus :**

```
Itération 0 (Ancre):
┌─────────┐
│  Alice  │ ← Sélectionné (ManagerID IS NULL)
└─────────┘

Itération 1 (Récursion):
┌─────────┐
│  Alice  │
└────┬────┘
     │
     ├─ Bob ← Sélectionné (ManagerID = 1, qui est Alice)

Itération 2 (Récursion):
┌─────────┐
│  Alice  │
└────┬────┘
     │
     ├─ Bob
     │  └─ Charlie ← Sélectionné (ManagerID = 2, qui est Bob)

Itération 3 (Récursion):
Aucun employé avec ManagerID = 3 → STOP
```

## Patterns fondamentaux des CTE récursives

### Pattern 1 : Descendre la hiérarchie (Top-Down)

**Objectif :** Partir d'un élément et trouver tous ses descendants.

**Contexte : Table Employes complète**
| EmployeID | NomEmploye | ManagerID | Poste |
|-----------|------------|-----------|-------|
| 1 | Alice | NULL | PDG |
| 2 | Bob | 1 | Directeur IT |
| 3 | Charlie | 1 | Directeur RH |
| 4 | David | 2 | Dev Senior |
| 5 | Eve | 2 | Dev Senior |
| 6 | Frank | 4 | Dev Junior |
| 7 | Grace | 3 | Manager RH |

#### Exemple 1 : Tous les employés de l'entreprise

```sql
WITH HierarchieComplete AS (
    -- Ancre : La racine (PDG)
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        Poste,
        0 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    -- Récursion : Tous les subordonnés
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        E.Poste,
        H.Niveau + 1
    FROM Employes E
    INNER JOIN HierarchieComplete H ON E.ManagerID = H.EmployeID
)
SELECT
    REPLICATE('  ', Niveau) + NomEmploye AS Hierarchie,
    Poste,
    Niveau
FROM HierarchieComplete
ORDER BY EmployeID;
```

**Résultat :**
| Hierarchie | Poste | Niveau |
|------------|-------|--------|
| Alice | PDG | 0 |
|   Bob | Directeur IT | 1 |
|   Charlie | Directeur RH | 1 |
|     David | Dev Senior | 2 |
|     Eve | Dev Senior | 2 |
|       Frank | Dev Junior | 3 |
|     Grace | Manager RH | 2 |

#### Exemple 2 : Subordonnés d'une personne spécifique

Trouver tous les subordonnés de Bob (directs et indirects).

```sql
WITH SubordonnesDeBob AS (
    -- Ancre : Bob lui-même
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS NiveauSousManager
    FROM Employes
    WHERE EmployeID = 2  -- Bob

    UNION ALL

    -- Récursion : Ses subordonnés
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        S.NiveauSousManager + 1
    FROM Employes E
    INNER JOIN SubordonnesDeBob S ON E.ManagerID = S.EmployeID
)
SELECT
    NomEmploye,
    NiveauSousManager,
    CASE
        WHEN NiveauSousManager = 0 THEN '👤 Manager'
        WHEN NiveauSousManager = 1 THEN '└─ Subordonné direct'
        ELSE '  └─ Subordonné niveau ' + CAST(NiveauSousManager AS VARCHAR)
    END AS Relation
FROM SubordonnesDeBob
ORDER BY NiveauSousManager, NomEmploye;
```

**Résultat :**
| NomEmploye | NiveauSousManager | Relation |
|------------|-------------------|----------|
| Bob | 0 | 👤 Manager |
| David | 1 | └─ Subordonné direct |
| Eve | 1 | └─ Subordonné direct |
| Frank | 2 | └─ Subordonné niveau 2 |

### Pattern 2 : Remonter la hiérarchie (Bottom-Up)

**Objectif :** Partir d'un élément et trouver tous ses ancêtres (parents).

#### Exemple 3 : Chaîne de management d'un employé

Trouver tous les managers de Frank, jusqu'au PDG.

```sql
WITH ChaineDeFrank AS (
    -- Ancre : Frank lui-même
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        Poste,
        0 AS NiveauAuDessus
    FROM Employes
    WHERE EmployeID = 6  -- Frank

    UNION ALL

    -- Récursion : Remonte vers les managers
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        E.Poste,
        C.NiveauAuDessus + 1
    FROM Employes E
    INNER JOIN ChaineDeFrank C ON E.EmployeID = C.ManagerID
)
SELECT
    REPLICATE('↑ ', NiveauAuDessus) + NomEmploye AS ChaineManagement,
    Poste,
    NiveauAuDessus
FROM ChaineDeFrank
ORDER BY NiveauAuDessus;
```

**Résultat :**
| ChaineManagement | Poste | NiveauAuDessus |
|------------------|-------|----------------|
| Frank | Dev Junior | 0 |
| ↑ David | Dev Senior | 1 |
| ↑ ↑ Bob | Directeur IT | 2 |
| ↑ ↑ ↑ Alice | PDG | 3 |

### Pattern 3 : Calcul du chemin hiérarchique

**Objectif :** Construire le chemin complet depuis la racine jusqu'à chaque élément.

#### Exemple 4 : Chemin hiérarchique de chaque employé

```sql
WITH HierarchieAvecChemin AS (
    -- Ancre : La racine
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS Niveau,
        CAST(NomEmploye AS VARCHAR(1000)) AS Chemin,
        CAST('/' + NomEmploye AS VARCHAR(1000)) AS CheminFormate
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    -- Récursion : Ajoute chaque niveau au chemin
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        H.Niveau + 1,
        CAST(H.Chemin + ' > ' + E.NomEmploye AS VARCHAR(1000)),
        CAST(H.CheminFormate + '/' + E.NomEmploye AS VARCHAR(1000))
    FROM Employes E
    INNER JOIN HierarchieAvecChemin H ON E.ManagerID = H.EmployeID
)
SELECT
    NomEmploye,
    Niveau,
    Chemin,
    CheminFormate
FROM HierarchieAvecChemin
ORDER BY Chemin;
```

**Résultat :**
| NomEmploye | Niveau | Chemin | CheminFormate |
|------------|--------|--------|---------------|
| Alice | 0 | Alice | /Alice |
| Bob | 1 | Alice > Bob | /Alice/Bob |
| David | 2 | Alice > Bob > David | /Alice/Bob/David |
| Frank | 3 | Alice > Bob > David > Frank | /Alice/Bob/David/Frank |
| Eve | 2 | Alice > Bob > Eve | /Alice/Bob/Eve |
| Charlie | 1 | Alice > Charlie | /Alice/Charlie |
| Grace | 2 | Alice > Charlie > Grace | /Alice/Charlie/Grace |

**Utilité du chemin :**
- Tri naturel de la hiérarchie
- Détection de cycles (un élément ne doit pas apparaître deux fois dans son propre chemin)
- Affichage du contexte complet
- Filtrage par branche

## Techniques avancées pour les hiérarchies

### Technique 1 : Compter les descendants

Combien de subordonnés (directs et indirects) chaque manager a-t-il ?

L'idée : pour **chaque** employé pris comme point de départ, on descend toute sa sous-arborescence. On construit donc l'ensemble des couples `(ancêtre, descendant)`, puis on compte les descendants par ancêtre.

```sql
WITH Descendants AS (
    -- Ancre : chaque employé est la racine de sa propre sous-arborescence
    SELECT
        EmployeID AS AncetreID,
        EmployeID AS DescendantID
    FROM Employes

    UNION ALL

    -- Récursion : on rattache les enfants de chaque descendant déjà connu
    SELECT
        D.AncetreID,
        E.EmployeID
    FROM Employes E
    INNER JOIN Descendants D ON E.ManagerID = D.DescendantID
)
SELECT
    A.NomEmploye,
    COUNT(*) - 1 AS NombreSubordonnes   -- -1 pour exclure l'employé lui-même
FROM Descendants D
INNER JOIN Employes A ON A.EmployeID = D.AncetreID
GROUP BY A.EmployeID, A.NomEmploye
HAVING COUNT(*) - 1 > 0                 -- garder seulement ceux qui ont des subordonnés
ORDER BY NombreSubordonnes DESC;
```

**Résultat :**
| NomEmploye | NombreSubordonnes |
|------------|-------------------|
| Alice | 6 |
| Bob | 3 |
| Charlie | 1 |
| David | 1 |

**Comment ça marche :**
- L'**ancre** crée un couple `(AncetreID, DescendantID)` où chaque employé est son propre descendant (distance 0).
- La **récursion** ajoute, pour chaque couple `(A, D)` déjà connu, les enfants directs de `D` — qui deviennent de nouveaux descendants de `A`.
- On capture ainsi **toutes** les relations ancêtre/descendant (directes ET indirectes) ; il suffit ensuite de regrouper par ancêtre et de compter (en retirant l'employé lui-même).

### Technique 2 : Niveau de profondeur maximum

Quelle est la profondeur maximale de la hiérarchie ?

```sql
WITH HierarchieAvecNiveau AS (
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        H.Niveau + 1
    FROM Employes E
    INNER JOIN HierarchieAvecNiveau H ON E.ManagerID = H.EmployeID
)
SELECT
    MAX(Niveau) AS ProfondeurMaximale,
    COUNT(DISTINCT Niveau) AS NombreNiveaux
FROM HierarchieAvecNiveau;
```

**Résultat :**
| ProfondeurMaximale | NombreNiveaux |
|--------------------|---------------|
| 3 | 4 |

### Technique 3 : Détection de cycles (boucles infinies)

**Problème :** Que se passe-t-il si les données contiennent une référence circulaire ?

**Exemple de données problématiques :**
| EmployeID | ManagerID |
|-----------|-----------|
| 1 | 2 |
| 2 | 3 |
| 3 | 1 | ← Cycle ! 1 → 2 → 3 → 1 → ...

**Solution : Suivre le chemin parcouru**

```sql
WITH HierarchieSecurisee AS (
    -- Ancre
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS Niveau,
        CAST(',' + CAST(EmployeID AS VARCHAR(10)) + ',' AS VARCHAR(1000)) AS CheminID
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    -- Récursion avec détection de cycle
    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        H.Niveau + 1,
        CAST(H.CheminID + CAST(E.EmployeID AS VARCHAR(10)) + ',' AS VARCHAR(1000))
    FROM Employes E
    INNER JOIN HierarchieSecurisee H ON E.ManagerID = H.EmployeID
    WHERE H.CheminID NOT LIKE '%,' + CAST(E.EmployeID AS VARCHAR(10)) + ',%'
    -- ↑ Cette condition empêche de revisiter un nœud déjà visité
)
SELECT
    NomEmploye,
    Niveau,
    CheminID
FROM HierarchieSecurisee;
```

**Explication :**
- `CheminID` stocke tous les IDs visités : ",1,2,4,"
- `NOT LIKE '%,4,%'` vérifie que 4 n'est pas déjà dans le chemin
- Si un cycle existe, la récursion s'arrête avant de le revisiter

### Technique 4 : Filtrer par profondeur

Afficher seulement les 2 premiers niveaux de la hiérarchie.

```sql
WITH HierarchieAvecNiveau AS (
    SELECT
        EmployeID,
        NomEmploye,
        ManagerID,
        0 AS Niveau
    FROM Employes
    WHERE ManagerID IS NULL

    UNION ALL

    SELECT
        E.EmployeID,
        E.NomEmploye,
        E.ManagerID,
        H.Niveau + 1
    FROM Employes E
    INNER JOIN HierarchieAvecNiveau H ON E.ManagerID = H.EmployeID
    WHERE H.Niveau < 2  -- Limite à 2 niveaux supplémentaires
)
SELECT
    REPLICATE('  ', Niveau) + NomEmploye AS Hierarchie,
    Niveau
FROM HierarchieAvecNiveau
ORDER BY EmployeID;
```

**Résultat (max 2 niveaux) :**
| Hierarchie | Niveau |
|------------|--------|
| Alice | 0 |
|   Bob | 1 |
|     David | 2 |
|     Eve | 2 |
|   Charlie | 1 |
|     Grace | 2 |

### Exemple 1 : Catégories de produits

**Table Categories**
| CategorieID | NomCategorie | ParentCategorieID |
|-------------|--------------|-------------------|
| 1 | Électronique | NULL |
| 2 | Informatique | 1 |
| 3 | Audio | 1 |
| 4 | Ordinateurs | 2 |
| 5 | Accessoires | 2 |
| 6 | Portables | 4 |
| 7 | Fixes | 4 |
| 8 | Casques | 3 |

#### Afficher l'arbre des catégories

```sql
WITH ArbreCategories AS (
    -- Ancre : Catégories racines
    SELECT
        CategorieID,
        NomCategorie,
        ParentCategorieID,
        0 AS Niveau,
        CAST(NomCategorie AS VARCHAR(500)) AS Chemin
    FROM Categories
    WHERE ParentCategorieID IS NULL

    UNION ALL

    -- Récursion : Sous-catégories
    SELECT
        C.CategorieID,
        C.NomCategorie,
        C.ParentCategorieID,
        A.Niveau + 1,
        CAST(A.Chemin + ' > ' + C.NomCategorie AS VARCHAR(500))
    FROM Categories C
    INNER JOIN ArbreCategories A ON C.ParentCategorieID = A.CategorieID
)
SELECT
    REPLICATE('│  ', Niveau) +
    CASE WHEN Niveau > 0 THEN '└─ ' ELSE '' END +
    NomCategorie AS ArbreCategories,
    Niveau,
    Chemin
FROM ArbreCategories
ORDER BY Chemin;
```

**Résultat :**
| ArbreCategories | Niveau | Chemin |
|-----------------|--------|--------|
| Électronique | 0 | Électronique |
| │  └─ Audio | 1 | Électronique > Audio |
| │  │  └─ Casques | 2 | Électronique > Audio > Casques |
| │  └─ Informatique | 1 | Électronique > Informatique |
| │  │  └─ Accessoires | 2 | Électronique > Informatique > Accessoires |
| │  │  └─ Ordinateurs | 2 | Électronique > Informatique > Ordinateurs |
| │  │  │  └─ Fixes | 3 | Électronique > Informatique > Ordinateurs > Fixes |
| │  │  │  └─ Portables | 3 | Électronique > Informatique > Ordinateurs > Portables |

#### Trouver tous les produits d'une catégorie et ses sous-catégories

Supposons une table Produits liée aux catégories :

```sql
WITH SousCategoriesDeInformatique AS (
    -- Ancre : La catégorie Informatique
    SELECT CategorieID
    FROM Categories
    WHERE NomCategorie = 'Informatique'

    UNION ALL

    -- Récursion : Toutes les sous-catégories
    SELECT C.CategorieID
    FROM Categories C
    INNER JOIN SousCategoriesDeInformatique S ON C.ParentCategorieID = S.CategorieID
)
SELECT
    P.NomProduit,
    C.NomCategorie
FROM Produits P
INNER JOIN Categories C ON P.CategorieID = C.CategorieID
WHERE P.CategorieID IN (SELECT CategorieID FROM SousCategoriesDeInformatique)
ORDER BY C.NomCategorie, P.NomProduit;
```

```sql
WITH LieuxEnIDF AS (
    -- Ancre : Île-de-France
    SELECT
        LieuID,
        NomLieu,
        ParentLieuID,
        Type,
        0 AS Niveau
    FROM Lieux
    WHERE NomLieu = 'Île-de-France'

    -- Récursion : Tous les lieux enfants
    SELECT
        L.LieuID,
        L.NomLieu,
        L.ParentLieuID,

        LI.Niveau + 1

    INNER JOIN LieuxEnIDF LI ON L.ParentLieuID = LI.LieuID
)
SELECT
    REPLICATE('  ', Niveau) + NomLieu AS Hierarchie,
    Type,
    Niveau
FROM LieuxEnIDF
ORDER BY Niveau, NomLieu;
```

|     75001 | Arrondissement | 2 |

### Exemple 3 : Commentaires imbriqués (forum)

**Table Commentaires**
| CommentaireID | Texte | ParentCommentaireID | Auteur |
|---------------|-------|---------------------|--------|
| 1 | Post original | NULL | Alice |
| 2 | Première réponse | 1 | Bob |
| 3 | Réponse à Bob | 2 | Charlie |
| 4 | Autre réponse | 1 | David |
| 5 | Réponse à Charlie | 3 | Eve |

#### Afficher le fil de discussion

```sql
WITH FilDiscussion AS (
    -- Ancre : Message original
    SELECT
        CommentaireID,
        Texte,
        ParentCommentaireID,
        Auteur,
        0 AS Niveau,
        CAST(CommentaireID AS VARCHAR(100)) AS Ordre
    FROM Commentaires
    WHERE ParentCommentaireID IS NULL

    UNION ALL

    -- Récursion : Réponses
    SELECT
        C.CommentaireID,
        C.Texte,
        C.ParentCommentaireID,
        C.Auteur,
        F.Niveau + 1,
        CAST(F.Ordre + '.' + CAST(C.CommentaireID AS VARCHAR(10)) AS VARCHAR(100))
    FROM Commentaires C
    INNER JOIN FilDiscussion F ON C.ParentCommentaireID = F.CommentaireID
)
SELECT
    REPLICATE('  ', Niveau) +
    CASE WHEN Niveau > 0 THEN '└─ ' ELSE '' END +
    Auteur + ': ' + Texte AS Discussion,
    Niveau
FROM FilDiscussion
ORDER BY Ordre;
```

**Résultat :**
| Discussion | Niveau |
|------------|--------|
| Alice: Post original | 0 |
|   └─ Bob: Première réponse | 1 |
|     └─ Charlie: Réponse à Bob | 2 |
|       └─ Eve: Réponse à Charlie | 3 |
|   └─ David: Autre réponse | 1 |

## Optimisation et performances

### 1. Créer des index appropriés

Pour les hiérarchies, indexez toujours la colonne de référence parente.

```sql
-- Index sur la colonne ParentID pour accélérer les jointures
CREATE INDEX IDX_Employes_ManagerID ON Employes(ManagerID);

-- Index composite si vous filtrez souvent par d'autres critères
CREATE INDEX IDX_Employes_Manager_Dept ON Employes(ManagerID, DepartementID);
```

### 2. Limiter la profondeur de récursion

```sql
WITH Hierarchie AS (
    SELECT ...
    UNION ALL
    SELECT ...
    WHERE Niveau < 10  -- Limite à 10 niveaux
)
SELECT * FROM Hierarchie;
```

Ou utiliser `MAXRECURSION` :

```sql
WITH Hierarchie AS (...)
SELECT * FROM Hierarchie
OPTION (MAXRECURSION 50);  -- Maximum 50 itérations
```

### 3. Matérialiser les hiérarchies stables

Pour des hiérarchies qui changent rarement, créez une table pré-calculée :

```sql
-- Table de matérialisation
CREATE TABLE HierarchieEmployes (
    EmployeID INT,
    AncetreID INT,
    Niveau INT,
    Chemin VARCHAR(1000)
);

-- Remplir avec le CTE récursif
-- ⚠️ Le WITH se place AVANT le INSERT : « INSERT INTO table WITH (...) »
-- serait interprété comme un hint de table et provoquerait une erreur.
WITH Hierarchie AS (...)
INSERT INTO HierarchieEmployes (EmployeID, AncetreID, Niveau, Chemin)
SELECT EmployeID, AncetreID, Niveau, Chemin
FROM Hierarchie;

-- Créer des index
CREATE INDEX IDX_Hier_Emp ON HierarchieEmployes(EmployeID);
CREATE INDEX IDX_Hier_Anc ON HierarchieEmployes(AncetreID);
```

### 4. Utiliser des approches alternatives pour de très grandes hiérarchies

Pour des millions de nœuds, considérez :
- **Nested Sets** (ensembles imbriqués)
- **Materialized Path** (chemin matérialisé)
- **Closure Table** (table de fermeture)

## Limites et pièges à éviter

### 1. Limite de récursion par défaut

Par défaut, SQL Server limite à **100 itérations**.

```sql
-- ❌ Erreur si plus de 100 niveaux
WITH Hierarchie AS (...)
SELECT * FROM Hierarchie;

-- ✅ Augmenter la limite
WITH Hierarchie AS (...)
SELECT * FROM Hierarchie
OPTION (MAXRECURSION 500);

-- ⚠️ Pas de limite (dangereux !)
OPTION (MAXRECURSION 0);
```

### 2. Toujours utiliser UNION ALL (pas UNION)

```sql
-- ❌ ERREUR : SQL Server INTERDIT UNION (sans ALL) dans une CTE récursive
WITH Hierarchie AS (
    SELECT ... WHERE ...
    UNION  -- ← Erreur : « does not contain a top-level UNION ALL operator »
    SELECT ...
)

-- ✅ CORRECT : UNION ALL requis
WITH Hierarchie AS (
    SELECT ... WHERE ...
    UNION ALL  -- ← Obligatoire
    SELECT ...
)
```

Ce n'est donc **pas** un simple choix de performance : `UNION ALL` est **obligatoire** dans une CTE récursive (le membre d'ancrage et le membre récursif doivent être combinés par un `UNION ALL` de premier niveau). Utiliser `UNION` provoque une erreur de compilation.

### 3. Ne pas oublier la condition d'arrêt

```sql
-- ⚠️ Risque de récursion infinie si mauvaises données
WITH Hierarchie AS (
    SELECT ... WHERE ManagerID IS NULL
    UNION ALL
    SELECT ...
    FROM Employes E
    INNER JOIN Hierarchie H ON E.ManagerID = H.EmployeID
    -- Pas de condition d'arrêt explicite
)
```

**Solution :** Ajouter une condition ou limiter les niveaux :

```sql
WHERE H.Niveau < 100  -- Sécurité supplémentaire
```

### 4. Attention aux données circulaires

Toujours prévoir la détection de cycles pour les données potentiellement problématiques.

```sql
-- Sauvegarder le chemin et vérifier l'absence de cycle
WHERE H.CheminID NOT LIKE '%,' + CAST(E.EmployeID AS VARCHAR(10)) + ',%'
```

## Résumé

Les **CTE récursives** sont l'outil idéal pour gérer les **hiérarchies** en SQL.

### Structure de base

```sql
WITH NomCTE AS (
    -- Ancre : Point de départ
    SELECT ... WHERE ParentID IS NULL

    UNION ALL

    -- Récursion : Référence au CTE
    SELECT ...
    FROM Table T
    INNER JOIN NomCTE ON T.ParentID = NomCTE.ID
)
SELECT * FROM NomCTE;
```

### Trois patterns principaux

1. **Descendre (Top-Down)** : Trouver tous les descendants d'un nœud
2. **Remonter (Bottom-Up)** : Trouver tous les ancêtres d'un nœud
3. **Chemin complet** : Construire le chemin hiérarchique

### Techniques essentielles

- **Niveau** : Calculer la profondeur de chaque nœud
- **Chemin** : Stocker le chemin depuis la racine
- **Détection de cycles** : Éviter les boucles infinies
- **Limitation** : Utiliser `MAXRECURSION` pour la sécurité

### Bonnes pratiques

✅ **À faire :**
- Indexer les colonnes ParentID
- Limiter la profondeur si possible
- Détecter les cycles dans les données non fiables
- Tester avec `MAXRECURSION` raisonnable
- Matérialiser les grandes hiérarchies stables

❌ **À éviter :**
- Utiliser `UNION` au lieu de `UNION ALL`
- Omettre la condition d'arrêt
- Utiliser `MAXRECURSION 0` sans précaution
- Oublier les index sur ParentID

### Cas d'usage typiques

- 📊 **Organigrammes** d'entreprise
- 🏷️ **Catégories** de produits
- 🌍 **Structures géographiques**
- 💬 **Commentaires** imbriqués
- 📁 **Arborescences** de fichiers
- 🔗 **Réseaux** et graphes

Les CTE récursives transforment ce qui serait un problème complexe nécessitant du code applicatif en une simple requête SQL élégante et performante !
