# 1.1.3 Différence entre SGBD et SGBDR

## Introduction

Lorsqu'on parle de bases de données, on rencontre souvent les acronymes **SGBD** et **SGBDR**. Bien qu'ils se ressemblent, ils ne désignent pas exactement la même chose. Comprendre cette distinction vous aidera à mieux saisir ce qu'est Microsoft SQL Server et pourquoi il est classé comme un SGBDR.

## Qu'est-ce qu'un SGBD ?

### Définition

**SGBD** signifie **Système de Gestion de Base de Données** (en anglais : **DBMS** - Database Management System).

Un SGBD est un **logiciel** qui permet de :
- **Stocker** des données de manière organisée
- **Gérer** ces données (ajouter, modifier, supprimer)
- **Récupérer** des données (les interroger)
- **Sécuriser** l'accès aux données
- **Assurer l'intégrité** des données

### Analogie simple

Imaginez un SGBD comme un **bibliothécaire électronique** :
- Il sait où sont rangés tous les livres (données)
- Il peut vous aider à trouver un livre spécifique
- Il peut ajouter de nouveaux livres
- Il contrôle qui peut emprunter quels livres
- Il s'assure que les livres sont en bon état

### Le rôle d'un SGBD

Un SGBD sert d'**intermédiaire** entre :
- Les **utilisateurs** ou **applications** (qui veulent accéder aux données)
- Les **fichiers de données** (stockés physiquement sur le disque dur)

Sans SGBD, vous devriez gérer manuellement tous les fichiers, ce qui serait complexe et risqué !

### Caractéristiques principales d'un SGBD

1. **Indépendance des données** : Les applications n'ont pas besoin de savoir comment les données sont physiquement stockées
2. **Gestion des accès concurrents** : Plusieurs utilisateurs peuvent accéder aux données simultanément
3. **Sécurité** : Contrôle des droits d'accès (qui peut voir ou modifier quoi)
4. **Sauvegarde et récupération** : Mécanismes pour protéger contre la perte de données
5. **Intégrité** : S'assure que les données respectent certaines règles

## Qu'est-ce qu'un SGBDR ?

### Définition

**SGBDR** signifie **Système de Gestion de Base de Données Relationnelles** (en anglais : **RDBMS** - Relational Database Management System).

Un SGBDR est un **type spécifique de SGBD** qui :
- Organise les données selon le **modèle relationnel** (que nous avons vu dans la section 1.1.2)
- Utilise des **tables** pour stocker les données
- Permet de créer des **relations** entre les tables
- Utilise le langage **SQL** (Structured Query Language) pour interroger les données

### La différence clé

> **SGBDR** = **SGBD** + **Modèle Relationnel**

En d'autres termes :
- **Tous les SGBDR sont des SGBD**
- **Mais tous les SGBD ne sont pas des SGBDR**

### Caractéristiques spécifiques d'un SGBDR

En plus des fonctionnalités d'un SGBD classique, un SGBDR offre :

1. **Organisation en tables** : Les données sont structurées en lignes et colonnes
2. **Clés primaires et étrangères** : Mécanismes pour identifier et relier les données
3. **Intégrité référentielle** : Garantit la cohérence des liens entre les tables
4. **Normalisation** : Techniques pour éviter la redondance des données
5. **Langage SQL standardisé** : Un langage universel pour interroger les données
6. **Transactions ACID** : Garantit la fiabilité des opérations

## Comparaison : SGBD vs SGBDR

### Tableau comparatif

| Critère | SGBD (général) | SGBDR (relationnel) |
|---------|----------------|---------------------|
| **Structure des données** | Variable (fichiers, objets, documents...) | Tables avec lignes et colonnes |
| **Relations entre données** | Pas toujours supportées | Relations explicites via clés |
| **Langage d'interrogation** | Varie selon le système | SQL (standard) |
| **Intégrité référentielle** | Pas toujours garantie | Garantie par le système |
| **Normalisation** | Non applicable | Principes de normalisation |
| **Exemples** | Systèmes de fichiers, bases NoSQL | SQL Server, Oracle, MySQL, PostgreSQL |

## Exemples de SGBD non-relationnels

Pour mieux comprendre la différence, voici quelques types de SGBD qui ne sont **pas** relationnels :

### 1. Bases de données hiérarchiques

**Concept :** Les données sont organisées en arbre (parent-enfant), comme une structure de dossiers.

**Exemple :** IBM IMS (Information Management System)

**Structure :**
```
Entreprise
├── Département A
│   ├── Employé 1
│   └── Employé 2
└── Département B
    ├── Employé 3
    └── Employé 4
```

**Limitation :** Difficile de représenter des relations complexes (un employé ne peut avoir qu'un seul parent).

### 2. Bases de données réseau

**Concept :** Extension du modèle hiérarchique permettant plusieurs parents.

**Exemple :** IDMS (Integrated Database Management System)

**Limitation :** Complexe à utiliser et à maintenir.

### 3. Bases de données NoSQL (Not Only SQL)

**Concept :** Conçues pour gérer de gros volumes de données non structurées, souvent distribuées.

**Types :**
- **Orientées documents** : MongoDB, CouchDB (stockent des documents JSON)
- **Orientées colonnes** : Cassandra, HBase (optimisées pour des lectures massives)
- **Clé-Valeur** : Redis, DynamoDB (stockage simple clé → valeur)
- **Orientées graphes** : Neo4j (pour des relations complexes type réseaux sociaux)

**Avantages :** Très performantes pour certains cas d'usage spécifiques (big data, temps réel).

**Différence :** Ne suivent pas le modèle relationnel, pas de schéma fixe, pas de langage SQL standard.

## Exemples de SGBDR populaires

Tous ces systèmes utilisent le modèle relationnel et le langage SQL :

### 1. Microsoft SQL Server
- **Éditeur :** Microsoft
- **Système :** Windows, Linux (depuis 2017)
- **Particularités :** Excellent pour l'écosystème Microsoft, intégration avec .NET
- **Langage :** T-SQL (Transact-SQL)

### 2. Oracle Database
- **Éditeur :** Oracle Corporation
- **Système :** Multi-plateformes
- **Particularités :** Très puissant, utilisé dans les grandes entreprises
- **Langage :** PL/SQL

### 3. MySQL
- **Éditeur :** Oracle (depuis le rachat de Sun Microsystems en 2010)
- **Système :** Multi-plateformes
- **Particularités :** Très populaire pour le web ; édition Community **open source** (GPL), édition Enterprise commerciale
- **Langage :** SQL standard

### 4. PostgreSQL
- **Éditeur :** Communauté open source
- **Système :** Multi-plateformes
- **Particularités :** Open source, très respectueux des standards SQL
- **Langage :** SQL standard + PL/pgSQL

### 5. MariaDB
- **Éditeur :** Communauté (fork de MySQL)
- **Système :** Multi-plateformes
- **Particularités :** Compatible MySQL, totalement open source

## Pourquoi SQL Server est un SGBDR ?

Microsoft SQL Server est définitivement un **SGBDR** car il :

### 1. Utilise le modèle relationnel
- Organise toutes les données en **tables**
- Utilise des **clés primaires** pour identifier les enregistrements
- Supporte les **clés étrangères** pour créer des relations

### 2. Garantit l'intégrité référentielle
- Empêche la suppression d'un client si des commandes lui sont rattachées
- Assure la cohérence des données entre tables liées

### 3. Utilise le langage SQL (T-SQL)
- T-SQL est une extension de SQL standard
- Permet de créer, lire, mettre à jour et supprimer des données
- Supporte les jointures entre tables

### 4. Respecte les propriétés ACID
- **Atomicité** : Une transaction est complète ou n'existe pas
- **Cohérence** : Les données restent cohérentes avant et après une transaction
- **Isolation** : Les transactions concurrentes ne s'interfèrent pas
- **Durabilité** : Une fois validée, une transaction est permanente

### 5. Supporte la normalisation
- Permet d'organiser les données selon les règles de normalisation
- Évite la redondance des données

## Quand utiliser un SGBDR vs un autre type de SGBD ?

### Utilisez un SGBDR (comme SQL Server) quand :

- ✅ Vos données ont une **structure claire** et définie
- ✅ Vous avez besoin de **relations complexes** entre les données
- ✅ L'**intégrité des données** est cruciale (banques, e-commerce, RH)
- ✅ Vous devez effectuer des **requêtes complexes** avec des jointures
- ✅ Vous avez besoin de **transactions fiables** (ACID)
- ✅ Les données sont **structurées** et ne changent pas fréquemment de forme

**Exemples d'applications :**
- Systèmes de gestion de clients (CRM)
- Applications de comptabilité
- Systèmes de gestion des ressources humaines
- E-commerce
- Applications d'entreprise traditionnelles

### Utilisez un autre type de SGBD (NoSQL) quand :

- ✅ Vous gérez d'**énormes volumes** de données (big data)
- ✅ Vos données sont **non structurées** ou **semi-structurées**
- ✅ Vous avez besoin de **flexibilité** dans la structure des données
- ✅ Les **performances en lecture** sont plus importantes que l'intégrité stricte
- ✅ Vous devez **scaler horizontalement** (ajouter des serveurs facilement)
- ✅ Les données changent fréquemment de **format**

**Exemples d'applications :**
- Réseaux sociaux (graphes de relations)
- Analyse de logs en temps réel
- Stockage de documents JSON
- Caches haute performance
- Internet des objets (IoT)

## L'évolution : Approches hybrides

Aujourd'hui, la frontière devient parfois floue :

### SQL Server et les fonctionnalités NoSQL

Microsoft SQL Server intègre désormais des fonctionnalités "NoSQL" :
- Support natif du **JSON** (depuis SQL Server 2016)
- Support du **XML**
- Tables **In-Memory** pour des performances extrêmes
- Support des **graphes** (depuis SQL Server 2017)

### Le terme "NewSQL"

Certains systèmes modernes essaient de combiner le meilleur des deux mondes :
- Garanties ACID des SGBDR
- Performance et scalabilité des bases NoSQL

## Résumé

| Concept | Définition |
|---------|------------|
| **SGBD** | Système de Gestion de Base de Données - Concept général |
| **SGBDR** | Système de Gestion de Base de Données **Relationnelles** - Type spécifique de SGBD |
| **Différence clé** | Le SGBDR utilise le modèle relationnel (tables, relations, SQL) |
| **SQL Server** | Un SGBDR développé par Microsoft |

### Points à retenir

- Un **SGBDR** est un **SGBD** qui suit le modèle relationnel
- Les **SGBDR** organisent les données en **tables** liées entre elles
- Le langage **SQL** est le standard pour interroger les SGBDR
- **SQL Server** est un SGBDR (et non un simple SGBD)
- D'autres types de SGBD existent (NoSQL) pour des besoins spécifiques
- Le choix dépend de vos besoins : structure vs flexibilité, intégrité vs performance

### Pourquoi cette distinction est importante ?

Comprendre que SQL Server est un SGBDR vous aide à :
1. Savoir que vous travaillerez avec des **tables** et des **relations**
2. Comprendre que le **langage SQL** est votre outil principal
3. Anticiper les **forces** (intégrité, requêtes complexes) et **limites** (moins flexible que NoSQL) du système
4. Faire les bons choix de conception de base de données
