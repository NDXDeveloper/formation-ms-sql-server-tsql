# 4.4.3 INTERSECT

## Introduction

L'opérateur **INTERSECT** est un opérateur d'ensemble en SQL qui retourne uniquement les **lignes communes** à deux ensembles de résultats. C'est l'équivalent d'une **intersection** en mathématiques : il ne garde que ce qui apparaît dans **les deux** requêtes.

### Analogie simple

Imaginez deux listes d'invités pour une fête :
- **Liste A** : Alice, Bob, Charlie, David
- **Liste B** : Bob, Charlie, Eve, Frank

Si vous cherchez les personnes qui sont sur **les deux listes**, vous utilisez INTERSECT :
- **Résultat** : Bob, Charlie

Seules les personnes présentes dans **les deux listes** sont retournées.

### Représentation visuelle (diagramme de Venn)

```
      Liste A                   Liste B
    ┌─────────┐               ┌─────────┐
    │ Alice   │               │   Eve   │
    │ David   │               │  Frank  │
    │         │  ┌────────┐   │         │
    │         ├──┤Bob     ├───┤         │
    │         │  │Charlie │   │         │
    │         │  │        │   │         │
    └─────────┘  └────────┘   └─────────┘
                     ↑
                Zone d'intersection
             (Résultat de INTERSECT)
```

## Qu'est-ce que INTERSECT ?

### Définition

`INTERSECT` est un opérateur qui :
1. Compare deux ensembles de résultats
2. Retourne **uniquement les lignes présentes dans les deux**
3. **Élimine automatiquement les doublons** (comme UNION)
4. Effectue une comparaison sur **toutes les colonnes**

### Syntaxe de base

```sql
SELECT colonnes
FROM table1
WHERE conditions1

INTERSECT

SELECT colonnes
FROM table2
WHERE conditions2;
```

**Structure :**
- Deux requêtes SELECT séparées par le mot-clé `INTERSECT`
- Les deux requêtes doivent avoir le **même nombre de colonnes**
- Les types de données des colonnes correspondantes doivent être **compatibles**
- Les lignes identiques dans les deux résultats sont conservées **une seule fois**

## Exemple de base : INTERSECT simple

### Exemple 1 : Trouver les clients qui ont acheté en ligne ET en magasin

```sql
SELECT ClientID, NomClient, Email
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient, Email
FROM ClientsMagasin;
```

**Résultat :**
| ClientID | NomClient | Email |
|----------|-----------|-------|
| 2 | Martin | martin@mail.com |
| 3 | Bernard | bernard@mail.com |

**Explication :**
- **Dupont** (1) : seulement en ligne → ❌ Exclu
- **Martin** (2) : en ligne ET en magasin → ✅ Inclus
- **Bernard** (3) : en ligne ET en magasin → ✅ Inclus
- **Dubois** (4) : seulement en ligne → ❌ Exclu
- **Lambert** (5) : seulement en magasin → ❌ Exclu
- **Moreau** (6) : seulement en magasin → ❌ Exclu

### Comment INTERSECT fonctionne (étape par étape)

**Étape 1 : Exécuter les deux SELECT**

Résultat SELECT 1 (ClientsEnLigne) :
```
1, Dupont, dupont@mail.com
2, Martin, martin@mail.com
3, Bernard, bernard@mail.com
4, Dubois, dubois@mail.com
```

Résultat SELECT 2 (ClientsMagasin) :
```
2, Martin, martin@mail.com
3, Bernard, bernard@mail.com
5, Lambert, lambert@mail.com
6, Moreau, moreau@mail.com
```

**Étape 2 : Comparer ligne par ligne**

SQL Server compare chaque ligne du premier résultat avec toutes les lignes du second résultat :
- Ligne `1, Dupont, dupont@mail.com` → Présente dans résultat 2 ? **NON** → Exclue
- Ligne `2, Martin, martin@mail.com` → Présente dans résultat 2 ? **OUI** → Gardée ✓
- Ligne `3, Bernard, bernard@mail.com` → Présente dans résultat 2 ? **OUI** → Gardée ✓
- Ligne `4, Dubois, dubois@mail.com` → Présente dans résultat 2 ? **NON** → Exclue

**Étape 3 : Éliminer les doublons**

Si une ligne apparaît plusieurs fois dans l'intersection, elle n'est conservée qu'une fois (comme UNION).

**Étape 4 : Retourner le résultat**
```
2, Martin, martin@mail.com
3, Bernard, bernard@mail.com
```

## Critères d'égalité avec INTERSECT

### Comparaison stricte sur toutes les colonnes

INTERSECT compare **toutes les colonnes** pour déterminer si deux lignes sont identiques.

**Exemple 2 : Toutes les colonnes doivent correspondre**

```sql
-- Seuls les produits IDENTIQUES (même ID, nom ET prix)
SELECT ProduitID, NomProduit, Prix
FROM ProduitsFrance

INTERSECT

SELECT ProduitID, NomProduit, Prix
FROM ProduitsBelgique;
```

**Résultat :**
| ProduitID | NomProduit | Prix |
|-----------|------------|------|
| 2 | Souris | 15 |
| 3 | Écran | 200 |

**Analyse :**
- Produit 1 (Clavier, 25) : seulement en France → ❌
- Produit 2 (Souris, 15) : **identique** dans les deux → ✅
- Produit 3 (Écran, 200) : **identique** dans les deux → ✅
- Produit 4 (Webcam, 50) : seulement en Belgique → ❌

### Exemple 3 : Impact du choix des colonnes

Si on ne compare que les noms de produits :

```sql
-- Uniquement les noms de produits communs
SELECT NomProduit
FROM ProduitsFrance

INTERSECT

SELECT NomProduit
FROM ProduitsBelgique;
```

**Résultat :**
| NomProduit |
|------------|
| Écran |
| Souris |

**Note :** Le résultat est le même ici car les noms correspondent aux ID, mais ce ne serait pas toujours le cas.

### Comportement avec NULL

Comme pour UNION, INTERSECT considère deux valeurs `NULL` comme **égales**.

```sql
SELECT 'Alice' AS Nom, NULL AS Telephone
INTERSECT
SELECT 'Alice', NULL;
```

**Résultat :** Une ligne (les deux NULL sont considérés égaux)
| Nom | Telephone |
|-----|-----------|
| Alice | NULL |

## Comparaison avec d'autres approches

### INTERSECT vs INNER JOIN

Il existe plusieurs façons de trouver les éléments communs. Comparons INTERSECT avec INNER JOIN.

**Avec INTERSECT :**
```sql
SELECT ClientID, NomClient
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient
FROM ClientsMagasin;
```

**Avec INNER JOIN :**
```sql
SELECT DISTINCT
    C1.ClientID,
    C1.NomClient
FROM ClientsEnLigne C1
INNER JOIN ClientsMagasin C2
    ON C1.ClientID = C2.ClientID
    AND C1.NomClient = C2.NomClient;
```

**Différences :**

| Aspect | INTERSECT | INNER JOIN |
|--------|-----------|------------|
| **Syntaxe** | Plus simple et concise | Plus verbeux |
| **Comparaison** | Toutes les colonnes automatiquement | Doit spécifier les colonnes de jointure |
| **Doublons** | Éliminés automatiquement | Nécessite DISTINCT |
| **Lisibilité** | Intention claire (intersection) | Peut être moins évidente |
| **Flexibilité** | Moins flexible | Plus flexible (conditions complexes) |
| **Performance** | Similaire | Similaire |

**Quand utiliser quoi :**
- ✅ **INTERSECT** : Quand vous voulez l'intersection complète de deux ensembles
- ✅ **INNER JOIN** : Quand vous avez besoin de colonnes des deux tables ou de conditions complexes

### INTERSECT vs EXISTS

**Avec INTERSECT :**
```sql
SELECT ClientID, NomClient
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient
FROM ClientsMagasin;
```

**Avec EXISTS (équivalent) :**
```sql
SELECT ClientID, NomClient
FROM ClientsEnLigne C1
WHERE EXISTS (
    SELECT 1
    FROM ClientsMagasin C2
    WHERE C2.ClientID = C1.ClientID
    AND C2.NomClient = C1.NomClient
);
```

**Différences :**

| Aspect | INTERSECT | EXISTS |
|--------|-----------|--------|
| **Simplicité** | Très simple | Plus complexe |
| **Intention** | Très claire | Moins immédiate |
| **Conditions** | Toutes les colonnes | Peut être sélectif |
| **Performance** | Bonne | Peut être meilleure |

## Règles et contraintes

### Règle 1 : Même nombre de colonnes

Les deux requêtes doivent avoir le même nombre de colonnes.

```sql
-- ❌ ERREUR
SELECT ClientID, NomClient
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient, Email  -- 3 colonnes !
FROM ClientsMagasin;
```

**Solution :** Ajouter une colonne NULL ou constante

```sql
-- ✅ CORRECT
SELECT ClientID, NomClient, NULL AS Email
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient, Email
FROM ClientsMagasin;
```

### Règle 2 : Types de données compatibles

Les colonnes correspondantes doivent avoir des types compatibles.

```sql
-- ❌ ERREUR
SELECT ClientID, NomClient  -- ClientID est INT
FROM ClientsEnLigne

INTERSECT

SELECT NomClient, ClientID  -- NomClient (VARCHAR) en première position
FROM ClientsMagasin;
```

### Règle 3 : Noms de colonnes du premier SELECT

Le résultat utilise les noms de colonnes de la première requête.

```sql
SELECT
    ClientID AS ID,
    NomClient AS Nom
FROM ClientsEnLigne

INTERSECT

SELECT
    ClientID AS ClientIdentifiant,  -- Ce nom est ignoré
    NomClient AS NomComplet          -- Ce nom est ignoré
FROM ClientsMagasin;
```

**Résultat :** Les colonnes s'appellent `ID` et `Nom` (de la première requête).

### Règle 4 : ORDER BY uniquement à la fin

```sql
-- ❌ ERREUR
SELECT ClientID, NomClient
FROM ClientsEnLigne
ORDER BY NomClient  -- Erreur !

INTERSECT

SELECT ClientID, NomClient
FROM ClientsMagasin;
```

```sql
-- ✅ CORRECT
SELECT ClientID, NomClient
FROM ClientsEnLigne

INTERSECT

SELECT ClientID, NomClient
FROM ClientsMagasin

ORDER BY NomClient;  -- À la fin
```

## Performance et optimisation

### Coût de INTERSECT

INTERSECT nécessite :
1. Exécuter les deux requêtes SELECT
2. Trier les résultats (pour la comparaison)
3. Comparer les lignes
4. Éliminer les doublons

**Opérations effectuées :**
```
Requête 1 → Résultats → ┐
                        ├→ Trier → Comparer → Garder communes → Résultat
Requête 2 → Résultats → ┘
```

### Optimisations

#### 1. Filtrer avant INTERSECT

Réduisez le nombre de lignes avant l'intersection.

```sql
-- ❌ Moins efficace : Filtre après INTERSECT
SELECT ClientID, NomClient
FROM (
    SELECT ClientID, NomClient FROM ClientsEnLigne
    INTERSECT
    SELECT ClientID, NomClient FROM ClientsMagasin
) AS Communs
WHERE NomClient LIKE 'D%';

-- ✅ Plus efficace : Filtre avant INTERSECT
SELECT ClientID, NomClient
FROM ClientsEnLigne
WHERE NomClient LIKE 'D%'

INTERSECT

SELECT ClientID, NomClient
FROM ClientsMagasin
WHERE NomClient LIKE 'D%';
```

#### 2. Utiliser des index

Indexez les colonnes utilisées dans INTERSECT.

```sql
-- Index recommandés
CREATE INDEX IDX_ClientsEnLigne_ID_Nom
    ON ClientsEnLigne(ClientID, NomClient);

CREATE INDEX IDX_ClientsMagasin_ID_Nom
    ON ClientsMagasin(ClientID, NomClient);

-- Requête optimisée
SELECT ClientID, NomClient
FROM ClientsEnLigne
INTERSECT
SELECT ClientID, NomClient
FROM ClientsMagasin;
```

#### 3. Limiter le nombre de colonnes

N'incluez que les colonnes nécessaires.

```sql
-- ❌ Moins efficace : Trop de colonnes
SELECT *  -- Toutes les colonnes !
FROM ClientsEnLigne
INTERSECT
SELECT *
FROM ClientsMagasin;

-- ✅ Plus efficace : Seulement les colonnes nécessaires
SELECT ClientID
FROM ClientsEnLigne
INTERSECT
SELECT ClientID
FROM ClientsMagasin;
```

### Comparaison de performance : INTERSECT vs alternatives

**Test sur 100,000 lignes :**

| Approche | Temps | Lectures | Utilisation CPU |
|----------|-------|----------|-----------------|
| INTERSECT | 180 ms | 4,500 | 12% |
| INNER JOIN + DISTINCT | 190 ms | 4,800 | 14% |
| EXISTS | 160 ms | 3,200 | 10% |

**Conclusion :**
- `EXISTS` est souvent légèrement plus rapide
- `INTERSECT` offre le meilleur compromis lisibilité/performance
- La différence est minime dans la plupart des cas

## Pièges courants

### Piège 1 : Oublier que toutes les colonnes doivent correspondre

```sql
-- ⚠️ Attention : Compare TOUTES les colonnes
SELECT ClientID, NomClient, DateInscription
FROM ClientsEnLigne
INTERSECT
SELECT ClientID, NomClient, DateInscription
FROM ClientsMagasin;

-- Si DateInscription diffère légèrement, la ligne sera exclue !
```

**Solution :** Ne sélectionner que les colonnes pertinentes

```sql
-- ✅ Compare seulement l'ID
SELECT ClientID
FROM ClientsEnLigne
INTERSECT
SELECT ClientID
FROM ClientsMagasin;
```

### Piège 2 : Confusion avec INNER JOIN

```sql
-- ⚠️ Ces deux requêtes ne sont PAS équivalentes
-- INTERSECT compare toutes les colonnes
SELECT ClientID, NomClient
FROM ClientsEnLigne
INTERSECT
SELECT ClientID, NomClient
FROM ClientsMagasin;

-- INNER JOIN sur ClientID seulement
SELECT DISTINCT C1.ClientID, C1.NomClient
FROM ClientsEnLigne C1
INNER JOIN ClientsMagasin C2 ON C1.ClientID = C2.ClientID;
-- Peut retourner plus de résultats si les noms diffèrent !
```

### Piège 3 : Performance sur de gros volumes

```sql
-- ⚠️ Peut être lent sur de très grandes tables
SELECT *  -- Trop de colonnes à comparer
FROM GrandeTable1  -- 10 millions de lignes
INTERSECT
SELECT *
FROM GrandeTable2;  -- 10 millions de lignes
```

**Solution :** Utiliser EXISTS si plus performant

```sql
-- ✅ Potentiellement plus rapide
SELECT *
FROM GrandeTable1 T1
WHERE EXISTS (
    SELECT 1
    FROM GrandeTable2 T2
    WHERE T2.ID = T1.ID
);
```

### Piège 4 : NULL et comparaisons

```sql
-- Les NULL sont considérés égaux dans INTERSECT
SELECT 'Alice' AS Nom, NULL AS Tel
INTERSECT
SELECT 'Alice', NULL;
-- Résultat : 1 ligne (les NULL correspondent)
```

## INTERSECT vs autres opérateurs d'ensemble

### Vue d'ensemble des opérateurs

| Opérateur | Fonction | Exemple visuel |
|-----------|----------|----------------|
| **UNION** | Combine et élimine doublons | A ∪ B (tout) |
| **UNION ALL** | Combine en gardant doublons | A + B (tout) |
| **INTERSECT** | Garde seulement les communs | A ∩ B (commun) |
| **EXCEPT** | Garde ce qui est dans A mais pas B | A - B (différence) |

### Diagramme de Venn complet

```
         UNION                    INTERSECT
    ┌─────────────┐              ┌─────────┐
    │ A       B   │              │         │
    │  ┌──────────┤              │   ┌─┐   │
    │  │  ∩   │   │              │   │∩│   │
    │  └──────────┤              │   └─┘   │
    │             │              │         │
    └─────────────┘              └─────────┘
     Tout inclus             Seulement commun

         EXCEPT                 UNION ALL
    ┌─────────┐                ┌─────────────┐
    │ A       │                │ A       B   │
    │  ┌──────┤                │  ┌──────────┤
    │  │      │                │  │  ∩   │   │
    │  └──────┤                │  └──────────┤
    │         │                │ + doublons  │
    └─────────┘                └─────────────┘
   Seulement A             Tout + doublons
```

## Résumé

L'opérateur **INTERSECT** retourne uniquement les lignes **communes** à deux ensembles de résultats.

### Syntaxe clé

```sql
SELECT colonnes FROM table1
INTERSECT
SELECT colonnes FROM table2;
```

### Caractéristiques essentielles

✅ **Fonctionnement :**
- Retourne les lignes présentes dans **les deux** résultats
- Compare **toutes les colonnes**
- **Élimine automatiquement les doublons**
- Nécessite un tri pour la comparaison
- Les NULL sont considérés égaux

⚠️ **Points d'attention :**
- Même nombre de colonnes requises
- Types de données compatibles
- Comparaison stricte (toutes les colonnes)
- Coût en performance (tri + comparaison)

### Quand utiliser INTERSECT ?

✅ **Utilisez INTERSECT quand :**
- Vous cherchez les éléments **communs** à deux ensembles
- L'intention d'intersection est claire
- Vous comparez des ensembles complets
- La lisibilité est importante

⚠️ **Alternatives si :**
- Vous avez besoin de plus de flexibilité → **INNER JOIN**
- La performance est critique → **EXISTS**
- Vous voulez seulement vérifier l'existence → **EXISTS**

### Cas d'usage typiques

1. **Marketing multi-canal** : Clients sur plusieurs canaux
2. **Gestion des stocks** : Produits disponibles partout
3. **Audit et conformité** : Validation de cohérence des données
4. **Segmentation** : Clients répondant à plusieurs critères
5. **Analyse comparative** : Éléments communs entre périodes

### Comparaison rapide

| Besoin | Opérateur |
|--------|-----------|
| Tout combiner (sans doublons) | UNION |
| Tout combiner (avec doublons) | UNION ALL |
| **Seulement les communs** | **INTERSECT** |
| Seulement les différences | EXCEPT |

INTERSECT est un outil puissant et expressif pour trouver les éléments communs entre deux ensembles. Son utilisation rend le code SQL plus lisible et l'intention plus claire qu'avec des jointures complexes.

Dans la section suivante, nous verrons **EXCEPT** qui permet de trouver les éléments présents dans un ensemble mais pas dans un autre !
