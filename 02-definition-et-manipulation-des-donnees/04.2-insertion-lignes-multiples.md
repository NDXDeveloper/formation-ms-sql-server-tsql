# 2.4.2 Insertion de lignes multiples

## Introduction

Dans la section précédente, nous avons appris à insérer une seule ligne de données à la fois avec `INSERT INTO ... VALUES`. Mais que se passe-t-il si vous devez ajouter 10, 50 ou même 100 lignes ? Devez-vous écrire autant d'instructions `INSERT` séparées ?

Heureusement, **non** ! T-SQL vous permet d'insérer **plusieurs lignes en une seule instruction**, ce qui est à la fois plus efficace et plus lisible.

---

## Pourquoi insérer plusieurs lignes à la fois ?

### Avantages

1. **Performance améliorée** : Une seule instruction est beaucoup plus rapide que plusieurs instructions individuelles
2. **Code plus concis** : Moins de lignes de code à écrire et à maintenir
3. **Moins de transactions** : Réduit la charge sur le serveur
4. **Meilleure lisibilité** : Plus facile de voir toutes les données insérées en un coup d'œil

### Comparaison

**❌ Méthode inefficace (ancienne approche)** :

```sql
INSERT INTO Produits (ProduitID, Nom, Prix) VALUES (1, 'Ordinateur', 899.99);
INSERT INTO Produits (ProduitID, Nom, Prix) VALUES (2, 'Souris', 25.50);
INSERT INTO Produits (ProduitID, Nom, Prix) VALUES (3, 'Clavier', 45.00);
INSERT INTO Produits (ProduitID, Nom, Prix) VALUES (4, 'Écran', 299.99);
```

**✅ Méthode efficace (insertion multiple)** :

```sql
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Ordinateur', 899.99),
    (2, 'Souris', 25.50),
    (3, 'Clavier', 45.00),
    (4, 'Écran', 299.99);
```

> **Note** : La deuxième approche est **jusqu'à 10 fois plus rapide** pour de grandes quantités de données !

---

## Syntaxe de l'insertion multiple

La syntaxe est une extension naturelle de l'insertion simple :

```sql
INSERT INTO nom_de_table (colonne1, colonne2, colonne3, ...)
VALUES
    (valeur1_ligne1, valeur2_ligne1, valeur3_ligne1, ...),
    (valeur1_ligne2, valeur2_ligne2, valeur3_ligne2, ...),
    (valeur1_ligne3, valeur2_ligne3, valeur3_ligne3, ...),
    ...
    (valeur1_ligneN, valeur2_ligneN, valeur3_ligneN, ...);
```

### Points clés

- **VALUES** apparaît une seule fois au début
- Chaque ligne de données est entre **parenthèses**
- Les lignes sont **séparées par des virgules**
- Le **point-virgule** termine l'instruction (après la dernière ligne)
- La dernière ligne **n'a pas de virgule** après ses parenthèses

---

## Exemple complet et détaillé

Imaginons une table `Employes` pour gérer les employés d'une entreprise :

```sql
CREATE TABLE Employes (
    EmployeID INT PRIMARY KEY,
    Prenom VARCHAR(50),
    Nom VARCHAR(50),
    Departement VARCHAR(50),
    Salaire DECIMAL(10, 2)
);
```

### Insertion de plusieurs employés

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom, Departement, Salaire)
VALUES
    (1, 'Marie', 'Dupont', 'Ventes', 45000.00),
    (2, 'Pierre', 'Martin', 'IT', 52000.00),
    (3, 'Sophie', 'Bernard', 'RH', 48000.00),
    (4, 'Luc', 'Petit', 'Marketing', 43000.00),
    (5, 'Julie', 'Moreau', 'IT', 55000.00);
```

**Que se passe-t-il ?**
- SQL Server insère **5 lignes** d'un seul coup
- Chaque ensemble de parenthèses représente **une ligne complète**
- Toutes les lignes doivent avoir le **même nombre de valeurs** (correspondant aux colonnes spécifiées)

---

## Formatage et lisibilité

Pour améliorer la lisibilité, il est recommandé de **bien formater** votre code :

### ✅ Bonne pratique (formatage aligné)

```sql
INSERT INTO Clients (ClientID, Nom,            Ville,        Pays)
VALUES
    (101, 'Jean Martin',    'Paris',      'France'),
    (102, 'Anna Schmidt',   'Berlin',     'Allemagne'),
    (103, 'Carlos Garcia',  'Madrid',     'Espagne'),
    (104, 'Emma Johnson',   'Londres',    'Royaume-Uni');
```

### ❌ Moins lisible (tout sur une ligne)

```sql
INSERT INTO Clients (ClientID, Nom, Ville, Pays) VALUES (101, 'Jean Martin', 'Paris', 'France'), (102, 'Anna Schmidt', 'Berlin', 'Allemagne'), (103, 'Carlos Garcia', 'Madrid', 'Espagne');
```

> **Conseil** : Utilisez les **sauts de ligne** et l'**indentation** pour rendre votre code plus facile à lire et à maintenir.

---

## Insertion avec valeurs NULL

Vous pouvez bien sûr insérer des valeurs `NULL` dans certaines lignes :

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom, Departement, Salaire)
VALUES
    (6, 'Thomas', 'Dubois', 'Ventes', 41000.00),
    (7, 'Claire', 'Leroy', NULL, 39000.00),           -- Département non défini
    (8, 'Marc', 'Roux', 'IT', NULL),                  -- Salaire non défini
    (9, 'Isabelle', 'Blanc', 'Finance', 50000.00);
```

---

## Insertion avec des types de données variés

### Exemple avec dates et nombres

```sql
INSERT INTO Commandes (CommandeID, ClientID, DateCommande, Montant, Statut)
VALUES
    (5001, 101, '2025-01-15', 1250.50, 'En cours'),
    (5002, 102, '2025-01-16', 890.00, 'Livrée'),
    (5003, 103, '2025-01-16', 2100.75, 'En préparation'),
    (5004, 101, '2025-01-17', 450.25, 'En cours');
```

**Points importants** :
- Les **dates** sont entre guillemets simples : `'2025-01-15'`
- Les **nombres** n'ont pas de guillemets : `1250.50`
- Les **chaînes de caractères** sont entre guillemets simples : `'En cours'`

---

## Gestion des apostrophes dans les chaînes

Si vos données contiennent des apostrophes, n'oubliez pas de les **doubler** :

```sql
INSERT INTO Livres (LivreID, Titre, Auteur)
VALUES
    (1, 'L''Étranger', 'Albert Camus'),
    (2, 'Les Misérables', 'Victor Hugo'),
    (3, 'L''Assommoir', 'Émile Zola');
```

Notez `L''Étranger` et `L''Assommoir` avec deux apostrophes consécutives.

---

## Combien de lignes peut-on insérer à la fois ?

### Limite théorique

SQL Server peut techniquement insérer **jusqu'à 1000 lignes** en une seule instruction `INSERT`. Cependant, il existe des limites pratiques :

- **Lisibilité** : Au-delà de 50-100 lignes, le code devient difficile à lire
- **Taille de la requête** : Il existe des limites de taille pour une instruction SQL
- **Performance** : Pour des insertions massives (milliers de lignes), d'autres techniques sont préférables

### Recommandations

- **10 à 50 lignes** : Idéal pour l'insertion multiple simple
- **50 à 500 lignes** : Acceptable, mais surveillez la lisibilité
- **Plus de 500 lignes** : Envisagez d'autres méthodes (BULK INSERT, INSERT INTO ... SELECT, etc.)

---

## Ordre d'exécution et atomicité

### Transaction atomique

L'insertion multiple est **atomique** : soit **toutes les lignes** sont insérées avec succès, soit **aucune** ne l'est.

```sql
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (10, 'Produit A', 100.00),
    (11, 'Produit B', 200.00),
    (10, 'Produit C', 150.00);  -- ❌ ERREUR : ProduitID = 10 existe déjà
```

**Résultat** : **Aucune** des trois lignes ne sera insérée, même si les deux premières sont valides. C'est le principe du "tout ou rien".

> **Important** : Si une seule ligne viole une contrainte, **toute l'instruction échoue**.

---

## Erreurs courantes et solutions

### 1. Virgule manquante entre les lignes

```sql
-- ❌ INCORRECT : Pas de virgule après la première ligne
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Produit A', 100.00)
    (2, 'Produit B', 200.00);
```

**Erreur** : "Syntaxe incorrecte."

**Solution** : Ajoutez une virgule après chaque ligne sauf la dernière.

```sql
-- ✅ CORRECT
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Produit A', 100.00),
    (2, 'Produit B', 200.00);
```

### 2. Virgule en trop après la dernière ligne

```sql
-- ❌ INCORRECT : Virgule après la dernière ligne
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Produit A', 100.00),
    (2, 'Produit B', 200.00),
    (3, 'Produit C', 150.00),  -- ← Virgule en trop
```

**Erreur** : "Syntaxe incorrecte près de ';'."

**Solution** : Supprimez la virgule après la dernière ligne.

### 3. Nombre de valeurs incohérent entre les lignes

```sql
-- ❌ INCORRECT : Ligne 2 a seulement 2 valeurs au lieu de 3
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Produit A', 100.00),
    (2, 'Produit B'),           -- Manque le prix
    (3, 'Produit C', 150.00);
```

**Erreur** : "Le nombre de valeurs ne correspond pas au nombre de colonnes."

**Solution** : Assurez-vous que **chaque ligne** a le même nombre de valeurs.

### 4. Violation de contrainte sur une seule ligne

```sql
-- ❌ INCORRECT : La ligne 2 viole la contrainte PRIMARY KEY
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (1, 'Produit A', 100.00),
    (1, 'Produit B', 200.00),   -- ← ProduitID dupliqué
    (3, 'Produit C', 150.00);
```

**Résultat** : **Aucune** ligne n'est insérée (tout est annulé).

**Solution** : Vérifiez que toutes les valeurs respectent les contraintes de la table.

## Comparaison de performance

Voici une comparaison approximative du temps d'exécution pour insérer 100 lignes :

| Méthode | Temps approximatif | Gain |
|---------|-------------------|------|
| 100 INSERT individuels | ~500 ms | Base |
| 1 INSERT avec 100 lignes | ~50 ms | **10x plus rapide** |

> **Note** : Les valeurs exactes dépendent de votre environnement, mais le gain est significatif.

## Cas d'usage pratiques

### 1. Initialisation de données de test

```sql
INSERT INTO Categories (CategorieID, Nom, Description)
VALUES
    (1, 'Électronique', 'Appareils électroniques et accessoires'),
    (2, 'Vêtements', 'Vêtements pour hommes et femmes'),
    (3, 'Alimentation', 'Produits alimentaires et boissons'),
    (4, 'Livres', 'Livres et magazines');
```

### 2. Import de données d'une source externe

Lorsque vous importez des données d'un fichier CSV ou Excel, vous pouvez les regrouper par lots :

```sql
INSERT INTO ImportClients (Nom, Email, Telephone)
VALUES
    ('Client 1', 'client1@example.com', '0123456789'),
    ('Client 2', 'client2@example.com', '0987654321'),
    ('Client 3', 'client3@example.com', '0147258369'),
    -- ... jusqu'à 50-100 lignes par lot
```

### 3. Création de données de référence

```sql
INSERT INTO Pays (PaysID, NomPays, CodeISO)
VALUES
    (1, 'France', 'FR'),
    (2, 'Allemagne', 'DE'),
    (3, 'Italie', 'IT'),
    (4, 'Espagne', 'ES'),
    (5, 'Belgique', 'BE');
```

## Vérification après insertion

Après une insertion multiple, vous pouvez vérifier le nombre de lignes insérées :

```sql
-- Insérer les données
INSERT INTO Employes (EmployeID, Prenom, Nom, Departement, Salaire)
VALUES
    (10, 'Alice', 'Durand', 'Ventes', 44000.00),
    (11, 'Bob', 'Leclerc', 'IT', 51000.00),
    (12, 'Carla', 'Morel', 'RH', 47000.00);

-- Vérifier le résultat
SELECT * FROM Employes WHERE EmployeID >= 10;
```

Vous pouvez également utiliser la variable système `@@ROWCOUNT` pour connaître le nombre de lignes affectées :

```sql
INSERT INTO Produits (ProduitID, Nom, Prix)
VALUES
    (20, 'Produit X', 100.00),
    (21, 'Produit Y', 200.00);

SELECT @@ROWCOUNT AS [Lignes insérées];
-- Affichera : 2
```

---

## Bonnes pratiques

### ✅ À faire

1. **Regroupez les insertions** : Préférez une insertion multiple à plusieurs insertions individuelles
2. **Formatez clairement** : Mettez chaque ligne de données sur une ligne distincte
3. **Limitez la taille** : Ne dépassez pas 50-100 lignes par instruction pour la lisibilité
4. **Vérifiez vos données** : Assurez-vous que toutes les lignes respectent les contraintes
5. **Testez sur un petit échantillon** : Avant d'insérer des centaines de lignes, testez avec 2-3 lignes

### ❌ À éviter

1. Ne mettez pas tout sur une seule ligne (illisible)
2. N'oubliez pas les virgules entre les lignes
3. Ne mélangez pas différents nombres de colonnes
4. N'insérez pas plus de 500-1000 lignes en une seule instruction (pour la lisibilité)

---

## Alternatives pour les insertions massives

Si vous devez insérer **des milliers** ou **des millions** de lignes, l'insertion multiple classique n'est pas la meilleure approche. Voici des alternatives :

### 1. BULK INSERT

Pour importer des données depuis un fichier :

```sql
BULK INSERT Employes
FROM 'C:\Data\employes.csv'
WITH (FIELDTERMINATOR = ',', ROWTERMINATOR = '\n');
```

### 2. INSERT INTO ... SELECT

Pour copier des données d'une table à une autre (nous verrons cela en détail dans la section 2.4.3) :

```sql
INSERT INTO EmployesArchive (EmployeID, Prenom, Nom)
SELECT EmployeID, Prenom, Nom
FROM Employes
WHERE Annee = 2024;
```

> **Note** : Ces techniques seront abordées dans les sections suivantes du cours.

## Résumé

L'insertion de lignes multiples est une technique essentielle pour améliorer la performance et la lisibilité de votre code SQL. Voici les points clés :

- **Syntaxe** : Une seule instruction `INSERT INTO` avec plusieurs ensembles de valeurs séparés par des virgules
- **Performance** : Jusqu'à **10 fois plus rapide** que les insertions individuelles
- **Atomicité** : Tout ou rien - si une ligne échoue, aucune n'est insérée
- **Limite pratique** : 10 à 100 lignes pour une bonne lisibilité
- **Formatage** : Alignez vos données pour faciliter la lecture

### Syntaxe à retenir

```sql
INSERT INTO table (col1, col2, col3)
VALUES
    (val1, val2, val3),
    (val1, val2, val3),
    (val1, val2, val3);
```
