# 4.2.2 Sous-requêtes dans le WHERE (vs IN et EXISTS)

## Introduction

Dans la section précédente, nous avons vu les sous-requêtes scalaires qui retournent **une seule valeur**. Maintenant, nous allons explorer les sous-requêtes qui retournent **plusieurs lignes**, et comment les utiliser dans la clause `WHERE` pour filtrer nos résultats.

Ces sous-requêtes sont particulièrement utiles quand vous devez filtrer des données en fonction de valeurs provenant d'une autre table ou d'un autre ensemble de données.

## Contexte : Tables d'exemple

Pour illustrer nos exemples, utilisons trois tables simples :

**Table Clients**
| ClientID | NomClient | Ville |
|----------|-----------|------------|
| 1 | Dupont | Paris |
| 2 | Martin | Lyon |
| 3 | Bernard | Paris |
| 4 | Dubois | Marseille |

**Table Commandes**
| CommandeID | ClientID | DateCommande | Montant |
|------------|----------|--------------|---------|
| 101 | 1 | 2024-01-15 | 150.00 |
| 102 | 1 | 2024-01-20 | 200.00 |
| 103 | 3 | 2024-01-18 | 75.00 |

**Table Produits**
| ProduitID | NomProduit | Prix | EnStock |
|-----------|------------|------|---------|
| 1 | Clavier | 25.00 | 1 |
| 2 | Souris | 15.00 | 1 |
| 3 | Écran | 200.00 | 0 |
| 4 | Webcam | 50.00 | 1 |

## L'opérateur IN avec sous-requêtes

### Concept de base

L'opérateur `IN` permet de vérifier si une valeur appartient à un **ensemble de valeurs**. Quand on combine `IN` avec une sous-requête, cette sous-requête retourne une liste de valeurs (plusieurs lignes, une colonne).

### Syntaxe

```sql
SELECT colonnes
FROM table1
WHERE colonne IN (sous-requête);
```

### Exemple 1 : Trouver les clients qui ont passé des commandes

```sql
SELECT NomClient, Ville
FROM Clients
WHERE ClientID IN (SELECT ClientID FROM Commandes);
```

**Explication :**
- La sous-requête `SELECT ClientID FROM Commandes` retourne la liste : `1, 1, 3`
- SQL Server élimine les doublons automatiquement : `1, 3`
- La requête principale sélectionne les clients dont l'ID est dans cette liste

**Résultat :**
| NomClient | Ville |
|-----------|-------|
| Dupont | Paris |
| Bernard | Paris |

**Équivalent sans sous-requête :**
```sql
-- Cette approche fonctionne pour cet exemple simple
SELECT DISTINCT C.NomClient, C.Ville
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

### Exemple 2 : Trouver les clients qui n'ont PAS passé de commandes

En utilisant `NOT IN`, on peut inverser la logique :

```sql
SELECT NomClient, Ville
FROM Clients
WHERE ClientID NOT IN (SELECT ClientID FROM Commandes);
```

**Résultat :**
| NomClient | Ville |
|-----------|----------|
| Martin | Lyon |
| Dubois | Marseille |

### ⚠️ Attention avec NOT IN et les valeurs NULL

`NOT IN` a un comportement particulier avec les valeurs `NULL` :

```sql
-- ⚠️ Si la sous-requête renvoie au moins un NULL, la condition NOT IN
-- vaut UNKNOWN pour TOUTES les lignes → la requête ne retourne AUCUN résultat !
SELECT NomClient
FROM Clients
WHERE ClientID NOT IN (SELECT ClientID FROM Commandes);
-- Il suffit qu'un seul ClientID de Commandes soit NULL pour que le résultat soit vide.
```

**Règle importante :** Utilisez `NOT EXISTS` plutôt que `NOT IN` quand il y a un risque de valeurs `NULL`.

## L'opérateur EXISTS

### Concept de base

`EXISTS` vérifie simplement si une sous-requête retourne **au moins une ligne**. Il ne regarde pas les valeurs elles-mêmes, seulement si des lignes existent ou non.

- Si la sous-requête retourne au moins une ligne → `EXISTS` est `TRUE`
- Si la sous-requête ne retourne aucune ligne → `EXISTS` est `FALSE`

### Syntaxe

```sql
SELECT colonnes
FROM table1
WHERE EXISTS (sous-requête);
```

### Particularité importante : Les sous-requêtes corrélées

Avec `EXISTS`, on utilise généralement des **sous-requêtes corrélées**, c'est-à-dire que la sous-requête fait référence à la requête principale.

### Exemple 3 : Trouver les clients qui ont passé des commandes (avec EXISTS)

```sql
SELECT NomClient, Ville
FROM Clients C
WHERE EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
);
```

**Explication détaillée :**
1. La requête principale parcourt chaque client dans la table `Clients`
2. Pour chaque client, la sous-requête vérifie s'il existe des commandes pour ce client
3. `CMD.ClientID = C.ClientID` : la sous-requête est **corrélée** (elle référence `C` de la requête externe)
4. Si au moins une commande existe pour ce client, `EXISTS` retourne `TRUE`
5. On utilise `SELECT 1` par convention car `EXISTS` ne regarde que l'existence, pas les valeurs

**Résultat :**
| NomClient | Ville |
|-----------|-------|
| Dupont | Paris |
| Bernard | Paris |

### Exemple 4 : Trouver les clients qui n'ont PAS passé de commandes (avec NOT EXISTS)

```sql
SELECT NomClient, Ville
FROM Clients C
WHERE NOT EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
);
```

**Résultat :**
| NomClient | Ville |
|-----------|----------|
| Martin | Lyon |
| Dubois | Marseille |

### Exemple 5 : Condition plus complexe avec EXISTS

Trouver les clients qui ont passé une commande de plus de 100€ :

```sql
SELECT NomClient, Ville
FROM Clients C
WHERE EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
    AND CMD.Montant > 100
);
```

**Résultat :**
| NomClient | Ville |
|-----------|-------|
| Dupont | Paris |

## Les opérateurs ANY et ALL

`ANY` et `ALL` comparent une valeur à **l'ensemble des valeurs** renvoyées par une sous-requête, en combinaison avec un opérateur de comparaison (`>`, `<`, `>=`, `<=`, `=`, `<>`). `SOME` est un synonyme de `ANY`.

- **`> ALL (sous-requête)`** : vrai si la valeur est supérieure à **toutes** les valeurs → revient à « supérieure au **maximum** ».
- **`> ANY (sous-requête)`** : vrai si la valeur est supérieure à **au moins une** valeur → revient à « supérieure au **minimum** ».

```sql
-- Produits plus chers qu'AU MOINS UNE commande
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > ANY (SELECT Montant FROM Commandes);
-- Montants des commandes : 75, 150, 200 → la condition revient à « Prix > 75 »
```

**Résultat :**
| NomProduit | Prix |
|------------|------|
| Écran | 200.00 |

```sql
-- Produits plus chers que TOUTES les commandes (> au plus grand montant, 200)
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > ALL (SELECT Montant FROM Commandes);
-- Aucun produit ne dépasse 200 → résultat vide
```

### Équivalences utiles

| Écriture | Équivalent |
|----------|------------|
| `x = ANY (sous-requête)` | `x IN (sous-requête)` |
| `x <> ALL (sous-requête)` | `x NOT IN (sous-requête)` |

> ⚠️ Comme `IN`/`NOT IN`, `ANY`/`ALL` sont sensibles aux `NULL` (un `NULL` dans la sous-requête peut vider le résultat de `<> ALL`). En pratique, on réserve `ANY`/`ALL` aux comparaisons `>`/`<` (test vis-à-vis du min/max) ; pour l'appartenance, `IN`/`EXISTS` sont plus lisibles.

## IN vs EXISTS : Quelle est la différence ?

### Comparaison conceptuelle

| Aspect | IN | EXISTS |
|--------|-----|--------|
| **Logique** | Vérifie si une valeur est dans une liste | Vérifie si au moins une ligne existe |
| **Sous-requête** | Retourne une colonne de valeurs | Retourne TRUE/FALSE (existence) |
| **Corrélation** | Généralement non corrélée | Généralement corrélée |
| **NULL** | Problèmes avec `NOT IN` et NULL | Gère bien les NULL |
| **Performance** | Peut être moins performant | Souvent plus performant (s'arrête dès la première ligne trouvée) |

### Exemple comparatif : Même résultat, deux approches

**Avec IN :**
```sql
SELECT NomClient
FROM Clients
WHERE ClientID IN (SELECT ClientID FROM Commandes WHERE Montant > 100);
```

**Avec EXISTS :**
```sql
SELECT NomClient
FROM Clients C
WHERE EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
    AND CMD.Montant > 100
);
```

Les deux requêtes donnent le même résultat, mais :
- `IN` récupère d'abord toutes les valeurs de `ClientID` correspondantes
- `EXISTS` s'arrête dès qu'il trouve une correspondance (plus efficace)

### Quand utiliser IN ?

✅ **Utilisez IN quand :**
- La sous-requête retourne une petite liste de valeurs
- Vous travaillez avec des valeurs statiques ou simples
- La sous-requête n'est pas corrélée
- Il n'y a pas de risque de valeurs NULL (ou utilisez `WHERE ... IS NOT NULL`)

**Exemple typique avec IN :**
```sql
-- Liste fixe et courte
SELECT NomProduit
FROM Produits
WHERE ProduitID IN (1, 2, 4);

-- Ou sous-requête simple
SELECT NomClient
FROM Clients
WHERE Ville IN (SELECT DISTINCT Ville FROM Commandes);
```

### Quand utiliser EXISTS ?

✅ **Utilisez EXISTS quand :**
- Vous avez besoin de conditions complexes dans la sous-requête
- Vous utilisez `NOT EXISTS` (pour éviter les problèmes de NULL)
- La performance est critique (EXISTS s'arrête à la première correspondance)
- La sous-requête est corrélée

**Exemple typique avec EXISTS :**
```sql
-- Condition complexe
SELECT NomClient
FROM Clients C
WHERE EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
    AND CMD.DateCommande >= '2024-01-01'
    AND CMD.Montant > 100
);
```

## Exemples avancés

### Exemple 6 : Combinaison de IN et EXISTS

Trouver les clients de Paris ou Lyon qui ont passé au moins une commande :

```sql
SELECT NomClient, Ville
FROM Clients C
WHERE Ville IN ('Paris', 'Lyon')
AND EXISTS (
    SELECT 1
    FROM Commandes CMD
    WHERE CMD.ClientID = C.ClientID
);
```

**Résultat :**
| NomClient | Ville |
|-----------|-------|
| Dupont | Paris |
| Bernard | Paris |

### Exemple 7 : NOT EXISTS pour trouver les orphelins

Trouver les produits qui n'ont jamais été commandés (si on avait une table LignesCommandes) :

```sql
-- Hypothèse : une table LignesCommandes existe
SELECT NomProduit, Prix
FROM Produits P
WHERE NOT EXISTS (
    SELECT 1
    FROM LignesCommandes LC
    WHERE LC.ProduitID = P.ProduitID
);
```

### Exemple 8 : IN avec sous-requête et agrégation

Trouver les clients dont le montant total des commandes dépasse 200€ :

```sql
SELECT NomClient, Ville
FROM Clients
WHERE ClientID IN (
    SELECT ClientID
    FROM Commandes
    GROUP BY ClientID
    HAVING SUM(Montant) > 200
);
```

**Explication :**
- La sous-requête regroupe les commandes par client
- `HAVING SUM(Montant) > 200` filtre les clients ayant plus de 200€ de commandes
- `IN` sélectionne les clients correspondants

**Résultat :**
| NomClient | Ville |
|-----------|-------|
| Dupont | Paris |

## Points importants à retenir

### ✅ Bonnes pratiques

1. **Préférez EXISTS à IN** pour les sous-requêtes corrélées complexes
2. **Utilisez NOT EXISTS plutôt que NOT IN** pour éviter les problèmes avec NULL
3. **IN est plus lisible** pour des listes courtes ou des valeurs statiques
4. **EXISTS est plus performant** quand vous avez besoin de vérifier l'existence sans traiter toutes les lignes

### ⚠️ Pièges à éviter

1. **NOT IN avec NULL :**
   ```sql
   -- ❌ Peut retourner 0 ligne si la sous-requête contient NULL
   WHERE ClientID NOT IN (SELECT ClientID FROM TableAvecNull)

   -- ✅ Solution
   WHERE ClientID NOT IN (SELECT ClientID FROM TableAvecNull WHERE ClientID IS NOT NULL)
   -- ou mieux encore
   WHERE NOT EXISTS (SELECT 1 FROM TableAvecNull WHERE ...)
   ```

2. **Sous-requêtes non corrélées inutiles avec EXISTS :**
   ```sql
   -- ❌ Moins efficace
   WHERE EXISTS (SELECT ClientID FROM Commandes)

   -- ✅ Utiliser plutôt une jointure ou IN
   ```

3. **Performances avec de grandes tables :**
   - Si la sous-requête retourne beaucoup de lignes, `IN` peut être lent
   - `EXISTS` est optimisé pour s'arrêter dès qu'une correspondance est trouvée

## Résumé

Les sous-requêtes dans le `WHERE` avec `IN` et `EXISTS` sont des outils puissants pour filtrer vos données en fonction de critères provenant d'autres tables :

- **IN** : Idéal pour vérifier l'appartenance à une liste de valeurs
- **EXISTS** : Optimisé pour vérifier simplement l'existence de lignes correspondantes
- **NOT EXISTS** : Le choix le plus sûr pour les exclusions (évite les problèmes de NULL)

En pratique, `EXISTS` est souvent préféré pour sa performance et sa robustesse, mais `IN` reste très utile pour des cas simples et des listes courtes de valeurs.
