# 5.2.1 Blocs BEGIN ... END

## Introduction

Lorsque vous écrivez du code T-SQL, vous aurez souvent besoin de **regrouper plusieurs instructions** pour qu'elles soient traitées comme une seule unité logique. C'est exactement le rôle des **blocs BEGIN ... END**.

Pensez à BEGIN ... END comme aux **accolades { }** dans des langages comme C#, Java ou JavaScript. Ils permettent de délimiter un bloc de code qui doit être exécuté ensemble.

Dans cette section, nous allons découvrir comment et pourquoi utiliser ces blocs dans vos scripts T-SQL.

---

## 1. Qu'est-ce qu'un bloc BEGIN ... END ?

### Définition

Un **bloc BEGIN ... END** est une structure qui permet de **regrouper plusieurs instructions T-SQL** en une seule unité logique.

### Syntaxe de base

```sql
BEGIN
    Instruction1;
    Instruction2;
    Instruction3;
    -- ... autant d'instructions que nécessaire
END
```

### Analogie

Imaginez que vous donnez des instructions à quelqu'un :

**Sans regroupement :**
- "Va au magasin"
- "Achète du pain"
- "Achète du lait"

**Avec regroupement :**
- "Commence"
  - "Va au magasin"
  - "Achète du pain"
  - "Achète du lait"
- "Fin"

Le regroupement indique clairement que toutes ces actions font partie d'une même tâche.

---

## 2. Pourquoi utiliser BEGIN ... END ?

### Cas 1 : Grouper plusieurs instructions

Sans BEGIN ... END, certaines structures de contrôle (comme IF, WHILE) n'exécutent qu'**une seule instruction**.

#### Exemple SANS BEGIN ... END (incorrect)

```sql
DECLARE @Age INT = 25;

IF @Age >= 18
    PRINT 'Vous êtes majeur';
    PRINT 'Vous pouvez voter';  -- Cette ligne s'exécute TOUJOURS !
```

**Problème :** Seule la première instruction (`PRINT 'Vous êtes majeur'`) est liée au IF. La deuxième s'exécute **toujours**, même si @Age < 18.

#### Exemple AVEC BEGIN ... END (correct)

```sql
DECLARE @Age INT = 25;

IF @Age >= 18
BEGIN
    PRINT 'Vous êtes majeur';
    PRINT 'Vous pouvez voter';
END
```

**Solution :** BEGIN ... END regroupe les deux instructions. Elles s'exécutent toutes les deux uniquement si la condition est vraie.

### Cas 2 : Améliorer la lisibilité

Même pour une seule instruction, BEGIN ... END peut rendre le code plus clair et cohérent.

```sql
IF @Solde > 0
BEGIN
    PRINT 'Compte créditeur';
END
ELSE
BEGIN
    PRINT 'Compte débiteur';
END
```

### Cas 3 : Obligatoire dans certaines structures

BEGIN ... END est **obligatoire** dans :
- Les procédures stockées
- Les fonctions
- Les triggers
- Les blocs TRY ... CATCH

---

## 3. Utilisation de base

### Exemple simple

```sql
DECLARE @Message VARCHAR(100);

BEGIN
    SET @Message = 'Début du traitement';
    PRINT @Message;
    PRINT 'Traitement en cours...';
    SET @Message = 'Fin du traitement';
    PRINT @Message;
END
```

**Résultat :**
```
Début du traitement
Traitement en cours...
Fin du traitement
```

### Blocs imbriqués

Vous pouvez **imbriquer** des blocs BEGIN ... END les uns dans les autres :

```sql
DECLARE @Score INT = 85;

BEGIN
    PRINT 'Début de l''évaluation';

    IF @Score >= 50
    BEGIN
        PRINT 'Vous avez réussi !';

        IF @Score >= 80
        BEGIN
            PRINT 'Mention : Très bien';
        END
    END

    PRINT 'Fin de l''évaluation';
END
```

**Résultat :**
```
Début de l'évaluation
Vous avez réussi !
Mention : Très bien
Fin de l'évaluation
```

## 4. BEGIN ... END avec IF ... ELSE

### Structure IF simple

```sql
DECLARE @Temperature INT = 22;

IF @Temperature > 25
BEGIN
    PRINT 'Il fait chaud';
    PRINT 'Pensez à vous hydrater';
END
```

### Structure IF ... ELSE

```sql
DECLARE @Stock INT = 5;

IF @Stock > 0
BEGIN
    PRINT 'Produit disponible';
    PRINT 'Stock actuel : ' + CAST(@Stock AS VARCHAR);
END
ELSE
BEGIN
    PRINT 'Produit en rupture de stock';
    PRINT 'Veuillez commander';
END
```

### Structure IF ... ELSE IF ... ELSE complète

```sql
DECLARE @Note INT = 75;

IF @Note >= 90
BEGIN
    PRINT 'Excellent !';
    PRINT 'Continuez ainsi';
END
ELSE IF @Note >= 70
BEGIN
    PRINT 'Bien';
    PRINT 'Bon travail';
END
ELSE IF @Note >= 50
BEGIN
    PRINT 'Passable';
    PRINT 'Vous pouvez mieux faire';
END
ELSE
BEGIN
    PRINT 'Insuffisant';
    PRINT 'Redoublez d''efforts';
END
```

## 5. BEGIN ... END avec WHILE

### Exemple simple

```sql
DECLARE @Compteur INT = 1;

WHILE @Compteur <= 5
BEGIN
    PRINT 'Itération numéro ' + CAST(@Compteur AS VARCHAR);
    SET @Compteur = @Compteur + 1;
END

PRINT 'Boucle terminée';
```

**Résultat :**
```
Itération numéro 1
Itération numéro 2
Itération numéro 3
Itération numéro 4
Itération numéro 5
Boucle terminée
```

### Exemple avec plusieurs instructions

```sql
DECLARE @Compteur INT = 1;
DECLARE @Total INT = 0;

WHILE @Compteur <= 10
BEGIN
    -- Ajouter au total
    SET @Total = @Total + @Compteur;

    -- Afficher l'état actuel
    PRINT 'Compteur : ' + CAST(@Compteur AS VARCHAR) +
          ', Total : ' + CAST(@Total AS VARCHAR);

    -- Incrémenter
    SET @Compteur = @Compteur + 1;
END

PRINT 'Somme finale : ' + CAST(@Total AS VARCHAR);
```

## 6. BEGIN ... END dans les procédures stockées

### Structure obligatoire

Dans les procédures stockées, BEGIN ... END est **obligatoire** pour délimiter le corps de la procédure.

```sql
CREATE PROCEDURE AfficherMessage
    @Prenom VARCHAR(50)
AS
BEGIN
    -- Tout le code de la procédure va ici
    PRINT 'Bonjour ' + @Prenom;
    PRINT 'Bienvenue dans notre système';
END
```

### Procédure avec logique conditionnelle

```sql
CREATE PROCEDURE VerifierStock
    @ProduitID INT
AS
BEGIN
    DECLARE @Stock INT;

    -- Récupérer le stock
    SELECT @Stock = QuantiteEnStock
    FROM Produits
    WHERE ProduitID = @ProduitID;

    -- Vérifier et afficher
    IF @Stock IS NULL
    BEGIN
        PRINT 'Produit introuvable';
    END
    ELSE IF @Stock = 0
    BEGIN
        PRINT 'Rupture de stock';
        PRINT 'Commande nécessaire';
    END
    ELSE IF @Stock < 10
    BEGIN
        PRINT 'Stock faible : ' + CAST(@Stock AS VARCHAR) + ' unités';
        PRINT 'Recommandez bientôt';
    END
    ELSE
    BEGIN
        PRINT 'Stock suffisant : ' + CAST(@Stock AS VARCHAR) + ' unités';
    END
END
```

## 7. Indentation et lisibilité

### Importance de l'indentation

Une bonne indentation rend votre code **beaucoup plus lisible**. Chaque niveau de BEGIN ... END devrait être indenté.

#### Mauvaise indentation (difficile à lire)

```sql
DECLARE @X INT = 10;
IF @X > 5
BEGIN
PRINT 'X est grand';
IF @X > 8
BEGIN
PRINT 'X est très grand';
END
END
```

#### Bonne indentation (claire et lisible)

```sql
DECLARE @X INT = 10;

IF @X > 5
BEGIN
    PRINT 'X est grand';

    IF @X > 8
    BEGIN
        PRINT 'X est très grand';
    END
END
```

### Conventions recommandées

```sql
-- BEGIN sur la même ligne que la structure de contrôle
IF condition BEGIN
    -- Instructions
END

-- OU BEGIN sur une nouvelle ligne (plus lisible)
IF condition
BEGIN
    -- Instructions
END

-- Pour les procédures, BEGIN sur une nouvelle ligne
CREATE PROCEDURE MaProc
AS
BEGIN
    -- Instructions
END
```

## 8. Exemples pratiques complets

### Exemple 1 : Calcul de remise

```sql
DECLARE @MontantAchat DECIMAL(10,2) = 150.00;
DECLARE @Remise DECIMAL(5,2);
DECLARE @MontantFinal DECIMAL(10,2);

-- Calculer la remise selon le montant
IF @MontantAchat >= 200
BEGIN
    SET @Remise = 20.00;
    PRINT 'Remise de 20% appliquée';
END
ELSE IF @MontantAchat >= 100
BEGIN
    SET @Remise = 10.00;
    PRINT 'Remise de 10% appliquée';
END
ELSE
BEGIN
    SET @Remise = 0.00;
    PRINT 'Aucune remise';
END

-- Calculer le montant final
SET @MontantFinal = @MontantAchat * (1 - @Remise / 100);

-- Afficher les résultats
PRINT 'Montant initial : ' + CAST(@MontantAchat AS VARCHAR);
PRINT 'Remise : ' + CAST(@Remise AS VARCHAR) + '%';
PRINT 'Montant final : ' + CAST(@MontantFinal AS VARCHAR);
```

**Résultat :**
```
Remise de 10% appliquée
Montant initial : 150.00
Remise : 10.00%
Montant final : 135.00
```

### Exemple 2 : Validation de données

```sql
CREATE PROCEDURE AjouterEmploye
    @Prenom VARCHAR(50),
    @Nom VARCHAR(50),
    @Email VARCHAR(100),
    @Salaire DECIMAL(10,2)
AS
BEGIN
    -- Validation des données
    IF @Prenom IS NULL OR @Prenom = ''
    BEGIN
        PRINT 'Erreur : Le prénom est obligatoire';
        RETURN;
    END

    IF @Nom IS NULL OR @Nom = ''
    BEGIN
        PRINT 'Erreur : Le nom est obligatoire';
        RETURN;
    END

    IF @Email IS NULL OR @Email NOT LIKE '%@%'
    BEGIN
        PRINT 'Erreur : Email invalide';
        RETURN;
    END

    IF @Salaire < 0
    BEGIN
        PRINT 'Erreur : Le salaire ne peut pas être négatif';
        RETURN;
    END

    -- Si tout est valide, insérer
    BEGIN
        INSERT INTO Employes (Prenom, Nom, Email, Salaire)
        VALUES (@Prenom, @Nom, @Email, @Salaire);

        PRINT 'Employé ajouté avec succès';
        PRINT 'ID : ' + CAST(@@IDENTITY AS VARCHAR);
    END
END
```

### Exemple 3 : Traitement par lots

```sql
DECLARE @Compteur INT = 1;
DECLARE @Total INT = 0;
DECLARE @BatchSize INT = 100;

WHILE @Compteur <= 1000
BEGIN
    -- Traiter un lot de données
    UPDATE Commandes
    SET Statut = 'Traité'
    WHERE CommandeID BETWEEN @Compteur AND (@Compteur + @BatchSize - 1)
    AND Statut = 'En attente';

    -- Enregistrer le nombre de lignes traitées
    SET @Total = @Total + @@ROWCOUNT;

    -- Afficher la progression
    IF @Compteur % 200 = 1
    BEGIN
        PRINT 'Progression : ' + CAST(@Compteur AS VARCHAR) + ' / 1000';
        PRINT 'Total traité : ' + CAST(@Total AS VARCHAR);
    END

    -- Passer au lot suivant
    SET @Compteur = @Compteur + @BatchSize;
END

PRINT 'Traitement terminé : ' + CAST(@Total AS VARCHAR) + ' commandes traitées';
```

## 9. Erreurs courantes à éviter

### Erreur 1 : Oublier BEGIN ... END dans un IF avec plusieurs instructions

**❌ Incorrect :**
```sql
IF @Condition = 1
    PRINT 'Ligne 1';
    PRINT 'Ligne 2';  -- S'exécute toujours !
```

**✅ Correct :**
```sql
IF @Condition = 1
BEGIN
    PRINT 'Ligne 1';
    PRINT 'Ligne 2';
END
```

### Erreur 2 : BEGIN ... END mal imbriqués

**❌ Incorrect :**
```sql
BEGIN
    IF @X > 0
    BEGIN
        PRINT 'Positif';
    -- END manquant !
END
```

**✅ Correct :**
```sql
BEGIN
    IF @X > 0
    BEGIN
        PRINT 'Positif';
    END
END
```

### Erreur 3 : Point-virgule après END

**⚠️ Attention :**
```sql
BEGIN
    PRINT 'Message';
END;  -- Le point-virgule ici est optionnel mais peut causer des problèmes
GO
```

En général, vous n'avez **pas besoin** de point-virgule après END, sauf dans certains contextes spécifiques.

## 10. BEGIN ... END vs autres langages

Si vous connaissez d'autres langages de programmation, voici les équivalences :

| T-SQL | C# / Java / JavaScript | Python |
|-------|------------------------|--------|
| `BEGIN` | `{` | `:` (indentation) |
| `END` | `}` | Fin d'indentation |

**Exemple C# :**
```csharp
if (age >= 18)
{
    Console.WriteLine("Majeur");
    Console.WriteLine("Peut voter");
}
```

**Équivalent T-SQL :**
```sql
IF @Age >= 18
BEGIN
    PRINT 'Majeur';
    PRINT 'Peut voter';
END
```

## 11. Bonnes pratiques

### ✅ À FAIRE

1. **Toujours utiliser BEGIN ... END** avec IF, ELSE, WHILE, même pour une seule instruction (cohérence)
2. **Indenter correctement** votre code (2 ou 4 espaces par niveau)
3. **Aligner verticalement** les BEGIN et END correspondants
4. **Commenter** les blocs complexes pour expliquer leur rôle
5. **Utiliser des noms de variables explicites** dans vos blocs

### ❌ À ÉVITER

1. **Ne pas oublier BEGIN ... END** quand vous avez plusieurs instructions
2. **Ne pas négliger l'indentation** (code illisible)
3. **Ne pas imbriquer trop profondément** (refactoriser si > 3-4 niveaux)
4. **Ne pas mélanger les styles d'indentation** dans le même script

## 12. Quand BEGIN ... END n'est PAS nécessaire

### Instructions uniques simples

Pour une instruction unique et simple, BEGIN ... END peut être omis :

```sql
-- Acceptable sans BEGIN ... END
IF @X > 0
    PRINT 'Positif';
```

Mais pour la cohérence, beaucoup de développeurs préfèrent **toujours** utiliser BEGIN ... END :

```sql
-- Recommandé pour la cohérence
IF @X > 0
BEGIN
    PRINT 'Positif';
END
```

### Au niveau principal du script

Vous n'avez pas besoin d'envelopper tout votre script dans BEGIN ... END :

**❌ Pas nécessaire :**
```sql
BEGIN
    DECLARE @X INT = 10;
    SELECT @X;
END
```

**✅ Suffisant :**
```sql
DECLARE @X INT = 10;
SELECT @X;
```

## Résumé

- **BEGIN ... END** permet de regrouper plusieurs instructions en un seul bloc logique
- Essentiel avec les structures de contrôle (**IF**, **WHILE**) quand vous avez plusieurs instructions
- **Obligatoire** dans les procédures stockées, fonctions et triggers
- Les blocs peuvent être **imbriqués** les uns dans les autres
- Une **bonne indentation** est cruciale pour la lisibilité
- BEGIN ... END est l'équivalent des **accolades { }** dans d'autres langages
- Même pour une instruction unique, utiliser BEGIN ... END améliore la **cohérence** du code

Maintenant que vous maîtrisez les blocs BEGIN ... END, vous êtes prêt à découvrir les structures de contrôle plus avancées comme les conditions IF ... ELSE et les boucles WHILE dans les sections suivantes.
