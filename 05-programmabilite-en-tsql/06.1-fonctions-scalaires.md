# 5.6.1 Fonctions Scalaires (Retournent une seule valeur)

## Introduction

Les **fonctions scalaires** sont des fonctions personnalisées que vous pouvez créer en T-SQL pour effectuer des calculs ou des transformations et qui **retournent une seule valeur**. Contrairement aux procédures stockées qui peuvent exécuter plusieurs actions, une fonction scalaire se concentre sur un objectif simple : prendre des paramètres en entrée et retourner un résultat unique.

**Analogie simple :** Imaginez une fonction scalaire comme une calculatrice spécialisée. Vous lui donnez des nombres (ou d'autres informations), elle effectue un calcul précis, et vous renvoie un seul résultat.

---

## Qu'est-ce qu'une fonction scalaire ?

Une fonction scalaire (ou UDF scalaire - User Defined Function) est une fonction qui :
- Accepte **zéro ou plusieurs paramètres** en entrée
- Effectue un traitement (calcul, transformation de texte, logique conditionnelle, etc.)
- **Retourne une seule valeur** d'un type de données spécifique (INT, VARCHAR, DATE, etc.)
- Peut être utilisée directement dans des requêtes SELECT, WHERE, ou toute autre clause SQL

---

## Syntaxe de base

Voici la structure générale pour créer une fonction scalaire :

```sql
CREATE FUNCTION nom_schema.nom_fonction
(
    @parametre1 type_donnees,
    @parametre2 type_donnees,
    ...
)
RETURNS type_donnees_retour
AS
BEGIN
    -- Déclaration de la variable de retour
    DECLARE @resultat type_donnees_retour;

    -- Logique de traitement
    -- Calculs, transformations, conditions...
    SET @resultat = ...;

    -- Retour de la valeur
    RETURN @resultat;
END;
```

**Éléments clés :**
- `CREATE FUNCTION` : Mot-clé pour créer la fonction
- `nom_schema.nom_fonction` : Nom complet de la fonction (ex: `dbo.CalculerTVA`)
- `(@parametre1 type_donnees, ...)` : Liste des paramètres d'entrée (optionnels)
- `RETURNS type_donnees_retour` : Type de données que la fonction va retourner
- `BEGIN ... END` : Bloc contenant la logique de la fonction
- `RETURN @resultat` : Instruction qui retourne la valeur calculée

---

## Exemple 1 : Fonction simple sans paramètre

Créons une fonction qui retourne toujours la date du jour :

```sql
CREATE FUNCTION dbo.ObtenirDateJour()
RETURNS DATE
AS
BEGIN
    RETURN CAST(GETDATE() AS DATE);
END;
```

**Utilisation :**
```sql
-- Dans une requête SELECT
SELECT dbo.ObtenirDateJour() AS DateDuJour;

-- Résultat : 2025-11-18 (la date actuelle)
```

**Explication :**
- Cette fonction ne prend aucun paramètre (parenthèses vides)
- Elle retourne un type `DATE`
- Elle utilise `GETDATE()` pour obtenir la date et l'heure actuelle, puis `CAST` pour ne garder que la partie date
- Notez que pour appeler une fonction, vous devez toujours préfixer son nom avec le schéma (ici `dbo.`)

---

## Exemple 2 : Fonction avec un paramètre

Créons une fonction qui calcule la TVA sur un montant donné :

```sql
CREATE FUNCTION dbo.CalculerTVA
(
    @montantHT DECIMAL(10,2)
)
RETURNS DECIMAL(10,2)
AS
BEGIN
    DECLARE @tva DECIMAL(10,2);

    -- Calcul de la TVA à 20%
    SET @tva = @montantHT * 0.20;

    RETURN @tva;
END;
```

**Utilisation :**
```sql
-- Calculer la TVA sur 100€
SELECT dbo.CalculerTVA(100.00) AS MontantTVA;
-- Résultat : 20.00

-- Utiliser la fonction dans une requête sur une table
SELECT
    NomProduit,
    PrixHT,
    dbo.CalculerTVA(PrixHT) AS TVA,
    PrixHT + dbo.CalculerTVA(PrixHT) AS PrixTTC
FROM Produits;
```

**Explication :**
- La fonction accepte un paramètre `@montantHT` de type `DECIMAL(10,2)`
- Elle déclare une variable locale `@tva` pour stocker le résultat du calcul
- Elle calcule 20% du montant HT
- Elle retourne ce montant calculé
- On peut utiliser cette fonction directement dans des calculs et des requêtes

---

## Exemple 3 : Fonction avec plusieurs paramètres

Créons une fonction plus flexible qui permet de spécifier le taux de TVA :

```sql
CREATE FUNCTION dbo.CalculerTVAAvecTaux
(
    @montantHT DECIMAL(10,2),
    @tauxTVA DECIMAL(5,2)  -- Taux en pourcentage (ex: 20.00 pour 20%)
)
RETURNS DECIMAL(10,2)
AS
BEGIN
    DECLARE @tva DECIMAL(10,2);

    -- Calcul de la TVA avec le taux fourni
    SET @tva = @montantHT * (@tauxTVA / 100.0);

    RETURN @tva;
END;
```

**Utilisation :**
```sql
-- TVA à 20%
SELECT dbo.CalculerTVAAvecTaux(100.00, 20.00) AS TVA_20;
-- Résultat : 20.00

-- TVA à 5.5% (taux réduit)
SELECT dbo.CalculerTVAAvecTaux(100.00, 5.5) AS TVA_5_5;
-- Résultat : 5.50

-- Utiliser dans une requête avec différents taux
SELECT
    NomProduit,
    PrixHT,
    TauxTVA,
    dbo.CalculerTVAAvecTaux(PrixHT, TauxTVA) AS MontantTVA
FROM Produits;
```

## Exemple 4 : Fonction avec logique conditionnelle

Créons une fonction qui attribue une catégorie selon l'âge d'une personne :

```sql
CREATE FUNCTION dbo.ObtenirCategorieAge
(
    @age INT
)
RETURNS VARCHAR(20)
AS
BEGIN
    DECLARE @categorie VARCHAR(20);

    -- Logique conditionnelle
    IF @age < 18
        SET @categorie = 'Mineur';
    ELSE IF @age >= 18 AND @age < 65
        SET @categorie = 'Adulte';
    ELSE
        SET @categorie = 'Senior';

    RETURN @categorie;
END;
```

**Utilisation :**
```sql
-- Test avec différents âges
SELECT dbo.ObtenirCategorieAge(15) AS Categorie;  -- Résultat : 'Mineur'
SELECT dbo.ObtenirCategorieAge(30) AS Categorie;  -- Résultat : 'Adulte'
SELECT dbo.ObtenirCategorieAge(70) AS Categorie;  -- Résultat : 'Senior'

-- Utiliser sur une table de clients
SELECT
    NomClient,
    Age,
    dbo.ObtenirCategorieAge(Age) AS Categorie
FROM Clients;
```

## Exemple 5 : Fonction pour manipuler du texte

Créons une fonction qui formate un nom complet (Nom + Prénom) :

```sql
CREATE FUNCTION dbo.FormaterNomComplet
(
    @prenom VARCHAR(50),
    @nom VARCHAR(50)
)
RETURNS VARCHAR(101)  -- 50 + 50 + 1 (espace)
AS
BEGIN
    DECLARE @nomComplet VARCHAR(101);

    -- Mettre la première lettre en majuscule et le reste en minuscule
    -- puis combiner prénom et nom
    SET @nomComplet = UPPER(LEFT(@prenom, 1)) + LOWER(SUBSTRING(@prenom, 2, LEN(@prenom)))
                    + ' '
                    + UPPER(LEFT(@nom, 1)) + LOWER(SUBSTRING(@nom, 2, LEN(@nom)));

    RETURN @nomComplet;
END;
```

**Utilisation :**
```sql
-- Test
SELECT dbo.FormaterNomComplet('JEAN', 'DUPONT') AS NomFormate;
-- Résultat : 'Jean Dupont'

SELECT dbo.FormaterNomComplet('marie', 'MARTIN') AS NomFormate;
-- Résultat : 'Marie Martin'

-- Sur une table
SELECT
    ClientID,
    dbo.FormaterNomComplet(Prenom, Nom) AS NomComplet
FROM Clients;
```

## Exemple 6 : Fonction avec calcul de date

Créons une fonction qui calcule le nombre de jours ouvrés entre deux dates (version simplifiée) :

```sql
CREATE FUNCTION dbo.CalculerJoursOuvres
(
    @dateDebut DATE,
    @dateFin DATE
)
RETURNS INT
AS
BEGIN
    DECLARE @joursOuvres INT;
    DECLARE @totalJours INT;
    DECLARE @weekends INT;

    -- Calculer le nombre total de jours
    SET @totalJours = DATEDIFF(DAY, @dateDebut, @dateFin) + 1;

    -- Estimation simple : environ 2/7 des jours sont des weekends
    -- (Cette formule est simplifiée pour l'exemple)
    SET @weekends = (@totalJours * 2) / 7;

    -- Jours ouvrés = Total - Weekends
    SET @joursOuvres = @totalJours - @weekends;

    RETURN @joursOuvres;
END;
```

**Utilisation :**
```sql
-- Calculer les jours ouvrés entre deux dates
SELECT dbo.CalculerJoursOuvres('2025-11-01', '2025-11-30') AS JoursOuvres;

-- Sur une table de projets
SELECT
    NomProjet,
    DateDebut,
    DateFin,
    dbo.CalculerJoursOuvres(DateDebut, DateFin) AS DureeEnJoursOuvres
FROM Projets;
```

## Avantages des fonctions scalaires

1. **Réutilisabilité** : Écrivez la logique une fois, utilisez-la partout dans vos requêtes
2. **Lisibilité** : Le code devient plus clair et expressif
   ```sql
   -- Au lieu de :
   SELECT PrixHT * 1.20 FROM Produits;

   -- Vous pouvez écrire :
   SELECT dbo.CalculerPrixTTC(PrixHT) FROM Produits;
   ```
3. **Maintenance** : Si la logique change (ex: le taux de TVA), vous ne modifiez qu'un seul endroit
4. **Encapsulation** : Cacher la complexité derrière une interface simple

---

## Limitations importantes à connaître

### 1. Impact sur les performances

Les fonctions scalaires peuvent **ralentir considérablement** vos requêtes, surtout quand elles sont appelées sur de nombreuses lignes. Pourquoi ?

- Elles sont exécutées **ligne par ligne** (pas d'optimisation par ensemble)
- Elles empêchent certaines optimisations du moteur SQL Server
- Le plan d'exécution ne peut pas estimer correctement le coût

**Exemple de problème :**
```sql
-- Cette requête peut être TRÈS lente sur une grosse table
SELECT
    ClientID,
    dbo.CalculerRemise(Montant) AS Remise  -- Appelée pour CHAQUE ligne !
FROM Commandes
WHERE Montant > 1000;
```

**Conseil :** Pour des calculs simples, préférez les expressions T-SQL directes plutôt qu'une fonction.

> 💡 **Nuance (SQL Server 2019+)** : depuis SQL Server 2019 (niveau de compatibilité 150+), le **Scalar UDF Inlining** réécrit automatiquement de nombreuses fonctions scalaires en expressions intégrées, ce qui supprime une grande partie de cette pénalité — y compris pour des fonctions qui lisent des tables. Ce mécanisme, ses conditions et ses limites sont détaillés en [5.6.4](/05-programmabilite-en-tsql/06.4-limitations-performance-udf.md). Le conseil reste valable (concevoir avec des expressions/JOIN/fonctions inline), car l'inlining ne couvre pas tous les cas ni les versions ≤ 2017.

### 2. Restrictions dans les fonctions

Les fonctions scalaires **ne peuvent pas** :
- Modifier des données (pas d'INSERT, UPDATE, DELETE sur des tables permanentes)
- Créer ou modifier des objets de base de données
- Utiliser des transactions explicites (BEGIN TRAN, COMMIT)
- Gérer les erreurs avec TRY...CATCH, ni lever d'erreur avec RAISERROR ou THROW (interdit dans **toutes** les versions de SQL Server)
- Appeler des procédures stockées

### 3. Effets de bord interdits

Les fonctions doivent être **déterministes** (idéalement) : pour les mêmes entrées, elles doivent toujours retourner le même résultat.

**Fonction non-déterministe :**
```sql
-- Cette fonction retourne un résultat différent à chaque appel
CREATE FUNCTION dbo.DateActuelle()
RETURNS DATETIME
AS
BEGIN
    RETURN GETDATE();  -- Non-déterministe !
END;
```

## Modifier ou supprimer une fonction

### Modifier une fonction existante

Utilisez `ALTER FUNCTION` :

```sql
ALTER FUNCTION dbo.CalculerTVA
(
    @montantHT DECIMAL(10,2)
)
RETURNS DECIMAL(10,2)
AS
BEGIN
    DECLARE @tva DECIMAL(10,2);

    -- Nouveau taux de TVA : 21%
    SET @tva = @montantHT * 0.21;

    RETURN @tva;
END;
```

### Supprimer une fonction

Utilisez `DROP FUNCTION` :

```sql
DROP FUNCTION dbo.CalculerTVA;
```

Ou, pour éviter les erreurs si la fonction n'existe pas :

```sql
DROP FUNCTION IF EXISTS dbo.CalculerTVA;
```

---

## Bonnes pratiques

1. **Nommage clair** : Utilisez des noms descriptifs (ex: `CalculerRemise`, `FormaterTelephone`)
2. **Documentation** : Ajoutez des commentaires pour expliquer le but de la fonction
3. **Validation des paramètres** : Vérifiez que les entrées sont valides
   ```sql
   IF @montantHT < 0
       RETURN 0;  -- Ou gérer l'erreur autrement
   ```
4. **Préférez les expressions simples** : Si le calcul est simple, utilisez-le directement dans la requête plutôt qu'une fonction
5. **Attention aux performances** : Pour des traitements sur de gros volumes, envisagez d'autres solutions (vues, tables calculées, etc.)

---

## Quand utiliser les fonctions scalaires ?

**✅ Bon cas d'usage :**
- Calculs métier complexes réutilisés fréquemment
- Formatage ou transformation de données spécifiques à votre domaine
- Logique conditionnelle métier partagée
- Petits volumes de données

**❌ À éviter :**
- Requêtes sur de très grandes tables (milliers/millions de lignes)
- Calculs simples qui peuvent être faits directement en SQL
- Opérations nécessitant des modifications de données

---

## Résumé

Les **fonctions scalaires** en T-SQL sont des outils puissants pour :
- Encapsuler de la logique métier réutilisable
- Retourner une seule valeur calculée
- Simplifier et clarifier vos requêtes

**Points clés à retenir :**
- Elles retournent **toujours une seule valeur**
- Elles peuvent être utilisées partout où une expression SQL est attendue
- Elles ont des **limitations de performance** importantes
- Elles ne peuvent pas modifier de données
