# 3.2.1 La clause WHERE

## Introduction

Jusqu'à présent, vous avez appris à afficher des données avec `SELECT` et `FROM`. Mais il y a un problème : ces requêtes affichent **TOUTES** les lignes de la table !

Imaginez une table `Clients` contenant 100 000 clients. Si vous faites :

```sql
SELECT *
FROM Clients
```

Vous obtiendrez les 100 000 clients ! Ce n'est probablement pas ce que vous voulez.

**La solution ?** La clause `WHERE` !

`WHERE` est comme un **filtre** qui ne laisse passer que les lignes qui correspondent à vos critères. C'est l'une des clauses les plus importantes et les plus utilisées en SQL.

---

## Qu'est-ce que la clause WHERE ?

### Définition

La clause `WHERE` permet de **filtrer** les lignes d'une table en spécifiant une ou plusieurs **conditions**. Seules les lignes qui satisfont ces conditions seront incluses dans les résultats.

### Analogie

Imaginez que vous cherchez un livre dans une bibliothèque :
- **Sans WHERE** : Le bibliothécaire vous apporte **tous** les livres (inutile !)
- **Avec WHERE** : Vous dites "Je veux uniquement les livres de science-fiction publiés après 2020" → Le bibliothécaire ne vous apporte que les livres correspondants

---

## Syntaxe de base

```sql
SELECT colonnes
FROM table
WHERE condition
```

La clause `WHERE` se place **après** `FROM` et **avant** d'autres clauses comme `ORDER BY` (que nous verrons plus tard).

### Ordre logique

```sql
SELECT Prenom, Nom          -- 3. Affiche ces colonnes
FROM Clients                -- 1. Dans cette table
WHERE Ville = 'Paris'       -- 2. Mais seulement les lignes où Ville = 'Paris'
```

**Important** : Même si `SELECT` est écrit en premier, SQL évalue d'abord `FROM`, puis `WHERE`, et enfin `SELECT`.

---

## Premier exemple simple

### Sans WHERE

```sql
SELECT Prenom, Nom, Ville
FROM Clients
```

**Résultat** : Tous les clients, quelle que soit leur ville

| Prenom | Nom    | Ville      |
|--------|--------|------------|
| Sophie | Martin | Paris      |
| Pierre | Dubois | Lyon       |
| Marie  | Leroy  | Paris      |
| Luc    | Moreau | Marseille  |

### Avec WHERE

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville = 'Paris'
```

**Résultat** : Uniquement les clients qui habitent à Paris

| Prenom | Nom    | Ville |
|--------|--------|-------|
| Sophie | Martin | Paris |
| Marie  | Leroy  | Paris |

Notez que Pierre (Lyon) et Luc (Marseille) n'apparaissent **pas** dans les résultats !

---

## Les opérateurs de comparaison

La clause `WHERE` utilise des **opérateurs** pour comparer les valeurs. Voici les plus courants :

| Opérateur | Signification | Exemple |
|-----------|---------------|---------|
| `=` | Égal à | `WHERE Age = 25` |
| `!=` ou `<>` | Différent de | `WHERE Ville != 'Paris'` |
| `>` | Supérieur à | `WHERE Prix > 100` |
| `<` | Inférieur à | `WHERE Stock < 10` |
| `>=` | Supérieur ou égal à | `WHERE Age >= 18` |
| `<=` | Inférieur ou égal à | `WHERE Prix <= 50` |

---

## Exemples avec différents opérateurs

### Exemple 1 : Égalité (=)

Trouver tous les produits de catégorie "Électronique" :

```sql
SELECT NomProduit, Categorie, Prix
FROM Produits
WHERE Categorie = 'Électronique'
```

---

### Exemple 2 : Différent de (!= ou <>)

Trouver tous les clients qui n'habitent **pas** à Paris :

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville != 'Paris'
```

**Note** : `<>` est équivalent à `!=` (les deux fonctionnent)

```sql
WHERE Ville <> 'Paris'  -- Identique
```

---

### Exemple 3 : Supérieur à (>)

Trouver tous les produits dont le prix est supérieur à 100€ :

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > 100
```

**Résultat** :

| NomProduit | Prix   |
|------------|--------|
| Ordinateur | 800.00 |
| Téléphone  | 650.00 |

Les produits à 100€ exactement ne sont **pas** inclus (utilisez `>=` pour les inclure).

---

### Exemple 4 : Inférieur ou égal à (<=)

Trouver tous les produits dont le stock est inférieur ou égal à 5 (produits en rupture imminente) :

```sql
SELECT NomProduit, Stock
FROM Produits
WHERE Stock <= 5
```

---

### Exemple 5 : Avec des dates

Trouver toutes les commandes passées après le 1er janvier 2024 :

```sql
SELECT CommandeID, DateCommande, MontantTotal
FROM Commandes
WHERE DateCommande > '2024-01-01'
```

**Important** : Les dates en SQL Server s'écrivent entre apostrophes au format `'AAAA-MM-JJ'`

---

## Comparaison de chaînes de caractères

### Sensibilité à la casse

En T-SQL, la comparaison de chaînes **n'est généralement pas sensible à la casse** par défaut (selon la configuration du serveur) :

```sql
WHERE Ville = 'Paris'
WHERE Ville = 'paris'
WHERE Ville = 'PARIS'
```

Ces trois conditions sont souvent équivalentes.

### Les apostrophes (')

Les valeurs textuelles doivent **toujours** être entourées d'apostrophes simples :

**✅ Correct** :
```sql
WHERE Nom = 'Dupont'
WHERE Ville = 'Lyon'
```

**❌ Incorrect** :
```sql
WHERE Nom = Dupont      -- Erreur : SQL pense que Dupont est une colonne
WHERE Ville = "Lyon"    -- Évitez les guillemets doubles pour les chaînes
```

### Apostrophe dans une chaîne

Si votre valeur contient une apostrophe, doublez-la :

```sql
WHERE Ville = 'L''Havre'     -- Notez les deux apostrophes
WHERE Nom = 'O''Connor'
```

---

## Comparaison de valeurs numériques

Avec les nombres, **pas d'apostrophes** :

**✅ Correct** :
```sql
WHERE Prix = 100
WHERE Quantite > 50
WHERE Age >= 18
```

**❌ Incorrect** :
```sql
WHERE Prix = '100'     -- Fonctionne parfois (conversion automatique) mais à éviter
```

---

## Exemples pratiques par secteur

### Commerce électronique

**Trouver les produits en rupture de stock** :
```sql
SELECT NomProduit, Stock
FROM Produits
WHERE Stock = 0
```

**Trouver les produits chers** :
```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix >= 500
```

---

### Gestion des ressources humaines

**Trouver les employés d'un département** :
```sql
SELECT Prenom, Nom, Departement
FROM Employes
WHERE Departement = 'Informatique'
```

**Trouver les employés embauchés récemment** :
```sql
SELECT Prenom, Nom, DateEmbauche
FROM Employes
WHERE DateEmbauche >= '2024-01-01'
```

---

### Gestion de la relation client

**Trouver les clients d'une ville spécifique** :
```sql
SELECT Prenom, Nom, Email
FROM Clients
WHERE Ville = 'Marseille'
```

**Trouver les clients ayant un email spécifique** :
```sql
SELECT Prenom, Nom
FROM Clients
WHERE Email = 'sophie.martin@example.com'
```

---

## La clause WHERE avec SELECT *

Vous pouvez bien sûr combiner `WHERE` avec `SELECT *` :

```sql
SELECT *
FROM Produits
WHERE Categorie = 'Informatique'
```

Cela affichera toutes les colonnes, mais uniquement pour les produits de catégorie "Informatique".

---

## Combien de lignes seront retournées ?

Le nombre de lignes dans le résultat dépend de combien de lignes satisfont la condition :

- **Aucune ligne** : Si aucune ligne ne correspond, vous obtenez un résultat vide (pas d'erreur !)
- **Une ligne** : Si une seule ligne correspond
- **Plusieurs lignes** : Si plusieurs lignes correspondent
- **Toutes les lignes** : Si toutes les lignes satisfont la condition

### Exemple avec zéro résultat

```sql
SELECT *
FROM Produits
WHERE Prix < 0
```

Résultat : Aucune ligne (un prix ne peut pas être négatif)

**Important** : Ce n'est **pas une erreur**, c'est simplement un résultat vide.

---

## Bonnes pratiques

### ✅ À faire

1. **Toujours mettre les apostrophes pour les chaînes** :
   ```sql
   WHERE Ville = 'Paris'  -- ✅
   ```

2. **Utiliser la bonne syntaxe pour les dates** :
   ```sql
   WHERE DateCommande > '2024-01-01'  -- ✅
   ```

3. **Être précis dans vos conditions** :
   ```sql
   WHERE Statut = 'Actif'  -- ✅ Clair et précis
   ```

4. **Utiliser >= ou <= quand approprié** :
   ```sql
   WHERE Age >= 18  -- ✅ Inclut 18
   ```

---

### ❌ À éviter

1. **Oublier les apostrophes pour les chaînes** :
   ```sql
   WHERE Ville = Paris  -- ❌ Erreur
   ```

2. **Mettre des apostrophes pour les nombres** :
   ```sql
   WHERE Prix = '100'  -- ⚠️ Fonctionne mais incorrect
   ```

3. **Utiliser = au lieu de >= ou <=** :
   ```sql
   WHERE Prix > 100  -- Exclut les produits à 100€ exactement
   ```

4. **Conditions impossibles** :
   ```sql
   WHERE Prix < 0  -- Donnera toujours zéro résultat
   ```

---

## Ordre d'exécution logique

Bien que vous écriviez la requête dans cet ordre :

```sql
SELECT Prenom, Nom     -- Écrit en 1er
FROM Clients           -- Écrit en 2ème
WHERE Ville = 'Paris'  -- Écrit en 3ème
```

SQL l'exécute dans cet ordre :

```
1. FROM Clients           -- D'abord, identifie la table
2. WHERE Ville = 'Paris'  -- Ensuite, filtre les lignes
3. SELECT Prenom, Nom     -- Enfin, sélectionne les colonnes à afficher
```

Cet ordre logique est important pour comprendre certains comportements (notamment pourquoi vous ne pouvez pas utiliser un alias de colonne dans WHERE).

---

## Cas particuliers et limitations

### 1. WHERE et les alias de colonnes

Vous **ne pouvez pas** utiliser un alias de colonne dans la clause WHERE :

**❌ Ceci ne fonctionne pas** :
```sql
SELECT
    Prix * Quantite AS MontantTotal
FROM Commandes
WHERE MontantTotal > 1000  -- ❌ Erreur : MontantTotal n'existe pas encore
```

**✅ Solution** : Répéter l'expression
```sql
SELECT
    Prix * Quantite AS MontantTotal
FROM Commandes
WHERE Prix * Quantite > 1000  -- ✅ Fonctionne
```

**Pourquoi ?** Parce que `WHERE` est évalué **avant** `SELECT`, donc l'alias n'existe pas encore.

---

### 2. WHERE avec des colonnes calculées

Vous pouvez utiliser des expressions dans WHERE :

```sql
SELECT NomProduit, Prix, Quantite
FROM Produits
WHERE Prix * Quantite > 5000
```

---

### 3. Comparaison avec NULL

Les comparaisons avec `NULL` nécessitent une syntaxe spéciale (nous verrons cela dans la section 3.2.5 sur les NULL).

**Aperçu** :
- `WHERE Telephone = NULL` ❌ Ne fonctionne pas
- `WHERE Telephone IS NULL` ✅ Correct

---

## Vérification et débogage

### Comment vérifier votre requête ?

1. **Commencez simple** : Testez d'abord sans WHERE
   ```sql
   SELECT * FROM Clients  -- Voir toutes les données
   ```

2. **Ajoutez WHERE progressivement** :
   ```sql
   SELECT * FROM Clients WHERE Ville = 'Paris'
   ```

3. **Comptez les résultats** :
   ```sql
   SELECT COUNT(*) FROM Clients WHERE Ville = 'Paris'
   ```

### Messages d'erreur courants

**"Invalid column name"** :
- Vous avez mal orthographié le nom de la colonne
- La colonne n'existe pas dans la table

**"Conversion failed"** :
- Vous comparez des types incompatibles (ex: texte avec nombre)

| Aspect | Description | Exemple |
|--------|-------------|---------|

## Résumé

### Ce qu'il faut retenir

1. **WHERE** permet de filtrer les lignes selon des conditions

2. **Syntaxe** : `WHERE colonne opérateur valeur`

3. **Opérateurs de comparaison** : `=`, `!=`, `<>`, `>`, `<`, `>=`, `<=`

4. **Chaînes de caractères** : Entre apostrophes simples `'texte'`

5. **Nombres** : Sans apostrophes `123`

6. **Dates** : Entre apostrophes au format ISO `'2024-01-01'`

7. **Ordre d'exécution** : FROM → WHERE → SELECT

8. **Résultat vide** : Normal si aucune ligne ne correspond
