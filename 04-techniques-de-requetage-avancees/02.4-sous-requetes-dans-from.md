# 4.2.4 Sous-requêtes dans le FROM (Tables dérivées)

## Introduction

Jusqu'à présent, nous avons vu des sous-requêtes dans les clauses `SELECT` et `WHERE`. Il existe un autre endroit très puissant où placer une sous-requête : **dans la clause FROM**.

Quand vous placez une sous-requête dans le `FROM`, elle crée ce qu'on appelle une **table dérivée** (ou **inline view**) : un ensemble de résultats temporaire que vous pouvez traiter comme s'il s'agissait d'une vraie table.

### Analogie simple

Imaginez que vous avez besoin de faire des calculs sur des données déjà agrégées. C'est comme :
1. **Étape 1** : Créer un tableau résumé sur une feuille de papier
2. **Étape 2** : Utiliser ce tableau résumé pour faire d'autres calculs

La sous-requête dans le `FROM` fait exactement cela : elle crée un "tableau temporaire" que vous pouvez ensuite interroger.

## Syntaxe de base

```sql
SELECT colonnes
FROM (
    -- Sous-requête qui crée une table dérivée
    SELECT colonnes_calculées
    FROM table_source
    WHERE conditions
) AS AliasObligatoire
WHERE autres_conditions;
```

**Points essentiels :**
1. La sous-requête est entre **parenthèses**
2. Elle DOIT avoir un **alias** (nom temporaire)
3. Elle se comporte comme une table normale dans la requête externe

## Contexte : Tables d'exemple

Utilisons des tables simples pour nos exemples :

## Exemples de base

### Exemple 1 : Agréger puis filtrer les agrégations

**Problème :** Trouver les départements où le salaire moyen dépasse 3000€.

**Tentative incorrecte :**
```sql
-- ❌ ERREUR : On ne peut pas utiliser AVG() dans WHERE
SELECT DepartementID, AVG(Salaire) AS SalaireMoyen
FROM Employes
WHERE AVG(Salaire) > 3000  -- Ceci ne fonctionne pas !
GROUP BY DepartementID;
```

**Solution avec HAVING :**
```sql
-- ✅ Solution classique
SELECT DepartementID, AVG(Salaire) AS SalaireMoyen
FROM Employes
GROUP BY DepartementID
HAVING AVG(Salaire) > 3000;
```

**Solution avec table dérivée :**
```sql
-- ✅ Solution alternative avec table dérivée
SELECT *
FROM (
    SELECT DepartementID, AVG(Salaire) AS SalaireMoyen
    FROM Employes
    GROUP BY DepartementID
) AS DeptStats
WHERE SalaireMoyen > 3000;
```

**Résultat :**
| DepartementID | SalaireMoyen |
|---------------|--------------|
| 1 | 3500 |

**Explication :**
1. La sous-requête calcule la moyenne par département et crée une table temporaire `DeptStats`
2. Cette table a deux colonnes : `DepartementID` et `SalaireMoyen`
3. La requête externe filtre ensuite cette table avec un `WHERE` normal

**Avantage :** Plus lisible et permet de réutiliser `SalaireMoyen` plusieurs fois dans la requête externe.

### Exemple 2 : Faire des calculs sur des agrégations

**Problème :** Trouver les vendeurs dont les ventes totales sont supérieures à la moyenne des ventes totales de tous les vendeurs.

```sql
SELECT Vendeur, TotalVentes
FROM (
    -- Étape 1 : Calculer le total par vendeur
    SELECT Vendeur, SUM(Montant) AS TotalVentes
    FROM Ventes
    GROUP BY Vendeur
) AS VentesParVendeur
WHERE TotalVentes > (
    -- Étape 2 : Calculer la moyenne des totaux
    SELECT AVG(TotalVentes)
    FROM (
        SELECT Vendeur, SUM(Montant) AS TotalVentes
        FROM Ventes
        GROUP BY Vendeur
    ) AS Moyennes
);
```

**Décomposition étape par étape :**

**Étape 1 - La table dérivée principale :**
```sql
SELECT Vendeur, SUM(Montant) AS TotalVentes
FROM Ventes
GROUP BY Vendeur
```
Résultat intermédiaire :
| Vendeur | TotalVentes |
|---------|-------------|
| Alice | 3700 |
| Bob | 2800 |

**Étape 2 - Calculer la moyenne de ces totaux :**
```sql
SELECT AVG(TotalVentes) FROM ...
```
Résultat : (3700 + 2800) / 2 = 3250

**Étape 3 - Filtrer :**
- Alice : 3700 > 3250 ✓
- Bob : 2800 > 3250 ✗

**Résultat final :**
| Vendeur | TotalVentes |
|---------|-------------|
| Alice | 3700 |

### Exemple 3 : Simplifier des requêtes complexes

**Problème :** Afficher chaque employé avec son salaire et le pourcentage qu'il représente par rapport au total de son département.

```sql
SELECT
    E.NomEmploye,
    E.Salaire,
    E.DepartementID,
    DeptTotals.TotalSalaireDept,
    ROUND((E.Salaire * 100.0 / DeptTotals.TotalSalaireDept), 2) AS PourcentageDept
FROM Employes E
INNER JOIN (
    -- Table dérivée : Totaux par département
    SELECT
        DepartementID,
        SUM(Salaire) AS TotalSalaireDept
    FROM Employes
    GROUP BY DepartementID
) AS DeptTotals ON E.DepartementID = DeptTotals.DepartementID
ORDER BY E.DepartementID, E.Salaire DESC;
```

**Résultat :**
| NomEmploye | Salaire | DepartementID | TotalSalaireDept | PourcentageDept |
|------------|---------|---------------|------------------|-----------------|
| Lambert | 4000 | 1 | 10500 | 38.10 |
| Martin | 3500 | 1 | 10500 | 33.33 |
| Dupont | 3000 | 1 | 10500 | 28.57 |
| Dubois | 3200 | 2 | 8500 | 37.65 |
| Bernard | 2800 | 2 | 8500 | 32.94 |
| Moreau | 2500 | 2 | 8500 | 29.41 |

**Explication :**
1. La table dérivée `DeptTotals` calcule le total des salaires par département
2. On joint cette table dérivée avec la table `Employes`
3. On peut ensuite calculer le pourcentage pour chaque employé

## Pourquoi utiliser des tables dérivées ?

### 1. Contourner les limitations de GROUP BY

Vous ne pouvez pas mélanger colonnes agrégées et non-agrégées sans `GROUP BY`. Les tables dérivées permettent de faire des calculs supplémentaires après l'agrégation.

**Sans table dérivée (impossible) :**
```sql
-- ❌ Erreur : On ne peut pas filtrer sur le rang directement
SELECT DepartementID, AVG(Salaire) AS Moyenne
FROM Employes
GROUP BY DepartementID
WHERE RANK() OVER (ORDER BY AVG(Salaire) DESC) = 1;  -- Ne fonctionne pas !
```

**Avec table dérivée :**
```sql
-- ✅ Fonctionne
SELECT *
FROM (
    SELECT
        DepartementID,
        AVG(Salaire) AS Moyenne,
        RANK() OVER (ORDER BY AVG(Salaire) DESC) AS Rang
    FROM Employes
    GROUP BY DepartementID
) AS Ranked
WHERE Rang = 1;
```

### 2. Réutiliser des calculs complexes

Éviter de répéter la même logique plusieurs fois.

**Sans table dérivée (répétitif) :**
```sql
SELECT
    Vendeur,
    SUM(Montant) AS Total,
    SUM(Montant) / (SELECT SUM(Montant) FROM Ventes) * 100 AS Pourcentage
FROM Ventes
GROUP BY Vendeur
HAVING SUM(Montant) > 3000;  -- On répète SUM(Montant)
```

**Avec table dérivée (plus clair) :**
```sql
SELECT
    Vendeur,
    Total,
    Total / (SELECT SUM(Montant) FROM Ventes) * 100 AS Pourcentage
FROM (
    SELECT Vendeur, SUM(Montant) AS Total
    FROM Ventes
    GROUP BY Vendeur
) AS VentesTotales
WHERE Total > 3000;  -- On utilise l'alias
```

### 3. Améliorer la lisibilité

Découper une requête complexe en étapes logiques.

```sql
-- Étape 1 : Calculer les statistiques de base
-- Étape 2 : Utiliser ces statistiques pour d'autres calculs
SELECT
    Stats.DepartementID,
    Stats.NbEmployes,
    Stats.SalaireMoyen,
    CASE
        WHEN Stats.NbEmployes > 3 THEN 'Grand département'
        ELSE 'Petit département'
    END AS Taille
FROM (
    SELECT
        DepartementID,
        COUNT(*) AS NbEmployes,
        AVG(Salaire) AS SalaireMoyen
    FROM Employes
    GROUP BY DepartementID
) AS Stats
ORDER BY Stats.NbEmployes DESC;
```

## Exemples avancés

### Exemple 4 : Plusieurs tables dérivées dans une même requête

Comparer les performances de vente par mois :

```sql
SELECT
    M1.Mois,
    M1.TotalVentes AS VentesMois,
    M2.TotalVentes AS VentesMoisPrecedent,
    M1.TotalVentes - M2.TotalVentes AS Difference
FROM (
    -- Ventes du mois courant
    SELECT
        MONTH(DateVente) AS Mois,
        SUM(Montant) AS TotalVentes
    FROM Ventes
    WHERE YEAR(DateVente) = 2024
    GROUP BY MONTH(DateVente)
) AS M1
LEFT JOIN (
    -- Ventes du mois précédent
    SELECT
        MONTH(DateVente) + 1 AS Mois,  -- Décalage d'un mois
        SUM(Montant) AS TotalVentes
    FROM Ventes
    WHERE YEAR(DateVente) = 2024
    GROUP BY MONTH(DateVente)
) AS M2 ON M1.Mois = M2.Mois
ORDER BY M1.Mois;
```

### Exemple 5 : Filtrer sur des fonctions de fenêtrage

**Problème :** Trouver les 3 employés les mieux payés de chaque département.

```sql
SELECT
    NomEmploye,
    Salaire,
    DepartementID,
    Rang
FROM (
    SELECT
        NomEmploye,
        Salaire,
        DepartementID,
        ROW_NUMBER() OVER (
            PARTITION BY DepartementID
            ORDER BY Salaire DESC
        ) AS Rang
    FROM Employes
) AS EmployesRanges
WHERE Rang <= 3
ORDER BY DepartementID, Rang;
```

**Résultat :**
| NomEmploye | Salaire | DepartementID | Rang |
|------------|---------|---------------|------|
| Lambert | 4000 | 1 | 1 |
| Martin | 3500 | 1 | 2 |
| Dupont | 3000 | 1 | 3 |
| Dubois | 3200 | 2 | 1 |
| Bernard | 2800 | 2 | 2 |
| Moreau | 2500 | 2 | 3 |

**Explication :**
- La fonction `ROW_NUMBER()` ne peut pas être utilisée directement dans un `WHERE`
- On crée d'abord une table dérivée avec le rang calculé
- Ensuite, on filtre sur cette table dérivée

### Exemple 6 : Agréger des agrégations

**Problème :** Trouver le département avec le salaire moyen le plus élevé.

```sql
SELECT TOP 1
    DepartementID,
    SalaireMoyen
FROM (
    SELECT
        DepartementID,
        AVG(Salaire) AS SalaireMoyen
    FROM Employes
    GROUP BY DepartementID
) AS MoyennesParDept
ORDER BY SalaireMoyen DESC;
```

**Alternative sans TOP :**
```sql
SELECT DepartementID, SalaireMoyen
FROM (
    SELECT
        DepartementID,
        AVG(Salaire) AS SalaireMoyen
    FROM Employes
    GROUP BY DepartementID
) AS MoyennesParDept
WHERE SalaireMoyen = (
    SELECT MAX(SalaireMoyen)
    FROM (
        SELECT AVG(Salaire) AS SalaireMoyen
        FROM Employes
        GROUP BY DepartementID
    ) AS MaxMoyenne
);
```

## Tables dérivées vs Autres approches

### Comparaison avec les CTE (Common Table Expressions)

Les **CTE** (que nous verrons dans la section suivante) offrent une alternative plus lisible.

**Avec table dérivée :**
```sql
SELECT *
FROM (
    SELECT DepartementID, AVG(Salaire) AS Moyenne
    FROM Employes
    GROUP BY DepartementID
) AS Stats
WHERE Moyenne > 3000;
```

**Avec CTE (plus lisible) :**
```sql
WITH Stats AS (
    SELECT DepartementID, AVG(Salaire) AS Moyenne
    FROM Employes
    GROUP BY DepartementID
)
SELECT *
FROM Stats
WHERE Moyenne > 3000;
```

**Avantages des CTE :**
- ✅ Plus lisibles (surtout pour les requêtes complexes)
- ✅ Peuvent être réutilisés plusieurs fois dans la même requête
- ✅ Supportent la récursivité
- ✅ Mieux pour le débogage (on peut tester chaque CTE séparément)

**Avantages des tables dérivées :**
- ✅ Plus compactes pour des cas simples
- ✅ Disponibles dans toutes les versions de SQL Server
- ✅ Fonctionnement identique aux CTE en termes de performance

### Comparaison avec les vues

**Table dérivée :** Temporaire, existe uniquement pendant l'exécution de la requête.

**Vue :** Permanente, stockée dans la base de données, peut être réutilisée.

```sql
-- Créer une vue (permanent)
CREATE VIEW VueMoyennesDept AS
SELECT DepartementID, AVG(Salaire) AS SalaireMoyen
FROM Employes
GROUP BY DepartementID;

-- Utiliser la vue
SELECT * FROM VueMoyennesDept WHERE SalaireMoyen > 3000;
```

**Quand utiliser une vue vs une table dérivée :**
- **Vue** : Logique réutilisée fréquemment, abstraction de données complexes
- **Table dérivée** : Besoin ponctuel, calcul spécifique à une requête

### Comparaison avec les tables temporaires

**Table dérivée :**
```sql
-- Existe uniquement le temps de la requête
SELECT * FROM (SELECT ...) AS Temp;
```

**Table temporaire :**
```sql
-- Existe pendant toute la session
CREATE TABLE #Temp (Col1 INT, Col2 VARCHAR(50));
INSERT INTO #Temp VALUES (1, 'Test');
SELECT * FROM #Temp;
DROP TABLE #Temp;
```

**Quand utiliser une table temporaire vs une table dérivée :**
- **Table temporaire** : Résultats intermédiaires volumineux, utilisés plusieurs fois
- **Table dérivée** : Résultat utilisé une seule fois, requête auto-contenue

## Points importants à retenir

### ✅ Avantages des tables dérivées

1. **Contournent les limitations** : Permettent de filtrer ou trier sur des agrégations
2. **Clarté** : Décomposent les requêtes complexes en étapes logiques
3. **Réutilisation** : Les alias peuvent être utilisés dans la requête externe
4. **Performance** : Pas de coût de stockage (contrairement aux tables temporaires)

### ⚠️ Limites et précautions

1. **Alias obligatoire** : Une table dérivée doit toujours avoir un alias
   ```sql
   -- ❌ Erreur
   SELECT * FROM (SELECT * FROM Employes);

   -- ✅ Correct
   SELECT * FROM (SELECT * FROM Employes) AS E;
   ```

2. **Pas de réutilisation** : Une table dérivée ne peut être référencée qu'une fois
   ```sql
   -- ❌ Impossible : Impossible de référencer Stats deux fois
   SELECT *
   FROM (SELECT ...) AS Stats
   CROSS JOIN Stats;  -- Erreur !

   -- ✅ Solution : Utiliser un CTE
   WITH Stats AS (SELECT ...)
   SELECT * FROM Stats CROSS JOIN Stats;
   ```

3. **Colonnes nommées** : Toutes les colonnes doivent avoir un nom (ou alias)
   ```sql
   -- ❌ Erreur si le calcul n'a pas d'alias
   SELECT * FROM (SELECT Salaire * 2 FROM Employes) AS E;

   -- ✅ Correct
   SELECT * FROM (SELECT Salaire * 2 AS SalaireDouble FROM Employes) AS E;
   ```

4. **Performance** : Pas de matérialisation automatique, recalculée si nécessaire
   - SQL Server peut optimiser et éviter les recalculs inutiles
   - Pour les requêtes très complexes, comparer avec les tables temporaires

### 💡 Bonnes pratiques

1. **Noms d'alias descriptifs**
   ```sql
   -- ❌ Peu clair
   SELECT * FROM (SELECT ...) AS T;

   -- ✅ Descriptif
   SELECT * FROM (SELECT ...) AS StatsDepartements;
   ```

2. **Indentation pour la lisibilité**
   ```sql
   SELECT
       S.DepartementID,
       S.Moyenne
   FROM (
       SELECT
           DepartementID,
           AVG(Salaire) AS Moyenne
       FROM Employes
       GROUP BY DepartementID
   ) AS S
   WHERE S.Moyenne > 3000;
   ```

3. **Commenter les requêtes complexes**
   ```sql
   SELECT
       Stats.*
   FROM (
       -- Calcul des moyennes par département
       -- pour identifier les départements à hauts salaires
       SELECT
           DepartementID,
           AVG(Salaire) AS Moyenne
       FROM Employes
       GROUP BY DepartementID
   ) AS Stats
   WHERE Stats.Moyenne > 3000;
   ```

4. **Éviter les imbrications trop profondes**
   ```sql
   -- ❌ Difficile à lire (3 niveaux d'imbrication)
   SELECT * FROM (
       SELECT * FROM (
           SELECT * FROM (
               SELECT * FROM Employes
           ) AS A
       ) AS B
   ) AS C;

   -- ✅ Utiliser des CTE pour plus de clarté
   WITH A AS (SELECT * FROM Employes),
        B AS (SELECT * FROM A),
        C AS (SELECT * FROM B)
   SELECT * FROM C;
   ```

## Résumé

Les **tables dérivées** (sous-requêtes dans le `FROM`) sont un outil puissant pour :
- **Décomposer** des requêtes complexes en étapes logiques
- **Filtrer ou trier** sur des résultats agrégés
- **Réutiliser** des calculs dans la requête externe
- **Contourner** les limitations de SQL sur les agrégations

**Syntaxe clé :**
```sql
SELECT colonnes
FROM (sous-requête) AS AliasObligatoire
WHERE conditions_sur_alias;
```

**Quand les utiliser :**
- Quand vous devez faire des calculs sur des agrégations
- Quand vous voulez filtrer sur des fonctions de fenêtrage
- Pour rendre des requêtes complexes plus lisibles
- Pour des besoins ponctuels (sinon, créer une vue)

**Alternative moderne :** Les **CTE (Common Table Expressions)** offrent généralement une syntaxe plus claire et plus flexible, que nous verrons dans la section suivante.

Les tables dérivées restent très utiles et sont un concept fondamental à comprendre, car elles forment la base de nombreuses techniques avancées en SQL !
