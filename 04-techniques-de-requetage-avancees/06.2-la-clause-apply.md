# 4.6.2 La clause APPLY (CROSS APPLY, OUTER APPLY)

## Introduction

La clause **APPLY** est une fonctionnalité puissante de T-SQL qui permet d'**appliquer une expression de table** (comme une fonction table ou une sous-requête) à **chaque ligne** d'une table source. C'est comme une jointure, mais avec la capacité unique d'utiliser les colonnes de la table de gauche dans la partie droite.

Il existe deux variantes :
- **CROSS APPLY** : Similaire à INNER JOIN (n'affiche que les lignes avec correspondance)
- **OUTER APPLY** : Similaire à LEFT OUTER JOIN (affiche toutes les lignes de gauche, même sans correspondance)

### Pourquoi APPLY est différent des jointures

**Jointure classique :**
```sql
-- ❌ ERREUR : Impossible de référencer C.ClientID dans une sous-requête de FROM
SELECT C.ClientID, TopVentes.*
FROM Clients C
INNER JOIN (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID  -- ❌ C.ClientID non accessible ici !
    ORDER BY Montant DESC
) AS TopVentes ON ...
```

**Avec APPLY :**
```sql
-- ✅ CORRECT : APPLY permet d'utiliser C.ClientID
SELECT C.ClientID, TopVentes.*
FROM Clients C
CROSS APPLY (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID  -- ✅ C.ClientID accessible !
    ORDER BY Montant DESC
) AS TopVentes;
```

## Analogie simple : Le restaurant

Imaginez un restaurant avec des clients et leurs commandes :

### Jointure classique (INNER JOIN)
C'est comme avoir une **liste fixe de plats** que vous comparez avec ce que chaque client a commandé.
- La liste des plats est **la même pour tous les clients**

### APPLY
C'est comme avoir un **menu personnalisé** pour chaque client basé sur ses préférences.
- Le "menu" (ensemble de lignes) peut **changer pour chaque client**
- Vous pouvez utiliser les informations du client pour décider quelles lignes afficher

## 1. CROSS APPLY - Appliquer avec filtrage

### Concept

**CROSS APPLY** applique une expression de table à chaque ligne de la table source et retourne **uniquement les lignes pour lesquelles l'expression produit des résultats**.

C'est l'équivalent d'un **INNER JOIN** avec la capacité de référencer les colonnes de la table de gauche.

### Syntaxe

```sql
SELECT colonnes
FROM TableGauche
CROSS APPLY (
    <expression_table_utilisant_colonnes_de_TableGauche>
) AS Alias;
```

### Exemple de base : Top N par groupe

**Scénario :** Trouver les 2 commandes les plus récentes de chaque client.

**Données :**

**Table Clients :**

| ClientID | NomClient |
|----------|-----------|
| 1 | Dupont |
| 2 | Martin |
| 3 | Durand |

**Table Commandes :**

| CommandeID | ClientID | DateCommande | Montant |
|------------|----------|--------------|---------|
| 101 | 1 | 2024-01-15 | 100 |
| 102 | 1 | 2024-02-20 | 150 |
| 103 | 1 | 2024-03-10 | 200 |
| 104 | 2 | 2024-01-05 | 80 |
| 105 | 2 | 2024-02-15 | 120 |

**Requête avec CROSS APPLY :**

```sql
SELECT
    C.NomClient,
    TopCommandes.CommandeID,
    TopCommandes.DateCommande,
    TopCommandes.Montant
FROM Clients C
CROSS APPLY (
    SELECT TOP 2
        CommandeID,
        DateCommande,
        Montant
    FROM Commandes
    WHERE ClientID = C.ClientID  -- Utilise C.ClientID de la table de gauche !
    ORDER BY DateCommande DESC
) AS TopCommandes;
```

**Résultat :**

| NomClient | CommandeID | DateCommande | Montant |
|-----------|------------|--------------|---------|
| Dupont | 103 | 2024-03-10 | 200 |
| Dupont | 102 | 2024-02-20 | 150 |
| Martin | 105 | 2024-02-15 | 120 |
| Martin | 104 | 2024-01-05 | 80 |

**Note :** Durand n'apparaît pas car il n'a pas de commandes (comme un INNER JOIN).

### Comment ça fonctionne ?

**Étape par étape :**

1. **Pour Dupont (ClientID = 1) :**
   - Exécute la sous-requête avec ClientID = 1
   - Trouve les 2 commandes les plus récentes (103, 102)
   - Retourne ces 2 lignes combinées avec Dupont

2. **Pour Martin (ClientID = 2) :**
   - Exécute la sous-requête avec ClientID = 2
   - Trouve les 2 commandes les plus récentes (105, 104)
   - Retourne ces 2 lignes combinées avec Martin

3. **Pour Durand (ClientID = 3) :**
   - Exécute la sous-requête avec ClientID = 3
   - Ne trouve aucune commande
   - **N'affiche pas Durand** (comportement CROSS APPLY)

### Exemple : Calcul dynamique par ligne

```sql
SELECT
    P.Produit,
    P.Prix,
    Remise.Pourcentage,
    P.Prix * (1 - Remise.Pourcentage/100.0) AS PrixFinal
FROM Produits P
CROSS APPLY (
    SELECT
        CASE
            WHEN P.Prix > 100 THEN 10
            WHEN P.Prix > 50 THEN 5
            ELSE 0
        END AS Pourcentage
) AS Remise;
```

**Résultat :**

| Produit | Prix | Pourcentage | PrixFinal |
|---------|------|-------------|-----------|
| Laptop | 800 | 10 | 720.00 |
| Souris | 25 | 0 | 25.00 |
| Clavier | 60 | 5 | 57.00 |

La remise est calculée **dynamiquement** en fonction du prix de chaque produit.

### Exemple : Décomposition de chaîne de caractères

```sql
SELECT
    Employe,
    Email,
    Parties.Partie,
    Parties.Position
FROM Employes
CROSS APPLY (
    VALUES
        ('Utilisateur', SUBSTRING(Email, 1, CHARINDEX('@', Email) - 1)),
        ('Domaine', SUBSTRING(Email, CHARINDEX('@', Email) + 1, LEN(Email)))
) AS Parties(Partie, Position);
```

**Données :**

| Employe | Email |
|---------|-------|
| Dupont | dupont@entreprise.com |

**Résultat :**

| Employe | Email | Partie | Position |
|---------|-------|--------|----------|
| Dupont | dupont@entreprise.com | Utilisateur | dupont |
| Dupont | dupont@entreprise.com | Domaine | entreprise.com |

Chaque email est **décomposé** en utilisateur et domaine.

## 2. OUTER APPLY - Appliquer sans filtrage

### Concept

**OUTER APPLY** fonctionne comme CROSS APPLY, mais retourne **toutes les lignes de la table de gauche**, même si l'expression de table ne produit aucun résultat.

C'est l'équivalent d'un **LEFT OUTER JOIN** avec la capacité de référencer les colonnes de la table de gauche.

### Syntaxe

```sql
SELECT colonnes
FROM TableGauche
OUTER APPLY (
    <expression_table_utilisant_colonnes_de_TableGauche>
) AS Alias;
```

### Exemple de base

Reprenons l'exemple précédent avec **OUTER APPLY** :

```sql
SELECT
    C.NomClient,
    TopCommandes.CommandeID,
    TopCommandes.DateCommande,
    TopCommandes.Montant
FROM Clients C
OUTER APPLY (
    SELECT TOP 2
        CommandeID,
        DateCommande,
        Montant
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS TopCommandes;
```

**Résultat :**

| NomClient | CommandeID | DateCommande | Montant |
|-----------|------------|--------------|---------|
| Dupont | 103 | 2024-03-10 | 200 |
| Dupont | 102 | 2024-02-20 | 150 |
| Martin | 105 | 2024-02-15 | 120 |
| Martin | 104 | 2024-01-05 | 80 |
| Durand | NULL | NULL | NULL |

**Différence :** Durand apparaît maintenant avec des valeurs NULL (comme un LEFT JOIN).

### Exemple : Dernière commande par client

```sql
SELECT
    C.ClientID,
    C.NomClient,
    DerniereCommande.DateCommande,
    DerniereCommande.Montant
FROM Clients C
OUTER APPLY (
    SELECT TOP 1
        DateCommande,
        Montant
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS DerniereCommande;
```

**Résultat :**

| ClientID | NomClient | DateCommande | Montant |
|----------|-----------|--------------|---------|
| 1 | Dupont | 2024-03-10 | 200 |
| 2 | Martin | 2024-02-15 | 120 |
| 3 | Durand | NULL | NULL |

**Tous les clients** sont affichés, même ceux sans commandes.

### Exemple : Calcul avec valeur par défaut

```sql
SELECT
    E.Employe,
    E.Salaire,
    ISNULL(Bonus.Montant, 0) AS Bonus,
    E.Salaire + ISNULL(Bonus.Montant, 0) AS SalaireTotal
FROM Employes E
OUTER APPLY (
    SELECT TOP 1 Montant
    FROM BonusAnnuels
    WHERE EmployeID = E.EmployeID
      AND Annee = 2024
) AS Bonus;
```

Affiche le bonus de 2024 pour chaque employé, ou 0 s'il n'y en a pas.

## 3. Différences CROSS APPLY vs OUTER APPLY

### Tableau comparatif

| Aspect | CROSS APPLY | OUTER APPLY |
|--------|-------------|-------------|
| **Équivalent JOIN** | INNER JOIN | LEFT OUTER JOIN |
| **Lignes sans correspondance** | Exclues | Incluses avec NULL |
| **Résultat vide** | Ligne non retournée | Ligne retournée avec NULL |
| **Usage** | Seulement les correspondances | Tous les éléments de gauche |

### Exemple côte à côte

**Table Clients :**

| ClientID | NomClient |
|----------|-----------|
| 1 | Dupont |
| 2 | Martin |
| 3 | Durand |

**Table Commandes :**
- Dupont : 2 commandes
- Martin : 1 commande
- Durand : 0 commande

**Avec CROSS APPLY :**

```sql
SELECT C.NomClient, Cmd.CommandeID
FROM Clients C
CROSS APPLY (
    SELECT CommandeID
    FROM Commandes
    WHERE ClientID = C.ClientID
) AS Cmd;
```

**Résultat :** 3 lignes (Durand absent)

| NomClient | CommandeID |
|-----------|------------|
| Dupont | 101 |
| Dupont | 102 |
| Martin | 104 |

**Avec OUTER APPLY :**

```sql
SELECT C.NomClient, Cmd.CommandeID
FROM Clients C
OUTER APPLY (
    SELECT CommandeID
    FROM Commandes
    WHERE ClientID = C.ClientID
) AS Cmd;
```

**Résultat :** 4 lignes (Durand présent avec NULL)

| NomClient | CommandeID |
|-----------|------------|
| Dupont | 101 |
| Dupont | 102 |
| Martin | 104 |
| Durand | NULL |

## 4. Cas d'usage pratiques

### A. Top N par groupe avec CROSS APPLY

**Problème :** Trouver les 3 produits les plus vendus dans chaque catégorie.

```sql
SELECT
    Cat.Categorie,
    TopProduits.Produit,
    TopProduits.QuantiteVendue
FROM Categories Cat
CROSS APPLY (
    SELECT TOP 3
        Produit,
        QuantiteVendue
    FROM Produits P
    WHERE P.CategorieID = Cat.CategorieID
    ORDER BY QuantiteVendue DESC
) AS TopProduits;
```

**Avantage sur ROW_NUMBER() :**
- Plus simple à écrire
- Peut utiliser TOP avec TIES
- Performance parfois meilleure

### B. Statistiques agrégées par ligne

**Problème :** Afficher chaque vente avec les statistiques du vendeur.

```sql
SELECT
    V.VenteID,
    V.Vendeur,
    V.Montant,
    Stats.TotalVentes,
    Stats.MoyenneVentes,
    Stats.NombreVentes
FROM Ventes V
CROSS APPLY (
    SELECT
        SUM(Montant) AS TotalVentes,
        AVG(Montant) AS MoyenneVentes,
        COUNT(*) AS NombreVentes
    FROM Ventes
    WHERE Vendeur = V.Vendeur
) AS Stats;
```

**Note :** Les fonctions de fenêtrage sont souvent préférables ici, mais APPLY reste utile pour des calculs complexes.

### C. Recherche dans plusieurs tables

**Problème :** Trouver toutes les mentions d'un client dans différentes tables.

```sql
SELECT
    C.ClientID,
    C.NomClient,
    Mentions.Source,
    Mentions.Date,
    Mentions.Description
FROM Clients C
OUTER APPLY (
    SELECT 'Commande' AS Source, DateCommande AS Date, 'Commande n°' + CAST(CommandeID AS VARCHAR) AS Description
    FROM Commandes WHERE ClientID = C.ClientID
    UNION ALL
    SELECT 'Réclamation', DateReclamation, Sujet
    FROM Reclamations WHERE ClientID = C.ClientID
    UNION ALL
    SELECT 'Feedback', DateFeedback, Commentaire
    FROM Feedbacks WHERE ClientID = C.ClientID
) AS Mentions
ORDER BY C.ClientID, Mentions.Date DESC;
```

Combine les données de **plusieurs tables** en une seule vue.

### D. Manipulation de chaînes complexes

**Problème :** Diviser une liste de valeurs séparées par des virgules en lignes.

```sql
SELECT
    P.ProduitID,
    P.Produit,
    Tags.Valeur AS Tag
FROM Produits P
CROSS APPLY STRING_SPLIT(P.Tags, ',') AS Tags;
```

**Données :**

| ProduitID | Produit | Tags |
|-----------|---------|------|
| 1 | Laptop | Informatique,Portable,Business |
| 2 | Souris | Informatique,Accessoire |

**Résultat :**

| ProduitID | Produit | Tag |
|-----------|---------|-----|
| 1 | Laptop | Informatique |
| 1 | Laptop | Portable |
| 1 | Laptop | Business |
| 2 | Souris | Informatique |
| 2 | Souris | Accessoire |

### E. Génération de séries de dates

**Problème :** Générer une ligne pour chaque jour entre deux dates.

```sql
SELECT
    E.Employe,
    E.DateDebut,
    E.DateFin,
    Calendrier.Date
FROM Employes E
CROSS APPLY (
    SELECT DATEADD(DAY, Number, E.DateDebut) AS Date
    FROM master..spt_values
    WHERE Type = 'P'
      AND DATEADD(DAY, Number, E.DateDebut) <= E.DateFin
) AS Calendrier;
```

Crée une ligne pour **chaque jour** de la période d'emploi.

**Alternative moderne (SQL Server 2022+) :**

```sql
SELECT
    E.Employe,
    Calendrier.Date
FROM Employes E
CROSS APPLY GENERATE_SERIES(0, DATEDIFF(DAY, E.DateDebut, E.DateFin)) AS Jours(Number)
CROSS APPLY (
    SELECT DATEADD(DAY, Jours.Number, E.DateDebut) AS Date
) AS Calendrier;
```

### F. Calculs conditionnels complexes

```sql
SELECT
    Commande.CommandeID,
    Commande.Montant,
    Remise.Type,
    Remise.Pourcentage,
    Commande.Montant * (1 - Remise.Pourcentage/100.0) AS MontantFinal
FROM Commandes Commande
OUTER APPLY (
    SELECT
        CASE
            WHEN Commande.Montant > 1000 THEN 'Premium'
            WHEN Commande.ClientFidele = 1 THEN 'Fidélité'
            WHEN Commande.CodePromo IS NOT NULL THEN 'Promo'
            ELSE 'Standard'
        END AS Type,
        CASE
            WHEN Commande.Montant > 1000 THEN 15
            WHEN Commande.ClientFidele = 1 THEN 10
            WHEN Commande.CodePromo IS NOT NULL THEN 5
            ELSE 0
        END AS Pourcentage
) AS Remise;
```

Calcule des remises **complexes et conditionnelles** basées sur plusieurs critères.

## 5. APPLY avec des fonctions table

### Fonctions Table Inline (TVF)

Les fonctions table sont particulièrement puissantes avec APPLY.

**Créer une fonction table :**

```sql
CREATE FUNCTION dbo.GetTopVentes(@ClientID INT, @Limite INT)
RETURNS TABLE
AS
RETURN (
    SELECT TOP (@Limite)
        CommandeID,
        DateCommande,
        Montant
    FROM Commandes
    WHERE ClientID = @ClientID
    ORDER BY Montant DESC
);
```

**Utiliser avec APPLY :**

```sql
SELECT
    C.ClientID,
    C.NomClient,
    TopVentes.*
FROM Clients C
CROSS APPLY dbo.GetTopVentes(C.ClientID, 3) AS TopVentes;
```

**Avantages :**
- Réutilisabilité du code
- Paramètres dynamiques
- Encapsulation de la logique métier
- Performance optimisée

### Exemple : Calcul de distance géographique

```sql
-- Fonction qui calcule les magasins proches
CREATE FUNCTION dbo.GetMagasinsProches(
    @Latitude FLOAT,
    @Longitude FLOAT,
    @RayonKm INT
)
RETURNS TABLE
AS
RETURN (
    SELECT
        MagasinID,
        NomMagasin,
        Distance = dbo.CalculerDistance(@Latitude, @Longitude, Latitude, Longitude)
    FROM Magasins
    WHERE dbo.CalculerDistance(@Latitude, @Longitude, Latitude, Longitude) <= @RayonKm
);
GO

-- Utilisation
SELECT
    C.ClientID,
    C.NomClient,
    Proches.NomMagasin,
    Proches.Distance
FROM Clients C
OUTER APPLY dbo.GetMagasinsProches(C.Latitude, C.Longitude, 10) AS Proches
ORDER BY C.ClientID, Proches.Distance;
```

Trouve les magasins dans un rayon de 10 km pour **chaque client**.

## 6. APPLY vs Jointures classiques

### Quand utiliser APPLY ?

✅ **Utilisez APPLY quand :**
- Vous devez utiliser TOP N **par groupe**
- Vous avez besoin de **référencer des colonnes de gauche** dans la partie droite
- Vous utilisez des **fonctions table paramétrées**
- Vous voulez appliquer une **logique complexe** à chaque ligne
- Vous devez exécuter une **sous-requête corrélée** pour chaque ligne

✅ **Utilisez JOIN quand :**
- Vous avez une **relation simple** entre deux tables
- Aucune logique dynamique basée sur les valeurs de gauche
- Les performances sont critiques et JOIN est plus rapide

### Équivalences

**CROSS APPLY = INNER JOIN** (mais plus puissant)

```sql
-- Avec CROSS APPLY
SELECT *
FROM Clients C
CROSS APPLY (
    SELECT * FROM Commandes WHERE ClientID = C.ClientID
) AS Cmd;

-- Équivalent avec INNER JOIN
SELECT C.*, Cmd.*
FROM Clients C
INNER JOIN Commandes Cmd ON C.ClientID = Cmd.ClientID;
```

**OUTER APPLY = LEFT JOIN** (mais plus puissant)

```sql
-- Avec OUTER APPLY
SELECT *
FROM Clients C
OUTER APPLY (
    SELECT * FROM Commandes WHERE ClientID = C.ClientID
) AS Cmd;

-- Équivalent avec LEFT JOIN
SELECT C.*, Cmd.*
FROM Clients C
LEFT JOIN Commandes Cmd ON C.ClientID = Cmd.ClientID;
```

### Quand APPLY est obligatoire

**1. TOP N par groupe :**

```sql
-- ❌ Impossible avec JOIN simple
-- ✅ Facile avec APPLY
SELECT *
FROM Clients C
CROSS APPLY (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS Top3;
```

**2. Fonctions table paramétrées :**

```sql
-- ❌ Impossible avec JOIN
SELECT C.ClientID, Cmd.*
FROM Clients C
INNER JOIN dbo.GetCommandes(C.ClientID) AS Cmd -- Erreur !

-- ✅ Correct avec APPLY
SELECT C.ClientID, Cmd.*
FROM Clients C
CROSS APPLY dbo.GetCommandes(C.ClientID) AS Cmd;
```

**3. Expressions complexes avec VALUES :**

```sql
-- Génère plusieurs lignes pour chaque produit
SELECT P.Produit, Periodes.Periode
FROM Produits P
CROSS APPLY (
    VALUES ('Matin'), ('Après-midi'), ('Soir')
) AS Periodes(Periode);
```

## 7. Performance et optimisation

### Conseils de performance

**1. Index appropriés**

Assurez-vous d'avoir des index sur les colonnes utilisées dans les conditions WHERE :

```sql
-- Cette requête bénéficiera d'un index sur Commandes(ClientID, DateCommande)
CREATE INDEX IX_Commandes_ClientID_DateCommande
ON Commandes(ClientID, DateCommande);

SELECT C.*, TopCmd.*
FROM Clients C
CROSS APPLY (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS TopCmd;
```

**2. Limiter les données tôt**

Filtrez dans la table source plutôt que dans APPLY :

```sql
-- ✅ Meilleur : Filtre avant APPLY
SELECT C.*, TopCmd.*
FROM Clients C
WHERE C.Actif = 1  -- Filtre ici
CROSS APPLY (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS TopCmd;

-- ❌ Moins bon : Plus de lignes traitées
SELECT C.*, TopCmd.*
FROM Clients C
CROSS APPLY (
    SELECT TOP 3 *
    FROM Commandes
    WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS TopCmd
WHERE C.Actif = 1;  -- Filtre après
```

**3. Éviter les APPLY inutiles**

Si un simple JOIN suffit, utilisez-le :

```sql
-- ❌ APPLY inutile ici
SELECT *
FROM Clients C
CROSS APPLY (
    SELECT * FROM Adresses WHERE ClientID = C.ClientID
) AS Adr;

-- ✅ JOIN plus simple et possiblement plus rapide
SELECT C.*, Adr.*
FROM Clients C
INNER JOIN Adresses Adr ON C.ClientID = Adr.ClientID;
```

**4. Analyser les plans d'exécution**

APPLY peut parfois être moins performant que d'autres approches. Comparez :

```sql
-- Méthode 1 : APPLY
SELECT C.*, Top3.*
FROM Clients C
CROSS APPLY (
    SELECT TOP 3 * FROM Commandes WHERE ClientID = C.ClientID
    ORDER BY DateCommande DESC
) AS Top3;

-- Méthode 2 : ROW_NUMBER avec CTE
WITH CommandesClassees AS (
    SELECT *,
        ROW_NUMBER() OVER(PARTITION BY ClientID ORDER BY DateCommande DESC) AS Rn
    FROM Commandes
)
SELECT C.*, Cmd.*
FROM Clients C
INNER JOIN CommandesClassees Cmd ON C.ClientID = Cmd.ClientID
WHERE Cmd.Rn <= 3;
```

Testez les deux et vérifiez les plans d'exécution !

### Pièges de performance

**❌ APPLY dans une boucle (très lent) :**

```sql
-- Ne faites JAMAIS cela !
DECLARE @ClientID INT;
DECLARE ClientCursor CURSOR FOR SELECT ClientID FROM Clients;
OPEN ClientCursor;
FETCH NEXT FROM ClientCursor INTO @ClientID;

WHILE @@FETCH_STATUS = 0
BEGIN
    SELECT * FROM Commandes WHERE ClientID = @ClientID; -- Mauvais !
    FETCH NEXT FROM ClientCursor INTO @ClientID;
END;
```

**✅ Utilisez APPLY directement :**

```sql
SELECT C.*, Cmd.*
FROM Clients C
CROSS APPLY (
    SELECT * FROM Commandes WHERE ClientID = C.ClientID
) AS Cmd;
```

## 8. Limitations et considérations

### Limitations de APPLY

**1. Ordre d'exécution**

APPLY est évalué **pour chaque ligne** de la table de gauche. Avec beaucoup de lignes, cela peut être coûteux.

**2. Pas de référence circulaire**

Vous ne pouvez pas référencer un alias d'APPLY dans la table source :

```sql
-- ❌ ERREUR
SELECT *
FROM Clients C
CROSS APPLY (SELECT * FROM Commandes WHERE ClientID = C.ClientID) AS Cmd
WHERE Cmd.Montant > 100;  -- Cmd n'est pas encore disponible ici

-- ✅ CORRECT : Filtrer après
SELECT *
FROM (
    SELECT C.*, Cmd.*
    FROM Clients C
    CROSS APPLY (SELECT * FROM Commandes WHERE ClientID = C.ClientID) AS Cmd
) AS Result
WHERE Montant > 100;
```

**3. Complexité pour les débutants**

APPLY peut être difficile à comprendre au début. Privilégiez la simplicité quand possible.

### Quand éviter APPLY

- Quand un simple JOIN fait l'affaire
- Quand les performances sont critiques et que d'autres méthodes sont plus rapides
- Quand la lisibilité du code est compromise
- Quand vous travaillez avec une équipe peu familière avec APPLY

## 9. Bonnes pratiques

### ✅ À faire

1. **Utiliser des noms d'alias clairs**
   ```sql
   CROSS APPLY (...) AS CommandesRecentes  -- ✅ Clair
   CROSS APPLY (...) AS X  -- ❌ Peu clair
   ```

2. **Commenter la logique complexe**
   ```sql
   -- Récupère les 5 produits les plus vendus pour chaque catégorie
   CROSS APPLY (
       SELECT TOP 5 * ...
   ) AS TopProduits
   ```

3. **Limiter les résultats avec TOP**
   ```sql
   -- Évite de retourner trop de lignes par groupe
   CROSS APPLY (SELECT TOP 10 * ...) AS Limited
   ```

4. **Encapsuler dans des fonctions table**
   ```sql
   -- Réutilisable et testable
   CROSS APPLY dbo.GetTopItems(C.ClientID, 5) AS TopItems
   ```

5. **Vérifier les plans d'exécution**
   - Comparer avec d'autres approches
   - Identifier les goulots d'étranglement

### ❌ À éviter

1. **APPLY quand JOIN suffit**
2. **Sous-requêtes trop complexes dans APPLY**
3. **APPLY sur des tables volumineuses sans index**
4. **APPLY imbriqués (plusieurs niveaux)**
5. **Oublier OUTER APPLY quand toutes les lignes sont nécessaires**

## Tableau récapitulatif

| Aspect | CROSS APPLY | OUTER APPLY | INNER/LEFT JOIN |
|--------|-------------|-------------|-----------------|
| **Lignes sans correspondance** | Exclues | Incluses (NULL) | Exclues / Incluses |
| **Référence colonnes gauche** | ✅ Oui | ✅ Oui | ❌ Non (dans FROM) |
| **TOP N par groupe** | ✅ Facile | ✅ Facile | ❌ Difficile |
| **Fonctions table paramétrées** | ✅ Oui | ✅ Oui | ❌ Non |
| **Expressions VALUES** | ✅ Oui | ✅ Oui | ❌ Non |
| **Performance simple** | Similaire | Similaire | Parfois meilleur |
| **Lisibilité** | Moyenne | Moyenne | Haute |

## Résumé

La clause **APPLY** est un outil puissant de T-SQL qui permet d'appliquer une expression de table à chaque ligne d'une table source.

**Points clés :**

**CROSS APPLY :**
- Équivalent à INNER JOIN avec plus de flexibilité
- Exclut les lignes sans correspondance
- Parfait pour TOP N par groupe

**OUTER APPLY :**
- Équivalent à LEFT OUTER JOIN avec plus de flexibilité
- Inclut toutes les lignes de gauche (avec NULL si nécessaire)
- Utile pour les statistiques avec valeurs par défaut

**Cas d'usage principaux :**
- Top N par catégorie/groupe
- Appel de fonctions table paramétrées
- Calculs dynamiques par ligne
- Décomposition de chaînes
- Génération de séries

**Avantages :**
- Référencer les colonnes de la table de gauche
- Logique complexe par ligne
- Code souvent plus concis que les alternatives

**Considérations :**
- Vérifier les performances (comparer avec JOIN ou ROW_NUMBER)
- Utiliser des index appropriés
- Préférer JOIN quand APPLY n'apporte rien

**Quand utiliser APPLY :**
- TOP N par groupe
- Fonctions table avec paramètres provenant de chaque ligne
- Calculs complexes nécessitant les valeurs de la ligne courante

APPLY est un outil avancé qui, utilisé correctement, peut simplifier considérablement des requêtes complexes et améliorer la lisibilité du code !
