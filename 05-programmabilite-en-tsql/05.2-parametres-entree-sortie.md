# 5.5.2 Paramètres d'Entrée (Input) et de Sortie (OUTPUT)

## Introduction

Les paramètres sont essentiels pour rendre les procédures stockées **flexibles** et **réutilisables**. Ils permettent de passer des informations à la procédure (paramètres d'entrée) et de récupérer des résultats calculés (paramètres de sortie).

Dans cette section, nous allons explorer en profondeur ces deux types de paramètres et apprendre à les utiliser efficacement.

---

## 1. Paramètres d'Entrée (Input Parameters)

### 1.1 Qu'est-ce qu'un Paramètre d'Entrée ?

Un **paramètre d'entrée** (ou *input parameter*) est une valeur que vous passez à la procédure lors de son exécution. C'est le type de paramètre le plus courant et le plus simple à comprendre.

**Analogie :** C'est comme les **ingrédients** d'une recette de cuisine :
- Vous donnez les ingrédients (paramètres) à la recette (procédure)
- La recette utilise ces ingrédients pour préparer le plat (résultat)

### 1.2 Syntaxe de Base

```sql
CREATE PROCEDURE nom_procedure
    @parametre1 type_donnees,
    @parametre2 type_donnees,
    @parametre3 type_donnees
AS
BEGIN
    -- Utilisation des paramètres
END;
```

**Note :** Par défaut, tous les paramètres sont des **paramètres d'entrée**.

---

### 1.3 Exemple Simple : Recherche par ID

```sql
-- Procédure avec un paramètre d'entrée
CREATE PROCEDURE SpObtenirClientParID
    @ClientID INT  -- Paramètre d'entrée
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Ville
    FROM Clients
    WHERE ClientID = @ClientID;
END;
```

**Exécution :**

```sql
-- Passer la valeur 5 au paramètre @ClientID
EXEC SpObtenirClientParID @ClientID = 5;
```

**Résultat :** La procédure retourne les informations du client ayant l'ID 5.

---

### 1.4 Exemple avec Plusieurs Paramètres d'Entrée

```sql
-- Procédure avec plusieurs paramètres
CREATE PROCEDURE SpRechercherProduits
    @Categorie VARCHAR(50),
    @PrixMin DECIMAL(10,2),
    @PrixMax DECIMAL(10,2)
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ProduitID,
        NomProduit,
        Categorie,
        Prix,
        StockDisponible
    FROM Produits
    WHERE
        Categorie = @Categorie
        AND Prix BETWEEN @PrixMin AND @PrixMax
    ORDER BY Prix;
END;
```

**Exécution :**

```sql
-- Rechercher les produits électroniques entre 100€ et 500€
EXEC SpRechercherProduits
    @Categorie = 'Électronique',
    @PrixMin = 100,
    @PrixMax = 500;
```

---

### 1.5 Paramètres d'Entrée avec Valeurs Par Défaut

Vous pouvez définir des **valeurs par défaut** pour rendre certains paramètres **optionnels**.

```sql
-- Procédure avec paramètres optionnels
CREATE PROCEDURE SpListerClients
    @Ville VARCHAR(50) = NULL,        -- Optionnel
    @Actif BIT = 1,                   -- Valeur par défaut : 1
    @TriPar VARCHAR(20) = 'Nom'       -- Valeur par défaut : 'Nom'
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        ClientID,
        Nom,
        Prenom,
        Email,
        Ville,
        Actif
    FROM Clients
    WHERE
        (@Ville IS NULL OR Ville = @Ville)
        AND Actif = @Actif
    ORDER BY
        CASE
            WHEN @TriPar = 'Nom' THEN Nom
            WHEN @TriPar = 'Ville' THEN Ville
            ELSE Nom
        END;
END;
```

**Différentes façons d'exécuter :**

```sql
-- Sans aucun paramètre (tous par défaut)
EXEC SpListerClients;
-- Résultat : Tous les clients actifs, triés par nom

-- Avec le filtre ville uniquement
EXEC SpListerClients @Ville = 'Paris';
-- Résultat : Clients actifs de Paris, triés par nom

-- Avec plusieurs paramètres
EXEC SpListerClients
    @Ville = 'Lyon',
    @Actif = 0,
    @TriPar = 'Ville';
-- Résultat : Clients inactifs de Lyon, triés par ville

-- Paramètre par position (déconseillé avec valeurs par défaut)
EXEC SpListerClients 'Marseille', 1, 'Nom';
```

**Bonne pratique :** Utilisez toujours le passage par nom quand vous avez des paramètres optionnels.

---

### 1.6 Utilisation des Paramètres dans les Calculs

Les paramètres d'entrée peuvent être utilisés dans des calculs et des traitements :

```sql
-- Procédure calculant une remise
CREATE PROCEDURE SpCalculerPrixAvecRemise
    @PrixOriginal DECIMAL(10,2),
    @PourcentageRemise DECIMAL(5,2)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @MontantRemise DECIMAL(10,2);
    DECLARE @PrixFinal DECIMAL(10,2);

    -- Calculs utilisant les paramètres d'entrée
    SET @MontantRemise = @PrixOriginal * (@PourcentageRemise / 100);
    SET @PrixFinal = @PrixOriginal - @MontantRemise;

    -- Afficher les résultats
    SELECT
        @PrixOriginal AS PrixOriginal,
        @PourcentageRemise AS RemisePourcent,
        @MontantRemise AS MontantRemise,
        @PrixFinal AS PrixFinal;
END;
```

**Exécution :**

```sql
EXEC SpCalculerPrixAvecRemise
    @PrixOriginal = 250.00,
    @PourcentageRemise = 15;
```

**Résultat :**
```
PrixOriginal | RemisePourcent | MontantRemise | PrixFinal
250.00       | 15.00          | 37.50         | 212.50
```

## 2. Paramètres de Sortie (OUTPUT Parameters)

### 2.1 Qu'est-ce qu'un Paramètre de Sortie ?

Un **paramètre de sortie** (ou *output parameter*) permet à la procédure de **retourner une valeur calculée** à l'appelant. Contrairement aux paramètres d'entrée qui sont en lecture seule, les paramètres de sortie peuvent être **modifiés** par la procédure et leur valeur est **retournée** après l'exécution.

**Analogie :** C'est comme une **balance de cuisine** :
- Vous mettez les ingrédients (entrée)
- La balance vous donne le poids (sortie)

### 2.2 Syntaxe

```sql
CREATE PROCEDURE nom_procedure
    @parametre_entree type,
    @parametre_sortie type OUTPUT  -- Mot-clé OUTPUT
AS
BEGIN
    -- Modifier @parametre_sortie
    SET @parametre_sortie = valeur_calculee;
END;
```

**Points clés :**
- Le mot-clé `OUTPUT` (ou `OUT`) est obligatoire dans la définition
- Le mot-clé `OUTPUT` doit aussi être utilisé lors de l'exécution

---

### 2.3 Exemple Simple : Compter les Clients

```sql
-- Procédure avec un paramètre de sortie
CREATE PROCEDURE SpCompterClients
    @NombreTotal INT OUTPUT  -- Paramètre de sortie
AS
BEGIN
    SET NOCOUNT ON;

    -- Calculer et stocker dans le paramètre de sortie
    SELECT @NombreTotal = COUNT(*)
    FROM Clients;
END;
```

**Exécution :**

```sql
-- Déclarer une variable pour recevoir le résultat
DECLARE @Resultat INT;

-- Exécuter la procédure en passant la variable OUTPUT
EXEC SpCompterClients @NombreTotal = @Resultat OUTPUT;

-- Afficher le résultat
PRINT 'Nombre total de clients : ' + CAST(@Resultat AS VARCHAR(10));
```

**Résultat :**
```
Nombre total de clients : 150
```

**Important :**
1. Vous devez déclarer une variable pour recevoir la valeur
2. Le mot-clé `OUTPUT` doit être présent lors de l'appel

---

### 2.4 Exemple avec Entrée et Sortie

Souvent, vous aurez à la fois des paramètres d'entrée et de sortie :

```sql
-- Procédure avec entrée ET sortie
CREATE PROCEDURE SpCompterCommandesClient
    @ClientID INT,              -- Paramètre d'entrée
    @NombreCommandes INT OUTPUT -- Paramètre de sortie
AS
BEGIN
    SET NOCOUNT ON;

    -- Compter les commandes pour ce client
    SELECT @NombreCommandes = COUNT(*)
    FROM Commandes
    WHERE ClientID = @ClientID;
END;
```

**Exécution :**

```sql
-- Variable pour le résultat
DECLARE @NbCommandes INT;

-- Exécuter avec entrée et sortie
EXEC SpCompterCommandesClient
    @ClientID = 5,                      -- Entrée
    @NombreCommandes = @NbCommandes OUTPUT;  -- Sortie

-- Utiliser le résultat
PRINT 'Le client 5 a ' + CAST(@NbCommandes AS VARCHAR(10)) + ' commandes';
```

---

### 2.5 Exemple : Multiples Paramètres de Sortie

Une procédure peut avoir plusieurs paramètres de sortie :

```sql
-- Procédure avec plusieurs sorties
CREATE PROCEDURE SpStatistiquesClient
    @ClientID INT,                     -- Entrée
    @NombreCommandes INT OUTPUT,       -- Sortie 1
    @TotalAchats DECIMAL(10,2) OUTPUT, -- Sortie 2
    @DerniereCommande DATE OUTPUT      -- Sortie 3
AS
BEGIN
    SET NOCOUNT ON;

    -- Calculer toutes les statistiques
    SELECT
        @NombreCommandes = COUNT(*),
        @TotalAchats = ISNULL(SUM(MontantTotal), 0),
        @DerniereCommande = MAX(DateCommande)
    FROM Commandes
    WHERE ClientID = @ClientID;
END;
```

**Exécution :**

```sql
-- Déclarer des variables pour tous les résultats
DECLARE @NbCmd INT;
DECLARE @Total DECIMAL(10,2);
DECLARE @Derniere DATE;

-- Exécuter la procédure
EXEC SpStatistiquesClient
    @ClientID = 5,
    @NombreCommandes = @NbCmd OUTPUT,
    @TotalAchats = @Total OUTPUT,
    @DerniereCommande = @Derniere OUTPUT;

-- Afficher tous les résultats
PRINT 'Statistiques du client 5 :';
PRINT 'Nombre de commandes : ' + CAST(@NbCmd AS VARCHAR(10));
PRINT 'Total des achats : ' + CAST(@Total AS VARCHAR(20)) + '€';
PRINT 'Dernière commande : ' + CAST(@Derniere AS VARCHAR(20));
```

**Résultat :**
```
Statistiques du client 5 :
Nombre de commandes : 12
Total des achats : 3450.75€
Dernière commande : 2024-11-15
```

---

### 2.6 Paramètre à la fois Entrée ET Sortie

Un paramètre peut servir à la fois d'entrée et de sortie. La valeur initiale est utilisée, puis modifiée :

```sql
-- Paramètre INPUT/OUTPUT
CREATE PROCEDURE SpAppliquerTVA
    @Montant DECIMAL(10,2) OUTPUT  -- Entrée ET sortie
AS
BEGIN
    SET NOCOUNT ON;

    -- Utiliser la valeur d'entrée et la modifier
    SET @Montant = @Montant * 1.20;  -- Ajouter 20% de TVA
END;
```

**Exécution :**

```sql
-- Variable avec valeur initiale
DECLARE @Prix DECIMAL(10,2) = 100.00;

PRINT 'Prix HT : ' + CAST(@Prix AS VARCHAR(20));

-- Appliquer la TVA
EXEC SpAppliquerTVA @Montant = @Prix OUTPUT;

PRINT 'Prix TTC : ' + CAST(@Prix AS VARCHAR(20));
```

**Résultat :**
```
Prix HT : 100.00
Prix TTC : 120.00
```

## 3. Comparaison : Paramètres d'Entrée vs Sortie

| Aspect | Paramètre d'Entrée | Paramètre de Sortie |
|--------|-------------------|---------------------|
| **Mot-clé** | Aucun (par défaut) | `OUTPUT` ou `OUT` |
| **Direction** | Appelant → Procédure | Procédure → Appelant |
| **Modification** | Lecture seule (dans la pratique) | Modifiable |
| **Utilisation** | Passer des données | Retourner des résultats |
| **Variable nécessaire** | Non | Oui (pour recevoir) |
| **Exemple** | `@ClientID INT` | `@Total INT OUTPUT` |

## 4. Cas d'Usage Pratiques

### 4.1 Validation et Notification d'Erreur

Utiliser un paramètre de sortie pour indiquer le succès ou l'échec :

```sql
-- Procédure avec indicateur de succès
CREATE PROCEDURE SpCreerClient
    @Nom VARCHAR(50),
    @Prenom VARCHAR(50),
    @Email VARCHAR(100),
    @ClientID INT OUTPUT,          -- ID du client créé
    @MessageErreur VARCHAR(255) OUTPUT  -- Message d'erreur éventuel
AS
BEGIN
    SET NOCOUNT ON;

    -- Initialiser les valeurs de sortie
    SET @ClientID = NULL;
    SET @MessageErreur = NULL;

    -- Validation : Email existe déjà ?
    IF EXISTS (SELECT 1 FROM Clients WHERE Email = @Email)
    BEGIN
        SET @MessageErreur = 'Erreur : Cet email existe déjà';
        RETURN;
    END

    -- Validation : Nom et prénom non vides
    IF @Nom = '' OR @Prenom = ''
    BEGIN
        SET @MessageErreur = 'Erreur : Nom et prénom obligatoires';
        RETURN;
    END

    -- Créer le client
    INSERT INTO Clients (Nom, Prenom, Email, DateInscription)
    VALUES (@Nom, @Prenom, @Email, GETDATE());

    -- Récupérer l'ID généré
    SET @ClientID = SCOPE_IDENTITY();
    SET @MessageErreur = 'Client créé avec succès';
END;
```

**Exécution :**

```sql
-- Variables pour les résultats
DECLARE @NouveauClientID INT;
DECLARE @Message VARCHAR(255);

-- Tenter de créer un client
EXEC SpCreerClient
    @Nom = 'Martin',
    @Prenom = 'Sophie',
    @Email = 'sophie.martin@email.com',
    @ClientID = @NouveauClientID OUTPUT,
    @MessageErreur = @Message OUTPUT;

-- Vérifier le résultat
IF @NouveauClientID IS NOT NULL
BEGIN
    PRINT 'Succès ! ID du nouveau client : ' + CAST(@NouveauClientID AS VARCHAR(10));
END
ELSE
BEGIN
    PRINT 'Échec : ' + @Message;
END
```

### 4.2 Calculs Complexes avec Plusieurs Résultats

```sql
-- Procédure de calcul de facture
CREATE PROCEDURE SpCalculerFacture
    @CommandeID INT,
    @MontantHT DECIMAL(10,2) OUTPUT,
    @MontantTVA DECIMAL(10,2) OUTPUT,
    @MontantTTC DECIMAL(10,2) OUTPUT,
    @FraisLivraison DECIMAL(10,2) OUTPUT,
    @MontantFinal DECIMAL(10,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @TauxTVA DECIMAL(5,2) = 0.20;  -- 20%

    -- Calculer le montant HT
    SELECT @MontantHT = SUM(Quantite * PrixUnitaire)
    FROM DetailsCommande
    WHERE CommandeID = @CommandeID;

    -- Si pas de commande trouvée
    IF @MontantHT IS NULL
    BEGIN
        SET @MontantHT = 0;
        SET @MontantTVA = 0;
        SET @MontantTTC = 0;
        SET @FraisLivraison = 0;
        SET @MontantFinal = 0;
        RETURN;
    END

    -- Calculer la TVA
    SET @MontantTVA = @MontantHT * @TauxTVA;

    -- Calculer TTC
    SET @MontantTTC = @MontantHT + @MontantTVA;

    -- Calculer frais de livraison (gratuit si > 50€)
    IF @MontantTTC > 50
        SET @FraisLivraison = 0;
    ELSE
        SET @FraisLivraison = 5.99;

    -- Montant final
    SET @MontantFinal = @MontantTTC + @FraisLivraison;
END;
```

**Exécution :**

```sql
-- Variables pour tous les résultats
DECLARE @HT DECIMAL(10,2);
DECLARE @TVA DECIMAL(10,2);
DECLARE @TTC DECIMAL(10,2);
DECLARE @Livraison DECIMAL(10,2);
DECLARE @Final DECIMAL(10,2);

-- Calculer la facture
EXEC SpCalculerFacture
    @CommandeID = 123,
    @MontantHT = @HT OUTPUT,
    @MontantTVA = @TVA OUTPUT,
    @MontantTTC = @TTC OUTPUT,
    @FraisLivraison = @Livraison OUTPUT,
    @MontantFinal = @Final OUTPUT;

-- Afficher la facture
PRINT '=== FACTURE ===';
PRINT 'Montant HT    : ' + CAST(@HT AS VARCHAR(20)) + '€';
PRINT 'TVA (20%)     : ' + CAST(@TVA AS VARCHAR(20)) + '€';
PRINT 'Montant TTC   : ' + CAST(@TTC AS VARCHAR(20)) + '€';
PRINT 'Frais livraison: ' + CAST(@Livraison AS VARCHAR(20)) + '€';
PRINT '================';
PRINT 'TOTAL À PAYER : ' + CAST(@Final AS VARCHAR(20)) + '€';
```

### 4.3 Opération avec Compteur

Retourner le nombre de lignes affectées :

```sql
-- Procédure de mise à jour en masse
CREATE PROCEDURE SpActiverClientsVille
    @Ville VARCHAR(50),
    @NombreActives INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    -- Activer tous les clients de la ville
    UPDATE Clients
    SET Actif = 1
    WHERE Ville = @Ville AND Actif = 0;

    -- Retourner le nombre de lignes affectées
    SET @NombreActives = @@ROWCOUNT;
END;
```

**Exécution :**

```sql
DECLARE @NbActives INT;

EXEC SpActiverClientsVille
    @Ville = 'Paris',
    @NombreActives = @NbActives OUTPUT;

PRINT CAST(@NbActives AS VARCHAR(10)) + ' clients ont été activés à Paris';
```

## 5. Erreurs Courantes à Éviter

### Erreur 1 : Oublier le mot-clé OUTPUT lors de l'appel

```sql
-- ❌ ERREUR : Oubli du mot-clé OUTPUT
DECLARE @Total INT;
EXEC SpCompterClients @NombreTotal = @Total;  -- OUTPUT manquant !
-- Résultat : @Total reste NULL

-- ✅ CORRECT
DECLARE @Total INT;
EXEC SpCompterClients @NombreTotal = @Total OUTPUT;
```

### Erreur 2 : Ne pas déclarer de variable pour recevoir

```sql
-- ❌ ERREUR : Pas de variable
EXEC SpCompterClients @NombreTotal = OUTPUT;  -- Impossible !

-- ✅ CORRECT
DECLARE @Resultat INT;
EXEC SpCompterClients @NombreTotal = @Resultat OUTPUT;
```

### Erreur 3 : Oublier d'initialiser le paramètre de sortie

```sql
-- ⚠️ ATTENTION : Ne pas laisser un paramètre de sortie non initialisé
CREATE PROCEDURE SpMauvaisExemple
    @Resultat INT OUTPUT
AS
BEGIN
    -- Si la condition n'est jamais vraie, @Resultat reste NULL
    IF 1 = 2
        SET @Resultat = 100;
    -- @Resultat n'est pas initialisé dans tous les cas !
END;

-- ✅ BONNE PRATIQUE : Toujours initialiser
CREATE PROCEDURE SpBonExemple
    @Resultat INT OUTPUT
AS
BEGIN
    SET @Resultat = 0;  -- Initialisation par défaut

    IF EXISTS (SELECT 1 FROM Clients)
        SET @Resultat = 100;
END;
```

### Erreur 4 : Confondre OUTPUT et RETURN

```sql
-- ❌ ERREUR CONCEPTUELLE
CREATE PROCEDURE SpConfusion
    @Total INT OUTPUT
AS
BEGIN
    SELECT @Total = COUNT(*) FROM Clients;
    RETURN @Total;  -- RETURN et OUTPUT sont différents !
END;

-- ✅ CORRECT : Choisir l'un ou l'autre
CREATE PROCEDURE SpAvecOutput
    @Total INT OUTPUT
AS
BEGIN
    SELECT @Total = COUNT(*) FROM Clients;
    -- Pas de RETURN nécessaire pour OUTPUT
END;
```

## 6. Paramètres OUTPUT vs SELECT vs RETURN

Il existe trois façons principales de retourner des données depuis une procédure. Voyons leurs différences :

### Méthode 1 : SELECT (Jeu de résultats)

```sql
CREATE PROCEDURE SpAvecSelect
    @ClientID INT
AS
BEGIN
    SELECT Nom, Prenom, Email
    FROM Clients
    WHERE ClientID = @ClientID;
END;

-- Utilisation
EXEC SpAvecSelect @ClientID = 5;
-- Retourne un jeu de résultats (comme une requête normale)
```

**Quand utiliser :**
- ✅ Pour retourner plusieurs lignes
- ✅ Pour des données tabulaires
- ✅ Pour affichage direct

### Méthode 2 : OUTPUT (Paramètre de sortie)

```sql
CREATE PROCEDURE SpAvecOutput
    @ClientID INT,
    @NomComplet VARCHAR(100) OUTPUT
AS
BEGIN
    SELECT @NomComplet = Nom + ' ' + Prenom
    FROM Clients
    WHERE ClientID = @ClientID;
END;

-- Utilisation
DECLARE @Nom VARCHAR(100);
EXEC SpAvecOutput @ClientID = 5, @NomComplet = @Nom OUTPUT;
-- @Nom contient maintenant le nom complet
```

**Quand utiliser :**
- ✅ Pour retourner 1 ou quelques valeurs simples
- ✅ Pour des valeurs calculées
- ✅ Pour utilisation dans d'autres traitements

### Méthode 3 : RETURN (Code de retour)

```sql
CREATE PROCEDURE SpAvecReturn
    @ClientID INT
AS
BEGIN
    IF EXISTS (SELECT 1 FROM Clients WHERE ClientID = @ClientID)
        RETURN 1;  -- Client trouvé
    ELSE
        RETURN 0;  -- Client non trouvé
END;

-- Utilisation
DECLARE @CodeRetour INT;
EXEC @CodeRetour = SpAvecReturn @ClientID = 5;
-- @CodeRetour contient 1 ou 0
```

**Quand utiliser :**
- ✅ Pour codes d'état (succès/échec)
- ✅ Pour valeurs entières uniquement
- ⚠️ Limité à INT

**Note :** RETURN sera détaillé dans la section 5.5.3.

---

### Tableau Comparatif

| Aspect | SELECT | OUTPUT | RETURN |
|--------|--------|--------|--------|
| **Type de données** | Jeu de résultats | N'importe quel type | INT uniquement |
| **Quantité** | Plusieurs lignes/colonnes | 1 ou plusieurs valeurs | 1 valeur |
| **Usage principal** | Affichage, rapports | Calculs, valeurs uniques | Codes d'état |
| **Assignation à variable** | Complexe | ✅ Direct | ✅ Direct |
| **Plusieurs valeurs** | ✅ Oui | ✅ Oui (plusieurs params) | ❌ Non |
| **Exemple** | Liste de clients | Nombre de commandes | 0 = échec, 1 = succès |

## 7. Exemple Complet : Transaction Bancaire

Voici un exemple réaliste combinant plusieurs concepts :

```sql
-- Procédure de transfert d'argent
CREATE PROCEDURE SpTransfertArgent
    @CompteSource INT,           -- Entrée : compte à débiter
    @CompteDestination INT,      -- Entrée : compte à créditer
    @Montant DECIMAL(10,2),      -- Entrée : montant à transférer
    @NouveauSoldeSource DECIMAL(10,2) OUTPUT,    -- Sortie : nouveau solde source
    @NouveauSoldeDestination DECIMAL(10,2) OUTPUT, -- Sortie : nouveau solde destination
    @MessageErreur VARCHAR(255) OUTPUT            -- Sortie : message d'erreur
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @SoldeActuelSource DECIMAL(10,2);

    -- Initialiser les sorties
    SET @NouveauSoldeSource = NULL;
    SET @NouveauSoldeDestination = NULL;
    SET @MessageErreur = NULL;

    -- Validation 1 : Montant positif
    IF @Montant <= 0
    BEGIN
        SET @MessageErreur = 'Le montant doit être positif';
        RETURN;
    END

    -- Validation 2 : Comptes différents
    IF @CompteSource = @CompteDestination
    BEGIN
        SET @MessageErreur = 'Impossible de transférer vers le même compte';
        RETURN;
    END

    -- Validation 3 : Compte source existe et est actif
    IF NOT EXISTS (
        SELECT 1 FROM Comptes
        WHERE CompteID = @CompteSource AND Actif = 1
    )
    BEGIN
        SET @MessageErreur = 'Compte source invalide ou inactif';
        RETURN;
    END

    -- Validation 4 : Compte destination existe et est actif
    IF NOT EXISTS (
        SELECT 1 FROM Comptes
        WHERE CompteID = @CompteDestination AND Actif = 1
    )
    BEGIN
        SET @MessageErreur = 'Compte destination invalide ou inactif';
        RETURN;
    END

    -- Validation 5 : Solde suffisant
    SELECT @SoldeActuelSource = Solde
    FROM Comptes
    WHERE CompteID = @CompteSource;

    IF @SoldeActuelSource < @Montant
    BEGIN
        SET @MessageErreur = 'Solde insuffisant';
        RETURN;
    END

    -- Effectuer le transfert
    BEGIN TRANSACTION;

    BEGIN TRY
        -- Débiter le compte source
        UPDATE Comptes
        SET Solde = Solde - @Montant
        WHERE CompteID = @CompteSource;

        -- Créditer le compte destination
        UPDATE Comptes
        SET Solde = Solde + @Montant
        WHERE CompteID = @CompteDestination;

        -- Enregistrer la transaction
        INSERT INTO Transactions (CompteSourceID, CompteDestID, Montant, DateTransaction)
        VALUES (@CompteSource, @CompteDestination, @Montant, GETDATE());

        -- Récupérer les nouveaux soldes
        SELECT @NouveauSoldeSource = Solde
        FROM Comptes
        WHERE CompteID = @CompteSource;

        SELECT @NouveauSoldeDestination = Solde
        FROM Comptes
        WHERE CompteID = @CompteDestination;

        -- Valider la transaction
        COMMIT TRANSACTION;

        SET @MessageErreur = 'Transfert effectué avec succès';

    END TRY
    BEGIN CATCH
        -- En cas d'erreur, annuler
        ROLLBACK TRANSACTION;
        SET @MessageErreur = 'Erreur lors du transfert : ' + ERROR_MESSAGE();
    END CATCH
END;
```

**Utilisation :**

```sql
-- Variables pour les résultats
DECLARE @SoldeSource DECIMAL(10,2);
DECLARE @SoldeDestination DECIMAL(10,2);
DECLARE @Message VARCHAR(255);

-- Effectuer le transfert
EXEC SpTransfertArgent
    @CompteSource = 101,
    @CompteDestination = 202,
    @Montant = 150.00,
    @NouveauSoldeSource = @SoldeSource OUTPUT,
    @NouveauSoldeDestination = @SoldeDestination OUTPUT,
    @MessageErreur = @Message OUTPUT;

-- Afficher les résultats
PRINT '=== RÉSULTAT DU TRANSFERT ===';
PRINT @Message;

IF @SoldeSource IS NOT NULL
BEGIN
    PRINT 'Nouveau solde compte source : ' + CAST(@SoldeSource AS VARCHAR(20)) + '€';
    PRINT 'Nouveau solde compte destination : ' + CAST(@SoldeDestination AS VARCHAR(20)) + '€';
END
```

## 8. Bonnes Pratiques

### ✅ À FAIRE

1. **Toujours initialiser les paramètres OUTPUT**
   ```sql
   CREATE PROCEDURE SpExemple
       @Resultat INT OUTPUT
   AS
   BEGIN
       SET @Resultat = 0;  -- Initialisation par défaut
       -- Reste du code
   END;
   ```

2. **Utiliser des noms explicites**
   ```sql
   -- ✅ BON
   @NombreClientsActifs INT OUTPUT
   @MontantTotalTTC DECIMAL(10,2) OUTPUT

   -- ❌ MAUVAIS
   @Nb INT OUTPUT
   @Total DECIMAL(10,2) OUTPUT
   ```

3. **Documenter les paramètres OUTPUT**
   ```sql
   /*
   Paramètres de sortie :
       @ClientID - ID du client créé (NULL en cas d'échec)
       @MessageErreur - Message d'erreur ou de succès
   */
   ```

4. **Utiliser OUTPUT pour les valeurs calculées**
   - Nombres
   - Indicateurs de succès/échec
   - IDs générés

5. **Préférer SELECT pour les jeux de données**
   - Listes de résultats
   - Rapports
   - Données tabulaires

### ❌ À ÉVITER

1. **Ne pas oublier OUTPUT lors de l'appel**
   ```sql
   -- ❌ ERREUR
   EXEC SpProcedure @Param = @Variable;

   -- ✅ CORRECT
   EXEC SpProcedure @Param = @Variable OUTPUT;
   ```

2. **Ne pas utiliser trop de paramètres OUTPUT**
   ```sql
   -- ❌ MAUVAIS : Trop de paramètres (difficile à utiliser)
   CREATE PROCEDURE SpTropDeParams
       @Out1 INT OUTPUT,
       @Out2 INT OUTPUT,
       @Out3 INT OUTPUT,
       @Out4 INT OUTPUT,
       @Out5 INT OUTPUT,
       @Out6 INT OUTPUT,
       @Out7 INT OUTPUT

   -- ✅ MIEUX : Retourner un SELECT ou diviser en plusieurs procédures
   ```

3. **Ne pas mélanger OUTPUT avec de multiples SELECT**
   - Soit vous utilisez OUTPUT pour retourner des valeurs simples
   - Soit vous utilisez SELECT pour des jeux de résultats
   - Mélanger les deux peut créer de la confusion

## 9. Cas d'Usage : Quand Utiliser OUTPUT

### ✅ Utilisez OUTPUT pour :

1. **Retourner des valeurs calculées uniques**
   ```sql
   @TotalVentes DECIMAL(10,2) OUTPUT
   @NombreCommandes INT OUTPUT
   ```

2. **Retourner des IDs générés**
   ```sql
   @NouveauClientID INT OUTPUT
   ```

3. **Retourner des messages de statut**
   ```sql
   @MessageErreur VARCHAR(255) OUTPUT
   @CodeStatut INT OUTPUT
   ```

4. **Retourner plusieurs valeurs simples**
   ```sql
   @Min DECIMAL(10,2) OUTPUT,
   @Max DECIMAL(10,2) OUTPUT,
   @Moyenne DECIMAL(10,2) OUTPUT
   ```

### ❌ N'utilisez PAS OUTPUT pour :

1. **Retourner des listes de données**
   - Utilisez plutôt SELECT

2. **Retourner des structures complexes**
   - Utilisez plutôt SELECT avec plusieurs colonnes

3. **Retourner simplement un code de succès/échec**
   - Utilisez plutôt RETURN (section 5.5.3)

## Résumé

### Points Clés

**Paramètres d'entrée (INPUT) :**
- Type par défaut (pas de mot-clé spécial)
- Permettent de passer des données à la procédure
- Peuvent avoir des valeurs par défaut (optionnels)
- Syntaxe : `@parametre type`

**Paramètres de sortie (OUTPUT) :**
- Nécessitent le mot-clé `OUTPUT` ou `OUT`
- Permettent de retourner des valeurs calculées
- Doivent être utilisés avec une variable lors de l'appel
- Syntaxe : `@parametre type OUTPUT`

**Différences clés :**
```sql
-- Entrée
@ClientID INT

-- Sortie
@Total INT OUTPUT

-- Entrée avec défaut
@Ville VARCHAR(50) = NULL

-- Entrée ET sortie
@Montant DECIMAL(10,2) OUTPUT
```

**Bonne pratique générale :**
- Paramètres INPUT : pour les filtres et les données nécessaires
- Paramètres OUTPUT : pour 1 à 5 valeurs simples calculées
- SELECT : pour des jeux de résultats tabulaires
- RETURN : pour des codes d'état (0/1, succès/échec)

Les paramètres INPUT et OUTPUT sont essentiels pour créer des procédures stockées flexibles et réutilisables. Maîtriser leur utilisation vous permettra de concevoir des procédures robustes et faciles à utiliser !
