# 4.1.3 LEFT (OUTER) JOIN

## Introduction

Vous avez appris que l'INNER JOIN ne retourne que les lignes ayant une correspondance dans **les deux tables**. Mais que se passe-t-il si vous voulez conserver **toutes les lignes d'une table**, même celles qui n'ont pas de correspondance dans l'autre table ?

C'est exactement le rôle du **LEFT JOIN** (aussi appelé LEFT OUTER JOIN) !

Le LEFT JOIN est l'une des jointures les plus utiles en SQL. Il permet de répondre à des questions comme :
- "Quels sont **tous mes clients**, même ceux qui n'ont jamais passé de commande ?"
- "Tous nos produits, y compris ceux qui n'ont jamais été vendus"
- "Tous les employés, même ceux qui ne sont pas encore assignés à un département"

---

## Qu'est-ce qu'un LEFT JOIN ?

### Définition

Un **LEFT JOIN** retourne :
- **Toutes les lignes de la table de gauche** (première table mentionnée)
- Les lignes correspondantes de la table de droite
- Pour les lignes de gauche sans correspondance à droite, les colonnes de droite contiendront `NULL`

En termes simples : **la table de gauche est complètement préservée**, qu'il y ait ou non des correspondances dans la table de droite.

### Analogie visuelle : Le diagramme de Venn

```
        Table GAUCHE         Table DROITE
          (A)                    (B)
          ___                    ___
         /   \                  /   \
        |     \                /     |
        |      \    ____      /      |
        |       \  /    \    /       |
        |  ████████████  \  /        |
        |  ████████████  \/         |
        |  ████████████  /\          |
        |       /  \____/  \         |
        |      /            \        |
        |     /              \       |
         \___/                \___/

    LEFT JOIN = Toute la table A + intersection
```

Le LEFT JOIN retourne :
- ✅ **Toute la partie gauche** (table A complète)
- ✅ **L'intersection** (les correspondances)
- ❌ **Seulement la partie droite** qui correspond (pas le reste de B)

---

## Syntaxe du LEFT JOIN

### Syntaxe de base

```sql
SELECT colonnes
FROM TableGauche
LEFT JOIN TableDroite ON condition_de_jointure;
```

ou de manière plus explicite (strictement équivalent) :

```sql
SELECT colonnes
FROM TableGauche
LEFT OUTER JOIN TableDroite ON condition_de_jointure;
```

### Note sur OUTER

Le mot-clé `OUTER` est optionnel. Ces deux syntaxes sont identiques :
- `LEFT JOIN` (forme abrégée, la plus courante)
- `LEFT OUTER JOIN` (forme complète, plus explicite)

**En pratique**, on utilise généralement `LEFT JOIN` pour sa concision.

---

## Exemple complet et détaillé

### Contexte : Tables de départ

Reprenons nos tables d'exemple, mais observons bien les particularités :

**Table `Clients`** (Table de GAUCHE)

| ClientID | NomClient | Ville      |
|----------|-----------|------------|
| 1        | Dupont    | Paris      |
| 2        | Martin    | Lyon       |
| 3        | Bernard   | Marseille  |
| 4        | Dubois    | Toulouse   |

**Table `Commandes`** (Table de DROITE)

| CommandeID | ClientID | Montant | DateCommande |
|------------|----------|---------|--------------|
| 101        | 1        | 150€    | 2025-01-15   |
| 102        | 2        | 200€    | 2025-01-16   |
| 103        | 1        | 75€     | 2025-01-17   |

### Observations clés

- **Dupont** (ID=1) a passé **2 commandes**
- **Martin** (ID=2) a passé **1 commande**
- **Bernard** (ID=3) n'a passé **AUCUNE commande**
- **Dubois** (ID=4) n'a passé **AUCUNE commande**

### Rappel : Requête avec INNER JOIN

```sql
SELECT
    C.ClientID,
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Résultat INNER JOIN** (3 lignes)

| ClientID | NomClient | CommandeID | Montant |
|----------|-----------|------------|---------|
| 1        | Dupont    | 101        | 150€    |
| 1        | Dupont    | 103        | 75€     |
| 2        | Martin    | 102        | 200€    |

❌ Bernard et Dubois sont **absents** car ils n'ont pas de commandes.

### Requête avec LEFT JOIN

```sql
SELECT
    C.ClientID,
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Résultat LEFT JOIN** (5 lignes)

| ClientID | NomClient | CommandeID | Montant |
|----------|-----------|------------|---------|
| 1        | Dupont    | 101        | 150€    |
| 1        | Dupont    | 103        | 75€     |
| 2        | Martin    | 102        | 200€    |
| 3        | Bernard   | NULL       | NULL    |
| 4        | Dubois    | NULL       | NULL    |

### Analyse du résultat

**Ce qui est inclus :**
- ✅ **Tous les clients** de la table de gauche (4 clients)
- ✅ Dupont apparaît **2 fois** (ses 2 commandes)
- ✅ Martin apparaît **1 fois** (sa commande)
- ✅ Bernard apparaît **1 fois** (même sans commande)
- ✅ Dubois apparaît **1 fois** (même sans commande)

**Les valeurs NULL :**
- Pour Bernard et Dubois, les colonnes de la table `Commandes` (`CommandeID` et `Montant`) contiennent `NULL`
- `NULL` signifie "absence de valeur" ou "pas de correspondance trouvée"

---

## Différence fondamentale : INNER JOIN vs LEFT JOIN

Voici une comparaison visuelle claire :

### INNER JOIN : Seulement les correspondances

```
Clients          Commandes          Résultat INNER JOIN
-------          ----------         -------------------
Dupont (1)   →   101 (1)      →     Dupont - 101
Dupont (1)   →   103 (1)      →     Dupont - 103
Martin (2)   →   102 (2)      →     Martin - 102
Bernard (3)  ✗   (aucune)           [absent]
Dubois (4)   ✗   (aucune)           [absent]
```

**Résultat** : 3 lignes

### LEFT JOIN : Toute la table de gauche

```
Clients          Commandes          Résultat LEFT JOIN
-------          ----------         ------------------
Dupont (1)   →   101 (1)      →     Dupont - 101
Dupont (1)   →   103 (1)      →     Dupont - 103
Martin (2)   →   102 (2)      →     Martin - 102
Bernard (3)  ✗   (aucune)     →     Bernard - NULL
Dubois (4)   ✗   (aucune)     →     Dubois - NULL
```

**Résultat** : 5 lignes (tous les clients préservés)

---

## Comprendre les valeurs NULL

### Qu'est-ce que NULL ?

`NULL` est une valeur spéciale en SQL qui signifie **"absence de valeur"** ou **"valeur inconnue"**.

Dans un LEFT JOIN, `NULL` apparaît dans les colonnes de la table de droite quand aucune correspondance n'a été trouvée.

### Important : NULL n'est pas zéro !

```sql
-- ❌ Toute comparaison avec NULL via = renvoie UNKNOWN (jamais TRUE, jamais FALSE)
NULL = 0        → UNKNOWN
NULL = ''       → UNKNOWN
NULL = NULL     → UNKNOWN   -- NULL n'est même pas « égal » à lui-même

-- En pratique, dans un WHERE, une ligne dont la condition vaut UNKNOWN
-- n'est PAS retournée : UNKNOWN est traité comme « non vrai » (≠ FALSE pour autant).

-- ✅ CORRECT : pour tester NULL, utilisez IS NULL / IS NOT NULL
colonne IS NULL     → TRUE ou FALSE
colonne IS NOT NULL → TRUE ou FALSE
```

### Tester les valeurs NULL

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    CMD.Montant
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.CommandeID IS NULL;
```

**Résultat** : Cette requête retourne uniquement Bernard et Dubois (ceux sans commande).

---

## Cas d'usage : Trouver les enregistrements sans correspondance

Un cas d'usage très courant du LEFT JOIN est de trouver les enregistrements de la table de gauche qui **n'ont pas de correspondance** dans la table de droite.

### Exemple : Clients sans commandes

```sql
SELECT
    C.ClientID,
    C.NomClient,
    C.Ville
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.CommandeID IS NULL;
```

**Résultat**

| ClientID | NomClient | Ville     |
|----------|-----------|-----------|
| 3        | Bernard   | Marseille |
| 4        | Dubois    | Toulouse  |

### Explication

1. Le LEFT JOIN retourne tous les clients
2. Pour ceux sans commande, `CMD.CommandeID` vaut `NULL`
3. La clause `WHERE CMD.CommandeID IS NULL` filtre pour ne garder que ces lignes

**Application pratique** : Cette technique est très utile pour identifier :
- Les clients inactifs
- Les produits jamais vendus
- Les employés sans affectation
- Les comptes sans transactions

---

## Ordre des tables : Importance capitale !

L'ordre des tables dans un LEFT JOIN est **crucial** car il détermine quelle table est complètement préservée.

### Exemple 1 : Clients LEFT JOIN Commandes

```sql
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Résultat** : **Tous les clients** sont présents, même sans commande (Bernard, Dubois avec NULL)

### Exemple 2 : Commandes LEFT JOIN Clients (inversé)

```sql
SELECT C.NomClient, CMD.CommandeID
FROM Commandes CMD
LEFT JOIN Clients C ON CMD.ClientID = C.ClientID;
```

**Résultat** : **Toutes les commandes** sont présentes, même sans client valide

Si on avait une commande avec ClientID=99 (client inexistant), elle apparaîtrait avec `NULL` pour le nom du client.

### Règle d'or

```
FROM TableA LEFT JOIN TableB
     ↑
   Cette table est COMPLÈTEMENT préservée
```

Posez-vous toujours la question : "De quelle table je veux **absolument conserver toutes les lignes** ?"
➜ Cette table doit être à **gauche** du LEFT JOIN.

---

## LEFT JOIN avec plusieurs tables

Vous pouvez enchaîner plusieurs LEFT JOIN :

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    D.NomDepartement
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
LEFT JOIN Departements D ON C.DepartementID = D.DepartementID;
```

### Comportement

- **Tous les clients** sont préservés
- Si un client n'a pas de commande → `CMD.CommandeID` = NULL
- Si un client n'a pas de département → `D.NomDepartement` = NULL
- Un client peut avoir NULL dans les deux tables jointes

---

## Mélanger INNER JOIN et LEFT JOIN

Vous pouvez combiner différents types de jointures dans une même requête :

```sql
SELECT
    C.NomClient,
    CMD.CommandeID,
    P.NomProduit
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
LEFT JOIN Produits P ON CMD.ProduitID = P.ProduitID;
```

### Ordre d'exécution et comportement

1. **INNER JOIN** entre Clients et Commandes → Seuls les clients avec commandes sont conservés
2. **LEFT JOIN** avec Produits → Toutes les commandes précédentes sont conservées, même si le produit n'existe plus

**Attention** : L'ordre des jointures peut changer radicalement le résultat !

### Exemple pour comprendre l'impact de l'ordre

```sql
-- Version 1 : LEFT JOIN puis INNER JOIN
SELECT C.NomClient, CMD.CommandeID, P.NomProduit
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
INNER JOIN Produits P ON CMD.ProduitID = P.ProduitID;
```

**Problème** : L'INNER JOIN après le LEFT JOIN **élimine** les clients sans commande, car `CMD.ProduitID` sera NULL pour eux, et NULL ne correspond à rien dans Produits.

**Résultat** : Équivalent à un INNER JOIN entre Clients et Commandes !

```sql
-- Version 2 : INNER JOIN puis LEFT JOIN
SELECT C.NomClient, CMD.CommandeID, P.NomProduit
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
LEFT JOIN Produits P ON CMD.ProduitID = P.ProduitID;
```

**Résultat** : Clients avec commandes (grâce à INNER JOIN), même si le produit n'existe pas (grâce à LEFT JOIN).

## Agrégations avec LEFT JOIN

Le LEFT JOIN est très utile pour les statistiques incluant les valeurs "zéro" :

### Exemple : Nombre de commandes par client

```sql
SELECT
    C.ClientID,
    C.NomClient,
    COUNT(CMD.CommandeID) AS NombreCommandes,
    COALESCE(SUM(CMD.Montant), 0) AS TotalDepense
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.ClientID, C.NomClient;
```

**Résultat**

| ClientID | NomClient | NombreCommandes | TotalDepense |
|----------|-----------|-----------------|--------------|
| 1        | Dupont    | 2               | 225€         |
| 2        | Martin    | 1               | 200€         |
| 3        | Bernard   | 0               | 0€           |
| 4        | Dubois    | 0               | 0€           |

### Explication

- `COUNT(CMD.CommandeID)` compte les valeurs non-NULL → 0 pour Bernard et Dubois
- `COALESCE(SUM(CMD.Montant), 0)` remplace NULL par 0
- Sans `COALESCE`, le total serait NULL pour les clients sans commande

### Attention avec COUNT(*)

```sql
-- ❌ Donne un résultat incorrect
SELECT
    C.NomClient,
    COUNT(*) AS NombreCommandes
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.ClientID, C.NomClient;
```

**Problème** : `COUNT(*)` compte toutes les lignes, même celles avec NULL. Bernard et Dubois auront `1` au lieu de `0` !

**Solution** : Utilisez `COUNT(CMD.CommandeID)` ou `COUNT(CMD.UneColonne)` pour compter uniquement les valeurs non-NULL.

---

## COALESCE : Remplacer NULL par une valeur par défaut

La fonction `COALESCE` est très utile avec LEFT JOIN pour gérer les NULL :

### Syntaxe

```sql
COALESCE(valeur1, valeur2, valeur3, ...)
```

Retourne la **première valeur non-NULL** de la liste.

### Exemples pratiques

```sql
SELECT
    C.NomClient,
    COALESCE(CMD.CommandeID, 0) AS CommandeID,
    COALESCE(CMD.Montant, 0) AS Montant,
    COALESCE(CMD.DateCommande, '1900-01-01') AS DateCommande
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

Pour Bernard et Dubois, au lieu d'avoir NULL :
- `CommandeID` affichera `0`
- `Montant` affichera `0`
- `DateCommande` affichera `1900-01-01`

### Alias : ISNULL en T-SQL

SQL Server propose aussi `ISNULL` (spécifique à T-SQL) :

```sql
ISNULL(CMD.Montant, 0)  -- Équivalent à COALESCE(CMD.Montant, 0)
```

`COALESCE` est préférable car :
- Standard SQL (portable vers d'autres SGBD)
- Accepte plus de 2 arguments
- Plus flexible

> ⚠️ **Piège de type** : `ISNULL` impose le **type et la longueur du premier argument**, alors que `COALESCE` applique les règles de priorité de types sur l'ensemble des arguments. Ainsi `ISNULL(CAST(NULL AS VARCHAR(2)), 'remplacement')` renvoie `'re'` (tronqué à 2 caractères !), tandis que `COALESCE(CAST(NULL AS VARCHAR(2)), 'remplacement')` renvoie `'remplacement'` en entier. C'est une raison de plus de préférer `COALESCE`.

## Performances et index

### Impact sur les performances

Le LEFT JOIN est généralement **légèrement plus coûteux** qu'un INNER JOIN car :
- Il doit vérifier toutes les lignes de la table de gauche
- Il doit générer des NULL pour les non-correspondances

### Optimisation

Les mêmes règles d'indexation s'appliquent :
- **Indexer les colonnes de jointure** (surtout les clés étrangères)
- Les clés primaires sont déjà indexées automatiquement
- Les clés étrangères doivent souvent être indexées manuellement

```sql
-- Créer un index pour optimiser le LEFT JOIN
CREATE INDEX IX_Commandes_ClientID ON Commandes(ClientID);
```

### Astuce : Filtrer avant de joindre

Si possible, filtrez les données avant la jointure pour réduire le volume :

```sql
-- Moins efficace : jointure puis filtre
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE C.Ville = 'Paris';

-- Plus efficace : filtre puis jointure (dans une sous-requête)
SELECT C.NomClient, CMD.CommandeID
FROM (SELECT * FROM Clients WHERE Ville = 'Paris') C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Note** : L'optimiseur SQL est intelligent et fait souvent cette optimisation automatiquement.

## Différence entre WHERE et ON avec LEFT JOIN

C'est un point crucial qui confond souvent les débutants !

### Filtre dans ON

```sql
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
                        AND CMD.Montant > 100;
```

**Résultat** : Tous les clients sont présents. Les commandes de moins de 100€ ne sont simplement pas appariées (NULL).

### Filtre dans WHERE

```sql
SELECT C.NomClient, CMD.CommandeID
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.Montant > 100;
```

**Résultat** : Seuls les clients ayant des commandes > 100€ sont présents. Le LEFT JOIN est "annulé" par le WHERE !

### Explication de la différence

- **ON** : Filtre appliqué **pendant** la jointure (affecte seulement les correspondances)
- **WHERE** : Filtre appliqué **après** la jointure (élimine les lignes NULL créées par LEFT JOIN)

### Règle pratique

- Pour filtrer la table de **droite** sans éliminer les lignes de gauche → Mettez la condition dans **ON**
- Pour filtrer le résultat final → Mettez la condition dans **WHERE**

### Exemple pour clarifier

Vous voulez tous les clients, mais seulement leurs commandes > 100€ :

```sql
-- ✅ CORRECT : Filtre dans ON
SELECT C.NomClient, CMD.CommandeID, CMD.Montant
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
                        AND CMD.Montant > 100;
```

Bernard et Dubois apparaissent avec NULL (pas de commandes)  
Dupont apparaît avec sa commande de 150€ (celle de 75€ est filtrée mais Dupont reste)  

```sql
-- ❌ FAUX : Filtre dans WHERE (transforme le LEFT JOIN en INNER JOIN)
SELECT C.NomClient, CMD.CommandeID, CMD.Montant
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.Montant > 100;
```

Seuls les clients avec des commandes > 100€ apparaissent (Bernard et Dubois sont éliminés).

## Erreurs courantes à éviter

### 1. Confondre LEFT JOIN et INNER JOIN

```sql
-- Vous voulez tous les clients, mais écrivez par erreur :
SELECT * FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID;
```

**Erreur** : Les clients sans commande disparaissent.  
**Correction** : Utilisez LEFT JOIN.  

### 2. Utiliser WHERE sur les colonnes NULL

```sql
-- ❌ Transforme accidentellement le LEFT JOIN en INNER JOIN
SELECT * FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE CMD.Montant > 0;  -- Élimine les NULL !
```

**Solution** : Si vous devez filtrer sur la table de droite, utilisez ON ou gérez les NULL explicitement :

```sql
WHERE CMD.Montant > 0 OR CMD.Montant IS NULL
```

### 3. Mauvais comptage avec COUNT(*)

```sql
-- ❌ Donne 1 au lieu de 0 pour les clients sans commande
SELECT C.NomClient, COUNT(*)
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.NomClient;
```

**Solution** : Utilisez `COUNT(CMD.CommandeID)`.

### 4. Oublier COALESCE pour les sommes

```sql
-- ❌ SUM retourne NULL pour les clients sans commande
SELECT C.NomClient, SUM(CMD.Montant) AS Total
FROM Clients C
LEFT JOIN Commandes CMD ON C.ClientID = CMD.ClientID
GROUP BY C.NomClient;
```

**Solution** : `COALESCE(SUM(CMD.Montant), 0)` ou `SUM(COALESCE(CMD.Montant, 0))`.

---

## Points clés à retenir

1. **LEFT JOIN** retourne **toutes les lignes de la table de gauche**, avec ou sans correspondance.

2. **Les colonnes de la table de droite** contiennent `NULL` quand il n'y a pas de correspondance.

3. **L'ordre des tables est crucial** : la table à gauche est complètement préservée.

4. **Syntaxe** : `FROM TableGauche LEFT JOIN TableDroite ON condition`

5. **Le mot OUTER est optionnel** : `LEFT JOIN` = `LEFT OUTER JOIN`

6. **Utilisation principale** : Identifier les enregistrements sans correspondance (`WHERE ColonneDroite IS NULL`).

7. **NULL n'est pas zéro** : Utilisez `IS NULL` et `IS NOT NULL` pour tester.

8. **WHERE vs ON** : Les filtres dans WHERE après un LEFT JOIN peuvent transformer le comportement en INNER JOIN.

9. **Utilisez COALESCE** pour remplacer les NULL par des valeurs par défaut.

10. **COUNT(*)** compte les lignes NULL, utilisez `COUNT(colonne)` pour compter seulement les valeurs non-NULL.

---

## Quand utiliser un LEFT JOIN ?

Utilisez un LEFT JOIN quand :

- ✅ Vous voulez **toutes les lignes de la table de gauche**, même sans correspondance
- ✅ Vous cherchez les enregistrements qui **n'existent pas** dans une autre table
- ✅ Vous faites des **statistiques incluant les valeurs zéro** (clients sans commande, produits sans vente)
- ✅ Vous voulez des **rapports complets** sans exclure les données manquantes

N'utilisez PAS un LEFT JOIN quand :

- ❌ Vous voulez seulement les enregistrements avec correspondance → Utilisez INNER JOIN
- ❌ Vous voulez toutes les lignes des deux tables → Utilisez FULL OUTER JOIN
- ❌ L'ordre des tables ne convient pas → Envisagez RIGHT JOIN (ou réorganisez avec LEFT JOIN)

---

## En résumé

Le **LEFT JOIN** est un outil puissant pour conserver l'intégralité d'une table tout en l'enrichissant avec des informations d'une autre table.

C'est particulièrement utile pour :
- Identifier les données manquantes ou incomplètes
- Faire des rapports exhaustifs
- Calculer des statistiques incluant les zéros
- Éviter de perdre des informations importantes

La gestion correcte des valeurs NULL est essentielle quand vous travaillez avec LEFT JOIN. Pensez toujours à :
- Tester avec `IS NULL` / `IS NOT NULL`
- Utiliser `COALESCE` pour les valeurs par défaut
- Faire attention à la différence entre WHERE et ON

Maintenant que vous maîtrisez le LEFT JOIN, vous êtes prêt à découvrir le RIGHT JOIN qui fonctionne selon le même principe, mais dans l'autre direction !
