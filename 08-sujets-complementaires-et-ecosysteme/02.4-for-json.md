# 8.2.4 FOR JSON (Génération de JSON)

## Introduction

Dans les sections précédentes, nous avons appris à **stocker**, **interroger** et **transformer** du JSON. Maintenant, nous allons voir comment faire l'opération inverse : **générer du JSON à partir de données relationnelles** stockées dans des tables SQL Server.

C'est particulièrement utile pour :
- Créer des APIs REST qui retournent du JSON
- Exporter des données vers d'autres systèmes
- Générer des configurations ou des fichiers JSON
- Alimenter des applications web ou mobiles
- Créer des réponses formatées pour des services web

SQL Server offre la clause **`FOR JSON`** qui transforme automatiquement les résultats d'une requête SELECT en format JSON.

**Analogie** : Si `OPENJSON()` est comme ouvrir un cadeau emballé, `FOR JSON` est comme emballer un cadeau - vous prenez des données "en vrac" (tables) et les mettez dans un joli paquet (JSON).

## Les modes de FOR JSON

La clause `FOR JSON` propose **deux modes** principaux :

| Mode | Caractéristique | Structure | Contrôle |
|------|-----------------|-----------|----------|
| **AUTO** | Structure automatique basée sur les jointures | Hiérarchique selon les relations | Faible |
| **PATH** | Contrôle total de la structure | Définie par vous via des chemins | Élevé |

**Note** : Il n'existe pas de mode RAW ou EXPLICIT comme pour XML. Microsoft a simplifié l'API JSON.

**Recommandation** : Utilisez **PATH** pour la plupart des cas - il offre plus de flexibilité tout en restant simple.

## Préparation : Données d'exemple

Créons des tables simples pour illustrer la génération JSON :

```sql
-- Table des clients
CREATE TABLE Clients (
    ClientID INT PRIMARY KEY,
    Nom NVARCHAR(50),
    Email NVARCHAR(100),
    Ville NVARCHAR(50)
);

-- Table des commandes
CREATE TABLE Commandes (
    CommandeID INT PRIMARY KEY,
    ClientID INT,
    DateCommande DATE,
    Montant DECIMAL(10,2),
    FOREIGN KEY (ClientID) REFERENCES Clients(ClientID)
);

-- Insertion de données
INSERT INTO Clients VALUES
(1, 'Dupont', 'dupont@example.com', 'Paris'),
(2, 'Martin', 'martin@example.com', 'Lyon'),
(3, 'Durand', 'durand@example.com', 'Marseille');

INSERT INTO Commandes VALUES
(101, 1, '2024-11-01', 250.00),
(102, 1, '2024-11-10', 180.50),
(103, 2, '2024-11-05', 420.00),
(104, 3, '2024-11-15', 95.75);
```

## Mode AUTO : Structure automatique

### Concept

Le mode **AUTO** analyse automatiquement les **relations** entre les tables (via les jointures) et crée une structure JSON hiérarchique correspondante.

### Syntaxe de base

```sql
SELECT colonnes
FROM table1
JOIN table2 ON ...
FOR JSON AUTO;
```

### Exemple 1 : AUTO simple (une table)

```sql
SELECT ClientID, Nom, Email, Ville
FROM Clients
FOR JSON AUTO;
```

**Résultat** (une seule ligne de texte JSON) :
```json
[
  {"ClientID":1,"Nom":"Dupont","Email":"dupont@example.com","Ville":"Paris"},
  {"ClientID":2,"Nom":"Martin","Email":"martin@example.com","Ville":"Lyon"},
  {"ClientID":3,"Nom":"Durand","Email":"durand@example.com","Ville":"Marseille"}
]
```

**Observations** :
- Le résultat est un **tableau JSON** (entre `[]`)
- Chaque ligne de la table devient un **objet JSON** (entre `{}`)
- Les noms de colonnes deviennent des **clés JSON**
- Le tout est retourné comme une **seule chaîne de caractères**

### Exemple 2 : AUTO avec jointure (hiérarchie)

```sql
SELECT
    C.ClientID,
    C.Nom,
    C.Email,
    CMD.CommandeID,
    CMD.DateCommande,
    CMD.Montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
FOR JSON AUTO;
```

**Résultat** (formaté pour lisibilité) :
```json
[
  {
    "ClientID": 1,
    "Nom": "Dupont",
    "Email": "dupont@example.com",
    "CMD": [
      {"CommandeID": 101, "DateCommande": "2024-11-01", "Montant": 250.00},
      {"CommandeID": 102, "DateCommande": "2024-11-10", "Montant": 180.50}
    ]
  },
  {
    "ClientID": 2,
    "Nom": "Martin",
    "Email": "martin@example.com",
    "CMD": [
      {"CommandeID": 103, "DateCommande": "2024-11-05", "Montant": 420.00}
    ]
  },
  {
    "ClientID": 3,
    "Nom": "Durand",
    "Email": "durand@example.com",
    "CMD": [
      {"CommandeID": 104, "DateCommande": "2024-11-15", "Montant": 95.75}
    ]
  }
]
```

**Observations importantes** :
- SQL Server a **automatiquement créé une hiérarchie** !
- Les commandes sont **imbriquées** dans leurs clients respectifs
- Le nom du tableau imbriqué (`CMD`) correspond à l'alias de la table `Commandes`
- Chaque client a un tableau `CMD` contenant ses commandes

**C'est la puissance de AUTO** : la hiérarchie est générée automatiquement selon les relations détectées.

### Exemple 3 : Personnaliser les noms avec des alias

Les alias de colonnes et de tables affectent les noms dans le JSON :

```sql
SELECT
    C.ClientID AS id,
    C.Nom AS nom,
    C.Email AS email,
    CMD.CommandeID AS numero,
    CMD.DateCommande AS date,
    CMD.Montant AS montant
FROM Clients C
INNER JOIN Commandes CMD ON C.ClientID = CMD.ClientID
WHERE C.ClientID = 1
FOR JSON AUTO;
```

**Résultat** :
```json
[
  {
    "id": 1,
    "nom": "Dupont",
    "email": "dupont@example.com",
    "CMD": [
      {"numero": 101, "date": "2024-11-01", "montant": 250.00},
      {"numero": 102, "date": "2024-11-10", "montant": 180.50}
    ]
  }
]
```

**Note** : Les alias de colonnes changent les noms des clés JSON, mais l'alias de table (`CMD`) définit le nom du tableau imbriqué.

### Limites de AUTO

**Inconvénients** :
- Contrôle limité sur la structure
- Les noms de tableaux imbriqués dépendent des alias de tables
- Difficile de créer des structures complexes ou personnalisées
- L'ordre des colonnes affecte la structure

**Pour plus de contrôle, utilisez PATH.**

## Mode PATH : Contrôle total

### Concept

Le mode **PATH** vous donne un **contrôle complet** sur la structure JSON générée. Vous définissez la hiérarchie en utilisant des **chemins** (paths) dans les alias de colonnes.

**Syntaxe des chemins** :
- Point (`.`) : Crée des niveaux hiérarchiques
- Pas de préfixe : Crée une propriété simple
- Chemin imbriqué : Crée des objets imbriqués

### Syntaxe de base

```sql
SELECT colonnes AS 'chemin.vers.propriete'
FROM table
FOR JSON PATH;
```

### Exemple 1 : PATH simple (équivalent à AUTO)

```sql
SELECT ClientID, Nom, Email, Ville
FROM Clients
FOR JSON PATH;
```

**Résultat** :
```json
[
  {"ClientID": 1, "Nom": "Dupont", "Email": "dupont@example.com", "Ville": "Paris"},
  {"ClientID": 2, "Nom": "Martin", "Email": "martin@example.com", "Ville": "Lyon"},
  {"ClientID": 3, "Nom": "Durand", "Email": "durand@example.com", "Ville": "Marseille"}
]
```

Sans chemins spécifiques, PATH se comporte comme AUTO pour une table simple.

### Exemple 2 : Créer une hiérarchie avec des points

Utilisons le `.` pour créer des objets imbriqués :

```sql
SELECT
    ClientID AS 'id',
    Nom AS 'informations.nom',
    Email AS 'informations.email',
    Ville AS 'informations.adresse.ville'
FROM Clients
WHERE ClientID = 1
FOR JSON PATH;
```

**Résultat** :
```json
[
  {
    "id": 1,
    "informations": {
      "nom": "Dupont",
      "email": "dupont@example.com",
      "adresse": {
        "ville": "Paris"
      }
    }
  }
]
```

**Explication** :
- `'informations.nom'` crée un objet `informations` avec une propriété `nom`
- `'informations.adresse.ville'` crée `informations` → `adresse` → `ville`
- La hiérarchie est définie par les chemins, pas par les jointures

### Exemple 3 : Tableaux imbriqués avec sous-requêtes

Pour créer des tableaux imbriqués, utilisez une **sous-requête** avec `FOR JSON PATH` :

```sql
SELECT
    C.ClientID AS 'id',
    C.Nom AS 'nom',
    C.Email AS 'email',
    (
        SELECT
            CMD.CommandeID AS 'numero',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR JSON PATH
    ) AS 'commandes'
FROM Clients C
WHERE C.ClientID = 1
FOR JSON PATH;
```

**Résultat** :
```json
[
  {
    "id": 1,
    "nom": "Dupont",
    "email": "dupont@example.com",
    "commandes": [
      {"numero": 101, "date": "2024-11-01", "montant": 250.00},
      {"numero": 102, "date": "2024-11-10", "montant": 180.50}
    ]
  }
]
```

**Important** : La sous-requête avec `FOR JSON PATH` génère automatiquement un tableau JSON.

### Exemple 4 : Structure complexe personnalisée

Créons une structure JSON complexe et personnalisée :

```sql
SELECT
    C.ClientID AS 'client.id',
    C.Nom AS 'client.nom',
    C.Email AS 'client.contact.email',
    C.Ville AS 'client.contact.adresse.ville',
    'France' AS 'client.contact.adresse.pays',
    (
        SELECT
            CMD.CommandeID AS 'id',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant',
            'EUR' AS 'devise'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR JSON PATH
    ) AS 'commandes',
    (
        SELECT
            COUNT(*) AS 'total',
            SUM(Montant) AS 'montantTotal'
        FROM Commandes
        WHERE ClientID = C.ClientID
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    ) AS 'statistiques'
FROM Clients C
WHERE C.ClientID = 1
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{
  "client": {
    "id": 1,
    "nom": "Dupont",
    "contact": {
      "email": "dupont@example.com",
      "adresse": {
        "ville": "Paris",
        "pays": "France"
      }
    }
  },
  "commandes": [
    {"id": 101, "date": "2024-11-01", "montant": 250.00, "devise": "EUR"},
    {"id": 102, "date": "2024-11-10", "montant": 180.50, "devise": "EUR"}
  ],
  "statistiques": {
    "total": 2,
    "montantTotal": 430.50
  }
}
```

**Observations** :
- Structure très personnalisée et lisible
- Objets imbriqués multiples (`client.contact.adresse`)
- Tableaux et objets combinés
- `WITHOUT_ARRAY_WRAPPER` retire les crochets pour un objet unique

## Options communes

### ROOT : Ajouter un élément racine

Par défaut, `FOR JSON` retourne un tableau ou un objet. Pour ajouter un nom de racine :

```sql
SELECT ClientID, Nom, Email
FROM Clients
FOR JSON PATH, ROOT('clients');
```

**Résultat** :
```json
{
  "clients": [
    {"ClientID": 1, "Nom": "Dupont", "Email": "dupont@example.com"},
    {"ClientID": 2, "Nom": "Martin", "Email": "martin@example.com"},
    {"ClientID": 3, "Nom": "Durand", "Email": "durand@example.com"}
  ]
}
```

Le tableau est maintenant enveloppé dans un objet avec la clé `clients`.

### INCLUDE_NULL_VALUES : Inclure les NULL

Par défaut, les valeurs NULL sont **omises** du JSON généré. Pour les inclure :

```sql
-- Ajoutons une colonne nullable
ALTER TABLE Clients ADD Telephone NVARCHAR(20) NULL;

-- Mise à jour partielle
UPDATE Clients SET Telephone = '0123456789' WHERE ClientID = 1;

-- Sans INCLUDE_NULL_VALUES (par défaut)
SELECT ClientID, Nom, Telephone
FROM Clients
FOR JSON PATH;
```

**Résultat** :
```json
[
  {"ClientID": 1, "Nom": "Dupont", "Telephone": "0123456789"},
  {"ClientID": 2, "Nom": "Martin"},
  {"ClientID": 3, "Nom": "Durand"}
]
```

Les clients 2 et 3 n'ont pas de propriété `Telephone`.

```sql
-- Avec INCLUDE_NULL_VALUES
SELECT ClientID, Nom, Telephone
FROM Clients
FOR JSON PATH, INCLUDE_NULL_VALUES;
```

**Résultat** :
```json
[
  {"ClientID": 1, "Nom": "Dupont", "Telephone": "0123456789"},
  {"ClientID": 2, "Nom": "Martin", "Telephone": null},
  {"ClientID": 3, "Nom": "Durand", "Telephone": null}
]
```

Maintenant, les NULL sont explicitement représentés comme `null` en JSON.

### WITHOUT_ARRAY_WRAPPER : Retourner un objet unique

Par défaut, `FOR JSON` retourne toujours un **tableau** (même pour une seule ligne). Pour retourner un **objet unique** :

```sql
-- Avec wrapper (par défaut)
SELECT ClientID, Nom, Email
FROM Clients
WHERE ClientID = 1
FOR JSON PATH;
```

**Résultat** :
```json
[
  {"ClientID": 1, "Nom": "Dupont", "Email": "dupont@example.com"}
]
```

**Avec crochets** → Tableau d'un seul élément

```sql
-- Sans wrapper
SELECT ClientID, Nom, Email
FROM Clients
WHERE ClientID = 1
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{"ClientID": 1, "Nom": "Dupont", "Email": "dupont@example.com"}
```

**Sans crochets** → Objet unique

**Cas d'usage** : Utile pour des APIs qui retournent un objet pour une ressource unique (ex: `/api/clients/1`).

**⚠️ Attention** : N'utilisez `WITHOUT_ARRAY_WRAPPER` que si vous êtes **certain** d'avoir une seule ligne. Sinon, le JSON sera invalide.

## Combinaison d'options

Vous pouvez combiner plusieurs options :

```sql
SELECT ClientID, Nom, Email, Telephone
FROM Clients
WHERE ClientID = 1
FOR JSON PATH,
    ROOT('client'),
    WITHOUT_ARRAY_WRAPPER,
    INCLUDE_NULL_VALUES;
```

**Résultat** :
```json
{
  "client": {
    "ClientID": 1,
    "Nom": "Dupont",
    "Email": "dupont@example.com",
    "Telephone": "0123456789"
  }
}
```

## Cas d'usage pratiques

### Cas 1 : API REST - Liste de ressources

```sql
-- Endpoint: GET /api/clients
-- Retourne la liste de tous les clients avec leurs commandes

SELECT
    C.ClientID AS 'id',
    C.Nom AS 'nom',
    C.Email AS 'email',
    C.Ville AS 'ville',
    (
        SELECT
            CMD.CommandeID AS 'id',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR JSON PATH
    ) AS 'commandes'
FROM Clients C
FOR JSON PATH, ROOT('clients');
```

**Résultat** : JSON prêt à être consommé par une application frontend.

### Cas 2 : API REST - Ressource unique

```sql
-- Endpoint: GET /api/clients/1
-- Retourne un client spécifique avec ses détails

SELECT
    C.ClientID AS 'id',
    C.Nom AS 'nom',
    C.Email AS 'email',
    C.Ville AS 'ville',
    (
        SELECT
            CMD.CommandeID AS 'id',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR JSON PATH
    ) AS 'commandes',
    (
        SELECT COUNT(*)
        FROM Commandes
        WHERE ClientID = C.ClientID
    ) AS 'nombreCommandes',
    (
        SELECT ISNULL(SUM(Montant), 0)
        FROM Commandes
        WHERE ClientID = C.ClientID
    ) AS 'totalAchats'
FROM Clients C
WHERE C.ClientID = 1
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

### Cas 3 : Configuration JSON

```sql
-- Générer un fichier de configuration
SELECT
    'MyApp' AS 'application.nom',
    '1.0.0' AS 'application.version',
    'Production' AS 'environnement',
    (
        SELECT
            'localhost' AS 'serveur',
            'MaBase' AS 'nomBase',
            1433 AS 'port',
            30 AS 'timeout'
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    ) AS 'baseDeDonnees',
    (
        SELECT
            'smtp.example.com' AS 'serveur',
            587 AS 'port',
            'app@example.com' AS 'expediteur'
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    ) AS 'email'
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER, ROOT('configuration');
```

**Résultat** : Un fichier de configuration JSON structuré.

### Cas 4 : Export de données pour analyse

```sql
-- Export de données de ventes par mois
SELECT
    YEAR(CMD.DateCommande) AS 'annee',
    MONTH(CMD.DateCommande) AS 'mois',
    COUNT(*) AS 'nombreCommandes',
    SUM(CMD.Montant) AS 'chiffreAffaires',
    AVG(CMD.Montant) AS 'panierMoyen'
FROM Commandes CMD
GROUP BY YEAR(CMD.DateCommande), MONTH(CMD.DateCommande)
ORDER BY YEAR(CMD.DateCommande), MONTH(CMD.DateCommande)
FOR JSON PATH, ROOT('statistiquesVentes');
```

### Cas 5 : Webhook / Event payload

```sql
-- Générer un payload JSON pour un webhook lors d'une nouvelle commande
DECLARE @CommandeID INT = 101;

SELECT
    'nouvelle_commande' AS 'event',
    GETDATE() AS 'timestamp',
    (
        SELECT
            CMD.CommandeID AS 'id',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant',
            (
                SELECT
                    C.ClientID AS 'id',
                    C.Nom AS 'nom',
                    C.Email AS 'email'
                FROM Clients C
                WHERE C.ClientID = CMD.ClientID
                FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
            ) AS 'client'
        FROM Commandes CMD
        WHERE CMD.CommandeID = @CommandeID
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    ) AS 'data'
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{
  "event": "nouvelle_commande",
  "timestamp": "2024-11-18T14:30:00",
  "data": {
    "id": 101,
    "date": "2024-11-01",
    "montant": 250.00,
    "client": {
      "id": 1,
      "nom": "Dupont",
      "email": "dupont@example.com"
    }
  }
}
```

## Génération JSON avec des types de données spéciaux

### Dates

Par défaut, les dates sont au format ISO 8601 :

```sql
SELECT
    CommandeID,
    DateCommande,  -- Format: 2024-11-01
    GETDATE() AS DateHeure  -- Format: 2024-11-18T14:30:00
FROM Commandes
WHERE CommandeID = 101
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{
  "CommandeID": 101,
  "DateCommande": "2024-11-01",
  "DateHeure": "2024-11-18T14:30:00"
}
```

Pour un format personnalisé :

```sql
SELECT
    CommandeID,
    FORMAT(DateCommande, 'dd/MM/yyyy') AS DateFormatee
FROM Commandes
WHERE CommandeID = 101
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

### Booléens

SQL Server n'a pas de vrai type booléen, mais utilisez BIT (0/1) :

```sql
SELECT
    ClientID,
    Nom,
    CAST(CASE WHEN Ville = 'Paris' THEN 1 ELSE 0 END AS BIT) AS estParisien,
    CAST(CASE WHEN Email LIKE '%@%' THEN 1 ELSE 0 END AS BIT) AS emailValide
FROM Clients
WHERE ClientID = 1
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{
  "ClientID": 1,
  "Nom": "Dupont",
  "estParisien": true,
  "emailValide": true
}
```

**Note** : Les valeurs BIT (0/1) sont automatiquement converties en `true`/`false` en JSON.

### Valeurs NULL

```sql
SELECT
    ClientID,
    Nom,
    Telephone  -- NULL pour certains clients
FROM Clients
FOR JSON PATH, INCLUDE_NULL_VALUES;
```

**Résultat** :
```json
[
  {"ClientID": 1, "Nom": "Dupont", "Telephone": "0123456789"},
  {"ClientID": 2, "Nom": "Martin", "Telephone": null}
]
```

## JSON imbriqué depuis une colonne JSON existante

Si vous avez déjà du JSON dans une colonne, vous pouvez l'inclure directement :

```sql
-- Table avec une colonne JSON
CREATE TABLE Produits (
    ProduitID INT PRIMARY KEY,
    Nom NVARCHAR(100),
    DetailsJSON NVARCHAR(MAX)
);

INSERT INTO Produits VALUES
(1, 'Laptop', '{"marque": "Dell", "prix": 899.99, "stock": 5}');

-- Inclure le JSON existant dans la génération
SELECT
    ProduitID,
    Nom,
    JSON_QUERY(DetailsJSON) AS details
FROM Produits
FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

**Résultat** :
```json
{
  "ProduitID": 1,
  "Nom": "Laptop",
  "details": {
    "marque": "Dell",
    "prix": 899.99,
    "stock": 5
  }
}
```

**Important** : Utilisez `JSON_QUERY()` pour inclure du JSON existant, sinon il sera échappé (avec `\"` au lieu de `"`).

## Comparaison : AUTO vs PATH

| Aspect | AUTO | PATH |
|--------|------|------|
| **Simplicité** | ★★★★★ | ★★★☆☆ |
| **Contrôle** | ★★☆☆☆ | ★★★★★ |
| **Hiérarchie** | Automatique (jointures) | Manuelle (chemins) |
| **Personnalisation** | Limitée | Totale |
| **Structure** | Basée sur les relations | Définie par vous |
| **Sous-requêtes** | Difficile | Facile |
| **Recommandation** | Export simple | Production, APIs |

**Règle générale** : Utilisez **PATH** pour tout projet sérieux - il est plus flexible et maintenable.

## Bonnes pratiques

### 1. Utiliser des alias parlants

```sql
-- ❌ Mauvais : Noms de colonnes SQL
SELECT ClientID, Nom, DateCreation
FROM Clients
FOR JSON PATH;

-- ✅ Bon : Noms cohérents avec conventions JSON (camelCase ou snake_case)
SELECT
    ClientID AS 'id',
    Nom AS 'nom',
    DateCreation AS 'dateCreation'
FROM Clients
FOR JSON PATH;
```

### 2. Structurer le JSON de manière logique

```sql
-- ✅ Structure claire et organisée
SELECT
    ClientID AS 'client.id',
    Nom AS 'client.nom',
    Email AS 'client.email',
    DateCommande AS 'commande.date',
    Montant AS 'commande.montant'
FROM ...
FOR JSON PATH;
```

### 3. Gérer les NULL de manière cohérente

Décidez d'une politique : soit vous incluez toujours les NULL, soit vous les omettez toujours.

```sql
-- Pour une API : souvent mieux d'omettre les NULL (par défaut)
FOR JSON PATH;

-- Pour un export complet : inclure les NULL
FOR JSON PATH, INCLUDE_NULL_VALUES;
```

### 4. Éviter les JSON trop volumineux

Pour de gros volumes, paginez vos résultats :

```sql
-- Pagination : 10 résultats, page 2
SELECT
    ClientID AS 'id',
    Nom AS 'nom',
    Email AS 'email'
FROM Clients
ORDER BY ClientID
OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY
FOR JSON PATH, ROOT('clients');
```

### 5. Tester le JSON généré

Validez toujours que le JSON généré est valide et bien formé :

```sql
-- Utiliser ISJSON pour valider
DECLARE @json NVARCHAR(MAX);

SET @json = (
    SELECT ClientID, Nom, Email
    FROM Clients
    FOR JSON PATH
);

SELECT
    ISJSON(@json) AS EstValide,
    @json AS JSON;
```

### 6. Documenter la structure attendue

```sql
-- Commentaires clairs sur la structure générée
-- Structure retournée:
-- {
--   "id": number,
--   "nom": string,
--   "email": string,
--   "commandes": [
--     {"numero": number, "date": string, "montant": number}
--   ]
-- }

SELECT
    C.ClientID AS 'id',
    C.Nom AS 'nom',
    C.Email AS 'email',
    (
        SELECT
            CMD.CommandeID AS 'numero',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant'
        FROM Commandes CMD
        WHERE CMD.ClientID = C.ClientID
        FOR JSON PATH
    ) AS 'commandes'
FROM Clients C
FOR JSON PATH;
```

## Performance

### 1. Indexation

Assurez-vous d'avoir des index appropriés sur les colonnes utilisées dans les jointures et WHERE :

```sql
-- Index pour améliorer les performances
CREATE INDEX IX_Commandes_ClientID ON Commandes(ClientID);
```

### 2. Limitation des données

N'incluez que les colonnes nécessaires :

```sql
-- ❌ Mauvais : SELECT *
SELECT * FROM Clients FOR JSON PATH;

-- ✅ Bon : Colonnes spécifiques
SELECT ClientID, Nom, Email FROM Clients FOR JSON PATH;
```

### 3. Utilisation en production

Pour des APIs à fort trafic :
- Mettez en cache le JSON généré si les données changent peu
- Utilisez des vues matérialisées si approprié
- Considérez la compression du JSON

## Limitations

### 1. Taille maximale

Le JSON généré est stocké en NVARCHAR(MAX), limité à 2 Go. Pour des jeux de données énormes, envisagez :
- La pagination
- Le streaming (génération par lots)
- L'export en fichiers multiples

### 2. Types de données complexes

Certains types SQL Server ne se convertissent pas bien en JSON :
- BINARY, VARBINARY → Encodés en Base64 (verbeux)
- XML → Converti en chaîne (pas idéal)
- Géométries spatiales → Nécessitent un formatage spécial

### 3. Pas de validation de schéma

SQL Server génère du JSON bien formé, mais ne valide pas contre un schéma JSON. Vous devez gérer cette validation côté application si nécessaire.

## Résumé des syntaxes

### Mode AUTO
```sql
SELECT colonnes
FROM table1
JOIN table2 ON ...
FOR JSON AUTO [, options];
```

### Mode PATH
```sql
SELECT
    colonne1 AS 'chemin.vers.prop1',
    colonne2 AS 'chemin.vers.prop2'
FROM table
FOR JSON PATH [, options];
```

### Options
```sql
FOR JSON PATH,
    ROOT('nomRacine'),              -- Ajouter un élément racine
    WITHOUT_ARRAY_WRAPPER,          -- Retourner objet unique au lieu de tableau
    INCLUDE_NULL_VALUES;            -- Inclure les valeurs NULL
```

### Sous-requête pour tableau imbriqué
```sql
(
    SELECT col1, col2
    FROM table
    WHERE condition
    FOR JSON PATH
) AS 'nomTableau'
```

| Fonctionnalité | Syntaxe | Usage |
|----------------|---------|-------|
| **Mode AUTO** | `FOR JSON AUTO` | Structure automatique |
| **Mode PATH** | `FOR JSON PATH` | Contrôle total |
| **Élément racine** | `ROOT('nom')` | Envelopper dans un objet |
| **Objet unique** | `WITHOUT_ARRAY_WRAPPER` | Pour une seule ligne |

## Exemple complet : API e-commerce

Voici un exemple réaliste combinant toutes les techniques :

```sql
-- API endpoint: GET /api/commandes/101
-- Retourne une commande complète avec tous ses détails

DECLARE @CommandeID INT = 101;

SELECT
    -- Métadonnées de réponse
    'success' AS 'status',
    GETDATE() AS 'timestamp',

    -- Données de la commande
    (
        SELECT
            CMD.CommandeID AS 'id',
            CMD.DateCommande AS 'date',
            CMD.Montant AS 'montant',
            'EUR' AS 'devise',

            -- Informations client
            (
                SELECT
                    C.ClientID AS 'id',
                    C.Nom AS 'nom',
                    C.Email AS 'email',
                    C.Ville AS 'adresse.ville'
                FROM Clients C
                WHERE C.ClientID = CMD.ClientID
                FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
            ) AS 'client',

            -- Statut de la commande
            'En cours' AS 'statut',

            -- Méthode de paiement
            (
                SELECT
                    'Carte bancaire' AS 'methode',
                    'Visa' AS 'type',
                    '**** 1234' AS 'numero'
                FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
            ) AS 'paiement'

        FROM Commandes CMD
        WHERE CMD.CommandeID = @CommandeID
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    ) AS 'data'

FOR JSON PATH, WITHOUT_ARRAY_WRAPPER;
```

## Conclusion

**`FOR JSON`** est l'outil parfait pour transformer vos données relationnelles en JSON :

- ✅ **MODE AUTO** : Simple et rapide pour des exports basiques
- ✅ **MODE PATH** : Contrôle total pour des APIs professionnelles
- ✅ **Options flexibles** : ROOT, WITHOUT_ARRAY_WRAPPER, INCLUDE_NULL_VALUES
- ✅ **Structures complexes** : Objets imbriqués, tableaux, hiérarchies
- ✅ **Intégration facile** : Parfait pour les APIs REST et web services

**Points clés à retenir** :
1. Privilégiez **PATH** pour un contrôle maximal
2. Utilisez des **alias** pour des noms JSON propres
3. Les **sous-requêtes** créent des tableaux imbriqués
4. **WITHOUT_ARRAY_WRAPPER** pour un objet unique
5. Testez toujours avec **ISJSON()** pour garantir la validité

**Quand utiliser FOR JSON ?**
- Créer des APIs REST
- Exporter des données vers d'autres systèmes
- Générer des fichiers de configuration
- Alimenter des applications web/mobile
- Créer des webhooks et event payloads

Avec `FOR JSON`, vous pouvez facilement exposer vos données SQL Server au monde JSON des applications modernes !
