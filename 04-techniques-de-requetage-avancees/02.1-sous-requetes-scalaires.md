# 4.2.1 Sous-requêtes scalaires (retournant une seule valeur)

## Qu'est-ce qu'une sous-requête scalaire ?

Une **sous-requête scalaire** est une requête SQL imbriquée à l'intérieur d'une autre requête, qui retourne **une seule valeur** (une cellule : une ligne et une colonne). Cette valeur unique peut ensuite être utilisée dans la requête principale comme s'il s'agissait d'une constante ou d'une colonne.

### Caractéristiques principales

- Retourne **exactement une valeur** (un résultat composé d'une ligne et d'une colonne)
- Peut être utilisée partout où une valeur unique est attendue
- Placée entre parenthèses `()`
- Souvent utilisée dans les clauses `SELECT`, `WHERE`, `HAVING`, ou même `ORDER BY`

## Syntaxe de base

```sql
SELECT colonne1, colonne2, (sous-requête_scalaire)
FROM table1
WHERE colonne3 = (sous-requête_scalaire);
```

La sous-requête est entourée de parenthèses et doit retourner une seule valeur.

## Exemples pratiques

### Contexte : Tables d'exemple

Imaginons que nous travaillons avec deux tables simples :

**Table Produits**
| ProduitID | NomProduit | Prix | CategorieID |
|-----------|------------|------|-------------|
| 1 | Clavier | 25.00 | 1 |
| 2 | Souris | 15.00 | 1 |
| 3 | Écran | 200.00 | 2 |
| 4 | Webcam | 50.00 | 2 |

**Table Commandes**
| CommandeID | ProduitID | Quantite | DateCommande |
|------------|-----------|----------|--------------|
| 101 | 1 | 5 | 2024-01-15 |
| 102 | 2 | 10 | 2024-01-16 |
| 103 | 3 | 2 | 2024-01-17 |

### Exemple 1 : Comparer une valeur à une moyenne

Trouver tous les produits dont le prix est supérieur au prix moyen de tous les produits.

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix > (SELECT AVG(Prix) FROM Produits);
```

**Explication :**
- La sous-requête `(SELECT AVG(Prix) FROM Produits)` calcule le prix moyen de tous les produits
- Cette sous-requête retourne une seule valeur, par exemple `72.50`
- La requête principale compare ensuite chaque prix à cette valeur moyenne

**Résultat :**
| NomProduit | Prix |
|------------|------|
| Écran | 200.00 |

### Exemple 2 : Sous-requête dans la clause SELECT

Afficher chaque produit avec son prix et le prix moyen de tous les produits.

```sql
SELECT
    NomProduit,
    Prix,
    (SELECT AVG(Prix) FROM Produits) AS PrixMoyen
FROM Produits;
```

**Explication :**
- La sous-requête est utilisée comme une colonne calculée
- Elle retourne la même valeur (le prix moyen) pour chaque ligne
- C'est utile pour des comparaisons visuelles

**Résultat :**
| NomProduit | Prix | PrixMoyen |
|------------|------|-----------|
| Clavier | 25.00 | 72.50 |
| Souris | 15.00 | 72.50 |
| Écran | 200.00 | 72.50 |
| Webcam | 50.00 | 72.50 |

### Exemple 3 : Trouver le produit le plus commandé

Afficher les informations du produit qui a été commandé en plus grande quantité totale.

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE ProduitID = (
    SELECT TOP 1 ProduitID
    FROM Commandes
    GROUP BY ProduitID
    ORDER BY SUM(Quantite) DESC
);
```

**Explication :**
- La sous-requête identifie le `ProduitID` ayant la quantité totale la plus élevée
- Elle retourne une seule valeur (l'ID du produit)
- La requête principale utilise cet ID pour récupérer les détails du produit

### Exemple 4 : Calcul avec sous-requête

Afficher le prix de chaque produit et calculer l'écart par rapport au produit le plus cher.

```sql
SELECT
    NomProduit,
    Prix,
    (SELECT MAX(Prix) FROM Produits) - Prix AS EcartAvecMax
FROM Produits;
```

**Explication :**
- La sous-requête `(SELECT MAX(Prix) FROM Produits)` retourne le prix maximum
- On soustrait le prix de chaque produit pour obtenir l'écart

**Résultat :**
| NomProduit | Prix | EcartAvecMax |
|------------|------|--------------|
| Clavier | 25.00 | 175.00 |
| Souris | 15.00 | 185.00 |
| Écran | 200.00 | 0.00 |
| Webcam | 50.00 | 150.00 |

## Points importants à retenir

### ✅ Avantages des sous-requêtes scalaires

1. **Simplicité** : Permettent d'écrire des requêtes complexes de manière lisible
2. **Modularité** : La logique est isolée dans la sous-requête
3. **Flexibilité** : Utilisables dans de nombreux contextes (SELECT, WHERE, HAVING, etc.)

### ⚠️ Points d'attention

1. **Une seule valeur obligatoire** : Si la sous-requête retourne plusieurs lignes ou colonnes, vous obtiendrez une erreur
   ```sql
   -- ❌ ERREUR : Cette sous-requête retourne plusieurs lignes
   SELECT NomProduit
   FROM Produits
   WHERE Prix = (SELECT Prix FROM Produits);
   ```

2. **Gestion des NULL** : Si la sous-requête ne retourne aucun résultat, elle renvoie `NULL`
   ```sql
   -- Si aucun produit n'existe dans la catégorie 99, la sous-requête retourne NULL
   SELECT NomProduit
   FROM Produits
   WHERE Prix > (SELECT AVG(Prix) FROM Produits WHERE CategorieID = 99);
   ```

3. **Performance** : Les sous-requêtes scalaires sont réévaluées pour chaque ligne de la requête principale
   - Si la sous-requête est dans le `SELECT`, elle est exécutée pour chaque ligne retournée
   - Dans le `WHERE`, SQL Server optimise généralement et ne l'exécute qu'une fois

## Cas d'usage typiques

Les sous-requêtes scalaires sont particulièrement utiles pour :

- Comparer une valeur à un **agrégat** (moyenne, maximum, minimum, somme)
- Récupérer une **valeur de référence** depuis une autre table
- Effectuer des **calculs dynamiques** basés sur l'ensemble des données
- Filtrer les résultats en fonction d'une **condition calculée**

## Différence avec d'autres types de sous-requêtes

| Type | Retourne | Exemple d'usage |
|------|----------|-----------------|
| **Scalaire** | Une seule valeur (1 ligne, 1 colonne) | `WHERE Prix > (SELECT AVG(Prix) ...)` |
| Multi-lignes | Plusieurs lignes, 1 colonne | `WHERE ProduitID IN (SELECT ...)` |
| Table dérivée | Un ensemble de résultats (table) | `FROM (SELECT ...) AS T` |

## Résumé

Les sous-requêtes scalaires sont un outil puissant pour intégrer des calculs ou des valeurs de référence directement dans vos requêtes SQL. Leur règle d'or : **elles doivent toujours retourner exactement une valeur**. Elles rendent le code plus lisible et permettent d'éviter les requêtes séparées pour obtenir des valeurs de référence.
