# 3.2.4 IN, BETWEEN, LIKE (Wildcards % et _)

## Introduction

Dans les sections précédentes, vous avez appris à filtrer des données avec des conditions simples et à les combiner avec AND, OR et NOT. Maintenant, nous allons découvrir trois **opérateurs spéciaux** qui simplifient grandement l'écriture de certaines requêtes courantes :

- **IN** : Pour tester si une valeur appartient à une liste
- **BETWEEN** : Pour tester si une valeur est dans une plage
- **LIKE** : Pour rechercher des motifs dans du texte

Ces opérateurs vous feront gagner du temps et rendront votre code plus lisible.

---

## 1. L'opérateur IN

### Le problème sans IN

Imaginez que vous voulez trouver les clients de Paris, Lyon et Marseille. Avec ce que vous savez déjà, vous écririez :

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville = 'Paris'
   OR Ville = 'Lyon'
   OR Ville = 'Marseille'
```

Ça fonctionne, mais c'est **répétitif** et **long**, surtout si vous avez 10 villes !

### La solution : IN

L'opérateur `IN` permet de tester si une valeur fait partie d'une **liste de valeurs**.

**Syntaxe** :
```sql
WHERE colonne IN (valeur1, valeur2, valeur3, ...)
```

**Exemple équivalent** :
```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville IN ('Paris', 'Lyon', 'Marseille')
```

**Avantages** :
- ✅ Plus court
- ✅ Plus lisible
- ✅ Plus facile à maintenir

---

### Comment fonctionne IN ?

`IN` retourne `TRUE` si la valeur de la colonne **correspond à au moins une** des valeurs de la liste.

**Traduction** : "Est-ce que la ville est Paris **OU** Lyon **OU** Marseille ?"

| Ville du client | Dans la liste ? | Inclus ? |
|-----------------|-----------------|----------|
| Paris | ✅ Oui | ✅ Oui |
| Lyon | ✅ Oui | ✅ Oui |
| Marseille | ✅ Oui | ✅ Oui |
| Toulouse | ❌ Non | ❌ Non |
| Bordeaux | ❌ Non | ❌ Non |

---

### Exemples avec IN

#### Exemple 1 : Villes multiples

Trouver les clients de plusieurs villes :

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville IN ('Paris', 'Lyon', 'Marseille', 'Toulouse', 'Bordeaux')
```

---

#### Exemple 2 : Catégories de produits

Trouver les produits de plusieurs catégories :

```sql
SELECT NomProduit, Categorie, Prix
FROM Produits
WHERE Categorie IN ('Électronique', 'Informatique', 'Téléphonie')
```

---

#### Exemple 3 : Statuts de commandes

Trouver les commandes actives :

```sql
SELECT CommandeID, Statut, DateCommande
FROM Commandes
WHERE Statut IN ('En cours', 'En préparation', 'Expédiée')
```

---

#### Exemple 4 : Identifiants spécifiques

Trouver plusieurs clients par leurs IDs :

```sql
SELECT *
FROM Clients
WHERE ClientID IN (101, 205, 308, 412, 599)
```

**Note** : Pas d'apostrophes pour les nombres !

---

#### Exemple 5 : Années spécifiques

Trouver les employés embauchés certaines années :

```sql
SELECT Prenom, Nom, YEAR(DateEmbauche) AS Annee
FROM Employes
WHERE YEAR(DateEmbauche) IN (2020, 2021, 2022)
```

---

### L'opérateur NOT IN

Vous pouvez **exclure** des valeurs avec `NOT IN` :

**Syntaxe** :
```sql
WHERE colonne NOT IN (valeur1, valeur2, valeur3)
```

**Exemple** : Tous les clients **sauf** ceux de Paris, Lyon et Marseille

```sql
SELECT Prenom, Nom, Ville
FROM Clients
WHERE Ville NOT IN ('Paris', 'Lyon', 'Marseille')
```

**Équivalent avec OR** :
```sql
WHERE Ville != 'Paris'
  AND Ville != 'Lyon'
  AND Ville != 'Marseille'
```

**Note** : Avec `NOT IN`, vous devez utiliser **AND** (pas OR) dans l'équivalent.

---

### IN avec des nombres vs des chaînes

**Avec des nombres** (pas d'apostrophes) :
```sql
WHERE Age IN (18, 21, 25, 30)
WHERE Prix IN (9.99, 19.99, 29.99)
WHERE ClientID IN (1, 5, 10, 15)
```

**Avec des chaînes** (avec apostrophes) :
```sql
WHERE Ville IN ('Paris', 'Lyon')
WHERE Statut IN ('Actif', 'En attente')
WHERE Categorie IN ('Livres', 'DVD', 'Musique')
```

---

### Cas particulier : IN avec une sous-requête

`IN` peut aussi utiliser le résultat d'une autre requête (concept avancé que nous verrons plus tard) :

```sql
SELECT NomProduit
FROM Produits
WHERE CategorieID IN (
    SELECT CategorieID
    FROM Categories
    WHERE NomCategorie LIKE '%Électro%'
)
```

---

### Attention avec NULL et NOT IN

**Piège important** : Si votre liste contient `NULL`, `NOT IN` peut donner des résultats inattendus.

```sql
-- ⚠️ Attention si Email contient des NULL
WHERE Email NOT IN ('test@mail.com', NULL)
```

Cette requête pourrait ne retourner **aucun** résultat à cause du comportement de NULL.

**Recommandation** : Évitez NULL dans les listes IN/NOT IN, ou gérez-le explicitement.

## 2. L'opérateur BETWEEN

### Le problème sans BETWEEN

Pour trouver les produits entre 50€ et 100€, vous écririez :

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix >= 50 AND Prix <= 100
```

C'est correct, mais encore une fois, il y a **plus simple** !

### La solution : BETWEEN

L'opérateur `BETWEEN` teste si une valeur est **dans une plage** (bornes incluses).

**Syntaxe** :
```sql
WHERE colonne BETWEEN valeur_min AND valeur_max
```

**Exemple équivalent** :
```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix BETWEEN 50 AND 100
```

**Important** : Les deux bornes sont **INCLUSES** (50 et 100 compris).

---

### Comment fonctionne BETWEEN ?

`BETWEEN x AND y` est équivalent à `>= x AND <= y`

**Visualisation** :

```
    0     25    50    75    100   125   150
    |_____|_____|_____|_____|_____|_____|
              ↑                    ↑
         [  50  ≤  valeur  ≤  100  ]
              ↑____________________↑
              Bornes INCLUSES
```

Valeurs incluses : 50, 51, ..., 99, 100

---

### Exemples avec BETWEEN

#### Exemple 1 : Plage de prix

Produits de milieu de gamme :

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix BETWEEN 100 AND 500
```

**Équivalent** :
```sql
WHERE Prix >= 100 AND Prix <= 500
```

---

#### Exemple 2 : Plage d'âges

Employés entre 25 et 40 ans :

```sql
SELECT Prenom, Nom, Age
FROM Employes
WHERE Age BETWEEN 25 AND 40
```

Inclut les employés de 25 ans **et** de 40 ans.

---

#### Exemple 3 : Plage de dates

Commandes du premier trimestre 2024 :

```sql
SELECT CommandeID, DateCommande, MontantTotal
FROM Commandes
WHERE DateCommande BETWEEN '2024-01-01' AND '2024-03-31'
```

Inclut les commandes du 1er janvier **et** du 31 mars.

---

#### Exemple 4 : Plage de stock

Produits avec un stock moyen :

```sql
SELECT NomProduit, Stock
FROM Produits
WHERE Stock BETWEEN 10 AND 50
```

---

#### Exemple 5 : Période spécifique

Employés embauchés entre 2020 et 2022 :

```sql
SELECT Prenom, Nom, DateEmbauche
FROM Employes
WHERE YEAR(DateEmbauche) BETWEEN 2020 AND 2022
```

---

### L'opérateur NOT BETWEEN

Pour **exclure** une plage, utilisez `NOT BETWEEN` :

**Syntaxe** :
```sql
WHERE colonne NOT BETWEEN valeur_min AND valeur_max
```

**Exemple** : Produits **hors** de la gamme de prix moyenne

```sql
SELECT NomProduit, Prix
FROM Produits
WHERE Prix NOT BETWEEN 50 AND 100
```

**Équivalent** :
```sql
WHERE Prix < 50 OR Prix > 100
```

**Résultat** : Produits soit très bon marché (< 50€) soit chers (> 100€).

---

### BETWEEN avec des dates : Attention aux heures !

**Piège courant** : BETWEEN avec des dates incluant l'heure

```sql
-- ⚠️ Attention : exclut les commandes après 00:00:00 du 31 mars
WHERE DateCommande BETWEEN '2024-03-01' AND '2024-03-31'
```

Si `DateCommande` contient une heure (ex: `2024-03-31 14:30:00`), elle sera **exclue** !

**✅ Solution 1** : Utiliser le jour suivant avec `<`
```sql
WHERE DateCommande >= '2024-03-01' AND DateCommande < '2024-04-01'
```

**✅ Solution 2** : Spécifier l'heure de fin
```sql
WHERE DateCommande BETWEEN '2024-03-01 00:00:00' AND '2024-03-31 23:59:59'
```

---

### BETWEEN avec des chaînes de caractères

`BETWEEN` fonctionne aussi avec du texte (ordre alphabétique) :

```sql
SELECT Nom
FROM Clients
WHERE Nom BETWEEN 'D' AND 'M'
```

**Résultat** : Noms commençant par D, E, F, G, H, I, J, K, L, M

**Note** : 'M' est inclus, mais pas 'Martin' (commence par 'Ma' qui vient après 'M').

---

### Ordre des valeurs dans BETWEEN

**Important** : La valeur minimale doit être **avant** la valeur maximale !

**❌ Incorrect** :
```sql
WHERE Prix BETWEEN 100 AND 50  -- Inversé !
```

Cette requête retournera **zéro** résultat.

**✅ Correct** :
```sql
WHERE Prix BETWEEN 50 AND 100
```

## 3. L'opérateur LIKE

### Le problème de la correspondance exacte

Jusqu'à présent, nous avons cherché des **correspondances exactes** :

```sql
WHERE Nom = 'Dupont'
```

Mais que faire si vous voulez :
- Tous les noms **commençant par** "Du" ?
- Tous les emails **se terminant par** "@gmail.com" ?
- Tous les produits **contenant** le mot "portable" ?

**La solution** : L'opérateur `LIKE` !

---

### Introduction à LIKE

L'opérateur `LIKE` permet de rechercher des **motifs** (patterns) dans du texte en utilisant des **caractères génériques** (wildcards).

**Syntaxe** :
```sql
WHERE colonne LIKE 'motif'
```

**Les deux wildcards** :
- `%` : Représente **zéro, un ou plusieurs** caractères
- `_` : Représente **exactement un** caractère

---

## 4. Le wildcard % (pourcentage)

### Signification

Le symbole `%` remplace **n'importe quelle séquence de caractères** (même vide).

### Patterns courants avec %

| Pattern | Signification | Exemple |
|---------|---------------|---------|
| `'A%'` | Commence par A | Alice, Antoine, Avion |
| `'%a'` | Se termine par a | Anna, Maria, Pizza |
| `'%or%'` | Contient "or" | Ordinateur, Portable, Trésor |
| `'A%e'` | Commence par A, finit par e | Alice, Antoine, Avenue |
| `'%'` | N'importe quoi | Tout (équivalent à pas de filtre) |

---

### Exemples avec % au début

**Pattern** : `'%texte'` → Se termine par "texte"

```sql
-- Tous les emails Gmail
SELECT Prenom, Nom, Email
FROM Clients
WHERE Email LIKE '%@gmail.com'
```

**Résultat** :
- ✅ sophie.martin@gmail.com
- ✅ pierre.dupont@gmail.com
- ❌ marie@yahoo.fr

---

```sql
-- Produits se terminant par "ette"
SELECT NomProduit
FROM Produits
WHERE NomProduit LIKE '%ette'
```

**Résultat** :
- ✅ Tablette
- ✅ Raquette
- ✅ Disquette
- ❌ Ordinateur

---

### Exemples avec % à la fin

**Pattern** : `'texte%'` → Commence par "texte"

```sql
-- Clients dont le nom commence par "Mar"
SELECT Prenom, Nom
FROM Clients
WHERE Nom LIKE 'Mar%'
```

**Résultat** :
- ✅ Martin
- ✅ Martinez
- ✅ Marchand
- ❌ Dupont

---

```sql
-- Produits commençant par "Ordi"
SELECT NomProduit
FROM Produits
WHERE NomProduit LIKE 'Ordi%'
```

**Résultat** :
- ✅ Ordinateur
- ✅ Ordinateur Portable
- ✅ Ordinateur de Bureau
- ❌ Tablette

---

### Exemples avec % au milieu

**Pattern** : `'%texte%'` → Contient "texte" (n'importe où)

```sql
-- Produits contenant le mot "portable"
SELECT NomProduit
FROM Produits
WHERE NomProduit LIKE '%portable%'
```

**Résultat** :
- ✅ Ordinateur Portable
- ✅ Disque Dur Portable
- ✅ Batterie Portable
- ❌ Tablette

---

```sql
-- Clients avec "marie" dans leur prénom
SELECT Prenom, Nom
FROM Clients
WHERE Prenom LIKE '%marie%'
```

**Résultat** :
- ✅ Marie
- ✅ Marie-Claire
- ✅ Anne-Marie
- ✅ Rosemarie
- ❌ Sophie

---

### Exemples avec % aux deux extrémités

**Pattern** : `'texte1%texte2'` → Commence par "texte1" et finit par "texte2"

```sql
-- Noms commençant par "M" et finissant par "n"
SELECT Nom
FROM Clients
WHERE Nom LIKE 'M%n'
```

**Résultat** :
- ✅ Martin
- ✅ Morin
- ✅ Maison
- ❌ Moreau (finit par 'u')
- ❌ Dupont (ne commence pas par 'M')

---

### Exemples pratiques avec %

#### E-commerce

```sql
-- Recherche de produits Apple
SELECT NomProduit, Prix
FROM Produits
WHERE NomProduit LIKE '%Apple%'
```

```sql
-- Produits "Pro"
SELECT NomProduit
FROM Produits
WHERE NomProduit LIKE '%Pro%'
```

---

#### Recherche d'adresse

```sql
-- Clients habitant rue de la Paix
SELECT Prenom, Nom, Adresse
FROM Clients
WHERE Adresse LIKE '%rue de la Paix%'
```

```sql
-- Toutes les adresses à Paris
SELECT Prenom, Nom, Adresse
FROM Clients
WHERE Adresse LIKE '%Paris%'
```

---

#### Recherche de téléphone

```sql
-- Numéros commençant par 06 (mobiles français)
SELECT Prenom, Nom, Telephone
FROM Clients
WHERE Telephone LIKE '06%'
```

```sql
-- Numéros contenant "12 34"
SELECT Prenom, Nom, Telephone
FROM Clients
WHERE Telephone LIKE '%12 34%'
```

## 5. Le wildcard _ (underscore)

### Signification

Le symbole `_` (underscore) remplace **exactement un** caractère (ni plus, ni moins).

### Différence entre % et _

| Wildcard | Nombre de caractères | Exemple |
|----------|---------------------|---------|
| `%` | 0, 1, ou plusieurs | `'A%'` = A, AB, ABC, ABCD... |
| `_` | Exactement 1 | `'A_'` = AB, AC, AD (2 caractères uniquement) |

---

### Patterns courants avec _

| Pattern | Signification | Exemple |
|---------|---------------|---------|
| `'A_'` | A suivi d'un caractère | AB, AC, A1, A9 |
| `'_A'` | Un caractère puis A | BA, CA, 1A, 9A |
| `'A__'` | A suivi de 2 caractères | ABC, A12, AXY |
| `'___'` | Exactement 3 caractères | ABC, 123, XYZ |
| `'A_C'` | A, un caractère, puis C | ABC, ADC, A1C |

---

### Exemples avec _

#### Exemple 1 : Codes à format fixe

Trouver les codes produits au format "A" suivi de 3 chiffres :

```sql
SELECT CodeProduit, NomProduit
FROM Produits
WHERE CodeProduit LIKE 'A___'
```

**Résultat** :
- ✅ A123
- ✅ A456
- ✅ A789
- ❌ A12 (trop court)
- ❌ A1234 (trop long)
- ❌ B123 (ne commence pas par A)

---

#### Exemple 2 : Codes postaux

Codes postaux commençant par 75 (Paris) :

```sql
SELECT Nom, CodePostal
FROM Clients
WHERE CodePostal LIKE '75___'
```

**Résultat** :
- ✅ 75001
- ✅ 75015
- ✅ 75020
- ❌ 7500 (trop court)
- ❌ 750001 (trop long)
- ❌ 69001 (ne commence pas par 75)

---

#### Exemple 3 : Dates avec format spécifique

Dates en 202X (2020-2029) :

```sql
SELECT CommandeID, DateCommande
FROM Commandes
WHERE CONVERT(VARCHAR, DateCommande, 23) LIKE '202_-__-__'
```

**Note** : Cet exemple montre que `_` peut être combiné avec du texte fixe.

---

#### Exemple 4 : Noms de 4 lettres

Clients avec un prénom de exactement 4 lettres :

```sql
SELECT Prenom, Nom
FROM Clients
WHERE Prenom LIKE '____'
```

**Résultat** :
- ✅ Jean
- ✅ Anne
- ✅ Paul
- ❌ Sophie (5 lettres)
- ❌ Luc (3 lettres)

---

### Combinaison de _ et %

Vous pouvez combiner les deux wildcards !

#### Exemple 1 : Format flexible

Noms commençant par "M", suivi de 2 caractères quelconques, puis "tin" :

```sql
SELECT Nom
FROM Clients
WHERE Nom LIKE 'M__tin'
```

**Résultat** :
- ✅ Martin (M + ar + tin)
- ✅ Mautin (M + au + tin)
- ❌ Mortin (M + or + tin) → "Mortin" a 6 lettres, donc ça marche !
- ❌ Mtin (trop court)
- ❌ Maartin (trop long)

---

#### Exemple 2 : Email avec format spécifique

Emails avec exactement 3 caractères avant le @ :

```sql
SELECT Email
FROM Clients
WHERE Email LIKE '___@%'
```

**Résultat** :
- ✅ joe@mail.com
- ✅ ann@test.fr
- ❌ john@mail.com (4 lettres avant @)
- ❌ j@mail.com (1 lettre avant @)

---

#### Exemple 3 : Téléphones avec format

Numéros de téléphone au format 06.__.__.__.__ :

```sql
SELECT Telephone
FROM Clients
WHERE Telephone LIKE '06.__.__.__.__ '
```

## 6. L'opérateur NOT LIKE

Pour **exclure** des motifs, utilisez `NOT LIKE` :

**Syntaxe** :
```sql
WHERE colonne NOT LIKE 'motif'
```

### Exemples avec NOT LIKE

#### Exemple 1 : Exclure des emails

Tous les clients sauf ceux avec Gmail :

```sql
SELECT Prenom, Nom, Email
FROM Clients
WHERE Email NOT LIKE '%@gmail.com'
```

---

#### Exemple 2 : Exclure des produits

Tous les produits sauf ceux contenant "Portable" :

```sql
SELECT NomProduit
FROM Produits
WHERE NomProduit NOT LIKE '%Portable%'
```

---

#### Exemple 3 : Exclure un préfixe

Tous les clients dont le nom ne commence pas par "Du" :

```sql
SELECT Nom
FROM Clients
WHERE Nom NOT LIKE 'Du%'
```

---

## 7. Sensibilité à la casse avec LIKE

Par défaut en SQL Server, `LIKE` **n'est pas sensible à la casse** (selon la collation) :

```sql
WHERE Nom LIKE 'martin%'
WHERE Nom LIKE 'Martin%'
WHERE Nom LIKE 'MARTIN%'
```

Ces trois requêtes sont souvent **équivalentes** et trouveront :
- Martin
- MARTIN
- martin
- Martinez

**Pour forcer la sensibilité à la casse** (avancé) :

```sql
WHERE Nom COLLATE Latin1_General_CS_AS LIKE 'Martin%'
```

## 8. Caractères d'échappement

### Le problème

Que faire si vous cherchez littéralement un `%` ou un `_` dans vos données ?

**Exemple** : Trouver les produits dont le nom contient "50%" (comme "Remise 50%")

```sql
-- ❌ Ceci ne fonctionne pas comme attendu
WHERE NomProduit LIKE '%50%%'
```

Le deuxième `%` sera interprété comme un wildcard, pas comme le symbole %.

---

### La solution : Échappement avec [ ]

Encadrez le caractère spécial avec des crochets :

```sql
-- ✅ Correct : cherche littéralement "50%"
WHERE NomProduit LIKE '%50[%]%'
```

**Explication** :
- Premier `%` : wildcard (0 ou plusieurs caractères)
- `50` : texte littéral
- `[%]` : le caractère % littéral
- Dernier `%` : wildcard (0 ou plusieurs caractères)

---

### Exemples d'échappement

#### Chercher un underscore littéral

```sql
-- Trouver "Code_Produit" (avec underscore)
WHERE Description LIKE '%Code[_]Produit%'
```

---

#### Chercher des crochets littéraux

```sql
-- Trouver "[Nouveau]"
WHERE Tag LIKE '%[[]Nouveau]%'
```

---

## 9. Performance de LIKE

### Considérations de performance

**⚠️ Attention** : `LIKE` peut être **lent** sur de grandes tables, surtout avec un wildcard au début.

#### Performances relatives

| Pattern | Performance | Peut utiliser un index ? |
|---------|-------------|-------------------------|
| `'texte%'` | ✅ Rapide | ✅ Oui |
| `'%texte'` | ⚠️ Lent | ❌ Non |
| `'%texte%'` | ⚠️ Lent | ❌ Non |

**Pourquoi ?**

Les index (nous les verrons plus tard) fonctionnent bien pour trouver des valeurs qui **commencent** par quelque chose, mais pas pour celles qui **contiennent** ou **finissent** par quelque chose.

### Recommandations

1. **Évitez `%` au début** quand c'est possible :
   ```sql
   -- ✅ Rapide
   WHERE Nom LIKE 'Mar%'

   -- ⚠️ Plus lent
   WHERE Nom LIKE '%tin'
   ```

2. **Pour des recherches complexes**, envisagez :
   - La recherche en texte intégral (Full-Text Search)
   - Des colonnes calculées
   - Des outils de recherche dédiés (Elasticsearch, etc.)

```sql
-- Recherche par nom partiel

-- Recherche par ville

FROM Clients

SELECT Prenom, Nom, Email
FROM Clients

```

### Recherche de produits

```sql
-- Produits d'une marque
SELECT NomProduit, Prix

SELECT NomProduit
FROM Produits
WHERE NomProduit LIKE '%Pro%'

-- Catégorie
SELECT NomProduit
FROM Produits

```

---

### Filtrage de données

```sql
-- Exclure les emails de test
SELECT *
FROM Commandes
WHERE EmailClient NOT LIKE '%test%'
  AND EmailClient NOT LIKE '%demo%'

-- Trouver les anomalies
SELECT *
FROM Produits
WHERE CodeProduit NOT LIKE '[A-Z][A-Z][A-Z]___'  -- Format attendu: 3 lettres + 3 chiffres
```

## 11. Tableau récapitulatif

### Opérateurs

| Opérateur | Fonction | Exemple | Résultat |
|-----------|----------|---------|----------|
| **IN** | Liste de valeurs | `WHERE Ville IN ('Paris', 'Lyon')` | Paris ou Lyon |
| **NOT IN** | Exclut une liste | `WHERE Ville NOT IN ('Paris')` | Sauf Paris |
| **BETWEEN** | Plage (incluse) | `WHERE Prix BETWEEN 50 AND 100` | 50 ≤ Prix ≤ 100 |
| **NOT BETWEEN** | Hors plage | `WHERE Prix NOT BETWEEN 50 AND 100` | Prix < 50 ou Prix > 100 |
| **LIKE** | Motif de texte | `WHERE Nom LIKE 'M%'` | Commence par M |
| **NOT LIKE** | Exclut un motif | `WHERE Nom NOT LIKE 'M%'` | Ne commence pas par M |

---

### Wildcards

| Wildcard | Signification | Exemple | Correspond à |
|----------|---------------|---------|--------------|
| `%` | 0 ou plusieurs caractères | `'A%'` | A, AB, ABC, ABCD... |
| `%` | 0 ou plusieurs caractères | `'%Z'` | Z, AZ, ABZ, ABCZ... |
| `%` | 0 ou plusieurs caractères | `'%test%'` | test, testing, protest... |
| `_` | Exactement 1 caractère | `'A_'` | AB, AC, A1... (2 car. exactement) |
| `_` | Exactement 1 caractère | `'A__'` | ABC, A12... (3 car. exactement) |

## 12. Comparaisons et équivalences

### IN vs OR

```sql
-- Avec OR (long)
WHERE Ville = 'Paris' OR Ville = 'Lyon' OR Ville = 'Marseille'

-- Avec IN (court)
WHERE Ville IN ('Paris', 'Lyon', 'Marseille')
```

**✅ Préférez IN** : Plus lisible et maintenable.

---

### BETWEEN vs AND

```sql
-- Avec AND
WHERE Prix >= 50 AND Prix <= 100

-- Avec BETWEEN
WHERE Prix BETWEEN 50 AND 100
```

**✅ Préférez BETWEEN** : Plus concis et expressif.

---

### LIKE vs =

```sql
-- Égalité stricte
WHERE Nom = 'Martin'  -- Seulement "Martin" exactement

-- Recherche de motif
WHERE Nom LIKE 'Martin%'  -- Martin, Martinez, Martini...
```

**Conseil** : Utilisez `=` pour les correspondances exactes (plus rapide).

---

## 13. Bonnes pratiques

### ✅ À faire

1. **Utilisez IN pour plusieurs valeurs** :
   ```sql
   WHERE Statut IN ('Actif', 'En cours', 'Validé')
   ```

2. **BETWEEN pour les plages** :
   ```sql
   WHERE Prix BETWEEN 50 AND 100
   ```

3. **LIKE sans % au début quand possible** :
   ```sql
   WHERE Nom LIKE 'Mar%'  -- ✅ Peut utiliser un index
   ```

4. **Échappez les caractères spéciaux** :
   ```sql
   WHERE Description LIKE '%50[%]%'  -- Cherche littéralement "50%"
   ```

5. **Testez vos patterns LIKE** :
   ```sql
   -- Vérifiez d'abord le nombre de résultats
   SELECT COUNT(*) FROM Clients WHERE Nom LIKE '%test%'
   ```

---

### ❌ À éviter

1. **OR répétitifs** :
   ```sql
   WHERE x = 1 OR x = 2 OR x = 3 OR x = 4  -- ❌ Utilisez IN
   ```

2. **Conditions redondantes** :
   ```sql
   WHERE Prix >= 50 AND Prix <= 100 AND Prix BETWEEN 50 AND 100  -- ❌ Redondant
   ```

3. **LIKE au lieu de =** :
   ```sql
   WHERE Nom LIKE 'Martin'  -- ⚠️ Utilisez = pour l'égalité exacte
   ```

4. **LIKE avec % des deux côtés sans raison** :
   ```sql
   WHERE Nom LIKE '%Martin%'  -- ⚠️ Lent, évitez si possible
   ```

5. **BETWEEN inversé** :
   ```sql
   WHERE Prix BETWEEN 100 AND 50  -- ❌ Min doit être avant Max
   ```

---

## Résumé

### Points clés à retenir

1. **IN** : Liste de valeurs possibles
   - `WHERE Ville IN ('Paris', 'Lyon')`
   - Plus court que plusieurs OR

2. **BETWEEN** : Plage de valeurs (bornes incluses)
   - `WHERE Prix BETWEEN 50 AND 100`
   - Équivalent à `>= min AND <= max`

3. **LIKE** : Recherche de motifs dans du texte
   - `%` : 0 ou plusieurs caractères
   - `_` : Exactement 1 caractère

4. **Performance** : LIKE avec `%` au début est lent

5. **NOT** : Fonctionne avec IN, BETWEEN, et LIKE

### Aide-mémoire

| Besoin | Opérateur | Exemple |
|--------|-----------|---------|
| Plusieurs valeurs exactes | IN | `IN ('A', 'B', 'C')` |
| Plage de valeurs | BETWEEN | `BETWEEN 10 AND 20` |
| Commence par | LIKE | `LIKE 'text%'` |
| Se termine par | LIKE | `LIKE '%text'` |
| Contient | LIKE | `LIKE '%text%'` |
| Format fixe | LIKE avec _ | `LIKE '___'` (3 car.) |
