# 2.4.1 Syntaxe INSERT INTO ... VALUES

## Introduction

L'instruction `INSERT INTO` est l'une des commandes fondamentales du langage SQL. Elle permet d'**ajouter de nouvelles lignes de données** dans une table existante. C'est l'équivalent de "remplir un formulaire" et de l'enregistrer dans votre base de données.

Une fois que vous avez créé votre structure de table (avec `CREATE TABLE`), vous devez la remplir avec des données réelles. C'est exactement le rôle de l'instruction `INSERT INTO`.

---

## Syntaxe de base

La forme la plus simple de l'instruction `INSERT INTO` suit cette structure :

```sql
INSERT INTO nom_de_table (colonne1, colonne2, colonne3, ...)
VALUES (valeur1, valeur2, valeur3, ...);
```

### Décomposition de la syntaxe

- **INSERT INTO** : Mots-clés indiquant que nous voulons insérer des données
- **nom_de_table** : Le nom de la table dans laquelle vous souhaitez ajouter des données
- **(colonne1, colonne2, ...)** : La liste des colonnes pour lesquelles vous fournissez des valeurs
- **VALUES** : Mot-clé qui introduit les valeurs à insérer
- **(valeur1, valeur2, ...)** : Les valeurs correspondant aux colonnes, **dans le même ordre**

> **Important** : L'ordre des valeurs doit correspondre exactement à l'ordre des colonnes spécifiées.

---

## Exemple simple et détaillé

Imaginons que nous avons une table `Employes` avec la structure suivante :

```sql
CREATE TABLE Employes (
    EmployeID INT PRIMARY KEY,
    Prenom VARCHAR(50),
    Nom VARCHAR(50),
    Email VARCHAR(100),
    Salaire DECIMAL(10, 2)
);
```

### Insertion d'une ligne complète

Pour ajouter un nouvel employé, nous utilisons :

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom, Email, Salaire)
VALUES (1, 'Marie', 'Dupont', 'marie.dupont@example.com', 45000.00);
```

**Que se passe-t-il ici ?**
- Nous insérons une nouvelle ligne dans la table `Employes`
- `EmployeID` prendra la valeur `1`
- `Prenom` prendra la valeur `'Marie'`
- `Nom` prendra la valeur `'Dupont'`
- `Email` prendra la valeur `'marie.dupont@example.com'`
- `Salaire` prendra la valeur `45000.00`

---

## Types de valeurs

### Valeurs numériques

Les nombres s'écrivent **sans guillemets** :

```sql
INSERT INTO Produits (ProduitID, Prix, Quantite)
VALUES (101, 29.99, 150);
```

### Valeurs textuelles (chaînes de caractères)

Les chaînes de caractères doivent être entourées de **guillemets simples** `'...'` :

```sql
INSERT INTO Clients (ClientID, Nom, Ville)
VALUES (1, 'Jean Martin', 'Paris');
```

> **Attention** : En T-SQL, on utilise les guillemets simples (`'`) pour les chaînes, pas les guillemets doubles (`"`).

### Valeurs de dates

Les dates sont également entourées de guillemets simples :

```sql
INSERT INTO Commandes (CommandeID, DateCommande, DateLivraison)
VALUES (5001, '2025-01-15', '2025-01-20');
```

**Format recommandé** : `'YYYY-MM-DD'` (Année-Mois-Jour), par exemple `'2025-11-16'`

---

## Insertion sans spécifier les noms de colonnes

Il est possible d'omettre la liste des colonnes, mais **uniquement si vous fournissez des valeurs pour toutes les colonnes de la table**, dans l'ordre exact de leur création :

```sql
INSERT INTO Employes
VALUES (2, 'Pierre', 'Durand', 'pierre.durand@example.com', 42000.00);
```

### Pourquoi cette approche est déconseillée ?

Bien que valide, cette syntaxe présente des **risques importants** :

1. **Fragilité** : Si la structure de la table change (ajout ou réorganisation de colonnes), votre code peut se casser
2. **Lisibilité réduite** : Il est difficile de savoir quelle valeur correspond à quelle colonne
3. **Erreurs silencieuses** : Vous pourriez insérer des données dans les mauvaises colonnes sans le remarquer

> **Bonne pratique** : Spécifiez **toujours** explicitement les noms des colonnes.

---

## Insertion partielle (colonnes facultatives)

Vous n'êtes **pas obligé** de fournir des valeurs pour toutes les colonnes. Vous pouvez insérer des données uniquement pour certaines colonnes, à condition que :

1. Les colonnes omises acceptent les valeurs `NULL`, OU
2. Les colonnes omises ont une valeur par défaut (`DEFAULT`), OU
3. Les colonnes omises sont auto-générées (comme une colonne `IDENTITY`)

### Exemple

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES (3, 'Sophie', 'Bernard');
```

Dans cet exemple :
- Seules trois colonnes reçoivent des valeurs
- `Email` et `Salaire` seront définis à `NULL` (si aucune valeur par défaut n'est définie)

---

## Gestion des valeurs NULL

Si vous souhaitez **explicitement** insérer une valeur `NULL` dans une colonne, utilisez le mot-clé `NULL` (sans guillemets) :

```sql
INSERT INTO Employes (EmployeID, Prenom, Nom, Email, Salaire)
VALUES (4, 'Luc', 'Petit', NULL, 38000.00);
```

Ici, l'employé n'a pas d'adresse email (valeur `NULL`).

> **Note** : `NULL` signifie "absence de valeur" ou "valeur inconnue", ce n'est pas la même chose qu'une chaîne vide `''`.

---

## Gestion des chaînes avec apostrophes

Si votre chaîne de caractères contient une apostrophe (guillemet simple), vous devez la **doubler** pour l'échapper :

```sql
INSERT INTO Clients (ClientID, Nom)
VALUES (10, 'L''Entreprise Moderne');
```

Notez les **deux apostrophes** consécutives dans `L''Entreprise` pour représenter une seule apostrophe dans la valeur finale.

---

## Vérification après insertion

Après avoir inséré des données, vous pouvez vérifier que l'insertion s'est bien déroulée en interrogeant la table :

```sql
SELECT * FROM Employes;
```

Cette commande affichera toutes les lignes de la table `Employes`, y compris celle que vous venez d'insérer.

---

## Erreurs courantes et comment les éviter

### 1. Nombre de colonnes ≠ Nombre de valeurs

```sql
-- ❌ INCORRECT : 3 colonnes mais 2 valeurs
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES (5, 'Alice');
```

**Erreur** : "Le nombre de valeurs ne correspond pas au nombre de colonnes."

**Solution** : Assurez-vous que chaque colonne a une valeur correspondante.

### 2. Type de données incompatible

```sql
-- ❌ INCORRECT : Texte dans une colonne numérique
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES ('ABC', 'Bob', 'Smith');
```

**Erreur** : "Erreur de conversion du type de données."

**Solution** : Respectez le type de données défini pour chaque colonne.

### 3. Violation de contrainte de clé primaire

```sql
-- ❌ INCORRECT : EmployeID = 1 existe déjà
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES (1, 'Julie', 'Moreau');
```

**Erreur** : "Violation de contrainte PRIMARY KEY. Impossible d'insérer une clé dupliquée."

**Solution** : Utilisez une valeur unique pour la clé primaire.

### 4. Oubli des guillemets pour les chaînes

```sql
-- ❌ INCORRECT : Guillemets manquants
INSERT INTO Employes (EmployeID, Prenom, Nom)
VALUES (6, Paul, Legrand);
```

**Erreur** : SQL pense que `Paul` et `Legrand` sont des noms de colonnes ou de variables.

**Solution** : Entourez les chaînes de guillemets simples : `'Paul'`, `'Legrand'`.

---

## Bonnes pratiques

### ✅ À faire

1. **Spécifiez toujours les noms de colonnes** explicitement
2. **Utilisez des guillemets simples** pour les chaînes et les dates
3. **Respectez les types de données** de chaque colonne
4. **Vérifiez vos insertions** avec un `SELECT` après l'opération
5. **Utilisez des noms significatifs** pour vos valeurs

### ❌ À éviter

1. Omettre la liste des colonnes
2. Utiliser `SELECT *` sans raison
3. Insérer des valeurs sans valider leur format
4. Oublier de gérer les apostrophes dans les chaînes

---

## Résumé

L'instruction `INSERT INTO ... VALUES` est essentielle pour ajouter des données dans vos tables SQL Server. Voici les points clés à retenir :

- **Syntaxe** : `INSERT INTO table (colonnes) VALUES (valeurs);`
- **Ordre** : Les valeurs doivent correspondre exactement à l'ordre des colonnes
- **Types** : Respectez les types de données (nombres sans guillemets, textes avec guillemets simples)
- **NULL** : Utilisez le mot-clé `NULL` pour insérer une absence de valeur
- **Bonne pratique** : Spécifiez toujours les noms des colonnes explicitement

Avec cette commande, vous êtes maintenant capable d'ajouter des données à vos tables et de commencer à construire votre base de données !
