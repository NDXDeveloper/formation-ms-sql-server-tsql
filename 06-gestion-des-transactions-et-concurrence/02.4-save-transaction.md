# 6.2.4 SAVE TRANSACTION (Points de Sauvegarde)

## Introduction

Nous avons vu que `ROLLBACK` annule **toute** une transaction, ramenant la base de données à son état initial avant le `BEGIN TRANSACTION`. Mais que faire si vous voulez annuler seulement **une partie** de votre transaction, tout en conservant le reste ?

C'est là qu'interviennent les **points de sauvegarde** (savepoints) avec la commande `SAVE TRANSACTION`. Cette fonctionnalité vous permet de créer des "checkpoints" à l'intérieur d'une transaction, vers lesquels vous pouvez revenir en cas de besoin, sans annuler toute la transaction.

## Qu'est-ce qu'un Point de Sauvegarde ?

Un **point de sauvegarde** (savepoint) est un **marqueur** placé à l'intérieur d'une transaction. Il vous permet de faire un `ROLLBACK` partiel jusqu'à ce point, au lieu d'annuler toute la transaction.

### Analogie : Les Points de Contrôle dans un Jeu Vidéo

Imaginez que vous jouez à un jeu vidéo avec plusieurs niveaux :

```
Début du Jeu (BEGIN TRANSACTION)
    │
    ├─► Niveau 1 terminé ✓
    │   └─► POINT DE SAUVEGARDE 1 💾
    │
    ├─► Niveau 2 terminé ✓
    │   └─► POINT DE SAUVEGARDE 2 💾
    │
    ├─► Niveau 3 : ÉCHEC ❌
    │
    └─► Charger le Point de Sauvegarde 2
        └─► Vous recommencez au Niveau 3
            (mais vous gardez les progrès des niveaux 1 et 2)
```

Sans points de sauvegarde, échouer au niveau 3 vous ferait recommencer **depuis le début du jeu**.

Avec points de sauvegarde, vous recommencez seulement **depuis le dernier checkpoint**.

### Autre Analogie : Le Traitement de Texte

```
Rédaction d'un Document (Transaction)
    │
    ├─► Écrire l'introduction
    │   └─► Sauvegarde "Intro" 💾
    │
    ├─► Écrire le chapitre 1
    │   └─► Sauvegarde "Chapitre1" 💾
    │
    ├─► Écrire le chapitre 2
    │   └─► Oups, pas satisfait ❌
    │
    └─► Revenir à "Chapitre1"
        └─► Réécrire le chapitre 2 différemment
            (l'intro et le chapitre 1 sont conservés)
```

---

## Syntaxe de SAVE TRANSACTION

### Créer un Point de Sauvegarde

```sql
SAVE TRANSACTION nom_sauvegarde;
-- ou en abrégé :
SAVE TRAN nom_sauvegarde;
```

Le nom de sauvegarde doit être un **identifiant valide** (comme un nom de variable).

### Revenir à un Point de Sauvegarde

```sql
ROLLBACK TRANSACTION nom_sauvegarde;
-- ou en abrégé :
ROLLBACK TRAN nom_sauvegarde;
```

**Important :** Quand vous spécifiez un nom dans ROLLBACK, vous revenez à ce point de sauvegarde. Si vous n'indiquez pas de nom, vous annulez **toute** la transaction.

## Comment Fonctionnent les Points de Sauvegarde

### Schéma Conceptuel

```
BEGIN TRANSACTION
    │
    ├─► Opération A
    ├─► Opération B
    │
    ├─► SAVE TRANSACTION Point1 💾
    │
    ├─► Opération C
    ├─► Opération D
    │
    ├─► SAVE TRANSACTION Point2 💾
    │
    ├─► Opération E
    ├─► Opération F (ERREUR ❌)
    │
    └─► ROLLBACK TO Point2
        │
        ├─► Opération E annulée ⏪
        ├─► Opération F annulée ⏪
        │
        └─► État : A, B, C, D sont conservés ✓
            Point2 est toujours actif
            On peut continuer la transaction
```

### Ce qui se Passe en Mémoire

```
Ligne du Temps de la Transaction :

T1: BEGIN TRANSACTION
    │
T2: INSERT Ligne1          ──► Enregistrée dans le journal
    │
T3: UPDATE Table1          ──► Enregistrée dans le journal
    │
T4: SAVE TRANSACTION SP1   ──► 💾 Marqueur placé dans le journal
    │
T5: INSERT Ligne2          ──► Enregistrée dans le journal
    │
T6: DELETE FROM Table2     ──► Enregistrée dans le journal
    │
T7: ROLLBACK TO SP1        ──► ⏪ Annulation jusqu'au marqueur SP1
    │                          (T5 et T6 annulés, T2 et T3 conservés)
    │
T8: INSERT Ligne3          ──► Nouvelle opération après le rollback
    │
T9: COMMIT                 ──► ✅ Valide T2, T3 et T8
                                (T5 et T6 ont été annulés)
```

## Exemples Détaillés

### Exemple 1 : Point de Sauvegarde Simple

Voici l'utilisation la plus basique des points de sauvegarde :

```sql
BEGIN TRANSACTION;

    -- Opération 1 : Créer un client
    INSERT INTO Clients (ClientID, Nom, Email)
    VALUES (1001, 'Martin Dupont', 'martin@example.com');
    PRINT 'Client créé';

    -- Point de sauvegarde après la création du client
    SAVE TRANSACTION ApresCréationClient;
    PRINT 'Point de sauvegarde créé';

    -- Opération 2 : Ajouter une adresse
    INSERT INTO Adresses (ClientID, Rue, Ville)
    VALUES (1001, '15 Rue de la Paix', 'Paris');
    PRINT 'Adresse ajoutée';

    -- Simuler une erreur
    DECLARE @ErreurSimulee BIT = 1;

    IF @ErreurSimulee = 1
    BEGIN
        -- Annuler seulement l'ajout de l'adresse
        ROLLBACK TRANSACTION ApresCréationClient;
        PRINT 'Adresse annulée, client conservé';

        -- Ajouter une adresse différente
        INSERT INTO Adresses (ClientID, Rue, Ville)
        VALUES (1001, '8 Avenue Victor Hugo', 'Lyon');
        PRINT 'Nouvelle adresse ajoutée';
    END

-- Valider la transaction complète
COMMIT;
PRINT 'Transaction validée : Client avec adresse de Lyon';

-- Résultat :
-- ✓ Client 1001 existe
-- ✓ Adresse à Lyon existe
-- ✗ Adresse à Paris n'existe pas (annulée)
```

**Ce qui s'est passé :**
1. Le client a été créé
2. Un point de sauvegarde a été créé
3. Une première adresse a été ajoutée
4. On est revenu au point de sauvegarde (adresse annulée)
5. Une nouvelle adresse a été ajoutée
6. Le COMMIT a validé : le client + la nouvelle adresse

### Exemple 2 : Plusieurs Points de Sauvegarde

Vous pouvez créer plusieurs points de sauvegarde dans une même transaction :

```sql
BEGIN TRANSACTION;

    -- Étape 1 : Créer une catégorie
    INSERT INTO Categories (CategorieID, Nom)
    VALUES (100, 'Électronique');
    PRINT 'Catégorie créée';

    SAVE TRANSACTION ApresCatégorie;

    -- Étape 2 : Ajouter le produit 1
    INSERT INTO Produits (ProduitID, Nom, CategorieID, Prix)
    VALUES (1001, 'Smartphone', 100, 599.99);
    PRINT 'Produit 1 ajouté';

    SAVE TRANSACTION ApresProduit1;

    -- Étape 3 : Ajouter le produit 2
    INSERT INTO Produits (ProduitID, Nom, CategorieID, Prix)
    VALUES (1002, 'Tablette', 100, 399.99);
    PRINT 'Produit 2 ajouté';

    SAVE TRANSACTION ApresProduit2;

    -- Étape 4 : Ajouter le produit 3 (avec erreur)
    BEGIN TRY
        INSERT INTO Produits (ProduitID, Nom, CategorieID, Prix)
        VALUES (1003, NULL, 100, 299.99); -- NULL sur colonne NOT NULL → ERREUR
    END TRY
    BEGIN CATCH
        PRINT 'Erreur sur produit 3';
        -- Revenir au point après le produit 2
        ROLLBACK TRANSACTION ApresProduit2;
        PRINT 'Retour au point après produit 2';
    END CATCH

    -- Ajouter un produit 3 valide
    INSERT INTO Produits (ProduitID, Nom, CategorieID, Prix)
    VALUES (1003, 'Casque Audio', 100, 149.99);
    PRINT 'Produit 3 valide ajouté';

COMMIT;

-- Résultat final :
-- ✓ Catégorie Électronique
-- ✓ Smartphone
-- ✓ Tablette
-- ✓ Casque Audio
```

### Exemple 3 : Traitement de Commande avec Points de Sauvegarde

Exemple plus réaliste d'une commande e-commerce avec plusieurs étapes :

```sql
BEGIN TRANSACTION;

BEGIN TRY
    DECLARE @CommandeID INT;
    DECLARE @ClientID INT = 123;

    -- Étape 1 : Créer la commande
    INSERT INTO Commandes (ClientID, DateCommande, Statut)
    VALUES (@ClientID, GETDATE(), 'En cours');

    SET @CommandeID = SCOPE_IDENTITY();
    PRINT 'Commande ' + CAST(@CommandeID AS VARCHAR) + ' créée';

    SAVE TRANSACTION ApresCommande;

    -- Étape 2 : Ajouter les produits
    DECLARE @ProduitsCurseur CURSOR;
    DECLARE @ProduitID INT, @Quantite INT, @Stock INT;

    -- Simuler une liste de produits à commander
    DECLARE @ProduitsCommande TABLE (ProduitID INT, Quantite INT);
    INSERT INTO @ProduitsCommande VALUES (101, 2), (102, 5), (103, 1);

    SET @ProduitsCurseur = CURSOR FOR
    SELECT ProduitID, Quantite FROM @ProduitsCommande;

    OPEN @ProduitsCurseur;
    FETCH NEXT FROM @ProduitsCurseur INTO @ProduitID, @Quantite;

    WHILE @@FETCH_STATUS = 0
    BEGIN
        -- Créer un point de sauvegarde pour chaque produit
        DECLARE @NomSavepoint VARCHAR(50) = 'Produit_' + CAST(@ProduitID AS VARCHAR);
        SAVE TRANSACTION @NomSavepoint;

        -- Vérifier le stock
        SELECT @Stock = StockDisponible
        FROM Produits
        WHERE ProduitID = @ProduitID;

        IF @Stock < @Quantite
        BEGIN
            PRINT 'Stock insuffisant pour produit ' + CAST(@ProduitID AS VARCHAR);
            -- Annuler ce produit uniquement
            ROLLBACK TRANSACTION @NomSavepoint;
            PRINT 'Produit ' + CAST(@ProduitID AS VARCHAR) + ' ignoré';
        END
        ELSE
        BEGIN
            -- Ajouter à la commande
            INSERT INTO LignesCommande (CommandeID, ProduitID, Quantite, PrixUnitaire)
            SELECT @CommandeID, @ProduitID, @Quantite, Prix
            FROM Produits
            WHERE ProduitID = @ProduitID;

            -- Mettre à jour le stock
            UPDATE Produits
            SET StockDisponible = StockDisponible - @Quantite
            WHERE ProduitID = @ProduitID;

            PRINT 'Produit ' + CAST(@ProduitID AS VARCHAR) + ' ajouté à la commande';
        END

        FETCH NEXT FROM @ProduitsCurseur INTO @ProduitID, @Quantite;
    END

    CLOSE @ProduitsCurseur;
    DEALLOCATE @ProduitsCurseur;

    -- Vérifier qu'au moins un produit a été ajouté
    IF NOT EXISTS (SELECT 1 FROM LignesCommande WHERE CommandeID = @CommandeID)
    BEGIN
        -- Aucun produit n'a pu être ajouté, annuler toute la commande
        ROLLBACK TRANSACTION ApresCommande;
        RAISERROR('Aucun produit disponible, commande annulée', 16, 1);
    END

    -- Calculer et mettre à jour le total
    UPDATE Commandes
    SET Total = (SELECT SUM(Quantite * PrixUnitaire)
                 FROM LignesCommande
                 WHERE CommandeID = @CommandeID)
    WHERE CommandeID = @CommandeID;

    -- Tout s'est bien passé
    COMMIT;
    PRINT '✓ Commande validée avec succès';

END TRY
BEGIN CATCH
    -- En cas d'erreur, annuler toute la transaction
    ROLLBACK;
    PRINT '✗ Erreur : ' + ERROR_MESSAGE();
END CATCH;
```

**Points clés :**
- Chaque produit a son propre point de sauvegarde
- Si un produit n'est pas disponible, on annule juste ce produit
- Les autres produits disponibles restent dans la commande
- Si aucun produit n'est disponible, on annule toute la commande

### Exemple 4 : Points de Sauvegarde Imbriqués

Les points de sauvegarde peuvent être créés à différents niveaux :

```sql
BEGIN TRANSACTION;

    -- Niveau 1
    INSERT INTO Logs (Message) VALUES ('Début traitement');
    SAVE TRANSACTION Niveau1;

    -- Niveau 2
    INSERT INTO Logs (Message) VALUES ('Étape A');
    SAVE TRANSACTION Niveau2;

    -- Niveau 3
    INSERT INTO Logs (Message) VALUES ('Étape B');
    SAVE TRANSACTION Niveau3;

    -- Niveau 4
    INSERT INTO Logs (Message) VALUES ('Étape C - Erreur');

    -- Revenir au niveau 2
    ROLLBACK TRANSACTION Niveau2;
    -- Les niveaux 2, 3, 4 sont annulés
    -- Le niveau 1 est conservé

    -- Continuer après le niveau 1
    INSERT INTO Logs (Message) VALUES ('Reprise après Niveau1');

COMMIT;

-- Résultat dans la table Logs :
-- ✓ 'Début traitement'
-- ✓ 'Reprise après Niveau1'
-- ✗ 'Étape A' (annulée)
-- ✗ 'Étape B' (annulée)
-- ✗ 'Étape C - Erreur' (annulée)
```

## SAVE TRANSACTION vs ROLLBACK Complet

### Comparaison

| Aspect | ROLLBACK (sans nom) | ROLLBACK TO savepoint |
|--------|---------------------|----------------------|
| **Portée** | Annule TOUTE la transaction | Annule jusqu'au point de sauvegarde |
| **@@TRANCOUNT** | Remis à 0 | Reste inchangé |
| **État après** | Transaction terminée | Transaction toujours active |
| **Peut continuer** | Non | Oui, on peut ajouter des opérations |
| **Utilisation** | Erreur fatale | Erreur partielle récupérable |

### Visualisation de la Différence

```
ROLLBACK complet (sans nom) :

BEGIN TRANSACTION
    │
    ├─► Opération A ✓
    ├─► Opération B ✓
    ├─► SAVE TRANSACTION SP1
    ├─► Opération C ✓
    ├─► Opération D ✓
    │
    └─► ROLLBACK (sans nom)
        │
        └─► ❌ TOUT annulé (A, B, C, D)
            @@TRANCOUNT = 0
            Transaction TERMINÉE
            Impossible de continuer


ROLLBACK vers un savepoint :

BEGIN TRANSACTION
    │
    ├─► Opération A ✓
    ├─► Opération B ✓
    ├─► SAVE TRANSACTION SP1 💾
    ├─► Opération C ✓
    ├─► Opération D ✓
    │
    └─► ROLLBACK TRANSACTION SP1
        │
        ├─► ✓ A et B conservés
        ├─► ❌ C et D annulés
        ├─► @@TRANCOUNT = 1 (toujours en transaction)
        └─► ✓ Peut continuer avec nouvelles opérations
```

## Règles et Limitations des Points de Sauvegarde

### ✅ Ce que Vous POUVEZ Faire

#### 1. Créer Plusieurs Points de Sauvegarde

```sql
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    SAVE TRANSACTION SP2;
    SAVE TRANSACTION SP3;
    -- Tous coexistent
```

#### 2. Remplacer un Point de Sauvegarde

Si vous créez un point de sauvegarde avec un nom déjà existant, l'ancien est remplacé :

```sql
BEGIN TRANSACTION;
    INSERT INTO Table1 VALUES (1);
    SAVE TRANSACTION SP1; -- Premier SP1

    INSERT INTO Table2 VALUES (2);
    SAVE TRANSACTION SP1; -- Remplace le premier SP1

    ROLLBACK TRANSACTION SP1; -- Revient au second SP1
    -- INSERT Table2 annulé, INSERT Table1 conservé
```

#### 3. Utiliser des Points de Sauvegarde dans des Procédures

```sql
CREATE PROCEDURE AjouterProduit
    @ProduitID INT,
    @Nom VARCHAR(100)
AS
BEGIN
    SAVE TRANSACTION AvantAjoutProduit;

    BEGIN TRY
        INSERT INTO Produits VALUES (@ProduitID, @Nom);
    END TRY
    BEGIN CATCH
        ROLLBACK TRANSACTION AvantAjoutProduit;
        PRINT 'Produit non ajouté';
    END CATCH
END;
```

### ❌ Ce que Vous NE POUVEZ PAS Faire

#### 1. Compter sur un SAVE TRANSACTION hors d'une transaction

Hors d'une transaction active (`@@TRANCOUNT = 0`), un `SAVE TRANSACTION` ne **déclenche pas d'erreur** : SQL Server l'**ignore silencieusement** (il n'existe aucune transaction où poser le point de sauvegarde). Le piège est sournois — vous croyez disposer d'un point de restauration… qui n'existe pas.

```sql
-- ⚠️ Pas d'erreur, mais AUCUN effet utile : aucune transaction active
SAVE TRANSACTION SP1;
-- « Commands completed successfully » — pourtant aucun savepoint exploitable n'a été créé
```

#### 2. Faire un COMMIT « partiel » jusqu'à un point de sauvegarde

```sql
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    -- ❌ Il n'existe PAS de « COMMIT jusqu'à SP1 ».
    --    (Écrire COMMIT TRANSACTION SP1 ne plante pas, mais le nom est IGNORÉ
    --     et valide TOUTE la transaction — voir l'« Erreur 2 » plus bas.)
    -- On ne peut donc que : ROLLBACK TRANSACTION SP1 (annulation partielle)
    --                  ou : COMMIT (validation complète).
```

#### 3. Revenir à un Point de Sauvegarde Déjà Annulé

```sql
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    INSERT INTO Table1 VALUES (1);
    SAVE TRANSACTION SP2;

    ROLLBACK TRANSACTION SP1; -- SP2 est également détruit

    -- ❌ ERREUR : SP2 n'existe plus
    ROLLBACK TRANSACTION SP2;
    -- Msg 6401 : Cannot roll back SP2. No transaction or savepoint of that name was found.
```

**Important :** Quand vous faites ROLLBACK vers un savepoint, tous les savepoints créés **après** celui-ci sont détruits.

---

## Impact sur @@TRANCOUNT

Un point important : `SAVE TRANSACTION` et `ROLLBACK TO savepoint` n'affectent **pas** `@@TRANCOUNT`.

```sql
SELECT @@TRANCOUNT; -- 0

BEGIN TRANSACTION;
SELECT @@TRANCOUNT; -- 1

    SAVE TRANSACTION SP1;
    SELECT @@TRANCOUNT; -- 1 (inchangé)

    INSERT INTO Table1 VALUES (1);

    ROLLBACK TRANSACTION SP1;
    SELECT @@TRANCOUNT; -- 1 (toujours inchangé)

    -- La transaction est toujours active !

COMMIT; -- ou ROLLBACK (sans nom)
SELECT @@TRANCOUNT; -- 0
```

**Conclusion :** `@@TRANCOUNT` reste à 1 tant que vous n'avez pas fait un `COMMIT` ou un `ROLLBACK` complet (sans nom).

## Cas d'Usage Pratiques

### ✅ Cas 1 : Traitement par Lots avec Tolérance d'Erreur

```sql
BEGIN TRANSACTION;

    DECLARE @Compteur INT = 1;
    DECLARE @Succes INT = 0;
    DECLARE @Echecs INT = 0;

    WHILE @Compteur <= 100
    BEGIN
        SAVE TRANSACTION TraitementLigne;

        BEGIN TRY
            -- Traiter la ligne
            INSERT INTO ResultatsTraitement (LigneID, Resultat)
            SELECT @Compteur, TraitementComplexe(Donnee)
            FROM SourceDonnees
            WHERE ID = @Compteur;

            SET @Succes = @Succes + 1;

        END TRY
        BEGIN CATCH
            -- Annuler juste cette ligne, continuer avec les autres
            ROLLBACK TRANSACTION TraitementLigne;
            SET @Echecs = @Echecs + 1;
        END CATCH

        SET @Compteur = @Compteur + 1;
    END

COMMIT;

PRINT 'Traitement terminé :';
PRINT '  Succès : ' + CAST(@Succes AS VARCHAR);
PRINT '  Échecs : ' + CAST(@Echecs AS VARCHAR);
```

**Avantage :** Les lignes qui peuvent être traitées le sont, même si certaines échouent.

### ✅ Cas 2 : Validation Progressive

```sql
BEGIN TRANSACTION;

    -- Étape 1 : Opérations critiques
    INSERT INTO TransactionsBancaires (Montant, Type) VALUES (10000, 'Virement');
    UPDATE Comptes SET Solde = Solde - 10000 WHERE ID = 1;
    UPDATE Comptes SET Solde = Solde + 10000 WHERE ID = 2;

    -- Point de sauvegarde après les opérations critiques
    SAVE TRANSACTION ApresCritique;

    -- Étape 2 : Opérations optionnelles (notification, logs, etc.)
    BEGIN TRY
        -- Envoyer notification (peut échouer sans problème)
        INSERT INTO Notifications (Message) VALUES ('Virement effectué');

        -- Logger dans un système externe (peut échouer)
        EXEC sp_EnvoyerAuSystemeExterne @Montant = 10000;

    END TRY
    BEGIN CATCH
        -- Si les opérations optionnelles échouent, on les annule
        -- mais on garde les opérations critiques
        ROLLBACK TRANSACTION ApresCritique;
        PRINT 'Notifications échouées, mais virement effectué';
    END CATCH

COMMIT;
```

### ✅ Cas 3 : Tentative avec Fallback

```sql
BEGIN TRANSACTION;

    DECLARE @MethodeReussie VARCHAR(20);

    -- Essayer la méthode premium
    SAVE TRANSACTION MethodePremium;

    BEGIN TRY
        EXEC TraitementPremium @Param1, @Param2;
        SET @MethodeReussie = 'Premium';
    END TRY
    BEGIN CATCH
        -- La méthode premium a échoué, essayer la méthode standard
        ROLLBACK TRANSACTION MethodePremium;

        SAVE TRANSACTION MethodeStandard;

        BEGIN TRY
            EXEC TraitementStandard @Param1, @Param2;
            SET @MethodeReussie = 'Standard';
        END TRY
        BEGIN CATCH
            -- La méthode standard a aussi échoué, essayer la méthode basique
            ROLLBACK TRANSACTION MethodeStandard;

            EXEC TraitementBasique @Param1, @Param2;
            SET @MethodeReussie = 'Basique';
        END CATCH
    END CATCH

COMMIT;

PRINT 'Traitement effectué avec méthode : ' + @MethodeReussie;
```

> ⚠️ **Limite importante : un savepoint ne « sauve » pas une transaction devenue non validable.** Les patterns ci-dessus (revenir à un savepoint dans un `CATCH` pour poursuivre la transaction) ne fonctionnent que si la transaction reste **validable**. Or certaines erreurs — et surtout `SET XACT_ABORT ON` — rendent la transaction **non validable** (« doomed ») : `XACT_STATE()` renvoie alors `-1`, et toute tentative de `ROLLBACK TRANSACTION nom_savepoint` échoue ; le seul recours possible est un `ROLLBACK` **complet**. Avant de revenir à un savepoint dans un `CATCH`, on peut donc tester l'état de la transaction :
>
> ```sql
> BEGIN CATCH
>     IF XACT_STATE() = 1            -- validable : un rollback partiel est possible
>         ROLLBACK TRANSACTION MonPoint;
>     ELSE IF XACT_STATE() = -1      -- « doomed » : seul un rollback complet est permis
>         ROLLBACK;
> END CATCH
> ```

## Bonnes Pratiques

### ✅ Nommez Vos Points de Sauvegarde de Façon Explicite

```sql
-- ✓ BON : Noms explicites
SAVE TRANSACTION ApresCreationClient;
SAVE TRANSACTION AvantMiseAJourStock;
SAVE TRANSACTION DebutTraitementProduit;

-- ✗ MOINS BON : Noms vagues
SAVE TRANSACTION SP1;
SAVE TRANSACTION Point;
SAVE TRANSACTION Temp;
```

### ✅ Documentez les Points de Sauvegarde

```sql
BEGIN TRANSACTION;

    -- Opérations critiques qui ne doivent jamais être annulées
    INSERT INTO AuditLog (Action) VALUES ('Début transaction');

    -- Point de sauvegarde avant opérations risquées
    -- Permet de revenir ici si les opérations suivantes échouent
    SAVE TRANSACTION AvantOperationsRisquees;

    -- Opérations qui peuvent échouer...
```

### ✅ Vérifiez Qu'une Transaction est Active

```sql
IF @@TRANCOUNT > 0
BEGIN
    SAVE TRANSACTION MonPoint;
    -- ...
END
ELSE
BEGIN
    PRINT 'Aucune transaction active, impossible de créer un point de sauvegarde';
END
```

### ✅ Utilisez TRY...CATCH avec les Points de Sauvegarde

```sql
BEGIN TRANSACTION;

    SAVE TRANSACTION MonPoint;

    BEGIN TRY
        -- Opérations risquées

    END TRY
    BEGIN CATCH
        ROLLBACK TRANSACTION MonPoint;
        -- Continuer ou logger l'erreur
    END CATCH

COMMIT;
```

### ✅ Gardez les Noms de Savepoints Uniques

Si vous réutilisez le même nom, l'ancien point est écrasé :

```sql
BEGIN TRANSACTION;
    INSERT INTO Table1 VALUES (1);
    SAVE TRANSACTION SP1; -- Premier SP1

    INSERT INTO Table2 VALUES (2);
    SAVE TRANSACTION SP1; -- ⚠️ Écrase le premier SP1

    ROLLBACK TRANSACTION SP1; -- Revient au SECOND SP1 uniquement
    -- INSERT Table1 est conservé
    -- INSERT Table2 est annulé
```

## Erreurs Courantes

### ❌ Erreur 1 : Oublier que ROLLBACK Détruit les Savepoints Suivants

```sql
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    -- Opérations...
    SAVE TRANSACTION SP2;
    -- Opérations...
    SAVE TRANSACTION SP3;

    ROLLBACK TRANSACTION SP1; -- ⚠️ Détruit aussi SP2 et SP3

    -- ❌ ERREUR : SP2 n'existe plus
    ROLLBACK TRANSACTION SP2;
```

### ❌ Erreur 2 : Penser que COMMIT Valide Jusqu'à un Savepoint

Il n'existe **pas** de « COMMIT vers un savepoint ». Écrire `COMMIT TRANSACTION SP1` ne déclenche **pas** d'erreur de syntaxe, mais ne fait pas non plus ce qu'on imagine : comme **tout nom passé à un `COMMIT` est ignoré** (voir [6.2.2](/06-gestion-des-transactions-et-concurrence/02.2-commit-transaction.md)), cette instruction valide en réalité **toute la transaction** — exactement comme un simple `COMMIT;`.

```sql
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    -- Opérations...

    -- ⚠️ TROMPEUR : le nom « SP1 » est ignoré → ceci valide TOUTE la transaction,
    --    et NON « jusqu'au savepoint SP1 ».
    COMMIT TRANSACTION SP1;

    -- ✓ Équivalent et plus clair : COMMIT valide TOUTE la transaction
    COMMIT;
```

Pour n'annuler qu'une *partie* de la transaction, utilisez `ROLLBACK TRANSACTION SP1` ; mais pour *valider*, c'est toujours tout ou rien.

### ❌ Erreur 3 : Croire qu'un savepoint existe hors d'une transaction

```sql
-- ⚠️ Pas d'erreur, mais SANS EFFET : aucune transaction active
SAVE TRANSACTION SP1;
-- SQL Server l'ignore silencieusement → aucun point de sauvegarde exploitable
```

Le danger n'est pas un plantage, mais l'**illusion** d'avoir un point de restauration. Posez toujours vos savepoints à l'intérieur d'un `BEGIN TRANSACTION`.

### ❌ Erreur 4 : Abus des Points de Sauvegarde

```sql
-- ❌ Trop de points de sauvegarde = code complexe
BEGIN TRANSACTION;
    SAVE TRANSACTION SP1;
    -- 1 opération
    SAVE TRANSACTION SP2;
    -- 1 opération
    SAVE TRANSACTION SP3;
    -- 1 opération
    SAVE TRANSACTION SP4;
    -- ... (50 savepoints plus tard)
COMMIT;
```

**Conseil :** Utilisez les savepoints avec parcimonie, uniquement quand c'est vraiment nécessaire.

## Performance et Considérations

### Impact Minimal sur les Performances

Les points de sauvegarde ont un impact **minimal** sur les performances :
- ✅ Très rapides à créer (simple marqueur dans le journal)
- ✅ ROLLBACK vers un savepoint plus rapide qu'un ROLLBACK complet
- ⚠️ Chaque savepoint consomme un peu de mémoire

### Verrous Toujours Actifs

**Important :** Les points de sauvegarde ne libèrent **pas** les verrous :

```sql
BEGIN TRANSACTION;
    UPDATE Table1 SET Col = 'A'; -- 🔒 Verrous posés

    SAVE TRANSACTION SP1;

    UPDATE Table2 SET Col = 'B'; -- 🔒 Plus de verrous

    ROLLBACK TRANSACTION SP1; -- ⏪ Annule UPDATE Table2
                              -- ⚠️ Mais verrous sur Table1 TOUJOURS actifs

COMMIT; -- ✅ Verrous finalement libérés
```

Les verrous restent actifs jusqu'au `COMMIT` ou `ROLLBACK` complet.

## Résumé des Commandes

```sql
-- Créer un point de sauvegarde
SAVE TRANSACTION nom_savepoint;

-- Revenir à un point de sauvegarde (annulation partielle)
ROLLBACK TRANSACTION nom_savepoint;

-- Annuler toute la transaction
ROLLBACK TRANSACTION; -- ou simplement ROLLBACK;

-- Valider toute la transaction
COMMIT TRANSACTION; -- ou simplement COMMIT;
```

## Points Clés à Retenir

### ✓ Les savepoints permettent un ROLLBACK partiel

Vous pouvez annuler une partie de la transaction sans tout perdre.

### ✓ SAVE TRANSACTION crée un marqueur dans le journal

Très léger en termes de performance.

### ✓ ROLLBACK TO savepoint ne change pas @@TRANCOUNT

La transaction reste active, vous pouvez continuer à ajouter des opérations.

### ✓ ROLLBACK TO détruit les savepoints créés après

Si vous revenez à SP1, tous les savepoints créés après SP1 sont détruits.

### ✓ Les savepoints ne libèrent pas les verrous

Les verrous restent actifs jusqu'au COMMIT ou ROLLBACK complet.

### ✓ Pas de COMMIT partiel

Il n'existe pas de "COMMIT TO savepoint". COMMIT valide toujours toute la transaction.

### ✓ Nécessite une transaction active

Vous ne pouvez pas créer de savepoint en dehors d'une transaction.

### ✓ Utilisez avec parcimonie

Les savepoints sont utiles mais peuvent rendre le code complexe si abusés.

---

## Conclusion

Les points de sauvegarde (`SAVE TRANSACTION`) sont un outil puissant pour un contrôle fin de vos transactions. Ils vous permettent de créer des "checkpoints" à l'intérieur d'une transaction, vers lesquels vous pouvez revenir en cas de besoin, sans perdre tout le travail accompli.

**Cas d'usage principaux :**
- Traitement par lots avec tolérance aux erreurs
- Opérations critiques suivies d'opérations optionnelles
- Mécanismes de fallback (essayer méthode A, sinon méthode B, sinon méthode C)

**Règle d'or :** Utilisez les savepoints quand vous avez besoin d'annuler **une partie** d'une transaction, mais documentez bien leur utilisation pour garder votre code lisible.
