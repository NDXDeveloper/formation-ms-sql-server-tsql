# 2.3.1 PRIMARY KEY (Clé primaire)

## Introduction

Imaginez une bibliothèque avec des milliers de livres. Comment faire pour identifier **un livre spécifique** parmi tous les autres ? Vous pourriez utiliser un **numéro unique** attribué à chaque livre. C'est exactement le rôle d'une **clé primaire** dans une base de données.

Une **PRIMARY KEY** (clé primaire) est une colonne (ou un ensemble de colonnes) qui identifie de manière **unique** chaque ligne d'une table. C'est l'un des concepts les plus fondamentaux et importants des bases de données relationnelles.

## Qu'est-ce qu'une Clé Primaire ?

### Définition Simple

Une clé primaire est un **identifiant unique** pour chaque enregistrement d'une table.

**Analogie :**
- Dans une table `Clients`, chaque client a un `IdClient` unique
- Dans une table `Étudiants`, chaque étudiant a un `NumeroEtudiant` unique
- Dans une table `Pays`, chaque pays pourrait avoir un `CodeISO` unique (FR, US, JP...)

### Exemple Concret

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100),
    Prenom VARCHAR(50),
    Email VARCHAR(100)
);
```

Dans cet exemple :
- `IdClient` est la clé primaire
- Chaque client a un `IdClient` différent
- On peut identifier précisément un client avec son `IdClient`

**Exemple de données :**

| IdClient | Nom | Prenom | Email |
|----------|-----|--------|-------|
| 1 | Dupont | Marie | marie.dupont@email.com |
| 2 | Martin | Paul | paul.martin@email.com |
| 3 | Bernard | Sophie | sophie.bernard@email.com |

Grâce à `IdClient`, vous pouvez dire précisément : "Je veux les informations du client numéro 2" et obtenir Paul Martin.

## Pourquoi les Clés Primaires sont-elles Essentielles ?

### 1. Identification Unique

Sans clé primaire, vous ne pouvez pas garantir l'unicité des lignes :

```sql
-- ❌ SANS clé primaire : Problème !
CREATE TABLE Clients
(
    Nom VARCHAR(100),
    Prenom VARCHAR(50)
);

-- Que se passe-t-il si deux personnes s'appellent "Marie Dupont" ?
-- Comment les distinguer ?
INSERT INTO Clients VALUES ('Dupont', 'Marie');
INSERT INTO Clients VALUES ('Dupont', 'Marie');  -- Doublon !
```

```sql
-- ✅ AVEC clé primaire : Solution !
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100),
    Prenom VARCHAR(50)
);

-- Même avec des noms identiques, l'ID est différent
INSERT INTO Clients VALUES (1, 'Dupont', 'Marie');
INSERT INTO Clients VALUES (2, 'Dupont', 'Marie');  -- OK, IDs différents
```

### 2. Relations entre Tables

Les clés primaires permettent de **relier les tables** entre elles (nous verrons cela avec les clés étrangères) :

```sql
-- Table Clients avec clé primaire
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100)
);

-- Table Commandes qui référence les clients
CREATE TABLE Commandes
(
    IdCommande INT PRIMARY KEY,
    IdClient INT,  -- Référence vers Clients
    DateCommande DATE
);
```

### 3. Performance

Les clés primaires créent automatiquement un **index** qui accélère les recherches :

```sql
-- Recherche rapide grâce à la clé primaire
SELECT * FROM Clients WHERE IdClient = 1234;
```

### 4. Intégrité des Données

Une clé primaire garantit qu'il n'y aura jamais :
- ❌ De doublons (deux lignes avec le même ID)
- ❌ De valeurs NULL (un ID manquant)

## Caractéristiques d'une Clé Primaire

Une colonne définie comme PRIMARY KEY doit respecter **deux règles strictes** :

### 1. UNIQUE (Unicité)

Chaque valeur de la clé primaire doit être **unique** dans la table. Aucun doublon n'est autorisé.

```sql
CREATE TABLE Produits
(
    CodeProduit VARCHAR(10) PRIMARY KEY,
    Nom VARCHAR(100)
);

-- ✅ OK
INSERT INTO Produits VALUES ('P001', 'Ordinateur');
INSERT INTO Produits VALUES ('P002', 'Souris');

-- ❌ ERREUR : P001 existe déjà
INSERT INTO Produits VALUES ('P001', 'Clavier');
-- Erreur : Violation of PRIMARY KEY constraint
```

### 2. NOT NULL (Non Null)

Une clé primaire ne peut **jamais** être NULL (vide).

```sql
-- ❌ ERREUR : La clé primaire ne peut pas être NULL
INSERT INTO Produits VALUES (NULL, 'Clavier');
-- Erreur : Cannot insert the value NULL into column 'CodeProduit'
```

### 3. Une Seule par Table

Une table ne peut avoir qu'**une seule** clé primaire (mais elle peut avoir plusieurs colonnes uniques).

```sql
-- ❌ ERREUR : Impossible d'avoir deux PRIMARY KEY
CREATE TABLE Exemple
(
    Id1 INT PRIMARY KEY,
    Id2 INT PRIMARY KEY  -- ERREUR !
);
```

**Note :** Cependant, une clé primaire peut être **composite** (composée de plusieurs colonnes), nous verrons cela plus loin.

### 4. Immuable (Idéalement)

Une clé primaire devrait **rarement changer**. Choisissez des valeurs stables.

```sql
-- ❌ MAUVAIS : Email comme clé primaire (peut changer)
CREATE TABLE Clients
(
    Email VARCHAR(100) PRIMARY KEY,
    Nom VARCHAR(100)
);

-- ✅ BON : ID numérique comme clé primaire (stable)
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Email VARCHAR(100),
    Nom VARCHAR(100)
);
```

## Comment Créer une Clé Primaire ?

Il existe plusieurs méthodes pour définir une clé primaire.

### Méthode 1 : Lors de la Création de la Table (Inline)

La méthode la plus simple et la plus courante :

```sql
CREATE TABLE Clients
(
    IdClient INT PRIMARY KEY,
    Nom VARCHAR(100),
    Email VARCHAR(100)
);
```

### Méthode 2 : Avec Contrainte Nommée (Recommandé)

Il est recommandé de **nommer** vos contraintes pour faciliter la gestion :

```sql
CREATE TABLE Clients
(
    IdClient INT,
    Nom VARCHAR(100),
    Email VARCHAR(100),
    CONSTRAINT PK_Clients PRIMARY KEY (IdClient)
);
```

**Avantage :** Vous pouvez facilement identifier et supprimer la contrainte par son nom (`PK_Clients`).

**Convention de nommage :** `PK_NomTable` ou `PK_NomTable_NomColonne`

### Méthode 3 : Après la Création de la Table

Vous pouvez ajouter une clé primaire à une table existante :

```sql
-- D'abord créer la table
CREATE TABLE Clients
(
    IdClient INT NOT NULL,
    Nom VARCHAR(100),
    Email VARCHAR(100)
);

-- Ensuite ajouter la clé primaire
ALTER TABLE Clients
ADD CONSTRAINT PK_Clients PRIMARY KEY (IdClient);
```

**Important :** La colonne doit déjà être `NOT NULL` et ne doit pas contenir de doublons.

### Méthode 4 : À la Fin de CREATE TABLE

```sql
CREATE TABLE Clients
(
    IdClient INT NOT NULL,
    Nom VARCHAR(100),
    Email VARCHAR(100),
    PRIMARY KEY (IdClient)
);
```

## Types de Clés Primaires

### 1. Clé Primaire Simple (Une Colonne)

La plupart du temps, une clé primaire est composée d'**une seule colonne** :

```sql
CREATE TABLE Employes
(
    IdEmploye INT PRIMARY KEY,
    Nom VARCHAR(100),
    Prenom VARCHAR(50),
    Poste VARCHAR(50)
);
```

### 2. Clé Primaire Composite (Plusieurs Colonnes)

Parfois, il faut **plusieurs colonnes combinées** pour identifier uniquement une ligne :

```sql
CREATE TABLE Inscriptions
(
    IdEtudiant INT,
    IdCours INT,
    DateInscription DATE,
    CONSTRAINT PK_Inscriptions PRIMARY KEY (IdEtudiant, IdCours)
);
```

**Explication :**
- Un étudiant peut s'inscrire à plusieurs cours
- Un cours peut avoir plusieurs étudiants
- La combinaison `(IdEtudiant, IdCours)` est unique

**Exemple de données valides :**

| IdEtudiant | IdCours | DateInscription |
|------------|---------|-----------------|
| 1 | 101 | 2025-01-15 |
| 1 | 102 | 2025-01-16 |
| 2 | 101 | 2025-01-15 |

**Ce qui serait refusé :**

| IdEtudiant | IdCours | DateInscription |
|------------|---------|-----------------|
| 1 | 101 | 2025-01-15 |
| 1 | 101 | 2025-01-20 | ❌ Doublon !

### Quand Utiliser une Clé Composite ?

Utilisez une clé primaire composite quand :
- Vous avez une **table de liaison** (relation plusieurs-à-plusieurs)
- **Aucune colonne seule** ne peut garantir l'unicité
- La **combinaison** de colonnes a un sens métier

**Exemple : Table de Lignes de Commande**

```sql
CREATE TABLE LignesCommande
(
    IdCommande INT,
    NumeroDeLigne INT,
    IdProduit INT,
    Quantite INT,
    CONSTRAINT PK_LignesCommande PRIMARY KEY (IdCommande, NumeroDeLigne)
);
```

Chaque ligne d'une commande a un numéro unique **dans le contexte de cette commande**.

## IDENTITY : Auto-Incrémentation

Dans la plupart des cas, vous voudrez que votre clé primaire soit **générée automatiquement**. C'est le rôle de `IDENTITY`.

### Syntaxe de Base

```sql
CREATE TABLE Clients
(
    IdClient INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(100),
    Email VARCHAR(100)
);
```

**Explication de `IDENTITY(1,1)` :**
- Premier `1` : valeur de départ (commence à 1)
- Deuxième `1` : incrément (augmente de 1 à chaque insertion)

### Comment ça Fonctionne ?

```sql
-- Vous n'insérez PAS la valeur de IdClient
INSERT INTO Clients (Nom, Email)
VALUES ('Dupont', 'dupont@email.com');

INSERT INTO Clients (Nom, Email)
VALUES ('Martin', 'martin@email.com');

-- SQL Server génère automatiquement les IDs : 1, 2, 3...
SELECT * FROM Clients;
```

**Résultat :**

| IdClient | Nom | Email |
|----------|-----|-------|
| 1 | Dupont | dupont@email.com |
| 2 | Martin | martin@email.com |

### Personnaliser IDENTITY

Vous pouvez choisir d'autres valeurs de départ et d'incrément :

```sql
-- Commencer à 1000, incrémenter de 1
IdEmploye INT IDENTITY(1000,1)
-- Résultat : 1000, 1001, 1002...

-- Commencer à 10, incrémenter de 10
NumeroCommande INT IDENTITY(10,10)
-- Résultat : 10, 20, 30...

-- Commencer à 1, incrémenter de 5
IdTicket INT IDENTITY(1,5)
-- Résultat : 1, 6, 11, 16...
```

### Récupérer la Dernière Valeur Générée

Après une insertion, vous pouvez récupérer l'ID généré :

```sql
-- Insérer un client
INSERT INTO Clients (Nom, Email)
VALUES ('Bernard', 'bernard@email.com');

-- Récupérer l'ID qui vient d'être généré
SELECT SCOPE_IDENTITY() AS DernierID;
-- Retourne par exemple : 3
```

**Fonctions disponibles :**
- `SCOPE_IDENTITY()` : dernier ID dans le scope actuel (recommandé)
- `@@IDENTITY` : dernier ID global (peut inclure d'autres tables)
- `IDENT_CURRENT('NomTable')` : dernier ID d'une table spécifique

### Réinitialiser IDENTITY

Si vous videz une table avec `DELETE`, l'IDENTITY continue. Pour le réinitialiser :

```sql
-- Vider la table ET réinitialiser IDENTITY
TRUNCATE TABLE Clients;

-- OU réinitialiser manuellement
DBCC CHECKIDENT ('Clients', RESEED, 0);
```

## Choix d'une Bonne Clé Primaire

### Types de Valeurs Possibles

#### 1. Entier Auto-Incrémenté (Recommandé)

**✅ Avantages :**
- Simple et efficace
- Performant (petite taille, index compact)
- Garanti unique
- Aucune information métier (stable)

```sql
CREATE TABLE Clients
(
    IdClient INT IDENTITY(1,1) PRIMARY KEY,
    Nom VARCHAR(100)
);
```

**Quand l'utiliser :** Dans la majorité des cas. C'est le choix par défaut recommandé.

#### 2. GUID / UNIQUEIDENTIFIER

**Avantages :**
- Unique globalement (même entre serveurs)
- Utile pour la réplication
- Pas de collision

**⚠️ Inconvénients :**
- Taille importante (16 octets vs 4 pour INT)
- Moins performant
- Difficile à lire/déboguer

```sql
CREATE TABLE Documents
(
    IdDocument UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    Titre VARCHAR(200)
);

-- Insertion
INSERT INTO Documents (Titre) VALUES ('Rapport 2025');
-- Génère automatiquement un GUID : 6F9619FF-8B86-D011-B42D-00C04FC964FF
```

**Quand l'utiliser :** Systèmes distribués, synchronisation entre bases, besoin d'unicité absolue.

#### 3. Code Métier (VARCHAR)

**Exemple :** Code produit, numéro de série, code pays...

```sql
CREATE TABLE Pays
(
    CodeISO CHAR(2) PRIMARY KEY,
    NomPays VARCHAR(100)
);

INSERT INTO Pays VALUES ('FR', 'France');
INSERT INTO Pays VALUES ('US', 'États-Unis');
```

**⚠️ Attention :**
- Doit être **vraiment unique** et **stable**
- Moins performant qu'un INT
- Peut causer des problèmes si le format change

**Quand l'utiliser :** Quand un code métier naturel existe et est garanti stable (codes ISO, numéros d'immatriculation standardisés, etc.)

#### 4. Valeurs Métier Composées

**❌ Généralement déconseillé** comme clé primaire :

```sql
-- ❌ À ÉVITER : Nom comme clé primaire
CREATE TABLE Employes
(
    Nom VARCHAR(100) PRIMARY KEY,  -- Mauvaise idée !
    Prenom VARCHAR(50)
);
```

**Problèmes :**
- Les noms peuvent changer (mariage, correction)
- Doublons possibles (homonymes)
- Moins performant

### Recommandations Générales

**Pour la plupart des tables :**
```sql
-- ✅ RECOMMANDÉ
CREATE TABLE MaTable
(
    IdMaTable INT IDENTITY(1,1) PRIMARY KEY,
    -- Autres colonnes...
);
```

**Pour les tables de référence avec codes naturels :**
```sql
-- ✅ ACCEPTABLE
CREATE TABLE Devises
(
    CodeDevise CHAR(3) PRIMARY KEY,  -- USD, EUR, JPY
    NomDevise VARCHAR(50)
);
```

**Pour les systèmes distribués :**
```sql
-- ✅ SI NÉCESSAIRE
CREATE TABLE Transactions
(
    IdTransaction UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    Montant DECIMAL(10,2)
);
```

## Exemples Pratiques Complets

### Exemple 1 : Table Simple avec IDENTITY

```sql
CREATE TABLE Produits
(
    IdProduit INT IDENTITY(1,1) PRIMARY KEY,
    CodeProduit VARCHAR(20) NOT NULL UNIQUE,
    Nom VARCHAR(150) NOT NULL,
    Description VARCHAR(500),
    Prix DECIMAL(10,2) NOT NULL,
    DateAjout DATE DEFAULT GETDATE()
);

-- Insertions
INSERT INTO Produits (CodeProduit, Nom, Prix)
VALUES
    ('PROD001', 'Ordinateur Portable', 899.99),
    ('PROD002', 'Souris Sans Fil', 29.99),
    ('PROD003', 'Clavier Mécanique', 149.99);

-- Vérification
SELECT IdProduit, CodeProduit, Nom, Prix
FROM Produits;
```

### Exemple 2 : Table avec Clé Primaire Composite

```sql
CREATE TABLE Horaires
(
    IdEmploye INT,
    Jour DATE,
    HeureDebut TIME,
    HeureFin TIME,
    CONSTRAINT PK_Horaires PRIMARY KEY (IdEmploye, Jour)
);

-- Un employé ne peut avoir qu'un seul horaire par jour
INSERT INTO Horaires VALUES (1, '2025-01-15', '09:00', '17:00');
INSERT INTO Horaires VALUES (1, '2025-01-16', '09:00', '17:00');  -- OK, jour différent
INSERT INTO Horaires VALUES (2, '2025-01-15', '10:00', '18:00');  -- OK, employé différent

-- ❌ Ceci échouerait (doublon)
-- INSERT INTO Horaires VALUES (1, '2025-01-15', '13:00', '21:00');
```

### Exemple 3 : Ajout de Clé Primaire à une Table Existante

```sql
-- Table créée sans clé primaire (erreur de débutant)
CREATE TABLE Articles
(
    IdArticle INT NOT NULL,
    Titre VARCHAR(200),
    Contenu VARCHAR(MAX)   -- VARCHAR(MAX), et non TEXT (type déprécié)
);

-- Insertion de données
INSERT INTO Articles VALUES (1, 'Premier article', 'Contenu...');
INSERT INTO Articles VALUES (2, 'Deuxième article', 'Contenu...');

-- Vérifier qu'il n'y a pas de doublons
SELECT IdArticle, COUNT(*)
FROM Articles
GROUP BY IdArticle
HAVING COUNT(*) > 1;

-- Ajouter la clé primaire
ALTER TABLE Articles
ADD CONSTRAINT PK_Articles PRIMARY KEY (IdArticle);

-- Maintenant la table est correctement structurée
```

### Exemple 4 : Table avec GUID

```sql
CREATE TABLE Fichiers
(
    IdFichier UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    NomFichier VARCHAR(255) NOT NULL,
    Taille BIGINT,
    DateUpload DATETIME2 DEFAULT GETDATE()
);

-- Insertion (le GUID est généré automatiquement)
INSERT INTO Fichiers (NomFichier, Taille)
VALUES ('document.pdf', 2048576);

-- Résultat avec GUID
SELECT * FROM Fichiers;
-- IdFichier: A7B8C9D0-1234-5678-90AB-CDEF12345678
-- NomFichier: document.pdf
-- ...
```

## Supprimer une Clé Primaire

Si vous devez supprimer une clé primaire (rare, mais possible) :

```sql
-- Supprimer une clé primaire nommée
ALTER TABLE Clients
DROP CONSTRAINT PK_Clients;

-- Si vous ne connaissez pas le nom de la contrainte
-- Trouver le nom
SELECT name
FROM sys.key_constraints
WHERE type = 'PK' AND parent_object_id = OBJECT_ID('Clients');

-- Puis supprimer avec le nom trouvé
ALTER TABLE Clients
DROP CONSTRAINT [nom_trouvé];
```

**⚠️ Attention :** Supprimer une clé primaire peut casser des relations (clés étrangères) avec d'autres tables.

## Erreurs Courantes et Solutions

### Erreur 1 : Tentative d'Insertion d'un Doublon

```sql
INSERT INTO Clients (IdClient, Nom) VALUES (1, 'Dupont');
INSERT INTO Clients (IdClient, Nom) VALUES (1, 'Martin');
-- Erreur : Violation of PRIMARY KEY constraint 'PK_Clients'
```

**Solution :** Utilisez IDENTITY pour la génération automatique, ou vérifiez l'unicité avant insertion.

### Erreur 2 : Tentative d'Insertion de NULL

```sql
INSERT INTO Clients (IdClient, Nom) VALUES (NULL, 'Dupont');
-- Erreur : Cannot insert NULL into column 'IdClient'
```

**Solution :** Assurez-vous de fournir une valeur ou utilisez IDENTITY.

### Erreur 3 : Tentative d'Ajouter une Clé Primaire sur des Données avec Doublons

```sql
-- Table avec doublons
CREATE TABLE Test (Id INT, Nom VARCHAR(50));
INSERT INTO Test VALUES (1, 'A'), (1, 'B');  -- Doublon sur Id

-- Tentative d'ajouter une clé primaire
ALTER TABLE Test ADD PRIMARY KEY (Id);
-- Erreur : Duplicate key value
```

**Solution :** Nettoyez les doublons d'abord :

```sql
-- Identifier les doublons
SELECT Id, COUNT(*)
FROM Test
GROUP BY Id
HAVING COUNT(*) > 1;

-- Supprimer les doublons (conserver un seul)
DELETE FROM Test WHERE Id IN (
    SELECT Id FROM (
        SELECT Id, ROW_NUMBER() OVER (PARTITION BY Id ORDER BY Id) AS rn
        FROM Test
    ) t WHERE rn > 1
);

-- Maintenant ajouter la clé primaire
ALTER TABLE Test ADD PRIMARY KEY (Id);
```

## Bonnes Pratiques

### 1. Toujours Définir une Clé Primaire

**Chaque table devrait avoir une clé primaire.** Sans exception.

```sql
-- ❌ MAUVAIS : Table sans clé primaire
CREATE TABLE Commandes
(
    DateCommande DATE,
    MontantTotal DECIMAL(10,2)
);

-- ✅ BON : Table avec clé primaire
CREATE TABLE Commandes
(
    IdCommande INT IDENTITY(1,1) PRIMARY KEY,
    DateCommande DATE,
    MontantTotal DECIMAL(10,2)
);
```

### 2. Nommez Vos Contraintes

```sql
-- ✅ BON : Contrainte nommée
CONSTRAINT PK_Clients PRIMARY KEY (IdClient)

-- ❌ Acceptable mais moins maintenable : Contrainte anonyme
PRIMARY KEY (IdClient)
```

### 3. Utilisez INT IDENTITY dans le Doute

Pour 99% des tables, `INT IDENTITY(1,1)` est le meilleur choix :

```sql
CREATE TABLE MaTable
(
    IdMaTable INT IDENTITY(1,1) PRIMARY KEY,
    -- ...
);
```

### 4. Convention de Nommage Cohérente

Choisissez une convention et respectez-la :

```sql
-- Option 1 : Id + NomTable
IdClient, IdCommande, IdProduit

-- Option 2 : NomTable + Id
ClientId, CommandeId, ProduitId

-- Option 3 : Simplement "Id" (si pas d'ambiguïté)
Id

-- L'important : ÊTRE COHÉRENT dans tout le projet
```

### 5. Documenter les Clés Composites

Si vous utilisez une clé composite, documentez pourquoi :

```sql
-- Table de liaison : Un étudiant peut suivre plusieurs cours
-- et un cours peut avoir plusieurs étudiants
-- La combinaison (IdEtudiant, IdCours) est unique
CREATE TABLE Inscriptions
(
    IdEtudiant INT,
    IdCours INT,
    DateInscription DATE,
    CONSTRAINT PK_Inscriptions PRIMARY KEY (IdEtudiant, IdCours)
);
```

## Résumé

| Aspect | Description |
|--------|-------------|
| **Définition** | Identifiant unique pour chaque ligne d'une table |
| **Caractéristiques** | UNIQUE + NOT NULL + Une seule par table |
| **Syntaxe simple** | `IdClient INT PRIMARY KEY` |
| **Syntaxe nommée** | `CONSTRAINT PK_Clients PRIMARY KEY (IdClient)` |
| **Auto-incrémentation** | `INT IDENTITY(1,1)` |
| **Types** | Simple (1 colonne) ou Composite (plusieurs colonnes) |
| **Choix recommandé** | `INT IDENTITY(1,1)` dans la majorité des cas |
| **Importance** | Essentielle pour l'intégrité, les relations et la performance |

## Points Clés à Retenir

1. ✅ **Toujours** définir une clé primaire sur chaque table
2. 🔑 Une clé primaire garantit **l'unicité** et interdit les valeurs **NULL**
3. 🎯 Utilisez `INT IDENTITY(1,1)` dans la plupart des cas
4. 📝 Nommez vos contraintes : `CONSTRAINT PK_NomTable PRIMARY KEY (...)`
5. 🔗 Les clés primaires sont essentielles pour créer des **relations** entre tables
6. ⚡ Elles améliorent automatiquement les **performances** via un index
7. 📊 Une table ne peut avoir qu'**une seule** clé primaire (simple ou composite)
