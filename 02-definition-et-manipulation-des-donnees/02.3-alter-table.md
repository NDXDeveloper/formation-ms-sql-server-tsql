# 2.2.3 ALTER TABLE (Ajouter, Modifier, Supprimer des colonnes)

## Introduction

Après avoir créé une table, vous découvrirez souvent qu'elle n'est pas parfaite : vous avez oublié une colonne, vous devez changer un type de données, ou une colonne n'est plus nécessaire.

Heureusement, SQL Server permet de **modifier** la structure d'une table existante sans avoir à la recréer depuis zéro. C'est le rôle de la commande `ALTER TABLE`.

**Important :** `ALTER TABLE` modifie la **structure** de la table (ses colonnes), pas les **données** qu'elle contient.

## Les Trois Opérations Principales

Avec `ALTER TABLE`, vous pouvez effectuer trois opérations principales sur les colonnes :

1. **Ajouter** une nouvelle colonne (`ADD`)
2. **Modifier** une colonne existante (`ALTER COLUMN`)
3. **Supprimer** une colonne (`DROP COLUMN`)

## 1. Ajouter une Colonne (ADD)

### Syntaxe de Base

```sql
ALTER TABLE NomTable
ADD NomColonne TypeDonnées;
```

### Exemple Simple

Imaginons que nous avons créé cette table :

```sql
CREATE TABLE Clients
(
    IdClient INT,
    Nom VARCHAR(50),
    Prenom VARCHAR(50)
);
```

Maintenant, nous réalisons qu'il nous faut également stocker l'email des clients :

```sql
ALTER TABLE Clients
ADD Email VARCHAR(100);
```

**Résultat :** La table `Clients` possède maintenant une quatrième colonne nommée `Email`.

### Ajouter Plusieurs Colonnes en Une Fois

Vous pouvez ajouter plusieurs colonnes simultanément :

```sql
ALTER TABLE Clients
ADD
    Telephone VARCHAR(20),
    DateInscription DATE,
    EstActif BIT;
```

**Note :** Séparez chaque colonne par une virgule.

### Ajouter une Colonne avec une Valeur par Défaut

Lorsque vous ajoutez une colonne à une table qui contient déjà des données, toutes les lignes existantes reçoivent la valeur `NULL` pour cette nouvelle colonne (sauf si vous spécifiez une valeur par défaut).

```sql
ALTER TABLE Clients
ADD Pays VARCHAR(50) DEFAULT 'France';
```

**Résultat :**
- Pour les nouvelles lignes insérées après cette modification : si aucun pays n'est spécifié, 'France' sera utilisé
- Pour les lignes existantes : elles auront `NULL` (sauf si vous ajoutez `NOT NULL`, voir ci-dessous)

> 💡 Pour qu'une colonne **NULLable** dotée d'un `DEFAULT` remplisse aussi les **lignes déjà présentes** avec la valeur par défaut (au lieu de `NULL`), ajoutez `WITH VALUES` :
> ```sql
> ALTER TABLE Clients
> ADD Pays VARCHAR(50) DEFAULT 'France' WITH VALUES;
> ```

### Ajouter une Colonne Obligatoire (NOT NULL)

Si vous voulez ajouter une colonne qui ne peut pas être `NULL` et que la table contient déjà des données, vous **devez** fournir une valeur par défaut :

```sql
-- CORRECT
ALTER TABLE Clients
ADD CodePostal VARCHAR(10) NOT NULL DEFAULT '00000';

-- ERREUR si la table contient des données
-- ALTER TABLE Clients
-- ADD CodePostal VARCHAR(10) NOT NULL;  -- Impossible sans DEFAULT !
```

## 2. Modifier une Colonne Existante (ALTER COLUMN)

### Syntaxe de Base

```sql
ALTER TABLE NomTable
ALTER COLUMN NomColonne NouveauType;
```

### Exemple : Augmenter la Taille d'une Colonne

Supposons que `VARCHAR(50)` n'est plus suffisant pour stocker les noms :

```sql
ALTER TABLE Clients
ALTER COLUMN Nom VARCHAR(100);
```

**Résultat :** La colonne `Nom` peut maintenant contenir jusqu'à 100 caractères au lieu de 50.

### Exemple : Changer le Type de Données

```sql
-- Changer un INT en BIGINT (nombre plus grand)
ALTER TABLE Commandes
ALTER COLUMN IdCommande BIGINT;

-- Changer un VARCHAR en NVARCHAR (pour supporter l'Unicode)
ALTER TABLE Produits
ALTER COLUMN Description NVARCHAR(200);
```

### Ajouter ou Retirer NOT NULL

**Ajouter NOT NULL :**

```sql
-- D'abord, assurez-vous qu'il n'y a pas de valeurs NULL
UPDATE Clients
SET Email = 'non.renseigne@exemple.com'
WHERE Email IS NULL;

-- Ensuite, ajoutez NOT NULL
ALTER TABLE Clients
ALTER COLUMN Email VARCHAR(100) NOT NULL;
```

**Retirer NOT NULL :**

```sql
ALTER TABLE Clients
ALTER COLUMN Email VARCHAR(100) NULL;
```

### Limitations Importantes

⚠️ **Attention** : Vous ne pouvez pas toujours modifier librement une colonne. Voici quelques restrictions :

1. **Réduction de taille** : Si des données existantes sont plus grandes que la nouvelle taille, la modification échouera
   ```sql
   -- Si un nom contient 80 caractères, ceci échouera :
   ALTER TABLE Clients
   ALTER COLUMN Nom VARCHAR(50);
   ```

2. **Changement de type incompatible** : Vous ne pouvez pas convertir n'importe quel type en un autre
   ```sql
   -- Impossible si la colonne contient du texte non numérique
   ALTER TABLE Clients
   ALTER COLUMN Email INT;
   ```

3. **Colonnes avec contraintes** : Si une colonne a une clé primaire, une clé étrangère ou un index, vous devrez peut-être supprimer ces contraintes d'abord

## 3. Supprimer une Colonne (DROP COLUMN)

### Syntaxe de Base

```sql
ALTER TABLE NomTable
DROP COLUMN NomColonne;
```

### Exemple Simple

Pour supprimer la colonne `Telephone` de la table `Clients` :

```sql
ALTER TABLE Clients
DROP COLUMN Telephone;
```

**⚠️ ATTENTION** : Cette opération est **irréversible**. Toutes les données de cette colonne seront **définitivement perdues** !

### Supprimer Plusieurs Colonnes

```sql
ALTER TABLE Clients
DROP COLUMN Telephone, DateInscription;
```

**Note :** Séparez les colonnes par des virgules (pas besoin de répéter `DROP COLUMN` pour chaque colonne).

### Restrictions sur la Suppression

Vous ne pouvez **pas** supprimer une colonne si :

1. Elle fait partie d'une **clé primaire**
2. Elle fait partie d'une **clé étrangère**
3. Elle a un **index** défini dessus
4. Elle a une **contrainte** (CHECK, DEFAULT, etc.)
5. C'est la **seule colonne** de la table (une table doit avoir au moins une colonne)

Dans ces cas, vous devrez d'abord supprimer la contrainte ou l'index, puis supprimer la colonne.

## 4. Renommer une Colonne

SQL Server n'a pas de commande `ALTER TABLE ... RENAME COLUMN` standard. À la place, on utilise une procédure stockée système :

### Syntaxe avec sp_rename

```sql
EXEC sp_rename 'NomTable.AncienNomColonne', 'NouveauNomColonne', 'COLUMN';
```

### Exemple

```sql
-- Renommer 'Prenom' en 'PrenomClient'
EXEC sp_rename 'Clients.Prenom', 'PrenomClient', 'COLUMN';
```

**Note :** `sp_rename` affichera un avertissement vous rappelant que renommer des objets peut casser des scripts ou procédures stockées qui les référencent.

## Exemples Pratiques Complets

### Scénario 1 : Évolution d'une Table Produits

```sql
-- Table initiale
CREATE TABLE Produits
(
    IdProduit INT,
    Nom VARCHAR(50),
    Prix DECIMAL(8, 2)
);

-- Ajout de nouvelles colonnes
ALTER TABLE Produits
ADD
    Description VARCHAR(500),
    QuantiteStock INT DEFAULT 0,
    DateAjout DATE DEFAULT GETDATE();

-- Augmenter la taille de la colonne Nom
ALTER TABLE Produits
ALTER COLUMN Nom VARCHAR(150);

-- Ajouter une colonne obligatoire avec valeur par défaut
ALTER TABLE Produits
ADD Categorie VARCHAR(50) NOT NULL DEFAULT 'Non classé';
```

### Scénario 2 : Correction d'une Table Employés

```sql
-- Table initiale avec une erreur
CREATE TABLE Employes
(
    IdEmploye INT,
    NomComplet VARCHAR(50),  -- Trop petit !
    Salaire INT               -- Devrait être DECIMAL !
);

-- Correction : augmenter la taille
ALTER TABLE Employes
ALTER COLUMN NomComplet VARCHAR(150);

-- Correction : changer le type (attention, la table doit être vide ou contenir des valeurs compatibles)
ALTER TABLE Employes
ALTER COLUMN Salaire DECIMAL(10, 2);

-- Ajout de colonnes manquantes
ALTER TABLE Employes
ADD
    Email VARCHAR(100),
    DateEmbauche DATE,
    Departement VARCHAR(50);

-- Supprimer une colonne inutile (exemple)
-- ALTER TABLE Employes
-- DROP COLUMN ColonneInutile;
```

### Scénario 3 : Nettoyage d'une Table

```sql
-- Supprimer plusieurs colonnes obsolètes
ALTER TABLE Clients
DROP COLUMN
    AncienneColonne1,
    AncienneColonne2,
    ColonneNonUtilisee;

-- Renommer une colonne pour plus de clarté
EXEC sp_rename 'Clients.Tel', 'Telephone', 'COLUMN';
```

## Vérifier la Structure d'une Table

Avant de modifier une table, il est utile de voir sa structure actuelle :

```sql
-- Méthode 1 : Voir toutes les colonnes et leurs types
SELECT
    COLUMN_NAME,
    DATA_TYPE,
    CHARACTER_MAXIMUM_LENGTH,
    IS_NULLABLE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'Clients'
ORDER BY ORDINAL_POSITION;

-- Méthode 2 : Commande rapide (dans SSMS)
EXEC sp_help 'Clients';
```

## Bonnes Pratiques

### 1. Testez sur une Copie d'Abord

Avant de modifier une table en production, testez vos commandes sur une copie :

```sql
-- Créer une copie de la table
SELECT * INTO Clients_Backup FROM Clients;

-- Tester vos modifications sur la copie
ALTER TABLE Clients_Backup
ADD NouvelleColonne VARCHAR(100);

-- Si tout fonctionne, appliquez à la table originale
```

### 2. Documentez vos Modifications

Ajoutez des commentaires dans vos scripts SQL :

```sql
-- 2025-11-16 : Ajout de la colonne Email pour la newsletter
ALTER TABLE Clients
ADD Email VARCHAR(100);

-- 2025-11-16 : Augmentation de la taille pour les noms composés
ALTER TABLE Clients
ALTER COLUMN Nom VARCHAR(150);
```

### 3. Vérifiez les Dépendances

Avant de supprimer ou modifier une colonne, vérifiez qu'elle n'est pas utilisée :
- Dans des vues (views)
- Dans des procédures stockées
- Dans des applications externes
- Dans des rapports

### 4. Sauvegardez Avant les Modifications Importantes

Pour les modifications critiques sur des tables avec beaucoup de données :

```sql
-- 1. Sauvegarder les données
SELECT * INTO Clients_Backup_20251116 FROM Clients;

-- 2. Effectuer la modification
ALTER TABLE Clients
ALTER COLUMN Email VARCHAR(150);

-- 3. Vérifier que tout fonctionne
-- 4. Si OK, supprimer la sauvegarde après quelques jours
```

### 5. Attention aux Tables Volumineuses

Sur de très grandes tables (millions de lignes), certaines modifications peuvent :
- Prendre beaucoup de temps
- Bloquer l'accès à la table
- Nécessiter beaucoup d'espace disque temporaire

Dans ces cas, planifiez vos modifications pendant les périodes de faible activité.

## Ordre Logique des Modifications

Quand vous devez effectuer plusieurs modifications, respectez cet ordre :

1. **Supprimer** les contraintes si nécessaire
2. **Modifier** les colonnes existantes
3. **Ajouter** de nouvelles colonnes
4. **Supprimer** les colonnes obsolètes
5. **Ajouter** les nouvelles contraintes

Exemple :

```sql
-- 1. Supprimer une contrainte
ALTER TABLE Clients
DROP CONSTRAINT DF_Clients_Pays;

-- 2. Modifier la colonne
ALTER TABLE Clients
ALTER COLUMN Pays VARCHAR(100);

-- 3. Ajouter de nouvelles colonnes
ALTER TABLE Clients
ADD
    Region VARCHAR(50),
    CodePostal VARCHAR(10);

-- 4. Supprimer colonne obsolète
ALTER TABLE Clients
DROP COLUMN AncienneColonne;

-- 5. Recréer la contrainte
ALTER TABLE Clients
ADD CONSTRAINT DF_Clients_Pays DEFAULT 'France' FOR Pays;
```

## Messages d'Erreur Courants

### Erreur : Colonne introuvable

```
Invalid column name 'Email'.
```

**Cause :** Vous essayez de modifier/supprimer une colonne qui n'existe pas.  
**Solution :** Vérifiez le nom exact de la colonne (sensible à la casse dans certains cas).  

### Erreur : Conflit de données

```
ALTER TABLE statement conflicted with the CHECK constraint...
```

**Cause :** Des données existantes ne respectent pas la nouvelle contrainte.  
**Solution :** Corrigez les données avant d'appliquer la contrainte.  

### Erreur : Impossible de modifier

```
The object 'DF_Clients_Email' is dependent on column 'Email'.
```

**Cause :** Une contrainte DEFAULT existe sur cette colonne.  
**Solution :** Supprimez d'abord la contrainte avec `DROP CONSTRAINT`.  

## Exemple Complet : Évolution Réaliste d'une Table

```sql
-- ===================================
-- CRÉATION INITIALE (Semaine 1)
-- ===================================
CREATE TABLE Commandes
(
    IdCommande INT,
    DateCommande DATE,
    MontantTotal DECIMAL(8, 2)
);

-- ===================================
-- ÉVOLUTION 1 (Semaine 2)
-- Besoin : ajouter les informations client
-- ===================================
ALTER TABLE Commandes
ADD
    IdClient INT,
    NomClient VARCHAR(100);

-- ===================================
-- ÉVOLUTION 2 (Semaine 3)
-- Besoin : augmenter la précision du montant
-- ===================================
ALTER TABLE Commandes
ALTER COLUMN MontantTotal DECIMAL(12, 2);

-- ===================================
-- ÉVOLUTION 3 (Mois 2)
-- Besoin : ajouter le statut de la commande
-- ===================================
ALTER TABLE Commandes
ADD Statut VARCHAR(20) NOT NULL DEFAULT 'En attente';

-- ===================================
-- ÉVOLUTION 4 (Mois 3)
-- Nettoyage : NomClient n'est plus nécessaire (on utilise IdClient)
-- ===================================
ALTER TABLE Commandes
DROP COLUMN NomClient;

-- ===================================
-- ÉVOLUTION 5 (Mois 4)
-- Amélioration : ajouter la date de livraison
-- ===================================
ALTER TABLE Commandes
ADD DateLivraison DATE NULL;

-- Vérifier la structure finale
EXEC sp_help 'Commandes';
```

## Résumé

| Opération | Syntaxe | Usage |
|-----------|---------|-------|
| **Ajouter une colonne** | `ALTER TABLE table ADD colonne type;` | Nouvelle colonne nécessaire |
| **Modifier une colonne** | `ALTER TABLE table ALTER COLUMN colonne nouveauType;` | Changer type ou taille |
| **Supprimer une colonne** | `ALTER TABLE table DROP COLUMN colonne;` | Colonne obsolète |
| **Renommer une colonne** | `EXEC sp_rename 'table.ancien', 'nouveau', 'COLUMN';` | Clarifier le nom |

## Points Clés à Retenir

1. ✅ `ALTER TABLE` modifie la **structure**, pas les données
2. ✅ Vous pouvez ajouter, modifier ou supprimer des colonnes
3. ⚠️ La suppression de colonnes est **irréversible**
4. ⚠️ Certaines modifications nécessitent de supprimer les contraintes d'abord
5. ✅ Testez toujours sur une copie avant de modifier une table importante
6. ✅ Documentez vos modifications dans vos scripts SQL
